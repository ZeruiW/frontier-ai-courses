直白说

所以「单目深度估计」这个任务名字里隐含了一个必须交代的问题：它输出的到底是什么？如果是米，那么这个米从哪来——不可能来自图像。三种真实的答案：① 相对深度（只保证前后关系与比例，不给单位）；② 仿射不变的视差（差一个尺度与一个位移，见第 3 节）；③ 米——而这个米来自训练数据里的统计规律（房间大概多大、人大概多高、车道大概多宽）。

严谨说

第三种最有用也最脆弱。它把一个几何问题换成了一个统计问题：「这张图的场景尺度与训练分布里哪一类最像」。所以它在室内数据上训练、拿到航拍图上就会系统性地错，而错的方式是整体缩放——图看起来完全合理，只是尺度不对。这类错误在任何「相对」指标下都看不见，只在绝对指标下暴露。

与 C72 模块 03 对照着看会更清楚。C72 列了四种补齐缺失自由度的办法：另一个视角、平面假设、已知尺寸、另一个传感器。前馈单目方法用的是第五种：一个从数据里学到的先验。而 C72 的那四种都能写出误差传播公式（比如已知尺寸时误差 ∝ 尺寸分类的相对误差），第五种不能——它的误差取决于分布偏移的程度，而那没有闭式。

直白说

只有「视差域 + 仿射」能把这个完美预测器还原到 0.3%。其余三种组合都差 40–110 倍。原因很干净：仿射关系成立的域是视差域，换到深度域之后 $\hat z = 1/(a/z + b)$ 不是 $z$ 的仿射函数——所以在深度域拟合一条直线，本身就是在拟合一个错的模型。

严谨说

而这条规律是对称的。notebook 反过来测了一个「深度域仿射完美」的预测器：深度域 + 仿射 → AbsRel 0.000304；视差域 + 仿射 → 0.073561（差 242 倍）。所以规则不是「视差域更好」，而是「对齐域必须与模型的不变性所在的域一致」。而这意味着：评测协议不能独立于模型来定。

选择三：用哪个指标——它们对同一种错误的反应差很多

回到第一张表的第二行（视差域 + 只做尺度对齐）：AbsRel 是 0.33928，而 $\delta<1.25$ 是 0.2978。**两个指标都说「很差」，但它们差的方式不同**：

指标定义它对什么敏感它对什么不敏感
AbsRel$\mathrm{median}\,\vert\hat z - z\vert / z$相对误差的典型大小尾部——用中位数时 10% 的极端错误完全不影响它
$\delta<1.25$$\max(\hat z/z,\,z/\hat z) < 1.25$ 的像素比例「有多少像素合格」——一个通过率合格像素错多少、不合格像素错多离谱，它都不管
RMSE / RMSE-log$\sqrt{\mathrm{mean}(\cdot)^2}$尾部（平方 + 均值）而它被远处的大深度支配，所以 RMSE-log 更常用

直白说

三个指标里只有 $\delta<1.25$ 有一个绝对的解释：「这个像素的深度可以用吗」。而 25% 这个阈值是一个约定，它来自 Eigen et al.(2014)——并不是某个应用需求推出来的。所以做一个具体应用时，正确的做法是按需求换阈值：机器人抓取可能要 $\delta<1.02$，而背景虚化只需要 $\delta<1.5$。

严谨说

而组合起来看才有意义。AbsRel 小但 $\delta<1.25$ 也低 → 大部分像素略微超标（系统性偏置）；AbsRel 大但 $\delta<1.25$ 高 → 少数像素错得很离谱（离群/遮挡）；两个都差 → 尺度或对齐口径错了（第一张表的第 2、4 行）。只报一个指标，这三种情形无法区分。

三个选择合起来，同一个模型的 AbsRel 可以是 0.003 或 0.427——差 154 倍。而三者都是「合理的」协议，只是回答不同的问题：逐图对齐问「形状对不对」，全局对齐问「形状 + 跨场景的尺度一致性对不对」，不对齐问「绝对尺度对不对」。所以看到一个单目深度的数字时，必须先问三件事：域、自由度、逐图还是全局——缺任何一个，这个数字都不可比。

3为什么是「仿射不变」而不是「尺度不变」

尺度歧义只有 1 个自由度（第 1 节），那么第 2 节里那个「位移」$b$ 是从哪来的？

位移 $b$尺度对齐的 rel-RMSE仿射对齐的 rel-RMSE比值
0.000.002340.002341.0×
0.050.040340.0023417.2×
0.420.252650.00234107.9×
2.000.532580.00234227.5×

直白说

$b=0$ 时两种对齐完全相同——所以位移项确实是一个额外的自由度，不是尺度的一部分。它的来源是训练侧而不是几何侧：MiDaS 类模型在十几个数据集上混合训练，而这些数据集的「深度」定义各不相同——有的是米、有的是视差、有的是相对深度、有的经过未知的重标定；而且很多只有相对标注。要在这些数据上共同训练，就必须用一个对「尺度 + 位移」都不变的损失。

严谨说

而选视差而不是深度，有一个独立的理由：$z\to\infty$ 时视差 $\to 0$，是有界的。天空、远景在深度域是 $+\infty$（无法回归），在视差域是 0（可以回归）。所以「预测视差 + 仿射不变损失」这个组合是被两件事同时逼出来的：① 混合数据集的标注不一致；② 深度的无界性。而代价就是第 2 节那张表——用错口径会让数字差两个数量级。

一个由此推出的实践建议：把「模型输出什么」写进接口签名里。返回一个裸的 $H\times W$ 数组时，调用方无法知道它是相对深度、仿射不变视差、还是米——而这三者的下游用法完全不同。而这类混淆在跨团队协作时几乎必然发生一次：一方按「米」用，另一方按「视差」出，结果是前后关系整体反转（因为视差与深度是倒数关系）。
Depth Anything V2 之后的一个变化值得注意：出现了「metric」分支。做法是在仿射不变的骨干上再接一个针对特定域（室内/室外）微调的头，让它直接输出米。这不是解决了第 1 节的不可观测性，而是把那个统计先验显式化了——所以它必须按域分开训练与使用，而跨域用就会系统性地缩放错。

4点图：把内参也一起回归掉

DUSt3R 类方法的输出不是深度图，而是**点图**（pointmap）：每个像素对应一个 3D 点 $(X,Y,Z)$，且**两张图的点图在同一个坐标系里**。

深度图 vs 点图： 深度图： 像素 (u,v) -> z 需要内参 K 才能变成 3D 点 1 个通道 -> 所以内参必须已知或另外估计 点图： 像素 (u,v) -> (X, Y, Z) **自带**内参信息 3 个通道 -> 因为 u = cx + f X/Z 反过来能解出 f 而「两张图共一个坐标系」意味着相对位姿也自带了： 对应点的刚体变换 = 相对位姿 -> 所以 SfM 那一步也被吸收了
真值 $f$从点图最小二乘反解的 $f$相对误差

直白说

焦距是精确可解的（$u - c_x = f\,X/Z$ 是一个超定线性方程）。所以「预测点图」这个输出形式把「标定」这一步也吸收进了网络。这就是 pose-free、calibration-free 的真实含义：不是不需要内参，而是内参被输出而不是被输入。

严谨说

而代价是过参数化，且倍数恰好是 3.00：点图有 $3HW$ 个自由度，而它要表示的东西只有（深度 $HW$ + 内参 1~4）个。

直白说

冗余的后果是「一致性必须靠网络自己保证，而不是被构造保证」。一个合法的深度图 + 内参组合必然对应一个「射线一致」的点图（所有点都落在从光心出发的射线束上）；但一个任意的 $3HW$ 张量不必如此。所以网络输出的点图可能是「几何上不自洽」的——而这种不自洽在可视化上不明显，但在下游（三角化、位姿求解）会放大。

严谨说

实践中的对策有两条，都在真实实现里出现：① 后处理投影——从点图先解出 $f$，再把每个点投影回它自己的射线上（只保留深度分量），于是自洽性被强制恢复；② 全局对齐（DUSt3R 的第二阶段）——把多对点图放进一个优化里，同时求各图的位姿与尺度，而这一步本质上就是一次束调整（模块 01）。所以 pose-free 方法并没有真的取消 SfM，它把 SfM 从「必须先做对」变成了「用来收尾」。

5全局对齐：它就是一次束调整

点图是逐对预测的（DUSt3R 一次吃两张图），而每一对有自己的未知尺度。要把 $N$ 张图拼成一个模型，就要同时求各图的位姿、各对的尺度、以及公共的 3D 点——**而这是一个和模块 01 同构的问题**。

$N{=}5$（10 对，60 个点）个数
各图位姿$5\times6 = 30$
各对尺度$10\times1 = 10$
场景点$60\times3 = 180$
参数合计220
观测（每对两张点图 × 60 点 × 3 维）3,600
Hessian 的秩亏恰好 7（谱间隙 $3.6\times10^{12}$）

直白说

秩亏 7——与模块 01 的束调整完全相同，因为它是同一个 gauge：世界坐标系的相似变换。区别只在残差的形式：模块 01 是 2D 重投影差，这里是 3D 点差。所以模块 01 的全套结论直接适用：需要固定或投影掉 gauge（否则尺度会随机漂移）、点块是块对角的所以可以用 Schur 补、协方差依赖 gauge 的选择。

严谨说

而这说明「pose-free」并没有取消 SfM，它换了 SfM 的位置：传统流程里 SfM 在最前面，必须先做对，做不对整条链就断（模块 01 第 2、6 节）；前馈流程里前馈网络先给出每对的几何，然后用一次已经有很好初值的全局优化收尾。后者的关键优势不是「不需要优化」，而是「优化不会掉进坏的局部解」——因为初值不是从零开始的贪心增量，而是网络一次给出的。

6输出表示的四种选择：各自把哪一部分「构造保证」掉了

前馈方法的输出形式不是实现细节——**它决定了哪些一致性是免费的、哪些必须靠网络自己学会**。用「自由度账」来看最清楚（以 $H\times W$ 的图像为单位）：

输出表示自由度真正需要的自由度冗余构造上免费保证的必须靠网络学会的
相对深度（视差图）$HW$$HW$1.00×射线一致性（每个像素只有一个沿射线的量）尺度与位移（第 3 节：2 个自由度对不上）
度量深度$HW$$HW$1.00×同上，且尺度已定尺度的正确性——而它来自分布假设（第 1 节）
点图 pointmap$3HW$$HW+1$3.00×无需内参；相对位姿隐含在两图的点图里射线一致性 + 内参自洽（第 4 节）
直接出高斯（Splatter Image 类）$\approx 14 HW$ 起（C74 模块 05）$HW+1$> 14×可直接渲染，无需后处理几何 + 外观 + 不透明度全部

直白说

规律很清楚：冗余越大，网络要自己学会的一致性越多。深度图的冗余是 1.00×，所以它不可能输出一个「几何上不自洽」的结果——射线一致性是被表示本身构造保证的。点图的 3.00× 冗余买到了「不需要内参」，代价是它可以输出不自洽的东西（第 4 节）。

严谨说

而这个取舍与 C74 模块 02 的那个是同一类：C74 里「不直接存协方差、而存 $(s,q)$ 再算 $RSS^\top R^\top$」把正定性编码进了参数化，于是优化器再也不可能违反它。这里是反方向的选择：点图放弃了把射线一致性编码进表示，换来了内参的自由。两个课程、两个方向，而判断的依据相同：「这个约束是硬的还是软的？硬的就编码进表示，软的才交给优化」。

所以「该选哪种输出」有一个可操作的判据：内参已知且可信 → 用深度图（冗余 1.00×，一致性免费）；内参未知或不可信 → 用点图（多付 3× 冗余，换标定自由）；要直接渲染且不在乎几何精度 → 直接出高斯。而最后一种在几何评测上通常最差——因为它把几何、外观、不透明度混在一个 $14HW$ 的张量里，而只有渲染损失在监督它（C74 模块 05 第 7 节的「要几何准就用 2DGS」是同一件事）。

7前馈绕开了什么，又引入了什么

SfM 的失败模式（模块 01）前馈方法还怕它吗为什么
视角太少（1–2 张）不怕先验代替了几何约束——这是它最大的卖点
基线太短 / 纯旋转（条件数 $4.4\times10^{17}$）不怕单目预测根本不依赖基线
无纹理 / 周期纹理（模块 02）基本不怕先验会「填」进一个合理的表面，而不是像 NCC 一样给出噪声（模块 02 第 3 节）
共面场景（$E$ 退化）不怕不解 $E$
前馈方法新引入的失败模式表现怎么检测
尺度分布偏移整体缩放错，但图看起来完全合理只有绝对指标能抓到——而第 2 节说逐图对齐会把它完全掩盖掉
几何不自洽（第 4 节的过参数化）点图不落在射线束上；多对点图拼不起来投影回射线后看残差；或看全局对齐的收敛残差
「合理但错」的补全遮挡区、玻璃、镜子处给出一个平滑合理的表面，而它不对无法从单张图检测——必须用另一个视角或另一个传感器
对分布内的场景过于自信不输出不确定度，或输出的不确定度与真实误差不相关需要专门的校准评估（见 C10）

直白说

把两张表并排读，结论是「两类方法的失败模式几乎不重叠」。几何方法在信息不足时拒绝回答（条件数爆掉、代价曲线平）；前馈方法在信息不足时照样回答（先验会填）。所以它们是互补的，而不是替代关系。

严谨说

而这就是 2024 年以来的主流做法：混合。用前馈方法做初始化与「无纹理区的填充」，用几何优化（束调整）做收尾与精度。MASt3R 就是这个形状：前馈出点图与匹配，再做全局对齐；而 3DGS/2DGS 的位姿也越来越多地由前馈方法给初值、再联合优化。模块 05 会说明这条混合路线对评测的影响：当初值来自一个学到的先验时，「重建误差」里混进了「先验有多合适」这一项。

8诊断：一个前馈重建能不能用

按「花的时间从少到多」排列。前两条不需要任何真值。

  1. 射线一致性检验（点图专用，不需要真值）——从点图先解出 $f$（第 4 节：精确可解），再把每个点投影回它自己的射线上，看残差。残差大就说明网络输出的 $3HW$ 张量不自洽，而这时任何下游几何计算都不可信
  2. 换视角渲一张（如果有稠密表示）——与 C74 模块 05 的浮物检测是同一招。遮挡区被「合理地填」出来的东西，在新视角下立刻露馅
  3. 全局对齐的收敛残差（第 5 节）——把多对点图放进一次优化。残差小说明各对之间自洽；残差大说明至少有一对是错的，而看每对的残差就能定位是哪一对
  4. 用一个已知长度做尺度检验——这是唯一能抓到第 1 节那个「整体缩放错」的办法。而它也是 gauge 无关的（模块 01 第 7 节）
  5. 与几何方法交叉验证——在纹理充分的区域跑一次 MVS（模块 02），与前馈结果比。两者的失败模式几乎不重叠（第 7 节），所以它们一致的地方基本可信
这五条的顺序不是随意排的：前两条不需要真值，后三条需要。而「不需要真值的自检」在部署时是唯一可用的——线上没有真值，但射线一致性与「换视角渲一张」随时都能做。所以把它们做成一条自动流水线，比事后拿真值评测更有价值——后者只能告诉你「上次那批数据上表现如何」，前者能告诉你「这一次的输出可不可信」。
而有一类问题这五条都抓不到：整个场景的尺度先验用错了，但内部完全自洽。射线一致 ✓、新视角合理 ✓、全局对齐收敛 ✓、与 MVS 一致 ✓（因为 MVS 也只有相对尺度）。只有第 4 条（已知长度）能抓到它——所以如果你的应用真的需要米，那么「场景里放一个已知尺寸的标定物」不是可选的工程便利，而是唯一的信息来源。
