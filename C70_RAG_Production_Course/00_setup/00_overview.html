1这门课讲什么：RAG 的失败大多不在检索算法里

C11 已经把检索算法讲透了：嵌入、BM25、混合检索、IVF/HNSW/PQ、cross-encoder 重排、precision@k / nDCG、faithfulness 与 context recall。这门课从一个不同的观察出发：在真实系统里，「答不上来」这件事绝大多数时候和这些算法没有关系。

一个真实 RAG 系统的完整链路 ┌──────────┐ ┌────────┐ ┌────────┐ ┌────────┐ ┌────────┐ │ 文档摄取 │──►│ 分块 │──►│ 索引 │──►│ 检索 │──►│ 组装 │──►答 │ 与解析 │ │ │ │ │ │ │ │ 上下文 │ └──────────┘ └────────┘ └────────┘ └────────┘ └────────┘ ▲ ▲ ▲ ▲ │ │ │ │ 本课 01 本课 02 本课 05 C11 全课 本课 03（查询侧改写）· 本课 04（迭代检索） C11 覆盖的是「检索」这一格里的算法，以及最右边的评测。 本课覆盖的是它左边的三格和右边的一格——**输入侧与运维侧**。

直白说

为什么这个分工重要？因为检索算法只能在「已经进了索引的东西」里找。如果答案在解析时被丢掉了、在分块时被切断了、在索引里已经过期了，那么把 HNSW 换成暴力 kNN、把 top-5 改成 top-20、加一个 cross-encoder 重排——一个都救不回来。这类失败的共同特征是：检索指标看起来正常，端到端答案却是错的。

严谨说

形式化一点：设问题 $q$ 的答案证据是文档集合里的一个片段 $e$。端到端可答的必要条件是$e \subseteq \bigcup_{c \in \text{retrieved}(q)} c$，而这个条件可以在四个地方被破坏：$e$ 在解析时丢失（$e \notin \text{corpus}$）、$e$ 被分块切断（$\nexists c: e \subseteq c$）、$e$ 的索引版本已过期、$q$ 与承载 $e$ 的块之间存在词汇或语义鸿沟。只有最后一个是检索算法能处理的，而 C11 的全部工具都作用在最后一个上。

一句话记住本课的定位：C11 教你在语料里把对的段落找出来，本课教你让「对的段落」一开始就存在、并且在一年后还是对的。

2六个静默失败：它们都不会让检索指标变差

下面这六个是本课每个模块各自的靶子。把它们排在一起是因为它们有一个共同的、危险的性质：发生时没有任何报错，而且离线检索指标可能完全正常。

#失败症状（用户看到的）为什么检索指标抓不到本课模块
1解析丢结构「这张表里 2023 年的数字是多少」答错表格被拍平成文本后，行列对应关系已经不在语料里了；检索照样能召回那个块，块里的字也都在01
2阅读顺序错乱把 A 的属性说成 B 的双栏版面按坐标乱序拼接后，句子仍然是「相关」的，只是实体与属性错配了01
3答案跨块边界答案说一半召回的块确实是最相关的那个——precision@k 满分，但答案的后半截在下一个块里02
4词汇鸿沟「明明文档里写了」却答不出来用户的问法和文档的写法不共享任何词；这在用查询本身做的评测里看不出来03
5需要两跳答案自信但错单轮检索的 recall 对这个问题天然是 0，而 recall 是按「标注的相关文档」算的——标注本身只标了第一跳04
6索引过期 / 删除没生效答出了已经删掉的内容离线评测跑在一个静态快照上，快照里没有「时间」这一维05

第 6 个值得单独强调，因为它同时是一个合规问题：如果用户要求删除一份文档，而它的向量还留在索引里，那么这份文档仍然会被检索到并被喂给模型。「从源库删除」和「从索引删除」是两件事，而只有后者决定用户还能不能看到它。

本课的每个模块都遵循同一个套路：先把这类失败做成一个可以复现的实验，然后给出一个能把它变成机器可判定的检查。「注意分块要合理」不是工程，「答案完整落在单块内的比例 ≥ 0.9，低于就报警」才是。

3课程地图：四段流水线 + 一段运维

六个模块分成两半：01–04 是数据与查询怎么进来，05 是它进来之后怎么活下去。

模块主题核心主张（一句话）
01文档摄取与解析解析的目标不是「拿到文字」，而是拿到文字 + 它的结构与来源；丢掉的结构在下游无法恢复
02分块分块不是「切成差不多大的段」，而是让答案有机会完整地落在一个可检索单元里；这是一个可以直接测量的量
03查询侧改写与路由查询是流水线里唯一你能在运行时改写的东西；而第一个该问的问题是「这个查询到底该不该检索」
04迭代与图检索多跳问题的单轮 recall 天然是 0；迭代必须带停止准则，否则成本没有上界
05索引运维索引是有状态的、会腐烂的；「换 embedding 模型」是一次不可混用的全量迁移，不是一次配置修改

三条贯穿全课的纪律

  1. 每一个块都要能回答「你从哪来」——文档 ID、版本、页码/章节、字符区间。没有 provenance 的块无法被删除、无法被更新、无法被引用核查。这条在 01 建立，在 05 被用来做删除与新鲜度。
  2. 摄取必须幂等——同一份文档摄取两次，索引里不能出现两份块。实现只需要一句话：主键 (doc_id, version, chunk_index)，写入前先查在不在（与 C68 模块 00 的幂等 store 同构）。
  3. 每一层改动都要能被同一套离线集重测——换分块参数、加一个查询改写、升级 embedding 模型，都必须能跑出「之前 / 之后」两个数。这门课不重复 C11 的指标定义，但会反复用它们做 A/B。

5方法论：为什么用玩具嵌入而不接真实模型

这门课的 notebook 全部是纯 numpy / 标准库、CPU、断网、无需 API key。嵌入是确定性的玩具向量，「生成」是规则函数。这是一个刻意的选择，理由有三条。

  1. 本课要测的量都不需要真实模型——「答案完整落在单块内的比例」「近重复占满 top-k 的程度」「索引滞后导致的过期答案率」「新旧 embedding 混用后的相似度失真」，这些全都是流水线的结构性质，与用哪个嵌入模型无关。
  2. 只有在知道真值的条件下，才能验证一个改动是把结果推近了还是推远了。真实模型会把「分块改好了」和「模型今天心情好」混在一起；玩具替身让每个实验只有一个变量。这与 C66/C67/C68 的方法论是同一条。
  3. 玩具替身让「失败」可以被精确注入——OCR 错误率设成 3%、索引滞后设成 6 小时、答案跨块设成必然发生。真实系统里这些故障是偶发的，而偶发的故障没法用来教学。

每个模块末尾都有 🧪 真实工程胶囊：可以原样复制到生产的落地代码骨架（unstructured / pypdf 的解析入口、父子块的存储布局、查询改写的 prompt 与缓存、增量索引的双写与原子切换、检索层的监控指标）。但课程本身不依赖它们。

每个模块的固定结构

  • 讲解页：机制 → 可测量的量 → 怎么变成检查项
  • notebook：5–7 个 worked 小节，每节都以一个 assert 结尾
  • 4 道 ✏️ 练习：TODO 骨架 + assert 自动判分 + 📖 参考答案
  • 🧪 真实工程胶囊：接真实解析库 / 向量库 / 生产索引的代码
