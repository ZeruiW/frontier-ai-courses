RAG 生产工程

C11 已经把检索算法讲透了。而在真实系统里，「RAG 答不上来」这件事绝大多数时候和这些算法没有关系——检索算法只能在「已经进了索引的东西」里找。如果答案在解析时被丢掉了、在分块时被切断了、在索引里已经过期了，那么换 embedding、加重排、放大 top-k 一个都救不回来，而这类失败的共同特征是检索指标看起来正常、端到端答案却是错的。本课的核心主张：RAG 的调试顺序必须是从左往右的——先确认答案在语料里、再确认它没被切断、再确认查询能碰到它，最后才去调检索算法。

6 模块 五格流水线：摄取 · 分块 · 索引 · 检索 · 组装 四个静默失败（只有一个能被检索指标看见） 完整率公式 min(1,(s−a+1)/(s−o)) 后置过滤返空 (1−φ)^k 跨 embedding 空间内积 ≈ 0 纯 numpy · CPU · 断网可跑
怎么用： 先读模块的 NN_讲解.html，再跑同目录下的同名 .ipynb。notebook 用确定性玩具嵌入 + 规则型「生成」——嵌入是 hashing trick（中文取单字与二元组，4096 维），「生成」是「答案字符串是否完整出现在召回块里」。这比接真实模型更适合本课：要测的量（答案完整率、eff@k、过期答案率、跨空间相似度失真）都是流水线的结构性质，与用哪个嵌入模型无关，而玩具替身让故障可以被精确注入。每个模块末尾的 🧪 真实工程胶囊 给出可原样复制的落地代码（unstructured 的 element 与坐标、分隔符优先级、父子块存储布局、查询改写 prompt 与缓存键、实体倒排两张表、影子索引双写与 alias 切换）——但课程全程 CPU、断网、无需 API key。一个诚实的说明：玩具嵌入在否定与同义词泛化上比真实模型更弱，课程在用到这一点的地方（模块 03 第 6 节）明确说明了。
