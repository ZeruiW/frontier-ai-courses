02 · 分块

分块是一个有约束的优化问题：在答案完整率 ≥ 阈值的前提下最小化块数——而这个约束不需要试，可以算 · $\text{intact}(s,o,a) = \min(1, (s-a+1)/(s-o))$，与穷举实测差 $10^{-4}$ · 重叠的正确取值只由最长答案决定：$o \ge a-1$，在 s=60…500 上都成立——「重叠设块长的 10%」把重叠绑在了错误的量上 · 达到完整率 1 的索引成本倍数是 $s/(s-a+1)$：s=500,a=50 时 1.11×（直接加），s=80,a=70 时 7.3×（该换分块方式而不是继续调重叠） · 主题纯度要用「块有没有跨越文档自己的结构边界」这个精确定义，不要用块内句相似度——那个代理依赖的正是你要评估的嵌入 · 语义分块的分位数阈值有两个真实的退化（相似度大量为 0 时 q 完全失效；相似度全相等时处处切），修法是绝对阈值 + 双向硬约束 · 父子块同时拿到大块的命中率与接近小块的上下文成本，前提是父块去重 + 归因指向子块 · 稀释是 $1/\sqrt{1+\|z\|^2/\|r\|^2}$ 型的，比线性慢

1分块的目标函数：三个互相竞争的量

「块该多大」是 RAG 里被问得最多、被回答得最差的问题。常见答案是「512 token，重叠 50」——这个答案的问题不是数字错了，而是它没有说这个数字在优化什么。

分块要同时管三个量，而它们互相竞争：

量定义块变大时块变小时
答案完整率 intact答案完整落在某一个块内的比例上升（大块装得下）下降（答案被切断）
主题纯度 1 − cross块没有跨越文档自己的结构边界的比例下降（一个块里混了几个主题）上升
索引成本 n_chunks块的数量（存储、向量、检索延迟、上下文预算）下降上升

直白说

所以「块该多大」不是一个有唯一答案的问题，而是一个有约束的优化问题：在答案完整率不低于某个阈值的前提下，最小化块数。阈值来自你的业务（答案说一半是不可接受的失败），而不是来自某篇博客的默认值。

严谨说

写成规划问题：$\min_{s, o} \; n(s, o)$ s.t. $\text{intact}(s, o) \ge \tau$，$\text{purity}(s) \ge \rho$。本模块的核心贡献是：$\text{intact}(s, o)$ 有一个精确的解析式（第 3 节），所以这个约束不需要试，可以算。$n(s, o) = L / (s - o)$，也是解析的。而第 4 节的纯度定义也是算术——所以这三个量全都不需要试，可以算。

有一个判据能立刻看出一个分块方案有没有想清楚：问「你们的最长答案有多长？」答不上来，那么重叠设多少都是猜的——第 3 节会证明重叠的正确取值只由这一个量决定。

2固定窗口的两个失败

固定字符/token 窗口是所有分块的基线。它有两个失败，而它们的方向相反——这正是上一节那张表的来源。

失败一：块太小 → 答案被切断 文档: ...正式员工每年享有 15 天带薪年假。试用期员工... │ │ 块边界 ──────────────┴──────────────┘ 块 k: "...正式员工每年享有 15 " 块 k+1: "天带薪年假。试用期员工..." → 召回块 k（它确实最相关），答案说一半。**Precision@1 满分。** 失败二：块太大 → 主题混在一起 块 j: "...年假需提前三日申请。报销流程说明。餐饮报销单次上限 200 元..." └────── 主题 A ──────┘└────────── 主题 B ──────────┘ → 查「报销上限」时，这个块的向量被主题 A 稀释了（第 7 节量这件事）； 查「年假申请」时，喂给模型的上下文里混进了无关的报销规定。

失败一是断崖式的、可以被精确计算的；失败二是渐进式的、需要测量。这个不对称决定了工程上的处理顺序：先用公式把完整率钉在阈值之上，再在满足约束的配置里挑纯度最好的那个。

为什么「按 token 切」不比「按字符切」更安全

直白说

很多实现从字符换成 token 后就认为问题解决了。不是——切断的概率只与「块长/答案长」的比值有关，与单位无关。换单位只是换了刻度。唯一真正有用的改变是让边界落在语义边界上（句号、段落、标题），这是第 4、5 节的内容。

严谨说

严格地说：设答案长 $a$、块长 $s$、步长 $s-o$，这三个量用同一个单位度量时，第 3 节的公式只依赖 $a/s$ 与 $o/s$。换单位等于同时缩放 $a, s, o$，公式的值不变。唯一的例外是当单位本身携带语义信息时——「按句切」的分块，答案（通常是一到两句）被切断的概率天然更低，因为切点与答案的边界对齐了。

3答案完整率的精确公式（本模块最有用的一条）

这一节给出 intact 的解析式。它的价值是让「重叠设多少」从一个玄学问题变成一次算术。

设文档长 $L$、块长 $s$、重叠 $o$、步长 $\text{step} = s - o$，答案是一个长 $a$ 的连续片段，起点在文档里近似均匀分布。块的起点是 $0, \text{step}, 2\,\text{step}, \dots$

直白说

答案能完整落进第 $i$ 个块，当且仅当它的起点 $p$ 满足$i \cdot \text{step} \le p$ 且 $p + a \le i \cdot \text{step} + s$。也就是说，每个块提供了一段长 $s - a + 1$ 的「安全区」，而相邻块的起点相差 $\text{step}$。安全区盖不满的那部分，就是答案必然被切断的位置。

严谨说

把它写出来：$$\text{intact}(s, o, a) = \begin{cases} 0, & s < a \\ \min\!\left(1, \dfrac{s - a + 1}{s - o}\right), & s \ge a \end{cases}$$notebook 第 2 节把它与穷举实测对拍，误差在 $10^{-3}$ 量级（差异只来自文档两端的边界效应）。

三个立刻可用的推论

  1. 要让完整率达到 1，重叠必须满足 $o \ge a - 1$。把 $\min$ 里的分式设为 $\ge 1$ 解一下即可。也就是说：重叠的正确取值只由最长答案的长度决定，和块大小无关。「重叠设块长的 10%」这个流行做法之所以经常不够，就是因为它把重叠绑在了错误的量上。
  2. 达到完整率 1 的索引成本倍数是 $\dfrac{s}{s - a + 1}$。$s = 500, a = 50$ 时是 1.11 倍（很便宜）；$s = 100, a = 60$ 时是 2.44 倍；$s = 80, a = 70$ 时是 7.3 倍（这时候该换分块方式，而不是加重叠）。
  3. $s < a$ 时完整率是 0，加多少重叠都没用。这听起来显然，但它给出了块大小的硬下界：$s \ge a$。所以流程是先由最长答案定下界，再由纯度与成本定具体值。

怎么知道 a

$a$ 是可以测的，而且很便宜：从你的评测集里取答案（或答案证据）的字符/token 长度，取 95 分位数而不是最大值——最大值通常是一个异常长的表格类答案，为它把重叠拉满不划算。把这个 P95 写进分块配置的注释里，它是整个配置唯一的自由输入。

4结构感知分块：用模块 01 拿到的东西

固定窗口的边界是任意的。而模块 01 已经把 section_path 与 element_type 拿到手了——用它们当边界，纯度会立刻改善，而且不花任何额外成本。

结构感知分块的三条规则（按优先级） ① 绝不跨 element 边界切表格 表格块 = 行转句（模块 01），一行一块或几行一块，永不与正文混合 ② 优先在结构边界切：标题 > 段落 > 句子 > 字符 这就是 RecursiveCharacterTextSplitter 的分隔符优先级列表在做的事 ③ 每个块继承它所在的 section_path，并把它**拼进块的文本** 块文本 = "第三章 / 报销制度\n\n餐饮报销的单次上限是 200 元。" ↑ 这一步让「章节名里的词」也参与检索—— 用户问「报销制度里餐饮怎么规定」时，章节名提供了关键的匹配信号

直白说

第三条常被忽略，但它的收益/成本比是本模块最高的。标题里的词往往正是用户查询里的词，而正文里可能一次都没出现。把 section_path 拼进块文本，等于给每个块免费加了一组关键词。代价是每个块多了十几个字符。

严谨说

形式化地看，这是一次上下文增强：块的可检索表示从 $\text{emb}(c)$ 变成 $\text{emb}(\text{path}(c) \oplus c)$。注意它同时改变了两件事：召回（好事，多了匹配信号）与同章节块之间的相似度（副作用——同一章的块彼此变得更像，可能挤占 top-k 的多样性）。所以路径要短：只拼最近一两级，不要拼整棵树。

主题纯度怎么测：用文档自己的结构，不要用相似度

纯度需要一个可计算的定义。一个看起来很自然的选择是「块内句子两两相似度的平均值」——但它在实践中不好用：同一小节里的两句话（「餐饮报销上限 200 元」与「交通报销需提供发票」）共享的表层词很少，相似度并不比跨小节的两句高。这个代理依赖嵌入模型的质量，而它本身正是我们要评估的东西之一。

本课用一个精确、不依赖任何模型的定义：

\[\text{cross}(C) = \frac{|\{c \in C : |\text{sections}(c)| > 1\}|}{|C|},\qquad \text{purity} = 1 - \text{cross}(C)\]

直白说

也就是「有多少比例的块跨越了文档自己的结构边界」。文档作者已经把主题边界标出来了（标题、小节），跨越它就是把两个主题混进了一个块。这个量是算术，不是测量——没有噪声，可以直接进门禁。

严谨说

它有一个明显的性质：结构感知分块的 cross 恒为 0（按构造）。所以「结构感知比固定窗口纯」这个对比在这个指标下是同义反复——这正好说明了结构感知分块的价值来源：它不是「更聪明」，而是直接把这个指标设成了最优。有意义的对比是语义分块——它不知道小节在哪，只能从相似度谷点猜；notebook 第 5 节量出它猜得有多准（本例约 1/3 的块跨了小节）。

5语义分块：在相似度的谷点切

语义分块的想法很直接：逐句算与下一句的相似度，在相似度的「谷点」切开——那里大概就是话题转换的地方。

语义分块有一个容易被忽略的问题：它产生的块大小方差很大。一段话题连续的长篇会被切成一个巨大的块，而这个块可能装不进上下文预算，也会在检索时因为稀释效应（第 7 节）而分数偏低。所以语义分块必须配一个硬上限：超过 $s_{\max}$ 就在内部再切。

一条实用的结论：在有结构的文档上（绝大多数企业文档），结构感知分块的收益已经拿到了大部分，语义分块的边际收益很小。把预算花在把模块 01 的解析做对上，回报比换分块算法高得多。

6父子块：让 precision 与完整率同时上升

前面所有讨论都假设「被检索的单元」和「被喂给模型的单元」是同一个东西。放弃这个假设，三个竞争的量里有两个可以同时改善。

父子块（small-to-big） 父块（喂给模型） 子块（进索引，被检索） ┌─────────────────────┐ ┌──────────────────┐ │ 第三章 报销制度 │──►│ 子1: 餐饮报销... │ ← 小、主题纯、 │ │ ├──────────────────┤ 向量不被稀释 │ 餐饮报销的单次上限是 │──►│ 子2: 差旅报销... │ │ 200 元。差旅报销的 │ ├──────────────────┤ │ 单次上限是 3000 元。 │──►│ 子3: 提交时限... │ │ 所有报销需在 30 天内 │ └──────────────────┘ │ 提交。 │ └─────────────────────┘ ▲ │ └──── 命中子块 → 返回父块 ──┘ 索引里存子块的向量，返回时按 parent_id 换成父块。

直白说

为什么这样能同时改善两个量？因为它把「检索粒度」和「上下文粒度」解耦了。检索要小块（纯、不被稀释、precision 高）；喂模型要大块（答案完整、有上下文）。把它们绑在一起是固定窗口方案的一个隐含约束，而这个约束是不必要的。

严谨说

代价有三个，都要清楚：① 上下文预算——返回父块意味着 token 用量按父/子的大小比放大，去重（同一个父块被多个子块命中）是必须的；② 存储——父块要另存一份（或存偏移量）；③ 归因——引用要指向命中的子块而不是父块，否则用户拿到一大段话却不知道具体依据在哪一句。notebook 第 6 节把去重和归因都实现了。

三个变体，成本递增

  • 句窗口（sentence-window）：子块 = 一句，父块 = 该句 ± k 句。最轻，不需要额外存储（父块由偏移量算出来）。
  • 段落父块：子块 = 句/小段，父块 = 所在段落或小节。最常用的一档。
  • 摘要索引：子块 = 父块的 LLM 摘要，父块 = 原文。召回质量最好，但摘要要花钱、要缓存、要跟着文档版本失效——它是一个派生资产，必须进摄取流水线并带版本，否则文档更新后摘要会静默过期（模块 05 的问题）。

7稀释效应：为什么大块的检索分数会偏低

这一节解释第 2 节「失败二」的机制，并给出一个反直觉的推论：把块做大不只是降低纯度，它还会降低召回本身。

直白说

机制：块的向量是块内所有词的聚合。相关的那一句被无关的内容按比例摊薄了。一个块里只有 1/5 的内容与查询相关时，它的相似度明显低于「只有那一句」的块——于是它可能排不进 top-k，哪怕它确实包含答案。

严谨说

在词袋型嵌入下这可以算出来。设相关句的词向量为 $r$、无关内容为 $z$（与查询近似正交），块的未归一化向量是 $r + z$，归一化后与查询 $q$ 的相似度是$$\cos = \frac{\langle r, q\rangle}{\|r + z\|} \approx \frac{\langle r, q\rangle}{\sqrt{\|r\|^2 + \|z\|^2}}$$分子不变，分母随无关内容的量增长——所以相似度大致按 $1/\sqrt{1 + \|z\|^2/\|r\|^2}$ 衰减。notebook 第 7 节把这条曲线量出来，并验证它比线性衰减慢（这也是为什么大块不是灾难，只是次优）。

稀释效应给出了一个很实用的直觉：「把 top-k 从 3 加到 10」和「把块从 200 加到 600」不是同一件事。前者只是多看几个候选；后者改变了候选的分数本身，会让真正相关的块与不相关的块之间的差距变小。

父子块正是对稀释效应的直接回应：让进索引的单元保持小（分数不被稀释），让喂给模型的单元保持大（上下文完整）。这就是上一节能同时改善两个量的物理原因。

8分块的 A/B 与门禁：四个必须一起报的数

分块参数是本课里最容易被随手改、也最容易改坏的东西。纪律：分块参数进 spec、进指纹；任何改动跑同一套离线集，报四个数。

intact答案完整落在单块内的比例（或用公式算）硬约束。低于阈值直接否决，不看其它三个数
recall@kC11 的定义，不重复改分块的主要收益应当体现在这里
n_chunks / 索引体积块数与向量总量成本；与 recall 的提升一起看性价比
context_tokens@ktop-k 拼起来的 token 数（父子块下会放大）这一项最常被漏报——父子块把 recall 提上去的同时可能让上下文翻倍（C33 的预算）
分块 A/B 报告模板 spec: chunker=structure_aware s=400 o=80 parent=section fingerprint: 7c2a91be （参数变了指纹就变——C68-01） answer_len P95 = 62 字符 （o=80 ≥ a-1 ✓） baseline(固定400/0) candidate(结构400/80) intact 0.87 1.00 ← 硬约束达标 recall@5 0.71 0.83 n_chunks 1,240 1,510 (+22%) context_tokens@5 1,980 2,310 (+17%) cross(跨小节块比例) 0.86 0.00 判读: recall +12pp，成本 +22% 索引 / +17% 上下文 → 接受 （若 intact 未达标，无论 recall 多高都否决）

放进 CI 的三项检查

  1. 确定性：o >= answer_len_p95 - 1。这一项是纯算术，误报率为零，可以直接阻断（C68 模块 04 的分级）。
  2. 确定性：块数与向量数一致，且每个块都有 doc_id/version/chunk_index/section_path。缺一项就阻断——模块 01 已经说过这些事后补不回来。
  3. 统计：recall@k 相对基线的变化超过阈值才算真的变了。阈值按 C68 模块 04 的三步走从方差推，不要拍脑袋。

最后一条纪律，也是最常被违反的：换分块方案必须重建全部索引，而且不能与旧块混在一个索引里。混着的后果是同一份内容以两种粒度存在，top-k 被同一段内容的两个版本占满（模块 01 第 5 节的近重复问题，只不过这次是自己造的）。模块 05 会给出双索引 + 原子切换的做法。

9分块的三个反模式

这三个都很常见，而且都会让前面八节的工作白做。

反模式为什么有人这么做后果正确做法
把分块参数放在代码里而不是 spec 里「就一个数字，改起来方便」指纹不变，两次评测看起来可比而实际不可比；半年后没人知道当前索引是用什么参数建的参数进 spec、进指纹（C68 模块 01）；并把 answer_len_p95 作为注释写在旁边——它是这组参数唯一的自由输入
换了分块方案但复用旧索引「重建太慢，先增量迁移」同一份内容以两种粒度共存，top-k 被自己造的近重复占满（第 6 节的问题，只不过这次是自己造的）全量重建 + 双索引原子切换（模块 05 第 5 节）；结构腐烂不能局部修
用 recall 的提升为分块改动辩护，但不报 intactrecall 是大家都认的指标intact 不达标时 recall 的提升可能来自「召回了更多碎片」——而碎片拼不出完整答案intact 是硬约束，先看它；不达标就否决，不看 recall

第三条值得展开，因为它是一个真实的指标误导：把块切小会让 recall@k 上升（同样的 k，小块能覆盖更多不同的位置），但答案完整率同时下降。如果只报 recall，「把块切小」看起来是一次改进；而端到端可能变差。这就是为什么第 8 节要求四个数一起报，且 intact 排在第一位。
