# 术语词典 · RAG 生产工程

> 每条包含：英文 / 中文 / 一句话定义 / 为什么重要 / 常见误解。
> **本课不重复 C11 的检索算法术语**（embedding / BM25 / IVF / HNSW / PQ / cross-encoder /
> MMR / RRF / precision@k / nDCG / faithfulness）——那些在 C11 的词典里。

---

## 一 · 全课骨架

| 术语 | 中文 | 定义 | 为什么重要 | 常见误解 |
|---|---|---|---|---|
| pipeline layer | 流水线分层 | 摄取/解析 → 分块 → 索引 → 检索 → 组装，五格。 | **调试必须从左往右**：解析丢的、切断的、过期的，在检索层都救不回来。 | 以为「效果不好」就是检索算法的问题。**先确认答案在语料里**。 |
| silent failure | 静默失败 | 发生时没有报错，而且离线检索指标可能完全正常的失败。 | 本课四个靶子里只有「词汇鸿沟」能被检索指标看见。 | 以为只要监控了 recall 就安全。recall 是「块与查询的相关性」的函数，与「答案能不能从块里恢复」无关。 |
| provenance | provenance（来源链） | 每个块携带的 `doc_id / version / chunk_index / start / end / section_path`。 | **没有 provenance 的块无法被删除、更新、引用核查**。模块 05 的全部运维能力都建立在它上面。 | 以为它只是为了「显示引用」。它首先是运维字段。 |
| idempotent ingestion | 幂等摄取 | 同一份文档摄取两次，索引里不出现两份块。 | 实现只需一句话：主键 `(doc_id, version, chunk_index)`，upsert 而不是 append。 | 以为「代码写对了就幂等」。**唯一可靠的验证是把同一批数据再摄取一遍并断言 `written == 0`**。 |
| answer-intact rate | 答案完整率 | 答案完整落在**某一个块**内的样本比例。 | 分块的硬约束；它有精确解析式（见下）。 | 与 recall 混淆。recall 问「块被召回了吗」，intact 问「答案在某个块里是完整的吗」。 |

## 二 · 摄取与解析（模块 01）

| 术语 | 中文 | 定义 | 为什么重要 | 常见误解 |
|---|---|---|---|---|
| structure loss | 结构损失 | 解析时丢掉表格行列对应、标题层级、阅读顺序、位置。 | **解析是唯一「下游无法补救」的环节**——投影是不可逆的。 | 以为「字都在就行」。拍平后的块里每个字都在，但关系不可恢复。 |
| row-to-sentence | 行转句 | 把表格每一行渲染成一句自然语言，**带上列名**。 | 它对「列主序读取」与「块边界落在行内」两个条件都免疫，实现只有五行。 | 以为「拍平表格必然丢结构」。行主序拍平在小表上保住了行对应，**丢的是列名**。 |
| reading order | 阅读顺序 | 把带坐标的文本块拼成文本时选的顺序。 | 双栏版面按 y 排序会交错两栏，产生**读起来完全通顺的实体-属性错配**。 | 以为解析库都处理好了。**按 y 排序在单栏文档上完全正确**，所以这个 bug 在测试文档上常常不出现。 |
| XY-cut | XY-cut | 递归地在投影直方图的最大空白处切分版面。 | 它同时给出阅读顺序与一棵版面树，而版面树正是模块 02 需要的输入。 | 对表格与图文混排会过切，需要配合 element 类型做例外。 |
| word corruption rate | 词级破坏率 | $1-(1-\varepsilon)^{L}$：字符错误率 $\varepsilon$ 下长度 $L$ 的词被破坏的概率。 | **OCR 噪声优先毁掉长词**，而专有名词、型号、法条号恰恰都是长串。 | 以为「按 token 切就没事」。破坏概率只与 $L$ 有关，与单位无关。 |
| lexical vs semantic decay | 词法 vs 语义的衰减 | 精确词匹配随查询长度**指数**衰减；字符 n-gram 相似度是渐进衰减。 | ε=3% 时两者的相对跌幅差 3 倍以上——这是混合检索在扫描件语料上的实际动机。 | 以为语义检索「更抗噪」是玄学。它抗噪是因为一个字符错误只毁掉包含它的那几个 n-gram。 |
| metadata filter cliff | 过滤断崖 | 元数据过滤是硬约束，**没有「排名靠后」这个中间状态**。 | 过滤条件写窄一格，recall 直接变 0，而检索层完全不报错。 | 以为过滤只影响精度。它决定候选集，写错就是召不回。 |
| eff@k | 有效独立文档数 | top-k 里不同「内容簇」的数量。 | 近重复必然一起进 top-k（相似度是内容的函数），**浪费的是上下文预算**。 | 以为去重是为了省存储。RAG 里它主要是为了省上下文。 |
| tombstone | 删除记录 | 记录 `doc_id` + 删除时间 + 原因，用来拒绝被删文档被全量同步重新灌回。 | 没有它，上游的全量同步会把删掉的文档当成新文档重新索引。 | 以为删了块就够了。 |

## 三 · 分块（模块 02）

| 术语 | 中文 | 定义 | 为什么重要 | 常见误解 |
|---|---|---|---|---|
| intact formula | 完整率公式 | $\text{intact}(s,o,a)=\min\!\big(1,\frac{s-a+1}{s-o}\big)$（$s \ge a$，否则 0）。 | **它让「重叠设多少」从玄学变成一次算术**，与穷举最大偏差 $6.7\times10^{-4}$（两端边界效应）。 | 以为它对所有分块方式都成立。它假设**切点与答案边界无关**——句边界分块下句子级答案恒完整。 |
| overlap saturation | 重叠饱和点 | 完整率达到 1 的条件：$o \ge a-1$。 | **只由最长答案决定，与块大小无关**（s=60…500 都成立）。 | 「重叠设块长的 10%」——这把重叠绑在了错误的量上。 |
| index cost multiplier | 索引成本倍数 | 达到完整率 1 所需的块数倍数：$s/(s-a+1)$。 | s=500,a=50 → 1.11×（直接加）；s=80,a=70 → 7.3×（**该换方案而不是继续调重叠**）。 | 以为重叠总是便宜的。当最长答案接近块长时代价会爆炸。 |
| cross | 跨结构边界率 | 跨越文档自己的小节边界的块比例；纯度 = 1 − cross。 | **它是算术不是测量**，没有噪声，可以直接进门禁。 | 用「块内句相似度」当纯度代理——那个代理依赖的正是你要评估的嵌入。 |
| structure-aware chunking | 结构感知分块 | 按 `section_path` 与 element 类型切，绝不跨表格边界。 | cross 恒为 0（按构造）；**它的价值不是「更聪明」，而是直接把这个指标设成了最优**。 | 以为它需要额外成本。它只需要模块 01 已经拿到的元数据。 |
| section_path injection | 章节路径拼接 | 把 `section_path` 拼进**进嵌入的**块文本。 | 章节名里的词往往正是查询里的词，而正文里可能一次都没出现。 | 忘了副作用：同章节的块彼此更像，会挤占 top-k 的多样性。**path 要短**。 |
| semantic chunking degeneracy | 语义分块的退化 | 分位数阈值的两个失效：相似度大量为 0 时 q 完全失效；相似度全相等时处处切。 | 它们不是实现 bug，是「分位数阈值」这个设计的性质——它假设分布连续且有区分度。 | 以为调 q 就能修。修法是**绝对阈值 + `min_size`/`max_size` 双向硬约束**。 |
| parent-child (small-to-big) | 父子块 | 小块进索引（检索粒度），大块喂模型（上下文粒度）。 | **它把检索粒度与上下文粒度解耦**，于是三个竞争的量里两个可以同时改善。 | 漏掉两个必做细节：**父块去重**与**归因指向子块**。漏掉任一个收益就没了。 |
| dilution effect | 稀释效应 | 块向量被无关内容摊薄：$\cos \propto 1/\sqrt{1+\|z\|^2/\|r\|^2}$。 | 大块不只降低纯度，**它降低召回本身**——相关块与不相关块的差距被压缩。 | 以为「把 top-k 加大」和「把块加大」是同一件事。前者多看候选，后者改变分数本身。 |

## 四 · 查询侧（模块 03）

| 术语 | 中文 | 定义 | 为什么重要 | 常见误解 |
|---|---|---|---|---|
| routing | 路由 | 先判断「这个查询该不该检索、该查哪个源」。 | **两类错误代价不对称**：漏检索 → 答不上来；误检索 → 注入噪声。目标是「漏检索为 0」。 | 「一律检索」是一个默认值而不是一个决定；它对闲聊与算术类查询是净损害。 |
| query rewriting | 查询改写 | 把用户的问法映射到文档的写法，或消解多轮指代。 | 它是词汇鸿沟的直接对策，也是流水线里唯一可运行时改的一层。 | 以为改写可以**替换**原查询。改写会改变语义（「不含增值税」→「增值税」），所以**原查询永远保留为并行的一路**。 |
| HyDE | 假设性文档嵌入 | 先让模型编一个答案，用这个假答案去检索。 | **伪答案不需要正确**——相似度 0.05 → 0.87，连数字写错也一样有效；它换的是嵌入输入的分布。 | 以为它是「让模型猜答案」。推论：不必高温度采样、不必追求事实正确。 |
| multi-query fusion | 多查询融合 | m 路改写各自检索，用 RRF 合成一个排序。 | **它降的是方差不是均值**：融合高于均值、远高于最差，但**不保证超过最好的单路**。 | 「加了融合最好情况反而降了」——这是预期行为。能可靠挑出最好那一路的话就不需要融合。 |
| pre-filter vs post-filter | 前置 / 后置过滤 | 过滤作用在候选集上 vs 作用在已算好的 top-k 上。 | 后置过滤返回空的概率是 $(1-\phi)^k$：φ=5%、k=10 → **60% 的请求返空**。 | 以为它们只是实现细节。φ=1% 时后置过滤需要 k=459，这不是「调大 k」能解决的。 |
| negation blindness | 否定失明 | 语义相反的句对在向量空间里几乎重合（本课量到 0.81–0.94）。 | **否定、数值区间、时间窗、集合成员这四类必须走结构化过滤**。 | 以为换个更强的嵌入模型能修。这是一个被反复报告的已知局限。 |
| constraint extraction | 约束抽取 | 把查询里的硬约束抽成过滤器，剩下的语义交给向量检索。 | 查询侧的第一步其实是一次结构抽取；它依赖模块 01 把对应元数据抽全。 | 正则只匹配中文——部门名可能是英文，而**约束静默失效比写错更难发现**。 |
| paraphrase sensitivity | 表述敏感度 | 同一问题的不同表述之间命中与否不一致的比例。 | 它比平均 recall 有信息量得多——直接告诉你「换个说法就不行了」的发生频率。 | 只报平均 recall。平均会被大量「本来就能答对」的样本冲淡。 |
| eval-set word overlap | 评测集词重叠 | 评测查询与目标块的词重叠率。 | 用文档原句改成的问题重叠率 0.82 vs 真实问法 0.27——**词汇鸿沟这个失败在前者上根本不存在**。 | 以为评测集只要「题目对」就行。构造方式带来的偏乐观从一开始就在里面。 |

## 五 · 迭代与图（模块 04）

| 术语 | 中文 | 定义 | 为什么重要 | 常见误解 |
|---|---|---|---|---|
| multi-hop | 多跳 | 第二跳的查询是第一跳结果的函数：$q_2 = f(q_1, \text{docs}_1)$。 | **单轮 recall 天然为 0**：查询里没有那个实体，而它要等第一跳被读到才存在。 | 以为「排序不够好」。本课的十条邮箱块与查询的相似度**完全相等**——剩下的命中率来自抽签，不随模型变强而提高。 |
| tie group | 并列组 | 分数完全相同的块集合。 | 在并列组上比较名次是没有意义的；`argsort` 的稳定排序会产生**假信号**。 | 以为向量库的返回顺序是确定的。它取决于索引结构、分片、浮点累加顺序。 |
| anchoring | 锚定 | 后续查询 = 新实体 ⊕ **原问题的目标谓词**（谓词永不改变）。 | 不锚定时查询一跳一跳走远，再也回不到目标。 | 从证据里取「字典序最小的实体」——那可能来自一个排名很靠后的块，第一跳就走偏了。 |
| stopping criterion | 停止准则 | 固定轮数 / 覆盖度 / 边际收益。 | **只改变期望跳数，不改变最坏情况**（最坏由 `MAX_HOPS` 封住）。所以它是纯粹的成本优化。 | ① 用「答案对不对」当准则——线上没有真值；② 以为边际收益准则总是有效——**新块数不等于新信息量**，并列组大时它退化成固定轮数。 |
| slot dependency | 槽位依赖 | 「问某人的邮箱」的两个槽位：谁负责 → 那个人的邮箱，**第二个依赖第一个**。 | 写成「有人名 + 有 @ 就算够」会在第一跳提前停止，而那条邮箱可能是别人的。 | 以为覆盖度判据可以逐槽位独立检查。 |
| drift guard | 漂移护栏 | 要求新查询仍然包含原问题的目标谓词。 | **要用结构性条件而不是相似度阈值**——锚定的查询本身与原问题的相似度也只有 0.25。 | 用「相似度不低于第一跳的 50%」当护栏，会把正确的锚定查询也拦掉。 |
| entity inverted index | 实体倒排 | `entity → chunk_ids` 两张表，不建完整知识图谱。 | 已能答「同时提到 X 和 Y 的块」与**共同点**类问题；答案是图算出来的，不在任何块里。 | 以为图检索必须先建知识图谱。这一档的成本只是一次实体识别。 |
| fact-recall | 事实级 recall | 必需事实集合被**完整**覆盖的题目比例（全或无）。 | 同一批结果下文档级 recall 给 1.00 / 0.50，而可答率是 0——只有 fact-recall 与端到端一致。 | 用「只标了第一跳」的评测集。标注者也是搜出来的，所以他标不到第二跳。 |
| $/success | 每次成功的成本 | 总成本 / 成功数。 | 迭代按 `$/query` 一定更贵；**按 `$/success` 是否划算取决于停止判断用不用 LLM**。 | 以为 `$/success` 自动偏向迭代。用 LLM 判断时它比单轮更贵。 |

## 六 · 索引运维（模块 05）

| 术语 | 中文 | 定义 | 为什么重要 | 常见误解 |
|---|---|---|---|---|
| index rot | 索引腐烂 | 内容腐烂（源文档变了）/ 结构腐烂（分块换了）/ 模型腐烂（嵌入换了）。 | **内容腐烂能局部修；后两种必须整体换。** | 「先写新格式，旧的以后再说」——那会产生一个既不是旧的也不是新的索引，行为无法解释。 |
| write-only update | 只写新块 | 更新时只写新版本，不删旧版本。 | 症状是**间歇性的**：取决于查询与旧块的相似度，因此不可复现。 | 以为「旧块永远不会被访问到」。除非它比新块更像查询。 |
| verifiable delete | 可验证删除 | 删除操作返回删掉的条数，调用方断言它。 | 「执行了删除但删掉 0 条」看起来是一次成功的删除；在合规语境下这是实质性的。 | 以为「从源库删了」就够了。只有索引里删掉才决定还能不能被检索到。 |
| stale fraction | 过期比例 | $1-(1-p)^{L}$：变更率 $p$、滞后 $L$。 | **先测 $p$，再定重建周期**，而不是反过来。$p$ 几乎总能从源库 `updated_at` 免费算出。 | 按「文档均匀」估——**π 与 p 正相关**（热门文档也是改得最勤的），本课量到低估 5.4 倍。 |
| reconciliation | 对账 | 比对源库与索引的 `(doc_id, content_sha)` 集合。 | 事件驱动一定会丢事件，而**丢了的那一篇会永久过期**。 | 以为事件流可靠就不需要对账。 |
| cross-space inner product | 跨空间内积 | 两个不同嵌入模型产生的向量的内积。 | **它接近 0，而它看起来完全正常**（在 [-1,1] 之间，有分布，能排序）——所以混用不报错，只安静地给出错误排序。 | 以为「不太准」。它是一个随机投影的内积，期望为 0。混版本索引里跨空间的块**连用自己的原文查都排不到第一名**。 |
| shadow index | 影子索引 | 与主索引并存的新索引，回填期间双写。 | 切换的正确性只有一个要求：**中途状态必须不可达**。 | 忘了双写；或者读取方在进程启动时缓存了 active 指针——那会让切换后不同实例返回不同结果。 |
| atomic switch | 原子切换 | 改一个指针（collection alias / 配置键）。 | **回滚必须是同一指针的反向操作**；如果回滚需要重建索引，那就等于没有回滚。 | 以为「切换」是一次数据迁移。它应该是一次配置变更。 |
| coverage check | 覆盖率校验 | 新旧索引的 docs / blocks 数必须**完全相等**。 | 确定性检查，零误报，直接阻断。 | 用「结果重叠率」当门禁——**它低既可能是变好也可能是变坏**，不能判定方向。它唯一确定的用途是等于 1.0 时说明配置没生效。 |
| derived asset staleness | 派生资产过期 | 摘要、三元组、实体倒排、缓存、评测集 gold id 没跟着文档版本失效。 | 内容会从另一条路回来；而图检索答出来的东西「不在任何块里」，**无法通过引用核查发现**。 | 最危险的一个是**评测集绑 chunk_id**——换分块后部分标注失效，看起来像一次严重的效果退化。 |
| tenant isolation | 租户隔离 | 元数据过滤（共享索引）/ 独立索引 / 混合。 | 选择的判据是「**一次漏写的距离**」：可选参数 → 一行漏写就是泄漏；必填参数 → 漏写报错；独立索引 → 要连错索引。 | 忘了**缓存键必须含 tenant**——而且这条泄漏在低流量测试里不出现（两个租户很少查同一个问题）。 |
| retrieval monitoring | 检索层监控 | 零结果率（**分租户**）/ top-1 分数分位数 / 引用率 / 新鲜度滞后。 | 四项都不需要真值；**top-1 分数分布是模型腐烂的唯一线上信号**。 | 只报中位数——模型腐烂的信号在**左尾**，中位数可能一点不动。 |
