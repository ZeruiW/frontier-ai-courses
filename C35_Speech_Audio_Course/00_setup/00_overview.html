1这门课讲什么

欢迎来到 语音与音频。这门课只追求一件事：让你把「声音」变成模型能学的东西，并亲手把这条流水线从零重建出来。

绝大多数人和语音模型的关系，止于 whisper.transcribe(audio) 和 tts.synthesize(text)。这门课要往下钻一层：一段录音在硬盘里到底长什么样？模型为什么不直接吃波形、而要先变成谱图？Whisper 怎么把成千上万帧音频对齐到几十个字符？EnCodec 怎么把一秒钟的声音压成几十个整数、还能还原？Griffin-Lim 凭什么只靠幅度谱就「猜」出相位、把谱图变回能听的声音？语音 LLM（AudioLM、Moshi）又是怎么把声音塞进「下一个 token 预测」的？

这些问题的答案不在任何 API 文档里，而在信号的物理性质与把连续声音离散化、对齐、再生成的一系列巧思之中。一段声音，本质上是一维的、随时间变化的振幅序列——又长又冗余又连续。几乎所有语音/音频建模，归根结底都在回答同一个问题——如何把这条又长又连续的波形，变成一个又短又结构化、模型能高效学习的表示（频谱、特征、或离散 token）。本课就沿着这条主线，把五个核心环节（信号与特征、ASR/CTC、神经编解码、TTS/声码器、语音 LLM）从零拆开、亲手重建。

学完你应当能回答这类问题（也是语音/多模态岗位的高频面试题）：采样率和帧长怎么定，时频分辨率为什么不能两头都要？梅尔刻度和 MFCC 在做什么、为什么至今好用？CTC 的 blank 和折叠规则解决了什么？RVQ 凭什么用几个小码本表达海量精度？Griffin-Lim 为什么能收敛？语音 LLM 的 token 从哪来？——并且能在 numpy 里把这些机制都从零实现、与朴素参考或暴力枚举对拍。

一句方法论上的话先说在前面：本课的价值不在「我们没有 GPU 也能学」这个妥协，而在它逼你只关注真正难的部分——表示与算法的正确性。网络结构、训练框架、GPU 加速，这些有了正确的表示与算法之后都是工程活，且年年在变；而「怎么把声音切帧、变频谱、做对齐、量化成 token、再重建」是不随框架过时的硬功夫。把它练扎实，换到任何工具链（torchaudio、librosa、Whisper、EnCodec）都立刻能上手。

2世界观：波形、时频、与「丢相位」

先把贯穿全课的世界观摆出来：声音是一维时间序列，但人对声音的感知是频率的、是非线性的。这条「时域↔频域、线性↔感知」的张力，决定了语音建模的几乎所有设计。

层次是什么典型表示本课模块
波形 waveform原始一维振幅序列，最完整但最冗余$x[n]$，16 kHz 下每秒 16000 个数01（采样/量化）
时频 time-frequency把波形切帧做 FFT，看频率随时间怎么变STFT / 谱图 / 梅尔谱 (时间×频率)01（STFT/梅尔/MFCC）
符号 symbolic把语音对齐成文字（识别）字符/词序列 + 对齐02（CTC/Whisper）
离散 token discrete把波形压成整数序列（量化）RVQ codes，每秒几十~几百个整数03（VQ/RVQ 编解码）
生成 generative从特征/token 造回声音梅尔→波形、token→波形04（声码器）、05（语音 LM）
相位 vs 幅度

最反直觉、也最重要的一条：人耳几乎不在乎相位，却极在乎幅度谱与频率的非线性分布。这一条同时解释了本课好几个看似无关的设计——为什么语音特征普遍丢掉相位、只留幅度（谱图、梅尔谱、MFCC 都是）；为什么频率轴要压成梅尔刻度（低频细、高频粗，贴合听感）；以及为什么生成时相位要专门「造」回来（Griffin-Lim、神经声码器的全部工作）。记住「丢相位很安全、但生成时要还回来」，模块 01 与模块 04 就连成了一条线。

把这张「波形→时频→符号/token→生成」的阶梯记在心里，本课每个模块都在打通其中一两级：模块 01 把波形变成时频特征；模块 02 把时频对齐成符号（文字）；模块 03 把波形压成离散 token；模块 04 把时频特征还原回波形；模块 05 把离散 token 纳入语言模型去生成。先有这张地图，再看每块拼图，就不会在细节里迷路。

3课程地图：从一维波形到语音 LLM

课程地图：从一维波形到语音 LLM

声音给你的：一条又长又连续的一维波形 x[n]（16 kHz = 每秒 16000 个数） 模块 01 信号与特征 采样/量化 → 分帧加窗 → STFT → 梅尔滤波器组 → MFCC │ 「把又长又连续的波形，变成 (时间×频率) 的二维特征」 ▼ 模块 02 ASR / CTC CTC blank+折叠+前向算法、贪心/beam 解码、Whisper 架构 │ 「把成百上千帧，对齐成几十个字符」 ▼ 模块 03 神经编解码 矢量量化 VQ → 残差量化 RVQ → 码本/比特率/重建权衡 │ 「把波形压成每秒几十个整数 token，还能还原」 ▼ 模块 04 TTS / 声码器 梅尔逆变换 → Griffin-Lim 相位重建 → 神经声码器 │ 「把只有幅度的谱图，造回能听的波形」 ▼ 模块 05 语音 LLM 音频 token 化 → 离散语音 LM → 文本对齐 → 流式生成 「把声音塞进『下一个 token 预测』的统一范式」

注意这不是松散的专题集合，而是一条有内在逻辑的链：模块 03 的离散 token 正是模块 05 语音 LM 的「词表」；模块 01 的梅尔谱正是模块 04 声码器要还原的目标、也是模块 02 Whisper 的输入；模块 02 的 CTC 对齐思想在流式（模块 05）里再次出现。读到最后你会发现，所谓「语音大模型」不过是把前四模块的零件（特征、对齐、token 化、生成）按「token 预测」重新组装。这也是本课刻意的编排：把前沿系统还原成几个朴素零件的拼装，让你确信「我也能理解并重建它」。

每一级台阶都对应一个可独立验证的能力：跑完模块 01 你能从零算出 STFT、梅尔谱、MFCC 并与 `librosa`/`scipy` 对拍；模块 02 你手写的 CTC 前向会与暴力枚举所有路径的概率和逐位相等；模块 03 你的 RVQ 重建误差会随码本级数单调下降；模块 04 你的 Griffin-Lim 谱收敛度会随迭代单调改善；模块 05 你的离散语音 LM 困惑度会优于均匀基线。每一步都有 assert 兜底，绝不靠「感觉对了」。

4方法论：用 numpy 从零实现并对拍

方法论：没有大模型，怎么学语音系统？

本环境不装 torch / torchaudio / whisper，全程纯 numpy + 标准库、CPU 秒级。但语音系统的难点从来不是调框架，而是表示与算法：怎么切帧做谱、怎么定义梅尔、怎么做 CTC 对齐、怎么残差量化、怎么迭代恢复相位。这些用 numpy 在 CPU 上也能精确地表达和验证。

打个比方：学作曲不一定要有交响乐团。语音系统的「乐理」是信号怎么变成特征、序列怎么对齐、连续怎么离散、谱图怎么还原；这些都是和框架无关的算法结构。Whisper 内部那步 log-mel，和你在 numpy 里写的梅尔滤波器组是同一个数学操作；EnCodec 的 RVQ，和你写的「逐级量化残差」是同一套递推。我们用 numpy 把这些操作显式地、可观察地写出来——结构与真实系统一模一样，只是规模小、能逐步打印、能 assert。

直白说

我们把语音系统的每个机制翻译成 numpy 里看得见摸得着的东西：分帧就是按 hop 切片再 stack，STFT 就是对每帧 `np.fft.rfft`，梅尔就是一个 (滤波器×频点) 矩阵乘，CTC 前向就是一张动态规划表，RVQ 就是几轮「找最近码字、减掉、再量化残差」，Griffin-Lim 就是 iSTFT↔STFT 来回迭代。你写的是算法结构，不是性能。

严谨说

关键纪律是对拍（differential testing）：每个机制都和一个绝对可信的参考比对——DFT 对拍 np.fft、梅尔/DCT 对拍 scipy（缺失则跳过）、CTC 前向对拍暴力枚举所有对齐路径的概率和、RVQ 验证重建误差逐级单调下降、Griffin-Lim 验证谱收敛度逐迭代改善。结构正确 → 数值与参考一致；数值一致 → 你的实现可以原样迁移到 torchaudio/librosa/Whisper。

语音系统机制本课的 numpy 实现对应真实工具

为什么把对拍提到方法论的高度？因为语音代码的 bug 极其阴险：帧错位、窗能量没归一、梅尔频点取整偏差、CTC 递推漏了某条转移、log 空间溢出——往往不报错，只是悄悄给出看起来差不多但其实错了的谱图或概率。在真实系统里这种 bug 要靠听感大海捞针；而在 numpy 里我们有一个绝对可信的参考（np.fft、暴力枚举、单调性），任何偏差都会被 assert 当场抓住。本课每个机制都先有参考、再写实现、立刻对拍——这套「先有 ground truth，再实现」的纪律，正是真实语音研究（与 librosa/torch 对拍）的核心工作流。

务必清楚本课不教什么：不训练真实的大模型、不追求 SOTA 的 WER 或音质、不写 GPU/并行代码。这些在你有了正确的表示与算法之后，是第二步（references 里的 Whisper、EnCodec、HiFi-GAN、Moshi 接手）。本课负责把第一步——表示、对齐、量化、重建的正确性夯死；这一步搞定，第二步才有意义。

5环境与运行

环境与运行

环境极简：只需 numpy（画谱图/波形可选 matplotlib；个别真实数据对拍可选 scipy，缺失自动跳过/回退合成）。全课 CPU 秒级运行，无需 GPU、torch、torchaudio、whisper、librosa。

conda create -n speech python=3.11 -y && conda activate speech
pip install numpy            # 必需
pip install scipy matplotlib # 可选：scipy 用于个别对拍，matplotlib 画谱图/波形
jupyter lab

每个模块配一个 notebook，结构统一：先用 numpy 把机制从零实现并对拍（5–6 个 worked 小节，每节都跑出可打印的验证与 assert），再做 3–4 道带 assert 判分的 ✏️ 练习（先给骨架，自己填，再对照 📖 参考答案），最后一个真实数据胶囊（用真实工程数值——真实采样率、真实梅尔公式、真实编解码配置——把纸面知识接到现实，联网/scipy 缺失时回退合成）。

建议的学习节奏：先读完整章 HTML 建立直觉与数学框架，再打开 notebook 亲手实现。读和做缺一不可——只读会觉得「好像懂了」，真正动手写分帧切片、调 FFT 维度、让 CTC 前向对上暴力枚举、让 Griffin-Lim 收敛时，才会发现魔鬼藏在哪些细节里（帧对齐、窗归一、取整、log 稳定、相位初始化）。这门课的深度正是为「动手」服务的。

配套先读：Oppenheim《Discrete-Time Signal Processing》当 DSP 字典；Graves 2006（CTC）、Radford 2022（Whisper）、van den Oord 2017（VQ-VAE）、Défossez 2022（EnCodec）、Borsos 2022（AudioLM）是五个模块各自的奠基论文。完整清单见 references.md。

✅ 学完整门课，你应该能：
  1. 解释采样定理与时频分辨率权衡，从零算出 STFT、梅尔谱、MFCC 并与参考对拍；
  2. 讲清 CTC 的 blank、折叠规则与前向算法，并手写出与暴力枚举一致的前向概率 + 贪心/beam 解码；
  3. 实现矢量量化与残差矢量量化，解释码本大小、级数、比特率、重建质量、码本利用率之间的权衡；
  4. 从零实现 Griffin-Lim，说清相位重建为何可行、为何收敛，并量化其谱收敛度；
  5. 把音频 token 化并训练一个玩具离散语音 LM，解释 AudioLM/VALL-E/Moshi 如何用「token 预测」统一语音任务；
  6. 把上述 numpy 实现映射到 torchaudio / Whisper / EnCodec 的真实接口，知道下一步怎么用真框架。
