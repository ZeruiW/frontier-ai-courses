1把声音当成一种语言

到这里，前四个模块已经备齐了所有零件：模块 01 把波形变成特征，模块 02 把语音对齐成文字，模块 03 把波形压成离散 token，模块 04 把特征/token 还原成波形。本模块把它们组装成一个统一范式——speech / audio language model（语音/音频语言模型）：把声音当成一种『语言』，用『预测下一个 token』来理解和生成它。

这是 2022 年后语音 AI 最重要的范式转移。它的核心洞察朴素到惊人：既然模块 03 已经能把音频变成离散整数 token 序列，那就可以原封不动地套用文本大模型的全套机器——同样的 Transformer、同样的『下一个 token 预测』、同样的交叉熵、采样、KV-cache。AudioLM、VALL-E、MusicLM、Moshi 全都建立在这一个想法上。语音建模因此与 NLP彻底打通：识别是『音频 token → 文本 token』，合成是『文本 token → 音频 token』，对话是『听到的 token → 说出的 token』——都是序列到序列的 token 预测。

本模块讲清这套范式的四个要件：audio tokenization（音频 token 化，承接模块 03）、离散语音 LM（在 token 上做自回归，本课用玩具 n-gram 实现）、文本与音频对齐/交错（多模态怎么塞进一个序列）、streaming / online generation（流式生成，实时对话的硬要求）。notebook 会从零把音频 token 化、训一个玩具离散语音 LM（对拍困惑度优于均匀基线）、做流式分块。

一句话抓住本模块：把声音变成整数序列（模块 03），就能像写文章一样『写声音』——用语言模型预测下一个音频 token，再用声码器/解码器（模块 04）变回波形。识别、合成、对话，全都统一成『预测下一个 token』。这是把整门课的零件拼成一个系统的最后一步。

2音频 token 化：语音 LM 的词表

音频 token 化：语音 LM 的『词表』从哪来

文本 LM 的词表是天然离散的（字、词、subword）；音频是连续的，所以语音 LM 的第一步是 audio tokenization——把波形变成 discrete token（离散整数序列）。这正是模块 03 的输出：用神经编解码（EnCodec/SoundStream）的 RVQ，把每帧音频量化成 $N$ 个码本下标。

但这里有个关键的二分，是理解所有语音 LM 架构的钥匙——音频 token 有两种，刻画的东西不同：

token 类型来自刻画什么特点
semantic token 语义自监督模型(HuBERT/w2v-BERT)量化语言内容、语义、长程结构紧凑、序列短、丢声学细节
acoustic token 声学神经编解码(EnCodec)RVQ音色、声学环境、波形细节保真、序列长、缺语义结构

为什么要两种？因为单一 token 顾此失彼：声学 token 保真但缺乏语义结构（直接拿它做语言建模，模型学不到长程的『说什么』，只会学到局部的『听起来像』）；语义 token 有内容但丢了音色细节（还原不出具体是谁的声音）。AudioLM 的核心设计正是分而治之：先用语义 token 建模长程结构（说什么），再用声学 token 补全细节（怎么发声）——『语义→声学』两段式生成，既连贯又高保真。

直白说

打个比方：语义 token 像剧本（说什么内容、什么逻辑），声学 token 像演员的具体演绎（音色、语气、口音）。只有剧本，声音是干巴巴的机器音；只有演绎细节而无剧本，声音是连贯的胡言乱语。AudioLM 先写剧本（语义）、再配演绎（声学），两者都要。

严谨说

形式上：语义 token $s_{1:T}$ 捕捉 $p(\text{内容})$ 的长程依赖；声学 token $a_{1:T}^{(1:N)}$（RVQ 的 $N$ 级）捕捉细节。AudioLM 分阶段建模 $p(s)\to p(a^{(1)}\mid s)\to p(a^{(2:N)}\mid s,a^{(1)})$。这把一个『又长又要保真又要连贯』的难题，分解成几个各自可控的子问题——又一次『分解 + 分层』的工程智慧，呼应模块 03 的 RVQ 分级。

3离散语音 LM：下一个 token 预测

离散语音 LM：在 token 上做下一个预测

有了离散 token，语言建模就完全是文本 LM 那一套。给定 token 序列 $u_{1:T}$，自回归地分解联合概率、用交叉熵训练：

真实系统里 $p(u_t\mid u_{n-gram language model（n 元模型）替代——用前 $n-1$ 个 token 的频次估计下一个 token 的概率。它虽简单，却能让你亲手把『音频建模』和『文本 LM』彻底打通：同样的计数、同样的条件概率、同样的困惑度、同样的采样生成，只是 token 来自音频而非文本。

怎么知道语音 LM『学到了东西』？看 困惑度（perplexity） $=\exp(\mathcal{L})$——它衡量模型平均在多少个 token 里『纠结』。一个均匀随机基线的困惑度等于词表大小 $K$（完全没学到结构）；只要模型学到了 token 间的任何规律（音频 token 远非均匀——相邻帧高度相关、有重复模式），困惑度就会显著低于 $K$。这正是 notebook 要对拍的不变量：玩具语音 LM 的困惑度 < 均匀基线，证明它确实捕捉到了音频 token 的结构。

worked 微例（困惑度到底在数什么）：设词表 $K=4$。均匀基线对每个 token 都给 $1/4$ 概率，交叉熵 $\mathcal{L}=-\log(1/4)=\log 4\approx1.386$，困惑度 $=\exp(1.386)=4=K$——『平均在 4 个里瞎猜』。现在假设音频 token 高度重复、有可学的结构。一个学到这点的模型在留出序列上，比方说70% 的步把概率押对（真实 token 拿到 $0.7$）、30% 的步押偏（真实 token 只有 $0.1$）。那么 $\mathcal{L}=-[0.7\log0.7+0.3\log0.1]\approx-[0.7\times(-0.357)+0.3\times(-2.303)]\approx0.94$，困惑度 $\approx\exp(0.94)\approx2.6$。$2.6<4$——『有效只在约 2.6 个里纠结』，比瞎猜的 4 个少了。这就是 notebook 里 perplexity < K 那个 assert 的全部含义：困惑度从 $K$ 往下掉多少，量化了模型从音频 token 的冗余结构里榨出了多少可预测性。把 $K$ 换成真实编解码的 $1024$，道理一字不差。

波形 ──(模块03)──► 音频 token 序列 u_{1:T} (整数, 词表 K) │ │ 训练: 数 n-gram 频次, 估 p(u_t | u_{t-n+1..t-1}) ▼ 离散语音 LM p(下一个token | 历史) │ ├─ 评估: 困惑度 exp(交叉熵) < K (均匀基线) ──► 学到了结构 ★ │ └─ 生成: 自回归采样 token ──(模块04解码器)──► 续写的波形

用 n-gram 而非真 Transformer，是刻意的教学选择，值得说清它教到了什么、又简化了什么。它如实保留的，是语音 LM 的全部概念骨架：自回归分解、条件概率、交叉熵、困惑度、采样生成——这些在 n-gram 和 Transformer 里形式完全一致，只是后者用神经网络而非计数来估计 $p(u_t\mid u_{简化掉的，是『如何从有限数据泛化到长程依赖』：n-gram 只看固定的前 $n-1$ 个 token、且靠硬计数（数据稀疏时退化），而 Transformer 用注意力看全部历史、用参数共享泛化。所以本课的玩具 LM 让你亲手验证范式可行（音频 token 能建模、困惑度能下降），而把『规模化的泛化能力』留给真实的 Transformer 语音 LM。这正是『理解机制』与『追求性能』的恰当分工——先确信原理，再谈放大。

困惑度是语音 LM 的『体温计』：均匀瞎猜 = K，学到结构 < K，学得越好越低。本课玩具 n-gram 的意义不在性能，而在让你确信——音频 token 序列和文本 token 序列没有本质区别，文本 LM 的一切（n-gram、Transformer、困惑度、采样）原样适用。这就是『语音 LLM』之所以可能的全部秘密。

4文本与音频对齐：塞进一个序列

文本与音频对齐：多模态塞进一个序列

语音 LM 常要同时处理文本和音频（如 ASR=音频→文本、TTS=文本→音频、语音对话=两者交替）。怎么让一个自回归模型同时建模两种 token？关键技巧是 interleaving / alignment（交错/对齐）——把不同模态/不同流的 token 按某种规则排进同一个序列，模型照常做下一个 token 预测。

几种典型排法：

  • 拼接（concatenation）：文本 token 全放前面、音频 token 全放后面（VALL-E 的 TTS：先文本提示，再生成音频 token）。简单，但跨模态的时间对齐弱。
  • 交错（interleaving）：文本与音频 token 按时间细粒度交替（一段文本、对应一段音频、再一段……）。对齐强，适合流式与对话。
  • 多流（multi-stream）：RVQ 的多级 token、或『语义流 + 声学流 + 文本流』并行，在每个时间步同时预测多个流（Moshi 的做法）。能建模全双工（同时听说）。

直白说

把多模态塞进一个序列，就像把双语字幕排进一行字：可以『先全英文再全中文』（拼接），可以『一句英一句中交替』（交错），也可以『上下两行同时滚动』（多流）。排法决定了模型能多紧地把两种信息对齐——对话要实时呼应，就得交错或多流。

严谨说

这又是模块 02『对齐』主题的延续：那里是音频帧↔字符的对齐（CTC/注意力），这里是文本 token↔音频 token 的对齐（交错/多流）。Moshi 用多流 + 时间对齐让文本与多级音频 token 在每个时间步并行预测，从而实现 full-duplex（全双工，能同时听和说）——这是把『对齐』推到极致的工程成果。本质上，从 CTC 到 Moshi，都是在回答同一个问题：不同长度/模态的序列，如何在一个模型里协同。

VALL-E（Wang 2023）用拼接做零样本 TTS（3 秒音色克隆）；AudioLM（Borsos 2022）用语义/声学分层；Moshi（Défossez 2024）用多流实现全双工对话。均见 references.md。它们的差异主要在token 怎么排、几个流、谁条件谁——核心都是『离散 token + 下一个预测』。

5流式生成：实时对话的硬约束

流式生成：实时对话的硬约束

语音对话和 ASR 有一个文本任务没有的硬约束：延迟。人类对话的自然节奏要求端到端 latency 低于约 200–300 ms，否则就有明显的『卡顿感』。这逼出了 streaming / online generation（流式/在线生成）——不能等整段输入到齐再处理，必须边收边算边出。

流式的核心是 chunk / lookahead（块/前瞻）：把音频切成小 块（chunk），来一块处理一块；为提精度可允许多看少量未来帧（前瞻）。这带来一个根本权衡：

块大小 / 前瞻延迟上下文 / 精度适用
小块、无前瞻低上下文少、精度略降实时对话、同传
大块、有前瞻高上下文多、精度高离线转写、字幕
整段（非流式）最高（等全部）最高批处理

流式对模型结构提出要求：注意力必须是因果的或受限窗口的（不能看未来，或只看有限未来），编解码必须是因果卷积（模块 03 的 EnCodec 有流式版，Mimi 专为低延迟设计）。回忆模块 02：CTC 天然流式（逐帧出），而 Whisper 式自回归 seq2seq 流式更难（要等前一个 token）——这个权衡在语音 LM 里再次出现，且更尖锐（既要听又要说）。Moshi/Mimi 把帧率压到很低（如 12.5 Hz）、用流式编解码 + 多流 LM，做到了低延迟的全双工对话。

再把延迟拆开算一笔账，体会为何低帧率 token 对实时如此关键。端到端延迟大致由三块构成：算法延迟（攒够一个 chunk + 前瞻才能出第一个结果）+ 计算延迟（模型前向耗时）+ 声码器延迟（token → 波形）。其中算法延迟正比于 chunk 时长——而一个 chunk 含多少 token 又取决于帧率。EnCodec 的 75 Hz 意味着每个 token 只覆盖 13 ms，要攒一个像样的 chunk 得不少 token；Mimi 的 12.5 Hz 让每个 token 覆盖 80 ms，更少的 token 就能构成一个有意义的处理单元、且自回归步数大减（同样时长的音频，token 数少 6 倍 → 模型要预测的步数少 6 倍）。这就是为什么 Moshi 不惜在编解码上下功夫把帧率压到 12.5 Hz：低帧率 token 同时缩短了算法延迟和自回归长度，是实时全双工的前提。把这笔账记住，你就懂了『为什么实时语音 LM 都在卷低帧率 tokenizer』。

本课 notebook 会模拟流式处理：把一个 token 序列分块、逐块用语音 LM 预测、维护跨块的状态（历史 token），验证分块流式的结果与一次性处理整段一致（因为 n-gram 只依赖固定长度历史，分块只要保留足够的边界 token 即可无损）。这把『流式』这个抽象概念，变成一个你能 assert 的等价性命题。

6拼起来：端到端语音系统

把整门课拼起来：一个端到端语音系统

本模块是全课的收束。退一步看，五个模块拼成的正是一个完整的现代语音系统：

┌─────────────── 统一范式: 下一个 token 预测 ───────────────┐ 输入语音 ──(01 特征/03 编码)──► 音频 token ──┐ 文本提示 ──(tokenize)──────────► 文本 token ──┤ ├─► 语音 LM (05) ──► 输出 token (02 的对齐思想: 交错/多流)──┘ │ ▼ 输出 token ──(03 解码/04 声码器)──► 输出波形 识别 = 音频token→文本token 合成 = 文本token→音频token 对话 = 听token→说token

这张图里每个箭头都是前面某个模块：特征前端（01）、CTC/对齐（02）、token 化（03）、声码器/解码器（04）、token 预测（05）。所谓『语音大模型』没有一个全新的概念——它是把前四模块的零件，按『离散 token + 下一个预测』这一条主线重新组装。这也是本课从第一模块就埋下的伏笔：每一步都在为『把声音变成模型能学的 token』做准备，本模块则把这些 token 喂进语言模型，闭环。

一个值得记住的历史视角：语音 AI 经历了从专用流水线（HMM-GMM、信号处理专家手工设计每一环）到端到端深度模型（CTC/seq2seq 各管一个任务）再到统一的 token 语言模型（一个模型、一种范式、多个任务）的演进。这与 NLP 从专用模型到 GPT 式通用模型的轨迹惊人地平行——而把它们统一起来的，正是『离散 token + 自回归预测』这个朴素而强大的想法。你学完这门课，就站在了这个统一范式的内部。

最后留一个批判性的思考，免得把『token 语言模型』当成万能解。这套范式有它的代价与争议：离散化是有损的（量化误差不可逆，音质天花板受 tokenizer 限制）；自回归逐 token 生成在长音频上慢且会累积误差；声学 token 的多级（RVQ）让『一步一个 token』变成『一步多个流』，建模复杂度陡增。正因如此，连续路线（扩散/流模型直接生成波形或连续 latent，绕开离散化损失）在音质上常有优势，是与 token-LM 并行的活跃方向。两条路线各有胜场：要和文本 LLM 统一、要可组合可编辑，离散 token 更顺；要极致音质、不在乎 LLM 范式，连续生成可能更好。把这层张力放在心里——你学到的不是『token LM 是终极答案』，而是『离散化让音频接入了语言模型，但这是一个有代价的选择，边界仍在演进』。带着这种判断力去读前沿论文，比记住任何单一结论都重要。

7从零实现的路线图

从零实现的路线图

notebook 会把本模块拆成可验证的几块，对拍可信参考与不变量：

波形 (合成) │ ├─ tokenize_audio(): 特征 + VQ → 整数 token 序列 ──对拍── token 在 [0,K) │ ├─ n-gram 语音 LM: 计数 → p(下一个|历史) ──对拍── 概率归一 │ ├─ 困惑度 < 词表大小 K ──验证── 学到了 token 结构 ★ │ ├─ 流式分块: 分块预测 == 整段预测 ──验证── 流式无损 ★ │ └─ 自回归采样: 用 LM 生成新 token 序列 ──对拍── 生成的 token 合法

两个关键验证：(1) 困惑度 < K——把音频 token 化、训 n-gram LM、在留出序列上算困惑度，它必须显著低于均匀基线 $K$（证明 LM 捕捉到了音频 token 的结构，而非瞎猜）；(2) 流式 == 整段——把序列分块、逐块预测并维护历史，结果与一次性处理整段逐位相等（证明你的流式实现无损、状态维护正确）。这两个一过，你就完整理解了语音 LM 的训练（计数/困惑度）与部署（流式）。

这套『玩具实现 + 不变量验证』再次体现本课方法论：我们不追求 SOTA 的语音 LM（那要海量数据与算力），而是用最小可跑的 n-gram，把『音频 = 可建模的 token 序列』『困惑度衡量学到多少』『流式 = 分块等价』这几个不随规模变化的核心概念夯死。理解了它们，你再看 AudioLM/Moshi 的论文，看到的就不是黑魔法，而是同一套思想在 Transformer + 海量数据上的放大。

最后点明流式无损那个等价性测试的深意，它不只是个 numpy 练习。流式系统最隐蔽的 bug，是跨块的状态维护出错——边界处该带的历史 token 漏了、或带多了、或顺序错了，导致块边界附近的预测与整段处理不一致。在真实流式 ASR/语音对话里，这种 bug 表现为『每隔一个 chunk 就吐错一个字』，极难定位（因为大部分输出是对的）。本课把它变成一个干净的命题：流式分块预测 == 整段预测（逐位相等）。对 n-gram，只要每块带足前 $n-1$ 个边界 token 就能严格无损；对 Transformer，对应的是『KV-cache 跨块正确传递』。你在玩具上验证过这个等价性，就建立了检验任何流式实现正确性的标准动作——拿流式输出和整段输出对拍，一票否决。这正是把『从零 + 对拍』方法论用到部署正确性上的范例。

8研究前沿与开放问题

研究前沿与开放问题

  • 语义/声学的统一 tokenizer：分层（语义→声学）有效但复杂。能否用单一 tokenizer 同时编码语义与声学（如 Mimi）、让语音 LM 更简洁，是当前热点。
  • 低延迟全双工：Moshi 把延迟压到对话级别，但全双工（同时听说、自然插话）的建模仍不成熟。多流对齐、流式编解码、超低帧率 token 是关键方向。
  • 文本-语音的深度融合：是把语音 token 加进文本 LLM 的词表（统一一个模型），还是分开建模再对齐？语音-文本基础模型（speech-text foundation model）的最佳架构仍在探索。
  • 音频 token 的『可懂性』：文本 token 人类可读，音频 token 是黑盒整数。如何让音频 token 更可解释、可编辑、可控制（指定音色/情感），关系到可用性与安全。
  • 评测与安全：语音生成的评测（自然度、可懂度、说话人相似度）缺统一标准；而零样本音色克隆（VALL-E）带来深度伪造（deepfake）风险——水印、检测、滥用防范是必须面对的（与 C04/C05 的安全主题相连）。
