# 视觉-语言-动作模型（VLA）与感知接口

这门课回答一个非常具体的工程问题：

> **一个交通标志检测器（TSR）辛辛苦苦输出的类别、距离、置信度、跟踪 ID，
> 到底应该以什么形式、在哪一层、带着多少不确定性，交给下游的 VLA？
> 交错了会发生什么？**

这条问题不是学术兴趣。它是 XPENG「TSR 2D Detection」岗位 JD 里那条最独特、
也最容易被求职者跳过的职责：

> *Improve VLA models to effectively consume TSR outputs and support
> traffic-sign-aware instruction following through VLA prompts.*

绝大多数人准备这个岗位时，会把力气全花在检测器上（YOLO / RT-DETR / 小目标 / 长尾），
然后在被问到「你的检测结果怎么用」的时候，只能答一句「输出给下游」。
**这门课就是补这一段。** 模块 03 是全课的落点，其余五个模块都是为它铺路或收尾。

| 模块 | 主题 | 目录 |
|---|---|---|
| 00 | 课程总览与环境 | `00_setup/` |
| 01 | 从 VLM 到 VLA | `01_vlm_to_vla/` |
| 02 | 动作表示与输出头设计 | `02_action_repr/` |
| **03** | **TSR 输出如何进入 VLA：接口设计**（全课落点） | `03_perception_interface/` |
| 04 | 交通规则的指令跟随与约束化 | `04_instruction/` |
| 05 | VLA 的评测与上车 | `05_eval_deploy/` |

## 一句话说清这门课的结构

一个 VLA 系统 = **输入接口** → 模型 → **输出接口** → 约束与兜底 → 评测闭环。

- 模块 00/01 划定**这个模型是什么、不是什么**；
- 模块 **03** 讲**输入接口**（感知怎么进来）—— 这是 JD 那条职责；
- 模块 02 讲**输出接口**（动作怎么出去）；
- 模块 04 讲动作出去之后**怎么被约束成合法、可执行的东西**；
- 模块 05 讲**怎么证明它真的能用、以及怎么上车**。

## 三条贯穿全课的主线

1. **接口即设计 · The Interface Is the Design**
   模型能力再强，也只能消费你喂给它的东西。
   一份不带置信度、不带坐标系说明、不带生命周期的检测结果，
   会强迫下游把所有输出当作确定事实——**这是感知-决策接口最常见、也最贵的设计错误**。
   本课把 TSR → VLA 的 schema 拆到字段级别，每个字段都要能回答
   「下游少了它会**具体**做错什么」。

2. **不确定性必须一路传下去 · Uncertainty Must Propagate**
   传置信度只是第一步。**未标定的置信度比没有置信度更危险**：
   当模型说 0.9 而实际正确率只有 0.6 时，下游所有基于阈值的保守策略都被系统性绕过。
   所以接口设计必须同时回答：置信度怎么算、怎么标定、下游怎么用、
   以及在低置信时系统的默认行为是什么。

3. **能力边界要主动说清 · Be Honest About the Boundary**
   VLA 解决的是**长尾语义**（「前方施工，借对向车道通行」这类规则写不完的场景）。
   它**不会**提升你的检测召回，**不会**让 8 像素的标志变清楚，
   **不会**天然保证输出的轨迹物理可行，也**不会**自己变得可验证。
   本课在每个模块都会回到这条边界。
   **在面试里能主动、准确地说出「VLA 做不到什么」，比多背两个模型名字有用得多**——
   它证明你区分得开「技术趋势」与「工程现实」。

## 学习路径

- **只想补上 JD 那条职责**（约 2 小时）：00 → 03 → 04。
  读完你能画出 TSR → VLA 的完整接口图，说清三种融合层次的取舍，
  并给出一份带置信度与生命周期的 schema。这是最短路径。
- **想把 VLA 讲成一个连贯的技术故事**（约 4 小时）：00 → 01 → 02 → 03。
  从 VLM 的三段式讲到动作表示，再落到接口——这条线适合回答
  「说说你对 VLA 的理解」这类开放题。
- **面向落地与评测**（约 3 小时）：00 → 04 → 05。
  约束化、安全兜底、开环/闭环评测、蒸馏上车。
  这条线里的「开环指标失效」是**最容易在面试里显出水平**的一段。
- **完整路径**：00 → 01 → 02 → 03 → 04 → 05。
  后面的模块会反复引用前面的结论（03 的 schema 在 04 里被翻译成约束，
  在 05 里被用作评测的输入）。

每个模块的 notebook 都可以独立运行，纯 numpy、CPU，几秒到几十秒出结果。
练习都带 `assert` 判分，做错了会立刻告诉你。

## 环境

见 `requirements.txt`。**纯 numpy + matplotlib，CPU 可跑，不需要 GPU，
也不需要装 torch / transformers / CARLA / nuScenes devkit。**

本课复现的是这些系统的**机制与账本**：

- 动作离散化的量化误差（闭式上界 + 实测）
- 多模态动作分布下回归的「平均失效」（可构造、可度量）
- 三种融合层次的 token 成本与信息保留率
- 置信度标定曲线（可靠性图 / ECE）与下游动作错误率的关系
- 约束的作用域-生命周期状态机（含冲突消解）
- 开环误差与闭环误差的增长率差异（误差累积模拟）

这些恰恰是可迁移的那部分——模型会换代，账不会。
每个模块末尾有一个 🧪 **真实工程胶囊**，把当天的结论翻译成可原样复制的
prompt 模板、schema 定义（JSON / dataclass）与评测脚本片段。

## ⚠️ 关于本课里的模型与数字

VLA 是本批课程里**变化最快**的一门。讲解中引用的模型（RT-2 / OpenVLA / π0 /
DriveVLM / EMMA / LINGO 等）与数字来自各自论文与公开材料，**用于说明设计取舍与量级，
不是复现结果，也不代表任何公司的当前量产方案**。
量产系统的具体架构通常不公开，本课讲的是**可以从公开信息推断出的工程约束**
（频率、延迟、算力、安全要求），以及这些约束如何唯一地决定了一部分设计。

**在面试里谈 VLA 时，请把「论文里的做法」「公开报道的路线」「你自己的推断」三者分开说。**
把推断说成事实是最容易翻车的地方；而清晰地标注哪一部分是自己的推理，反而是加分项。
