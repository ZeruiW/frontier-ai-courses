1VLM 回顾：为什么这个结构「顺手」就能接上动作

VLM（Vision-Language Model）的三段式结构在 C00 讲透了，这里只回顾与「接动作」直接相关的那一点。

直白说

为什么说这个结构「顺手」就能接动作？因为它已经干过一次同样的事了：视觉本来也不是语言，是连接器硬把它投成了「看起来像 token 的向量」塞进序列的。既然图像能这么进来，动作为什么不能这么出去？RT-2 的全部创意就是把这个念头执行到底。

严谨说

更精确地说，VLM 建立了一个模态无关的序列接口：输入侧任何模态只要经过一个投影器就能进入同一个 token 序列；输出侧任何东西只要能被编码成词表里的符号，就能被 LM head 生成。这两件事合起来意味着「多模态」不是三个模型拼一起，而是一个序列模型加若干个适配器。VLA 因此不是新架构，是在这个既有接口上多插了一个模态——理解这点，后面所有设计选择都变得可推导。

VLA 看不见 3 像素的限速牌

一个必须现在就说清、且与 TSR 岗位直接相关的硬伤：VLM 的视觉塔分辨率太低，它自己看不见小交通标志。

算一笔账：1920×1080、60° 水平 FOV 的前视相机，焦距约 f = 960 / tan(30°) ≈ 1662 px。60 m 外一块 0.6 m 的限速牌成像 1662 × 0.6 / 60 ≈ 16.6 px。而 VLM 的视觉塔通常吃 384×384（甚至 224×224）的整图——缩放比 0.2——这块牌子变成 3.3 px。ViT 的 patch 是 14 px，它连一个 patch 的四分之一都占不满。

所以「让 VLA 自己去看标志」在物理上就不成立，必须有一个独立的、高分辨率的 TSR 模块把结果检出来再喂进去。这不是工程妥协，这是这门课存在的物理理由——也是 JD 里那条职责的根。

2RT-2 的那一步：把控制问题变成语言问题

RT-2（Robotic Transformer 2, 2023）做的事情，用一句话说完：把连续动作离散化成整数，把整数映射到词表里已有的 token，于是动作就成了「话」，LM head 一个参数都不用改。

具体怎么做

机器人动作是 7 个连续量 + 1 个终止位：末端位移 (Δx, Δy, Δz)、旋转 (Δroll, Δpitch, Δyaw)、夹爪开合、以及 terminate 标志。每一维各自均匀分成 256 个 bin：

\[b(a)=\operatorname{clip}\!\left(\left\lfloor \frac{a-a_{\min}}{a_{\max}-a_{\min}}\cdot B \right\rfloor,\,0,\,B-1\right),\qquad \hat a(b)=a_{\min}+\frac{b+\tfrac12}{B}\,(a_{\max}-a_{\min})\]

重建误差是有下界的，而且这个下界可以直接算出来——这是 notebook 第 2 节要验证的第一件事：

\[\Delta=\frac{a_{\max}-a_{\min}}{B},\qquad |\varepsilon|_{\max}=\frac{\Delta}{2},\qquad \varepsilon_{\mathrm{RMS}}=\frac{\Delta}{\sqrt{12}}\approx 0.289\,\Delta\]

然后把 b ∈ [0, 255] 映射到词表里的 256 个 token id。于是一次动作输出就是一句 8 个 token 的「话」，训练目标与语言建模完全相同（对这 8 个位置算交叉熵）。

直白说

「把控制问题变成语言问题」的收益是继承：模型不必从零学「杯子是什么」「哪个是垃圾桶」，这些在预训练里已经有了；机器人数据只需要教它「怎么把已有的语义映射到动作」。这就是为什么 RT-2 能对训练里没出现过的物体和指令做出合理反应，而 RT-1 不能。面试里这是 RT-2 唯一必须记住的点——它的贡献是这个转换本身，不是效果数字。

严谨说

代价有三条，且都不是实现问题而是范式自带的。① 分箱误差有硬下界：ε_RMS = Δ/√12，加 bin 只能线性改善而 token 预算是有限的。② token 之间没有序关系：bin 128 与 bin 129 对应的两个词表 token，在 embedding 空间里并不比 bin 128 与 bin 5 更近——动作的连续性必须完全从数据里重新学出来，这是把动作塞进离散词表最深的代价。③ 自回归解码是串行的：D × K 个 token 就是 D × K 次前向，动作维度或时间步一多，延迟直接线性爆炸。后面 π0 换掉动作头，三条全是冲着这里来的。

把这一节压成一句可迁移的心法：只要你能把一个问题的输出编码成词表里的符号，你就能白嫖整个语言模型预训练。这条心法在 RT-2 之外同样成立——Decision Transformer 把 RL 变成序列建模、EMMA 把 3D 检测框写成文本、Pix2Seq 把检测框写成 token，全是同一招。反过来，这也划出了它的适用边界：当输出的连续性、精度或维度让「编码成符号」变得昂贵时，这招就该停了——这正是 §4 的内容。

3OpenVLA：唯一能看清全部实现细节的那一个

RT-2 是闭源的，论文里很多关键细节没写。OpenVLA（2024，7B）是目前唯一一个把训练配方、数据处理、tokenizer 处理全部公开的 VLA——所以它的工程细节比它的效果数字更值得读。

设计决策怎么做的为什么（这才是要点）
双视觉塔SigLIP + DINOv2 的特征在通道维拼接后送连接器SigLIP 给语言对齐的语义，DINOv2 给空间/几何。只用其一在需要精确定位的任务上明显更差
LLM 主干Llama-2 7B（Prismatic VLM 配方）7B 是「有常识」与「单卡能微调」的折中点
动作 bin每维 256 个 bin，均匀分箱与 RT-2 保持一致，便于对照
归一化范围用数据的 1% / 99% 分位数，不是 min/max关键工程点：min/max 会被离群动作撑爆，导致 99% 的正常动作挤在极少数 bin 里
token 映射覆盖 Llama tokenizer 中最少使用的 256 个 token不新增 token 就不用改 embedding 与 LM head 的形状；被覆盖的 token 在机器人语境下几乎不出现
训练数据Open X-Embodiment，约 97 万条轨迹、22 种机器人跨本体训练；不同机器人的动作空间要先统一到同一套 7-DoF 表示
下游适配LoRA 微调 + 推理时量化（int4/int8）让「用得起」成为可能，这是开源生态最重要的一步

直白说

「用 1%/99% 分位数而不是 min/max」这一条，是整篇论文里最该记住的工程细节。动作数据里总有极少数异常大的位移（遥操作抖了一下、数据里有一条错误轨迹）。用 min/max 归一化，这几个离群点就把整个 [a_min, a_max] 撑得极宽；结果是绝大多数正常动作被压进中间很少的几个 bin，等效分辨率暴跌。这与 C52 讲的量化离群值问题是同一个现象——notebook 第 3 节会把这个损失量化出来。

严谨说

「覆盖最少使用的 token」这一条则暴露了「动作即语言」的一个隐性约束：你不能直接把动作写成数字字符串。因为 tokenizer 会把 "128" 切成不定数量的 token，而 "7" 只切成一个——动作序列的长度会随数值变化，固定长度解码和并行监督就都做不了了。所以必须建立「bin 编号 ↔ 单个 token id」的一一映射。EMMA 走了相反的路（直接用文本数字），代价就是 token 数不可控——见 §5。

别把 OpenVLA 的设定直接搬到自动驾驶上。它的输入是单张 224×224 的第三人称图 + 一句短指令，输出是单步 7-DoF 动作。自驾要的是 7–11 路相机、360°、200 m 距离、4–8 s 的轨迹——输入侧和输出侧的规模都差一到两个数量级。把 OpenVLA 当成「VLA 的参考实现」是对的，当成「自驾 VLA 的原型」就错了。§6 的差异表就是为了防这个错。

4π0 的流匹配动作头：什么时候该离开离散 token

π0（2024）是第一个在大规模上放弃离散 token 的 VLA。它的动机不是「离散不好」，而是「在高频、高维、多模态的动作上，离散 token 的三条代价同时爆掉」——这个判断标准比结论重要得多。

三条代价怎么爆的

  • token 数：灵巧双臂 18 个自由度、50 Hz、一次输出 1 秒的动作块 → 18 × 50 = 900 个动作 token。自回归解码 900 步，在任何硬件上都不可能做到 50 Hz。
  • 精度：灵巧操作的位置精度要求在毫米级，动作范围若是 ±10 cm，256 个 bin 给出 Δ = 0.78 mm，ε_RMS ≈ 0.23 mm——刚好在「勉强够」的边缘，再苛刻一点就不够了。
  • 多模态：抓杯子可以从左边也可以从右边。逐维独立 softmax 能表达每一维的多峰，但表达不了「维度之间的联合多峰」（左路径与右路径各自是一组协调的 7 维动作，逐维取 argmax 会拼出一个两边都不是的怪动作）。

π0 的做法：VLM 主干（PaliGemma 3B）负责理解，另接一个 3 亿参数的 action expert，用 flow matching（流匹配）直接生成一整块连续动作（50 步 × D 维，一次出）。

\[a^{\tau}=\tau\,a+(1-\tau)\,\epsilon,\quad \epsilon\sim\mathcal N(0,I);\qquad \mathcal L=\mathbb E\big\|v_\theta(a^{\tau},\tau\mid o)-(a-\epsilon)\big\|^2;\qquad a^{\tau+\delta}=a^{\tau}+\delta\,v_\theta(a^{\tau},\tau\mid o)\]
动作头精度能表达多模态一次推理的前向次数实现/训练复杂度还能用语言解释自己吗
离散 token受 Δ/√12 限制逐维可以，联合不行D × K（串行）最低（复用 LM head）能
连续回归高不行（会输出平均值）1低不能
扩散（DDPM）高能50–100高（噪声调度、训练不稳）不能
流匹配高能约 10（直线路径）中不能

直白说

流匹配可以这么理解：扩散是让模型学「怎么一点点去噪」，流匹配是让模型学「从噪声直着走向答案的那个速度」。因为训练时用的概率路径是直线（噪声与真值之间的线性插值），推理时的积分轨迹也接近直线，10 步欧拉积分就够，而扩散通常要 50–100 步。这个 5–10 倍的步数差，正是它能上机器人而扩散策略吃力的原因。

严谨说

严谨地说，流匹配学的是把先验 p₀ = N(0,I) 输运到数据分布 p₁ 的条件速度场。取 optimal-transport 形式的条件路径 a^τ = τa + (1-τ)ε，其条件速度恒为 a - ε（与 τ 无关），于是回归目标极其简单且方差小——这是它比扩散训练稳定的技术原因。推理是对 ODE da/dτ = v_θ 做数值积分。代价是：动作不再是词表里的符号，「输出头就是 LM 头」这个便利被放弃了，模型也就不再能用同一条通路输出「我为什么这么动」的语言解释。这是一个真实的取舍，不是纯升级。

给一条可以直接用在面试里的判据：「频率越高、动作维度越高、越需要表达联合多模态，就越该离开离散 token；反之，越需要可解释、越需要与语言共用一条通路，就越该留在离散 token。」自动驾驶恰好落在中间——维度低（2–3 维）、频率不高（VLA 只出 2–10 Hz 的粗轨迹）、但极需要多模态（路口该左该右）与可解释性。所以自驾 VLA 的动作头选型至今没有定论，这是 m02 整节的内容。

5自动驾驶 VLA：DriveVLM、EMMA 与量产的那条路

机器人 VLA 的路子搬到车上，第一件事就撞墙：延迟。一个 3B–10B 的模型在车端跑一次要几百毫秒，而车辆每 20 ms 就要一个控制指令。这个矛盾催生了自驾 VLA 的两个标志性设计：慢-快双系统，与云-端蒸馏。

直白说

EMMA 的「一切皆文本」值得单独说一句，因为它与本课的接口主题直接相关。Waymo 把 3D 检测框、道路要素、未来轨迹全部写成文本数字，让一个模型用同一套接口做全部任务。好处是任务间正迁移明显、加新任务只要加一种文本格式；坏处是 token 成本与数值精度——一个三位小数的坐标要好几个 token，一条 8 秒轨迹的路点就能吃掉几百个 token。这正好是 §3 里 OpenVLA 用「bin ↔ 单 token」映射要避开的问题，两者做了相反的选择。

严谨说

而量产路线的核心不是模型，是「数据引擎 + 蒸馏」的闭环。云端大模型的真正角色有两个：① 直接做教师，蒸馏出车端小模型；② 做自动标注器，把车队回传的长尾片段变成训练数据（这就是 C58 m04 里「用 VLM 打标」那条线，也是 JD 里 automated data mining workflows 的指向）。所以「VLA 上车」不是一次模型部署，而是一条持续运转的流水线——理解这点，才能回答「这东西怎么迭代」这类系统设计题。而蒸馏一致性怎么度量、教师的错误怎么不被继承，目前没有标准答案（m05）。

一个会当场翻车的说法：「小鹏/特斯拉已经把大模型放到车上了」。准确的说法是：车端跑的是蒸馏后的小模型，云端才是大模型；而且 VLA 的输出仍要过规则层与安全层。把「云端大模型」和「车端模型」混为一谈，是这个话题上最常见的外行破绽——因为它直接暴露你没算过延迟与算力的账。随口能说出「车端几 B、int8 量化、2–10 Hz、下游控制器 10–100 Hz 跟踪」这几个数，可信度立刻不一样。

6机器人 VLA 与自驾 VLA：五个维度的关键差异

这是本模块最该背下来的一张表。大部分候选人读的是机器人 VLA 的论文（因为那边论文多），然后把结论直接套到自驾上——而这两者在几乎每个设计维度上都不同。能把差异说清楚，是「读过论文」与「想过问题」的分水岭。

维度机器人 VLA（RT-2 / OpenVLA / π0）自驾 VLA（DriveVLM / EMMA / 量产）这个差异导致什么
动作空间维度7 DoF（单臂）～ 14–18（双臂灵巧）2–3 维（纵向加速度 + 曲率）或路点序列自驾维度低 → 离散 token 的 token 预算压力小得多，离散化仍然可行
频率要求10–50 Hz（灵巧操作要 50 Hz）VLA 出轨迹 2–10 Hz，下游控制器 10–100 Hz自驾天然分层 → VLA 只出意图，不直接控车
时间视界1–2 s（一次抓取）3–8 s（一次变道/路口通行）自驾必须输出轨迹而非单步动作 → 动作分块是刚需
安全约束强度力矩限制 + 工作空间限制；软约束ISO 26262 / SOTIF；硬约束，需可论证自驾必须有 VLA 之外的规则层与安全层，机器人可以没有
可用传感器1–3 路近距 RGB(-D)，视野窄、距离 < 2 m7–11 路相机 360°、毫米波雷达、（可选）激光，距离 200 m自驾输入 token 数大得多 → 不可能把所有原始像素都喂进 LLM，必须先压缩/抽象
失败代价打翻杯子；可以重置重来碰撞、人身伤害；不可重置自驾不能靠「多试几次」，开环评测严重高估、必须闭环（m05）
数据获取遥操作主动采集，可定向补数据车队被动采集，长尾靠触发回传挖掘自驾的数据闭环是核心竞争力（C58 整门课）
长尾的类型没见过的物体与抓法没见过的语义规则场景（施工改道、临时管制、区域性标志）自驾长尾正是 TSR 的战场 —— 这就是本课的落点

表里有两行值得展开，因为它们最容易被想反：

直白说

「自驾动作维度低」经常被误读成「自驾更简单」。恰恰相反：维度低意味着离散 token 这条便宜路线在自驾上仍然可用（2 维 × 40 步 = 80 个 token，完全可接受，而 π0 是 900 个），所以自驾 VLA 反而更有理由保留「动作即语言」的可解释性。真正难的不是动作维度，是输入侧——7–11 路相机的信息量远超单臂机器人的一张图。难点从「怎么输出」搬到了「怎么输入」，而这正是本课讲接口的原因。

严谨说

「失败代价」这一行决定了整个评测方法论。机器人可以把成功率当主指标，因为失败了重置就行、可以统计几百次；自驾不能——一次严重失败的代价无法用几百次成功摊平。更麻烦的是：机器人可以真机跑闭环，自驾的闭环要么靠仿真（有域差）要么靠实车（贵且危险），于是大量工作退化成开环比对专家轨迹，而开环评测不暴露误差累积，会系统性高估。这个高估有多大、怎么修正，是 m05 的核心内容。

把这张表压成一句话交给面试官：「机器人 VLA 的难点在动作端——高维、高频、多模态；自驾 VLA 的难点在感知端与安全端——输入信息量巨大、失败不可逆、必须可论证。所以两边的技术选择往相反方向走：机器人在换动作头，自驾在做接口与兜底。」说得出这句，基本就说明你不是只看了 demo 视频。

7能力边界：VLA 被高估的三件事

模块 00 已经划过一次边界，这里补三条只有读过论文细节才知道的。它们都可以量化，所以可以在面试里作为「我读过而且算过」的证据。

① demo 视频的成功率与它的复合效应

机器人 VLA 论文里的成功率通常在 50%–85%（RT-2 在未见任务上约 60%，OpenVLA 在标准套件上 70% 左右）。这些数字在机器人语境下很好，在自驾语境下是灾难。而且成功率在多步任务上是相乘的：

\[P_{\text{整段成功}}=\prod_{i=1}^{n} p_i \;\approx\; p^{\,n};\qquad p=0.9,\ n=10 \;\Rightarrow\; 0.35;\qquad p=0.99,\ n=200 \;\Rightarrow\; 0.13\]

一次城市通勤有几百个需要语义判断的决策点。就算每个点 99% 正确，整段通勤不出错的概率也只有 13%。这不是说 VLA 没用，而是说「必须有下游兜底」不是保守，是算出来的结论。

② 「泛化」这个词被用得太宽

论文里的泛化通常是：换个桌布、换个没见过的物体、换个措辞的指令。这些都是「同分布内的组合泛化」。而自驾需要的泛化是：换一个国家的标志体系、换一种从未在互联网图片里出现过的临时施工牌、换一套区域性的道路规则。预训练常识覆盖的是互联网上常见的长尾，不是你这条路上的长尾——这两者的差距，正是量产仍然需要针对性数据与蒸馏的原因。

③ 思维链说的理由，不一定是它实际用的依据

VLA 能输出「我因为看到施工牌所以减速」这样的解释，这对调试和用户信任都很有价值。但语言模型的思维链是可能不忠实的（unfaithful）：模型可能因为图像里的某个无关线索做出决定，然后生成一段听起来合理但与实际计算无关的理由。把 CoT 当成因果解释来做故障归因，会把排查引向完全错误的方向。

直白说

这三条合起来给出一个务实的态度：把 VLA 当成「一个在长尾语义上比规则强、但输出必须被检查的建议器」，而不是「一个能开车的司机」。它的价值在于把「完全不会处理」变成「大概率处理得不错」，而把「大概率」变成「可以上路」是下游那几层的工作。

严谨说

更技术地说，VLA 的输出应当被视为一个带不确定性的高层意图，而非一个可执行指令。这意味着接口设计上要求三件事：① 它要能表达「我不确定」（而不是永远给出自信答案）；② 它的输出要能被下游做可行性检查（所以必须是结构化的轨迹/约束，而不是自由文本）；③ 它的失败模式要能被日志捕获。这三件事都不是模型能力问题，是接口与系统设计问题——也就是 m03、m04、m05 的全部内容。

面试里最危险的一句话是「VLA 能理解场景」。「理解」是一个无法证伪的词，说出来只会招来「怎么证明它理解了？」这个你答不上的追问。把它换成可验证的表述：「VLA 在需要组合语义先验的长尾场景上，比穷举规则的方案有更高的正确率；代价是延迟、幻觉与不可验证性；所以它的输出必须过安全层。」同样的意思，但每一句都能被追问且你都答得上。

8回到 TSR：那条 JD 职责在这条链路的哪个位置

把 JD 那句话拆开：「Improve VLA models to effectively consume TSR outputs and support traffic-sign-aware instruction following through VLA prompts」——三个动词短语，对应三件不同的工作。

JD 短语实际要做的事本课对应模块衡量它做得好不好的指标
consume TSR outputs设计 TSR → VLA 的序列化 schema：传哪些字段、什么形式、置信度怎么传m03同样的感知输入下，下游决策正确率；token 成本
traffic-sign-aware把标志语义翻译成可执行约束：作用域、生命周期、冲突优先级m04交通标志相关的规则违反率；约束撤销的正确率
through VLA promptsprompt 模板设计与稳定性：字段顺序、数值格式、缺失值、先验注入m03 / m04prompt 扰动下输出的稳定性；字段消融的敏感度

注意这三件事没有一件是「训 VLA」。这个岗位在 VLA 这条链路上的位置是上游 + 接口，不是模型本身。这与 JD 的主体（TSR 2D Detection）完全自洽——公司要的是一个既懂检测、又知道自己的输出会被怎么消费的人。

面试标准答案骨架

  1. 先定位：「VLA 在自动驾驶栈里是接在感知之后、规划之上的语义决策层，它不直接控车，输出要过安全层。」（先给架构位置，避免被当成只会背名词）
  2. 再讲转换：「VLA 的起点是 RT-2 把动作离散化成 token、复用 VLM 的输出头，把控制问题变成语言问题——这样才能继承预训练的常识。代价是分箱误差、token 无序关系、自回归延迟。」
  3. 然后讲分化：「机器人那边因为高频高维走向了流匹配动作头（π0）；自驾这边动作维度低、更需要可解释，所以离散 token 仍然可用，真正的难点搬到了输入侧。」
  4. 落到自己的位置：「所以我的工作是让 TSR 的输出能被 VLA 正确消费——至少要传类别、数值、置信度（且经过校准）、距离、车道关联、track_id、临时/固定这七项，因为下游需要区分『看到了』与『确认了』、『我车道』与『对向』、『临时』与『固定』。」
  5. 最后主动划边界：「VLA 会把错误的感知输入合理化成一段像样的推理，所以低置信输入必须触发保守行为，而不是交给模型自己判断。这是接口设计的第一性要求。」

这个骨架的设计逻辑：架构定位 → 关键技术转换 → 领域分化 → 自己的位置 → 主动划边界。前三步证明你读过东西，第四步证明你想过自己的工作，第五步证明你不吹。五步里最容易被跳过、也最能拉开差距的是第五步——大多数候选人讲完技术就停了，而面试官最想知道的恰恰是「你知不知道它什么时候不行」。

9研究前沿与开放问题

这一节列的是写这门课时仍无共识的问题。它们全部与本模块的内容直接相关，可以作为面试中「你觉得这个方向的难点是什么」的现成答案。

  • 离散 token 的「无序关系」能否被修好：bin 128 与 bin 129 在 embedding 空间里毫无关联，模型必须从数据里重学动作的连续性。有工作尝试给动作 token 加上有序的位置编码、或用残差量化（RVQ）建立粗-细层次，但都还没成为共识做法。这是「动作即语言」最深的技术债。
  • 自驾动作头的选型没有定论：维度低（离散可行）+ 强多模态需求（离散不够）+ 需要可解释（扩散做不到）三个约束互相冲突。目前看到的方案从「离散 token + 多候选轨迹」到「轨迹词表（trajectory vocabulary）」到「小步数流匹配」都有，还没有胜出者（m02 详述）。
  • 视觉 token 的预算分配：7–11 路相机的原始像素不可能全进 LLM。该给远处的小目标区域多分 token 还是均匀分？该在 BEV 空间抽 token 还是在图像空间抽？——这与 TSR 的小目标问题（C57）直接耦合，是当前最工程化也最缺公开结论的一块。
  • 思维链的忠实性：VLA 输出的推理链与它实际使用的依据是否一致，目前既缺度量也缺保证。如果不忠实，把 CoT 用于故障归因就是有害的；而 CoT 恰恰是 VLA 相对端到端最被看重的卖点。
  • 蒸馏的长尾保真：云端大模型 → 车端小模型的蒸馏，在头部场景上很容易对齐，但长尾恰恰是样本最少、蒸馏信号最弱的地方——而长尾又是用 VLA 的全部理由。怎么度量「蒸馏后长尾能力有没有掉」，缺乏标准方法（m05）。
  • 跨本体 / 跨车型迁移：Open X-Embodiment 证明了跨机器人本体训练有正迁移。自驾这边，不同车型的传感器布置、标定、动力学都不同，「一个 VLA 服务多种车型」的迁移问题几乎没有公开研究。
  • 评测的开环-闭环鸿沟：开环比对专家轨迹会严重高估（不暴露误差累积），而闭环需要高保真仿真或实车。「开环指标提升多少才对应闭环真实提升」这个换算关系，目前每家自己拍脑袋。

必读（按建议顺序，每篇只需读指定部分）：RT-2: Vision-Language-Action Models Transfer Web Knowledge to Robotic Control（Brohan et al., 2023 —— 只读动作离散化与 co-fine-tuning 两小节，这是「动作即 token」的原点）；OpenVLA: An Open-Source Vision-Language-Action Model（Kim et al., 2024 —— 读动作归一化的分位数选择与 tokenizer 覆盖策略，是全篇最有工程价值的两处）；π0: A Vision-Language-Action Flow Model for General Robot Control（Black et al., 2024 —— 读 action expert 与流匹配动作头，理解什么时候该离开离散 token）；Flow Matching for Generative Modeling（Lipman et al., 2023 —— 只需读 OT 条件路径那一节，理解为什么 10 步就够）；DriveVLM / DriveVLM-Dual（Tian et al., 2024 —— 慢-快双系统的代表）；EMMA: End-to-End Multimodal Model for Autonomous Driving（Hwang et al., 2024 —— 重点看它怎么把感知结果与轨迹写成文本，与本课 m03 的接口设计正好互为对照）；Open X-Embodiment（2023 —— 跨本体数据集，理解动作空间统一的工程难度）。相邻课程：C00（VLM 结构）、C55（TSR 上游）、C57（小目标与视觉 token 预算）、C60（车端量化与部署）。完整清单见 references.md。
