1自动驾驶架构的三代演进：每一代在换什么

这门课要讲的 VLA（Vision-Language-Action，视觉-语言-动作模型）不是凭空冒出来的。它是自动驾驶软件架构第三次大改的产物，而要理解它为什么值得做，必须先理解前两代各自卡在哪里。

① 模块化流水线（2015–2021 量产主流） 传感器 → 感知 → 融合/跟踪 → 预测 → 规划 → 控制 │ │ │ │ └──────┴───────────┴───────┴─ 每段接口由**人手写死**（结构化 schema） 优点：每段可单测、可回归、出问题能定位到具体模块 代价：**接口 schema 之外的信息全部丢失**，且下游只能消费你想到要写的字段 ② 端到端 / 一段式（2022– ，UniAD、部分量产方案） 传感器 ══════════ 一个网络（中间表示由梯度决定）══════════ 轨迹 优点：不再有人为信息瓶颈；上限由数据决定而不是由 schema 决定 代价：**不可解释、不可局部修复**——路测出问题，你不知道该补哪一段数据 ③ VLA（2023– ） 传感器 → 视觉编码器 ─┐ ├→ 语言模型（常识 + 推理）→ 动作 token → 轨迹 指令 / 规则 / 标志语义 ┘ 优点：中间表示是**语言**——可读、可写、可注入先验、可要求它解释自己 代价：延迟大、会幻觉、缺乏形式化安全保证；必须外挂规则层与安全层

直白说

三代的演进不是「后一代全面优于前一代」，而是每一代都在拿一样东西换另一样东西。模块化拿「信息完整性」换了「可定位性」；端到端把它换了回来——拿「可定位性」换「信息完整性」；VLA 想做的是第三条路：用语言当中间表示，既保留可读性又不写死 schema。它并没有取消这个权衡，只是换了个位置站。

严谨说

更精确地说，三代的差别在于「归纳偏置写在哪里」。模块化把归纳偏置写在接口与规则里（人的知识以代码形式存在）；端到端把它写在数据分布里（人的知识必须先变成标注）；VLA 把它写在预训练权重 + prompt 里（人的知识可以以自然语言形式直接注入，不必先变成代码也不必先变成标注）。这第三种注入方式的边际成本远低于前两种，这就是 VLA 的全部经济学理由。

一个必须先说清的事实：今天没有任何量产车是「纯 VLA」的。所有落地方案都是混合体——VLA 负责语义理解与粗轨迹意图，下游仍有传统的规划器、控制器与安全监控层。面试里如果你把 VLA 描述成「取代了整个软件栈」，会立刻暴露只读过新闻稿。正确的描述是：VLA 是接在感知之后、规划之上的一层「语义决策」，它的输出仍要经过可行性与安全校验。

2VLA 是什么，更重要的是不是什么

先给一个能背下来的定义：VLA = 一个在大规模视觉-语言数据上预训练过的模型，被继续训练成「看图 + 读指令 → 输出动作」。关键词是「预训练过的」——如果从头训一个吃图像吐轨迹的网络，那是端到端，不是 VLA。VLA 的全部价值来自它继承了视觉-语言预训练里的常识与推理能力。

常见误解实际是什么为什么这个区分重要
「给车装个聊天机器人」语言在这里是内部表示与接口，不是给用户聊天用的把它当交互功能，就会把评测做成对话质量，完全测不到该测的东西
「VLA 取代了感知」VLA 消费感知输出；感知（含 TSR）反而更重要了感知错了 VLA 会把错误合理化成一段像模像样的推理
「端到端 = VLA」端到端强调「无手写接口」，VLA 强调「继承预训练语义」两者动机不同：一个为了信息不丢，一个为了长尾常识
「VLA 能保证遵守交通规则」它只是更可能遵守；没有任何形式化保证规则层与安全层不能省，这是量产红线
「上车就是把大模型塞进车机」量产路线是云端大模型 → 蒸馏 → 车端小模型不知道这条，就答不出「几百 ms 延迟怎么可能上车」
「参数越大越好」车端算力与延迟预算是硬约束，存在最优规模而非越大越好面试问「为什么不用 72B」，答不上来会很尴尬

直白说

「不是什么」比「是什么」更值得花时间，原因很实际：VLA 是当前最被过度宣传的方向之一，面试官几乎一定会用一两个夸大的说法来试探你。能主动划出能力边界、能说出「这件事 VLA 现在做不到」的候选人，可信度会立刻上一个台阶。反过来，把 demo 视频当成能力证据，是最容易被追问穿的。

严谨说

边界大致有四条，值得记住：①「延迟」——大模型推理频率只有几 Hz，而车辆控制需要 10–100 Hz，所以 VLA 只能出「意图/粗轨迹」，高频跟踪必须交给下游控制器；②「幻觉」——它会报告不存在的标志、或为错误的感知输入编造合理解释；③「长尾仍是长尾」——预训练常识覆盖的是互联网上常见的长尾，不是你这条路上的长尾；④「不可验证」——目前无法对一个 VLA 给出「在场景集合 S 上永不违反规则 R」的论证。这四条都不是工程调优能消掉的，是范式自带的。

面试当场翻车的典型：被问「VLA 相比端到端好在哪」，回答「效果更好」。这个回答几乎一定会被追问「哪个指标上好？在什么场景？代价是什么？」而崩掉。正确的骨架是：「不是通用指标更好，而是在需要语义理解的长尾场景上更好，代价是延迟与不可验证性；所以量产是混合架构，不是替换。」

3核心痛点：长尾语义理解，或者说「规则写不完」

如果只能记住这门课的一句话，记这句：VLA 要解决的不是「开得更准」，而是「遇到没写过规则的场景时不至于失措」。这个痛点有一个可以算出来的形状。

为什么规则一定写不完

把「驾驶场景类型」按出现频率排序，它近似服从 Zipf 分布（幂律）：第 r 常见的场景类型出现频率 ∝ r-α，α 通常接近 1。一条规则覆盖一种场景类型，那么写 K 条规则能覆盖的场景实例比例是：

\[\mathrm{Cov}(K)=\frac{\sum_{r=1}^{K} r^{-\alpha}}{\sum_{r=1}^{N} r^{-\alpha}}\;\xrightarrow{\;\alpha=1\;}\;\frac{H_K}{H_N}\approx\frac{\ln K+\gamma}{\ln N+\gamma}\quad\Longrightarrow\quad K(c)\approx N^{\,c}\]

代入 N = 5000 种场景类型（这个量级对一个国家的路网是保守估计），得到三个应该记住的数字：

想覆盖的场景实例比例需要的规则条数 K相比上一档新增
50%53—
90%2014+1961
99%4562+2548
99.9%≈ 4939+377（且每条只覆盖约 0.0003%）

读法：53 条规则覆盖一半的路况，而最后那 9% 要再写 2548 条。这不是工程师偷懒，是幂律分布的数学性质——规则法的成本随覆盖率超线性上升，而每条新规则的边际收益指数下降。更糟的是这 2548 条规则彼此还会冲突，维护成本再乘一个系数。

「前方施工改道」：一个具体的例子

设想这一帧：前方 80 m 有临时限速 40 的牌子（置信度 0.71，因为是临时牌、反光差、还小），40 m 处有一块固定的限速 80 牌（置信度 0.93，大而清晰），右侧有个「车道封闭」牌（置信度 0.44，被锥桶挡了一半），地上还有引导锥桶。人类司机零思考就知道该怎么办：临时的压固定的，不确定就保守，往左并。

而模块化流水线会怎么处理？规则表里如果没有「临时标志优先于固定标志」这一条，它就会取最近的那块牌——限速 80；construction_ahead 这个类别如果不在规则表里，直接被忽略；lane_closed_right 置信度 0.44 低于阈值 0.6，被丢弃。三个信息全部丢失，输出「保持 80 km/h、保持车道」——一个危险且完全「符合设计」的结果。（notebook 里会把这条链路完整跑一遍。）

直白说

VLA 的赌注是：「临时的压固定的」「不确定就保守」这类知识不需要被写成规则，因为它已经在语言预训练里了。你只要把感知输出序列化成文本、把优先级原则写成一句自然语言先验，模型就能组合出正确结论——而且换个国家、换种没见过的标志，同一句先验仍然成立。这就是「边际成本低」的具体含义。

严谨说

严谨地说，VLA 把「规则覆盖问题」转化成了「语义组合泛化问题」：不再要求为每个 (场景类型 → 动作) 配对写规则，而是要求模型能把有限的语义原语（临时/永久、封闭/开放、置信高/低、保守/激进）组合到没见过的配对上。这个转化是否成立，是当前 VLA 研究最核心的经验问题——它在互联网常见场景上大致成立，在区域性、行业性的长尾上并不可靠（模型没在中国某省的临时施工牌上预训练过）。所以量产方案里仍然需要针对性数据与蒸馏，这不是矛盾，是必要补充。

把这一节浓缩成一句可迁移的心法：规则法的成本随覆盖率超线性上升，学习法的成本随覆盖率次线性上升——两条曲线一定会交叉，交叉点之后就该换范式。VLA 的出现不是因为它「更先进」，而是因为量产车队的场景覆盖率已经推到了那个交叉点右边。

4为什么这门课的落点是「感知接口设计」

这门课对应 JD 里的一条职责：「Improve VLA models to effectively consume TSR outputs and support traffic-sign-aware instruction following through VLA prompts」。翻译成人话：不是让你去训 VLA，而是让你把交通标志识别（TSR）的输出，设计成 VLA 能吃、能吃对、吃错了还能兜住的形式。

相机 ──→ [ TSR 检测 + 分类 ] ──→ [ 跟踪 / 多帧融合 ] ──→ ★ 接口层 ★ ──→ [ VLA ] ──→ 动作 │ │ │ 类别·框·分数 track_id·稳定语义 **本课的战场** 序列化 schema 置信度传递 prompt 模板 低置信降级策略 ★ 接口层要回答的四个问题： 1. 传什么字段？（类别 / 数值 / 距离 / 车道关联 / 置信度 / track_id / 首次检出时间） 2. 用什么形式传？（文本 · 特征 token · 共享 BEV query —— 三种融合层次） 3. 置信度怎么传、怎么让下游真的用它？（不传 = 强迫下游把所有检测当真） 4. 感知错的时候，怎么让 VLA 保守而不是「合理化」错误输入？
融合层次怎么做信息量可解释性token/带宽成本典型使用者
① 符号 / 文本级检测结果序列化成结构化文本塞进 prompt低（有损）高（人能直接读）高（占上下文）研发调试、云端大模型
② 特征级感知特征作为额外 token 或 cross-attention 注入高低中研究工作
③ 中间表示级共享 BEV query / 场景 token高中低量产系统主流

直白说

为什么「接口」值得单开一门课？因为感知与决策之间的接口，是整个自动驾驶栈里最容易出错、又最少被系统讲授的地方。最常见的设计错误只有一句话：只传类别不传置信度——这等于强迫下游把 0.44 的检测和 0.93 的检测同等对待。而在 TSR 里，0.44 的「车道封闭」和 0.93 的「限速 80」触发的是完全相反的动作。

严谨说

更深一层的问题是错误传播的不对称性。传统流水线里，感知错误会被下游的规则「挡住」（阈值、合理性检查、地图比对）；而 VLA 是一个生成模型，它面对错误输入的默认行为不是拒绝，而是生成一段能解释这个输入的连贯推理——也就是把感知错误放大成决策错误并附赠一个听起来很有道理的理由。这使得「让 VLA 在低置信输入下保持保守」不是锦上添花，而是接口设计的第一性要求。本课 m03、m04 会把这件事做成可测量、可实现的机制。

面试里这条职责的高分答法：「TSR 输出进 VLA 不是把类别名拼成字符串就完了。至少要传置信度、距离、车道关联、track_id 与首次检出时间五项，因为下游需要区分『看到了』和『确认了』、『在我车道』和『在对向』；而且置信度必须是校准过的，否则下游用不了。」能主动说出「校准」两个字，基本就赢了这一问。

与其他课的关系

  • C00（VLM）：视觉编码器 + 连接器 + LLM 的结构在那里讲透了。本课 m01 只做必要回顾，直接从「怎么接上动作」开始。如果你对 CLIP/SigLIP 视觉塔与 projector 完全陌生，先补 C00 的对应两节。
  • C55（TSR 与自动驾驶感知）：本课的上游。C55 讲怎么把标志检出来、怎么跟踪、怎么评测；本课讲检出来之后怎么交给 VLA。两门课在 m03 直接接口，建议连着学。
  • C58（难例挖掘与长尾数据闭环）：本课 m00 讲的「规则写不完」，在 C58 是「数据永远补不完」——同一个幂律的两种表现。C58 m04 提到的「用 VLM 给数据打标」也是 VLA 生态的一部分。
  • C60（车端部署与一致性）：本课 m05 的蒸馏与延迟预算，落到 C60 的量化、导出与训练-部署一致性上。「云端大模型蒸馏到车端」这句话的工程内容，一半在 C60。
  • C61（实战与面试实务）：本课的内容会以「架构演进题」「系统设计题」的形式出现在那里。

学习顺序上的一个建议：不要跳过 m02 直接看 m03。m03 讲的「置信度必须传递」之所以重要，前提是你知道 m02 里「动作是被离散化 / 被回归 / 被采样出来的」——不同的动作头对输入噪声的敏感方式完全不同。跳过 m02 会让你把 m03 读成一份字段清单，而它其实是一套关于误差传播的推理。

6环境、方法论与这门课怎么用

本课所有 notebook 纯 numpy + 标准库，CPU 可跑，不联网、不下模型、不需要 GPU。这是刻意的选择，理由值得说明白。

直白说

方法论上，这门课坚持一件事：凡是能算的都算出来，凡是能构造反例的都构造出来。「离散化会损失精度」是一句正确的废话；「256 个 bin 把曲率量化到 7.8×10⁻⁴ m⁻¹，在 30 m 前视距离上对应 0.18 m 的最大横向偏差、50 m 上就是 0.49 m」才是能用来做决策的信息。m01 的 notebook 会把这个数一步步算出来。

严谨说

对应到学习方式：每个 notebook 的 ✏️ 练习都是「把讲解里那句结论亲手算一遍」，不是语法练习。做不出来通常意味着讲解里某个环节没读懂，此时回去读那一节比看答案有效得多。参考答案放在最后，刻意与练习隔开。另外 notebook 里的 assert 全部是真判分的——它们通过，说明你的实现在数值上真的对，而不是「看起来像」。

7研究前沿与开放问题

这个方向变化极快，下面几条是2024–2026 年仍然没有共识的问题。面试里主动提出其中一两条，比复述任何 SOTA 数字都有用。

  • 动作表示之争尚未收敛：离散 token（RT-2、OpenVLA）、连续回归、扩散/流匹配（π0、RDT）各有拥趸。目前的经验规律是「频率越高、维度越高、越需要多模态表达，就越该离开离散 token」，但自动驾驶这种「低维、需要高精度、又必须多模态」的组合到底该用哪个，仍是开放问题（m02 详述）。
  • VLA 到底有没有「常识迁移」：VLA 在没见过的场景上表现好，究竟是真的迁移了预训练常识，还是因为微调数据里已经有近似样本？目前缺少能干净分离这两者的评测协议——这直接影响「值不值得用大模型」这个投资决策。
  • 延迟-能力的帕累托前沿：思维链让推理更准但更慢，而车端延迟预算是硬的。快慢双系统（快系统直接反应、慢系统深度推理）是当前主流答案，但两个系统如何交接、慢系统结论过期了怎么办，没有标准做法（m04）。
  • 幻觉的度量与抑制：VLA 会报告不存在的标志、或为错误感知编造解释。如何在没有完美 ground truth 的路测数据上度量幻觉率，仍是开放问题（m05）。
  • 云端蒸馏的一致性保证：量产路线是「云端大模型教车端小模型」，但怎么证明蒸馏后的小模型在长尾上没有系统性退化？蒸馏一致性的度量、以及「教师错了学生跟着错」的检测，都缺工具。
  • 感知接口的标准化：本课 m03 讲的序列化 schema，目前每家一套。是否会出现一个类似 ONNX 之于模型的「感知-决策接口标准」，现在还看不出来——但这恰恰意味着现在做这件事的人有定义权。
  • 可验证性：如何对一个 VLA 给出「在场景集合 S 上不违反规则 R」的论证？目前的答案是「做不到，所以外挂规则层」。这层兜底能不能被形式化、能不能被证明完备，是 VLA 上车规模化的真正瓶颈。

必读（按建议顺序）：RT-2: Vision-Language-Action Models Transfer Web Knowledge to Robotic Control（Brohan et al., 2023 —— 「动作即 token」的起点，读第 3 节的动作离散化就够）；OpenVLA: An Open-Source Vision-Language-Action Model（Kim et al., 2024 —— 唯一能看到全部实现细节的，读它的动作归一化与 bin 设计）；π0: A Vision-Language-Action Flow Model for General Robot Control（Black et al., 2024 —— 流匹配动作头与动作分块）；DriveVLM: The Convergence of Autonomous Driving and Large Vision-Language Models（Tian et al., 2024 —— 自驾侧的慢-快双系统）；EMMA: End-to-End Multimodal Model for Autonomous Driving（Hwang et al., 2024 —— Waymo 的做法，重点看它怎么把感知结果写成文本）。相邻课程：C00（VLM 结构）、C55（TSR 上游）、C60（车端部署）。完整清单见 references.md。
