## 一 · 架构演进 · Architecture Generations

| 术语 (EN) | 中文 | 一句话定义 | 为什么重要 | ⚠️ 常见误解 |
|---|---|---|---|---|
| modular pipeline | 模块化流水线 | 感知 → 融合/跟踪 → 预测 → 规划 → 控制，每一段有明确定义的输入输出契约。 | 可调试、可分工、可单独回归测试，量产系统长期的主流形态。**每个接口都是一份契约，本课讲的就是其中一份。** | 以为模块化已经过时。它的真实问题是**接口处的信息损失**与人工规则的长尾成本，而不是「不够先进」。 |
| information bottleneck（接口处） | 接口信息瓶颈 | 上游把丰富的中间表示压缩成少量结构化字段传给下游，压掉的信息不可恢复。 | 它同时是模块化的**优点**（可解释、可测试）与**缺点**（丢信息）。理解这个二重性是本课的起点。 | 以为瓶颈越宽越好。宽接口（如直接传特征）确实少丢信息，但**同时丢掉了可调试性与可验证性**。 |
| end-to-end driving | 端到端自动驾驶 | 从传感器输入直接输出轨迹或控制量，中间不再有人工定义的接口。 | 消除了接口的信息损失与误差级联，UniAD/VAD 证明了它在开环指标上的优势。 | 以为「端到端」= 没有中间表示。UniAD 恰恰强调**保留中间任务**（检测、跟踪、建图、占据、预测）作为可监督的中间节点。 |
| planning-oriented perception | 面向规划的感知 | UniAD 的主张：所有中间任务都应该为最终的规划目标服务，并按此设计梯度通路。 | 它回答了「端到端里中间任务该不该留」——留，但要让规划的梯度能流回去。 | 以为它等于多任务学习。差别在于**任务之间是串行传递 query 的**，不是并行挂几个头。 |
| VLA (Vision-Language-Action) | 视觉-语言-动作模型 | 把视觉-语言预训练模型的输出端接到动作空间上，用语言作为中间的推理与指令载体。 | 它是目前唯一能把互联网规模的**常识**引入驾驶决策的路径，专治规则写不完的长尾语义。 | 以为 VLA 是「装了个聊天机器人」。**语言在 VLA 里主要是内部表示与接口，不是给用户聊天的**；对话能力只是副产品。 |
| 三代演进 | modular → end-to-end → VLA | 三种范式在「信息损失 / 可解释性 / 长尾能力 / 可验证性」四个维度上的取舍不同。 | 面试常问「你怎么看端到端」，能画出这张四维取舍表就赢了一半。 | 以为是简单的替代关系。**量产系统普遍是混合体**：VLA 做语义与决策，传统模块做安全兜底与高频控制。 |
| BEV (bird's-eye view) | 鸟瞰图表示 | 把多相机特征投影到自车坐标系的俯视平面上，形成统一的空间表示。 | 它是多传感器融合与下游规划的共同语言，也是「中间表示级接口」的载体。 | 以为 BEV 只是一种可视化。它是**特征空间**，检测/建图/预测都直接在它上面做。 |
| occupancy (OCC) | 占据栅格 / 占据网络 | 用 3D 体素表达空间被占据的概率（可含语义），处理形状不规则或未知类别的障碍物。 | 补上 3D 框表示的短板（异形障碍、掉落物），是当前量产感知的标配之一。 | 以为占据能取代检测。占据没有**实例概念**，跟踪与语义关联仍需要检测输出——TSR 尤其如此。 |
| latency budget | 延迟预算 | 从传感器出图到控制指令下发之间允许的总时间，逐段分配给每个模块。 | VLA 的一切设计取舍（模型大小、去噪步数、思维链长度）最终都撞在这条预算上。 | 以为「模型 200 ms 就够快了」。要算的是**端到端**：曝光 + ISP + 感知 + VLA + 规划 + 控制 + 执行机构响应。 |
| frequency gap | 频率鸿沟 | 大模型推理 2–10 Hz，横纵向控制需要 50–100 Hz，中间差一到两个数量级。 | **这条鸿沟是分层架构的物理原因**，不是工程偷懒；它直接推出 action chunking 与下游跟踪控制器。 | 以为「把模型做小就能提频」。小到能跑 50 Hz 的模型已经不具备 VLA 的语义能力了，**分层是唯一解**。 |
| long-tail semantics | 长尾语义 | 出现频率极低但需要正确理解的语义场景（临时改道、交警手势、特殊标牌组合）。 | **这是 VLA 存在的唯一充分理由**。高频场景传统方法已经做得很好，VLA 的增量全在这里。 | 以为长尾就是「数据少的类别」。长尾语义的难点是**组合爆炸**：标志 + 施工 + 对向来车 + 时段限制的组合无法穷举。 |
| ODD | 运行设计域 | 系统被设计为可安全运行的条件集合（道路类型、天气、光照、地理区域、速度范围）。 | 一切能力声明都必须绑定 ODD，否则无法验证也无法交付。 | 以为 ODD 只是市场话术。它是**验证的边界条件**：ODD 外的行为不需要保证，但必须能被检测并安全退出。 |

## 二 · VLA 基础 · VLA Fundamentals

| 术语 (EN) | 中文 | 一句话定义 | 为什么重要 | ⚠️ 常见误解 |
|---|---|---|---|---|
| VLM | 视觉-语言模型 | 视觉编码器 + 连接器 + LLM 的三段式，把图像变成 LLM 能消费的 token。 | VLA 的躯干。理解 VLA 的前提是知道 VLM 在哪里结束——**它止步于「输出文本」**。 | 以为 VLM 与 VLA 差在训练数据。差在**输出空间**：VLM 输出语言，VLA 输出可执行动作。 |
| connector / projector | 连接器 / 投影层 | 把视觉特征映射到 LLM 词嵌入空间的模块（线性层 / MLP / Q-Former / Perceiver Resampler）。 | 它决定了**视觉信息以多少个 token、多少精度进入 LLM**，直接影响能否分辨远处小标志。 | 以为连接器只是维度对齐。它同时在做**token 数压缩**，压得越狠小目标信息丢得越多（详见 C00）。 |
| visual token budget | 视觉 token 预算 | 一帧图像被编码成多少个 token 送进 LLM。 | 多相机 + 多帧下 token 数爆炸，直接撞上上下文长度与延迟；**这是感知接口必须精简的根本原因**。 | 以为多给 token 就更准。token 增加使注意力被稀释、延迟平方级上升，**信息密度比数量重要**。 |
| action as text | 动作即文本 | RT-2 的核心手法：把连续动作离散化成整数，再映射到词表中最少用的若干 token 上。 | 复用了 LM 的输出头与全部预训练权重，**这是常识泛化能力传导到动作的唯一通路**。 | 以为这只是个实现技巧。它是**范式选择**：一旦动作走别的头，语言预训练的语义就未必能传下来。 |
| action tokenization | 动作 token 化 | 把连续动作向量按维度分箱、映射为离散 token 序列的过程。 | 决定了动作精度上限、token 消耗、以及能否复用 LM 头。模块 02 会给出它的误差闭式解。 | 以为分箱越细越好。箱数翻倍只把误差减半，但**词表占用与训练难度线性上升**，且超过传感器噪声后毫无意义。 |
| co-fine-tuning | 共同微调 | 训练 VLA 时把机器人/驾驶数据与原始的视觉-语言数据混在一起训。 | RT-2 的关键发现：**只用动作数据微调会灾难性遗忘语义能力**，混训才保住泛化。 | 以为混训只是正则化。它保的是**任务本身依赖的能力**（认字、认符号、常识推理），少了它 VLA 就退化成普通策略网络。 |
| emergent semantic generalization | 涌现的语义泛化 | VLA 能对训练中未见过的物体/指令做出合理动作（例如「把东西放到能吸水的东西上」）。 | 这是 VLA 相对传统策略网络的**唯一质变**，也是它值得付出巨大算力代价的理由。 | 以为泛化是无限的。它泛化的是**语义组合**，不泛化**物理技能**与**未见过的动力学**。 |
| OpenVLA | 开源 VLA | 7B 规模的开源 VLA（视觉双编码器 + Llama 2 骨架），每个动作维度 256 个 bin。 | 目前复现与二次开发的事实基线，**读它的代码比读三篇论文更快理解 VLA**。 | 以为开源就等于可直接上车。它的推理频率与安全约束都不满足车规，是**研究基线**不是产品。 |
| π0 (pi-zero) | 流匹配 VLA | 在 VLM 骨架上接一个**流匹配**动作专家，输出高频连续动作块。 | 证明了「动作头可以不是 LM 头」，并给出了高频灵巧控制所需的精度。 | 以为流匹配头就一定优于离散 token。它换来精度与频率，**代价是与语言预训练的耦合变弱**，语义泛化需要额外设计。 |
| DriveVLM | 自驾 VLA（双系统） | 用 VLM 做场景描述-分析-分层规划，并与传统端到端模块组成快慢双系统。 | 它给出了自驾 VLA 最现实的落地形态：**大模型不接管高频控制，只提供慢速的语义决策**。 | 以为双系统是过渡方案。频率鸿沟是物理约束，**双系统很可能是终局形态**。 |
| EMMA | 端到端多模态自驾模型 | 把所有输入输出都表达成自然语言 / 文本化表示，交给多模态大模型统一处理。 | 展示了「一切皆文本」的极致形态，也暴露了它的代价：token 消耗、延迟、3D 精度。 | 以为文本化没有信息损失。数值精度、坐标系、置信度在文本化时**极易被格式吞掉**，这正是模块 03 要解决的。 |
| cloud-to-vehicle distillation | 云端-车端蒸馏 | 在云上训练/运行大模型，把能力蒸馏进车端可实时运行的小模型。 | 量产路线的通行解法：云端负责能力上限，车端负责实时与可靠。 | 以为蒸馏只是压缩。它同时是**分布迁移**——车端模型面对的输入分布与云端教师并不相同，必须专门度量一致性。 |
| instruction following | 指令跟随 | 模型按自然语言指令改变行为（「在下一个路口右转」「遵守前方限速」）。 | 它是 TSR 语义进入 VLA 的**表达形式**：标志被翻译成指令或约束后进入 prompt。 | 以为指令跟随就是听懂人话。在自驾里更多是**系统内部**的指令：由感知与地图生成、送给 VLA、再由兜底层校验。 |
| grounding | 落地 / 指代对齐 | 把语言中的指称（「前方那块限速牌」）对齐到具体的感知实例上。 | 没有 grounding，VLA 的解释与真实场景对不上，**日志与调试全部失效**。 | 以为 grounding 是可选的可视化功能。它是**可测试性的前提**：不能对齐实例就无法判断模型是对还是蒙对。 |
| system prompt | 系统提示 | 固定在上下文最前面的角色、规则与输出格式约定。 | 它是驾驶策略的「宪法层」：优先级规则、安全底线、输出 schema 都写在这里。 | 以为 system prompt 是硬约束。它是**软约束**，可被上下文冲垮；真正的硬约束必须在模型之外实现。 |
| context window | 上下文窗口 | 模型一次能处理的 token 上限。 | 多相机 × 多帧 × 结构化感知描述会迅速吃满窗口，**接口精简不是美学问题而是硬约束**。 | 以为窗口够大就可以塞满。注意力被稀释后**关键字段反而更容易被忽略**，长上下文里的中间信息尤其容易丢。 |

## 三 · 动作表示 · Action Representation

| 术语 (EN) | 中文 | 一句话定义 | 为什么重要 | ⚠️ 常见误解 |
|---|---|---|---|---|
| action space | 动作空间 | 模型输出的物理量集合（转向角、加速度、或未来轨迹点）。 | 定义它就等于定义了下游控制器的契约；换动作空间等于换系统。 | 以为动作空间只是输出维度。它还隐含**坐标系、时间基准、单位与更新频率**，这四项不写清就无法对接。 |
| discretization / binning | 离散化 / 分箱 | 把连续动作按均匀或分位数切成 B 个箱，用箱索引代表动作。 | 让动作能进 LM 词表；模块 02 会推出误差上界 **range/(2B)**。 | 以为均匀分箱总是对的。动作分布通常极不均匀（大部分时间加速度接近 0），**分位数分箱在相同 B 下误差小得多**。 |
| quantization error | 量化误差 | 分箱造成的不可恢复的动作误差，均匀分箱下最大值为 半个箱宽。 | 它给出「需要多少个 bin」的硬答案：**先定控制精度，再反推 B**，而不是拍脑袋取 256。 | 以为误差可以靠模型学回来。它是**表示层的信息损失**，与模型能力无关。 |
| regression head | 回归头 | 直接用 MSE/L1 输出连续动作向量。 | 精度不受分箱限制、实现最简单，低多模态场景下是最优选择。 | **最危险的误解**：以为回归总能学到「最可能的动作」。MSE 的最优解是**条件期望**，不是众数。 |
| mode averaging | 模式平均 | 动作分布有多个峰时，回归输出各峰的加权平均。 | 路口该左该右，回归给出直行——**这个直行动作在训练数据里一次都没出现过，却是 MSE 的全局最优解**。 | 以为多训练几轮就能解决。这是**损失函数决定的**，不是欠拟合；换损失或换表示才行。 |
| multimodal action distribution | 多模态动作分布 | 同一观测下存在多个同样合理的动作。 | 驾驶里到处都是（绕障走左还是走右、跟车还是变道），**它是扩散策略与离散分类存在的理由**。 | 以为加更多上下文就能消除多模态。上下文能减少但**消不完**——人类专家自己也不一致。 |
| diffusion policy | 扩散策略 | 用去噪扩散模型建模动作分布，从噪声迭代生成动作序列。 | 能表达任意多模态分布，在灵巧操作上大幅超越回归与离散方案。 | 以为它慢到不可用。**去噪步数可以蒸馏到 1–4 步**（consistency / shortcut 类方法），但步数直接乘进延迟这条账要自己算。 |
| flow matching | 流匹配 | 学一个连续时间的速度场，把噪声分布沿直线路径推到数据分布。 | 比扩散更少的步数得到同等质量，π0 的动作头用的就是它。 | 以为它是「另一种扩散」。训练目标不同（回归速度场而非噪声），**路径更直所以步数更少**，这是它的核心优势。 |
| denoising steps | 去噪步数 | 生成一次动作需要的迭代次数。 | **它直接乘进延迟**：单步 20 ms × 10 步 = 200 ms，可能吃掉全部预算。 | 以为步数是精度旋钮可以随便调。步数减少会先损失**分布覆盖**（多模态塌缩），再损失精度。 |
| action chunking | 动作分块 | 一次预测未来 K 步动作，执行若干步后再重新预测。 | **延迟受限系统的关键技巧**：推理频率降到 1/K，且块内动作天然时序一致。 | 以为 K 越大越好。K 大则块尾动作基于过时观测，**开环执行时间变长、对突发事件反应变慢**——K 是延迟与反应性的权衡。 |
| temporal ensembling | 时序集成 | 对重叠的多个动作块在同一时刻的预测做加权平均（ACT 的做法）。 | 消除块与块交界处的跳变，是 chunking 落地的必要配套。 | 以为它等于低通滤波。它平均的是**不同时刻做出的预测**，隐含了对预测新鲜度的加权。 |
| waypoints | 路径点 | 用未来若干时刻的位置点表示轨迹（如未来 3 秒每 0.5 秒一个点）。 | 自驾 VLA 最常用的动作表示：与控制解耦、易可视化、易加约束。 | 以为 waypoints 就是可执行轨迹。它**没有速度/加速度/曲率的连续性保证**，必须经过平滑与动力学检查。 |
| trajectory parameterization | 轨迹参数化 | 用多项式、样条或 Bézier 曲线的少量系数表示整条轨迹。 | 参数少、天然平滑、可解析求导，便于加曲率与加加速度约束。 | 以为参数化一定优于 waypoints。参数化**难以表达急变**（紧急避让），且系数空间的多模态更难建模。 |
| control commands | 控制量 | 直接输出方向盘转角、油门/刹车开度。 | 最短路径，但与具体车型强绑定。 | 以为直接输出控制量最「端到端」。它使模型**无法跨车型迁移**，且失去了轨迹层的可解释与可校验性。 |
| hierarchical control | 分层控制 | 上层低频出轨迹，下层高频跟踪（LQR / MPC / PID）。 | **频率鸿沟的标准解**，也让安全约束能在下层被强制执行。 | 以为分层是妥协。分层同时提供了**故障隔离**：上层挂了下层仍能沿最后轨迹安全停车。 |
| receding horizon | 滚动时域 | 每次规划一段较长的未来，只执行开头一小段，然后重新规划。 | 让系统能持续吸收新观测，是 chunking 的控制论对应物。 | 以为重规划越频繁越好。过于频繁会导致**决策抖动**（在两个方案间反复横跳），需要迟滞或一致性惩罚。 |
| jerk | 加加速度 | 加速度的时间导数，直接对应乘客的不适感。 | 舒适度指标的主体；**VLA 输出的轨迹经常 jerk 超标**，因为训练目标里没有它。 | 以为舒适度是次要指标。频繁的顿挫会导致接管率上升，**在量产里它和安全指标同样是发布门禁**。 |
| open-loop rollout | 开环推演 | 不与环境交互，直接按模型输出逐步展开。 | 便宜、可复现，是日常迭代的主力。 | 以为开环误差小就代表好。见第六组的 **compounding error**——这是本课最重要的批判之一。 |

## 四 · 感知接口 · Perception Interface

| 术语 (EN) | 中文 | 一句话定义 | 为什么重要 | ⚠️ 常见误解 |
|---|---|---|---|---|
| perception interface | 感知接口 | 感知模块与下游（VLA / 规划）之间的数据契约：字段、语义、坐标系、单位、更新频率、缺失约定。 | **本课的核心对象，也是 JD 那条职责的直接指向。** 它决定了下游能做什么、做不到什么。 | 以为接口是「工程细节」。接口定义了下游可获得的**全部信息**，它的表达力上限就是系统的能力上限。 |
| symbolic / textual fusion | 符号级 / 文本级融合 | 把检测结果序列化成结构化文本（JSON / 表格 / 自然语言）塞进 prompt。 | 可解释、易调试、可单元测试、可人工审查，**中小规模系统的最优起点**。 | 以为文本化没有代价。它有三重代价：**信息损失**（只保留被序列化的字段）、**token 成本**、**格式敏感性**。 |
| feature-level fusion | 特征级融合 | 把感知的特征张量作为额外 token 或通过 cross-attention 注入 LLM。 | 信息保留最完整，能传递文本无法表达的细节（纹理、模糊边界、密集空间关系）。 | 以为信息多就一定更好。特征级融合**不可解释、不可单元测试**，且需要联合训练，出问题时无法定位到具体字段。 |
| intermediate-representation fusion | 中间表示级融合 | 感知与 VLA 共享 BEV query / 场景 token 等统一表示。 | **量产系统的主流选择**：避免了重复编码，空间关系天然对齐。 | 以为它是特征级的同义词。差别在于**表示是共享且有明确空间语义的**，可以做部分可视化与探针。 |
| BEV query | 鸟瞰查询 | 一组绑定到 BEV 空间位置的可学习向量，通过 cross-attention 从多相机特征取信息。 | 它让「某个空间位置有什么」成为可寻址的对象，是共享表示的技术载体（概念源自 DETR 的 object query，见 C54）。 | 以为 query 是特征。它更接近**可学习的位置先验 + 读取指针**，特征是它读回来的东西。 |
| serialization schema | 序列化 schema | 感知结果转成文本/结构体时的字段定义与格式约定。 | 模块 03 的主产物。**每个字段都必须能回答「下游少了它会具体做错什么」**，否则就是在浪费 token。 | 以为字段越全越好。多余字段会稀释注意力、增加延迟，且**每个字段都是一份需要长期维护的契约**。 |
| field ablation | 字段消融 | 逐个去掉 schema 里的字段，测量下游任务指标的变化。 | 把「这个字段有没有用」变成可测量的问题，是 schema 设计的标准方法。 | 以为消融只用于模型结构。**接口设计同样需要消融**，而且这类实验通常便宜得多。 |
| coordinate frame | 坐标系 | 图像像素坐标 / 自车坐标 / 世界坐标 / BEV 网格坐标。 | **不写清坐标系的接口等于没有接口**；同一个数字在不同坐标系下含义完全不同。 | 以为下游能从上下文推断。它推断不了，而且**推断错了不会报错**，只会在特定场景下悄悄做错决策。 |
| confidence propagation | 置信度传递 | 把感知的不确定性作为一等字段送给下游。 | **不传置信度 = 强迫下游把所有检测当作确定事实**，这是感知-决策接口最常见的设计错误。 | 以为「只传高置信度的结果」就等于传了置信度。阈值化把连续信息压成 0/1，**下游失去了做代价权衡的能力**。 |
| calibration | 置信度标定 | 模型输出的分数与真实正确率一致（说 0.9 就真的 90% 对）。 | **未标定的置信度比没有置信度更危险**：下游所有基于阈值的保守策略被系统性绕过。 | 以为分类器天然标定。现代深度网络**普遍过度自信**，且蒸馏、量化、数据漂移都会进一步破坏标定。 |
| ECE (Expected Calibration Error) | 期望标定误差 | 把样本按置信度分桶，计算每桶「平均置信度 - 实际准确率」的加权绝对差。 | 标定质量的标准标量指标，可直接进回归门禁。 | 以为 ECE 低就万事大吉。ECE 是**全局平均**，可能掩盖关键类别（如「停车让行」）的严重失准。 |
| reliability diagram | 可靠性图 | 横轴置信度、纵轴实际准确率的分桶曲线，对角线为完美标定。 | 一眼看出是过度自信还是不足自信，以及在哪个区间失准。 | 以为它和 PR 曲线一回事。PR 看**排序质量**，可靠性图看**数值的绝对含义**——一个模型可以排序完美但数值全错。 |
| temperature scaling | 温度缩放 | 在 logits 上除以一个标量 T，用验证集拟合 T 来改善标定。 | 单参数、不改变排序、不损失精度，**性价比最高的标定手段**。 | 以为它能修好一切。温度缩放只做**全局单调变换**，对类别间的失准差异无能为力。 |
| track ID / lifecycle | 跟踪 ID / 生命周期 | 同一物理标志在多帧间的唯一标识，以及 tentative → confirmed → lost 的状态。 | 让下游能区分「同一块牌被看了 10 帧」与「10 块不同的牌」，**这是约束能否正确解除的前提**。 | 以为单帧检测结果就够了。没有 ID，下游无法做时序累积，也无法判断一块牌是新出现还是刚被确认。 |
| first-detection distance | 首检距离 | 某块标志第一次被稳定检出时的自车距离。 | 决定下游有多少时间做决策与执行，是 TSR 最重要的时序指标之一（详见 C55）。 | 以为它只是感知的内部指标。它必须**进入接口**：VLA 需要知道「这条信息有多新、还剩多少反应时间」。 |
| hallucination | 幻觉 | 模型输出了输入中不存在的内容（说看到了一块并不存在的限速牌）。 | 在驾驶场景里，幻觉出的约束会导致**无理由的减速或变道**，是接管率的直接来源。 | 以为幻觉只发生在语言生成里。**结构化输出同样会幻觉**：模型会补全 schema 里缺失的字段并给出貌似合理的数值。 |
| error rationalization | 错误合理化 | 感知输入有误时，VLA 会围绕这个错误输入生成自洽且自信的解释与动作。 | 它使错误**更难被发现**：日志里的推理链条看起来完全合理。 | 以为让模型「多想一步」能发现输入错误。思维链会**强化**已接受的前提，除非显式提供不确定性与矛盾证据。 |
| garbage-in-confident-out | 垃圾进，自信出 | 输入质量下降时，模型的输出置信度并不同步下降。 | 这是接口设计要对抗的核心现象：**低置信输入必须触发保守行为，而不是自信的臆测**。 | 以为这是模型能力问题。很大一部分是**接口没有把不确定性传进去**，模型根本不知道输入可疑。 |
| prompt template stability | 模板稳定性 | 字段顺序、数值格式、单位写法、缺失值表示的一致性。 | 同样的信息换个顺序或格式，输出可能显著变化；**模板必须版本化并纳入回归测试**。 | 以为模型对格式鲁棒。实测中**字段顺序、小数位数、空值写法**都会改变结果，这是必须被固定的工程细节。 |
| missing-value convention | 缺失值约定 | 字段无效时写 null、写 unknown、还是整个省略。 | 三种写法会诱导出完全不同的下游行为；**省略最危险**（模型倾向于当作不存在或自行补全）。 | 以为省略等于「没有信息」。省略常被模型解读为**否定**（「没有标志」），而不是「不知道」。 |
| provenance / traceability | 来源可追溯 | 每条下游决策都能回溯到具体的感知实例与帧号。 | 端到端系统最缺的就是这个；**没有它就无法做事故归因**。 | 以为日志记全了就有可追溯性。需要的是**ID 级别的关联**，而不是两份各自完整但对不上的日志。 |

## 五 · 规则与约束 · Rules & Constraints

| 术语 (EN) | 中文 | 一句话定义 | 为什么重要 | ⚠️ 常见误解 |
|---|---|---|---|---|
| semantics-to-constraint translation | 语义到约束的翻译 | 把标志的语义翻译成可执行的数学约束（限速 → v ≤ 60；禁左 → 屏蔽左转候选）。 | **这是 TSR 与规控之间真正的桥**，模块 04 的主线。 | 以为翻译是一一对应的查表。同一块牌在不同车道、不同车型、不同时段下的约束**并不相同**。 |
| hard vs soft constraint | 硬约束 vs 软约束 | 硬约束不可违反（法规、动力学），软约束进代价函数（舒适、效率）。 | 分清两者才能设计正确的兜底层：**硬约束必须在模型之外强制执行**。 | 以为把规则写进 prompt 就是硬约束。prompt 里的一切都是**软的**，会被上下文冲垮。 |
| constraint scope | 约束作用域 | 约束在空间上的适用范围（哪条车道、哪个路段、哪个方向）。 | 对向车道的限速牌不该约束本车；辅路的禁令不该套到主路上。**关联错车道是 TSR 下游的高频事故**。 | 以为「看到就生效」。必须先做**车道/路径关联**，这一步的错误率往往高于检测本身。 |
| constraint lifetime | 约束生命周期 | 约束从何时开始生效、何时自然失效、被什么显式解除。 | **TSR 下游最容易出错的地方**：漏掉一块解除牌，车会一路按 40 km/h 开上高速。 | 以为「开过去就失效」。多数限速在**下一个路口或下一块标志之前持续有效**，规则因国家而异。 |
| cancellation sign | 解除标志 | 显式取消先前限制的标志（解除限速、解除禁止超车）。 | 它是生命周期状态机里唯一的**显式终止事件**，漏检的代价是长期错误状态。 | 以为解除牌和普通牌一样重要。**它的漏检代价远高于普通牌**，因为错误会持续到下一个事件，应单独设阈值与召回目标。 |
| rule priority | 规则优先级 | 多条规则冲突时的裁决顺序（临时施工 > 可变电子牌 > 固定标志 > 地图限速 > 默认路网）。 | 冲突在真实道路上极常见（施工区叠加原限速），**必须有确定性的裁决规则**。 | 以为优先级是固定偏序。**时效性可以反超**：一块 5 分钟前更新的电子牌，通常应压过一块可能已过期的临时牌。 |
| conflict resolution | 冲突消解 | 在优先级、时效、置信度之间做确定性裁决并记录理由。 | 裁决必须**可复现、可解释、可回归测试**，否则事故无法归因。 | 以为让模型自己判断就好。模型的裁决**不稳定且不可复现**，冲突消解应该是确定性代码。 |
| safety guardrail / fallback layer | 安全兜底层 | 位于 VLA 之外、对其输出做可行性与合规性校验的独立模块。 | **量产红线**：VLA 输出必须经过动力学可行性、碰撞检查、法规硬约束三关才能下发。 | 以为它是「模型不够强时的临时补丁」。它是**永久性架构组件**：任何学习系统都无法给出形式化保证。 |
| feasibility check | 可行性校验 | 检查输出轨迹是否满足曲率、加速度、加加速度、车辆动力学上限。 | 最便宜的一道防线，能挡掉大量明显不可执行的输出。 | 以为模型学过就不会输出不可行轨迹。分布外输入下**它一定会**，而且不会有任何征兆。 |
| MRC (minimal risk condition) | 最小风险状态 | 系统失效或超出 ODD 时进入的安全状态（减速停在路边）。 | 每个降级路径都必须终止于一个明确定义的 MRC。 | 以为 MRC 就是紧急刹车。在高速上直接急停可能**更危险**，MRC 必须是场景相关的。 |
| RSS (Responsibility-Sensitive Safety) | 责任敏感安全 | 用形式化的最小安全距离与责任规则定义「不引发事故」的可验证条件。 | 提供了一套**可数学验证**的安全包络，可作为兜底层的判据来源。 | 以为 RSS 能保证绝对安全。它保证的是**在其假设成立时不承担责任**，假设本身（如他车最大减速度）仍需标定。 |
| dual-system (fast-slow) | 快慢双系统 | 快系统高频低延迟做常规反应，慢系统低频做深度语义推理。 | **频率鸿沟与「思维链越长越准也越慢」两个约束的共同解**，DriveVLM 等的核心架构。 | 以为慢系统随时可以覆盖快系统。切换需要**明确的接管条件与超时策略**，否则慢系统的延迟会污染快系统的实时性。 |
| chain-of-thought latency | 思维链延迟 | 推理链每多一步就多一次前向，延迟线性增长。 | 它把「更准」与「更快」变成显式权衡，直接决定慢系统的调用频率。 | 以为思维链总能提升准确率。在**时间紧迫且证据充分**时，长链推理反而会引入自我说服式的错误。 |
| constrained decoding | 约束解码 | 在生成时限制词表或语法，强制输出符合 schema 或取值范围。 | 让「输出格式合法」从概率问题变成确定性问题，是结构化输出的工程标配。 | 以为它能保证语义正确。它只保证**语法与取值范围合法**，一个格式完美的错误动作照样能通过。 |
| shielding | 屏蔽 / 安全护盾 | 安全 RL 里的做法：在动作执行前用一个正确性模型过滤不安全动作。 | 与兜底层同源，提供了「学习系统 + 形式化保证」的组合范式。 | 以为屏蔽会大幅损害性能。设计良好的屏蔽**只在极少数状态下触发**，日常几乎不介入。 |
| explainable output | 可解释输出 | 模型同时给出动作和理由（「因为前方 80 米处限速 40 且路面湿滑，所以减速」）。 | 对调试、事故归因、用户信任三者都必要，也是 VLA 相对黑箱端到端的主要优势。 | **最重要的误解**：以为模型给出的理由就是它真实的决策依据。理由是**事后生成的文本**，与内部计算未必因果一致——它有诊断价值，但不能当作证据。 |
| instruction conflict | 指令冲突 | 用户指令与交通规则冲突（「快点开」vs 限速牌）。 | 必须有明确的裁决策略，且**法规永远优先**——这条要写死在架构里而不是 prompt 里。 | 以为在 system prompt 里写清楚就够了。用户可以通过多轮对话逐步侵蚀软约束，硬的必须在代码里。 |

## 六 · 评测与上车 · Evaluation & Deployment

| 术语 (EN) | 中文 | 一句话定义 | 为什么重要 | ⚠️ 常见误解 |
|---|---|---|---|---|
| open-loop evaluation | 开环评测 | 用记录好的数据，比较模型输出与专家轨迹的差异（L2 距离等）。 | 便宜、可复现、可大规模跑，是日常迭代的主力工具。 | **本课最重要的误解**：以为开环 L2 低就等于会开车。它不暴露误差累积，且极易被自车状态泄漏刷分。 |
| closed-loop evaluation | 闭环评测 | 模型的动作真实改变后续观测（仿真器或实车）。 | **唯一能暴露分布漂移与误差累积的评测方式**，也是真正与驾驶体验相关的那个。 | 以为闭环仿真就等于真实。仿真存在**渲染域差与他车行为不真实**两大问题，结论要谨慎外推。 |
| compounding error | 误差累积 | 模型的小误差改变了后续状态，使其进入训练分布之外，误差进一步放大。 | 它解释了「开环误差与闭环表现脱钩」这个核心现象，也是模仿学习的根本困难。 | 以为累积是线性的。在模仿学习的经典分析里，误差随时域**平方级**增长（T² 量级），这是本质差别。 |
| covariate shift | 协变量偏移 | 模型自己驾驶时遇到的状态分布与训练时专家演示的分布不同。 | 误差累积的形式化表述，DAgger 等方法都是为它设计的（原理见 C41）。 | 以为多收集数据就能解决。专家数据里**天然缺少「已经开偏了之后怎么办」**的样本。 |
| ego status leakage | 自车状态泄漏 | 模型可以从自车速度/加速度/历史轨迹外推出未来轨迹，几乎不需要看图像。 | **AD-MLP / BEV-Planner 的核心批判**：在 nuScenes 开环上，一个只吃自车状态的 MLP 就能接近 SOTA 的 L2。 | 以为这只是数据集缺陷。它揭示的是**指标设计的失效**：开环 L2 无法区分「会开车」与「会外推」。 |
| L2 displacement error | L2 位移误差 | 预测轨迹点与专家轨迹点的欧氏距离（常报 1s/2s/3s）。 | 开环评测的主流指标，几乎所有论文都报。 | 以为它可以横向比较。**评测协议差异巨大**（是否用自车状态、坐标系、采样率、是否用 GT 感知），跨论文比较基本无效。 |
| collision rate | 碰撞率 | 单位里程或单位场景数内发生碰撞的比例。 | 最直接的安全指标，闭环评测的第一指标。 | 以为开环也能算碰撞率。开环下的「碰撞」是**假设他车不反应**算出来的，与真实碰撞相关性很弱。 |
| rule violation rate | 规则违反率 | 单位里程内违反交通规则的次数（超速、压线、闯禁令、未停让）。 | **本课最相关的指标**：它直接度量 TSR → VLA 这条链路是否真的起作用。 | 以为它是 TSR 精度的同义反复。违反率同时包含**检测、关联、翻译、生命周期、执行**五段的失效，需要分解归因。 |
| traffic-sign compliance | 标志遵从率 | 在有标志约束的路段上，行为符合该约束的比例。 | 可以按标志类别分桶，是 TSR 下游最细粒度的效果指标。 | 以为只要检测对了就会遵从。**约束作用域与生命周期错误**同样会导致不遵从，而检测指标看不出来。 |
| hallucination rate | 幻觉率 | 模型报告的实体/约束中不存在于真值里的比例。 | **必须与漏检分开度量**：一个是「凭空多出来的约束」，一个是「丢掉的约束」，处置方式完全不同。 | 以为它等于误检率（FP）。幻觉常发生在**推理与描述层**（检测正确但描述编造），检测指标完全捕捉不到。 |
| takeover / disengagement rate | 接管率 | 单位里程内人类接管的次数。 | 量产系统的北极星指标之一，直接对应用户体验。 | 以为接管率低就是安全。**保守到不敢开也会降低接管率的某些统计口径**，必须与通行效率一起看。 |
| comfort metrics | 舒适度指标 | 加速度、加加速度（jerk）、横向加速度的分布与超阈次数。 | 用户能直接感知，且 VLA 输出的轨迹经常在这里翻车。 | 以为舒适度可以最后再调。它与安全约束**有时冲突**（紧急避让必然不舒适），需要在设计期就定优先级。 |
| scenario-based testing | 场景化测试 | 按失效模式与语义场景组织的小型测试集，每个场景配明确的通过判据。 | 比整体平均指标有用得多：**能定位到具体能力的回归**。 | 以为场景集越大越好。关键是**判据明确且与失效模式一一对应**，否则只是又一个平均指标。 |
| long-tail scenario bank | 长尾场景库 | 从路测与影子模式中挖掘出的稀有场景集合。 | VLA 的价值只在长尾体现，**不测长尾就测不出 VLA 的价值**。 | 以为场景库只能靠人工整理。可以用嵌入检索与自动标签批量挖掘（方法见 C58）。 |
| shadow mode | 影子模式 | 新模型在车上实时运行但不控车，只记录输出与差异。 | 上车的第一阶段：零风险地获得真实分布上的表现与分歧样本。 | 以为影子模式能验证安全性。它**看不到反事实**——不知道如果按新模型开会发生什么，只知道它和现行方案哪里不同。 |
| staged rollout | 分阶段放开 | 影子 → 限定场景/区域 → 逐步扩大 → 全量。 | 每一阶段有独立的准入门禁与回滚条件，是负责任发布的标准形态。 | 以为分阶段只是保守。它同时是**信息获取策略**：每阶段收集的数据决定下一阶段的门禁。 |
| distillation consistency | 蒸馏一致性 | 车端学生模型与云端教师模型在同一输入下输出的一致程度。 | 蒸馏的验收标准；**不只看平均一致率，要看关键场景与低置信区间的一致率**。 | 以为一致率高就等于能力保住了。一致率通常在**常见场景上很高、长尾上崩塌**，而长尾正是保留大模型的理由。 |
| agreement rate / KL | 一致率 / KL 散度 | 用 top-1 一致率、动作 L2 差、或输出分布的 KL 度量师生差异。 | 给蒸馏一致性一个可进门禁的标量。 | 以为 top-1 一致率够用。它丢掉了**分布信息**：学生可能选对了动作但完全丢失了多模态表达能力。 |
| quantization for VLA | VLA 量化 | 用 INT8/INT4 压缩权重与激活以满足车端算力与显存（方法见 C60）。 | 车端部署的必经之路。 | 以为量化掉点与普通模型类似。**长链推理会放大误差**：单步的小偏差在多步推理与多步去噪中会被逐级放大。 |
| observability | 可观测性 | 中间表示、注意力、约束状态、决策理由的可记录与可回放程度。 | **端到端系统最大的工程风险是不可测试**，可观测性必须在设计期规划而不是事后补。 | 以为多打日志就有可观测性。需要的是**结构化、可关联、可回放**的记录，而不是散落的字符串。 |
| regression gate | 回归门禁 | 发布前必须通过的一组硬性判据（关键场景不掉点、违规率不上升、延迟 p99 达标）。 | 把「感觉变好了」变成可执行的发布决策。 | 以为门禁只看总体指标。**必须包含分场景切片**，否则整体 +0.5 会掩盖某个关键场景 -5。 |
