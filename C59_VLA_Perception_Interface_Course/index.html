VLA 与感知接口

视觉-语言-动作模型（VLA）不是「给车装个聊天机器人」，而是把视觉-语言预训练的常识与推理接到动作输出上，用来吃掉规则永远写不完的那条长尾语义。但一个 VLA 的实际表现，取决于两个接口：感知怎么进来（TSR 的类别、距离、置信度、生命周期如何被序列化与融合），以及动作怎么出去（离散 token / 连续回归 / 扩散与流匹配，分块与分层）。本课把这两个接口拆到字段级别，并在最后给出评测与上车的完整判据。

怎么用： 每个模块先读 HTML 讲解，再跑 notebook——后者用纯 numpy 把每个机制从零复现：一个把动作离散化再还原的分箱误差分析器（给出 range/(2·B) 的闭式上界并实测验证）、一个能证明「回归会输出训练集里从未出现过的平均动作」的多模态实验、一套 TSR → VLA 的序列化 schema 与三种融合层次的 token 成本 / 信息量对比、一个把感知错误注入下游、测量动作错误率如何随置信度标定质量变化的实验、一台标志 → 约束的翻译器与生命周期状态机（含冲突消解与安全兜底校验）、以及一组把开环指标的失效亲手复现出来的误差累积模拟。每个练习都有紧跟的 assert 自测判分。配套 术语词典 与 参考清单。本课的主张是：VLA 的工程价值，八成不在模型本身，而在它两端的接口——喂进去的感知结果有没有带上不确定性与生命周期，以及吐出来的动作有没有被约束成物理可行、法规合规、可以被兜底层校验的东西。接口设计错了，模型再大也只是把错误输入合理化得更流畅。本环境不需要 GPU，也不需要装 torch / transformers / CARLA：我们复现的是这些系统的机制与账本（分箱误差、token 预算、置信度标定曲线、约束的作用域状态机、误差累积的增长率），而这恰恰是可迁移的那部分——模型会换代，账不会。每个模块末尾都有一个 🧪 真实工程胶囊，把当天的结论翻译成可以直接放进prompt 模板、schema 定义或评测脚本里的代码片段。最后一句提醒：本课会克制地、反复地说明 VLA 的能力边界。在面试里能主动说清「VLA 做不到什么」，比多背两个模型名字有用得多。
