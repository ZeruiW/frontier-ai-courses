1答题结构：先讲判断依据 → 再讲方案 → 最后讲验证

这是整批课程的收官模块。前面八门课给了你知识，模块 01–04 给了你方法论与叙事，这一节给的是把它们输出出去的统一外壳。所有题目——白板、原理、评测、部署、系统设计——都可以用同一个三段结构回答。

┌──────────────────────────────────────────────────────────────────┐ │ ① 判断依据（10–30 秒） │ │ 「我先看什么 / 我的假设是什么 / 为什么排除掉别的方向」 │ │ ↳ 这一段决定面试官给你的第一印象分。**必须在方案之前** │ │ │ │ ② 方案（60–120 秒，分层 + 排优先级） │ │ 「分三层：数据侧 / 模型侧 / 部署侧。优先级是 ___，因为 ___」 │ │ ↳ 分层 = 结构化思维；排优先级 = 有工程判断而不是罗列 │ │ │ │ ③ 验证（20–40 秒） │ │ 「我怎么证明它真的有用：切片 / 多种子 / 回归门禁 / 灰度」 │ │ ↳ **这一段是绝大多数候选人完全没有的**，加进去立刻区分开 │ │ │ │ ⇢ 然后停下来。把控制权交还给面试官，让他选深挖哪一层。 │ │ 一口气讲五分钟，等于替他做了取舍，而且大概率取舍错了。 │ └──────────────────────────────────────────────────────────────────┘

为什么必须判断在前、方案在后？因为「方案」是可背诵的，「判断」不是。你上来就说「我会用 copy-paste + 重采样 + Focal Loss」，面试官无法区分你是想清楚了还是背下来了；你先说「我会先看这个长尾是实例级的还是图像级的，因为前者用重采样会连带把 head 类的背景也重复采进来」——他立刻知道你处理过真实的长尾数据。

直白说

「先澄清问题」这件事有边界，用错了会显得拖沓。规则：题目里有未定义的关键量时才澄清，且一次问不超过两个。系统设计题必须澄清（不问约束的系统设计一定跑偏）；数据与评测题应该澄清一个（口径或场景）；白板题基本不用澄清——直接说出你的假设（「我假设是 xyxy 格式、不含 +1，如果贵司用的是 xywh 我改一下」）比反问更利落，因为它同时展示了你知道这里有分歧。

严谨说

还有一个被严重低估的技巧：说完骨架后主动停顿。多数候选人害怕沉默，于是一口气把所有知道的都倒出来，结果是——①面试官失去了引导的机会，无法探到你的深度；②你把时间用在了他不关心的分支上；③听感上像在背书。正确做法是给完三段结构后停下来，说一句「这三层里您想让我展开哪一层？」这句话本身就是一个信号：你知道这个问题有多个深度，且你有能力在任一层展开。它把面试从「考试」变成了「技术讨论」，而技术讨论里你的表现天然更好。

「我不知道」要说得有结构

被问到确实不会的东西，用三段式（模块 04 已给过，这里再强调一次，因为在题库演练里你会频繁用到）：①明确承认边界「这个我没有实操过」；②给相邻知识「但它要解决的问题是 ___，思路上应该是 ___」；③给行动方案「如果要落地我会先做 ___ 的最小验证」。切忌用「应该是」「大概」把不确定的内容说成确定的——一次被抓到，面试官会回头给你之前所有的陈述打折。

2白板题 I：IoU / NMS / soft-NMS

白板题不是在考你会不会写代码——检测岗位的候选人不会写不出 IoU。它考的是你写代码时暴露出来的工程习惯：边界条件的意识、复杂度的敏感、以及你知不知道这段代码在真实系统里的哪个位置、会出什么问题。

白板通用纪律（每一题都适用）

  1. 先口述思路和复杂度，再动手写。「排序 $O(N\log N)$，抑制循环最坏 $O(N^2)$，实际是 $O(NK)$，$K$ 是保留数」——这句话说出来，后面写慢一点也没关系。
  2. 先把边界情况列在白板角落：无交集 / 完全包含 / 退化框（宽或高为 0）/ 分数相同 / 空输入。列出来但暂不实现，写完主逻辑再回来补——这个顺序展示的是你先抓主干的能力。
  3. 明确说出你的假设：坐标格式（xyxy / xywh / cxcywh）、是否含 +1、坐标是像素还是归一化、score 是否已过 sigmoid。检测里 90% 的对不齐问题出在这四个假设上（见 C60）。
  4. 写完自己跑两个例子：一个正常的、一个边界的。主动验算比等面试官指出错误强得多。
  5. 写完补一句这段代码在系统里的位置：「实际部署时这段在 GPU 上做，或者用 TensorRT 的 EfficientNMS plugin；纯 Python 版本只用于离线评测」。

Q1 · 手写 IoU

\[\mathrm{IoU}(A,B) \;=\; \frac{|A \cap B|}{|A \cup B|} \;=\; \frac{|A\cap B|}{|A| + |B| - |A\cap B|}\]

交集用 max(x1)/min(x2) 求重叠区间，负宽负高必须 clip 到 0——不 clip 会得到「两个负数相乘等于正面积」的经典错误，两个完全不相交的框会算出一个正的 IoU。

项内容
考察点clip 到 0 / 分母为 0 的保护 / 是否会写向量化版本 / 知不知道 +1 的历史包袱
常见错误① 忘记 clip(w, 0)（不相交时算出正 IoU）；② 分母不做 max(union, eps)（退化框除零）；③ 写成 $|A\cap B| / |B|$（那是 IoF/IoA 不是 IoU）；④ 只会写标量版，面试官要 N×M 矩阵时卡住
加分点主动提「+1 问题」：早期 VOC/Faster R-CNN 代码用 (x2-x1+1)，因为把坐标当成闭区间的像素索引；现代实现（COCO/mmdet）不加 1。两边不一致会让框微妙地偏、评测结果对不上——这是 C60 讲的训练-部署不一致的经典来源。再主动提一句小目标的尺度不公平性：8×8 的框沿对角线位移 2 px，IoU 从 1.0 掉到 0.39（交 36 / 并 92），而 64×64 的框同样位移还有 0.88 —— 所以同一个 IoU 阈值对不同尺度是极不公平的（C57 模块 01）

Q2 · 手写 NMS

order = argsort(-scores)          # 稳定排序：分数相同时保持原顺序，结果才可复现
keep = []
while order:
    i = order[0]; keep.append(i)
    ious = iou(boxes[i], boxes[order[1:]])
    order = order[1:][ious <= iou_thr]     # 注意是 <=，等于阈值时不抑制
return keep
项内容
考察点排序稳定性 / 循环终止条件 / class-wise 还是 class-agnostic / 复杂度
常见错误① 忘了 class-wise——不同类别的框互相抑制，一个「限速 60」会把重叠的「路面湿滑」删掉；② 死循环（order 没缩小）；③ 用不稳定排序导致同分时结果不可复现；④ 阈值边界写反（< 与 <=）
加分点class-wise 的 offset 技巧：给每个框的坐标加上 label × (坐标最大值+1)，让不同类别的框在数值上永远不相交，然后调用一次 class-agnostic NMS 即可——这是 torchvision batched_nms 的真实实现。再补：实际部署会先做 top-k 预筛把 $N$ 钉死（比如 1000），因为 NMS 是整条推理链路上唯一一个耗时依赖输入数据的模块，$O(NK)$ 且 $N$、$K$ 都随场景复杂度增长（C53 模块 04 实测 log-log 斜率约 1.7）

Q3 · soft-NMS

贪心 NMS 的问题是硬删除：IoU 超过阈值就直接置零。在密集场景里（一根杆子上下挂两块牌、龙门架上一排限速牌），真实存在的相邻目标会被误删——而这个误删是不可恢复的。soft-NMS 把「删除」换成「降分」：

\[s_i \;\leftarrow\; s_i \cdot f(\mathrm{IoU}(M, b_i)), \qquad f_{\text{linear}}(u) = \begin{cases} 1 - u, & u \ge N_t \\ 1, & u < N_t \end{cases}, \qquad f_{\text{gauss}}(u) = e^{-u^2/\sigma}\]

高斯版是连续的（没有阈值处的跳变），$\sigma$ 通常取 0.5。代价有三个，必须一起说：①输出框数变多（不再删除，只降分），所以后面必须接一个 score 阈值，否则下游被大量低分框淹没；②增加了一个超参 $\sigma$；③在评测指标上通常涨 AP，但在固定工作点的 precision 上不一定更好——因为它把重复框留下来了，只是分数低。

直白说

什么时候 soft-NMS 真的值得用？目标高度重叠且重叠是真实的——密集人群、货架商品、以及 TSR 里的组合标志牌（一个限速牌下面挂一个「货车」辅助牌，两者的框重叠可能超过 0.5）。反过来，如果你的场景里重叠框基本都是同一个目标的重复检测，soft-NMS 只会让你多留一堆低分重复框。面试里能说出「这取决于你的重叠是真实的还是重复的」，比背两个公式有价值。

严谨说

更根本地看，soft-NMS 与 DETR 系的「无 NMS」是对同一个问题的两种回答。问题是：去重发生在哪里。NMS/soft-NMS 把去重放在推理期，靠几何启发式（IoU 阈值）做决定，因此必然存在「真实相邻目标」与「重复检测」无法区分的情形；DETR 把去重放在训练期，靠一对一匈牙利匹配让每个 GT 只有一个 query 负责，推理时天然无重复（C54 模块 01）。YOLOv10 的一致双分配证明了这条路不是 Transformer 的专利——CNN 密集预测器同样可以做到。能把「无 NMS 的本质是一对一标签分配，与架构无关」这句话说出来，是这一组题的最高分答案。

argsort 默认不稳定

白板最常见的当场翻车：写完 NMS 被问「那两个分数完全相同的框怎么办？」标准答案：用稳定排序（kind='stable'），保证结果可复现——不可复现的后处理会让你的回归测试随机失败，而这类 flaky 测试查起来极其痛苦。再被追问「numpy 的 argsort 默认是稳定的吗？」——不是，默认 quicksort（introsort）不稳定，必须显式指定。知道这个细节的人极少，它是一个很好的加分点。

3白板题 II：mAP / 匈牙利匹配 / Focal Loss / GIoU

这四题比第一组难一个档次。mAP 和匈牙利是「能不能完整推导一个流程」的测试，Focal 和 GIoU 是「知不知道每一项在解决什么问题」的测试。

Q4 · 手推 mAP

① 把某一类的所有预测框，按 score 降序排成一列（跨图像混在一起） ↓ ② 逐个判定 TP / FP：与该图 GT 算 IoU，取最大者 · IoU >= 阈值 且 **这个 GT 还没被更高分的预测认领** -> TP，标记该 GT · 否则 -> FP ← **「每个 GT 只能匹配一次」是最常被忘的一条** ↓ 忘了它，重复检测会全部算成 TP，AP 虚高 ③ 累积：cumTP[k], cumFP[k] Recall[k] = cumTP[k] / **GT 总数**（分母是 GT 数，不是预测数！） Precision[k] = cumTP[k] / (cumTP[k] + cumFP[k]) ↓ ④ 单调包络：从右往左取后缀最大值，把 PR 曲线的锯齿抹平 p_interp(r) = max{ p(r') : r' >= r } ↓ ⑤ 求面积 -> AP。**三种口径给出的数不一样**： · VOC2007 11 点插值 （粗，系统性偏高） · VOC2010+/面积法 （矩形分段求和，最常用） · COCO 101 点插值 （细，且对 IoU 0.50:0.05:0.95 十档取平均） ↓ ⑥ 对所有类别取平均 -> mAP。**注意是按类平均，不是按实例平均** -> 所以一个只有 12 个实例的稀有类，权重和一个上万实例的 head 类相同
\[\mathrm{AP} \;=\; \sum_{k}\bigl(r_k - r_{k-1}\bigr)\, p_{\text{interp}}(r_k), \qquad p_{\text{interp}}(r) = \max_{r' \ge r} p(r')\]
项内容
考察点每个 GT 只匹配一次 / recall 的分母 / 单调包络的方向 / COCO 与 VOC 的区别
常见错误① 忘记「每个 GT 只匹配一次」，重复框全算 TP；② recall 分母写成预测数；③ 包络从左往右取最大（方向反了）；④ 漏检的 GT 没有被计入（要在末尾补 recall=1、precision=0 的点，否则漏检不受惩罚）；⑤ 忽略 iscrowd/difficult 的 ignore 语义
加分点主动说清 COCO mAP@[.5:.95] 与 VOC mAP@0.5 的区别：前者对 10 个 IoU 阈值取平均，因此强烈奖励定位精度；后者只看 0.5，定位差一点也算对。在 TSR 上这个区别很关键：小目标的 IoU 天然低（8×8 框位移 2px 就掉到 0.39），用 COCO 口径会把小目标的分数压得很低，用 VOC 口径又看不出定位质量退化——所以我会两个口径都报，并且加一个按像素尺寸分桶的 recall（C55 模块 05）

Q5 · 匈牙利匹配（DETR 的一对一分配）

先讲为什么需要它：DETR 输出 $N=100$ 个无序的预测，GT 有 $M$ 个也是无序的，要算损失就必须先把它们对齐。而对齐必须是一对一的——正是这个一对一约束在训练期压制了重复预测，使推理期不需要 NMS。

为什么不能贪心？给一个 2×2 的反例就够了：代价矩阵 $\begin{pmatrix}1 & 2\\ 2 & 100\end{pmatrix}$。贪心先挑全局最小的 1（行 0 配列 0），行 1 只剩列 1，总代价 $1+100=101$；最优解是行 0 配列 1、行 1 配列 0，总代价 $2+2=4$。贪心的问题是「局部最优会锁死后续的选择」——这个反例值得背下来，30 秒就能在白板上写出来。

代价矩阵的三项（DETR 原文）：

\[\mathcal{C}_{i,j} \;=\; -\,\lambda_{\text{cls}}\,\hat{p}_i(c_j) \;+\; \lambda_{\text{L1}}\,\lVert \hat{b}_i - b_j \rVert_1 \;+\; \lambda_{\text{giou}}\,\bigl(-\mathrm{GIoU}(\hat{b}_i, b_j)\bigr)\]

三个细节值得主动说：①分类项用概率而不是 log 概率（用 log 会让分类项数值上压倒框项，匹配退化成「只看分类」）；②框必须归一化到 $[0,1]$，否则 L1 项的尺度依赖图像大小；③匹配阶段的代价与损失函数不完全相同（匹配用概率，损失用 focal/CE），这是很多人没注意的。

项内容
考察点为什么需要匹配 / 为什么贪心不行 / 代价三项 / 复杂度 $O(n^3)$ / 为什么一对一能替代 NMS
常见错误① 说成「就是找 IoU 最大的 GT」（那是一对多分配，不是二分匹配）；② 忘了 no-object 填充（预测数 $N$ 通常远大于 GT 数 $M$，多出来的匹配到 $\varnothing$）；③ 说不出复杂度
加分点主动提匹配不稳定性：同一个 GT 在相邻 epoch 可能被不同 query 认领，导致优化目标抖动、收敛慢——这正是 DN-DETR 用带噪 GT 作为额外 query「绕过匹配」的动机，也是 DINO 对比去噪的起点（C54 模块 04）。再补一句：一对一是推理需求，不是训练最优——Group DETR / H-DETR / Co-DETR / DEIM 都在训练期加一对多分支提供密集监督，推理时丢掉

Q6 · Focal Loss

\[\mathrm{FL}(p_t) \;=\; -\,\alpha_t\,(1-p_t)^{\gamma}\,\log p_t, \qquad p_t = \begin{cases} p, & y = 1\\ 1-p, & y = 0\end{cases}\]

$\gamma$ 和 $\alpha$ 管的是两件不同的事，这是本题的核心考点：$\gamma$（focusing parameter，典型 2.0）按难度加权——已经分对的样本 $p_t \to 1$，$(1-p_t)^\gamma \to 0$，损失被压到接近零；$\alpha$（典型 0.25）按类别加权——直接给正负样本不同的固定权重。只有 $\alpha$ 解决不了问题，因为一阶段检测器的负样本不仅多（$10^4$ 量级 vs 十几个正样本），而且绝大多数是极易分的背景，它们单个损失很小但数量巨大，累加起来仍然压倒前景。

一个可以直接报的数字：一个 logit $=-6$ 的易分负样本，$p \approx 0.0025$，$\gamma=2$ 时它的损失被压到 $\gamma=0$ 时的 $p^2 \approx 6\times10^{-6}$ 倍；梯度贡献被压到约 $1.8\times10^{-5}$ 倍（notebook 会数值验证）。而一个 logit $=0$ 的难样本只被压到 $0.25$ 倍——这个「压易不压难」的比例差，就是 Focal Loss 的全部作用。

数值稳定 + prior bias 初始化

白板写 Focal 的两个陷阱：①数值稳定——直接写 -log(sigmoid(x)) 在 $x$ 很负时会下溢成 inf；正确写法是用 logits 形式的稳定 BCE：max(x,0) - x*y + log1p(exp(-|x|))。②初始化偏置——RetinaNet 论文里把分类头最后一层的 bias 初始化成 $-\log((1-\pi)/\pi)$（$\pi=0.01$），让训练初期模型对所有 anchor 都输出 0.01 的前景概率，否则前几个 iteration 的损失会被海量负样本主导而发散。这个细节能说出来是很强的信号，因为它只有真的训过一阶段检测器才会知道。

Q7 · GIoU 及其变体

\[\mathrm{GIoU}(A,B) \;=\; \mathrm{IoU}(A,B) \;-\; \frac{|C \setminus (A \cup B)|}{|C|}, \qquad C = \text{包围 } A,B \text{ 的最小轴对齐框}\]

它解决的问题：IoU 在两框不相交时恒为 0，梯度也是 0——模型不知道「差一点点」和「差很远」的区别，无法优化。GIoU 加的惩罚项让不相交时仍有梯度，且随距离单调变差，值域是 $[-1, 1]$。

变体在 GIoU 基础上加了什么解决什么代价 / 何时不必要
GIoU最小包围框的空白面积惩罚不相交时无梯度两框包含时惩罚项退化为 0，此时与 IoU 无异；收敛慢
DIoU中心点距离惩罚 $\rho^2(b,b^{gt})/c^2$直接拉近中心，收敛更快；还可用于 NMS（DIoU-NMS 对遮挡场景更友好）不管长宽比
CIoUDIoU + 长宽比一致性项 $\alpha v$同时管重叠、中心、长宽比多一个超参；长宽比项的梯度在极端形状下不稳定
EIoU / SIoU把长宽分别惩罚 / 引入角度项CIoU 的长宽比项是「比例」而非「尺寸」，EIoU 直接惩罚 $w,h$ 差边际收益小，选择往往取决于具体数据
NWD把框建模成 2D 高斯，用 Wasserstein 距离对尺度不敏感，且不相交时仍平滑——小目标的正解不是 IoU 的直接替代，阈值语义要重标定（C57 模块 03）

直白说

被问「这几个你会选哪个」时，不要选一个然后夸它。正确的回答形状是：「默认我会先用 CIoU 或 GIoU 做 baseline，因为它们是社区默认、可比性最好；然后我会按误差分析来选——如果 TIDE 分解显示我的损失主要在 Loc 且集中在小目标桶，我会试 NWD 或对小目标放宽分配阈值；如果损失主要在 Miss，换 IoU 变体基本没用，该去改分配和数据。」

严谨说

背后的通用原则值得单独说出来：损失函数的选择应该由误差分解驱动，而不是由论文的排行榜驱动。IoU 变体全部作用在已经被分配为正样本的框上——如果你的问题是「小目标根本分不到正样本」，那么换多少种 IoU 变体都不会有效果，因为那些框压根没进损失。这个「先定位损失落在哪一环，再选工具」的思路，是模块 02（误差分析）与本模块之间的桥。在面试里，能主动说明「什么情况下我这个方案是无效的」，比方案本身更值钱——它证明你的知识是有结构的，不是一堆并列的名词。

Q8 · DETR 为什么不需要 NMS？

项内容
面试官想听你知道这来自训练期的一对一标签分配，而不是某种推理技巧或架构魔法
骨架「因为去重被提前到了训练期。DETR 用匈牙利算法在 $N$ 个预测和 $M$ 个 GT 之间做一对一的最优匹配，每个 GT 只有一个 query 被判为正样本，其余全部被推向 no-object 类。训练完成后，多个 query 对同一个目标同时给高分这件事本身就被压制了，所以推理时直接输出即可。对比之下，密集预测器用的是一对多分配（一个 GT 匹配多个 anchor/位置），必然产生重复，只能在推理期用 NMS 删掉。所以「无 NMS」的本质是一对一分配，跟 Transformer 无关——YOLOv10 用一致的双分配（训练时一对多 + 一对一双头，推理只留一对一）在 CNN 上做到了同一件事。」
加分点补代价：「一对一的代价是监督信号极稀疏——每张图只有 $M$ 个正样本，加上匹配在相邻 epoch 会翻转，导致 DETR 要 500 epoch 才收敛。后续工作全在补这个：Deformable 加稀疏采样、DN-DETR 用带噪 GT 绕过匹配、DINO 加对比去噪、Group/Co-DETR 训练时加回一对多分支。这说明「一对一」是推理需求，不是训练最优。」
踩雷点说「因为 Transformer 有全局注意力所以不会重复」——这是错的，与注意力无关；说「因为只有 100 个 query 所以不会重复」——query 之间同样可以预测同一个目标，是 self-attention + 一对一匹配共同压制的

Q9 · RT-DETR 凭什么比 YOLO 快？

项内容
面试官想听你能把「快」拆成「计算量更省」和「延迟更稳」两件独立的事
骨架「四点。①无 NMS——删掉了整条链路上唯一一个耗时依赖输入数据的模块，端到端延迟变成常数。②efficient hybrid encoder——self-attention 只在最高层 S5 的 400 个 token 上做（AIFI），跨尺度融合全用卷积（CCFF）；如果三尺度拼成 8400 token 做全局 attention，光二次项就贵 205 倍；判据可以手算：$2(HW)^2d + 4HWd^2 < 9HWd^2 \iff HW < \tfrac52 d$，$d=256$ 时交叉点是 640 token，S5 的 400 在下面、S4 的 1600 在上面。③uncertainty-minimal query selection——按分类与定位一致的分数选 300 个 query，给 decoder 一个准的起跑线（可变形注意力只在参考框附近采样，起跑线歪了救不回来）。④decoder 层数可调——每层都有辅助头，推理时截断到 $k$ 层，一份权重出多档速度。」
加分点把均值和方差分开：「平均只省 1–3 ms，这部分 GPU NMS 也能压；压不掉的是方差——NMS 是 $O(NK)$，$N$、$K$ 都随场景复杂度增长，实测 log-log 斜率约 1.7，目标数翻 10 倍耗时涨约 50 倍。于是延迟尖峰恰好出现在场景最复杂、最需要及时反应的时候。对实时系统这意味着 WCET 无法静态确定。」
踩雷点只说「去掉了 NMS 所以快」；把 hybrid encoder 说成「一个高效的 Transformer 编码器」（它 90% 以上的计算量是卷积）

Q10 · 标签分配的演进讲一下

项内容
面试官想听你知道标签分配比 backbone 更影响精度，且能说出每一步在解决前一步的什么问题
骨架「一条主线：从「按几何规则固定分配」走向「按模型当前状态动态分配」。①静态 IoU 阈值（Faster R-CNN / RetinaNet）：阈值是拍的，对不同尺度和形状极不公平，小目标几乎匹配不到正样本。②ATSS：用每个 GT 的候选 anchor 的 IoU 均值 + 标准差做自适应阈值，把「阈值该多少」交给数据。③OTA / SimOTA（YOLOX）：把分配看成最优传输问题，代价 = 分类 + 回归，每个 GT 的正样本数 dynamic-k 由其 top-k IoU 之和决定——目标质量好就多给几个。④TaskAligned（TOOD/YOLOv8）：用 $t = s^\alpha \cdot u^\beta$（分类分数 × 定位质量）做对齐度量，直接解决分类头与回归头不一致。⑤RTMDet 的 dynamic soft label：把硬正负标签换成软标签，代价里含中心先验。⑥一对一（DETR / YOLOv10）：为了去掉 NMS。」
加分点落回 TSR：「分配策略对小目标和密集场景影响最大。静态 IoU 阈值下，8×8 的标志几乎没有 anchor 能超 0.5，正样本严重稀缺；ATSS 的自适应性和 SimOTA 的 dynamic-k 天然更公平，这是我在小目标任务上优先考虑动态分配的原因。」
踩雷点只罗列名字不说动机；说不出「一对多 vs 一对一」的本质差别（前者提供密集监督，后者提供无重复输出）

Q11 · anchor-free 的本质是什么？

项内容
面试官想听你知道 anchor-free 不是「去掉了一个组件」，而是换了一种正样本定义方式
骨架「本质是把「哪个位置负责这个目标」的判定，从「预设框与 GT 的 IoU」换成了「位置本身的属性」。anchor-based 需要预设一组尺度/长宽比的框，用 IoU 阈值判正负；anchor-free（FCOS / CenterNet / YOLOX）直接问「这个特征点是否落在 GT 内部 / 是否靠近中心」，然后回归到四条边的距离或中心+宽高。好处三个：①去掉了 anchor 尺度、长宽比、数量这些需要按数据集调的超参；②正样本不再受 IoU 阈值的尺度偏见；③输出通道数大幅减少，部署更简单。但它并没有消灭「分配」这个问题——只是把它从 IoU 阈值换成了中心先验 + 尺度范围，后来又被 ATSS 证明：anchor-based 和 anchor-free 的性能差距，主要来自分配方式而不是有没有 anchor。」
加分点「ATSS 那篇论文的核心实验就是：把 RetinaNet 和 FCOS 的分配方式统一之后，两者性能几乎相同。这基本终结了「anchor 有没有用」的争论——真正的变量一直是分配。」
踩雷点说「anchor-free 更快」（推理速度差别很小，主要差别在超参和分配）；说不出它仍然需要某种正负样本定义

Q12 · FPN 的层级分配规则是什么？为什么小目标要单独考虑？

项内容
面试官想听你能写出分配公式，并且知道它在小目标上会失效
骨架「FPN 的思路是让不同尺度的目标由不同分辨率的特征层负责。经典分配规则来自 FPN 论文的 RoI 分配：$k = \lfloor k_0 + \log_2(\sqrt{wh}/224) \rfloor$，$k_0=4$——224 是 ImageNet 预训练的尺度，所以一个 224 像素的目标去 P4，目标每缩小一半就下降一层。问题在于层数是有下界的：常见检测头只到 P3（stride 8），按公式一个 28 像素的目标就已经该去 P2 了，但 P2 不存在，于是全部小目标挤在 P3 上。而在 stride 8 的特征图上，一个 8 像素的标志只占 1×1 个格子——它的空间信息在下采样里基本被抹掉了。」
加分点给出代价的量化：「加 P2 层能直接改善小目标，但 token 数是 P3 的 4 倍，计算量和显存按分辨率平方增长。所以量产上更常见的是三条便宜路线：①提高输入分辨率（代价线性于面积，比加层可控）；②两级级联——低分辨率全图找 ROI，高分辨率精检 ROI；③改分配与度量（center-based、NWD），让小目标至少能拿到正样本。选哪条完全取决于延迟预算，这也是我在 TSR 上做过的取舍。」
踩雷点把 FPN 和 PAN 混为一谈（PAN 多了自底向上的第二条路径，补的是定位信息）；说不出加 P2 的代价量级

直白说

五道题连起来看，会发现它们其实是同一条主线的五个切面：检测器的核心问题一直是「哪个位置该为哪个目标负责」。anchor-based 用预设框 + IoU 阈值回答，anchor-free 用中心先验回答，ATSS/SimOTA 用数据统计动态回答，FPN 用尺寸分层回答，DETR 用匈牙利匹配一对一回答。backbone 和 neck 只是在提供特征，真正决定精度上限的是这个「负责关系」怎么定。

严谨说

所以被问到任何一道架构题时，都可以往这条主线上收：「这个设计改变的是正负样本的定义 / 监督信号的密度 / 还是特征的表达能力？」这三类的收益量级差别很大——改分配通常带来 1–3 AP 且几乎零推理代价；改特征表达（更大 backbone、更多层）带来的收益递减且直接换成延迟；改监督密度（辅助头、深监督、一对多分支）主要影响收敛速度与训练成本，推理时可以完全丢掉。能把一个新方法归到这三类里的哪一类，比记住它的名字有用得多——而且这正是面试官问「你怎么看某某新工作」时想听到的分析框架。

五道题的共同答题结构：先给一句结论式的判断（「本质是标签分配从一对多变成一对一」），再讲机制，再给一个关键数字，最后给代价。缺「数字」显得没做过；缺「代价」显得没上线过。把每题的那个关键数字背下来（205×、$HW=2.5d$、$k_0=4$、$t=s^\alpha u^\beta$、0.39），比背整篇论文有效。

Q13 · 交通标志类别极度长尾，你怎么处理？

先澄清一个问题再答：「这个长尾是实例级的（某些类的框特别少）还是图像级的（含稀有类的图片本身就少）？两者的解法不同——图像级长尾用图像重采样会连带把该图里的 head 类实例也重复采进来。」问出这一句，这题的分基本就拿到了。然后分五层给方案：

层次手段为什么有效 / 代价优先级判断
① 数据侧Copy-paste（把稀有类实例抠出来贴到新背景）；定向挖掘回传；repeat factor sampling $r_c = \max(1, \sqrt{t/f_c})$直接增加稀有类的正样本数与背景多样性。代价：合成样本有域差；重采样有过拟合风险，尾部类可能只是把同几张图看了 20 遍最先做——收益最直接，且不改模型不影响部署
② 损失侧Focal Loss；Class-Balanced Loss（有效样本数 $(1-\beta^n)/(1-\beta)$）；EQL / EQLv2（检测特有：稀有类被海量负梯度淹没）；LDAM不改数据分布，改梯度分布。代价：多超参，且与重采样叠加时容易「补偿过头」第二做。注意别和重采样同时上，否则归因不清
③ 推理侧logit adjustment（推理时按类别先验修正 logit）；解耦训练（表示用原分布学，分类器用平衡数据重训）零训练成本，理论优美（等价于把训练的后验修正回目标分布）。解耦训练非常实用性价比最高，很多人不知道，主动提是加分点
④ 架构侧两级架构：检测器只做类别无关 / 粗类检出，第二级高分辨率 crop 分类器细分几百类把长尾问题从检测器移到分类器——分类器可以用更高分辨率、更容易做重采样、新增标志类别不必重训检测器。代价：延迟叠加、误差级联（级联召回 = 检测召回 × 分类准确率）TSR 量产系统的主流选择，一定要提
⑤ 评测侧按类别频段分桶报指标（head / mid / tail）；关键类别单独看；mAP 是按类平均的，本来就已经放大了尾部权重不改任何东西，但决定了你能不能看见问题最先做（比 ① 还先）——看不见就改不动

Q14 · mAP 不够用怎么办？你会怎么设计 TSR 的评测体系？

骨架：「mAP 有五个不足：①按类平均掩盖了关键类（漏检『停车让行』和漏检『景点指示』完全不是一回事）；②与距离/像素尺寸无关；③无时序（闪烁、误报持续时长看不出来）；④不反映误检的绝对量（precision 是比例，工程要的是 FP 的绝对频率）；⑤与下游动作脱节。所以我会在 mAP 之外加四类指标：

  • 分桶指标：按像素尺寸 / 距离 / 光照 / 天气 / 遮挡度分桶的 recall 与 FP。这是最重要的一条——不分桶的评测看不见小目标退化。
  • 代价敏感指标：给关键类别加权（禁令类 > 警告类 > 指路类），得到一个风险加权的漏检率。
  • FP per km / per hour：工程语言。「precision 0.98」听不出严重性，「每公里 3 次误报」下游立刻知道能不能接受。
  • 时序稳定性：首次检出距离、闪烁次数（confirmed↔lost 的翻转率）、误报持续时长。这些指标只有把评测做成视频序列级才能算出来。

「最后是回归门禁：每个失效模式建一个小的场景化回归集，新模型要发布必须满足『目标场景涨、其他场景不掉超过容差』，且容差要考虑种子方差。这一整套的目的是让评测结果能直接翻译成「能不能上车」，而不是一个论文数字。」

Q15 · +0.3 mAP 算提升吗？

直白说

标准答案是「不一定，我需要先知道三件事」：①你跑了几个种子？检测任务同配置不同种子的 mAP 波动典型在 ±0.2–0.5，单种子的 +0.3 落在噪声范围内。②你用的是同一个评测口径和同一个工作点吗？换了 score 阈值就是在 PR 曲线上滑动，不是真的涨。③分场景切片是什么样的？总 mAP +0.3 完全可能是「夜间 +3、白天 −1」的合成结果，而白天占数据的 80%——那么这个改动上线后是负收益。「回答完这三条，我会说：如果要确认 +0.3 是真的，我需要 5 个以上种子做配对检验，或者直接问一个更有用的问题——这个改动在我关心的那个切片上涨了多少。」

严谨说

这道题是面试里性价比最高的一题，因为它极短、极常问，而且绝大多数候选人会直接答「算」或「不算」。给出「我需要先知道三件事」这个形状的回答，展示的是三个不同能力：统计素养（知道方差的量级）、评测纪律（知道口径和工作点会让数字不可比）、业务判断（知道总指标会掩盖切片）。更进一步的加分：主动提功效分析——「如果我确实想检出 +0.3 这个量级的效应，在 $\sigma=0.35$ 的情况下，配对设计大约需要 8–10 个种子才有 80% 的把握；如果我只能跑 3 个种子，那我应该去追求更大的效应，而不是把预算浪费在验证一个测不出来的差异上。」这句话会让面试官记住你（C61 模块 01 有完整推导）。

Q16 · 线上某类标志突然漏检，你的排查流程？

骨架（二分定位思路）：「第一刀切在「离线能不能复现」。①拿到线上回传的原图，用离线模型跑一遍：如果离线也漏 → 是模型/数据问题；如果离线正常而车上漏 → 是部署一致性问题（预处理 / 量化 / 后处理 / 算子 fallback），转 C60 的三层对拍。②如果是模型问题，第二刀切在「是没检出还是检出了被过滤掉」——把 score 阈值降到 0.01 看看框在不在。在但分数低 → 是模型信心不足（数据/难例问题）；根本没有框 → 可能是分配/尺度问题（这个类的目标尺寸落在了哪个桶？）。③然后做分桶归因：这个类是不是新出现的变体？是不是只在某个场景（夜间/逆光）漏？混淆矩阵里它被错分成了什么？④最后才是动手：定向挖掘 + 定向增强 + 回归验证。整个流程的原则是：每一步都要把假设空间砍一半，而不是先改一个东西看看有没有用。」

这一组题的共同结构：先澄清一个关键定义 → 分层给方案 → 排优先级 → 给验证方式。四步里最容易被跳过的是「排优先级」——罗列五个方案而不说先做哪个，等于把决策推给了面试官，而决策能力正是他要考察的东西。

Q17 · INT8 量化后 mAP 掉了 3 个点，怎么排查？

INT8 掉点 3 分 │ ┌───────────┴────────────┐ │ ① 先排除非量化因素 │ ← **最容易被跳过，也最容易中** │ · FP32 engine 的 mAP │ │ 和 PyTorch 对得上吗？│ │ · 预处理两边一致吗？ │ └───────────┬────────────┘ 对不上 → 不是量化问题，去查 C60 m01（预处理）/ m04（后处理） │ 对得上 ┌───────────┴────────────┐ │ ② 校准集诊断 │ ← **真实事故里占比最高** │ · 用了多少张？(几百~上千)│ │ · **覆盖夜间/逆光/雨天/ │ │ 隧道口了吗？** │ │ · 预处理与线上完全一致？│ │ （用训练集头 500 张 = │ │ 可能全是晴天白天） │ └───────────┬────────────┘ │ 校准集没问题 ┌───────────┴────────────┐ │ ③ 换校准算法 │ │ MinMax（被离群值毁灭） │ │ → Entropy/KL（TRT 默认）│ │ → Percentile 99.9% │ └───────────┬────────────┘ │ 仍掉点 ┌───────────┴────────────┐ │ ④ 逐层敏感度分析 │ │ 只量化第 i 层 → 测 mAP │ │ 排序找出敏感层 │ │ → 敏感层保 FP16（混合精度）│ │ → per-tensor 改 per-channel│ └───────────┬────────────┘ │ 仍掉 > 1-2 分 ⑤ QAT（fake quant + STE） 最后手段：训练成本高

三个必须主动补的细节：①检测模型的分类头与回归头敏感度不同，通常回归头对量化更敏感（输出是连续值，误差直接变成框偏移）；②小目标掉得更多——所以「掉 3 个点」这个总数没意义，必须按尺寸分桶看，很可能是「大目标掉 0.5、小目标掉 8」；③一定要检查静默回退——不支持的算子被切成子图交给别的后端，模型能跑但不快也可能不准，症状是「转了 TRT 但没变快」，要看分区数与各分区后端。

Q18 · 离线 mAP 0.82，车上跑起来像 0.6，怎么查？

骨架：三层二分 + 对拍工具。「我的主张是任何一致性问题都能在半小时内定位到具体层，只要你有对拍工具。三层是预处理 / 模型本体 / 后处理，逐层用同一张图 dump 两边的张量做逐元素 diff。

层最常见的三个坑怎么验（通过条件）
预处理①BGR/RGB 弄反（模型照样跑，mAP 掉 10+ 分）；②resize 算法与语义不同（OpenCV INTER_LINEAR vs PIL bilinear vs torch 的 align_corners；缩小时 INTER_AREA 与 INTER_LINEAR 差别巨大）；③letterbox 分歧（padding 值 114 还是 0、居中还是左上、缩放比是否取整）同一张图两边 dump 预处理后的张量，np.abs(a-b).max() 应 < 1e-4（uint8 输入时应严格为 0）
模型本体①ONNX 导出的 opset 不匹配 / 动态 shape profile 不含实际 shape；②FP16 溢出层（激活范围超出 65504）；③算子静默回退成 FP32 或切给别的后端先 PyTorch vs onnxruntime 对齐（atol=1e-4），再 onnxruntime vs TRT。分区数必须 == 1
后处理①letterbox 逆变换写错（症状：框整体平移或整体缩放，是「框都偏一点」最常见的原因）；②NMS 实现差异（class-wise vs agnostic、top-k 截断、IoU 的 +1）；③sigmoid/softmax 放在模型内还是外，重复做或漏做从图像文件到最终框做端到端对拍，逐阶段 diff；框整体偏移优先怀疑逆变换，框零散不同优先怀疑 NMS

Q19 · 怎么测延迟？为什么关心 p99？

直白说

「测法：warmup 丢弃前几十次（首次调用有 CUDA context 初始化与 kernel 加载）→ 显式同步（异步 API 不同步测出来是提交时间不是执行时间）→ 跑几百上千次取分布而不是均值 → 报 p50 和 p99。而且必须用目标数差异很大的真实帧，不能同一张图跑一千次——那测不出 NMS 的数据依赖性。为什么是 p99：车端是实时系统，安全关心的是最坏情况。均值 8 ms 但 p99 是 25 ms 的模型，会周期性丢帧，而丢帧恰好发生在场景最复杂的时候。」

严谨说

再往深一层是车端特有的三个延迟来源，多数候选人完全想不到：①功耗墙与降频——持续满负载下 SoC 会降频，延迟随时间漂移，所以验收必须做长时间稳定性测试（跑满 30 分钟看延迟曲线），而不是测 1000 次就完事；②多任务抢占——TSR 只是众多感知任务之一（BEV 检测、占用栅格、车道线、红绿灯），它们在共享算力上排期，你的 p99 取决于别人的负载；③内存拷贝——H2D/D2H 常常占端到端的大头，而论文的 FPS 基本都不含它。能说出「所以我报延迟一定会写清口径：batch、卡型、含不含预处理与 NMS、什么精度、warmup 多少、p50 还是 p99」，这题就满分了——因为它同时展示了测量素养和对论文数字的批判性。

给范围 + 给决定因素，不要给死数字

这组题最容易翻车的地方是「说得太笃定」。比如被问「INT8 掉点一般多少」时答「一般掉 1 个点」——这个数字强烈依赖模型结构、任务、校准集，说死了会被追问到崩。正确的形状是给范围 + 给决定因素：「纯卷积检测器 PTQ 通常在 0.5–2 mAP，但 attention 与 LayerNorm 对 INT8 更敏感，DETR 系常常要混合精度；具体掉多少取决于校准集覆盖度和有没有做逐层敏感度分析——这也是我一定会先做敏感度分析再下结论的原因。」

7系统设计题：把八门课拼成一个闭环

系统设计题没有标准答案，但有标准的结构。面试官评的是：你会不会先问约束、会不会定义成功指标、会不会分层、会不会说取舍、有没有验证与演进的意识。

系统设计题的六步框架（任何题都能套） ① 澄清约束（**必做，1–2 分钟**） 算力平台？延迟预算？数据规模？标注预算？团队规模？现有基线？ ↳ 不问约束就开画，是这类题最大的扣分项 ② 定义成功指标 「这个系统做成什么样算成功」——**用可测量的指标，不用形容词** TSR：分尺寸桶的 recall、FP/km、首次检出距离、p99 延迟 ③ 分层画架构 数据层 / 训练层 / 评测层 / 部署层 / 反馈层，每层给 2–3 个关键选择 ④ 每层说取舍 「这里我选 A 不选 B，因为约束是 ___；如果约束变成 ___ 我会换 B」 ⑤ 验证与门禁 分场景切片 + 回归门禁 + 灰度/影子 —— **这一步是区分度所在** ⑥ 演进路线 「第一版先做 ___（2 周能出）；第二版加 ___；长期做 ___」 ↳ 展示你知道什么该先做，而不是一次画一个完美但落不了地的图

Q20 · 设计一个 TSR 的数据-模型-评测-部署闭环

这是 JD 的「What Success Looks Like」原话对应的题目，务必准备到能画图讲 10 分钟。骨架：

Q21 · 让我们把某个场景（比如夜间）的 recall 提升 10 个点，你会怎么做？

骨架：「先做三件不花钱的事：①确认这 10 个点的空间在哪——夜间桶的 TIDE 分解，是 Miss 还是 Cls？如果是 Cls，说明目标看见了但认错了，那是分类能力问题不是曝光问题；②看混淆矩阵——夜间的错误是不是集中在几对特定类别（反光的背面 vs 正面）；③统计夜间数据占比——如果训练集夜间只占 3% 而线上占 25%，那第一优先级就是采样配比而不是模型。然后才分层给方案：数据侧（定向挖掘夜间数据 + 低光合成增强 + copy-paste 到夜间背景）、损失/采样侧（提高夜间样本权重）、模型侧（如果确认是曝光导致的信息丢失，考虑输入端的 ISP 对齐或增加曝光增强）、评测侧（夜间必须单独成为一个门禁切片）。最后给验证：夜间切片涨多少、白天切片不许掉超过容差、多种子确认、影子模式两周。并且我会先给一个「不做什么」的判断：我不会一上来就换更大的模型，因为夜间问题通常不是容量问题。」

Q22 · TSR 的输出怎么接入 VLA / 下游规控？

直白说

「三种融合层次：①符号/文本级——把检测结果序列化成结构化文本塞进 prompt，可解释、易调试，但有信息损失且占 token；②特征级——感知特征作为额外 token 或通过 cross-attention 注入，信息全但不可解释；③中间表示级——BEV query / 场景 token 共享，是量产系统的主流。无论哪一层，schema 里必须有置信度——不传置信度等于强迫下游把所有检测当成真的，这是感知-决策接口最常见的设计错误。字段至少要有：类别、位置（图像坐标 + 相对自车的距离）、尺寸、置信度、跟踪 ID、首次检出时间、关联车道。」

严谨说

更值得说的是下游怎么消费：标志语义要翻译成可执行约束——限速牌 → 速度上限；禁左 → 轨迹候选屏蔽；停车让行 → 必须完全停止的时空约束；解除牌 → 撤销之前的约束。而约束的「作用域与生命周期」是最容易出错的地方：从哪里开始生效、到哪里失效、被什么解除、和地图限速冲突时谁优先（临时施工牌 > 可变电子牌 > 固定标志 > 地图先验，大致如此但要按法规定）。最后一定要补一句安全兜底：VLA 的输出必须经过规则层与安全层的可行性校验，这是量产系统的红线——因为端到端模型会「合理化」错误的感知输入，感知错了它不会报错，它会给你一个自洽但危险的动作。（C59 模块 03/04）

优先级 + 回滚路径

系统设计题的两个隐形扣分项：①画了一个完美但没有优先级的图——什么都有，但说不出「如果只有两周先做哪块」；②只讲了正向流程，没讲失败与回滚——线上模型出问题怎么回滚？回滚需要多久？有没有降级路径（比如 RT-DETR 的 decoder 层数可调，负载高时降级而不是丢帧）？补上这两点，你的答案会比 90% 的候选人完整。

三个万能的高质量反问

  1. 「如果我入职，前三个月最想让我解决的问题是什么？」——它同时做三件事：展示你以交付为导向、获取关于岗位真实内容的信息、以及让面试官在脑子里把你放进那个位置想象一遍（这个心理效应是真实的）。
  2. 「你们现在最痛的是数据、算法还是工程？」——这个问题会得到非常诚实的回答，而且答案直接决定了你要不要来。如果答案是「工程」而你的强项是刷点，这个信息比 offer 本身更有价值。
  3. 「我今天的回答里，有没有哪部分让您觉得还需要补强？」——高风险高回报。它展示了极强的自我改进意愿，而且你会得到真实反馈；但如果你前面表现明显不佳，这个问题会让气氛尴尬。建议只在自我感觉良好或至少中性时使用。

直白说

还有一个战术细节：反问的问题要在面试过程中即时更新，而不是照着准备好的清单念。如果面试官在讲解题目时提到「我们现在小目标还比较头疼」，你的反问就应该变成「您刚才提到小目标，你们现在是走高分辨率还是两级级联这条路？」——这证明你在认真听，而且能把对话内容转化成有针对性的问题，这比任何准备好的问题都强。

严谨说

面试结束后还有两个低成本高回报的动作。①当天写一封简短的跟进邮件：三句话——感谢、重申一个你认为最匹配的点、补充一个你当时答得不够好的问题的完整答案。第三句是关键：它把一次失误转化成了「这个人会复盘、会补课」的正面信号，而且给了面试官一个在评审会上替你说话的材料。②自己做一份复盘：哪些题答得好、哪些卡住、卡在三层追问的哪一层（模块 04 的自审框架直接可用）。把卡住的题补完，写进你的题库——一轮面试的最大价值往往不是这个 offer，而是它精确地告诉了你知识边界在哪。

反问的判据和整门课是一致的：问一个「不了解这个领域就问不出来」的问题。「你们的评测有没有分像素尺寸的桶」——外行问不出这句话，因为他不知道不分桶就看不见小目标退化。这就是似然比大的问题。

9研究前沿与开放问题

  • 无 NMS 的两条路仍未合流。DETR 系靠一对一匈牙利匹配，YOLOv10 靠一致的双分配。共识是「一对一是推理需求、一对多是训练最优」（Group DETR / Co-DETR / DEIM 都在训练期补密集监督），但两者如何最优组合、能否推导出一个统一的分配目标，仍无定论。这是一个很好的「你怎么看这个领域的下一步」的回答素材。
  • 小目标仍然是结构性弱区。NWD 之类的尺度不敏感度量、RFLA 的感受野先验分配、切片推理，都是在绕开「IoU 对小框极度敏感」这个根本问题。是否存在一个既能替代 IoU 做分配、又能直接作为回归损失、且阈值语义与 IoU 兼容的度量，目前仍然开放。
  • 评测指标与下游安全的脱节。mAP 是为学术可比性设计的，它按类平均、与距离无关、无时序、不反映误检绝对量。自动驾驶社区提出了各种「安全导向」的检测指标（按碰撞风险加权、按规划影响加权），但都没有形成 COCO 那样的统一标准——这使得跨团队的结果无法比较。能指出这一点，说明你知道自己在用的指标是有边界的。
  • 「+0.3 是不是提升」背后的复现性问题。检测领域长期存在报告单种子最优结果的习惯；Bouthillier 等人的实证工作说明，仅仅改变随机种子与数据划分，基准结果的波动就足以掩盖大量声称的改进。多种子 + 方差报告仍未成为主流，这既是问题，也是你在面试里主动提出更严格方法论的机会。
  • VLA 的可测试性。端到端系统的失败难以定位到具体环节，而自动驾驶又是最需要可归因的领域之一。中间表示与日志设计必须在架构阶段就规划好，否则事后无法做根因分析；此外开环评测（比对专家轨迹）会严重高估性能，因为它不暴露误差累积，而闭环评测需要仿真器或实车——这个评测缺口目前是 VLA 落地最大的工程障碍之一。
  • 面试本身的效度。结构化行为面试的预测效度在工业组织心理学里长期被认为显著高于非结构化面试，但近年对早期元分析的效应量修正引发了讨论。对候选人的实际含义没有变：把 STAR 结构和「判断 → 方案 → 验证」的答题骨架练成肌肉记忆，在两种面试形式下都不会吃亏。
