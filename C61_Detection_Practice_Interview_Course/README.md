# 检测工程实战与面试实务（C53–C61 收官课）

这门课回答一个和前八门都不一样的问题：**你怎么证明你做的东西真的变好了；坏了你怎么查；以及你怎么把这两件事讲给别人听。**

C53–C60 给你的是**素材**：实时检测器的选型账、DETR 的匹配机制、TSR 的领域知识与失效模式、
增强配方、小目标的物理推导、长尾数据闭环、VLA 的接口设计、车端部署与一致性排查。
但素材本身不是能力。**能力 = 素材 + 方法论 + 表达**，这门课补的就是后两项：

- **指标意识** —— 任何改动，你都能先说出「它影响哪个指标、量级大概多少、代价是什么」，再去跑。
- **归因能力** —— 指标变了，你能在半小时内定位到具体原因，而不是重跑三遍看运气。
- **交付纪律** —— 你的结果可复现、可回滚、可交接；别人能接手，也能推翻。

对应到面试：前八门课决定你**答得对不对**，这门课决定你**听起来像不像干过**。

## 三个贯穿全课的数字

1. **±0.2–0.5** —— 检测任务上，同一份配置只换随机种子，mAP 的典型波动区间。
   它意味着：**绝大多数「我把 mAP 提升了 0.3」的说法，在统计上和「我什么都没做」不可区分。**
   模块 01 会把这件事变成可计算的：需要几个种子、用什么检验、多重比较怎么校正。

2. **六类** —— TIDE 把 mAP 的损失拆成 Cls / Loc / Both / Dupe / Bkg / Miss。
   关键不在分类本身，而在**每一类的「修复收益」**（把这类错全改对，mAP 能涨多少）。
   有了这个数，"下一步做什么" 就不再是品味问题。模块 02 从零实现它。

3. **三大原因** —— mAP 恒为 0 时，类别 ID 偏移、坐标格式弄反、类别表不一致，三者占了绝大多数。
   **它们的共同点是都不报错。** 模块 03 给出每类 bug 的可识别指纹与二分定位法。

## 面试冲刺路线（距面试还有一周）

> 假设你已经通读过 C53–C60 至少一遍。下表的原则是：**必读 = 高概率被直接问到或被追问；
> 可跳 = 知道结论即可，临场不会因为细节缺失而失分。** 时间不够就砍「可跳」那一列，不要砍必读的深度。

**如果只剩 48 小时**（这是最常见的现实）：
`C61-02`（误差分析，因为它能撑起一半的追问）→ `C61-05`（题库 + 白板参考实现）→

## 前八门课分别贡献了什么

这门课不产生新的技术素材，它把 C53–C60 的产出**重新组织成叙事与题库**。对照着看：

| 课程 | 它给你的素材 | 在项目叙事里出现的位置 | 在题库里对应的题 |
|---|---|---|---|
| **C53 · 实时检测器架构** | 延迟-精度账、帕累托前沿、标签分配的收益归因 | Action 段的「为什么选 X 不选 Y」——有数字的选型推理 | 「RT-DETR 凭什么快」「一对一 vs 一对多的本质」「YOLOX 三件套各涨多少」 |
| **C54 · DETR 集合预测** | 匈牙利匹配的白板实现、集合损失、收敛难题的两个根因 | 技术深度展示段（讲清一个机制的完整因果链） | 「DETR 为什么不需要 NMS」「匹配代价包含哪三项」「Deformable 解决了什么」 |
| **C55 · TSR 与自驾感知** | 领域语言、失效模式清单、安全导向的评测体系 | Situation 段——把场景说到让人信你真见过 | 「怎么设计 TSR 评测」「mAP 不够用怎么办」「两级 vs 端到端怎么选」 |
| **C56 · 检测数据增强** | 具体改动 + 它的消融证据（含反例：翻转会把左转变右转） | Action 段第一条改动，也是最容易讲出「领域思考」的一条 | 「水平翻转的坑」「为什么要 close-mosaic」「增强怎么验证有效」 |
| **C57 · 小目标检测** | 像素尺寸的物理推导、IoU 位移敏感性、NWD、切片推理 | Task 段的约束量化（「要在 60 m 检出，就得有 ≥ N 像素」） | 「小目标为什么难，你会从哪几个方向改」「APs 低是模型问题还是分配问题」 |
| **C58 · 难例挖掘与长尾** | 数据闭环全流程、触发策略、边际收益曲线 | Result 段之后的「下一步」——证明你在做系统而不是单次实验 | 「长尾怎么办（多层次答）」「线上某类漏检的排查流程」 |
| **C59 · VLA 与感知接口** | 感知输出的 schema 设计、置信度传递、约束化 | 加分段：JD 里唯一独有的那条职责 | 「TSR 输出如何接入 VLA」「置信度怎么传给下游」 |
| **C60 · 车端部署与一致性** | 一致性排查 checklist、INT8 掉点决策树、p99 延迟 | 代价段——把「上车代价」讲清楚，这是资深度的分水岭 | 「INT8 后掉 3 个点怎么查」「车端和离线不一致的可能原因」 |

**用法**：模块 04 会带你把上表右边两列变成 3–4 个 10 分钟的故事；模块 05 会把它们变成带评分要点的题库。
反过来也成立——如果某个故事你讲不出「代价」和「验证」，说明对应那门课还欠一遍。

## 与 C37 / C40 的关系

| 课程 | 它讲什么 | 与本课的分工 |
|---|---|---|
| **C37 · MLOps** | 实验跟踪、版本管理、CI/CD 门禁、监控漂移、反馈重训 | **工程形态在 C37，判断标准在这里。** C37 告诉你「用什么工具记录实验」，本课 01 告诉你「记录哪些字段才算完整，以及记录之后怎么判断这个提升是不是真的」；C37-03 的回归门禁需要一个「掉多少算掉」的阈值，那个阈值来自本课 01 的显著性分析。 |
| **C40 · 研究方法论** | 读论文与复现、实验设计、研究统计学、研究工程、写作与评审 | **通论在 C40，检测特化在这里。** C40-03 讲统计检验的一般原理，本课 01 把它落到 mAP 这个具体指标上（mAP 不是均值型指标，逐图 bootstrap 与逐类 bootstrap 结论不同）；C40-05 讲学术写作，本课 04 讲的是<em>面试与技术评审场景</em>的叙事——受众不同，结构也不同。 |

如果你时间充裕，推荐顺序是 **C40-02/03 → C61-01**（先通论后特化），
以及 **C61-01/02 → C37-03**（先知道怎么判断，再去设计门禁）。

## 学习路径

- **面试冲刺**（约 3 小时）：02 → 05 → 04。误差分析撑起追问，题库补齐硬题，叙事收口。
- **补方法论**（约 4 小时）：00 → 01 → 02。这两个模块是「指标意识 + 归因能力」的正面训练。
- **正在带项目**（约 4 小时）：01 → 03 → 04。实验设计定规范、调试手册救急、叙事用于周报与评审。
- **完整路径**：00 → 01 → 02 → 03 → 04 → 05。后面的模块会反复引用前面的结论，尤其 04/05 会直接调用 01/02 的结果。

每个模块的 notebook 都可独立运行，纯 numpy、CPU，几秒到几十秒出结果，练习带 `assert` 判分。

## 环境

见 `requirements.txt`。**纯 numpy + matplotlib，CPU 可跑，不需要 GPU，也不需要装 torch / mmdetection / TensorRT。**

本课复现的是**判断力的可执行形式**：

- 显著性判定（多种子 + 配对 bootstrap + BH 校正 + 功效分析）
- 误差分解（TIDE 六类 + 每类的修复收益 ΔAP）
- 诊断器（PR 曲线病症识别、数据管线 bug 指纹、梯度健康检查）
- 自检器（实验记录字段校验、项目叙事完整性校验、追问覆盖度校验）

这些工具的价值不在于代码有多难，而在于**它们会毫不留情地告诉你：你上一个「提升」可能是噪声。**

## ⚠️ 关于本课里的数字

讲解中引用的 mAP 波动区间、各类误差的典型占比、修复收益量级，来自公开论文的消融表与社区实测报告，
**用于说明量级与相对关系，不是你自己数据集上的真值**。不同数据集、类别数、目标尺寸分布，都会显著改变这些数字。

**本课教的不是这些数字，而是「怎么在你自己的数据上把这些数字算出来」。**
在面试里引用具体数字时，务必同时说出来源与测量条件——这本身就是加分项，
而说不出来源的具体数字是减分项，因为面试官会顺着追问。
