1为什么必须先匹配：两个无序集合之间没有天然的对应关系

检测的输出是一个集合：{（限速60, 框A）,（禁止超车, 框B）}。GT 也是一个集合。两个集合都没有顺序——你把 GT 列表里的两个元素交换位置，标注的含义一点都没变。

但损失函数是逐元素算的。loss(pred[0], gt[0]) + loss(pred[1], gt[1]) 这种写法隐含地假设了「第 0 个预测负责第 0 个 GT」——而这个假设毫无根据。同一份标注，把 GT 的存储顺序换一下，损失值就变了，梯度方向就变了，训练结果就变了。一个依赖数据存储顺序的损失函数在数学上是没有定义的。

直白说

传统检测器是怎么绕开这个问题的？它们用「空间位置」当成了天然的对应关系：Faster R-CNN 说「和这个 anchor 的 IoU 最大的那个 GT 归你负责」，FCOS 说「落在这个 GT 框内部的所有位置都归它负责」，YOLO 说「GT 中心点所在的那个格子负责它」。这些规则把「谁对应谁」这个问题用手工先验回答掉了——代价是这些规则本身变成了一堆要调的超参（IoU 阈值、中心采样半径、层级分配公式），也就是 C53 模块 02 讲的label assignment（标签分配）。

严谨说

集合预测拿掉了 anchor，也就同时拿掉了这个天然对应关系。N 个 object query 在几何上没有任何先验位置（原版 DETR 的 query 就是 N 个可学习向量，编号本身没有含义），所以「第 3 个 query 该对哪个 GT 负责」必须在每次前向之后现算。这就是匹配（matching）：给定这一次前向的预测结果，找出一个使总代价最小的一一对应。它每个 iteration 都会重算一次，而且结果可能和上一个 iteration 不同——这个「可能不同」正是本模块第 8 节的主题。

换个角度看，匹配就是「动态的标签分配」：传统检测器用固定规则做分配（静态），DETR 用一个最优化问题做分配（动态，依赖当前预测）。面试里如果被问「DETR 的标签分配是什么」，标准答案就是「基于匈牙利算法的一对一动态分配」——而不是「DETR 没有标签分配」。这两者的差别决定了后面所有的性质：一对一带来无 NMS，动态带来不稳定。

2形式化：线性指派问题（Linear Assignment Problem）

把它写成数学。设预测集合有 N 个元素 ŷ_1..ŷ_N（N = query 数，固定），GT 集合有 M 个元素 y_1..y_M（M 随图像变化，通常 M ≪ N）。定义一个代价矩阵 C ∈ ℝ^{N×M}，其中 C_ij 表示「让第 i 个预测去认领第 j 个 GT」的代价。我们要找的是一个单射 σ: {1..M} → {1..N}，使总代价最小：

\[\hat{\sigma} \;=\; \arg\min_{\sigma}\; \sum_{j=1}^{M} C\big(\hat{y}_{\sigma(j)},\, y_j\big) \qquad \text{s.t.}\quad \sigma(j_1) \neq \sigma(j_2)\ \ \forall\, j_1 \neq j_2\]

这就是运筹学里的线性指派问题（linear assignment problem, LAP），也叫二分图最小权完美匹配。三个要素缺一不可：

要素含义去掉它会怎样
代价矩阵 C_ij「预测 i 认领 GT j」有多贵。它把「像不像」量化成一个数无法比较不同配对的优劣，问题不成立
一对一约束每个 GT 恰好一个预测，每个预测至多一个 GT（σ 是单射）退化成逐 GT 独立取 argmin——多个 GT 会抢同一个 query，重复框就回来了
总代价最小优化的是总和，不是逐个最优变成贪心匹配，会得到次优解（notebook 里实测约 37% 的随机矩阵上贪心次优）

直白说

第二行是这门课的地基。「一对一」这三个字承载了 DETR 的全部特殊性：如果允许多个预测认领同一个 GT（一对多），那就是传统检测器的标签分配，输出必然重复，必须 NMS；只有强制一对一，模型才被迫学会「一个目标只输出一个框」。而一对一约束恰恰是让这个问题从「N 次独立 argmin」变成「一个组合优化问题」的原因——也是它需要匈牙利算法而不是一行 argmin 的原因。

严谨说

第三行则常被低估。「总代价最小」与「每个 GT 各自选最便宜的」是两回事。考虑一个 2×2 的代价矩阵 [[1, 2], [2, 100]]：贪心先拿走全局最小的 C[0,0]=1，剩下只能吃 C[1,1]=100，总代价 101；而最优解是交叉配对 C[0,1]+C[1,0] = 2+2 = 4。差了 25 倍。贪心的错误不是「选贵了」，而是「它的选择锁死了别人的选择」——这正是组合优化与逐点优化的分界线。

一个实现上的坑：M 可能是 0（这一帧没有任何交通标志，在 TSR 数据里非常常见——高速空旷路段整段都是空帧）。此时代价矩阵是 N×0，匹配为空集，所有 N 个 query 都算 no-object 损失。没有对空矩阵做保护是 DETR 复现里最常见的 crash 来源之一，而且它只在遇到空帧的那个 batch 才炸，可能训练几个小时后才暴露。

3机理之一：增广路径——先解「有没有」，再解「多好」

匈牙利算法的名字来自 König 与 Egerváry 两位匈牙利数学家的定理，Kuhn 在 1955 年把它整理成算法。理解它要分两步走：先理解无权版本（最大二分匹配），再把权重加进去。无权版本的核心概念只有一个——augmenting path（增广路径）。

左边是 query，右边是 GT，一条边表示「这对可以配」。粗线 ═ 表示已在当前匹配里。 当前匹配 M = { q0═g0, q1═g1 }，匹配数 2。现在轮到 q2： q0 ═══════ g0 q2 只连着 g1，而 g1 已被 q1 占用。 直接放弃？不行 —— 也许 q1 可以让位。 q1 ═══════ g1 ╱ 走一条**交替路径**（非匹配边、匹配边交替出现）： q2 ───────╱ q2 ──→ g1 (非匹配边) q1 ─────── g2 g1 ══→ q1 (匹配边，反向走) q1 ──→ g2 (非匹配边) g2 是**未匹配**的右点 → 路径终止 这条路径就是**增广路径**：起点是未匹配左点，终点是未匹配右点，边交替。 增广 = 把路径上所有边的「匹配/非匹配」状态取反： 非匹配边 3 条 → 变匹配 (+3) 匹配边 1 条 → 变非匹配 (−1) 净增 1 条匹配边。 增广前: q0═g0, q1═g1 (2 条) 增广后: q0═g0, q2═g1, q1═g2 (3 条) ← q1 让位给 q2，自己去了 g2 Berge 定理：一个匹配是最大匹配 ⟺ 图中不存在增广路径。 所以算法就是：**对每个左点找一次增广路径，找到就增广。** 复杂度 O(V·E)。

直白说

增广路径的直觉是「链式让位」：新来的 query 想要一个已被占用的 GT，那就问占用者能不能换个别的；占用者去问下一个……只要这条链最终走到一个空位，整条链就能集体挪一格，多容纳一个人。如果走不到空位（所有可达的右点都已被占且它们的占用者也无处可去），说明当前匹配在这一块已经饱和，这个新 query 就只能落空。

严谨说

这个「落空」的情形在 DETR 里有直接对应：当 M > N（GT 数超过 query 数）时，必然有 GT 无法被匹配，它们的监督信号直接丢失。这就是「N 必须大于单图最大目标数」这条工程铁律的来源。TSR 场景要特别小心：绝大多数帧只有 0–3 块标志，但复杂路口一次能出现十几块（龙门架 + 路侧杆 + 地面附着牌）。按平均数设 N 会在最需要它的那些帧上漏检——而这些帧恰恰是安全最关键的。

这里有个可迁移的心法：「先解可行性，再解最优性」。无权最大匹配回答的是「最多能配几对」，带权最优匹配回答的是「在配满的前提下总代价最小是多少」。KM 算法的整个设计就是把第二个问题化归成第一个问题反复求解——用对偶变量筛出一个「只保留最划算的边」的子图，然后在这个子图上跑最大匹配。下一节就是这件事。

4机理之二：对偶变量与 Kuhn–Munkres，为什么是 O(n³) 而不是 O(n!)

带权版本的核心技巧是对偶。给每一行（query）配一个数 u_i，每一列（GT）配一个数 v_j，要求它们满足：

\[u_i + v_j \;\le\; C_{ij} \qquad \forall\, i, j\]

在这个约束下，对任意一个合法的一对一匹配，其总代价都 ≥ Σu + Σv（把匹配上的每一对的不等式加起来即可）。所以 Σu + Σv 是最优总代价的一个下界。线性规划对偶告诉我们：把这个下界推到最大，它就等于最优值。

\[\max_{u,v}\ \Big(\sum_i u_i + \sum_j v_j\Big) \quad = \quad \min_{\sigma}\ \sum_j C_{\sigma(j)\, j}\]

取等的条件是互补松弛：被匹配上的那些格子必须满足 u_i + v_j = C_{ij}（称为tight edge，紧边）。于是算法的形态就出来了：

  1. 维护一组满足 u_i + v_j ≤ C_ij 的对偶变量（初始可全取 0，若代价有负数则先做行减最小值）。
  2. 只看紧边组成的子图（equality subgraph，相等子图），在上面用增广路径找匹配。
  3. 如果找不到增广路径，说明紧边不够用——计算一个最小的松弛量 δ，调整 u/v 让至少一条新的边变紧，然后回到第 2 步。
  4. 每次调整至少让一条边变紧，每个左点最多做 O(n) 次调整，每次调整扫描 O(n) 列 → 总复杂度 O(n³)。

直白说

为什么这个复杂度可以接受？因为匹配是在 CPU 上、对每张图单独做的，而且矩阵极小：N=100（或 DINO 的 900），M 通常个位数。DETR 的官方实现直接调 scipy.optimize.linear_sum_assignment，在整个训练里占比不到 1%。真正的代价不在时间，而在它是一个不可微的离散步骤——它决定了梯度流向谁，但它自己没有梯度。

严谨说

「不可微」这一点值得说透。匹配 σ̂ 是一个 argmin，在反向传播里被当作常量（DETR 实现里外面套了 torch.no_grad()）。所以匹配代价 C 里那些项（分类概率、L1、GIoU）在匹配阶段只起「选择」作用，它们的梯度来自后面的损失阶段。这也是为什么匹配代价和损失函数可以用不同的形式——比如匹配用 −p，损失用 −log p（下一节详述）。面试里能主动区分「匹配代价」和「损失函数」是加分项，很多人以为它们是同一个东西。

O(n³) 的来源要能说清

不要在面试里说「匈牙利算法是 O(n!)」或者「它就是暴力枚举的优化」。它和暴力枚举没有任何关系——它是一个基于线性规划对偶的原始-对偶算法，每一步都在可证明地提升下界。被追问「为什么是 O(n³)」时，标准答案骨架是：n 个左点，每个点最多 n 次对偶调整，每次调整扫描 n 列。如果还能补一句「它的对偶变量 u/v 满足互补松弛，所以算法终止时自带一个最优性证书」，这题就满分了。

5DETR 的匹配代价：三项设计，以及为什么分类项用概率而不是 log

代价矩阵怎么填，决定了「谁认领谁」，进而决定了每个 query 收到什么梯度。代价函数的设计比匹配算法本身更影响最终精度。DETR 用的是三项之和：

\[C_{ij} \;=\; -\,\lambda_{cls}\,\hat p_i(c_j) \;+\; \lambda_{L1}\,\lVert \hat b_i - b_j \rVert_1 \;-\; \lambda_{giou}\,\mathrm{GIoU}(\hat b_i,\, b_j)\]
项形式默认权重它负责什么单独用会怎样
分类项−p̂_i(c_j)，直接用 softmax 概率1让「已经觉得自己是这一类」的 query 优先认领只按分数匹配 → 选到框很差的 query（C53 模块 04 讲的 query selection 同一个病）
L1 项‖b̂ − b‖₁，归一化 cxcywh 四维之和5中心与尺寸的绝对偏差，对小框友好（不随尺度衰减）对尺度极其敏感：同样 0.01 的偏差，对小框是致命的，对大框无所谓
GIoU 项−GIoU(b̂, b) ∈ [−1, 1]2尺度不变的重叠度量；不相交时仍有梯度（IoU 没有）尺度不变意味着它无法区分「小框差一点」和「大框差很多」

直白说

L1 与 GIoU 必须同时用，因为它们的失效模式正好互补。L1 在归一化坐标下对小目标不友好：一块 24×24 像素的限速牌在 1920 宽的图上，宽度归一化后只有 0.0125，你的框宽错一倍（0.025）L1 才 0.0125，几乎不产生代价；而对一块占半张图的指路牌，同样 0.0125 的误差可以忽略不计。GIoU 反过来：它只看重叠比例，24 像素的框错 2 像素 IoU 就掉到 0.39，代价立刻拉满。

严谨说

而 GIoU 相对 IoU 的关键改进是「不相交时仍有梯度」：两个完全不相交的框，IoU 恒为 0，无论它们相距 10 像素还是 500 像素——作为代价它无法区分「差一点」和「差得离谱」。GIoU 减去了「最小外接框中的空白占比」，所以框越远 GIoU 越负，一直到 −1。这一点对匹配尤其重要：训练早期所有预测框都是乱的，几乎没有一个和 GT 相交，如果只用 IoU，代价矩阵会退化成一片 0，匹配就完全由分类项决定，等于随机分配。模块 02 会把 GIoU/DIoU/CIoU 的梯度性质完整推一遍。

为什么分类项是 −p 而不是 −log p

这是本节最值得记住的一个细节，也是高频面试题。DETR 论文明确写了：匹配代价里的分类项用概率而非对数概率，「这样它就与框的代价项在同一量级上，我们观察到这带来了更好的表现」。原因有两层：

  • 有界性：−p ∈ [−1, 0]，和 GIoU 项的 [−1, 1] 量级相当；而 −log p 在 p→0 时趋于 +∞。DETR 有 91 个类，训练初期每类概率约 0.01，−log p ≈ 4.6，而 L1 项通常在 0.1–1 之间——分类项会以数量级优势主导整个代价矩阵，匹配几乎完全由分类分数决定，框的质量被忽略。
  • 饱和性：−p 在 p 已经很高时增益递减（0.9→0.99 只多赚 0.09），所以「非常自信」的 query 不会因为多一点自信就压倒「框更准」的 query。−log p 则在低概率区极度陡峭，会把一个框很好但分类还没学会的 query 直接判死刑——而训练早期所有 query 的分类都还没学会。

notebook 里有一个三选一的最小反例：q0 分类很自信但框偏了 0.4，q1 框几乎完美（GIoU 0.95）但分类概率只有 0.02，q2 两头都平庸。用 −p 匹配选中 q1（框好的那个，正确）；换成 −log p 就选中了 q2——一个两头平庸的 query 拿走了这个 GT，而框最准的 q1 被判成背景。

但要注意损失函数里仍然用 −log p（交叉熵），只有匹配代价用 −p。把这两处搞混（匹配也用 log，或者损失也用概率）是复现 DETR 时的经典 bug：前者会让训练早期匹配退化成按分数排序，后者会让分类梯度在 p 很小时消失。记法：匹配要「公平比较」所以要有界；损失要「强力纠错」所以要无界。

6N 个 query、M 个 GT：矩形代价矩阵与 no-object

实际的代价矩阵几乎从不是方阵。DETR 用 N=100（DINO 用 900），而一张图里的 GT 通常只有几个。TSR 场景更极端：一段高速上大量帧的 M=0，市区普通路段 M=1–3，复杂路口偶尔 M=12。所以代价矩阵是 100×M 的瘦长矩形。

GT (M=3) padding 到方阵 (N=6) g0 g1 g2 g0 g1 g2 ∅ ∅ ∅ q0 [ 0.3 2.1 1.8 ] q0 [ 0.3 2.1 1.8 c c c ] q1 [ 1.9 0.4 2.2 ] q1 [ 1.9 0.4 2.2 c c c ] q2 [ 2.4 1.7 0.5 ] ==> q2 [ 2.4 1.7 0.5 c c c ] q3 [ 1.1 1.3 1.6 ] q3 [ 1.1 1.3 1.6 c c c ] q4 [ 2.0 2.2 1.4 ] q4 [ 2.0 2.2 1.4 c c c ] q5 [ 1.5 1.9 2.1 ] q5 [ 1.5 1.9 2.1 c c c ] 要点：padding 列的代价是**同一个常数 c**。 每种指派方案里恰好有 (N−M)=3 行落到 padding 列，贡献 3c —— **对所有方案都一样**。 => c 取什么值都不改变 argmin。**所以直接解矩形问题即可，不需要真的 padding。** 落到 padding 列的那 3 个 query 的实际待遇：**在损失里被判为 no-object (∅)**。

直白说

很多人第一次看 DETR 的公式会卡在「GT 集合要 pad 到大小 N」这句话上，以为要真的构造一个 N×N 矩阵。数学上 padding 是为了让 σ 成为一个排列（permutation），叙述更干净；工程上完全不需要——因为 padding 列的代价是常数，它对所有指派方案的贡献相同，argmin 不受影响。DETR 官方实现里就是直接把 N×M 的矩形矩阵扔给 linear_sum_assignment。

严谨说

但「no-object 在匹配里代价为常数」这个设计本身是有后果的，值得想清楚：它意味着「一个 query 该不该被判为背景」这件事完全不由匹配决定，只由「有没有轮到它」决定。哪怕某个 query 的框和某个 GT 极度吻合，只要有另一个 query 更吻合，它就被打成背景，承受完整的 no-object 损失。这就是「训练期压制重复」的机械原理，也是匹配不稳定性伤害如此之大的原因——身份翻转会让同一个 query 在相邻 epoch 收到方向完全相反的分类监督。

顺带回答一个常见困惑：为什么 N 不能设得太大？ 三个理由。① 正样本比例：N=100、M=3 时前景 query 只占 3%，no-object 损失即使降权也会主导训练（模块 02 量化这一点）；② 计算量：decoder 的 self-attention 是 O(N²)，N 从 100 到 900 是 81 倍；③ 重复风险：query 越多，「两个 query 都学到差不多的行为」的机会越大。反过来 N 也不能太小——N < 单图最大目标数会直接漏检。实务经验：N 取「数据集里单图目标数的 99.9 分位数」的 3–5 倍。TSR 数据上这通常意味着 N=100 足够，但要先真的去统计那个分位数，而不是照抄 COCO 的配置。

7为什么一对一匹配能替代 NMS：训练期压制 vs 推理期删除

这是本模块、也是整门课最核心的一个问题，几乎每场 DETR 相关的面试都会问。答案的骨架是三句话：① 重复框的根源是「多个预测同时被判为同一目标的正样本」；② 一对一匹配从训练目标上禁止了这件事；③ 被禁止的那些 query 收到 no-object 梯度，于是学会主动把自己压低。

一对多分配（传统检测器）一对一匹配（DETR 系）
训练时一个 GT 对应几个正样本几个到几十个（IoU 阈值 / center sampling / SimOTA 的 dynamic-k）恰好 1 个
训练信号密度稠密——收敛快（12–36 epoch）稀疏——收敛慢（原版 500 epoch）
推理时同一目标的高分预测数多个（因为训练时它们都被教成正样本）≈ 1 个
去重发生在推理期：NMS 按 IoU 阈值删（不可微、O(n²)、阈值全局）训练期：no-object 损失把落选者压低（可微、无额外开销）
误删真目标的风险存在（模块 00 算过：TSR 组合牌场景阈值窗口为空集）不存在（没有抑制步骤）
延迟随目标数增长，p99 不可控常数

notebook 里有一个可以完整跑起来的最小实验：8 个 query、2 个 GT、纯 numpy 手写梯度下降 600 步，只改「分配方式」这一个变量。

同一份数据、同一个模型、同一套梯度，只改分配方式： 一对多（半径 0.15 内全算正样本） 一对一（匈牙利匹配，每 GT 只 1 个正样本） ──────────────────────────────── ────────────────────────────────────── 正样本: q1 q2 q3 | q4 q5 q6 正样本: q2 | q5 负样本: q0, q7 负样本: q0 q1 q3 q4 q6 q7 训练 600 步后 sigmoid(score)： 训练 600 步后 sigmoid(score)： q0 0.01 q0 0.01 q1 0.99 ┐ q1 0.01 q2 0.99 ├ 3 个框挤在 GT0 上 q2 0.99 ← 只有它认领 GT0 q3 0.99 ┘ q3 0.01 q4 0.99 ┐ q4 0.01 q5 0.99 ├ 3 个框挤在 GT1 上 q5 0.99 ← 只有它认领 GT1 q6 0.99 ┘ q6 0.01 q7 0.01 q7 0.01 触发数 = 6 → **必须 NMS 才能回到 2** 触发数 = 2 → **不需要任何后处理**

直白说

这个实验里有一个自我强化的动力学值得注意：匹配代价里包含 −p，所以分数被压低的 query 代价更高、更不容易被匹配上，下一步又被压得更低。这个正反馈让「谁认领这个 GT」很快就锁定下来。它既是一对一匹配能稳定收敛的原因，也是「一旦早期锁错了 query 就很难纠正」的原因——后者是 DETR 训练里 query 利用率不均衡问题的一个来源（模块 05 会给诊断指标）。

严谨说

必须诚实地补上另一半：一对一匹配换来无 NMS，代价是监督信号密度掉了一个数量级。一对多分配下一张图有几百个正样本，一对一只有 M 个（TSR 场景常常就 1–3 个）。这是 DETR 需要 500 epoch 的第一个根因。所以 2022 年之后出现了一批「训练时加一对多分支、推理时丢掉」的工作（Group DETR、H-DETR、Co-DETR），都能稳定涨点 1–2 AP。它们证明了一件重要的事：一对一是「推理端的需求」，不是「训练端的最优」。面试里能说出这一层，说明你不只是背了 DETR 的结论。

动机（匹配）与能力（self-attention）缺一不可

面试高频陷阱题：「一对一匹配就够了吗？把 decoder 的 self-attention 去掉，还能不出重复框吗？」 正确答案是不能。一对一匹配提供的是「不要重复」的动机，decoder self-attention 提供的是「知道别人已经认领了」的能力——query 之间必须能互相看到，才能协商谁让谁。去掉 self-attention 后，多个 query 面对同一个目标时无法区分彼此，训练会在几个近似解之间震荡，重复框显著回升。把「动机 vs 能力」这组词说出来，这题就答满分了。

8匹配不稳定性：DETR 收敛慢的第二个根因

现在讲这个模块最有价值、也最少被讲清楚的一件事。匹配是一个离散的 argmin，代价矩阵的微小扰动可以让整个指派翻转。而代价矩阵在训练中每个 iteration 都会变（模型在更新、数据在换、增强在随机）。后果是：同一个 GT 在相邻 epoch 可能被不同的 query 认领。

同一块 40x40 的「禁止超车」牌，在相邻 epoch 被谁认领： epoch 120 121 122 123 124 125 126 127 128 认领者 q17 q17 q42 q17 q42 q42 q17 q42 q17 └翻转┘ └翻转┘ └翻转┘ └翻转┘ └翻转┘ └翻转┘ 翻转率 6/8 = 75% q17 这一路收到的监督信号： epoch 120 121 122 123 124 125 126 127 128 身份 前景 前景 背景 前景 背景 背景 前景 背景 前景 分类梯度 ↑ ↑ ↓ ↑ ↓ ↓ ↑ ↓ ↑ 框梯度 拉向GT 拉向GT 无 拉向GT 无 无 拉向GT 无 拉向GT 净效果：分类梯度方向来回抵消 —— 累计 9 步只净得 (5−4)/9 ≈ 11% 的有效信号， 而一个**稳定被认领**的 query 净得 100%。 等价于：**有歧义的那批 query 的有效学习率只有别人的 1/9。**

notebook 里把这件事做成了可量化的实验：构造一个 8 query × 4 GT 的代价矩阵，其中 GT0 和 GT2 各有两个「势均力敌」的候选 query（代价差 0.01 / 0.02），GT1 和 GT3 的候选则拉开明显差距（代价差 0.70）。给代价矩阵叠加高斯噪声模拟训练抖动，跑 2000 个「epoch」统计翻转率：

直白说

三个必须读出来的结论。① 不稳定性是局部的，不是全局的：代价差 0.70 的那两个 GT 在任何噪声下都几乎不翻转，而代价差 0.01 的那两个一翻就是 48%。所以「匹配不稳定」真正的意思是「一小撮势均力敌的候选之间反复易主」，而不是整个指派随机乱跳。② 翻转率会饱和在 0.5：两个候选完全势均力敌时，每个 epoch 各 50% 概率，相邻两 epoch 不同的概率就是 0.5。σ 从 0.05 加到 0.20 平均翻转率只从 0.239 涨到 0.252，就是因为已经饱和了。

严谨说

③ 「势均力敌」在真实训练里是常态而不是例外。想想 TSR 场景：一块 24 像素的远处限速牌周围，好几个 query 的预测框只差一两个像素，它们的 L1 项与 GIoU 项几乎相同，分类概率也在同一个量级——代价差恰恰就在 0.01 这个量级上。而每个 iteration 里数据增强的随机裁剪、颜色抖动、乃至 dropout，都会给代价矩阵注入远超 0.01 的扰动。小目标 + 密集目标的场景，匹配不稳定性最严重——这正好是 TSR 的画像。

这个观察直接催生了后面两代工作，模块 04 会展开：

工作对付不稳定性的思路效果
DN-DETR（CVPR 2022）把「加了噪声的 GT 框」作为额外的 query 送进 decoder，它们的标签已知且固定，完全绕过匹配，只做去噪重建50 epoch 达到原版 500 epoch 的精度；论文里直接画了「不稳定性指标随 epoch 下降」的曲线
DINO（ICLR 2023）在 DN 基础上加对比去噪（同一个 GT 给一组小噪声正样本 + 一组大噪声负样本），教模型「多远算同一个目标」长期 SOTA 骨架；对重复框的抑制也更强
Stable-DINO（ICCV 2023）用定位质量给分类分数加权再进匹配代价，让「框准」这件事在匹配里更有决定性，减少势均力敌直接针对匹配不稳定，在多个 backbone 上稳定涨点
Group / H / Co-DETR训练时并行多组一对多分配，用监督密度对冲不稳定的伤害涨 1–2 AP，推理零开销

把这一节压成一句可迁移的话：凡是「用一个离散 argmin 决定谁接受监督」的系统，都会有优化目标抖动的问题。这不是 DETR 独有的——MoE 的专家路由、稀疏检索的 top-k 选择、乃至 SimOTA 的 dynamic-k，都是同一个病。通用解法只有两类：让选择更确定（Stable-DINO 的加权、MoE 的负载均衡损失），或者绕过选择（DN-DETR 的去噪 query、MoE 的 soft routing）。能把 DETR 的匹配不稳定和 MoE 的路由不稳定联系起来，是很强的信号。

9研究前沿与开放问题

匹配这件事看起来已经被解决了（算法是 1955 年的，代价函数是 2020 年定下来的），但它仍然是 DETR 系里最活跃的改进入口之一。

  • 匹配稳定性的理论刻画仍然缺失。目前所有工作都是「观察到不稳定 → 提出一个启发式 → 实验证明有效」，没有人回答「给定代价矩阵的分布，翻转率的期望是多少」「翻转率降到多少才不影响收敛」。本模块 notebook 里的那个 2000 次模拟，本质上就是在做这件事的最小版本——把它扩展到真实代价矩阵上是一个现成的研究点。
  • 一对一与一对多的最优配比。Group DETR 用 11 组，H-DETR 用一对多分支 + 一对一分支，Co-DETR 挂三个辅助头——组数、噪声强度、损失权重全是调出来的。「训练时该给多稠密的监督」目前没有理论指导，也没有随训练进程自适应的方案。
  • 可微匹配 / 软匹配。用 Sinkhorn 迭代做熵正则化的最优传输（OTA、SimOTA 的思想来源）可以得到一个可微的软指派，理论上能让梯度流过匹配步骤。但在 DETR 上至今没有稳定超过硬匹配的方案——软指派会让多个 query 都收到部分前景梯度，重复抑制的效果被削弱，绕回了一对多的老问题。
  • 代价函数的自动设计。三项权重 (1, 5, 2) 是 DETR 论文里试出来的，此后几乎所有工作都沿用。但它对数据集分布是敏感的：小目标为主的数据集（TSR、航拍）理论上应该提高 GIoU 权重或改用 NWD 这类尺度不变度量（C57 模块 03）。目前没有系统的调参方法论，也没有「按数据集自动搜代价权重」的工作。
  • 匹配与时序的结合。视频/多帧场景里，同一个目标在相邻帧应当被同一个 query 认领（这样 query 就自带跟踪 ID）。TrackFormer / MOTR 这类工作把 query 沿时间传播，但「跨帧匹配一致性」与「单帧最优匹配」之间的冲突还没有好的解法。对 TSR 尤其有价值：交通标志是静止的、自车运动可预测，跨帧一致的 query 认领能直接给出稳定的跟踪 ID（见 C55 模块 04）。
