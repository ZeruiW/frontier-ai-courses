1训练配方：为什么 backbone 的学习率是 0.1×

先把 DETR 官方配置摊开。这些数字里有一半是「不能动」的，另一半是「必须按数据集调」的，能分清楚这两半就是工程能力。

项DETR 官方值属于哪一半改错了会怎样
优化器AdamW不能动换 SGD 基本训不动（Transformer 对自适应步长强依赖）
lr（transformer）1e-4按 batch 调线性缩放规则；太大早期 loss 尖峰
lr_backbone1e-5（= 0.1×）不能动用 1×：预训练特征被冲毁，AP 掉几个点
weight_decay1e-4按数据量调小数据集要加大；但不能作用于 norm/bias/query embedding
clip_max_norm0.1不能动去掉后早期梯度尖峰会让 loss 炸；0.1 是异常小的值，是刻意的
BNFrozenBatchNorm2d不能动用普通 BN：单卡 batch=2 的统计量噪声极大，训练不稳
epochs / lr_drop300 / 200（或 500/400）按方法调DINO 系用 12 或 24，配 MultiStep 在 11 步降
dropout0.1（DETR）→ 0.0（Deformable/DINO）按方法调后续工作普遍关掉 dropout，因为收敛已不是瓶颈

0.1× 的第一个理由：预训练权重已经接近好解，最优步长本来就更小

这不是玄学，可以算出来。把「一个参数块的训练」建模成带噪声的一阶迭代（噪声来自 mini-batch 采样）：

\[\mathbb{E}\big[\|\theta_T - \theta^\star\|^2\big] \;=\; \underbrace{(1-\eta)^{2T} d_0^2}_{\text{初始偏差的衰减}} \;+\; \underbrace{\frac{\eta\,\sigma^2}{2-\eta}}_{\text{梯度噪声的稳态项}}\]

第一项要求 η 大（衰减快），第二项要求 η 小（噪声地板低）。最优 η 由二者平衡决定，而 d₀（离最优点的距离）越小，最优 η 就越小——因为没有多少偏差需要衰减，剩下的全是噪声。

直白说

翻译成人话：ImageNet 预训练的 backbone 已经站在一个相当好的位置（d₀ 小），而随机初始化的 transformer 与检测头离最优解还很远（d₀ 大）。同一个学习率对前者是「用噪声把好东西震坏」，对后者是「步子还不够大」。notebook 里会扫描 d₀，画出「最优步长比随预训练质量下降」的曲线。

严谨说

严格说这个模型省略了曲率（Hessian）的差异，而真实情况里 backbone 与 transformer 的曲率尺度也不同。但结论方向是稳健的，而且它给了一条可操作的推论：预训练越好，backbone 的相对学习率就该越小。推论一：用 COCO 预训练的检测器去微调 TSR 时，backbone 的比例可以比 0.1 更小甚至冻结；推论二：如果 backbone 是随机初始化的（罕见但存在），0.1× 就是错的。面试里能说出「0.1 不是常数，是 d₀ 的函数」，比背下这个数字强得多。

第二、第三个理由

  1. 早期梯度对 backbone 是纯噪声。训练开始时 decoder 的匹配在剧烈翻转（模块 04 的 φ 接近随机），传回 backbone 的梯度方向本身就是错的。此时 backbone 走得越快，破坏越彻底。
  2. 检测数据集比预训练数据小两个数量级。COCO 118k 对 ImageNet 1.28M；TSR 自建数据集可能只有十几万张且高度相关（同一段路的连续帧）。大步长 + 小数据 = 灾难性遗忘，症状是训练集 AP 正常、跨域/跨城市泛化崩掉。
weight decay 的分组是另一个容易漏的点：AdamW 的权重衰减不应该作用于 bias、LayerNorm/BatchNorm 的仿射参数、以及 object query 的可学嵌入与 reference point 参数。对 query embedding 施加 weight decay 等于持续把它往原点拉，而它编码的是空间先验——会直接削弱 query 的空间特化（模块 03 讲的现象）。这类 bug 不会报错，只会让 AP 低 0.5~1 点，而且极难归因。notebook 里会实现一个正确的 param group 构造器。

把学习率分组的心法提炼一句：「离最优解越近、被噪声破坏的风险越大的参数块，步长越小」。这条规则在任何「预训练 + 新头」的迁移场景都成立——VLM 的视觉塔、LLM 的 LoRA 基座、语音模型的前端，全部是同一个道理。面试时把它讲成一条通用原则而不是 DETR 的特例，效果完全不同。

2DETR 对小目标弱：三个根因与它们各自的解法

原版 DETR 的 AP_S 只有 20.5，而同期的 Faster R-CNN 是 22.9、Deformable DETR 是 26.4。这不是一个原因造成的，是三个——而且它们的解法完全不同。面试里能拆成三条，是这一节的全部价值。

根因机制怎么验证是它解法
① 单尺度特征只用 C5（stride 32），16×16 的目标占 0.25 个格子，信息在下采样时已被抹掉把 GT 按像素尺寸分桶看 AP，<32px 桶塌陷多尺度（P3–P6，TSR 还要评估 P2）
② query 数量固定且偏少N=100 对密集小目标不够；且 N 固定时，小目标多的图会被挤掉统计单图 GT 数分布与前景 query 占比加大 N（Deformable 300 / DINO 900）
③ 匹配代价对小框近似平局小 GT 与绝大多数 query 的 IoU=0，GIoU 在不相交区几乎不变化 → 代价由噪声的分类项决定 → 匹配随机翻转按 GT 尺寸分别统计匹配翻转率 φ两阶段/查询选择给参考点；DN 绕开匹配

根因 ③ 值得展开，因为它最反直觉

很多人以为「小目标的匹配代价变化更剧烈（IoU 掉得快），所以匹配应该更稳」。恰恰相反。

\[\mathcal{C}(\hat{y}_i, y_j) = -\lambda_{\text{cls}}\,\hat{p}_i(c_j) \;+\; \lambda_{L1}\,\|\hat{b}_i - b_j\|_1 \;+\; \lambda_{\text{giou}}\,\big(1 - \text{GIoU}(\hat{b}_i, b_j)\big)\]
  • IoU 对绝对位移的敏感性与框尺寸成反比。同样沿对角线平移 2 像素：8×8 的框 IoU 从 1.0 掉到 0.39，64×64 的框还有 0.88，160×160 的框还有 0.95。而模型的预测误差与人工标注的抖动都是绝对像素量级的（标注 ±2 px 是常态）。
  • 于是对一个 8~16 px 的 GT，「谁该认领它」这个决策运行在标签噪声之下——GT 框本身就有 ±12%~25% 的相对不确定性，代价矩阵的最小值位置随之抖动。
  • notebook 里把候选框按相对尺度生成（即各尺寸的几何构型完全相同），唯一变化的只有「2 px 占框尺寸的比例」，测得的匹配翻转率是：8 px → 95%，16 px → 86%，32 px → 57%，64 px → 17%，160 px → 0%。一条干净的单调曲线，说明这不是玄学而是几何。
  • 此外 GIoU 在不相交区间只由外接框面积决定，提供的排序信息远弱于相交区间——而小 GT 与绝大多数 query 恰好都不相交。两个效应叠加。

直白说

所以「小目标的匹配不稳定」和「小目标的注意力质量低」是两个独立的伤害，且互相强化：注意力质量低 → 分类分数没有信息 → 匹配靠噪声决定 → 梯度指向错误目标 → 注意力更学不到东西。这就是为什么单靠「加多尺度」还不够，DINO 必须同时上 DN。

严谨说

有一个可操作的诊断：把匹配翻转率 φ 按 GT 的像素尺寸分桶统计。健康的训练里 φ 随 epoch 单调下降；如果小尺寸桶的 φ 长期居高不下（比如 30 epoch 后仍 > 0.3），说明代价矩阵在小目标上没有区分度。对策不是调学习率，而是①检查有没有接上低层特征 ②调整代价权重（在小目标数据集上适当提高 λ_L1、降低 λ_giou，因为归一化 L1 至少还随位置单调变化）③上 DN。notebook 里会把这个分桶 φ 实现出来。

小目标塌陷在总 mAP 上几乎看不见

TSR 场景的直接后果：交通标志的有效检出距离决定了系统能提前多久告知下游。要在 60 米外报出限速牌，目标就是 16 像素级别——恰好落在上述三个根因全部生效的区间。

更危险的是它在指标上「看不见」：如果测试集里小标志只占 15%，把它们的 AP 从 0.45 打到 0.20 也只让总 mAP 掉 3.7 点——而路测体验是「远处的牌子要开到很近才报」，这是一个能被用户直接感知的严重缺陷。所以 TSR 的评测必须按像素尺寸分桶（C55 模块 05 / C57 模块 05 会给完整方法）。

3训练失败模式诊断树：四种症状，各自的成因与检查步骤

DETR 系的失败模式和密集检测器很不一样，因为它多了「匹配」这一层，很多症状的根因藏在匹配里而不是在模型里。下面四种覆盖了绝大多数情况。

症状：训练不收敛 / 结果异常 │ ├─ ① loss 完全不降（几个 epoch 后仍在初始值附近） │ 检查顺序： │ 1. **类别 id 是否 0-based**？很多标注是 1-based，导致所有目标被判成别的类 │ 2. 框格式是不是 **归一化的 cxcywh**？给成 xyxy 或像素坐标 -> 代价矩阵全错 │ 3. 匹配代价的三个权重是否被误设为 0（尤其 cls 项用的是**概率**不是 log 概率） │ 4. backbone 是否被整体冻结（含最后一个 stage） │ 5. **先把一个 batch 过拟合**：单张图训 500 步，loss 必须接近 0 │ ├─ ② 全部预测背景（前景 query 占比 -> 0，AP=0 但 loss 在降） │ 成因：**no-object 的类别权重没降**（eos_coef）。N=100 个 query 里 │ 93 个是背景，不降权时背景项主导梯度 -> 最优策略就是全判背景 │ 检查：打印前景 query 占比；看 cls loss 中前景/背景的贡献比 │ 修复：eos_coef=0.1（DETR）；或换 focal loss（Deformable/DINO 的做法） │ ├─ ③ 框全都聚在图像中心（中心分布熵极低） │ 成因：query 还没完成空间特化 —— 这是**早期的正常现象**， │ 但如果 30 epoch 后仍如此，说明 cross-attention 没学起来 │ 检查：中心分布熵随 epoch 的曲线；cross-attention 的注意力质量 alpha │ 修复：接多尺度；上两阶段/查询选择给参考点；检查位置编码是否真的生效 │ └─ ④ 重复框大量出现（同一目标 2~3 个高分框） 成因 a：**decoder 的 self-attention 被误关**（或 mask 写错）-> query 无法协商去重 成因 b：一对多分支与一对一分支**共用了同一次 self-attention**（模块 04） 成因 c：训练不足，模型还没学会一对一 检查：统计重复框率；关掉 self-attn 对比；看 DN 的 attention mask 是否非对称 修复：按成因治；**在收敛前不要用「加 NMS」来掩盖它**

直白说

第 ② 种最值得记住，因为它的表现极具迷惑性：loss 在稳稳下降，曲线好看得不得了，AP 却是 0。原因是模型找到了一个「局部最优」——既然 93% 的 query 目标都是背景，那全判背景就能把分类损失压得很低。这不是 bug，是损失函数设计不当时的理性行为。

严谨说

所以 eos_coef（no-object 的分类损失权重）是 DETR 里少数几个「必须按 N 与目标密度调」的超参：N 越大、单图目标越少，背景占比越高，就越需要降权。DETR 用 N=100、eos_coef=0.1；Deformable/DINO 换成 focal loss 后不再需要它，因为 focal 的 (1−p)^γ 会自动压制已经学会的简单背景样本——这是模块 02 讲的「集合损失与 focal loss 的关系」在工程上的落点。面试里能把 eos_coef 和 focal loss 联系起来，说明你理解的是机制而不是配置项。

最有用的一条：先把一个 batch 过拟合

这是排查一切训练问题的万能第一步：拿单张图（或 2 张）反复训 300–1000 步，关掉所有增强，看损失能不能压到接近 0、预测框能不能贴合 GT。

  • 压不下去 → 问题在数据管线或损失定义（类别 id、坐标格式、匹配代价、归一化），与超参无关；
  • 能压下去但正常训练不行 → 问题在数据规模/增强/学习率/正则，模型和损失本身是对的；
  • 压下去了但预测框位置系统性偏移 → 坐标变换的逆变换写错（letterbox / resize 的还原，C60 模块 04 的经典坑）。

这个方法的价值在于它把「无穷多个可能原因」一刀切成两半。不做这一步就去调学习率，是新手和熟手最明显的分界线。面试里被问「训练不收敛你怎么查」，第一句话就说这个，后面再展开诊断树。

4训练期该盯的四个诊断指标（而不是只盯 loss）

DETR 系的 loss 曲线信息量很低——它是分类损失、L1、GIoU 在匹配之后的加权和，任何一项出问题都会被其他项掩盖。下面四个指标各自对应一个具体故障，而且都便宜到可以每个 epoch 算一次。

指标怎么算健康值异常说明什么
① 匹配翻转率 φ相邻两次评估同一批图，统计「GT 换了认领 query」的比例随 epoch 单调下降，后期 < 0.1居高不下 = 代价矩阵没区分度（按尺寸分桶看）
② 前景 query 占比score > 阈值且 argmax ≠ no-object 的 query 数 / N接近 (单图平均 GT 数)/N→0 = 塌陷到全背景（查 eos_coef）；过高 = 重复框
③ 框中心分布熵预测中心打进 G×G 网格，算归一化熵接近 GT 中心分布的熵极低 = 框全聚在中心，query 没完成空间特化
④ 逐层 AP 单调性每层 decoder 的辅助输出各算一次 AP随层数单调上升非单调 = 迭代细化或 look-forward 配置有问题

第 ④ 个尤其被低估。DETR 系每层 decoder 都有辅助头，等于免费提供了 6 个「中途快照」——正常训练下 AP 应该逐层上升且增量递减。如果第 3 层比第 5 层还高，说明后面的层在「破坏」而不是「细化」，通常是参考框的传递（detach / 坐标空间 / sigmoid-logit 转换）写错了。

直白说

这四个指标的共同点：它们都在回答「机制有没有按预期工作」，而不是「效果好不好」。loss 和 AP 告诉你结果，这四个告诉你原因。建议把它们做成训练期的固定日志项，成本是每 epoch 在一个固定的小验证子集（200~500 张）上多跑一次前向。

严谨说

有一个实现细节要注意：φ 必须在「同一批图、同一个匹配代价函数」下测量，否则数据增强的随机性会污染结果。正确做法是固定一小批图、关掉增强、只用模型当前权重重新算一次匹配。另外 ③ 的熵要与 GT 中心分布的熵比较，而不是与均匀分布比——真实数据里目标本来就不是均匀分布的（TSR 的标志集中在图像上半部分与两侧），拿均匀分布当基准会给出误导性的「熵太低」结论。

别把这四个指标当成 KPI 去优化。它们是诊断工具，不是目标函数——比如「前景 query 占比」可以通过降低阈值人为拉高，但那毫无意义。它们的正确用法是：出问题时看哪个偏离了健康区间，从而把搜索范围从「所有超参」缩小到「一个具体机制」。

5推理端：top-k、阈值，以及要不要留一个 NMS 兜底

DETR 的推理看起来简单（没有 NMS），但有三个决定会显著影响最终指标，而且论文里往往一笔带过。

① argmax 还是 top-k：一个白拿的召回

做法怎么出框输出框数适用
argmax（原版 DETR）每个 query 取概率最大的非背景类≤ Nsoftmax + no-object 类的设定
flatten top-k（Deformable/DINO/RT-DETR）把 N × C 个 (query, 类别) 分数拉平取 top-kk（100 或 300）sigmoid/focal 的设定

差别在于：flatten top-k 允许同一个 query 输出多个类别的框。当一个 query 的 top-1 类别错了但 top-2 对了（TSR 里限速 60/80 互相错分是家常便饭），argmax 直接丢掉这个目标，top-k 还能把它救回来。代价是输出里会有更多低分框——但那正是 AP 计算所需要的（低分框只影响 PR 曲线尾部）。

这条在面试里是个漂亮的细节：「DETR 换成 sigmoid + flatten top-k 之后，AP 会涨，但这不是模型变强了，是解码方式不再丢信息」。它同时解释了为什么后续工作全部从 softmax+no-object 转向了 focal+sigmoid——no-object 类在 softmax 里会和所有前景类竞争同一份概率质量，而 sigmoid 下每个类独立判定，天然适合 top-k 解码。

② score 阈值：离线评测与在线部署要用两套

离线算 mAP 时不该设阈值（或设得极低，如 0.001）——mAP 是在整条 PR 曲线上积分的，砍掉低分框只会让 AP 变低。而在线部署必须设阈值，因为下游只能处理有限数量的候选，而且误检有代价。

  • 阈值应该按「工作点」选，不是按经验数字选：给定可接受的 FP/km（C55 模块 05 的指标），在验证集上反查出对应的分数阈值。
  • DETR 系的分数分布与 YOLO 系不同：一对一训练让高分框数量接近真实目标数，分数分布是双峰的（高分的少数 + 低分的一大堆），所以阈值的敏感区间很窄，0.3 和 0.5 的差别可能很小。
  • 置信度标定（calibration）不能省：模型输出的 0.8 不等于 80% 正确率。TSR 的下游（跟踪、地图匹配、VLA）要用置信度做贝叶斯融合，未标定的分数会让整条链路的决策偏移（C55 模块 02、C59 模块 03）。

③ 要不要仍然加一个 NMS 兜底

直白说

正确答案是：可以加，但必须知道你加的是什么。一个训练充分的 DETR，输出里的重复框率极低（notebook 里会量化），此时加 NMS 几乎删不掉任何东西——它是一道保险，不是一个后处理步骤。而它的代价是把「延迟确定性」这个选 DETR 的核心理由部分退还回去（NMS 的耗时随目标数波动）。

严谨说

所以决策取决于你选 DETR 的动机：① 如果动机是「无 NMS 的延迟确定性」（车端最常见），那就不要加，而是把重复框率做成上线门禁指标；② 如果动机是「精度」（离线自动标注、教师模型），那加一个 class-wise NMS（IoU=0.8 这种很宽松的阈值）作为保险没有坏处；③ 绝对不要用 NMS 来掩盖训练不充分——如果 NMS 能删掉大量框，说明模型还没学会一对一，此时你既付了 DETR 的训练成本，又没拿到 DETR 的部署好处。

新增后处理 = 新增一条训练-部署鸿沟

一个真实的部署陷阱：训练时不用 NMS、部署时加了 NMS，而两边的框格式/坐标系/类别处理方式不一致。典型症状是「离线 mAP 正常，上车后框整体偏移或成片消失」。C60 模块 04 会讲完整的对拍方法，这里只记一条：任何在推理端新增的后处理，都必须有一份 Python↔C++ 的逐阶段 diff 报告，否则不许上线。

6部署侧的真实差异：算子、动态形状与延迟稳定性

选型讨论里最容易被忽略的一半是部署。DETR 系和 YOLO 系在这一侧的差别，比在 AP 上的差别大得多。

部署维度YOLO / RTMDet 系DETR 系（Deformable/DINO/RT-DETR）
核心算子Conv / BN / SiLU —— 所有推理框架的一等公民MHA、grid_sample（可变形采样）、top-k、cumsum
TensorRT 支持全部原生融合可变形注意力常需自定义 plugin；不写就静默回退到低效实现
车端 SoC（NPU）支持成熟，量化工具链完备attention 与 grid_sample 的 NPU 支持参差不齐，可能整块落到 DSP/CPU
INT8 量化工程实践极多，掉点可控attention 的 softmax 与 LayerNorm 对量化敏感，常需混合精度
动态形状只有输入分辨率一个维度多尺度展平后的序列长度随分辨率变，optimization profile 更复杂

端到端延迟方差p99 明显高于 p50（拥堵场景目标多）p99 ≈ p50

直白说

把这张表读成一句话：DETR 系用「更难的算子」换来了「更确定的延迟」。这个交换在数据中心 GPU 上几乎白赚（算子都支持，延迟确定性是纯收益），在车端 SoC 上则要具体测——如果可变形采样在你的芯片上跑得极慢，那省下来的 NMS 时间可能远远不够补。

严谨说

还有一个常被忽略的 DETR 系部署优势：decoder 层数可以在推理时裁剪，而无需重训。因为每层都有辅助头，第 3 层的输出本身就是一个可用的检测结果。这意味着同一份权重可以支持多档速度-精度（RT-DETR 明确把它作为卖点）——在多硬件平台的量产项目里，这个性质的工程价值极高：低算力车型跑 3 层，高配车型跑 6 层，模型管理只有一份。YOLO 系要做到这一点必须训多个模型。

「无 NMS」这个卖点要算清楚才能用。NMS 在目标少时只要零点几毫秒，在密集场景（几百个候选）才会涨到几毫秒。如果你的场景目标数稳定且不多（TSR 单帧标志数通常 < 10），NMS 的绝对耗时和波动都很小，「无 NMS」带来的实际收益可能不到 1 ms——此时它不足以成为选型的决定性理由。C53 模块 05 会给出实测方法。面试里能主动说出「这个收益要看目标数分布」，比背诵卖点有说服力得多。

这是本模块最该背下来的一张表。注意每一行都要能说出「为什么」，只念结论会被追问穿。

维度YOLO / RTMDet 系DETR 系（DINO / RT-DETR）为什么
数据量需求低：几千张就能出可用模型高：一对一监督稀疏，小数据下方差大监督密度差一到两个数量级（模块 04）

三条容易记混的更正

  • 「DETR 收敛慢」已经过时。那是 2020 年的 DETR。DINO 是 12 epoch，比 YOLO 的 300 epoch 在墙钟时间上未必更慢。面试里说「DETR 系收敛慢所以不选」会被直接判为知识停留在三年前。
  • 「DETR 不需要 NMS 所以更快」是错的。无 NMS 带来的是延迟确定性而不是绝对速度；DETR 的 decoder 本身有成本。RT-DETR 之所以能比 YOLO 快，靠的是 hybrid encoder 的设计（C53 模块 04），不是「省了 NMS」。
  • 「DETR 对小目标弱」要加时间戳。原版 DETR 弱是真的；Deformable 之后主要弱在极小目标（<16px），中等小目标已经不弱。说这句话时要能给出尺寸区间，否则显得没实测过。

把选型逻辑压缩成一条决策规则：「先看约束，再看指标」。约束包括：车端芯片支持什么算子、数据量有多少、迭代节奏多快、延迟预算的 p99 要求是多少、团队有没有 DETR 系的调试经验。这些约束往往能直接排除一半选项，剩下的才轮到比 AP。面试里被问「你会选哪个」，先反问约束是加分项，直接报模型名是减分项。

8给 TSR 选哪个：一次完整的论证

现在把上面所有东西串成一个真实的选型决定。场景设定：量产乘用车的交通标志识别，车端 SoC，与其他感知任务共享算力，数据闭环每周迭代。

第一步：把约束列全，并给出量级

约束TSR 的具体值对选型的含义
延迟预算整个感知 33 ms（30 FPS），TSR 分到 3–6 ms排除大骨干；p99 必须可控
目标像素尺寸主力 12–48 px，长尾到 8 px多尺度必需；极小目标是 DETR 系的弱区
单帧目标数通常 < 10，龙门架场景 10–20NMS 的绝对耗时很小 → 无 NMS 的收益有限
类别数含变体 40–200+，长尾极重两级架构有吸引力（C55 模块 02）
数据量十几万到百万张，但高度相关（连续帧）有效样本数远小于名义数量 → 偏向数据效率高的方案
迭代节奏每周更新数据并重训训练时长必须在 1 天内
部署工具链车规 SoC + 厂商 NPU 编译器，INT8 为主非标准算子风险高

第二步：逐条比对，给出结论

  1. 延迟稳定性的收益在 TSR 上被削弱：单帧目标数 < 10，NMS 耗时零点几毫秒且波动很小。选 DETR 的第一理由在这个场景里不成立。
  2. 部署风险的代价在车端被放大：可变形采样在 NPU 上没有原生支持时，可能整块回退，延迟直接超预算。这是一个「要么能跑要么不能跑」的硬约束，不是 0.5 AP 的取舍。
  3. 极小目标是 TSR 的核心场景，恰好是 DETR 系的弱区：而 YOLO/RTMDet 系有成熟的小目标工程生态（P2、切片推理、NWD 等，见 C57）。
  4. 数据效率有利于密集检测器：TSR 数据虽多但高度相关，稀有标志类可能只有几百个实例，一对一的稀疏监督在长尾类上更吃亏。
  5. 但 DETR 系不是没有位置：DINO/Co-DETR 这类大模型在离线环节的价值极高——作为自动标注的教师模型、作为难例挖掘的高召回筛选器、作为蒸馏的教师（C58）。这些环节没有延迟约束，正好发挥 DETR 系的精度上限优势。

结论（可以原样在面试里说）：

车端量产模型选 YOLO/RTMDet 系（或 RT-DETR，视 SoC 对 attention 与 grid_sample 的支持而定），离线环节用 DINO/Co-DETR 系。

理由三句话：① TSR 单帧目标少，无 NMS 的延迟收益不足以抵消车端算子支持的风险；② 极小目标与长尾稀有类是 TSR 的核心场景，密集检测器在数据效率和小目标工程生态上更有优势；③ 但 DETR 系的精度上限在没有延迟约束的离线环节（自动标注、难例召回、蒸馏教师）价值极高，所以正确答案不是二选一，而是分工。

第三步：把结论变成可验证的方案

只给结论不给验证方案，是面试里最常见的失分点。下面这套动作要能说出来：

  • 先做算子可行性验证，再做精度实验：拿目标 SoC 的编译器把 RT-DETR 的可变形采样跑一遍，看是否回退、延迟多少。这一步一天就能做完，而且能直接砍掉一整条路线。
  • 评测必须按像素尺寸分桶：至少分 <16 / 16–32 / 32–64 / >64 四桶，外加按距离、光照、天气分桶（C55 模块 05）。总 mAP 在 TSR 上是一个几乎没有信息量的指标。
  • 用 p99 而不是均值报延迟，并在「密集场景（龙门架 + 拥堵）」这个最坏切片上单独测。
  • 把 DETR 系作为离线教师的收益也要量化：伪标注的精度、难例召回率、蒸馏后学生模型的增益——否则「离线用 DINO」只是一句好听的话。
先进 ≠ 适合量产

最后一个必须避开的坑：不要因为「DETR 是端到端的、更先进」就选它。「端到端」在论文里是优点，在量产系统里是可测试性的敌人——出了问题无法定位到具体模块。TSR 是一个安全相关功能，可解释性与可回滚性的权重远高于架构的先进性。C59 模块 05 会展开讲这一点。

9研究前沿与开放问题

这一节列的是「今天还没有好答案、但直接影响 TSR 工程决策」的问题。

  • DETR 系在小数据集上的行为缺乏系统研究：几乎所有对比都在 COCO（118k 图）上做。在几千到几万张的自建数据集上，一对一匹配的方差有多大、需要多少 DN 组、query 数该怎么定——没有可靠的经验规律。而这恰恰是绝大多数工业项目的真实规模。
  • NMS-free 的「确定性」缺少形式化保证：一对一是训练出来的性质，不是结构保证的。在分布外输入（罕见的密集同类场景）上，模型可能重新输出重复框，而系统没有任何兜底。「如何给 NMS-free 一个可验证的上界」是开放问题，对安全相关系统尤其重要。
  • 可变形采样的边缘部署效率：grid_sample 类算子在各家 NPU 上的支持与效率差异巨大，且缺少公开的横向评测。「用固定采样点模式（可离线展开成 gather）近似可变形采样」是一个有前景但研究不足的方向，它能把动态采样变成静态图友好的操作。
  • 置信度标定：DETR 系的分数分布与密集检测器差别很大，而下游（跟踪、地图融合、VLA）都假设分数是概率。一对一训练下的标定方法（温度缩放是否适用、分尺寸标定是否必要）研究很少，但对 TSR 的多帧融合（C55 模块 04）是硬需求。
  • decoder 层数可裁剪的精度-延迟曲线：RT-DETR 把它当卖点，但「裁到几层开始崩」「不同场景的最优层数是否不同」缺少系统刻画。如果层数能按场景动态决定（简单场景 2 层、复杂场景 6 层），车端的平均算力占用可以大幅下降——但动态深度会破坏静态图导出，这是算法与部署的又一处直接冲突。
  • DETR 系与时序的结合：TSR 本质是「接近过程」，单帧检测只是输入。MOTR / TransTrack 把 query 跨帧传递的思路很自然，但训练稳定性问题（跨帧的匹配翻转）比单帧更严重，目前尚无量产级方案。这是 C55 模块 04 与本课的交叉地带。

必读：★ End-to-End Object Detection with Transformers（Carion et al., ECCV 2020）——附录里的训练细节与超参消融，是本模块第 1 节的一手来源；★ DINO（Zhang et al., ICLR 2023）与 detrex / mmdetection 里 DINO 的完整配置文件，逐项对照本模块的配方表；★ RT-DETR: DETRs Beat YOLOs on Real-time Object Detection（Zhao et al., CVPR 2024）——重点看 hybrid encoder 的动机与 decoder 层数可调的实验，以及它对「无 NMS 到底值多少」的量化；Deformable DETR（Zhu et al., ICLR 2021）的实现细节部分（多尺度参考点与 offset 的归一化方式，是复现时最容易写错的地方）；Detection Transformer with Stable Matching（Liu et al., ICCV 2023）对匹配不稳定的最新解释；YOLO 侧对照读 YOLOv10（一致双分配，把 NMS-free 带进 YOLO）与 RTMDet。相邻课程：C53 模块 04/05（RT-DETR 与实时检测器选型）、C55（TSR 系统设计与安全导向评测）、C57（小目标）、C60（车端部署与一致性）、C61 模块 05（面试题库）。完整清单见 references.md。
