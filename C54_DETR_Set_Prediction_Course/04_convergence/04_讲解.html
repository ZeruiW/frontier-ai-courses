1500 epoch 从哪来：把「慢」拆成两个可以分别修的根因

原版 DETR 在 COCO 上要训 500 epoch 才追平 Faster R-CNN 的 1× 配方（12 epoch）。这是 40 倍的训练成本差距，也是 2020–2022 年整个 DETR 家族演进的唯一驱动力。

但「慢」不是一个可以直接修的东西。面试里能立刻拉开差距的答法，是把「慢」拆成两个彼此独立的根因——它们发生在模型的不同部位、用不同的指标度量、由不同的后续工作解决。只会说「DETR 收敛慢」的人和能说出这两条的人，水平差一个档次。

根因 ①：cross-attention 在初期近似均匀，梯度被摊薄到全图

decoder 的 cross-attention（交叉注意力）要做的事是：让每个 object query 在 HW 个空间位置里找到自己该负责的那个目标。但在训练刚开始时，Q/K 投影是随机初始化的小权重，点积结果接近 0，softmax 之后注意力权重近似均匀分布——每个空间位置分到大约 1/HW 的权重。

这意味着什么？反向传播时，落在目标区域上的梯度只占总梯度的一个极小比例，其余全部打在背景上。而且这个比例随目标变小而急剧恶化。

\[\alpha_0 \;=\; \frac{\text{目标在特征图上占的格子数}}{H \cdot W} \;=\; \frac{(w/s)\cdot(h/s)}{H \cdot W}\]
场景（1333×800 输入，C5 stride 32）目标像素尺寸占特征图格子初始注意力质量 α₀
大目标（近处车辆）256×2568×8 = 646.2%
中目标（行人）64×1282×4 = 80.78%
COCO 平均目标≈100×100≈9.80.95%
TSR：30 m 外的限速牌32×321×1 = 10.098%
TSR：60 m 外的限速牌16×160.5×0.5 = 0.250.024%

最后两行就是这门课要反复回到的地方：在交通标志检测里，原版 DETR 的 cross-attention 初期把 99.98% 的梯度打在了背景上。模型必须靠这 0.02% 的信号慢慢把注意力「拧」到标志上——这就是 500 epoch 的第一半。

直白说

为什么这不是「学一会儿就好了」？因为注意力要变尖锐，靠的是 Q/K 投影学到「这个 query 的内容和那个位置的特征相似」。可是在注意力还没变尖锐之前，query 拿到的是全图平均特征，根本形不成有区分度的内容——这是一个鸡生蛋的循环。Deformable DETR 论文里画的注意力图显示，要训到约 10 万次迭代注意力才明显稀疏化。

严谨说

更精确地说：这是一个「初始化处于高熵鞍区」的优化问题。softmax 注意力的对数几率需要从 0 增长到 ln((HW−n)/n) 才能让目标区域占到一半的注意力质量。目标越小，n 越小，需要的对数几率增量越大——而增长速率由梯度决定，梯度又正比于当前的注意力质量。于是小目标陷入「信号弱→学得慢→信号仍弱」的自锁。notebook 里会用一个玩具模型把这个 epoch 数算出来，并复现「小目标需要的 epoch 数显著多于大目标」。

根因 ②：二分匹配不稳定，优化目标每个 epoch 都在抖

模块 01 已经指出了这个问题，这里给它一个精确的说法：同一张图的同一个 GT，在相邻两个 epoch 里可能被不同的 query 认领。一旦认领关系翻转，上个 epoch 被训练着去拟合「停车让行标志」的那个 query，这个 epoch 的目标变成了「背景」；而另一个一直在学背景的 query 突然被要求回归出一个精确的框。

梯度方向不是变小，而是掉头。这与「学习率太大」的症状完全不同——损失曲线看起来在降，但每个 query 学到的东西被反复覆盖。

最后一行是这一节的核心：两个根因彼此正交，所以两次收益可以相乘而不是相加。这解释了为什么 DINO = Deformable 的多尺度采样 + DN 的稳定监督，能在 12 epoch 拿到 49.0 AP——它同时修好了「往哪看」和「学什么」。面试里如果只答出一个根因，追问「那 DN-DETR 又解决了什么」时就会卡住。

有一个常见的错误归因：把 DETR 收敛慢归结为「Transformer 需要大数据 / 缺少归纳偏置」。这个说法太笼统，而且被后续工作证伪了——DINO 用的还是 Transformer、还是从 ImageNet 预训练的 ResNet-50、还是 COCO 那 118k 张图，12 epoch 就到了 49 AP。真正被修好的是注意力的空间稀疏性和监督信号的稳定性，不是「归纳偏置」这种不可操作的东西。

2Deformable Attention：把 O(HW) 的全局搜索换成 K 个可学采样点

Deformable attention（可变形注意力）的想法一句话就能说完：与其让 query 和全图 HW 个 key 做点积再 softmax，不如让 query 直接预测「我要看哪 K 个点」，只在这 K 个点上采样加权。

\[\text{MSDeformAttn}(z_q, \hat{p}_q, \{x^l\}) = \sum_{m=1}^{M} W_m \Bigg[ \sum_{l=1}^{L} \sum_{k=1}^{K} A_{mlqk} \cdot W'_m\, x^l\big(\phi_l(\hat{p}_q) + \Delta p_{mlqk}\big) \Bigg]\]

符号逐个解释，每一个都对应一个设计决策：

符号含义为什么这么设计
z_qquery 的内容向量偏移与权重只由它产生
p̂_qreference point（参考点，归一化 [0,1]²）给 query 一个空间先验；两阶段版本里它来自 encoder 提案
Δp_mlqk第 m 头、第 l 层、第 k 个采样点的偏移由 z_q 线性预测，可学；双线性插值让它可微
A_mlqk采样点的注意力权重，对 L·K 做 softmax也由 z_q 线性预测——不做 Q·K 点积
x^l第 l 层特征图L=4 个尺度共享同一套 query
φ_l把归一化坐标映射到第 l 层的像素坐标让同一个参考点能跨尺度采样
表里最容易被忽略、也最容易在面试里拿分的一行是 A_mlqk：可变形注意力的权重不是 query 和 key 的相似度，而是 query 自己「凭空」输出的一组数。换句话说它放弃了内容匹配，只保留了「加权求和一小撮位置」这个骨架。这就是它便宜的根本原因（不需要算 HW 个点积），也是它的代价（权重与被采样位置的内容无关，靠采样位置本身来编码「看什么」）。被问到「Deformable attention 还算不算注意力」时，这是标准答案。
DETR cross-attention（每个 query 看全图） query ──┬─► key(0,0) w≈1/1025 ├─► key(0,1) w≈1/1025 HW = 25×41 = 1025 个 key ├─► ... 权重来自 Q·K 点积，初期近似均匀 └─► key(24,40) w≈1/1025 **梯度被摊薄 1025 份** Deformable attention（每个 query 只看 L×K 个点） query z_q ──► 参考点 p̂_q ──► 线性层预测 Δp_1..Δp_K 与 A_1..A_K │ ├─► 双线性采样 x(p̂_q + Δp_1) × A_1 ├─► 双线性采样 x(p̂_q + Δp_2) × A_2 L×K = 16 个点 ├─► ... **权重不经过 Q·K** └─► 双线性采样 x(p̂_q + Δp_K) × A_K 梯度同时流向两处： ① 被采样格点的特征值（4 个格点/采样点，由双线性权重分配） ② **采样位置 Δp 自己**（dv/dx, dv/dy 来自双线性插值的解析导数） ← 这是「学会往哪看」的直接通道，全局 attention 没有这条路

直白说

第 ② 条是整个机制的灵魂。全局注意力只能间接地学「往哪看」——它得先把某个位置的特征学得和 query 相似，权重才会上去。而可变形注意力有一条直达的梯度：如果往右挪 3 个像素能让损失变小，dL/dΔp 就直接告诉你往右挪。这就是 500 epoch 变 50 epoch 的机制层解释。

严谨说

严格地说，这条梯度来自双线性插值的可微性。设采样点落在格点 (x0,y0) 的单元内，dx = x−x0，则 ∂v/∂x = (1−dy)(f₁₀−f₀₀) + dy(f₁₁−f₀₁)——它正比于特征图在该处的局部差分，也就是特征的空间梯度。推论：在特征平坦的区域（比如纯色天空），∂v/∂Δp ≈ 0，采样点收不到位置梯度，会停在原地不动。notebook 里会把这个解析梯度写出来并用中心差分校验到 1e-7。

计算量账：为什么 DETR 做不了多尺度而 Deformable 可以

把与 query 数相乘的那部分算清楚（C=256，N_q=300，1333×800 输入）：

方案每个 query 的乘加量总量（×300 query）相对
DETR，单尺度 C5（HW=1025）2·1025·256 ≈ 5.2×10⁵1.6×10⁸1×
DETR，若做 4 尺度（HW≈22148）2·22148·256 ≈ 1.1×10⁷3.4×10⁹21.6×
Deformable，4 尺度 K=4L·K·C + C·(3·L·K) ≈ 1.6×10⁴4.9×10⁶0.03×

最后两行放在一起看就明白了：原版 DETR 不是「忘了」做多尺度，而是全局注意力在多尺度上的复杂度直接不可承受（encoder 的 self-attention 更是 O((HW)²)，4 尺度下会爆炸）。可变形注意力把复杂度从「与特征图面积成正比」改成「与采样点数成正比」，多尺度才第一次变得免费。这是一个「先有机制，才有能力」的经典例子。

别把可变形注意力和 deformable convolution（可变形卷积，DCN）混为一谈。DCN 是每个输出位置学一组偏移去采样输入，偏移由局部特征产生，本质仍是卷积；可变形注意力是每个 query（不绑定在特征图格点上）学一组偏移，并且带 softmax 权重与多尺度聚合。共同点只有「用双线性插值实现可学采样」这一条实现技巧。面试里被追问区别时，答「query 不绑定空间位置 + 跨尺度 + 带注意力权重」这三点即可。

3Deformable DETR 的另外两件事：多尺度与两阶段

很多人把 Deformable DETR 的收益全部归给「可变形注意力」，这在面试里会被追问穿。论文的消融清楚地把收益拆成了四块，而且可变形注意力本身只是打开大门的那一块。

+ 可变形注意力K 点采样替代全局梯度弥散；让多尺度成为可能—

+ 迭代框细化每层 decoder 在上一层框上出增量让参考点逐层逼近，采样越来越准45.4
+ 两阶段encoder 出提案，top-K 作为参考点query 不再从零猜位置46.2

多尺度：为什么它对 TSR 是生死问题而不是加分项

原版 DETR 只用 C5（stride 32）。回到上一节的表：一个 60 米外、16×16 像素的限速牌，在 stride 32 的特征图上只占 0.25 个格子——它在数值上根本没有独立的特征向量，被邻域的路面、树木、天空混叠在同一个格子里。任何注意力机制都救不了「信息已经在下采样时被抹掉」这件事。

特征层stride16×16 标志占几个格子32×32 标志占几个格子能不能被采样到
P382×2 = 44×4 = 16能
P4161×1 = 12×2 = 4勉强
P5（DETR 唯一用的层）320.5×0.5 = 0.251×1 = 1不能
P6640.06250.25不能
多尺度不是选项，是准入条件

这张表推出一条对 TSR 项目非常硬的结论：如果你要用 DETR 系做交通标志检测，多尺度（至少到 stride 8，理想是加 stride 4 的 P2）不是调参选项，是准入条件。「我们用了 DINO，但为了省显存只保留了 P4–P6」这种配置，在远距离小标志上的召回会直接崩掉，而整体 mAP 可能只掉两三个点——因为小标志在数量上并不占多数，平均值把它掩盖了。这也是 C55 会反复强调「必须按像素尺寸分桶评测」的原因。

两阶段与迭代细化：让参考点从「猜」变成「有依据」

原版 Deformable DETR 的 query 仍然是可学嵌入，参考点由 query 线性预测——它对具体这张图一无所知。两阶段版本改成：让 encoder 输出的每个特征点都当作一个提案，预测 objectness 与初始框，取 top-K（K = query 数）作为 decoder 的参考点。

单阶段（原始 Deformable DETR） 可学 query 嵌入 ──► Linear ──► 参考点 p̂_q （与图像无关，只是学到的统计先验） 两阶段（Deformable DETR two-stage / DINO 沿用） encoder 特征（所有尺度所有位置，约 2.2 万个） │ ├─► 每个位置预测 (objectness, box) ← 这一步就是一个密集检测器 │ └─► top-K 挑选（K = 300/900）──► 参考点 p̂_q 与初始框 │ decoder 只需要**细化**，不需要**发现** 迭代框细化（look forward once, Deformable DETR） layer1: b1 = b0 + Δ1 loss1 ── 梯度 ──► Δ1 的参数 └─ detach ──► layer2: b2 = b1 + Δ2 loss2 ── 梯度 ──► Δ2 的参数 └─ detach ──► layer3: ... **detach 切断了 loss2 对第 1 层参数的梯度** ← DINO 的 look forward twice 就是去掉它

直白说

两阶段的价值可以用一句话概括：它把「在整张图里找出目标大概在哪」这件本来要 decoder 从零学的事，交给了一个密集预测头——而密集预测头本来就擅长这个（它每个位置都有监督）。decoder 于是从「发现 + 细化」的双重任务降级为「细化」的单一任务。这也解释了为什么两阶段对小目标的收益更明显：小目标最难的是「发现」。

严谨说

代价有三个，都要能说出来：① encoder 侧多了一个检测头，训练时要为它单独算一份密集损失（Deformable DETR 复用了同一套 Hungarian 损失做提案监督）；② top-K 选择在推理时引入了一次排序，虽然便宜但让计算图多一个数据依赖的算子（C60 会讲这对导出与 TensorRT 的影响）；③ 提案的质量成了新的瓶颈——如果 encoder 的 objectness 对某类目标系统性偏低，那类目标连进入 decoder 的资格都没有。第 ③ 点在长尾场景（TSR 的稀有标志）里是真实风险。

4DN-DETR：与其修匹配，不如绕开匹配

Deformable DETR 把 epoch 从 500 压到 50，但根因 ② 原封不动：匹配依然在翻转。DN-DETR 的做法极其漂亮——它没有去改进匈牙利算法，也没有加匹配的稳定性正则，而是额外塞进一批「不需要匹配」的 query。

去噪任务：把最后一公里单独拎出来训练

  1. 取这张图的 GT 框，加一点噪声（中心平移 + 尺寸缩放），得到一个「差不多但不准」的框；
  2. 取这张图的 GT 类别，以概率 γ 翻转成另一个类别；
  3. 把 (带噪框, 带噪标签) 编码成额外的 query，和正常的 matching query 一起送进 decoder；
  4. 这些 query 的监督目标是已知的——把框还原成 GT 框、把标签还原成 GT 标签。完全不经过匈牙利匹配。

直白说

为什么这管用？因为去噪任务恰好就是匹配分支最终要学会的那件事的「最后一公里」：给你一个大致对的框，把它修准。原来 query 要同时学「找到目标」和「修准框」，而且这两件事的监督还在抖；现在「修准框」这件事有了一份从第一个 iteration 就完全稳定的监督。

严谨说

更精确地说，DN 把一个不稳定的联合任务分解成了两个子任务的和：匹配分支继续学「发现 + 认领」，去噪分支专门学「条件重建」。二者共享同一套 decoder 参数与 cross-attention，所以去噪分支学到的定位能力会直接迁移到匹配分支。关键是去噪分支的监督密度：每个 GT 在每次迭代都被 G 组去噪 query 各学一遍（G 常取 5~100），而匹配分支每个 GT 只有 1 个 query。监督信号密度提升了一到两个数量级，而且完全无噪。

attention mask：这个机制的成败全在这里

去噪 query 携带了 GT 的信息（框的位置、类别）。如果匹配 query 能通过 self-attention 读到它们，就是把答案抄给了模型——训练损失会掉得非常漂亮，验证 AP 一塌糊涂。所以必须用 attention mask 做隔离：

谁看谁允许？理由
匹配 query → 去噪 query❌ 禁止否则 GT 泄漏，这是最致命的一条
去噪组 g → 去噪组 g'（g≠g'）❌ 禁止每组是同一批 GT 的不同噪声版本，互看等于抄答案
去噪组 g → 同组内部✅ 允许同组内每个 query 对应不同 GT，互相去重是有意义的
去噪 query → 匹配 query✅ 允许匹配 query 不含 GT 信息，看它无害；官方实现确实是不屏蔽的
匹配 query → 匹配 query✅ 允许这就是原本的去重协商
mask 写错 = 训练时抄答案

第四行是个高频考点：attention mask 不是对称的。很多人默认「互相看不见」就写成对称矩阵，那样会削弱去噪分支从匹配分支获得的上下文。官方 DINO 实现里，去噪 query 的行只屏蔽其他去噪组的列，匹配 query 的列是开放的。

而忘记加 mask 的症状极具欺骗性：训练 loss 迅速降到很低、去噪分支的重建误差趋近 0、验证 AP 却比不加 DN 还差。排查方法：把去噪分支关掉重训一次，如果验证 AP 反而涨了，八成是 mask 写错了。

噪声强度：一个必须调但很少有人讲清楚的超参

噪声太小，去噪任务退化成恒等映射，学不到东西；噪声太大，带噪框和 GT 已经不是同一个目标，去噪变成了「无中生有」，反而制造错误监督。DN-DETR 用两个参数控制：

参数典型值含义太大会怎样
box_noise_scale λ0.4中心平移 ≤ λ/2·w，尺寸缩放 ∈ [1−λ, 1+λ]带噪框与 GT 的 IoU 掉到 0.3 以下，重建目标不合理
label_noise_ratio γ0.2 ~ 0.5以 γ 的概率把标签换成另一个类分类分支学到「输入标签无所谓」，去噪退化
dn_number G100（DINO）去噪组数显存与训练时间线性上升；单图 GT 多时要动态截断

标签翻转这一项对 TSR 特别有价值：它训练的正是「给我一个大致对的框和一个可能是错的类别，请你从图像证据里纠正它」。交通标志里限速 60 / 80 / 100 这类形状完全相同、只有数字不同的类，恰恰最需要这种纠错能力。把 γ 调大一点、并且让翻转优先发生在易混类之间（而不是全类均匀采样），是一个有依据的定制方向。

记住 DN 最漂亮的一点：它不改任何网络结构、不加任何推理开销。去噪 query 只在训练时存在，推理时整块拿掉，模型的参数量、FLOPs、延迟完全不变。「零推理成本换 4 倍收敛速度」——这类改动在工业界的采纳率总是最高的，因为它不需要重新做部署验证。面试里主动点出这一点，说明你在用工程视角读论文。

5DINO：三件小事，各修一个具体短板

DINO（DETR with Improved deNoising anchOr boxes，注意与自监督的 DINO 同名不同物）是 DETR 家族第一个在 COCO 榜首击败所有密集检测器的模型（Swin-L 63.3 AP test-dev）。它在 DAB-Deformable-DETR + DN 的基础上只加了三件事，每件都小到可以在一段话里讲完，但每件都精确地对准了一个具体缺陷。

① 对比去噪 CDN：教模型说「不」

原版 DN 只有正样本：所有去噪 query 的目标都是「还原成这个 GT」。问题是模型从来没被教过「这个框离得太远，应该判为背景」——于是它倾向于把任何接近的框都拉向最近的 GT，结果就是重复框与过度自信的低质量预测。

对比去噪 CDN：每个 GT 生成一对 query λ1 λ2 GT ●───────────────┼───────────────┼──────────────► 离 GT 的噪声尺度 │ 正样本区 │ 负样本区 │ （不生成） │ noise < λ1 │ λ1<noise<λ2 │ └─► 目标 = 还原成 GT 的框与类别 └─► 目标 = **no-object**（背景） λ1 = 1.0, λ2 = 2.0（DINO 默认，单位是框宽高的倍数） 作用：在 GT 周围划出一圈「近但不够近」的硬负样本， 直接教模型「什么距离算认领成功」——**这正是 NMS 在推理期做的事， 被搬到了训练期**，所以 DINO 的重复框显著少于 DN-DETR。

直白说

CDN 的作用可以类比成给模型加了一条决策边界的直接监督。没有负样本时，模型只知道「往 GT 靠」这个方向，不知道边界在哪；有了负样本，正负两组 query 的噪声尺度之差就明确定义了边界的位置。论文里 CDN 对小目标 AP_S 的提升最明显——因为小目标的「近但不够近」区域相对框尺寸更大，最容易产生重复。

严谨说

严格看，CDN 是把 hard negative mining（难负样本挖掘）以一种可控且无需搜索的方式引入了 DETR：负样本不是从模型预测里挑出来的（那样会有课程学习的不稳定性），而是由 GT 按固定噪声尺度构造出来的。代价是这些负样本的分布由 λ1/λ2 人为决定，不一定匹配模型真实的困难区域——这是 C58「难例挖掘」里会展开讨论的取舍：构造式负样本 vs 挖掘式负样本。

② Mixed query selection：只借位置，不借内容

两阶段 Deformable DETR 从 encoder 的 top-K 特征里同时取出了位置（初始框）和内容（作为 decoder query 的初始特征）。DINO 发现后者是错的：

方案位置（reference box）内容（decoder embedding）问题 / 收益
静态（原始 DETR / DAB）可学嵌入可学嵌入与图像无关，decoder 要从零发现
纯查询选择（two-stage Deformable）encoder top-K 的框encoder top-K 的特征encoder 特征是「初步的」，可能歧义或含多个目标，用作内容会误导 decoder
Mixed（DINO）encoder top-K 的框仍用可学的静态嵌入位置有图像依据，内容保持中性 → 更稳

这个设计的逻辑值得记住：位置先验是安全的（错了后面还能细化），内容先验是危险的（错了会一直误导 cross-attention 去看错地方）。面试里被问「为什么不把 encoder 特征直接当 query」，这就是答案。

③ Look forward twice：让每一层的框预测也为下一层负责

Deformable DETR 在层间对参考框做了 detach()（论文里叫 look forward once）：第 i 层预测出的框传给第 i+1 层时切断梯度，所以第 i 层的参数只被第 i 层的辅助损失监督。DINO 去掉这个 detach（look forward twice）——第 i 层的参数同时被第 i 层和第 i+1 层的损失监督。

\[\text{LFO}:\; \frac{\partial \mathcal{L}}{\partial \theta_i} = \frac{\partial \mathcal{L}_i}{\partial \theta_i} \qquad\qquad \text{LFT}:\; \frac{\partial \mathcal{L}}{\partial \theta_i} = \frac{\partial \mathcal{L}_i}{\partial \theta_i} + \frac{\partial \mathcal{L}_{i+1}}{\partial b_{i+1}}\cdot\frac{\partial b_{i+1}}{\partial b_i}\cdot\frac{\partial b_i}{\partial \theta_i}\]

为什么原来要 detach？因为担心早期层的框预测不准，梯度会互相干扰。DINO 的论证是：既然有了 DN 提供的稳定监督，早期层的框已经足够好，此时打通梯度带来的「早期层为最终结果负责」收益大于干扰。这是一个典型的「前一个改进让后一个改进变得可行」的例子——顺序不能颠倒。

改动修的是哪个具体缺陷论文消融量级（R50, 12 epoch）
CDN 对比去噪重复框多、置信度不校准、小目标误检约 +0.7 AP，AP_S 提升最明显
Mixed query selectionencoder 特征作内容会误导 cross-attention约 +0.2 AP
Look forward twice早期层的框预测缺少下游监督约 +0.2 AP
三者叠加 + DN + Deformable—49.0 AP @ 12 epoch

看到「+0.2 AP」不要轻视，也不要迷信。检测任务里同一配置换随机种子的波动就有 ±0.2~0.5 AP（C61 模块 01 会详细讲），所以单看一个 +0.2 的消融数字是没有统计意义的。DINO 这三项之所以被普遍接受，是因为它们在多个骨干、多个 epoch 配置、多个后续工作里都稳定复现——而不是因为那张表上的数字。面试里如果对方拿一个 +0.3 的结果问你「这算改进吗」，正确答案是「要看几个种子、方差多大」。

6一对多匹配的回归：训练要密集，推理才要唯一

2022 年底开始出现一批看似「开倒车」的工作：Group DETR、H-DETR、Co-DETR 又把一对多匹配加回了训练。理解它们，等于理解了 DETR 范式最深的一层。

一句话点破：「一对一匹配」是推理端的需求（输出不能有重复框，才能扔掉 NMS），不是训练端的最优（每个 GT 只有 1 个正样本，监督密度比密集检测器低两个数量级）。既然如此，正确的做法就是——训练时用一对多拿密集监督，推理时只留一对一分支拿无重复输出。这个「训练与推理不对称」的设计，是近三年检测领域最重要的观念转变之一。

先把监督密度的账算清楚。COCO 平均每图 7.3 个标注框：

检测器每图每次迭代的正样本数相对 DETR推理端有重复框吗
Faster R-CNN（RPN + head）≈ 256（采样后）35×有 → 需要 NMS

这张表把「DETR 为什么慢」的第三个角度也讲清楚了：密集检测器每个 iteration 从一张图里榨出几百条监督，DETR 只榨出 7 条。要拿到同样多的梯度更新次数，DETR 自然需要几十倍的 epoch。notebook 里会用这个账反推出「500 epoch ÷ 11 组 ≈ 45 epoch」——和 Group DETR 论文报告的收敛加速惊人地一致。

直白说

三者的差别在于「密集监督加在哪一层」：Group DETR 加在 query 层（复制 query），H-DETR 加在匹配层（复制 GT），Co-DETR 加在 encoder 层（直接挂密集头）。越靠近底层，对 backbone/encoder 表征的监督越直接，收益越大，但工程侵入性也越强——Co-DETR 相当于把一个完整的密集检测器缝在了 DETR 上，训练代码复杂度显著上升。

严谨说

有一个共同的隐性约束必须说清楚：一对多分支绝不能与一对一分支共享同一次 self-attention。self-attention 的作用是让 query 互相协商去重；如果一对多的 query 和一对一的 query 在同一次 attention 里，一对多那些「本来就该重复」的 query 会把去重信号搅乱，结果是一对一分支也开始输出重复框，NMS-free 的性质丢失。Group DETR 用分组 mask、H-DETR 用两次独立前向来保证这一点——这与 DN 的 attention mask 是同一类设计约束。

这一节还有一个反向的工程结论：如果你在推理端仍然要加 NMS，那你就没必要坚持一对一匹配。「训练慢了几倍、部署还是要 NMS」是最糟糕的组合。选 DETR 系的唯一硬理由是「无 NMS 带来的延迟确定性」（C53 模块 04 / 本课模块 05 会算这笔账）；如果这个理由对你的系统不成立，密集检测器在同等算力下几乎总是更省心。

7一条主线：每一步都在解决「监督信号太稀疏」

这一节是本模块的核心，也是面试里能一击命中的总结。前面五节看起来是五个互不相干的技巧，其实它们全部在回答同一个问题：怎么让每一次前向传播产生更多、更准、更稳的监督信号？

\[\rho \;\propto\; \underbrace{N_{\text{pos}}}_{\text{每次迭代被监督的 query 数}} \;\times\; \underbrace{\alpha}_{\text{注意力落在目标上的质量}} \;\times\; \underbrace{(1-\phi)}_{\text{匹配未翻转的比例}}\]

这不是论文里的公式，是一个用来组织记忆的粗糙模型：三个因子分别对应「监督有多少」「监督打在哪」「监督稳不稳」。DETR 家族的每一步演进，都可以定位到它抬高了哪个因子。

面试答法骨架

  1. 先给结论：DETR 收敛慢有两个正交根因——注意力初期弥散、匹配不稳定；后续工作按这两条线分头解决。
  2. 再讲第一条线：Deformable DETR 用 K 点可学采样把注意力从一开始就集中，顺带让多尺度在算力上变得可行，小目标 AP_S 从 20.5 到 26.4，500→50 epoch。
  3. 再讲第二条线：DN-DETR 加一批带噪 GT 作为额外 query，监督目标已知、不经匹配，从第一步就稳定；关键实现是 attention mask 防泄漏；50→12 epoch，且推理零开销。
  4. 再讲合流：DINO = Deformable + DAB + CDN（正负噪声对，教决策边界）+ mixed query selection（只借位置不借内容）+ look forward twice，12 epoch 到 49.0 AP，成为之后三年的默认骨架。
  5. 最后给洞察：Group/H-/Co-DETR 又把一对多加回训练，说明「一对一是推理需求而非训练最优」——这一句能显著抬高对方对你的评价，因为它说明你理解的是范式而不是模型列表。
  6. 如果对方追问「那你会怎么用」：接模块 05 的选型论证（数据量、迭代周期、部署工具链、延迟稳定性）。

把整条线压缩成一句可迁移的心法：当一个模型「收敛慢」时，不要先去调学习率，先去数「每次前向产生了多少条有效监督」，再去看「这些监督打在了正确的位置吗」「它们在相邻 iteration 之间稳定吗」。这个三问在任何用了匹配 / 采样 / 稀疏监督的系统上都成立——分割的 mask2former、跟踪的 MOTR、姿态的 PETR，走的是完全一样的演进路径。

8回到 TSR：这条演进线对交通标志检测意味着什么

这一节把前面所有结论翻译成 TSR 项目里的具体决定。四条，每条都有可执行的动作。

① 多尺度是准入条件，而且要往下加而不是往上加

交通标志的像素尺寸分布与 COCO 完全不同：绝大多数有效检出发生在 12~48 像素区间（因为要在 40~80 米外就报出来，留给下游决策的时间才够）。按前面的 stride 表，这意味着 P3（stride 8）是主力层，P2（stride 4）值得认真评估，而 P6/P7 几乎没有负载。直接照抄 COCO 配置（P3–P7 均匀分配）会把大量算力浪费在没有目标的高层上。

  • 动作：统计自己数据集的标志像素尺寸直方图，按 FPN 层级分配规则算出各层负载，据此裁剪层数（C57 模块 02 会给完整方法）。
  • 动作：可变形注意力的采样点数 K 可以按层设置——低层（小目标）给更多采样点，高层减少。

② 去噪的标签翻转应该按混淆结构定制，而不是全类均匀

默认实现里，标签翻转是在全部类别中均匀采样。但 TSR 的错分是高度结构化的：限速 60/80/100 互相错分的概率远高于「限速 60 错成禁止掉头」。把翻转分布改成按混淆矩阵采样，相当于让去噪分支专门练易混类。

这是一个「读懂机制之后才能想到」的定制点，在面试里作为「你会怎么改进」的回答非常有力：它不是换个 backbone 那种谁都能说的答案，而是说明你理解 DN 的监督到底在训练什么。配套的验证方式也要说出来：看易混类对的混淆矩阵非对角元是否下降，而不是只看总 mAP。

③ 收敛速度的真实价值不是省 GPU，是缩短数据闭环周期

量产 TSR 的工作方式是每周甚至每天都有新挖掘的难例进来（C58 讲的数据闭环）。在这种节奏下，「一次训练要 500 epoch」意味着数据改进和模型验证之间隔了一两周——闭环转不动，数据飞轮就不存在。

方案COCO 规模的一次训练TSR 数据（约 15 万图）估算一周能迭代几次
DETR（500 ep, 8×V100）≈ 6 天≈ 8 天< 1
Deformable DETR（50 ep）≈ 1.5 天≈ 2 天3

「12 epoch」才是让 DETR 系真正进入量产候选名单的门票。在此之前，无论 AP 多高，工程团队都不会选一个改一次数据要等一周的模型。

④ 密集同类场景要特别小心一对一匹配

高速龙门架上一排 5 个方向指示牌、施工区连续摆放的同款锥形警示牌——这类「多个同类目标紧邻」的场景是一对一匹配的天然弱区：query 之间的去重协商可能把相邻的真目标误判为重复而抑制掉。

密集同类目标：一对一匹配的天然弱区

症状是「密集排列时少检一两个，而且总是少中间那几个」。这不是分类问题也不是定位问题，是 self-attention 的去重把真目标当成了重复。排查方法：把 decoder self-attention 关掉重新推理一次（或者看该场景下 query 之间的注意力矩阵），如果漏检消失，就确认是去重过度。

对策：① 训练期加一对多分支（Group/H-DETR），让模型见过「相邻的多个同类目标都是正样本」；② 增大 query 数并检查前景 query 占比（模块 05 的诊断指标）；③ 数据侧用 copy-paste 合成密集同类场景（C56 模块 03）。

9研究前沿与开放问题

DETR 家族在 2023 年之后进入了「细化与统一」阶段。下面这些是仍然开放、且与 TSR 直接相关的方向。

  • 匹配稳定性的理论仍不完整：Stable-DINO 指出问题的根源是分类分数与定位质量不对齐——匹配代价里分类项用的是与位置无关的分数，导致「分类高但框差」的 query 赢得匹配。它用位置监督（position-supervised loss）修正，在 12 epoch 上再涨约 +1.5 AP。但「什么样的匹配代价能保证稳定」尚无理论刻画。
  • 去噪超参缺少原则：λ1/λ2/G/γ 四个超参都靠经验，且与数据集的目标尺寸分布强耦合。小目标数据集上「噪声尺度按框宽高的倍数」这个定义本身就可疑——16 像素的框加 0.4 倍噪声只有 6 像素，可能小于标注误差本身。这在 TSR 上是真实问题，值得做消融。
  • 一对一与一对多的统一：DEIM（2025）提出 Dense O2O——用 mosaic/mixup 提高单图目标密度，从而在保持一对一匹配的前提下提高正样本数，再配合 Matchability-Aware Loss。这条路线试图不引入额外分支就拿到密集监督，方向很干净，但对增强策略的依赖使它与「贴近部署分布」的增强原则（C56）存在张力。
  • 极小目标仍是 DETR 系的短板：即使 DINO + P2，在 8~16 像素区间的 AP 依然明显低于专门设计的密集检测器 + 切片推理（C57 模块 04）。核心矛盾是采样点数固定：K=4 个点对一个只占 2×2 格子的目标已经饱和，加点无益；而全局注意力又太贵。「稀疏采样如何在极小目标上不丢信息」没有好答案。
  • NMS-free 在边缘部署的实证仍少：论文报告的是 GPU 上的端到端延迟，而车端 SoC 上 top-k、多尺度采样（grid_sample 类算子）的支持度与效率都不同。「去掉 NMS 换来的延迟确定性，是否足以抵消可变形采样算子在边缘芯片上的低效」是一个需要在具体硬件上测的问题，C60 会给方法。
  • query 数与场景密度的耦合：N 是超参且固定。密集场景需要大 N，稀疏场景大 N 浪费且降低正样本比例。自适应 query 数（按图像内容动态决定）会破坏静态图导出——这是一个算法与部署直接冲突的开放问题。

必读（按阅读顺序）：★ Deformable DETR: Deformable Transformers for End-to-End Object Detection（Zhu et al., ICLR 2021）——重点看 Fig.2 的注意力可视化与 Table 关于多尺度/两阶段的消融；★ DN-DETR: Accelerate DETR Training by Introducing Query DeNoising（Li et al., CVPR 2022）——重点看 attention mask 的构造与不稳定性度量的定义；★ DINO: DETR with Improved DeNoising Anchor Boxes（Zhang et al., ICLR 2023）——重点看 CDN 与 mixed query selection 两节；DAB-DETR（Liu et al., ICLR 2022，4D anchor query）与 Conditional DETR（Meng et al., ICCV 2021）补足第一条线的中间环节；Group DETR（Chen et al., ICCV 2023）、DETRs with Hybrid Matching（Jia et al., CVPR 2023）、DETRs with Collaborative Hybrid Assignments（Zong et al., ICCV 2023）看一对多的回归；Detection Transformer with Stable Matching（Liu et al., ICCV 2023）看匹配稳定性的最新解释。相邻课程：本课模块 01（匈牙利匹配）、模块 03（object query）、C53 模块 04（RT-DETR 如何把这条线做到实时）、C57（小目标）。完整清单见 references.md。
