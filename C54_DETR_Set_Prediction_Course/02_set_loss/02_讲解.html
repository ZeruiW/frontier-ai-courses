1匹配代价与训练损失：两个长得像、职责完全不同的东西

模块 01 解决了「哪个预测对哪个 GT」。本模块解决「对上了之后，梯度怎么写」。这两步之间横着一个初学者几乎必然踩、面试官几乎必然追问的区分：matching cost（匹配代价）和 Hungarian loss（集合损失）不是同一个函数，虽然它们的三个组成项名字一模一样。

原因很朴素：匹配代价只用来排序（选出总代价最小的那个一一对应），它在 torch.no_grad() 里算完就扔；而损失要反向传播。一个只需要「谁比谁小」，另一个需要「梯度指向哪」。这两个需求会推出不同的函数形式。

匹配代价 C(i, σ(i))训练损失 L
用途给匈牙利算法排序，决定一一对应产生梯度，更新参数
是否需要可导不需要（在 no_grad 下计算）必须可导
分类项形式-p̂σ(i)(ci)（概率，负号取最大）-log p̂σ(i)(ci)（交叉熵）

直白说

为什么匹配时用概率 p 而不是 log p？因为要和 L1、GIoU 放在同一个代价矩阵里相加。-log p 是无界的：一个 p=1e-8 的预测会贡献 18.4 的代价，而 L1 项（归一化坐标下）通常只有 0.05 量级，GIoU 项最多 2。结果就是分类项会完全淹没定位项，匹配退化成「只看分类」——而分类分数高但框歪到天上的 query 就会抢走 GT。用概率则把分类项压在 [-1, 0]，三项量纲可比。

严谨说

严格地说，匈牙利算法要求的只是代价矩阵的序结构，任何单调变换都不改变最优匹配——但那只在单项时成立。一旦三项相加，单调变换会改变各项的相对贡献，从而改变最优匹配。所以「用 p 还是 log p」在这里不是数值技巧而是设计决策：DETR 论文明确写了这一点（§3.1 脚注）。而损失端必须用 log，因为 -p 的梯度在 p→0 时不消失也不放大，收敛远慢于交叉熵。同一件事，排序要有界，优化要陡峭。

别把代价和损失混为一谈 面试高频陷阱：被问「DETR 的匹配代价是什么」时，如果直接背出 CE + L1 + GIoU，面试官会追问「那你说的 CE 是 -log p 吗？为什么」。面试官想听的是：匹配阶段不需要梯度，所以可以（也应该）用无量纲、有界的 -p，让三项可比；损失阶段需要梯度，所以用 -log p。这一句话能立刻把「读过论文」和「看过博客摘要」区分开。

2Hungarian loss 的完整公式：逐项拆开

先把整个式子摆出来，再逐项解释每一项为什么长这样。设网络输出 N 个预测 {(p̂i, b̂i)}，GT 集合用 ∅ 补齐到 N 个 {(ci, bi)}，σ* 是模块 01 求出的最优排列：

\[\mathcal{L}_{\mathrm{Hungarian}}(y,\hat{y}) \;=\; \sum_{i=1}^{N}\Big[\, -\lambda_{\mathrm{cls}}\,w_{c_i}\log \hat{p}_{\sigma^*(i)}(c_i) \;+\; \mathbb{1}_{\{c_i \neq \varnothing\}}\;\mathcal{L}_{\mathrm{box}}\big(b_i,\hat{b}_{\sigma^*(i)}\big)\,\Big]\]
\[\mathcal{L}_{\mathrm{box}}(b,\hat{b}) \;=\; \lambda_{\mathrm{L1}}\,\lVert b-\hat{b}\rVert_1 \;+\; \lambda_{\mathrm{giou}}\,\big(1-\mathrm{GIoU}(b,\hat{b})\big)\]

项作用去掉它会怎样
分类 CE（前景）让被认领的 query 说对类别框对了但不知道是什么；分类分数全靠背景项挤出来
分类 CE（∅ 背景）压制没认领到目标的 query所有 query 都会输出高分前景 → 满屏误检。这一项是 DETR「不需要 NMS」的另一半原因

把式子读成一句话：「每个 query 都要回答『我是什么』；只有被认领的 query 还要回答『在哪、多大』」。整个 DETR 的损失就这两句。后面所有 DETR 变体的损失改动，都只是在这两句话里换零件：把 CE 换成 focal、把 L1 换成分布回归、把 GIoU 换成别的 IoU 变体、或者给「我是什么」的目标加上定位质量。

3no-object 权重：背景 query 占 97%，不降权就废了

先算一笔具体的账。DETR 默认 N=100。COCO 一张图平均 7.7 个实例，所以典型情况下 92 个 query 被匹配到 ∅。而在交通标志检测（TSR）场景里这个比例更极端：一张高速公路前视图像上通常只有 1–3 块标志，意味着 97–99 个 query 的监督信号全是「你是背景」。

\[\underbrace{\frac{97}{100}}_{\text{背景 query 占比}} \;\times\; \underbrace{1.0}_{w_\varnothing=1 \text{ 时的权重}} \;=\; 0.97 \quad \text{vs} \quad \underbrace{\frac{3}{100}}_{\text{前景}} \times 1.0 = 0.03\]

如果不降权，分类损失里 97% 的信号在说「输出背景」。梯度下降的第一件事就是找到那个能立刻把 97% 的损失干掉的解——所有 query 一律预测背景。这不是理论担忧，是真实的训练崩溃模式：loss 快速下降、mAP 恒为 0。

DETR 的做法是给 ∅ 类一个固定权重 eos_coef = 0.1：

eos_coef有效背景/前景权重比（N=100, M=3）症状适用场景
1.0（不降权）97 : 3 ≈ 32:1全部预测背景，mAP≈0❌ 从不
0.1（DETR 默认）9.7 : 3 ≈ 3.2:1平衡；标准配置✅ softmax CE 版 DETR
0.021.94 : 3 ≈ 0.65:1误检明显增多，score 普遍偏高召回优先、下游有强过滤时
0（完全不管背景）0 : 3每个 query 都成前景 → 退化回需要 NMS❌ 从不
改用 focal loss由 γ 自动调节无需手调；后续工作的主流✅ Deformable DETR / DINO

直白说

eos_coef 的调法有个反直觉之处：它不该按「前景背景比例」精确配平。如果真的配成 1:1，模型会变得极其激进——因为「误报一个前景」的代价被压到和「漏掉一个前景」一样低。实际上 0.1 得到的 9.7:3 仍然是背景占优，这是刻意的：在检测里，让 query 默认沉默、只在有足够证据时才发声，才能得到干净的输出集合。

严谨说

更本质地看，eos_coef 调的是模型输出的工作点（operating point），而不是「是否学得会」。它和推理时的 score 阈值高度耦合：降低 eos_coef 等价于整体抬高 score，然后你必须相应提高推理阈值，最终 PR 曲线可能几乎不动。所以调它之前先问：你要的是 PR 曲线整体外扩（那要改数据/架构），还是只是换工作点（那调阈值更直接、且不用重训）。「调 eos_coef」和「调 score 阈值」的区别，是一个很好的深度探针问题。

在 TSR 这类误检代价高度不对称的场景里，把 eos_coef 调小来「提高召回」是危险的：误检一块限速牌，下游可能真的去执行一个错误的限速约束。正确做法是把召回问题留给数据与架构（小目标增强、多尺度、copy-paste），把工作点留给标定后的置信度阈值——而不是用损失权重去偷换工作点。

4为什么必须 L1 + GIoU 组合：两个互补的洞

这是本模块最重要的一节，也是白板题的高频出处。结论先行：L1 提供尺度敏感但处处存在的梯度，GIoU 提供尺度无关但在远离时衰减的梯度；它们各自都有一个致命的洞，恰好被对方补上。

洞一：L1 对尺度敏感 —— 同样的绝对误差，对小框是灾难，对大框无所谓

DETR 预测的是归一化坐标 (cx, cy, w, h) ∈ [0,1]4。在 640×640 的输入上，一个 8×8 像素的交通标志归一化宽高是 0.0125；一辆 64×64 像素的车是 0.1。现在两个框都对角偏移 2 像素：

目标像素尺寸对角偏移L1 误差（归一化）IoU1 − IoU
远处限速牌8 × 82 px0.00625（cx+cy 各 0.003125）36/92 = 0.3910.609
近处车辆64 × 642 px0.00625（完全相同）3844/4348 = 0.8840.116
大型广告牌256 × 2562 px0.00625（完全相同）0.9690.031

三个目标的 L1 损失完全相同，但实际定位质量（1−IoU）差了 20 倍。如果只用 L1，网络会认为「把大车的框修准 2 像素」和「把远处限速牌的框修准 2 像素」同样重要——而后者决定了这块牌子能不能被判定为检出。反过来，只用 L1 时大目标的绝对误差天然更大（一个 0.5×0.5 的大框偏 10% 就是 0.05 的 L1），大目标会主导梯度，小目标被淹没。这对 TSR 是致命的。

\[\text{1D 情形的解析解：宽 } w \text{ 的框沿 } x \text{ 平移 } d\;(0\le d< w) \;\Longrightarrow\; \mathrm{IoU}(d) = \frac{w-d}{w+d}, \qquad \left|\frac{\partial \mathrm{IoU}}{\partial d}\right|_{d=0} = \frac{2}{w}\]

最后那个导数是全节的关键：IoU 对位移的敏感度与框宽成反比。8 像素的框，敏感度是 64 像素框的 8 倍。这正是 IoU 系损失「尺度无关」的数学含义——它自动帮你把小目标的误差放大回来。

洞二：IoU 在两框不相交时梯度恒为零

如果两个框完全不重叠，I = 0，于是 IoU = 0，而且无论预测框往哪个方向挪、挪多远，IoU 都还是 0——梯度精确为零，不是「很小」，是数学上的零。这是一整片plateau（平台区），优化器在上面完全收不到方向信号。

这在 DETR 里不是边缘情形而是常态：训练初期 100 个 query 的框是随机初始化的，绝大多数预测框和它被匹配到的 GT 根本不相交。如果只用 IoU 损失，训练根本启动不了。

梯度存在吗？ 不相交 相交但不完美 完美重合 ┌────────┐ ┌────┬───┐ ┌────────┐ pred │ │ │ │▓▓▓│ │▓▓▓▓▓▓▓▓│ gt ┌────┐ └────┼───┤ └────────┘ │ │ └───┘ └────┘ IoU ❌ 梯度 = 0 ✅ 有梯度 ✅ 梯度 = 0（已最优） GIoU ✅ 有梯度（推近） ✅ 有梯度 ✅ 梯度 = 0 L1 ✅ 有梯度 ✅ 有梯度 ✅ 梯度 = 0 ↑ **只有这一列出问题，而它恰好是训练初期的常态**

直白说

GIoU 补的就是这个洞：它在 IoU 之外减去一项「最小外接框中的空白比例」。两框离得越远，最小外接框 C 越大，空白 (|C| − |U|)/|C| 越接近 1，GIoU → −1。于是「把两个不相交的框推近」这个动作，会稳定地降低损失——梯度回来了。GIoU 的值域是 [−1, 1]，而 IoU 只有 [0, 1]，多出来的负半轴正是用来编码「有多不相交」。

严谨说

但 GIoU 也有它自己的退化：当一个框完全包含另一个框时，最小外接框 C 就等于大框，|C| = |U|，惩罚项归零，GIoU 退化成 IoU。此时 GIoU 无法区分「小框在大框中心」和「小框贴在大框边缘」——两者 GIoU 相同。这正是 DIoU 引入中心点距离项要解决的问题。另外 GIoU 在框远离时的梯度会随距离衰减（因为 |C| 变大，惩罚项对位移的导数变小），收敛速度不如 L1 直接——所以 L1 也不能去掉。

一句话记住分工：L1 负责「把框拽到大致位置」（快、方向明确、但对尺度不公平），GIoU 负责「把框调到形状贴合」（尺度公平、但远处梯度弱）。DETR 的权重 λL1=5, λgiou=2 也印证了这个分工：归一化坐标下 L1 的数值只有 1e-2 量级，不乘 5 根本发不出声音；而 (1−GIoU) 本身就有 0.1–2 的量级，乘 2 即可。面试被问「为什么是 5 和 2」，答「量纲配平」比答「实验调出来的」高一个层次。

5IoU 家族：GIoU / DIoU / CIoU 的定义与各自补的洞

四个损失是一条清晰的递进链，每一个都精确地补上前一个的一个失效场景。记住这条链，比记住四个公式有用得多。

\[\mathrm{IoU} = \frac{|A\cap B|}{|A\cup B|} \qquad\qquad \mathrm{GIoU} = \mathrm{IoU} - \frac{|C \setminus (A\cup B)|}{|C|} = \mathrm{IoU} - 1 + \frac{|A\cup B|}{|C|}\]
\[\mathrm{DIoU} = \mathrm{IoU} - \frac{\rho^2(\mathbf{c}_A,\mathbf{c}_B)}{d_C^2} \qquad\qquad \mathrm{CIoU} = \mathrm{DIoU} - \alpha v\]
\[v = \frac{4}{\pi^2}\left(\arctan\frac{w_B}{h_B} - \arctan\frac{w_A}{h_A}\right)^2, \qquad \alpha = \frac{v}{(1-\mathrm{IoU}) + v}\]

其中 C 是两框的最小外接矩形，ρ 是两框中心点欧氏距离，dC 是 C 的对角线长度，v 度量宽高比不一致度，α 是自适应权重（重叠度越高，宽高比项越重要）。

损失补的洞新增惩罚项退化/失效场景典型用途
IoU—（基准）—不相交时梯度恒为 0评测指标；一般不直接当损失
GIoU不相交无梯度外接框中的空白面积占比包含关系时退化回 IoU；远距离时梯度衰减、收敛慢DETR 系默认
DIoU包含关系无区分度中心点距离 / 外接框对角线中心重合但宽高比不同时无区分NMS 的距离感知版（DIoU-NMS）
CIoU宽高比未被约束宽高比一致性 αvα 通常被 detach，梯度非严格；宽高极端时 v 数值不稳YOLO 系常用（v5/v8 默认）
（后续） SIoU / EIoU / MPDIoU角度、宽高绝对差、顶点距离各自不同增益边际、依赖数据分布调参空间；小目标可考虑 NWD（见 C57）

直白说

为什么 DETR 选 GIoU 而不是更「先进」的 CIoU？两个原因。① DETR 的框损失里已经有 L1 项，而 L1 对 (cx, cy) 和 (w, h) 都直接施加约束——DIoU 的中心项和 CIoU 的宽高比项在很大程度上被 L1 覆盖了，收益重叠。② GIoU 值域对称、数值最稳，而 CIoU 的 α 在实现里是 detach 的，意味着 CIoU 的「梯度」不是它自身的真实梯度——这在需要严格数值验证的场合是个负担。

严谨说

反过来，YOLO 系用 CIoU 是因为它们没有 L1 项（anchor-free 的框回归直接用 IoU 系损失），所以中心距离与宽高比必须由 IoU 损失自己承担。这是一个很好的例子：损失函数的选择依赖于整个损失组合，脱离上下文比较「哪个 IoU 变体更好」是无意义的。面试里如果对方问「GIoU 和 CIoU 哪个好」，最好的回答是先反问「在什么损失组合里」——这比直接站队更能显示你真的用过。

实现上的三个必查点：① 并集要减掉交集（U = A + B − I，写成 A + B 是最常见的低级 bug，会让 IoU 恒小于真值）；② 交集的宽高必须 clamp 到 ≥0（不 clamp 时两个负数相乘会得到正的假交集——这个 bug 极其隐蔽，因为只在完全不相交时触发，单元测试如果只测相交情形就查不出来）；③ 除零保护（退化框 w=0 或 h=0 会让 U=0）。

6解析梯度：手推 IoU / GIoU 对四个坐标的导数

「在白板上写出 IoU 的解析梯度」是检测岗最高频的手写题之一，因为它同时考察：链式法则、max/min 的次梯度处理、以及你是否真的知道「不相交时梯度为零」这句话在代码里长什么样。本节把它推完，notebook 里用数值梯度逐项校验。

记预测框 a = (x₁, y₁, x₂, y₂)（视为变量），GT 框 b（常量）。定义交集边界与面积：

ix1 = max(a.x1, b.x1) ix2 = min(a.x2, b.x2) iy1 = max(a.y1, b.y1) iy2 = min(a.y2, b.y2) iw = max(0, ix2 - ix1) ih = max(0, iy2 - iy1) I = iw * ih Aa = (a.x2-a.x1)(a.y2-a.y1) Ab = (b.x2-b.x1)(b.y2-b.y1) U = Aa + Ab - I IoU = I / U 外接框：cx1 = min(a.x1,b.x1) cx2 = max(a.x2,b.x2) （y 同理） Ac = (cx2-cx1)(cy2-cy1) GIoU = IoU - (Ac - U)/Ac = IoU - 1 + U/Ac

第一步：交集面积 I 对 a 的导数（关键在指示函数）

\[\frac{\partial I}{\partial a_{x_1}} = -\,ih \cdot \mathbb{1}[a_{x_1} > b_{x_1}] \cdot \mathbb{1}[iw>0]\mathbb{1}[ih>0], \qquad \frac{\partial I}{\partial a_{x_2}} = +\,ih \cdot \mathbb{1}[a_{x_2} < b_{x_2}] \cdot \mathbb{1}[iw>0]\mathbb{1}[ih>0]\]

解释：ix1 = max(a.x1, b.x1)，只有当 a.x1 是那个较大者时，动它才会改变 ix1——这就是指示函数 1[a.x1 > b.x1] 的来源。而 iw = ix2 − ix1，所以 ∂iw/∂a.x1 = −1[a.x1 > b.x1]，再乘上 ih 得到面积导数。最外层的 1[iw>0]1[ih>0] 就是「不相交时梯度为零」在代码里的样子——也是白板题最容易漏的一项。

第二步：并集与 IoU

\[\frac{\partial A_a}{\partial a} = (-h_a,\; -w_a,\; +h_a,\; +w_a), \qquad \frac{\partial U}{\partial a} = \frac{\partial A_a}{\partial a} - \frac{\partial I}{\partial a}\]
\[\frac{\partial\, \mathrm{IoU}}{\partial a} = \frac{\frac{\partial I}{\partial a}\,U - I\,\frac{\partial U}{\partial a}}{U^2}\]

第三步：GIoU 的额外一项

\[\frac{\partial\, \mathrm{GIoU}}{\partial a} = \frac{\partial\, \mathrm{IoU}}{\partial a} + \frac{\frac{\partial U}{\partial a}A_c - U\,\frac{\partial A_c}{\partial a}}{A_c^2}, \qquad \frac{\partial A_c}{\partial a_{x_1}} = -\,c_h\cdot\mathbb{1}[a_{x_1} < b_{x_1}]\]

注意外接框的指示函数方向和交集相反：cx1 = min(...)，所以只有 a.x1 更小时它才起作用。这个「一个取 max 一个取 min，指示函数方向相反」的对称性，是手推时最容易写反的地方。

白板题：IoU 的解析梯度 白板题评分要点（面试官在心里的 checklist）：① 有没有写出 U = Aa + Ab − I 而不是 Aa + Ab；② 有没有对 iw, ih 做 clamp，并且在梯度里体现出 clamp 的截断；③ 有没有意识到 max/min 会产生指示函数（而不是当成常数）；④ 能否说出「不相交 ⇒ 梯度恒 0 ⇒ 所以要 GIoU」；⑤ 加分项：主动说「实际训练中预测的是 (cx,cy,w,h)，还要再套一层从 (x1,y1,x2,y2) 到 (cx,cy,w,h) 的链式法则」——notebook 的练习 4 就是这一步。

直白说

为什么要手推而不是「反正 autograd 会算」？三个实际理由。① 调试：训练中出现 NaN 时，你需要知道 U=0（退化框）和 Ac=0 是唯二的除零来源，才能定位。② 部署：车端 C++ 侧如果要做在线的框精修或跟踪滤波，autograd 不在了。③ 理解：只有把 1[iw>0] 这一项写出来，「IoU 不相交无梯度」才从一句口号变成一个你亲眼见过的乘子。

严谨说

数值上还有一处必须注意：max/min 在相等点不可导（a.x1 == b.x1），此时任何一侧的次梯度都合法。PyTorch 的 torch.max 在 tie 时把梯度全给第一个参数，这个约定与你手写的实现可能不一致，从而导致极小概率的对拍失败。所以数值梯度校验时要避开退化配置（用随机连续坐标即可，tie 是零测集）；反过来，如果你的对拍在随机输入上就有 1% 的失败率，那多半不是 tie 而是真 bug。

7辅助损失：为什么「每层 decoder 都算一遍」能把收敛砍掉一大半

DETR 的 decoder 有 6 层。默认配置下，每一层的输出都接同一套（共享权重的）分类头与框头，各自独立做一次匈牙利匹配、各自算一份完整的 Hungarian loss，最后全部相加。这叫 auxiliary decoding losses（辅助损失），是 DETR 里性价比最高的一个设计——论文的消融显示去掉它 AP 掉约 2 点，且收敛显著变慢。

代价也要说清楚：匈牙利匹配是在 CPU 上做的 O(N³) 运算，6 层就是 6 次。当 N=900（DINO）时这已经不可忽略，是 DETR 系训练吞吐的一个真实瓶颈。显存方面，需要保留 6 层的中间输出用于反传——这也是 DETR 系显存占用偏高的原因之一。

直白说

推理时辅助头全部丢掉，只用最后一层。这带来一个非常实用的部署性质：既然每一层的输出都是「可用的」，那就可以在推理时只跑前 k 层。RT-DETR 正是靠这一点做到「同一份权重支持多档速度-精度，无需重训」——车端算力紧张时跑 3 层，空闲时跑 6 层。辅助损失从一个训练技巧变成了部署能力。

严谨说

更细的一点：DINO 等两阶段变体还会给 encoder 输出加一份损失（把 encoder 的 top-k 提议当作「第 0 层」的预测来监督）。此时损失项变成 6 × decoder + 1 × encoder + DN 分支，总共可能有十几份 Hungarian loss 在同时反传。这时候各份损失的权重就不再能靠直觉，必须做敏感性分析——而一个常被忽略的事实是：辅助层的权重通常直接取 1.0（与最后一层同权），这是个从未被认真消融过的默认值。

把辅助损失理解成「把一个 6 步的推理过程，改造成 6 个各自可评分的 1 步」。这个模式在 Transformer 之外也到处出现（扩散模型的每步去噪损失、级联检测器 Cascade R-CNN 的每级损失）。共同的心法是：当你有一个深的、串行的精修过程，而每个中间状态本身也有明确语义时，就应该给每个中间状态配一份监督。

直白说

换 focal 的根本理由是 softmax 与一对一匹配的哲学不兼容。softmax 强迫 K+1 个类互相抢概率质量，但集合预测里每个 query 是独立地在回答「我认领的这个东西是什么」——它和别的 query 认领什么无关，也不该和「我是不是背景」做零和竞争。sigmoid + focal 把「是不是前景」和「是哪一类」解耦，正好匹配这个语义。

严谨说

实践收益也很直接：① 省掉 eos_coef 这个超参（focal 的 (1−p)γ 自动把大量「已经预测得很低的背景 query」的梯度压下去）；② 支持把 N 从 100 提到 900——softmax 版在 N 增大时背景项会失控，而 focal 版几乎不受影响；③ 推理时在 N×K 个 (query, 类) 对里取 top-100，允许同一个 query 在两个易混类上都出框，这对 TSR 里「限速 60 / 限速 80」这类极易混淆的标志对是有实际价值的——下游可以拿到第二候选做时序投票，而 softmax 版的第二候选被压得几乎没有分数。

换成 focal 后有一个必须同步改的地方：推理阈值的语义变了。softmax 版的 score 是「在所有类里的相对份额」，天然归一化；sigmoid 版的 score 是「这一类的独立置信度」，多个类可以同时是 0.9，也可以全部是 0.1。把 softmax 时代的阈值（如 0.7）原样搬到 sigmoid 版上，召回会莫名其妙地掉一大截。对 TSR 这种需要把置信度传给下游做时序融合的系统，换损失之后必须重新做置信度标定（calibration），否则下游的贝叶斯累积会全盘失准。

9研究前沿与开放问题

集合损失看起来只是「三项加权和」，但它其实是 DETR 系近五年改动最密集的地方。下面几条是目前仍未收敛的问题，也是读论文时值得盯的方向。

  • 匹配代价与损失不一致的理论缺口：匹配用 −p、损失用 −log p，这意味着「谁被选中」和「选中后往哪优化」用的不是同一个目标。Stable-DINO / position-supervised loss 一类工作指出这会导致训练不稳定，并提出把定位质量直接写进分类目标（分类标签不再是 0/1 而是 IoU）来弥合。这条线与 Varifocal Loss、Quality Focal Loss（GFL）是同一个思想的不同分支。
  • 一对多辅助分支的回归：Group DETR / H-DETR / Co-DETR 在训练时额外挂一条一对多监督的分支（推理时丢弃），显著加速收敛并提点。这在理论上很值得玩味：它说明「一对一」是推理端的需求（去 NMS），而不是训练端的最优（监督太稀疏）。把训练目标和推理约束解耦，可能是这条线最重要的启示。
  • 框回归的表示之争：L1 直接回归四个数是最朴素的做法。GFL / D-FINE 改为预测每条边的概率分布（把回归变成分类），既能表达定位不确定性，又能提供更丰富的梯度。对 TSR 这种需要把定位不确定性传给时序融合的系统，分布式表示的价值可能被低估了。
  • IoU 变体的长尾：SIoU（角度感知）、EIoU（宽高绝对差）、WIoU（动态聚焦）、α-IoU（幂次调节）、MPDIoU（顶点距离）……大多数只在特定数据集上有零点几个点的增益，缺少跨数据集的一致结论。更值得注意的是为小目标专门设计的度量——NWD（把框建模成 2D 高斯，用 Wasserstein 距离）在不相交时仍有平滑梯度、且对尺度不敏感，这正是 TSR 远距离小标志最需要的性质（详见 C57 模块 03）。
  • 匹配的可微化：匈牙利匹配是离散的、不可导的。有工作尝试用 Sinkhorn 迭代做软匹配（可微的最优传输），或用 top-k 软选择替代硬匹配。目前尚未证明比硬匹配更好，但它触及一个根本问题：「先匹配再算损失」这个两阶段结构本身是不是必要的？
  • 开放问题：什么才是「正确」的集合损失？现有损失都是「先建立对应，再逐对算距离」。而集合之间本来有更自然的距离（Chamfer、Wasserstein、最优传输）。为什么检测里几乎没人用这些？主要障碍是：它们不强制一一对应，于是无法在训练期压制重复框——而这恰恰是 DETR 去掉 NMS 的全部依据。

必读（按顺序）：

  • ★ End-to-End Object Detection with Transformers（DETR, Carion et al. ECCV 2020）——读 §3.1「Object detection set prediction loss」全节 + 附录 A.1 的损失权重表。解决什么问题：把检测变成集合预测，并给出第一个可用的集合损失。
  • ★ Generalized Intersection over Union（Rezatofighi et al. CVPR 2019）——读 §3 与算法 1（GIoU 的解析形式）。解决什么问题：IoU 在不相交时梯度为零。
  • ★ Distance-IoU Loss（Zheng et al. AAAI 2020）——DIoU 与 CIoU 同一篇。解决什么问题：GIoU 在包含关系下退化、收敛慢。
  • Focal Loss for Dense Object Detection（Lin et al. ICCV 2017）——理解 Deformable DETR / DINO 为何弃用 eos_coef。
  • DINO: DETR with Improved DeNoising Anchor Boxes（Zhang et al. ICLR 2023）——看它的完整损失组合（decoder 辅助 + encoder + DN 分支）。
  • Detection Transformer with Stable Matching（Stable-DINO, ICCV 2023）——匹配-损失不一致问题的代表作。
