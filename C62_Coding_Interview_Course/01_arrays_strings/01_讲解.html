1双指针三形态：对撞、快慢、同向

如果只能学一个模板，学这个。双指针覆盖了 ML/CV 岗 coding 题里最大的一块，而且它的三种形态可以用一句话区分：两个指针是相向走、同向不同速走、还是同向且都只前进。把这三种的「适用信号」记住，你在听完题目的 30 秒内就能判断该用哪一种。

① 对撞指针 (converging / opposite) —— 前提：数组**有序**，或问题本身有单调性 a = [ 2 7 11 15 19 23 ] ↑ ↑ lo ───────► ◄─── hi 每轮把「一定不是答案」的一端排除掉 不变量：答案（若存在）一定还在闭区间 [lo, hi] 内 终止：lo >= hi 时区间为空 -> 无解 ② 快慢指针 (fast & slow) —— 前提：需要「相对位置」而不是绝对下标 a = [ 1 1 2 2 3 ] ↑ ↑ slow fast ──► fast 负责**读**，slow 负责**写** 不变量：a[0..slow-1] 已经是处理完的合法结果，且保持原相对顺序 典型：原地去重、原地移除、链表找中点/判环 ③ 同向双指针 / 滑动窗口 (sliding window) —— 前提：窗口的「合法性」随长度**单调** s = "a b c a b c b b" └──────┘ left right ──► right 只前进，left 只前进 -> 总步数 <= 2n 不变量：s[left..right] 始终满足题目约束（或「刚刚违反，正在修」） 终止：right 走完整个数组

三者的判别信号，按「听到什么就选什么」整理：

形态听到这些信号就想到它循环不变量代表题（频率 / 优先级）
对撞指针「已排序」「找两个数使和为 target」「首尾配对」「最大面积 / 最多容器」「回文」答案一定还在 [lo, hi] 内；每次排除的那一端可证明不可能是答案两数之和 II（高频·必会）、盛最多水的容器（高频·必会）、三数之和（高频·必会）
快慢指针「原地」「O(1) 额外空间」「返回新长度」「链表中点 / 判环」a[0..slow-1] 是已完成的合法前缀移除元素、删除有序数组重复项（高频·必会）、移动零（高频·必会）
同向 / 滑窗「连续子数组 / 子串」「最长 / 最短」「恰好包含」「窗口内不超过 k 个」窗口内始终满足约束；left 单调不减最长无重复子串（高频·必会）、最小覆盖子串（中频·加分）、长度最小的子数组（高频·必会）

直白说

为什么双指针能把 $O(n^2)$ 降到 $O(n)$？因为它不是「跳过一些检查」，而是「每检查一次就排除一整行或一整列」。拿两数之和 II 举例：暴力解要检查 $n(n-1)/2$ 个数对；对撞指针每比较一次，如果 a[lo]+a[hi] < target，那么 a[lo] 与 任何 a[hi']（$hi' \le hi$）的和都更小——一次比较排除了以 lo 为左端的整行 $hi-lo$ 个候选。$n$ 次比较排除了 $O(n^2)$ 个候选，这就是加速的来源。

严谨说

更严谨地说，双指针的正确性依赖一个单调性/交换论证结构：存在一个全序，使得「被排除的候选集」中不含最优解。这个论证必须逐题重新做一遍，不能想当然——同样是对撞指针，两数之和 II 依赖数组有序，而盛最多水的容器不依赖有序，它依赖的是「面积 = 宽 × min(两端高度)」这个函数在移动长板时必然不增。两道题的模板一模一样，但正确性证明完全不同。面试官追问「你怎么知道这样不会漏解」时，他要的就是这个证明，不是模板。第 2 节专门讲怎么当场把它说出来。

最常见的误用：在无序数组上用对撞指针。「两数之和」（无序，返回下标）必须用哈希表，而「两数之和 II」（有序，返回下标）才用对撞指针。如果面试官给的是无序数组而你直接排序，就破坏了「返回原下标」这个要求——这时正确的做法是排序前先记下 (值, 原下标)，或者干脆用哈希。听到「返回下标」这三个字，先问一句「需要原数组的下标吗」。

2循环不变量：怎么当场证明「不会漏解」

这一节是本模块最值钱的部分，因为它是区分「背过模板」和「懂了」的那道分水岭。面试官几乎一定会在你写完双指针后问一句：「你怎么保证这样不会漏掉最优解？」这时候有没有一句结构化的回答，直接决定「正确性」和「沟通」两栏的分。

循环不变量（loop invariant）是一个关于程序状态的命题，要证明三件事（CLRS 第 2 章的标准框架）：

  1. 初始化（initialization）：进入循环前它成立。
  2. 保持（maintenance）：如果某轮开始时成立，那么这轮结束时仍然成立。
  3. 终止（termination）：循环结束时，不变量 + 终止条件合起来直接给出答案。

完整示范：盛最多水的容器，为什么可以「移动短板」

题目：h[i] 是第 i 根柱子的高度，选两根柱子装水，面积 = $(j-i)\times\min(h_i,h_j)$，求最大面积。做法是 lo=0, hi=n-1，每轮结算当前面积，然后把矮的那一端往里移。

\[\text{不变量：}\quad \max_{\,0\le i

翻译成人话：「全局最优 = 已经记下的 best 与还没排除的区间里的最优，二者之一」。三步证明：

  • 初始化：lo=0, hi=n-1, best=0，右边那一项就是全体候选，成立。
  • 保持（关键的一步）：不妨设 $h_{lo} \le h_{hi}$，我们要移动 lo。需要证明「所有以 lo 为左端的候选都可以安全丢弃」。对任意 $j < hi$：$A(lo,j) = (j-lo)\cdot\min(h_{lo},h_j) \le (hi-lo)\cdot h_{lo} = A(lo,hi)$——宽度更小，且高度不可能超过 $h_{lo}$。而 $A(lo,hi)$ 这轮已经结算进 best 了。所以丢掉整列不会丢掉最优解，不变量保持。
  • 终止：lo == hi 时右边那一项是空集，于是 best 就是全局最优。

把这段证明压成面试里的一句话：「移动短板是安全的，因为以短板为一端的所有其他组合，宽更小、高也不可能超过短板，而最宽的那一个我这轮已经算过了。」这一句话就够了，不需要写公式。同样的句式可以套到两数之和 II：「a[lo]+a[hi] < target 说明 a[lo] 配任何更小的右端都更小，所以整行可以丢。」

直白说

为什么一定要写注释说明不变量？因为双指针代码的 bug 几乎全部来自不变量被写歪，而不是来自打字错误。典型三种：①该用 while lo < hi 写成了 <=（自己和自己配对）；②该在移动前结算写成了移动后结算（漏掉一个候选）；③相等时该动哪一边没想清楚（可能死循环）。在代码里写一行 # 不变量：...，等于强迫自己在写之前先想清楚这三件事。

严谨说

在评分表上，这一行注释同时命中三栏：代码质量（自解释的代码）、正确性（面试官能顺着不变量核对边界）、沟通（把思考过程留在纸面上）。成本是 8 个字，收益是三栏各半分。这是整个准备过程里投入产出比最高的习惯之一。在真实工程里它同样成立——NMS 的抑制循环、多帧跟踪的滑动窗口维护、切片推理的跨片合并，这些代码在 code review 里被问到的第一句话，永远是「这个循环结束时你保证了什么」。

不要用「我试了几个例子都对」来回答「怎么证明不漏解」。这句话在面试官耳朵里等价于「我不知道为什么对」。正确的降级答法是：「我没法当场严格证明，但直觉是这样：……。我可以写一个暴力解做随机对拍来增强信心。」——承认边界 + 给出验证方案，这在「诚实度」上是加分的，比硬编一个伪证明好得多。

3滑动窗口：定长与可变两套模板

滑动窗口是同向双指针的特例，但它值得单独一套模板，因为「什么时候收缩」这一个决定，分出了三类完全不同的题。先看模板骨架：

【模板 A · 定长窗口】窗口长度恒为 k，进一个出一个 s = sum(a[:k]) # 先把第一个窗口装满 best = s for right in range(k, n): s += a[right] - a[right - k] # ← 一进一出，O(1) 维护 best = max(best, s) # 不变量：循环体开始时，s == sum(a[right-k+1 .. right]) 【模板 B · 可变窗口】right 每步前进 1，left 按条件收缩 left = 0 for right in range(n): 加入 a[right] 到窗口状态 while <窗口非法>: # ← B1：违反约束才缩（求**最长**） 移出 a[left]; left += 1 best = max(best, right - left + 1) left = 0 for right in range(n): 加入 a[right] 到窗口状态 while <窗口已满足>: # ← B2：满足就缩到不能再缩（求**最短**） best = min(best, right - left + 1) 移出 a[left]; left += 1 差别只有一处：**while 的条件是「非法」还是「已满足」**， 以及**结算写在 while 里面还是外面**。写反了就得到相反的答案。

三类题的对照（这张表建议直接背下来）：

求什么while 条件结算位置代表题频率 / 优先级
最长合法子串/子数组窗口非法时收缩while 之后（此时窗口合法）最长无重复子串、至多含 K 个不同字符的最长子串高频 · 必会

为什么是 O(n)：摊还分析

很多人被「里面还有一个 while 循环」吓到，以为是 $O(n^2)$。不是，因为 left 只增不减，且上界是 $n$：

\[T(n) \;=\; \underbrace{n}_{\text{right 前进}} \;+\; \underbrace{\sum_{\text{right}} \Delta \text{left}}_{\text{总和} \,\le\, n} \;\le\; 2n \;=\; O(n)\]

这句话必须能当场说出来：「内层 while 看起来是嵌套循环，但 left 在整个执行过程中总共只前进 $n$ 步，所以内层循环体的总执行次数不超过 $n$ 次，整体还是 $O(n)$——这是摊还分析（amortized analysis）。」说得出这句，「复杂度」栏直接从 3 分变 5 分。

直白说

滑动窗口能成立，靠的是一个隐含前提：窗口的合法性关于长度是单调的——如果 s[left..right] 合法，那么它的任何子串也合法（对「最长」类题）；或者如果 s[left..right] 满足条件，那么任何包含它的更长区间也满足（对「最短」类题）。只有这个单调性成立，「收缩到边界就停」才不会漏解。

严谨说

反过来说，单调性一旦被破坏，滑动窗口立刻错，而且错得很隐蔽。最经典的反例是「和为 K 的子数组」在有负数时：加入一个负数会让窗口和变小，于是「和太大就收缩」这个规则失效——收缩之后可能反而更大。此时正确解法是前缀和 + 哈希表（第 4 节），复杂度同样 $O(n)$，但机制完全不同。面试里如果你上来就写滑窗，面试官很可能只补一句「数组里可以有负数」，然后看你是否意识到整个解法塌了。

面试当场的高频翻车：用 collections.defaultdict(int) 维护窗口计数，然后用 len(window) 判断「窗口里有几种字符」。defaultdict 在读取不存在的 key 时会创建它，于是 if window[c] == 0 这一句就把 c 塞进了字典，len(window) 从此永远偏大。正确做法：用普通 dict + .get(c, 0)，或者在计数归零时显式 del window[c]。这个 bug 在本地跑小例子常常看不出来，但在面试官的追问用例上会当场暴露。

4前缀和与差分：把「区间查询」压成 O(1)

前缀和是所有区间类问题的地基。定义上只有一行，但下标约定选错会让你在面试里反复 ±1，所以先把约定钉死：

pre = [0] * (n + 1)                 # ← 长度是 n+1，不是 n。这一步消灭了所有 if i == 0
for i in range(n):
    pre[i + 1] = pre[i] + a[i]

# 语义：pre[i] = a[0] + a[1] + ... + a[i-1]   （前 i 个元素之和，**不含** a[i]）
# 区间和 a[l..r]（闭区间）= pre[r + 1] - pre[l]        ← 只有这一个公式要背
# 自检：a[0..n-1] 的和 = pre[n] - pre[0] = pre[n]  ✓
「多留一格哨兵」是数组题里回报最高的一个技巧。长度 $n+1$ 的前缀和数组让「从头开始的区间」不再是特例；长度 $n+1$ 的差分数组让「改到最后一个元素」不越界。面试里每消掉一个 if 分支，就少一个可能写错的边界。

差分：前缀和的逆运算

差分数组 d 满足 a = 前缀和(d)。它解决的是「批量区间加，最后只问一次结果」：

操作朴素做法差分做法复杂度对比
把 a[l..r] 全部加 v（共 m 次操作）每次遍历区间d[l] += v; d[r+1] -= v$O(m\cdot n)$ → $O(m + n)$
查询任意区间和（共 q 次查询）每次遍历区间预处理前缀和后 pre[r+1]-pre[l]$O(q\cdot n)$ → $O(n + q)$
既要改又要查（交替进行）—差分/前缀和都不行，需要树状数组或线段树$O((n+q)\log n)$，低频，面试里可直接说「我会用 BIT」

差分在感知工程里的一个真实用途：统计「每个时刻同时被多少个 track 覆盖」。每条 track 是一个时间区间 [t_start, t_end]，要算每一帧的活跃 track 数——朴素做法是对每条 track 遍历它的所有帧（$O(\text{track 数}\times\text{帧数}）$），差分做法是每条 track 只做两次 ±1，最后扫一遍前缀和。

和为 K 的子数组：前缀和 + 哈希表

这是高频·必会题，也是第 3 节那个「滑窗在负数下失效」的正解。核心恒等式只有一行：

\[\mathrm{sum}(i..j) = k \iff \mathrm{pre}[j{+}1] - \mathrm{pre}[i] = k \iff \mathrm{pre}[i] = \mathrm{pre}[j{+}1] - k\]

于是从左往右扫，边扫边把见过的前缀和存进哈希表，对当前的 pre[j+1] 直接查「有多少个 pre[i] == pre[j+1] - k」。$O(n)$ 时间、$O(n)$ 空间，而且完全不依赖元素正负。

直白说

初始化 seen = {0: 1} 这一行是最容易漏的。它的含义是「空前缀 pre[0]=0 已经见过一次」——没有它，「从下标 0 开始就恰好等于 k 的子数组」会被漏掉。面试官如果想抓 bug，第一个试的用例就是 a=[k]。

严谨说

更本质地看，这道题展示了一个可迁移的转换范式：「区间问题 → 两点问题」。任何形如「求满足 $f(\text{区间}) = c$ 的区间个数」的问题，只要 $f$ 可以写成$g(\text{右端点}) \ominus g(\text{左端点})$ 的形式（$\ominus$ 是可逆运算），就可以用同一套「前缀量 + 哈希表」解决。把「和」换成「异或」就是「异或和为 K 的子数组」；换成「0/1 计数差」就是「含相同个数 0 和 1 的最长子数组」；换成「模 k 的余数」就是「和能被 k 整除的子数组」。识别出这个范式，等于一次拿下四五道题——面试里主动说出这个归纳，是明确的加分点。

直白说

在 TSR 的工程实践里，这个技巧最常出现在两个地方。①候选框的快速打分：拿到一张前景概率图和几千个候选框，要算每个框内的平均概率——逐框切片求和是 $O(\text{框数}\times\text{面积})$，积分图是建一次 + 每框四次访问。②图像内容的粗筛：判断「这一片区域是不是几乎全是天空/路面」，用积分图算区域均值与方差，可以在送进检测器之前就把大片无信息区域跳过（呼应 C57 的 ROI 裁剪）。

严谨说

两个必须知道的工程陷阱。①溢出：一张 1920×1080 的 uint8 图，积分图右下角的值是 $1920\times1080\times255 \approx 5.3\times10^{8}$，已经超过 int32 的一半——如果图是 float32 累加，大数吃小数会让远处的小矩形和产生可见误差。正确做法：整型图用 int64，浮点图用 float64 累加（OpenCV 的 cv2.integral 默认就给 float64/int32 两种输出，不是随便选的）。②闭区间还是半开区间：算法题里矩形边界通常是闭区间 [r0..r1]，而 bbox 常用半开或浮点坐标；两边混用会产生系统性的 off-by-one。面试里写这道题，先花 5 秒说清「我用闭区间，所以 +1 出现在这两处」，比事后改三遍强。

面试里不要直接调 np.cumsum 就说做完了。考点是容斥的四项和 +1 的位置，不是会不会用 numpy。可接受的做法是：先手写双重循环版本 S[i+1][j+1] = S[i][j+1] + S[i+1][j] - S[i][j] + I[i][j]（注意这里也是容斥），说清楚它，再补一句「实际工程里我会写成 img.cumsum(0).cumsum(1)，向量化后快两个数量级」。——先证明你懂机制，再展示你懂工程，两栏都拿到。

6原地修改与 O(1) 空间：读写双指针

「原地」（in-place）在面试里有一个精确定义，最好在开始写之前确认一遍：额外空间 $O(1)$，输出写回输入数组，返回有效长度——输出本身不算额外空间。很多人栽在这里：用了一个新列表装结果，最后再赋值回去，这不是原地。

# 读写双指针的通用骨架（快慢指针的最常见用法）
def compact(a, keep):
    write = 0                       # 不变量：a[0 .. write-1] 是已确定的结果，且保持原相对顺序
    for read in range(len(a)):      # read 负责扫描，write 负责落笔
        if keep(a[read]):
            a[write] = a[read]
            write += 1
    return write                    # a[:write] 是答案；a[write:] 是"垃圾区"，题目通常不关心

# 三道题共用这一个骨架，只换 keep：
#   移除元素        keep = lambda x: x != val
#   移动零(保序)     keep = lambda x: x != 0        （之后把 a[write:] 填 0）
#   删除有序数组重复 keep 依赖前一个写入值 -> 改成 if write == 0 or a[read] != a[write-1]
技巧做什么为什么面试爱考频率 / 优先级
读写双指针扫描 + 就地压缩一个骨架覆盖 4–5 道题，且能考出「相对顺序保不保」的细节高频 · 必会
三次反转轮转数组轮转 k 位 = 整体反转 + 前 k 反转 + 后 n−k 反转$O(1)$ 空间的漂亮解；追问「k > n 怎么办」（取模）中频 · 必会

就地哈希（下标即键）把值 v 交换到下标 v-1同上；能想到就是加分，想不到不致命低频 · 加分
Python 特有的三个复杂度陷阱 三个会把 $O(n)$ 悄悄变成 $O(n^2)$ 的 Python 写法，面试官盯着看的就是这些：
① for x in a: if x == val: a.remove(x) —— list.remove 是 $O(n)$，而且边遍历边删会跳过元素（双重错误）。
② a.pop(0) 当队列用 —— 每次 $O(n)$ 的元素搬移。正确做法是 collections.deque 的 popleft()（$O(1)$）。
③ 循环里做切片 window = a[left:right+1] —— 切片是 $O(k)$ 的拷贝，套在 $O(n)$ 的循环里就是 $O(n^2)$，而且额外空间也不再是 $O(1)$。滑动窗口题里这是最常见的隐藏复杂度炸弹。

直白说

为什么面试官这么在意 $O(1)$ 空间？表面理由是「考察你对内存的敏感度」，真实理由更具体：在嵌入式与车端场景里，堆分配本身就是延迟的不确定性来源。一个每帧都要 malloc 一块临时缓冲的后处理函数，在内存碎片化之后耗时会变得不可预测——这与 C53-04 讲的「NMS 让延迟依赖场景」是同一类问题。量产代码里常见的做法是预分配固定大小的缓冲池，函数只在里面就地操作。

严谨说

所以「原地」这个要求在面试里其实是一个代理指标：它测的不是你会不会写 write 指针，而是你是否知道内存分配有成本。面试里主动补一句会很加分：「这里我用了 $O(1)$ 额外空间；如果这段代码在车端每帧调用，我还会考虑把输出缓冲预分配好，避免每帧的动态分配——因为分配的耗时方差比它的均值更麻烦。」这一句话把一道算法题接到了工程现实上，是明确的信号。

7边界条件清单：写完不测是最贵的错误

回忆模块 00 的评分表：测试意识占 15%，而大部分候选人这一栏拿 1 分。拿到 5 分的成本其实极低——你只需要背一张六行的清单，每道题照着念一遍。

边界类别具体用例会挂在哪种题上为什么容易忘

把这张表做成一句口播，写完代码后照着念：「我过一遍边界：空数组走不进循环返回 0；单元素时 lo==hi 直接退出；全相同时去重那一行会跳过；有负数时……嗯，这里我的滑窗假设不成立，我得改成前缀和 + 哈希。」——注意最后半句：当场发现自己的 bug，比面试官发现它，分数高得多。

随机对拍：把「我觉得对」变成「我验证过」

边界清单覆盖的是你想得到的情况。真正强的做法是加一层随机对拍（stress testing）：写一个显然正确的暴力解，随机生成大量小规模输入，逐一比对两者的输出。

def stress(opt, brute, gen, trials=500, seed=0):
    rng = random.Random(seed)
    for _ in range(trials):
        arg = gen(rng)                      # 生成**小规模**输入：长度 0-10，值域窄，重复多
        g, w = opt(arg), brute(arg)
        if g != w:
            return {'ok': False, 'input': arg, 'got': g, 'want': w}   # 返回最小反例
    return {'ok': True, 'trials': trials}

三个让对拍真正有效的细节：①规模要小（长度 0–10），这样反例是人能一眼看懂的；②值域要窄（比如只用 0–3 或 'abc'），这样重复元素和边界会被高频触发；③要固定 seed，否则反例不可复现。

直白说

在 45 分钟的面试里当然来不及写完整的对拍框架，但你可以把它说出来：「我这里写了暴力解，如果时间允许我会用它做随机对拍，长度取 0 到 8、值域取 0 到 3，这样重复元素和空数组都能高频覆盖到。」这句话让「先给暴力解」这一步产生了第二笔收益——它不只是安全网，还是验证工具。

严谨说

这个方法论在真实工作里的对应物是参考实现对拍，在训练-部署一致性验证里是标准动作（C60 的主题）：用 PyTorch 的输出作为 reference，逐层比对 TensorRT engine 的输出；或者用 Python 版的 NMS 对拍 C++/CUDA 版的实现。「写一个慢但显然正确的版本作为 ground truth」不是面试技巧，是感知工程里定位问题最快的手段——差别只在于面试里对拍的是算法，工程里对拍的是实现。能把这个联系说出来，面试官会立刻知道你做过真实项目。

8回到 CV：这些模板在感知代码里长什么样

这一节把前面七节的东西接回本岗位。三条连接，每一条都可以在面试里主动提出来——它们同时展示算法功底和领域理解，是这门课相对于「纯刷题」的全部价值所在。

① IoU 的一维投影，就是区间求交

轴对齐框的 IoU，交集面积可以分解成两个独立的一维区间求交之积：

\[\mathrm{inter} = \underbrace{\max\bigl(0,\;\min(x_2,x_2') - \max(x_1,x_1')\bigr)}_{x\text{ 轴上的区间交长度}} \times \underbrace{\max\bigl(0,\;\min(y_2,y_2') - \max(y_1,y_1')\bigr)}_{y\text{ 轴上的区间交长度}}\]

而「给两组各自不相交且有序的区间，求所有交集」正是双指针的标准题（谁的右端点先结束谁前进，$O(m+n)$）。手撕完整的 IoU / GIoU / NMS / mAP 请去 C61 模块 05，本课不重复；这里只需要知道：那些代码的骨架，就是你在这一模块练的区间操作。

② NMS 就是「排序 + 扫描」

贪心 NMS 的结构是：按分数降序排序 → 从高到低扫描 → 每保留一个就抑制掉与它 IoU 超阈值的后续框。这与「区间调度」（按结束时间排序后贪心取）是同一个模式：排序建立一个全序，扫描时用一个「已选集合」做局部约束检查。C62 模块 04 会把 NMS 建模成加权区间调度并用 DP 求最优解，量化贪心的次优程度。

③ 多帧投票 = 滑动窗口；bbox 统计 = 积分图

TSR 的时序融合（C55-04）里，「最近 K 帧里这个 track 被检出了几次」就是一个定长滑动窗口的计数；「置信度在窗口内的移动平均」就是定长窗口求和。而候选框打分、前景像素统计、区域均值方差粗筛，都是积分图的直接应用。

9研究前沿与开放问题

数组与字符串算法是教科书里最「已完成」的一章，但仍然有几个值得知道的活跃问题——它们不会出现在一面里，却能在「你平时关注什么」的闲聊里显出你的深度。

  • 缓存友好性正在超越渐近复杂度。在现代 CPU 上，一个 $O(n\log n)$ 但访存随机的算法，常常慢于 $O(n^2)$ 但顺序访存的算法（在 $n$ 不太大时）。双指针与滑动窗口之所以在实践中极快，很大程度上是因为它们是顺序扫描，对预取器（prefetcher）极其友好；而哈希表虽然摊还 $O(1)$，每次查找都是一次可能的 cache miss。这个差距在 ML 后处理里是可测量的——把候选框按空间排序后再做 NMS，有时比不排序快，尽管复杂度没变。
  • SIMD 与向量化让「常数」重新变成主角。numpy 的向量化、AVX-512、以及 ARM NEON（车端 SoC 上就是它）能把顺序扫描类算法加速 8–32 倍。问题是：哪些算法可以向量化？前缀和有并行扫描（parallel scan / Blelloch）算法，但双指针的 left 更新是数据依赖的，天然难向量化。「可向量化性」正在成为算法选择的一个新维度，而教科书还没跟上。
  • 字符串匹配的实际最优解仍在演化。理论上 KMP 是 $O(n+m)$，但实践中 memmem / Boyer-Moore / SIMD 加速的两字节过滤常常更快。这是「渐近最优 ≠ 实际最优」最经典的案例，也是面试里一个很好的诚实回答素材：「我知道 KMP 是 $O(n+m)$，但如果是生产代码我会先测一下标准库的实现，它通常已经做了 SIMD 优化。」
  • 流式/在线版本的算法缺少系统教材。本模块所有算法都假设数据在内存里、可以随意回头看。但在车端，帧是流式到来的，你不能存下所有历史。滑动窗口天然适合流式（这也是它在时序融合里被大量使用的原因），而前缀和需要存整个数组。「把一个离线算法改成在线算法」是感知工程的日常，却几乎不出现在算法教材里——这也是 C55-04 的时序融合那一节要单独讲的原因。
  • LLM 会不会让这类题彻底退场？目前的观察是：题目本身在贬值，但「读懂一段别人写的双指针代码并指出它的不变量在哪一行被破坏」这类任务在升值。本模块的「暴力解 + 对拍」训练的正是这种验证能力——当代码变得廉价，验证代码的能力就变成瓶颈。

★ 必读：Cormen, Leiserson, Rivest, Stein, Introduction to Algorithms（CLRS, 4th ed.）第 2.1 节「Insertion sort」里的循环不变量框架——只读那三页，初始化/保持/终止这三步就是本模块第 2 节的全部理论来源。★ Viola & Jones, Rapid Object Detection using a Boosted Cascade of Simple Features（CVPR 2001）——积分图（integral image）的出处，读第 2.1 节即可；「用 $O(1)$ 的矩形求和换取实时性」这个思路今天仍然在用。★ Crow, Summed-Area Tables for Texture Mapping（SIGGRAPH 1984）——同一个数据结构在图形学里的更早出处，说明这是被独立发明了两次的想法。

配套材料：Skiena, The Algorithm Design Manual（3rd ed.）第 3 章（数据结构选择）；Blelloch, Prefix Sums and Their Applications（1990，并行前缀和，理解「为什么前缀和可以向量化而双指针不行」）。相邻课程：模块 00（六步协议与时间预算）、模块 02（哈希、排序与二分：本模块的「排序 + 扫描」在那里被展开）、模块 04（DP 与贪心：NMS 建模成加权区间调度）、C61 模块 05（IoU/NMS/mAP 手撕，本模块不重复）、C55 模块 04（时序融合：滑动窗口的工程形态）、C57 模块 04（切片推理：跨片合并里的区间与并查集）。完整清单见 references.md。
