# 术语词典 · Glossary（编程面试实战：算法与数据结构）

> 按主题分组。每条给出：**英文 / 中文 / 一句话定义 / 为什么重要 / 常见误解**。

> 而是告诉你**面试官问到这个词时想听到什么**，以及**大多数人在这里说错了什么**。

## 一 · 复杂度与分析 · Complexity & Analysis

| 术语 (EN) | 中文 | 一句话定义 | 为什么重要 | ⚠️ 常见误解 |
|---|---|---|---|---|
| time complexity | 时间复杂度 | 基本操作次数随输入规模 n 增长的**渐进阶**，忽略常数与低阶项。 | 面试里每写完一段代码都必须主动报出它——不主动报，面试官就得问，这一问你已经丢了「主动性」分。 | 以为「循环层数 = 复杂度指数」。两层循环里内层长度是 O(1) 时整体仍是 O(n)；反过来单层循环里调用了 `in list` 就已经是 O(n²)。 |
| space complexity | 空间复杂度 | 除输入之外**额外**占用的内存随 n 的增长阶。 | 「O(1) 额外空间」是很多题的隐藏要求，也是最容易被追问的一刀。 | 把输入本身算进额外空间；或者忘了**递归栈也是空间**——一个递归深度 O(n) 的解法不是 O(1) 空间。 |
| Big-O / Big-Θ / Big-Ω | 大 O / 大 Θ / 大 Ω | O 是上界、Ω 是下界、Θ 是紧界（上下界同阶）。 | 说「这个算法是 O(n²)」严格来说只是声明了上界；面试官问「能不能更紧」时，他是在问 Θ。 | 以为 O 就是「实际运行时间」。O(n) 的算法完全可以比 O(n log n) 的慢——常数与访存模式在 n 不大时占主导。 |
| amortized complexity | 均摊复杂度 | 一串操作的**总代价除以操作数**，允许单次很贵、但保证平均便宜。 | Python `list.append`、`dict` 插入都是均摊 O(1)——**「均摊」这两个字面试官一定会追问**：动态数组扩容时要拷贝全部元素，单次是 O(n)，但因为每次容量翻倍，n 次 append 的总代价是 O(n)。 | 把均摊当成「平均情况」。**两者完全不同**：平均是对输入分布取期望，均摊是对操作序列取平均，均摊是**最坏情况下的保证**，不依赖任何输入分布假设。 |
| worst / average / expected case | 最坏 / 平均 / 期望复杂度 | 分别是对所有输入取最大、对输入分布取期望、对算法内部随机性取期望。 | quicksort 最坏 O(n²)、平均 O(n log n)；随机化 quickselect 是**期望** O(n)（期望来自随机 pivot，不来自输入假设）。 | 以为「平均」和「期望」是同义词。期望复杂度只依赖你自己掷的骰子，**对手无法构造坏输入**；平均复杂度依赖输入分布假设，对手可以攻击。 |
| in-place algorithm | 原地算法 | 只用 O(1)（或 O(log n)）额外空间，直接在输入数组上修改。 | 「原地」是数组题最常见的加分约束：原地移除元素、原地旋转矩阵、原地去重都是高频题。 | 以为「不新建数组」就是原地。用了一个长度为 n 的 `visited` 数组仍然是 O(n) 空间；而 `sorted(a)` 返回新列表、`a.sort()` 才是原地。 |
| loop invariant | 循环不变量 | 在循环每次迭代**开始前后都成立**的命题，用来证明循环的正确性。 | **这是「我想清楚了」与「我背下来了」之间唯一可观测的区别。** 双指针、滑动窗口、二分的三套模板，正确性全靠它。面试里主动说一句「我的不变量是：`[0, i)` 里全是非零元素」，评分立刻不同。 | 以为不变量是注释里的废话。它是**可验证的断言**：本课 notebook 里会把不变量写成 `assert` 放进循环体，写错模板会当场崩。 |
| recursion depth | 递归深度 | 递归调用嵌套的最大层数，决定栈空间占用。 | Python 默认递归上限约 1000，**一个 n=10⁵ 的链表递归遍历会直接 RecursionError**——这是面试里演示「我考虑了工程约束」的好机会。 | 以为「递归写起来短就该用递归」。深度与 n 同阶时必须转迭代；深度是 O(log n)（平衡二分）时递归完全安全。 |
| tail recursion | 尾递归 | 递归调用是函数的最后一个动作，理论上可被编译成循环。 | 用来解释「为什么某些递归能机械地转成迭代」。 | 以为 Python 会做尾递归优化。**CPython 明确不做**，写了尾递归照样爆栈。 |
| complexity ↔ n 的经验换算 | 规模与复杂度的对照 | 给定 n 的量级，反推可接受的复杂度：n≤20 → O(2ⁿ)；n≤500 → O(n³)；n≤5000 → O(n²)；n≤10⁶ → O(n log n)；n≤10⁸ → O(n)。 | 面试官给出数据范围时，**那就是在给你复杂度提示**。听到「n 最大 20」还去想多项式解法是没接住信号。 | 以为这张表是硬规则。它的前提是「约 10⁸ 次基本操作 ≈ 1 秒」，而 **Python 慢一个数量级**，实际按 10⁷ 估更安全——面试里说出这个修正是加分项。 |
| CRUD 复杂度速查 | 常用容器操作复杂度 | Python `list`：索引 O(1)、`append` 均摊 O(1)、`insert(0,x)`/`pop(0)` O(n)、`in` O(n)；`dict`/`set`：查改删均摊 O(1)；`deque`：两端 O(1)；`heapq`：push/pop O(log n)。 | 一半的「我的解法应该是 O(n) 啊为什么超时」都出在 `list.pop(0)` 和 `x in list` 上。 | 以为 `set` 和 `list` 的 `in` 差不多。在 n=10⁵ 时差了五个数量级——**把 `list` 换成 `set` 是最廉价的一次优化**，也是面试里最常见的一次「优化思路」发言。 |
| trade-off: time vs space | 时空权衡 | 用额外内存换时间（哈希表、前缀和、记忆化），或用时间换内存（滚动数组、原地修改）。 | 几乎所有「从暴力到最优」的优化都是这个权衡的一次具体实施——**说清楚你在拿什么换什么，比说出答案更值钱**。 | 以为总是空间换时间。滚动数组、原地算法、双指针都是反方向；面试官问「能不能省空间」时想听的正是这些。 |

## 二 · 数组与指针技巧 · Arrays & Pointer Techniques

| 术语 (EN) | 中文 | 一句话定义 | 为什么重要 | ⚠️ 常见误解 |
|---|---|---|---|---|
| two pointers | 双指针 | 用两个下标同时扫描同一个（或两个）序列，把某些 O(n²) 的枚举压到 O(n)。 | 数组/字符串题最高频的技巧，没有之一。**关键不是会写，而是能说出为什么不漏解**。 | 以为双指针是一个模板。它至少有**三种形态**（对撞 / 快慢 / 同向），触发信号完全不同，混用是常见 bug 源。 |
| opposite-direction pointers | 对撞双指针 | 一头一尾向中间逼近，每步根据比较结果移动其中一个。 | 触发信号：**数组已排序** + 求「一对元素满足某条件」（两数之和、盛最多水的容器、验证回文）。 | 以为「移动左边还是右边」凭感觉。必须有**排除论证**：在盛水容器题里，移动较高的那根柱子永远不可能变好，所以移矮的——**说不出这个论证就等于没做出这题**。 |
| fast-slow pointers | 快慢双指针 | 两个指针以不同速度前进（常见 1 步 vs 2 步）。 | 触发信号：**环检测**（Floyd 判圈）、找中点、找倒数第 k 个。链表题的标志性技巧。 | 以为快慢指针只用于链表。数组上找重复数（把值当指针）同样是它；反过来，**Floyd 判圈相遇后为什么把一个指针放回头部就能找到环入口，需要一段两行的数学推导**——这是高频追问。 |
| same-direction pointers | 同向双指针 | 快指针负责读、慢指针负责写（或维护区间左端），两者同向前进。 | 触发信号：**原地过滤/去重/移动**（移除元素、移动零、有序数组去重）。不变量通常是「`[0, slow)` 是已处理好的结果」。 | 以为它和滑动窗口是两个东西。**滑动窗口就是同向双指针的一个特例**（慢指针作为窗口左端），把它们统一起来能少记一半模板。 |
| sliding window | 滑动窗口 | 用一对同向指针维护一段连续子区间，右端扩张、左端收缩。 | 所有「**连续**子数组/子串 + 满足某条件」的题的统一解法。这个「连续」二字是识别信号。 | 以为所有子数组题都能滑窗。**滑窗要求条件具有单调性**：窗口变大时「更容易违反」、变小时「更容易满足」。含负数的「和 ≥ K 的最短子数组」就不满足，必须换前缀和 + 单调队列。 |
| fixed-size window | 定长窗口 | 窗口大小固定为 k，右移一格就吐出一个、吃进一个。 | 最简单的形态，模板短到可以背；滑窗最大值、长度为 k 的最大平均值都是它。 | 以为定长窗口也需要 while 收缩。定长窗口用 `if i >= k` 一次性弹出即可，写成 while 说明模板没分清。 |
| variable-size window | 变长窗口 | 窗口大小由条件决定，用 `while 违反条件: 收缩左端`。 | 最长无重复子串、最小覆盖子串、和至少为 K 的最短子数组都是它。 | 以为「收缩到刚好满足就停」是显然的。要证明**不漏解**：对每个右端 r，我们找到的左端 l 是使窗口合法的最大 l，因此以 r 结尾的最优解一定被考察过——**这句话就是面试里要说出来的那句**。 |
| prefix sum | 前缀和 | `pre[i] = a[0]+…+a[i-1]`，则任意区间和 `= pre[r+1] - pre[l]`。 | 把「区间求和」从每次 O(n) 变成预处理 O(n) + 每次 O(1)。「和为 K 的子数组个数」= 前缀和 + 哈希表，是高频题。 | 忘了**前导 0**。`pre` 数组长度应为 n+1 且 `pre[0]=0`，否则 `l=0` 的情况要写特判——这是面试里最常见的一处 off-by-one。 |
| difference array | 差分数组 | `d[i] = a[i] - a[i-1]`；对 `a` 的区间 `[l,r]` 加 v，只需 `d[l]+=v; d[r+1]-=v`。 | 把「区间加」从每次 O(n) 变成 O(1)，最后一次前缀和还原。会议室安排、航班预订、公交上下车都是它。 | 以为差分和前缀和是两个技巧。**它们互为逆运算**：差分的前缀和是原数组。理解这一点，两个模板合并成一个。 |
| 2-D prefix sum | 二维前缀和 | `P[i][j]` = 左上角到 (i-1,j-1) 的矩形和；任意矩形和 = **四次查表两加两减**（容斥）。 | 任意子矩阵求和 O(1)，**与矩形大小无关**——这是它最反直觉也最有力的性质。 | 忽略了它在 CV 里的名字。 |
| integral image | 积分图 | 二维前缀和在图像上的名字（Viola & Jones 2001）。 | **这是本课与 CV 岗最直接的一个连接点**：Haar 特征需要在无数个不同大小的矩形上求和，积分图让每个特征都是 O(1)，人脸检测因此第一次做到实时。面试里说出这条渊源，「刷题选手」的标签立刻摘掉。 | 以为积分图是个 CV 专用黑科技。它就是前缀和；真正需要注意的是**数值范围**（uint8 图积到 1080p 会溢出 int32 吗）与**边界补 0 的那一行一列**。 |
| Kadane's algorithm | 最大子数组和 | 一次扫描维护「以当前元素结尾的最大和」，取全程最大值。 | 最经典的「DP 但看起来像贪心」的题，也是理解「状态定义要带上『以 i 结尾』」的最佳入门例。 | 以为它是贪心。它是**一维 DP 的空间压缩形态**：`f[i] = max(a[i], f[i-1]+a[i])`，只是 `f` 被压成了一个变量。 |
| monotonic stack | 单调栈 | 维持栈内元素单调，用来 O(n) 求「下一个更大/更小元素」。 | 每日温度、柱状图最大矩形、接雨水的标准解。**每个元素进栈出栈各一次，所以是 O(n)**——这句话就是复杂度论证。 | 以为它很难。它的识别信号非常明确：题目里出现「**下一个比它大的**」「**左右第一个小于它的**」时几乎必然是单调栈。 |
| monotonic deque | 单调队列 | 双端队列维持单调，用来 O(n) 求**滑动窗口最大值**。 | 滑窗最大值是 CV 岗高频题（对应 1-D 的非极大值抑制思路）。 | 以为用堆就够了。堆是 O(n log k) 且需要惰性删除；单调队列是 O(n) 且每个元素进出各一次——**面试里能同时给出这两个解并比较，是明确的加分项**。 |
| in-place removal (write pointer) | 原地删除 / 写指针 | 用一个写指针把要保留的元素依次覆写到前面，返回新长度。 | 「移除元素」「移动零」「有序数组去重」三题共用一个模板。 | 忘了收尾。有些题要求**剩余位置置零**，有些不要求；不问清楚就写是典型的「不问边界」失分。 |
| boundary checklist | 边界条件清单 | 空输入 / 单元素 / 全相同 / 极值（最大最小、正负零）/ 重复元素 / 溢出。 | **写完代码主动跑这六项，是「测试意识」这一维的全部得分点。** 而它只花 60 秒。 | 以为 Python 没有整数溢出所以不用管。Python 的 int 确实无限精度，但**面试官可能问「换成 C++ 呢」**；另外 numpy 的 int32/uint8 会真溢出，CV 场景里这是实打实的 bug 源。 |
| string immutability | 字符串不可变性 | Python 的 `str` 不可变，`s += c` 在循环里是 O(n²)。 | 字符串拼接题里这是隐形的复杂度炸弹，正确做法是 `list` 收集 + `''.join()`。 | 以为 CPython 的原地扩展优化能救你。那个优化只在引用计数为 1 时生效，**不能依赖**，面试里说 `''.join()` 才是标准答案。 |

## 三 · 哈希与排序 · Hashing & Sorting

| 术语 (EN) | 中文 | 一句话定义 | 为什么重要 | ⚠️ 常见误解 |
|---|---|---|---|---|
| hash table | 哈希表 | 用哈希函数把 key 映射到桶下标，实现均摊 O(1) 的查改删。 | 「用哈希表把 O(n²) 降到 O(n)」是面试里出现频率最高的一句优化发言。 | 以为查询是**保证** O(1)。是**均摊且期望** O(1)：所有 key 撞到同一个桶时退化成 O(n)，这正是哈希碰撞攻击（HashDoS）的原理。 |
| hash collision | 哈希冲突 | 两个不同的 key 映射到同一个桶。 | 面试官追问「dict 内部怎么实现」时，你至少要能说出**链地址法**与**开放寻址**两种，并指出 **CPython 用的是开放寻址（探测序列）**。 | 以为好的哈希函数能避免冲突。桶数有限，**冲突必然发生**（鸽笼原理）；哈希函数的目标是让冲突均匀，不是消灭冲突。 |
| load factor / rehashing | 负载因子 / 再哈希 | 元素数 ÷ 桶数；超过阈值（CPython 约 2/3）就扩容并重新分布所有元素。 | 解释了为什么插入是**均摊** O(1)：扩容那一次是 O(n)，但摊到之前的 n 次插入上是 O(1)。 | 以为扩容后所有 key 的桶位置不变。全部要重算——所以 **dict 的迭代顺序在扩容后可能变**（Python 3.7+ 保证的是插入顺序，那是靠额外的紧凑数组实现的，不是靠桶）。 |
| hashability | 可哈希性 | 对象要能做 dict 的 key，必须实现 `__hash__` 且在生命周期内不变。 | `list` 不可哈希、`tuple` 可哈希是高频小坑；**把坐标当 key 时要写 `(r, c)` 不能写 `[r, c]`**。 | 以为自定义类不能做 key。默认按 id 哈希是可以的，但**一旦重写 `__eq__` 而不重写 `__hash__`，对象立刻变不可哈希**——这是 Python 特有的一个坑。 |
| float as key | 浮点数做 key | 用浮点数（尤其是计算结果）作为字典键。 | CV 场景里很常见（把 IoU、坐标当 key），而 `0.1 + 0.2 != 0.3`，**等值判断会莫名失败**。 | 以为四舍五入就安全。`round()` 在边界上仍有二进制表示问题；正确做法是**量化成整数**（乘以 1000 取整）或改用容差比较。另注意 `hash(1) == hash(1.0) == hash(True)`，**`d[1]` 和 `d[True]` 是同一个键**。 |
| Counter / defaultdict | 计数器 / 带默认值字典 | `collections` 里的两个高频工具：前者一行统计频次，后者省掉 `if key not in d`。 | 哈希类题的标准写法，写得干净整洁是「代码质量」这一维的直接得分。 | 以为随便用。**考点是「自己实现计数」时（比如「不用内置库实现 Counter」），直接 `Counter(s)` 会被判绕过考点**——正确做法是先问一句「我可以用 collections 吗」，问了就没有风险。 |
| set operations | 集合运算 | 交（`&`）、并（竖线运算符）、差（`-`），单次元素判定均摊 O(1)。 | 「两数组交集」「找缺失数字」类题一行解决。 | 以为集合运算保序。**`set` 无序**，需要有序结果时必须显式排序，否则对拍会随机失败。 |
| comparison sort lower bound | 比较排序下界 | 任何基于比较的排序在最坏情况下至少需要 **Ω(n log n)** 次比较（决策树有 n! 个叶子）。 | 面试官问「能比 O(n log n) 更快吗」时，标准答案是「基于比较不行，除非利用值域」。 | 以为这个下界对所有排序成立。**计数排序 / 桶排序 / 基数排序不基于比较**，可以做到 O(n + k)——但代价是需要值域已知且不太大。 |
| stable sort | 稳定排序 | 相等元素的相对顺序在排序后保持不变。 | **这在检测里是正确性问题不是风格问题**：NMS 按分数排序时若出现同分框，不稳定排序会让同一份输入在两次运行、两个平台上给出不同的保留框，导致「离线复现不出线上结果」。Python 的 `sorted`/`list.sort` 是 **Timsort，保证稳定**。 | 以为稳定性只在「多关键字排序」时才有意义。它更重要的作用是**可复现性**；另外 numpy 的 `np.sort` 默认 quicksort **不稳定**，要稳定必须显式 `kind='stable'`——这是 CV 代码里的真实坑。 |
| multi-key sort | 多关键字排序 | 按多个字段依次排序，Python 用 `key=lambda x: (a, -b)` 或**利用稳定性分多趟从次要到主要排**。 | 「先按分数降序、分数相同按面积升序」这类需求在检测后处理里天天出现。 | 以为降序只能用 `reverse=True`。`reverse=True` 会把**所有**字段都反过来；混合升降序时要用负号（数值）或分多趟排（非数值）——**这正是稳定性的经典用途**。 |
| Timsort | Timsort | Python 的默认排序：归并 + 插入的混合，利用数据中已有的有序段（run）。 | 解释了为什么「近乎有序的数据」排起来接近 O(n)，最坏仍是 O(n log n)。 | 以为它是快排。它是**归并系**，所以稳定、且需要 O(n) 额外空间。 |
| quicksort | 快速排序 | 选 pivot 分区，递归排两侧；平均 O(n log n)，最坏 O(n²)。 | 分治思想的模板，也是 quickselect 的前身。 | 以为最坏情况不会发生。**已排序数组 + 取首元素当 pivot 就是最坏情况**，这是面试官最爱构造的反例；随机化 pivot 或三数取中是标准对策。 |
| merge sort | 归并排序 | 分治后合并两个有序数组；稳定，O(n log n) 保证，需 O(n) 空间。 | 「合并两个有序数组」这个子过程本身就是高频题；**逆序对计数**也是在归并里顺手完成的。 | 以为它只能排数组。**链表归并排序是 O(1) 额外空间的**（不需要拷贝，只改指针），这是链表题里的经典追问。 |
| counting / bucket / radix sort | 计数 / 桶 / 基数排序 | 不比较，直接利用值域分桶；O(n + k)。 | 值域小（如「排序 0–100 的分数」「按年龄排序」）时可以突破 n log n 下界。 | 以为线性排序总是更快。k 很大时（如排序 64 位整数）反而更慢，且空间开销大——**能说出它的适用前提比会写它更重要**。 |
| heap / priority queue | 堆 / 优先队列 | 完全二叉树，父节点总不大于（小顶堆）子节点；push/pop 为 O(log n)，建堆 O(n)。 | Top-K、合并 K 个有序链表、中位数流、滑窗最大值的备选解，全是它。 | 以为 `heapq` 有大顶堆。**Python 只有小顶堆**，要大顶堆得取负数（或用元组包装）；另外 `heapify` 是 **O(n) 不是 O(n log n)**，这是个高频追问点。 |
| Top-K | 前 K 大/小 | 从 n 个元素里取最大（小）的 K 个。 | 三种解法的取舍是标准面试对话：**全排序 O(n log n)**（K 接近 n 时最优且最简单）、**堆 O(n log K)**（K 远小于 n、或数据是流式时最优）、**quickselect 期望 O(n)**（一次性、数据全在内存、且不要求 K 个内部有序时最快）。 | 以为 quickselect 总是最优。它**最坏 O(n²)**、会**修改原数组**、且**不保证结果有序**；流式数据上根本用不了。把这三条说出来，这题就满分了。 |
| quickselect | 快速选择 | 快排的单边递归版：只递归包含第 k 位的那一侧；期望 O(n)，最坏 O(n²)。 | 「数组中第 K 大的元素」的最优解，也是展示「分治可以只走一边」的最佳例子。 | 以为期望 O(n) 需要输入随机。**期望来自随机 pivot**（算法自己掷骰子），与输入分布无关——这个区分是复杂度概念里最能显水平的一处。另：确定性的最坏 O(n) 算法（median-of-medians / BFPRT）存在但常数极大，实践中不用，**知道它存在即可**。 |
| deduplication idioms | 去重惯用法 | 有序数组用同向双指针原地去重；无序用 `set`；要保序去重用 `dict.fromkeys(a)`。 | 三种场景三种写法，选错就是多一个 log 或多一次排序。 | 以为 `set(a)` 保序。不保序；**`list(dict.fromkeys(a))` 才是 Python 3.7+ 的保序去重惯用法**。 |

## 四 · 二分 · Binary Search

| 术语 (EN) | 中文 | 一句话定义 | 为什么重要 | ⚠️ 常见误解 |
|---|---|---|---|---|
| binary search | 二分查找 | 在**单调**结构上每次砍掉一半搜索空间，O(log n)。 | 「排序 + 二分」是最廉价的一次复杂度降级；而二分本身是最容易写错的基础算法——**Bentley 说过工业界的二分实现有相当比例存在 bug，Java 的 `binarySearch` 在 2006 年才修掉溢出问题**。 | 以为二分只用于「在有序数组里找一个数」。它的本质是**在单调谓词上找分界点**，数组只是最朴素的一种。 |
| monotonic predicate | 单调谓词 | 一个布尔函数 `check(x)`，在阈值前恒为 False、之后恒为 True（或反之）。 | **这是二分的真正前提**。看到「有序数组」只是表象，看到「单调性」才算看懂。面试里先说一句「这个谓词是单调的，因为……」，正确性论证就完成了一半。 | 以为必须显式排序才能二分。旋转有序数组、峰值数组、矩阵按行列有序，都不是全局有序但仍可二分。 |
| lower_bound / left boundary | 左边界 / 第一个 ≥ target 的位置 | 返回第一个满足 `a[i] >= target` 的下标；不存在则返回 n。 | 三套模板里最有用的一套：**「第一个 ≥」能推出「最后一个 <」「等于 target 的个数」「插入位置」**，一套顶四套。对应 `bisect.bisect_left`。 | 以为要单独记「找第一个等于 target」。找到左边界后再检查 `a[i] == target` 即可，**不要写第二套模板**——多一套模板就多一处写错的机会。 |
| upper_bound / right boundary | 右边界 / 第一个 > target 的位置 | 返回第一个满足 `a[i] > target` 的下标。对应 `bisect.bisect_right`。 | `bisect_right(a,t) - bisect_left(a,t)` 就是 t 的出现次数，一行解决计数题。 | 把 `bisect_right` 理解成「最后一个等于 target 的位置」。它返回的是**那个位置的下一个**，差一位就是 off-by-one。 |
| loop invariant (binary search) | 二分的循环不变量 | 例：闭区间 `[lo, hi]` 写法的不变量是「答案若存在，必在 `[lo, hi]` 内」；左闭右开 `[lo, hi)` 写法的不变量是「`a[lo-1] < target ≤ a[hi]`」。 | **二分的所有 bug 都是不变量没想清楚。** 把不变量写在代码上方的注释里，然后每一行都对着它检查，是当场避免死循环的唯一可靠方法。 | 以为「多试几次边界」能代替不变量。面试里没有 judge，试不出来；说得出不变量才能当场论证。 |
| off-by-one / infinite loop | 差一错误 / 死循环 | `mid` 取法、`lo/hi` 更新、循环条件（`<` 还是 `<=`）三者不匹配导致的经典错误。 | 面试里写出死循环是**致命失误**（会直接卡死协作编辑器）。 | 以为死循环只会出现在 `while lo < hi` 里。**`lo = mid` 且 `mid` 向下取整**时，`lo` 和 `hi` 相邻就永远不动了——这时必须用 `mid = (lo + hi + 1) // 2` 向上取整。这条规则值得单独背下来。 |
| mid overflow | 中点溢出 | `(lo + hi) / 2` 在 lo、hi 都很大时溢出；正确写法 `lo + (hi - lo) // 2`。 | Python 没有这个问题（int 无限精度），但**面试官问「换 C++/Java 呢」时这就是标准答案**，答出来说明你读过实现而不只是刷过题。 | 以为 Python 里就完全不用管。用 numpy 的 int32 索引时仍会溢出。 |
| binary search on answer | 在答案上二分 | 不在数组上二分，而在**候选答案的值域**上二分，配一个 `check(x)` 判定该答案是否可行。 | **中高频题型的统一钥匙**：识别信号是题面出现「**最小化最大值**」「**最大化最小值**」「至少 / 最多能……」。典型题：分割数组的最大值最小、koko 吃香蕉、船的最低运载能力、在 D 天内送达包裹。 | 以为这是个偏门技巧。它其实是把**最优化问题**转成一串**判定问题**——这是算法设计里最通用的思路之一，也是能在面试里说出「我把优化问题转成判定问题」这句话的机会。 |
| feasibility check | 可行性判定 | 在答案上二分时的 `check(x)`：给定候选答案 x，用贪心/模拟判断能否达成。 | 这道题真正的难点通常不在二分，**而在写出正确的 check**——二分只有 5 行，check 有 15 行。 | 以为 check 可以随便写。**check 必须是单调的**（x 更宽松时更容易可行），否则二分无效；面试里要明确说出这一点。 |
| binary search on float | 浮点二分 | 在实数区间上二分，用 `while hi - lo > eps` 或**固定迭代次数**（如 100 次）终止。 | 求平方根、最优比例（0-1 分数规划）等题会用到。 | 以为 `eps` 越小越好。太小会死循环（浮点精度到极限后 `mid` 不再变化）；**固定迭代 100 次是更稳的写法**，因为每次区间减半，100 次足以逼近任何双精度可表示的精度。 |
| rotated / peak array search | 旋转数组 / 峰值二分 | 在局部有序或单峰的数组上二分。 | 高频变体题，考的是「你是否理解二分靠的是单调性而不是有序性」。 | 以为有重复元素时同样是 O(log n)。**旋转数组含重复元素时最坏退化到 O(n)**（`a[lo]==a[mid]==a[hi]` 时无法判断丢哪半），这是标准追问。 |
| exponential search | 倍增查找 | 先以 1,2,4,8… 倍增找到上界，再在该区间内二分。 | 用于**无边界的搜索空间**（未知长度的数组、流式接口、在答案上二分但上界难定）。 | 以为在答案上二分必须先猜一个大上界。倍增是更干净的做法，且复杂度仍是 O(log ans)。 |

## 五 · 树与图 · Trees & Graphs

| 术语 (EN) | 中文 | 一句话定义 | 为什么重要 | ⚠️ 常见误解 |
|---|---|---|---|---|
| recursion three parts | 递归三要素 | ① 终止条件 ② 拆解成子问题 ③ 合并子问题的解。 | 树题的通用脚手架。**面试里先口头说这三条再写代码，等于把正确性论证提前做完了**。 | 以为「想不清楚就先写，边写边补」。递归最忌讳这样——终止条件漏了就是无限递归，当场崩。 |
| DFS traversal (pre/in/post) | 前序 / 中序 / 后序遍历 | 根在子树之前 / 之间 / 之后被访问。 | 三者不是三个模板而是**同一个模板挪一行**。中序遍历 BST 得到有序序列，这是一大类题的钥匙。 | 以为后序只是「顺序不同」。后序的本质是「**先拿到子树的结果再处理当前节点**」，所以所有需要自底向上聚合的题（树的高度、直径、最大路径和）都必须是后序。 |
| BFS / level order | 广度优先 / 层序遍历 | 用队列逐层展开。 | **触发信号：问「最少几步」「最短路径」「逐层输出」**。 | 以为 BFS 一定比 DFS 快。两者都是 O(V+E)；BFS 的空间是「最宽一层」，在宽树上可能远大于 DFS 的 O(深度)。 |
| DFS vs BFS 选择信号 | 深搜与广搜的选型 | 最少步数 / 最短路（无权）→ BFS；所有路径 / 回溯 / 连通性 / 拓扑 → DFS。 | **这一条判据能覆盖八成图论题**，是本课模块 03 最值钱的一句话。 | 以为「能用 DFS 求最短路」。无权图上 DFS 求最短路要遍历所有路径，指数级；**BFS 第一次到达即最短**，这个性质来自「按层扩展」。 |
| recursion → iteration | 递归转迭代 | 用显式栈手工模拟调用栈：把「递归调用前的状态」压栈。 | 深度可能达到 10⁵ 时必须转（Python 递归上限约 1000）；**面试里主动提一句「n 很大的话我会改成迭代」是明确的加分**。 | 以为转迭代很难。它是**机械的**：每个递归调用点对应一次入栈，返回点对应一次出栈；后序遍历的迭代版需要一个「是否已展开」标记，这是唯一的技巧点。 |
| backtracking | 回溯 | DFS + 状态撤销（「做选择 → 递归 → 撤销选择」）。 | 全排列、子集、组合、N 皇后、单词搜索的统一模板。 | 忘了撤销，或者**在剪枝上省事**。回溯题的复杂度分析要说清「解空间大小 × 每个解的构造代价」，不能只说「指数级」。 |
| binary search tree (BST) | 二叉搜索树 | 左子树 < 根 < 右子树；中序遍历有序。 | 「验证 BST」是经典陷阱题。 | 以为只要检查「左孩子 < 根 < 右孩子」就够。**必须传递上下界**：一个左子树里的极右节点也不能大于根。这个错误在面试里出现率极高。 |
| trie | 字典树 | 用树结构共享字符串前缀，查询 O(L)。 | 前缀匹配、自动补全的标准结构。 | ML/CV 岗上属于**低频**，知道它的形态与适用场景即可，不必背实现——**本课把时间留给更高频的并查集**。 |
| union-find (DSU) | 并查集 | 维护不相交集合，支持 `find`（查代表元）与 `union`（合并）。 | **本课与 CV 连接最强的一个结构**：把「IoU > 阈值的框合并成一类」写成并查集是 O(n α(n))，而逐对比较 + 传播是 O(n²) 甚至更差；**切片推理（SAHI）跨片合并重复框**用的也是它。 | 以为它只能做「有多少个连通块」。它同时能做**动态连通性**（边一条条加进来）、**判环**（Kruskal 里）、**等价类合并**——而这三种形态在题面上长得完全不一样。 |
| path compression | 路径压缩 | `find` 时把沿途所有节点直接挂到根上。 | 单独用它，均摊复杂度已经降到 O(log n) 级别。 | 以为递归版更好写就一定要用递归。**深链上递归版会爆栈**；迭代版（两趟或路径分裂）同样简单，面试里写迭代版更稳。 |
| union by rank / size | 按秩 / 按大小合并 | 把矮的树挂到高的树下（或小集合挂到大集合下）。 | 与路径压缩合用后，单次操作均摊 **O(α(n))**，α 是反阿克曼函数。 | 以为 α(n) 是「几乎 O(1)」的模糊说法。它是有明确定义的：**对任何实际规模的 n（哪怕是可观测宇宙的原子数），α(n) ≤ 5**——说出这个数字比说「几乎常数」更有说服力。 |
| connected component | 连通分量 | 图中互相可达的极大节点集合。 | 网格版的连通分量就是下一条。 | 以为无向图和有向图一样。有向图要区分**弱连通**与**强连通**（SCC，Tarjan/Kosaraju），后者在 ML/CV 岗属低频。 |
| connected-component labeling (CCL) | 连通域标记 | 给二值图像里每个连通区域分配唯一编号（4 邻域或 8 邻域）。 | **「岛屿数量」这道经典题在 CV 里的真名**。两种主流实现：一遍 BFS/DFS 泛洪，或**两遍扫描 + 并查集**（Hoshen-Kopelman / 经典 two-pass）——后者正是并查集的原始应用之一。 | 以为 4 邻域和 8 邻域只是参数差异。**它们会给出不同的连通块数**（对角相接的像素在 4 邻域下是两块、8 邻域下是一块），且前景用 8 邻域时背景必须用 4 邻域才能保持拓扑一致——这是图像处理里的经典约定，面试里提到会很亮眼。 |
| flood fill | 泛洪填充 | 从一个种子点出发把整个连通区域染色。 | 与 CCL 同源；画图软件的油漆桶、分水岭前处理都是它。 | 以为递归泛洪总是安全的。**1080p 图像上最坏递归深度是两百万**，必须用显式栈或队列。 |
| topological sort | 拓扑排序 | 有向无环图上给出一个满足所有依赖的线性序。 | 课程表、任务调度、编译依赖；**DAG 上的 DP 也依赖它给出的遍历顺序**。 | 以为只有一种写法。**Kahn 入度法**（BFS，天然检测环：出队数 < n 即有环）与 **DFS 三色法**（白/灰/黑，遇到灰色即成环）各有用途；面试里能同时说出两种并指出「Kahn 更容易顺手检测环」是加分。 |
| cycle detection | 环检测 | 无向图用并查集或 DFS 的父节点排除法；有向图用三色法或 Kahn。 | 「能否完成所有课程」类题的核心。 | 无向图 DFS 判环时**忘了排除「回到父节点」这条边**，导致每条边都被误判成环。 |
| Dijkstra | 迪杰斯特拉最短路 | 非负权图上用优先队列每次取出当前最近的未定点。 | 带权最短路的默认解法，O((V+E) log V)。 | 以为它能处理负权。**不能**（负权要用 Bellman-Ford / SPFA）；另外「已出队的点不再更新」这个性质**正是靠非负权保证的**，说得出这句话说明你懂原理不是背模板。 |
| 0-1 BFS | 0-1 权最短路 | 边权只有 0 和 1 时，用双端队列代替优先队列，O(V+E)。 | 网格上「翻转最少格子」类题的最优解。 | 属于**低频加分项**，知道存在即可。 |
| maximum independent set (NMS 的图视角) | 最大独立集 | 图中两两不相邻的最大节点集合。**把每个候选框当节点、IoU > 阈值的框之间连边，NMS 求的就是一个（加权）独立集。** | **这是本课最能在面试里当谈资的一个重述**：它立刻说明了两件事——① 最大加权独立集是 **NP-难**的，所以 ② **贪心 NMS 只是一个近似算法**，它「按分数从高到低取、取一个删一圈」正是经典的贪心近似策略。 | 以为 NMS 是「显然最优」的。它不是；模块 04 会把 1-D 情形建模成**加权区间调度**（这个特例可以 DP 求最优），然后量化贪心到底差多少——差值不大正是贪心在工程上活得好好的原因。 |
| grid as implicit graph | 网格即隐式图 | 网格的每个格子是节点，相邻格子间有边；不需要显式建图。 | 网格题（岛屿、迷宫、腐烂的橘子）占了 CV 岗图论题的绝大多数。 | 以为要先建邻接表。**直接用方向数组 `[(0,1),(1,0),(0,-1),(-1,0)]` 遍历即可**；写成方向数组而不是四段重复代码，是「代码质量」维度的直接得分。 |
| visited marking | 访问标记 | 用 `visited` 集合/数组，或直接原地改写输入（把 '1' 改成 '0'）。 | 忘记标记 = 无限循环，是网格题第一大 bug。 | 以为原地改写总是可以。**面试里必须问一句「我可以修改输入吗」**——问了就是加分（体现边界意识），不问就直接改是风险。 |

## 六 · DP 与贪心 · Dynamic Programming & Greedy

| 术语 (EN) | 中文 | 一句话定义 | 为什么重要 | ⚠️ 常见误解 |
|---|---|---|---|---|
| DP 五步 | 动态规划五步法 | ① 状态定义 ② 转移方程 ③ 初始化 ④ 遍历顺序 ⑤ 答案位置。 | **面试里把这五步口头过一遍再写代码，是 DP 题唯一可靠的流程。** 尤其是第一步，必须说成一句完整的中文句子：「`f[i][j]` 表示……的最优值」。 | 以为「想出转移方程」是最难的。**最难的是状态定义**——状态定义对了转移几乎是自然的；转移写不出来，九成是状态维度少了或者定义模糊。 |
| optimal substructure | 最优子结构 | 问题的最优解包含子问题的最优解。 | DP 成立的前提之一，也是面试官问「为什么这题能用 DP」的标准答案。 | 以为所有问题都有最优子结构。**最长简单路径就没有**（子路径最优不能拼出整体最优），这也是它 NP-难的原因。 |
| overlapping subproblems | 重叠子问题 | 递归展开时同一个子问题被反复求解。 | DP 成立的另一个前提，也是「记忆化能省下多少」的来源。 | 以为「有递归就能 DP」。分治（归并排序）子问题不重叠，加了记忆化也没用。 |
| state definition | 状态定义 | `f[...]` 各维度分别代表什么，以及它的值代表什么。 | **状态定义错了后面全错。** 诊断法：如果转移方程写起来需要「回头看之前选了什么」，说明状态里少了一维（少记了信息）。 | 以为状态维度越多越保险。多一维就多一个数量级的时间空间；**先想最少够用的维度，不够再加**。 |
| transition | 转移方程 | 从已知状态推出新状态的递推式。 | 写成数学式子再翻译成代码，比直接写代码错误率低得多。 | 「填表方向」搞反：从 `f[i-1]` 推 `f[i]`（拉取式）与从 `f[i]` 推 `f[i+1]`（推送式）都对，但**不能在一份代码里混用**。 |
| traversal order | 遍历顺序 | 保证每个状态被计算时，它依赖的状态都已算好。 | **空间压缩之后遍历顺序会被彻底锁死**，这是背包题的核心考点。 | 以为顺序随便。**01 背包压成一维后必须倒序遍历容量**（否则同一物品被用多次），**完全背包必须正序**（正是因为要允许用多次）——这一对反差是背包题最经典的一问。 |
| memoization | 记忆化搜索 | 自顶向下递归 + 缓存（Python 一个 `@lru_cache` 装饰器）。 | **面试里的救命稻草**：想不出递推顺序时，先写记忆化保证正确，再讨论怎么改成递推。这个策略本身就值分。 | 以为它比递推慢很多所以不该用。常数确实大一些，但**只计算真正需要的状态**，在状态空间稀疏时反而更快；缺点是递归深度。 |
| tabulation | 递推 / 填表 | 自底向上迭代填表。 | 没有递归栈风险，常数小，可做空间压缩。 | 以为记忆化和递推总能互转。**能，但递推需要你显式想清楚遍历顺序**——这正是它更难的地方。 |
| rolling array | 滚动数组 | 只保留最近 1–2 行（或一列），把 O(nm) 空间压到 O(m)。 | 空间压缩是 DP 题最常见的追问：「能不能优化空间？」 | 以为压缩只是省内存。**它会改变遍历顺序的合法性**（见上），也会让「回溯出具体方案」变得不可能——如果题目要求输出方案本身，就不能压。 |
| 0-1 knapsack | 01 背包 | 每个物品最多取一次，求容量约束下的最大价值。 | 模板题，也是**「算力预算下选哪些优化方案」的数学模型**（呼应 C57-05 的方案排序）。 | 以为「按性价比排序贪心」能解。**不能**——这正是分数背包（可切分）与 01 背包（不可切分）的分水岭，也是面试官验证你懂不懂贪心适用条件的经典问法。 |
| unbounded knapsack | 完全背包 | 每个物品可取无限次。 | 零钱兑换、组合总和都是它。 | 「求组合数」与「求排列数」的循环嵌套顺序不同：**外层物品内层容量 = 组合数**，**外层容量内层物品 = 排列数**。这个坑非常隐蔽。 |
| LIS | 最长上升子序列 | 求最长严格递增的子序列长度。 | O(n²) DP 与 **O(n log n) 的贪心 + 二分**双解，是「同一题两种复杂度」的最佳示范题。 | 以为 O(n log n) 解法里那个 `tails` 数组就是答案序列。**它不是**（长度对，内容通常不是任何一个合法 LIS）；要还原序列必须额外记录前驱。这是最常被问倒的一处。 |
| edit distance / LCS | 编辑距离 / 最长公共子序列 | 二维序列 DP 的两道模板题。 | 编辑距离 **= 序列评测里的字距（WER/CER）**，OCR、车牌识别、字幕对齐直接用它；LCS 是 diff 工具的核心。 | 以为编辑距离只有插入/删除/替换三种操作。**Damerau 版本还有相邻交换**；另外「只允许插入删除」时最优解等价于 `n + m - 2·LCS`——能说出这个关系是加分。 |
| interval DP | 区间 DP | 状态是「区间 `[i,j]` 的最优值」，按区间长度从小到大枚举。 | 戳气球、矩阵链乘、最长回文子序列。 | 遍历顺序写错（按 i、j 直接双层循环）。**必须按区间长度递增遍历**，否则依赖的短区间还没算。 |
| weighted interval scheduling | 加权区间调度 | 每个区间有权重，选一组互不重叠的区间使总权重最大；按右端排序 + 二分找前驱 + DP，O(n log n)。 | **本课把 1-D NMS 建模成这个问题，用 DP 求出「最优的框子集」，再与贪心 NMS 对比**——这是把算法课和检测课接起来的关键一步。 | 以为它和「无权区间调度」一样能贪心。**无权版按右端点贪心是最优的**（有交换论证），**加权版贪心就不对了**，必须 DP。这一对对比是理解「贪心什么时候成立」的最佳材料。 |
| greedy algorithm | 贪心算法 | 每一步取当下最优，不回头。 | 代码短、常数小；但**正确性必须证明，否则就是在赌**。 | 以为「过了几个样例就是对的」。面试官会当场构造反例；**说不出证明就诚实地说「我需要一个交换论证来确认，先给出 DP 保底」**，这个回答比硬撑好得多。 |
| exchange argument | 交换论证 | 证明贪心正确的标准方法：假设存在最优解与贪心解首次不同，证明可以把最优解「换成」贪心的选择而不变差，归纳即得。 | **这是贪心题的唯一硬通货。** 会写「按右端点排序」的人很多，能在 30 秒内讲清交换论证的人很少。 | 以为交换论证很玄。它其实是模板化的三句话：① 设最优解 OPT 与贪心解 G 首次分歧于第 k 步；② 把 OPT 在这一步的选择换成 G 的，论证不变差；③ 归纳，故 G 也是最优。 |
| greedy counterexample | 贪心反例 | 一个直觉上贪心应该成立、实际不成立的最小实例。 | 本课会给出零钱兑换的经典反例（面额 `[1, 3, 4]` 凑 6：贪心给 4+1+1=3 枚，最优是 3+3=2 枚）——**用一个 6 就能推翻一个看起来很对的算法**。 | 以为「常见货币体系里贪心是对的」就说明贪心对。它对**只是因为那些面额恰好构成 canonical 系统**；换一组面额立刻崩——这正是「贪心依赖问题结构」的最好证据。 |
| DP vs greedy 判别 | 两者的选择判据 | 能给出交换论证 → 贪心；有最优子结构但局部最优会锁死全局 → DP；两者都不行 → 搜索 + 剪枝。 | 面试里这句判据本身就是答案的一部分。 | 以为贪心是 DP 的「弱化版」。它们是不同的证明结构：DP 靠穷举子问题，贪心靠一个**结构性定理**。 |
| DTW | 动态时间规整 | 允许时间轴伸缩的序列对齐，本质是编辑距离的连续版 DP。 | 时序对齐（轨迹匹配、动作识别）的经典方法，把算法与 ML 接起来。 | 以为它是深度学习之前的老古董。**soft-DTW 至今仍作为可微损失在时序任务里使用**。 |

## 七 · 采样与随机 · Sampling & Randomization

| 术语 (EN) | 中文 | 一句话定义 | 为什么重要 | ⚠️ 常见误解 |
|---|---|---|---|---|
| reservoir sampling | 蓄水池采样 | 从**长度未知**的流中等概率抽 k 个：前 k 个直接放入，第 i 个（i>k）以 k/i 的概率替换池中随机一个。 | **ML/CV 岗高频题**，因为它就是数据管线里的真实需求：从一个不知道多大的日志/视频流里均匀抽样。Vitter 1985 是原始文献。 | 以为「概率是 k/i」很显然。**必须能证明每个元素最终被选中的概率都是 k/n**——归纳证明只有三行，但当场推得出来和背下来是两回事，面试官一定会让你推。 |
| weighted reservoir sampling | 加权蓄水池采样 | 按权重不等概抽样（A-Res：给每个元素生成 `u^(1/w)` 作为键，取最大的 k 个）。 | **直接对应长尾重采样**（呼应 C58）：稀有类别给更高权重。 | 以为加权版只是把 k/i 换成加权比例。那样做在流式场景下不成立；**A-Res 的指数键技巧才是标准答案**。 |
| Fisher-Yates shuffle | Fisher-Yates 洗牌 | 从后往前，第 i 位与 `[0, i]` 中随机一位交换；O(n)，**每种排列等概率**。也叫 Knuth shuffle。 | 数据集 shuffle、交叉验证划分、mini-batch 采样的底层实现（`random.shuffle` 就是它）。 | 以为「随便两两交换若干次」也是均匀的。**不是**——常见错误写法是 `swap(i, random(0, n-1))`，它产生 nⁿ 条等概率路径去覆盖 n! 种排列，而 **nⁿ 不能被 n! 整除（n≥3）**，所以必然有偏。本课用卡方检验在几千次重复里把这个偏差直接测出来。 |
| uniformity test | 均匀性检验 | 用卡方检验判断经验频次是否符合均匀分布。 | **这是「我怎么知道我的随机算法对」的答案**——面试里说「我会跑一个卡方检验」比说「应该没问题」强太多。 | 以为跑几次看着差不多就行。n=3 时错误洗牌的偏差约 10%，肉眼看直方图**看不出来**，必须靠检验。 |
| random pivot / randomized algorithm | 随机化算法 | 算法内部使用随机数，使**最坏情况依赖于骰子而非输入**。 | quickselect、快排、跳表的复杂度保证都来自它。 | 以为随机化让最坏情况消失。最坏情况仍在，**只是对手无法构造**——概率极低。这个区分是复杂度讨论里的高分点。 |
| sampling without replacement | 无放回采样 | 每个元素最多取一次（`random.sample`）。 | 数据划分、负样本采样的默认需求。 | 用 `random.choice` 循环 k 次来模拟，导致**重复元素**；在负采样里这会悄悄改变分布。 |
| seed & reproducibility | 随机种子与可复现 | 固定种子使随机过程可复现。 | 对拍器、单测、实验对比都依赖它；**面试里写测试时随手 `random.seed(0)` 是专业度信号**。 | 以为设了 `random.seed` 就全局可复现。**numpy、torch、Python 各有独立的随机状态**，多线程/多进程还有各自的种子——CV 训练里「设了种子还是复现不了」十有八九是漏了某一个。 |

## 八 · 面试协议与工程习惯 · Interview Protocol

| 术语 (EN) | 中文 | 一句话定义 | 为什么重要 | ⚠️ 常见误解 |
|---|---|---|---|---|
| 六步答题协议 | six-step protocol | ① 复述澄清 ② 举例走一遍 ③ 先给暴力解 ④ 说优化思路 ⑤ 再写代码 ⑥ 测试与复杂度。 | **本课的核心资产。** 45 分钟里编码只占 18 分钟；前面 13 分钟不写一行代码，恰恰是最能拉开分差的部分。 | 以为「会做的题可以跳过前面几步直接写」。**恰恰相反**：会做的题跳步最亏——你把最容易拿的沟通分白送了，而且一旦题面有隐藏条件，你会写到一半推倒重来。 |
| brute force baseline | 暴力解基线 | 先给出一个必然正确、复杂度可能很差的解法。 | 三个作用：① 证明你理解了题；② 给面试官一个**评估你优化幅度的参照系**；③ 在 notebook 里当**对拍的参照实现**。 | 以为给暴力解显得水平低。**面试官普遍把「先给暴力解」记为正面信号**；真正显得水平低的是想了五分钟一句话都说不出来。 |
| 对拍 · stress testing | 随机对拍 | 用暴力解当参照，对随机生成的大量小规模输入比对最优解的输出。 | **这是面试之外自学时唯一可靠的自证方式**（面试里没有 judge）。本课每道题都配对拍器。 | 以为对拍要用大数据。**恰恰要用小规模**（n ≤ 8）+ 大量次数（10⁴ 组），这样出错时反例小到可以肉眼调试。 |
| 边界用例 · edge cases | 边界用例 | 空 / 单元素 / 全相同 / 极值 / 重复 / 溢出六项。 | 写完代码主动跑一遍，是「测试意识」这一维的全部得分点，只花 60 秒。 | 以为面试官会替你想边界。他在等你自己说；**你不说，他就当你没考虑**。 |
| dry run · 手动走查 | 手动走查 | 拿一个具体的小例子，把代码逐行执行一遍并报出变量值。 | 协作编辑器里通常**不能运行代码**，走查是唯一的验证手段，也是展示严谨性的最佳时机。 | 以为可以在脑子里默走。**要出声走**，边走边报变量值——面试官评的正是这个过程。 |
| 复杂度断言 | complexity assertion | 写完立刻主动报出时间与空间复杂度，并说明瓶颈在哪一行。 | 不主动报就得被问，被问就丢了主动性分。 | 只报时间不报空间；或者忘了**递归栈也算空间**。 |
| 五维评分表 | five-dimension rubric | 正确性 / 复杂度 / 代码质量 / 沟通 / 测试意识。 | 前两维是门槛，**后三维是区分度**。大部分候选人只在前两维用力。 | 以为「做出来就过了」。做出来但全程沉默、变量名是 `a/b/c/tmp2`、写完不测，同样可能被判不通过。 |
| think aloud | 边想边说 | 把思考过程实时外化。 | 面试官买的是你的推理过程；**沉默超过 30 秒是明确的负面信号**。 | 以为要「想好了再说」。正确做法是**先给 10 秒的结构**（「我打算先考虑暴力解，再看能不能用哈希优化」），再展开细节。 |
| 卡住时的脱困话术 | getting unstuck | 三招：① 退回上一层（「我先说说我确定的部分」）；② 举一个更小的具体例子；③ 明说「我需要一分钟安静想一下」。 | 卡住不丢分，**卡住且沉默才丢分**。 | 以为说「我不知道」是认输。说「我不知道，但我会这样查/这样推」是诚实度加分——**诚实度是 ML 岗面试里权重很高的一维**（C64 会展开）。 |
| 接住提示 | taking hints | 面试官给提示时，先复述一遍确认理解，再说它如何改变你的思路。 | 提示不是扣分信号，**不接住才是**。 | 以为被提示就已经挂了。面试官普遍会给提示，他评的是**你被提示后走得多远**。 |
| 七个翻车点 | seven pitfalls | 一上来就写、不问边界、写完不测、复杂度说错、变量名混乱、默默改需求、沉默超过 30 秒。 | 全都不需要额外算法能力就能避免——**这是投入产出比最高的一份清单**。 | 以为「默默改需求」不算大事。它是最严重的一条：面试官会认为你在**回避你解决不了的部分**。 |
| 频率 / 定位标注 | frequency & priority tags | 每题标「高频 / 中频 / 低频」与「必会 / 加分」。 | 在有限时间里排优先级；时间不够时**先做完所有「高频 + 必会」**。 | 以为刷题网站的热度榜可以直接套用。**ML/CV 岗的分布不一样**：矩阵、区间、采样类题明显更高频，链表、字典树、复杂图论明显更低频。 |
| 可用库的边界 | allowed built-ins | 哪些内置可以直接用，哪些一用就等于绕过考点。 | 考排序题直接 `sorted`、考哈希题直接 `Counter`、考堆直接 `heapq.nlargest`，都可能被判绕过考点。 | 以为要么全用要么全不用。**正确做法是问一句**：「这题我可以直接用 `sorted` 吗，还是您希望我手写排序？」——问了就零风险，还展示了对考点的理解。 |
