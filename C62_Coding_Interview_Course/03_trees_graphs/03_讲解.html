1递归三要素：为什么你写的递归会栈溢出

面试里的递归题，扣分几乎从来不是「想不出递归关系」，而是三要素里漏了一个。把三要素当成一张必填表格，每次写递归前口述一遍，是最便宜的保险。

要素要回答的问题漏掉的后果面试官的检查方式
终止条件（base case）最小的子问题长什么样？答案是什么？无限递归 → RecursionError「空树输入会怎样？」
拆解（recurse）怎么把问题变成严格更小的同类问题？规模不减 → 死循环；或漏分支 → 漏解「你凭什么保证它一定会停？」
合并（combine）子问题的答案怎么拼成当前答案？返回值语义混乱、边界处 off-by-one「你的函数返回的到底是什么？」

其中「严格更小」是终止性的唯一保证，它对应模块 01 里讲的「严格递减的整数度量」：树递归里度量是子树高度或结点数，图递归里度量是「未访问结点数」——图 DFS 必须有 visited 集合，正是因为图有环，没有 visited 就没有递减度量。

函数的「契约」必须先写下来

递归写错最常见的根因是函数返回值的语义没定清楚。以「求二叉树直径」为例：递归函数返回的是经过该结点向下的最大深度，而答案（直径）是在遍历过程中用一个外部变量维护的——这两件事是不同的量，混在一起就会写出「直径 = 左深度 + 右深度」然后向上层返回它这种错误。

心法：写递归时先写一行注释——「本函数输入什么、返回什么、副作用是什么」。返回值和答案不是一回事：很多树形 DP 都是「返回局部量，答案挂在外部变量上」。面试里先说出这一行，面试官立刻知道你不是在瞎试。

递归的三个隐性代价

  • 栈深度。CPython 默认递归上限约 1000 层（sys.getrecursionlimit()），而一条 10 万结点的退化成链表的树会直接炸。调大 limit 不是解法——真正的 C 栈只有几 MB，调太大会变成段错误（进程直接死掉，连异常都抓不到）。唯一稳妥的解法是转迭代（第 2 节）。
  • 调用开销。Python 的函数调用比循环慢一个量级；对每帧都要跑的后处理，把递归 flood fill 换成显式栈的版本，实测能快 2–4 倍（notebook 里有实测）。
  • 重复子问题。同一个子问题被求解多次 → 指数爆炸。这正是模块 04 记忆化搜索要解决的问题；在树上一般不会发生（子树不重叠），在图与网格上必须靠 visited 来杜绝。

直白说

递归的本质是把「记住走过的路」这件事外包给了调用栈。你没有写栈，但栈一直在那里——每层的局部变量、参数、返回地址都被压着。所以「递归转迭代」不是重写算法，只是把这个隐式的栈显式地写出来，算法本身一个字都不变。

严谨说

严谨地说，任何递归都可以机械地转成「显式栈 + 状态机」的迭代形式：每个栈帧保存参数、局部变量、以及「上次执行到第几个递归调用点」（返回点编号）。尾递归（tail recursion）是特例，它的栈帧在递归调用后不再被使用，所以可以直接退化成 while 循环并复用同一个帧——但 CPython 不做尾调用优化，所以在 Python 里尾递归依然会爆栈，这与 Scheme/Scala 的行为不同，是一个常被误答的面试点。

2递归转迭代：把调用栈写出来

这是本模块最能拉开差距的一节。会写递归的人很多，能当场把递归改成显式栈、并说清「为什么后序最麻烦」的人少得多。

三种转法，难度递增

转法适用关键技巧难度
直接循环尾递归 / 单分支递归（链表、二分）把递归参数变成循环变量★
单栈 + 顺序控制前序 DFS、图 DFS、flood fill先压右后压左，因为栈是后进先出★★
栈 + 状态机后序、树形 DP、任何「子结果回来后还要做事」的递归栈里存 (结点, 阶段)，阶段编号就是「返回点」★★★
递归的三次访问时机（前/中/后序就是在这三个时刻做事） ───────────────────────────────────────────────── 进入 node │ ← ① 前序：还没看孩子就做事 ├──▶ 递归左子树 │ ← ② 中序：左边做完了，右边还没开始 ├──▶ 递归右子树 │ ← ③ 后序：两个孩子的结果都回来了 离开 node 显式栈要模拟的正是「同一个结点被经过三次」这件事： 栈元素 = (node, stage) stage ∈ {0=待展开, 1=左已完成, 2=右已完成} 前序只需 stage 0 → 单栈就够 后序需要区分 0 与 2 → 必须带 stage（或用 last_visited 标记）

为什么前序可以只用单栈？因为前序在「进入结点」时就把事做完了，结点弹出栈之后不再需要回到它——栈帧可以立刻丢弃。而后序必须等两个孩子都算完才做事，结点弹出后还得再回来一次，所以必须记录「我上次走到哪了」。这一句话就是状态机式转换的全部动机。

后序的两种写法

  1. 改前序 + 反转：按「根→右→左」做前序，结果整体反转，就得到「左→右→根」。代码最短、最好背，但它只适用于「后序只是为了得到一个访问序列」的情况；如果你需要在后序时刻使用子树的返回值（树形 DP），这个技巧无效。
  2. 栈 + stage 状态机：通用解法，可以携带子树返回值，也是把任意递归（包括模块 04 的记忆化搜索）转成迭代的标准套路。面试里先给写法 1 展示手速，再主动说「如果要做树形 DP，得改成带 stage 的版本」——这是主动展示深度的机会。
面试当场翻车点：被问「你的递归会不会栈溢出」时回答「我可以 sys.setrecursionlimit(10**6)」。这是错的——Python 的递归上限是为了保护真实的 C 栈（通常 8 MB）；调到 10⁶ 后爆的是 C 栈，表现为段错误 / 进程被杀，没有异常、没有栈回溯、日志里什么都没有。在车端这种「进程崩溃就意味着感知输出断流」的场景里，这是安全事故。正确回答是：「数据规模可能让深度到 10⁵，所以我会写成显式栈的迭代版本」。

直白说

什么时候必须转迭代？三个信号：① 深度可能到 10⁴ 以上（长链、大网格的 flood fill）；② 需要可中断（车端在帧预算耗尽时要能停下来，把栈存着下一帧继续）；③ 需要可序列化（把搜索状态存盘、跨进程迁移）。后两条在工程里比第一条更重要，却几乎从不出现在算法教材里。

严谨说

严谨地说，转迭代把控制状态从「不可见的调用栈」变成了「可见的数据结构」，于是控制流获得了数据的全部性质：可检查、可持久化、可限长、可分片。这也是为什么工业级的图搜索（大规模连通域标记、点云聚类）几乎一律写成显式栈或队列：不是因为怕溢出，而是因为需要对内存占用有硬上界——显式容器可以 reserve(capacity) 并在超限时降级，调用栈做不到。

3二叉树的四种遍历：选哪个由「信息流方向」决定

遍历不是四个要背的名字，而是四种信息流方向。题目一给出，你要在 10 秒内判断：信息是从上往下带（前序）、还是从下往上聚（后序）、还是按层同步（BFS）。判断对了，代码几乎是自动的。

遍历信息流典型题为什么是它
前序 根左右自上而下传递路径和、序列化、克隆树、带前缀的路径枚举父结点的信息（累积路径、深度）要先传给孩子
中序 左根右有序输出BST 验证 / BST 第 k 小 / BST 转有序链表BST 的中序遍历恰好是升序——这是 BST 的定义性质
后序 左右根自下而上聚合树高、直径、树形 DP、判平衡、释放资源当前结点的答案依赖两个子树的答案
层序 BFS按深度分层每层最大值、最小深度、右视图、之字形需要「同一层」这个概念，或需要最先到达即最优

层序的实现只有一个要点：进入循环时先记下 n = len(queue)，然后只处理这 n 个——这 n 个恰好是当前整层。不记 n 就无法区分层，「每层最大值」这类题就写不出来。

BST 的中序：一个被反复考的性质

「验证一棵树是不是 BST」的经典错误是只比较结点与它的两个孩子。反例：根 10、左孩子 5、左孩子的右孩子 12——局部全部合法，但 12 出现在根的左子树里，不是 BST。两个正确解法：① 中序遍历必须严格递增（只需记住「上一个访问的值」）；② 递归时向下传递 (lower, upper) 开区间约束（这是前序：信息自上而下传）。把这两个解法都说出来，并指出它们分别是中序与前序，比只写对一个更有价值。

递归里最常见的三个 bug：① 空结点没处理（if not node: return ... 忘了写，或返回值语义不对）；② 把「答案」和「返回值」混为一谈（直径题：返回深度，答案挂在外部变量）；③ 判平衡这类题写成 height(左) - height(右) 然后每层重算高度 → 退化成 $O(n^2)$，正解是后序一趟返回「高度 + 是否平衡」，$O(n)$。这三个 bug 在 notebook 里都被对拍抓了出来。

直白说

为什么树题这么爱考？因为它用最短的代码同时检验递归、边界处理和返回值设计三件事，而且几乎不需要背任何数据结构细节。对 ML/CV 岗来说，纯树题的出现频率是中等偏低的，真正高频的是它的两个亲戚：网格 BFS/DFS（第 5 节）与并查集（第 6 节）——因为那两个直接对应图像上的操作。

严谨说

严谨地说，四种遍历都是同一次深度优先搜索在三个不同时刻做事的产物（前序/中序/后序），加上一次广度优先搜索（层序）。时间复杂度一律 $O(n)$；空间复杂度是关键区别：DFS 是 $O(h)$（$h$ 为高度，退化成链时是 $O(n)$），BFS 是 $O(w)$（$w$ 为最大层宽，完全二叉树里是 $O(n/2)$）。所以「深而窄的树用 DFS、浅而宽的树用 BFS」是一条真实的工程判据，面试里被问到空间复杂度时，说出 $h$ 与 $w$ 这两个字母就够了。

4BFS vs DFS 的选择信号，以及最短路的最简形态

这一节只需要记住一句话：BFS 的第一次到达就是最优（在边权相同时），DFS 没有这个性质。所有选择信号都是这句话的推论。

题面出现这些词用理由空间
最短 / 最少步数 / 最少操作 / 最短时间BFS按距离分层扩展，首次弹出即最短$O(\text{层宽})$
所有路径 / 全部方案 / 组合 / 排列DFS + 回溯需要「进入-撤销」的对称结构$O(\text{深度})$
连通性 / 有几个岛 / 是否可达都行（DFS 代码更短）只关心可达集合，不关心距离看形状
拓扑序 / 依赖顺序 / 检测环都行（Kahn=BFS，三色=DFS）见第 7 节$O(V)$
边权不同（有代价）Dijkstra（0/1 权用 deque-BFS）分层假设被破坏，必须按累计代价出堆$O(V)$
有负权边Bellman-FordDijkstra 的「已确定不再更新」假设失效$O(V)$

BFS 最短路：三个必须说对的细节

  1. 入队时就标记 visited，不是出队时。否则同一个结点会被多次入队，队列膨胀到 $O(E)$，在网格上就是 4 倍常数；更糟的是层数统计会出错。这是 BFS 最高频的实现错误。
  2. 距离记在哪里：要么用 dist 字典/数组，要么用「按层推进」（每轮处理 len(queue) 个，层数即距离）。两种写法都对，但不要混着写——混着写会出现「有的分支算了距离，有的靠层数」的混乱。
  3. 多源 BFS：把所有源点一次性全部入队，就得到「到最近源点的距离」。这个技巧在 CV 里就是距离变换（distance transform）：「每个像素到最近前景像素的距离」——一次 BFS 搞定，不需要跑 $k$ 次单源。
Dijkstra 的骨架（面试里能写出这 8 行就够了） ────────────────────────────────────────────── dist = {s: 0}; heap = [(0, s)] while heap: d, u = heappop(heap) if d > dist.get(u, INF): continue # ← 惰性删除：过期条目直接跳过 for v, w in adj[u]: nd = d + w if nd < dist.get(v, INF): dist[v] = nd heappush(heap, (nd, v)) # 不删旧条目，靠上面那行过滤 正确性依赖：边权非负 ⇒ 首次出堆的 d 就是最终最短距离 复杂度：O((V + E) log V) （堆里最多 E 个条目） 0/1 权特例：把堆换成 deque，权 0 走 appendleft、权 1 走 append ⇒ O(V + E)
\[d(s,v)\;=\;\min_{u\in N(v)}\bigl(d(s,u)+w(u,v)\bigr)\quad\Longrightarrow\quad \text{BFS 在 } w\equiv 1 \text{ 时按 } d \text{ 单调出队}\]
为什么 Python 的堆没有 decrease-key？因为惰性删除更简单也更快：不去修改旧条目，而是允许同一个结点在堆里存多份，出堆时用 d > dist[u] 一行过滤掉过期的。面试里主动解释这一行，是「写过真代码」的强信号——很多人抄了这行却说不出它是干什么的。

直白说

对本岗位来说，纯图论题的出现频率是低的（ML/CV coding 更爱矩阵、区间、采样）。但 BFS/DFS 是例外——因为网格搜索天天用：连通域标记、flood fill、距离变换、可行驶区域的连通性检查。所以这一节的投入产出比集中在「网格 + 多源 BFS」上，Dijkstra 会写骨架就够，Bellman-Ford / SPFA 知道名字与适用条件即可。

严谨说

严谨地说，BFS 求最短路的正确性来自「队列中的距离值单调不减，且至多取两个相邻值」这条不变量；一旦边权不等，这条不变量就破了，必须换成优先队列（Dijkstra），而 Dijkstra 的正确性又依赖边权非负——因为它假设「一个结点第一次出堆时距离已最终确定」，负权边可以在之后把它改小。0/1 权是二者之间的临界情形：距离值仍然只有两个相邻取值，所以双端队列足以维持单调性，复杂度回到线性。

5网格 BFS/DFS：它就是图像的连通域标记

这一节是本模块与本岗位的第一条硬连接。「岛屿数量」这类网格题在 LeetCode 上叫做算法题，在感知代码里叫做connected component labeling（连通域标记，CCL）——同一个算法，两个名字。

网格题的说法CV 里的说法在 TSR 流水线里出现在哪
岛屿数量 / 连通块计数连通域个数分割 mask → 候选实例个数
每个岛的面积连通域面积（像素数）按面积过滤噪点（< N 像素的斑点丢掉）
岛的外接矩形bounding boxmask → bbox：分割结果转成检测框
多源 BFS 的距离场距离变换 distance transform边缘距离、骨架化、watershed 的种子
flood fill区域填充 / 漏洞填补mask 后处理：填掉标志牌内部的空洞

4 邻域还是 8 邻域？这是一个语义选择，不是实现细节

4 邻域（上下左右） 8 邻域（含对角） . X . X X X X o X X o X . X . X X X 同一张 mask，两种邻域给出不同的连通域个数： 1 0 4 邻域 → 2 个连通域（对角不相连） 0 1 8 邻域 → 1 个连通域（对角相连） 后果（真实会上线的 bug）： · 用 8 邻域：两个仅在角上接触的标志牌被合成一个 → 输出一个巨大的错框 · 用 4 邻域：一条 1 像素宽的斜向反光条被切成一串碎块 → 面积过滤把它全丢了 拓扑事实：前景用 8 邻域 ⇔ 背景必须用 4 邻域，否则「前景连通」与「背景连通」会自相矛盾 （这是数字拓扑里的连通性悖论，Rosenfeld 1970）

两种实现路线，notebook 里会对拍：① BFS/DFS 一遍法——从每个未访问的前景像素出发泛洪，代码短、常数小，但递归版在大图上会爆栈（10⁶ 像素的连通域 → 10⁶ 层递归）；② 两遍扫描 + 并查集（Hoshen–Kopelman 家族）——第一遍逐行扫描给临时标号、遇到冲突就 union，第二遍把标号替换成代表元。路线 ② 是工业界与 GPU 实现的主流，因为它访存是顺序的（对预取器友好）、可以分块并行、内存占用有确定上界——这三条正是第 2 节说的「显式化」的好处。

网格题的四个必答边界：① 空网格 / 全 0 / 全 1；② 越界检查写在入队前还是出队后（写在入队前才不会污染 visited 的统计）；③ 是否允许原地修改输入（把访问过的 1 改成 0 可以省掉 visited 数组，但面试官可能追问「输入不许改怎么办」）；④ 递归深度——一个 1000×1000 的全 1 网格，DFS 递归深度是 10⁶。主动说出第 ④ 条并改成显式栈，是这类题最直接的加分点。

直白说

怎么在面试里把网格题答成「有领域感」的样子？做完基础版之后加一句：「这其实就是连通域标记，我在做分割后处理时用过；那时候我们用的是两遍扫描 + 并查集，因为它顺序访存、能分块并行；另外 4/8 邻域的选择要看目标形状——细长斜向目标必须用 8 邻域。」一句话同时给出算法别名、工程实现选择、和一个具体的失效模式，这比多写一道题有用得多。

严谨说

严谨地说，网格是一个特殊的图：$V = HW$，每个结点度数 $\le 4$（或 8），所以 $E = O(V)$，BFS/DFS 都是 $O(HW)$，与像素数线性。它的特殊性在于「邻接关系可以由坐标直接算出，不需要存邻接表」——这让空间从 $O(V+E)$ 降到 $O(V)$，也让 GPU 实现变得可行（每个像素一个线程）。而两遍扫描法的复杂度是 $O(HW\,\alpha(HW))$，$\alpha$ 是并查集的反阿克曼函数（实际上 $\le 4$），所以它与一遍法在渐进上等价，差别全在常数与并行性上。

6并查集：路径压缩、按秩合并，以及 bbox 聚类

这一节是本模块与本岗位的第二条硬连接，也是本模块唯一「一定要能默写出来」的数据结构。理由很实际：切片推理的跨片合并、框聚类、track ID 归并、近重复图片去重——这四件事在实现层面是同一个数据结构。

class DSU:
    def __init__(self, n):
        self.parent = list(range(n))      # 初始每个元素自成一集，代表元是自己
        self.rank   = [0] * n             # 树高的上界（按秩合并用）
        self.size   = [1] * n             # 集合大小（很多题目要它）
        self.count  = n                   # 集合个数：每次成功 union 减 1

    def find(self, x):                    # 迭代版：不会爆栈
        root = x
        while self.parent[root] != root:
            root = self.parent[root]
        while self.parent[x] != root:     # 路径压缩：把这条链上所有点直接挂到 root
            self.parent[x], x = root, self.parent[x]
        return root

    def union(self, a, b):
        ra, rb = self.find(a), self.find(b)
        if ra == rb:
            return False                  # 已经同集合 —— 返回值能用来"检测环"
        if self.rank[ra] < self.rank[rb]:  # 按秩合并：矮树挂到高树下，树高不增
            ra, rb = rb, ra
        self.parent[rb] = ra
        self.size[ra] += self.size[rb]
        if self.rank[ra] == self.rank[rb]:
            self.rank[ra] += 1            # 只有等高相并，树高才 +1
        self.count -= 1
        return True

两个优化各解决什么问题，必须分开说清：按秩（或按大小）合并让树高保持 $O(\log n)$——它防止「链化」；路径压缩把访问过的路径拍平——它把摊还代价降到几乎常数。只用一个也能到 $O(\log n)$，两个一起用才有下面这个著名结论：

\[m \text{ 次操作的总代价} \;=\; O\!\left(m\,\alpha(n)\right),\qquad \alpha(n)\le 4 \text{ 对一切实际的 } n\;(<2^{65536})\]

$\alpha$ 是inverse Ackermann function（反阿克曼函数），增长极慢。面试里的标准答法：「摊还近似常数，严格说是 $O(\alpha(n))$，实际当常数用；这个界是 Tarjan 证明的，而且是紧的——不存在渐进更快的通用不相交集合结构。」

并查集不能做什么（这才是深度问题）

  • 不能删边、不能分裂集合。路径压缩是不可逆的。需要「逐步删边」的问题，标准套路是离线倒序处理：把删边序列反过来变成加边序列。面试里能说出这一招，说明你真懂它的局限。
  • 不能回答「两点间距离」。它只知道「是否同属一个集合」，不保留结构。要距离就得上 BFS 或 LCA。
  • 不能表达「非传递」的关系。这是下面那个陷阱的根源。

bbox 聚类：并查集的正确用法与它的失效模式

把 $N$ 个候选框当成结点，IoU > 阈值就连一条边，然后用并查集求连通分量——这就是「框聚类」，在切片推理的跨片合并（见 C57-04）与多相机结果融合里天天用。notebook 里会把它与「逐对比较的暴力法」对拍，并实测 $O(N^2)$ 建边的耗时。

链式合并（chaining）—— 聚类法的致命失效模式。IoU 关系不是传递的：$\mathrm{IoU}(A,B)=0.6$、$\mathrm{IoU}(B,C)=0.6$，但 $\mathrm{IoU}(A,C)$ 可能是 $0$。而连通分量求的是传递闭包，于是 $A$、$B$、$C$ 被并成一个簇——在密集排列的一排限速牌上，这会把整排牌合成一个横跨半张图的巨大框。这正是 NMS 与「连通分量聚类」的本质区别：NMS 是贪心地选代表并抑制邻居（不传递），聚类是求连通分量（传递）。两者在稀疏场景下结果几乎一样，在密集场景下差别巨大。第 8 节会用图论语言把这件事说清楚。

直白说

什么时候该用并查集而不是 NMS？当你要「合并」而不是「筛选」时。跨片合并要的是把同一个目标的多个碎片拼成一个（union 后取外接框或加权平均），NMS 要的是从一堆重复框里挑一个。用错的症状很典型：该合并时用了 NMS → 跨边界的目标被截断成半个；该筛选时用了聚类 → 密集目标被连成一片。

严谨说

严谨地说，两者对应图上的两个不同问题：并查集聚类求连通分量（等价关系的商集，$O(N^2)$ 建边 + $O(N^2\alpha)$ 合并）；NMS 求按权重贪心的极大独立集（见第 8 节）。缓解 chaining 的三条工程手段：① 提高连边阈值并额外要求类别一致；② 用更严格的连边条件（如 IoU 且中心距 < 阈值 且尺度比在范围内）；③ 只在切片边界带内允许合并（跨片合并的标准做法）——把「传递性」限制在物理上确实可能是同一目标的区域内。

7拓扑排序与环检测：从依赖调度到计算图

拓扑排序的题面几乎总是伪装成别的东西：课程表、编译顺序、任务依赖、算子融合的合法顺序、数据流水线的执行计划。识别信号只有一个：「A 必须在 B 之前」这种成对约束。

写法机理副产物适合
Kahn（BFS 式）反复取出入度为 0 的结点，删掉它的出边输出的结点数 < V 就说明有环；天然支持「分层」（同层可并行）工程首选
DFS 后序反转DFS 完成时间的逆序就是拓扑序三色标记可精确定位环上的边证明题、找环
三色标记法（DFS 环检测）—— 面试里被问"怎么找到环"时的标准答案 ──────────────────────────────────────────────────────────── 白 WHITE = 0 尚未访问 灰 GRAY = 1 正在递归栈上（本次 DFS 的祖先链上） 黑 BLACK = 2 子树已全部完成 dfs(u): color[u] = GRAY for v in adj[u]: if color[v] == GRAY: ⇒ 发现 back edge，(u,v) 在环上 ★ if color[v] == WHITE: dfs(v) color[u] = BLACK 关键点：只有"指向灰色结点"才是环。 指向黑色结点只是 DAG 里的重复汇聚（forward / cross edge），不是环。 ── 这一条是最高频的错误来源：用一个 visited 集合是判不出环的。

Kahn 的分层副产物在工程上比拓扑序本身更有用：同一层的任务之间没有依赖，可以并行执行；层数就是关键路径长度，即在无限并行度下的最短完成时间。这直接对应 C63-04 的延迟预算分解：把感知流水线画成 DAG，关键路径决定了端到端延迟的下界，优化非关键路径上的算子是白费力气。

在本岗位上，拓扑序出现在哪

  • 训练/评测流水线的依赖调度：数据下载 → 解码 → 增强 → 训练 → 导出 → 量化 → 评测。环 = 配置写错了（比如「评测依赖导出、导出又依赖评测报告」），要在启动前就检出并指出环上的边。
  • 计算图的算子融合与执行顺序：TensorRT / 编译器做融合时必须保持拓扑序合法（见 C60）。
  • DAG 上的最长路 = 关键路径：按拓扑序做一遍 DP 就能求，$O(V+E)$。这是「DAG 上一切 DP 都按拓扑序推」的最简例子，与模块 04 的遍历顺序是同一件事。
一句话记住：拓扑排序 = 在 DAG 上找一个合法的线性执行顺序；它存在 ⟺ 图无环。所以「拓扑排序」与「环检测」是同一个算法的两种问法——Kahn 跑完数一下输出了几个结点，就同时回答了两个问题。

8图视角下的 NMS：极大独立集与贪心近似

这一节把前面所有东西收束到一个观点上，也是本模块最值得在面试里主动抛出的一段。它不需要你写代码，只需要 60 秒把话说清楚。（NMS 的手撕实现在 C61-05，这里不重复。）

建模：把 NMS 写成图问题

给定 $N$ 个候选框，每个框 $i$ 有分数 $s_i$。构造冲突图 $G=(V,E)$：$V$ 是全部候选框，$(i,j)\in E$ 当且仅当 $\mathrm{IoU}(i,j) > \tau$（「这两个框互相冲突」）。那么：

  • NMS 的输出集合 $S$ 满足：任意两个被保留的框之间没有边——$S$ 是 $G$ 的一个 independent set（独立集）。
  • 而且 $S$ 是极大的（maximal）：任何被抑制的框都至少与 $S$ 中某个框冲突，所以往 $S$ 里再加任何一个框都会破坏独立性。
  • 我们真正想要的是最大权独立集（maximum weight independent set, MWIS）——在保证两两不冲突的前提下让保留框的总分最高。
\[\max_{S\subseteq V}\;\sum_{i\in S}s_i \quad\text{s.t.}\quad \forall\,i,j\in S:\;(i,j)\notin E\]

关键结论：一般图上的 MWIS 是 NP-hard 的（而且在最坏情况下连好的近似都难）。所以贪心 NMS——按分数降序扫描、能加就加——正是 MWIS 的标准贪心近似算法。这一句话同时解释了三件事：

  1. 为什么 NMS 是贪心的、为什么它不最优：它是 NP-hard 问题的启发式。
  2. 为什么它「先排序」不可省：贪心的近似质量完全依赖那个全序（分数并列时 tie-break 不同 → 输出不同，见模块 02 的确定性讨论）。
  3. 贪心的近似比是有保证的：按权降序的贪心至少能拿到 $\mathrm{OPT}/(\Delta+1)$，其中 $\Delta$ 是冲突图的最大度。$\Delta$ 小（稀疏场景）时贪心几乎最优；$\Delta$ 大（密集场景）时才可能明显次优——这恰好解释了「NMS 在密集小目标场景里表现变差」这个经验现象。

一维特例：可以精确解

如果冲突关系来自一维区间的重叠（比如只看 $x$ 轴投影、或时序上的片段），冲突图是interval graph（区间图），而区间图上的最大权独立集可以用 DP 在 $O(n\log n)$ 内精确求解——这正是「加权区间调度」。模块 04 会把它写出来，并与贪心 NMS 对比，量化贪心到底次优多少。面试里能说出「二维一般图是 NP-hard，但一维区间图有多项式精确解」，是很强的信号：说明你知道难度来自哪里，而不是背下了「NMS 是贪心」这句话。

9研究前沿与开放问题

图算法是教科书里最成熟的一块，但它与视觉系统的接缝处仍有活跃问题——这些内容不会出现在一面的编程题里，却是「你平时关注什么」这类问题的好素材。

  • 并查集的并行化仍然没有完美答案。路径压缩本质是「写共享内存」，并发下要用无锁 CAS，而 GPU 上的连通域标记（block-based union-find、label equivalence）是一个持续被刷新的工程赛道。本质矛盾：并查集的高效来自「破坏结构以换取摊还」，而并行化要求「结构可预测」。
  • 动态图连通性（decremental / fully dynamic）是真难题。只加边有并查集，只删边或又加又删就需要复杂得多的结构（Holm–de Lichtenberg–Thorup 等），常数大到实践中常常干脆重算。这是「离线倒序处理」这个技巧在工业界如此常见的原因。
  • 把 NMS 做成可学习、可微的模块。Learning NMS（Hosang 2017）用网络学成对关系；无 NMS 检测器（DETR 的一对一匹配、YOLOv10 的一致双分配，见 C53/C54）则是从根上绕开这个 NP-hard 问题——把「推理期去重」变成「训练期就不产生重复」。这个视角转换是近五年检测领域最重要的思想之一，值得在面试里主动提。
  • GPU 上的 BFS 有本质的负载不均衡问题。层宽在图上剧烈变化，导致线程空转；frontier 压缩、方向优化（direction-optimizing BFS：稠密层改成自底向上）是标准手段。网格图相对规则，所以 CV 里的 flood fill 反而比一般图 BFS 好并行。
  • 图神经网络与经典图算法的关系正在被重新理解。「algorithmic alignment」这条线在研究 GNN 能否学会 BFS / Bellman-Ford 这类算法；结论倾向于：结构对齐的模型才泛化。对面试的启示：当被问「为什么不用学习方法替代 NMS」，可以答「因为经典算法在这个问题上的结构先验极强，学习方法要赢必须先对齐这个结构」。
  • LLM 时代这类题还考不考？题目本身在贬值，但「说清一个图算法的不变量与失效模式」在升值。本模块的两组对拍（递归 vs 迭代、并查集聚类 vs 逐对比较）训练的正是这种能力。

★ 必读：CLRS Introduction to Algorithms 第 19 章（Data Structures for Disjoint Sets）——只读 19.3 与 19.4，路径压缩 + 按秩合并的 $O(m\,\alpha(n))$ 证明。★ Tarjan & van Leeuwen, Worst-case Analysis of Set Union Algorithms（JACM 1984）——各种压缩/合并组合的紧界，知道结论即可。★ Hosang, Benenson, Schiele, Learning Non-Maximum Suppression（CVPR 2017）——把 NMS 当成一个可学习的关系推理问题，读引言与问题建模那两节就能拿到本模块第 8 节的全部视角。
