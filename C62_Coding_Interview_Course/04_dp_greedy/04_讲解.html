1DP 五步：面试里唯一需要的模板

先说结论：面试里 DP 题的翻车，绝大多数不是死在转移方程上，而是死在第一句话——你怎么定义 dp[i]。状态定义是这道题的「坐标系」，坐标系选歪了，后面的转移、初始化、遍历顺序、答案位置会一起歪，而且症状极具迷惑性：代码跑得通、小样例过、大样例错，你会花十分钟去 debug 转移方程，但根因在第一行。

所以本课只教一个模板，叫 DP 五步。它不是记忆术，它是你在白板前必须说出口的五句话——把这五句话说完，面试官已经能给你打分了，代码只是把它们翻译成 Python。

① 状态定义 dp[i] / dp[i][j] 的含义是什么？（一句完整的中文，必须含「以…结尾」或「前 i 个」这类限定词） │ └─ 检验：这句话能不能唯一确定一个数？如果不能，状态就没定义完 ▼ ② 转移方程 dp[i] 由哪些更小的状态决定？决策是什么？ │ └─ 检验：转移里出现的每一项，都必须在①里被定义过 ▼ ③ 初始化 哪些状态无法由转移得到？它们的值是多少？（含「不可达」用 -inf / +inf 还是 0） │ └─ 检验：dp[0] 的语义要和①一致，不能为了凑答案硬填 ▼ ④ 遍历顺序 计算 dp[i] 时它依赖的状态必须已经算好 │ └─ 检验：把依赖画成箭头，遍历方向必须与箭头同向 ▼ ⑤ 答案位置 答案是 dp[n]？还是 max(dp)？还是 dp[n][m]？ └─ 检验：把①的那句话代入，看它是不是题目要的东西
步骤白板上要说的话写错时的典型症状自检方法
① 状态定义「我定义 dp[i] 为以第 i 个元素结尾的最大子数组和」转移写不出来、需要额外变量才能转移、答案取不出来能不能只看这句话就写出转移？不能就是没定义完
② 转移方程「第 i 个要么接在前面后面，要么自己另起——dp[i]=max(dp[i-1]+a[i], a[i])」转移里用到了未定义的量；漏掉某个决策分支枚举「最后一步的所有可能决策」，每个决策一个分支
③ 初始化「dp[0]=a[0]，因为以第 0 个结尾只能是它自己」越界；把不可达状态填成 0 导致被误选为最优不可达用 -inf（求 max）或 +inf（求 min），不要填 0
④ 遍历顺序「i 从小到大，因为 dp[i] 依赖 dp[i-1]」结果永远等于初始值；或空间压缩后答案变成了另一道题的答案画依赖箭头；压缩后重点检查是否读到了「本轮已被覆盖」的值
⑤ 答案位置「答案是 max(dp)，不是 dp[n-1]，因为最大子数组可以在任意位置结束」所有中间值都对，最后一步取错——最隐蔽的一类错把①的那句话原样代入题目问句，读一遍是否通顺

「状态定义错了后面全错」的诊断法

这里给一个可当场演示的例子。打家劫舍（相邻两间不能同时偷，求最大值）有两种合法的状态定义：

\[\text{A: } dp_i=\text{前 }i\text{ 间房能偷到的最大值}\;\Rightarrow\; dp_i=\max(dp_{i-1},\ dp_{i-2}+a_i),\quad \text{答案}=dp_n\]
\[\text{B: } f_i=\textbf{必须偷第 }i\textbf{ 间}\text{时的最大值}\;\Rightarrow\; f_i=a_i+\max_{j\le i-2} f_j,\quad \text{答案}=\max_i f_i\]

两个都对。但如果你嘴上说的是 A、心里想的是 B，或者用了 B 的转移却取 A 的答案位置（f_n），就会得到一个「大部分用例都对、少数用例错」的程序——因为最优解恰好在最后一间房结束的概率相当高。notebook 里会把这两个版本都实现，并造出让错误版本翻车的用例。

直白说

诊断法很朴素：拿到一个错误答案时，不要先改转移方程，先把你的状态定义那句话念出来，然后手算 dp[1] 和 dp[2]，看程序算出来的是不是那个数。如果 dp[2] 就已经不符合你的定义，问题在①或③；如果 dp 数组全对但答案错，问题在⑤。这个二分法能在 30 秒内把 bug 锁死在五步中的一步——而在面试里，「能说清楚 bug 在哪一层」比「一次写对」得分更高。

严谨说

更严谨地说：DP 的正确性依赖最优子结构（optimal substructure）与无后效性（一旦 $dp_i$ 确定，后续决策只依赖 $dp_i$ 的值而不依赖它是怎么取到的）。状态定义的本质是选一个足以屏蔽历史的充分统计量。打家劫舍里，「前 $i$ 间的最大值」不足以判断第 $i+1$ 间能不能偷（因为不知道第 $i$ 间偷没偷），所以 A 的转移必须回看两步；而 B 的状态天然携带了「第 $i$ 间偷了」这条信息，代价是答案要在整个数组上取 max。两种定义的差别，就是把「第 i 间偷没偷」这一位信息放进状态里还是放进转移里。

一句心法：状态定义是一句中文，不是一个数组。数组只是这句中文的存储。面试里先把这句中文说给面试官听，他点头你再动手。

先说定义，再写数组

最常见的面试翻车姿势：一上来就写 dp = [0]*n。面试官看到这一行会立刻问「dp[i] 是什么意思？」，而如果你答不上来或者答得含糊（「就是到 i 为止的结果」——什么结果？），这道题的沟通分就没了，即使你后面把代码写对，评价也会是「像是背过这道题」。反过来，先说清定义再写代码，哪怕最后没写完，面试官也能判定你会做。

2五类模板与遍历顺序的约束

ML/CV 岗的 DP 题不会考区间 DP 的奇技淫巧，考的是下面五类里的前三类。把它们的识别信号背下来，比背题解重要——面试的第一分钟你要做的是把这道题归类。

类别状态形状识别信号代表题面试频率
一维序列 DPdp[i]答案与「前 i 个」或「以 i 结尾」有关；决策只看最近 1–2 个最大子数组和、打家劫舍、跳跃游戏、LIS高频
双序列 / 网格 DPdp[i][j]两个序列对齐，或二维网格上从左上走到右下编辑距离、LCS、最小路径和、不同路径高频
背包 DPdp[i][c] → dp[c]有「容量/预算」这个第二维；物品选或不选01 背包、分割等和子集、零钱兑换、目标和高频
状态机 DPdp[i][s]，s 是有限状态存在「持有/不持有」「冷冻期」「已用几次机会」这类离散状态买卖股票含冷冻期/手续费/至多 k 次中频
区间 DPdp[i][j]，i≤j答案由「合并两个相邻子区间」构成；枚举分割点戳气球、最长回文子序列、矩阵链乘低频（但能答出来是加分项）

遍历顺序不是风格问题，是正确性问题

遍历顺序的唯一规则是：计算 dp[x] 时，它依赖的所有状态必须已经是本轮的最终值。在二维数组上这条规则很宽松（几乎怎么写都对），一旦做空间压缩（滚动数组）就会变得极其苛刻——因为压缩后「上一行」和「本行」共用同一块内存，遍历方向直接决定你读到的是旧值还是新值。

二维原始形态 一维压缩后（同一块内存 dp[c]） dp[i][c] = max( dp[i-1][c], 倒序 c: C→0 正序 c: 0→C dp[i-1][c-w] + v ) 读 dp[c-w] 读 dp[c-w] ▲上一行 ▲上一行左侧 此时它还是 此时它已被 「上一行」的值 本轮覆盖过 dp[i][c] = max( dp[i-1][c], dp[i][c-w] + v ) ⇒ 每件物品最多取 1 件 ⇒ 同一件物品可重复取 ▲上一行 ▲本行左侧 = **01 背包** = **完全背包** 结论：同一份代码，只把 for c 的方向反过来，解的就是另一道题。

直白说

记不住方向怎么办？现场推一遍就行，只要 10 秒：「我需要的 dp[c-w] 是没考虑当前物品的值，还是已经考虑过当前物品的值？」01 背包要前者（每件只能拿一次，所以左边那个状态里不能已经拿过它）→ 必须让 dp[c-w] 保持旧值 → 倒序。完全背包要后者（可以再拿一件）→ 需要 dp[c-w] 已经更新 → 正序。把这段话说出来，比写对代码更能证明你懂。

严谨说

形式化地说，一维压缩把二维递推 $dp^{(i)}[c]=F(dp^{(i-1)}[\cdot],\,dp^{(i)}[\cdot])$ 就地实现，此时数组在时刻 $t$ 的内容是「已更新前缀 + 未更新后缀」的混合。倒序遍历保证 $c-wdp[c-w] 严格等于 $dp^{(i-1)}[c-w]$；正序遍历则保证它等于 $dp^{(i)}[c-w]$。空间压缩的代价是：你失去了「回溯出具体选了哪些物品」的能力（因为中间层被覆盖了）。面试里若追问「那我要输出方案怎么办」，标准答案是：保留二维表，或者记录 $O(nC)$ 的决策位图，或者用分治法（Hirschberg）以 $O(\min(n,m))$ 空间换 2 倍时间——最后一条是编辑距离在长序列上的真实工程做法。

空间压缩是面试里的加分项，不是必答项。正确的顺序是：先写清楚的二维版本并测通过，然后说「这里可以压成一维，因为每行只依赖上一行；01 背包要倒序遍历容量，否则会变成完全背包」——说出来即可得分，不一定要真的改写。反过来，一上来就写一维压缩版然后写错方向，是纯粹的失分。

3双序列 DP：编辑距离、LCS，以及它们在评测里的样子

双序列 DP 是 ML 岗最值得优先掌握的一类，原因很实际：你在评测代码里天天用它，只是没意识到。OCR / 车牌识别 / 标志文字识别的 CER（character error rate）与语音的 WER，定义就是「编辑距离 ÷ 参考长度」；时序对齐用的 DTW（dynamic time warping）是同一个递推换了代价函数；而多目标跟踪里把预测轨迹和真值轨迹对齐算 IDF1 时，序列匹配的骨架也是这个。

\[D[i][j]=\begin{cases} \max(i,j) & \min(i,j)=0\\[2pt] \min\bigl(\,D[i-1][j]+1,\;\; D[i][j-1]+1,\;\; D[i-1][j-1]+\mathbb{1}[a_i\ne b_j]\,\bigr) & \text{otherwise}\end{cases}\]

三项分别对应删除 / 插入 / 替换（或匹配）。把这三个词说出来，就等于把转移方程讲清楚了。五步走一遍：①D[i][j] = 把 a 的前 i 个字符变成 b 的前 j 个字符的最少操作数；②见上式；③D[i][0]=i, D[0][j]=j（全删 / 全插）；④ i、j 都从小到大（依赖左、上、左上）；⑤答案是 D[n][m]。

变体改哪一项得到什么在 ML 里的用途
LCS去掉替换分支，匹配时 +1 求 max最长公共子序列diff 工具；序列标注的一致性度量
CER / WER代价全为 1，最后除以参考长度错误率OCR / 标志文字识别的标准指标
加权编辑距离替换代价按混淆概率给（如 0↔O 便宜）领域敏感的距离车牌识别的容错评测
DTW代价换成 $|x_i-y_j|$，允许重复对齐（不删不插）时序弯曲距离轨迹相似度、时序对齐、动作匹配
最长公共子串不匹配时直接置 0，答案取全表 max连续公共段近重复检测的一个廉价特征

直白说

为什么这几道题「长得那么像」？因为它们问的都是同一个问题：把两个序列的元素两两配对，配对必须保持顺序不交叉，求最优配对。编辑距离允许「配不上就删/插并付代价」，LCS 只数「配上了几对」，DTW 允许「一对多」。识别信号很好记：只要题目里出现两个序列且要求保序，就画二维表。

严谨说

更精确地说，这类问题的解空间是两个序列索引的单调对齐路径：从 $(0,0)$ 走到 $(n,m)$，每步只能向右、向下或右下。不同的题只是给三种走法配了不同的代价。因此它们共享同一套性质：时间 $O(nm)$、空间可压到 $O(\min(n,m))$、路径可回溯出对齐方案。面试里被追问「能不能更快」时，标准答案是：一般情况下 $O(nm)$ 在细粒度归约下是紧的（SETH 条件下无法做到 $O((nm)^{1-\epsilon})$），但如果只需要判断编辑距离是否 $\le k$，可以只算主对角线附近的带状区域，降到 $O(nk)$——后者正是真实 CER 计算库的优化，也是这道题最好的加分点。

把编辑距离的三个分支翻译成人话：「我把 a 的最后一个字扔了（删）／「我在结果末尾补一个字」（插）／「这两个字对上了，对不上就改一下」（替换）。面试里边写边说这三句，比念公式有效得多。

4背包：从「选或不选」到「算力预算下的方案选择」

背包是唯一一类能直接对应你日常工作的 DP 题：给定一个预算（显存 / 延迟 / 标注人天 / 带宽），从一堆候选方案里挑一个组合使收益最大。C57 模块 05 排「小目标方案优先级」、C58 模块 04 分「标注预算」、C63 模块 04 做「容量估算」，本质都是背包。

\[\text{01 背包：}\;dp[i][c]=\max\bigl(dp[i-1][c],\;\; dp[i-1][c-w_i]+v_i\bigr),\qquad dp[0][c]=0\]
变体每件物品一维遍历方向初始化（求最大价值）初始化（求恰好装满）
01 背包最多取 1 件容量倒序 C→wdp[*]=0dp[0]=0，其余 -inf
完全背包可取无限件容量正序 w→Cdp[*]=0dp[0]=0，其余 -inf
多重背包最多取 k 件二进制拆分成 01 背包同上同上
分组背包每组至多选 1 件外层组、内层容量倒序、最内层组内物品同上同上
零钱兑换（最少硬币）可取无限件正序—dp[0]=0，其余 +inf

「恰好装满」那一列是高频追问点。如果初始化时把所有 dp[c] 都填 0，就等价于宣称「容量 c 存在一个价值 0 的合法方案」，于是那些其实凑不出来的容量会被当成可行解参与 max，结果偏大且无法察觉。求最少个数时同理，不可达必须是 +inf。这就是第 1 节说的「不可达状态不要填 0」。

直白说

背包在工程里最常见的伪装是：「延迟预算 33 ms，感知分到 12 ms，这 12 ms 里我要塞检测 + 跟踪 + 分类，各有几档配置，怎么配 AP 最高？」如果每个模块必须选且只能选一档，那是分组背包；如果某些模块可选可不选，那是 01 背包；如果预算是连续的（毫秒），就先量化成整数网格（比如 0.1 ms 一格）再跑 DP。能在系统设计面试里把「配置选择」一句话归约到背包，是很强的信号。

严谨说

但要诚实地说清背包解法的三个前提，否则会被追问打穿：① 价值可加——各模块的 AP 增益必须近似独立，实际上检测器换了，跟踪器的收益也会变，存在交互项；② 代价可加——延迟必须能线性相加，但存在显存带宽争抢、kernel launch 开销、流水线重叠，实测常常不等于求和；③ 容量是整数且不大——伪多项式复杂度 $O(nC)$，$C$ 太大（比如按微秒离散）就退化。0-1 背包是 NP-hard 的（判定版本是 NP-完全），$O(nC)$ 里的 $C$ 是数值而不是输入长度，这就是「伪多项式」的含义——面试官问「背包不是有多项式算法吗，怎么会 NP-hard」时，答的就是这一句。

面试里的经典陷阱：分割等和子集。「能否把数组分成两个和相等的子集」看起来是搜索题，实际是容量为 sum/2 的 01 背包可行性问题（dp[c] 为布尔）。识别信号：出现「恰好 / 是否存在 / 目标和」且元素只能用一次。先判 sum 是否为奇数——奇数直接返回 False，这个 1 行的剪枝面试官一定在等你写。

5记忆化搜索与递推的互转：先写能跑的那一版

在 45 分钟的面试里，记忆化搜索（top-down）通常是更安全的选择，因为它把「遍历顺序」这一步免掉了——递归天然按依赖顺序求值。代价是常数更大、有栈深度风险。这里给出两者的机械互转法，以及一条实用建议：先写记忆化把逻辑跑通，再当着面试官的面说「这可以改写成自底向上的递推，遍历顺序是 …」。

Python 里记忆化只要一行装饰器：from functools import lru_cache + @lru_cache(maxsize=None)（3.9+ 可用 @cache）。但要注意两条：参数必须可哈希（list 要转 tuple）；递归深度默认 1000，链式依赖的题（如 n=10⁴ 的 LIS）会 RecursionError。面试里主动说「我这里用 lru_cache，但如果 n 到 10⁵ 我会改成递推避免爆栈」——这是免费的分。

区间 DP：唯一需要「按区间长度遍历」的一类

区间 DP 的状态是 dp[i][j]（区间 [i,j] 的最优值），转移要枚举分割点 k，依赖的是更短的区间。所以遍历顺序不是「i 从小到大」，而是「长度从小到大」：for L in range(2, n+1): for i in range(n-L+1): j = i+L-1。这是「遍历顺序必须与依赖方向同向」这条规则最典型的体现——如果你写记忆化，这一步根本不用想。

面试策略：记忆化搜索是你的安全网。任何 DP 题，只要你能写出正确的暴力递归，加一个 cache 就是一个正确的 DP。所以卡住时的标准脱困路径是：「我先写一个暴力递归确保语义正确，然后加记忆化，最后如果还有时间我把它改成递推并压缩空间。」——这句话本身就展示了完整的解题方法论。

6贪心：正确性论证与那个「看起来对但错」的反例

贪心的难点从来不是写代码（通常 5 行），而是证明它对。面试里贪心题的评分点几乎全部在这里：面试官想听的不是「我按结束时间排序」，而是「为什么按结束时间排序一定不会更差」。

交换论证：一个可以背下来的证明模板

交换论证（exchange argument）的骨架只有四句话，任何贪心题都能套：

  1. 设 G 是贪心解，O 是任意一个最优解，且 O 与 G 在第 k 步第一次不同（前 k−1 步相同）。
  2. 把 O 的第 k 步换成 G 的第 k 步，得到 O′。
  3. 证明 O′ 仍然合法（不违反约束）且不比 O 差（目标值不下降）。
  4. 于是可以反复交换把 O 变成 G 而目标值不下降 ⇒ G 也是最优解。归纳完成。

以区间调度（给一堆区间，选最多个互不重叠的）为例，贪心是「按结束时间从早到晚选」。套模板：

\[\text{设 } g_k=[s,e),\; o_k=[s',e') \text{ 且 } g_k\ne o_k.\;\text{贪心选最早结束} \Rightarrow e\le e'.\]

因为 O 的第 k+1 个区间的起点 $\ge e' \ge e$，把 $o_k$ 换成 $g_k$ 后与后续区间仍不冲突，个数不变 ⇒ O′ 合法且同样最优。这个「$e\le e'$ 所以换了之后后面只会更宽松」就是整个证明的核心，面试里说这一句就够了。

一个「看起来对但错」的反例：找零

现在换一道几乎一模一样的题：给定硬币面值，用最少的硬币凑出金额 amount。自然的贪心是「每次拿能拿的最大面值」。在人民币面值 [1,5,10,20,50,100] 上它是对的，在 [1,25,10,5]（美分）上也是对的——所以你会误以为它总是对的。但：

面值集合目标贪心的解最优解结论
[1, 3, 4]64 + 1 + 1 = 3 枚3 + 3 = 2 枚贪心错
[1, 15, 25]3025 + 1×5 = 6 枚15 + 15 = 2 枚贪心错得离谱
[1, 5, 10, 25]任意同最优同最优对（该面值系是 canonical 的）
[1, 3, 4]54 + 1 = 2 枚4 + 1 = 2 枚小用例上巧合正确 ← 陷阱

注意最后一行。如果你在面试里只手测了 amount=5，贪心会通过，你会自信地说「这题贪心就行」，然后面试官给你 amount=6。这正是「看起来对但错」的杀伤方式：反例往往不在最小的用例里。

直白说

为什么区间调度能贪心而找零不能？直觉上：区间调度里「早结束」这个局部优势是单调传递的——早结束的区间给后面留下的空间严格更大，永远不亏；而找零里「拿大面值」这个局部优势会破坏余额的结构——拿了 4 之后剩下 2，而 2 只能用两个 1 凑，你在第一步换来的收益（少拿一枚）被第二步的损失（多拿两枚）盖过了。判别口诀：局部最优能不能「用一个不等式传递到下一步」？能就可能贪心，不能就上 DP。

严谨说

严格的判据是拟阵（matroid）与贪心选择性质 + 最优子结构：若可行解族构成拟阵（满足遗传性与交换性质），按权重贪心必然最优（Rado–Edmonds 定理）；区间调度虽不是拟阵但满足更弱的交换论证条件。找零问题的可行解族不满足交换性质：把最优解 $\{3,3\}$ 里的一枚换成贪心的 $4$，得到 $\{4,3\}$ 面值和是 7 而不是 6，交换后不合法，第 3 步就断了——这恰恰说明「交换论证走不通」本身就是「贪心不对」的强烈信号。面试里如果交换论证卡在第 3 步，不要硬凑，直接改用 DP，并说明「我尝试了交换论证但换完不合法，说明贪心选择性质不成立」——这是极高质量的回答。

面试里最危险的贪心句式是「我觉得贪心应该可以」。面试官听到「我觉得」就会开始找反例，而你没有准备。正确的说法有两种：①「我可以用交换论证证明：假设最优解与贪心解第一次不同于第 k 步…」——给出证明；②「我怀疑贪心不对，让我花半分钟找个反例……面值 [1,3,4] 凑 6，贪心 3 枚而最优 2 枚，所以要用 DP」——给出反例。两条路都得分，只有「我觉得」不得分。

7亮点实验：把 NMS 建模成加权区间调度，量化贪心的次优

这一节是本模块存在的理由。你每天用的 NMS 就是一个贪心算法，而且是一个可以被证明次优的贪心算法——把它和加权区间调度对照着看，你会同时理解两件事：这道算法题在考什么，以及你的检测器为什么会把两块相邻的限速牌合并成一个框。

归约：一维场景下 NMS = 加权区间调度

考虑一个简化但真实的场景：龙门架上并排挂着几块标志，检测框在 x 轴上排成一列（y 方向差异可忽略）。把每个检测框看成一个区间 $[s_i, e_i)$，score 看成权重 $w_i$。把 NMS 的 IoU 阈值取 0（任何重叠都算冲突），于是：

NMS（贪心） 加权区间调度（DP） ───────────────────────────── ───────────────────────────── 输入 : 框 + 分数 输入 : 区间 + 权重 约束 : 保留的框两两不重叠 约束 : 选中的区间两两不重叠 目标 : （隐含）留下"对的那些框" 目标 : 总权重最大 算法 : 按分数降序，能留就留 算法 : 按结束时间排序 + DP p(j) = 最大的 i<j 使 e_i <= s_j 复杂度: O(n log n + nK) 复杂度: O(n log n) 最优性: **无保证** 最优性: **精确最优** A ████████████████████ w=10 贪心先拿 A（分数最高）→ B、C 被抑制 → 总分 10 B █████ w=6 DP 选 B + C（互不重叠） → 总分 12 C ██████ w=6 ───────────────────────► x **贪心 / 最优 = 10/12 = 0.833**
\[\mathrm{OPT}(j)=\max\bigl(\underbrace{\mathrm{OPT}(j-1)}_{\text{不选第 }j\text{ 个}},\;\; \underbrace{w_j+\mathrm{OPT}(p(j))}_{\text{选第 }j\text{ 个}}\bigr),\qquad \mathrm{OPT}(0)=0\]

上面那个 A/B/C 的例子不是玩具——它就是「一个覆盖两块牌子的大框，分数略高于两个正确的小框」这一真实失效模式。贪心 NMS 一定会保留大框并杀掉两个正确框，最终 recall 掉一半；而 DP 会保留两个小框。notebook 里会把这个场景合成出来，并同时报告两个指标：总分与真正找回了几块牌子。

贪心到底能差多少？答案是：可以任意差

构造一族反例：一个长框覆盖 $k$ 块牌子、权重 $1+\epsilon$；$k$ 个正确的小框各权重 1。贪心拿长框得 $1+\epsilon$，最优拿 $k$ 个小框得 $k$，比值 $\frac{1+\epsilon}{k}\to 0$。所以「贪心 NMS 的近似比」没有常数下界——它不是「差一点点」，是「原则上可以差任意多」。在随机场景上它通常很接近最优（notebook 实测均值 > 0.97），但最坏情况恰好发生在密集排列的标志上，而那正是 TSR 最在意的场景。

直白说

那为什么工业界不换成 DP？三个理由，缺一不可，这也是这道题在面试里最好的收尾：① 二维不成立——一维区间的「不重叠」关系有良好结构（区间图），MWIS 可 DP 求解；二维 bbox 的冲突图是任意图，最大权独立集是 NP-hard，DP 没了。② 目标函数是假的——「总分最大」只是代理目标，真正想要的是「每个真实目标恰好留一个框」，分数高不等于框对。③ 延迟——NMS 已经是延迟的方差来源（见 C53-04），换成更重的算法只会更糟。

严谨说

但这个分析指出了改进方向，而这正是真实工作的样子：既然贪心的失效模式是「高分框独吞一片区域」，那么补救手段就都围绕「别让它一票否决」展开——Soft-NMS 不删框而是按重叠度衰减分数（把硬约束软化）；Cluster-NMS / Matrix-NMS 把抑制关系矩阵化并迭代，逼近全局解且可并行；WBF（weighted boxes fusion）把一簇框加权融合而不是择一（见 C56-04）；而 DETR 系与 YOLOv10 的一对一标签分配则是从根上取消这个组合优化问题——训练期就保证每个目标只有一个正样本，推理期无需去重（见 C53-04、C54）。「贪心的次优性 → 三条改进路线」这条链路，是把算法题和检测岗位真正连起来的地方。

一句话把两件事焊死：NMS 是「最大权独立集」的贪心近似，一维时最优解可以用加权区间调度 DP 精确求出，二维时问题变成 NP-hard 所以只能贪心。面试里被问「NMS 的本质是什么」，这就是满分答案（并可引 C62 模块 03 的图论表述）。

别把这个结论说过头。不要说「NMS 是错的，应该用 DP」——面试官会立刻反问二维复杂度和延迟，你会答不上来。正确的表述是：「NMS 是一个贪心近似，它的失效模式可以被精确刻画（高分框独吞区域），在一维退化情形下我可以用 DP 求出最优解并量化这个 gap；工程上的解法不是换成 DP，而是 Soft-NMS / WBF / 一对一分配。」

所有 DP 题的开场白都可以复用同一句：「我先定义状态：dp[i] 表示……。这样定义是因为它足以决定后续决策，不需要回看更多历史。」——第二句解释了「为什么这么定义」，而这正是面试官在等的东西。

9研究前沿与开放问题

  • 去重从「推理期组合优化」变成「训练期约束」。NMS 之所以是贪心近似，是因为它在推理期解一个 NP-hard 的最大权独立集。DETR 的一对一匈牙利匹配、YOLOv10 的一致双分配都是把这个问题挪到训练期解决。开放问题：一对一分配带来的监督稀疏与匹配不稳定（见 C54-04）尚无最优解，Group/Co-DETR 的「训练一对多、推理一对一」是当前折中。
  • 可微分的组合优化。把排序、Top-K、匹配、动态规划做成可微算子（soft-DTW、differentiable DP、Sinkhorn 近似匈牙利、Gumbel-Top-K），使「选择」本身可以被端到端训练。soft-DTW 在时序对齐上已经实用；可微 NMS 的尝试（如 Learning-NMS）效果有限，这仍是开放方向。
  • DP 的细粒度复杂度下界。编辑距离在 SETH 假设下不存在 $O(n^{2-\epsilon})$ 算法（Backurs–Indyk 2015），LCS 同理。这类结果解释了为什么工程上只能走「带状近似」「量化剪枝」而不是找更好的精确算法——面试里知道「这是有条件下界的」是很强的信号。
  • 近似算法的实用取舍。MWIS 在一般图上难以近似（$n^{1-\epsilon}$ 不可近似），但在有界厚度（bounded thickness）的几何图上有 PTAS。检测框的冲突图恰好是几何图且局部稀疏，理论上存在比贪心更好的多项式近似，但常数与延迟使其在车端不实用——这是「理论可行 ≠ 工程可用」的好例子。
  • 把预算分配问题做成在线/自适应背包。车端算力预算随其他任务负载波动（见 C53-04 的运行时降级），静态背包解出的配置在运行时可能不可行。在线背包与 bandit 式资源分配在这类场景下的理论保证仍不完善。
  • LLM 时代的算法面试还考不考 DP？业界正在从「手撕算法」转向「结对编程 + 代码审查 + 系统设计」。但 DP 题的核心考点——把模糊问题形式化成状态与转移、并论证正确性——恰恰是 AI 辅助编程无法替代的部分，所以短期内它只会换形式，不会消失。
