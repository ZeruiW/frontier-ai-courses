车端部署与训练-部署一致性

模型在服务器上 mAP 0.82，装到车上像 0.6——这不是玄学，是预处理 / 模型 / 后处理三层里某一层的数值不一致。这门课把「训练-部署一致性」变成一套可执行的工程纪律：每一层都有明确的对拍点、明确的容差、明确的定位算法。覆盖 ONNX 导出、TensorRT 构建与层融合、INT8 校准（含完整的 Entropy-KL 实现）、后处理与坐标对齐、C++ 推理管线，以及 p99 延迟剖析与发布前验收。

TensorRT 构建与优化

TensorRT 做的事情可以概括成三件：融合（减访存）、选 kernel（autotuning）、定形状（optimization profile）——理解这三件就理解了它的全部性能来源与全部坑；Conv+BN 融合的代数推导与「什么会阻止融合」；min/opt/max 三档里只有 opt 影响 kernel 选择；engine 与硬件三元组绑定意味着车端每多一个平台就多一条完整的构建-验证流水线；静默回退的检测方法（看分区数与各分区后端，而不是看端到端是不是变快了）。

MODULE 03

INT8 校准与精度恢复

INT8 不是「精度低一点」，而是「用 256 个格子去装原来 2^32 个值」——所以格子放在哪里（scale）就是全部；MinMax 会被单个离群值毁掉、Entropy-KL 在最小化量化前后的分布信息损失、Percentile 是工程上的折中；校准集的构造是这一章最容易做错、也最少被讲到的一步：必须覆盖夜间、逆光、雨雪，且预处理必须与线上逐字节一致；逐层敏感度分析告诉你哪 5% 的层值得保 FP16；以及一棵可以照着走的量化掉点排查决策树（面试高频）。

后处理对齐与 C++ 推理管线
