1为什么评测科学家要懂系统账本

这不是 CUDA 编程课，是一阶账本训练：给定模型规模、上下文长度、硬件、并行策略，你能不查任何工具就估出 显存够不够、要多少卡、训多久、推理多贵、瓶颈在算力还是带宽。

对做 model evaluation 的研究者，这套账本天天用得上：

  • 判断可行性：要评一个 70B 模型，单张 80GB 卡放得下吗？要不要量化？
  • 读懂论文/报告：别人说"用 256 张 H100 训了 3 个月"，你能反推这合不合理。
  • 成本归因：一次大规模 eval 跑下来烧了多少钱、瓶颈在哪、能不能用 batching/量化降本。
本课的精神：所有结论都能用一张纸 + 几个乘法算出来。显存 = 参数×字节×倍数；算力 = 6ND； 成本 = FLOPs / (峰值×MFU) × 卡时单价。把这些账记牢，你就有了系统直觉。

2为什么用真实模型 config 而非编造数字

很多系统教材用"假设一个 1B 模型"开头。问题是你学不会把真实架构数字翻译成账本。 本课不同：每个 notebook 都联网下载真实模型的 config.json（来自 HuggingFace）， 用它真实的 layers / hidden / heads / vocab / intermediate 算账。

主力是 EleutherAI Pythia 全家桶（160M → 12B，架构完全一致、只缩放规模——天生的 scaling 实验台）外加 GPT-NeoX-20B、GPT-2。 你会亲手验证：用架构数字算出的参数量，和这些模型公开的真实参数量分毫不差。这种"账能对上"的踏实感，正是系统能力的基础。

4环境与依赖

全课 CPU 可跑，不需要 GPU——我们算的是账本与模拟，不是真训练。依赖：

numpy · pandas · matplotlib · urllib（标准库，下载 config）
notebook 首次运行联网下载真实 config（每个几 KB），缓存到 ~/.training_systems_data/。模块 05 会下载一个真实 GPT-2 权重张量（几 MB，用 HTTP range 只取需要的部分）。无网时每章都给了 config 的关键数字可手填。

5全课复用的 config 管线

每本 notebook 顶部有同一个 load_config(model)：下载并缓存 HF 的 config.json，返回标准化的 dict（统一 GPT-2 与 NeoX 的字段名）。 这样你算账时面对的永远是 L, h, heads, V, I 这几个干净的数。notebook 里你会先用它把参数量算出来、和官方对上，建立"账能对上"的信心。

学完本章你应该能：跑通环境、解释为什么用真实 config、并从任意一个 HF config 算出参数量。 下一章把这套账扩展到训练显存的四块大头。
