1为什么量化：显存 + 带宽两本账

量化（quantization）就是把权重从 fp16（2 字节）压到 int8（1 字节）甚至 int4（0.5 字节）。它的两个收益直接落在模块 01 的两本账上：显存和带宽。先把这两笔收益讲清，才知道量化到底在买什么、代价付在哪。

  • 显存减半 / 减四：fp16→int8 权重显存对半砍，fp16→int4 砍到四分之一。模块 01 算过推理显存约 $2P$，量化后变 $P$ 甚至 $0.5P$——让原本放不进小卡的大模型放得下。
  • 带宽减半 / 减四：模块 01 的 roofline 指出自回归解码是 memory-bound，每生成一个 token 都要把整套权重从 HBM 搬一遍。权重位宽减半，搬运量减半，解码直接变快——这是量化在推理上提速的物理根据。

代价只有一个字：精度损失。把连续的 fp16 值塞进 256 个（int8）或 16 个（int4）整数格子，必然产生舍入误差。本章的全部技术——对称 / 非对称、per-channel/group、GPTQ/AWQ——都是在回答同一个问题：如何在压到这么少的位数下，把精度损失压到最小。

记住量化的两本账：显存（让模型放得下）与带宽（让解码更快）。前者对应模块 01 的 $2P$ 显存账，后者对应 roofline 的 memory-bound 解码。量化省的是空间和搬运，不是计算——这也解释了它为什么主要用于推理而非训练（训练的瓶颈是优化器状态那 12P，且多需 fp32 精度累加）。

2对称量化（absmax）

最简单的方案是对称量化（symmetric / absmax）：找权重绝对值的最大值，把 $[-\max|W|,\ \max|W|]$ 线性映射到 $[-127,127]$（int8）。

\[s=\frac{\max|W|}{127},\qquad q=\mathrm{round}(W/s)\in[-127,127],\qquad \hat W=q\cdot s\]

$s$ 是 scale（缩放因子），量化就是除以 $s$ 再取整，反量化就是乘回 $s$。对称的含义是：实数 0 精确映射到整数 0（无偏移），且正负范围关于 0 对称。它特别适合权重，因为权重通常近似零均值、左右对称分布——notebook 里你会在真实 GPT-2 张量上看到这个钟形对称分布确实成立。

为什么对权重选对称而不是更灵活的非对称？因为权重既然关于 0 对称，对称量化就不浪费任何一侧的格子，而且省掉了 zero-point（下一节）这个额外参数与额外加减运算。注意 int8 对称只用到 $[-127,127]$ 而非 $[-128,127]$——牺牲一个格子换来零点严格对称、反量化无偏，这是工程上常见的取舍。

对称量化的一句话：用最大绝对值定一把对称的尺子，零对零、正负对称。它对零均值对称的权重最贴合，是权重量化的默认选择。下一节会看到，一旦数据不对称（如激活），这把对称尺子就开始浪费格子，需要换工具。

3非对称量化（zero-point）

当数据不对称时，对称量化就吃亏了。最典型的是 ReLU 之后的激活——全是非负数。用对称尺子去量化全正数据，负的那一半 $[-127,0)$ 全部空置、浪费了一半范围，等效精度直接腰斩。对策是非对称量化（asymmetric）：引入一个 zero-point 把真实区间 $[\min,\max]$ 平移映射到 $[0,255]$（uint8）。

\[s=\frac{\max-\min}{255},\quad z=\mathrm{round}(-\min/s),\quad q=\mathrm{round}(W/s)+z\in[0,255],\quad \hat W=(q-z)\cdot s\]

zero-point $z$ 是真实 0 对应的那个整数值。它把整个区间平移，让 $\min$ 对齐到整数 0、$\max$ 对齐到 255，256 个格子一个不浪费地铺满数据的真实范围。代价是反量化要多做一次减 $z$，以及多存一个 $z$。经验法则很清晰：权重用对称（零均值对称），激活用非对称（常偏正、不对称）。

直白说

量化就是把一把连续的尺子刻成 256 个（int8）或 16 个（int4）格子。对称：格子关于 0 对称排开；非对称：先平移让最小值对齐第一个格子，再均匀分。格子越少（int4），同一个数被四舍五入得越狠，误差越大。

严谨说

对称把 $[-\max|W|,\max|W|]$ 映到 $[-127,127]$、零点固定；非对称把 $[\min,\max]$ 映到 $[0,255]$、用 zero-point $z$ 平移。数据若不关于 0 对称（如 ReLU 后全正），非对称避免空置半个范围，等效步长 $s$ 更小、误差更低。这就是激活用非对称的原因。

高频混淆点：权重对称、激活非对称，别记反。原因不是约定俗成，是分布决定的——权重近似零均值对称、对称尺子不浪费；激活（尤其 ReLU 后）偏正不对称、必须用 zero-point 平移才不糟蹋格子。面试若被问为什么不统一用一种，答分布形状不同，对称浪费了不对称数据的一半范围。

4量化误差方差推导：s²/12

要量化地比较各种方案，得先有误差的数学。把一个实数 round 到步长为 $s$ 的格点，量化误差 $e=\hat W-W$ 可近似看作均匀分布在 $[-s/2,\ s/2]$ 上（只要 $s$ 远小于数据范围、误差不系统偏向某侧）。由均匀分布的矩直接积分：

\[\mathbb E[e]=0,\qquad \mathrm{Var}(e)=\int_{-s/2}^{s/2} e^2\cdot\frac{1}{s}\,de=\frac{1}{s}\cdot\frac{e^3}{3}\Big|_{-s/2}^{s/2}=\frac{s^2}{12},\qquad \mathrm{RMSE}=\frac{s}{\sqrt{12}}\]

这条 $\mathrm{Var}(e)=s^2/12$ 是整章的定量基石。它说误差的大小只由步长 $s$ 决定，且随 $s$ 平方增长。于是减小 $s$ 就直接减小误差——这正是 per-channel/per-group 量化的全部动机：每个局部用自己的、更小的 $s$，误差就更小。也解释了 int4 为何误差大：格子只有 16 个，$s$ 被迫取得很大（约是 int8 的 16 倍量级），误差随之放大。

怎么把它变成可报告的相对误差？把 RMSE 除以权重的标准差：相对误差 $\approx \mathrm{RMSE}/\mathrm{std}(W)=(s/\sqrt{12})/\mathrm{std}(W)$。对一个近似正态、$\max|W|\approx k\cdot\mathrm{std}(W)$（$k$ 约 4–6）的权重张量，int8 对称的 $s=\max|W|/127$ 很小，算出的相对误差通常在零点几个百分点量级——这就是int8 几乎无损这个经验印象的来源。

把 $\mathrm{Var}(e)=s^2/12$ 刻进脑子：量化误差随步长平方走，步长由最大绝对值和格子数决定。于是两条推论顺理成章——① 格子多（int8 vs int4）误差小；② 局部 scale（per-channel vs per-tensor）让 $s$ 更小、误差更小。本章后面所有粒度与算法的优劣，都能用这一条公式来解释。

5从零算一遍：真实 GPT-2 权重

把 $s^2/12$ 落到一个真实张量上走一遍，你才真正握住量化的手感。配套 notebook 在 GPT-2 的 h.0.attn.c_proj.weight 上做 absmax int8 量化（这是一个 $768\times768$ 的注意力输出投影矩阵）。下面给出完整的纸面计算路径——不需要真跑，notebook 会实测验证每一步，包括 $\mathrm{Var}(e)\approx s^2/12$。

第一步：从张量统计量算出 scale

真实 GPT-2 权重近似零均值正态，典型地 $\mathrm{std}(W)\approx0.05$、$\max|W|\approx0.5$（约 $10$ 个标准差处的尾巴，深网权重常有这样的长尾）。per-tensor 对称的步长就是 $s=\max|W|/127=0.5/127\approx3.9\times10^{-3}$。

第二步：由 s 推 RMSE 与相对误差

由 $\mathrm{RMSE}=s/\sqrt{12}=3.9\times10^{-3}/3.46\approx1.1\times10^{-3}$。把它除以 $\mathrm{std}(W)$ 得到相对误差：$\mathrm{RMSE}/\mathrm{std}(W)\approx1.1\times10^{-3}/0.05\approx2.3\%$。这是 per-tensor int8 的量级——已经不算大，但还不到无损。这也印证了 int8 通常掉一点点、需要实测确认而非默认无损。

\[s=\frac{\max|W|}{127},\quad \mathrm{RMSE}=\frac{s}{\sqrt{12}},\quad \text{相对误差}=\frac{\mathrm{RMSE}}{\mathrm{std}(W)}\approx\frac{\max|W|}{127\sqrt{12}\,\mathrm{std}(W)}\]

第三步：per-channel 为什么把误差再压一截

per-tensor 的 $s$ 被全矩阵那个 $0.5$ 的离群最大值撑大。改成 per-channel，每列单独取 $\max$：大多数列的局部 $\max|W|$ 远小于 $0.5$（也许只有 $0.2$），于是它们的局部 $s\approx0.2/127\approx1.6\times10^{-3}$，相对误差降到约 $0.9\%$——误差小一截正是这么来的。只有含离群值的那一两列仍用大 $s$，但坏处被隔离在那几列，不再拖累全矩阵。notebook 会实测出 per-channel 的整体 RMSE 明显低于 per-tensor，且每列的 $\mathrm{Var}(e)$ 都贴近各自的 $s^2/12$。

这条计算路径里有个口径必须说清：相对误差 $\approx\max|W|/(127\sqrt{12}\,\mathrm{std}(W))$ 的大小取决于权重分布的尾巴有多长（$\max|W|$ 与 $\mathrm{std}$ 的比值）。尾巴越长（离群越重），per-tensor 越吃亏、per-channel 收益越大。所以同样是 int8，不同层、不同矩阵的误差可以差好几倍——报告时别用一个笼统的百分比盖住所有层。

6粒度与 int4 打包

有了 $s^2/12$，粒度的选择就清晰了：用越局部的 scale，每个局部的 $\max$ 越小、$s$ 越小、误差越低。三种粒度从粗到细：

粒度几个 scale优点致命弱点 / 代价
per-tensor整个矩阵 1 个最省、实现最简一个离群值撑大全局 $s$，其余值量化极粗
per-channel每列 / 行 1 个误差显著下降多存少量 scale（每列一个标量）
per-group每 128 个元素 1 组误差最低、最灵活多存更多 scale，int4 常配它

per-tensor 的致命弱点要重点理解：一个离群值（outlier）就能毁掉整个矩阵的量化。$s=\max|W|/127$ 取的是全矩阵的最大绝对值，只要某一列藏着一个极端大的值，$s$ 就被它撑大，于是所有其他正常值都得用这个粗大的步长去量化，误差集体恶化。per-channel 把 scale 局部化到每列，离群值只撑大它所在那一列的 $s$，不再殃及全矩阵。

per-group 更进一步：把每 128 个元素分一组、各用一个 scale，误差最低，但要存的 scale 也最多（一个 $4096\times4096$ 矩阵按 128 分组就有 $4096\times32$ 个 scale）。这点存储开销相对省下的几个 GB 权重微不足道。notebook 里你会在真实 GPT-2 的 h.0.attn.c_proj.weight 上实测：per-channel 的相对误差比 per-tensor小一截，并验证误差方差确实贴近理论的 $s^2/12$。

粒度是报告口径里最常被含糊的一项。说我做了 int8 量化几乎没有信息量——必须讲清是per-tensor 还是 per-channel/per-group、group size 多大。同样是 int8，per-tensor 遇到离群值可能掉 5 个点，per-group 可能几乎无损。粒度决定精度，含糊就等于没说。

int4 只有 16 个值（$-8\sim7$ 或 $0\sim15$），一个值只需 4 个比特，于是两个 int4 能塞进一个字节。打包用位运算：高 4 位放一个、低 4 位放另一个，解包再用移位和掩码取出。

\[\text{byte}=(q_{\text{hi}}\ll 4)\,|\,q_{\text{lo}},\qquad q_{\text{hi}}=\text{byte}\gg 4,\qquad q_{\text{lo}}=\text{byte}\,\&\,\text{0xF}\]
一个字节 (8 bit) 装两个 int4： bit: 7 6 5 4 | 3 2 1 0 └─ q_hi ┘ └─ q_lo ┘ 打包: byte = (q_hi << 4) | q_lo 解包: q_hi = byte >> 4 ; q_lo = byte & 0xF 例: q_hi=5(0101), q_lo=12(1100) → byte=0101 1100 = 0x5C

这样 int4 权重显存是 fp16 的 1/4——模块 01 的 $2P$ 推理显存直接压到 $0.5P$。代价由上一节的 $s^2/12$ 早已注定：格子从 256 跌到 16，步长 $s$ 被迫放大约 16 倍量级，误差随之显著增大。所以 int4 几乎从不单独使用，而是配 per-group + 误差感知量化（GPTQ/AWQ）才能把精度拉回可用。下表把 int8 与 int4 的账并排对比：

位宽格子数显存比（vs fp16）相对误差量级典型搭配
int82561/2零点几个百分点per-tensor / per-channel
int4161/4明显更大（数倍）per-group + GPTQ/AWQ

一句话抓住权衡：int4 把显存再砍一半（相对 int8），但误差大一个量级，必须靠更细的粒度和更聪明的算法来补。如果有人说我用 int4 量化且几乎无损，你应当立刻追问：per-group 吗？group size 多少？用了 GPTQ 还是 AWQ？——这些细节才是 int4 能否可用的关键。

int4 的两个常见误区：① 以为int4 和 int8 误差差不多（错，格子少 16 倍，误差大得多）；② 以为打包只是省一半存储的小技巧——其实它配合 per-group + GPTQ 才是 int4 实际可用的前提。单纯 per-tensor int4 几乎一定会让模型能力明显塌陷。

7GPTQ / AWQ：误差感知量化

朴素量化对每个权重独立四舍五入，完全忽略了一个事实：不同权重对最终输出的影响天差地别。前沿方法的共同信念是——量化误差不该被均匀对待，要优先保护对输出影响大的权重。两条代表性路线：

  • GPTQ（Frantar et al. 2023）：逐列量化，每量化完一列，就立刻调整剩余未量化的列来补偿这一列引入的误差——基于二阶 Hessian 信息决定怎么补偿，使整个权重矩阵造成的输出误差最小，而非单个权重误差最小。
  • AWQ（Lin et al. 2023，activation-aware）：观察到少数被大激活乘到的权重对输出影响最大，于是对这些重要通道做保护性缩放（量化前放大、量化后缩回），让量化的舍入误差尽量避开这些敏感通道。

两者的精神一致：从逐权重独立升级到感知全局影响。GPTQ 用 Hessian 看权重之间的相互补偿，AWQ 用激活统计看哪些权重被放大、最该保护。这也是为什么 int4 这种高误差场景几乎离不开它们——$s^2/12$ 说误差总量被位宽钉死，但误差落在哪里可以被这些算法重新分配，让它落在不痛不痒的权重上。

离群值（outlier features）是 LLM 量化的头号敌人。Dettmers 发现大模型的某些激活维度存在极端离群值，会把 per-tensor int8 的 scale 撑爆、毁掉精度。LLM.int8() 的解法是混合精度分解：把这些离群维度单独留 fp16 计算，其余维度走 int8——用一点点 fp16 的代价，守住整体精度。这正是不均匀对待量化误差思想最早、最有名的实例。

8面试 drill：分布与误差问答

把本章压成一组面试问答。量化题考的是你能否分清分布决定方案、步长决定误差，而不是背 API。下面逐条给出标准答法与口径：

  • 对称 vs 非对称，选哪个？ → 看分布：权重对称（零均值）用对称、激活不对称（如 ReLU 后全正）用非对称；对称浪费不对称数据的半个范围。
  • per-channel 为什么误差小？ → 误差 $\propto s$、$s=\max/格子数$；per-channel 让每列用各自更小的局部 $\max$，把离群值的影响隔离在单列，整体步长更小、误差更低（$\mathrm{Var}=s^2/12$）。
  • int4 为什么要配 per-group + GPTQ？ → int4 只 16 级、$s$ 大、误差大一个量级；per-group 缩小每组 $s$，GPTQ/AWQ 把误差重新分配到不重要的权重，两者合力才把精度拉回可用。
  • 量化模型评测要注意什么？ → 必须重跑真实任务；困惑度可能只涨一点，但推理 / 长尾知识可能塌方，别拿一个 perplexity 数字代表全部能力。

再串几个高频陷阱的正确反应：权重和激活用同一种量化吗 → 不，权重对称、激活非对称；离群值有什么危害 → 撑大 per-tensor 的全局 $s$、毁掉精度，解法是 per-channel/group 或 LLM.int8 的混合精度分解；int4 是不是几乎无损 → 看粒度与算法，per-tensor int4 几乎一定塌方、per-group + GPTQ 才可能接近无损。

扣分陷阱集锦：① 把权重 / 激活的对称性记反；② 以为per-channel 是玄学（其实就是缩小局部 $s$、$s^2/12$ 直接解释）；③ 以为int4 和 int8 误差差不多（差一个量级）；④ 量化后不重测就宣称无损（某些能力可能已塌方）。这四点几乎是量化面试的必设坑。

9研究前沿、评测纪律与开放问题

量化是部署侧最活跃的方向之一，而它对评测的意义常被低估，先把这条讲透，再看前沿。最重要的一条纪律：量化后必须重新跑评测。困惑度（perplexity）可能只涨一点点，给人几乎无损的错觉，但某些能力——多步推理、长尾事实知识——可能直接塌方。别假设量化只掉一点点，要用真实任务实测。

还有一条报告口径的纪律：说清楚量化了什么、怎么量化的。权重、激活、KV cache 的量化难度依次递增——KV cache 量化对长上下文显存尤其关键（呼应模块 06）。说int4 量化时必须交代是 per-tensor 还是 per-group、group size 多大、有没有用 GPTQ；这些直接决定精度，含糊其辞等于没报。

前沿则在沿几个方向继续推进，每一条都把本章的某个思想做到极致：

  • QLoRA / NF4：用 4-bit NormalFloat 量化冻结的主权重 + LoRA 微调，把大模型微调塞进单张消费卡（呼应模块 01 的 LoRA 显存账）。
  • SmoothQuant：把激活的量化难度（离群值）通过数学等价变换迁移到权重上，让激活更好量化。
  • AQLM / 向量量化：不再逐元素量化，而是把权重向量映射到一个学习出的码本（codebook），在极低位宽下逼近无损。
  • 4-bit scaling laws（Dettmers & Zettlemoyer 2023）：系统研究位宽与模型规模如何权衡，回答同样的显存预算下该选大模型低位宽还是小模型高位宽。
