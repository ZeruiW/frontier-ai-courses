1数学推导：训练 FLOPs ≈ 6ND（前向 2、反向 4）

这是整个 C08 的面试压轴。无数系统/研究岗的面试都会落到同一道题：「训这个模型大概要多少卡、跑多久、烧多少钱？」答得出数量级，面试官立刻知道你有真实的工程直觉；答不出，前面背的所有架构知识都显得悬浮。这一课就把这道题拆成一条可复现的数字链，并配多个完整算例。

一切的起点是一个万能公式：训练一个 $N$ 参数的模型、过 $D$ 个 token，总计算量约

\[\boxed{\ \text{Training FLOPs}\approx 6ND\ }\]

为什么是 6？拆成前向和反向两块。前向：Transformer 的主体计算是矩阵乘，每个参数对每个 token 参与一次乘加（multiply-accumulate），一次乘加 = 1 次乘法 + 1 次加法 = 2 FLOPs，所以前向 $\approx 2N$ FLOPs/token。反向：反向传播要算两类梯度——对激活的梯度（往前传，约 $2N$）和对权重的梯度（用来更新，约 $2N$），合计约 $4N$ FLOPs/token，恰是前向的两倍。前向 $2N$ + 反向 $4N$ = $6N$ FLOPs/token，乘以 $D$ 个 token，得 $6ND$。

计算块FLOPs / token / 参数口径来源
前向 matmul≈ 2N每参数每 token 一次乘加 = 2 FLOPs
反向：对激活的梯度≈ 2N链式法则往前传
反向：对权重的梯度≈ 2N算 ∂L/∂W 用来更新
合计≈ 6N前向 2N + 反向 4N

6ND 是系统面试的万能钥匙。记住「前向 2、反向 4、合计 6」这三个数，再加上「硬件峰值」和「MFU」两个参数，你就能口算出 GPT-3、LLaMA、任何模型的训练量级。后面四节就是把 6ND 这块原料，依次加工成 FLOPs → 时间 → 钱。

口径细节：这里的 $N$ 严格说应取非 embedding 参数——embedding 查表不做每 token 的 matmul 主体，不吃 6ND 的账。但做数量级估算时，用总参数量也无妨（embedding 通常占比小）。面试时点一句「N 取非 embedding 更准」会显得你抠过细节。

2直觉与口径：MFU——理论算力打几折

有了 $6ND$ 这块计算量，下一步要把它换成时间，就必须面对一个残酷现实：GPU 标称的峰值算力，你永远跑不满。

GPU datasheet 上的峰值（如 A100 bf16 312 TFLOP/s、H100 bf16 约 990 TFLOP/s）是理论上限，假设张量核心 100% 满载、数据永远就绪。真实训练里，通信（梯度 all-reduce、并行切分的数据交换）、内存带宽、kernel 启动开销、流水线气泡都会偷走时间。衡量「实际打了几折」的指标叫 MFU（Model FLOPs Utilization）：

\[\text{MFU}=\frac{\text{实际有效算力}}{\text{峰值算力}},\qquad \text{有效算力}=\text{峰值}\times\text{MFU}\times G\]

$G$ 是卡数。真实大模型训练的 MFU 通常落在 30%–55%——做得好的大规模训练能到 40%–50%，普通配置常在 30% 出头。这意味着一张 312 TFLOP/s 的 A100，有效产出可能只有 $312\times0.4\approx 125$ TFLOP/s。

MFU 是这道题的灵魂参数

没有 MFU 的时间/成本估算是耍流氓。用峰值（即 MFU=100%）算出来的时间会严重低估——MFU 40% 意味着真实时间是理论的 2.5 倍（$1/0.4=2.5$）。面试报数字时必须主动说出你的 MFU 假设，比如「按 A100、MFU 40% 估」；只字不提 MFU 的答案，懂行的面试官会直接判你没算过真实训练。

直白说

峰值算力像汽车仪表盘上的最高时速 250 km/h——理论上能到，但实际开在路上（红灯、堵车、上下坡）平均时速可能只有 100。MFU 就是「实际平均时速 ÷ 仪表盘最高速」。你要估一趟路开多久，得用实际平均速度，不能用仪表盘最高速。

严谨说

MFU 与硬件利用率 HFU（Hardware FLOPs Utilization）有别：HFU 把重计算（activation recomputation）等「有效但重复」的 FLOPs 也算进去，所以 HFU ≥ MFU。报训练效率时业界更常用 MFU，因为它对应「真正推进训练的有效计算」，是衡量系统好坏的更诚实的尺子。

3数学推导：时间与成本公式（成本与卡数无关）

把前两节拼起来，就得到这道题的两条主公式。时间 = 计算量 ÷ 有效算力；成本 = 卡数 × 时间 × 单价。

\[T=\frac{6ND}{\text{峰值}\times\text{MFU}\times G},\qquad \text{成本}=G\times T_{\text{小时}}\times \text{单价/卡时}\]

这里藏着一个非常漂亮、面试官爱考的洞察：把 $T$ 代进成本，卡数 $G$ 约掉了。

\[\text{成本}=G\cdot\frac{6ND}{\text{峰值}\cdot\text{MFU}\cdot G}\cdot\frac{\text{单价}}{3600}=\frac{6ND}{\text{峰值}\cdot\text{MFU}}\cdot\frac{\text{单价}}{3600}\]

（除以 3600 是因为单价按卡时计，而 $T$ 以秒为单位。）这条式子说：训练总成本与用多少卡无关——更多卡只是让训练更快完成，但总卡时（卡数 × 小时）守恒。买 2048 张卡比 1024 张快一倍，可账单一样（忽略并行通信损耗）。这是个反直觉但极重要的结论：卡数决定墙钟时间，不决定总花费。

类比：搬一堆砖，雇 10 个工人和雇 20 个工人，总工时（人 × 小时）一样，20 人只是搬得快。所以老板的人力账单不变（按工时付费），变的只是工期。训练同理——卡是工人，6ND 是那堆砖，MFU 是工人的实际效率。

4完整算例 A：训 GPT-3 要多少卡 / 多久 / 多少钱

现在上第一个完整算例，也是面试最经典的一道：训 GPT-3 要多少卡、多久、多少钱？GPT-3 的官方数字：$N=175\text{e}9$ 参数、$D=300\text{e}9$ token。我们一步步把数字链走完，每一步都给出数。

第 1 步：算总计算量 C = 6ND

\[C=6ND=6\times 175\text{e}9\times 300\text{e}9=3.15\text{e}23\ \text{FLOPs}\]

第 2 步：定硬件有效算力

用 A100 bf16，峰值 $312\text{e}12$ FLOP/s，MFU 取 40%（大规模训练的合理值）：

\[\text{有效/卡}=312\text{e}12\times 0.40=124.8\text{e}12\ \text{FLOP/s}\]

第 3 步：选卡数 G，算时间 T

取 $G=1024$ 张 A100：

\[T=\frac{3.15\text{e}23}{124.8\text{e}12\times 1024}=\frac{3.15\text{e}23}{1.278\text{e}17}\approx 2.46\text{e}6\ \text{s}\]

换算：$2.46\text{e}6 \text{ s} \div 86400 \approx 28.5$ 天，约等于 $2.46\text{e}6/3600\approx 684$ 卡时/卡。

第 4 步：算钱

A100 云价按约 \$1.5/卡时（量级，实际 \$1–2 区间）：

\[\text{成本}=1024\ \text{卡}\times 684\ \text{小时}\times \$1.5/\text{卡时}\approx \$1.05\text{e}6\]

约 105 万美元、1024 张 A100、跑 28.5 天——这就是 GPT-3 训练的量级答案。验证一下「成本与卡数无关」：若改用 2048 张卡，时间减半到约 14 天，但 $2048\times 342\times 1.5$ 仍约 \$1.05M，账单不变。

这是理论训练的账。真实 GPT-3 的总花费更高，因为还要叠加：失败重启与 checkpoint 回滚、数据清洗与预处理的算力、海量调参与消融实验（真正训出来前跑过的所有小实验）。经验上真实账常是理论训练的几倍。面试时报完理论数字，补一句这个，显得你见过真账。

5完整算例 B：Chinchilla 与给定预算反解最优模型

第二个核心问题：给定算力预算 $C=6ND$，参数 $N$ 和数据 $D$ 该怎么分，才能让最终 loss 最低？这正是 scaling laws 要回答的。Kaplan 等人 2020 的早期结论倾向「把算力多砸在参数上」；Hoffmann 等人 2022 的 Chinchilla 论文做了更系统的拟合，给出了著名修正。

Chinchilla 的核心结论：$N$ 和 $D$ 应当同比例增长，compute-optimal 时大约 $D\approx 20N$（每个参数配约 20 个训练 token）。换成 scaling 关系：

\[N_{\text{opt}}\propto C^{0.5},\quad D_{\text{opt}}\propto C^{0.5}\quad\Rightarrow\quad D_{\text{opt}}\approx 20\,N_{\text{opt}}\]

最实用的推论是给定预算反解最优模型大小。由 $C=6ND$ 和 $D=20N$ 联立，消去 $D$：

\[C=6N\cdot 20N=120N^2\ \Rightarrow\ N_{\text{opt}}=\sqrt{\frac{C}{120}},\quad D_{\text{opt}}=20\,N_{\text{opt}}\]

完整算例 B：给定 1000 张 H100 跑 30 天，最优模型多大？

先算总算力 $C$。H100 bf16 峰值约 $990\text{e}12$ FLOP/s，MFU 取 40%，$G=1000$，时间 $30\times 86400=2.592\text{e}6$ s：

\[C=990\text{e}12\times 0.40\times 1000\times 2.592\text{e}6\approx 1.03\text{e}24\ \text{FLOPs}\]

代入 Chinchilla 公式：

\[N_{\text{opt}}=\sqrt{\frac{1.03\text{e}24}{120}}=\sqrt{8.55\text{e}21}\approx 9.2\text{e}10,\quad D_{\text{opt}}=20\times 9.2\text{e}10\approx 1.85\text{e}12\]

即约 92B 参数、配约 1.85T token是这笔预算下的 compute-optimal 配置。这类反解题面试很爱出：给你硬件和时间，问你「应该训多大的模型」——答案不是「越大越好」，而是这条 $\sqrt{C/120}$。

参数大 ≠ 更强，要看数据配没配齐

GPT-3 是「训练不足」的活教材。它 175B 参数却只喂了 300B token，比值 $D/N\approx 1.7$，远低于 Chinchilla 的 20。按 compute-optimal，175B 模型应配约 $20\times 175\text{B}=3.5\text{T}$ token。Chinchilla 自己用 70B 参数 + 1.4T token（$D/N=20$）在更少的总算力下全面打败了 GPT-3——证明「参数不是越大越好，数据要配齐」。这对评测的启示：比较两个模型时先看它们是否各自 compute-optimal，否则比的是训练配置而非架构优劣。

6陷阱：训练 6ND vs 推理 2N/token，别混

一个面试高频混淆点，必须单独拎出来讲清：训练的 6ND 和推理的 2N 是两笔完全不同的账，别混。

推理时只有前向、没有反向（不算梯度、不更新权重），所以推理一次前向 ≈ 2N FLOPs/token——恰好是 6ND 里前向那一块 $2N$。注意推理这里没有 $D$：$D$ 是训练要过的总 token 数；推理是按 token 计费的边际成本，每生成 1 个 token 约 2N FLOPs。

\[\text{训练}\approx 6ND\ \text{(整个数据集)};\qquad \text{推理}\approx 2N\ \text{FLOPs/token}\]
训练推理（单 token 前向）
前向2N/token2N/token
反向4N/token无
系数6N/token2N/token
规模因子× D（总 token）× 每个生成 token
公式6ND（一次性）2N/token（边际）

一个有用的数量级感：训练的总 FLOPs ≈ 推理一次前向的 3D 倍（$6ND / 2N = 3D$）。GPT-3 训练过了 300B token，相当于做了约 $3\times 300\text{e}9=9\text{e}11$ 次「单 token 前向」的计算量。但反过来想：一旦训好，一次推理调用只花 2N——这正是「训练贵、推理（单次）便宜，但推理量大了总账也惊人」的根源。

面试陷阱原话：「推理一次要多少算力？」——答 $2N$ FLOPs/token，千万别脱口说 6N 或带上 D。把 6ND（训练、含反向、乘整个数据集）和 2N/token（推理、纯前向、按 token）这两个公式的「系数」和「规模因子」都说对，面试官就知道你脑子里这两笔账是分开的。

7面试 drill 模板：六步标准解法与量级速查表

把整道题固化成一个六步模板，面试时照着走，绝不漏项：

  1. 定 N、D：参数量 $N$ 直接给或估；数据 $D$ 若题目没给，用 Chinchilla 取 $20N$。
  2. 算 C = 6ND：一行算出总 FLOPs。
  3. 定硬件：峰值算力（A100 312T / H100 ~990T bf16）+ MFU（默认取 40%，并说出来）。
  4. 算时间 T：$T=C/(\text{峰值}\cdot\text{MFU}\cdot G)$，选定卡数 $G$，换算成天。
  5. 算钱：$G\cdot T_{\text{hr}}\cdot$ 单价（A100 约 \$1–2/卡时）；或用与卡数无关的成本式校验。
  6. 查显存：用模块 01/03 验证 $G$ 张卡放得下（权重 + 优化器状态 + 激活，ZeRO/并行切分）。

第 6 步常被忽略却很关键：算得出时间和钱，但卡数 $G$ 还得满足显存约束——一个 175B 模型的权重 + Adam 优化器状态（fp32 动量与方差）+ 梯度，单卡根本放不下，必须靠数据并行 + ZeRO 分片 + 张量/流水线并行把状态摊到足够多卡上。时间够快但显存放不下，方案就是空中楼阁。

注意 LLaMA-2 那行——$D/N$ 高达约 286，远超 Chinchilla 的 20，是故意过训练（over-training）。为什么明知不是 compute-optimal 还这么做？因为 Meta 要的是一个推理便宜的小模型：用更多训练算力换更小的 $N$，部署时每 token 推理成本（$2N$）更低。这正是下一节前沿要展开的「以推理成本换训练成本」。

8研究前沿、陷阱清单与课程收尾

6ND / MFU / Chinchilla 是这套账本的地基，但前沿一直在往上修正。把这些方向和它们改了地基的哪一块对上：

  • 后 Chinchilla 的过训练（over-training）：LLaMA-3、DeepSeek 等明知偏离 compute-optimal，也要把小模型喂到远超 20N 的 token——因为部署阶段海量推理调用的总成本，会盖过训练阶段一次性的额外算力。Sardana & Frankle 2023 把推理成本显式纳入 scaling law，给出「该训多小、过训多狠」的新最优点。
  • MoE 的 FLOPs 账：mixture-of-experts 模型每个 token 只激活一部分专家，「激活参数」远小于「总参数」。6ND 里的 $N$ 该用哪个？训练 FLOPs 用激活参数算更准——这让 MoE 能用很大的总参数量却只付较小的训练 / 推理 FLOPs，是另一种「以显存换算力」。
  • 数据墙（data wall）：Chinchilla 要 $D=20N$，但高质量人类文本是有限的。当 $D$ 撞到天花板，再加算力只能往参数堆（回到 Kaplan 区间）或靠合成数据、多轮重复——scaling 的范式正在被重写。
  • N 取非 embedding、MFU 必报：这两条不是前沿而是永远的纪律——前者让 6ND 更准，后者让时间 / 成本估算不至于乐观 2.5 倍。

把全课的陷阱收成一张清单，面试前过一遍：

  • 6ND 是训练；推理是2N/token。系数和规模因子都别混。
  • $N$ 取非 embedding更准；数量级估算用总参数可接受。
  • MFU 必报——没有 MFU 的时间/成本是耍流氓；MFU 40% = 实际时间 ×2.5。
  • 真实账 =理论的几倍（失败重启、数据预处理、调参试错）。
  • 比较模型先看是否各自 compute-optimal，否则比的是配置不是架构。

恭喜你完成了 C08 训练 / 推理系统课。从模块 00 的参数量与显存，到 01 的 roofline，到 02–04 的并行与 ZeRO，到 05 的量化，到 06 的推理服务，再到这一课的成本账本——你现在握有一整套第一性原理的工程账本：拿到任何一个模型，都能在一张餐巾纸上估出它要多少卡、训多久、烧多少钱、推理多贵、显存放不放得下。这正是把「会调 API」和「懂系统」区分开的那条线。带着这套账本，去看任何模型吧。
