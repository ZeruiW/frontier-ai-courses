1这门课讲什么

欢迎来到 GPU 内核与性能工程。这门课只追求一件事：让你从「会调用 FlashAttention」变成「会写 FlashAttention」。

绝大多数人和 GPU 的关系止于 model.cuda() 和 F.scaled_dot_product_attention(...)。这门课要往下钻一层：当你写 a @ b 时，GPU 上成千上万个线程是怎么协作算出这个矩阵乘的？为什么同样的 FLOPs，一种写法比另一种快十倍？为什么注意力在长序列上会爆显存，而 FlashAttention 不会——它少算了吗？（剧透：没有，它算得甚至更多，却快好几倍。）

这些问题的答案不在任何 API 文档里，而在硬件的物理约束和算法对这些约束的回应之中。一块 GPU 给你的，本质上是两样东西：海量的并行算力，和一个金字塔形的内存层级（越靠上越快越小）。几乎所有 GPU 性能工程，归根结底都是在回答同一个问题——如何把数据搬到尽量靠上的层级、并尽量多地复用它，从而少碰那个又慢又远的主显存。本课就是沿着这条主线，把五个核心内核（执行模型、合并访问、分块矩阵乘、规约/softmax、FlashAttention）从零拆开、亲手重建。

学完你应当能回答这类问题（也是 GPU/推理岗位的高频面试题）：GPU 的 thread/warp/block 到底怎么映射到我的数据？什么叫合并访问，不合并会慢多少？分块矩阵乘把什么指标提上去了，为什么这就够快？online softmax 凭什么能一遍流式算出归一化？FlashAttention 显存为什么是 O(n) 而不是 O(n²)？——并且能在 numpy 里把这五样东西都从零实现、和朴素版对拍到 1e-10。

一句方法论上的话先说在前面：本课的价值不在「我们没有 GPU 也能学」这个妥协，而在它逼你只关注真正难的部分——并行结构与正确性。API 语法、寄存器分配、指令选择，这些有了正确结构之后都是机械活，且各架构不同、年年在变；而「怎么把一个问题切成能并行、能复用、数值还正确的块」是不随硬件过时的硬功夫。把它练扎实，换到任何 DSL（Triton、CUTLASS、甚至下一代工具）都立刻能上手。

2世界观：三类瓶颈与「算力 ≫ 带宽」

贯穿全课的世界观来自一句话（Horace He 的名篇标题）：让深度学习跑得飞快，要先分清瓶颈在哪。性能瓶颈基本只有三类：

瓶颈类型意思典型算子对策
算力受限 compute-bound算术单元打满，等的是计算大矩阵乘、卷积用 Tensor Core、提高算力利用率
访存受限 memory-bound算得快但数据喂不上，等的是 HBM逐元素、softmax、LayerNorm、注意力合并访问、分块复用、算子融合
开销受限 overhead-bound真正干活的时间被调度/启动/python 淹没大量小内核、动态形状融合成大内核、用 CUDA Graph
算力 ≫ 带宽

最反直觉、也最重要的一条：现代硬件的算力增长远快于内存带宽增长。H100 的 FP16 算力以近 1000 TFLOP/s 计，而 HBM 带宽约 3 TB/s——意味着每从显存搬 1 个字节，硬件有空算几百个浮点运算。这个比值（脊点算术强度）几十年来只增不减：算力大约每两年翻倍，带宽却慢得多。结果是深度学习里大多数算子是访存受限的，优化的主旋律不是「少算」，而是「少搬数据」。这正是 tiling 与 FlashAttention 的灵魂。

把这三类瓶颈分清楚，是做任何性能优化的第一步且最容易被跳过的一步。新手最常犯的错是凭直觉乱优化——给一个访存受限的算子换更快的数学库（没用，瓶颈在搬数据），或给一个开销受限的程序优化内层循环（没用，时间花在 python 和内核启动上）。先测量、先归类，再对症下药：访存受限就想办法复用数据与融合算子，算力受限就提高算力利用率（用 Tensor Core、改精度），开销受限就把小内核合并、减少启动次数。

记住这张三分表，本课每个模块都在打其中一类瓶颈：模块 02 合并访问、模块 03 分块、模块 04/05 融合，全是访存受限这一栏的解药——因为这是深度学习里最普遍、最值钱的一类瓶颈。

3课程地图：从单线程到 FlashAttention

课程地图：从单个线程到 FlashAttention

硬件给你的：海量线程 + 一个金字塔形内存层级（越上越快越小） 模块 01 执行模型 thread → warp(32) → block → grid；SIMT、occupancy、延迟隐藏 │ 「我的数据怎么映射到这成千上万个线程？」 ▼ 模块 02 内存与合并 register / shared / global(HBM) 三级；合并访问、bank conflict │ 「怎么搬数据才不浪费带宽？」 ▼ 模块 03 分块矩阵乘 shared-memory tiling 把算术强度从 O(1) 提到 O(tile)；roofline │ 「复用数据 = 把访存受限推成算力受限」 ▼ 模块 04 规约 + softmax 树形规约 O(log n)、warp shuffle、数值稳定 / online softmax │ 「怎么并行地求和/求最大？怎么一遍算完 softmax？」 ▼ 模块 05 FlashAttention 分块 + online softmax 拼成一个内核，永不存 n×n 的 S 「把前四块拼起来 = 显存 O(n²)→O(n) 的精确注意力」

注意这不是松散的专题集合，而是一条严格递进的依赖链：FlashAttention（05）= 分块（03）+ online softmax（04）运行在执行模型（01）与内存层级（02）之上。读到最后一模块，你会发现它没有一个新概念——全是前四模块零件的组装。这也是本课刻意的编排：把一个看似高深的前沿内核，还原成几个朴素零件的乐高拼装，让你确信「我也能写出它」。

每一级台阶都对应一个可独立验证的能力：跑完模块 01 你能算占用率、量化分支发散的代价；模块 02 你能判断一段访问是否合并、为什么 bank 冲突；模块 03 你手写的分块 GEMM 会逐位等于 A@B，并能用 roofline 解释它为何更快；模块 04 你的 online softmax 会与朴素 softmax 对拍一致；模块 05 你拼出的 FlashAttention 会与朴素注意力对拍到 1e-10，且显存只用 O(n)。每一步都有 assert 兜底，绝不靠「感觉对了」。

4方法论：用 numpy 模拟 GPU 并对拍

方法论：没有 GPU，怎么学写 GPU 内核？

本环境没有 GPU、不装 CUDA/Triton。但 GPU 内核的难点从来不是 API 语法，而是并行结构：怎么把数据切块、怎么映射线程、怎么组织规约、怎么让 softmax 增量更新。这些结构用 numpy 在 CPU 上也能精确地表达和验证。

打个比方：学下棋不一定要有红木棋盘。GPU 内核的「棋理」是数据如何分块、线程如何协作、中间状态如何在片上增量维护；这些都是和硬件型号无关的算法结构。一个真实 CUDA 内核里那行 c[idx] = a[idx] + b[idx]，描述的是「单个线程做什么」；硬件并行地把它在所有 idx 上跑一遍。我们在 numpy 里就用一个显式的循环枚举所有 idx——这恰恰是硬件并行执行的那同一组操作，只是我们让它串行跑出来、好观察、好验证。结构一模一样，只差「同时」二字。

直白说

我们把 GPU 的每个机制翻译成 numpy 里看得见摸得着的东西：一个 block 就是一段循环，shared memory 就是一个临时小数组，warp shuffle 就是数组切片相加，online softmax 就是几个流式更新的标量。你写的是结构，不是性能。

严谨说

关键纪律是对拍（differential testing）：每个「内核」都和一个朴素参考实现比对，要求 np.allclose(kernel_out, naive_out, atol=1e-10)。分块 GEMM 必须逐位等于 A@B，FlashAttention 必须逐位等于朴素 softmax 注意力。结构正确 → 数值一致；数值一致 → 你的分块/规约逻辑可以原样搬到 Triton。

GPU 概念本课的 numpy 模拟对应真实工具
block / grid 遍历嵌套 for 循环遍历块下标blockIdx / program_id
shared memory tile切一个小 numpy 子数组__shared__ / tl.load 到 SRAM
warp 内规约对长度 32 的切片做树形/累加__shfl_down
online softmax 状态运行标量 m, l 与输出累加器FlashAttention 的 m_i, l_i, O_i
内核正确性np.allclose 对拍朴素实现单元测试 / 与 PyTorch 对拍

为什么把对拍提到方法论的高度？因为 GPU 内核的 bug 极其阴险：并行竞态、漏写同步、边界越界、数值溢出，往往不会报错，只是悄悄给出看起来差不多但其实错了的结果。在真实 GPU 上这种 bug 要靠 printf 大海捞针；而在 numpy 模拟里，我们有一个绝对可信的朴素参考（直接 A@B、直接朴素 softmax），任何偏差都会被 np.allclose 当场抓住。本课每个内核都先写参考、再写「优化版」、立刻对拍——这套「先有 ground truth，再优化」的纪律，正是真实 kernel 开发（与 PyTorch 对拍）的核心工作流，只是我们在更干净的环境里把它练成肌肉记忆。

务必清楚本课不教什么：不教 CUDA 语法细节、不测真实 GPU 时延、不调寄存器分配、不写真正并发的代码。这些在你有了正确的并行结构后，是第二步（references 里的 CUTLASS、Triton 教程、Nsight 接手）。本课负责把第一步——结构与正确性夯死；这一步搞定，第二步才有意义。

5环境与运行

环境与运行

环境极简：只需 numpy（画 roofline 图可选 matplotlib）。全课 CPU 秒级运行，无需 GPU、CUDA、Triton、torch。

conda create -n gpu-kernels python=3.11 -y && conda activate gpu-kernels
pip install numpy            # 必需
pip install matplotlib       # 可选，仅用于画 roofline / 带宽曲线
jupyter lab

每个模块配一个 notebook，结构统一：先用 numpy 把机制从零实现并对拍（5–6 个 worked 小节，每节都跑出可打印的验证与 assert），再做 3–4 道带 assert 判分的 ✏️ 练习（先给骨架，自己填，再对照 📖 参考答案），最后一个真实数据胶囊（用真实 GPU 的硬件参数或真实模型形状算一笔账，把纸面知识接到现实）。每个 notebook 里都附Triton 伪代码，让你看清 numpy 模拟与真实内核的逐行对应——学完照着把验证过的逻辑写成 @triton.jit 是最自然的下一步。

建议的学习节奏：先读完整章 HTML 建立直觉与理论框架，再打开 notebook 亲手实现。读和做缺一不可——只读会觉得「好像懂了」，真正动手写分块循环、调维度、让 assert 通过时，才会发现魔鬼藏在哪些细节里（边界、转置、数值稳定、校正因子）。这门课的深度正是为「动手」服务的。

配套先读：Horace He《Making Deep Learning Go Brrrr》建立瓶颈三分直觉；CUDA C++ Programming Guide 当字典查执行模型术语；FlashAttention（Dao 2022）是终点站。完整清单见 references.md。

✅ 学完整门课，你应该能：
  1. 把一个算子归类为算力/访存/开销受限，并说出该优化什么；
  2. 解释 thread/warp/block/grid 如何映射数据，算出一个内核的 occupancy 上限；
  3. 判断一段访存是否合并、一段 shared 访问是否 bank 冲突，并给出修法；
  4. 从零写出 shared-memory 分块矩阵乘（对拍 A@B），并用 roofline 论证它为何更快；
  5. 推导并实现 online softmax（一遍流式、对拍稳定 softmax）；
  6. 把以上拼成 FlashAttention（对拍朴素注意力到 1e-10），讲清它显存 O(n)、IO O(n²d²/M) 的来龙去脉；
  7. 把验证过的 numpy 分块逻辑映射到 Triton 伪代码，知道下一步怎么写真内核。
