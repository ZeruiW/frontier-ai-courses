13DGS 做对了什么：一个可以拆成四件事的答案

2020 年 NeRF 用一个 MLP 表示辐射场，渲染一张图要沿每条射线采几十到几百个点、每个点跑一次网络。2023 年 3DGS 把同样的质量做到了实时，而它的做法不是「更快的网络」——它把表示换成了一堆显式的、可光栅化的基元。

NeRF：隐式 + 光线行进 3DGS：显式 + 光栅化 ┌──────────────────────┐ ┌──────────────────────┐ │ f(x, d) -> (σ, c) │ │ {(μ, Σ, α, SH)} × N │ │ 一个 MLP │ │ 几十万到几百万个高斯 │ └──────────────────────┘ └──────────────────────┘ 渲染：每条射线采 N 个点 渲染：把每个高斯投影成 2D 椭圆 每点一次前向 按 tile 分箱 + 排序 成本 ∝ 像素数 × 采样数 × 网络 成本 ∝ (高斯,tile) 对数 ↓ ↓ 秒级 毫秒级

而「换表示」这件事拆开来是四个独立的部件，本课五个内容模块正好对应它们：

部件做什么它单独出错时会怎样在哪个模块
① α 合成把「一串半透明的东西」合成一个像素颜色这是 NeRF 与 3DGS 共用的地基——它决定了「为什么必须排序」01
② 各向异性高斯基元用 $(\mu,\Sigma,\alpha)$ 表示一小团半透明的东西，并投影成 2D 椭圆协方差非正定 → 整个高斯变成无意义的形状；而参数化方式决定了这件事会不会发生02
③ 可微分 tile 光栅化分箱、按深度排序、逐 tile 做 α 合成排序被打乱 → 图像错 20% 以上（第 3 节量出来）03
④ 自适应密度控制按梯度克隆/分裂、按不透明度剪枝不做 → 停在 SfM 点云的密度上，细节永远补不出来04
⑤ 外观与动态球谐表示视角依赖颜色；时间维度SH 阶数 3 的角分辨率是 45°——它表示不了镜面高光，而这是表示能力的限制05

直白说

四个部件里，只有 ② 和 ③ 是 3DGS 独有的。① 与 NeRF 完全共用；④ 在 NeRF 一侧对应的是「采样策略」；⑤ 在 NeRF 一侧是网络的视角输入。所以「3DGS 的贡献」精确地说是：把辐射场的基元从「MLP 的隐式输出」换成「可光栅化的显式椭球」，从而让整条渲染链路变成 GPU 光栅化擅长的形状。

严谨说

而本课把 ① 单独做成一个模块，是因为你在选课时跳过了 NeRF。α 合成不是 3DGS 的一部分——它是体渲染积分的离散化，而 3DGS 与 NeRF 都建立在它上面。模块 01 会把这个等价性验证到机器精度（而顺带得到一个很有用的结论：对分段常数的密度，α 合成是精确的，连 $N{=}1$ 都对）。

2一个「3D 高斯」到底是什么

它不是一个概率分布，虽然数学形式一样。它是一团「密度按高斯衰减的半透明物质」。

\[\sigma(x) = \alpha \cdot \exp\Bigl(-\tfrac12 (x-\mu)^\top \Sigma^{-1} (x-\mu)\Bigr)\]
参数维数含义怎么参数化（这一点很关键）
$\mu$3中心位置直接存
$\Sigma$6（对称）形状与朝向不直接存！存 $(s_1,s_2,s_3)$ 与四元数 $q$，再算 $\Sigma = RSS^\top R^\top$——这样它恒正定（第 2 节）
$\alpha$1不透明度存 logit，过 sigmoid → 恒在 $(0,1)$
SH 系数$3(\ell+1)^2$视角依赖的颜色$\ell{=}3$ 时 48 个浮点数——而它占了每个高斯 59 个浮点数里的 81%

直白说

第二行的参数化是 3DGS 最重要的一个工程决定。如果直接优化 $\Sigma$ 的 6 个分量，梯度下降几步之后它就不再正定，而一个非正定的「协方差」对应不到任何椭球——notebook 第 3 节把这件事量出来：直接参数化时非正定的比例，以及 $RSS^\top R^\top$ 为什么恒正定。

严谨说

而 SH 那一行说明一个容易忽略的事实：3DGS 的内存主要花在颜色上，不是几何上。位置 3 + 缩放 3 + 四元数 4 + 不透明度 1 = 11 个浮点数，而 SH（$\ell{=}3$）是 48 个。100 万个高斯在 $\ell{=}3$ 下是 0.236 GB，而 $\ell{=}0$ 只有 0.056 GB——4.2 倍的差别全在颜色的视角依赖性上（模块 05 会说明这 4.2 倍买到了什么）。

4与既有课程的分工

课程它讲什么分工
C72 · 多视角几何（硬前提）相机模型与畸变、标定、对极/三角测量/单应/PnP、BEV、时空对齐本课直接使用它的投影与雅可比，不再解释。而 3DGS 的输入（相机位姿 + 稀疏点云）正是 C72 与 C75 的产物——所以「3DGS 需要位姿」这句话的完整含义是「它需要一次 SfM」
C73 · 3D 表示与点云深度学习点云/体素/网格/隐式四种表示；置换不变性；稀疏卷积；3D 检测与评测C73 管「离散表示 + 判别式任务」，本课管「连续表示 + 渲染」。交界很有意思：3DGS 的基元是离散的（一堆椭球），而它表示的场是连续的——所以它在两者之间。而 C73 的「量化误差」在本课不存在（高斯有连续的位置），代价是它不再有规则网格可以卷积

C28 · 扩散与流前沿DiT、flow matching、consistency本课不涉及生成——3DGS 是一个拟合方法（每个场景单独优化，不泛化到新场景），而生成式的 3D 在 C75 第 4 节
C36 · GPU 内核与性能工程写 FlashAttention、访存与占用率3DGS 的实时性来自一个手写的 CUDA 光栅化内核，而本课模块 03 讲它的算法结构（分箱、排序、提前终止）而不是 CUDA 实现

5方法论：一个能跑的小光栅化器，而不是一个训练过的场景

本课 notebook 会从零写出一个能出图的 tile 光栅化器（投影、分箱、排序、α 合成、提前终止），并在一个手工搭的合成场景上跑。但它不训练任何真实场景。

直白说

理由与 C73 相同：3DGS 的关键设计几乎都由结构性质决定。「α 合成是顺序相关的」是一个恒等式的性质；「$RSS^\top R^\top$ 恒正定」是一个定理；「前 16 个高斯就饱和」是一个几何级数的计算；「仿射投影的误差由张角决定」是一次泰勒展开的余项。这些都不需要优化收敛，而它们恰好是「为什么必须排序」「为什么这样参数化」「为什么能实时」的全部答案。

严谨说

代价说清楚，有两条。① 本课不能回答「3DGS 的重建质量有多好」——那需要真实多视角数据与几十分钟的优化，属于工程实验；② 本课的「优化」只在一个玩具目标上做几百步，所以模块 04 关于密度控制的结论是机制性的（克隆 vs 分裂各自改变什么、增长率的量级），而不是「这套超参数最好」。所以本课的相对结论可迁移，具体数值只属于本课的合成配置。

每个模块的固定结构

  • 讲解页：机制 → 可验证的量 → 它决定了什么设计

  • 4 道 ✏️ 练习：TODO 骨架 + assert 判分 + 📖 参考答案
