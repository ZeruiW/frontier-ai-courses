# 参考清单 · References（构建编码 Agent）

> 每条注明它解决了什么问题、为什么值得读。先读 ★ 标记的奠基/必读。本课用纯标准库 + MockLLM 模拟的每个机制，都能在下列文献/代码库里找到真实编码 agent 的对应实现与权衡。

## Agent 范式与编码 Agent · Agent Paradigm & Coding Agents
- ★ **Anthropic, _Claude Code_（官方文档与产品）** — 本课的命名与设计灵感来源。Anthropic 官方命令行编码 agent：读改代码库、跑命令与测试、用 MCP 接外部工具。读它的文档能看到一个生产级编码 agent 对外暴露的能力边界与交互约定，正是本课五个模块要从零重建的东西。
- ★ **Yang, Jimenez et al. 2024, _SWE-agent: Agent-Computer Interfaces Enable Automated Software Engineering_** — 编码 agent 的里程碑论文。提出 agent-computer interface（ACI）概念：工具与反馈格式要为 LLM 专门设计（输出简洁、带行号、限长、错误清晰），并实证 ACI 的设计对 SWE-bench 成绩影响巨大。本课模块 01–05 的「对 LLM 友好的工具」原则全部源出于此，强烈建议精读。
- ★ **Yao et al. 2022, _ReAct: Synergizing Reasoning and Acting in Language Models_** — 工具调用 agent 的思想源头。提出让 LLM 交替产出「推理」与「行动」，行动的观察结果再喂回推理。本课 agent 主循环（模块 05）的范式基础。
- **aider（开源项目 `paul-gauthier/aider` 及其文档）** — 流行的 AI 结对编程 CLI。值得读的点：与 git 深度集成、精心设计的 diff/edit 编辑格式（含「search/replace 块」——本课模块 01 字符串替换编辑的直接现实对应）、把仓库结构压成 repo map 喂模型。对照它能看到本课文件工具在生产里的样子。
- **Cognition, _Devin_ / 各家 agentic IDE（Cursor、Windsurf 等）的工程博客** — 把编码 agent 产品化的实践：长任务规划、人在回路、IDE 内的工具与上下文管理。作为本课「之后还能往哪做」的视野延伸。

## 工具使用与 API · Tool Use & API
- ★ **Anthropic, _Tool use (function calling) with Claude_（官方文档）** — 本课对接真实模型的权威依据。讲清 `tools=[{name, description, input_schema}]` 的定义方式、`tool_use` / `tool_result` 内容块的多轮往返、`stop_reason` 如何驱动循环。模块 05 的真实 API 适配段完全照它实现。
- ★ **Anthropic, _Messages API_（API Reference）** — `client.messages.create(...)` 的完整参数与返回结构。理解 messages 列表怎么累积、content 块的类型、如何把工具结果以 `role:"user"` 回填。本课每个 notebook 的「无 key 回退」适配代码以它为准。
- **Anthropic, _Model Context Protocol (MCP)_（规范与 SDK）** — 把「给 agent 加工具」标准化的开放协议。让文件系统、数据库、第三方 API 以统一方式接入 agent。是本课手写工具层的工业级延伸——理解它，你写的工具就能被任何兼容 MCP 的 agent 复用。
- **OpenAI, _Function calling_ 文档（对照阅读）** — 另一主流厂商的工具调用约定。与 Anthropic 的差异（schema 风格、并行调用、消息格式）能帮你抽象出「工具调用」的共性，写出不绑死单一厂商的 agent。
- **Anthropic, _Prompt caching_ / _Token counting_ 文档** — 长跑 agent 的省钱省延迟手段：缓存不变的系统提示与工具定义、预估 token 控制上下文。模块 02/03 的「输出截断」与此同源——都是和上下文窗口/成本的搏斗。

## 评测：编码 Agent 怎么算行 · Evaluation
- ★ **Jimenez, Yang et al. 2023, _SWE-bench: Can Language Models Resolve Real-World GitHub Issues?_** — 编码 agent 的事实标准基准。从真实仓库取「issue + 修复 PR」，agent 在仓库快照上生成补丁，用该 PR 自带测试判定是否解决。本课模块 04/05「以测试是否通过为奖励」的评测视角直接来自它。必读。
- ★ **SWE-bench Verified（OpenAI 与原作者合作的人工筛选子集）** — 剔除描述不清、测试有问题的样本后的可信子集。报告编码 agent 成绩、做横向对比时的现行标准。读它的筛选标准能理解「一个好的 agent 评测样本」长什么样。
- **Chen et al. 2021, _Evaluating Large Language Models Trained on Code_（HumanEval 与 pass@k）** — 代码生成评测的奠基论文，提出 `pass@k` 指标与「用单元测试判正确」的范式。本课「测试通过即奖励」的思想前身。
- **Liu et al. 2023, _Is Your Code Generated by ChatGPT Really Correct?_（EvalPlus）** — 指出测试覆盖不足会高估模型，强化测试。提醒：以测试为奖励时，测试本身的质量决定评测的可信度——对 agent 自测同样适用。
- **Wang et al. 2024 / OpenDevin（现 OpenHands），_An Open Platform for AI Software Developers as Generalist Agents_** — 开源编码 agent 平台与评测，给出工具集、沙箱、轨迹记录的一整套工程参考。想把本课的玩具 agent 扩成真平台时的蓝本。

## 工程基础：本课工具层的标准库依据 · Engineering Foundations
- ★ **Python 官方文档：`subprocess`、`tempfile`、`pathlib`/`os.path`、`difflib`、`re`、`ast`、`glob`** — 本课全部工具的标准库基石。重点：`subprocess.run` 的 `capture_output`/`timeout`/`cwd`（模块 02）、`os.path.realpath` 做路径校验（模块 01）、`difflib.unified_diff` 生成补丁（模块 01）、`re` 与 `ast` 做搜索与符号定位（模块 03）、`tempfile.mkdtemp` 造隔离工作区（全课）。遇到行为细节以官方文档为准。
- **`difflib` 与 unified diff 格式（GNU diffutils 手册）** — 统一差异格式的权威说明：`@@ -a,b +c,d @@` hunk 头的含义、上下文行的作用。理解它，agent 生成/应用补丁、向人展示改动才靠谱。
- **OWASP, _Command Injection_ / _Path Traversal_ 条目** — 安全视角。讲清 shell 注入与路径穿越的成因与防御。本课模块 01 的路径校验、模块 02 的危险命令防护与 `shell=False` 偏好，都是这些条目的具体落地。
- **ripgrep（`BurntSushi/ripgrep`）项目 README 与设计说明** — 现代代码搜索后端的事实标准：为何默认遵守 `.gitignore`、跳过二进制、并行遍历为何快。本课模块 03 用标准库模拟它的行为，读它理解真实工具的取舍。

## 安全、对齐与风险 · Safety & Alignment
- ★ **Anthropic, _Building effective agents_（工程博客）** — 何时该用 agent、何时简单工作流就够；如何用最小的脚手架达成目标、避免过度工程。建立「agent 不是越复杂越好」的判断，贯穿全课的设计取舍。
- **Anthropic / 各家关于 _agent 安全与权限_ 的实践（如工具调用的人在回路确认、沙箱隔离、最小权限）** — 能跑命令、改文件的 agent 是把双刃剑。理解为什么破坏性操作要确认、为什么要在沙箱里跑、为什么要最小权限。本课的超时、危险命令拦截、路径校验、临时目录隔离都是这套思想的入门实践。
- **关于 prompt injection 对 agent 的威胁（社区与厂商讨论）** — 当 agent 会读取外部内容（网页、issue、文件）时，其中可能藏有恶意指令劫持 agent。是给工具加权限边界、不盲目信任工具输入的现实理由。

## 本课定位与衔接 · Scope & Cross-links
- ⚠️ **本课不依赖任何 agent 框架**：所有工具都是几十行纯标准库 Python；所有 notebook 用确定性 `MockLLM` 驱动真实工具循环，文件/shell/pytest 全在 `tempfile` 临时目录里<strong>真实执行</strong>——因此每个 agent 能在玩具仓库里真的把 bug 修好、把测试跑绿，而不只是「看起来对」。
- **无 key 回退契约**：每个 notebook 都附对接 **Anthropic Messages API（tool use）** 的适配代码，检测到 `ANTHROPIC_API_KEY` 与 `anthropic` 包就用真 Claude，否则自动回退 MockLLM。你随时能把验证过的循环切到真实模型，且不会因缺 key 而卡住。
- **可迁移性**：你在本课写出的工具（read/write/edit/diff、shell、grep/glob、test runner）与 agent 主循环，结构上与 SWE-agent / aider / Claude Code 一致；把 MockLLM 换成真实 Messages API 调用即可面对真实仓库。本课刻意让工具签名贴近真实 agent。
- **课程衔接**：上游接 C04（Agent 基础 / 工具使用）；同系列横向接「造通用 Agent」「造 Skills 系统」；下游可接评测课（SWE-bench 式自动判分）与安全课（agent 权限、沙箱、prompt injection）。
