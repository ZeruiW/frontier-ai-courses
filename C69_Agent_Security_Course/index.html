Agent 安全与提示注入

C05 讲「模型会不会说不该说的话」，C44 讲「扰动能不能改变模型的判断」。而当模型能行动时，出现了第三个问题：谁在实际控制这些行动。本课的核心主张：LLM 没有「数据 / 代码」的结构性分隔，所以提示注入没有「参数化查询」那样的彻底解法——因此全部防御思路都不是「消除注入」，而是「限制注入成功后能造成的后果」。不要问「怎么挡住提示注入」，要问「注入成功之后它能做什么，以及我怎么把那个集合缩小」。

6 模块 致命三要素：不受信内容 · 私密数据 · 对外通信 trust(输出) = min(上下文) 架构 > 检测 ASR@k · 自适应评测 纯 numpy · CPU · 断网可跑
怎么用： 先读模块的 NN_讲解.html，再跑同目录下的同名 .ipynb。本课的 notebook 里不包含针对任何真实系统的可用攻击载荷——被攻击的 agent 是一个几十行的规则匹配器，「注入」是形如 [[INJECT:action]] 的占位符标记。这样做不是为了回避，而是因为它更适合教学：你要学的是「信任等级怎么传播」「权限边界怎么设计」「攻击成功率怎么统计」这些结构性的东西，而这些用模拟器验证得更清楚、更可复现（服从注入的概率是一个可调旋钮，让你能研究「防御把 ASR 从 42% 降到 0.3%」这类定量问题）。真实的注入手法在讲解里以机制层面描述——足以让你设计防御，但不给可直接复制的载荷。而权限系统、出站白名单、审计日志、金丝雀判分是真实实现，因为它们本来就不需要真实模型。
