# C69 · Agent 安全与提示注入

> **一句话**：不要问「怎么挡住提示注入」，
> 要问「**注入成功之后它能做什么，以及我怎么把那个集合缩小**」。

6 个模块 · 纯 numpy / CPU / 断网可跑 · 每个模块 4 道 `✏️ 练习`（assert 判分）+
`📖 参考答案` + `🧪 真实工程胶囊`。

## 关于本课的教学约定（请先读这一段）

**本课的 notebook 里不包含针对任何真实系统的可用攻击载荷。**

- 被攻击的 agent 是一个几十行的规则匹配器；
- 「注入内容」是形如 `[[INJECT:read_secret]]` 的占位符标记；
- 模型「服从注入」的概率是一个**可调旋钮**——这让你能定量研究
  「某个防御把 ASR 从 42% 降到 0.3%」这类问题；
- 真实的注入手法在讲解里以**机制层面**描述（足以让你设计防御），不给可复制的载荷。

**而防御侧全部是真实实现**：权限系统（能力四维）、路径与域名的范围检查、
出站白名单与四类绕过、审计日志与 provenance 链、金丝雀判分、
工具清单锁——因为它们本来就不需要真实模型。

## 这门课补的洞

| 已有 | 覆盖了什么 | 缺什么 |
|---|---|---|
| **C05** · 模型安全评测与红队 | 危险能力评估、拒答与鲁棒性、越狱、安全案例 | **对象是「模型会说什么」**，不是「agent 会做什么」 |
| **C44** · 对抗与安全 | 对抗样本、扰动、后门 | 攻击目标是*模型的判断*，不是*系统的动作* |
| **C26 模块 05** | agent 评测与安全概览（半节） | 间接注入、权限边界、出站控制、攻击面评测全部没有 |
| **C34 模块 03** | 权限的实现 | 权限该怎么*设计*、怎么*评测* |

核心主张：

> **传统软件里「数据」和「代码」是两种东西**——SQL 注入能被参数化查询彻底解决，
> 是因为数据库能在结构上分开「查询语句」和「用户填的值」。
> **而在 LLM 里两者都是同一串 token，模型没有任何机制去区分。**
> 因此本课的全部防御思路不是「消除注入」，而是**限制注入成功后的后果**——
> 从「阻止攻击」转向「控制爆炸半径」。

## 三条防御姿态（决定了模块顺序）

1. **架构 > 检测。**
   去掉「致命三要素」里的一个，比训练一个更好的注入分类器有效得多，
   *而且它的效果不依赖攻击者的水平*。**先做权限与出站，再做检测。**
2. **假设注入会成功，设计爆炸半径。**
   目标不是「让注入失败」，而是「注入成功之后攻击者能做的最坏的事是什么」——
   这个问题有确定的答案（= agent 的权限集），而且可以被系统性地缩小。
3. **可逆操作与不可逆操作分开对待。**
   读文件、查数据可以自动做；发邮件、转账、删除、推送代码必须有一个
   **不接触 L0 内容**的确认环节。

## 上线前的三个问题（致命三要素）

```
① 这个 agent 会接触不受信任的内容吗？        （几乎总是「会」）
② 它能访问私密数据吗？
③ 它能对外通信吗？
   ——注意「对外通信」包括：渲染外链图片、生成可点击链接、
     写入会被别人读到的位置、以及**任何域名解析**

三个都是「是」→ 数据外泄链路完整。**先想办法去掉第三个。**
```

## 学习路径

### 路径 A · 完整走一遍（约 10–12 小时）

`00 → 01 → 02 → 03 → 04 → 05`，每天一个模块。

判断走完了没有的标准：**给你一个 agent 系统的架构图，
你能不能在十分钟内画出它的六个输入入口、列出它的危险组合、
并指出「注入成功之后攻击者能做的最坏的事」。**

### 路径 B · 手上有一个 agent 要上线（约 4 小时）

`00 全部 → 03 全部 → 04 第 3/6 节（白名单与清单）→ 02 第 5 节（工具集裁剪）`。

理由：**这四块是「做了就立刻降低真实风险」的部分**，而且都是架构层的动作，
不依赖任何检测能力。01 的注入机制与 05 的评测可以之后补。

### 路径 C · 只有两小时

`00 的致命三要素与 trust=min → 03 的能力四维 → 04 的十种通道与白名单`。

这三块是「知道了就能立刻改架构」的部分。
