### C62 · 编程面试实战：算法与数据结构

**m00** `00_setup | 00_overview.html | 00_environment_check.ipynb`
H1: `00 · 课程总览与环境`
要点：一面 coding 真正考什么——**不是难题，是「能否在压力下写出正确、可测、能讲清楚的代码」**；
**六步答题协议**（复述澄清 → 举例走一遍 → 先给暴力解 → 说优化思路 → 再写代码 → 测试与复杂度）
及每步的时间预算（45 分钟怎么分）；面试官的五维评分表（正确性/复杂度/代码质量/沟通/测试意识）；
**ML/CV 岗 coding 题的分布特点**（矩阵与几何、区间、采样、字符串解析偏多，纯图论/高级数据结构偏少）
并给出统计式的题型优先级；Python 面试子集（哪些内置该大方用、哪些会被判"绕过考点"，
如直接 `sorted` 考排序题、`collections.Counter` 考哈希题的边界）；本课与 C61 的分工。
NB：六步协议自检器；复杂度速查与经验换算（n 的量级 → 可接受复杂度）；
一道完整例题的**全流程逐步演示**（含"面试官会在这里追问什么"的旁注）。

**m01** `01_arrays_strings | 01_讲解.html | 01_arrays_strings.ipynb`
H1: `01 · 数组与字符串：双指针、滑动窗口、前缀和`
要点：**双指针三形态**（对撞 / 快慢 / 同向）各自的适用信号与循环不变量；
**滑动窗口**的定长与可变两套模板、何时收缩、如何证明不漏解；
**前缀和与差分**（一维、二维——二维前缀和就是图像里的积分图，直接连到 CV）；
原地修改与 O(1) 空间技巧；**边界条件清单**（空、单元素、全相同、极值、溢出、重复元素）；
与 CV 的连接：IoU 的区间求交本质是双指针、NMS 是排序+扫描、bbox 统计可用积分图加速。
NB：从零实现并单测 ≥10 道经典题（两数之和/三数之和、最长无重复子串、盛最多水的容器、
区间合并、和为 K 的子数组、最小覆盖子串、二维前缀和求任意矩形和、原地移除元素…），
每题含暴力解与最优解**对拍**、复杂度断言、边界用例。

**m02** `02_hash_sort_search | 02_讲解.html | 02_hash_sort_search.ipynb`
H1: `02 · 哈希、排序与二分`
要点：哈希表原理与**Python `dict`/`set` 的复杂度陷阱**（均摊 O(1) 但最坏 O(n)、
可哈希性、浮点数做 key 的坑）；自定义排序键、**稳定性为什么重要**（NMS 分数相同时的确定性）；
**二分的三套模板**（找精确值 / 找左边界 / 找右边界）与循环不变量的严格表述，
以及 `lo/hi` 开闭区间不一致导致的死循环；**在答案上二分**（最小化最大值 / 最大化最小值类问题，
这是中高频题型）；**Top-K 的三种解法**（全排序 O(n log n) / 堆 O(n log k) / quickselect O(n) 均摊）
与选择依据；去重与计数的惯用法。
NB：手写三套二分并用不变量断言 + 与 `bisect` 对拍；手写 quickselect 与堆解法并计时对比；
多关键字自定义排序（含稳定性演示）；在答案上二分的完整例题；≥8 道经典题单测。

**m03** `03_trees_graphs | 03_讲解.html | 03_trees_graphs.ipynb`
H1: `03 · 树、图与搜索`
要点：递归三要素（终止 / 拆解 / 合并）与**递归转迭代**（显式栈）；
二叉树的四种遍历与层序；**BFS vs DFS 的选择信号**（最短步数用 BFS、路径/回溯用 DFS）；
**并查集**（路径压缩 + 按秩合并，含复杂度）——**直接对应检测里的框聚类与切片推理的跨片合并**；
网格 BFS/DFS —— **就是图像的连通域标记（8 邻域）**；拓扑排序与环检测；
最短路的最简形态（BFS / Dijkstra 骨架）。
NB：并查集完整实现并**用于 bbox 聚类**（把 IoU>阈值 的框并成一类，与逐对比较对拍）；
网格连通域标记（4/8 邻域，与逐像素扫描法对拍）；BFS 最短路；拓扑排序；
二叉树遍历的递归与迭代双实现对拍；把 NMS 表述成**图上的极大独立集**并讨论贪心近似。

**m04** `04_dp_greedy | 04_讲解.html | 04_dp_greedy.ipynb`
H1: `04 · 动态规划与贪心`
要点：**DP 五步**（状态定义 → 转移方程 → 初始化 → 遍历顺序 → 答案位置）与
「状态定义错了后面全错」的诊断法；一维 / 二维 / 背包（01 与完全）/ 区间 / 序列 DP 五类模板；
**空间压缩**（滚动数组）与它对遍历顺序的约束；记忆化搜索与递推的互转；
**贪心的正确性论证**（交换论证 exchange argument；给出一个"看起来对但错"的反例）；
DP 与贪心的判别方法；与 ML 的连接：编辑距离 ↔ 序列评测、区间调度 ↔ NMS 的最优选择、
DTW ↔ 时序对齐、背包 ↔ 算力预算下的方案选择（呼应 C57-05 的方案排序）。
NB：编辑距离、LCS、01 背包（含空间压缩）、最长上升子序列（O(n²) 与 O(n log n) 对拍）、
区间调度；**把 NMS 建模成加权区间调度，用 DP 求最优解并与贪心 NMS 对比**（量化贪心的次优程度）；
每题含状态定义的文字说明与单测。

**m05** `05_mock_drills | 05_讲解.html | 05_mock_drills.ipynb`
H1: `05 · 模拟面试与压力下的编码`

## §C 本批特有的写作要求

1. **每一题/每一个知识点都要给「面试官想听什么」**。这批课的读者是要去面试的人，
   不是要通过考试的学生——所有内容都要能翻译成"当场怎么说"。

   有注释说明不变量；不要为了炫技写一行流。**每题都要有暴力解与最优解的对拍**。
3. **锚定 TSR / CV 岗位**：C62 优先选 ML/CV 岗真实高频题型（矩阵、区间、采样、几何）；
   C63 的主案例是 TSR；C64 的例子尽量取自视觉与检测；C65 的场景取自感知工程。
   但**不要重复 C53–C61 的内容**，需要时用「见 CXX-XX」引用。
4. **诚实标注难度与频率**：每道题标「高频/中频/低频」与「必会/加分」，
   帮助读者在有限时间里排优先级。
5. **notebook 必须可自测**：C62 每题带单测与对拍；C64/C65 的题库要做成
   可交互自测引擎（随机抽题、隐藏答案、记录掌握度）。
6. 其余（coursekit API、可见字符 ≥8600、NB ≥30 cells、DUAL/CALLOUT/TABLE/ASCII/MATH
   的数量要求、末节「研究前沿与开放问题」+ paper callout、纯 numpy/CPU/不联网、
   assert 必须真能通过）**全部沿用 `GAPKIT_SPEC.md` §1–§4、§7**。
7. **验证要用两遍执行**：写完后除了按序 exec，还必须**在参考答案生效后重跑练习自测 cell**
   （参见 `_buildkit/runnb2.py`）。单遍执行会让练习的 assert 被 `NotImplementedError` 跳过，
   造成"假通过"。
