## 4. notebook 规范

- **纯 numpy + 标准库，CPU 可跑，无需 GPU / torch / mmdet**。禁止联网下载。
  需要"数据"时用 `np.random` 按物理合理的方式合成（并说明合成规则），
  或用 `sklearn.datasets` 里的内置小数据集。
- 结构（严格按此顺序）：
  1. `md` 标题 cell：`# NN · 模块名（关键词1 / 关键词2 / …）` + 目标说明 + 「本 notebook 你会亲手实现什么」列表
  2. **5–6 个 worked 小节**：`## 1 · xxx` → code cell（含 `print` 展示 + `assert` 自校验）
  3. **3–4 道 ✏️ 练习**：`## ✏️ 练习 N：xxx` → 带 `TODO` 骨架的 code cell → 紧跟一个
     `# —— 练习 N 自测 ——` 的 assert 判分 cell
  4. `---` 分隔 → `### 📖 参考答案（先自己做，再对照）` → 每题一个答案 code cell
  5. `---` → `## 🧪 真实工程胶囊` → 一个 code cell，内容是可原样复制到真实项目的
     配置/命令/代码片段（用 `RECIPE = r'''...'''` + `print(RECIPE)` 的形式）
  6. `### 小结` md cell：3–5 条本模块的可迁移结论
- 每个 code cell 都要能**独立成功运行**（前面 cell 按顺序执行后）。
  变量命名清晰，关键行加简短中文注释。
- `assert` 必须真的能通过。写完后你要**在脑中逐行验算**，数值敏感的地方用
  `np.allclose` 而非 `==`。

### C54 · 端到端集合预测检测（DETR 家族）

**m00** `00_setup | 00_overview.html | 00_environment_check.ipynb`
H1: `00 · 课程总览与环境`
要点：集合预测（set prediction）的核心命题——把检测从"密集预测 + NMS 去重"变成

**m01** `01_hungarian | 01_讲解.html | 01_hungarian_matching.ipynb`
H1: `01 · 二分图匹配与匈牙利算法`
要点：为什么需要匹配（预测无序、GT 无序，损失要先对齐）；二分图最优匹配的形式化
（代价矩阵 + 一对一约束 + 总代价最小）；**匈牙利算法/Kuhn-Munkres 的完整机理**
（增广路径、对偶变量、O(n³)）；匹配代价的三项设计（分类项用概率而非 log、L1 项、
GIoU 项）与权重敏感性；padding 到 N 个 query 与 no-object；**为什么一对一匹配能替代 NMS**
（训练期就压制重复，而不是推理期删重复）；匹配的不稳定性问题（同一 GT 在相邻 epoch
被不同 query 认领 → 梯度方向震荡 → 收敛慢），这是后面 DN-DETR 的动机。
NB：从零实现匈牙利算法（scipy 不许用，自己写增广路径版本），与暴力枚举对拍；
实现 DETR 的完整代价矩阵；量化"匹配不稳定性"（模拟训练噪声，统计匹配翻转率）。

**m02** `02_set_loss | 02_讲解.html | 02_set_prediction_loss.ipynb`
H1: `02 · 集合预测损失：匹配之后怎么算账`
要点：Hungarian loss 完整公式（分类 CE + 框 L1 + GIoU，仅对匹配上的 query 算框损失）；
no-object 类的权重（背景 query 占绝大多数，不降权会压垮前景）；**为什么必须 L1 + GIoU 组合**
（L1 对尺度敏感、IoU 对不相交无梯度，GIoU 补上）；GIoU/DIoU/CIoU 的定义与梯度性质；
辅助损失（每层 decoder 都算损失）为什么显著加速收敛；损失权重的典型配比与调参经验；
**集合损失与 focal loss 的关系**（后续工作把 CE 换成 focal）。
NB：从零实现 IoU/GIoU/DIoU/CIoU 及其梯度（数值梯度校验）；完整 Hungarian loss 实现；
no-object 权重的消融实验（合成数据上看前景召回随权重变化）。

**m03** `03_queries | 03_讲解.html | 03_object_queries.ipynb`
H1: `03 · Object query 与交叉注意力：模型如何"认领"目标`
要点：query 到底是什么（可学习的位置嵌入，不是特征）；decoder 中 self-attention（query
之间去重协商）与 cross-attention（从图像特征取证据）各自的职责——**这个分工是理解
DETR 的关键**；query 的空间特化现象（训练后每个 query 偏好特定区域与尺度）；
query 数量 N 的选择（必须 > 单图最大目标数，太大浪费且降低正样本比例）；
DAB-DETR 的 4D anchor box query（把 query 显式解释为框，让 cross-attention 有空间先验）；
Anchor-DETR / Conditional DETR 的思路；**query 与 anchor 的本质异同**（面试爱问）。
NB：实现单头/多头注意力（numpy）；实现 decoder 的一层（self-attn + cross-attn + FFN）；
可视化 query 的空间特化（用合成任务训练一个极小的匹配模型，看 query 学到的偏好）。

**m04** `04_convergence | 04_讲解.html | 04_convergence_family.ipynb`
H1: `04 · 收敛难题与 DETR 家族演进`
要点：DETR 需要 500 epoch 的**两个根因**（① cross-attention 初期近似均匀，梯度稀疏；
② 匹配不稳定导致优化目标抖动）；**Deformable DETR**：可变形注意力（每个 query 只采样
K 个点，采样位置可学）+ 多尺度 + 两阶段，把 500 epoch 压到 50；**DN-DETR**：把带噪 GT
作为额外 query 去噪，绕过匹配 → 稳定优化；**DINO**：对比去噪（正负噪声对）+ mixed query
selection + look forward twice，成为长期 SOTA 骨架；**一对多匹配的回归**（Group DETR /
H-DETR / Co-DETR：训练时加一对多分支提供密集监督，推理时丢掉）——这说明"一对一"是
推理需求而非训练最优；演进脉络的**一句话总结**（每一步都在解决"监督信号太稀疏"）。
NB：实现可变形注意力的采样与双线性插值（含梯度）；模拟对比 DETR vs Deformable 的
有效梯度密度；实现 DN 去噪 query 的构造（噪声框生成 + 标签翻转 + attention mask 隔离）。

这对车端多硬件平台意味着什么；`trtexec` 的常用姿势
（构建、profile、逐层耗时、验证）；plugin 与自定义层（什么时候不得不写）；
**静默回退**：不支持的算子被切成子图交给其他后端，模型能跑但不快，
症状是"转了 TRT 但没变快"，要看分区日志。
NB：实现一个迷你图 IR + 融合规则引擎（Conv+BN 融合的数值等价证明）；
实现层融合前后的 FLOPs/访存量对比；

**m03** `03_int8 | 03_讲解.html | 03_int8_calibration.ipynb`
H1: `03 · INT8 校准与精度恢复`
要点：INT8 量化回顾（scale/zero-point、对称 vs 非对称、per-tensor vs per-channel）；
**校准算法**：MinMax（受离群值毁灭）、**Entropy/KL**（TensorRT 默认，
最小化量化前后分布的 KL 散度，原理与实现）、Percentile（截断 99.9%）——
三者的适用场景与失效场景；**校准集的构造是最容易做错的一步**：
必须覆盖长尾与极端场景（夜间、逆光、雨天），几百到上千张，
且预处理必须与线上完全一致——**用训练集头 500 张（可能全是晴天白天）是经典错误**；

量化对检测的特殊影响（分类头 vs 回归头敏感度不同、小目标更敏感）；
**QAT 何时值得**（PTQ 掉点 > 1-2 mAP 且无法用混合精度救回时）；
**量化掉点排查决策树**（完整流程，面试高频）。
NB：实现 MinMax/Percentile/**KL 熵校准**（完整算法：直方图、候选阈值、
KL 散度最小化）；对比三者在含离群值分布上的表现；
实现逐层敏感度分析与混合精度方案搜索；
构造"校准集分布不匹配"实验量化其危害。

**m04** `04_postprocess | 04_讲解.html | 04_postprocess_cpp.ipynb`

**m05** `05_profiling | 05_讲解.html | 05_profiling_latency.ipynb`
H1: `05 · 性能剖析与延迟工程`
