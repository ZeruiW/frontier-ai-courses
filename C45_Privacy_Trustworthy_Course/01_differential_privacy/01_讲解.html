1从「去标识」到差分隐私：范式转变

在有差分隐私之前，「保护隐私」基本等于去标识（de-identification）：把姓名、身份证、电话这些直接标识符删掉或替换，剩下的就当作匿名数据发布。这套思路统治了几十年，也一次次被攻破。最著名的两记耳光：Netflix 在 2006 年发布「匿名」的观影评分数据集做推荐比赛，研究者用公开的 IMDb 评分一对照，就重新识别出了大量用户；AOL 同年发布「匿名」搜索日志，记者顺着搜索内容里的蛛丝马迹找到了具体的人。教训是结构性的：只要还保留着足够的「准标识符」（quasi-identifier，如年龄+邮编+性别），攻击者就能拿外部数据来linkage attack（链接攻击）拼出身份。

问题出在哪？去标识把隐私定义成了「数据里有没有标识符」，这是个关于数据的属性，而隐私其实是个关于算法的属性。你永远不知道攻击者手里还有什么外部信息可以拿来链接——所以「删掉哪些字段才安全」这个问题根本没有可靠答案。差分隐私的革命性，在于它换了一个完全不同的问题：不问「数据里有什么」，而问「我这个发布算法，对任何单个人在不在数据里，敏不敏感？」如果一个人加入或退出数据集，几乎不改变算法的输出分布，那么任何攻击者——无论他手里有多少外部信息——都无法从输出里确定这个人的存在或他的数据。

直白说

差分隐私给你一个承诺：「不管你的数据在不在这次分析里，分析结果几乎都一样。」于是你可以放心提供数据——因为你的参与几乎不影响任何被发布的结论，攻击者也就无从针对你。隐私不再是「希望没人能链接」，而是「数学上保证单人影响极小」。

严谨说

形式上，DP 是一个关于随机算法的定义。它要求算法 $M$ 在任意一对neighboring datasets（相邻数据集，只差一条记录）$D, D'$ 上，输出分布足够接近。「接近」用一对参数 (ε,δ) 量化。关键转变：隐私不是输入数据的性质（能被外部信息打破），而是机制本身的性质——它对任意后处理、任意先验知识都成立，这正是去标识做不到的。

范式转变

一句话记住 DP 取代了什么：「匿名化」是关于数据的、脆弱的、可被链接攻击打破的；差分隐私是关于算法的、可证明的、对任意外部知识都成立的。这也意味着 DP 给的是最坏情况保证——它不假设攻击者无知，反而假设攻击者知道除目标外的一切（甚至知道整个数据集只差你这一条），在此之下仍保护你。这种偏执正是它可靠的来源。

2(ε,δ)-DP 的定义

(ε,δ)-DP 的定义

先把定义摆出来，再逐项拆解。一个随机算法 $M$ 满足 (ε,δ)-差分隐私，如果对所有相邻数据集 $D, D'$（只差一条记录）和所有可能的输出集合 $S$：

\[\Pr[M(D)\in S]\ \le\ e^{\varepsilon}\,\Pr[M(D')\in S]\ +\ \delta\]

逐项读懂这个不等式：$M(D)$ 是算法在数据集 $D$ 上的（随机）输出，$M(D')$ 是在去掉/换掉一条记录后的输出。不等式说：观察到任何一组结果的概率，在 D 和 D′ 上最多相差 $e^{\varepsilon}$ 倍（外加一个极小的 δ 松弛）。因为它对所有相邻对、所有输出集合都成立，所以无论攻击者关心哪个个体、用什么方式分析，他都无法靠输出可靠地区分「这个人在不在数据里」。

参数含义怎么选直觉
$\varepsilon$ (epsilon)隐私损失上界（乘性）越小越私密；实践常见 0.1 ~ 10$e^{\varepsilon}$ 是两个世界的概率比上限：ε=0 完全无法区分，ε 大则可区分
$\delta$ (delta)允许上界被突破的概率（加性松弛）取极小，理想 $\le 1/N$（N=数据量）「灾难性泄露」的概率上限；δ=0 时退化为更强的纯 ε-DP

为什么用乘性的 $e^{\varepsilon}$ 而不是加性的差？因为隐私关心的是似然比：攻击者看到输出 o 后，更新「这人在数据里」的信念，更新幅度正比于 $\frac{\Pr[M(D)=o]}{\Pr[M(D')=o]}$。把这个比限制在 $[e^{-\varepsilon}, e^{\varepsilon}]$ 内，就限制了攻击者从任何观察中能学到的关于单个个体的信息——这是一个贝叶斯式的保证：无论攻击者的先验信念是什么，看到 DP 输出后他对「某人是否在数据里」的后验，相比先验最多移动 ε 这么多。ε 因此被称为「隐私损失」的预算——这也引出后面的组合与预算管理。

一个常被忽略却很要紧的细节：「相邻」到底指什么？有两种约定。无界 DP（unbounded）把相邻定义为「增 / 删一条记录」（D′ 比 D 多或少一行），保护「你在不在数据里」；有界 DP（bounded）把相邻定义为「改一条记录」（D 与 D′ 行数相同、只有一行内容不同），保护「你的那一行是什么」。两者的敏感度可能差一倍（改 = 删+增），所以报告 ε 时必须说清用的是哪种相邻关系，否则同一个 ε 含义不同。本课默认用「增删一条」的无界定义，与 DP-SGD 的「采样一个样本」自然对应。

δ 不是可以随便取的小数。直觉上，一个「以概率 δ 直接把某人完整数据吐出来、其余时候完美隐私」的算法也能满足 (0,δ)-DP——所以 δ 必须远小于 1/N，否则「偶尔彻底泄露一个人」就成了合法行为。记住经验法则：ε 是你关心的隐私强度旋钮，δ 取一个可忽略的极小值（如 $10^{-5}$ 或 $1/N^{1.1}$）。还有一条容易踩的坑：DP 保护的是单个个体；若同一个人贡献了多条记录，或要保护一整个家庭/群体，需要用群体隐私（group privacy）——保护 k 个人会让 ε 放大到约 kε。

3敏感度：噪声的源头

敏感度：要加多少噪声的源头

DP 机制的核心动作是给真实答案加噪声，而加多少噪声，取决于这个查询有多「敏感」。sensitivity（敏感度）刻画的是：一条记录的变化，最多能让查询结果变多少。对一个数值查询 $f$：

\[\Delta_1 f=\max_{D\sim D'}\lVert f(D)-f(D')\rVert_1,\qquad \Delta_2 f=\max_{D\sim D'}\lVert f(D)-f(D')\rVert_2\]

$\Delta_1$（L1 敏感度）配 Laplace 机制，$\Delta_2$（L2 敏感度）配 Gaussian 机制。直觉：敏感度大，说明单个人能强烈影响结果，就得用大噪声把这个影响盖住；敏感度小，少量噪声就够。

举几个例子把它算实：计数查询「有多少人得了某病」——加或减一个人，计数最多变 1，所以 $\Delta_1=1$。求和查询「年龄总和」——若年龄被限定在 $[0,120]$，一个人最多贡献 120，则 $\Delta_1=120$（这说明限定取值范围（clipping）是控制敏感度的关键手段，后面 DP-SGD 的梯度裁剪正是同一招）。均值查询「平均年龄」——和除以 N，敏感度约 $120/N$，随数据量增大而减小（大数据集天然更易私有）。

敏感度是 DP 里最容易算错、也最关键的一步。记住两条：① 敏感度是最坏情况（对所有相邻数据集取 max），不是平均情况；② 想降噪声，就想办法降敏感度——给每条记录的贡献设上界（clip）。这条「限制单样本贡献」的思想会在模块 02 变成「逐样本梯度裁剪」，是把 DP 装进训练的钥匙。

4Laplace 机制：纯 ε-DP

Laplace 机制：纯 ε-DP

有了敏感度，第一个具体机制呼之欲出。Laplace mechanism：给查询结果加上均值 0、尺度 $b=\Delta_1 f/\varepsilon$ 的 Laplace 噪声，给出纯 ε-DP（δ=0）：

\[M(D)=f(D)+\mathrm{Lap}\!\left(b=\frac{\Delta_1 f}{\varepsilon}\right),\qquad p(x)=\frac{1}{2b}e^{-|x|/b}\]

为什么恰好是这个尺度？Laplace 分布的密度是 $e^{-|x|/b}$ 形状，两个相隔 $\Delta_1 f$ 的真值（来自相邻数据集）所对应的密度之比，处处不超过 $e^{\Delta_1 f/b}$。令这个比 $\le e^{\varepsilon}$，解出 $b\ge\Delta_1 f/\varepsilon$。敏感度越大、ε 越小（要求越私密），噪声尺度 b 越大——隐私-效用权衡在公式里一目了然。

# Laplace 机制：对一个计数查询加噪（伪代码，notebook 会实现并验证）
b = sensitivity / epsilon          # 尺度
noisy = true_count + np.random.laplace(0.0, b)
# epsilon 越小 -> b 越大 -> 噪声越大 -> 越私密但越不准

Laplace 机制适合L1 敏感度有界的数值查询：计数、求和、直方图。它的优点是给的是最坏情况、对任何输出都成立的纯 ε 保证（没有 δ 那个「偶尔翻车」的口子）；缺点是当输出是高维向量时，L1 噪声比 L2 噪声更「重」，所以高维场景（如梯度）通常改用下面的高斯机制。

这里值得补一句机制的谱系：Laplace（数值查询）和 Gaussian（高维/可组合）只是 DP 机制家族的两员。还有专门处理非数值输出的exponential mechanism（指数机制）——当你要从一堆候选里选一个（如「哪个商品最热门」「哪个模型最好」）而非加噪一个数时，指数机制按每个候选的「效用分」以 $\propto e^{\varepsilon\cdot\text{效用}/(2\Delta)}$ 的概率随机选，让高效用候选更可能被选中、却仍满足 ε-DP。本课聚焦 Laplace/Gaussian（它们直接通向 DP-SGD），但记住「加噪」只是 DP 的一种实现方式，核心永远是「让单人不影响输出分布」——指数机制用随机选择达到同样的目的，思想一脉相承。

怎么验证「我的 Laplace 机制真的是 ε-DP」？理论上 b=Δ/ε 即可。但在 notebook 里我们还会做经验验证：在一对相邻数据集上各跑机制很多次，估计输出落在某区间的概率比 $\frac{\Pr[M(D)\in S]}{\Pr[M(D')\in S]}$，验证它不超过 $e^{\varepsilon}$。这种「用经验分布检查隐私保证」的思路，正是隐私审计（模块 05）的雏形——也是检验一个 DP 实现有没有 bug 的最实用手段（噪声加错、敏感度算错，经验比值会立刻穿帮）。

5Gaussian 机制与 (ε,δ)-DP

Gaussian 机制与 (ε,δ)-DP

第二个核心机制是 Gaussian mechanism：加高斯噪声。它给的是 (ε,δ)-DP（带一个 δ 口子），配L2 敏感度。经典的充分条件是：

\[M(D)=f(D)+\mathcal{N}(0,\sigma^2 I),\qquad \sigma\ \ge\ \frac{\Delta_2 f\,\sqrt{2\ln(1.25/\delta)}}{\varepsilon}\quad(\varepsilon<1)\]

为什么要引入一个会「偶尔翻车」（概率 δ）的机制，而不是一直用更干净的 Laplace？两个理由。其一，高维下高斯噪声更省：对 d 维向量，Laplace 要按 L1 敏感度加噪（各维独立、噪声随维度线性涨），而高斯按 L2 敏感度（随 $\sqrt{d}$ 涨），在梯度这种高维对象上高斯的总噪声小得多。其二，也是更重要的——高斯机制的组合性质极好：多个高斯机制叠加仍是高斯式的隐私损失，可以用 RDP / moments accountant（模块 02）紧致地累加。这两点让高斯机制成为 DP-SGD 的默认选择（梯度高维 + 要叠加成千上万步）。

直白说

Laplace vs Gaussian 怎么选？低维、要最强保证（δ=0）、查询是计数/求和 → Laplace；高维（尤其梯度）、要把很多步叠起来 → Gaussian。本课模块 01 两个都实现，模块 02 的 DP-SGD 专用 Gaussian。

严谨说

注意上面的 $\sigma$ 公式只是一个充分条件（在 $\varepsilon<1$ 时成立），并不紧。现代实现（Balle & Wang 2018 的 analytic Gaussian）用数值方法解出精确的最小 $\sigma$，在高隐私区能省下可观噪声。但充分条件足以建立直觉：$\sigma\propto\Delta_2 f/\varepsilon$，且要更小的 δ 就要更大的 $\sigma$。

一个常见误解：以为 δ 越小越好、干脆设 0。设 δ=0 就退化成纯 DP，高斯机制不满足纯 DP（高斯尾巴再细也非零，总有极小概率产生区分性极强的输出）——这正是那个 δ 口子的来源。所以高斯机制必然带 δ；要 δ=0 就得用 Laplace。理解这一点才不会在标定噪声时把公式用错。

6组合定理与隐私预算

组合定理与隐私预算

现实中你很少只查一次数据。每多做一次 DP 查询，就多泄露一点——隐私损失会累加。composition theorem（组合定理）就是回答「累加了多少」的数学，它把 ε 变成一种可消费的预算。

组合方式总隐私损失适用场景直觉
基本组合 basic$k$ 次 ε-DP → $k\varepsilon$（线性相加）任意多次查询的保守上界每次花 ε，花 k 次就花了 kε
高级组合 advanced约 $\varepsilon\sqrt{2k\ln(1/\delta')}$（牺牲微小 δ′）大量查询时紧得多随机正负噪声部分抵消 → √k 而非 k
并行组合 parallel数据切成不相交子集各查 → 取 $\max$ 而非和直方图、分组统计每个人只落在一个子集里，只被花一次预算

两条组合要分清。串行组合（sequential）：在同一份数据上反复查，预算相加——查得越多越不私密。并行组合（parallel）：把数据切成互不相交的块各查一次（如直方图的每个桶独立加噪），总预算取各块的最大值而非求和——因为任何一个个体只属于一个块、只被消费一次预算。理解这个区别能在设计中省下大量预算：能并行就别串行。

还有一个让 DP 真正好用的性质——后处理免疫（post-processing immunity）：对一个 (ε,δ)-DP 算法的输出做任何不再碰原始数据的处理（画图、聚类、喂给下游模型、人工分析），隐私保证不变。这意味着隐私一旦「花钱买到」就锁定了，下游随便折腾都不会泄露更多。这条性质是 DP 区别于其他隐私方法的杀手锏，也是 DP-SGD 能成立的基础（训练出的模型是带噪梯度的后处理，因此自动继承隐私保证）。

还有一个正交于组合的设计维度，决定噪声加在哪里：local DP（本地差分隐私）vs central DP（中心化差分隐私）。central DP假设有一个可信的数据持有者，先把原始数据聚到一起、在发布结果时加噪——噪声小、效用高，但你得信任这个中心方（DP-SGD 属于此类）。local DP则不信任任何人：每个用户在数据离开自己设备前就先加噪，服务器只见带噪数据——无需信任中心，但每个人都加噪导致总噪声大得多、效用低（Apple/Google 的遥测统计用它，notebook 胶囊会实现）。这是「信任假设 vs 效用」的根本权衡：能信任中心就用 central（效用好），不能信任就用 local（更安全但更糊）；模块 03 的安全聚合正是想在两者间取折中——用密码学换取「无需信任中心也能用小噪声」。

把 ε 当成钱来管理，是 DP 工程的核心心智模型：你有一个总预算（比如 ε=1），每次发布数据、每轮训练都从里面扣，组合定理告诉你扣得对不对，扣光了就不该再碰这份数据。再记住 ε 是对数尺度的：ε 从 1 到 2 不是「隐私少一半」，而是似然比上限从 $e^1\approx2.7$ 跳到 $e^2\approx7.4$（攻击者区分能力翻倍多）——所以 ε=10 看着不大、其实 $e^{10}\approx22000$ 倍，隐私已形同虚设。模块 02 的隐私会计器就是这个「账本」的自动化，模块 05 的预算分配就是把总预算分给多个任务/多次发布的「财务规划」。没有预算管理的 DP 不是 DP——单次机制私密，但无限次查询会把隐私漏光。

7隐私-效用权衡：中心张力

隐私-效用权衡：DP 的中心张力

到这里 DP 的全貌已经清晰，而它的一切实践都绕着一条曲线转：隐私-效用权衡（privacy-utility tradeoff）。更强的隐私（小 ε）需要更大的噪声，更大的噪声损害结果的准确性 / 模型的效用。没有免费的隐私——只有「花多少 ε 换多少效用」。

这条曲线的形状由几个量决定，理解它们就能在实践中找到甜点：

  • 噪声 ∝ 敏感度 / ε：降 ε（更私密）或升敏感度都加大噪声。所以控制敏感度（clip）和合理选 ε 同等重要。
  • 数据量 N：均值/比例类查询的敏感度随 N 下降（一个人在大群体里影响小），所以数据越多，同样 ε 下效用越好——这是「DP 在大数据上更友好」的根本原因。
  • 信号强度：要测的真实效应越大（信噪比越高），同样噪声下越容易测准。弱信号 + 强隐私 = 几乎测不出，这是 DP 的硬限。
  • 查询次数：组合让多次查询分摊预算，每次能用的 ε 变小、噪声变大。少查、问对问题本身就是省效用。

怎么在曲线上选工作点？没有放之四海皆准的 ε。学术常用 ε∈[0.1, 10]，但「ε=1 算不算私密」高度依赖场景——美国 2020 人口普查为不同统计设了不同 ε 并引发激烈争论，Apple/Google 的遥测用 local DP 因噪声大而取了较大的 ε。ε 的选择是技术 + 政策的联合决策，工程师的责任是把「这个 ε 对应多大噪声、多少效用损失」如实算出来摆上桌（模块 05 的预算管理与文档）。

职业底线

最危险的反模式是「为了好看的指标偷偷调大 ε」或「不报告 ε 只说『我们用了差分隐私』」。DP 的保证强度完全由 ε（和 δ）决定；不报 ε 的「DP」等于没有保证。ε=100 在数学上仍是「DP」，但隐私形同虚设。诚实报告 (ε,δ) 与噪声标定，是 DP 工程的职业底线——这也是为什么本课反复强调「把账算清、把代价摆出」。

8研究前沿与开放问题

研究前沿与开放问题

  • 更紧的会计：从基本组合到高级组合到 RDP（模块 02）再到 PLD（privacy loss distribution）/ 数值会计，「同样的噪声能证明多小的 ε」一直在进步——更紧的界直接意味着同隐私下更高效用。
  • ε 的语义与沟通：ε 是个对数尺度的抽象量，「ε=2 到底意味着什么风险」连专家都难直观解释。如何把 ε 翻译成决策者/用户能懂的语言（如「攻击成功率上界」），是 DP 落地的社会-技术难题。
  • local 与 central 的中间地带：local DP 不信任服务器但噪声大，central DP 效用好但要信任中心。shuffle model、安全聚合 + DP（模块 03/05）试图在两者间取折中——用密码学换取「无需信任中心也能用小噪声」。
  • DP 与公平/效用的交互：DP 噪声对少数群体（数据本就少）的伤害可能更大，与公平性目标冲突；DP 对长尾、罕见类的效用损失也更重。隐私、公平、效用的三方权衡仍缺乏统一框架（与 C12 责任 AI 交叉）。
  • 经验隐私 vs 证明隐私的差距：用最强攻击（成员推断 / LiRA，见 C44）反推的「经验 ε」常远小于证明的 ε——说明证明很松，或攻击还不够强。弥合这个差距既能放心调小噪声，也是审计的核心（模块 05）。

必读：Dwork & Roth《算法基础》（定义、机制、组合的权威）、Dwork 2006（Laplace 机制奠基）、Mironov 2017（RDP，下一模块的会计基础）、Balle & Wang 2018（精确高斯标定）。清单见 references.md。
