1被遗忘权：让模型忘记一个人

前三个模块防的都是训练时的隐私：DP 让输出不泄露个体，联邦让数据不集中。但有一类需求它们都满足不了——事后撤回。一个用户今天同意你用他的数据训练，明天改主意了，依法（GDPR 的right to be forgotten，被遗忘权）要求你删除他的数据。删掉数据库里的原始记录很容易，但那条数据的影响早已被烤进了模型权重——模型可能还记得他、还能被攻击复原他。machine unlearning（机器遗忘）要解决的正是这个：如何让一个已经训练好的模型，忘记特定的训练数据。

先认清问题的难度。机器学习的整个范式就是把数据的信息压进参数——这是不可逆的有损压缩，而且每条数据的影响纠缠在所有参数里，不像数据库里能精确定位删除某一行。最诚实的遗忘方法是从头重训（用删除后的数据集重新训练一遍）——这给出完美的遗忘，但代价高到不可接受：每来一个删除请求就重训一次大模型，没人付得起。机器遗忘的全部研究，本质上都是在回答：如何在不重训（或只重训一小部分）的前提下，达到（或逼近）重训的效果。

这就劈出了两条路线，构成本模块的主线。精确遗忘（exact unlearning）：保证遗忘后的模型与「从一开始就没用过被删数据重训」的模型分布完全一致——代表是 SISA（Bourtoule 2021），用分片把重训成本降到一小块。近似遗忘（approximate unlearning）：只要求遗忘后的模型与重训模型足够接近（统计上不可区分到某个 ε），换取远低于重训的成本——代表是影响函数一步更新 + certified removal（Guo 2020）。两条路线的取舍是「成本 vs 保证强度」，本模块都会从零实现并验证。

一句话抓住机器遗忘的难处与两条路线：数据的影响被压进了参数、还纠缠在一起，删原始数据 ≠ 删模型里的影响。金标准是重训（完美但贵）；两条捷径是精确遗忘（SISA：分片，只重训一小块，结果与重训同分布）和近似遗忘（影响函数：一步更新逼近重训，更便宜但只是近似）。本模块 notebook 会用影响函数做近似遗忘、对拍真实重训，并用成员推断验证「到底忘了没」。

2金标准：重训与遗忘的定义

金标准：重训，与遗忘的「正确」定义

要谈「遗忘得对不对」，先得有一个正确的参照系。这个参照就是retraining（重训）：用删除了目标数据 $z$ 的数据集 $D\setminus\{z\}$ 从头训练，得到模型 $A(D\setminus\{z\})$。我们说一个遗忘算法 $U$ 是理想的，如果它作用在原模型上的结果 $U(A(D), z)$ 与重训结果 $A(D\setminus\{z\})$ 分布相同。

\[\text{精确遗忘}:\quad U(A(D), z)\ \stackrel{d}{=}\ A(D\setminus\{z\})\]

注意这里用的是分布相同（$\stackrel{d}{=}$）而非「参数相同」——因为训练本身是随机的（初始化、采样顺序），两次重训都不会得到完全一样的参数。正确的标准是：遗忘后的模型，看起来像是从一个「压根没见过 z 的世界」里训出来的。这个定义直接呼应了 DP（模块 01）——事实上 certified removal 的 (ε,δ) 保证就是借用 DP 的「分布不可区分」语言。

直白说

直白说：判断「忘干净了没」，就看遗忘后的模型能不能和「从没学过这个人的模型」区分开。区分不开 = 忘干净了；还能看出「这个模型学过他」= 没忘干净。重训是「从没学过」的标准答案，一切方法都跟它比。

严谨说

严谨说：精确遗忘要求输出分布相等，近似遗忘放宽为 (ε,δ) 不可区分（与 DP 同构）。这给了两个评估维度：① 与重训的参数/预测距离（越近越好）；② 抵抗成员推断攻击的程度（攻击者还能不能判断 z 被训练过）。本模块 notebook 两个都测。

为什么重训这么贵、贵到要发明遗忘？因为删除请求是持续到来的：GDPR 下用户随时可以要求删除，一个有百万用户的系统可能每天收到成千上万个删除请求。每个请求都全量重训一个大模型——计算成本、能耗、延迟都不可接受（重训可能要几天、几十万美元）。机器遗忘的全部价值，就是把「响应一个删除请求的成本」从全量重训降到一小块重训（SISA）或一步参数更新（影响函数）。

「分布相同」这个定义还有一个深刻推论，解释了遗忘为什么难以验证：因为训练本身随机，「学过 z」和「没学过 z」的两个模型分布是重叠的——单看一个遗忘后的模型，你没法 100% 断定它属于哪个分布。这意味着遗忘的成功是一个统计判断而非二元事实：我们只能说「遗忘后的模型在统计上更像没学过 z 的那一族」，而非「z 被彻底抹除了」。certified removal 的 (ε,δ) 正是量化这个「有多像」的统计距离——和 DP 用 (ε,δ) 量化「两个相邻数据集的输出有多难区分」是同一套数学。把遗忘和 DP 放在同一个「分布不可区分」的框架下理解，是本模块最重要的概念连接。

一个常见的误解：以为「在被删数据上多训练几步反向梯度（梯度上升）就能遗忘」。这既不精确也不安全：梯度上升会破坏模型在其他数据上的能力（连带损害），且没有任何「忘到什么程度」的保证，更糟的是可能过度遗忘（模型在 z 上表现得异常差，反而暴露了「这条数据被特殊处理过」，成为新的泄露信号）。正确的遗忘要逼近重训这个中性的参照，而不是「努力忘掉」。

3精确遗忘：SISA 分片重训

精确遗忘：SISA 分片重训

精确遗忘的核心难题是：重训太贵。SISA（Bourtoule 2021，Sharded-Isolated-Sliced-Aggregated）的洞察是——如果每条数据只影响模型的一小部分，那删它就只需重训那一小部分。

具体做法：把训练数据切成 $S$ 个不相交的分片（shard），每个分片独立训练一个子模型（互不共享参数）。推理时把 $S$ 个子模型的输出聚合（投票或平均）。当要删除数据 $z$ 时，只需找到 $z$ 所在的那一个分片，用「删掉 z 后的该分片」重训那一个子模型，其余 $S-1$ 个子模型纹丝不动。重训成本从「全量」降到「$1/S$」。

全部数据 -> 切成 S 个不相交分片 -> 各训一个子模型 -> 推理时聚合 shard 1 ──train──> model 1 ┐ shard 2 ──train──> model 2 ├─ 聚合(投票/平均) ─> 预测 shard 3 ──train──> model 3 ┘ 删除 z（在 shard 2）：只重训 model 2（用 shard2 \ {z}），model 1/3 不动 -> 重训成本 1/S；结果与「从没用过 z 重训」分布一致 = 精确遗忘

「Sliced」是第二层优化：在每个分片内部再按训练顺序切成若干切片（slice），并保存每个切片训练后的检查点（checkpoint）。删除 z 时，不必从该分片头重训，只需回到 z 所在切片之前的检查点，重训从该切片起的部分。进一步把成本降到分片的一个子集。代价是存储（要存检查点）和推理时跑 S 个模型（更慢、更占内存）。

直白说

SISA 的直白逻辑：把鸡蛋分篮装。每条数据只在一个篮子里，打破一个篮子（删一条数据）只需重做那一个篮子，不用重做全部。分的篮子越多（S 越大），删一条越便宜——但篮子太多每个篮子数据太少，子模型变弱、聚合精度下降。

严谨说

SISA 的取舍是S 越大遗忘越便宜，但精度越低：分片越多，每个子模型见的数据越少、越弱，聚合后的整体精度通常不如在全量数据上训一个模型。所以 S 是「遗忘成本 vs 模型效用」的旋钮。它最适合删除请求频繁、且数据足够多的场景；数据少时分片的精度代价可能不划算。

SISA 给精确遗忘的关键启示：遗忘的成本，在「训练架构」阶段就被决定了。如果你一开始就把模型训成「整体纠缠」的，那遗忘必然要全量重训；如果你预见到会有删除请求、提前把训练分片隔离，遗忘就便宜。这是「隐私即设计（privacy by design）」的典型——遗忘能力要在系统设计时就规划，不能等请求来了再补救。

4近似遗忘：影响函数

近似遗忘：影响函数

SISA 精确但要改训练架构、且推理变重。如果你有一个已经训好的单一模型、又能接受「近似忘掉」，就用influence function（影响函数）：不重训，只对参数做一步修正，把目标数据的影响「减掉」。

影响函数（Koh & Liang 2017 引入深度学习）回答一个反事实问题：如果训练时给某个样本 z 的权重稍微变一点，最优参数会怎么变？对一个在 $\hat\theta$ 处达到经验风险最小的模型，去掉样本 z（等价于把它的权重从 1 调到 0）对参数的影响近似为：

\[\theta_{-z}\ \approx\ \hat\theta\ +\ \frac{1}{n}\,H_{\hat\theta}^{-1}\,\nabla_\theta \mathcal{L}(z, \hat\theta)\]

逐项读懂：$\nabla_\theta \mathcal{L}(z,\hat\theta)$ 是 z 在当前模型上的梯度（z「想把参数往哪推」）；$H_{\hat\theta}$ 是经验风险在 $\hat\theta$ 处的 Hessian（损失曲面的曲率）。直觉：去掉 z，就把它当初施加的「拉力」反向撤销，而 Hessian 的逆 $H^{-1}$ 负责把这个梯度方向按损失曲面的曲率正确缩放（陡的方向少动、平的方向多动）。这是一步牛顿式的参数更新——不重训，一次线性代数就完成近似遗忘。

直白说

直白说：训练时每个样本都对最终参数施加了一点「拉力」。影响函数估计出 z 那份拉力是多少，然后反向加回去把它抵消，得到「仿佛没有 z 参与」的参数——全程不碰其他数据、不重训。

严谨说

严谨说：这来自经验风险的隐函数定理，是一阶近似，依赖两个假设：① 模型在 $\hat\theta$ 处收敛到驻点（梯度≈0）；② 损失强凸（Hessian 可逆、正定）。深度网络两者都不严格满足（非凸、未必收敛），所以影响函数对深度网络只是粗略近似——但对凸模型（逻辑回归、线性模型）相当准，正是本课 notebook 验证的场景。

成本对比一目了然：重训是 $O(\text{完整训练})$，SISA 是 $O(1/S \times \text{训练})$，影响函数是 $O(\text{一次 Hessian 求逆 + 一次梯度})$——对小模型几乎瞬时。代价是它只近似：去掉一个样本通常很准，但同时去掉很多样本、或在强非凸模型上，近似误差会累积，遗忘可能不彻底（被删数据仍能被成员推断揪出）。所以影响函数遗忘必须配合验证（下一节）和形式化保证（certified removal）才敢用。

影响函数和 DP-SGD 之间有一个优美的对偶，看穿它能加深对两者的理解。DP-SGD 是训练时通过裁剪+加噪限制每个样本能施加的影响（让单样本影响 ≤ C，从而想删谁都好删）；影响函数是训练后去估计并撤销某个样本已施加的影响。一个是「预防性地不让任何人影响太大」，一个是「事后精确地减掉某人的影响」。更妙的是 certified removal（Guo 2020）把两者缝合：它先用影响函数做一步遗忘，再加一点 DP 式的噪声把「近似遗忘的残余误差」盖住，从而给出 (ε,δ) 式的可证明遗忘——用 DP 的噪声，为影响函数的近似买单。这再次印证全课的主线：DP、遗忘看似两个主题，底层共享同一套「限制/度量单样本影响」的数学。

Hessian 求逆 $H^{-1}$ 是影响函数的计算与稳定性瓶颈：大模型的 Hessian 是 $d\times d$（d=参数量），既存不下也求不了逆。实践用 Hessian-向量积 + 共轭梯度 / LiSSA 迭代近似 $H^{-1}\nabla$ 而不显式求逆。此外 Hessian 在非凸/未收敛时可能非正定（有负特征值），需加阻尼 $H+\lambda I$ 稳定化。本课玩具用凸模型、小维度，可以直接求逆，把思想讲清；生产中这些近似是必须的工程。

5遗忘验证：证明真的忘了

遗忘验证：怎么证明「真的忘了」

遗忘最反直觉、也最危险的一点是：你没法直接「看见」模型忘没忘。参数变了不代表影响消除了，影响消除了参数也未必明显变。所以unlearning verification（遗忘验证 / 审计）是机器遗忘不可分割的一半——没有验证的遗忘等于自我安慰。有三类验证手段：

验证方法怎么做测的是什么强度
与重训对照比遗忘后模型 vs 真重训模型的参数/预测距离是否逼近金标准强（但需真重训当参照，仅评估时用）
成员推断攻击用 MIA 判断被删数据 z 还能否被识别为「训练过」z 的成员信号是否消失强（直接对应隐私目标）
性能一致性遗忘后模型在 z 上的表现 vs 在从未见过的数据上的表现z 是否「退化」成陌生样本中（必要不充分）

最贴合隐私目标的是成员推断验证（呼应 C12 测量课）：遗忘的终极目的是「让攻击者无法判断 z 被训练过」。所以测它最直接——在遗忘前，成员推断对 z 应有较高成功率（模型记得它）；遗忘成功后，这个成功率应掉回随机水平（≈50%），与「从没训练过 z」时一致。如果遗忘后 MIA 仍能高准确率识别 z，说明影响没删干净；如果 MIA 对 z 的表现异常地低（远低于陌生样本），则可能过度遗忘、反而制造了新的区分信号。理想是「无法区分」，不是「使劲忘」。

certified removal（Guo 2020）则给近似遗忘一个事前的形式化保证：证明遗忘后的模型与重训模型在分布上 (ε,δ) 不可区分（与 DP 同构）。它通过界定影响函数一步更新的残余梯度范数（遗忘后模型离真正驻点还有多远），把这个残余翻译成 (ε,δ) 式的「忘得有多干净」的证书。这把遗忘从「跑个 MIA 看着差不多」升级为「可证明地忘到 ε 内」——和 DP 从「希望没人能链接」升级为「数学保证」是同一种范式跃迁。

机器遗忘最深的开放难题：「证明遗忘发生过」本身极难（Thudi 2022）。一个不诚实的服务商完全可以声称删了你的数据却什么都没做——因为遗忘的效果藏在参数里，外部很难审计。更微妙的是：成员推断有方差，单个样本的「忘了没」统计上难判定；多次遗忘的累积效应、遗忘与继续训练的交织，都让验证变得脆弱。这意味着机器遗忘目前更多是「尽力而为 + 可审计」，而非「可证明地彻底」——把它当隐私的一道防线而非保险箱。

6遗忘的边界与连带损害

遗忘的边界：删不掉的与连带损害

机器遗忘有几个内在的局限，理解它们才能正确使用、不被「遗忘」二字的字面意思误导：

  • 删不掉已扩散的副本：遗忘只作用于一个模型的参数。如果被删数据已经被生成到模型输出里、被蒸馏进别的模型、被缓存在日志里、或模型快照已分发出去，遗忘一个模型管不了这些副本。真正的「删除」是系统级的，远不止改参数。
  • 连带损害（catastrophic unlearning）：删除 z 时可能伤害模型在其他数据上的能力——z 与其他样本共享的特征也被一并削弱。好的遗忘要在「删干净 z」和「保住其余能力」间平衡，验证必须同时检查这两面。
  • 群体 vs 个体：删一个人通常误差小；删一整类、一个群体（很多相关样本）影响大、近似误差累积快，可能需要重训。遗忘的「可删除量」是有限的。
  • 遗忘 ≠ 让模型不会某事：遗忘删的是特定训练样本的影响，不是让模型丧失某种能力。删掉某人的几张脸照，模型还是会人脸识别——遗忘不等于能力擦除（那是另一个问题，与 C44 / 安全相关）。

这些边界把机器遗忘放回它真实的位置：它是被遗忘权在模型层面的一道（重要但不完整的）落地，而非「一键彻底删除」的魔法。正确的工程姿势是把它嵌进一个更大的数据治理流程：删原始数据 + 遗忘模型影响 + 失效已分发的快照 + 审计验证 + 文档记录——缺一不可。这正是模块 05 端到端可信部署要把它接进去的原因。

一句话校准对机器遗忘的预期：它能（在可控成本下）让一个模型「看起来没学过某条数据」，但它管不了这条数据在系统别处的所有副本，也不保证零连带损害。把它当隐私治理的一个组件（配合数据删除、快照失效、审计），而不是当成「遗忘了就万事大吉」的终点。

7从 numpy 到生产的工程现实

从 numpy 到生产：遗忘的工程现实

机器遗忘比 DP/联邦更不成熟——没有 Opacus/Flower 那样的事实标准库，多是研究原型和自建方案。本课在 numpy 里用凸模型把两条路线讲透；生产中要面对的现实更复杂：

维度本课 numpy 做法生产现实
模型凸的逻辑/线性回归(影响函数准)深度网络(非凸，影响函数只是粗近似)
精确遗忘小数据 SISA 分片需提前架构化分片，权衡推理成本/精度
影响函数直接求 Hessian 逆Hessian-向量积 + CG/LiSSA + 阻尼
验证MIA + 与重训对拍强 MIA(LiRA)、金丝雀、第三方审计
数据治理只删模型影响删原始数据+失效快照+下游模型+日志

最值得记住的生产教训：遗忘能力要在训练系统设计之初就规划。如果你预见到会有大量删除请求（面向消费者的产品几乎必然），就该选便于遗忘的架构——SISA 式分片、可追溯每条数据进了哪个模型/检查点（data provenance / lineage）、保留必要的中间检查点。等删除请求堆积如山才想遗忘，往往只能被迫全量重训。「隐私即设计」在遗忘这里体现得最彻底：遗忘的成本是训练架构的函数。

从本课到生产的路径：你理解的「重训=金标准、SISA=分片重训、影响函数=一步逼近、MIA=验证」这套框架，对应到生产就是「按删除请求频率选架构、按模型类型选近似方法、按隐私要求选验证强度」的决策。看懂机制，才能判断一个遗忘方案是真删了还是自我安慰——这在遗忘这个「容易声称、难以验证」的领域尤其关键。

延伸：Bourtoule 2021（SISA）、Guo 2020（certified removal）、Koh & Liang 2017（影响函数）、Golatkar 2020（Fisher 擦除）、Thudi 2022（遗忘必须审计）。清单见 references.md。

8研究前沿与开放问题

研究前沿与开放问题

  • 可证明遗忘的扩展：certified removal 目前主要覆盖凸/线性模型。把形式化的 (ε,δ) 遗忘保证扩展到深度网络、且成本可控，是核心开放问题。
  • LLM 的遗忘：从大语言模型里「删掉」某人的隐私、某段版权文本、某种有害知识，是当下最热也最难的方向——参数纠缠极深、重训成本天文数字、验证极难（模型可能换种说法又吐出来）。与 C44 的抽取攻击正面对抗。
  • 遗忘的审计与「证明删除」：Thudi 2022 指出不诚实方可声称遗忘却不做。如何让用户/监管可验证地确认遗忘发生过（密码学承诺？可信硬件？），是隐私治理的关键缺口。
  • 遗忘与持续学习/再训练的交织：真实模型在不断被新数据更新，同时不断收到删除请求。「边学边忘」的累积隐私效应、遗忘后再训练是否「记起来」，缺乏理论。
  • 遗忘 vs 公平/效用的权衡：删除某些样本可能损害模型对相关群体的表现（连带损害），遗忘与公平、效用三者的权衡（与 C12 交叉）尚无统一框架。

必读：Bourtoule 2021（SISA，精确遗忘）、Guo 2020（certified removal，近似遗忘+保证）、Koh & Liang 2017（影响函数）。清单见 references.md。
