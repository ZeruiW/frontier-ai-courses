# 术语词典 · Glossary（隐私保护与可信 ML）

> 按主题分组，每条 2–3 句释义。读差分隐私 / 联邦学习 / 机器遗忘的论文遇到生词回这里查；英文术语保留原文（学术与工业界的通用语言）。本课用 numpy 在 CPU 上从零实现这些机制，但术语与真实隐私系统（Opacus、TF-Privacy、Flower）一一对应。

## 隐私威胁与目标 · Threats & Goals

| 术语 (EN) | 中文 | 释义 |
|-----------|------|------|
| privacy (in ML) | 机器学习中的隐私 | 防止模型或其训练过程泄露关于单个训练样本（通常是个人）的信息。注意它不同于安全（security，防越权访问）与机密性（confidentiality，防数据外泄）——即便没人偷数据，一个训得太好的模型也可能从输出里反推出训练个体。 |
| membership inference attack (MIA) | 成员推断攻击 | 攻击者判断某条具体记录是否在模型的训练集里。它是隐私泄露最基本的度量——若攻击者能可靠地区分「训练过」与「没训练过」，模型就在泄露成员身份。C12 课用它做隐私的「体温计」。 |
| attribute inference | 属性推断 | 由模型输出反推训练个体的某个敏感属性（如疾病、收入）。比成员推断更进一步，直接还原内容而非仅判断成员资格。 |
| data reconstruction / extraction | 数据重建 / 抽取 | 从模型（尤其大语言模型）里把训练样本逐字逐句复原出来。C44 攻击课的核心议题之一；DP 是已知最强的系统性防御。 |
| memorization | 记忆 | 模型把个别训练样本（而非普遍规律）存进权重的现象。是隐私泄露的根因：能被攻击复原的，正是被记住的样本。 |
| threat model | 威胁模型 | 明确「防谁、对方知道什么、能做什么」的假设集合：攻击者是否有白盒权限、能否多次查询、是否半诚实（honest-but-curious）还是恶意。任何隐私声明都必须先说清威胁模型，否则无意义。 |
| honest-but-curious / semi-honest | 半诚实 | 一种威胁模型：参与方会忠实执行协议，但会尝试从看到的中间信息里推断他人隐私。联邦学习与安全聚合常以此为基准假设。 |
| anonymization / de-identification | 匿名化 / 去标识 | 删除或替换直接标识符（姓名、身份证）。看似安全实则脆弱：通过准标识符（quasi-identifier）链接外部数据常可重新识别，著名反例如 Netflix Prize 与 AOL 搜索日志泄露。DP 的提出正是为了取代这种「靠删字段」的脆弱思路。 |
| linkage attack | 链接攻击 | 把「匿名」数据集与外部公开数据按准标识符拼接，从而重新识别个体。证明了去标识不足以保护隐私，是 DP 形式化定义的历史动机。 |

## 差分隐私 · Differential Privacy

| 术语 (EN) | 中文 | 释义 |
|-----------|------|------|
| differential privacy (DP) | 差分隐私 | 一个数学定义：一个随机算法是隐私的，当且仅当「数据集里有没有任何单个个体」几乎不改变算法的输出分布。它把隐私从「删了哪些字段」变成「输出分布对单人变化的稳定性」，提供可证明、可组合、抗任意后处理的保证。 |
| neighboring datasets | 相邻数据集 | 只差一条记录的两个数据集 $D, D'$（一条记录的增 / 删 / 改）。DP 要求算法在所有这样的相邻数据集对上输出分布都接近——这正是「单个个体不影响结果」的形式化。 |
| (ε, δ)-DP / epsilon-delta DP | (ε, δ)-差分隐私 | 对所有相邻数据集 $D,D'$ 与所有输出集合 $S$：$\Pr[M(D)\in S]\le e^{\varepsilon}\Pr[M(D')\in S]+\delta$。ε 是隐私损失上界（越小越私密），δ 是允许这个上界被突破的极小概率（理想 ≤ 1/数据量）。 |
| pure DP / ε-DP | 纯差分隐私 | δ=0 的特例，保证更强（对任何输出都成立的最坏情况界）。Laplace 机制给的就是纯 ε-DP。 |
| privacy budget ε | 隐私预算 | 衡量累计隐私损失的「钱」。每次对数据做带噪查询都花掉一部分预算，组合定理告诉你总共花了多少。ε 越小越私密但噪声越大、效用越差；它是隐私-效用权衡的旋钮，一旦花完就不该再碰数据。 |
| privacy loss (random variable) | 隐私损失（随机变量） | $\ln\frac{\Pr[M(D)=o]}{\Pr[M(D')=o]}$，刻画单次输出 o 泄露了多少。ε 是它的（近似）上界；RDP / moments accountant 直接追踪它的矩，给出更紧的组合界。 |
| sensitivity (L1 / L2) | 敏感度 | 一个查询函数 $f$ 在相邻数据集上输出能变化的最大幅度：$\Delta_1 f=\max\Vert f(D)-f(D')\Vert _1$（L1，配 Laplace），$\Delta_2 f$ 用 L2 范数（配 Gaussian）。敏感度决定了要加多少噪声——这是 DP 机制的核心计算量。 |
| Laplace mechanism | 拉普拉斯机制 | 给查询结果加均值 0、尺度 $b=\Delta_1 f/\varepsilon$ 的 Laplace 噪声，给出纯 ε-DP。适合 L1 敏感度有界的数值查询（计数、求和）。 |
| Gaussian mechanism | 高斯机制 | 给查询加方差 $\sigma^2$ 的高斯噪声，其中 $\sigma\ge \Delta_2 f\sqrt{2\ln(1.25/\delta)}/\varepsilon$，给出 (ε,δ)-DP。配 L2 敏感度，是 DP-SGD 的默认机制（高斯噪声与梯度的 L2 裁剪天然匹配）。 |
| randomized response | 随机化回应 | 最早的 DP 思想（Warner 1965）：回答敏感是非题时以一定概率说真话、一定概率随机翻转，使任何人都能否认自己的真实答案，却仍能从群体里估计总体比例。是 local DP 的原型。 |
| local DP (LDP) | 本地差分隐私 | 每个用户在数据离开设备前就自己加噪，服务器只见到带噪数据，无需信任服务器。代价是噪声更大、效用更低。Apple、Google 的遥测统计用它。 |
| central DP / global DP | 中心化差分隐私 | 假设有一个可信的数据持有者，先聚合原始数据再加噪发布结果。噪声更小、效用更高，但要信任中心方。DP-SGD 属于这一类。 |
| composition theorem | 组合定理 | 多次 DP 机制叠加后总隐私损失如何累加的定理。基本组合：ε 线性相加（k 次 ε-DP → kε）；高级组合 / RDP：在允许微小 δ 下，损失约按 $\sqrt{k}$ 增长，紧得多。是隐私预算核算的数学基础。 |
| sequential vs parallel composition | 串行 vs 并行组合 | 串行：在同一份数据上做多次查询，预算相加；并行：把数据切成不相交子集各查一次，总预算取各子集的最大值（因为每个个体只被一个子集碰到）。直方图每个桶独立加噪就是并行组合的典型。 |
| post-processing immunity | 后处理免疫 | DP 的关键性质：对 DP 算法的输出做任何不再碰原始数据的处理，隐私保证不变。意味着拿到带噪结果后随便分析、画图、喂给下游模型都不会泄露更多——隐私一旦花钱买到，就锁定了。 |
| privacy-utility tradeoff | 隐私-效用权衡 | 越强的隐私（小 ε）需要越多噪声，越损害结果的准确性 / 模型效用。这条权衡曲线是 DP 一切实践的中心：没有「免费的隐私」，只有「花多少 ε 换多少效用」。 |

## RDP 与隐私会计 · RDP & Privacy Accounting

| 术语 (EN) | 中文 | 释义 |
|-----------|------|------|
| Rényi differential privacy (RDP) | Rényi 差分隐私 | 用 Rényi 散度刻画隐私损失的一种 DP 变体（Mironov 2017）。它的组合极其简单（同阶 RDP 直接相加），且能紧致地转换回 (ε,δ)-DP，是现代 DP-SGD 隐私会计的事实标准。 |
| moments accountant | 矩会计 | Abadi 2016 提出的隐私会计方法：追踪隐私损失随机变量的对数矩（log moments）随训练步数的累加，给出比朴素 / 高级组合紧得多的总 ε。后被 RDP 框架统一与推广。 |
| privacy accountant | 隐私会计器 | 在 DP-SGD 训练过程中持续累加并报告「到目前为止花了多少 ε」的组件。Opacus / TF-Privacy 都内置；它把每步的噪声乘子、采样率、步数翻译成最终的 (ε,δ)。 |
| privacy amplification by subsampling | 子采样隐私放大 | 一条关键引理：如果每步只在随机抽到的一小批数据上运行 DP 机制，单步的有效隐私损失会被采样率 q 放大（变得更私密）。这是 DP-SGD 用小 batch + 噪声就能达到可用 ε 的根本原因。 |
| noise multiplier (σ) | 噪声乘子 | DP-SGD 里相对于裁剪范数 C 的噪声标准差比例（实际加的噪声 std = σ·C）。σ 越大越私密、ε 越小，但梯度信噪比越低、训练越难。是 DP-SGD 最主要的隐私旋钮。 |
| sampling rate (q) | 采样率 | 每步 batch 大小占总数据量的比例 $q=L/N$。它与噪声乘子 σ、步数 T 一起，经会计器决定最终 ε。 |

## DP-SGD · DP Training

| 术语 (EN) | 中文 | 释义 |
|-----------|------|------|
| DP-SGD | 差分隐私随机梯度下降 | 把 DP 装进训练的标准算法（Abadi 2016）：对每个样本单独算梯度、裁剪其 L2 范数到上界 C、把一个 batch 的裁剪梯度求和、加高斯噪声、再做平均与更新。每步是一次高斯机制，全程由隐私会计器累加 ε。 |
| per-sample gradient | 逐样本梯度 | 不是整个 batch 的平均梯度，而是每条样本各自的梯度。DP-SGD 必须先拿到它们才能逐个裁剪——这是 DP-SGD 比普通 SGD 慢且费显存的根源，也是工程实现（vmap / 扩展层）的难点。 |
| gradient clipping (per-sample) | 逐样本梯度裁剪 | 把每条样本梯度的 L2 范数限制在 C 以内：$g\leftarrow g\cdot\min(1, C/\Vert g\Vert _2)$。它把单样本对总梯度的影响（敏感度）硬性限制为 C，从而能用 Gaussian 机制标定噪声。 |
| clipping norm (C) | 裁剪范数 | 逐样本梯度的 L2 范数上界。它同时是高斯机制的敏感度。C 太小丢失梯度信息，C 太大需要更多噪声——是 DP-SGD 的关键超参，常取梯度范数的中位数附近。 |
| noise calibration | 噪声标定 | 根据敏感度（这里是 C）、目标 ε/δ、采样率、步数算出该加多大噪声。DP 的「算账」核心：标定对了才能既满足隐私又尽量保效用。 |
| utility cost (of DP) | DP 的效用代价 | 为隐私付出的准确率 / 性能下降。DP-SGD 在小数据、强隐私（小 ε）下代价显著；大数据、大模型、合适超参下代价可控。理解并压低这个代价是 DP 落地的主战场。 |

## 联邦学习 · Federated Learning

| 术语 (EN) | 中文 | 释义 |
|-----------|------|------|
| federated learning (FL) | 联邦学习 | 一种「数据不动、模型动」的分布式训练范式（McMahan 2017）：原始数据留在各客户端（手机 / 医院），只有模型更新被上传聚合。从源头减少集中化数据的隐私风险。 |
| FedAvg (Federated Averaging) | 联邦平均 | FL 的基准算法：每轮服务器把全局模型发给一批客户端，各自在本地数据上跑若干步 SGD，回传更新；服务器按数据量加权平均得到新全局模型。本课模块 03 从零实现并对拍集中式训练。 |
| client / server | 客户端 / 服务器 | FL 的两类角色：客户端持有本地数据、做本地训练；服务器协调轮次、聚合更新、不接触原始数据。 |
| communication round | 通信轮 | FL 的一次「下发全局模型 → 本地训练 → 上传更新 → 聚合」循环。通信（尤其上行带宽）常是 FL 的主要瓶颈，故每轮要做多步本地计算来摊薄通信。 |
| non-IID data | 非独立同分布数据 | 各客户端的数据分布不同（你手机里的照片和我手机里的不一样）。这是 FL 区别于普通分布式训练的核心难点：本地最优彼此冲突，朴素平均会震荡 / 变慢 / 掉精度。 |
| client drift | 客户端漂移 | 非 IID 下，各客户端本地多步训练后各自跑向自己的本地最优，偏离全局最优，导致聚合后的全局模型被「拽偏」。本地步数越多、数据越异质，漂移越严重。 |
| client sampling / participation | 客户端采样 / 参与 | 每轮只选一部分客户端参与（设备可能离线 / 省电）。采样带来方差，也带来类似子采样的隐私放大效果。 |
| communication compression | 通信压缩 | 通过量化、稀疏化（只传最大的若干梯度）、低秩分解等手段减少上传的模型更新字节数，缓解 FL 的通信瓶颈。 |
| secure aggregation (SecAgg) | 安全聚合 | 一种密码学协议（Bonawitz 2017），让服务器只能解出所有客户端更新的「和」，看不到任何单个客户端的更新。思路：客户端两两商定成对随机掩码，加进各自更新里，求和时成对掩码相互抵消。与 DP 正交叠加：SecAgg 防服务器看单个更新，DP 防从「和」里反推个体。 |
| pairwise masking | 成对掩码 | 安全聚合的核心技巧：每对客户端 (i,j) 共享一个随机向量，i 加上它、j 减去它（或反之），所有客户端求和时这些掩码两两抵消，只剩真实更新之和。 |
| cross-device vs cross-silo | 跨设备 vs 跨机构 | FL 的两种场景：跨设备（海量手机、单台数据少、频繁掉线）与跨机构（少数医院 / 银行、各自数据多、稳定在线）。二者在客户端数、可靠性、信任假设上差异很大，方案也不同。 |

## 机器遗忘 · Machine Unlearning

| 术语 (EN) | 中文 | 释义 |
|-----------|------|------|
| machine unlearning | 机器遗忘 | 在不重训整个模型的前提下，从已训练模型里「抹掉」特定训练数据影响的技术。动机是被遗忘权（right to be forgotten）等法规与用户撤回数据授权的需求。 |
| right to be forgotten (RTBF) | 被遗忘权 | GDPR 等法规赋予个人要求删除其个人数据的权利。问题在于：数据进了模型权重后，删原始数据不等于删模型里的影响——机器遗忘要解决的正是「让模型也忘记」。 |
| exact unlearning | 精确遗忘 | 让遗忘后的模型与「从一开始就没用过被删数据重训」得到的模型分布完全一致。最直接（但最贵）的实现是真的重训；SISA 通过分片把重训成本降下来。 |
| approximate unlearning | 近似遗忘 | 只要求遗忘后的模型与重训模型「足够接近」（统计上不可区分到某个 ε），换取远低于重训的成本。影响函数、梯度上升类方法属于此类，通常配合 certified removal 给出形式化保证。 |
| SISA (Sharded, Isolated, Sliced, Aggregated) | SISA 分片训练 | Bourtoule 2021 提出的精确遗忘框架：把数据切成不相交分片各训一个子模型、推理时聚合（投票 / 平均）。删一条数据只需重训它所在的那个分片（甚至分片内的一个切片），把重训成本从「全量」降到「一小块」。 |
| influence function | 影响函数 | 一个经典统计工具（Koh & Liang 2017 引入深度学习）：估计「去掉某训练样本会如何改变模型参数」而无需真重训，约为 $-H^{-1}\nabla_\theta L(z)$（H 是 Hessian）。是近似遗忘的主力工具之一。 |
| certified removal | 认证移除 | Guo 2020 提出的近似遗忘保证：给出一个形式化的 (ε,δ) 式界，证明遗忘后的模型与重训模型在分布上不可区分到该界内。把「大概忘了」升级为「可证明地忘到什么程度」。 |
| unlearning verification / audit | 遗忘验证 / 审计 | 用攻击（如成员推断）或行为测试检验「被删数据是否真的被忘掉」：若遗忘后成员推断对该数据的成功率掉回随机水平、模型在该样本上的表现与未见过它时一致，则遗忘可信。 |
| retraining (gold standard) | 重训（金标准） | 从头用「删后数据集」训练，是遗忘正确性的参照系。一切近似遗忘方法都以「逼近重训结果」为目标，并以与重训的差距来衡量质量。 |
| catastrophic / spurious unlearning | 灾难性遗忘（连带损害） | 遗忘目标数据时不小心损害了模型在其他数据上的能力。好的遗忘方法要在「删干净目标」与「保住其余能力」之间平衡，审计需同时检查这两面。 |

## 合规、部署与可信 · Compliance & Trustworthy Deployment

| 术语 (EN) | 中文 | 释义 |
|-----------|------|------|
| trustworthy ML | 可信机器学习 | 一个伞形概念，涵盖隐私、安全、公平、鲁棒、可解释、合规等让 ML 系统值得托付的属性。本课聚焦其中的隐私与去中心化支线（公平 / 可解释见 C12 / C06）。 |
| GDPR / CCPA | 通用数据保护条例 / 加州消费者隐私法案 | 欧盟与加州的代表性数据隐私法规，规定了知情同意、数据最小化、被遗忘权、可携权等义务。它们是 DP / FL / 遗忘等技术在工业界落地的外部驱动力。 |
| data minimization | 数据最小化 | 只收集、保留达成目的所必需的最少数据。是多数隐私法规的基本原则，也是 FL（数据不集中）、DP（不存原始查询）在设计上呼应的理念。 |
| privacy by design | 隐私即设计 | 把隐私保护内建进系统架构而非事后补丁的原则。DP 的预算管理、FL 的去中心化、安全聚合都是其技术体现。 |
| privacy budget management | 隐私预算管理 | 在一个长期运行的系统里把总 ε 当作有限资源分配给多次发布 / 多个查询 / 多轮训练，并持续核算余额、到期叫停的工程实践。是 DP 从单次机制走向生产系统的关键。 |
| differential privacy at scale | 规模化差分隐私 | 在真实大规模产品里部署 DP 的工程总和：会计、预算、噪声标定、与 FL / SecAgg 的组合、效用监控。美国人口普查 2020、Google / Apple 遥测是著名落地案例。 |
| audit / privacy audit | 审计 / 隐私审计 | 用经验攻击（成员推断、金丝雀注入 canary）反向估计系统实际泄露了多少隐私，检验声称的 ε 是否名副其实。是「声明的隐私」与「实际的隐私」之间的对账。 |
| canary | 金丝雀 | 故意注入训练集的、可识别的特殊样本，用于事后检测它是否被模型记住 / 泄露，从而经验性地审计隐私与遗忘效果。 |
| model card / datasheet | 模型卡 / 数据说明书 | 记录模型 / 数据集的用途、训练数据来源、隐私处理（用了多大 ε 的 DP？是否 FL？）、已知风险的标准化文档。是可信部署的「营养成分表」与审计入口。 |
| compliance checklist | 合规清单 | 上线前逐条核对隐私 / 合规义务（同意、最小化、预算未超、遗忘通道可用、文档齐备）的检查表。本课模块 05 会把它实现成可执行的检查函数。 |
