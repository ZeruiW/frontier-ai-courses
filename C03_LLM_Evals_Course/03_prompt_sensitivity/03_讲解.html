1同一模型同一基准，分数差 10+ 分从哪来：harness 解剖

一个让所有评测从业者警醒的现象：同一个开源模型、同一个 benchmark（比如 MMLU），不同团队跑出的分数可以相差 10 分以上——模型权重一个比特都没变。HELM 早期系统性对比就暴露了这一点 [Liang 2022]，lm-evaluation-harness 的维护者把它总结为可复现评测的头号教训 [Biderman 2024]。差异不来自模型，而来自评测 harness——把"模型"变成"分数"的那一整套胶水代码。

2表层特征敏感性：分隔符、空格也能改分 [Sclar 2023]

Sclar et al. 2023 做了一个系统实验：保持 prompt 的语义完全不变，只改表层特征（spurious features）——字段分隔符（Answer: vs Answer : vs ANSWER:）、大小写、空格与换行、选项间的连接符。结果：在 LLaMA-2-13B 等模型的 few-shot 任务上，仅语义等价的格式变化就能造成最高 76 个百分点的准确率差异，超过 10 分的差异比比皆是。更糟的是：格式好坏在模型间不迁移——对模型 A 最优的模板可能是模型 B 的最差模板，所以"给每个模型调到最好"与"全部用同一模板"两种做法会给出不同的排名。

直白讲

你跑一个模板得到 67.3 分，这个数不是"模型的 MMLU 能力"，而是"模型 × 这一个模板"的得分。换个分隔符可能就是 62 或 71。 单一模板的分数，只是从一大堆合理模板里随机抽了一个算出来的一次实现——你看到的是一个样本点，不是那个分布。

严谨讲

设语义等价的合理模板空间为 $\mathcal{T}$，模型在模板 $T$ 下的真实准确率为 $s(T)$。一次评测报告的 $\hat{s}(T_0)$ 是 $\{s(T):T\in\mathcal{T}\}$ 这一分布的单次实现（再叠加模块 02 讲的有限样本噪声）。 模型能力的诚实刻画是该分布的位置与离散度 $\big(\mathbb{E}_{T\sim\mathcal{T}}[s(T)],\ \mathrm{sd}_{T\sim\mathcal{T}}[s(T)]\big)$，而非任意单点。

Sclar 等人提出 FORMATSPREAD：在模板空间中采样 $K$ 个语义等价模板，报告性能区间。核心统计量是极差（spread）：

$$ \Delta(\mathcal{T}) \;=\; \max_{T\in\mathcal{T}} s(T)\;-\;\min_{T\in\mathcal{T}} s(T), \qquad \hat{s}(T) \;=\; \frac{1}{n}\sum_{i=1}^{n}\mathbf{1}\!\left[\,\mathrm{extract}\big(f(x_i;T)\big)=y_i\,\right] $$

注意 $\hat{s}(T)$ 的定义里显式写出了 $\mathrm{extract}(\cdot)$——抽取函数是评测函数的一部分，它自己也是敏感性来源（§4）。

[Sclar 2023] 的两个工程要点：①模板空间用一个小文法（grammar）定义——字段名 × 分隔符 × 大小写 × 空白的组合，保证"语义等价"是受控的；②朴素地评 $K$ 个模板要 $K$ 倍算力，他们用 bandit 式的自适应采样近似估计 spread 的上下界，把成本压到可接受。对评测从业者的直接含义：论文之间 1–2 分的差距，若没有跨模板的方差报告，不构成"超越"的证据——这条与模块 02 的置信区间结论同构，但方差来源不同。

3选项敏感性：顺序、标号与 position bias [Alzahrani 2024; Zheng 2023]

多选题（MCQA）是 LLM 评测中最常见的题型，它引入了一类专属的敏感性：模型对"选项怎么摆"的反应，常常大过对"选项是什么"的反应。

3.1 两类偏置：position bias 与 token bias

Zheng et al. 2023 的核心发现：LLM 在 MCQA 上存在系统性的选择偏置（selection bias），可分解为两种：

  • 位置偏置 position bias：偏好某个位置上的选项（如总倾向第一个/最后一个）；
  • 标号偏置 token bias：偏好某个标号 token（如无论内容如何都更爱输出 "A" 或 "C"）。

他们的实验表明标号偏置往往是主导因素：把正确答案移动到不同标号下，模型准确率随之大幅波动；不同模型偏爱的标号还不一样。Zheng 等人提出 PriDe（Debiasing with Prior estimation）：用一小部分样本上的选项排列（permutation）估计模型对各标号的先验偏好 $\pi_c$，再把它从预测中除掉：

$$ \tilde{p}(d_i \mid x) \;\propto\; \frac{p(c_i \mid x)}{\pi_{c_i}} $$

其中 $c_i$ 是标号（A/B/C/D），$d_i$ 是挂在该标号下的内容。直觉：观测到的"选 A 的概率"是"内容对"与"就爱说 A"两个因素的乘积，除以先验 $\pi_{c_i}$ 即近似剥离后者。

3.2 排行榜会被"摆法"重排 [Alzahrani 2024]

Alzahrani et al. 2024 把扰动做到了排行榜尺度：在 MMLU 上施加微小扰动——打乱选项顺序、把标号从 A/B/C/D 换成 1/2/3/4 或 (a)/(b)、微调答案格式——然后看开源排行榜的排名变化。结果：个别扰动能让模型在榜上移动多达 8 个名次。当 benchmark 成为优化目标（"benchmarks are targets"），模型可能恰好过拟合到某一种摆法上；换一种语义完全等价的摆法，排名洗牌。

这意味着"榜上 A 比 B 高 1.5 分"这类结论的脆弱性是双重的：模块 02 告诉你它可能在抽样噪声以内；本节告诉你即使统计显著，它也可能只在这一种选项摆法下成立。两关都过了，结论才站得住。

3.3 CircularEval：把"猜对"变成"必须都对"

一个优雅的工程对策是 CircularEval（由 MMBench 提出并推广，VLM 课模块 07 有展开；此处独立讲清）。做法：把每道题的选项循环移位 $k$ 次（4 选项即 4 种摆法，正确答案依次落在 A/B/C/D 上），同一道题问 $k$ 遍，全部答对才记这题为对：

$$ \mathrm{acc}_{\mathrm{circ}} \;=\; \frac{1}{n}\sum_{i=1}^{n}\ \prod_{k=0}^{K-1}\mathbf{1}\!\left[\hat{y}_i^{(k)}=y_i^{(k)}\right] $$

它同时压制两类问题：①position/token bias——靠偏爱某个标号蒙对的题，换个移位就露馅；②随机猜测——4 选项下单次猜对概率 $1/4$，循环全对的概率骤降为 $(1/4)^4\approx 0.39\%$（假设各次独立），基线噪声几乎被消除。代价是 $K$ 倍推理算力，以及指标变得更严格（数值会显著低于普通 accuracy，不可与之直接比较）。notebook 实验 2 与练习 3 会让你亲手实现它。

CircularEval 的本质是把"对扰动的鲁棒性"并入正确性定义：它测的不再是"在某一种摆法下你会不会"，而是"无论怎么摆你都会不会"。这是一种通用思路——任何已知的敏感轴（选项顺序、模板、标号体系）都可以这样"乘进"指标里，代价是算力与更保守的数值。

4答案抽取 pipeline：正则、兜底链与 unparseable

生成式评测的最后一公里：模型给了你一段自由文本，你要从里面挖出"它选了什么"。这个看似琐碎的步骤，是无数评测 bug 的藏身处。真实的模型输出长这样：

"Answer: B" ← 理想情况 "the answer is (b)." ← 小写 + 括号 + 句号 "**B**" ← markdown 加粗 "选 B" ← 换了语言 "B) Paris" ← 复述了整个选项 "Option A is tempting, but ... ← 推理在前，答案在后： therefore the answer is C." 朴素正则会抓到 A（错！） "I cannot determine this." ← 拒答 / unparseable

4.1 兜底链设计与它的系统性偏置

工业级抽取通常是一条兜底链（fallback chain）：从最严格、误报率最低的模式开始，逐级放宽：

① 显式声明（取最后一次出现） "answer is X" / "Answer: X" / "选 X" │ 未命中 ▼ ② 强格式标记 "**X**" / 行首 "X)" / "(X)." │ 未命中 ▼ ③ 独立字母 token 整段输出就是一个 "B" │ 未命中 ▼ ④ 返回 None → 计入 unparseable 率（必须单独报告，而非悄悄算错/算对）

两条设计铁律：取最后一次显式声明而非第一次（CoT 模型先讨论各选项再给答案，"第一个出现的字母"会系统性抓到被讨论的错误选项）；宁可 None 不要瞎猜（把 unparseable 悄悄判错，会把"格式问题"伪装成"能力问题"，见 §5）。

抽取错误不是随机噪声，而是系统性偏置：严格正则系统性惩罚话多的、双语的、爱用 markdown 的模型；first-match 抽取系统性惩罚做显式推理的模型。如果你比较的两个模型恰好一个简洁一个啰嗦，抽取规则本身就能制造出几个点的"能力差距"。比较多个模型时，必须用同一条抽取链，并对每个模型抽样人工检查 unparseable 与抽取错误。

4.2 logprob 选择 vs 生成式回答：两种评法测的不是同一件事

MCQA 有两种根本不同的评法：

维度logprob-based 选择生成式回答 + 抽取
机制比较各候选的条件对数概率，取 argmax自由解码，再从文本中抽取答案
公式$\hat{a}=\arg\max_{c}\ \tfrac{1}{|c|}\log p_\theta(c\mid x)$（常做长度归一）$\hat{a}=\mathrm{extract}(f_\theta(x))$
需要答案抽取？不需要——这是它最大的工程优势需要，引入本节全部问题
能否配合 CoT不能（不生成推理过程）能，且对难题往往必要
测的能力判别/识别：哪个候选更"像话"生成：能否产出并表达正确答案
额外敏感性长度归一方式、是否含标号、base 模型友好解码参数、max_tokens 截断、格式遵循
典型使用方lm-evaluation-harness 的经典任务 [Gao 2023]chat 模型评测、agent 评测、前沿能力评测

同一模型在两种评法下分数可以差很多分且排序都可能不同——它们本来就在测不同的能力切面。报告时必须写明用的是哪一种；对比不同来源的分数时，先确认评法一致，否则比较无意义 [Biderman 2024]。

5混淆变量：答错，还是没按格式答？

一个被严格 harness 判错的样本，背后有两种完全不同的失败：能力失败（模型真不会）与格式失败（模型会，但没按你要的格式说，或者你的抽取链没接住）。这两者在"accuracy 下降"里完全混淆（confounded），而它们对应的结论截然不同：前者是"模型不行"，后者是"评测不行"。对小模型、base 模型与非英语模型，格式失败的占比尤其高——这正是 notebook 用 1.5B 小模型做实验的原因之一。

格式宽松度梯度实验（leniency ladder）

分离这两种失败的标准做法：固定模型与输出不动，只移动抽取规则的宽松度，从严到宽评同一批输出：

L0 仅接受 "Answer: X" 精确格式 acc = 0.41 ┐ L1 + 大小写/括号/句号容忍 acc = 0.52 │ 这一段全是 L2 + 显式声明句式/中文/加粗 acc = 0.63 │ "格式/抽取"损失 L3 + 人工(或 LLM)逐条判读 acc = 0.66 ┘ ──────────── L3 仍答错的 34% ← 这才是能力问题
$$ \underbrace{1-\mathrm{acc}_{L0}}_{\text{观测误差}} \;=\; \underbrace{1-\mathrm{acc}_{L3}}_{\text{能力误差}} \;+\; \underbrace{\mathrm{acc}_{L3}-\mathrm{acc}_{L0}}_{\text{格式/抽取误差}} $$

若 $\mathrm{acc}_{L3}-\mathrm{acc}_{L0}$ 很大，说明你的评测在大量测量"指令遵循"而非目标能力。此时要么改进 prompt（明确格式要求 + few-shot 演示格式），要么放宽抽取链，要么把格式遵循作为一个独立指标单独报告。能力引出（elicitation）视角下，这属于"评测方未尽引出义务"——模块 06 展开。

一个值得内化的原则：unparseable 率与格式损失 $(\mathrm{acc}_{\text{宽}}-\mathrm{acc}_{\text{严}})$ 是评测质量指标，不是模型能力指标。它们高，先怀疑 harness，再怀疑模型。安全评测里这点更要命：把"模型没按格式答"误判成"模型没有该危险能力"，会系统性低估风险。

6few-shot 的坑：示例选择、顺序与泄漏

few-shot（in-context）示例是 harness 的又一大自由度。它带来三类经典问题：

  • 示例选择方差：换一组（同样合理的）示例，分数可动数个百分点。示例与测试题的难度/领域/标签分布是否匹配都有影响。诚实的做法是随机抽多组示例报均值±方差，而不是报你试出来最好的那组。
  • 示例顺序方差：同一组示例不同排列，结果可显著不同——模型存在 recency bias（更模仿最后一个示例）与多数标签偏置（示例答案集中在某标号会拉高该标号的输出概率）。这与 §2 的模板敏感性同根：都是模型对"语义无关的表层排布"的过度依赖，Sclar 2023 的模板文法里 few-shot 的拼接格式正是敏感维度之一。
  • demonstration 泄漏：两种形态——①示例直接泄答案模式：示例答案恰好都是 "C"，模型学到"这场考试答案是 C"这一捷径，而非任务本身；②示例与测试题来自同一数据集的同一来源，示例事实上"教"了测试题的特定知识或题式，使分数无法外推。更隐蔽的是：若 benchmark 的 few-shot 示例是公开固定的（很多榜单如此），训练数据里见过这几个示例的模型相当于提前拿到了考卷格式——这与模块 05 的污染问题连成一条线。
few-shot 数量本身就是排行榜上的常见"作弊面"：0-shot 与 5-shot 的 MMLU 分数可差很多，但表格里往往只写 "MMLU"。看到任何 few-shot 分数，先问三件事：几个示例？怎么选的？答案标号分布是否均衡？三问有一个答不上来，这个数就要打折扣。

7最佳实践：把"分数"升级为"分布 + 配置"

把本章所有内容收敛成可执行的清单——这也是你审稿、复现实验、搭自家 harness 时的检查表：

#实践对应风险（出处）
1多模板报均值±方差：≥3–5 个语义等价模板，报 $\mathbb{E}[s]$、$\mathrm{sd}[s]$ 与极差，而非单点表层敏感性 [Sclar 2023]
2选项扰动检查：顺序置换/循环移位下复评；MCQA 报告 position bias 矩阵，必要时用 CircularEval 或 PriDe 式去偏选择偏置 [Zheng 2023; Alzahrani 2024]
3固定并公开 harness 全配置：模板原文、few-shot 数与示例、解码参数、抽取代码、harness 版本号——理想情况直接公开可执行配置不可复现 [Biderman 2024; Gao 2023]
4报告 unparseable 率：作为一等公民指标；模型间比较时附格式宽松度梯度抽取偏置与混淆（§4–5）
5抽取链取"最后显式声明"+ 兜底 + None；对每个被比较模型抽样人工核查抽取正确性first-match 偏置（§4）
6few-shot 示例多组随机 + 标号均衡；写明示例来源示例方差与泄漏（§6）
7方差分解报告：把抽样方差（模块 02）与模板/示例方差分别报告，结论的显著性要同时扛住两者规格方差被冒充为能力差距
统一的心智模型：评测结果是 $\,\mathrm{score}(\text{model},\ \text{harness},\ \text{data sample})\,$ 的函数，你想声称的却只关于第一个参数。所有最佳实践本质上都是同一件事：要么把后两个参数固定并公开（可复现），要么对它们求期望并报方差（鲁棒）。只报一个单点而不交代后两者，是评测领域大多数不可复现结论的来源。

8研究前沿与开放问题

  • "合理模板空间"如何定义？ FORMATSPREAD 用文法生成语义等价模板，但真实用户的 prompt 分布远比文法宽。对"部署面向用户的模型"，也许应对真实用户 prompt 分布求期望——可这个分布没人有。评测视角：声明你的模板空间，是比声明单一模板更高一档、但仍不完备的诚实。
  • 鲁棒性该不该进排行榜主指标？ 报分布而非单点（如 mean−sd 作为保守分）会改变激励：模型厂商将被迫优化稳健性而非调表层格式。但也会让榜单更难读、算力成本 $K$ 倍。怎样的聚合既抗操纵又可沟通，是开放的机制设计问题 [Alzahrani 2024]。
  • 结构化输出会终结抽取问题吗？ JSON mode / function calling / constrained decoding 可以让"抽取"无损化，但它改变了被测对象：约束解码下模型的分布被截断，可能伤害（也可能帮助）实际能力表现，而且各家实现不一——抽取问题没有消失，而是变成了"约束实现敏感性"。这一交互目前缺乏系统研究。
  • MCQA 范式本身的有效性。 logprob 与生成式两种评法的分歧（§4.2）提示 MCQA 测到的是混合能力；加上选项可被"只看选项不看题"利用（模块 05 的 no-input 基线思想），前沿评测正在向自由生成 + 程序化判分 / LLM judge（模块 04）迁移——后者引入新的敏感性，循环并未终结。
  • 指令遵循与能力的解耦评测。 §5 的梯度实验是事后补救；更好的设计是把两者分开测：能力题给最大格式宽容，格式遵循单独建 benchmark。如何设计"对格式失败免疫"的能力评测（如多回合澄清、交互式打分），仍是开放问题——对安全评测的能力下界估计尤为关键。
