1为什么"评测是一门科学"：分数 ≠ 测量

每周都有新模型在某个榜单上"超越 GPT-4"。每天都有论文用一张表格宣称方法 A 比方法 B 高 0.4 分。 这门课的出发点是一个朴素但被普遍忽视的事实：benchmark 分数是一次有噪声的实验观测，而不是模型能力的真值。 把观测当真值，就会把噪声当结论。

直白讲

模型在 500 道题上答对 70%，不等于"它的能力就是 70%"。换一批题、换一个 prompt 模板、换一个答案抽取的正则， 分数都会动——动的幅度经常比"SOTA 提升"还大。所以一个孤零零的分数什么也证明不了， 你需要知道它会晃动多少，才能判断两个分数的差距是真是假。

严谨讲

把单题得分建模为 $X_i \sim \mathrm{Bernoulli}(p)$，$p$ 是模型在该任务分布上的真实正确率（潜变量）。 benchmark 分数 $\hat p = \frac{1}{n}\sum_{i=1}^n X_i$ 只是 $p$ 的一个点估计，其标准误 $\mathrm{SE}(\hat p)=\sqrt{p(1-p)/n}$ 随题目数 $n$ 的平方根衰减。 没有同时报告 $\hat p$ 和其不确定度的"结论"，在统计意义上不构成结论。

给个数量级直觉。最常用的 95% Wald 置信区间（模块 02 会讲它的缺陷与替代品）：

$$ \hat p \;\pm\; z_{0.975}\sqrt{\frac{\hat p(1-\hat p)}{n}}, \qquad z_{0.975}\approx 1.96 $$

代入 $\hat p=0.7$：$n=500$ 道题时半宽约 $1.96\times\sqrt{0.7\times0.3/500}\approx 0.040$ —— 也就是 ±4 个百分点；即使全量 MMLU（$n\approx 14000$）也有约 ±0.8 个百分点。 而排行榜上相邻模型的差距，常常不到 1 个百分点。

"67.2% > 66.8%，所以我们的模型更强"——这是本领域最高频的伪结论。 在 $n=500$、±4pp 的误差棒下，0.4pp 的差距完全可能是抽样噪声。 [Miller 2024, Adding Error Bars to Evals] 系统论证了这一点并给出可操作的方案；它是模块 02 的主角。 本课的第一条纪律：没有误差棒的分数不是结论。

而抽样噪声只是冰山一角。分数还会被这些因素系统性地扭曲：prompt 模板与选项顺序（模块 03）、 LLM 评委的偏置（模块 04）、训练集污染（模块 05）、能力引出不足（模块 06）、harness 实现差异（模块 07）。 评测科学 = 把这些噪声源与偏差源逐一识别、量化、控制的方法论。整门课组织成三个问题：

三问框架问的是什么对应模块
① 测什么（validity）这个 benchmark 度量的构念（construct）是什么？分数高真的意味着"能力强"吗？有没有被污染/饱和架空？01、05、08
② 怎么测得严谨（reliability）误差棒怎么算？prompt/抽取/评委引入多少方差与偏差？能力上限有没有被引出？02、03、04、06
③ 怎么报告（reporting）如何把测量结果写成可复现、可比较、不误导的结论？harness、配置披露、排行榜的陷阱。07、08
读任何一篇评测论文/模型卡时，把这三问当成检查清单：它声称测的构念是什么？数字的不确定度在哪？ 我能不能拿它的配置复现出同一个数？三问有一问答不上，这个分数就要打折扣。

3学习法：HTML 建框架 → notebook 动手 → 练习必做

每个模块交付两个文件，对应一条固定的学习回路：

NN_讲解.html NN_xxx.ipynb ┌────────────────┐ ┌─────────────────────────────┐ │ 理论框架 │ 读完 │ ① 演示 cell：跑通、改参数、看现象 │ │ 动机/推导/论文 │ ─────► │ ② ✏️ 练习：TODO 骨架 + 自测 assert │ │ 失败模式 │ │ ③ 📖 参考答案：先自己做再对照 │ └────────────────┘ └──────────────┬──────────────┘ ▲ │ assert 全过 → print("✅ 通过") └──────── 回头查讲解 ◄────── 卡住时 ┘
  • HTML 讲解负责"为什么"和"是什么"：动机、数学、关键论文、失败模式。先读它建立框架，不急着写代码。
  • notebook 是主战场，"实践中学习"：所有统计量自己算一遍、所有失败模式自己复现一遍。
  • ✏️ 练习是必做项，不是选做项。每题给函数骨架（关键处 raise NotImplementedError）， 紧跟一个自测 cell 用 assert 自动判分——全过会打印 ✅ 练习 N 通过。做不出再看文末 📖 参考答案。
评测科学的大部分知识是程序性知识：bootstrap 写错重采样维度、CI 用错公式、pass@k 用了有偏估计—— 这些坑只有亲手踩过才记得住。只读不练，等于没学。每个 notebook 末尾的练习 assert 是你的"自动判分器"， 请把"让 assert 全绿"当作完成该模块的硬性标准。

5前置自测 5 问

本课假设你有概率统计入门和 Python/numpy 基础。开课前自测以下 5 问——能不查资料答出 4 问即可放心开始； 答不出的，按右栏提示补课（都不超过一晚上的量）。

#自测问题要点与补课方向
1$X\sim\mathrm{Bernoulli}(p)$ 的期望和方差是什么？$n$ 个独立样本的均值 $\bar X$ 的方差又是什么？ $\mathbb{E}[X]=p$，$\mathrm{Var}(X)=p(1-p)$，$\mathrm{Var}(\bar X)=p(1-p)/n$。这是全课误差棒的根。不熟 → 复习随机变量与方差的基本性质。
2中心极限定理（CLT）说了什么？为什么它允许我们给"平均正确率"套正态置信区间？ 独立同分布均值经标准化后依分布收敛到 $\mathcal{N}(0,1)$，故大样本下 $\bar X$ 近似正态。不熟 → 任意一本统计入门的 CLT 章节。
3"95% 置信区间"的 95% 指的是什么？是"真值落在这个区间内的概率是 95%"吗？ 不是（频率学派下真值非随机）：指构造区间的程序在重复实验中有 95% 的次数盖住真值。这个区分在模块 02 反复使用。
4p-value 是什么？p = 0.04 能说明"备择假设为真的概率是 96%"吗？ p-value 是原假设为真时观测到至少这么极端数据的概率；不能反推假设为真的概率。不熟 → 复习假设检验框架（H0/H1、第一/二类错误）。
5不写 for 循环，用 numpy 生成 10000 次"抛 100 次硬币的正面数"并求其标准差，代码怎么写？ rng.binomial(100, 0.5, size=10000).std()。要点是向量化与 np.random.default_rng 的使用。不熟 → 过一遍 numpy quickstart。
注意第 3、4 问是"概念辨析"而不是计算——评测报告里的统计误读，多数恰恰发生在这两个概念上。 配套 notebook 的两道练习（Wald CI 与 bootstrap CI）就是对第 1–3 问的动手版自测。

6评测领域全局图景：能力 / 对齐 / 安全三条线

把视野拉远：今天的 LLM 评测大致沿三条线展开，三条线的问题形态、方法工具和失败代价都不同。

评测线核心问题代表工作方法特点
能力评测
capability evals		模型能做什么？做到什么程度？MMLU、GPQA、SWE-bench、HLE、Chatbot Arena静态题库 / agent 任务 / 人类偏好排名；本课的统计与方法论主要在这条线上展开
对齐评测
alignment evals		模型愿不愿按人类意图行事？诚实吗？谄媚吗？TruthfulQA、sycophancy 套件、instruction-following 评测大量依赖 LLM-as-a-judge 与行为探测，构念效度问题最尖锐
安全评测
safety evals		模型会不会造成危害？危险能力的上限在哪？METR 的自主性/长任务评测、各 frontier lab 的安全框架触发评测、CBRN/cyber uplift 评测关心能力上限而非平均表现 → elicitation 成为方法论核心；结论直接进入部署决策
本课与 METR 风格工作的关系。METR 这类第三方评测机构做的是第三条线：在部署前测出模型危险能力的 可信上限。这恰好要求把全课工具链拉满——能力引出要充分否则低估风险 [METR 2024, Elicitation Guidelines]、 误差棒要诚实否则误判阈值（模块 02/06）、任务要免污染（模块 05）、harness 要可复现可审计（模块 07）、 度量要能外推（模块 08 的 time-horizon：用"50% 成功率对应的人类任务时长"刻画 agent 能力 [Kwa 2025]）。 换言之：安全评测是评测科学的压力测试场——平均意义上的马虎在能力评测里丢的是论文分数，在安全评测里丢的是部署决策的正确性。

三条线共享同一套底层方法论（抽样、统计、引出、报告），本课以能力评测为主要载体讲透这套方法论， 并在模块 06/08 专门处理安全评测特有的"测上限"问题。

7研究前沿与开放问题

  • 评测的"复现危机"会到来吗？同一模型同一 benchmark，不同 harness 报出的分差可达数个百分点 [Biderman 2024]。社区尚无统一的配置披露标准——评测报告应该像实验科学一样强制披露哪些自由度？
  • 静态 benchmark 的寿命问题。污染与饱和让静态题库以"年"为单位失效（MMLU→GPQA→HLE 的军备竞赛）。 动态/实时评测（LiveBench）、私有 held-out 集与基于一手任务的 agent 评测，谁是可持续解？
  • 构念效度仍是悬案。"MMLU 分数高"到底度量了什么潜在能力？心理测量学（IRT、信效度理论） 向 LLM 评测的迁移刚刚起步，缺少公认的效度验证范式。
  • 上限引出无法证完备。安全评测需要"模型做不到 X"的否定性结论，但 elicitation 只能给出下界—— prompt、微调、scaffold 的组合空间无法穷尽。如何为"我们已尽力引出"建立可审计的标准？（模块 06 展开）
  • 评测本身被优化。当 benchmark 成为目标（leaderboard 经济、训练时"对题型"），Goodhart 定律生效 [Singh 2025, The Leaderboard Illusion]。如何设计抗优化（gaming-resistant）的评测协议是开放问题。
