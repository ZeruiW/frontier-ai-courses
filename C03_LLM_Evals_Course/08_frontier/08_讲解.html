1静态基准之外：偏好评测与时程评测两条前沿线

前 7 个模块的主线是静态基准：固定题目、固定答案、算准确率、配上误差棒。但模块 05 已经证明这条路有天花板—— 题目会泄漏（污染）、会被刷爆（饱和）、且单点准确率对"模型到底能干多大的活"几乎不提供刻度。 前沿评测于是分出两条互补的路线，恰好对应两类不同的问题：

2Bradley-Terry 模型：从成对比较到全局排名

成对比较的聚合问题早在 LLM 出现前 70 年就被解决了 [Bradley & Terry 1952]。 设每个模型 $i$ 有一个潜在强度参数 $\theta_i\in\mathbb{R}$，Bradley-Terry (BT) 模型假设 $i$ 击败 $j$ 的概率只取决于强度差：

$$ P(i \succ j) \;=\; \frac{e^{\theta_i}}{e^{\theta_i}+e^{\theta_j}} \;=\; \sigma(\theta_i-\theta_j), \qquad \sigma(x)=\frac{1}{1+e^{-x}} $$

直白讲

给每个模型发一个"实力分"。两个模型对战时，赢面只看分差：分差为 0 就五五开，分差越大赢面越接近 1。 拿到一堆对战记录后，反过来问：哪组实力分最能解释这些胜负？这就是最大似然估计。 Elo 则是同一件事的"边打边更新"版本：每打一场，按"实际得分 − 预期得分"微调双方分数。

严谨讲

BT 模型把成对比较建模为以强度差为 logit 的 Bernoulli 试验，等价于以"对战指示向量"为特征、无截距的 logistic 回归。 $\theta$ 仅在平移意义下可辨识（identifiable up to an additive constant），故需固定某个 $\theta_k=0$ 或约束 $\sum_i\theta_i=0$。 在比较图（comparison graph）连通的条件下，MLE 存在且唯一（模平移）。

MLE 拟合

给定对战集 $\mathcal{D}=\{(w_m, l_m)\}_{m=1}^{M}$（第 $m$ 场 $w_m$ 胜 $l_m$），负对数似然为：

$$ \mathcal{L}(\theta) \;=\; -\sum_{m=1}^{M} \log \sigma\!\left(\theta_{w_m}-\theta_{l_m}\right) $$

这是 $\theta$ 的凸函数，用任意二阶/拟牛顿优化器（notebook 用 scipy.optimize.minimize）即可求全局最优。对 $\theta_i$ 求梯度：

$$ \frac{\partial \mathcal{L}}{\partial \theta_i} \;=\; -\sum_{m:\,w_m=i}\Big(1-\sigma(\theta_i-\theta_{l_m})\Big) \;+\;\sum_{m:\,l_m=i}\sigma(\theta_{w_m}-\theta_i) \;=\; -\big(\underbrace{\#\text{实际赢}}_{\text{观测}}-\underbrace{\textstyle\sum \text{预期赢}}_{\text{模型}}\big)_i $$

即 MLE 的一阶条件是"每个模型的实际胜场数 = 模型预测的期望胜场数"——一个非常直觉的矩匹配条件。

Elo：BT 的在线随机近似

Elo 评分（国际象棋传统，base-10 / 400 刻度）对每场对战做增量更新：

$$ R_a \leftarrow R_a + K\,(S_a - E_a), \qquad E_a = \frac{1}{1+10^{(R_b-R_a)/400}}, \quad S_a\in\{0,\tfrac12,1\} $$

注意 $E_a$ 正是 BT 胜率（换底数：$\theta = R\cdot\ln 10/400$），而 $(S_a-E_a)$ 正是上面单场对战对数似然的负梯度。 所以 Elo = 对 BT 对数损失做学习率为 $K$ 的在线 SGD。由此立即得到 K 因子的全部权衡：

  • K 大：适应快（适合棋手——实力随时间变化），但稳态方差大，排名抖动；
  • K 小：收敛慢，但稳态估计更稳；
  • 顺序依赖：Elo 的最终评分依赖对战顺序——同一批数据打乱重放会得到不同评分。SGD 不取平均就不会精确收敛到 MLE。
LLM 评测应该用 BT MLE 而不是在线 Elo。一个固定 checkpoint 的模型强度是常数，不存在"棋手状态起伏"， 在线更新的顺序依赖与稳态方差是纯害无利的噪声。Chatbot Arena 早期用 Elo，后来正式切换为 BT MLE + bootstrap [Chiang 2024]。 notebook 里你会在同一份合成数据上直接对比两者的估计精度。

3Chatbot Arena 方法论与它的裂缝

Chatbot Arena [Chiang 2024] 是偏好评测的标杆实现：真实用户提交任意 prompt， 系统随机抽两个匿名模型并排作答，用户投票（A 胜 / B 胜 / 平 / 都差），累计百万级投票后拟合 BT 排名。

用户 prompt ──► ┌─────────────────────────┐ │ 随机抽取模型对 (i, j) │ ◄── 主动采样：优先抽 │ 双盲并排生成 │ 排名不确定的模型对 └────────────┬────────────┘ ▼ 用户投票 (A / B / tie / both-bad) │ 去噪：异常投票者检测、 │ 泄漏模型身份的对话剔除 ▼ ┌─────────────────────────┐ │ BT MLE 拟合 θ̂ │ │ bootstrap 重采样投票 │──► 排名 + 95% CI └─────────────────────────┘ （CI 重叠 ⇒ 名次并列）

方法论上的三个关键设计：

  • 匿名对战：投票时不显示模型身份（投完才揭示），阻断品牌效应；模型自报身份的对话会被剔除。
  • 投票去噪：检测异常投票者（如永远投同一边、投票速度异常），并用加权 BT 缓解模型对采样不均。
  • bootstrap 排名 CI：对投票记录有放回重采样、重新拟合 BT，得到每个模型 θ 与名次的置信区间—— 榜单上"第 2 名"和"第 3 名"的 CI 经常重叠，此时名次差异无统计意义（模块 02 的教训在此重现）。

裂缝：The Leaderboard Illusion

[Singh 2025] 对 Arena 生态做了系统审计，结论是榜单排名与真实能力之间存在多重系统性扭曲：

缺陷机制后果
风格偏好投票者系统性偏爱更长、格式更漂亮（markdown、列表、emoji）的回答，而非更正确的回答θ 混入"风格分"；style-control 回归后排名显著变动（呼应模块 04 的 judge 偏置）
投票者分布Arena 用户 ≠ 目标用户群：prompt 分布偏向闲聊/创作/英文，专业任务占比低排名只代表"这群投票者在这类 prompt 上的偏好"，外推到编码/科研场景无依据
私测刷榜大厂可私下匿名测试 N 个变体、只公开发布最高分的那个（best-of-N 选择偏差）；且专有模型获得更多对战采样、更多 arena 数据用于调优公开分数是 $\max$ 统计量而非无偏估计，系统性高估；对 arena 分布过拟合
退场不对称开源模型被更频繁地静默下架，比较图随时间断裂跨时段分数不可比，历史排名漂移
Leaderboard illusion 的本质是 Goodhart：当榜单成为目标，榜单就不再测量能力。 私测 best-of-N 在统计上等价于模块 02 警告过的多重比较不校正——抽 10 个变体取最大，期望排名提升是"免费"的。 作为评测科学家，读 arena 榜单时要问三件事：CI 是否重叠？是否做了 style control？该模型上榜前测过几个私有变体？

4METR time-horizon 深读：用"人类时长"丈量 agentic 能力

静态基准给出的准确率是无量纲的：SWE-bench 38% 和 45% 之间差多少"能力"？说不清。 [Kwa 2025]（METR）提出把模型能力投影到一个有物理意义的轴上：模型能以给定可靠性完成的任务，对应人类专家需要多长时间。

方法四步

① 任务套件 (HCAST / RE-Bench / SWAA 等) 每个任务 k 带标签 t_k = 人类专家完成时长 (经 baseline 实测, 秒~小时跨度) │ ② 模型以 agent 脚手架逐任务运行 ──► 成败 y_k ∈ {0,1} (模块 06: 引出要做足!) │ ③ logistic 回归: P(success) = σ( α + β·log t_k ), β < 0 │ ④ 反解 P50 horizon: h₅₀ = exp(−α/β) ← 预测成功率恰为 50% 的人类时长

第 ③ 步的模型假设是：任务对模型的"难度"主要由人类完成时长的对数刻画，成功率随 $\log t$ 单调下降。 拟合出 $\alpha,\beta$ 后令 $\sigma(\alpha+\beta\log h)=\tfrac12$，得：

$$ \alpha + \beta\log h_{50} = 0 \;\Longrightarrow\; h_{50} = \exp\!\left(-\frac{\alpha}{\beta}\right) $$

为什么比单点准确率更能刻画 agentic 能力

  • 跨基准可比：准确率依赖具体题目集，38% 在不同套件间不可比；horizon 的单位是"人类分钟"，把异构任务投影到同一根轴上。
  • 对饱和免疫的刻度：基准饱和时准确率挤在 95%+ 失去分辨率（模块 05），而 horizon 轴可以无限延伸——只要不断补充更长的任务。
  • 直接对应部署语义："P50 horizon ≈ 1 小时"可以直接翻译成"哪类工作流可以交给它"，这是 risk assessment 真正需要的量。
  • 利用了全部任务的信息：logistic 拟合把每个任务的成败按其时长加权汇入两个参数，而非对任意挑选的题目集合取平均。

核心发现与争议

[Kwa 2025] 对 2019–2025 的前沿模型测量 P50 horizon，发现其随发布时间指数增长，倍增期约 7 个月 （GPT-2 几秒 → GPT-4 约几分钟 → Claude 3.7 Sonnet 约 1 小时量级）。若外推成立，5 年内 horizon 达到"人类一个月"量级。 这是目前最被广泛引用的 AI 能力增长定量刻画之一。

主要争议（论文自己也部分承认）：

  • 任务"干净度"：套件任务自动可判分、目标明确、无真实世界的模糊性（messiness）。论文发现任务越"messy"，模型相对人类越差——真实工作的 horizon 可能系统性低于测量值。
  • 外推合法性：用 ~6 年、十几个模型的点外推未来 5 年，假设增长机制（算力、算法、数据）不变；倍增期本身在 2024 后疑似变短，趋势并非铁律。
  • 人类基线的定义：$t_k$ 是"有相关背景的专家、无该任务具体经验"的实测时长，换一群 baseliner 会平移整根轴。

5horizon 指标的统计细节

5.1 任务分布敏感性

horizon 不是模型的内禀属性，而是模型 × 任务分布的函数。logistic 拟合对 $\log t$ 轴上任务的覆盖范围与密度敏感： 若套件里 1 小时以上的任务很少，$h_{50}$ 超过 1 小时的模型的估计本质上是外推，CI 会急剧变宽。 更隐蔽的是：任务时长与任务类型混杂（长任务多为软件工程类），horizon 差异可能部分反映领域差异而非时长本身。 [Kwa 2025] 用不同任务子集重算 horizon 做敏感性分析——这是你复用该方法时必须照搬的步骤。

5.2 logistic 拟合的置信区间

正确的不确定性来源是任务层级的：30 个任务只有 30 个独立观测（同一任务跑多次是聚类数据——模块 02 的 clustered SE 再次登场）。 标准做法是对任务做 bootstrap 重采样、每次重拟合 logistic、收集 $h_{50}$ 的分布取分位数。 注意 $h_{50}=\exp(-\alpha/\beta)$ 是参数的非线性函数，delta method 在小样本下偏差大，bootstrap 是更稳妥的选择。 小套件下还可能出现完全分离（separation）使 MLE 发散——加弱正则或 Firth 校正（notebook 的牛顿法实现带 ridge）。

5.3 P50 vs P80：可靠性刻度

对任意目标成功率 $p$，反解 logistic 得：

$$ h_p = \exp\!\left(\frac{\mathrm{logit}(p)-\alpha}{\beta}\right), \qquad \log h_{80} - \log h_{50} = \frac{\mathrm{logit}(0.8)}{\beta} = \frac{\ln 4}{\beta} \;(<0\ \text{当}\ \beta<0) $$

两个要点：①$h_{80} < h_{50}$ 恒成立，且两者比值只由斜率 $\beta$ 决定——$|\beta|$ 越小（成功率随时长衰减越平缓）， $h_{80}/h_{50}$ 越小。[Kwa 2025] 实测 P80 horizon 通常比 P50 低一个数量级左右； ②语义完全不同：P50 回答"模型半数情况下能搞定多大的活"（能力上界视角），P80 回答"要 80% 可靠性时只能交给它多大的活"（部署/安全视角）。 风险评估应使用高可靠性分位点，宣传材料偏爱 P50——读报告时先看清是哪一个。

6评测报告规范：eval card、预注册与负结果

本课反复出现同一类事故：分数对 prompt 格式敏感（03）、judge 有偏（04）、数据被污染（05）、引出不充分（06）、 榜单被刷（本章）。这些事故的共同放大器是报告不透明——读者无法判断分数的生成过程。解法是把"模型卡"的思想搬到评测上：

Eval card：一次评测的完整披露清单

板块必须披露对应模块
配置模型精确版本/checkpoint、采样参数（temperature、top-p、max tokens）、prompt 模板全文、few-shot 样例、agent 脚手架与工具、随机种子03 / 06 / 07
数据基准版本与 split、题目数、污染检查方法与结果、任务来源与许可01 / 05
判分答案抽取规则（正则/judge）、judge 模型与 prompt、judge 与人工标注的一致性03 / 04
统计n、点估计 + CI、配对比较用配对检验、多重比较校正、bootstrap 细节（重采样单位！）02
局限已知失效模式、任务分布外推边界、与既有报告数字不可比的原因全部
  • 预注册（pre-registration）思想：跑评测之前写下假设、指标、模型清单与判读标准。 这直接封死两类操作：跑完再挑对自己有利的基准子集报告（cherry-picking），以及私测 N 取 1 [Singh 2025]。 内部评测同样适用——决定"哪个 checkpoint 上线"前先冻结评测协议。
  • 负结果披露：报告"试了 CoT 没有提升""在重述版基准上分数跌了 15 分"与报告正结果同等重要—— 负结果是社区校准 elicitation gap 与污染严重度的唯一数据来源。发布偏差（publication bias）在评测领域的代价是系统性高估全行业能力。
一个实用检验：拿着你的报告，一个没跟你说过话的同事能否独立复现出 ±1 个标准误内的数字？ 不能，就还不是合格的 eval card。模块 07 的 harness 把配置序列化成 manifest，正是为了让这件事自动成立。

8研究前沿与开放问题

  • 抗操纵的偏好评测：在 [Singh 2025] 揭示的激励结构下，如何设计机制（限制私测、强制披露变体数、style control 默认开启）让 arena 排名重新可信？开放问题：能否对"刷榜"做统计检测——例如检验某模型的对战胜率分布是否与 best-of-N 选择一致？
  • horizon 的外部效度：messy、目标模糊、需要与人协作的真实任务上，horizon 衰减多少？如何给"messiness"本身建立可测量的刻度并纳入回归？
  • 时长之外的难度轴：log(human_time) 是一维投影。任务对模型的难度显然还有正交维度（反馈回路长度、上下文获取成本、容错率）。多维 IRT 式的 horizon 推广是自然的下一步——但参数越多，对任务样本量的要求越苛刻。
  • 评测的评测（meta-evaluation）：eval card、预注册在学术圈尚无强制力。什么样的基础设施（类似 ML 会议的 reproducibility checklist、或 arena 的实时审计面板）能让"严谨"成为默认而非美德？
  • 评测视角的统一：Arena 测偏好、horizon 测自主能力、静态基准测知识——三者对"模型变强"的判断经常不一致（风格分↑、horizon 不变）。给定一个具体决策（部署/管控/采购），如何加权三类证据？这本质上是评测科学的决策论化，目前几乎空白。
