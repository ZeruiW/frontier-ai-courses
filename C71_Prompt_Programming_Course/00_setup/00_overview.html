1prompt 不是文本，是程序

绝大多数系统里的 prompt 是一个字符串常量，它被反复手改、没有版本、没有测试、也没有指标。这门课的主张是：它其实是一个有结构、可组合、可测试、可优化的程序，而把它当程序对待会改变你能做的事。

一次调用里，你实际上在控制四个独立的东西 ┌──────────────────────────────────────────────────────────┐ │ ① 指令 instruction 任务是什么、标签集是什么、边界在哪 │ │ ② 示例 demos 选哪些、几个、什么顺序 │ │ ③ 输出格式 format 字段、类型、如何解析 │ │ ④ 解码约束 decoding 哪些 token 在这一步是被允许的 │ └──────────────────────────────────────────────────────────┘ ▲ ▲ ▲ ▲ 本课 01 本课 02 本课 01/04 本课 04 本课 03（把 ①②③ 变成一个可搜索的空间） 本课 05（把它们变成可运维的资产） 四个的失败方式完全不同： ① 缺标签集 → 模型自创标签 → **解析失败率 100%**（notebook 会量出来） ② 选错示例 → 准确率掉一半，而且没有任何报错 ③ 没规定格式 → 解析失败，或者更糟：**只有一部分样本解析失败** ④ 没有约束 → 无效输出靠重试兜，而重试会引入选择偏倚

直白说

为什么这个拆分重要？因为它们的成本与可控性差一个量级。指令与格式几乎免费；示例选择要一次检索；自动优化要跑一整套评测；解码约束要改推理栈。而把它们混成一个字符串时，你无法分别评估，也就无法知道该在哪里投入。

严谨说

更形式化一点：一次调用是$y \sim \text{Decode}\big(M(\cdot \mid \text{render}(I, D, F, x)), \; C\big)$，其中 $I$ 是指令、$D$ 是示例序列、$F$ 是格式规范、$x$ 是输入、$C$ 是解码约束、$M$ 是模型。「prompt 工程」通常只在改 $I$；而 $D$（选择与顺序）、$F$、$C$ 是三个独立的、可以被系统性优化的维度。本课的每个模块对应其中一个或几个。

一个判断系统成熟度的问题：「你们上一次改 prompt 是什么时候，改了什么，效果变化多少？」三个问题都答不上来，说明 prompt 还没有被当成代码——而它是唯一一处「改一个字就直接影响生产行为、却通常不进 code review、不进 CI、不进版本记录」的地方。

2把它当程序对待，换来三条性质

性质含义没有它会怎样
可组合prompt 拆成有签名（输入/输出契约）的模块，模块之间可以串、可以换一个 800 行的字符串，改任何一处都可能影响别处，而没人敢删任何一句（「万一它有用」）
可测试每个模块有自己的输入输出与断言；格式合规性可以单独测，与效果解耦只能端到端看一个数；格式问题与能力问题混在一起——「答错」和「没按格式答」被记成同一件事（C03 模块 03 的混淆变量）
可优化$I, D, F$ 构成一个有限的搜索空间，而评测集给了目标函数——于是可以自动搜只能手改；而手改的样本量通常是「我试了三个版本」，这个样本量不足以区分改进与噪声（C68 模块 04 的阈值问题）

直白说

第三条是本课的核心，也是最容易被误解的一条。「自动提示优化」听起来像魔法，但它的机制很朴素：定义一个搜索空间、一个评分函数，然后搜。而它的全部风险也都在这两个定义里——模块 03 会证明：搜索空间定义不当会让搜索退化成噪声拟合，而评分函数与留出集的关系决定了搜出来的东西能不能上线。

严谨说

还有一条不那么明显的收益：可优化性反过来约束了设计。如果一个 prompt 的效果无法被自动评估，那么它也无法被可靠地手动改进——因为你没有判断改动方向的依据。所以「先有评测集，再谈 prompt」不是流程洁癖，而是这一层能不能被工程化的前提。这与 C67 的关系很直接：目标函数通常是一个 judge，而 judge 本身的正确性是 C67 的内容。

3课程地图

模块主题核心主张（一句话）
01prompt program 与可组合结构给每个模块一个签名，把「格式合规」与「答得对不对」分成两个可以独立测的量
02few-shot 示例选择与顺序示例不是「多放几个」——选择的收益远大于数量，而顺序的影响大到不能忽略
03自动提示优化搜索空间 + 评分函数 = 一次优化；而它最大的风险是在留出集上不成立
04受限解码与结构化输出约束能保证输出合法，但逐步掩码得到的分布不是「条件分布」——本课会把这个失真精确算出来
05提示的运维与跨模型迁移prompt 是会随模型失效的资产；它需要版本、指纹、回归门禁与迁移流程

三条贯穿全课的纪律

  1. 格式合规与任务正确必须分开计——「没按格式答」和「答错了」是两个不同的失败，修法也不同。这条在 01 建立，在 04 变成解析失败率与选择偏倚的分析。
  2. 任何 prompt 改动都要在留出集上复核——搜索空间越大，在训练集上过拟合越容易（03 会量出来）。而 prompt 的搜索空间通常比人们以为的大得多。
  3. prompt 的每一个组成部分都要进指纹——指令、示例集合与顺序、格式规范、解码约束、模型 ID 与温度。漏一项，两次评测就不可比而看起来可比（C68 模块 02 的老问题）。

5方法论：一个机制清楚的 in-context learning 模拟器

本课全程不调用任何真实模型。notebook 里的「模型」是一个三十行的确定性函数。但它不是随便编的——它的机制是有依据的，而且正是这个机制让本课的实验有意义。

ToyLM（模块 00–03 用） 输入: instruction, demos = [(x_i, y_i)], x ┌────────────────────────────────────────────────────────────┐ │ 1. 解析指令：标签集在 instruction 里声明了吗？ │ │ 没有 → 返回 UNPARSEABLE（模型「自创标签」的替身） │ │ 2. demos 为空 → 返回先验标签 │ │ 3. 否则：在 demos 上做 kNN │ │ score_i = sim(x, x_i) + recency * (i / (n-1)) │ │ └── 近因偏置：靠后的 demo 更重 │ │ 4. 返回 argmax 的那个 demo 的标签 │ └────────────────────────────────────────────────────────────┘

直白说

为什么用 kNN？因为「in-context learning 的行为在很多任务上很像在示例上做最近邻」这一点有相当多的经验支持，而且它自然地解释了本课要研究的三件事：示例选择为什么重要（决定了近邻集合）、示例数量的收益为什么会饱和（近邻已经够近了）、顺序为什么有影响（位置偏置叠加在相似度上）。

严谨说

用它的关键好处是每个实验只有一个变量。真实模型会把「示例选得更好」与「模型今天更配合」混在一起，而这里两者是可分离的。但也要诚实地说清它的局限：它没有真正的推理能力，所以它不能用来研究「思维链有没有用」这类问题；本课因此不讨论 CoT 的效果——那需要真实模型，属于 C09（推理与测试时计算）。

模块 04 用另一个替身：一个 token 级的小语言模型 + 一个 JSON 语法掩码器。它同样是几十行、确定性的，但它足以把「受限解码的分布失真」精确算出来——而这是一个用真实模型算不出来的量（需要枚举全部合法串）。

每个模块的固定结构

  • 讲解页：机制 → 可测量的量 → 怎么变成检查项
  • notebook：6–8 个 worked 小节，每节以 assert 结尾
  • 4 道 ✏️ 练习：TODO 骨架 + assert 判分 + 📖 参考答案
  • 🧪 真实工程胶囊：接真实模型 / DSPy / logits processor 的代码
