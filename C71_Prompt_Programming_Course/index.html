提示与上下文的程序化优化

绝大多数系统里的 prompt 是一个字符串常量：被反复手改、没有版本、没有测试、也没有指标。这门课的主张是：它其实是一个有结构、可组合、可测试、可优化、需要运维的程序。一次调用里你实际上在控制四个独立的东西——指令、示例、输出格式、解码约束，而它们的失败方式完全不同，所以需要四套不同的检查。把它们混成一个字符串，等于放弃了分别检查的可能，也就无法知道该在哪里投入。

6 模块 四个可优化对象：指令 · 示例 · 格式 · 解码约束 端到端 = 解析率 × 给定解析的正确率 顺序造成三倍差距（成本为零） 逐步掩码 ≠ 条件分布（KL 精确算出） prompt 候选上的胜者诅咒 纯 numpy · CPU · 断网可跑
怎么用： 先读模块的 NN_讲解.html，再跑同目录下的同名 .ipynb。notebook 里的「模型」是几十行确定性函数：模块 00–03/05 用一个机制清楚的 in-context learning 模拟器（demos 上的 kNN + 位置相关的近因偏置 + 先验标签，这个机制自然解释了示例选择为什么重要、数量收益为什么饱和、顺序为什么有影响）；模块 04 用一个 token 级、可全量枚举的小 LM + 语法掩码器——它足以把「受限解码的分布失真」精确算出来，而这是一个用真实模型算不出来的量（需要枚举全部合法串）。边界也说清楚：模拟器没有推理能力，所以本课不讨论思维链的效果（那属于 C09）；而课程里有两处给出了与流行做法相反的诚实结论——模块 02 的「打散标签」在本模拟器上无稳定收益，模块 04 的「语法越紧失真越大」是错的。每个模块末尾的 🧪 真实工程胶囊 给出可原样复制的落地代码（pydantic 签名与同源解析器、DSPy 的 signature/compile、Outlines / GBNF / LogitsProcessor 的约束入口、prompt 目录结构与 ACTIVE 指针、监控打点字段）——但课程全程 CPU、断网、无需 API key。
