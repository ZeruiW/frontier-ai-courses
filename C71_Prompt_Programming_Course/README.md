# 提示与上下文的程序化优化 · 把 prompt 当程序而不是文本

> **prompt 是唯一一处「改一个字就直接改变生产行为、却通常不进 code review、不进 CI、不进版本记录」的地方。**
> 讲解中文 + 英文术语，以真实可运行 Jupyter notebook 为主线，
> 每本含 6–8 个 worked 小节 + 4 道 ✏️ 练习（TODO 骨架 + assert 自动判分）+ 📖 参考答案 + 🧪 真实工程胶囊。
> **纯 numpy / 标准库 · CPU · 断网可跑 · 无需 API key** —— 「模型」是几十行确定性函数。

## 这门课讲什么

一次调用里，你实际上在控制四个独立的东西：

```
┌──────────────────────────────────────────────────────────┐
│ ① 指令 instruction    任务是什么、取值域是什么、边界在哪   │
│ ② 示例 demos          选哪些、几个、什么顺序               │
│ ③ 输出格式 format     字段、类型、如何解析                 │
│ ④ 解码约束 decoding   哪些 token 在这一步是被允许的        │
└──────────────────────────────────────────────────────────┘
```

**它们的失败方式完全不同，所以需要四套不同的检查：**

| 靶子 | 症状 | 该看的信号 |
|---|---|---|
| ① 缺取值域 | **解析失败率 100%**（不是「效果差」） | 解析率 |
| ② 选错示例 | 准确率掉一半，没有任何报错 | 按标签分层的准确率 |
| ② 顺序反了 | 预测分布整体偏移 | 预测标签分布 |
| ③ 没规定格式 | **只有一部分**样本解析失败 | 解析率 + 选择偏倚检查 |

而端到端准确率会把它们压成一个数——**这个数不告诉你该改哪里。**

## 五个模块的顺序不能换

**先定契约（01）→ 再拿免费收益（02）→ 再自动搜索（03）→ 能约束的用约束（04）→ 最后当资产管起来（05）。**

理由在课程里被量出来：

- 契约层没做对时，优化会在「准确率」上打转，而真正的损失在解析层（01）
- 示例的选择与顺序是零/低成本的，而它们的效应量可以是三倍（02）
- 自动搜索的前提是「评测集的噪声已知、目标函数可靠、有留出集」（03）
- 能用约束解决的问题不该用搜索解决——**约束跨模型保留，搜出来的措辞换模型就报废**（04/05）

## 方法论与它的边界

模块 00–03、05 的「模型」是一个**机制清楚的 in-context learning 模拟器**：
在 demos 上做 kNN + 一个位置相关的近因偏置 + 一个先验标签。
选它的理由是「ICL 的行为在很多任务上很像在示例上做最近邻」这一点有相当多的经验支持，
而且它自然解释了本课要研究的三件事：示例选择为什么重要、数量收益为什么饱和、顺序为什么有影响。

模块 04 用另一个替身：一个 **token 级、可全量枚举**的小语言模型 + 一个语法掩码器。
它足以把「受限解码的分布失真」精确算出来——**而这是一个用真实模型算不出来的量**
（需要枚举全部合法串）。

**边界要说清楚：** 模拟器没有真正的推理能力，所以本课**不讨论思维链的效果**——
那需要真实模型，属于 C09。课程里凡是用到模拟器特有性质的地方都明确标注了，
并且有两处给出了**与流行做法相反的诚实结论**（模块 02 的「打散标签」无稳定收益、
模块 04 的「语法越紧失真越大」是错的）。

每个模块末尾的 **🧪 真实工程胶囊** 给出可原样复制的落地代码
（pydantic 签名与同源解析器、DSPy 的 signature/compile、
Outlines / GBNF / LogitsProcessor 的约束入口、
prompt 目录结构与 ACTIVE 指针、监控打点字段）——**但课程本身不依赖它们。**
