# 术语词典 · 提示与上下文的程序化优化

> 每条包含：英文 / 中文 / 一句话定义 / 为什么重要 / 常见误解。
> **本课不重复 C33 的上下文工程术语**（token 预算、compaction、prefix cache 的机制）
> **也不重复 C03 的评测术语**（unparseable、prompt 敏感性的度量）。

---

## 一 · 全课骨架

| 术语 | 中文 | 定义 | 为什么重要 | 常见误解 |
|---|---|---|---|---|
| prompt program | 提示程序 | 由指令 $I$、示例序列 $D$、格式规范 $F$、解码约束 $C$ 四部分构成的可组合对象。 | **四者的失败方式完全不同，需要四套检查**；混成一个字符串就放弃了分别检查的可能。 | 「prompt 工程」通常只在改 $I$。而 $D$（选择与顺序）、$F$、$C$ 是三个独立的、可系统优化的维度。 |
| signature | 签名 | 输入字段 + 输出字段 + 取值域 + 不变量。 | **契约可以被机械检查，prompt 不能**——这是这一层能进 CI 的前提。 | 以为签名是文档。它是三个不调用模型就能跑的断言（取值域在指令里、格式字段名一致、解析器读的字段已声明）。 |
| the three numbers | 三个量 | 解析率 / 给定解析的正确率 / 端到端。 | $\text{end2end} = P(\text{parse}) \times P(\text{correct} \mid \text{parse})$，**两个因子的改进手段完全不同**。 | 只报乘积。那样「放宽取值域」这种有害改动看起来是改进（解析率升到 1.0 而下游拿到非法值）。 |
| slot（instruction slot） | 指令槽位 | 任务 / 取值域 / 输出格式 / 边界兜底 / 禁止项，五个功能不同的位置。 | **取值域是唯一「缺了就归零」的槽位**，而它的修法只是写一句话。 | 以为槽位是独立的。本课量到「兜底槽位那句话意外地声明了一个标签」——**边际贡献不可加**。 |
| portable vs model-specific | 可迁移 / 模型特定 | 签名、取值域、格式、解码约束跨模型保留；示例顺序、指令措辞、校准不保留。 | 把两半分开存，「换模型」就只换那一半。 | 以为「换更强的模型」是纯增益。本课量到：为 A 调过的顺序搬到 B 上会掉到基线以下。 |
| simulator transferability | 模拟器的可迁移边界 | 本课的 ToyLM 用 kNN 当 in-context learning 的替身；哪些结论跟着走、哪些不跟。 | **相对结论可迁移**（选择的效应大于数量、顺序有方向、覆盖缺失归零）；**具体数值只属于模拟器**（0.90 vs 0.30、k=1 就饱和）。 | 以为 kNN 是 ICL 的机制模型。它不是——Min et al. (EMNLP 2022) 量到随机替换示例标签几乎不掉分，与「照抄最近邻的标签」直接矛盾。用它的唯一理由是它让每个实验只有一个变量。 |

## 二 · 组合与契约（模块 01）

| 术语 | 中文 | 定义 | 为什么重要 | 常见误解 |
|---|---|---|---|---|
| error propagation | 错误传播 | 多级流水线的端到端 = 各级正确率之积。 | 本课验证它是**精确的**乘法（$p_1 p_2$ 与实测端到端相等）；两个 0.9 合起来是 0.81。 | 「每一步更简单所以每一步更准」。对，但简化的提升必须补偿掉多乘一次的损失——**三个条件之一不成立就不该拆**。 |
| failure non-propagation | 解析失败不向下传播 | 上一级解析失败时，下一级**不被调用**。 | 否则 `None` 被渲染进下一级的 prompt。 | 症状看起来像「模型答了个莫名其妙的东西」，很难定位到上游。 |
| when to split | 什么时候该拆级 | 拆成两级要赢，三条里至少成立一条：第一级近乎无误 / 子任务标签集差异很大 / 子任务需要不同的上下文。 | **三条都不成立就不该拆**——本课在同一任务上量到单级优于两级。 | 「每一步更简单所以每一步更准」。对，但每步的提升必须补偿掉多乘一次的损失。 |
| field count vs robustness | 字段数与鲁棒性 | 每多一个输出字段就多一个解析失败入口。 | 解析失败是**全或无**的。 | 「更结构化更好」。schema 复杂度该由下游真正需要的字段决定，不是「顺便多要几个」。 |
| field order | 字段顺序 | JSON 里 `reason` 在 `label` 之前还是之后。 | 前者让模型生成标签前已写过理由，后者是事后合理化。**它是一个可调项，要进指纹。** | 以为字段顺序无所谓（对自回归模型不是）。 |
| fingerprint-vs-changelog | 指纹与变更记录 | 指纹变了但 CHANGELOG 没动 → 阻断。 | **纯算术、零误报**，而它防的是「一次没人知道发生过的 prompt 变更」。 | 以为版本号就够。改了版本号但指纹相同（什么都没改）也要在写入时被拒绝。 |

## 三 · 示例（模块 02）

| 术语 | 中文 | 定义 | 为什么重要 | 常见误解 |
|---|---|---|---|---|
| selection vs count vs order | 选择 / 数量 / 顺序 | 示例的三个独立维度。 | **收益量级差一个数量级**：kNN 的 k=1 不输随机的 k=20；顺序造成三倍差距且成本为零。 | 只调数量（因为最容易），然后得出「few-shot 没什么用」。 |
| kNN demo selection | 按相似度选示例 | 取与当前输入最相似的 k 条。 | 收益最高。 | 忽略它的隐藏成本：**每个请求的 prompt 前缀都不同 → 前缀缓存全丢**（C33-05）。 |
| bucketed kNN | 分桶 kNN | 输入先粗分成 N 个桶，每桶一套固定示例。 | **相关性与缓存命中率的折中**；前缀只有 N 种。 | 以为它是妥协。在高 QPS、长 prompt 时它常常是总成本最优的那个。 |
| coverage floor | 覆盖保底 | 每个标签至少 n 条示例。 | **某类没有示例 → 该类准确率归零**，这是正确性问题不是效果问题。 | 「从最近 20 条标注里取示例」——稀有类会被完全漏掉。 |
| order sensitivity | 顺序敏感性 | 同一批示例、不同排列 → 不同结果。 | 本课量到 0.90 vs 0.30；而「最后一条放谁」解释了其中六成。 | ① 以为是噪声（它是有方向的偏置）；② 以为「打散标签」普遍有效——**本课给出诚实的负面结果**，可迁移的是方法不是规则。 |
| primacy vs recency | 首因 / 近因 | 位置加成的方向：靠后的示例更重（近因）或靠前的更重（首因）。 | **方向依模型而异**——模块 05 的 model-b 就是反过来的。所以工程结论不是「最像的放最后」，而是**必须测，并把测出来的顺序固定下来**。 | 以为存在一条通用摆放规则。跨模型迁移时它是第一个失效的东西。 |
| content-free probe | 无内容探针 | 用 `N/A` / `""` 当输入，看模型输出什么 = 标签先验。 | **一次调用**就把偏置从模糊担忧变成可测量；而且它可以进 CI（先验不该随一次改动而变）。 | 以为它只是好玩。它是模块 05 监控四项之一。 |
| contextual calibration | 减先验校准 | 从标签分数里减去探针给出的先验分数。 | 本课量到它把偏置最严重的顺序从 50% 救到 70%，与「other 放最后」持平——**不是与表里最好的 80% 持平**。 | 两个前提常被忽略：**需要 logprobs**；且隐含假设真实标签分布接近均匀。 |
| demo leakage | 示例泄漏 | 示例池与评测集有交集。 | **kNN 让它几乎必然发生**（本课：10/10 道题的示例里包含它自己）。 | 按时间切分就够了。必须按**稳定 ID**去重后再切，且近重复要单独查。 |
| mean chosen similarity | 选中示例的平均相似度 | 被选中的示例与输入的平均相似度。 | 这一层最好的**无真值**指标：同时反映池子覆盖度与线上分布变化。 | 它掉下来时去改 prompt。该做的是**补池子**。 |
| demo sourcing | 示例的四个来源 | 人工标注 / 线上日志回灌 / bootstrap / 合成，每个来源带一种特定偏倚。 | **最危险的是线上日志**，因为它看起来最「贴近真实」：用户已经学会了怎么问才有答案，于是「系统本来就不擅长」的那类输入被系统性漏掉。 | 以为回灌线上数据是无偏的。对策是留一个「困难样本」子池，并强制它在示例池里占固定的最小比例。 |
| demos ≠ documents | 示例选择 ≠ 文档检索 | 实现几乎一样（都是按相似度取 top-k），但目标函数不同。 | 检索里「不相关的段落」是纯噪声；示例里**内容不相关但形态相同**的样本仍然有用——它示范的是格式、推理粒度、边界情况怎么处理。 | 把两者等同，于是只优化内容相似度，而忽略覆盖度与顺序这两个更便宜的维度。 |

## 四 · 优化（模块 03）

| 术语 | 中文 | 定义 | 为什么重要 | 常见误解 |
|---|---|---|---|---|
| search space | 搜索空间 | $\lvert I\rvert \times \binom{\lvert P\rvert}{k} \times k! \times \lvert F\rvert$。 | 朴素规模 $3.66\times10^{11}$；**空间越大过拟合越容易**。 | 以为「把所有能变的都变一遍」是勤奋。三个有依据的压缩能降到 1,152。 |
| hard constraint vs weighted term | 硬约束 vs 加权项 | 解析率必须是可行性判断，不能进加权和。 | 加权版本会选中解析率只有 60% 的候选（准确率高）。 | 以为多目标就是加权求和。**可行性判断必须先于排名**。 |
| winner's curse (on prompts) | 胜者诅咒 | 取 N 个带噪声估计的最大值，这个最大值系统性偏高。 | **候选真实能力全相同时，搜索集分数从 0.59 涨到 0.838，而留出集始终 0.60（gap 0.249）。** | 以为「搜索集上提升 20 个点」是效果。它是「效果 + 选择偏差」，而偏差随 $\ln N$ 增长。 |
| overfit ratio | 过拟合比值 | 搜索集提升 / 留出集提升。 | **免费的过拟合指标**（两个数你都已经有了）；接近 1 = 真效果，很大 = 拟合噪声。 | 报告里不报候选数 N。没有 N，搜索集分数无法被解读。 |
| objective gaming | 目标函数被利用 | 优化器精确地朝目标函数的缺陷方向走。 | 用有偏 judge 当目标 → judge 分数升、真实准确率降、k 变大。与 C67-05 的奖励模型过优化同构。 | 以为「更强的搜索算法」总是好事。它只是更快地找到缺陷。 |
| bootstrap demos | 自举示例 | 用「当前 prompt 在训练集上答对的样本」当示例。 | 不需要人工标注新示例，且风格与模型天然一致（DSPy 的核心手段）。 | 忽略它的自我强化偏倚：**它只挑当前已做对的**，所以必须配覆盖保底。 |
| coordinate ascent | 坐标上升 | 固定其它维度，逐个维度扫到最优，循环几轮。 | 维度之间近似独立时性价比最高，而本课的空间正是这种；**比较算法时要固定「评估次数」预算，不是固定轮数**（一次评估 = 真实的钱）。 | 把「本课坐标上升更高效」当成普适结论。它依赖空间的结构。 |
| optimizer fingerprint | 优化器指纹 | 空间定义 + 目标函数 + 算法 + 种子。 | 优化是一次**会产出资产的运行**，要按 C68 的规矩报告；**缺 `space_size` 或 `n_evaluated` 就该确定性阻断**——没有这两个数，搜索集分数无法被解读。 | 以为只有 prompt 需要指纹。 |
| holdout | 留出集 | 从未参与搜索的评测集。 | **报告里报的是留出集分数，不是搜索集分数**——这是硬要求。 | 把 optimizer 的 valset 当留出集。valset 被反复使用，它是搜索集。 |

## 五 · 解码约束（模块 04）

| 术语 | 中文 | 定义 | 为什么重要 | 常见误解 |
|---|---|---|---|---|
| constrained decoding | 受限解码 | 每一步把不合法 token 的 logit 设成 $-\infty$。 | **唯一能把解析率<em>保证</em>到 1.0 的路**；同时消掉重试的偏倚与修复的语义风险。 | 以为它等于「从模型分布里只保留合法部分」。**不是**——见下一条。 |
| three roads to validity | 保证合法输出的三条路 | 重试 / 修复 / 约束。 | 三者不是三选一，而是**有优先级的组合**：能约束的字段用约束，约束不了的自由文本用修复兜底，两者都失败才重试。 | 顺序反过来——先上重试再考虑约束——等于用钱买一个本可以免费拿到的性质。 |
| valid-prefix mask | 合法前缀掩码 | 允许 = 「加上它之后仍是某个合法串的前缀」。 | 只看位置的掩码**不保证输出合法**（它在「所有合法串结构相同」时才侥幸安全）。 | 以为局部转移检查就够。正确实现需要在 FSM 上做可达性分析。 |
| stepwise-mask distortion | 逐步掩码的分布失真 | $P_{\text{mask}} \neq P_{\text{model}}(\cdot \mid \mathcal{S})$。 | 本课精确算出 KL = 0.081 nat，`bug` 被低估 2.25 倍。 | 以为「语法越紧失真越大」。**错**——见下一条。 |
| completion mass | 收尾能力 | 一个分支之后「还能合法收尾」的概率质量。 | **失真的<em>唯一</em>来源是分支之间收尾能力的差异**：尾部同质时 KL 恰好为 0，无论掩掉 56% 还是 91%。 | 把「被掩掉的质量」当成失真的驱动因素。它完全不影响失真。 |
| when distortion matters | 失真什么时候重要 | 温度 0 取 argmax 时通常不影响；采样多候选、把 logprob 当置信度时重要。 | 这解释了为什么大多数生产系统没被它咬到（它们跑温度 0）。 | 以为它总是可以忽略。在 best-of-n 与自一致性投票里它会系统性偏向「容易开头」的分支。 |
| range constraint | 区间约束 | `minimum` / `maximum`。 | **无法用逐步掩码表达**（`7` 的前缀在字符层合法但注定越界）。 | 以为有了约束就不需要 validate。不变量校验不能被约束替代。 |
| schema → mask | schema 编译成掩码 | `enum` → 只放行能前缀匹配某枚举项的 token；`type` → 数字 token；`required` → 字段未齐时不放行 `}`；`pattern` → 正则编成 FSM。 | **schema、掩码与解析器必须从同一个类型定义导出**，否则手写的两边会静默漂移。 | 以为四类约束都能编译。区间是那个例外（见上一条）。 |
| token-level grammar | token 层的语法 | 同一个字符串有多种 token 切分，所以掩码必须允许**任何能拼出某条合法路径的 token**，而不是只允许某一种切分。 | 过严 → 掩掉合法路径，症状看起来像「加了约束效果反而变差」；过松 → 生成出回不到合法状态的前缀（死局）。 | 以为在字符层判合法就够。正确做法是预计算一张 (FSM 状态) → (允许的 token 集合) 表——它也是受限解码运行时开销接近零的原因；**换 tokenizer 要重算**。 |
| retry bias | 重试偏倚 | 只在解析成功的样本上报分会高估。 | 因为解析成功与答对**都受难度影响**，因此正相关。 | 「解析成功的样本上准确率 92%」可以说，但不能单独说——必须与解析率一起出现。 |
| syntactic vs semantic repair | 语法修复 vs 语义猜测 | 去围栏 / 抽 JSON 块 vs 把 `unknown` 映射成 `bug`。 | 后者把「模型不知道答案」伪装成「模型给了答案」，而下游无法区分。 | 以为修复率越低越好。**修复率是一个必须被记录的健康指标**——静默修复会丢掉信号。 |

## 六 · 运维与迁移（模块 05）

| 术语 | 中文 | 定义 | 为什么重要 | 常见误解 |
|---|---|---|---|---|
| prompt rot | 提示腐烂 | 模型换版本 / 换家族 / 行为漂移 / 示例池腐烂。 | 四种里三种只能靠监控发现。 | 模型 ID 写 `latest`——服务方更新后你的 prompt 面对的是另一个模型，而一切只是「慢慢变差」（与 C70-05 的 embedding `latest` 同类）。 |
| migration risk is a side effect of optimization | 迁移风险是优化的副产物 | 没调过的 prompt 在四个模型上分数完全相同；调过之后搬过去会掉到基线以下。 | **它把「换模型的代价」重新归因到了「你做过多少 prompt 层优化」上。** | 以为换模型本身有风险。风险来自你为旧模型拟合过的那一半。 |
| layered gate | 按层判的门禁 | 任一分层的准确率显著下降就阻断。 | 本课量到「有层显著下降而总分几乎没动」。与 C68-03 的切片分析同构。 | 按总分判。类别不平衡或灰度占比小时，总分会把问题平均掉。 |
| observation vs gate | 观测量 vs 门禁 | 预测分布 PSI 是观测量，不设阻断阈值。 | 换模型必然让分布变化，PSI 高不代表坏。与 C70-05 的「top-k 重叠率」同构。 | 把观测量设成门禁，结果是门禁在正确的变更上误报。 |
| leading indicator | 前导指标 | 修复率 / 重试率先动，解析率后动。 | 格式依从度下降时先出现「需要修复」，之后才是「修不动了」。 | 只监控准确率。prompt 层的问题在准确率上反应很慢。 |
| cost identity | 成本恒等式 | $(n_I + \sum n_{d_i} + n_x)\, c_{\text{in}} (1-h) + n_y c_{\text{out}}$。 | 两个易忘的乘数：**tokenizer**（中文差 30%+）与 **缓存命中率 $h$**（由示例策略决定）。 | 「单价更低就更省钱」。本课把「两个口径何时分家」算成一个临界 token_ratio——并诚实指出在本课参数下它们其实一致，没有反例。 |
| stable-ID canary | 按稳定 ID 灰度（= C66–C69 的金丝雀发布） | 分流按 ID 哈希，不按请求随机。 | 否则同一用户在同一会话里遇到两套 prompt（多轮改写依赖历史）。 | 以为随机分流更均匀。均匀不是这里的目标，一致性才是。 |
| pointer rollback | 指针回滚 | 回滚 = 反向切 `ACTIVE`，旧版本文件原样保留。 | **如果回滚需要手动编辑 prompt，那么这次变更是不可回滚的，不该上线。** | 以为「把 prompt 改回去」就是回滚。手动编辑会引入新的差异。 |
| asset ownership | 资产所有权 | `portable/` 与下游消费方共同拥有；`models/<model>/` 归做功能的团队；示例池与标注/运营共同拥有；`ACTIVE` 指针归发布负责人。 | **改取值域或字段就是改接口**，但因为它「只是改了 prompt」，通常不会走接口变更的流程。把 `portable/` 单独成目录、单独设 owner，就是为了让这件事显眼。 | 以为 prompt 是某个人的私有文件。 |
