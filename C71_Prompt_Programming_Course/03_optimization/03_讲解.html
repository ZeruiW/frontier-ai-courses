03 · 自动提示优化

一次优化 = 搜索空间 + 评分函数 + 搜索算法，而投入顺序要反过来：先把目标做可靠，最后才换强算法——因为更强的算法只是更快地找到你目标函数里的缺陷 · 朴素空间 $3.66\times10^{11}$；三个有依据的压缩降到 1,152（压缩 $3.2\times10^{8}$ 倍）· 解析率必须是硬约束不是加权项——加权版本会选中解析率只有 60% 的候选 · 候选真实能力全同时，搜索集分数也一路上涨：N=1000 时搜索集 0.838 而留出集 0.589——gap 0.249 纯粹是选择造成的（C66-04 的胜者诅咒，参赛者换成了 prompt） · 「搜索集提升 / 留出集提升」是一个免费的过拟合指标 · 有偏 judge 会被优化精确利用：judge 分数升、k 朝偏差方向变大，而真实准确率没有变好 · bootstrap 示例会自我强化（只挑当前已做对的），必须配覆盖保底 · 「留出集提升不超过 2σ 就阻断」会否掉大多数看起来漂亮的优化——而这是正确的 · 「搜索集该多大」可以从 N 与目标 gap 反解（N=1000、gap 5% → 1,327 条）

1一次优化 = 空间 + 目标 + 算法

「自动提示优化」听起来像魔法。它的机制很朴素：定义一个搜索空间、一个评分函数，然后搜。而它的全部风险也都在这三样东西里。

组成它是什么它的风险本课在哪里处理
搜索空间候选 prompt 的集合（指令变体 × 示例子集 × 顺序 × 格式）空间越大，在搜索集上过拟合越容易——而 prompt 的空间通常大得离谱第 2 节（大小）+ 第 5 节（过拟合的定量关系）
评分函数评测集上的一个数（准确率 / judge 打分 / 加权组合）它的偏差会被优化过程直接放大——优化器会精确地利用你目标函数里的每一个缺陷第 3 节 + 第 6 节
搜索算法随机 / 坐标上升 / 进化 / 让模型自己提候选（OPRO 式）成本；以及更强的算法会更快地过拟合第 4 节

直白说

最后一行括号里那句话值得重读：搜索算法变强不总是好事。更强的算法在同样的预算下评估更多候选、或者更有效地朝着目标函数上升——而如果目标函数有缺陷，它就更快地找到那个缺陷。这与 C67 模块 05 的奖励模型过优化是同一个现象，只不过这里被优化的是 prompt 而不是权重。

严谨说

所以三者的正确投入顺序是反过来的：① 先把评分函数做可靠（评测集够大、judge 验证过、噪声量化过）；② 再把搜索空间定得小而有意义（而不是「把所有能变的都变一遍」）；③ 最后才考虑用更强的搜索算法。反过来做（先上一个花哨的 optimizer）几乎必然得到「搜索集分数很好、上线没效果」这个结局。

一个开工前必须回答的问题：「你的评测集上，两次相同配置的重复测量差多少？」答不上来 → 先去测这个方差（C68 模块 04 的第一步）。因为搜索出来的提升如果小于这个方差，它就是噪声。

2搜索空间：先算它有多大

prompt 的搜索空间通常比人们以为的大得多。而它的大小直接决定了过拟合的程度（第 5 节），所以第一步是把它算出来。

\[|\mathcal{S}| = |I| \times \binom{|P|}{k} \times k! \times |F|\]
维度本课的规模组合数
指令变体 $|I|$5 个槽位（notebook 里 2×1×2×2×2）24
示例子集 $\binom{|P|}{k}$从 20 条池子里选 8 条125,970
顺序 $k!$8 条的排列40,320
格式 $|F|$3 种3
合计—$3.66 \times 10^{11}$

直白说

$3.66\times10^{11}$ 这个数说明两件事。第一，穷举不可能，所以必须搜。第二，也是更重要的：在一个 $10^{11}$ 的空间里，「在 40 条评测样本上表现最好的那个候选」几乎肯定是运气好而不是真的好。这正是 C66 模块 04 的胜者诅咒，只不过参赛者从「模型」换成了「prompt」。

严谨说

所以工程上的第一个动作是把空间砍小，而且要砍得有依据：① 顺序维度用「最后一条放谁」代替全排列（模块 02 量到它解释了顺序效应的六成，把 $k!$ 从 40320 降到 $k$）；② 示例子集用选择策略代替自由子集（kNN / 分桶 kNN 把 $\binom{20}{8}$ 降到几种）；③ 指令用「槽位开关」代替自由文本（$2^5 = 32$ 种，可枚举）。砍完之后空间是 1,152——可以真正搜完（压缩了 $3.2\times10^{8}$ 倍），而且过拟合可控。

「让模型自由生成指令」（APE / OPRO 式）会把空间重新放回无限大。它能找到人想不到的写法，代价是过拟合风险回到最高档。用它的前提是评测集足够大、并且有一个从未参与搜索的留出集——而这两条通常比 optimizer 本身更难满足。

3评分函数：优化器会精确利用它的每一个缺陷

评分函数是优化的目标。而优化过程不知道你「真正想要」什么，它只知道这个数。

目标函数它漏掉了什么优化器会怎么利用这个漏洞
只用准确率解析率、成本、延迟搜出一个又长又慢的 prompt；或者搜出一个「放宽取值域」的格式（模块 01 讲解第 2 节的那个陷阱）
用一个有偏的 judgejudge 自己的偏差（长度、位置、自偏好）搜出一个专门迎合 judge 偏差的 prompt——它在 judge 上分更高，而真实指标没有变好（notebook 第 5 节量出来）
准确率的样本量太小噪声搜出一个恰好拟合这 20 条样本的配置；提升全部是噪声
只在一个分层上看其它分层牺牲稀有类换总分——而稀有类往往是业务上最重要的那些

直白说

第二行是最危险的一个，因为它的失败是不可见的：优化后 judge 分数上升，所有指标都变好，而真实质量下降。这与 C67 模块 05 的奖励模型过优化完全同构——只不过那里优化的是权重（贵、不可逆），这里优化的是 prompt（便宜、可回滚），所以这里更容易发生，而且更容易被忽略。

严谨说

三条对策，与 C67 一致：① 目标函数用组合而不是单一指标（准确率 + 解析率 + 成本惩罚，且解析率是硬约束不是加权项）；② 保留一个 judge 从未参与的独立信号（人工抽检、或一个规则化的可验证子集）；③ 报保守分数 $\mu - \lambda\sigma$ 而不是点估计——它天然惩罚了「在小样本上运气好」的候选。

还有一条形式上的纪律：解析率必须是硬约束（parse_rate == 1.0 才允许进入排名），不能作为加权项。因为加权项可以被「牺牲一点解析率换很多准确率」的候选钻空子，而下游拿到不合法的值可能直接崩。

4三种搜索算法

算法怎么搜评估次数什么时候用
随机搜索从空间里随机采 N 个候选，取最好的$N$基线，永远先做这个；而且它的过拟合行为最容易分析（第 5 节）
坐标上升固定其它维度，逐个维度扫到最优，循环几轮$\sum_d |D_d| \times \text{rounds}$维度之间近似独立时性价比最高；本课的空间正是这种（指令槽位 / 选择策略 / 末条 / 格式）
bootstrap 示例用「当前 prompt 在训练集上答对的样本」当示例，迭代几轮$\text{rounds} \times |train|$示例维度上最有效的一个（DSPy 的核心手段）；它不需要人工标注新示例

直白说

bootstrap 示例的想法很漂亮：示例不必是人挑的，可以是「当前系统自己做对的那些」。它的自举性质带来一个真实的好处：示例的风格与格式天然与模型一致。notebook 第 3 节实现它并量出收益。

严谨说

但它也有一个必须知道的偏倚：它只会挑「当前 prompt 已经能做对的」样本，于是它倾向于强化当前的行为，而不是纠正它。症状是：bootstrap 几轮之后在训练集上很好，而在「当前 prompt 一直做错的那类样本」上没有改善。对策是把 bootstrap 与「覆盖保底」结合（模块 02 练习 1 的混合选择器）——让每个标签至少有一条示例，即使那一类当前一条都没做对。

成本的可比口径

比较算法时必须固定「评估次数」这个预算，而不是固定轮数。因为一次评估 = 在评测集上跑一遍 = 真实的钱。notebook 第 2/3 节在同样的评估预算下比较随机搜索与坐标上升，结论是坐标上升在这个（近似独立的）空间上更高效——但这个结论依赖空间的结构，不能推广。

5过拟合：gap 随候选数增长的精确曲线

这是本模块最重要的一节。它说明「搜索集上提升了 20 个点」这句话在什么条件下毫无意义。

实验设定：N 个候选，**真实能力完全相同**（纯噪声） 搜索集 40 条、留出集 40 条 N 搜索集最优 该候选在留出集上 gap 1 0.590 0.601 -0.011 2 0.647 0.596 0.050 5 0.692 0.600 0.092 10 0.719 0.601 0.118 50 0.769 0.603 0.166 200 0.806 0.597 0.208 1000 0.838 0.589 0.249 留出集分数**始终在真值 0.60 附近**，而搜索集分数一路涨到 0.838。 → 「搜索集上的提升」里，有 25 个点纯粹是选择造成的。

直白说

这就是 C66 模块 04 的胜者诅咒，参赛者从「模型」换成了「prompt 候选」。取 $N$ 个带噪声估计的最大值，这个最大值系统性地高于真实最优，而偏差的量级随 $\ln N$ 增长。关键结论：搜索集上的分数不是效果，它是「效果 + 选择偏差」。

严谨说

定量地：设每个候选在搜索集上的估计$\hat s_i = s_i + \varepsilon_i$，$\varepsilon_i \sim \mathcal{N}(0, \sigma^2)$，$\sigma \approx \sqrt{p(1-p)/n}$。则 $\mathbb{E}[\max_i \hat s_i] - \max_i s_i$ 的量级是 $\mathcal{O}(\sigma\sqrt{2\ln N})$（注意 $\sigma\sqrt{2\ln N}$ 是一个上界，$N$ 不大时实际值更小——这一点在 C66 模块 04 里量过）。所以搜索集样本量 $n$ 与候选数 $N$ 必须一起看：$n$ 太小时，$N$ 越大结论越假。

三条可执行的对策

  1. 留出集必须从未参与搜索，而且报告里报的是留出集分数，不是搜索集分数。这一条是硬要求，不是最佳实践。
  2. 用 C66 模块 04 的 MDE 反推「搜索集该多大」：如果你想可靠地检出 3 个点的提升，先算需要多少样本；样本不够时正确的动作是「不搜」而不是「搜了再说」。
  3. 候选数进报告——「我们评估了 N 个候选」是解读搜索集分数的必要信息。报告里没有 $N$ 时，搜索集分数无法被评估。这与 C66 模块 04 第 6 节「$m$ 为参赛者数量」是同一条。

一个具体的、常见的失败：用同一个评测集反复搜了几个月。即使每次只搜十几个候选，累积下来 $N$ 已经是几千，而那个评测集早就被拟合掉了。对策：留出集要定期轮换，而且轮换记录要写进 CHANGELOG（与 C03 模块 05 的污染管理同构）。

6什么时候不该优化

  1. 评测集的噪声大于你想找的效应——先量 $\sigma$，再算 MDE。MDE 大于你期望的提升时，搜索只会产出噪声。
  2. 目标函数还没被验证过——用一个没做过元评测的 judge 当目标函数，等于把 judge 的偏差直接写进 prompt（C67 模块 03）。
  3. 契约层还没做对——解析率还不是 1.0 时，优化会在「准确率」上打转而真正的损失在解析层（模块 01 的三个量）。先修契约。
  4. 模块 02 的免费收益还没拿——选择策略与顺序是零/低成本的，而它们的效应量可以是三倍。先把它们做完再谈自动搜索。
  5. 没有留出集——没有留出集的优化不是优化，是在给评测集拟合一个 prompt。

直白说

反过来，什么时候该优化：契约层已经 1.0、选择与顺序已经调过、评测集的 $\sigma$ 已知且 MDE 小于目标提升、有一个独立的留出集。这四条同时成立时，自动优化是这一层最后一块、也确实有收益的一块。

严谨说

还有一个常被忽略的判据：优化的产出要能被审阅。搜出来的 prompt 如果是一段人类看不懂的咒语，那么它的可维护性是负的——换模型时它大概率失效（模块 05），而没人知道该怎么改它。所以「槽位开关 + 示例集合与顺序」这种结构化的搜索空间，比「自由文本指令」在长期上更值。

7优化器本身也要有 spec 与指纹

优化是一次会产出资产的运行，所以它要按 C68 的规矩来。

优化报告（每次优化后生成） optimizer: coordinate_ascent(rounds=2) space_size: 3,840 ← **必须报**（解读搜索集分数的前提） n_evaluated: 184 ← **必须报**（胜者诅咒的 N） objective: accuracy − 0.02·cost，且 parse_rate == 1.0 为硬约束 search_set: dev-2026w35 (n=40) σ=0.062（重复 10 次测得） holdout: holdout-2026w30 (n=40) ← **从未参与搜索** optimizer_fp: 4a1c88e2 ← 空间定义 + 目标函数 + 算法 + 种子 基线 → 搜索集 0.60 留出集 0.60 优化后 → 搜索集 0.78 留出集 0.65 └─ 搜索集提升 +18pp，**其中只有 +5pp 在留出集上成立** 判读: 留出集提升 5pp vs 2σ = 12.4pp → **不显著，不予上线**

最后一行是这一节的重点：一次搜索集上 +18pp 的优化，按正确口径判读是「不显著」。而如果只报搜索集分数，它会被当成一次巨大的成功。

门禁（按 C68 模块 04 分级）

  • 确定性阻断：报告里缺 space_size 或 n_evaluated；留出集与搜索集有交集；优化后的 parse_rate < 1.0
  • 统计阻断：留出集提升不超过 $2\sigma$
  • 报警：搜索集提升与留出集提升的比值 > 3（过拟合的直接信号）；预测标签分布的 PSI

那条报警值得单独说：「搜索集提升 / 留出集提升」这个比值是过拟合最直接的指标，而它几乎是免费的（两个数你都已经有了）。比值接近 1 → 搜索是真的在找效果；比值很大 → 搜索在拟合噪声。

8优化的产出是一份资产，不是一次调参

一次优化跑完，你得到的不是「更好的效果」，而是一份具体的、可 diff、可回滚、会过期的资产。

一次优化的产出 optimized/ instruction.txt ← 槽位组合（或搜出来的措辞） demos.jsonl ← **有序**的示例集合 calib.json ← 校准参数（如果做了） REPORT.md ← 空间大小 / 候选数 / 搜索集与留出集分数 / 过拟合比值 optimizer_fp.txt ← 空间定义 + 目标函数 + 算法 + 种子 它与「人手改出来的 prompt」是同一种资产 —— 走同一套版本与门禁（模块 01 第 7 节）。

直白说

把它当资产而不是「调好的参数」，有三个直接后果。① 它要进版本控制并带 CHANGELOG——「这套 demos 是自动搜出来的」本身就是一条必须记录的信息，因为它决定了下次该怎么改（重跑优化，而不是手改）。② 它会过期——模块 05 会说明：换模型时它基本报废。③ 它要能被审阅——搜出来的东西如果人看不懂，可维护性是负的。

严谨说

第三点值得展开，因为它反过来约束了搜索空间的设计。「槽位开关 + 示例集合与顺序」这种结构化空间的产出是可读的：你能看出「它关掉了禁止项、把覆盖示例放到了最后」。而自由文本指令搜索的产出常常是一段读不懂的咒语——它在离线指标上更好，但没人知道它为什么有效、换模型时该保留哪一句、出问题时该改哪里。所以在长期上，结构化空间的价值不只是「过拟合可控」，还包括「产出是可维护的」。

9人工改与自动搜的分工

自动优化不取代人。两者擅长的东西不同，而分工的判据很具体。

工作谁做为什么
定契约（签名、取值域、格式）人它来自业务需求，搜不出来；而且它是可迁移的那一半（模块 05）
写边界与兜底规则人「信息不足时输出 unknown」这类规则来自对下游的理解
选择策略与 k人定候选，机器扫候选很少（几种策略 × 几个 k），扫一遍就完了
示例顺序机器人对位置偏置没有直觉，而且方向依模型而异（模块 05）
示例集合机器（bootstrap）人挑示例会不自觉地选「自己觉得典型」的，而那不等于「对模型有用」
指令措辞先人后机器人写出五个槽位齐全的版本；机器只在这个基础上做小幅搜索——让机器从零写指令会把空间放回无限大（第 2 节）
判读结果、决定上不上人第 7 节那条「留出集提升不超过 2σ 就阻断」需要人接受这个结论

一句话概括这张表：人负责「什么是对的」，机器负责「哪个排列更好」。而混淆这两件事的典型症状是：让机器去搜一个本该由业务决定的取值域，或者让人去猜一个本该被扫出来的示例顺序。

10把三个风险重新排一遍

本模块开头说「风险全在空间、目标、算法这三个定义里」。这一节按「多常见 × 多严重」把它们重排，并给出每一个的最小对策。

风险常见程度严重程度最小对策
没有留出集极常见最严重切一个从未参与搜索的集合出来——这一条零成本，而没有它整个优化不可评估
报搜索集分数而不是留出集分数极常见最严重报告模板里把 holdout_best 放在 search_best 前面
报告里不写候选数 N常见严重没有 N，搜索集分数无法被解读（第 5 节）
解析率当加权项常见严重改成可行性判断（第 3 节的一行代码）
用未验证的 judge 当目标常见最隐蔽先做 C67 的元评测；或保留一个 judge 从未参与的独立信号
评测集反复被搜了几个月常见严重（累积）留出集定期轮换，轮换记录进 CHANGELOG
搜索空间是自由文本较少中换成槽位开关；它同时让产出可审阅（第 8 节）

直白说

前两行是同一件事的两面，而它们的对策都是零成本的。这意味着：绝大多数「优化没效果」的案例，问题不在优化算法上，而在评估口径上。而第 5 行是唯一一个「所有指标都变好而实际变差」的风险——所以它最隐蔽，也最值得在开工前处理。

严谨说

反过来，有一个风险被高估了：搜索算法不够强。本模块第 4 节在同样的评估预算下比较随机搜索与坐标上升，差别远小于「有没有留出集」造成的差别。换句话说：把预算花在扩评测集、验证 judge、切留出集上，回报远高于换一个更花哨的 optimizer。

11这一层的边界

自动提示优化是本课最容易被过度期待的一层。这一节说清它的天花板在哪。

  • 它不改变模型的能力上界。C03 模块 06 的 elicitation 阶梯里，prompt 优化只是其中一格；「模型根本不会做这类题」不是搜索能解决的问题。
  • 它不能替代评测集。而且它对评测集的要求比人工改 prompt 更高——因为搜索会消耗评测集的统计能力（第 4 节的胜者诅咒）。所以「没有好评测集所以让机器自己搜」是一个反向的结论。
  • 它的产出会随模型报废（模块 05 会量出来）。所以在预期一年内换模型的项目里，把预算从这一层挪到契约层与约束层更理性。
  • 它不改善可维护性，通常还会降低它。搜出来的东西如果人看不懂，出问题时没人知道该改哪里——这正是第 8 节要求「结构化搜索空间」的原因。

直白说

反过来，它确实能做到一件人做不好的事：扫排列。人对位置偏置没有直觉，而模块 02 量到顺序造成三倍差距。所以「顺序搜索」是这一层性价比最高的应用——它零成本、效应大、而且产出是可读的（一个排列）。

严谨说

如果要给这一层一句总结：它适合在一个已经定义清楚的小空间里做穷尽的比较，不适合用来「探索该怎么写 prompt」。前者是它的强项（机器不会漏、不会累、不会自我说服）；后者需要对任务的理解，而那是人的工作（第 9 节那张分工表）。
