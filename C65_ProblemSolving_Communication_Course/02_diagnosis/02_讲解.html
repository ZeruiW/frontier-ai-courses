1诊断题在面试里到底考什么

Problem-Solving 板块最常见的一类题是这样开场的：「线上某个指标这周突然掉了 3 个点，你会怎么查？」「这个模型训练了两天，loss 就是不降，你怎么办？」「为什么离线 mAP 有 0.82，一上车却感觉只有 0.6？」这些题没有标准答案——面试官事先往往也不知道真正的根因是什么，他甚至可能在追问的过程中临场编造「查了之后发现是这样……」来看你怎么反应。这意味着这类题从设计上就不是在考「你知不知道答案」。

诊断题真正评的是你的假设集合是不是在一步步变小、变得更精确，而不是你有没有一开始就蒙对根因。一个从头到尾只咬定一个猜测、查证方式含糊、最后蒙对了的候选人，分数通常低于一个列出 3–4 个假设、每一步用一次检查显式排除掉一部分、最后没查完但过程清清楚楚的候选人——因为后者的搜索过程是可复现、可审查的，前者的『蒙对』不可复现。

这一模块是模块 00 那个四步框架（澄清 → 分解 → 假设与验证 → 收敛与权衡）里「假设与验证」这一步的深挖专题。诊断与归因推理题的特殊性在于：候选原因往往有很多个、每验证一个都要花时间和资源、而且你必须在有限的追问时间里让面试官相信你的下一步动作是有理由的，而不是随手选一个查一查。

常见失败模式具体表现面试官的解读
从第一个想到的原因开始猛查「我觉得可能是数据问题，我去看看数据」——不说为什么先猜数据、别的可能性怎么办没有假设集合的概念，运气好才能蒙对
东一榔头西一棒子换假设查了数据没问题，转头说「那可能是模型问题」，没有记录已经排除了什么每一步查证的信息没有累积，等于每次都从零开始猜
把猜测说成结论「肯定是过拟合」——却拿不出会让这个判断落空的证据呼应模块 04 的可证伪问题：说得像结论，其实只是没被检验的猜测
拒绝承认不确定，不敢说「我需要先看一下 X」被逼着当场编一个理由，而不是坦然说「这个我需要更多信息才能判断」诚实度是评分维度之一（见 C64-00），硬编答案比承认信息不足更扣分

TSR 场景下最典型的一道诊断题：「新一版模型上线后，『停车让行』这个类别的漏检率从 2% 涨到了 6%，你怎么查？」——这道题背后可能是数据分布漂移、也可能是标注规范变了、也可能只是评测集本身换了一批场景更难的路段。面试官想看的不是你猜中了哪一个，是你怎么把这三个（以及更多）可能性排出优先级，一步步收敛。

直白说

换个说法：诊断题考的不是「破案」，是「你破案的方式能不能被另一个人复现」。如果你今天不在场，另一个工程师看你写下的假设列表和查证顺序，应该能接着往下查，而不需要重新发明一遍思路。

严谨说

更严谨地说，这是把归因推理（attribution reasoning）当成一个搜索问题：候选根因构成一个假设空间，每一次检查是一次查询，查询有成本、有信息量，诊断的目标是用最少的期望总成本把假设空间收敛到一个（或几个可接受的）根因上。本模块剩下的部分，就是把「怎么选下一次查询」这件事从直觉变成可以讲清楚、可以代码化验证的方法论。

2三种搜索策略：二分法 / 最便宜优先 / 信息增益最大

面对一堆候选根因，「下一步查什么」永远有很多种可能的排序方式。真正专业的诊断者不是随机试，而是三种策略里挑一种，且知道自己为什么挑它。这三种策略不是互相竞争的「谁更好」，而是分别在不同的结构假设下最优——挑错策略，通常不是查错了方向，而是白白多花了几步。

症状（观测到的异常） │ ▼ 枚举假设集 H = {h1, h2, ..., hn}（先验概率可以不均匀） │ ▼ 枚举可行检查 C = {c1, c2, ...}，每个检查有 (成本, 对假设集的划分方式) │ ▼ 按策略排序 ──┬── 最便宜优先：cost 升序 │ （假设概率接近均匀 + 查证成本差异悬殊时） ├── 二分法：沿有序链路二分 │ （阶段间有严格因果先后 + 故障单调传播时） └── 信息增益最大：期望增益/成本 降序 （假设概率不均匀、候选无序并列时，最通用） │ ▼ 执行排名第一的检查 → 用结果排除/保留假设 → 假设集变小 │ └── 循环，直到只剩一个假设，或达到可接受的置信度
策略核心思想必须成立的前提反例：前提不成立时会怎样典型场景
二分法 bisection候选沿一条链路排列，每次检查砍掉一半候选必须有序，且故障具有单调性（坏了就一直坏，不会时好时坏）链路里出现「间歇性故障」（某一段偶尔正常）时，二分会被虚假的『正常』结果带偏，定位到错误的段训练流水线的分阶段排查（见下节与 C61-03）、代码变更的 git bisect
最便宜优先 cheapest-first不管信息量，先做最省事的检查假设的先验概率大致接近，且检查成本之间的差异远大于信息量的差异如果一个假设先验概率极低但检查极便宜，会把宝贵的第一步浪费在几乎不可能的原因上线上问题排查里「先看仪表盘」这类零成本检查——前提是仪表盘信息量也不差
信息增益最大 info-gain-max选「期望信息增益 / 成本」最高的检查需要（哪怕粗略地）对每个假设的先验概率和每次检查的区分能力有估计估计本身不准时，排序可能失真——但通常仍优于纯拍脑袋假设不止一个、彼此先验概率明显不同、候选之间没有天然顺序时，最通用的默认策略

直白说

直白地说：如果候选像一列火车厢，只能顺着查，那就二分；如果候选是并列的几个嫌疑人、查谁都差不多贵，那就先挑嫌疑最大的那个先查；如果候选并列、但有的查起来很贵、有的很便宜，就得把「查完能排除多少」和「查一次要花多少」放在一起算账，而不是只看其中一个维度。

严谨说

严谨地说，二分法与最便宜优先都是信息增益最大策略在特定结构下的特例：当候选严格有序且故障单调时，「在中点检查」恰好是把候选概率质量精确切成 50/50——下一节会证明这正是让期望信息增益最大化的切法，所以二分法本质上就是「信息增益最大」策略在有序链路上的具体实现；而最便宜优先则是在假设先验粗略均匀的特殊场景下，用「成本」去近似「1/信息增益」的一种启发式简化，省去了估计每个检查区分能力的麻烦，但代价是当先验明显不均匀时会失灵（下一节的四个检查对比会给出一个具体反例）。

面试里最常见的策略误用：把「最便宜优先」当成万能默认策略，遇到什么问题都先说「我会先看日志/仪表盘，因为这最省事」。这句话在假设明显不均匀时是不够的——如果某个假设的先验概率极低，哪怕检查它成本为零，也不该排在第一位。下一节会用一个显式的反例数值证明这一点。

3信息增益的数学：为什么最优检查是把候选切成 50/50 那个

这一节把「信息增益最大」从一句直觉，变成一个可以严格推导、也可以在 notebook 里数值验证的命题。先固定记号：假设集合的先验概率分布记为 $P$，它的不确定性用香农熵（Shannon entropy）度量。

\[H(P) \;=\; -\sum_i p_i \log_2 p_i \qquad (\text{单位：bit})\]

一次检查会把假设集合按结果分桶（通常是「是/否」这样的二元结果）。信息增益就是「查之前的不确定性」减去「查之后剩余的期望不确定性」：

\[\text{IG}(\text{check}) \;=\; H(P_{\text{prior}}) \;-\; \mathbb{E}_{\text{outcome}}\big[\,H(P_{\text{posterior}\mid\text{outcome}})\,\big]\]

对一个把先验概率质量按 $w : (1-w)$ 分成两组的二元检查，有一个非常干净的代数恒等式——熵的分组公理（grouping axiom）：无论每一组内部的概率构成如何，上面这个期望信息增益恰好等于这个二元切分本身的熵，与组内细节完全无关：

\[\text{IG}(\text{check}) \;=\; H_b(w) \;=\; -w\log_2 w \;-\; (1-w)\log_2(1-w)\]

这个恒等式的意义很大：你不需要知道每个假设具体是什么、也不需要知道组内每个假设的具体概率，只要知道这次检查大致会把当前候选的概率质量切成多大比例的两半，就能算出它值多少信息量。而 $H_b(w)$ 是一个只有一个变量的函数，$H_b(0)=H_b(1)=0$（切偏了、等于没查），在 $w=0.5$ 处取得唯一最大值，恰好等于 1 bit——notebook 会在 0.01–0.99 之间扫描上百个候选切分点数值验证这一点，并且用「候选个数」的等价视角（$n$ 个等概率假设切成 $k:(n-k)$）交叉核对，两种视角算出来的最优切法完全对得上。

一条有严格先后顺序、且"一旦坏了下游必然跟着坏"的链路 （例如 C61-03 训练流水线的分阶段排查——这里不重复具体病例，只抽象出结构） 阶段: 0 1 2 3 4 5 6 7 状态: OK OK OK OK BAD BAD BAD BAD ← 单调性：坏了就不会变回好 ▲ 第一个坏的阶段，就是根因所在 二分定位：只需 ⌈log2 8⌉ + 1 = 4 次检查（而不是最坏 8 次线性扫描） 查 3 (中点) → OK → 根因在右半 [4,7]，候选从 8 个砍到 4 个 查 5 (中点) → BAD → 根因在左半 [4,5]，候选砍到 2 个 查 4 → BAD → 根因就是阶段 4，候选砍到 1 个 每一步查的都是"把剩余候选精确切一半"的那个点 —— 这正是 IG = H_b(0.5) = 1 bit 的具体体现
这个「恰好 1 bit」的优美结论有一个隐藏前提：检查结果必须是二元且无噪声的。真实工程里的检查经常达不到这个条件——一次「看日志」可能给出模糊的结果（三种可能而不是两种），或者检查本身有假阴性（比如单元测试没覆盖到真正出问题的分支）。面试里如果你把这个结论说得太绝对，反而会显得没有工程经验；正确的说法是「这给了我们一个排序检查优先级的近似原则，不是精确保证」。

4假设必须可证伪：把「可能是 X」翻译成「如果是 X，那么 Y 应该成立」

信息增益最大的前提是检查必须能真的把假设排除掉——而这要求假设本身是可证伪（falsifiable）的，即 Karl Popper 的经典标准：一个命题只有当存在某种可能出现的证据会让它落空时，才有科学意义。「可能是数据问题」这句话本身不可证伪——不管你查到什么，它都能被解释成「对，就是数据问题」或者「不是，但可能是另一种数据问题」，这句话没有任何信息量。

含糊说法（不可证伪）翻译成可证伪版本对应的检查
「可能是数据问题」「如果是数据问题，那么这个类别在训练集里的实例数应该明显偏少（比如 < 50 个）」查这个类别在训练集的样本计数
「模型可能过拟合了」「如果过拟合，那么 train loss 应该远低于 val loss，且这个差距应该随 epoch 增大而扩大」画 train/val loss 曲线，看差距的趋势而不只是当前差值
「可能是标注质量的问题」「如果是标注质量问题，那么用当前模型的高置信度错误反查这批标注，应该能发现系统性错误（呼应 C63-02 的模型回环质检）」抽样人工复核模型高置信错误的标注
「大概是评测口径变了」「如果评测口径变了，那么用旧脚本重跑本周数据应该能复现出旧的（更高的）指标」拿旧评测脚本对本周数据重新跑一遍
「可能只是运气不好，样本量太小」「如果只是抽样波动，那么把评测集从 500 张扩到 5000 张，指标差距应该明显缩小」扩大评测样本量重新算一次置信区间

这张表的规律是：好的假设表述里一定藏着一个「如果……那么……」的可检验预测，而且这个预测必须具体到「查什么、期待看到什么数字或现象」的程度。notebook 里会实现一个 is_falsifiable 检验器——给定一个假设的预测函数和一组可能出现的证据，判断是否存在某种可能证据会让这个预测落空；如果不管什么证据预测都成立，这个假设就是「永真式」，没有诊断价值。

直白说

怎么当场把一个含糊的猜测变可证伪？问自己一句话：「如果我是对的，我应该能在哪个具体的数字或现象上看到证据；如果我是错的，这个数字应该长什么样？」答不出后半句，说明这个猜测还没准备好被检验。

严谨说

更严谨地说，可证伪性不是「必须证明它对」，而是必须能设计出会证明它错的检验。这和统计学里假设检验的逻辑是同构的：零假设永远是可以被数据推翻的那个陈述，而「不管数据怎样都不会被推翻」的陈述根本不配称为一个假设——它只是一句安慰自己的话。

面试里的加分句式：当你说出一个猜测后，主动补一句「如果这个猜测是对的，我预期会在 ×× 上看到 ××；如果没看到，我就把它排除」。这一句话同时展示了假设生成能力和验证意识，比只说出猜测本身值钱得多。

5排除法与反例构造：每一次检查都是淘汰赛

如果说信息增益最大策略回答的是「先查哪个」，排除法回答的是「查完之后怎么处理假设集合」——答案很简单：凡是被证据反驳的假设立刻剔除，而不是「先记下来，回头再说」。这听起来是废话，但面试里真正的失分点是用一次检查只处理一个假设，而不是设计一次检查同时对多个假设做判断。

# 一次检查、三个假设同时判断（伪代码示意，notebook 里有完整可运行版本）
HYPOTHESES = {
    '数据标签错位（坐标系反了）': lambda ev: ev['bbox_valid_ratio'] < 0.5,
    '模型欠拟合':                 lambda ev: ev['train_loss'] > 2.0,
    '评测脚本口径错误':           lambda ev: ev['offline_metric'] != ev['manual_recompute'],
}
# 三个假设各自"如果为真，证据应该长什么样"的可证伪预测，一次查证据表就能同时判三个

上面这三个假设各自的预测互不冲突，意味着一次拉取证据（框有效比例、训练 loss、手工复算的指标）就能同时对三个假设做出裁决，而不是排队一个一个单独去查。这是排除法在效率上真正的价值——不是「淘汰得快」，是「一次行动淘汰多个」。

反例构造：面试官抛出一个断言，你需要主动想反例

诊断题里经常出现这样的桥段：面试官说「我们观察到超过 60cm 的标志几乎不会被误检」，然后问你怎么看。不要顺着这句话往下推——先想一个可能推翻它的反例：「如果这个断言成立，那我预期误检日志里不应该出现任何尺寸大于 60cm 的记录；让我们抽一下误检日志核实。」这正是模块 04 讲的可证伪思路的直接应用，只是这次反例来自你主动构造，而不是等对方给。

直白说

直白地说：排除法不是「一个一个划掉」，是「设计一次检查，让它同时对好几个假设下判断」；反例构造不是抬杠，是「在相信一个说法之前，先想一下什么证据会让它错」。

严谨说

从搜索的角度看，排除法把假设空间从枚举验证（逐一确认每个假设是否为真）转化为逐步收窄（每次检查砍掉一部分候选）——这正是为什么它比「挨个假设去证实」快得多：证实一个假设需要充分证据，而排除一个假设往往只需要一个反例。证伪比证实便宜，这也是 Popper 可证伪性标准的一个实践推论。

排除法的陷阱：如果你的假设集合本身不完整（真正的根因根本不在你列出的候选里），排除法会把你困在「剩下的都不对，但也查不出新东西」的死胡同。正确的做法是在假设集合里始终留一个「以上都不是，需要重新枚举」的桶，一旦所有列出的假设都被排除，主动回到「分解」这一步重新枚举，而不是在错误的候选集合里死磕。

6混杂因素：相关不等于因果

诊断推理里最容易踩的一个坑，是把「两个变量一起变化」直接当成「一个导致了另一个」。真正的原因往往是背后有一个混杂因素（confounder）——一个同时影响你正在比较的两件事的第三变量，让表面的相关性看起来像因果，实际上两者都只是它的副产品。这与 C63-02 讲的数据泄漏（地理/设备/时间维度的分组结构）是同一类问题的两面：泄漏是「混杂因素污染了你的评测」，本节讲的是「混杂因素污染了你的因果判断」。

观察到的相关看起来像的因果结论真正的混杂因素TSR 场景下的具体例子
「夜间场景的漏检率更高」「模型在暗光条件下能力差」夜间同时伴随更远的平均车速、更多逆光路段——真正驱动漏检的可能是车速导致的运动模糊，而不是亮度本身两条路：单独测「白天但运动模糊」的样本，看漏检率是否同样高
「使用某型号相机的车队误检率更高」「这款相机的成像质量差」这批车恰好都跑同一批新开通的路段，那批路段广告牌密度更高——真正驱动误检的是路段，相机型号只是和路段强相关的代理变量对比同型号相机在不同路段的误检率是否也有明显差异
「新模型上线后，某类别 AP 下降」「新模型在这个类别上变差了」上线时间恰好和评测集更新的时间重合——真正的驱动因素是评测集换了，模型本身可能没退步用旧评测集重新测一遍新模型

直白说

怎么识破混杂因素？问一句话：「除了我怀疑的这个原因，还有什么也会同时随它一起变化？」——如果答案不止一个，你手上的「相关」还不足以支撑「因果」这个结论。

严谨说

更严谨地说，判断因果需要能控制混杂变量后再比较——理想情况是随机对照实验（呼应 C63 模块 03 的 A/B 测试），现实中常用的近似手段是分层比较：把「白天+运动模糊」和「白天+清晰」分别拎出来单独比，而不是笼统地比「白天 vs 夜间」。辛普森悖论（Simpson's paradox，见 C64-04 的问答骨架，notebook 会复现经典数值）是混杂因素最极端的表现形式：分层看每一层结论都一致，合计看结论却反过来。

面试里的加分句式：「这个相关性可能是真因果，但也可能是第三个变量同时驱动了两者——我想先做一次分层对比，把这个混杂变量控制住，再下判断。」这一句话直接把你和「看到相关就下因果结论」的候选人区分开来。

7把 C61-03 的检测调试树抽象成通用诊断方法论

C61 模块 03 给出了一套非常具体的检测调试打法：loss 变 NaN 时的四条通路排除、loss 躺平时「按查起来由便宜到贵」排序的四个嫌疑人、mAP 恒为 0 时的三分钟分诊。本节不重复那些具体病例，而是指出一件更重要的事：那套打法本身就是本模块三种搜索策略的三个具体实例，理解了这一层，你就能把同一套方法论迁移到任何一个新领域的诊断题上，而不需要死记每个领域各自的调试清单。

C61-03 的具体做法本模块抽象出的通用步骤对应的搜索策略为什么是这个策略
loss 变 NaN：四条通路逐一排除有限候选集合的逐项验证 + 及时剔除排除法（本课模块 05 节）候选数量少（四个），且每条通路都有独立、廉价的可证伪检查
loss 躺平：四个嫌疑人「按查起来由便宜到贵」排序候选先验大致接近时，先做成本最低的检查最便宜优先四个嫌疑人没有强烈的先验差异，查证成本却相差很大，成本主导排序
mAP 恒为 0：三分钟分诊，三大元凶按优先级快速定位候选先验不均匀、检查代价不同，需要综合排序信息增益最大三大元凶的发生概率和查证代价都不相同，只按成本或只按发生率排都会走弯路
训练链路八段的二分定位候选沿一条有严格因果先后的链路排列，故障单调传播二分法阶段之间有天然顺序，且下游必然继承上游的故障——满足二分法的前提

直白说

直白地说：C61-03 不是一套「只对检测模型管用」的秘籍，而是把本模块的三种策略在检测调试这一个具体场景里各用了一次——候选少就排除、候选价差大就挑便宜的、候选有顺序就二分、都不满足就按信息增益排。

严谨说

更严谨地说，这正是本课程与 C61 的分工原则：C61-03 提供的是「在检测训练这个具体领域，症状与假设集合分别是什么」，本模块提供的是「不管在哪个领域，怎么从假设集合里选出下一步该查什么」——前者是知识，后者是方法。换一个领域（比如推荐系统的点击率突然下降），假设集合会完全不同，但选择下一步检查的方法论是同一套。

把这一节压成一句话：任何一份具体的调试清单，背后都可以拆解成「候选是什么结构（有序/并列/数量多少）→ 选哪种搜索策略」这两步。面试官抛给你一个从没见过的系统时，你不需要「恰好背过这个系统的调试清单」，你需要的是先判断候选结构，再套用对应策略。

8面试里诊断题怎么答：先要更多信息是加分项

很多候选人下意识地觉得「面试官抛出一个模糊的诊断题，我应该马上给出一个像样的答案」，于是硬着头皮编一个听起来合理的原因往下讲。这是最常见、也最可惜的失分方式。真实的诊断永远从「我需要先知道几件事」开始——主动要更多信息，展示的是你知道信息不足时不该下结论，这是加分项，不是拖延或不会做的表现。

  1. 复述症状 + 确认边界：「我确认一下：是所有类别都掉了，还是某几个类别掉得特别多？掉点是突然发生还是这几周慢慢滑坡？」——这两个问题直接决定后面假设集合的形状。
  2. 列出 2–4 个假设，并给出你把它们排在前面的理由：「先验上我会怀疑三件事：数据分布漂移、模型/评测版本不一致、以及标注口径变化。理由是……」——不需要穷尽所有可能，但要说清楚为什么是这几个而不是别的。
  3. 提出首选检查，并说明为什么选它：「我会先查模型版本号是否一致，因为这个检查几乎零成本，而且能直接排除或确认一个高优先级假设。」——呼应本模块的排序方法论，把选择的依据说出来。
  4. 预告收敛路径：「如果版本没问题，我下一步会去看输入分布是否漂移；如果分布也正常，我会怀疑评测口径本身变了。」——这一步展示你已经想好了一条完整的搜索路径，而不是走一步算一步。

这个框架和模块 00 的沟通三铁律（结论先行、显式说假设、主动暴露不确定性）有一个微妙但重要的区别：诊断题里，先行的不是「结论」，是「假设集合与查证计划」——因为此刻你还没有资格给结论，硬给结论反而是「假装知道」的信号。

面试当场最致命的开局：一听完题目就说「肯定是数据问题」，然后被追问「你怎么知道」时支支吾吾。正确的开局永远是「我需要先确认几件事」，哪怕面试官不提供额外信息，说出「如果是 A，我预期看到 X；如果得不到这个信息，我会假设最常见的情况往下走」也比直接下结论安全得多。

反过来，也不要把「要信息」用成拖延战术。问 2–4 个关键问题就要收敛开始给假设——呼应模块 04「卡在澄清阶段不动也是扣分项」的原则，诊断题里同样成立：要信息是为了让下一步查证更精准，不是为了拖过整个面试时间。

9研究前沿与开放问题

诊断与归因推理这件事，工业界称为 Root Cause Analysis（RCA），近几年因为系统越来越复杂而催生了不少自动化尝试。它们和本模块的方法论是同一个问题的不同解法，了解一下有助于在被追问「有没有更系统的做法」时给出有分量的回答。

  • 因果推断（causal inference）在观测数据上的局限。本模块只用了「相关 vs 因果」这个朴素区分，但 Judea Pearl 的 do-calculus 提供了一套更严谨的语言去区分「观察到 X 和 Y 一起变化」与「主动干预 X 会不会改变 Y」。问题是纯观测数据（没有做过 A/B 实验）通常无法唯一确定因果方向，这也是为什么工程实践里「分层对比」只是一个近似而不是严格证明。
  • 自动化根因分析（AIOps）。大规模系统已经开始用统计相关性 + 拓扑图去自动缩小根因候选范围——本质上是把本模块的「候选集合 + 排序策略」自动化了。但这类工具目前普遍存在假阳性率高的问题：统计相关性发现的「嫌疑人」经常需要人工用可证伪性再筛一遍，完全自动化的 RCA 还不成熟。
  • LLM 辅助的假设生成正在改变诊断的第一步。让大模型读日志、读 diff、读监控面板去生成候选假设列表，正在变得可行——但生成假设之后「怎么选下一步验证」这个排序问题（本模块的核心内容）目前仍然依赖人工判断，模型给出的假设也需要用可证伪性标准过滤掉空洞的说法。
  • 诊断的可复现性缺少统一的记录规范。「假设集合 + 每一步查证的结果」这条链路，在很多团队里只存在于个人的脑子和临时的聊天记录里，没有像代码版本管理那样的标准化留痕方式——这也是为什么同一个问题换一个人来查，经常要从头再走一遍已经走过的弯路。

★ 必读：Karl Popper, The Logic of Scientific Discovery——可证伪性标准的原始出处，本模块「假设必须可证伪」一节的理论根基。★ Judea Pearl & Dana Mackenzie, The Book of Why（2018）——用因果阶梯（关联/干预/反事实）的框架理解「相关不等于因果」，比朴素的辛普森悖论叙述更完整。★ Claude Shannon, A Mathematical Theory of Communication（1948）——熵与信息增益的原始定义，本模块「50/50 切分最优」证明的源头。
