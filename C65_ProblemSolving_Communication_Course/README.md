# 结构化问题求解与面试沟通

这门课补的是一块**全库里此前从未被系统覆盖**的板块。

HR 给出的一面形式白纸黑字写着：

> First Round Interview Format (including but not limited to):
> Technical Knowledge Assessment, **Problem-Solving**, and Practical (Coding) Exercise

而"Problem-Solving"——估算、诊断归因、权衡决策、模糊需求澄清、白板沟通——此前散落在各门课的字里行间，
从未被系统整理成一套可以练习的方法论。

## 核心主张

> **考的是思维过程的可见性——面试官买的是你的推理，不是答案。**

同一个正确答案，能不能展示出清晰的推理过程，评分可以差出一个档位。这门课把"怎么想清楚"和"怎么讲清楚"
拆成五个可以分别练习的能力：**估算**（数量级心算）、**诊断**（从症状到根因）、**权衡**（取舍显式化）、
**澄清**（收敛模糊问题）、**沟通**（把前四项组织成让人跟得上的表达）。

## 四步框架速记卡

这是贯穿全课的骨架，00 模块给出模板与自检器，01–04 模块的每一类题型都是这四步在具体场景上的展开。

| 步骤 | 一句话 | 常见失分点 |
|---|---|---|
| ① 澄清 | 把模糊问题转成可验收的规格：目标 / 用户 / 约束 / 现状 / 成功标准 / 不做什么 | 卡在这一步不动；或者一个问题都不问就直接开始给方案 |
| ② 分解 | 把问题拆成可以独立分析、互相独立又合起来穷尽（MECE）的子问题/子维度 | 分解维度互相重叠或遗漏关键维度 |
| ③ 假设与验证 | 每个假设都翻译成"如果成立，X 应该成立，我去查 X"的可证伪形式 | 提出无法验证的模糊假设（"可能是数据问题"） |
| ④ 收敛与权衡 | 列维度 → 定权重 → 打分 → 说清楚放弃了什么 | 只给结论不说放弃了什么；权重从不做敏感性检验 |

## 沟通三铁律速记卡

| 铁律 | 一句话 | 为什么必须同时满足三条 |
|---|---|---|
| 结论先行 | 先给判断，再展开支撑理由，而不是按发现顺序讲一遍再给结论 | 只有结论没有假设支撑，会显得武断 |
| 显式说假设 | 把没有明说但已经在用的前提主动讲出来 | 只讲假设不给结论，会显得抓不住重点 |
| 主动暴露不确定性 | 主动说出"这一步我不完全确定，原因是……" | 不说不确定性，会让考官误以为你对一个脆弱的结论盲目自信 |

## 学习路径（按你还剩多少时间选）

### 路径 A · 还有一周（约 8–10 小时）

完整走一遍 `00 → 01 → 02 → 03 → 04 → 05`，每天一个模块：先读 HTML 讲解并**大声复述四步框架在这一类题型上的具体展开**，
再跑 notebook 把每个估算器/诊断树/决策模拟亲手跑一遍。最后两天专门用 05 模块的 10 题模拟演练引擎自测，
计时、自评、标记连续答得不理想的题型。

判断走完了没有的标准：**随便给你一个模糊的开放题，你能不能在不看笔记的情况下，先用一句话说出你打算怎么展开，
再用四步框架把它讲完整。**

### 路径 B · 还有三天（约 4–5 小时）

`00 全部 → 01/02 各挑 2 个案例跑一遍 → 03/04 各读一遍讲解 → 05 的 10 题演练至少过 6 题`。

理由：**估算和诊断是被问到频率最高的两类题**，权衡和澄清的框架本身比较短，读一遍讲解就能掌握骨架，
真正需要反复练习的是估算和诊断案例的分步展开，以及最后的白板表达。

- **Day 1**：00（四步框架与沟通三铁律必须能脱稿复述）+ 01（估算：锚点数字表 + 两个完整案例）。
- **Day 2**：02（诊断：诊断树 + 一个"训练不收敛"案例）+ 03（权衡：敏感性分析这一步务必亲手跑一遍）。
- **Day 3**：04（澄清清单速览）+ 05（10 题模拟演练至少完成 6 题，重点过一遍脱困话术与中英对照句库）。

### 路径 C · 只剩一晚（约 2 小时）

**不要试图重新学框架，只做两件事：**

1. **重读 00 模块的四步框架与沟通三铁律**（20 分钟）——这是全课唯一必须脱稿复述的部分，
   剩下的模块都是这四步在具体题型上的展开。
2. **过一遍 05 模块的 10 题模拟演练，每题只看"满分答法骨架"不深究细节**（60 分钟）——
   这份清单覆盖了估算/诊断/权衡/澄清四类题型的典型开场方式，投入产出比全课最高。

剩下时间：把 05 模块的三种脱困话术和"我需要一分钟想一下"这句话默念到不假思索——
**卡壳时说出这句话，比沉默或硬撑安全得多，是性价比最高的兜底动作。**

**明确不要做的事**：不要在最后一晚试图纠结 Fermi 估算某个锚点数字的精确出处，或推敲后悔最小化和
最坏情况准则的数学证明细节。遇到这类被追问到深处的问题，诚实地说"这块我的推理是……，如果不对我会调整"，
比含糊地编一个数字更安全。
