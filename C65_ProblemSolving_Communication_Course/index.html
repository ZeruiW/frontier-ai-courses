结构化问题求解与面试沟通

HR 白纸黑字写着一面包含 Problem-Solving，而这一项在全库里此前从未被专门覆盖——估算、诊断归因、权衡决策、模糊需求澄清、白板沟通散落在各门课的字里行间，从未被系统整理成方法论。本课的核心主张：考的是思维过程的可见性——面试官买的是你的推理，不是答案。同一个正确答案，能不能展示出清晰的推理过程，评分可以差出一个档位。

6 模块 四步框架：澄清 → 分解 → 假设与验证 → 收敛与权衡 沟通三铁律：结论先行 · 显式说假设 · 主动暴露不确定性 10 个开放题完整模拟演练 · 每题给评分要点与满分答法骨架 CPU only · 纯 numpy/标准库 · 无需 GPU
怎么用： 每个模块先读 HTML 讲解（每个方法论都按为什么需要它 → 具体怎么做 → 面试官想听什么展开），再跑 notebook——把「知道有这个框架」变成「亲手跑出来验证过」。你会亲手实现的东西包括：Fermi 估算器与对数域误差传播计算器、四个完整估算案例（标注预算、训练时长、显存、QPS）的分步实现、诊断树的通用实现（按期望信息增益/成本排序下一步检查）、三个诊断案例的分步演练（线上指标掉了 / 训练不收敛 / 离线好线上差）、多维加权打分与敏感性分析（权重扰动会不会翻转结论）、帕累托前沿与预算约束下的方案组合计算、三种不确定性决策准则在同一问题上的分歧演示、澄清清单生成器与覆盖度检查、影响-成本-不确定性打分排序器、一套句式库与中英对照表、以及10 题模拟演练引擎（出题 → 计时 → 自评 → 弱项统计）。本课与 C61-04（项目叙事）、C63（系统设计）的分工：C61-04 教你怎么讲你做过的项目，C63 教你怎么设计一个系统，本课教的是通用的估算/诊断/权衡/澄清/沟通方法论，三者互补不重叠。本环境不需要 GPU：所有练习都是纯 numpy/CPU 的数值模拟与小型决策引擎，断网可跑，秒级出结果。
