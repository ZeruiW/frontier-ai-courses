1机密性攻击：API 即攻击面

前两个模块攻击的是模型的行为（让它出错）。本模块攻击的是模型的机密性：在只能query access（黑盒查询 API）的前提下，攻击者能偷走模型的功能（model extraction / stealing），甚至反推出训练数据（model inversion）。这把「模型即资产、API 即攻击面」的事实摆上台面。

直白说

一个部署在云端的模型，对外只暴露一个简单接口：你给输入，它回标签或置信度。看起来什么都没泄露——参数没给、训练数据没给。但 Tramèr 2016 证明：仅凭足够多的「问答对」，就能在本地训出一个功能几乎一样的副本。模型花百万美元训出来的能力，可能被几千次查询白嫖走。

严谨说

更进一步，模型的输出本身就是一条信息泄露通道。置信度向量编码了「模型对各类有多确信」，Fredrikson 2015 用人脸识别模型的置信度梯度，竟重建出了训练集中某个身份的近似人脸。输出越丰富（完整概率 > top-k > 仅 top-1），泄露越多——这是贯穿本模块的防御主线：降低输出信息量。

把这三类攻击放在一起，因为它们共享同一个深刻前提：一个训练好的模型，是其训练数据与算力投入的一种压缩存储——而压缩并非不可逆。窃取逆的是「功能」（把模型的输入-输出映射复制出来），反演逆的是「输入」（把某类的典型样子还原出来），提取逆的是「样本」（把被逐字记住的训练串诱出来）。三者由浅入深，共同戳破一个常见的安全幻觉——「我只开放了一个预测 API，又没给参数和数据，能泄露什么？」答案是：能泄露的，远比你以为的多。

本模块覆盖三类相关攻击：功能窃取（查询训替身）、模型反演（反推输入/属性）、训练数据提取（从生成模型逐字诱出记忆样本，连接下一模块的隐私）；并给出对应防御：限流、输出降信息量（只回 top-1 / 量化 / 加噪）、水印取证。

伦理边界

边界提醒：未经授权窃取他人模型、反推他人隐私数据，在法律上通常构成侵权甚至犯罪。本模块在自建玩具模型上演示，目的是让 ML 服务的提供者理解自己的 API 会泄露什么、该如何设防。把它当成保护自己模型的攻防演练，而非窃取工具。

2模型窃取：查询训替身

模型窃取：用查询训练替身

窃取的基本流程极简：① 准备一批查询输入（自有数据、公开数据、或合成点）；② 把它们逐个喂给目标 API，记录返回；③ 用「输入 → 目标返回」这些伪标签训练一个本地 surrogate / substitute model（替身）。训练目标是让替身的预测尽量贴近目标模型，而非贴近真实标签。

这本质上是一次知识蒸馏，只不过「教师」是别人花大价钱训出的黑盒模型，而「学生」是攻击者免费白嫖的副本。教师返回的软标签（完整置信度向量）比硬标签（仅 top-1）信息量大得多——它泄露了「目标对每个类有多确信」「哪些类容易混淆」这些决策边界的细节，让学生用更少的查询就能逼近。这也立刻提示了防御方向（第 6 节）：API 返回的信息越少（只回 top-1、量化置信度），蒸馏的效率就越低——把慷慨的软标签收紧，是抬高窃取成本最直接的一招。

攻击者 目标模型 (黑盒) 生成查询 x1,x2,... ──────► f(x) 收集返回 f(x1),f(x2) ◄────── (标签 / 置信度) │ ▼ 用 {(xi, f(xi))} 当训练集 训练替身 g ≈ f ← 窃取完成：本地拥有功能副本 ← 副本还可作生成可迁移对抗样本的跳板(接模块01)

效率取决于查询点的选择。随机查询能学个大概，但 Papernot 2017 的 Jacobian-based augmentation（基于雅可比的数据增广）更高效：用替身当前的雅可比指导，在决策边界附近合成新查询点——边界是信息量最大的地方，在那里多问几句，能用更少查询逼近目标。这与「主动学习」异曲同工：问最有信息的问题。

直白说

窃取像「隔着墙描摹一幅画」：你看不到画（参数），但可以无限次问「这个点是什么颜色」（查询）。问得越多、越聪明（专挑边界、轮廓处问），描出来的副本越像原作。

严谨说

一个常被混淆的区分（Jagielski 2020）：fidelity vs accuracy。保真度=替身与目标模型预测的一致率（连目标的错误也学）；准确率=替身在真实标签上的表现。纯功能窃取追求保真度（要一个一模一样的副本）；若只想要个好用的模型，则追求准确率。两者的最优查询策略不同。

把窃取的威胁模型讲清，能帮你判断自己的 API 暴露在哪一档风险下。按攻击者能拿到的信息从弱到强排：① 仅 top-1 标签——最弱通道，但 Tramèr 2016 证明足够多查询仍能窃取（只是慢）；② top-k 概率——泄露了类间混淆结构，蒸馏明显加速；③ 完整置信度向量——把决策边界的细节几乎和盘托出，窃取效率最高；④ 梯度/logit 接口（某些「可解释性」或嵌入 API 会暴露）——最危险，等于半个白盒。攻击者的另一个维度是查询分布：能用同分布真实数据查询的，比只能用随机噪声查询的高效得多——因为前者覆盖了模型真正会被用到的输入区域。一句话：你返回得越多、越允许贴近真实分布地查询，窃取就越省力，这两点正是第 6 节防御的两个着力点。

窃取还有一个常被忽视的放大效应：替身一旦到手，它就成了攻击者的白盒副本——而模块 01 告诉我们，在白盒上生成的对抗样本能迁移回原黑盒目标。于是「窃取 → 替身 → 在替身上白盒造对抗样本 → 迁移攻击原模型」连成一条完整的现实攻击链：本来你只开放了一个看似无害的预测 API，最终却让攻击者获得了精准攻击你的能力。这正是为什么本课把窃取（03）紧接在对抗样本（01）之后——它们不是孤立的章节，而是同一条攻击路径上的相邻环节。

notebook 会在玩具目标模型上完整实现：随机查询 → 收集返回 → 训替身 → 测保真度，并画出保真度随查询预算上升的曲线。

3查询预算与保真度权衡

查询预算与保真度权衡

窃取的核心经济学是 query budget（查询预算）与 fidelity vs accuracy 的权衡。一般规律：查询越多，替身保真度越高，但收益递减——前几百次查询学到大轮廓，之后每次查询的边际信息越来越少。这条曲线的形状，正是攻防双方博弈的战场。

\[\text{fidelity}(g, f) = \Pr_{x\sim\mathcal{D}}\big[\,g(x)=f(x)\,\big]\ \nearrow\ \text{随 query budget 上升而饱和}\]

对防御者，这条曲线给出明确的目标：把「达到给定保真度所需的查询数」推高。如果窃取一个 95% 保真度的副本需要十万次而非一千次查询，攻击的经济性就大打折扣（查询要花钱、要时间、容易触发异常检测）。这就是为什么限流与降低单次查询信息量是窃取防御的两大支柱——前者限制查询总量，后者降低每次查询的价值。

把窃取放进一个更大的经济账里看会更清楚：攻击者窃取的动机通常是省下自己训练的成本（训练数据、算力、调参的投入）。如果窃取一个够用副本所需的查询费用、时间、被封号的风险，加起来接近或超过自己从头训练的成本，理性的攻击者就不会窃取了。所以防御的真正目标不是「让窃取在数学上不可能」（做不到），而是把窃取的总成本抬到高于其收益——这与第 4 节反演、模块 04 隐私的防御哲学完全一致：安全是经济学，不是绝对论。

一笔 worked 微账，把「降信息量如何改写经济性」算给你看：假设按 API 计费每千次查询 $2。攻击者用软标签（完整概率向量）蒸馏，10 万次查询即可得到 95% 保真度的副本，成本约 $200——相对原模型的训练投入简直白送。防御方把 API 改成只返回 top-1 硬标签后，每次查询的信息量锐减，达到同样 95% 保真度的查询数可能涨到 100 万次甚至更多，成本随之升到 $2000+，且 100 万次的扫描极易触发限流与异常检测而被封号。一个「只改返回字段」的零算法改动，就把攻击成本抬高了一个数量级、并大幅增加暴露风险——这就是「降信息量」作为窃取防御第一招的性价比。

把窃取看成「攻击者花 N 次查询换 F 的保真度」。防御不是让 F 永远到不了高位（做不到——查询够多总能逼近），而是让换取高 F 的 N 大到不划算。安全工程里很多防御都是这个哲学：不追求绝对不可破，而是把攻击成本抬到超过攻击收益。

4模型反演与属性推断

模型反演与属性推断

model inversion（模型反演）的目标不是复制模型，而是反推训练数据。Fredrikson 2015 的经典案例：给定一个人脸识别模型和某个人的名字（类别），通过优化一张输入图，使模型对该类别的置信度最大化，竟能重建出一张可辨认该身份的人脸——因为模型为了识别这个人，把这个人的特征编码进了参数。

\[x^* = \arg\max_{x}\ f_c(x)\ -\ \lambda\,\mathcal{R}(x)\qquad(\text{优化输入使目标类置信度最大}+\text{正则保证“像真输入”})\]

式中正则项 $\mathcal{R}(x)$ 至关重要：没有它，纯粹最大化置信度会得到一个对抗样本式的怪图（模型很自信但人眼看是噪声）——这恰恰和模块 01 的对抗样本同根同源，只是优化方向相反（对抗样本要让模型错得自信，反演要让模型对某类自信）。正则把解约束在「看起来像真实输入」的流形上，重建的才是有意义的类原型而非噪声。notebook 里我们用简单的 L2 正则（防止输入跑飞），练习 4 会让你对比有无正则的重建质量——这是反演能否「重建出像样东西」的关键旋钮。

与之相关的是 attribute inference（属性推断）：已知个体的部分特征，利用模型反推其隐藏的敏感属性。例如某医疗模型，若攻击者知道病人的一些公开信息，可能通过查询模型反推出本应保密的诊断相关属性。两者共同说明：模型是训练数据的有损压缩，而压缩并非不可逆。

一个对比微例，把「类粒度决定危害」说穿：设模型 A 是「猫/狗」二分类，「猫」这个类背后是上万只不同的猫；反演爬出的「最大化猫置信度的输入」只会是一张四不像的平均猫——它不对应任何一只真猫，隐私危害近乎为零。设模型 B 是人脸识别，「张三」这个类背后只对应张三一个人；反演爬出的「最大化张三置信度的输入」就逼近张三本人的长相——隐私灾难。同一套梯度上升算法，危害天差地别，差别只在一个类对应多少个体：类越细、越接近「一类一人」，反演的输出就越从「类平均」坍缩到「具体个人」。这条规律给防御者一个直接的风险评估法则：盘点你的模型里有没有「一类几乎只对应一个人/一条记录」的类，那里才是反演风险真正高的地方。

反演要诚实地标注其边界：它重建出的，严格说是「最大化某类置信度的输入」，未必等于任何一条真实训练样本。当一个类对应很多人时，反演爬出的往往是该类的某种平均/典型形象，隐私危害有限；但当一个类几乎只对应一个个体（如「人脸识别中某个人的身份」）时，这个「类的典型形象」就逼近了那个人本身，隐私灾难才成立。理解这个「类粒度决定危害」的关系，能让你判断哪些模型/任务的反演风险真正高——这也是为什么本课玩具用「每类一簇」来清楚展示反演逼近类中心的机制。

直白说

反演的直觉：模型为了把某类分对，必然在内部「记住了该类长什么样」。攻击者不断问模型「这样像不像 X 类」，顺着置信度往上爬，就能爬出一个模型心目中X 类的典型样子——若该类只对应一个人，这就是隐私灾难。

严谨说

反演的成功度与模型的记忆程度强相关：模型越过拟合、类越细（极端是「每类一个人」），反演越有效；模型泛化好、类内多样，反演出的多是「类平均」而非具体个体。这条记忆-泄露的线索，正是下一模块成员推断的核心，也指向同一个防御——差分隐私。

反演与模块 01 的对抗样本是同一把梯度上升刀的两种用法，把这点想透很有启发：对抗样本固定模型与真标签、优化输入去最大化损失（让模型出错）；反演固定模型与目标类、优化输入去最大化该类置信度（让模型「认出」这个类）。两者都对输入求梯度、都沿梯度走、都需要正则约束在合理流形上。区别只在优化目标的符号与对象。这种「同一工具、不同目标」的模式在本课反复出现（PGD 攻击 vs 对抗训练、后门 vs 水印）——掌握底层工具（梯度、优化、约束投影），你就能在攻与防之间自由切换视角，这正是安全研究者的核心能力。

notebook 会在玩具回归/分类模型上演示反演的核心：固定模型、对输入做梯度上升最大化某类置信度，看重建出的输入是否逼近该类的训练样本中心。

5训练数据提取：记忆即泄露

训练数据提取：记忆即泄露

在生成式模型上，机密性攻击有一个更直接的形态：training data extraction（训练数据提取）。Carlini 2021 从 GPT-2 中逐字诱出了训练语料里的原文——包括真实的人名、电话、地址。模型并没有「理解」这些信息，只是把见过的稀有串记住了，于是在合适的提示下原样吐出来。

机理是 memorization（记忆）：模型把个别训练样本（尤其是稀有、独特的串）的细节编码进参数，而非只学普适规律。提取方法：用模型生成大量文本，再用「模型对它异常自信（困惑度极低）」等信号筛出最可能是逐字记忆的片段。记忆与样本出现频率、独特性强相关——越独特的私密信息，越容易被精确记住和提取。

为什么「困惑度极低」是逐字记忆的指纹，值得算一下：语言模型对一段文本的困惑度，衡量它「预测这段话有多吃力」。对一段普适、可由规律生成的文本（如常见句式），模型靠泛化也能预测得不错，困惑度中等。但对一段独一无二、毫无规律可循的串（如随机的电话号「13800001234」），模型唯一能把它预测得很准（困惑度极低）的方式，就是把它逐字背了下来——泛化帮不上忙。于是「模型对某段独特文本异常自信」几乎等价于「它记住了这段原文」。提取攻击正是反过来利用这点：大量采样生成，再挑困惑度异常低的片段，就把被逐字记忆的私密串筛了出来。这也立刻指出防御方向——训练前去重（重复越多越易被背）与含 PII 样本脱敏。

这里有个值得深思的反直觉点：越独特的信息越容易被精确记住，也就越容易被提取。一个常见的句式（「今天天气不错」）即使出现千百次，模型也只学成普适规律、提取不出特定来源；但一串独一无二的私密信息（某人的身份证号、一段私有密钥），模型为了拟合它只能逐字背下来，于是在合适的提示下原样吐出。这意味着隐私风险与信息的独特性正相关——恰恰是最该保护的敏感信息，最容易被记住和提取。这条规律会在下一模块（成员推断）以另一种形式再次出现：稀有样本最容易被指认为成员。

从防御视角，训练数据提取给出两条可操作的启示：① 训练前去重 + 脱敏——重复多次的串更易被记住，去重能显著降低逐字记忆；含 PII 的样本应在入训前清洗。② 差分隐私训练（接模块 04）从原理上限制任何单条样本对模型的影响，是对「记忆即泄露」最对症的防御。这也再次印证全课的主线——先理解攻击（记忆为何能被提取），才知道防御该往哪使劲（去重、脱敏、DP），而不是盲目地「加密模型文件」之类的无效操作。

隐私实锤

训练数据提取把「记忆 = 隐私风险」从理论变成实锤：用公开数据训练并不安全，因为公开语料里夹带的私密信息会被模型记住并可被提取。这直接连接下一模块（成员推断）与隐私防御：要从根上缓解，需要差分隐私训练（DP-SGD）或严格的训练数据去重/脱敏。本课不演示对真实模型的提取，只在玩具模型上说明「记忆可被探测」的机制。

6防御：限流、降信息量、水印

防御：限流、降信息量、水印

针对窃取/反演/提取，防御沿三条线展开，遵循「既然攻击靠查询和输出信息，就限制查询、压缩输出」：

防御做法原理代价
限流 / 异常检测 rate limiting / anomaly detection限制查询频率；检测系统性扫描边界的异常查询模式抬高达到给定保真度所需的时间/查询，使窃取不经济误伤高频正常用户；需调阈值
降输出信息量 extraction defense: rounding / noise只返回 top-1 标签而非完整概率；置信度量化/加噪每次查询泄露的信息变少 → 同样保真度需更多查询正常用户也拿不到细粒度置信度
差分隐私训练DP-SGD 训练（接模块 04）限制单样本对模型的影响 → 反演/提取更难还原个体干净精度下降
模型水印 watermarking (model)对特定触发输入嵌入可验证的特定输出事后证明某副本源自自己（取证/威慑）不预防窃取，只追责；可能被去除

注意一个分类：前三者是预防/缓解（让窃取更难、泄露更少），水印是取证/威慑（窃取发生后能追责）。成熟的防御是两者结合——既抬高攻击成本，又保留追责能力，再叠加监控，构成纵深防御。

这里有一个无法回避的根本张力：模型要有用就必须输出信息，而输出信息就会泄露。一个完全不泄露的模型（比如对所有输入都返回均匀分布）也完全没用。所有这些防御本质上都是在可用性与机密性之间挪动权衡点：返回完整置信度最有用也最泄露，只返回 top-1 标签泄露少但对正常用户也少了信息，加噪/限流进一步压缩泄露但也牺牲体验。没有「既完全有用又完全不泄露」的免费午餐——这正是为什么有原则的隐私防御（如差分隐私）要把这个权衡量化成可调的隐私预算，而不是靠拍脑袋。模块 04 会把这个量化的故事讲完。

直白说

降信息量是个朴素而有效的招：很多 API 默认返回完整概率向量，纯属慷慨。改成只返回 top-1 标签，反演和窃取的难度立刻上一个台阶——因为攻击者失去了最富信息的梯度/置信度信号。

严谨说

但要清醒：这些防御都是提高成本而非杜绝。Tramèr 2016 指出，即便只返回 top-1 标签，足够多的查询仍能窃取（只是更慢）。没有单一防御能挡住有耐心、有预算的攻击者——这正是为什么要限流 + 降信息量 + 监控 + 水印层层叠加，并接受「绝对安全不存在，只有成本权衡」。

水印这条取证线值得单独多说一句：它不预防窃取，只在窃取发生后提供「这是我的模型」的证据。机制类似一个良性后门（呼应模块 02）——对一组只有所有者知道的触发输入，模型给出特定的「暗号」输出。若怀疑某个部署是窃取自己的副本，就用这些触发输入去问它，对上暗号即为铁证。它的局限也明显：水印可能被微调/再蒸馏洗掉，且只能事后追责、不能阻止窃取本身。所以成熟方案总是预防（限流+降信息量+DP）与取证（水印）并用。

防御陷阱

对模型水印别抱两个错觉：① 「埋了水印就安全了」——水印不阻止任何一次窃取，只在事后提供证据；把它当预防手段会让你疏于真正的限流与降信息量。② 「水印一定查得出」——攻击者若不直接转卖、而是把窃来的替身再蒸馏一道、或在自有数据上微调几轮，触发式水印往往被冲刷殆尽，对暗号失败。换言之水印是一道会被洗掉的取证线，只能作为纵深的最后一环、配合预防与监控使用，绝不能当作单独的防线信任。

notebook 会量化这些防御：对比「返回完整置信度 vs 只返回 top-1 标签」时，窃取替身在相同查询预算下的保真度差异，亲眼看到降信息量如何抬高窃取成本。

7从玩具到现实：notebook 怎么练

从玩具到现实：本模块 notebook 怎么练

配套 notebook 在自建玩具目标模型上把三类攻击与防御走通：

  • 功能窃取：训一个玩具目标模型当「黑盒 API」，用随机查询收集返回、训替身，测保真度；
  • 保真度-查询曲线：扫不同查询预算，画保真度上升并饱和的曲线，理解查询预算的经济学；
  • 降信息量防御：对比「目标返回完整概率 vs 只返回 top-1 标签」时窃取保真度的差异，量化防御效果；
  • 模型反演：固定模型、对输入梯度上升最大化某类置信度，看重建结果是否逼近该类训练样本中心；
  • 水印：给目标模型嵌入触发式水印，验证「替身不会复制水印」可作为窃取取证信号。

每步都有 assert 锁定结论（如 assert fidelity_topk > fidelity_top1 验证降信息量确实抬高了窃取难度）。玩具规模让机制清晰可见，而你理解的窃取/反演结构与 Tramèr/Fredrikson 论文里的完全一致。

一个特别值得在 notebook 里亲手体会的点是水印为何需要非线性模型：我们刻意用一个 2 层 MLP 当目标，因为线性模型的决策函数是全局的——在偏僻区域埋的水印会均匀地改变整个决策面，于是替身在窃取功能时连水印一起学走了，取证失效。MLP 的非线性让水印可以局部化在攻击者查询覆盖不到的偏僻区域，目标记得住、替身复制不出，水印才成立。这个细节本身就是一堂课：防御机制的可行性常常依赖于模型的表达能力，脱离模型类谈防御是不严谨的。

8研究前沿与开放问题

研究前沿与开放问题

机密性攻击是一个攻防都在快速演进的领域——既因为模型越来越值钱（窃取动机增强），也因为生成模型把「记忆即泄露」的风险推到了新高度。几个活跃方向：

  • 高效窃取 LLM：从 API 窃取大模型的部分参数（如最后一层、嵌入矩阵）已被证明可行（Carlini 2024 等）。如何在合理查询下窃取/逼近前沿模型，以及如何防，是热点。
  • 反演的可还原边界：模型到底「记住」了多少可还原的训练信息？反演成功度与架构、过拟合、类粒度的定量关系，仍缺乏统一理论。
  • 水印的鲁棒性：模型水印能否抵御微调、剪枝、再蒸馏等去除手段？以及生成内容水印（区别于模型水印）能否可靠存活，是版权与溯源的关键。
  • 窃取与对抗样本的合流：替身模型是生成可迁移对抗样本的天然跳板（Papernot 2017）。窃取 → 替身 → 黑盒对抗攻击的完整链条，把本模块与模块 01 串成一条现实攻击路径。
  • 防御的根本张力：模型要有用就得输出信息，输出信息就会泄露。如何在可用性与机密性间找到有原则的平衡（如带 DP 保证的预测 API），是这条线的终极问题。

必读：Tramèr 2016（模型窃取奠基）、Papernot 2017（实用黑盒+替身）、Fredrikson 2015（模型反演）、Carlini 2021（训练数据提取）。完整清单见 references.md。
