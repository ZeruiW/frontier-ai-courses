1为什么学攻击：防御视角与伦理边界

传统软件安全问「攻击者能否让程序做它不该做的事」。机器学习系统把这个问题放大了一个维度：模型的行为不是写死的代码，而是从数据里学出来的——于是数据、训练过程、模型权重、推理接口、乃至整条交付供应链全都成了新的攻击面。这门课就是系统地走一遍这些攻击面：每一种攻击讲清它的机理、威胁模型与代价，然后立刻配上检测与防御。

ML 安全与传统软件安全有一个本质差异值得先点明：传统漏洞往往是实现 bug（缓冲区溢出、SQL 注入、逻辑错误），补丁能修；而许多 ML 脆弱性是学习范式本身的内禀属性——对抗样本源于高维决策边界的几何，成员泄露源于「记忆有助泛化」的张力，prompt 注入源于「模型分不清指令与数据」。它们不是「写错了一行代码」，而是当前学习方法的结构性后果，因此往往无法被彻底「修复」，只能被缓解、被度量、被纵深防御。认清这一点，能让你对「为什么没有一劳永逸的解药」有正确的预期——这也是本课不卖银弹、只教攻防权衡的原因。

直白说

把一个 ML 系统想成一条流水线：收集数据 → 训练 → 得到模型 → 上线提供预测 → 嵌入更大的应用（RAG/agent）。传统安全只盯最后那个 API；但攻击者可以在任何一段动手——往数据里掺毒、偷走模型、从输出反推隐私、用一段文本劫持 agent。防御者要做的，是把每一段都纳入威胁建模，而不是假设「模型一旦训好就安全了」。

严谨说

形式化地说，ML 安全在经典 CIA triad（机密性/完整性/可用性）之上展开：隐私攻击（成员推断、反演、窃取）破坏机密性；对抗样本与后门破坏完整性（让模型在选定输入上出错）；可用性投毒破坏可用性（让模型整体崩掉）。再加上 LLM 时代特有的 滥用/越权（prompt injection、工具滥用）。一个攻击属于哪一格，决定了它的目标、可行性与对应防线。

本课的根本立场必须先说清楚：讲攻击是为了防御。这与渗透测试、漏洞研究的伦理一脉相承——你必须理解攻击者怎么想、能做到什么程度，才能设计出真正挡得住的防御、把有限的安全预算花在刀刃上。所以本课的每一个攻击演示之后，都紧跟一个检测器或防御层；攻击本身只是通往防御的台阶，不是目的地。

伦理与法律边界

使用边界（请认真读）：本课所有攻击演示都是小规模、教学性的，跑在我们完全掌握真相的玩具分类器与合成数据上，目的是让你看懂机制，不提供、也不演示任何可直接迁移到真实系统、对他人造成真实危害的武器化产物。安全研究的通行准则同样适用于此：只在你自己拥有的、或已获得明确书面授权的系统上做攻击实验；未经授权探测、窃取、投毒、注入他人的 ML 系统在法律与伦理上都是不可接受的。把本课当成蓝队/红队的攻防素养训练，不是攻击手册。

2攻击面分类：按生命周期切

攻击面分类：按生命周期切

给攻击分类最有用的第一刀，是按它发生在 ML 生命周期的哪个阶段。不同阶段攻击者需要的访问权限、能造成的影响、以及防御的着力点都完全不同：

阶段代表攻击攻击者需要什么防御着力点本课模块
训练期 training-time数据投毒、后门植入能改/注入训练数据或干预训练数据来源可信 + 消毒 + 检测02
推理期 inference-time对抗样本、海绵样本能构造输入（白盒或查询）鲁棒训练 + 输入校验 + 检测01
提取期 extraction模型窃取、反演、成员推断、数据提取查询 API（看标签/置信度）限流 + 降信息量 + DP + 水印03 / 04
部署/系统期 deploymentprompt 注入、工具滥用、供应链投毒能影响模型读到的内容或依赖隔离 + 最小权限 + 签名校验05

这张表就是整门课的骨架。注意一个容易被忽视的事实：攻击面随系统变复杂而扩张。一个孤立的图像分类器主要担心对抗样本；一个开放查询的云端模型还要担心被窃取与隐私提取；而一个能读网页、调工具的 LLM agent，攻击面则膨胀到包含它读到的每一段不可信文本和它依赖的每一个第三方组件。这也是为什么本课从单点攻击（对抗样本）一路讲到系统级攻击（prompt 注入 + 供应链）——攻防的边界正随 AI 系统的能力一同推进。

为什么「按阶段切」比「按攻击名字列清单」更有用？因为同一阶段的攻击共享防御思路。训练期的攻击（投毒、后门）不论花样如何，防线都落在数据来源可信、训练前消毒、训练后检测这同一组手段上；提取期的攻击（窃取、反演、成员推断）不论目标是功能还是隐私，防线都落在限流、降低输出信息量、差分隐私上。把攻击归到阶段，你就知道该往流水线的哪一段加防护、该复用哪一套工具——而不是为每个新攻击名字单独发明一个补丁。这正是分类学（taxonomy）的工程价值：它把无穷无尽的攻击变体，收敛成有限的几类防御战场。

还要强调阶段之间的传导与放大：攻击很少孤立发生。一个训练期植入后门的模型，会经部署期的供应链扩散给所有下游用户（模块 02→05）；一个被提取期窃取出来的替身，又能成为推理期黑盒对抗样本的跳板（模块 03→01）。所以真实的威胁建模不能只看单点，要顺着这条跨阶段的攻击链想——这也是为什么纵深防御（每个阶段都设防）比把所有赌注压在某一道「最强防线」上更稳健。

一个好用的记忆法：把攻击者问三个问题——他在哪一步插手（阶段）、他想破坏 C/I/A 哪一个（目标）、他有多大权限（白盒/黑盒/查询/能改数据）。这三个维度（阶段 × 目标 × 能力）正是 NIST AML 分类的主轴，任何一种新攻击都能用它们定位，任何一种防御也都能问「它挡住了哪一格」。

3攻击者建模：能力 × 知识 × 目标

攻击者建模：能力 × 知识 × 目标

「这个系统安全吗」是个没法回答的问题——必须先固定威胁模型：我们假设攻击者有什么、想要什么。脱离威胁模型谈安全，就像不说载重就问「这座桥结实吗」。一个严谨的威胁模型至少要钉死三件事：

  • 知识（knowledge）：white-box（知道结构与全部参数，可算梯度）/ black-box（只能看输入输出）/ 灰盒（知道结构不知参数）。白盒是最坏情况假设——按它设防最稳妥；但很多真实攻击（窃取、黑盒对抗样本）恰恰证明黑盒也足够危险。
  • 能力（capability）：能否改训练数据（投毒）、能查询多少次（query budget）、能否读梯度、能否影响模型读到的外部内容（注入）。能力假设直接决定攻击是否可行。
  • 目标（goal）：破坏机密性 / 完整性 / 可用性中的哪个；完整性攻击里又分 attacker goal: targeted / untargeted（指定误分到某类 vs 只要分错）。目标决定攻击的难度与衡量指标。

一个关于「知识」假设的经典智慧，来自密码学的 Kerckhoffs 原则：系统的安全性不应依赖于算法的保密，而应只依赖于密钥。搬到 ML 上就是——不要假设「攻击者不知道我的模型/防御机理」能带来安全。这种「靠隐藏求安全」（security by obscurity）一再被证明脆弱：模型可以被窃取（模块 03）、对抗样本可以迁移（模块 01）、防御机理可以被逆向。所以严肃的威胁建模通常采用白盒最坏情况假设：假定攻击者完全了解你的系统，在此之下仍然安全，才是真的安全。本课反复回到这一点：防御要在攻击者知情的前提下成立。

一条贯穿全课的安全工程原则是 defense-in-depth（纵深防御）：不要把希望寄托在单一防线上。对抗样本可以靠鲁棒训练 + 输入检测 + 输出监控三层叠加；prompt 注入要靠输入过滤 + 权限隔离 + 人类确认多层兜底。因为几乎每一种单点防御都被证明可被adaptive attack（自适应攻击）绕过——攻击者一旦知道你的防御机理，就会专门针对它。层层设防的意义在于：突破一层不等于得手，每多一层都抬高攻击成本、增加被发现的概率。这与「假设攻击者知情」是同一枚硬币的两面——正因为单层一定会被针对性攻破，才需要多层让攻破全部的总成本高到不值得。

直白说

用威胁模型说话，能让安全讨论从「我觉得这样比较安全」升级为「在攻击者只能黑盒查询 1000 次的假设下，这个防御能把窃取保真度压在 70% 以下」——可证伪、可度量、可改进。

严谨说

这也解释了为什么本课每个模块都给攻击和防御都配了量化指标：对抗样本看 robust accuracy @ ε，后门看 ASR，窃取看 fidelity @ query budget，成员推断看 TPR @ low FPR。没有数字的安全主张是空话——攻防的本质是一场可度量的成本竞赛，而非「安全/不安全」的二元判断。

4方法论：玩具模型 + 攻击→检测→防御

方法论：玩具模型 + 合成数据 + 攻击→检测→防御三件套

本课全程纯 numpy、CPU 可跑，刻意用玩具模型与合成数据。这不是简化的妥协，而是教育与伦理的双重选择：

为什么玩具模型/合成数据带来的好处
我们知道全部真相（埋了哪个后门、哪些是成员、真概念方向是什么）攻击/防御的效果可以对照 ground truth 精确验证，而不是「看起来对了」
规模小、CPU 秒级能把每个算法从零写出来、逐行看懂机制，而非调库黑箱
不依赖、不产出真实系统的可攻击产物符合「防御视角、授权研究」的定位，绝不外溢成危害他人的工具
机制与真实攻击同构你在玩具上理解的 FGSM/PGD/MIA/注入结构，与真实论文里的完全一致，只差规模

每个模块的 notebook 都遵循同一条攻击 → 检测 → 防御的纪律：先用 numpy 把攻击从零实现、打印出它确实奏效的证据（如对抗样本让准确率从 95% 掉到 10%）；再实现一个检测器（如谱签名挑出毒样本、loss 阈值识别成员）；最后实现一个防御（如对抗训练把鲁棒精度拉回来、限流压低窃取保真度），并用 assert 验证防御确有效果。只演示攻击而不给防御，在本课是不完整的——这正是「讲攻击是为了防御」在代码层面的落实。

为什么坚持用 assert 把每个结论钉死？因为安全工程里最危险的是「我以为它有效」。对抗样本、后门、隐私泄露的效果都是反直觉的——肉眼看不出扰动、测试集看不出后门、平均指标看不出隐私风险。如果只靠「打印出来看着差不多」，极容易自欺。本课让每个攻击都断言「它确实把指标打坏了」、每个防御都断言「它确实把指标救回来了」，用可复现的数字代替感觉。这套先有可信基线、再做改动、用断言验证的纪律，正是真实安全评估（红队/蓝队报告）的工作方式，也是把「安全」从口号变成工程的关键。

有人会问：玩具模型上得到的结论，凭什么相信它在真实系统上也成立？答案是——本课追求的不是数值的可迁移，而是机制的可迁移。FGSM 在 64 维玩具上沿梯度符号走一步，与在 ImageNet 上沿梯度符号走一步，是逐行相同的算法；后门在玩具数据上「学一个 trigger 捷径」，与在真实数据集上完全同构；MIA 利用的「成员损失更低」在任何用经验风险最小化训练的模型上都成立。规模会改变数字（鲁棒精度多少、ASR 多高），但不会改变为什么攻击奏效、为什么防御有效。把机制吃透，换到任何规模、任何架构你都能立刻判断「这个攻击在这里成不成立、这个防御该往哪使劲」——这正是玩具教学的价值所在。

一个反复出现的方法论陷阱（模块 01 会专门展开）：评测攻击/防御时，弱攻击会制造虚假的安全感。一个防御挡住了 FGSM，不代表它挡得住 PGD 或自适应攻击；一个 MIA 平均准确率不高，不代表它不能以极低误报精准指认少数样本。本课坚持用强基线 + 正确指标评测，并反复提醒：安全里没被攻破 ≠ 安全，只是还没遇到对的攻击。

5课程衔接、环境与学习节奏

与其他课程的衔接、环境与学习节奏

本课在课程体系里的位置很明确：补「经典对抗 ML + AI 安全工程」这块系统骨架，与几门姊妹课互补——

  • C05 前沿模型安全评估与红队：偏 LLM 红队、危险能力评测、AI control。本课的模块 05（prompt 注入）与它直接接壤，但本课更系统地覆盖经典对抗 ML（对抗样本、投毒、窃取、成员推断）这一 C05 较少展开的层面。
  • C12 负责任 AI：偏偏见、公平、毒性、隐私与危害分类。本课模块 04（成员推断与隐私）、模块 03（数据提取）从攻击与度量的角度补强它的隐私章节——你需要先会攻击，才能验证隐私防御是否真的有效。
  • 隐私防御工程（差分隐私等）：本课模块 04 把成员推断作为攻击侧讲透，并指向差分隐私（DP-SGD）作为有原则的防御落点，是「先理解威胁、再上防御」的标准顺序。

再点明一次本课刻意不做什么，以校准预期：不教对特定真实模型有效的越狱串、不提供可直接投放到他人系统的攻击载荷、不追求真实规模的攻击效果。这些既是伦理边界（防御视角、授权研究），也是教学选择——真实武器化产物会把注意力从「机制」拽向「招式」，而招式会过时、机制不会。本课要你掌握的是可迁移、不过时的攻防直觉：FGSM/PGD 的优化结构、后门的捷径学习、MIA 的过拟合根源、注入的「指令-数据不分」、供应链的「加载即执行」——这些理解放到任何规模、任何具体系统上都成立。

✅ 学完整门课，你应该能：
  1. 对一个 ML 系统画出攻击面（阶段 × 目标 × 能力），并指出最该优先防的环节；
  2. 在玩具模型上从零实现 FGSM/PGD 对抗样本，并用对抗训练把鲁棒精度拉回来、识别梯度遮蔽式的虚假鲁棒；
  3. 构造后门（trigger→目标类），并用谱签名 / 激活聚类把毒样本检测出来；
  4. 通过查询训练替身实现模型窃取，量化保真度随查询预算的变化，并设计限流/降信息量防御；
  5. 实现 loss 阈值与 shadow-model 成员推断，用 TPR@low FPR 正确评价它，并说明差分隐私如何缓解；
  6. 模拟直接/间接 prompt 注入与 agent 工具滥用，设计权限隔离 + 双 LLM + 输入校验的分层防御；
  7. 审计一条 ML 供应链（权重/数据/依赖/反序列化），用 safetensors、哈希签名、最小权限堵住高危点。
