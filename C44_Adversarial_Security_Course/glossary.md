# 术语词典 · Glossary（对抗 ML 与 AI 安全攻防）

> 按主题分组，每条 2–3 句释义。读对抗样本 / 投毒 / 模型窃取 / 成员推断 / prompt 注入论文与 NIST AML 分类遇到生词回这里查；英文术语保留原文（安全社区与论文的通用语言）。本课立场为**防御视角**：术语既覆盖攻击机理，也覆盖对应的检测与防御。

## 威胁建模 · Threat Modeling

| 术语 (EN) | 中文 | 释义 |
|-----------|------|------|
| threat model | 威胁模型 | 对「谁、有什么能力、想达成什么、在系统哪个环节」的结构化描述。做任何安全分析的第一步：脱离威胁模型谈「安全/不安全」没有意义。 |
| attack surface | 攻击面 | 系统中所有可被攻击者触及、施加影响的入口的集合。ML 系统的攻击面横跨训练数据、训练过程、模型权重、推理 API、部署依赖与供应链。 |
| adversary capability | 攻击者能力 | 攻击者掌握的资源与访问权限：白盒/黑盒、查询次数预算、能否改训练数据、能否读梯度等。能力假设决定攻击是否可行、防御是否足够。 |
| white-box / black-box | 白盒 / 黑盒 | 白盒指攻击者完全掌握模型结构与参数（可算梯度）；黑盒指只能观察输入输出。灰盒介于两者之间（如知道结构不知参数）。 |
| query access | 查询访问 | 攻击者能向模型 API 提交输入并取回输出（标签、置信度或 logits），但看不到内部。模型窃取、黑盒对抗样本、成员推断多基于此。 |
| CIA triad | 机密性-完整性-可用性 | 经典安全三元组：Confidentiality（隐私不泄露）、Integrity（行为不被篡改）、Availability（服务不被瘫痪）。ML 攻击可逐一对应：隐私攻击破 C、对抗样本/后门破 I、可用性投毒破 A。 |
| confidentiality / privacy attack | 机密性 / 隐私攻击 | 试图从模型中窃取本不该泄露的信息：训练数据成员、训练样本内容、模型参数本身。对应成员推断、模型反演、模型窃取。 |
| integrity attack | 完整性攻击 | 让模型在攻击者选定的输入上给出错误/被操纵的输出，而整体性能看似正常。对抗样本（推理期）与后门（训练期）是两大代表。 |
| availability attack | 可用性攻击 | 让模型整体性能崩溃或服务不可用。无差别（unavailability）数据投毒、海绵样本（sponge example，拉高推理能耗）属于此类。 |
| attacker goal: targeted / untargeted | 定向 / 非定向目标 | 定向攻击要让样本被分到攻击者指定的某一类；非定向只要分错即可（更容易）。后门通常定向（trigger→目标类）。 |
| NIST AML taxonomy | NIST 对抗机器学习分类 | NIST AI 100-2 提出的统一分类，按学习阶段（训练/部署）、攻击者目标（可用性/完整性/隐私/滥用）、能力等维度组织对抗 ML 攻击与缓解，是本领域的术语基准。 |
| kill chain | 杀伤链 | 借自网络安全：把一次攻击拆成侦察→武器化→投递→利用→…的阶段。用于在最早可阻断的环节布防，而非只盯最后一步。 |
| defense-in-depth | 纵深防御 | 不依赖单一防线，而是层层设防（输入校验 + 鲁棒训练 + 监控 + 最小权限），任一层被突破仍有后续拦截。本课每个模块的防御都强调分层。 |

## 对抗样本 · Adversarial Examples

| 术语 (EN) | 中文 | 释义 |
|-----------|------|------|
| adversarial example | 对抗样本 | 在正常输入上加一个精心构造、人眼/常识几乎不可察觉的微小扰动，却使模型给出错误预测的样本。Szegedy 2013 首次系统揭示，是推理期完整性攻击的核心。 |
| perturbation | 扰动 | 加到原始输入上的改动向量 δ。对抗攻击通常约束 ‖δ‖ 在某个范数预算内，使其「不可察觉」。 |
| Lp norm / threat model | Lp 范数威胁模型 | 用 ‖δ‖_p ≤ ε 界定「不可察觉」。L∞ 限每个像素改动幅度、L2 限总能量、L0 限改动像素个数；不同范数对应不同攻击与防御，结论不能互相外推。 |
| epsilon (ε) budget | 扰动预算 | 范数约束的上界 ε。ε 越大攻击越强但越易被察觉；鲁棒性评测必须报告在哪个 ε 下测的，否则数字无意义。 |
| FGSM (Fast Gradient Sign Method) | 快速梯度符号法 | Goodfellow 2014 的单步 L∞ 攻击：δ = ε·sign(∇ₓ L)。沿损失对输入梯度的符号方向走一步，极快，是理解对抗样本「线性假说」的入口。 |
| PGD (Projected Gradient Descent) | 投影梯度下降 | Madry 2017 的多步迭代攻击：每步沿梯度符号走一小步 α，再投影回 ε-球内，可随机起点重启。被视为一阶攻击的「事实标准」强基线。 |
| projection (clip) | 投影 / 裁剪 | 把越出 ε-球的扰动拉回边界（L∞ 下即逐元素 clip 到 [−ε, ε]，再 clip 到合法像素域）。保证每步后扰动仍在威胁模型内。 |
| linearity hypothesis | 线性假说 | Goodfellow 2014 的解释：高维空间中，即使每维改动极小，线性模型 wᵀ(x+δ) 的累积改变也可很大；对抗样本主要源于模型局部近似线性，而非过拟合。 |
| transferability | 可迁移性 | 针对模型 A 生成的对抗样本，常能骗过结构/数据不同的模型 B。这使黑盒攻击可行（在替身上生成、迁移到目标），也是防御困难的根源之一。 |
| adversarial training | 对抗训练 | Madry 把鲁棒性写成 min-max：内层用 PGD 生成最坏扰动，外层最小化这些对抗样本上的损失。目前最可靠的经验防御，代价是训练更贵、干净精度略降。 |
| robust accuracy | 鲁棒准确率 | 在 ε-球内最坏扰动下的准确率，是鲁棒性的核心指标。必须与干净准确率（clean accuracy）并列报告。 |
| certified robustness | 可认证鲁棒性 | 用数学保证「该样本在半径 r 内不会被攻破」，如随机平滑（randomized smoothing）、区间界传播。比经验防御弱但有证明，不会被更强攻击推翻。 |
| gradient masking / obfuscated gradients | 梯度遮蔽 / 混淆梯度 | 一类**虚假**的鲁棒性：防御让梯度不可用或失真，使基于梯度的攻击失败，但模型本身并不鲁棒。Athalye 2018 指出大量防御栽在这里——评测陷阱的头号杀手。 |
| adaptive attack | 自适应攻击 | 针对具体防御机理量身设计的攻击（如绕过其梯度遮蔽）。评估防御**必须**用自适应攻击，用固定的标准攻击会高估鲁棒性。 |
| AutoAttack | —— | Croce 2020 的免调参、自适应攻击集合（含 APGD 等），作为鲁棒性评测的可靠默认基线，减少「评测太弱导致虚高」的问题。 |

## 投毒与后门 · Poisoning & Backdoors

| 术语 (EN) | 中文 | 释义 |
|-----------|------|------|
| data poisoning | 数据投毒 | 攻击者在训练数据中注入/篡改样本，从而影响训练出的模型。按目标分为破坏整体性能（可用性投毒）与精准操纵特定行为（定向投毒/后门）。 |
| availability poisoning | 可用性投毒 | 注入噪声/冲突样本，拉低模型整体精度，使其不可用。Biggio 2012 在 SVM 上的梯度投毒是奠基工作。 |
| label flipping | 标签翻转 | 最简单的投毒：把部分训练样本的标签改错。少量翻转即可显著拉低线性模型精度，是理解投毒的入门攻击。 |
| targeted poisoning | 定向投毒 | 不破坏整体性能，只让某个/某类特定测试输入被分错。比可用性投毒隐蔽得多。 |
| backdoor / trojan | 后门 / 木马 | 在模型里植入一个隐藏触发逻辑：带特定 trigger 的输入被强制分到目标类，不带 trigger 时行为完全正常。Gu 2017 的 BadNets 是奠基工作。 |
| trigger | 触发器 | 激活后门的特定模式（如图像角落一个小色块、文本里一个稀有词）。攻击者用它在部署后随意触发被植入的行为。 |
| poison rate | 投毒率 | 被污染样本占训练集的比例。后门常只需很低的投毒率（百分之几甚至更低）即可达到高攻击成功率，这正是其危险所在。 |
| attack success rate (ASR) | 攻击成功率 | 带 trigger 的（非目标类）样本被成功分到目标类的比例。后门攻击的核心指标，与「干净样本上的正常精度」并列看。 |
| clean-label attack | 干净标签攻击 | 投毒样本的标签**看起来正确**（不靠改标签），仅靠精心扰动特征植入后门或定向错误。绕过「人工核对标签」这道防线，更难检测。 |
| spectral signature | 谱签名 | Tran 2018 的后门检测：被投毒样本在某层特征的协方差谱上留下可分离的「签名」，对特征做 SVD、按 top 奇异向量投影可把毒样本挑出。 |
| activation clustering | 激活聚类 | Chen 2018 的后门检测：对每个类的训练样本取隐层激活做聚类，干净类聚成一簇，被投毒类裂成「干净 + 毒」两簇，从而定位毒样本。 |
| data sanitization | 数据消毒 | 训练前清洗可疑样本：离群点剔除、近邻一致性检查、按损失/影响函数筛除异常样本，降低投毒成功率。 |
| Neural Cleanse | —— | Wang 2019 的后门检测/缓解：为每个类逆向求「把任意输入改判为该类所需的最小扰动」，后门类对应的扰动异常小，据此发现并修补 trigger。 |
| influence function | 影响函数 | 度量「去掉某个训练样本会如何改变模型/某预测」。可用于追踪是哪些训练样本导致了异常行为，是投毒溯源与数据归因的工具。 |

## 模型窃取与反演 · Extraction & Inversion

| 术语 (EN) | 中文 | 释义 |
|-----------|------|------|
| model extraction / stealing | 模型窃取 | 攻击者通过查询目标模型 API、用返回结果训练一个功能相近的「替身（surrogate）」，窃取其功能或近似参数。Tramèr 2016 系统化此攻击。 |
| surrogate / substitute model | 替身模型 | 攻击者用查询数据训练出来、模仿目标模型的本地副本。可用于免费白嫖功能、或作为生成可迁移对抗样本的跳板。 |
| fidelity vs accuracy | 保真度 vs 准确率 | 保真度=替身与**目标模型**预测的一致程度（含目标的错误也学）；准确率=替身在**真实标签**上的表现。窃取攻击关心保真度，二者目标不同。 |
| query budget | 查询预算 | 窃取/黑盒攻击允许的查询次数。保真度随查询数上升而提高；防御的核心之一就是抬高达到给定保真度所需的查询量。 |
| Jacobian-based augmentation | 基于雅可比的数据增广 | Papernot 2017 的窃取技巧：用替身的雅可比指导在决策边界附近合成新查询点，用更少查询逼近目标边界。 |
| model inversion | 模型反演 | 利用模型输出反推训练数据的输入特征。Fredrikson 2015 经典案例：由人脸识别模型的置信度梯度重建出某身份的近似人脸。 |
| attribute inference | 属性推断 | 从模型/输出推断个体的某个敏感属性（如由部分特征 + 模型反推出隐藏的敏感字段），是隐私泄露的一种。 |
| training data extraction | 训练数据提取 | 从（尤其生成式）模型中逐字诱出被记住的训练样本。Carlini 2021 从 GPT-2 提取出含个人信息的原文，揭示记忆带来的直接隐私风险。 |
| watermarking (model) | 模型水印 | 在模型行为中嵌入可验证的隐藏标记（如对特定触发输入给特定输出），用于事后证明某个被窃模型源自自己。是窃取的**取证**手段而非预防。 |
| extraction defense: rounding / noise | 窃取防御：四舍五入 / 加噪 | 降低输出信息量以抬高窃取成本：只返回 top-1 标签而非完整概率、对置信度量化或加噪、对异常查询模式限流/封禁。代价是正常用户的可用信息也变少。 |
| rate limiting / anomaly detection | 限流 / 异常检测 | 监控查询频率与分布，对疑似系统性扫描决策边界的查询模式（如大量近边界点）限速或拦截。窃取防御的工程一线。 |

## 成员推断与隐私 · Membership Inference & Privacy

| 术语 (EN) | 中文 | 释义 |
|-----------|------|------|
| membership inference attack (MIA) | 成员推断攻击 | 判断「某条具体样本是否在模型的训练集里」。是最基础的隐私攻击，也是衡量模型「记忆/泄露」程度的标准探针。Shokri 2017 奠基。 |
| shadow model | 影子模型 | 攻击者用与目标同分布的数据训练的一批仿制模型，已知哪些样本是其成员，用于生成攻击模型的训练数据（学会区分成员/非成员的输出模式）。 |
| loss-based MIA | 基于损失的 MIA | 最简 MIA：成员样本的训练损失通常显著低于非成员，设一个损失阈值即可判别成员。简单却出奇有效，是 MIA 的基线。 |
| confidence / entropy attack | 置信度 / 熵攻击 | 用模型对样本的预测置信度或熵作为成员信号：成员往往被预测得更自信、熵更低。 |
| LiRA (Likelihood Ratio Attack) | 似然比攻击 | Carlini 2022 的强 MIA：对每个样本用「成员」与「非成员」两组影子模型的损失分布做似然比检验，按 per-sample 校准，在低误报区远强于全局阈值。 |
| overfitting–privacy link | 过拟合-隐私关联 | 模型越过拟合（训练/测试差距越大），成员与非成员的输出差异越明显，MIA 越容易成功。泛化好 ≈ 隐私风险低，是核心直觉。 |
| memorization | 记忆 | 模型把个别训练样本的细节（而非普适规律）编码进参数。记忆是 MIA 与训练数据提取成功的根源，与样本稀有度强相关。 |
| TPR @ low FPR | 低误报率下的真正率 | MIA 的正确评价方式（Carlini 2022）：平均准确率会被「大多数样本判不出」掩盖；真正危险的是「能以极低误报确信指认少数样本」，故要看 log-scale ROC 的左端。 |
| differential privacy (DP) | 差分隐私 | 形式化隐私保证：单条样本的增删对输出分布的影响被 (ε, δ) 严格限制。DP-SGD（训练中裁剪梯度 + 加噪）是抵御 MIA/提取的有原则防御，代价是精度下降。 |
| (ε, δ)-DP / privacy budget | (ε,δ)-差分隐私 / 隐私预算 | ε 越小隐私越强（单样本影响越小），δ 是允许的小概率失效。ε 是可量化、可累加的「隐私预算」，把模糊的「隐私」变成可工程化的旋钮。 |
| privacy auditing | 隐私审计 | 用 MIA/提取等攻击**实测**模型的隐私泄露，给 DP 的理论 ε 一个经验下界，验证实现是否真的达到了声称的隐私保证。 |

## Prompt 注入与供应链 · Prompt Injection & Supply Chain

| 术语 (EN) | 中文 | 释义 |
|-----------|------|------|
| prompt injection | 提示注入 | 把恶意指令混入 LLM 的输入，劫持其行为、覆盖系统提示。因为 LLM 不可靠地区分「可信指令」与「不可信数据」，这是 LLM 应用的头号风险（OWASP LLM Top 10 之首）。 |
| direct prompt injection | 直接提示注入 | 用户在自己的输入里直接写恶意指令（如「忽略上面的规则」）。与越狱高度重叠，针对的是模型的对齐边界。 |
| indirect prompt injection | 间接提示注入 | Greshake 2023 揭示：恶意指令藏在 LLM 会读取的**外部内容**里（网页、邮件、文档、工具返回），用户毫不知情就触发。是 RAG/agent 系统最严重的攻击面。 |
| jailbreak | 越狱 | 用角色扮演、编码、催眠式话术等绕过模型的安全对齐，使其产出本应拒绝的内容。属直接注入的子类，针对对齐而非系统提示。 |
| system prompt | 系统提示 | 开发者设定的、约束模型行为的上层指令。注入攻击的常见目标就是覆盖或泄露它。 |
| tool / function abuse | 工具滥用 | agent 被注入后调用其可用工具（发邮件、执行代码、读写文件、转账）做出危害动作。危害从「说错话」升级为「做错事」，是 agent 安全的核心。 |
| confused deputy | 混淆代理 | 经典权限问题：一个被信任、握有权限的实体（agent）被诱导替攻击者行使其权限。间接注入本质就是让 LLM 充当混淆代理。 |
| privilege separation / least privilege | 权限隔离 / 最小权限 | 只给 agent/组件完成任务所必需的最小权限（如只读、白名单工具、人类确认高危动作），即便被注入，可造成的破坏也被限制住。 |
| dual LLM / quarantine | 双 LLM / 隔离模式 | Willison 提出的防御：一个有权限的「特权 LLM」永不直接读不可信内容，由一个无权限的「隔离 LLM」处理不可信数据并只回传结构化结果，切断注入到行动的通路。 |
| content provenance / trust boundary | 内容来源 / 信任边界 | 明确标注每段输入的来源与可信级别，在「数据」和「指令」之间划清边界，是缓解注入的架构原则（但当前模型仍难严格执行）。 |
| ML supply chain | ML 供应链 | 训练到部署涉及的全部外部依赖：预训练权重、第三方数据集、开源库、序列化格式、模型仓库。任一环节被污染都会传导到最终系统。 |
| insecure deserialization | 不安全反序列化 | 加载不可信的序列化对象时执行了其中携带的代码。Python `pickle`（及基于它的旧式 `.pt`/`.bin` 检查点）可在 `load` 时执行任意代码，是模型分发的高危点。 |
| safetensors | —— | 一种**只存张量数据、不能执行代码**的模型权重格式，用来替代 pickle，从根上消除「加载即中招」的反序列化风险。是供应链防御的实践基线。 |
| model / data provenance & signing | 模型 / 数据来源与签名 | 用哈希校验与数字签名确认权重/数据集来自可信来源、未被篡改（如 model cards、sigstore、SBOM）。供应链完整性的工程手段。 |
| typosquatting / dependency confusion | 抢注 / 依赖混淆 | 攻击者发布名字与流行包极相近（或同名高版本号）的恶意包，诱使 `pip install` 装错。ML 项目依赖庞杂，是常见的供应链投毒入口。 |
| poisoned pretrained model | 投毒预训练模型 | 从公开仓库下载的预训练权重本身已被植入后门。下游微调常不能清除它，凸显「权重来源可信」与下载后检测的重要性。 |
