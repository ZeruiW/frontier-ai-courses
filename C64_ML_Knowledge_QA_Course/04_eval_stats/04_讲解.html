1为什么这一段区分度最高：三段式答法用在统计上

前三个模块的三段式答法是「一句话定义 → 为什么需要 → 什么时候失效」。到了评估与统计这一段，「什么时候失效」不再是加分项，而是整个答案的重心——因为统计方法的正确性从来不是「公式对不对」，而是「前提假设成不成立」。正态置信区间假设样本够大、比例不极端；ROC-AUC 假设你关心排序而不是绝对错误率；A/B 测试的显著性检验假设你没有中途偷看结果。忘记假设，工具就会给你一个看起来很科学、实际上错误的答案。

这也是为什么这一段是全部 C64 里区分度最高的一段。背公式人人都会——$F_1 = 2PR/(P+R)$ 三秒钟能查到，$\text{ROC-AUC}$ 的定义随口能说。但能不能在 30 秒内说出「这个指标在什么场景下会撒谎」，才能看出候选人是真的用过、debug 过这些指标，还是只在课堂上背过定义。

面试官的追问只背公式的候选人懂失效边界的候选人
「不平衡数据下你会用什么指标？」「F1，因为它综合了精确率和召回率」「先看不平衡程度：如果负类占 99%，我会看 PR-AUC 而不是 ROC-AUC，因为……」
「那 ROC-AUC 有什么问题？」卡壳，或重复一遍 ROC-AUC 的定义「它的分母里有海量真阴性，会稀释假阳性的影响，我可以举个数字例子」
「能举一个 ROC-AUC 很高但模型没用的例子吗？」说不出来秒举：10 万分之一的欺诈检测，ROC-AUC=0.98 但精确率只有 5%

统计学面试问的从来不是「这个指标是什么」，是「这个指标什么时候会说谎，以及你怎么发现它在说谎」。把这句话当成本模块所有小节的统一读法。

直白说

每一个统计工具都是在一组假设下才成立的近似。正态置信区间假设样本够大、分布不太偏；ROC-AUC 假设你关心的是「谁的分数更高」而不是「绝对错了多少」；A/B 测试的 $p$ 值假设你只看了一次结果。忘记假设，工具不会报错，它只会安静地给你一个错误的自信。

严谨说

更精确地说，每个统计方法都对应一个「如果条件不满足，第一类/第二类错误率会怎样膨胀」的具体机制——小样本下正态近似的覆盖率会低于名义置信度（尤其 $\hat p$ 接近 0 或 1 时）；ROC-AUC 作为一个排序统计量（等价于 Mann-Whitney U 统计量的归一化形式），本身与类别先验无关，这正是它在不平衡场景下「对假阳性数量不敏感」的数学根源——不是它坏了，是它压根没有被设计来衡量这件事。

面对不熟悉的检验，正确姿势是「我会先确认这个检验的假设是否满足——比如样本是否独立、方差是否齐性——再决定能不能用」，而不是硬着头皮编一个公式出来。承认「我需要先查一下」比编错一个公式安全得多，见模块 05 的知识边界练习。

数学推导（贝叶斯公式的完整推导、交叉验证的方差分解）见 C07，本模块不重复；这里只训练「60 秒讲清 + 接住追问」。

2指标全家：Accuracy / Precision / Recall / F1 / Fβ

五个最基础的指标都从同一张混淆矩阵（TP/FP/FN/TN）里算出来，但它们回答的是五个不同的问题——把「它们都是分类指标」当成一回事，是这一段最常见的踩雷点。

指标公式一句话回答的问题什么时候它会骗你
Accuracy$(TP+TN)/N$整体猜对了多少类别不平衡时完全失效：全猜负类在 99:1 数据上也有 99% accuracy
Precision$TP/(TP+FP)$我说是正的，有多少真是正的只看它会忽略召回——把阈值调到 1.0，precision 可以刷到 1，但漏检全部
Recall$TP/(TP+FN)$真正的正例，我抓到了多少只看它会忽略代价——把阈值调到 0，recall 恒为 1，但全是假阳性
F1$2PR/(P+R)$precision 与 recall 的调和平均默认 precision 与 recall 同等重要——代价不对称时这个假设本身就是错的
Fβ$(1{+}\beta^2)PR / (\beta^2P+R)$让 recall 的重要性是 precision 的 $\beta$ 倍$\beta$ 选错等于假设错了代价比——很多人报了 F1 却没意识到自己隐含选了 $\beta{=}1$
\[F_\beta = \frac{(1+\beta^2)\cdot P \cdot R}{\beta^2 \cdot P + R}, \qquad \beta{>}1 \text{ 更看重召回}, \;\; \beta{<}1 \text{ 更看重精确率}\]

直白说

调和平均（而不是算术平均）的意义在于惩罚两者失衡：precision=1.0、recall=0.01 时，算术平均还有 0.505 看起来不错，调和平均只有 0.0198，一眼就能看出「这个模型基本没用」。F1 就是靠这一点防止你被单边的高分数骗过去。

严谨说

严格地说 $\beta$ 是「召回相对于精确率的重要性倍数」：$\beta{=}2$（即 F2）意味着面试官告诉你「漏检的代价是误检的 4 倍」（$\beta^2{=}4$）——这在 TSR 里对应停车让行这类标志：漏检一次的安全代价远高于多一次误刹车，此时该报 F2 甚至更极端的 recall 优先指标，而不是默认报 F1。

「accuracy 高就是模型好」是面试里最容易当场翻车的一句话。一个 TSR 数据集里「限速 5」这一类可能只占 0.1%，一个永远不预测这个类的模型 accuracy 照样很高——面试官只要追问一句「稀有类的 recall 呢」，这句话就会当场破功。

典型追问：给你一组 P/R，能不能秒算 F1/F0.5/F2？

$P{=}0.9, R{=}0.1$ 时：$F_1{=}2{\times}0.9{\times}0.1/1.0{=}0.18$；$F_{0.5}$（更看重精确率）$\approx 0.36$；$F_2$（更看重召回）$\approx 0.12$。记住这个方向就够了：$\beta$ 越大，Fβ 越贴近 recall 本身；$\beta$ 越小，越贴近 precision 本身——不需要在白板上心算到小数点后四位，说对趋势 + 给出边界情况（$\beta\to 0$ 退化为 P，$\beta\to\infty$ 退化为 R）就已经拿到分。

3ROC-AUC vs PR-AUC vs mAP：不平衡数据下谁在骗你

这是本模块的招牌问题：「不平衡数据下 ROC-AUC 为什么会骗人？」几乎是检测/风控/医疗类岗位的必考题，而且是少数几个「能当场用数字讲清楚」的理论问题。

ROC 空间：坐标是 (FPR, TPR) PR 空间：坐标是 (Recall, Precision) TPR Precision 1 ┤ ╭────────── 1 ┤╲ │ ╭──╯ 看起来都贴着左上角 │ ╲___ │ ╭──╯ —— 因为 FPR 分母里有 │ ╲___ —— 不平衡时会 │╭─╯ 海量真阴性 TN 在稀释 FP │ ╲___ 塌到很低， 0 └───────────────────────► FPR 0 └──────────────►Recall 0 1 0 1 两条不同分类器的 ROC 曲线几乎重合 同样两条分类器的 PR 曲线拉开明显差距 （因为 FPR = FP/(FP+TN)，TN 巨大时不敏感） （因为 Precision = TP/(TP+FP)，直接受 FP 绝对数量影响）

拿一组具体数字讲清楚：负类 99000、正类 1000。分类器 A 产生 900 个真阳性、1000 个假阳性——$FPR = 1000/99000 \approx 0.0101$，看起来微不足道，ROC 曲线几乎贴着左上角，$\text{ROC-AUC}$ 可以高达 0.97+。但 $\text{Precision} = 900/(900{+}1000) \approx 0.47$——你发出的每两个报警里就有一个是错的，这在下游系统里是完全不同的体验，而 PR 曲线会把这个问题直接暴露出来。

\[\text{ROC-AUC} = P\big(s(x^+) > s(x^-)\big) \quad \text{—— 只关心排序，与类别先验无关}\]
指标数学本质对类别先验适用场景常见误用
ROC-AUC排序统计量（Mann-Whitney U 的归一化形式）不敏感——这是它「骗人」的根源两类样本量相近、你关心排序能力在极不平衡数据上报 ROC-AUC 当作唯一指标
PR-AUC精确率-召回率曲线下面积敏感——正类越稀少，同样的 FP 数量对 precision 冲击越大正类稀少、你关心「报警的可信度」把 PR-AUC 和 ROC-AUC 数值直接比大小（量纲不同，基线不同）
mAP对每个类别算 PR-AUC 再求平均（检测里还要在多个 IoU 阈值上再平均）对类别间不平衡不敏感——平均会掩盖表现极差的类多类检测的整体排行榜指标只看 mAP 不看逐类 AP——见 C61-02 的 TIDE 式误差分解；细节推导见 C18、C53–C61

直白说

直白地说：ROC 曲线的横轴（假阳性率）分母里站着全部真阴性，负类越多，同样数量的假阳性占比就越小，曲线自然显得好看；PR 曲线的横轴纵轴里根本没有真阴性这一项，假阳性一多，precision 立刻掉下来，藏不住。

严谨说

严格地说，PR-AUC 的这种敏感性不是「优点」而是对代价结构的不同建模：ROC-AUC 隐含假设「阴性样本被误判的相对代价 = 阴性样本的相对数量」，而这在类别本身极不平衡时通常不成立——真正在意的是「每次报警的可信度」而非「负类整体被误判的比例」。选 ROC 还是 PR，本质是在选一个隐含的代价假设，这也是为什么 Davis & Goadrich (2006) 证明「一条曲线在 ROC 空间占优，当且仅当它在 PR 空间也占优」——两者排序一致，但绝对数值的可读性天差地别。

面试当场翻车模板：面试官给你一份「ROC-AUC=0.95」的报告问「这个模型能上线吗」，你说「AUC 这么高，能上」——这是本节要根除的反应。正确反应是反问一句「正负类比例是多少？能不能看一下 PR 曲线和实际阈值下的 precision？」。

一句话记住选择规则：正类稀少 → 看 PR-AUC；两类均衡 → ROC-AUC 也可信；多类检测的整体排行 → mAP，但永远要配一张逐类 AP 表。

4阈值、工作点与代价敏感决策

指标是连续的，但线上系统要做一个非黑即白的决定——这中间的桥梁就是阈值（threshold）。「用 0.5 当阈值」是最常见的默认动作，也是最没有依据的一个默认动作。

直白说

0.5 只在一种情况下天然合理：两个类别一样多、犯两种错误的代价完全相等。现实里这两条几乎从不同时成立——类别常常不平衡，犯错的代价也几乎总是不对称的（漏检一个停车让行标志，和多看错一次广告牌，后果完全不是一个量级）。

严谨说

更严谨的做法是显式写出代价矩阵 $C_{FP}, C_{FN}$，选择使期望代价$E[\text{cost}] = C_{FP}\cdot FP(\tau) + C_{FN}\cdot FN(\tau)$ 最小的阈值 $\tau$——这把「选阈值」从一个经验动作变成了一个可以在白板上写出目标函数的优化问题。

场景$C_{FN}$（漏检代价）$C_{FP}$（误检代价）该往哪个方向调阈值
TSR 停车让行标志检测极高——可能导致未减速通过路口低——多一次不必要的减速降低阈值，牺牲精确率换召回
广告牌误识别为限速牌中——如果误触发限速会造成不必要减速中——同上阈值需结合下游多帧融合再定（见 C55-04）
垃圾邮件过滤低——漏判一封垃圾邮件影响小高——把重要邮件误判为垃圾邮件代价大提高阈值，牺牲召回换精确率
医疗初筛（阳性即转诊复查）极高——漏诊致命中——多一次复查有成本但可接受降低阈值，宁可信其有

阈值选择必须建立在验证集上，不能用测试集调阈值——这和用测试集调超参数是同一类错误，会让你在测试集上的评估结果虚高。工程上常见做法是在验证集上扫描阈值画出 PR 曲线，锁定阈值后才在测试集上报一次最终指标。

典型追问：Youden's J 与「与场景无关」的阈值选择

如果面试官问「没有明确代价矩阵怎么选阈值」，一个安全答案是 Youden's J 统计量：$J = TPR - FPR$ 最大化的点，几何上是 ROC 曲线上离对角线最远的点。但要补一句「这只是一个无代价假设下的默认解，真实工程里几乎总有代价矩阵，应该优先用它」——只给出公式而不加这句限定，会显得你没有工作点选择的实战经验。

一句话总结：阈值不是从指标里「读」出来的，是从代价矩阵里「算」出来的；没有代价矩阵时才退而求其次用 Youden's J 或 F1 最大点。

5校准：可靠性图、ECE、温度缩放

校准（calibration）回答的是一个和「准不准」完全不同的问题：「模型说我 90% 有把握时，它真的有 90% 的时候是对的吗？」——这是「高置信不等于高准确」这句话的精确版本。

直白说

现代深度网络有一个广为人知的坏毛病：它们通常过度自信。一个 softmax 输出 0.99 的预测，实际正确率可能只有 0.85——网络在「知道自己不知道」这件事上是不诚实的，而这在需要做风险决策的系统里（要不要触发紧急制动、要不要转诊）是致命的。

严谨说

严格定义：模型是完美校准可靠性图（reliability diagram）把预测按置信度分桶，画「桶内平均置信度」vs「桶内实际准确率」，完美校准应该落在对角线上；ECE（Expected Calibration Error）把每个桶的偏差按桶内样本占比加权求和，给出一个标量总结这条曲线偏离对角线的程度。

\[\text{ECE} = \sum_{b=1}^{B} \frac{n_b}{N}\, \big|\, \text{acc}(b) - \text{conf}(b)\, \big|\]
可靠性图（10 个置信度桶） 准确率 1.0┤ ╱ ← 完美校准（对角线） │ ●╱ │ ● ╱ │ ● ╱ ● = 模型的实际桶（常见现象： │ ● ╱ 高置信区间的柱子低于对角线 │ ● ╱ —— over-confident） 0.0└──────────────────────────────► 置信度 0.0 1.0
校准方法做什么代价适用场景
温度缩放 Temperature Scaling把 logits 除以标量 $T{>}1$ 再过 softmax，压平过度自信的分布只有 1 个参数，验证集拟合几秒钟首选——不改变预测排序（不影响 accuracy/AUC），只调整置信度的尺度
Platt Scaling在 logit 上拟合一个逻辑回归 $\sigma(aZ+b)$2 个参数，比温度缩放灵活但也更容易过拟合验证集二分类、样本量适中
Isotonic Regression非参数、单调地重映射置信度参数量随分桶数增长，小验证集上容易过拟合验证集足够大时效果最好，但要小心过拟合
「高置信不等于高准确」是这一节唯一要记住的一句话。在检测/分类的下游决策里（例如 TSR 输出直接喂给 VLA，见 C59-03），如果不传置信度、或置信度本身没有校准过，下游系统会把「模型自信但错了」的输出当真——这是感知-决策接口最常见也最隐蔽的设计错误。

温度缩放只能修正整体的过度自信，修不了「模型对某个特定类别系统性地过度自信」这种更细粒度的偏差——那需要按类别做校准，而且要小心校准用的验证集本身分布是否和线上一致。

6置信区间与显著性检验：正态 / bootstrap / Wilson

「AP 从 0.42 涨到 0.45」——这句话本身没有意义，除非你能回答「这个 0.03 是噪声还是真实提升」。置信区间和显著性检验就是回答这个问题的两套工具，选错方法会让你把噪声当成信号（见 C61-01）。

方法假设什么时候用什么时候失效
正态近似 CI$n$ 足够大，$\hat p$ 不接近 0 或 1（中心极限定理生效）样本量大、比例适中的场景，计算最快小样本或极端比例下覆盖率显著低于名义值——比如 $n{=}20, \hat p{=}0.95$ 时区间可能跑到 1 以外
Bootstrap只需要能重复重采样，几乎不假设分布形状任意统计量（中位数、AUC、mAP 这类没有解析方差公式的量）计算量大；重采样次数不够时区间本身有噪声；对极小样本仍然不稳
Wilson Score专为二项比例设计，用「反转正态检验」推导，天然把区间约束在 $[0,1]$二分类准确率/召回率这类比例型指标的首选，尤其小样本只适用于二项比例，不能直接套到均值或 AUC 上
\[\text{Wilson}:\quad \hat p_{center} = \frac{\hat p + \frac{z^2}{2n}}{1+\frac{z^2}{n}}, \qquad \text{margin} = \frac{z}{1+\frac{z^2}{n}}\sqrt{\frac{\hat p(1-\hat p)}{n} + \frac{z^2}{4n^2}}\]

直白说

正态 CI 的公式人人都写得出（$\hat p \pm z\sqrt{\hat p(1-\hat p)/n}$），但它有一个致命的隐藏假设：$n$ 要足够大。$n{=}20$ 时测出 19 次正确（$\hat p{=}0.95$），正态公式会给出一个可能超过 1 的上界——区间本身就已经荒谬了，这正是「小样本下别无脑用正态近似」的活证据。

严谨说

Wilson 区间的推导思路是反转显著性检验：先问「对哪些 $p_0$，观测到的 $\hat p$ 不会被拒绝」，把这些 $p_0$ 的集合作为置信区间——这个构造方式天然保证区间落在 $[0,1]$ 内，且小样本下的覆盖率比正态近似更接近名义值。这也是为什么 Wilson 区间是二项比例场景下更稳的默认选择，而不是「更复杂所以更好」。

显著性检验：配对 vs 非配对

同一批测试样本上，模型 A 与模型 B 的差异要用配对检验（paired t-test 或 bootstrap 配对），因为两组分数天然相关（同一张图片难，两个模型大概率都难）；如果是两批不同的测试样本（比如 A/B 测试里两组不同用户），才用非配对检验。用错会低估显著性——把配对数据当非配对处理，方差会被高估，导致本该显著的结果被判为不显著。

「+0.3 mAP 算不算提升」是检测岗最常见的追问（见 C61-01）。正确答法：先给出多种子的方差范围（比如典型 ±0.2–0.5），再说明用的是配对还是非配对检验，最后给出结论——不给方差范围直接说「涨了」，是这一段最容易失分的地方。

7A/B 测试：样本量、功效、新奇效应与多重比较

A/B 测试是把「显著性检验」搬到真实用户身上的工程实践，多出的坑全部来自「真实世界」这三个字——用户会变、实验会被同时运行多个、新功能天然会引来短暂的额外关注。

\[n \;\approx\; \frac{(z_{\alpha/2} + z_{\beta})^2 \big(p_1(1-p_1) + p_2(1-p_2)\big)}{(p_1 - p_2)^2}\]

直白说

样本量公式的直觉是：想检出的效应 $|p_1-p_2|$ 越小，需要的样本量按平方反比暴涨——想把「能检出的最小提升」减半，样本量要翻 4 倍。这也是为什么很多团队宁愿多等两周攒够样本，也不愿意在样本不够时强行下结论。

严谨说

$z_{\alpha/2}$ 由显著性水平 $\alpha$（第一类错误率，通常 0.05）决定，$z_\beta$ 由功效（power，$1-\beta$，通常要求 0.8）决定——功效是「真的有效应时，你的实验有多大概率检测出来」，这是经常被忽略的一半：很多「无显著差异」的实验结论，其实只是样本量不够、功效太低，而不是真的没有效应。

陷阱机制怎么防
新奇效应 novelty effect用户因为「新」而多点击/多停留，效应会随时间衰减实验跑够长（覆盖至少一个完整周期），看效应是否随时间递减
多重比较 multiple comparisons同时看 10 个指标，每个都用 $\alpha{=}0.05$，至少一个假阳性的概率飙到 $1-0.95^{10}\approx 40\%$Bonferroni 校正（$\alpha/m$）或控制 FDR（Benjamini-Hochberg），或提前锁定唯一的主指标
提前偷看（peeking）看到显著就提前停止实验，等价于隐式做了多重比较，实际第一类错误率远高于 0.05预先固定样本量/时长，或用序贯检验（sequential testing）等专门为「持续监控」设计的方法
样本比例失衡 / SRM分流本身就有 bug，两组样本比例不是预期的 50/50先做样本比例不匹配（Sample Ratio Mismatch）检验，比看指标更优先
「每天看一眼 dashboard，一看到显著就下结论」是 A/B 测试里最常见的事故根源——本质上是把「提前偷看」和「多重比较」揉在了一起：你在多个时间点上反复检验同一个假设，总有一个时间点会因为纯噪声而「显著」。

记住这条判断顺序：先查 SRM → 再查功效是否够 → 再查是不是多个指标/多个时间点在偷看 → 最后才谈论 $p$ 值本身。大部分「A/B 测试结论不可信」的真实故事，问题都出在前三步，而不是最后一步。

8统计陷阱四重奏与概率题：从辛普森悖论到基率谬误

这一节是「快问快答」的预演——面试官爱用一个简短故事考你能不能认出陷阱的名字，然后追问「你怎么在自己的数据里发现它」。

陷阱一句话机制怎么在数据里发现它
辛普森悖论 Simpson's Paradox分组内的趋势，合并后反转——因为组的权重（样本量）在分组间不同任何「整体指标」的结论，都要按关键维度（场景/子群体）切片复核一遍，见 C58-05 的分场景切片评测
幸存者偏差 Survivorship Bias只观察到「活下来」的样本，看不到被淘汰的那部分，导致结论系统性偏乐观检查数据收集流程本身是否存在过滤——线上只收集到「成功上报」的 badcase，漏检的往往不在里面
回归到均值 Regression to the Mean一次极端表现之后，下一次测量自然会更靠近均值，容易被误认为「干预生效」设对照组；只对「上次表现极端」的样本做前后对比是这个陷阱的经典触发条件
p-hacking试了很多种切分/指标/模型，只报告显著的那个，本质是隐式的多重比较实验前预注册要检验的假设与指标；多重比较必须做校正（见上一节）
辛普森悖论的最小可复现构造： 组 A（小样本） 组 B（大样本） 合并 方案甲 8/10 = 80% 30/90 = 33% 38/100 = 38% 方案乙 45/50 = 90% 2/10 = 20% 47/60 = 78% ← 合并后乙反而遥遥领先！ 但分组看：组 A 里甲(80%)<乙(90%)，组 B 里甲(33%)>乙(20%) —— 两组内乙都不是简单地"更差" 真相：乙把大量样本堆在组 A（乙容易的场景），甲把大量样本堆在组 B（甲难的场景）， 合并比例被"谁在哪个组测得多"主导，而不是被"哪个方案更好"主导。

直白说

贝叶斯定理直白地说，是「反过来想」：你想知道的是 $P(\text{病}\mid\text{阳性})$，但你手上的数据通常是 $P(\text{阳性}\mid\text{病})$（检测的灵敏度）——贝叶斯公式就是把后者倒过来算前者，而中间那个容易被忽略的分母，才是基率谬误（base rate fallacy）的根源。

严谨说

$P(A\mid B) = P(B\mid A)P(A) / P(B)$，其中 $P(B) = P(B\mid A)P(A) + P(B\mid \neg A)P(\neg A)$。基率谬误就是只盯着灵敏度 $P(B\mid A)$，忘了先验 $P(A)$ 极小时分母会被 $P(\neg A)$ 那一项主导——这正是「99% 准确率的检测，阳性结果却大概率是假的」这类反直觉结论的完整数学解释。

\[P(\text{disease}\mid{+}) = \frac{P({+}\mid\text{disease})\,P(\text{disease})}{P({+}\mid\text{disease})P(\text{disease}) + P({+}\mid\neg\text{disease})P(\neg\text{disease})}\]

代入一个经典数字：患病率 $P(\text{disease}){=}0.001$，检测灵敏度与特异度都是 99%。算出来 $P(\text{disease}\mid{+}) \approx 0.09$——阳性结果里超过 90% 是假阳性，尽管测试本身「99% 准」。这个数字每次算出来都会让人意外，这正是它作为面试题的价值：它检验的不是你会不会背公式，而是你有没有真正把公式在脑子里跑过一遍。

「期望的线性性」$E[X+Y]=E[X]+E[Y]$永远成立，不需要 $X,Y$ 独立——这是概率题里最容易被误用的一条「附加条件」，很多人下意识加上「因为独立」，其实线性性对任意随机变量、任意相关结构都成立，独立只在算方差 $\text{Var}(X{+}Y)$ 时才是必要条件。

9研究前沿与开放问题

最后放一组更长期的问题——它们不会直接出现在你的一面里，但决定了「评估这件事」本身正在往哪个方向演化。

  • 校准在分布漂移下会失效吗？温度缩放假设验证集与部署分布一致；一旦线上出现验证集没见过的天气/光照，温度缩放学到的那个标量 $T$ 不再适用。如何做「分布漂移鲁棒」的校准，仍是一个开放问题——目前的工程折中通常是按场景分桶各自校准（呼应 C58-05 的分场景评测），而不是追求一个全局最优 $T$。
  • 安全攸关系统里 PR-AUC 也不够用。它仍然是一个「平均」指标，掩盖了具体在哪个阈值下、哪个子场景下会出问题。TSR、医疗这类领域正在转向分桶 + 场景化的评测体系（按距离/光照/类别切片，见 C55-05），单一标量指标的地位正在下降。
  • 持续实验平台上的多重比较问题被低估。大公司同时跑成百上千个 A/B 实验，传统的 Bonferroni 校正过于保守（会让检出效应变得极难），FDR 控制和贝叶斯层级模型是当前更主流的工业实践，但「怎么在保持高吞吐决策的同时控制长期误报率」仍在演进中。
  • LLM 参与统计推理时会不会引入新的统计错误？让大模型辅助做数据分析、自动选择检验方法，正在成为新的工作流，但它们和人类一样会犯基率谬误、会被辛普森悖论骗到——而且更危险的是它们输出时的语气通常很自信，这让「高置信不等于高准确」这条规律在人机协作场景里更加重要。
  • 贝叶斯 A/B 测试与频率派方法之争仍未有定论。贝叶斯框架允许「持续监控不受多重比较惩罚」这类更符合工程直觉的用法，但它引入了先验选择的主观性；两派方法在工业界的取舍仍是一个活跃的讨论。
