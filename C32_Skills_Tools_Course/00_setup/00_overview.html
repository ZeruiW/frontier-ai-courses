1这门课讲什么

欢迎来到 Skills 与工具生态（不依赖框架）。这门课只追求一件事：让你从「会用 Claude Code 的 skills / slash 命令 / MCP / 插件」变成「会亲手把它们的内核造出来」——而且全程不依赖任何现成框架。

当代 agent 真正的分水岭，不在模型本身有多强，而在它能不能在不改核心代码的前提下不断长出新能力：今天接一个查数据库的工具、明天加一份「怎么写提交信息」的 skill、后天用一个 `/deploy` 命令把上线流程一键化、再后天装一个别人写的插件……Claude Code 这样的系统之所以强大，很大程度上是因为它有一套可扩展性子系统：skills（按需加载的指令）、slash 命令（用户显式触发的工作流）、MCP（标准化的工具/数据接口）、插件（把能力打包分发）。这门课要往下钻一层：当你给一个 agent「加一个 skill / 一条命令 / 一个 MCP server / 一个插件」时，背后那套代码到底在做什么？

这些机制的精髓不在模型里，而在模型外面的脚手架（scaffold）里。一个朴素的事实是：同一个模型，配一套好的可扩展性子系统和一套差的，能干的事可能差十倍——因为它决定了你能给模型接入多少能力、这些能力能不能被恰当地发现与组合、会不会把上下文撑爆。本课就是把这套子系统的五个核心零件——skill 定义与加载、slash 命令与动态注入、MCP server、工具打包与插件、完整 skills 系统——从零拆开、亲手重建，不借助 Claude Code，只用 Python 标准库。

学完你应当能回答这类问题（也是 agent / infra 岗位的高频面试题）：skill 凭什么能「平时不占上下文、用到才加载」？frontmatter 怎么解析、相关性怎么判？slash 命令的 `$ARGUMENTS`、`!`shell`` 是怎么展开的？MCP 凭什么能解决 M×N 集成爆炸，它的握手与 tools/call 长什么样？插件怎么打包、怎么避免命名冲突、怎么检查版本依赖？——并且能在纯标准库 + MockLLM 里把这五样东西都从零跑通、用 assert 验证，再换上真实 Claude API。

一句方法论上的话先说在前面：本课的价值不在「我们不用 Claude Code 也能学」这个限制，而在它逼你只关注真正难、真正不过时的部分——协议、控制流与正确性。框架会换代、命令语法会变、提示工程的奇技淫巧明年就过时；而「一份 skill 如何被发现与按需加载」「一条命令如何解析与展开」「一个 MCP 握手如何协商能力」「一个插件如何隔离命名空间」这些结构性的东西，换到任何框架、任何厂商都立刻能用。把它们练扎实，就抓住了 agent 可扩展性里真正稳定的那一层。

2世界观：能力 = 发现→选择→注入/调用 的流水线

贯穿全课的世界观，是把 agent 的能力理解成一条从「潜在能力」到「本轮实际能力」的流水线，而非一堆写死的 if-else。一个写死的 agent 是「我会的就这几样，改不了」；一个可扩展的 agent 是：

磁盘上的能力 发现 注册表（轻量目录） 选择 注入/调用 ┌──────────────┐ ┌────────┐ ┌──────────────────┐ ┌────────┐ ┌──────────────┐ │ SKILL.md ×N │ ──读 ──►│ 解析 │ ──── ►│ name → 描述/路径 │──►│ 按相关 │ ──── ►│ 把命中 skill │ │ commands ×N │ frontm. │ frontm. │ │ (描述常驻, 正文惰 │ 性 │ 性挑选 │ 任务 │ 正文/工具 │ │ plugins ×N │ -atter │ /清单 │ │ 性按需加载) │ │ 子集 │ │ 注入给模型 │ │ MCP servers │ └────────┘ └──────────────────┘ └────────┘ └──────────────┘ └──────────────┘ ▲ │ └──────── 渐进披露：轻量进、完整按需 ─────────┘

这张图就是整门课的总纲：每个模块都是在实现或加固这条流水线的某一段。模块 01（skill 加载）实现「磁盘上的指令 → 解析 frontmatter → 注册 → 按相关性注入」这条主线，并立起渐进披露这个贯穿全课的原则；模块 02（slash 命令）实现另一条入口：用户显式 `/命令` → 解析参数 → 展开模板（含动态注入）→ 发给模型；模块 03（MCP）把「能力从哪来」标准化——用一套开放协议即插即用地接入任意外部工具与数据；模块 04（插件）把 skill、命令、工具、MCP 配置打包成一个可分发、可安装、可隔离的单元，是上面所有零件的「分发层」；模块 05（完整系统）把前四块组装起来，接到 agent 循环上，用一个真实任务端到端验证「发现→选择→组合→执行」。

把这条流水线记牢，你会发现五个看似分散的主题其实是同一条流水线的五个面：指令怎么按需加载（01）、命令怎么展开（02）、能力从哪标准化接入（03）、怎么打包分发与隔离（04）、整条线怎么组装运转（05）。这也是本课刻意的编排——不堆专题，而是绕着「让 agent 可扩展」这一个核心对象层层加深。

3两条触发路径与能力递进链

两条触发路径：模型自动 vs 用户显式

如果只能记住一组对照来理解 skills 与 slash 命令，那就是：skill 由模型按相关性自动触发，slash 命令由用户显式触发。这两条路径覆盖了「让能力被用上」的两种根本方式，缺一不可。

维度skill（模块 01）slash 命令（模块 02）
谁触发模型（读 description 判断相关）用户（显式打 `/命令`）
文件形态SKILL.md：frontmatter + 正文指令命令模板：frontmatter + 带占位符的 prompt
何时进上下文命中相关性后注入正文用户调用并绑定参数后展开
典型用途「这类任务该怎么做」的知识与约定「一键跑某个工作流」的固定动作
参数无（靠任务文本驱动）有（`$ARGUMENTS`/`$1`，可 `!`shell``/`@file` 动态注入）

顺着这两条路径往外看，本课的五个模块构成一条能力递进链：

模块在流水线里加了什么一句话能力
01 skill 加载把「指令知识」做成可发现、可按需加载、可注入的零件让 agent 能「平时不占上下文、用到才加载」一份做事指南
02 slash 命令把「固定工作流」做成可解析、可绑参、可动态注入的命令让用户能一键触发带实时上下文的预设动作
03 MCP把「能力从哪来」标准化为一套开放协议让任意外部工具/数据都能被任意 agent 即插即用地接入
04 插件把 skill/命令/工具/MCP 打包成可分发、可隔离的单元让能力可以被打包、安装、版本化、互不冲突地共存
05 完整系统把前四块组装、接到 agent 循环、做选择与组合让 agent 能在一个任务里恰当地发现、选择、组合、执行能力

注意这不是松散的专题集合，而是一条有内在逻辑的链：先有按需加载的指令（01）与显式触发的命令（02）两条能力入口，再用一套协议把外部能力标准化接进来（03），然后把这些能力打包成可分发的插件并解决共存问题（04），最后把一切组装起来、接到模型的决策循环上（05）。读到最后你会看到：所谓「可扩展的 agent」，就是把这五块严丝合缝地拼起来——而且每一块你都亲手造过、不靠任何框架。

4方法论：用 MockLLM 从零造并对拍（不依赖框架）

方法论：没有大模型、没有 API key、不依赖框架，怎么学造这套系统？

本环境没有 GPU、不接任何真实大模型、不需要任何 API key，也不依赖 Claude Code 等任何框架。但 skills 与工具生态的难点，从来不是「调用模型这一行 API」，而是包在模型外面的那一切可扩展性机制：frontmatter 怎么解析、相关性怎么判、命令怎么展开、MCP 怎么握手、插件怎么隔离、能力怎么选择与组合。这些用纯 Python 标准库就能精确地表达和验证。

我们的核心工具叫 MockLLM：一个确定性的、规则驱动的假模型。它不学习、不联网、没有神经网络——只是对给定的上下文，按预设规则返回一个结构正确的工具调用或文本（比如「看到注入了 git skill 且任务含 提交 就返回 调用 git_commit」）。这听起来像作弊，恰恰相反：把模型换成确定性的桩，能力的不确定性就被剥离，剩下的全是你这套可扩展性子系统的对错。你写的 skill 加载器、命令路由、MCP server、插件加载器，在 MockLLM 下要么对、要么错，没有「模型今天状态不好」的借口——这正是把工程逻辑练成肌肉记忆的最干净环境。

直白说

打个比方：学装修不一定要先有业主入住。skills/工具生态的「装修」是怎么把能力做成可插拔的零件、怎么发现/加载/打包/组合它们；这些在一个空房子（MockLLM）里能装得更扎实。等每个零件都装对了，住进真人（真实模型）只是把样板间换成实际使用——逻辑一模一样。

严谨说

关键纪律是对拍 + assert：每个零件都和一个朴素参考实现或明确的不变量比对。frontmatter 解析器要在合法输入上解析正确、在残缺输入上优雅处理；命令解析要把 `/cmd a "b c"` 拆成正确的参数；MCP server 对 `tools/call` 要返回与直接调用函数一致的结果；插件加载后命名空间不能冲突。结构正确 → assert 通过；assert 通过 → 这套逻辑可以原样搬到真实 Claude Code / MCP。

真实 Claude Code / MCP 生态里的东西本课的从零实现对应真实接口
大模型（决定调什么 / 哪个 skill 相关）MockLLM：规则驱动的确定性桩（无 key 时自动回退）Anthropic messages.create(model=claude-sonnet-4-6)
SKILL.md（frontmatter + 正文）纯标准库手写的 frontmatter 解析 + 注册表Anthropic Agent Skills / Claude Code skills
slash 命令模板（$ARGUMENTS / !shell / @file）自写的解析器 + 绑定 + 动态注入器Claude Code slash commands
MCP server 进程一个本地 Python 对象 + JSON-RPC 编解码 + 内存 stdio真实 MCP server（stdio / HTTP）
插件（plugin.json manifest）自写的 manifest 解析 + 加载 + 命名空间隔离Claude Code plugins
可扩展的 agent 循环把四块零件组装 + MockLLM 驱动Claude Code 的 agent 运行时

务必清楚本课不教什么：不教提示工程的具体话术、不调真实模型的超参、不追求生产级的沙箱隔离、不复刻 Claude Code 的全部细节。这些在你有了正确的零件之后，是第二步（references 里的官方文档接手）。本课负责把第一步——协议、控制流与正确性夯死；这一步搞定，第二步才有意义。也正因如此，本课的代码刻意不依赖任何框架、不调用任何需要密钥的服务，你随时能 `python` 跑通每一个 cell。

5环境与运行

环境与运行

环境极简：只需 Python 3 标准库（numpy 都不需要；个别可视化可选 matplotlib）。全课 CPU 秒级运行，无需 GPU、无需联网、无需任何 API key、无需安装任何框架。凡是用到「模型」的地方都是 MockLLM；想接真实 Claude 时只需 `pip install anthropic` 并设 `ANTHROPIC_API_KEY`，没有 key 也会自动回退、绝不报错。

conda create -n skills-tools python=3.11 -y && conda activate skills-tools
# 本课纯标准库，无需任何安装即可跑通所有 notebook
pip install anthropic      # 仅当你想接真实 Claude 时（可选，无 key 自动回退 MockLLM）
pip install matplotlib     # 可选，仅个别图
jupyter lab

每个模块配一个 notebook，结构统一：先用纯标准库把机制从零实现并验证（5–6 个 worked 小节，每节都跑出可打印的输出与 assert 自测），再做 3–4 道带 assert 判分的 ✏️ 练习（先给骨架，自己填，再对照 📖 参考答案），最后一个真实数据胶囊（用真实 SKILL.md / 真实 slash 命令 / 真实 MCP 报文 / 真实 plugin.json 的形状，把纸面知识接到现实）。每个 notebook 都端到端可跑、不需要密钥；并在关键处旁附真实 Claude API 适配代码（`messages.create(model=...)`，无 key 自动回退 MockLLM），让你看清从零实现与真实生态的逐行对应——学完照着把验证过的零件接到真实 Claude Code / MCP，是最自然的下一步。

建议的学习节奏：先读完整章 HTML 建立直觉与协议框架，再打开 notebook 亲手实现。读和做缺一不可——只读会觉得「好像懂了」，真正动手写 frontmatter 解析器、调命令展开、让 MCP 握手正确、让插件命名空间不冲突、让 assert 通过时，才会发现魔鬼藏在哪些细节里（残缺 frontmatter、带引号的参数、握手顺序、命名冲突、版本约束）。这门课的深度正是为「动手」服务的。

配套先读：Anthropic Agent Skills 文档（skill 形状）、Claude Code slash commands / plugins 文档（命令与插件）、MCP 规范（modelcontextprotocol.io）、JSON-RPC 2.0 规范（消息格式）、以及渐进披露这一贯穿原则。完整清单见 references.md。

✅ 学完整门课，你应该能：
  1. 把 agent 的能力理解成「发现→选择→注入/调用」的流水线，说清渐进披露在每一段做什么；
  2. 从零写 skill 加载器：纯标准库解析 frontmatter、发现并注册、按相关性触发、按需注入正文、控制 token 预算；
  3. 从零写 slash 命令系统：解析 `/cmd args`、绑定 `$ARGUMENTS`/`$1`、动态注入 `!`shell``/`@file`、路由到处理器；
  4. 从零写一个 mini MCP：JSON-RPC 2.0 编解码、initialize 握手与能力协商、tools/resources/prompts 列举与调用、错误码，server+client 端到端闭环；
  5. 从零写一个插件系统：解析 manifest、发现并加载、命名空间隔离避免冲突、检查 semver 版本依赖；
  6. 把以上四块组装成一个不依赖框架的完整 skills 系统，接到 agent 循环（MockLLM 驱动），端到端完成一个真实任务并评测；
  7. 把验证过的纯标准库零件映射到真实 Claude Code / MCP 接口，并用 `messages.create(model=...)` 接上真实模型（无 key 自动回退）。
