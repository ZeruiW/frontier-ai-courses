1这门课讲什么

欢迎来到 Agent Harness 从零（动手造 Agent）。这门课只追求一件事：让你从「会调用 agent 框架」变成「会亲手造一个能跑的 agent」。

现在人人都在用 agent：Claude Code 帮你改代码、各种「AI 助手」帮你订机票查资料。但绝大多数人和 agent 的关系，止于 pip install some-agent-framework 然后调它的 API。这门课要往下钻一层：当一个 agent「自己」决定先搜索、再计算、再回答时，它内部到底发生了什么？模型明明只会输出文本，怎么就「调用」了工具？工具的结果又是怎么回到模型脑子里的？为什么有的 agent 会陷入死循环、有的会崩溃、有的会悄悄烧掉你一百块钱？

这些问题的答案不在任何框架的文档里，而在框架替你藏起来的那几百行编排代码之中。一个 agent，剥到底，本质上只是四样东西拼起来的程序：一个循环（反复问模型「下一步做什么」）、一套工具（模型能调用的外部能力）、一个 LLM 接口（把「问模型」这件事统一起来）、以及一层鲁棒性（让它在出错时不崩、不死循环、不烧钱）。本课就是沿着这条主线，把这四样东西从零拆开、亲手用纯 Python 标准库重建，最后拼成一个真正能用工具多步完成任务的最小 agent。

学完你应当能回答这类问题（也是 agent / LLM 工程岗位的高频面试题）：agent 循环到底是怎么转的？模型只输出文本，「工具调用」是怎么实现的？工具结果怎么回灌给模型？ReAct 的 thought/action/observation 怎么解析？agent 怎么知道该停了？怎么防止它死循环、怎么处理它调用不存在的工具、怎么接真实的 Claude API？——并且能在纯标准库里把这一切从零写出来、用 MockLLM 端到端验证它确实多步完成了任务。

一句方法论上的话先说在前面：本课刻意不依赖任何框架，不是为了重复造轮子，而是因为「亲手造一遍」是真正理解的唯一捷径。框架把循环、解析、分发、重试全替你做了——方便，但也让你对「它为什么这么设计、出问题时该改哪里」一无所知。本课把这层魔法彻底拆开：你写的每一行都没有黑箱，每个设计取舍都看得见。练扎实这套地基，再去读 Claude Code、LangChain 的源码，你会发现它们只是把你已经懂的东西做得更全面——你将能看懂、改动、甚至自己造任何 agent 系统。

2agent 的解剖：它是一个程序

agent 的解剖：它不是一个模型，而是一个程序

第一个、也是最重要的认知纠正：agent 不等于 LLM。LLM 是一个函数——给它文本，它返回文本，仅此而已。它不会「执行」任何动作，不会「记得」上一轮，不会「决定」做什么。把一个只会输出文本的模型，变成一个能自主查资料、算数、改文件、多步完成任务的 agent，靠的是围绕模型的那一圈编排代码——这圈代码就是 agent 的本体，本课称之为 agent harness。

组成是什么解决什么问题本课模块
agent 循环 loop反复「问模型→执行→回灌」的主循环让模型能多步行动、而非只答一次01
工具系统 tools注册表 + schema + 分发器给模型「手脚」：调用外部能力02
LLM 接口 adapter统一的 complete() 抽象 + MockLLM/真实让循环不关心背后是 mock 还是真模型03
鲁棒层 robustness重试/超时/循环检测/成本追踪让它出错不崩、不死循环、不烧钱04
最小 agent把以上拼成一个能用的整体端到端多步完成真实任务05

注意这张表不是松散的功能清单，而是一条严格递进的依赖链：最小 agent（05）= 循环（01）+ 工具（02）跑在 LLM 接口（03）之上、外裹鲁棒层（04）。读到最后一个模块，你会发现它没有一个新概念——全是前四个模块零件的组装。这也是本课刻意的编排：把一个看似高深的「AI agent」，还原成几个朴素零件的拼装，让你确信「我也能造出它」。

一个有用的类比：LLM 是引擎，agent harness 是整辆车。引擎再强，没有方向盘（决策循环）、轮子（工具）、油路（上下文回灌）、刹车（鲁棒性），也只是个原地轰鸣的铁块。市面上的「agent」之所以能力天差地别，差的往往不是引擎（大家都用差不多的大模型），而是这辆车造得好不好。本课教你造车。

3一圈循环：agent 如何「自主」行动

一圈循环：agent 是怎么「自主」行动的

agent 的「自主」其实没有任何魔法，就是一个 perceive-decide-act-observe（感知-决策-行动-观察）的循环在转。把它画出来：

┌──────────────────────────────────────────────┐ │ │ ▼ │ ① 感知 perceive 把历史(thought/action/observation) │ │ 组织成 prompt 喂给模型 │ ▼ │ ② 决策 decide LLM 输出「下一步动作」 │ │ (调工具 X 参数{...} / 给最终答案) │ ▼ │ ③ 行动 act 是最终答案? ──是──► 停止，返回答案 │ │ 否(要调工具) │ ▼ harness 执行工具、拿到结果 │ ④ 观察 observe 把结果写回历史 ────────────────────┘ (回到 ① 进入下一轮)

逐步看一遍：① harness 把当前对话历史（包括之前几轮模型的思考、调过的工具、拿到的结果）组织成 prompt；② 调用 LLM，模型输出它的决定——要么「我要调用 search，参数是 ...」，要么「我已经知道答案了，是 ...」；③ harness 检查：如果是最终答案就结束循环、返回；如果是工具调用，就真正去执行那个工具；④ 把工具的执行结果（observation）写回历史，回到 ①，让模型基于新信息再决定一次。如此往复，直到模型给出最终答案或触发安全上限。

直白说

打个比方：agent 就像一个蒙着眼睛、只能靠你转述的助手。你（harness）告诉它当前状况（感知），它说「帮我查下 X」（决策），你去查（行动），把查到的结果念给它听（观察），它再说下一步……它的每个「自主」决定，都建立在你忠实地把上一步结果回灌给它之上。

严谨说

形式上：这个循环把一个无状态的函数（LLM 每次调用互相独立、不记得过去）变成了一个有状态的过程——状态就藏在那个不断累积的历史（scratchpad）里。每一轮把新的 observation 追加进去，模型下一次就「看得见」它。所谓 agent 的「记忆」，本质就是这段越来越长的上下文。

这个循环就是模块 01 的全部内容。它简单得惊人——核心不过十几行——但正确地实现它出奇地容易出错：怎么解析模型那段半结构化的输出？怎么判断「这是最终答案」还是「这是工具调用」？万一模型永远不给最终答案怎么办（死循环）？这些正是本课要一个个解决的。

4MockLLM：端到端可跑且不烧钱

MockLLM：本课能端到端跑、且不烧钱的关键

本课有一个贯穿始终的方法论，必须先讲清楚：我们用一个叫 MockLLM 的「假大脑」来驱动 agent，而不是真实的 Claude API。这看起来像个妥协（没有真模型），实则是本课能成立的关键设计，理由有三。

  • 能端到端真实运行：MockLLM 返回一段预设的动作序列（如「第一步调 search、第二步调 calculator、第三步给答案」）。把它插进 agent 循环，整个 agent 就真的转起来了——真的解析、真的分发工具、真的回灌、真的停止。你看到的不是伪代码，是一个真在跑的 agent。
  • 能用 assert 精确验证：真实 LLM 带随机性，你没法断言「它一定会这么做」。但 MockLLM 是确定性的——给定脚本，agent 的轨迹完全可预测。于是我们能写 assert agent 在第 2 步调用了 calculator、assert 它在 3 步内停止 这样的精确判据，把「循环对不对、分发对不对、停止对不对」钉死，而非「看起来像对」。
  • 零成本、不需要 API key：MockLLM 不联网、不花钱、秒级运行。你能反复跑、随便改、放进 CI，完全不碰真实账单。这让「学习 agent 内部机制」这件事和「有没有 API key、舍不舍得烧钱」彻底解耦。

直白说

可以把 MockLLM 理解成给 agent 拍戏用的「替身演员」：它严格按剧本（预设动作）走位，让你能反复排练整场戏（agent 循环）、检查每个走位是否到位（assert），而不必请来真正的大牌（昂贵且难预测的真实模型）。等整台戏排顺了，换上真演员只是一行选角。

严谨说

形式上，MockLLM 与真实 client 实现同一个接口（`complete(system, messages, tools)`），靠的是pluggable（可插拔 / 依赖注入）：把 LLM 当成参数注入 agent，而非写死。于是测试用 mock、上线换真实，agent 循环一个字都不用改。这正是模块 03 的核心，也是工业级 agent 框架的标准做法。

一定要清楚 MockLLM 不能做什么：它不会真的「思考」，只会播放你预设的脚本。所以它能验证机制（循环转得对不对、工具分发对不对、错误处理对不对），但不能验证智能（模型选的动作明不明智）。这恰好是本课的分工：用 MockLLM 把 harness 的机制夯死，再把真实智能交给 Claude——每个模块都附「换上真实 Claude API」的适配代码，有 key 就接真模型、没 key 自动回退 MockLLM，两条路都全程可跑。

5接真实 Claude：无 key 自动回退

接真实 Claude：有 key 接真模型，没 key 自动回退

本课不是「纸上谈兵的玩具」。每个 notebook 在用 MockLLM 把机制讲透之后，都附一段真实可用的 Claude 适配代码：它实现与 MockLLM 完全相同的接口，内部用 anthropic SDK 调真实的 claude-opus-4-8。于是你写的、用 MockLLM 验证过的整套 agent 循环，能一行替换就接到真实模型上跑。

# 本课真实适配的统一姿态（每个 notebook 都有）：
def make_llm():
    if os.environ.get('ANTHROPIC_API_KEY'):
        return AnthropicLLM(model='claude-opus-4-8')   # 有 key：接真实 Claude
    return MockLLM(script=[...])                       # 没 key：回退假大脑，照样跑

agent = Agent(llm=make_llm(), tools=registry)         # agent 循环对二者一视同仁

这段「无 key 自动回退」是本课的硬性纪律——绝不让缺 API key 阻断 notebook。没有 key 的读者用 MockLLM 把每个机制学透、跑通、过 assert；有 key 的读者把同一份代码接到真实 Claude 上，亲眼看到真模型在你亲手造的 harness 里多步完成任务。两种读者读的是同一份代码，只差一个环境变量。

真实适配会用到 Claude Messages API 的几个要点（模块 03 详讲、这里先建立印象）：调用是 client.messages.create(model, system, messages, tools, max_tokens)；模型想调工具时返回一个 tool_use 块、stop_reason 为 "tool_use"；你执行后把结果作为 tool_result 块放进一条 user 消息回传（tool_use_id 对应）。本课内部的消息格式刻意与这套协议同构，所以适配器几乎只是格式翻译。

配套先读：Anthropic《Building effective agents》建立「workflow vs agent」的取舍直觉；ReAct（Yao 2022）是 agent 循环的奠基；Anthropic 的 tool use 与 Messages API 文档是真实适配的权威依据。完整清单见 references.md。若对 Claude API 细节不确定，可查 claude-api skill。

6环境与运行

环境与运行

环境极简到几乎不需要环境：本课所有 notebook 都是纯 Python 标准库，不装任何第三方包就能端到端跑通（MockLLM 不联网、不需要 key）。只有当你想接真实 Claude 时，才需要 pip install anthropic 并设置 API key。

# 学全部机制（MockLLM 路径）—— 零依赖，任何 Python 3.9+ 都能跑
python3 01_agent_loop.ipynb 里的代码   # 或在 jupyter lab 里逐 cell 运行

# 想接真实 Claude（可选）：
pip install anthropic
export ANTHROPIC_API_KEY=sk-ant-...
# 之后同一份代码会自动走真实路径

每个模块配一个 notebook，结构统一：先用纯标准库把那一块机制从零实现并端到端跑通（5–6 个 worked 小节，每节都用 MockLLM 跑出可打印的验证与 assert 自检），再做 3–4 道带 assert 自测的 ✏️ 练习（先给骨架，自己填，再对照 📖 参考答案），最后一个真实数据胶囊（接真实 Claude 的适配代码，无 key 自动回退 MockLLM、全程可跑）。

建议的学习节奏：先读完整章 HTML 建立直觉与设计框架，再打开 notebook 亲手实现。读和做缺一不可——只读会觉得「好像懂了」，真正动手写循环、解析模型输出、调试为什么死循环、让 assert 通过时，才会发现魔鬼藏在哪些细节里（解析的边界、停止的判定、错误的隔离、并行结果的对位）。这门课的深度正是为「动手」服务的。

✅ 学完整门课，你应该能：
  1. 讲清 agent = 模型 + 循环 + 工具 + 上下文，并说出每一块解决什么问题；
  2. 从零写出一个 agent 循环（解析 ReAct 的 thought/action/observation、回灌观察、正确停止、max-steps 防护），用 MockLLM 端到端验证；
  3. 从零搭一个工具系统（注册表、JSON Schema 校验、分发、并行、错误隔离），让坏调用变成可反馈的错误而非崩溃；
  4. 设计一个可插拔的 LLM 接口，写出 MockLLM 与真实 Claude 适配器，做到一行互换、无 key 自动回退；
  5. 给 agent 加一层鲁棒性（指数退避重试、超时、幻觉工具名处理、无限循环检测、token/成本追踪与预算熔断）；
  6. 把以上拼成一个能用工具多步完成真实任务的最小 agent，端到端跑通并讲清它的每个扩展点；
  7. 读懂 Claude Code / LangChain 这类框架的源码，知道它们的每个设计取舍为什么这么做。
