1为什么「类别体系」比模型选型更早决定天花板

模块 00 算清了物理边界：146 米处只有 6.8 个像素。这一节要说清另一条同样刚性、但更容易被忽视的边界——你定义的类别体系决定了这个系统最好能到什么程度，而且它一旦上线就极难改。

原因很直接：类别体系是标注规范（annotation protocol）的输入，标注规范决定了已标数据的语义，而已标数据是不可逆资产。改一次细类定义，历史上所有数据要么重标（几十万框，成本以百万计），要么废弃。所以「先随便定几个类，跑通再说」在 TSR 里是最贵的一种技术债。

直白说

举个具体的例子。假设你一开始把限速牌定义成 speed_limit_60、speed_limit_80 这样的扁平类别。三个月后产品说「要支持区间测速起终点」「要支持货车专用限速」「要支持 LED 可变限速牌」。在扁平体系里，这三件事各自把限速类别数乘以一个倍数——原来 14 个限速值变成 14×5×2×16 = 2240 个类别，而其中绝大多数一辈子也收集不到 10 个样本。而在层次体系里，这三件事只是给属性头多加三个字段。

严谨说

更严谨地说：扁平类别体系把语义的笛卡尔积硬编码进了输出层，于是类别数随语义维度指数增长，而每个类别的样本数随之指数衰减——这就是 TSR 长尾的人造成分。真实世界的长尾（某些标志本来就罕见）是不可消除的；但由类别设计造成的长尾是可以设计掉的。「先分清哪部分长尾是真实的、哪部分是你自己造出来的」，是 TSR 数据工作的第一步，也是面试里能立刻显出经验的判断。

本模块的主线可以浓缩成一句话：把「类别」压到最少，把「属性」做到最全，把「几何证据」原样输出。类别负责「这是哪一族标志」（样本充足、可靠），属性负责「具体参数是多少」（可共享参数、可增量扩展），几何证据负责「它是否对自车生效」（交给有上下文的下游判断）。模块 00 的四层输出（L0 定位 / L1 粗类 / L2 细类 / L3 属性），正是这个原则的产物。

还应该知道的第二梯队

  • LISA（美国, MUTCD 体系）：≈6,610 帧、≈7,855 个标注、47 种美国标志。价值在于它是 MUTCD 体系的对照组——把它和 GTSRB 放一起看，「形状-颜色-语义映射」的体系差异一目了然。
  • DFG Traffic Sign Dataset（斯洛文尼亚）：约 7,000 张、13,000 个实例、200 个细类，且刻意保留了长尾。它是「细类多 + 每类样本少」这个 TSR 典型形态的干净实验床。
  • CURE-TSD / CURE-TSR：在同一批场景上人工施加 12 种退化（雨、雪、雾、镜头模糊、过曝、噪声、编码伪影…）× 5 个强度等级。这是做「失效模式分桶评测」（模块 03/05）时最省事的现成材料。
  • RTSD（俄罗斯）：十万量级帧、150+ 类，覆盖冬季与低光。
  • nuScenes / Waymo Open Dataset：都没有细粒度的交通标志类别——nuScenes 把标志放在高精地图图层里而不是检测标注里，Waymo 有一个笼统的 sign 类。不要在面试里说「我用 nuScenes 做 TSR」，这会暴露没真看过标注。

直白说

把这些数据集串起来看，会发现一个尴尬但重要的事实：没有任何一个公开数据集能直接支撑量产 TSR。GTSRB 没有检测框、GTSDB 太小、TT100K 域差大且只有一万张有效图、MTSD 画质异质、BDD100K 没有细类。所以真实岗位上你面对的一定是「自建数据集 + 公开数据集做预训练/验证」的组合——而这正是「标注规范」和「类别体系」如此重要的原因：你才是那个定义数据的人。

严谨说

更进一步：这些数据集的价值应该按用途分开评估，而不是按「哪个更大」排序。预训练与结构验证用 TT100K（中国体系、小目标充分）；跨域泛化研究用 MTSD（唯一的多区域来源）；恶劣条件鲁棒性用 BDD100K + CURE-TSD；分类头的快速消融用 GTSRB（分类任务干净、迭代快）；长尾方法的对照实验用 DFG（200 类且尾巴真实）。「按用途选数据集」而不是「按大小选数据集」，是数据工作成熟度的直接体现。

GTSRB 的 track 泄漏是一个必须知道、且面试里可以主动提的坑。数据集里每一块物理标志会以约 30 帧的连续 track 形式出现（车在接近，标志越来越大）。如果你把所有图块打散后随机划分 train/test，同一块物理标志的第 7 帧会进训练集、第 8 帧会进测试集——两张图几乎一模一样。结果是测试准确率虚高好几个点。GTSRB 官方是按 track 划分的，正是为了避免这一点；而很多复现代码没注意，直接 train_test_split。这个坑在自建数据集上会以「按帧划分而不是按路段/按物理标志划分」的形式重现，而且更隐蔽，因为没有人提醒你。

3三大标志体系：形状-颜色-语义的映射是三个不同的函数

「用红色分割 + 圆形检测找限速牌」这类传统 CV 方法，以及「CNN 隐式学到颜色和形状先验」这个事实，都建立在一个假设上：形状与颜色到语义存在稳定映射。这个假设在单一区域内成立，跨区域则彻底失效——因为世界上有三套互不兼容的标志体系。

三个最有杀伤力的具体差异

  1. 警告标志的形状：Vienna 与中国是三角形，美国是黄色菱形。一个在中国数据上训练的模型，学到的「三角形 ⇒ 警告」先验在美国一次都用不上。
  2. 限速牌的表示方式：Vienna/中国是「红圈 + 数字」——颜色和形状承载了「这是限速」这个语义，数字只承载参数；美国是「白底矩形 + SPEED LIMIT 文字 + 数字」——语义完全由文字承载。这导致两个体系的限速识别是两种不同的任务：前者是细粒度视觉分类 + 数字识别，后者本质上是场景文字识别（OCR）。
  3. 蓝色的含义：中国和 Vienna 里蓝底圆形是强制性指示（「必须直行」「必须靠右」）；美国的蓝色是服务设施（加油站、医院、休息区），完全没有强制性。把「蓝色 ⇒ 必须执行」这条规则带到美国，会让车对着加油站指示牌做动作。
  4. 指路牌底色与道路等级的映射甚至在欧洲内部就不一致：中国「绿底 = 高速」，德国「蓝底 = 高速（Autobahn）、黄底 = 联邦公路」。也就是说，同一块蓝底指路牌在中国意味着「普通道路」，在德国意味着「高速公路」——语义正好相反。

直白说

这些差异导出一个非常实用的结论：「跨区域迁移 TSR 模型」不是域适应问题，是任务重定义问题。域适应（domain adaptation）解决的是「同一个语义在不同外观分布下的识别」——比如晴天训练、雨天部署。而跨标志体系改变的是标签空间本身与形状-颜色-语义映射函数，没有任何域适应方法能处理「三角形在这里是警告、在那里不存在」。正确的工程回答是：换区域 = 换类别体系 + 换标注 + 重训分类头（检测头因为是类别无关的，往往可以复用——这又是两级方案的一个隐藏优势，见模块 02）。

严谨说

但也存在一条可迁移的中间层，值得作为面试里的「加分观点」：把标志分解成「几何形状 + 主色 + 内部图元（数字/箭头/符号/文字）」这三个可组合的部件，而不是把每个标志当成一个整体模板。部件是跨体系共享的——八角形、红色、数字「60」在三个体系里都存在，变的只是组合规则与组合后的语义。因此「部件级表示 + 区域相关的组合规则表」在理论上能让视觉主干跨区域复用，只替换那张规则表。这正是本节末尾「研究前沿」里会再提到的开放方向：它有明确的工程价值，但目前还没有被公认可行的实现。

同形不同义：跨区域最危险的一类错误

一个真实会出事的场景：某些标志在不同体系里形状相同、语义不同。例如「圆形 + 红边 + 白底 + 数字」在 Vienna 体系是最高限速，但在美国某些州的特定语境（如收费/桥梁限重的圆形牌）以及在部分国家的「建议速度」牌里，同样的视觉形态含义不同；再如倒三角在多数国家是「让行」，而在日本「一时停止」用的是倒三角红底白字「止まれ」——它的语义是 STOP 而不是 YIELD。模型看到倒三角输出 YIELD，在日本就是「该停不停」。所以跨区域部署必须有一张显式的「区域 → 标志体系」配置表，而不是指望模型自己泛化。这条在面试里讲出来，比背十个数据集名字有用。

4类别数爆炸：真实长尾与人造长尾

TSR 的类别数为什么会失控？因为每增加一个语义维度，类别数就乘以一个倍数。以中国的限速牌为例，把它写成笛卡尔积：

限速类的语义维度（中国 GB 5768 场景） ① 限速值 {5,10,15,20,30,40,50,60,70,80,90,100,110,120} 14 种 ② 牌型变体 {限速, 解除限速, 最低限速(蓝底), 区间测速起, 区间测速终} 5 种 ③ 载体 {实体反光牌, LED 可变电子牌(VMS)} 2 种 ④ 辅助牌槽位 {车型限定?, 时段限定?, 距离预告?, 车道限定?} 各有/无 → 2^4 = 16 种 扁平类别数 = 14 x 5 x 2 x 16 = **2,240 类** —— 而这只是「限速」这一支 再算上其余细类（禁令/警告/指示/指路/辅助，约 59 个非限速细类）： 扁平总数 = (59 + 14x5) x 2 x 16 = 129 x 32 = **4,128 类** ──────────────────────────────────────────────────────────── 层次分解后**需要学的输出维度**： L1 粗类 7 + L2 细类 60 + 限速值 14 + 牌型 5 + 载体 2 + 辅助槽 4 = **92 维** 压缩比 ≈ **45x** 更重要的是**增量成本**： 新增一个限速值（比如 “限速 25”） 扁平体系 → 新增 5 x 2 x 16 = **160 个类别**，每个都要凑样本 层次体系 → 属性头多 **1 个分箱**，检测器与粗/细类头**完全不动**

直白说

这张账最重要的一行是最后那个「增量成本」。扁平体系的问题不是「类别多」，而是「类别数随需求线性增长的斜率太陡」。产品每提一个新需求（支持货车限速、支持区间测速、支持电子牌），你的类别表就要膨胀一个数量级，而新增的类别绝大多数永远收集不到足够样本——于是它们全都躺在长尾里，拖低指标、消耗算力、还得为它们单独做 badcase 分析。

严谨说

把这件事说清楚需要区分两种长尾。真实长尾（intrinsic）：某些标志在物理世界里本来就罕见——「注意牲畜」「注意落石」「潮汐车道」，你再怎么设计类别体系也改变不了它们的出现频率。人造长尾（induced）：由类别定义的笛卡尔积造出来的——「限速60+货车+8:00-18:00+前方500m 的 LED 牌」之所以只有 3 个样本，不是因为这种情况罕见，而是因为你把四个独立维度组合成了一个类别。真实长尾要靠数据闭环（C58）和重采样/重加权解决；人造长尾要靠类别体系设计消除。面试里能把这两者分开谈，是能力分水岭。

还有三类会持续制造新类别的东西，必须在设计阶段就想好归属：① 可变电子牌（VMS）——LED 点阵、黑底发光字，外观与实体牌完全不同，且内容随时变化，所以它的「限速 60」在语义上和实体牌一样、在视觉上完全是另一个东西；② 组合牌——主标志 + 一到多块辅助牌，组合数天然爆炸；③ 标准换版——GB 5768 从 1999 到 2009 再到 2022 改过图案，道路上会长期并存新旧两版。这三类如果按「新语义 = 新类别」处理，类别表会持续膨胀且永远追不上现实。

5层次标签设计：把长尾从「类别」赶到「属性」

解法在上一节已经出现了，这里把它做成可执行的设计。层次标签的核心动作只有一个：把「决定用哪套模型能力」的信息留在类别里，把「参数」赶到属性里。

层次感知的评测指标

扁平准确率有个致命缺陷：它把「限速60 错成限速80」和「限速60 错成注意行人」都记为 0 分。而这两种错误的下游后果差了一个量级。层次 F1（hierarchical F-measure，Kiritchenko 等人的定义）用祖先集合的重合度解决这个问题。记 Aug(c) 为从根到类别 c 的路径上的所有节点（不含根）：

\[hP=\frac{|Aug(\hat{y})\cap Aug(y)|}{|Aug(\hat{y})|},\quad hR=\frac{|Aug(\hat{y})\cap Aug(y)|}{|Aug(y)|},\quad hF=\frac{2\,hP\,hR}{hP+hR}\]
真值预测扁平准确率hF解读
限速60限速6011.00完全正确
限速60prohibitory（只给粗类）00.67诚实的降级——比自信的错答分更高，这正是我们想要的激励
限速60禁止驶入（同为禁令）00.50同族错分：下游至少知道「这是个禁令牌」
限速60注意行人（跨大类）00.00跨族错分：形状与颜色都判错了，通常是严重问题
「诚实的降级得分 0.67 > 自信的错答得分 0.50」这个不等式，是层次评测最重要的性质。它把「不确定时输出粗类」变成了一个被指标奖励的行为，而不是被惩罚的行为。在扁平体系下，模型没有任何理由输出「我只知道这是禁令牌」——因为那和答错一样是 0 分，还不如赌一个细类。指标的形状决定了模型（以及调模型的人）的行为；这条规律在模块 05「安全导向评测」里会以更大的尺度重现。顺带一提，本节 notebook 会证明「层次误分类代价矩阵」恰好等于 1 − hF，两者是同一个东西的两种写法。

6标注规范：十二条必须在第一天就定死的规则

标注规范写得含糊，等价于给数据集注入了一层不可见的噪声，而且这层噪声在训练时表现为「模型学不好」、在评测时表现为「指标不稳」，几乎不可能被反向定位。下面这十二条，每一条都对应一个真实会引发返工的坑。

#坑推荐规则不定死会怎样
1多小算有效三档：短边 <4 px → 不标（连有无都判不了）；4–16 px → 标为 ignore（不算正样本也不算负样本）；≥16 px → 正常标注只用「标 / 不标」两档是最常见的错误：不标 → 远处小标志变成负样本，模型学会「忽略小标志」，远距离召回崩；全标 → 人也看不清类别，引入大量标签噪声
2遮挡多少算有效按可见比例三档（<30% 不标 / 30–60% ignore / ≥60% 正常），并额外要求「关键判别区域可见」只按面积比例判会出错：限速牌边缘被挡 80% 仍可读，数字被挡 20% 就完全不可读。面积比例是代理指标，关键区域可见性才是真指标
3截断（图像边界）统一用 clipped（只标可见部分）或 amodal（标估计的完整范围），二选一并写进规范，且加 is_truncated 标记两种混用会让 IoU 计算、尺寸统计、分桶评测全部失真，且不同标注员之间产生系统性分歧
4背面标志标为独立类 sign_back（灰色圆板/三角板），训练时作为难负样本不标 → 模型对背面无监督，容易误检成正面标志；直接忽略 → 浪费了一批高价值的难负样本
5大角度侧面标志记录 facing: front / side / back；side 一般标为 ignore侧面标志严重透视变形，作为正样本会污染分类器；作为负样本又会压制真实召回
6对向车道 / 辅路标志照常标注，但记录几何属性（facing、横向位置、若有则 3D 位置），由下游判断是否对自车生效这是最容易设计错的一条：让标注员判断「这块牌对不对自车生效」需要车道拓扑与路径信息，标注员看不到 → 标注一致性极差、且信息不可逆丢失
7褪色 / 破损 / 涂鸦 / 贴纸正常标注 + condition 属性（normal / faded / damaged / graffiti）不记录 → 无法做分桶评测，也就永远不知道「模型在褪色牌上掉了多少」；直接丢弃 → 训练分布与真实道路不符
8不可读（过曝 / 反光 / 强逆光）标框 + 类别置 UNKNOWN + ignore 该样本的分类损失（但保留检测损失）整条丢弃 → 检测器学不到「这里有个牌」；强行猜类别 → 标签噪声直接进分类头
9组合牌（主牌 + 辅助牌）各标各的框 + 共享 group_id；辅助牌有自己的类别与属性整体标一个大框 → 类别爆炸且框不贴合；只标主牌 → 丢掉「限速仅对货车/仅在某时段」这类会直接改变控制动作的信息
10可变电子牌（VMS）carrier: vms + 标注时刻的读数 + is_variable: true当成实体牌标 → 下游会把一个临时读数当成永久限速；不标 → 高速场景最重要的一类限速源丢失
11框的边界到哪统一「含标志白边/外框、不含支撑杆件与背板」，并给出图示含不含边框会带来 5–10% 的尺寸系统偏差 → 直接污染 anchor 设计与按尺寸分桶的评测
12非真实标志不标为正样本：广告牌里的标志图案、车身贴纸、前车导航屏、驾校教具、玩具；但要单独收集为难负样本标了 → 模型学会检测广告牌 → 幽灵刹车；不管 → 这类误检永远修不掉（因为训练集里没有对应的负样本）

直白说

这十二条里最容易被低估的是第 1 条的「三档」设计。绝大多数团队一开始只有「标 / 不标」两档，而这在小目标任务里是有害的：不标的小标志会被标签分配算法当作背景，于是模型被显式训练成「看到 10 px 的圆牌要判负」——这与「我们希望它在远处至少给出 L1 粗类」的目标直接冲突。ignore 区域（COCO 的 iscrowd、mmdetection 的 gt_bboxes_ignore）存在的意义就是表达「这里我不知道，别拿它算账」，它既不产生正样本梯度也不产生负样本梯度。

严谨说

第二个容易被低估的是第 6 条：把「是否对自车生效」的判断权留给下游。这其实是一条通用的接口设计原则：把判断留在拥有上下文的那一层，把证据留在产生它的那一层。标注员（和感知模型）拥有的上下文是「这块牌长什么样、在图像的哪个位置、朝向如何」；「它属于哪条车道、我的规划路径会不会经过那条车道」这些信息只存在于地图与规控层。一旦让感知层做这个判断，你就永久丢掉了做正确判断所需的证据——因为被判为「不生效」的标志根本不会出现在输出里，下游连纠错的机会都没有。这条原则在模块 02（系统设计）与 C59（VLA 接口）会反复出现。

标注规范变更必须版本化并评估回溯

一条真实事故级的坑：标注规范变更后没有回溯重标，导致同一个数据集里存在两种语义。典型场景是「第一季度规定 16 px 以下不标，第二季度改成标为 ignore」——于是第一季度的数据里，小标志是负样本；第二季度的数据里，小标志是无监督区域。两批数据混在一起训练，模型收到互相矛盾的梯度，表现为「远距离召回怎么调都上不去，且方差很大」。而这个问题在任何指标上都不会直接显形。所以标注规范必须版本化，每一条标注都要带规范版本号，且变更时必须评估是否需要回溯——这与 C43 讲的数据血缘是同一件事。

7标注一致性：先量化标签噪声，再谈模型精度

在 TSR 里有一个反直觉但极其重要的事实：小目标的标注噪声量级，与你想要争取的精度提升量级是同一个数量级。如果不先量化标注一致性，你会花几个月去追一个本来就在噪声里的提升。

先看几何。模块 00 已经给过这个数：边长 s 的正方形框在 x、y 各偏移 δ 后，与原框的 IoU 是

\[\mathrm{IoU}(s,\delta)=\frac{(s-\delta)^2}{2s^2-(s-\delta)^2}\ \Longrightarrow\ \mathrm{IoU}(8,2)=0.391,\quad \mathrm{IoU}(16,2)=0.620,\quad \mathrm{IoU}(64,2)=0.884\]

直白说

把这个数翻译成标注场景：两个都很认真的标注员，对同一块 8 px 的远处标志各画一个框，彼此差 2 个像素——按 IoU≥0.5 的标准，他们会被判定为「标的不是同一个目标」。而 2 像素的分歧对 8 px 的目标来说，人眼根本无法避免（标志边缘本身就模糊了一两个像素）。也就是说，在小尺寸段，标注一致性天然很低，而这个不一致性会同时污染训练标签与评测真值。

严谨说

严谨的表述是：标注误差的绝对量级大致恒定（人手画框的抖动约 ±1–2 px，与目标大小无关），但相对量级随目标尺寸反比放大。对 64 px 的框，±2 px 是 3% 的相对误差；对 8 px 的框，±2 px 是 25% 的相对误差。这意味着小目标的标签本身就是带噪的，而且噪声结构是「定位噪声」而非「类别噪声」。直接后果：在小尺寸桶上，用 IoU=0.5 甚至 0.75 的严格阈值去评测是没有意义的——你测的一大半是标注抖动而不是模型能力。 实践中的做法是：小尺寸桶单独用更宽松的匹配阈值（或改用中心点距离 / NWD 这类对尺度不敏感的度量，见 C57），并明确声明该桶的指标不可与大尺寸桶直接比较。

怎么量一致性：三个必测的数

指标怎么算典型健康值异常时说明什么

Cohen's κ 的定义（po 是观察到的一致率，pe 是按各自边缘分布随机一致的期望）：

\[\kappa=\frac{p_o-p_e}{1-p_e},\qquad p_e=\sum_k p_A(k)\,p_B(k)\]
κ 而不是原始一致率，原因是类别分布极度长尾。当 60% 的标志都是「限速」时，两个人闭着眼睛都猜「限速」就有 36% 的一致率——原始一致率会把这部分算成「一致性好」。κ 把这部分扣掉，所以它才是长尾任务里唯一有意义的一致性指标。同理，在报告标注一致性时必须分层报告（按尺寸桶、按粗类），因为一个 0.85 的总体 κ 完全可能由「大目标 0.95 + 小目标 0.55」组成，而后者才是你真正要修的地方。

一条可以直接用的工作纪律：在启动任何模型改进之前，先做一次双标注抽检（同一批 500–1000 张由两个人独立标），把三个一致性数算出来。这件事成本很低（一两天），但它给你三样东西：① 一个「指标提升的噪声地板」——低于这个量级的提升不值得追；② 一份规范漏洞清单——分歧集中在哪几条规则上，那几条就是写得不够清楚的；③ 一个分尺寸桶的评测阈值依据。「你怎么知道你的 +0.5 mAP 不是噪声」是面试高频追问，而「我先量了标注一致性，噪声地板是 ±0.3」是最有说服力的答案之一。

8数据集偏差与跨域泛化：你训的到底是什么分布

前面几节讲的是「标签空间」，这一节讲「图像分布」。TSR 的跨域问题比通用检测严重得多，因为标志的外观由标准规定、几乎没有类内变化，于是模型会把大量容量花在拟合采集条件而不是标志本身上。

直白说

「划分泄漏」这一行值得单独强调，因为它是自建数据集上最普遍、也最容易被忽视的一个错误。TSR 数据天然是视频：一块标志在接近过程中被拍到 75 帧（模块 00 算过）。如果你按帧随机划分，train 和 test 里会出现同一块物理标志的相邻帧——它们的背景、光照、遮挡状态几乎完全一样。模型只要记住「这个路口的这块牌」就能答对，而这在真实道路上毫无价值。 正确的划分单位是物理标志实例（同一块牌的所有帧必须在同一侧），更保守的做法是按路段或采集时段划分。

严谨说

更一般地说，划分单位应当与泛化目标一致：你希望模型泛化到「没见过的标志实例」，就按实例划分；希望泛化到「没见过的道路」，就按路段划分；希望泛化到「没见过的城市 / 天气」，就按城市 / 天气划分。每换一个划分单位，测出来的数字会显著不同，而这个差值本身就是有用的诊断信息：按帧划分 95% / 按实例划分 88% / 按城市划分 72%，这三个数一起报告，才说清了模型到底泛化到了哪一层。只报最高的那个是自欺，而只报最低的那个又会低估模型在已覆盖区域的可用性。面试里被问「你的模型泛化性怎么样」，用这三档来答，会比任何单个数字都有说服力。

把本节浓缩成一条可执行的检查：拿到（或建好）一个数据集后，先问三个问题——① 图像是怎么采的（平台 / 相机 / ISP / 时段 / 天气分布）？② 标签空间属于哪个标志体系、版本是哪一版？③ 划分单位是什么？ 这三问答不上来，任何在这个数据集上得到的数字都不该被信任。而这三问恰好也是审阅别人实验结果时最有效的三个追问——它们能在两分钟内识别出大部分「看起来很好但没有意义」的结果。

9研究前沿与开放问题

  • 部件级（compositional）标志表示：把标志分解成「几何形状 + 主色 + 内部图元」的可组合表示，让视觉主干跨 GB 5768 / Vienna / MUTCD 三大体系复用，只替换一张区域相关的组合规则表。这在概念上很干净，但目前缺少公认可行的实现——难点在于「图元」的粒度怎么定（数字、箭头、剪影符号、文字各有不同的识别难度），以及组合规则本身也存在同形不同义的冲突。
  • 开放词表 / 少样本标志识别：用 CLIP / GLIP / Grounding DINO 这类模型实现「新增标志类型不重训」。目前的实验结论并不乐观：开放词表模型的强项是粗粒度语义对齐（「这是一个交通标志」），而 TSR 的难点恰好是极细粒度的差异（圆圈里的数字是 60 还是 80）。「粗类用开放词表、细类用专用头」的混合方案更现实，但如何在两者之间传递不确定性仍是开放问题。
  • 层次标签的自动构建：现在的类别树基本靠人根据国标手工设计。能否从数据（视觉相似度 + 语义相似度 + 下游动作相似度）自动导出一棵「对模型友好且对下游有意义」的层次结构，并随数据增长自动重构（分裂过粗的节点、合并样本不足的节点），是一个有明确工程价值的方向。notebook 里的 merge_tail_classes 是这个想法的最朴素版本。
  • 标注噪声的建模与利用：与其把标注抖动当成需要消除的坏东西，不如把它显式建模——用「框的分布」而非「框的点估计」作为监督信号（这与 GFL / 分布式框回归、以及 C57 里的 NWD 把框建模成高斯分布是同一个思路）。对小目标而言，「标签本身是分布」比「标签是一个精确的框」更符合事实，但如何在标注工具与训练流程里贯彻这一点，尚无成熟实践。
  • 合成数据与标志的可控生成：交通标志的「理想模板」是公开的（国标附图），理论上可以用渲染 + 域随机化（透视、光照、褪色、遮挡、运动模糊）为任意长尾类批量造样本。已有工作证明这对分类头有效，但对检测头收益有限——因为检测的难点在背景与上下文，而那部分合成不出来。「合成解决类别长尾、真实数据解决场景长尾」的分工是目前较可靠的经验，也直接连到 C56 的 copy-paste 与 C58 的定向挖掘。
  • 缺一个时序的、代价敏感的公开基准：现有 TSR 基准几乎都是单帧 mAP，而量产系统关心的是首检距离、闪烁率、FP/km、关键类召回（模块 05）。没有公开的时序基准，意味着学术界的改进与车上的体验之间缺少可验证的桥梁——这可能是这个领域最明显、也最容易被解决的空白。
