1先把任务拆开：TSR 不是「一个检测器」

很多人一听「交通标志识别」就想到「训练一个多类检测器」。这个直觉在 demo 上成立，在量产系统里几乎必然崩掉。原因是 TSR 的输出不是一个框加一个类别，而是一条从像素到可执行约束的链路——每一段都有自己的失败方式、自己的迭代节奏、自己的算力预算。

图像帧 │ ├─[1] 定位 Where? → 框 (x, y, w, h) ← 目标常常只有 12×12 px │ ├─[2] 识别 What? → 细类 (限速60 / 禁止左转 / …) ← 类别数 200+，极度长尾 │ ├─[3] 属性 Which one? → 状态、有效性、附加牌语义 │ · 电子牌当前显示值 │ · 是否被遮挡 / 褪色 / 破损 │ · 「限重 10t」「雨天」这类辅助牌条件 │ └─[4] 关联 For me? → 这块牌管哪条车道 / 哪个方向 / 从哪里开始生效 ← 对向车道、辅路、匝道的牌**不该管我** 最终交付给下游（规控 / VLA）的其实是 [1]+[2]+[3]+[4] 的合成结果： 「本车道，前方 42 m 起，限速 60，置信度 0.93，已连续确认 7 帧」

把这四段并列写出来，两个工程结论立刻浮现：

  • 它们的难度与数据需求完全不同。[1] 定位是几何问题，对光照/分辨率敏感，但类别无关，数据可以跨类别共享；[2] 识别是细粒度分类问题，受长尾支配，且新类别会不断出现；[4] 关联几乎是几何+地图问题，和像素关系不大。
  • 它们的迭代节奏不同。新增一个标志类别（比如某省新启用的一种警示牌），[2] 需要改；[1] 完全不需要改——因为「一块蓝底白字的矩形牌」在几何上和以前的牌没有区别。如果你把它们塞进同一个多类检测器，加一个类就得重训整个检测器，还要重新验证所有旧类不掉点。

直白说

所以「两级 vs 端到端」这个问题的真正含义不是「哪个 mAP 高」，而是 「[1] 和 [2] 该不该共用同一组参数与同一次训练」。端到端多类检测器的回答是「该」——一次前向同时输出位置和细类；两级方案的回答是「不该」——先用一个类别无关（class-agnostic）或粗类的检测器找出所有「牌状物」，再把每个 crop 送进一个专门的分类器。

严谨说

更精确地说，这是一个 factorization（因式分解）选择。端到端建模的是联合分布 p(box, class | image)；两级把它分解成 p(box | image) · p(class | crop(box))。分解的合理性依赖一个条件独立假设：给定 crop，类别与图像的其余部分无关。这个假设在 TSR 里近似成立（标志的语义几乎完全写在牌面上），但不完全成立——比如同一个圆形红边牌在高速与市区含义可能不同，上下文被 crop 丢掉了。知道这个假设在哪里失效，是这一节最值钱的部分。

一句话记住整节：检测器解决「像不像一块牌」，分类器解决「是哪块牌」——这是两个统计性质完全不同的问题，把它们分开，你就获得了分别优化它们的自由。而这个自由值多少钱，取决于你的类别有多长尾、新类来得有多频繁。

2两级方案的四个动机（以及它们各自的适用条件）

两级（two-stage / detect-then-classify）方案在 TSR 里几乎是工业界默认答案。它的四个动机不是并列的口号，每一条都对应一个可以量化的收益，也各自有一个「什么时候不成立」的边界。面试里被问「为什么用两级」，逐条讲清动机 + 边界，比背四个名词强十倍。

【端到端多类检测】 1920×1080 ──▶ Detector(200+ 类) ──▶ (box, class, score) ▲ └── 每个类别的正样本都要从整图里学： 「限速 5」全数据集只有 40 个实例 → 学不动 【两级：检测 → 分类】 1920×1080 ──▶ Detector(1~5 粗类) ──▶ box ──┐ 「牌状物」，样本量 = 全部标志之和 │ ▼ crop + 放大到 96×96 │ ▼ Classifier(200+ 细类) ▲ 输入已归一化：尺度、位置都不再是变量 └─ 长尾在这里单独治，重采样/重加权代价极低
动机具体收益为什么两级能做到什么时候这条动机不成立
① 长尾解耦检测器的正样本从「某一类的 40 个」变成「全部类的 12 万个」；分类器可以随意重采样而不影响检测检测器只学「牌状物」这一个概念，所有类别的实例都是它的正样本；分类阶段输入是已裁好的 crop，重采样 = 改 sampler，代价几乎为零类别本身在几何上差异巨大（如八角形 STOP vs 长条形指路牌）时，粗类合并会让检测器的回归目标变得多模态 → 要拆成 3–5 个粗类而非 1 个
② 增类不重训检测器新增一个标志类别只需重训分类器（分钟~小时级），检测器权重与验证结果全部复用新类的几何外观属于已有粗类（圆形禁令牌），检测器本来就能框到它新类的几何形态前所未见（如新出现的电子矩阵屏），检测器没见过 → 仍要补检测数据
③ 分类器可用更高分辨率远处 16×16 的牌，检测阶段在下采样特征图上只有半个格子；crop 后上采样到 96×96 送分类器，有效像素密度提升 6×（后文有账）分类器的输入是一小块 ROI，全分辨率处理它的算力开销 = 整图的 (96/1920)² ≈ 0.25%牌本身的物理像素就只有 12×12，上采样不能凭空造信息 —— 提升的是网络能分配给它的计算量，不是信息量
④ 可独立迭代定位问题（漏检远处小牌）与识别问题（限速 60/80 混淆）可以由不同的人、不同的数据、不同的评测集并行推进两级之间的接口是「crop + 框」，这是一个稳定、可版本化、可离线缓存的中间产物接口本身要改时（如决定给 crop 加更多 padding），两边都要重训 —— 接口设计错了，独立性就是假的

代价同样要背下来，只讲收益不讲代价是面试里最典型的减分项：

代价量级缓解手段
延迟叠加检测 8 ms + N 个 crop × 分类 0.4 ms。N=20 时分类阶段就是 8 ms，直接翻倍batch 化所有 crop 一次前向；上限 N（按分数 top-k 截断）；分类器做得极小（MobileNet 级）
误差级联检测漏掉的，分类器永远救不回来 —— 这是本模块的核心公式，下一节展开检测阶段用低阈值宁滥勿缺，把去伪的责任交给分类器（含 background 类）
工程复杂度两个模型、两套数据、两套评测、两条部署流水线；端到端指标要自己拼把两级封成一个 ONNX/TensorRT 图；建立联合评测脚本（见模块 05）
置信度不可比检测分数与分类分数是两个不同尺度的东西，直接相乘会得到一个没有概率语义的数分别标定后再合成 —— 第 6 节的主题

一个高频误解：「两级 = R-CNN 那种 two-stage 检测器」。不是。Faster R-CNN 的两阶段（RPN → RoI head）在同一个网络、同一次训练、共享 backbone 里，梯度是打通的；这里说的两级是两个独立训练、独立部署的模型，中间隔着一次真实的图像裁剪。面试里如果你把这两个概念混着说，对方会立刻判断你没真的做过量产系统。

3核心公式：级联召回 = 检测召回 × 分类准确率

这一节是整个模块的心脏。所有关于「两级到底行不行」的争论，最后都会归约到一个乘法。

\[R_{\text{end2end}} \;=\; R_{\text{det}} \times A_{\text{cls}}\]

其中 R_det 是检测阶段的召回（有多少真实标志被框到，且 IoU 达标），A_cls 是分类阶段在这些被框到的 crop 上的准确率。注意这是条件准确率：分子分母都只统计检测已经框到的样本。更一般地，如果每一级的通过率是 p_i，那么

\[R_{\text{cascade}} \;=\; \prod_{i=1}^{K} p_i \qquad\Longrightarrow\qquad \log R_{\text{cascade}} \;=\; \sum_{i=1}^{K} \log p_i\]

取对数之后，级联的性质变得一目了然：各级的损失在对数域上是相加的，且没有任何一级能补偿另一级的损失。这直接推出三条反直觉但极其实用的结论。

结论数值示例工程含义
① 90% × 90% = 81%，不是 90%检测召回 0.90、分类准确率 0.90 → 端到端 0.81。两个「看起来还行」的模块合起来是「不能用」永远不要用分级指标去汇报系统性能。汇报必须是端到端的
② 边际收益取决于另一级R_det 0.90→0.95（+5.6%），若 A_cls=0.99 则端到端 +5.5%；若 A_cls=0.70 则端到端只 +3.5%∂R/∂p_i = R/p_i —— 改进哪一级收益大，要看当前 R 和该级的 p。短板优先，但短板的定义是「1-p 最大」而不是「p 最小的绝对值」
③ 级数越多越危险5 级各 0.98 → 0.98⁵ = 0.904。每加一级，就多一次乘法这是「不要为了工程优雅而多分几级」的定量理由。TSR 两级已经是甜点，三级（检测→粗类→细类）要有很强的理由

直白说

第 ② 条值得展开，因为它决定你下个季度做什么。假设当前 R_det = 0.92、A_cls = 0.94，端到端 0.865。现在你有两个候选项目：把检测召回提到 0.95（+0.03），或把分类准确率提到 0.97（+0.03）。两者对端到端的贡献恰好相等吗？算一下：0.95×0.94 = 0.893（+0.028）；0.92×0.97 = 0.892（+0.027）。几乎相等——因为端到端增量 ≈ Δp_i × (其余各级的乘积)，而两级情况下「其余各级的乘积」就是另一级的 p，两者接近时贡献自然接近。

严谨说

但真实决策还要乘上成本与天花板。检测召回的提升往往需要更高分辨率或更大模型（吃算力、影响延迟），而分类准确率的提升常常只需要补数据、改采样、加增强（几乎不增加线上开销）。所以在算力受限的车端，同等收益下优先改分类。另一方面，Bayes error（贝叶斯误差）在两级上不同：远距离 12×12 的牌，信息论上就分不出限速 60 还是 80，A_cls 有硬天花板；而 R_det 的天花板通常更高（「有个牌」比「是哪个牌」容易得多）。把「当前值、成本、天花板」三个量放在一起排序，才是完整的答案。

端到端多类检测器是不是就没有这个乘法？

这是最容易被绕进去的地方。端到端检测器并没有消除这个乘法，只是把它藏进了同一次前向里。一个多类检测器输出的分数本身就是 p(objectness) · p(class | object) 的某种耦合形式（YOLO 系甚至显式地把 objectness 与 class 分数相乘）。区别在于：

  • 端到端里两项共享特征、联合优化，所以理论上可以学到一个比分解更优的联合解；
  • 但代价是两项的梯度互相干扰——分类头的长尾梯度会污染定位特征；而且你无法单独测量「定位错了多少、分类错了多少」，除非另做误差分解（这正是 C61 模块 02 的 TIDE 分析要干的事）。
级联指标的谎言

一个会在生产中真实发生的事故：团队 A 报「检测召回 96%」，团队 B 报「分类准确率 97%」，PM 记下「系统性能 96%+」。上线后路测发现每 10 块牌漏 1 块——因为真实端到端是 0.96×0.97 = 0.931，而且这还没算 B 的 97% 是在干净的 GT crop 上测的，而线上分类器吃的是检测器给的、带偏移带截断的 crop，真实条件准确率只有 0.92 → 端到端 0.883。

两条铁律：① 分类器必须在「检测器输出的 crop」上评测，不是在 GT crop 上；② 对外汇报只能报端到端。这两条几乎是面试里检验「有没有做过真系统」的试金石。

4端到端多类检测的适用边界：什么时候两级是过度设计

两级不是免费的。上一节的四个代价里，「工程复杂度」在小团队里往往是决定性的——两套数据、两套评测、两条流水线，意味着你的迭代速度会慢一半。所以必须知道端到端方案什么时候更好。

判据端到端更合适两级更合适TSR 落在哪一侧
类别数≤ 30，且每类样本 ≥ 1000≥ 100，长尾跨度 ≥ 3 个数量级两级（GB 5768 细类 200+，TT100K 里 45 类样本 < 100）
新类频率类别表基本冻结每季度都可能加类 / 加区域两级（进新省份、新国标、临时牌）
目标尺寸目标占图 > 5%，细节充分目标 < 32 px，细节要靠放大两级（60 m 外的 60 cm 牌 ≈ 16 px）
类间几何差异各类外形差异大，需分别回归各类外形高度同构（都是牌）两级（圆/三角/矩形，3–5 个粗类足够）
延迟预算极紧（< 5 ms 总预算）有 2–3 ms 余量给第二级看平台。Orin 级算力 → 两级可行
团队规模1–2 人，要快速出活有独立的检测组与分类组量产团队 → 两级

直白说

最诚实的说法是：如果你只做「限速牌 + 停车让行 + 禁止通行」这十几类，端到端检测器又快又准，两级纯属自找麻烦。TSR 之所以几乎必然走两级，是因为真实产品要覆盖的类别数从来不是十几类——一个能上量产的 TSR 至少要认 100+ 类，且必须支持「进入新市场时快速加类」。先问清楚「到底要认多少类、加类频率多高」，再决定架构，这是系统设计题的正确开场。

严谨说

还有一条中间路线值得知道：共享 backbone 的多头方案——检测头与分类头共用主干特征，分类头通过 RoIAlign 从特征图上取 ROI 特征而不是从原图裁剪。它保留了「分类可独立重训（冻结主干只训分类头）」的部分好处，又省掉了第二次特征提取的算力。代价是：分类器再也拿不到比主干 stride 更精细的信息——而这恰恰是 TSR 最需要的（12 px 的牌在 stride-8 特征图上只有 1.5 个格子）。所以在小目标主导的 TSR 里，「从原图重新裁剪并上采样」这个看似浪费的做法，是有信息论理由的。

算一笔真实的算力账

假设输入 1920×1080，检测器在 1280×736 上跑（letterbox 后），分类器输入 64×64，单帧平均 12 个候选 crop：

检测阶段:  1280 × 736  = 942,080 px            → 设为 1.00 单位算力
分类阶段:  64 × 64 × 12 = 49,152 px  ≈ 0.052 单位 (按像素数线性估)
           实际因分类网络更浅更窄, 通常 ≈ 0.03–0.08 单位

结论: 第二级的算力开销约为检测的 3%–8%,  却换来:
      · 200+ 类的细粒度识别能力
      · 长尾类可任意重采样
      · 加类不动检测器
  ⇒ 这个交换在几乎所有量产 TSR 里都是划算的

把上面的账反过来读更有启发：之所以两级在 TSR 里划算，根本原因是「标志很小」。目标越小，crop 的总面积相对整图越小，第二级越便宜；同时目标越小，检测器在下采样特征图上能分给它的计算越少，第二级的增益越大。「小目标 + 长尾 + 频繁加类」这三件事同时成立时，两级几乎是唯一合理选择——而 TSR 正好三条全中。

5接口设计：crop 策略是两级方案里最被低估的一环

两级方案的接口就是那个 crop。接口设计错了，前面所有的解耦优势都会变成「两个模块互相甩锅」。crop 有三个必须定死并写进契约的参数：padding 比例、对齐方式、输出分辨率。

① padding 比例：为什么不能是 0

直觉上，检测框就是牌的边界，直接裁就好。但这在实践中会出两个问题：

  • 检测框本身有误差。小目标上这个误差是致命的：一个 16×16 的牌，检测框位移 2 px，IoU 从 1.0 掉到约 0.60；若直接按框裁剪，牌的边缘（红圈、外框——恰恰是最有判别力的部分）会被切掉。
  • 上下文有信息。牌的杆件、背板、周围是天空还是树，都是判别「这是真牌还是广告牌」的线索。padding 把这些一起带进来。
padding 比例效果适用
0%边缘常被切；对检测框误差极不鲁棒只有当检测框极准（大目标）时
10%–20%常用甜点。覆盖典型框误差，保留完整牌面 + 一圈背景绝大多数 TSR 系统
30%–50%上下文丰富，对误检判别（广告牌）帮助大；但小牌在 crop 里占比下降背景误检是主要痛点时
按框尺寸自适应小框给更大比例 padding（因为小框的相对误差更大）更优：pad = max(0.15, 3px / min(w,h))

② 对齐：正方形化与长宽比

标志的原始长宽比多样（圆牌 1:1、指路牌 3:1、附加牌 2:1）。分类器需要固定输入尺寸，处理长宽比有三种做法，而它们对精度的影响远大于直觉：

做法做什么问题
直接 resize 到方形拉伸长宽比信息被销毁 —— 而形状本身是 TSR 的一级语义（圆=禁令、三角=警告）。这是一个真实的、常见的、代价很大的错误
扩成方形再裁取 max(w,h) 为边长，以框中心扩成正方形后裁剪会带入更多背景，但保长宽比。多数系统的选择
letterbox 填充保比例缩放 + 灰边填充保比例且不引入真实背景；但填充区域是无信息的死像素，浪费算力

③ 输出分辨率：上采样有意义吗

一个 16×16 的 crop 上采样到 64×64，并没有增加任何信息——这是显然的。但它仍然有意义，原因有三个，面试里能把这三条说清楚就已经超过大多数候选人：

  1. 计算量分配。CNN 分给一个输入的计算量正比于输入面积。16×16 输入在一个 stride-32 的网络里连一个格子都不到；上采样到 64×64 后，网络有足够的层数与空间维度去提取特征。信息没增加，但「能用来处理这些信息的计算」增加了 16 倍。
  2. 批处理统一。所有 crop 归一到同一尺寸才能 batch 化前向——这是延迟能压下来的前提。
  3. 与训练分布对齐。分类器在固定尺寸上训练，推理必须同尺寸。而这引出一个真实的坑：训练时如果用 GT 框裁剪并 resize，推理时用检测框，两者的「牌在 crop 中的占比分布」不同 → 训练-推理分布漂移。
训练用 GT crop、推理用检测 crop = 隐形的域差

接上面第 3 条：分类器的训练数据必须用「模拟检测器输出的框」来裁剪，而不是 GT 框。具体做法是给 GT 框加上与检测器误差分布一致的扰动（中心偏移 + 尺度抖动），再裁剪。

不这么做的后果是可测量的：某些系统上，在 GT crop 上 97% 准确率的分类器，换成检测框 crop 后掉到 91%——6 个点凭空消失，而离线评测完全看不出来。这是「离线指标好、路测差」最常见的成因之一，也是本模块 notebook 要你亲手复现的实验。

直白说

把这一节浓缩：crop 是两级方案的 API，而 API 一旦定下来，两边的模型都是围绕它训练的。改 padding 比例 = 破坏性变更，两个模型都要重训重验。所以这几个参数应该在项目早期就定死、写进配置、纳入版本管理——像对待接口契约一样对待它。

严谨说

更严谨地说，crop 策略定义了第二级看到的条件分布 p(crop | box, image)。两级分解的正确性依赖训练与推理时这个分布一致。任何改变这个分布的东西——padding、对齐、插值方式（bilinear vs bicubic）、是否做 letterbox、填充值——都是分布漂移的来源。与 C60 讲的「训练-部署一致性」是同一个问题的不同外衣：预处理必须逐位对齐。

6置信度合成与标定：两个分数怎么变成一个可信的概率

两级系统输出两个分数：检测分数 s_det（这里有个牌吗）与分类分数 s_cls（是哪个牌）。下游（跟踪、决策、VLA）需要一个数，而且需要它是真的概率——「0.9」应该意味着「这样的 100 次里约 90 次是对的」。

合成：为什么是乘法

\[p(\text{class}=c \,\wedge\, \text{object} \mid \text{image}) = \underbrace{p(\text{object} \mid \text{image})}_{s_{det}} \cdot \underbrace{p(c \mid \text{object}, \text{crop})}_{s_{cls}}\]

乘法来自链式法则，前提是 s_det 与 s_cls 都是标定过的概率。这个前提在实践中几乎从不满足：

分数实际语义典型偏差
检测分数经过 focal loss / 正负样本极度不均衡训练出的分数系统性偏低（focal loss 压低了所有分数），且与 IoU 相关性弱 —— 高分不代表框准
分类分数softmax 输出系统性过度自信（现代深网络的典型症状），尤其在长尾尾部类上
乘积两个未标定分数的乘积没有任何概率语义；偏差方向甚至可能互相抵消，制造「看起来还行」的假象

标定：ECE 与可靠性图

calibration（标定）要回答的问题是：把所有预测按置信度分桶，每个桶里「平均置信度」与「实际准确率」是否相等。差距的加权平均就是 ECE（Expected Calibration Error，期望标定误差）：

\[\mathrm{ECE} \;=\; \sum_{m=1}^{M} \frac{|B_m|}{n} \bigl| \mathrm{acc}(B_m) - \mathrm{conf}(B_m) \bigr|\]

其中 B_m 是第 m 个置信度区间里的样本集合，acc 是该桶实际准确率，conf 是该桶平均预测置信度。把 (conf, acc) 画出来就是reliability diagram（可靠性图）：完美标定的模型落在对角线上；过度自信的模型落在对角线下方。

标定方法做法参数量适用
Temperature scalinglogits 除以一个标量 T 后再 softmax，在验证集上最小化 NLL 求 T1 个首选。单参数、不改变 argmax（即不影响准确率）、效果好得出奇
Vector / Matrix scaling每类一个缩放/完整线性变换K / K²类间偏差差异大时；有过拟合风险
Histogram binning分桶后用桶内经验准确率替换置信度M 个非参数，样本足够时稳；但输出离散
Isotonic regression拟合单调映射非参比 histogram 平滑；小样本易过拟合

直白说

Temperature scaling 有一个性质在工程上特别重要：它不改变预测的排序，因此不改变准确率、不改变 mAP，只改变置信度的数值。这意味着你可以在模型冻结、评测通过之后，作为一个纯后处理步骤加上去——不需要重训、不需要重跑检测评测、风险极低。它几乎是「白拿」的改进，而很多团队从来没做过。

严谨说

但有两个陷阱。① 标定是在特定分布上做的：用晴天数据标出来的 T，在夜间/雨天分布上依然过度自信。严谨做法是分场景标定（按天气/光照/距离分桶各标一个 T），或至少在标定集里保证场景配比与线上一致。② 检测分数的标定要按 IoU 定义「正确」：一个 score 0.9 的框如果 IoU 只有 0.4，它算对还是错？定义变了，标定结果就变了。TSR 里更该关心的是「这个框对应一块真牌」而非「IoU ≥ 0.5」，所以标定的正确性判据应该按下游需求定，而不是照抄 COCO。

常见错误：在训练集上做标定。训练集上模型近乎完美，标出来的 T 接近 1，等于没做。标定必须用独立的、未参与训练的验证集，而且这个集合要足够大（每个置信度桶至少几十个样本，否则 ECE 估计本身噪声极大）。另一个错误是只报一个 ECE 数字——ECE 会把「低置信度区过度保守」与「高置信度区过度自信」互相抵消。必须看可靠性图，尤其是高置信度区间那几个桶，因为下游只会用高置信度的检测。

7拒识与未知类：softmax 一定会给你一个答案，哪怕输入是垃圾

两级方案有一个结构性风险：分类器的 softmax 在任何输入上都会输出一个和为 1 的分布。检测器误检了一块广告牌，分类器不会说「这不是标志」，它会说「这是限速 40，置信度 0.87」。这不是 bug，是 softmax 的定义决定的。

输入 crop │ ┌─────────┴─────────┐ │ │ 真标志 广告牌 / 车身贴纸 / 树叶缝隙 │ │ ▼ ▼ softmax over 200 类 softmax over 200 类 │ │ ▼ ▼ 「限速60, 0.95」 「限速40, 0.87」 ← 一样自信！ ▲ └─ 闭集分类器的根本缺陷: 它只会回答「200 类里最像哪个」 从不回答「是不是这 200 类之一」
拒识方案机制优点代价 / 坑
① 加 background 类训练时把检测器的误检（hard negative）作为第 201 类最简单、最有效；直接复用现有训练框架background 类的样本必须来自真实检测器的误检，随机负样本没用；且检测器一改，负样本分布就变了
② 阈值 + margin要求 top1 > τ 且 top1 − top2 > δ零成本，可在线调过度自信的模型上 top1 阈值几乎不起作用 —— 必须先标定
③ 能量 / logit 范数用 -T·logsumexp(logits/T) 作为 OOD 分数（能量越低越像已知类）不需重训，比 max-softmax 更能分开 OOD阈值仍需在 OOD 验证集上定；对分布偏移敏感
④ 开集识别 / 原型距离在特征空间量测到各类原型的距离，太远则拒识有几何解释，可增量加类特征空间的度量需要专门训练（metric learning）；实现复杂度高

直白说

在 TSR 里，方案 ① 几乎总是第一步，而且它的效果取决于负样本的来源。正确做法是：用当前版本的检测器在大量无标注路测视频上跑一遍，把所有「检测器给了高分但不在 GT 里」的 crop 收集起来，人工快速筛掉真漏标的，剩下的就是最有价值的 background 训练样本。这就是 C58 讲的难例挖掘在两级系统里的具体形态。

严谨说

更深一层的问题是：拒识阈值应该按「代价」而不是按「准确率」来定。漏检一块「停车让行」与误报一块「景点指示」的代价差好几个数量级。所以正确的做法是给每个类别定义误报代价 c_FP(k) 与漏检代价 c_FN(k)，然后最小化期望代价：当 p(c) · c_FN(c) > (1-p(c)) · c_FP(c) 时上报，否则拒识——这就是逐类别的最优决策阈值 τ_c = c_FP / (c_FP + c_FN)。这也是为什么第 6 节的标定是必须的：只有标定过的 p 才能代进这个不等式。模块 05 会把它扩展成完整的代价敏感评测。

把拒识放进级联公式里看会更清楚：拒识降低 A_cls 的分子（有些对的也被拒了），但同时降低误报率。所以它不是「白拿的改进」，而是一个可调的工作点。本质上你是在用召回换精度，而换的比例由阈值控制。系统设计题里被问「怎么处理未知标志」，正确的答案结构是：先说 softmax 的闭集缺陷 → 再给两三个方案 → 最后说阈值该按代价定而不是按准确率定。

8量产落地：在算力与组织约束下会怎么选

到这里技术选项已经讲完了。真实的架构决策还要过三关：算力预算、迭代组织、可验证性。这一节把它们串起来，给出一个可以直接在系统设计面试里复述的推理链。

推理链（可直接背）

  1. 先确定输出契约：下游要的是「本车道、多少米外、什么标志、置信度多少、稳定了几帧」。这决定了必须有 [4] 关联环节，也决定了必须传置信度。
  2. 再确定类别规模与加类频率：200+ 类、每季度加类 → 检测与分类必须解耦。这一条就基本判定了两级。
  3. 再确定尺寸分布：要在 60–80 m 检出 → 目标 12–20 px → 检测器需要高分辨率输入 + 浅层特征（P2），分类器需要独立的高分辨率 crop。
  4. 再算延迟：33 ms 一帧里，TSR 大概只分到 8–12 ms（还有 BEV、动态目标、车道线在抢）。检测 6–8 ms + 分类 1–2 ms（batch 化 top-k crop）+ 后处理 1 ms。关键是给 crop 数设硬上限（如 16），否则复杂路口延迟会爆。
  5. 再定置信度与拒识：分别标定 → 乘法合成 → 逐类代价阈值 → 拒识。
  6. 最后接时序：单帧输出进跟踪器做多帧确认（模块 04），下游拿到的永远是时序稳定后的结果，不是单帧结果。
约束对架构的具体影响常见的妥协
算力（Orin / 自研 NPU）检测器输入分辨率与 backbone 宽度是最大开销；第二级几乎免费牺牲检测输入分辨率 → 直接损失远距召回。宁可砍 backbone 也别砍分辨率（小目标场景的通用结论）
延迟 p99 而非均值crop 数随场景波动（空旷路段 2 个，复杂路口 30 个）→ 第二级延迟方差大固定 batch 大小（padding 到 16），用确定的延迟换掉方差 —— 车端偏好确定性
存储与带宽两个模型两份权重；难例回传要带 cropcrop 很小（64×64），回传成本低 —— 这反而是两级的一个隐性优势
组织检测组与分类组可并行；但接口变更要跨组同步把 crop 契约冻结成配置文件 + 版本号，变更走评审
可验证性端到端失败要能定位到是哪一级日志必须同时记录 s_det、s_cls、crop 坐标，否则线上 badcase 无法归因

最后一行值得单独强调，因为它是把「两级」的好处兑现的关键：如果日志里只有最终结果，那么「这个漏检是检测没框到，还是分类判成 background 了」就永远说不清，两级的可调试性优势直接归零。

正确做法：每一帧的每个候选都记录 (box, s_det, top3 类别与分数, 是否被拒识, 拒识原因)。这份日志的体积很小（每帧几百字节），却是整个数据闭环的地基 —— 模块 05 的分桶评测、C58 的难例触发，全都建立在它上面。「先设计日志，再设计模型」在量产感知里不是玩笑。

直白说

如果面试官追问「小鹏这种量产系统会怎么做」，一个稳妥且真实的回答是：类别无关或粗类检测器（3–5 个粗类：圆形禁令 / 三角警告 / 矩形指示 / 电子屏 / 附加牌）+ 一个小分类器 + 强时序确认，检测阶段阈值放得很低（宁滥勿缺），把精度责任交给分类器的 background 类与时序确认。因为漏检一旦发生就是永久损失，而误检可以被后面两道关卡过滤掉。

严谨说

背后的原理是级联系统的阈值应该「前松后紧」：早期阶段的漏检不可恢复（乘法里的 0 吞掉一切），而早期阶段的误检可以被后续阶段以更低的代价滤除（因为后续阶段看到的是放大后的高分辨率 crop，判别力更强）。这与经典的 Viola-Jones 级联分类器是同一个设计原则——每一级都追求极高召回、只做温和的精度提升，把难判的样本留给后面算力更贵的阶段。这个「前松后紧」的原则可以迁移到任何级联系统，值得记死。

9研究前沿与开放问题

两级 vs 端到端并没有被「解决」，只是在当前的算力与数据条件下有一个工程上的最优解。下面几个方向正在改变这个平衡点。

  • 开放词汇检测（open-vocabulary detection）冲击「加类」这个动机。GLIP / Grounding DINO / OWL-ViT 这类模型用文本描述作为类别定义，理论上「加一个新标志」只需要加一句文本描述，不需要任何训练。如果这条路成熟，两级方案的动机 ② 就消失了。目前的现实是：这些模型在小目标与细粒度区分（限速 60 vs 80）上还远不够，且推理开销大；但作为数据挖掘工具（在无标注视频里找出「黄色菱形警告牌」）已经非常实用。
  • 端到端可微的级联。把 crop 操作写成可微的 RoIAlign / STN（spatial transformer），让分类损失的梯度回传到检测器 —— 理论上能得到「解耦的结构 + 联合的优化」。难点是：可微 crop 只能从特征图取，而 TSR 需要的是原图分辨率的 crop，两者矛盾。
  • 置信度标定的分布偏移问题。现有标定方法都假设标定集与测试集同分布，而自动驾驶恰恰是分布持续偏移的场景（新城市、新季节、新天气）。「在线自适应标定」（用时序一致性作为无监督信号来重标定）是一个活跃且尚未有定论的方向。
  • 不确定性的分解。aleatoric（数据固有的，如 12 px 的牌本来就分不清）与 epistemic（模型没见过，如新型电子屏）不确定性对下游的含义完全不同：前者应该等更近再判，后者应该触发数据回传。把它们分开估计并分别驱动不同的下游动作，目前还是研究问题。
  • 与 VLA 的接口。如果下游是一个 VLA 模型（C59），它到底需要「结构化的 TSR 结果」还是「原始特征」？结构化输出可解释、省 token，但有信息损失；特征级注入信息全但不可调试。这个取舍目前没有定论，且直接决定 TSR 模块的输出契约该怎么设计。
  • 级联系统的联合评测理论。多级系统的置信区间、显著性检验该怎么做（各级误差不独立）；如何在固定标注预算下分配「标检测数据」与「标分类数据」的比例 —— 后者是一个实际的、几乎每个团队都在拍脑袋决定的问题。

必读：Viola & Jones, Rapid Object Detection using a Boosted Cascade of Simple Features（2001，级联「前松后紧」原则的源头，读第 4 节的级联训练即可）；Guo et al., On Calibration of Modern Neural Networks（ICML 2017，temperature scaling 与 ECE 的原始论文，必读，短且实用）；Hendrycks & Gimpel, A Baseline for Detecting Misclassified and Out-of-Distribution Examples（ICLR 2017，max-softmax 基线）与 Liu et al., Energy-based Out-of-distribution Detection（NeurIPS 2020）；Zhu et al., Traffic-Sign Detection and Classification in the Wild（CVPR 2016，TT100K 数据集与两级基线，TSR 必读）；Liu et al., Grounding DINO（开放词汇检测的当前代表）。相邻课程：C57（小目标）、C58（长尾与难例挖掘）、C60（训练-部署一致性）、C61（误差分解）。完整清单见 references.md。
