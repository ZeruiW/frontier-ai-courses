课程总览与环境

TSR 在自驾软件栈里的位置；与通用检测的五个本质不同（极小目标 / 区域相关的长尾 / 语义直连安全动作 / 时序可用且必须用 / 误检代价高度不对称）；任务定义不止「画框 + 分类」；用针孔模型把「60 米外的限速牌是几个像素」变成一道能算的算术题——这个数字决定了后面所有技术选型。

MODULE 02

TSR 系统设计：两级 vs 端到端

两级级联的四个动机与三项代价；级联召回是个乘法——两级各自都「不错」，合起来能掉近 9 个点；crop 扩边必须按比例而非固定像素；两级置信度不先标定，乘出来的分数没有概率意义；拒识让「不确定」成为一个安全的输出，而「自信地错」才是危险的；量产算力约束下的真实取舍。

MODULE 03

失效模式全景：TSR 到底在哪些地方出错

四象限框架让「该修哪个」从争论变成可排序的表。逐一深挖：远距离小目标、遮挡、逆光与隧道出入口（局部过曝与欠曝同时发生）、夜间眩光、雨雾雪的对比度衰减、运动模糊与卷帘快门、褪色涂鸦、广告牌与车身贴纸的高分误检、对向车道与辅路的错误关联（这一类检测再准也解决不了）。优先级 = 发生频率 × 安全后果 × 修复成本——只按频率排，低频高危永远排不上去。

MODULE 04

时序与多帧融合：从单帧检测到稳定输出

TSR 是一个「接近过程」：远处信息弱但恰恰需要早决策。标志静止 + 自车位姿已知 → 下一帧位置可预测，这是 TSR 相对行人跟踪的巨大优势，也让 SORT 这种极简方案在这里几乎完美成立。ByteTrack 的低分二次关联对远处小标志收益极大；贝叶斯 log-odds 累积与 K-of-N 投票的响应延迟不同；迟滞双阈值消灭闪烁；「越稳越晚」这个矛盾必须被量化成一条曲线，而不是靠拍脑袋调参数。

MODULE 05

安全导向的评测体系

mAP 不足以衡量 TSR 的五个理由；分桶评测让「整体 +0.3 其实是雨天 +3、晴天 -1」这种真相浮出水面；代价矩阵是把安全写进指标的唯一方式；FP/km 是绝对量，能直接换算成「用户每天遇到几次」；首检距离决定下游有多少时间决策，闪烁率是体感的直接代理；每个失效模式配一个回归切片，让修好的问题不会再回来；最后回答那个所有人都遇到过的问题——离线指标涨了，为什么路测没感觉。
