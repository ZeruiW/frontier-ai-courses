1这门课讲什么：TSR 不是「检测 + 分类」的简单组合

TSR（Traffic Sign Recognition，交通标志识别）在教科书里通常只占半页纸：「用检测器找出标志框，再用一个分类器判断是哪一类」。这个描述没有错，但它省略了这门课全部的内容——因为它没有回答任何一个真正决定成败的问题。

先看一组把问题说清楚的数字。一块中国城区常见的圆形禁令标志直径 60 cm；一台 1920×1080、水平视场角 60° 的前视相机，等效焦距约 1663 像素。那么这块标志在图像里有多大？

距离标志边长（像素）标志面积（像素²）占全图面积在 COCO 定义下
20 m50 px24880.12%small 的上界附近
30 m33 px11060.053%刚好越过 32² 门槛
60 m17 px2760.013%典型 small
100 m10 px1000.005%接近可检测下界
146 m6.8 px470.002%物理上无法可靠分类

再看一组安全侧的数字。车速 100 km/h，要把速度降到 60 km/h，取舒适减速度 2 m/s²、感知确认+决策+执行的总反应时间 0.8 s，需要的距离是 146 米。

直白说

把这两组数字放在一起，这门课的全部张力就出来了：安全需求要求你在 146 米外就认出限速牌，而物理光学告诉你那时它只有 6.8 个像素。6.8 个像素里塞不下「60」和「80」的区别——这不是模型不够强，是信息不存在。所以量产 TSR 系统必然不是「一个更好的检测器」，而是多相机 + 时序累积 + 地图先验的组合。

严谨说

严谨地说，这是一个信息可用性（information availability）约束而非模型容量约束。给定针孔相机模型 px = f·S/Z，在焦距 f、物理尺寸 S 固定时，可用像素数随距离平方衰减（面积意义上）。任何单帧算法的性能上界都被这个物理量锁死。识别出「这是信息问题不是模型问题」，并据此把工程投入从「换更大 backbone」转向「换相机配置 / 加时序 / 用地图」，是 TSR 工程师与通用检测工程师最显著的能力差别。

学完这门课你应当能当场回答：TSR 与通用目标检测有哪五个本质不同？两级方案（类别无关检测 + crop 分类）与端到端多类检测各自的动机与代价是什么？级联召回为什么是乘法？为什么 mAP 不足以衡量 TSR，该换成什么？多帧融合的响应延迟与稳定性怎么量化权衡？对向车道的标志为什么必须在感知之外被丢掉？ 这些问题在 XPENG「TSR 2D Detection」这类岗位的面试里几乎必然出现。

2TSR 在自动驾驶软件栈里的位置

面试里一个高频的开放题是「讲讲 TSR 系统怎么设计」。面试官想听的第一件事不是模型，而是你知不知道 TSR 的输入从哪来、输出到哪去——因为这决定了你会不会把「检测框」当成终点。下面这张图是本课的坐标系，后面每个模块都会回到它。

直白说

这张图里有两条经常被忽略的边。第一条是「感知层 → 融合层」：TSR 的单帧输出不是产品，稳定的标志实例才是。单帧检测抖一下没关系，但仪表上的限速数字闪一下用户立刻能看见。所以 TSR 的最终指标必须定义在时序输出上，而不是逐帧 mAP 上——这是模块 04 与 05 的主题。

严谨说

第二条是「融合层 → 地图/定位层」：一个标志「在图像里存在」与「对自车生效」是两件完全不同的事。对向车道的限速牌、辅路的禁令牌、匝道的指示牌都会合法地出现在前视图像里，而它们全都不应该改变自车的行为。把这个判断放在感知层做（比如训练模型只检测「属于自车车道的标志」）是错误的设计——因为它需要车道拓扑与路径规划信息，那些信息在感知层根本不存在。正确做法是感知层如实输出所有标志 + 几何属性，由下游做关联。面试里主动讲出这一点，会立刻区分你和「只跑过检测器」的候选人。

另一个常见误解：把红绿灯识别（TLR）和交通标志识别（TSR）当成同一个任务。它们的相似之处只有「都是小目标、都在路边」；本质差别很大：红绿灯是动态状态（颜色随时间变化，时序上不能做「多帧投票取众数」，必须做状态跳变检测），交通标志是静态语义（除可变电子牌外，多帧信息可以放心累积）。这直接导致两者的时序融合策略完全不同。把两者混为一谈会在面试里立刻暴露。

3TSR 与通用目标检测的五个本质不同

这是本课最需要背下来的一个框架，也是面试开场最常被问到的题。用五个字记：小 · 偏 · 硬 · 连 · 歪——目标小、分布偏、语义硬、时序连、代价歪。

#维度通用检测（COCO/BDD）TSR由此导出的工程后果
①小：目标尺度目标中位边长 50–100 px，small 只占一部分16–30 px 是常态而非极端；60 m 外仅 17 px必须动 stride/P2 层/输入分辨率/切片；IoU 阈值对小框极不公平；标注误差相对量级大
②偏：类别分布80 类，最长尾/最短头相差 100× 量级200+ 细类，头尾相差 10³–10⁴ 倍，且尾巴随地域改变长尾方法是必需品不是加分项；类别体系必须分层；跨区域部署要换尾巴
③硬：语义→动作输出是「有一只猫」，下游是统计消费输出直接变成控制约束：限速 60 → 速度上限 60错分「60/80」不是掉 1 点 AP，是让车开错速度；细类错分的代价 ≫ 定位不准
④连：时序可用性目标自身在动，未来位置不可预测标志是静止刚体 + 自车运动已知 → 位置可精确预测时序是最便宜的精度来源；不用时序等于白扔一半信息；跟踪难度远低于行人跟踪
⑤歪：代价不对称FP 与 FN 大致对称，用 mAP 平均即可双重不对称：FN vs FP 不对称，且按类别再次不对称指标要代价加权；工作点按 FP/km 定；mAP 会掩盖关键类的失效

① 小：为什么「16 px 是常态」这句话很重

模块 05 会给完整推导，这里先给结论的量纲。8×8 的框在 x、y 各偏移 2 px，IoU 从 1.0 掉到 36/92 ≈ 0.391；同样偏移 2 px，64×64 的框 IoU 还有 0.884。

\[\mathrm{IoU}(s,\delta)=\frac{(s-\delta)^2}{2s^2-(s-\delta)^2}\quad\Longrightarrow\quad \mathrm{IoU}(8,2)=0.391,\ \ \mathrm{IoU}(64,2)=0.884\]

这意味着 IoU=0.5 这个阈值对 8 px 的目标要求「亚 2 像素」的定位精度，而对 64 px 的目标只要求「10 像素以内」。同一个阈值，两个数量级的严苛度差异。所以小目标的正样本稀缺不是「模型学不好」，是「分配规则本身把它们判死了」——这条线索会一直贯穿到模块 03 与 C57。

② 偏：长尾还是「会搬家」的长尾

通用检测的长尾是固定的：COCO 里 person 永远比 toaster 多。TSR 的长尾是区域相关的——「注意牲畜」在西部国道是常见类，在上海内环一年遇不到一次；「潮汐车道」在部分城市是高频类，在别处根本不存在。这意味着「在采集数据上是尾部类」不等于「在部署区域是尾部类」，而按训练集频率做的重加权在新区域会系统性偏错。

③ 硬：语义直接变成安全动作

错分不是掉分，是错误的控制动作

把「限速 80」错分成「限速 60」在 mAP 上是一个类别的一次错误，在车上是无缘无故的减速；反过来把「限速 60」错分成「限速 80」是超速。而在通用检测里，把 cat 分成 dog 只是掉分。这条差异导出了一个直接的工程要求：混淆矩阵比 mAP 重要——你必须知道哪几对类别互相错分、每一对的下游后果是什么，然后针对性地加数据或加代价权重。面试里被问「你怎么衡量 TSR 效果」，只答 mAP 基本等于放弃这一轮。

④ 连：这是 TSR 相对于行人检测的巨大优势

车速 100 km/h、相机 30 FPS，一块标志从 100 m 接近到 30 m 的过程中，你有 75 帧观测它。而且因为标志静止、自车运动已知（轮速+IMU+定位），下一帧它会出现在哪里是可以解析预测的——不需要卡尔曼滤波去猜运动模型。「TSR 的跟踪本质上是自车运动补偿而非目标运动建模」，这句话在面试里很有杀伤力。模块 04 会把它做成代码。

⑤ 歪：双重不对称

漏检一块「停车让行」可能导致路口冲突；漏检一块「景点指示」用户根本不会察觉。而误检的代价同样不对称：把广告牌误检成限速 30 会触发幽灵刹车（phantom braking），这是用户投诉的头号来源，而漏掉一块限速解除牌只是让车多开慢一会儿。因此 TSR 的评测必须是代价敏感的，工作点必须按「每公里误报次数」（FP/km）而不是 precision 来定——这是模块 05 的核心。

直白说

把五点浓缩成一句可迁移的判断：TSR 是一个「信息严重不足、分布严重偏斜、错误代价严重不对称」的检测任务，而它同时享有「目标静止、自车运动已知」这个通用检测拿不到的红利。好的 TSR 方案就是用第四点去补前三点——用时序累积换单帧信息不足，用时序一致性挖掘长尾，用时序稳定性压住误报。

严谨说

更严谨地说，前三点是问题难度（irreducible difficulty），第五点是损失函数的形状（asymmetric loss），第四点是额外的结构先验（structural prior）。三者是不同类型的东西，混在一起谈会导致「用错工具解错问题」：比如用更强的 backbone 去解第①点（信息不足）收益很小，用代价加权去解第②点（长尾）会牺牲整体精度，而用时序去解第①③⑤点则同时有效。能把「这个问题属于哪一类」说清楚，就是系统设计能力。

4TSR 的完整任务定义：四层输出

「TSR 的输出是什么」这个问题，一半的候选人会答「框 + 类别」。正确答案是四层，而且缺任何一层下游都没法用。

层输出内容为什么必须有缺了会怎样
L0 定位2D 框（xyxy）+ 检测置信度 + 所属相机 + 时间戳下游要做多相机融合与时序关联，必须知道「哪台相机的哪一帧」跨相机重复上报同一块标志；时序关联无法对齐
L1 粗类禁令 / 警告 / 指示 / 指路 / 辅助 / 施工 / 可变电子牌粗类由形状+颜色决定，样本充足、准确率高，可作为降级输出细类不确定时只能输出「无」，白白丢掉「这里有个禁令牌」这条强信息
L2 细类限速 / 禁止驶入 / 禁止左转 / 注意行人 / …决定下游施加哪一类约束无法翻译成控制约束
L3 属性限速值、生效时段、限定车型、箭头方向、距离数字、褪色/遮挡状态、是否面向自车、关联车道同一细类下的参数决定具体约束值；几何属性决定这块牌是否对自车生效「限速」但不知道限多少；对向车道的牌被错误施加到自车

直白说

L1 存在的唯一理由是「可降级」。远处一块牌只有 12 px，你能看出它是「白底红圈的圆形」（禁令）但看不出是禁止什么。此时输出 {L1: prohibitory, L2: unknown, conf: 0.7} 对下游非常有用——规控可以先保守一点、跟踪器可以先建实例、下一帧近了再补上 L2。而如果你的输出 schema 只有「类别」这一个字段，这条信息就只能被丢掉。

严谨说

L3 里的「是否面向自车」与「关联车道」是最容易被漏掉、也最容易在面试里加分的两项。感知层能提供的是几何证据：标志平面法向与自车朝向的夹角（背面/侧面会显著不同）、标志在图像中的横向位置与消失点的关系、以及（若有）标志的 3D 位置。感知层不做「这块牌是否对我生效」的最终判断，但必须把做这个判断所需的证据全部输出——这就是模块 02 讲的「接口设计原则：把判断留给有上下文的那一层，把证据留在产生它的那一层」。

置信度必须逐层输出，而不是只给一个总分。两级方案里最终置信度是「检测置信度 × 分类置信度」，但下游需要区分这两种情况：「我很确定这里有个牌，但不确定是什么」（det 0.95 × cls 0.4） 与 「我不太确定这里有牌，但如果有的话肯定是限速 60」（det 0.4 × cls 0.95）。两者乘积都是 0.38，但下游的正确反应完全不同（前者应该继续观察，后者应该等更多证据）。把两个置信度乘起来再输出，就把这个区别永久抹掉了。这是感知-决策接口最常见的设计错误之一。

5像素预算：用一个公式推出这门课的所有难点

本课所有的定量推理都从针孔相机模型出发。给定图像宽 W（像素）与水平视场角 HFOV，等效焦距（像素单位）是：

\[f_{px}=\frac{W/2}{\tan(\mathrm{HFOV}/2)},\qquad \text{标志成像边长}\ \ p=\frac{f_{px}\cdot S}{Z}\]

其中 S 是标志的物理尺寸（米），Z 是距离（米）。把真实参数代进去：

相机配置fpx60 cm 标志 @50 m@100 m@146 m评价
广角 120° · 1920×10805546.7 px3.3 px2.3 px完全不可用（它的任务是近场与路口）
主摄 60° · 1920×1080166320 px10 px6.8 px50 m 内可靠，100 m 勉强，146 m 无望
主摄 60° · 3840×2160332640 px20 px13.7 px分辨率翻倍 = 有效距离翻倍，代价是算力 4×
长焦 30° · 1920×1080358243 px21 px14.7 px远距离 TSR 的现实解，代价是视场窄

直白说

这张表回答了一个高频面试题：「要在 100 米外检出限速牌，你会怎么做？」。差的答案是「用更大的模型 / 加 FPN 的 P2 层」——那些都对，但都改变不了「10 个像素里没有 60 与 80 的区别」这个事实。好的答案是先算像素预算，再说「所以我需要一路长焦相机，或者 4K 主摄，或者接受在 100 m 只输出 L1 粗类、靠时序累积到 60 m 再确认 L2」。

严谨说

从公式还能反推一个非常实用的量：给定「必须在 Z 米外达到 p 像素」的需求，所需焦距是 f = pZ/S，对应的 HFOV = 2·arctan((W/2)/f)。代入 S=0.6 m、Z=100 m、p=20 px，得 f=3333 px、HFOV≈32°——这恰好就是量产车上「长焦相机 30° 左右」这个配置的来历。反过来，一台 60° 的主摄能在 50 m 处刚好达到 20 px（HFOV≈59.9°）。能把「相机选型」和「感知需求」用一个公式连起来，是这门课最值钱的一页。notebook 里你会把这个求解器写出来。

再叠加安全侧的约束。从 v₀ 减速到 v₁ 所需的距离（含反应时间 t_r、减速度 a）是：

\[D = v_0 t_r + \frac{v_0^2-v_1^2}{2a}\quad\xrightarrow{\ 100\to 60\,\mathrm{km/h},\ a=2,\ t_r=0.8\ }\quad D=22.2+123.5=145.7\ \mathrm{m}\]

把两个公式连起来就得到本课的中心矛盾：安全需要 146 m 的检出距离，而 146 m 处标志只有 7–15 px。这个矛盾无法在单帧、单相机内解决，所以量产 TSR 必然是一个「多相机 + 时序 + 地图」的系统工程问题，而不是一个模型问题。 记住这句话——它是本课后面五个模块存在的全部理由，也是面试里你应该主动抛出的第一个判断。

本课有一个必须坦白的约束：它讲的东西本质上需要真实车队数据与真实标志图像，而这些既不能下载也不能开源。所以 notebook 全部走「物理建模 + 合成数据」的路线：用真实的相机参数、真实的标志尺寸标准（GB 5768）、真实的车速与减速度、真实的长尾指数，去合成可计算的场景。合成的是像素，不是规律。

严谨说

这个约束其实指向了更好的学法。TSR 的困难几乎都不在「怎么写模型代码」，而在「怎么把物理约束、安全需求、数据分布、代价结构翻译成工程决策」——而这些全都是可以用几十行 numpy 精确复现的。你在 notebook 里算出的「146 m 处只有 6.8 px」，与在真车上量出来的是同一个数。讲解里则紧跟真实的数据集数字、真实的标注规范条款、可原样复制的配置——这些放在每个模块末尾的 🧪 胶囊里。

7研究前沿与开放问题

  • 端到端感知与显式 TSR 模块的竞争：以 UniAD / VAD 为代表的端到端架构主张「感知不必输出人类可读的中间结果」，而 TSR 恰恰是最需要显式中间结果的任务之一（限速值必须显示在仪表上、必须可审计、出事故要能追溯）。「哪些感知任务可以被端到端吸收、哪些必须保留显式接口」目前没有定论，而可解释性与法规要求正在把天平推向后者。
  • VLM/VLA 做长尾标志理解：用视觉-语言模型直接读懂「前方 500 米施工，货车禁行，8:00–18:00」这类组合牌与文字牌，绕开「为每种组合定义一个类别」的死路。难点是延迟（VLM 推理频率远低于 30 FPS）与幻觉（模型会「合理化」看不清的牌）。现实路线是分层：小模型做高频检测，大模型对少数复杂牌做低频语义解析。这条线在 C59 展开。
  • 开放词表检测（open-vocabulary detection）在 TSR 的适用性：GLIP / Grounding DINO / OWL-ViT 让「用文本描述定义新类别」成为可能，理论上直接对上「新增标志类型不重训」的需求。但交通标志的细类差别是「圆圈里的数字不同」这种极细粒度的视觉差异，而开放词表模型的强项是粗粒度语义对齐——两者是否匹配，目前实验结果并不乐观。
  • 跨区域泛化与标志体系的形式化：如何把「在德国训练的模型」迁移到中国，本质上是「形状-颜色-语义映射函数」的迁移。是否存在一种把 GB 5768 / Vienna / MUTCD 统一起来的中间表示（比如「形状+主色+图元」的组合编码），使得模型学到的是可组合的部件而非整体模板，是一个既有理论价值又有工程价值的开放问题。
  • 物理世界对抗攻击：贴纸、涂鸦、特定图案可以让「停车让行」被稳定误分类（Eykholt 等人的经典工作），而这类攻击在真实道路上极易实施。防御手段（时序一致性、多相机交叉验证、地图先验）都不是模型内部的，而是系统层面的——这再次说明 TSR 的鲁棒性必须在系统层解决。
  • 评测基准与真实体验的脱节：现有 TSR 基准几乎都是单帧 mAP，而量产系统关心的是首检距离、闪烁率、FP/km、关键类召回。缺少一个被广泛接受的、时序的、代价敏感的 TSR 基准，是这个领域最明显的空白之一——也意味着大量论文的提升在车上不可见。
