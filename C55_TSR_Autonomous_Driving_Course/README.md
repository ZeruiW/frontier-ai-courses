# 交通标志识别与自动驾驶感知（TSR）

> **这是整个补缺批次（C53–C61）里最贴近岗位的一门课。**
> 它直接对应 XPENG「TSR 2D Detection」岗位 JD 中最难靠刷题或刷 COCO 补上的那一块：
> **不是「会训一个检测器」，而是「懂交通标志这个具体问题」**——
> 类别体系怎么定、系统怎么切、置信度怎么传、多帧怎么融、指标怎么设计。

通用目标检测的课教你怎么把 mAP 从 40 提到 45。这门课教你的是另一件事：
当面试官问「你这个模型上车之后会在哪儿出错」，你能不能脱口说出十种失效模式、
指出哪一种后果最重、并把成因归到数据 / 模型 / 传感器 / 标注规范中的某一处，
再给出各自的对策与验证方案。**这才是量产感知岗位真正筛人的地方。**

## TSR 与通用目标检测的五个本质不同

这五条是全课的主轴，每个模块都在展开其中一条或几条：

1. **目标极小** — 60 米外的 60 cm 限速牌在 1920×1080 / 60° FOV 的相机上只有十几个像素。
   小目标的所有问题（IoU 对位移极敏感、正样本稀缺、下采样抹掉信息、标注误差相对量级大）在这里全部叠加。
2. **类别极度长尾，且与区域相关** — 「限速 60」上万条、「注意牲畜」十几条；
   而且同一形状在不同国家含义可能完全不同，一套类别表走不了全球。
3. **语义直接影响安全动作** — 检测出「停车让行」和检测出一只猫，下游的后果完全不在一个量级。
4. **时序信息可用而且必须用** — TSR 是一个"接近过程"：从远到近，越来越清楚。
   标志静止、自车位姿已知，所以它的关联问题比行人跟踪简单一个量级——不用是浪费。
5. **误检代价高度不对称** — 漏检景点指示牌几乎无感，误检一块广告牌导致无端减速会被用户立刻投诉。
   这条直接否定了「用一个 mAP 概括一切」的做法。

## 学习路径

**推荐顺序：00 → 01 → 02 → 03 → 04 → 05，一条直线读完。** 后面的模块依赖前面的概念。

- **看清问题（00–01）** — 先把物理量算清楚（多远、多少像素），再把类别体系搞明白（法规才是类别定义书）。
  这两件事没做对，后面所有努力都会打折。
- **做出系统（02–03）** — 02 决定架构（两级还是端到端），03 决定优先级（先修哪个失效模式）。
  这两个模块是全课信息密度最高的部分，也是面试里最容易展开讲十分钟的部分。
- **让它可靠（04–05）** — 04 把单帧检测变成稳定输出，05 把"稳定"变成可度量、可门禁的工程属性。

**如果你时间很紧**（比如面试在三天后）：先读 **02 + 03 + 05**。
这三个模块覆盖了 TSR 面试里最高频的三类问题——系统设计题、失效分析题、评测设计题。
04 的跟踪部分如果你已经学过 C54 的匈牙利匹配，可以只读迟滞与状态机那两节。

## 与相邻课程的分工

这门课是「问题侧」，其他几门课是「方法侧」。它们互为前后：

| 课程 | 关系 |
|---|---|
| **C53 · 实时检测器架构** | 提供 TSR 的**检测器候选**（YOLO 演进 / RTMDet / RT-DETR）与延迟-精度选型方法。本课 02 的架构决策会直接引用它的选型结论。 |
| **C54 · 端到端集合预测（DETR）** | 提供**匈牙利匹配**这把锤子。本课 04 的跨帧关联用的是同一个算法——训练时用它对齐预测与 GT，跟踪时用它对齐轨迹与检测。 |
| **C57 · 小目标检测** | 展开本课"五个不同"里的第①条。本课只给出物理量与后果，**具体怎么解**（NWD、加 P2、切片推理）在 C57。 |
| **C58 · 难例挖掘与长尾闭环** | 展开第②条。本课 01 讲长尾的**结构**（层次标签、类别爆炸），C58 讲怎么**挖数据、怎么闭环、怎么证明数据真的有用**。 |
| **C59 · VLA 与感知接口** | 承接本课的输出。本课 02 讲置信度必须标定并向下传递，C59 讲这个 schema 具体怎么设计、怎么进 VLA 的 prompt 或 token。 |
| **C60 · 车端部署与一致性** | 承接本课 05 的最后一节。本课指出"离线指标与路测体验会背离"，C60 给出定位方法（预处理 / 模型 / 后处理逐层对拍）。 |
| **C56 · 检测数据增强** | 提供本课 03 里各类失效模式的**对策工具箱**（低光合成、大气散射雾化、运动模糊核、copy-paste 补长尾）。 |
| **C61 · 检测工程实战与面试实务** | 本课内容的**表达层**：怎么把这些洞察组织成 10 分钟能讲完、经得起追问的项目叙事。 |

## 环境

见 `requirements.txt`。**纯 numpy + 标准库，CPU 可跑，不需要 GPU，也不需要下载任何数据集。**

所有实验用**按物理规则合成的数据**：针孔投影算出的像素尺寸序列、Zipf 分布的类别频次、
大气散射模型给出的对比度衰减、接近过程中逐帧变化的检测分数。
我们复现的是**结构与量级**——「小目标的 IoU 掉得多快」「级联召回会掉多少」
「多帧投票要等几帧」「FP/km 换算成用户每天遇到几次」——而这恰恰是可迁移的那部分：
数据集会换、模型会换，这些数量关系不会。

每个模块末尾有一个 🧪 **真实工程胶囊**，把当天的结论翻译成可原样复制进真实项目的
配置、schema 与评测脚本。
