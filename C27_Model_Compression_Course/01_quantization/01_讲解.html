1量化是什么：用整数近似浮点

量化是当下大模型压缩里收益最直接、应用最广的一招。它的全部出发点是一个朴素的观察：神经网络的权重（和激活）用 16 位甚至 32 位浮点存着，但模型其实不需要这么高的精度也能工作得很好。既然如此，我们能不能用更少的 bit——比如 8 位整数（256 个级别）、甚至 4 位整数（仅 16 个级别）——来近似它们，从而省下成倍的显存与带宽？

把这个想法精确化。量化要解决的是一个映射问题：怎么把一段连续的浮点数（比如权重，大致分布在 [−0.3, 0.3]）映射到一组离散的整数（比如 int8 的 [−127, 127]），并且能近似地还原回来。最通用的映射是affine quantization（仿射量化）：

\[q = \mathrm{round}\!\left(\frac{x}{s}\right) + z, \qquad \hat x = s\,(q - z)\]

其中 s 是scale（缩放因子，决定每个整数级别代表多大的浮点步长），z 是zero-point（零点，整数域中代表浮点 0 的那个整数）。前一个式子把浮点 x 压成整数 q（量化），后一个把整数还原成浮点近似 x̂（dequantization，反量化）。整门量化的学问，归根结底就是怎么选 s 和 z、以及在多大的粒度上各选一套。

直白说

把 scale 想成尺子的刻度。int8 给你 256 个刻度去量一段浮点。刻度太粗（s 太大），细节就丢了；刻度太细（s 太小），尺子量程不够、量不到的部分就被截断。选 scale 就是在「分辨率」和「量程」之间找平衡。

严谨说

反量化值 x̂ 与原值 x 之差叫quantization noise（量化噪声）。在均匀量化下，单个误差近似服从 [−s/2, s/2] 的均匀分布，期望平方误差约 s²/12（本模块 notebook 会从零验证这个公式）。s 越小误差越小——这就是为什么我们想方设法把 scale 压小，而离群值（撑大范围、逼着 s 变大）是头号敌人。

一句话抓住量化：用一把只有少数刻度的尺子去近似连续的权重，误差由刻度粗细（scale）决定。之后所有的花样——对称还是非对称、整张矩阵一套 scale 还是每行一套、要不要专门处理离群值——都是在回答同一个问题：怎么让这把尺子在最该精确的地方最精确。

为什么神经网络能容忍这么粗的近似？这本身是个深刻的现象。直觉上，训练好的网络对权重的微小扰动是鲁棒的——成千上万个权重协同工作，单个权重抖动一点，会被后续层的平均与非线性吸收掉。量化噪声恰好像一种结构化的小扰动，只要它的幅度（由 scale 控制）足够小、且不偏不倚（均值近 0），模型的输出几乎不变。这也提示了量化会失败的两种情形：scale 太大（噪声盖过信号）、或噪声有系统性偏置（不再零均值）——后续的对称性选择、误差补偿（模块 02）本质都在控制这两件事。

还要先建立一个bit 与级别的数量感，它贯穿全课：b bit 能表示 2^b 个级别——int8 是 256 个、int4 只有 16 个、int2 仅 4 个。每少一个 bit，可表示的级别就减半，量化误差大致翻倍（scale 要翻倍才能覆盖同样范围）。这条「每少 1 bit，误差约 ×2」的规律，解释了为什么 int8 往往近乎无损、int4 需要精细技巧、而 int2 几乎必须重训（QAT）。压缩越狠，越要靠后面模块的算法把误差按回去。

2对称 vs 非对称：要不要零点

对称 vs 非对称：要不要零点

仿射量化里 z 是否为 0，分出两条路。

对称量化（symmetric）令 z=0：整数区间关于 0 对称，反量化退化成一次乘法 x̂ = s·q。最常见的 scale 选法是 absmax：s = max(|x|)/qmax，让绝对值最大的元素刚好映射到整数边界。权重大致关于 0 对称，所以权重量化几乎都用对称——简单、快、反量化开销最小。

\[\text{absmax}:\quad s = \frac{\max_i |x_i|}{q_{\max}}, \quad z = 0, \quad q = \mathrm{round}(x/s)\in[-q_{\max}, q_{\max}]\]

非对称量化（asymmetric）允许 z≠0：用数据的 min/max 两端把任意区间铺满整个整数范围。scale 与 zero-point 为：

\[s = \frac{x_{\max}-x_{\min}}{q_{\max}-q_{\min}}, \qquad z = q_{\min} - \mathrm{round}\!\left(\frac{x_{\min}}{s}\right)\]

它更贴合偏斜分布。最典型的是 ReLU/GELU 之后的激活——大量值挤在 0 附近、全为正。用对称量化去量一段 [0, 6] 的激活，等于浪费掉整个负半轴的整数级别（一半精度白扔）；非对称则把零点挪到整数区间的最左端，把所有 256 个级别都用在 [0,6] 上。

维度对称 (absmax)非对称 (zero-point)
零点 z固定 0随分布偏移
反量化s·q（一次乘法）s·(q−z)（含零点项）
适合权重（近似对称）激活（偏斜、全正）
整数范围利用对称分布满、偏斜分布浪费一半任意分布都铺满
矩阵乘里的额外开销无零点项要单独展开累加

非对称量化在整数矩阵乘里会引入额外的零点项：(q_w − z_w)(q_x − z_x) 展开后多出三项要处理（Jacob et al. 2018 详细推导）。这是为什么即便激活偏斜，很多 weight-only 方案仍对权重用对称、只对激活用非对称——把复杂度留在激活侧。选对称还是非对称，不只看分布，还要看它下游怎么被算。

再补一个整数边界的细节，初学者常踩坑：int8 对称量化通常用 [−127, 127] 而非完整的 [−128, 127]。为什么主动放弃 −128？因为对称量化要求整数区间关于 0 镜像，这样 x̂ = s·q 才严格对称、q=0 精确对应 x=0。若用上 −128，区间就不对称了，会引入一个微小的系统性偏置。少用一个级别（256 里的 1 个）换来零点的精确与对称，这笔账绝大多数场景都划算。

一个实践上的判断流程：拿到一个张量要量化时，先看它的分布形状。近似关于 0 对称（绝大多数权重、注意力的 QKV 投影）→ 用对称 absmax，省事且无零点开销；明显偏斜或单边（ReLU/GELU/Sigmoid 后的激活、全正的 gate）→ 用非对称，否则白扔一半级别。这个「先看分布再选量化器」的习惯，比记住任何公式都重要——它是把量化用对的第一步，也是 notebook 第 1、2 节要你亲手对比对称/非对称误差的原因。

3量化粒度：tensor / channel / group

量化粒度：per-tensor → per-channel → group-wise

第二个核心旋钮是粒度——多大一块共用一套 (s, z)。粒度越细，越能贴合局部分布、越准，但要存的元数据（scale 们）越多。

  • per-tensor（逐张量）：整个权重矩阵共用一个 scale。最省元数据、最快，但一个离群值就毁掉全矩阵——它撑大 absmax，逼着 scale 变大，于是所有其他元素的精度都被它拖累。
  • per-channel（逐通道）：每个输出通道（矩阵的每一行）独立一个 scale。离群值的影响被隔离在它所在的那一行，其余行不受牵连。几乎是 int8 权重量化的标配，元数据开销很小（每行才多一个 float）。
  • group-wise（分组）：把每一行再切成每 g 个元素（典型 g=128）一组，各组独立 scale。这是 int4 保精度的关键——16 个级别太少，必须靠极细的粒度去贴合每一小段的局部范围。

这里有个清晰的权衡谱：从 per-tensor 到 group-wise，量化误差单调下降、元数据开销单调上升。实践中的经验是：int8 用 per-channel 通常就够（近乎无损）；int4 必须上 group-wise（g=128 是社区默认），否则 16 个级别配上离群值会掉点严重。本模块 notebook 会把三种粒度都实现出来，让你亲眼看到同一矩阵的输出误差如何随粒度变细而下降。

为什么粒度这么关键？因为权重矩阵的不同部分量级差异很大：有的行/段数值大、有的小。用一个全局 scale，就得照顾最大的那个（否则它溢出），结果小数值区域的精度被白白浪费。把 scale 局部化，等于让每一小块都用最适合自己量级的尺子——这正是 group-wise 在 int4 下不可或缺的原因。

4Bit packing：兑现 int4 的压缩

Bit packing：把 int4 真正塞进更小的空间

有个容易被忽略的工程现实：numpy/PyTorch 里没有 int4 这个原生类型。如果你把权重 round 到 [−8, 7] 却还存在 int8 容器里，显存一点没省——每个 4-bit 值仍占着 8 bit。要兑现 int4 的 4× 压缩，必须做 bit packing（位打包）：把两个 int4 拼进一个 int8。

两个 int4 (0..15) 打包进一个 uint8： a = 0b1011 (=11) b = 0b0010 (=2) packed = (a << 4) | b = 0b1011_0010 (=178) └─ 高4位=a ─┘└─ 低4位=b ─┘ 解包： a = packed >> 4 (取高4位) b = packed & 0b1111 (取低4位, 即 & 15)

打包用两个位运算：packed = (a << 4) | b（a 左移到高 4 位，与 b 的低 4 位或起来）。解包是逆操作：a = packed >> 4（右移取高位），b = packed & 0xF（与掩码取低位）。这样 N 个 int4 只占 N/2 个字节，4× 压缩才真正落地。

直白说

打包就像把两个人塞进一个双人座：每人本来占一个 8 位的座位，现在两人合用一个，空间省一半。代价是上车（打包）下车（解包）要多两步，但座位（显存）实打实省了。

严谨说

注意打包通常对无符号整数做最方便（直接位运算）。对有符号 int4（[−8,7]）的常见做法是先加偏移变成无符号 [0,15] 再打包，解包后减回去；或者用非对称量化直接产出 [0,15] 的 q。反量化前必须先解包还原出每个 4-bit 值。

打包不是「可选优化」，而是 int4 压缩的兑现步骤。常见的坑：忘了打包（以为量化到 int4 就省显存了，其实没有）；打包/解包的高低位顺序写反（解出来 a、b 互换）；有符号值不加偏移直接打包导致符号位错乱。本模块 notebook 会从零写打包/解包并 assert 往返无损（pack 再 unpack 等于原值），把这些坑一次性堵死。

5量化误差与离群值

量化误差：为什么离群值是头号敌人

现在把「量化掉多少精度」量化（pun intended）。均匀量化下，把 x 舍入到最近的网格点，误差 x̂ − x 落在 [−s/2, s/2]。若误差近似均匀分布，其期望平方误差（也就是量化噪声功率）是：

\[\mathbb{E}\big[(\hat x - x)^2\big] \approx \int_{-s/2}^{s/2} \frac{u^2}{s}\,du = \frac{s^2}{12}\]

这个简洁的公式（s²/12）是理解量化的钥匙：误差完全由 scale 决定，而 scale 由数据范围决定。而数据范围——尤其在 absmax 下——被最大绝对值撑着。于是问题归结到一个词：outlier（离群值）。

离群值毁精度

离群值是低 bit 量化的头号敌人。假设一行权重 99% 落在 [−0.1, 0.1]，但有一个 3.0 的离群值。absmax scale 被这个 3.0 撑到 3.0/127 ≈ 0.0236，于是那 99% 的正常权重每个只能落在 ±2 个整数级别里——256 个级别，正常权重只用到了 8 个，精度灾难性浪费。Dettmers et al.（LLM.int8()）发现大模型激活里恰恰存在这种离群特征维度，这是 8-bit 量化在 6.7B 以上模型上一度失败的根因。

对付离群值有三条路，正好对应本课后续：更细的粒度（per-channel/group-wise，把离群值的影响圈在局部，本模块）；截断（clipping，主动牺牲离群值、给主体更多精度，本模块 notebook 演示）；以及更聪明的算法（GPTQ 用误差补偿、AWQ/SmoothQuant 用缩放迁移把离群难度挪走，模块 02）。

一个常用且立竿见影的技巧是截断（clipping）：不取 absmax，而取某个分位点（如 99%）当范围，把超出的离群值夹到边界。这牺牲极少数离群值的精度，换来把 scale 显著压小、让占绝大多数、真正主导层输出的正常权重精度大涨。要点是看 clipping 改善了哪部分的误差：被夹掉的离群值误差会变大，但占 99% 的正常权重 MSE 会大幅下降——notebook 会用一个带离群值的分布、专门度量正常权重上的 MSE 把这一点跑出来。在权重量化里，正常权重才是输出的主体，所以这笔交易通常很划算；这也是 AWQ/SmoothQuant 之类「把离群难度挪走」的更精细版本要解决的同一个问题。

6weight-only 量化为何能加速

从权重量化到推理：weight-only 量化为什么能加速

把前面的零件拼起来看一个真实场景：weight-only 量化（仅权重量化，GPTQ/AWQ 都属此类）。做法是把权重存成 int4（group-wise + 打包），推理时先反量化回 fp16，再做正常的 fp16 矩阵乘。

初看这很奇怪：既然算之前要反量化回 fp16，那算的次数一点没少（甚至多了反量化），凭什么更快？

直白说

答案在模块 00 的世界观里：大模型推理是访存受限的。逐 token 生成时，瓶颈是把几十 GB 的权重从显存搬到计算单元，而不是算那些乘加。权重存成 int4，每次要搬的字节就少 4 倍，于是更快——省的是带宽，不是算力。

严谨说

更精确地说：weight-only 量化把权重的内存占用与传输量降到 1/4，反量化（一次乘加）的开销相比省下的 HBM 往返微不足道。这也解释了为什么 int8 激活量化（W8A8，要同时量化激活、改动矩阵乘）反而不总是值得——它省的是算力，而推理瓶颈在带宽。Horace He 的「Brrrr」一文把这层道理讲得最透。

weight-only int4 推理的一层： 存储: W_int4 (打包, 1/4 显存) + scales (group-wise) │ ▼ 解包 + 反量化 (便宜) W_fp16 ──► Y = W_fp16 @ X (正常 fp16 GEMM) 省的是: 把 W 从 HBM 搬进来的字节数 (4x) ←── 这才是瓶颈 没省的: GEMM 的 FLOPs (一样多, 还多了反量化)

记住这条反直觉但核心的结论：在访存受限的 LLM 推理里，量化的加速来自省带宽，不是省计算。所以「weight-only、推理时反量化」不是妥协，而是恰好对症——它精准地砍掉了瓶颈（权重搬运），而把不在瓶颈上的计算（GEMM）原样留着。理解了这点，你才会明白为什么 int4 weight-only 是当前 LLM 推理量化的主流。

这里要区分两个不同的推理阶段，它们的瓶颈不一样。自回归生成分prefill（一次性处理整段 prompt，是大矩阵乘、偏算力受限）和decode（逐个 token 生成，每步只算一行、严重访存受限）。decode 阶段每生成一个 token 都要把整个模型的权重完整过一遍，而真正的算术量却很小——这是 weight-only 量化收益最大的地方。所以同一个量化模型，在长输出的对话场景（decode 占比高）提速最明显，在大批量打分（prefill 占比高、更算力受限）收益相对小。把这层分清，你才能预判量化到底能为你的负载省多少。

最后澄清一个常见混淆：weight-only（只量化权重，激活仍 fp16）与全量化（W8A8、W4A4，权重激活都量化）是两条不同的路。前者实现简单、几乎不掉点、专省带宽，是当前 LLM 推理的主流；后者要改动矩阵乘本身用整数算（省算力），但激活离群值更难对付（LLM.int8()、SmoothQuant、QuaRot 都在攻这块）。本模块与模块 02 聚焦 weight-only 这条最实用的线；全量化的难点（激活离群值）会在模块 02 的 AWQ/SmoothQuant 缩放迁移里再深入。

7一条完整的量化流水线

把它跑起来：一条完整的量化流水线

综合本模块所学，量化一个权重矩阵到 int4 的完整流程是：

  1. 选粒度（int4 选 group-wise，g=128）与对称性（权重选对称 absmax）；
  2. 对每一组算 scale：s_g = max(|W_g|)/7（int4 对称 qmax=7）；
  3. 量化：q_g = round(W_g / s_g).clip(−8, 7)；
  4. （可选）对离群值做 clipping，用分位点代替 absmax；
  5. bit packing：每两个 int4 打包进一个字节，存 q 与 scales；
  6. 推理时：解包 → 反量化 Ŵ_g = s_g·q_g → 正常矩阵乘。

这条流水线就是 bitsandbytes 的 load_in_4bit、AutoGPTQ、AutoAWQ 背后做的事（它们在第 2–3 步用更聪明的算法，见模块 02，但骨架相同）。本模块 notebook 会把这整条流水线从零搭出来，并对拍：量化-反量化的输出误差在 int8 下 <1%、int4 group-wise 下也能控制在可接受范围。

一个值得记住的数量级感：相对 fp16，int8 压缩约 2×、int4 约 4×。一个 70B 模型 fp16 要 140GB，int4 后约 35GB——从「单卡装不下」变成「单张 48GB 卡能跑」。这就是量化在生产里的真实价值：不是让模型更准，而是让它装得下、跑得起、搬得快。

量化不是没有代价的免费午餐。常见的失败模式：int4 不做 group-wise 直接 per-tensor（掉点严重）；忘了打包（显存没省）；对有离群值的层不做特殊处理（精度崩）；把激活也粗暴量化（破坏 LLM.int8() 要保护的离群特征）。本模块教你把这些坑识别出来；模块 02 的 GPTQ/AWQ 则提供更系统的解法。

8研究前沿与开放问题

研究前沿与开放问题

  • 更低 bit（2-bit、1.58-bit）：能压到 int2 甚至三值（BitNet b1.58 的 {−1,0,1}）吗？这需要 QAT 或特殊架构，是「极限压缩」的活跃方向，挑战在于 2 bit 下信息论上的级别实在太少。
  • 非均匀量化：均匀网格未必最优。QLoRA 的 NF4 按权重的近似正态分布设量化级别（分位点量化），信息论上更匹配。量化级别该怎么放，仍有空间。
  • 权重+激活联合（W4A4 等）：weight-only 省带宽，但要省算力得连激活一起量化。激活离群值更凶，W4A4 在大模型上仍是难题（QuaRot 用旋转把离群值打散是新思路）。
  • KV-cache 量化：长上下文推理的显存大头是 KV cache。把它量化到 int4/int8（且要在线、逐 token）是与权重量化互补、正在快速落地的一条线。
  • 量化与其他压缩的叠加：量化 + 剪枝（SparseGPT 同时做）、量化 + 蒸馏怎么协同而不互相放大误差，是把压缩推到极致的系统问题。
