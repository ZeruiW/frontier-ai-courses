1这门课讲什么

欢迎来到 模型压缩与高效化。这门课只追求一件事：让你从「会调用 bitsandbytes / AutoGPTQ / AutoAWQ」变成「会从零写出它们的核心算法」。

绝大多数人和模型压缩的关系，止于在 from_pretrained 里加一句 load_in_4bit=True，或者跑一遍 AutoGPTQ 的脚本。这门课要往下钻一层：当你把一个权重从 bf16 压到 int4，里面到底发生了什么？为什么同样压到 4 bit，朴素的就近舍入（RTN）会明显掉点，而 GPTQ、AWQ 几乎无损——它们多做了什么？为什么 fp8 训练要那么小心翼翼地缩放，否则就 NaN？蒸馏里那个「温度」到底在放大什么？2:4 稀疏凭什么能在硬件上真的快一倍？

这些问题的答案不在任何 API 文档里，而在数值的物理约束和算法对这些约束的回应之中。一个被压缩的模型，本质上是在用更少的 bit 去近似原来那张高精度的权重张量；压缩的全部艺术，就是在给定 bit 预算下，让这个近似对模型的最终行为伤害最小。本课沿着这条主线，把现代大模型压缩的五大支柱（整数量化、GPTQ/AWQ 后训练量化、fp8 训练、知识蒸馏、剪枝与稀疏）从零拆开、亲手重建。

学完你应当能回答这类问题（也是推理/部署岗位的高频面试题）：absmax 量化和 zero-point 量化差在哪，什么时候该用哪个？int4 为什么必须配 group-wise？GPTQ 的逆 Hessian 误差补偿到底在补偿什么？AWQ 为什么只缩放权重就能保住精度？fp8 的 E4M3 和 E5M2 为什么一个管前向一个管梯度？蒸馏的温度为什么能传递暗知识？2:4 稀疏为什么是 2:4 而不是别的？——并且能在 numpy 里把这五样东西都从零实现、和全精度参考对拍。

一句方法论上的话先说在前面：本课的价值不在「我们没有 GPU 也能学压缩」这个妥协，而在它逼你只关注真正难的部分——压缩算法的数值逻辑与正确性。CUDA 内核、bit 级打包的工程细节、各框架的 API，这些有了正确的算法骨架之后都是机械活，且年年在变；而「怎么选 scale、怎么补偿误差、怎么搜保护缩放、怎么设温度、怎么排稀疏」是不随框架过时的硬功夫。把它练扎实，换到任何库（bitsandbytes、TransformerEngine、下一代工具）都立刻能上手。

2世界观：压缩是为了对抗内存墙

贯穿全课的世界观，要先纠正一个最常见的误解：压缩主要不是为了「少算」，而是为了「少搬数据、少占显存」。

直白说

很多人以为把模型量化到 int4 是为了「算得更快」。但大模型推理（尤其是逐 token 生成）大多是访存受限的——瓶颈在把几十上百 GB 的权重从显存搬到计算单元，而不是算那些乘加。于是压缩最直接的收益是：权重小了，每生成一个 token 要搬的字节就少了，于是更快；同时显存装得下更大的模型或更长的上下文。

严谨说

这解释了一个初看反直觉的现象：weight-only 量化（如 GPTQ/AWQ）推理时还要先把 int4 反量化回 fp16 再做矩阵乘，算的次数一点没少、甚至多了反量化，却依然更快。因为省下的是HBM 带宽（搬 int4 比搬 fp16 少 4 倍字节），而带宽正是瓶颈。这与 C36 课「访存受限算子上省 IO 比省 FLOPs 值钱」是同一条原理。

压缩手段主要省什么为什么有用典型代价
量化 int8/int4显存 + 带宽搬更少 bit；LLM 推理访存受限低 bit 下掉点，需补偿/分组
fp8 训练训练算力 + 带宽Tensor Core 对 fp8 吞吐翻倍范围/精度不足，需 scaling
蒸馏参数量（换小模型）小模型更省一切，软标签提质要训练学生，需教师
剪枝/稀疏参数 + 计算0 不必存不必算；2:4 硬件加速非结构难加速，高稀疏掉点
内存墙

最反直觉、也最重要的一条：现代硬件的算力增长远快于内存带宽与容量。结果是大模型部署的瓶颈越来越偏向显存装不下与带宽喂不饱，而非算力不够。这就是为什么压缩的主旋律是「用更少的 bit 表示同样的模型」——量化省 bit、稀疏省 bit、蒸馏换小模型，全都在对抗内存墙。把这条记牢，本课每个技术为什么存在就都说得通了。

3统一框架：压缩 = 带约束的近似

把压缩的五种手段放进一个统一的数学框架，你会发现它们惊人地相似——都在解同一类问题。

设原模型某层的权重是 W，我们要找一个更便宜的近似 Ŵ（低 bit、或稀疏、或小模型），使得它对模型行为的伤害最小。形式化为：

\[\min_{\hat W \in \mathcal{C}}\ \big\| W x - \hat W x \big\|^2 \quad\text{（在校准数据 } x \text{ 上）}\]

这里 𝒞 是「便宜」的约束集合：量化要求 Ŵ 的每个元素落在量化网格上；剪枝要求 Ŵ 有很多 0；蒸馏则把整个小模型当作 Ŵ。目标都是让层（或模型）的输出尽量不变。这个「逐层重建」视角是理解 GPTQ、AWQ、SparseGPT 的总钥匙——它们的差别只在于如何在各自的约束下高效地解这个最小化。

直白说

一句话串起全课：压缩 = 在「便宜」的约束下，找一个最接近原权重（或原输出）的替身。量化的约束是「只能用 16 个或 256 个值」，剪枝的约束是「一半得是 0」，蒸馏的约束是「得是个小网络」。约束不同，但都是带约束的近似。

严谨说

注意优化目标里是 ‖Wx − Ŵx‖² 而非 ‖W − Ŵ‖²：我们要的是输出接近，不是权重本身接近。这个区别正是 GPTQ（用 XXᵀ 形式的 Hessian 加权误差）和 AWQ（按激活幅度保护通道）比朴素 RTN（只看 ‖W−Ŵ‖）更准的根本原因——它们把激活纳入了考量。

有了这个框架，本课的模块顺序就有了内在逻辑：模块 01 先解最简单的约束（量化网格，逐元素就近舍入）；模块 02 在同样的量化约束下引入激活感知（GPTQ 的 Hessian、AWQ 的缩放），把目标从 ‖W−Ŵ‖ 升级到 ‖Wx−Ŵx‖；模块 05 把同一套重建思想搬到稀疏约束（SparseGPT）。模块 03（fp8）和 04（蒸馏）则从另外两个角度（训练时的低精度、换一个小模型）攻同一个「用更少资源近似原模型」的问题。

4方法论：用 numpy 从零实现并对拍

本环境没有 GPU、不装 CUDA/bitsandbytes/TransformerEngine。但压缩算法的难点从来不是这些库的 API，而是数值逻辑：scale 怎么算、误差怎么补偿、缩放怎么搜、温度怎么缩放梯度、稀疏怎么排。这些用 numpy 在 CPU 上也能精确地表达和验证。

打个比方：学会计不一定要有 SAP 系统。压缩的「算理」是如何用更少的信息近似一个张量、并量化这个近似的代价；这些都是和框架无关的数学。一个真实的 int4 量化内核里那行 bit 打包、那次反量化乘法，描述的是「怎么存、怎么还原」；我们在 numpy 里就用 np.round、整数移位、np.clip 把同一套逻辑显式写出来——结构一模一样，只差「在 GPU 上并行跑」这一层工程。

直白说

我们把每个压缩机制翻译成 numpy 里看得见摸得着的东西：量化就是 round(W/s) 再 clip，反量化就是乘回 s；GPTQ 的误差补偿就是几行逆 Hessian 的矩阵运算；蒸馏就是两个 softmax 之间的 KL；2:4 稀疏就是每 4 个里把最小的 2 个置 0。你写的是算法，不是性能。

严谨说

关键纪律是对拍（differential testing）：每个压缩算法都和一个全精度参考比对——量化误差要符合理论值，GPTQ 的层输出 MSE 要明显小于 RTN，蒸馏的 KL 要随温度单调变化，剪枝后微调要找回精度。每个结论都有 assert 兜底，绝不靠「感觉对了」。

压缩概念本课的 numpy 实现对应真实工具
int8/int4 量化round(W/s).clip(qmin,qmax)bitsandbytes / TFLite
GPTQ 误差补偿逆 Hessian 的 Cholesky + 逐列更新AutoGPTQ
AWQ 缩放保护按激活幅度搜 per-channel scaleAutoAWQ
fp8 cast + scaling模拟 E4M3/E5M2 量化 + amax 缩放TransformerEngine
温度蒸馏softmax(z/T) 间的 KL × T²HF Trainer / 自定义 loss
2:4 稀疏每 4 元素保留 |·| 最大的 2 个Sparse Tensor Core / apex

务必清楚本课不教什么：不教各框架的 API 调用细节、不测真实 GPU 上的加速比、不写 CUDA 量化内核、不调优内存布局。这些在你有了正确的算法逻辑后，是第二步（references 里的 bitsandbytes、AutoGPTQ、TransformerEngine 接手）。本课负责把第一步——算法与数值正确性夯死；这一步搞定，第二步才有意义。

5环境与运行

环境与运行

环境极简：只需 numpy（画精度-压缩率曲线可选 matplotlib）。全课 CPU 秒级运行，无需 GPU、CUDA、bitsandbytes、torch。

conda create -n compression python=3.11 -y && conda activate compression
pip install numpy            # 必需
pip install matplotlib       # 可选，仅用于画精度-稀疏度/压缩率曲线
jupyter lab

每个模块配一个 notebook，结构统一：先用 numpy 把算法从零实现并对拍全精度（5–6 个 worked 小节，每节都跑出可打印的验证与 assert），再做 3–4 道带 assert 判分的 ✏️ 练习（先给骨架，自己填，再对照 📖 参考答案），最后一个真实数据胶囊——尽量用真实模型配置或真实权重统计（带 try/except 联网回退，确保离线也能跑），把纸面知识接到现实。

关于真实 GPT-2 权重：部分 notebook 会尝试加载真实 GPT-2 的某个权重张量来量化/剪枝（让你看到真实权重分布上的效果），但联网失败会自动回退到统计匹配的合成权重（同样的形状、近似的分布），算法逻辑与结论完全不变。所以无网络也能完整跑完，不必担心。

建议的学习节奏：先读完整章 HTML 建立直觉与理论框架，再打开 notebook 亲手实现。读和做缺一不可——只读会觉得「好像懂了」，真正动手写 scale 计算、调误差补偿、让 assert 通过时，才会发现魔鬼藏在哪些细节里（对称还是非对称、per-channel 还是 group、补偿系数的方向、温度的 T² 缩放、2:4 的边界）。这门课的深度正是为「动手」服务的。

配套先读：Horace He《Making Deep Learning Go Brrrr》建立「访存受限」世界观；Nagel et al. 量化白皮书当字典查术语；五大支柱各有奠基论文（LLM.int8()、GPTQ、AWQ、FP8 Formats、Hinton 蒸馏、SparseGPT、2:4、彩票假说），完整清单见 references.md。

✅ 学完整门课，你应该能：
  1. 从零实现 int8/int4 量化（absmax/zero-point、对称/非对称、per-tensor/channel/group、bit packing），并度量量化误差、验证 s²/12 公式；
  2. 讲清 RTN 为何不是最优，从零实现 GPTQ 的逆 Hessian 误差补偿与 AWQ 的激活感知缩放，并量化它们相对 RTN 的提升；
  3. 讲清 fp8 的 E4M3/E5M2 取舍，从零实现 fp8 cast、动态 scaling 与 loss scaling，搭一个混合精度的玩具配方；
  4. 从零实现温度知识蒸馏（soft label + KL + T² 缩放），并理解 logit/feature/attention/自蒸馏的区别；
  5. 从零实现幅度剪枝（全局/逐层）、2:4 半结构稀疏、剪枝-微调恢复，画出稀疏度-精度曲线，并讲清 SparseGPT 与彩票假说；
  6. 把以上五种手段放进「带约束的逐层重建」统一框架，知道每种压缩在生产里用哪个库落地。
