1指令层：唯一能真正增加信息量的增强

模块 01 与 02 的增强都只是「把已有样本换个说法」——信息量不增加，它们提供的是正则化。指令层不一样：它从教师模型的知识里采样出训练集里根本不存在的样本。

词面/语义层增强的信息流: 你的 1000 条数据 ──扰动/释义──▶ 4000 条数据 └─ 信息量上限 = 那 1000 条 （同一份信息的多个视角） 指令层合成的信息流: 你的 175 条种子 ──▶ [ 教师 LLM ] ──▶ 52,000 条新指令数据 ▲ └─ 信息来自**教师模型的预训练知识** └─ 信息量上限 = **教师模型的能力**（远大于种子） 代价：① 你只能拿到教师会的东西（学生 ≤ 教师） ② 教师的偏差、风格、错误会被**完整继承甚至放大** ③ 反复用合成数据训练下一代，会走向**模式坍塌**（model collapse）

直白说

这个转变是质变而非量变。Self-Instruct（Wang et al. 2023）从 175 条人写的种子任务出发，用 GPT-3 生成了 52k 条指令数据，把一个基座模型的指令跟随能力提到接近 InstructGPT 的水平。这条路线后来成了整个开源指令模型生态的基础——Alpaca、Vicuna、WizardLM、以及无数领域模型都走的是它的变体。

严谨说

但也要看清它的结构性上限：学生模型的能力上限是教师。这不是一个可以通过「造更多数据」绕过的问题——你造一百万条也不会让学生超过教师在那个能力维度上的水平（除了少数「弱到强泛化」的特殊设置，C23 有讨论）。所以合成数据的正确用途是把教师的能力「蒸馏」进一个更小/更便宜/更专用的模型（C49 模块 05 讲过这个模式），而不是「凭空创造新知识」。

指令层合成有一个与前两个模块完全不同的风险维度：数据污染。词面增强不可能造出测试集里的句子（它只扰动训练集）；但 LLM 可能生成与你的测试集高度相似甚至相同的样本——因为教师模型很可能在预训练时见过那个测试集。这会让你的评测分数虚高，且极难察觉。所以指令层合成必须配去污染检查（模块 04），这在前两个模块里是可选的。

2Self-Instruct：一个四步循环

种子池 (175 条人写任务) │ ├──▶ ① 采样：从池里随机取 8 条（6 条人写 + 2 条已生成）作为 few-shot 示例 │ └─ 混合人写与已生成，是为了在「质量」与「多样性」之间平衡 │ ├──▶ ② 生成新指令：让 LLM 续写第 9 条指令 │ ├──▶ ③ 过滤： │ · 与池中任一指令的 ROUGE-L > 0.7 -> 丢弃（**去重，最关键的一步**） │ · 太长/太短、含图像/音频等无法执行的要求 -> 丢弃 │ · 关键词黑名单（"画一张图"、"写代码并运行"）-> 丢弃 │ ├──▶ ④ 生成实例：为通过的指令生成 (输入, 输出) 对 │ · 分类任务用「输出优先」（先定标签再造输入，防标签分布倾斜） │ · 其他任务用「输入优先」 │ └──▶ 加入池，回到 ①（自举）

这个循环里第 ③ 步的去重是全流程的命门。理解它为什么关键，就理解了 Self-Instruct 的全部。

直白说

如果没有去重，会发生什么？LLM 在 few-shot 提示下有很强的模式惯性——你给它 8 个「翻译类」的例子，它就倾向于继续生成翻译类任务。几轮自举之后，池子里会挤满同一类任务的变体，多样性坍塌。而池子越单一，下一轮的 few-shot 示例就越单一，形成正反馈。去重是打断这个正反馈的唯一机制。

严谨说

ROUGE-L > 0.7 这个阈值是 Self-Instruct 论文的选择，它的作用可以精确描述：它在「多样性」与「产出率」之间设定了一个交换比。阈值越严（如 0.5），保留下来的指令彼此越不像、多样性越高，但丢弃率急剧上升（要生成十条才留一条），成本相应上升。阈值越松（如 0.9），产出快但池子迅速同质化。notebook 会把这条曲线扫出来——你会看到丢弃率随阈值收紧呈超线性增长，这直接决定了合成的成本。

「输出优先」：一个防标签倾斜的关键设计

第 ④ 步里有个容易被忽略但很重要的细节。对分类任务，Self-Instruct 用「输出优先」（output-first）：先让模型列出所有可能的标签，再为每个标签生成对应的输入。

  • 输入优先（先造输入、再让模型标注）的问题：LLM 生成的输入会严重偏向某一类。让它「生成一条餐厅评论」，它大概率写正面的——因为正面评论在预训练数据里更常见、也更「安全」。结果标签分布极度倾斜。
  • 输出优先：先说「标签是负面」，再让它「写一条负面评论」。标签分布由你控制，不由模型的先验决定。

这个设计的一般化教训值得记住：凡是让 LLM 生成带标签的数据，都要问「标签分布由谁决定」。如果由模型决定，你会得到它的先验（通常是不平衡的、安全的、常见的）；如果由你决定，你能控制分布并覆盖长尾。「先定标签再造样本」是合成分类数据的默认正确姿势，也是补长尾类别最有效的手段。notebook 会把两种顺序的标签分布对比出来。

3Evol-Instruct：用演化算子提升难度与深度

Self-Instruct 解决「量」和「广度」，但生成的指令往往偏简单——因为 LLM 在续写时倾向于产出与示例难度相当的东西。WizardLM 的 Evol-Instruct（Xu et al. 2023）补的是「深度」。

演化算子做什么例子
加约束给原指令增加一个限制条件「写一首诗」→「写一首不含字母 e 的十四行诗」
深化把宽泛的问题变具体、要求更深的推理「解释光合作用」→「解释 C4 植物的光合作用与 C3 的差异及其生态意义」
具体化把抽象概念替换成具体实例「分析一种算法」→「分析快速排序在近乎有序输入上的退化」
增加推理步数要求多步推理而非单步「3+5 等于几」→「一个数加 5 后是它的两倍，求这个数」
复杂化输入让输入格式更复杂（表格、代码、嵌套）纯文本 → 带表格的问题
广度演化生成一个「同领域但全新」的指令（而非改造原指令）维持多样性，防止只在少数主题上深挖

直白说

Evol-Instruct 的循环是：随机选一个算子作用在池中的一条指令上 → 生成演化后的指令 → 生成回答 → 过滤 → 加回池。因为演化是迭代的（第二代在第一代基础上再演化），难度可以逐代提升——这是 Self-Instruct 单轮生成做不到的。

严谨说

但迭代演化引入了两个新问题。① 演化失败：模型可能产出「演化后的指令」其实与原指令等价、或者变成无法回答的胡话。原论文用一个「消除」步骤（elimination）过滤掉这些：让 LLM 判断演化后的指令是否真的更难、是否可回答、是否与原指令实质不同。② 难度分布漂移：若一直演化不加广度算子，池子会在少数主题上越挖越深，广度反而下降。所以「深度演化」必须配「广度演化」——这与 Self-Instruct 的去重是同一个「防坍塌」逻辑的不同表现。

Evol-Instruct 有一个在实践中反复出现的失败模式：难度伪装。模型学会了「让指令看起来更难」（加更多约束词、更长的描述），但实际推理难度没变。症状是：合成数据的平均长度和约束数量在涨，但学生模型在真实困难基准上没有提升。防护办法是用「可验证的难度代理」——比如要求生成带标准答案的题目，然后看基座模型的答对率（答对率下降才说明真的变难了）。这与 C22（推理 RL）里 RLVR 的可验证性思路一致。

4Magpie 式无种子生成：用模板前缀「钓」出指令

Self-Instruct 与 Evol-Instruct 都需要种子。Magpie（Xu et al. 2024）提出了一个更简洁的思路：只给指令模型「用户回合的起始模板」，让它自己续写出用户会问什么。

# 给一个**只有模板前缀、没有任何内容**的输入：
<|im_start|>user
                       ← 到这里就停，让模型自己续写

# 指令模型会续写出一条它「觉得用户会问」的指令：
<|im_start|>user
帮我写一个 Python 函数，把嵌套字典展平成单层。<|im_end|>

# 然后正常地让它回答这条指令，得到 (指令, 回答) 对。

直白说

为什么这能工作？因为对齐后的指令模型在训练时见过大量「用户回合」，它的分布里编码了「用户通常问什么」。给它一个空的用户回合前缀，它就从这个分布里采样。本质上是在「反演」模型的对齐训练数据分布。

严谨说

它的优点是零种子、极简、且多样性天然较高（因为采样直接来自模型的完整用户分布，而不是被 few-shot 示例锚定在少数几类上）。缺点是可控性最差：你几乎无法指定领域、难度或标签分布。所以它适合造通用指令数据，不适合补特定长尾。实践中三者常组合使用：Magpie 起量与广度、Self-Instruct 定领域、Evol-Instruct 提难度。

方法需要种子可控性多样性最适合
Self-Instruct需要（175 条量级）中（种子决定领域）中（靠去重维持）定向造某个领域的指令数据
Evol-Instruct需要（在已有池上演化）中高（算子可选）中（需配广度算子）提升难度与深度
Magpie不需要低高零成本起量、造通用指令数据
定向 prompt 生成不需要（用规格说明）最高取决于规格补特定长尾、造特定标签分布

从这张表可以提炼出一条实用的组合策略：用最可控的方法补最缺的部分。如果你的问题是「数据总量不够」，用 Magpie 或 Self-Instruct 起量；如果是「某个类别/场景样本太少」，用定向 prompt 精确补（并用「输出优先」控制标签）；如果是「模型在难样本上表现差」，用 Evol-Instruct 提难度。先诊断缺什么，再选方法——这比「用最新的那个方法」有效得多。

5教师偏差的传递与模式坍塌

合成数据最深的问题不是「质量不够好」，而是它的分布是教师模型的分布，而不是真实世界的分布。这带来两个不同层次的问题。

① 偏差传递：学生完整继承教师的系统性倾向

教师的倾向在合成数据里表现为学生学到什么
长度偏好（回答越长越「好」）合成回答系统性偏长学生也变啰嗦；若用于 DPO 会加剧长度偏差（C50 模块 04）
格式偏好（爱用列表、Markdown 标题）几乎每条回答都是分点列表学生在不该用列表的场合也用列表
安全过度（对边界话题一律拒答）合成数据里大量「我不能帮你…」学生过度拒答，实用性下降
知识错误（教师本身答错的领域）错误答案被当成金标准错误被固化，且学生无法自行纠正
文化/语言偏斜以英语世界视角为默认在其他文化语境下表现差

「知识错误」这一行最需要警惕，因为它与其他几行有本质区别：其他偏差是「风格问题」（可以靠后续 SFT 调整），而知识错误是把错的当对的写进了训练目标。学生模型不但学不到正确答案，还会对错误答案变得更自信（因为它是唯一的监督信号）。

② 模式坍塌：递归使用合成数据的长期后果

直白说

model collapse（Shumailov et al. 2024）描述的是：用上一代模型的输出训练下一代，反复几轮后，模型的输出分布会逐渐丢失尾部、向众数收缩。直观地说——每次采样都倾向于采到高概率区域，低概率的「尾部」内容被系统性地采不到，于是下一代模型就不知道尾部存在了。几代之后，分布退化成少数几个模式。

严谨说

这个现象在数学上是一个方差递减 + 尾部截断的过程。它有两个可分离的成因：①统计误差（有限采样必然欠采样尾部，这个即使模型完美也存在）；②模型误差（模型对尾部的建模本来就不准，误差逐代放大）。关键的缓解手段是「保留真实数据」——只要每一代训练里都混入足量的原始真实数据，坍塌就能被大幅延缓。这也是为什么「用合成数据完全替代真实数据」是危险的，而「用合成数据补充真实数据」是可行的。

坍塌的四个早期征兆

坍塌的早期征兆是可以监测的，而且不需要等到效果崩溃：①多样性指标下降（distinct-n 降、self-BLEU 升——模块 04 会实现）；②长度分布收窄（方差变小，都变成差不多长）；③高频模式占比上升（某些开头/句式的比例逐代增加，如「当然！我很乐意帮你…」）；④嵌入空间覆盖收缩。把这四个指标做成每一代都跑的看板，你就能在坍塌显现于下游指标之前发现它。这是本课「多样性指标不是为了好看，是为了当警报」这个立场的最强论据。

6算一笔账：合成数据的成本与去重阈值

\[\text{单条可用数据成本} = \frac{c_{gen}\times(n_{instr} + n_{resp})}{\text{通过率}}\]

其中「通过率」是去重 + 格式过滤 + 质量过滤后的保留比例。这个分母是成本的主导因素，而它由去重阈值直接控制。

ROUGE-L 阈值去重后多样性通过率每条可用数据的相对成本适合
0.5（严）最高低（~20–30%）3–5×追求多样性、预算充足
0.7（Self-Instruct 默认）高中（~50%）2×默认起点
0.9（松）中高（~80%）1.25×只是要起量；接受同质化
不去重会坍塌100%1×❌ 不要这么做

方法相对成本信息量保真度风险污染风险多样性
EDA / AEDA1不增加中（可用保护规则控制）无低
回译 + 过滤~1000不增加中（隐蔽，需过滤）无中
Self-Instruct~5000增加中（教师偏差）有中高
Evol-Instruct~10000（多轮）增加中高（难度伪装）有高（配广度算子）

读这张表：指令层贵三到四个数量级，但它是唯一能真正增加信息量的。所以选择逻辑很清晰——

  • 需要的只是正则化（有足够数据但容易过拟合）→ 用最便宜的（EDA/AEDA/embedding 噪声）。
  • 需要的是真正缺失的样本类型（某类场景一条都没有）→ 只有指令层能做，贵也得做。
  • 需要的是「让小模型学会大模型的能力」→ 指令层的数据蒸馏是标准路径（C49 模块 05）。

把本模块浓缩成一句可迁移的智慧：合成数据的质量上限是教师，多样性上限是去重阈值，而它的长期风险是坍塌——三者都必须被显式测量。前两个模块你可以「凭经验调参」，指令层不行：因为它的失败是渐进的、不报错的、且会在几代之后才显现。所以指令层合成必须配一套持续运行的监测（多样性四指标 + 去污染 + 教师-学生能力对比），这也是模块 04 存在的理由。

7把三种方法组合成一条可执行的合成管线

模块前面分别讲了 Self-Instruct、Evol-Instruct、Magpie。实践中它们不是三选一，而是流水线上的三个阶段——因为它们各自补的洞不同。

诊断：先问「我缺的是什么」，再决定用哪一段 缺「量与广度」 缺「特定领域/标签分布」 缺「难度」 │ │ │ ▼ ▼ ▼ ① Magpie 起量 ② 定向 prompt / SI ③ Evol-Instruct （零种子、多样性高） （输出优先控标签分布） （深度算子+广度算子） │ │ │ └────────────┬───────────┴─────────────────────┘ ▼ ④ 统一的去重（ROUGE-L） ▼ ⑤ 去污染（vs 测试集，模块 04）—— **对合成数据必做** ▼ ⑥ 混入真实数据（防坍塌） ▼ ⑦ 多样性四指标入看板（趋势监测）
阶段输入输出关键参数验收
① 起量无（或模板前缀）宽而浅的指令池生成条数领域熵、唯一 key 比
② 定向补缺缺口清单（领域/标签/场景）针对性样本输出优先的标签分布补完后各类别的样本数
③ 提难度已有池更深的变体算子集（必须含广度算子）可验证难度（基座答对率）
④ 去重全部候选去重后的池ROUGE-L 阈值（0.7 起）丢弃率（>70% 说明生成器同质化）
⑤ 去污染去重后的池干净的池n-gram 的 n（8–13）丢弃率 >1% 就要查
⑥ 混真实合成池 + 真实数据最终训练集合成占比上限合成占比是否超过约束
⑦ 监测每批数据看板相对变化阈值四个征兆是否有告警

直白说

这条管线里最容易被跳过、后果也最严重的是 ⑤ 去污染。前两个模块（词面、语义增强）不需要它——扰动训练集的句子不可能凭空造出测试集的内容。但指令层合成完全不同：教师模型很可能在预训练时见过你的测试集，于是它「凭记忆」生成的样本可能与测试集高度相似甚至相同。而这个失效的症状是「评测分数变好」，所以不会引起任何警觉。

严谨说

第二个容易跳过的是 ② 之前的「诊断」。很多团队直接从「用最新的那个方法造一批数据」开始，而不先问「我到底缺什么」。缺量、缺特定类别、缺难度，这三种缺口对应完全不同的方法与完全不同的验收标准。诊断的成本很低（统计一下各类别/各场景的样本数、看看模型在哪些子集上错得多），但它能避免「造了五万条数据，缺的那类还是只有十条」这种典型浪费。

关于第 ⑥ 步的合成占比，给一个务实的起点：合成数据不超过总量的 50%，且每一轮迭代都要重新混入真实数据（而不是「第一轮混过就行」）。模块的坍塌实验已经显示，只要每代都有真实数据注入，尾部就能被持续带回来。如果你发现「真实数据不够，混不到 50%」——那正是这条约束想告诉你的：你需要的是标注，不是更多合成。

8研究前沿与开放问题

  • 合成数据的缩放律：真实数据有 Chinchilla 式的缩放律（C21），合成数据没有。「加十倍合成数据」的收益曲线是什么形状、什么时候饱和、饱和点与教师能力的关系——这些都缺乏系统刻画。经验上收益饱和得比真实数据快得多，但没有定量规律。
  • 弱到强泛化：学生能否超过教师？Burns et al. 2023 的 weak-to-strong generalization 表明在某些设置下可以（学生的预训练知识 + 弱监督 > 弱监督本身），这挑战了「学生 ≤ 教师」的朴素结论。什么条件下成立、能超多少，是当前对齐研究的核心问题之一（C23）。
  • 坍塌的定量刻画：Shumailov et al. 2024 给出了现象与简化模型，但「混入多少比例真实数据能完全避免坍塌」「不同任务的坍塌速率差异」缺乏可操作的结论。工程上目前只能靠监测而非预测。
  • 难度的可验证代理：Evol-Instruct 的「难度伪装」问题需要可验证的难度度量。数学/代码有天然的可验证性（答案对错），开放式任务没有。把可验证性引入开放式指令数据的合成是活跃方向（与 RLVR 同源，C22）。
  • 合成数据的检测与标注：随着合成数据在网络上大量出现，「这段文本是不是模型生成的」变得重要——既为了避免用合成数据污染预训练语料（加剧坍塌），也为了溯源。水印与检测都不可靠，这是个开放的社会技术问题（C12/C14）。
