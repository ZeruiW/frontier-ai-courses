1回译：用两次翻译换一个新说法

back-translation（回译）是语义层增强的代表：把句子翻译到另一种语言，再翻回来。得到的句子通常语义相同、措辞不同。

原文 (zh): 这家店的菜非常好吃，服务也不错。 │ │ 正向翻译 (zh -> en) ▼ 中间 (en): The food at this restaurant is delicious, and the service is good. │ │ 反向翻译 (en -> zh) ▼ 回译 (zh): 这家餐厅的食物很美味，服务也很好。 ← 语义相同、措辞全变 为什么能保语义？因为「翻译」这个任务本身的训练目标就是**保持语义**。 为什么措辞会变？因为翻译不是双射——en 的一个句子可以对应多个 zh 表达， 反向模型只是选了其中一个（且解码策略决定选哪个）。

直白说

回译相对词面增强的最大优势是它在「语义空间」而不是「词面空间」操作。EDA 删掉一个「不」字不会有任何机制阻止它；而翻译模型如果丢掉了否定，正向翻译的 loss 就会很高——「保语义」这个约束是内建在模型里的。所以回译的标签保真度通常比 EDA 高一个档次。

严谨说

但它的失效方式更隐蔽。EDA 破坏标签时你能一眼看出来（句子变得不通顺）；回译产出的句子总是通顺的，即使语义已经漂移。「这家店不太干净」回译成「这家店比较干净」——句子完美，标签反了，而且你不看原文根本发现不了。通顺性给了它一种虚假的可信度，这是回译最需要防的一点。所以回译更需要自动的保真度检验（本模块第四节）。

回译的第二个代价是成本。它需要两次 seq2seq 推理，对每条样本、每个增强副本都要跑一遍。1000 条样本 × 4 个副本 × 2 次翻译 = 8000 次生成。这已经不是「几乎零成本」了——它与「用 LLM 直接改写」的成本进入同一量级（模块 03），而后者可控性更强。所以现实的选择常常是：要么用便宜的词面增强，要么直接上 LLM；回译处在一个不太经济的中间地带——除非你恰好有现成的高质量翻译模型且不想调 LLM。

2多样性从哪来：解码策略比中间语言更重要

一个常见误解是「换中间语言就能增加多样性」。实际上多样性的主要来源是反向翻译的解码策略。

多样性来源怎么控制效果代价
解码策略beam search → 采样（do_sample=True、top_p、温度）最主要：同一中间句能产出多个不同回译温度过高会语义漂移
中间语言（枢轴）zh→en→zh vs zh→de→zh vs zh→ja→zh中等：不同语言的表达约束不同需要多个翻译模型；小语种质量差
多跳zh→en→de→zh较高，但误差累积每跳都可能丢语义，保真度快速下降
beam 里取第 k 名取 beam 的 top-k 而非 top-1低（beam 的候选彼此很像）几乎免费

直白说

Edunov et al. 2018 在 NMT 的合成数据场景里给出了一个重要发现：用采样（或加噪的 beam）做回译，比用纯 beam search 更有效。原因是 beam search 倾向于产出「最安全」的翻译——所有回译结果都很像，多样性极低，模型学不到新东西。采样引入了多样性，代价是引入了噪声，而在合成数据的场景里这个交易是划算的（因为原文的标签仍然由原始样本给定）。

严谨说

但注意这个结论不能直接搬到分类任务的增强上。在 NMT 里，回译产生的是「合成的源句 + 真实的目标句」，噪声主要影响源侧、而目标侧仍然是干净的人类文本。在分类增强里，回译产生的是「新的输入 + 沿用的旧标签」——一旦语义漂移，标签就错了。所以分类增强应该用更保守的采样温度（比 NMT 场景低），并且必须配保真度检验。这是同一个技术在两个任务上取舍不同的好例子。

关于中间语言的选择有一条实用经验：语言距离越远，回译的措辞变化越大、语义漂移风险也越大。zh→en→zh 相对稳（英语资源最好、翻译质量最高）；zh→ja→zh 变化中等；zh→某个低资源语言→zh 则变化剧烈但常常已经漂了。先用 en 做枢轴，只有在多样性明显不足时才引入第二个枢轴语言——而且要为每个枢轴单独测保真度，别假设它们一样安全。

3回译什么时候会毁掉标签：四类高危场景

高危场景例子为什么危险
否定与双重否定「不是不好吃」→「还不错」（强度变了）；「没什么问题」→「有问题」（极性翻了）翻译模型对否定的处理本就是已知弱点，尤其中英之间否定结构差异大
程度与情感强度「还行」→「很好」；「有点贵」→「太贵了」细粒度情感/评分任务上直接改标签；二分类任务上可能还能忍
专业术语与实体「Transformer」→「变压器」→「transformer」（领域错了）；药名、型号、法条翻译模型没有领域约束，会按通用语义翻
数字、时间、单位「3 天内」→「within three days」→「三日内」（还行）；但「30%」→「三成」→「30 percent」可能丢精度数值型信息抽取任务会直接错

这四类的共同点是：它们都是「标签由局部的、语义敏感的片段决定」的情形。这和模块 01 的结论呼应——无论哪种增强，最危险的都是「标签由少数关键成分决定」的样本。所以模块 01 的保护思路在这里同样适用，只是实现方式不同：

  • 约束解码：让回译时某些词必须出现（force_words_ids，C50 模块 01 提到过）。可以保护实体与数字。
  • 占位符替换：翻译前把实体/数字替换成 <ENT_0>、<NUM_1> 这类占位符，翻译后再换回。这是工业界处理这个问题的标准做法，简单且有效。
  • 事后过滤：回译后检查关键成分是否还在（否定词数量、实体、数字），不通过就丢弃这个副本。丢弃比修正更可靠。
否定的奇偶性检查

特别提醒否定的处理，因为它是回译最容易翻车的地方且后果最严重。一个可操作的检查是：比较原文与回译的「否定词计数的奇偶性」——如果原文有 1 个否定词、回译有 0 个或 2 个，极性很可能变了，直接丢弃。这个检查极其粗糙，但它能挡住大部分致命案例，而成本几乎为零。notebook 会实现它并量化它挡住了多少破坏。「粗糙但零成本的过滤器」在数据管线里往往比「精细但昂贵的修正器」更值得先做。

4自动保真度检验：三个廉价判据

既然回译产出的句子总是通顺、无法靠「读起来对不对」判断，就必须有自动判据。三个从便宜到贵的层次：

判据怎么算能抓什么成本
① 关键成分一致性否定词计数、实体集合、数字集合、单位是否保持极性翻转、实体错译、数值失真几乎零
② round-trip 相似度原文与回译的 token 重叠（如 BLEU / chrF / Jaccard）语义大幅漂移（相似度过低）与无效增强（相似度过高=没变化）低
③ 模型一致性用一个已训练的分类器给原文与回译打分，看预测是否一致微妙的语义漂移中（需要一个模型）

直白说

判据 ② 有一个反直觉的用法：它是「双边」过滤器而不是「单边」的。相似度太低说明语义漂了（要丢），但相似度太高也要丢——因为那意味着回译几乎等于原文，这个副本没有提供任何新信息，只是把数据复制了一遍（还浪费了两次翻译的算力）。所以正确的做法是保留相似度落在一个中间带（如 Jaccard ∈ [0.3, 0.85]）的副本。

严谨说

判据 ③ 有个链式依赖问题要注意：你需要一个分类器来筛选增强数据，而这个分类器是用未增强的数据训的。这引入了一个偏差——被保留的增强样本会偏向「当前模型已经能正确分类的」，也就是信息量较低的那些。这在自训练/伪标签里是个已知问题（confirmation bias）。缓解办法是只用它做「明显不一致」的硬过滤（如两边预测相反且都很自信），而不是按置信度排序取 top-k。

把三个判据组合成一条流水线，顺序很重要：先跑最便宜的、能挡住最严重问题的。① 关键成分（挡致命错误，零成本）→ ② 相似度双边带（挡漂移与无效副本，低成本）→ ③ 模型一致性（可选，挡微妙漂移）。这个「先便宜后贵」的多阶段过滤节奏，和 C43 模块 04 的大规模质量过滤是同一个模式——在任何数据管线里都成立。

5释义模型：回译的更直接替代

回译是「用两次翻译间接实现释义」。既然目标是释义，为什么不直接用释义模型（paraphrase model）？

回译专门的释义模型LLM 改写（模块 03）
推理次数2 次1 次1 次
可控性低（只能调解码）中（可训练成特定风格）高（prompt 里直接约束）
保语义✅ 内建（翻译目标）✅ 内建（训练目标就是释义）🔶 靠 prompt 约束，可能不遵守
多样性中（靠采样）中高（可以要求「换一种更正式的说法」）
模型可得性翻译模型很多、质量高专门的释义模型较少、质量参差任何指令模型都能做
成本2× 生成1× 生成1× LLM 调用（更贵但更少次数）

从这张表可以看出技术路线的历史演变：回译在 2016–2020 年是主流，因为当时高质量翻译模型远比高质量释义/指令模型容易得到。而今天，「让 LLM 换一种说法」在可控性、多样性、实现简单度上全面胜出——你可以直接要求「保持情感不变、换成更口语的说法、不要改变任何数字」，这些约束在回译里根本无法表达。

所以本模块的一个诚实结论是：如果你今天有 LLM 可用，回译在大多数场景下已经不是最优选择。它仍然值得学，因为①它的思想（在语义空间而非词面空间做增强）是对的且会一直有用；②它的失效模式分析（否定、实体、数字）对 LLM 改写完全适用；③在没有 LLM 预算、但有现成翻译模型或需要完全离线的场景里，它是可行方案。把这一节当成「语义层增强的通用方法论」来学，而不是「回译这个具体技巧」。

6算一笔账：保真-多样权衡前沿

回译的两个旋钮（采样温度与相似度过滤带）共同决定你在保真-多样平面上的位置。这是本模块要让你亲手画出的东西。

\[\text{保留率} = \Pr\big[\text{关键成分一致} \wedge \text{sim} \in [\tau_{lo}, \tau_{hi}]\big]\]
温度保真度（过滤前）多样性（过滤前）过滤后保留率过滤后保真度
0.0（贪心/beam）高很低（副本几乎相同）低（多数因「太像」被丢）高
0.7中高中较高高
1.3低高低（多数因「漂移」被丢）中

这张表的关键在最后两列：过滤把不同温度下的「过滤后保真度」拉到接近的水平，代价是保留率不同。所以温度的作用不再是「保真 vs 多样」的直接权衡，而是「要生成多少候选才能得到一个可用副本」——也就是成本。

\[\text{有效成本/副本} = \frac{2 \times \text{生成成本}}{\text{保留率}}\]

这个公式让温度选择变成一个纯成本问题：选让「保留率 × 多样性」最大的那个温度。notebook 会把这条曲线扫出来。

最后给一个与模块 01 对比的成本量级（相对 EDA=1）：

方法相对算力成本典型保真度（过滤后）典型多样性何时选
EDA + 保护10.98+低-中算力受限；只需要正则化
AEDA11.00低要绝对安全的正则化
回译 + 过滤~1000（两次 seq2seq）0.97+中有现成翻译模型且需离线
LLM 改写 + 过滤~2000（含 API 费）0.95–0.99（取决于 prompt）高有 LLM 预算；需要可控性

把本模块浓缩成一句可迁移的智慧：语义层增强的可靠性不来自「生成得多好」，而来自「过滤得多严」。任何生成式增强都会产出一部分坏样本（回译会漂移、LLM 会不遵守约束），而你无法通过调生成来消除它——但你可以用几乎零成本的规则过滤把它们挡掉。「宽松生成 + 严格过滤」几乎总是优于「保守生成 + 不过滤」，因为前者的多样性上限更高而保真度由过滤保证。

7另一条路：不用增强样本当训练数据，而用它做一致性约束

本模块（以及整门课）的默认框架是：增强样本 + 沿用原标签 → 加进训练集。这个框架的致命弱点已经反复出现——一旦语义漂移，标签就错了，所以必须投入大量精力在保真度检验上。

但还有一条完全不同的用法，它从根上绕开了保真度问题：一致性正则（consistency training，Xie et al. 2020 的 UDA）。

\[\mathcal{L} = \underbrace{\mathcal{L}_{sup}(x_l, y_l)}_{\text{有标注数据的常规损失}} + \lambda \cdot \underbrace{\mathrm{KL}\big(f(x_u) \,\|\, f(T(x_u))\big)}_{\text{无标注数据上：原样本与增强样本的预测要一致}}\]

直白说

关键差别：第二项完全不用标签。它只要求「模型对 x 和 T(x) 给出一致的预测分布」。所以即使 T 偶尔改变了真实语义，你也没有断言一个错误的标签——你只是（错误地）要求两者一致，这个错误的代价远小于「往训练集里塞一条错标数据」。而且它能吃无标注数据，这在低资源场景下是巨大的优势。

严谨说

代价有三个。①需要无标注数据（通常不是问题——无标注文本几乎总是充足的）。②需要调 λ 与置信度阈值（UDA 会只在模型对 x 足够自信时才施加一致性约束，否则会强化错误）。③训练更复杂：每步要跑原样本与增强样本两次前向。但对「有大量无标注数据 + 少量标注」的场景，它通常显著优于把增强样本当训练数据。

增广式（本课默认框架）一致性正则（UDA 式）
增强样本的用法当作带标签的训练数据只用于「两次预测要一致」的约束
对保真度的依赖高（漂移=错标）低（不断言标签）
能否用无标注数据❌✅ 这是它的主战场
实现复杂度低（改数据即可）中（改损失函数与训练循环）
适合只有标注数据、增强可控无标注数据充足、增强不完全可靠

这条路线值得知道，因为它体现了一个更一般的设计思路：当你对某个信号的「正确性」没把握时，不要把它当成硬监督，而要把它降级成一个更弱的约束。同样的模式在别处反复出现——伪标签用置信度阈值筛（不自信就不用）、RLHF 用偏好序而非绝对分数、弱监督用多个噪声源投票。「把不可靠的信号降级使用」比「努力让它变可靠」往往更划算。

8三种语义层手段的横向选择

把「换个说法」这件事的三种实现放在一起，给一个可执行的选择规则。

维度回译释义模型LLM 改写
最少依赖两个方向的翻译模型一个释义模型一个指令模型（或 API）
每副本推理次数211
能否指定约束❌ 只能调解码🔶 需要训练成特定风格✅ prompt 里直接写
保语义的机制翻译目标内建释义目标内建靠 prompt，可能不遵守
失效模式否定/实体/数字漂移同左 + 释义模型质量参差同左 + 不遵守约束、风格同质化
离线可行✅✅🔶（需自建模型）
需要的过滤关键成分 + 双边相似度同左同左 + 约束遵守性检查

直白说

选择规则可以压缩成三句话：①能调 LLM 且量不大 → 直接 LLM 改写（可控性碾压，且能表达「保持情感、不改数字、换成更口语」这类约束）；②必须离线或量极大 → 回译（翻译模型好找、质量稳定、可自建）；③有现成的高质量释义模型 → 用它（少一次推理）。注意三者的过滤流水线是共用的——这就是为什么本模块花最大篇幅讲过滤而不是讲生成。

严谨说

还有一个跨越三者的实用建议：不要只用一种。不同手段的失效模式不同（回译容易丢否定、LLM 容易不遵守约束、释义模型容易风格单一），混合使用能让单一失效模式的影响被稀释，同时提高整体多样性。混合的成本几乎为零（同一套过滤器），收益是实实在在的鲁棒性。这与集成学习「不同错误模式的模型混合更稳」是同一个道理。

对 LLM 改写要特别加一条检查：约束遵守性。你在 prompt 里写「不要改变任何数字」，模型有相当概率还是改了——而这个失效不会被回译的关键成分检查之外的任何东西发现。所以用 LLM 改写时，prompt 里写的每一条约束，都要有一个对应的自动检查。「写了约束就以为模型会遵守」是 LLM 时代新增的一类天真，模块 03 会再遇到它。

9一条可直接照抄的回译管线

把本模块的结论压成一段伪代码。它的形状对任何生成式增强都适用，只需替换第 ② 步的生成器。

for x, y in train_only:                     # ⚠️ 只对训练集做（模块 04 的铁律）
    protected = extract_protected(x)         # ① 实体/数字 -> 占位符，翻译前替换
    x_masked  = mask_entities(x, protected)

    for _ in range(n_candidates):            # ② 宽松生成：温度调到甜点区（本模块第 4 节）
        z  = translate(x_masked, src->pivot, temperature=0.8, sample=True)
        x2 = translate(z, pivot->src, temperature=0.8, sample=True)
        x2 = unmask_entities(x2, protected)  # 换回实体与数字

        # ③ 三级过滤：先便宜后贵，任何一级不过就丢弃（**丢弃比修正可靠**）
        if not key_components_match(x, x2):  continue     # 否定词数 / 实体集 / 数字集
        sim = jaccard(x, x2)
        if not (LO <= sim <= HI):            continue     # **双边**：太低=漂移，太高=无效
        if not model_consistent(x, x2):      continue     # 可选：两边预测明显相反则丢

        emit(x2, y)                          # ④ 沿用原标签
        break                                # 每条原样本取 1 个可用副本就够

log_stage_drop_rates()                       # ⑤ 分阶段丢弃率 = 诊断报告（模块 04）
这一步对应本模块哪一节调错了会怎样
① 占位符替换四类高危场景实体被错译成另一个实体，且关键成分检查也发现不了（因为集合仍是「一个实体」）
② 温度多样性来自解码策略太低 → 副本几乎等于原文（白花两次翻译）；太高 → 保留率崩、成本翻倍
③ 三级过滤自动保真度检验少了双边中的上界 → 大量无效副本混进训练集
④ 沿用原标签回译的基本假设—（这正是保真度检验存在的理由）
⑤ 分阶段统计模块 04只知道「留下了 60%」，不知道该调温度还是该调过滤带

直白说

这段伪代码里有个细节值得点出：第 ③ 步「任何一级不过就丢弃」而不是「尝试修正」。修正听起来更省（不浪费已生成的样本），但它有两个问题：①修正逻辑本身可能引入新错误（把回译里丢失的否定词加回去，位置往往不对）；②被修正的样本质量分布与正常样本不同，等于往训练集里塞了一批「人工缝合」的怪样本。丢弃是干净的，而生成成本远低于「修正错了」的代价。

严谨说

另一个细节是 break：每条原样本只取一个可用副本。为什么不多取几个？因为同一条原样本的多个回译副本彼此高度相似（它们都受同一个原文约束），边际多样性收益很快趋零，而每一个都要占训练集的一个位置、稀释原始样本的权重。「宽度优先」（每条原样本 1–2 个副本、覆盖更多原样本）通常优于「深度优先」（少数原样本各造十个副本）。

把整个模块的方法论提炼成一句可迁移的话：生成式增强的工程重心不在生成端，而在过滤端与统计端。生成端你能调的只有温度与枢轴（旋钮很少、效果有限）；过滤端决定了最终数据的保真度（也就是能不能用）；统计端决定了你能不能诊断问题、能不能回答「该改哪一步」。看到一份增强管线的代码，先看它的过滤与日志写了多少行——那才是它的质量水位。

10研究前沿与开放问题

  • 采样回译的最优噪声水平：Edunov et al. 2018 在 NMT 上发现「加噪的 beam」最好，但那是合成源句的场景。在分类增强（合成输入 + 沿用标签）里最优噪声应该更低，具体多低缺乏系统研究。这是个边界清晰、容易做的实证问题。
  • 一致性正则化 vs 数据增广：UDA（Xie et al. 2020）不是把回译样本当额外训练数据，而是要求「原样本与回译样本的预测分布一致」（KL 项）。这在半监督场景下利用了无标注数据，且不依赖标签保真（因为不用标签）。这条路线与本课主线互补，值得知道它绕开了保真度问题。
  • 过滤器的偏差：用模型一致性做过滤会引入 confirmation bias（保留的都是模型已会的）。这与自训练/伪标签的经典问题同源。如何设计不引入这种偏差的过滤器（或量化它的影响）仍是开放的。
  • 低资源语言的回译：回译最需要的场景（低资源语言的分类任务）恰恰是翻译模型最差的场景——这是一个结构性的鸡生蛋问题。用多语言模型的零样本翻译、或用高资源语言做枢轴，效果都不理想。
  • 释义的「语义等价」到底怎么定义：所有语义层增强都假设存在「保持语义」这个操作，但语义等价在语用层面并不清晰（「还行」与「很好」在评论语境里是否等价？取决于任务）。这个模糊性是保真度检验只能靠任务特定规则的根本原因。
