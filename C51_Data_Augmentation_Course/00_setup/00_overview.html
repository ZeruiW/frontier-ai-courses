1这门课讲什么

欢迎来到 文本数据增强与合成数据工程。这门课回答一个看起来简单、实际上非常容易做错的问题：标注数据不够时，怎么「造」出更多数据，并且能证明造得有用。

先说清它为什么值得单独一门课。图像增强是件相对安全的事——旋转一张猫的照片，它还是猫；加点噪声，标签不变。文本不是这样：把「这家店不好吃」里的「不」删掉，标签从负面变成正面；把「他给了她一本书」的词序打乱，语义可能崩掉；用同义词替换「银行」，可能把「金融机构」换成「河岸」。文本的离散性与组合性，让「增强」与「破坏」之间的界限非常薄。

直白说

所以本课的核心不是「教你十种增强技巧」——那些在网上都能查到。核心是「怎么判断一个增强是不是真的有用」。这个判断需要三个独立的检验：①有效性（下游指标真的涨了，且涨幅超过噪声）；②保真度（增强后的样本标签仍然正确）；③多样性（新样本带来了新信息，不是原样本的近似副本）。三者缺一，你的「增强」很可能是在给模型喂噪声或喂重复。

严谨说

这三个检验分别对应本课的三条技术线。保真度要求你能量化「标签是否被破坏」——需要标签保持性检验与人工/模型审核（模块 04）。多样性要求你能量化「新样本有多新」——需要 distinct-n、嵌入覆盖、self-BLEU 这类度量（模块 04）。有效性要求你能做出可信的对照实验——需要配对检验、学习曲线、以及最关键的一个对照组：「同样的算力/人力预算下，直接加真实数据会不会更好」（模块 05）。这个对照组几乎总是被省略，而它常常给出否定答案。

学完你应当能回答这类问题：EDA 的四个操作里哪个最危险？回译为什么能保语义、什么时候会失效？self-instruct 的种子池该多大、怎么防止模式坍塌？增强强度（α）与数据量是什么关系、为什么小数据集才受益？「多样性指标涨了」能不能推出「有用」？怎么设计一个能证伪「增强有效」这个假设的实验？什么时候用增强还不如去标注 500 条真实数据？——并且能在 numpy 里把每种增强、每个多样性度量、每套检验都实现一遍。

2三个层次：词面 / 语义 / 指令

按「改动发生在哪一层」把文本增强分成三类。层次越高，保真度越好，成本越高。 ① 词面层 (lexical) —— 直接改字符与词 同义词替换 / 随机插入 / 随机交换 / 随机删除 (EDA) / 字符噪声 / token dropout 成本: 几乎为零（查词典 + 采样） 保真: ⚠️ 脆弱（否定词、专有名词、程度副词一改就变标签） 多样: 低（新样本与原样本的词面重叠很高） 适合: 小数据集（<1k 条）的分类任务；作为轻量正则 ② 语义层 (semantic) —— 保语义、换表达 回译 (back-translation) / 释义模型 / 句法变换（主被动、语序） 成本: 中（需要翻译或释义模型的推理） 保真: ✅ 较好（语义被显式保持） 多样: 中（表达变了，信息量没变） 适合: 中等数据量；对措辞鲁棒性有要求的任务 ③ 指令层 (instructional) —— 让 LLM 直接造新样本 self-instruct / evol-instruct / Magpie / 教师蒸馏 / 场景化生成 成本: 高（LLM 调用） 保真: 🔶 取决于教师；**会继承教师的偏差** 多样: ✅ 可以很高（能造出训练集里根本没有的场景） 适合: 指令微调 / 无标注冷启动 / 长尾场景补全 关键区别：① ② 是「把已有样本换个说法」（信息量不增加）； ③ 是「造出新样本」（信息量可以真的增加，但来源是教师模型的知识）。
层次本质信息量最大风险
词面对原样本做局部扰动不增加（同一条信息的多个视角）标签被破坏而你不知道
语义换表达、保语义不增加释义失真（尤其专业术语、否定、数字）
指令从教师模型的知识里采样新样本可以增加（但上限是教师）继承教师偏差 + 模式坍塌 + 数据污染

「信息量不增加」这一点必须想清楚，因为它决定了增强的收益上限。词面与语义增强本质上是一种正则化——它告诉模型「这些不同的表面形式对应同一个标签」，从而减少对表面特征的过拟合。所以它在小数据集上收益明显，在大数据集上收益趋零甚至为负（大数据集本身就包含了足够的表面多样性，再增强只是在加噪声）。如果你有十万条标注数据还在纠结要不要做 EDA，答案基本是「不要」。

4四种常见的误用（先认出它们）

在进入具体技术之前，先把最常见的四种误用摆出来。它们的共同点是：看起来都很合理，也都会产生「涨分」的观察，但结论站不住。本课后面每个模块都会回到它们。

误用表现为什么错在哪个模块修
① 先增强后划分在整个数据集上做增强，然后随机切训练/测试同一条原样本的副本分落两边，测试集已经泄漏，所有指标虚高模块 04
② 只比 C vs A「增强组 86 分，baseline 84 分，所以增强有效」没有排除「样本更多 / 训练更久」这个混淆——把数据复制五遍也常常涨分模块 05
③ 单个种子跑一次，看到高 1.2 分就下结论小数据集微调的种子标准差就有 2–3 分，单次结论可能完全相反模块 05
④ 只看多样性「distinct-2 涨了，说明增强有效」完全随机的文本多样性最高、却毫无价值；而且多样性指标可以被刷模块 04

直白说

这四种误用不是「新手才犯的错」——它们在已发表的论文里也非常普遍。原因不是作者不严谨，而是确认性设计比证伪性设计更省事、也更容易得到「好看」的结果：不做复制对照就少跑一组实验；只跑一个种子就少花五倍时间；不做真实数据对照就不用去标注。每一步偷懒都是局部理性的，加起来就是一个不可信的结论。

严谨说

本课的应对不是「你要更严谨」这种空话，而是把纪律变成可执行的检查清单与可运行的代码：一个 assert_no_test_ids() 断言挡住误用 ①；一个「四臂实验 + 配对 bootstrap」的函数挡住 ② 和 ③；一套「保真度硬门槛 + 多度量交叉」挡住 ④。纪律只有变成默认执行的代码，才会真的被遵守——这与 C48 把运维纪律写成断言、C50 把 Trainer 的隐式依赖写成校验器，是同一个思路。

还有一个不算「误用」但值得先破除的期待偏差：很多人来学数据增强，是希望得到「一套万能的、能让任何任务涨分的技巧」。这套东西不存在。真实的结论是分场景的：小数据 + 昂贵标注 + 长尾类别 + 零标注冷启动 → 增强非常有用；中等以上数据 + 廉价标注 → 大概率不如去多标注一些。本课会把这条分界线量化出来（模块 05 的「等价真实数据量」）。能诚实地说出「你这个场景不该做增强」，本身就是这门课的价值之一。

5方法论：每个增强都过三重检验

本课全程 纯 numpy / 标准库、CPU、不联网。没有真实的翻译模型、没有 LLM API——那怎么学增强？

直白说

关键洞察是：本课要教的判断力，几乎不依赖增强器的具体实现，只依赖「增强前后的样本对」。所以我们用可控的模拟增强器——一个带「失真强度」参数的假翻译器、一个带「教师偏差」参数的假 LLM、一个带「坍塌倾向」参数的假生成器。因为参数可控，你能做真实环境里做不到的实验：比如「把教师偏差从 0 调到 0.3，看学生模型的偏差怎么变」，或者「让生成器逐代坍塌，看多样性指标什么时候先报警」。

严谨说

三重检验会被实现成三个可复用的函数，贯穿全课：fidelity(pairs)——增强后标签仍正确的比例（用可验证的规则标签，如「含否定词则为负面」，这样标签是可精确判定的）；diversity(texts)——distinct-n / self-BLEU / 嵌入覆盖；effectiveness(clean, augmented)——在一个可训练的小模型上做配对检验。每个模块的每种增强，都要过这三关并给出数字。

本课有一条贯穿全篇的立场，值得先说明：它对数据增强持「有条件的怀疑」态度。不是因为增强没用——它在小数据、低资源、长尾场景下确实有用；而是因为增强的文献里充满了「在小数据集上涨了 1 分」这类不可靠结论（种子方差就有 2–3 分，C49 模块 03 讲过）。本课要给你的不是「增强很棒」的信念，而是「怎么在自己的数据上判断它到底有没有用」的能力——包括接受「没用」这个答案。

6环境与运行

本课全程 纯 numpy + 标准库、CPU 可跑，不需要 GPU、翻译模型、LLM API 或联网。所有 notebook 在 CPU 上实跑验证、assert 0 失败。

pip install -r requirements.txt      # numpy / pandas / jupyterlab / ipykernel
jupyter lab                          # 打开 00_setup/00_environment_check.ipynb
你需要本课怎么处理
同义词词典（WordNet 等）用一个几十词的迷你同义词表，含刻意埋入的陷阱（一词多义、程度副词）
翻译模型（回译）可控失真的模拟翻译器：distortion 参数决定语义漂移程度
LLM（指令合成）可控的模拟教师：bias / diversity / collapse_rate 三个参数
嵌入模型（多样性）用字符/词袋 + 随机投影作为廉价嵌入；度量的性质与真实嵌入一致
下游任务与标注用规则可判定的合成任务（如「含否定词 → 负面」），这样标签保真度可精确计算

最后说明本课与相邻课程的分工：C21（大规模预训练）讲预训练语料的配比与合成数据在预训练中的角色；C43（数据工程）讲 PB 级去重/过滤/流式的工程手艺；C14 讲合成数据的理论与生成媒体评测；C10 讲测量科学与标注质量。本课聚焦在「有标注任务的训练集不够用时，怎么造与怎么验」这个具体问题上，并把「造」的每一步都接上「验」。
