1从词法到语义：为什么需要 embedding

检索的第一个、也是最根本的问题是：怎么让机器判断两段文本『意思相近』？传统检索的答案是看词的重叠——你查「汽车价格」，它找含「汽车」「价格」的文档。这套词法检索（lexical retrieval）几十年来很能打，但有个致命盲区：同义改写。查「汽车」，它认不出「automobile」「轿车」「四轮代步工具」；查「如何降低血压」，它匹配不到「reducing hypertension」。

现代检索的答案是 embedding（嵌入）：把每段文本映射成一个稠密向量，让语义相近的文本，向量也相近。于是「汽车」与「automobile」尽管一个字都不重叠，它们的向量却几乎同方向；检索从「字面匹配」升级成了向量空间里的近邻查找。这一跃迁是 RAG、语义搜索、推荐召回的共同地基。

直白说

把 embedding 想成给每段文本在一张巨大的「语义地图」上标一个坐标：意思相近的句子落在同一片区域，毫不相关的句子隔得很远。检索一段文本，就是在这张地图上找离它最近的几个点。词法检索看的是「用词一不一样」，语义检索看的是「站得近不近」。

严谨说

形式上：一个编码器 $f:\text{text}\to\mathbb{R}^d$ 把文本映到 $d$ 维向量。好的编码器满足：若 $a,b$ 语义相近，则相似度 $\text{sim}(f(a),f(b))$ 高。检索即 $\arg\max_{d\in\mathcal{D}}\text{sim}(f(q),f(d))$。本课不训练 $f$（那是表示学习的主题），而是聚焦有了向量之后的相似度、检索、索引与评测——这条又长又值钱的流水线。

这个从「字面」到「语义」的跃迁，背后有一个深刻的假设值得点明：意义可以用几何来编码——具体说，是分布假设（distributional hypothesis）：「一个词的意义由它出现的上下文决定」（Firth 1957）。如果「汽车」和「automobile」总出现在相似的语境里（道路、引擎、驾驶），那么任何从语境学习表示的模型，都会把它们映到相近的向量。embedding 不是凭空给文本编号，而是把「语境上的可替换性」沉淀成了「几何上的接近」。这也解释了它的能力边界：embedding 擅长它在训练语料里见够了上下文的概念，而对罕见实体、专业术语、新造词往往编不准——因为它没见过足够的语境去定位它们。这个边界正是后面 BM25 与混合检索的用武之地。

一句话定调本模块：embedding 把『语义相近』这件玄学，变成了『向量距离』这件可计算的事。一旦语义变成了几何，检索就成了几何问题——找近邻。本模块先讲清这套几何（相似度、归一化），再讲它与词法检索（BM25）各自的强弱，最后讲为什么实战常把两者混合。这条『语义→几何→近邻』的链路，是整门课（乃至所有向量检索、推荐召回、聚类）的共同地基。

2相似度：点积、余弦、归一化

相似度：点积、余弦、归一化

有了向量，怎么量化「近」？最廉价的是 dot product（点积）：

\[a\cdot b=\sum_{i=1}^{d}a_i b_i=\|a\|\,\|b\|\cos\theta\]
它同时混入了两个信息：两向量的方向是否一致（$\cos\theta$）和它们的模长（$\|a\|,\|b\|$）。点积是注意力分数、最大内积搜索（MIPS）的核心运算，因为它就是一次向量乘加，极快。

但对语义检索，模长往往是噪声：一个词的句子和一个长段落，即便意思一样，模长可能差很多；我们要的是方向（意思），不是长度。于是有了 cosine similarity（余弦相似度）——把模长除掉，只留方向：

\[\cos(a,b)=\frac{a\cdot b}{\|a\|\,\|b\|}\in[-1,1]\]

余弦 = 1 表示完全同向（最相似），0 表示正交（无关），-1 表示反向。它对向量模长不敏感，这正是语义检索想要的：只问「意思像不像」，不问「文本长不长」。

一个极其常用的工程技巧是 L2 normalization（L2 归一化）：预先把每个向量除以自身的 L2 范数，让所有向量落到单位球面（模长都为 1）。归一化之后，点积直接等于余弦相似度——省掉了每次检索都要算分母的开销。更妙的是，单位向量上欧氏距离与余弦相似度给出完全相同的近邻排序：

\[\|a-b\|^2=\|a\|^2+\|b\|^2-2a\cdot b=2-2\cos(a,b)\quad(\text{当}\ \|a\|=\|b\|=1)\]

直白说

归一化就是「把所有向量拉到同一个长度，只比方向」。这样一来，『点积最大』『余弦最大』『欧氏距离最小』三件事完全等价——这给了索引极大的自由：很多向量库内部用欧氏距离实现，照样能服务余弦检索。

严谨说

严谨地说：上式表明在单位球面上 $\|a-b\|^2=2-2\cos(a,b)$ 是 $\cos$ 的单调减函数，故 $\arg\max\cos=\arg\min\|a-b\|$。所以归一化后，最大内积搜索（MIPS）= 最近邻搜索（NNS），FAISS 等库正是借此把余弦检索化归为它高度优化的 L2 检索。

那为什么不直接用欧氏距离、非要绕道余弦？关键在模长承载的信息对语义检索是干扰。在很多 embedding 里，向量模长与「文本长度」「词频规模」「该文本有多『典型』」相关，而与「讲的是什么主题」无关。两段都在讲量子物理的文本，一长一短，欧氏距离可能很大（因为模长差很多），余弦却很小（方向一致）——后者才是我们要的「同主题」。所以语义检索几乎总用余弦（或归一化后的点积/欧氏，三者等价）。反过来，当模长确实有意义时（某些推荐场景下模长编码了『热度』），才会直接用点积/MIPS——这时归一化反而会抹掉有用信息。选哪种相似度，本质是在问：模长对我的任务是信号还是噪声？

别忘了那个 +1e-12：归一化要除以范数，零向量（或近零向量）会除出 nan/inf。实现里永远写 v / (norm + eps)。这是检索代码最常见的低级 bug 之一，notebook 第 2 节会专门验证它。空文档、全停用词文档都可能产出近零向量，生产中务必兜住。

3玩具 embedding：没有神经网络也能造语义向量

玩具 embedding：没有神经网络也能造语义向量

本课不训练神经编码器，但我们需要有语义结构的向量来驱动后面所有检索实验。怎么在纯 numpy 里确定性地造出「意思近 → 向量近」的玩具 embedding？两条朴素但有效的路：

  • 哈希词袋（hashing bag-of-words）：把每个词哈希到固定维度的某些坐标上 +1，整段文本的向量是其词向量之和。共享词多的文本，向量自然接近。简单、确定、零训练，足以演示相似度与检索机制。
  • 共现/主题构造：人工指定若干「主题维」，按文本属于哪些主题给相应维赋权。能精确控制「哪些文档该相似」，便于设计可验证的练习。

这类向量当然没有真实 Sentence-BERT 的语义深度——它抓不住「汽车≈automobile」这种跨语言同义（除非我们手工编码进去）。但请记住本课的立场：我们要练的是『有了向量之后』的相似度、索引、重排、评测，而非向量本身怎么学。玩具 embedding 在结构上与真实 embedding 完全一致（都是 $\mathbb{R}^d$ 里的点、都用余弦比近邻），只是语义质量不同。把流水线练扎实，换上真实 embedding 立刻就能用。

还有一个常被混淆的点要厘清：真实的句向量并不是把词向量简单相加。Sentence-BERT 等模型先用 Transformer 对整句做上下文编码（每个词的向量都看过全句），再做池化（pooling，常用 mean-pooling 或取 [CLS]）得到句向量——所以它能区分「狗咬人」与「人咬狗」这类词相同但语义相反的句子，而我们的哈希词袋不能（它对词序完全无感）。我们的玩具 embedding 在这一点上是退化的：它只编码「出现了哪些词」，丢掉了词序与上下文。这对演示相似度、索引、评测的机制完全够用（机制不关心向量怎么来），但你要清楚真实系统在「向量怎么来」这一步做了多得多的工作。

一个有用的心智校准：embedding 的『质量』和『用法』是两件正交的事。质量（向量到底多懂语义）由表示学习决定、年年在进步；用法（怎么用向量做检索、索引、评测）是本课的主题、十年不变。我们冻结前者（用玩具向量），把后者学透——这正是『从零搭全栈』的精髓。换上真实 embedding，本课的每一行检索/索引/评测代码都一字不用改。

4词法检索的王者：BM25

词法检索的王者：BM25

在为语义检索欢呼之前，必须严肃对待它的老对手——BM25。这是个没有任何神经网络、不需训练的词法打分函数，却是检索领域几十年来最难击败的强基线：很多号称 SOTA 的稠密检索器，在跨领域评测（BEIR）上仍打不过它。理解 BM25 强在哪，才能理解语义检索的真正价值边界。

BM25 给查询 $q$ 与文档 $d$ 打分，核心是对查询里每个词 $t$ 的贡献求和。每个词的贡献由三部分相乘：

\[\text{BM25}(q,d)=\sum_{t\in q}\underbrace{\text{IDF}(t)}_{\text{词有多稀有}}\cdot\frac{\overbrace{tf(t,d)}^{\text{在 }d\text{ 里多频繁}}\,(k_1+1)}{tf(t,d)+k_1\!\left(1-b+b\,\frac{|d|}{\text{avgdl}}\right)}\]

拆开看这三个设计，每个都对应一个朴素直觉：

  • IDF（逆文档频率）：log((N-df+0.5)/(df+0.5)) 量级——一个词在越少文档里出现（越罕见），它就越有区分力、权重越高。于是 the/of 这类到处都是的词几乎零贡献，而专有名词、罕见术语权重很高。
  • 词频饱和（saturation）：分子分母里的 $tf$ 让词频贡献递增但有上限。一个词出现 10 次当然比出现 1 次相关，但不该比出现 5 次相关性翻倍——$k_1$ 控制这条饱和曲线的弯度。这是 BM25 胜过朴素 TF-IDF 的关键。
  • 文档长度归一化：(1-b+b·|d|/avgdl) 抵消「长文档天然词频高」的偏置——否则检索会一味偏向长文档。$b\in[0,1]$ 控制归一化强度。

直白说

BM25 的精神是：罕见词比常见词金贵，但同一个词多出现几次的边际价值递减，而且别让长文档占便宜。三条朴素直觉拼出一个惊人耐打的公式——它不懂语义，却把『关键词匹配』这件事做到了极致。

严谨说

$k_1$（典型 1.2–2.0）调词频饱和速度：$k_1\to0$ 退化为只看词在不在（布尔），$k_1\to\infty$ 退化为线性 TF。$b$（典型 0.75）调长度惩罚：$b=0$ 不惩罚长文档，$b=1$ 完全按长度归一。这两个超参数几乎不用怎么调就很稳，是 BM25 实用性的一部分。

BM25 还有一个常被低估的工程优势：它天然配合inverted index（倒排索引）。倒排索引把语料组织成「词 → 含该词的文档列表」的映射，于是给一个查询打分时，BM25只需扫描含查询词的那些文档（而非全库），且每个词的 IDF、每个文档的长度都能预计算。这让 BM25 在十亿级文档上仍能毫秒级响应——而这套倒排+打分的架构，正是 Lucene/Elasticsearch 等搜索引擎几十年的基石。相比之下，稠密检索要靠上一节的归一化 + 矩阵乘 + ANN 索引（下一模块）才能达到类似规模，两条技术栈截然不同。

BM25 出自 Robertson 等的概率检索框架（见 references 的 Robertson & Zaragoza 2009）。它和倒排索引（inverted index）是经典搜索引擎的两大支柱：倒排索引让你只需扫描含查询词的文档，BM25 给这些文档打分排序。即便在 LLM 时代，它依然是 RAG 检索里不可或缺的一路——别因为它『老』就轻视它。

5语义 vs 词法：各自的盲区

语义 vs 词法：各自的盲区

现在把两位选手放上擂台。它们的强弱恰好互补，这不是巧合，而是它们看问题的角度根本不同：

维度词法检索（BM25）语义检索（embedding）
同义改写抓不住（汽车≠automobile）强（向量近）
罕见实体/术语/代码符号强（精确匹配）弱（embedding 编不准罕见词）
精确关键词/数字/型号强（一字不差）中（可能被语义平滑掉）
需要训练/模型不需要（开箱即用）需要好的编码器
可解释性高（命中了哪些词）低（向量黑盒）
跨语言弱强（若编码器多语）

一个具体例子最能说明问题。查询「RoPE 位置编码」：语义检索可能召回大量讲「位置编码」的相关段落（好），但也可能漏掉那篇标题就是「RoPE」却没怎么展开解释的关键论文（embedding 把罕见缩写 RoPE 编得不准）；而 BM25 会精确命中所有含「RoPE」的文档（好），但对只说「rotary embedding」不提「RoPE」的同义文档视而不见。两者都会漏，但漏的不是同一批——这正是混合检索的根本动机。

一个反复让人栽跟头的误区：『上了 embedding 就可以扔掉 BM25』。大量实证（BEIR）表明，在专业领域、含大量实体/代码/数字的语料、或编码器没见过的新词上，纯语义检索常常输给 BM25。稠密检索不是词法检索的替代品，而是互补品。把 BM25 当成可以抛弃的旧东西，是 RAG 工程里代价高昂的常见错误。

6混合检索：让两者取长补短

混合检索：让两者取长补短

既然语义与词法各有盲区、且漏的不是同一批，自然的想法就是把两路结果融合——hybrid retrieval（混合检索）。这几乎是当下生产级 RAG 的默认配置。融合有两条主流路线：

  • 分数加权：把两路的分数各自归一化（min-max 或 z-score）到可比区间，再加权求和 α·sem + (1-α)·lex。直接，但难点在归一化——余弦分数在 $[-1,1]$、BM25 分数无上界，量纲天差地别，归一化方式一变结果就抖。
  • 倒数排名融合 RRF：彻底绕开分数，只用名次。一个文档的融合分 Σ 1/(k + rank)（在每一路里的名次取倒数再求和，$k$ 常取 60）。无需归一化、对分数量纲免疫、异常稳健——所以是混合检索的默认选择（详见模块 03）。

为什么 RRF 这么受欢迎？因为它把一个脆弱的数值问题（怎么把两种不可比的分数对齐）换成了一个稳健的序问题（谁排得靠前）。名次是天然可比的：不管 BM25 给 38.5 分还是余弦给 0.81 分，「这篇在 BM25 里排第 2、在语义里排第 5」是确定无歧义的。融合分只奖励「在多路里都排得靠前」的文档——而那往往正是真正相关的文档。notebook 会从零实现分数加权与 RRF 两种融合，并在一个语义与词法各有盲区的小语料上，验证混合检索的召回严格优于任何单路。

一个值得内化的更深的点：融合之所以有效，前提是两路犯的错不相关。如果语义和词法漏的是同一批文档，融合不会带来任何提升（融合只在『一路漏了但另一路抓到』时才赚）。语义（看意思）和词法（看字面）恰恰是两种正交的视角，它们的错误高度不相关——这才是混合检索几乎总能涨点的根本原因。这个洞察会在下一步推广：不只融合两路，还可以融合多个不同 embedding、不同 chunk 粒度、不同检索器的结果，只要它们的错误足够不相关。集成（ensemble）的智慧在检索里同样成立。

记住这个一句话结论：语义检索抓『意思』，词法检索抓『字面』，混合检索两者都要。RAG 实战里，『先 BM25 + 稠密双路召回，再 RRF 融合，再 cross-encoder 重排』是一条久经考验的强基线——本课模块 01→02→03 正是把这条流水线逐段搭出来。融合的前提是『两路犯的错不相关』，这也是为什么正交的语义+词法组合几乎总能涨点。

7从单查询到批量：检索的向量化

从单查询到批量：检索的向量化

最后讲一点把上述数学落成高效代码的工程。检索的核心运算是「一个查询向量 vs 全库向量的相似度」，朴素写法是 for 循环逐个算余弦，但这慢得离谱。正确写法是向量化：把全库 $N$ 个向量堆成矩阵 $\mathbf{D}\in\mathbb{R}^{N\times d}$，查询 $q\in\mathbb{R}^d$，则所有相似度一次矩阵乘搞定：

\[\mathbf{s}=\mathbf{D}q\in\mathbb{R}^{N}\quad(\text{若 }\mathbf{D},q\text{ 已 L2 归一化，}\mathbf{s}\text{ 即全部余弦})\]

再用 np.argsort(-s)[:k] 取 top-k。批量查询则是矩阵-矩阵乘 Q @ D.T（$Q\in\mathbb{R}^{m\times d}$ 得 $m\times N$ 的相似度矩阵）。这背后是 BLAS 高度优化的 GEMM，比 Python 循环快几个数量级——这也是为什么「先归一化、再矩阵乘」是检索的标准姿势。

直白说

一句话：别写循环，写矩阵乘。把『查询 vs 每条文档』想成『一个向量乘一个矩阵』，一次算出所有相似度，再排序取前几名。归一化放在建库时一次做完，在线检索就只剩一次矩阵乘加一次排序。

严谨说

复杂度：暴力检索是 $O(Nd)$ 的矩阵乘 + $O(N\log k)$ 的部分排序。$N$ 小时这快得很；但当 $N$ 上到百万、千万、上亿，$O(Nd)$ 就成了瓶颈——这正是下一模块近似最近邻登场的理由：用次线性的索引把『扫描全库』变成『只看一小部分』。

注意一个常被忽略的细节：取 top-k 不必完全排序整个相似度数组。np.argpartition 能在 $O(N)$ 时间内把前 $k$ 个挑出来（不保证它们内部有序），再只对这 $k$ 个排序，把代价从 $O(N\log N)$ 降到 $O(N + k\log k)$。这类小优化在 $N$ 大时很值钱，也是真实检索库里的常规操作。notebook 会同时给出 argsort 与 argpartition 两种写法并对拍结果一致。

最后值得一提的是内存布局与精度对检索速度的隐形影响。库矩阵 $\mathbf{D}$ 最好是连续、行优先（C-contiguous）的 float32：连续内存让 BLAS 的 GEMM 跑满带宽，而 float32 相比 float64 减半内存、几乎不损检索精度（近邻排序对这点数值误差不敏感）。真实向量库甚至用 float16/int8 进一步压缩（以可控的召回损失换内存与带宽）——这已经和下一模块的量化（PQ）思想接壤了。把这些放在心上：检索的性能不只在算法复杂度，也在数据怎么摆、用什么精度。

8研究前沿与开放问题

研究前沿与开放问题

  • 更强、更小、更专的编码器：从 Sentence-BERT 到 E5、BGE、GTE 等指令微调的通用 embedding，再到领域专用编码器。如何用对比学习 + hard negatives 训出既通用又抓得住罕见实体的向量，仍是活跃前沿。
  • 学习式稀疏检索：SPLADE 等用神经网络学习稀疏的词项权重，兼得词法的可解释/精确与神经的语义扩展，模糊了语义 vs 词法的边界。
  • Matryoshka / 可截断 embedding：训练让向量的前若干维就足以检索，从而按预算截断维度（省内存/算力）。让同一套 embedding 适配不同的延迟-精度需求。
  • 多向量与延迟交互：ColBERT 为每个 token 存向量、查询时做 token 级 MaxSim，介于 bi- 与 cross-encoder 之间。如何在精度与存储/速度间取舍，是检索架构的开放谱系。
  • embedding 的可靠性与偏差：embedding 会编码训练数据的偏见、对分布外文本不稳、相似度分数难以校准成概率。如何评测与修正这些，是把语义检索用于高风险场景前必须面对的。
