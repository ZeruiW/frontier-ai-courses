1这门课讲什么

欢迎来到 检索增强与长上下文评测。这门课只追求一件事：让你从「会调一个 RAG 库」变成「会从零搭一条检索增强全栈、并量化它的每一环」。

绝大多数人和 RAG 的关系，止于把文档丢进某个向量库、调一行 index.query(question)、再把结果拼进提示。这门课要往下钻：当你做语义检索时，文本是怎么变成向量、相似度凭什么衡量语义？当库有上亿条时，为什么暴力比对不可行、近似最近邻凭什么能快几个数量级还几乎不丢召回？为什么第一段检索回来的结果还要重排？一个 RAG 系统答错了，到底是没检索到（context recall 低）、检索到一堆噪声（context precision 低）、还是检索到了却在编（faithfulness 低）——你怎么把这三种病分开诊断？

这些问题的答案不在任何框架的文档里，而在信息检索几十年的积累与大模型时代的新约束的交汇处。一个 RAG 系统本质上是一条流水线：把知识嵌入成向量 → 建索引快速检索 → 重排精选 → 拼进上下文生成 → 评测每一环的质量。本课就沿着这条流水线，把六个核心环节（嵌入与相似度、向量检索、重排、RAG 评测、检索指标、长上下文）从零拆开、亲手用 numpy/pandas 重建。

学完你应当能回答这类问题（也是 RAG / 检索 / 评测岗位的高频面试题）：余弦相似为什么比欧氏距离更适合语义检索？IVF 和 HNSW 各靠什么把检索从 O(N) 降下来，分别牺牲了什么？为什么要 cross-encoder 重排、它比 bi-encoder 强在哪、又贵在哪？faithfulness 和 answer relevance 有什么区别，怎么自动测？nDCG 比 MRR 多了什么信息？lost-in-the-middle 是什么、它对「该把检索到的最相关文档放上下文哪个位置」有什么启示？——并且能在 numpy/pandas 里把这些机制都从零实现、对拍暴力/朴素参考。

一句方法论上的话先说在前面：本课的价值不在「我们不训练大模型也能学 RAG」这个妥协，而在它逼你只关注真正难、且不随模型过时的部分——检索的结构与评测的科学。具体用哪个 embedding 模型、哪个向量库、哪代 LLM，每年都在变；而「相似度怎么定义、索引怎么权衡召回与延迟、排序质量怎么量化、检索与生成的失败怎么归因」是十年不过时的硬功夫。把它练扎实，换任何工具、任何模型都立刻能上手、能评。

2为什么 LLM 需要外挂检索

为什么强大的大模型还需要外挂一个检索器？因为模型权重里那份参数化记忆（parametric memory）有四个治不好的毛病，而非参数化记忆（non-parametric memory）——一个外部可检索的知识库——恰好对症：

参数化记忆的毛病具体表现RAG 的解法（非参数化）
会过时训练截止后的新事实一概不知；更新知识要重训，代价高昂知识库随时增删改，检索即用，无需动模型
会幻觉对长尾/边角事实，模型会流畅地「编」一个看似合理的错误答案把真实片段放进上下文，让模型开卷作答、有据可依
不可溯源答案出处无从查证，无法审计、无法定位错误来源每个论断可指回检索到的具体文档（attribution）
容量有限再大的模型也装不下所有私有/专业/实时知识外部库可任意大，按需检索相关的一小块

直白说

打个比方：纯大模型像一个闭卷考试的学霸——博学但记忆会糊、会串、考完就过时，还不准翻书。RAG 把它变成开卷考试：题目（问题）发下来，先去资料库里翻出相关那几页（检索），再据此作答。开卷的学霸不必背下整个图书馆，只要会查、会用查到的东西。

严谨说

形式上：RAG 把问答从「在参数 $\theta$ 里隐式查」改成「显式地 $\arg\max_z p(z\mid q)$ 检索证据 $z$，再 $p(a\mid q,z)$ 据证据生成」。Lewis 2020 证明这种检索器+生成器的组合，在知识密集任务上同时提升了准确率与可溯源性。知识从权重里搬到了可更新、可引用的外部索引里。

但开卷也带来了新问题，且这些问题正是本课的主线：翻到的页对不对？（检索质量）、翻得快不快？（索引效率）、一堆候选里怎么挑最相关的几页？（重排）、学霸有没有真照着资料答、还是又在自由发挥？（faithfulness）、我怎么客观地给这套流程打分？（检索指标与 RAG 评测）。RAG 没有消灭难题，而是把「让模型记住一切」这个不可能任务，换成了一串可分解、可量化、可逐环优化的工程问题——这恰恰是好消息，因为可量化的东西才可改进。

3课程地图：从一个向量到长上下文评测

课程地图：从一个向量到长上下文评测

一条 RAG 流水线：把知识变向量 → 检索 → 重排 → 生成 → 评测每一环 模块 01 嵌入与语义搜索 文本→向量；点积/余弦/归一化；语义 vs 词法(BM25)；混合 │ 「怎么把『意思』变成能比距离的向量？」 ▼ 模块 02 向量检索 暴力 kNN → IVF 分桶 / HNSW 图 / PQ 量化；召回-延迟-内存 │ 「上亿条向量，怎么又快又准地找近邻？」 ▼ 模块 03 重排 bi-encoder 召回 + cross-encoder 精排；MMR 多样性；RRF 融合 │ 「召回一把，怎么精挑出真正相关的几条？」 ▼ 模块 04 RAG 评测 faithfulness / answer relevance / context precision·recall │ 「答错了，是没检索到、检索到噪声、还是在编？」 ▼ 模块 05 检索指标 P@k / R@k / MRR / MAP / nDCG；二元 vs 分级相关性 │ 「排序质量到底怎么用一个数说清楚？」 ▼ 模块 06 长上下文评测 NIAH 大海捞针 / lost-in-the-middle 位置偏置 / 多针 / RAG vs 长窗口 「不检索、直接把全书塞进超长窗口，行不行、会怎么坏？」

注意这不是松散的专题集合，而是一条沿数据流前进的依赖链：没有模块 01 的向量与相似度，就没有模块 02 的检索；没有 02 的召回，03 的重排无米下锅；而模块 04/05 是给前三段装上仪表盘——没有可量化的评测，你根本不知道改了 embedding、换了索引、加了重排到底是变好还是变坏。模块 06 则把视角推到前沿：当上下文窗口长到能装下整本书，检索这一步还需不需要？

每一级台阶都对应一个可独立验证的能力：模块 01 你能从零算余弦相似与 BM25、做混合检索；02 你手写的 IVF/HNSW/PQ 会与暴力 kNN 对拍召回率；03 你能量化重排带来的 nDCG 提升、用 MMR 去冗余、用 RRF 融合多路；04 你能把一个 RAG 答案拆成论断、自动判它是否忠实于上下文；05 你手算的 MRR/MAP/nDCG 会与定义逐位吻合；06 你能复现 NIAH 与 lost-in-the-middle 的 U 形曲线。每一步都有 assert 兜底，绝不靠「感觉对了」。

4方法论：用 numpy/pandas 从零搭并对拍

方法论：不训练大模型，怎么学 RAG 与评测？

本环境不训练神经网络、不调用线上大模型 API。但 RAG 与检索评测的难点从来不是「跑一个大模型」，而是结构与度量：相似度怎么定义、索引怎么权衡、排序怎么量化、检索与生成的失败怎么归因。这些用 numpy/pandas 在 CPU 上就能精确表达和验证。

打个比方：学评判一场考试的公平性，不需要你自己先成为考生。RAG 评测的「考点」是相似度结构、索引的召回-延迟权衡、排序指标的数学、检索与生成的归因；这些都是与具体模型无关的算法与统计结构。一个真实系统里 embedding 由神经网络产生，但一旦有了向量，后面的相似度、索引、重排、指标计算，与向量怎么来的无关——我们用确定性的玩具 embedding（哈希/共现构造）顶替神经网络这一步，把全部精力放在向量之后那条又长又值钱的流水线上。结构一模一样，只差「向量是学出来的还是造出来的」。

直白说

我们把 RAG 的每个环节翻译成 numpy/pandas 里看得见摸得着的东西：embedding 是一个确定性函数造的向量矩阵，检索是矩阵乘+topk，索引是聚类分桶或图导航，重排是对候选重新打分，评测是把论断与上下文做集合/蕴含比对。你写的是结构与度量，不是某个模型的性能。

严谨说

关键纪律是对拍（differential testing）：每个「近似/优化」组件都和一个朴素参考比对。ANN 的召回率 = 与暴力 kNN 的 top-k 重合度；PQ 近似距离的排序 = 与精确距离排序的相关性；手写的 nDCG = 按定义直算的 nDCG。任何偏差都被 assert 当场抓住。结构正确 → 度量一致 → 你的逻辑可以原样搬到 FAISS/真实评测。

RAG 概念本课的 numpy/pandas 实现对应真实系统
text embedding确定性哈希/共现构造的向量矩阵Sentence-BERT / OpenAI embedding
向量检索矩阵乘 + argsort topk / 聚类分桶 / 图导航FAISS / HNSWlib / ScaNN
cross-encoder 重排一个看 query-doc 交互特征的打分函数monoBERT / Cohere Rerank
faithfulness 判定论断 vs 上下文的词/蕴含级比对RAGAS + LLM judge / NLI 模型
排序指标按定义从零算 P@k/MRR/MAP/nDCGpytrec_eval / ir_measures
近似索引正确性对拍暴力 kNN 的召回率ANN-Benchmarks 的 recall 曲线

为什么把对拍提到方法论的高度？因为检索与评测的 bug 极其阴险：一个召回率算错的索引、一个边界没处理对的 nDCG、一个把「答案正确」误当「忠实于上下文」的评测，往往不会报错，只会悄悄给出看起来合理但其实错了的数字，让你基于错误的指标做错误的决策。在本课里，我们对每个组件都有一个绝对可信的朴素参考（暴力 kNN、按定义直算的指标），任何偏差当场暴露。这套「先有 ground truth，再优化/近似」的纪律，正是真实检索系统与评测平台的核心工作流。

5环境与运行

环境与运行

环境极简：只需 numpy 与 pandas（画召回-延迟曲线、位置偏置曲线可选 matplotlib）。全课 CPU 秒级运行，无需 GPU、无需训练、无需调用任何线上模型。

conda create -n rag python=3.11 -y && conda activate rag
pip install numpy pandas      # 必需
pip install matplotlib        # 可选，仅用于画召回-延迟 / 位置偏置曲线
jupyter lab

每个模块配一个 notebook，结构统一：先用 numpy/pandas 把机制从零实现并对拍（5–6 个 worked 小节，每节都跑出可打印的验证与 assert 自测），再做 3–4 道带 assert 判分的 ✏️ 练习（先给骨架，自己填，再对照 📖 参考答案），最后一个真实数据胶囊（优先联网拉取真实公开数据如 SQuAD 做一次端到端实验，下载失败则回退到内置的真实样本，保证离线也能跑、且逻辑与真实数据完全一致）。

建议的学习节奏：先读完整章 HTML 建立直觉与数学框架，再打开 notebook 亲手实现。读和做缺一不可——只读会觉得「好像懂了」，真正动手写 IVF 分桶、调 PQ 段数、让 nDCG 的 assert 通过、把 RAG 答案拆成论断时，才会发现魔鬼藏在哪些细节里（归一化、边界、相关性分级、蕴含判定）。这门课的深度正是为「动手」服务的。

配套先读：Lewis 2020（RAG 奠基）建立全栈视角；Karpukhin 2020（DPR）理解稠密检索；Es 2023（RAGAS）理解无参考评测；Liu 2023（Lost in the Middle）理解长上下文位置偏置。完整清单见 references.md。

✅ 学完整门课，你应该能：
  1. 把文本嵌入成向量、从零实现余弦相似/归一化/BM25，并做语义+词法的混合检索；
  2. 从暴力 kNN 出发，实现 IVF/HNSW/PQ 近似索引并对拍其召回率，讲清召回-延迟-内存的三角权衡；
  3. 搭两段式检索：bi-encoder 召回 + cross-encoder 重排，量化重排提升、用 MMR 去冗余、用 RRF 融合多路；
  4. 对一个 RAG 三元组做 faithfulness / answer relevance / context precision·recall 评测，把幻觉与漏检分开诊断；
  5. 从零推导并实现 P@k / R@k / MRR / MAP / nDCG，知道每个指标在奖励什么、对什么敏感；
  6. 复现 NIAH 与 lost-in-the-middle 的位置偏置曲线，权衡 RAG 与长上下文两条路线；
  7. 对任何 RAG/检索系统做出可量化、可复现、能定位瓶颈的评测。
