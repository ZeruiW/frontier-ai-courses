1为什么需要排序指标：qrels 与相关性

前四个模块我们搭出了一条检索流水线：嵌入、向量检索、重排、RAG 评测。但有一个贯穿始终、却一直被我们用「召回率」一笔带过的问题，现在必须正面拿下——一个排好序的检索结果，到底好不好，怎么用一个数说清楚？这就是检索指标（retrieval metrics）的全部主题。没有它，你换了 embedding、调了 nprobe、加了重排，根本无法判断系统是变好还是变坏。

检索的输出永远是一个有序列表：给定查询，返回 doc₁, doc₂, …, docₙ，越靠前越「该相关」。要评价它，先要有 ground truth——人工标注的qrels（query relevance judgments，相关性标注），告诉我们每个 (查询, 文档) 到底相不相关。标注有两种粒度：

标注粒度取值例子适用指标
二元相关性 binary0 / 1（不相关 / 相关）这篇文档回答了问题吗？Precision@k, Recall@k, MRR, MAP
分级相关性 graded0 / 1 / 2 / 3（多档）完美 / 相关 / 沾边 / 无关nDCG（能利用分级）

直白说

把检索指标想成给搜索结果打的「考试分数」：标准答案是人工标注的 qrels，学生答卷是检索返回的排序。不同指标用不同的评分规则——有的只看「第一个对的排多前」，有的看「对的整体排得齐不齐」，有的还区分「答案有多对」。选错评分规则，就会奖励错误的行为。

严谨说

一个必须先厘清的混淆：本模块的 recall@k 与模块 02 的 recall@k同名但参照物完全不同。模块 02 的 recall 量的是「近似索引 vs 暴力精确检索」（ground truth 是暴力 top-k）；本模块的 recall 量的是「检索结果 vs 人工相关性标注」（ground truth 是 qrels）。一个评『索引准不准』，一个评『系统找得全不全』。

指标不是中立的——你优化哪个指标，就在塑造系统的哪种行为。只看 Precision@1 会鼓励系统把最稳的一条放最前、不管后面；只看 Recall@k 会鼓励多召回不管排序。报单一指标几乎总是误导，成熟的检索评测一定同时报多个互补指标——这是本模块最实用的一条戒律。

2Precision@k 与 Recall@k

Precision@k 与 Recall@k：最朴素的一对

最直接的两个指标，都只需二元相关性，且都只看 top-k（前 k 个结果）。Precision@k（前 k 精确率）问：我返回的前 k 个里，有几个是真相关的？Recall@k（前 k 召回率）问：所有相关文档里，有几个进了我的前 k？

\[\text{P@}k=\frac{|\{\text{top-}k\text{ 中相关的}\}|}{k}\qquad\text{R@}k=\frac{|\{\text{top-}k\text{ 中相关的}\}|}{|\{\text{全部相关文档}\}|}\]

分子完全相同（top-k 里命中的相关文档数），只是分母不同：precision 除以 k（你返回了多少），recall 除以「总相关数」（本该找到多少）。一个看返回的有多干净，一个看该找的漏没漏。

这两者天然此消彼长：把 k 调大，recall 单调不降（看得越多越不容易漏），但 precision 往往下降（后面混进的无关文档拉低了纯度）。这就是经典的 precision-recall 权衡。在 RAG 里这个权衡尤其要紧：检索召回（recall）直接决定生成的信息上限——关键证据没进上下文，生成器再强也无米下锅；而 precision 低则意味着上下文里塞了噪声，稀释信号、挤占宝贵的 token 预算、甚至误导生成。

那 RAG 里到底该偏向 precision 还是 recall？答案通常是先保 recall：生成器有一定的抗噪能力（能在几条无关上下文里挑出有用的），但对根本没检索到的信息无能为力。所以实践中常先用较大的 k 把 recall 顶上去（宁可多带几条噪声），再靠重排（模块 03）和生成器自身的判断把 precision 找补回来。这也是为什么 Recall@k 几乎是 RAG 检索段的头号体检指标——它卡住的是天花板，而天花板比纯度更难事后补救。

一个常被忽略的陷阱：P@k 和 R@k 都不看名次——把相关文档放在第 1 名还是第 k 名，分数完全一样。这对「用户只看前几条」的搜索场景是个大问题：两个 P@10 都等于 0.3 的系统，一个把 3 个相关项放在前 3、另一个放在第 8/9/10，体验天差地别，P@k 却给了同分。要区分它们，就需要下面看名次的指标（MRR、MAP、nDCG）。这个『盲区』正是理解为什么需要更复杂指标的最好切入点。

3MRR：第一个对的排多前

MRR：第一个对的排多前

很多场景里，用户只要一个正确答案就够了——问答、导航类查询、「我手气不错」。这时候我们最关心的不是「找回多少相关的」，而是第一个相关结果排在多靠前。这正是 MRR（Mean Reciprocal Rank，平均倒数排名）度量的东西。

对单个查询，找到第一个相关结果的名次 rank₁（1-indexed），它的倒数排名就是 1/rank₁：排第 1 得 1.0，排第 2 得 0.5，排第 3 得 0.33……排得越靠后，分数掉得越快。MRR 就是把所有查询的倒数排名取平均：

\[\text{MRR}=\frac{1}{|Q|}\sum_{q\in Q}\frac{1}{\text{rank}_1(q)}\]

其中 rank₁(q) 是查询 q 的结果里第一个相关文档的名次；若前若干名（或整个列表）一个相关的都没有，该查询贡献 0。

直白说

MRR 像在问：「用户平均要往下翻几条，才能看到第一个有用的结果？」翻到第 1 条就有，满分；要翻到第 4 条，只得 0.25。它把『靠前』的价值用倒数狠狠放大——第 1 名和第 2 名的差距（1.0 vs 0.5）远大于第 9 名和第 10 名（0.111 vs 0.100）。

严谨说

MRR 的「视野」极窄：它只看第一个相关项，完全无视后面还有没有相关文档、有几个。所以它只适合「找到一个就行」的任务；对「需要综合多篇」的任务（多跳问答、综述、推荐多样性），MRR 会严重低估系统价值——你需要 MAP 或 nDCG。

为什么用倒数而不是名次本身？因为倒数恰好捕捉了「头部位置的边际价值急剧递减」这一用户直觉：从第 1 名掉到第 2 名，用户多付出的代价（多看一条）感受强烈；而从第 50 名掉到第 51 名，用户根本不在乎（早就放弃翻页了）。倒数函数 1/rank 的曲线正是前陡后平——前几名之间分差很大，越往后越扁平。这让 MRR 天然聚焦于「能不能把对的那条顶到最前面几位」，与问答、导航类任务「用户只看头部」的行为高度吻合。

在 RAG 语境里，MRR 有一个特别贴切的解读：如果你的策略是只把检索到的第 1 名喂给生成器（或第 1 名权重远高于其余），那 MRR 几乎直接预测了「生成器能拿到正确证据」的概率。反过来，如果你会把 top-5 全塞进上下文，MRR 就不够用了——它看不到第 2 到第 5 名的贡献，这时 MAP / Recall@5 才是对的尺子。指标该匹配你『怎么用检索结果』，这是贯穿本模块的核心思想。

MRR 源自 TREC 的问答评测（见 references 的 Voorhees 1999 / Craswell）。它的极致简洁（只需知道第一个相关项的位置）使它成为问答、实体检索的标准报告指标之一，也是 RAG 检索「能不能把对的那篇放最前」的快速体检。

4AP 与 MAP：沿名次平均精确率

AP 与 MAP：把精确率沿名次平均

如果说 MRR 只盯第一个相关项，那 AP（Average Precision，平均精度）就是把目光放到每一个相关项上，综合考量「精确率」与「名次」——它是二元相关性下最常用的综合排序指标。

AP 的定义：遍历排序列表，每当遇到一个相关文档，就记下「到此为止的 Precision@该位置」，最后把这些精确率取平均（除以相关文档总数）：

\[\text{AP}=\frac{1}{|R|}\sum_{k:\,\text{rel}_k=1}\text{P@}k\qquad \text{MAP}=\frac{1}{|Q|}\sum_{q\in Q}\text{AP}(q)\]

其中 |R| 是该查询的相关文档总数，求和只在「相关文档出现的位置 k」上进行。把所有查询的 AP 再取平均，就是 MAP（Mean Average Precision）。

看个手算的例子。排序的相关性是 [1, 0, 1, 1, 0, 0]（相关总数 3）：

位置 k: 1 2 3 4 5 6 相关 rel_k: 1 0 1 1 0 0 遇到相关项 → 算 P@k: 位置1: 命中1个/前1 = 1/1 = 1.000 位置3: 命中2个/前3 = 2/3 = 0.667 位置4: 命中3个/前4 = 3/4 = 0.750 AP = (1.000 + 0.667 + 0.750) / 3 = 0.806

直白说

AP 奖励两件事：相关文档既要多、又要靠前。把相关项往前提，它经过的每个 P@k 都更高，AP 就上升。所以 AP 同时惩罚『漏召回』（相关项总数少）和『排得乱』（相关项靠后）——比 MRR 全面得多。

严谨说

严谨地说，AP 近似等于 precision-recall 曲线下的面积（AUC-PR 的离散版）。它把整条排序的质量压成一个数，且对相关项的位置敏感。这也是为什么 TREC 等学术检索评测长期以 MAP 作为主指标——它在二元相关性下信息量最大。

MRR vs MAP 一句话区分：MRR 只问第一个对的排多前，MAP 问所有对的整体排得好不好。前者适合「找一个答案」，后者适合「找全相关集」。两者都建立在二元相关性上；当相关性有「程度之分」时，就轮到 nDCG。

5nDCG：分级相关性的排序指标

nDCG：当相关性有等级之分

前面所有指标都假设相关性非黑即白。但现实常是分级的：一篇「完美回答」和一篇「沾点边」都算「相关」，可它们的价值天差地别。nDCG（normalized Discounted Cumulative Gain，归一化折损累积增益，Järvelin 2002）就是为分级相关性设计的指标，也是工业搜索/推荐最常用的排序指标。它由三个零件搭成：

  • Gain（增益）：相关性等级越高，价值越大。常用 gain = 2^rel − 1——等级 0 给 0，等级 1 给 1，等级 2 给 3，等级 3 给 7，指数放大高相关项的重要性。
  • Discount（折损）：排得越靠后，价值打折越狠。用 1/log2(pos+1)（pos 从 1 开始）——位置 1 不打折（log2(2)=1），位置 2 打到 0.63，位置 3 打到 0.5……体现「用户越往后看得越少」。
  • Normalize（归一化）：除以理想排序（把所有文档按真实相关性降序排）的 DCG，即 IDCG，把分数压到 [0,1]，使不同查询可比。
\[\text{DCG@}k=\sum_{i=1}^{k}\frac{2^{\text{rel}_i}-1}{\log_2(i+1)}\qquad \text{nDCG@}k=\frac{\text{DCG@}k}{\text{IDCG@}k}\]

完美排序（高相关全在最前）的 DCG 恰好等于 IDCG，故 nDCG = 1.0；排得越乱，DCG 越小于 IDCG，nDCG 越低。归一化这一步至关重要：没有它，一个『相关文档天生多』的查询 DCG 会虚高，无法和『相关文档少』的查询横向比较——除以各自的 IDCG 才把它们拉到同一标尺。

直白说

nDCG 像一个挑剔的评委：不仅看你把相关的排前面（折损），还看你有没有把『最相关的』排在『次相关的』前面（增益分级），最后还按『理论最好成绩』给你打百分比（归一化）。这让它成为最贴近真实用户体验的排序指标。

严谨说

注意折损用对数而非线性：1/log2(pos+1) 的衰减比 1/pos 平缓，意味着 nDCG 认为「第 5 名和第 10 名的差距」没有「第 1 名和第 2 名的差距」那么悬殊——这符合『用户最在意头部、尾部差异钝化』的直觉。也有人用 1/log2(pos+1) 之外的折损，但对数折损是事实标准。

nDCG 的两个实现陷阱：① 位置从 1 还是 0 开始决定 log 里加 1 还是加 2，务必全程一致（本课约定位置 1-indexed，折损 = 1/log2(pos+1)）；② 全零相关时 IDCG=0，要特判返回 0 避免除零。这两个 off-by-one / 除零是 nDCG 自己实现时最常见的 bug，notebook 会用手算值逐一对拍。

6二元还是分级：指标怎么选

二元还是分级？指标该怎么选

现在把五个指标摆到一起，关键问题是：面对一个具体任务，该报哪些指标？答案取决于两件事——你的标注粒度和你的任务目标。

指标需要的标注看名次?核心问题最适合
P@k二元否返回的前 k 有多干净结果集纯度、固定展示位
R@k二元否该找的漏没漏RAG 检索召回、合规检索
MRR二元是（仅第一个）第一个对的排多前问答、导航、找一个即可
MAP二元是（所有相关项）相关集整体排得好不好学术检索综合评测
nDCG分级是（含等级）高相关的是否排在最前工业搜索/推荐、有相关程度

一条实用的决策路径：① 如果你的标注是分级的（有「完美/相关/沾边」之分），优先用 nDCG——它是唯一能利用这份信息的；② 如果是二元标注，看任务——「找一个答案」用 MRR，「找全相关集」用 MAP；③ 无论如何，把 Recall@k 作为 RAG 检索的「体检项」常报，因为它直接卡住生成的信息上限。

但最重要的原则不是「选哪一个」，而是别只选一个。这些指标各有盲区：P@k 不看名次、MRR 不看第一个之后、MAP 不分相关等级、nDCG 对截断 k 和折损函数的选择敏感。成熟的做法是报一组互补指标（如同时报 nDCG@10、MRR、Recall@100），从多个角度交叉印证——任何单一数字都可能在某个维度上骗你。

把指标选择想成「用对的尺子量对的东西」：要量身高别用体重秤。nDCG 量「分级排序质量」，MRR 量「首个命中位置」，Recall 量「覆盖完整性」。用错指标比没有指标更危险——它会给你一个看似精确、实则误导的数字，让你朝错误方向优化。

7指标敏感度与平均的陷阱

指标敏感度与平均的陷阱

理解每个指标对什么变化敏感、对什么麻木，是正确解读评测结果的关键。同一个改动，在不同指标上的反应可能截然不同：

  • MRR 只对「第一个相关项的位置」敏感：把第 5 名的相关项提到第 2 名，若第一个相关项位置没变，MRR 纹丝不动；但若它本是第一个相关项，MRR 大涨。
  • Recall@k 只对「截断 k」敏感：相关项从第 11 名提到第 9 名，Recall@10 从漏掉变命中（跳变）；但在 k 以内怎么挪，Recall@k 不变。
  • nDCG 对「高相关项是否靠前」最敏感：把一个等级 3 的文档从第 3 名提到第 1 名，nDCG 明显上升（高 gain × 低折损）；挪一个等级 1 的文档则影响很小。

这意味着选指标时要让它对你在意的变化敏感。你在乎「把最相关的放最前」，就该用 nDCG（它对此敏感）而非 P@k（它对此麻木）。notebook 会用一组「同样的相关文档、不同排列」的实验，让你亲眼看到三个指标对同一改动的不同反应。

还有一个常被忽视的平均的陷阱：MAP、MRR、nDCG 报的都是跨查询的平均，而平均会掩盖分布。一个 MAP=0.6 的系统，可能是「所有查询都 0.6」，也可能是「一半查询 1.0、一半 0.2」——后者有大量用户体验极差，但平均值一样。所以除了均值，成熟评测还会看分布（中位数、最差的 10% 查询、有多少查询是 0 分），并对两个系统的差异做显著性检验（如配对 t 检验 / 置换检验），确认「MAP 高了 0.01」不是噪声。

一个真实世界反复上演的错误：用一个数字、在一小撮查询上、不做显著性检验，就宣布 A 系统比 B 好。检索指标方差很大，几十个查询上的 0.02 差距极可能是随机波动。报均值也报分布、报多指标、做显著性检验、用足够大的查询集——这四条是把检索评测从「自欺」变成「科学」的底线。

8研究前沿与开放问题

研究前沿与开放问题

  • 离线指标 vs 在线指标的鸿沟：nDCG/MAP 是离线代理，真正重要的是线上用户行为（点击、停留、转化）。离线指标涨了线上未必涨——如何让离线评测更好地预测线上效果，是检索评测的核心开放问题。
  • 点击模型与反事实评测：用户点击受位置偏置（position bias）污染（排前面的天然更易被点），不能直接当相关性。如何从带偏的点击日志里无偏地估计相关性（counterfactual / off-policy evaluation），是工业检索评测的活跃前沿。
  • RAG 端到端指标与检索指标的脱节：检索 nDCG 高，不必然 RAG 答案好（生成器可能没用上、或被噪声带偏）。如何设计「面向下游生成」的检索指标，而非孤立地评排序，是 RAG 时代的新问题（呼应模块 04）。
  • LLM 时代的相关性再定义：当『相关』不再是「包含答案的文档」而是「能帮 LLM 生成正确答案的上下文」，传统 qrels 标注范式面临挑战；用 LLM 自动生成相关性标注又会引入模型自身的偏差。
  • 超越列表的评测：对话式检索、多轮澄清、检索结果的多样性与公平性，都难以被「单查询单列表」的经典指标刻画，需要新的评测协议。

必读：Järvelin & Kekäläinen 2002（nDCG 原始定义）、Manning《IR 导论》第 8 章（P/R/MAP/MRR/nDCG 权威定义）、Voorhees 1999（MRR 与 TREC qrels）、Wang 2013（nDCG 理论性质）。清单见 ../references.md。
