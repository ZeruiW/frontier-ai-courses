1RAG 为什么难评：三元组与分科体检

前三个模块我们把 RAG 的检索半边搭了起来：把文本嵌成向量、建索引找近邻、重排精选候选。但 RAG 的全称是 Retrieval-Augmented Generation——检索到的上下文最终要喂给一个生成器去作答。于是一个尖锐的问题浮现：怎么知道这套系统答得好不好？这就是本模块的主题——RAG 评测，也是把 RAG 从「能跑」推向「可信」的关键一环。

最朴素的想法是：拿一批有标准答案的问题，看系统答对了几道，算个准确率（或 EM / F1）。这在抽取式 QA 上还行，但对开放式、生成式的 RAG 远远不够。原因在于 RAG 是一条两段流水线，一个端到端准确率把太多东西揉成了一个数字，掩盖了失败到底发生在哪一段。

理解 RAG 评测，要先把它拆成一个三元组：question（用户问题 $q$）、retrieved context（检索到的上下文 $c$）、answer（模型生成的答案 $a$）。一次 RAG 调用就是 $q\to c\to a$ 的链条，而评测要分别盯住这条链的每一环与每一对关系：

RAG 三元组与它们之间要评的关系 question (q) │ \ context \ answer relevance: a 切题地回应 q 吗? recall/precision \ │ \ ▼ ▼ context (c) ───▶ answer (a) faithfulness: a 的每个论断都被 c 支持吗(没在编)? 检索段质量: context precision / recall | 生成段质量: faithfulness / answer relevance

直白说

把 RAG 想成「开卷考试」：检索是「翻书翻到对的页」，生成是「照着翻到的页写答案」。只看最终得分（答对没），你分不清扣分是因为没翻到对的页（检索差），还是翻到了却抄错或自由发挥（生成差）。要改进系统，必须把这两类错分开诊断——这正是三元组评测的全部动机。

严谨说

形式上：端到端正确率 $P(a\ \text{correct})$ 是 $P(\text{retrieve good }c)\cdot P(\text{generate good }a\mid c)$ 的混合，单个数字无法解耦两个因子。RAG 评测的核心是把它分解为检索侧指标（context precision/recall，第 4 节）与生成侧指标（faithfulness/answer relevance，第 2、3 节），从而定位瓶颈、对症下药。

一句话定调本模块：好的 RAG 评测不是给系统打一个分，而是给它做一次『分科体检』——检索这一科考了多少、生成这一科考了多少。本模块从零实现这套体检的四项核心指标（faithfulness、answer relevance、context precision、context recall），并用它们把不同病症的 RAG 案例诊断出来。我们用规则版（词重叠/集合包含作蕴含代理）模拟 RAGAS 的 LLM 判官思想，让你看清每个指标在量什么、怎么算。

2faithfulness：答案有据吗（防幻觉）

先看 RAG 评测里最核心、最关乎安全的指标：faithfulness（忠实度，也叫 groundedness 接地度）。它回答一个问题：答案里说的每一句，都能在检索到的上下文里找到依据吗？如果答案冒出了上下文根本没提的内容，那就是模型在编——也就是hallucination（幻觉）。

这里有一个极其重要、却常被忽略的区分：faithfulness 与『答案是否正确』是两回事。一个答案可能恰好正确（与世界事实相符），但如果它的依据不在上下文里、而是模型从自己参数化记忆里掏出来的，那它仍然是不忠实的。

忠实 ≠ 正确

为什么「恰好正确但不忠实」也要算失败？因为 RAG 的承诺是可溯源、可控、可更新：答案应当由你给的知识库支撑，这样你换库就能换知识、能审计每个论断的出处。一个靠参数化记忆「蒙对」的答案，今天对、明天模型一变就可能错，且你无从追查它凭什么这么说。不忠实的正确答案是侥幸，不是可靠系统——这正是 faithfulness 必须独立于正确性来度量的原因。

怎么自动算 faithfulness？工业界（如 RAGAS）的做法分两步，本课用规则版模拟其骨架：

  1. 论断分解（claim decomposition）：把答案这段话拆成若干可独立验证的原子论断。比如「巴黎是法国首都，人口约 200 万」拆成两条：① 巴黎是法国首都；② 巴黎人口约 200 万。
  2. 逐条蕴含判定（entailment）：对每条论断，判断它是否被上下文entail（蕴含/支持）。真实 RAGAS 用 LLM 或 NLI 模型判；本课用词重叠代理——论断的内容词若足够多地出现在某条上下文里，就算被支持。
\[\text{faithfulness}(a, c)=\frac{\#\{\text{被上下文 }c\text{ 支持的论断}\}}{\#\{a\text{ 中的全部论断}\}}\in[0,1]\]

于是 faithfulness 就是被支持论断的比例：全部论断都有依据 → 1.0（完全忠实）；有一条论断在上下文里查无实据 → 分数下降，那条就是疑似幻觉。notebook 会造一个含 1 条捏造论断的答案，亲眼看到 faithfulness 从 1.0 掉下来，并精确定位是哪条论断在编。

直白说

faithfulness 像查作业有没有「抄题目给的资料」：把学生的每句话拿去和发的资料逐句比对，凡是资料里找不到出处的，就标记为「自己瞎写的」。瞎写的越多，忠实度越低。

严谨说

严谨地说，这是把「答案是否 grounded」操作化为「论断集合对上下文的可推导比例」。真实系统用 NLI 的三分类（entailment / neutral / contradiction）：被 entail 记忠实，neutral/contradiction 记不忠实。本课的词重叠代理是其廉价近似，抓的是「论断的信息是否出现在上下文中」这一核心。

3answer relevance：答案切题吗

第二个生成侧指标是 answer relevance（答案相关性）：答案切题地回应了问题吗？它和 faithfulness 是正交的两个维度——这一点必须想清楚，否则会把两类完全不同的毛病混为一谈。

看一个具体的对照。问「埃菲尔铁塔有多高？」，上下文是关于埃菲尔铁塔的一段介绍：

答案faithfulness（忠实于上下文？）answer relevance（切题？）诊断
「埃菲尔铁塔高约 330 米。」高（上下文有此数据）高（正面回答了高度）✅ 理想
「埃菲尔铁塔在巴黎，建于 1889 年。」高（上下文确有这些）低（答非所问，没说高度）❌ 忠实但跑题
「埃菲尔铁塔高约 1000 米。」低（上下文无此数，是编的）高（形式上在答高度）❌ 切题但幻觉

第二行就是 faithfulness 高、answer relevance 低的典型：模型老老实实复述了上下文，但复述的是无关的部分，等于没回答问题。第三行反过来，形式上切题却在编数字。两个指标各管一边，缺一不可：faithfulness 防「编」，answer relevance 防「跑题」。

怎么算 answer relevance？一个直接的代理是度量答案与问题的语义贴合度（如用上一模块的余弦相似，或答案对问题关键词的覆盖）。RAGAS 用了一个更巧的反向生成思路：让 LLM 从答案反推出它最可能在回答的问题，再比较反推出的问题与原问题的相似度——如果答案切题，反推的问题应当和原问题很像。

直白说

answer relevance 像问：「光看这个答案，你能猜出它在回答什么问题吗？猜出来的问题和真问题对得上吗？」一个跑题的答案，反推出的问题会和原问题南辕北辙；一个切题的答案，反推的问题几乎就是原问题。

严谨说

形式上，反向生成法估计 $\text{relevance}\approx \text{sim}(q,\ \hat{q})$，其中 $\hat q$ 是从答案 $a$ 生成的问题。本课用更简单的 $\text{sim}(q, a)$（问题-答案的词/向量相似度）作代理，核心都是捕捉『答案是否朝着问题的方向』，而非答案是否有依据（那是 faithfulness 的事）。

4context precision & recall：检索段质量

把视角转到检索侧。检索段的质量直接决定生成段的上限——garbage in, garbage out：检索回来一堆噪声或漏了关键证据，再强的生成器也救不回。检索侧有两个互补的指标：context precision 和 context recall，它们恰好对应「带回来的对不对」和「该带的全不全」。

注意这里的 precision/recall 是针对一次 RAG 调用的上下文而言（不同于模块 05 的整体排序指标）：

指标定义低分意味着后果
context precision检索到的上下文里，真正与问题相关的比例带回了一堆无关片段噪声稀释信号、挤占上下文预算、可能误导生成
context recall回答问题所需的信息，被检索上下文覆盖的比例关键证据没被检索到生成器巧妇难为无米之炊——RAG 最常见的失败根因
\[\text{precision}=\frac{|\text{相关的检索片段}|}{|\text{全部检索片段}|}\qquad \text{recall}=\frac{|\text{被覆盖的所需要点}|}{|\text{回答所需的全部要点}|}\]

两者此消彼长，但在 RAG 里 recall 往往更致命。道理很直接：上下文里有点噪声（precision 不满），强生成器通常能忽略无关片段、从相关片段里提炼答案；但如果回答所需的关键事实压根没被检索到（recall 不满），生成器要么拒答、要么只能靠参数化记忆瞎编（幻觉）。漏检比噪声更难补救。

这给 RAG 调优一条重要启示：第一段检索（召回阶段）应当偏向高 recall——宁可多召回一些候选（哪怕带点噪声），也别漏掉关键文档；精度的问题交给后面的重排（模块 03）去收拾。这正是「召回求全、重排求精」两段式设计的评测依据：召回阶段的 KPI 是 recall，重排阶段的 KPI 才是 precision/排序质量。

怎么算 context recall？需要一个ground truth：回答这个问题到底需要哪些要点（可由标准答案分解得到）。然后看每个要点是否被某条检索上下文覆盖，覆盖比例就是 recall。context precision 则要判断每条检索片段是否与问题相关（同样用词重叠/蕴含代理）。notebook 会把两者都从零实现，并验证「漏检案例 recall 低、噪声案例 precision 低」。

5RAGAS：无参考的自动评测

把前面三节的四个指标——faithfulness、answer relevance、context precision、context recall——合成一套自动化、无需人工标准答案的评测框架，就是 RAGAS（Es 2023，Retrieval-Augmented Generation Assessment）的核心思想。它是当下 RAG 评测最有影响力的工作之一。

RAGAS 最重要的卖点是 reference-free（无参考）：传统评测要为每个问题准备人工写的标准答案，昂贵且难规模化；RAGAS 仅凭 $q$、$c$、$a$ 三者之间的一致性就能打分，从而能大规模、自动、甚至在线地评测和监控 RAG 系统。它的每一项分都落在前面讲过的某对关系上：

RAGAS 四项 = 三元组上的四对一致性 ┌──────────── answer relevance (q ↔ a) ───────────┐ │ │ question (q) ──context precision/recall (q ↔ c)──▶ context (c) ──faithfulness (c ↔ a)──▶ answer (a) 生成侧: faithfulness(c→a 没编) + answer relevance(q→a 切题) 检索侧: context precision(c 干净) + context recall(c 全)

RAGAS 用 LLM 充当判官来做论断分解与蕴含判定；本课用规则版（词重叠、集合包含）替代 LLM，得到的是同构的、可解释、可复现的简化版。这样做有意为之：先理解每个指标在数学上量的是什么，再去理解 LLM 判官只是把『判定是否支持/相关』这一步换成了更聪明（但也更贵、更不稳定）的实现。

直白说

RAGAS 像给 RAG 系统配了一个不知疲倦、不用标准答案的「自动阅卷员」：它读问题、读你检索的资料、读你的答案，然后从四个角度打分——资料找全了吗、资料干净吗、答案有据吗、答案切题吗。把这四个分摆在一起，系统哪一环弱一目了然。

严谨说

严谨地说，RAGAS 把 RAG 评测从「需要 gold answer 的有参考评测」转为「只需 (q,c,a) 的无参考评测」，代价是依赖 LLM 判官的可靠性（见第 8 节的偏差与校准问题）。本课的规则代理虽不如 LLM 灵活，但完全确定、零成本、可单元测试，正适合学清楚指标的定义。

6幻觉检测：忠实度与一致性

faithfulness 低，本质就是检测到了 hallucination（幻觉）——生成了无法由上下文支持的内容。值得单独一节，因为幻觉是 RAG（乃至一切生成式 AI）落地的头号风险，而 RAG 对它的关系很微妙：RAG 抑制幻觉，但不消灭幻觉。

说 RAG 抑制幻觉，是因为它把真实证据放进了上下文，让模型有据可依、不必硬编。但说它不消灭幻觉，是因为生成器仍可能『无视上下文』：上下文里明明有正确信息，模型却用自己参数化记忆里（可能过时或错误）的版本作答；或者上下文不全时，模型用编造来「填空」让答案看起来完整。这两种都是 faithfulness 要抓的。

漏检逼出幻觉

一个尤其危险的幻觉模式是过度自信的填空：当 context recall 不足（关键信息没检索到），一个「乐于助人」的模型往往不会说「我不知道」，而是流畅地编一个看起来合理的答案。这就是为什么 context recall 低 + faithfulness 低 经常一起出现：漏检逼出了幻觉。检测幻觉因此不能只看生成段，还要回头看检索段是不是没喂够料。

除了 faithfulness 这种基于上下文的检测，还有一类无需外部知识的幻觉检测思路，以 SelfCheckGPT（Manakul 2023）为代表：让模型对同一问题多次采样生成多个答案，如果模型是「知道」的，多次回答会彼此一致；如果是在编，多次回答会互相矛盾、东拉西扯。用答案之间的一致性（consistency）作为「非幻觉」的代理——矛盾越多，越可能在编。

直白说

两条检测幻觉的路：一条是「对答案」——把答案和发给它的资料逐句核对（faithfulness）；另一条是「对自己」——让它把同一题答好几遍，看几遍说得一不一致（SelfCheckGPT）。前者需要上下文，后者连上下文都不需要，靠的是「真知道的人怎么问都答得一样，瞎编的人每次编得不一样」。

严谨说

技术底座上，「论断是否被支持」最终是一个 NLI（自然语言推理 / 蕴含）问题：context $\models$ claim 则忠实，context 与 claim 矛盾或无关则可能幻觉。本课用词重叠近似 entailment；真实系统用专门的 NLI 模型或 LLM 判官（见 references 的 Honovich 2022《TRUE》把忠实度统一成 NLI）。notebook 会用『多答案一致性』的玩具模拟体会 SelfCheckGPT 的直觉。

7端到端评测与归因诊断

有了四项指标，最后一步是把它们合起来用——做端到端评测与归因（attribution）：当一个 RAG 系统表现不佳，到底该去修检索还是修生成？这正是开篇说的「分科体检」要回答的问题，也是 RAG 评测真正的实用价值所在。

最有用的工具是一张二维诊断矩阵：横轴是检索段好坏（context recall/precision 高不高），纵轴是生成段好坏（faithfulness/answer relevance 高不高）。四个象限对应四种截然不同的病症与处方：

RAG 归因诊断矩阵（检索 × 生成） 生成好(faithful+relevant) 生成差(不忠实/跑题) ┌────────────────────────┬────────────────────────┐ 检索好 │ ✅ 理想 │ ⚠ 修生成器 │ (recall高) │ 系统健康 │ 料给够了却答不好 │ │ │ (换/调LLM, 改prompt) │ ├────────────────────────┼────────────────────────┤ 检索差 │ ⚠ 修检索器 │ ❌ 两段都要修 │ (recall低) │ 答案侥幸对/靠参数记忆 │ 漏检逼出幻觉 │ │ (改embedding/索引/重排)│ (先救检索, 再看生成) │ └────────────────────────┴────────────────────────┘

这张矩阵把一个模糊的「系统不好」精确化成可执行的下一步：左下角（检索差、生成『好』）要警惕——答案可能是靠模型参数化记忆侥幸蒙对的，不可持续，得去补检索；右上角（检索好、生成差）说明料喂够了是生成器的锅，去调 prompt 或换模型；右下角两段全坏，优先救检索（因为它是上游、且常是幻觉的根因）。

还有一个细腻的指标值得一提：context utilization（上下文利用率）——答案实际用到了检索上下文中多少有效信息。它能区分一种隐蔽情形：context recall 高但答案没用上（证据检索到了却被生成器忽略），这指向生成端而非检索端的问题，是右上角象限的细分诊断。

一句话收束归因：不要问『RAG 好不好』，要问『检索这一科几分、生成这一科几分』。四项指标 + 诊断矩阵把一个不可操作的整体印象，拆成两个可独立优化、可分别问责的子系统。这就是为什么严肃的 RAG 团队从不只看一个端到端准确率——那个数字告诉你『病了』，却不告诉你『病在哪』。notebook 会给四个不同病症的案例，让你用四项分把每个的瓶颈准确诊断出来。

8研究前沿与开放问题

RAG 评测是个年轻而活跃的领域，自动化与可信度之间的张力催生了一批前沿问题：

  • LLM-as-judge 的偏差与校准：用 LLM 当判官（RAGAS 的做法）会引入系统性偏差——偏好更长的答案、偏好自己家族模型的风格、对位置/措辞敏感、判定不稳定（同输入多次给不同分）。如何校准、去偏、量化判官本身的可靠性，是把自动评测用于高风险决策前的必答题。
  • 有参考 vs 无参考的折中（ARES）：ARES（Saad-Falcon 2023）用少量人工标注 + LLM 判官构建可校准、带统计置信的评测，试图兼得无参考的规模与有参考的可信。如何用最少的人工标注换最大的评测可信度，是工程上的核心权衡。
  • 多跳与复杂 RAG 的评测：当回答需要串联多处证据、多步推理（multi-hop），单步的 context recall/faithfulness 不够用——要评「推理链的每一跳是否都有据」「中间结论是否正确传递」。复杂 RAG（agentic RAG、迭代检索）的评测仍缺乏成熟范式。
  • 对抗鲁棒性与负样本（RGB）：RGB（Chen 2023）系统地测 RAG 在噪声鲁棒性、负样本拒答（该说不知道时会不会拒答）、信息整合、反事实抵抗四种能力上的表现。真实系统会遇到检索到错误/矛盾/不相关信息的情况，评测必须覆盖这些『坏输入』下的行为。
  • 评测的可复现与基准漂移：LLM 判官随模型版本变化，导致同一套评测在不同时间给出不同结果（基准漂移）；如何让 RAG 评测可复现、可跨时间比较，是个被低估的难题。

必读：Es 2023（RAGAS，无参考四项指标，本模块的蓝本）、Chen 2023（RGB，RAG 的四种能力与坏输入鲁棒性）、Saad-Falcon 2023（ARES，可校准的自动评测）、Manakul 2023（SelfCheckGPT，一致性幻觉检测）、Honovich 2022（TRUE，把忠实度统一成 NLI）。完整清单见 ../references.md。
