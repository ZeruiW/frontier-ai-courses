1这门课讲什么

欢迎来到 上下文工程与记忆（动手造 Agent 系列）。这门课只追求一件事：让你学会把「上下文窗口」当成 agent 最稀缺的核心资源来经营，并亲手把经营它的那一整套基础设施造出来。

过去两年，agent 从「一次问答」走向「在循环里长时间自主行动」。一个 agent 跑久了，会撞上一道几乎所有人都会撞上的墙：上下文窗口不够用。对话越来越长、工具结果越堆越多、要记住的事越来越杂——迟早超过模型一次能看到的 token 上限。撞墙时会发生两件糟糕的事：「爆」（超出窗口，请求直接失败或被粗暴截断）与 「丢」（为了塞下而丢掉了关键信息，agent 突然『失忆』、开始跑题或自相矛盾）。这门课要解决的，正是如何让一个 agent 在有限的窗口里长时间运行，既不爆、也不丢，还尽量不贵。

这件事的答案不在模型里，而在模型外面的脚手架（scaffold）里——具体说，在「每一步到底把哪些信息、以什么形式放进那个窗口」的决策里。这门学科有个名字叫 context engineering（上下文工程）。它不是『写一句好提示』，而是管理一个会随时间增长、随时可能溢出的信息预算：什么进窗口、什么裁掉、什么压缩成摘要、什么写到窗口外的记忆里再按需召回、什么用检索临时拉进来、哪些稳定内容可以缓存下来省钱。本课就是把这套工程的五个核心零件——token 预算与截断、compaction 与摘要、文件记忆、检索入上下文、prompt 缓存——从零拆开、亲手重建。

学完你应当能回答这类问题（也是 agent / infra 岗位的高频面试题）：一个 200K 窗口的 agent 聊到第几百轮就该做什么？token 怎么数、预算怎么分、超了先丢谁？compaction 在何时触发、把什么压成摘要、又必须保住什么？什么该写进文件记忆、怎么去重？检索怎么把海量外部知识按预算注入？prompt 缓存凭什么省 90% 的钱、又会被什么悄悄搞失效？——并且能在纯 Python 标准库 + MockLLM 里把这五样东西都从零跑通、用 assert 验证。

一句方法论上的话先说在前面：本课的价值不在「我们没有大模型/API key 也能学」这个妥协，而在它逼你只关注真正难、真正不过时的部分——预算、控制流与正确性。模型会换代、窗口会变大、厂商接口会变；而「token 不够时先丢谁」「历史怎么压才不丢关键信息」「缓存前缀为什么一个字节都不能动」这些结构性的东西，换到任何模型、任何窗口大小都立刻能用。把它们练扎实，就抓住了 agent 工程里真正稳定的那一层。

2世界观：上下文窗口 = 有限预算

贯穿全课的世界观，是把上下文窗口理解成一块固定大小、必须精打细算分配的预算，而非一个可以随便往里塞东西的大筐。一次请求里，所有要让模型「看到」的东西都得挤进这同一块预算：

┌────────────────── 上下文窗口 (例如 200K tokens) ──────────────────┐ │ [系统提示] [工具定义] [召回的记忆] [检索结果] [对话历史/摘要] [本轮输入] │ + 给输出预留(max_tokens) │ 钉住·必保 钉住·必保 按需·少量 按预算 会无限增长↑ 每轮变 ↑必须先扣 │ └──────────────────────────────────────────────────────────────────┘ ▲ 加起来必须 ≤ 窗口，否则就「爆」；为塞下而乱丢就「丢」

这张图就是整门课的总纲：每个模块都在解决「如何让这块预算装得下、装得对、装得省」的某一面。模块 01（token 预算与截断）是地基——学会数 token、分预算，并在超出时按优先级裁剪而不是乱丢；模块 02（compaction 与摘要）解决「历史无限增长」这一最大的占用源——到阈值就把旧消息压成摘要而非简单丢弃，腾出空间又不失忆；模块 03（文件记忆）把「该长期记住但不必时刻在场」的东西移出窗口、按需召回，从根本上突破窗口上限；模块 04（检索入上下文）解决「外部知识太多」——用向量检索按预算只拉进最相关的少量，即 agent 的 RAG；模块 05（prompt 缓存）则是经济学——把稳定前缀缓存下来，让长会话不仅装得下、还便宜。

把这块「预算」记牢，你会发现五个看似分散的话题其实是同一道约束的五种应对：超了先裁谁（01）、历史怎么压（02）、什么移到窗口外（03）、外部知识怎么按预算拉进来（04）、稳定部分怎么缓存省钱（05）。这也是本课刻意的编排——不堆专题，而是绕着「窗口是有限预算」这一个核心约束层层加深。

3为什么「窗口是有限资源」是枢纽：能力递进链

为什么「窗口是有限资源」是这一切的枢纽

如果只能记住一句话来理解上下文工程，那就是：模型一次只能看到窗口那么多 token；凡是要影响这一步输出的信息，都必须在这一刻挤进窗口——而窗口装不下全部历史与知识。于是一切矛盾都从这里来：历史在涨、知识无限、记忆要留，窗口却固定。所以上下文工程就是在固定窗口与无限信息之间做分配与取舍，本课把它放在第一位不是偶然。

顺着这条枢纽往外看，本课的五个模块构成一条能力递进链：

模块针对窗口的哪种压力一句话能力
01 token 预算与截断总量超限：先得会数、会分、会按优先级裁让上下文永远塞得进窗口且不丢钉住项
02 compaction 与摘要历史无限增长：最大的占用源把旧历史压成摘要，腾空间又不失忆
03 文件记忆该长期记住的东西占着窗口把记忆移出窗口、按需召回少量
04 检索入上下文外部知识海量、无法全放按预算只把最相关的知识拉进来（RAG）
05 prompt 缓存长会话重复处理稳定前缀=贵缓存稳定前缀，长会话装得下还便宜

注意这不是松散的专题集合，而是一条有内在逻辑的链：先得会数 token、会在超限时正确裁剪（01），才谈得上更聪明的腾挪；对最大的占用源——不断增长的历史——用压缩而非丢弃（02）；把不必时刻在场的记忆移到窗口外、按需取回（03）；把窗口外的海量知识用检索按预算拉进来（04）；最后，当这套机制让 agent 能长时间运行时，成本就浮现为新的约束，于是用缓存把稳定部分的开销压下去（05）。读到最后你会看到：所谓「会做上下文工程」，就是把这五块严丝合缝地拼起来，让一个 agent 能聊上千轮还不爆、不丢、不破产。

4方法论：用 MockLLM 模拟上下文管线并对拍

方法论：没有大模型、没有 API key，怎么学上下文工程？

本环境没有 GPU、不接任何真实大模型、不需要任何 API key。但上下文工程的难点，从来不是「调用模型那一行 API」，而是包在模型外面的那一切：token 怎么数、预算怎么分、超了丢谁、历史怎么压才不丢关键信息、什么写进记忆、检索怎么按预算注入、缓存前缀为什么一个字节都不能动。这些用纯 Python 标准库 + 一个假模型就能精确地表达和验证。

我们的核心工具叫 MockLLM：一个确定性的、规则驱动的假模型。它不学习、不联网、没有神经网络——只是对给定输入返回一个结构正确、可预测的输出（比如「摘要」=按规则抽取并拼接要点；「embedding」=确定性的词频向量；「回答」=查表）。这听起来像作弊，恰恰相反：把模型换成确定性的桩，模型质量的不确定性就被剥离，剩下的全是 scaffold 的对错。你写的 token 预算器、截断器、compaction 器、文件记忆、检索器、缓存模拟，在 MockLLM 下要么对、要么错，没有「模型今天状态不好」的借口——这正是把上下文工程练成肌肉记忆的最干净环境。

直白说

打个比方：学管理一座仓库，不必先有一座爆满的真仓库。上下文工程的「仓管技能」是怎么数货、怎么分区、满了先清谁、怎么把旧货打包压缩、怎么把不常用的移到外仓再按需调回；这些在一个货物可预测的「模型仓库」（MockLLM）里能练得更扎实。等每个动作都做对了，换到真实货流（真实模型）只是把假货换成真货——分配与取舍的逻辑一模一样。

严谨说

关键纪律是对拍 + assert：每个零件都和一个朴素参考实现或明确的不变量比对。截断后总 token 必须 ≤ 预算且钉住项还在；compaction 后关键 id 集合仍可被检出、压缩比落在区间；检索 top-k 必须与暴力扫描一致；缓存命中数必须等于按前缀稳定性解析出的值。结构正确 → assert 通过；assert 通过 → 这套逻辑可以原样搬到真实模型。

真实上下文管线里的东西本课的模拟对应真实接口
大模型（生成/摘要/嵌入）MockLLM：规则驱动的确定性桩Anthropic client.messages.create(model='claude-sonnet-4-6')
token 计数确定性近似计数器（按空白/字符规则）messages.count_tokens（对目标模型精确）
一次请求的上下文system + messages 数组（自写组装）Messages API 的 system 字段 + messages
对话压缩摘要旧消息 + 保留近期（自写）服务端 compaction / 上下文编辑
外部记忆本地文件 + 读/写/更新/去重（自写）memory 工具（/memories 目录）
检索toy 词频 embedding + 余弦 + top-kembedding 模型 + 向量库(FAISS/ANN)
prompt 缓存前缀哈希 + 命中表 + 成本账（自写）cache_control: {type:'ephemeral'} + usage

务必清楚本课不教什么：不教提示工程的具体话术、不调真实模型的超参、不追求检索/摘要的 SOTA 质量。这些在你有了正确的 scaffold 之后，是第二步（references 里的官方文档、RAG/MemGPT/Lost-in-the-Middle 接手）。本课负责把第一步——预算、控制流与正确性夯死；这一步搞定，第二步才有意义。也正因如此，本课的代码刻意不调用任何需要密钥的服务，你随时能 `python` 跑通每一个 cell。

5环境与运行

环境与运行

环境极简到了极致：只需 Python 3 标准库（个别可视化可选 matplotlib，且非必需）。全课 CPU 秒级运行，无需 GPU、无需联网、无需任何 API key、甚至不需要 pip 装任何东西。凡是用到「模型」的地方都是 MockLLM。

# 真的什么都不用装——标准库就够
python3 -V          # 3.8+ 即可
jupyter lab         # 若要在 notebook 里跑（jupyter 非课程依赖）
# 想接真实模型时(可选)：pip install anthropic，并设置 ANTHROPIC_API_KEY

每个模块配一个 notebook，结构统一：先用标准库把机制从零实现并验证（5–6 个 worked 小节，每节都跑出可打印的输出与 assert 自测），再做 3–4 道带 assert 判分的 ✏️ 练习（先给骨架，自己填，再对照 📖 参考答案），最后一个真实数据胶囊（用真实文本/真实 token 量级/真实接口形状，把纸面知识接到现实）。每个 notebook 都端到端可跑、不需要密钥；并在关键处旁附真实 Anthropic Messages API + prompt caching 的形状对照——更进一步，本课的真实适配代码刻意写成「有 key 就用真实 Claude，没 key 自动回退 MockLLM」，所以无论你有没有密钥，整本 notebook 都能一路跑到底，绝不阻断。

建议的学习节奏：先读完整章 HTML 建立「窗口即预算」的直觉，再打开 notebook 亲手实现。读和做缺一不可——只读会觉得「好像懂了」，真正动手写预算器、调截断顺序、让 compaction 不丢关键 id、让 top-k 与暴力解一致、让缓存命中数对上时，才会发现魔鬼藏在哪些细节里（输出预留漏扣、钉住项被误丢、摘要漂移、注入超预算、前缀里一个时间戳让缓存全 miss）。这门课的深度正是为「动手」服务的。

配套先读：Anthropic 的 _Effective context engineering for AI agents_（世界观总纲）、_Prompt caching_ 与 _Messages API_ 文档（接口）、Liu 2023 _Lost in the Middle_（为什么不能无脑塞满）、Lewis 2020 _RAG_（检索增强）、Packer 2023 _MemGPT_（分层记忆）。完整清单见 references.md。

✅ 学完整门课，你应该能：
  1. 把上下文窗口理解成一块有限预算，说清在每一步里 scaffold 如何为它分配与取舍；
  2. 从零写一个 token 预算器 + 截断器：计数、按部分分预算、扣输出预留、按优先级裁剪并保住钉住项；
  3. 从零写一个 compaction 器：按阈值触发、把旧消息摘要、保留近期原文、连续触发不丢关键信息、并算出压缩比；
  4. 从零写一个文件记忆系统：结构化条目的写入/读取/更新/去重与按需召回；
  5. 从零写一个检索器：toy embedding + 余弦相似 + top-k + 重排 + 注入预算，把外部知识按预算拉进上下文；
  6. 从零模拟 prompt 缓存：前缀命中、TTL、并为一个长会话算出开缓存能省多少钱；
  7. 把验证过的标准库 / MockLLM scaffold 映射到真实 Anthropic Messages API + prompt caching，知道下一步怎么接真模型（且无 key 也能回退跑通）。
