1模拟 vs 真实测量：为什么两者都要

00–07 的全部实验跑在模拟推理器上：每步成功率 $p$、verifier 噪声 $\sigma$、题目难度分布全部由你设定， ground truth 完全已知。这是做机制研究的理想实验台——但它回答不了一个问题： 这些结论在真实模型上还成立吗？本模块就是来补这一块的。

直白讲

模拟器像风洞：可控、可重复、便宜，能把"majority voting 为什么会被系统性偏差卡住"这种机制问题拆到根上。 但风洞里的飞机没遇到过真天气。真模型实验就是试飞：贵、吵、不可控变量一堆，但只有它能告诉你 风洞结论的外推范围。先风洞后试飞，是工程学的标准流程——评测科学也一样。

严谨讲

模拟实验提供internal validity（内部效度）：变量可控、因果链清晰、 结论可与解析解对照（如 02 的 majority@N 期望公式）。真模型实验提供external validity （外部效度）：测量对象就是部署对象。二者的分工是理论模型预测 → 真实测量检验： 模拟给出定性形状（曲线上升/饱和/分叉），真模型检验该形状是否出现、在何处偏离。 只有模拟没有测量是空中楼阁，只有测量没有模拟则无法归因——这正是 evaluation scientist 的日常工作循环。

本模块每个实验都遵循同一张表格：模拟预测（00–07 已得）→ 真模型观测 → 一致 / 偏离 / 无法判定。 注意我们对照的是定性形状而不是具体数值——模拟器的 $p=0.8$ 和 Gemini 在你那 20 道题上的正确率没有数值上的对应关系。

2真模型实验的设计要点：预算、采样参数、答案抽取

把模拟实验搬到真模型，有三个新自由度必须钉死，否则结果不可解释：

设计维度本模块的选择为什么重要
采样参数多样性采样用 temperature=1.0（self-consistency 需要多样的推理路径 [Wang 2022]）；verifier 与判分用 temperature≈0（要的是稳定判断不是多样性）02 模块证明过：聚合的收益来自路径多样性。temperature=0 采 16 条全一样，majority@N 曲线必然是平线——这不是模型问题，是实验设计错误
预算口径统一用 token 计数（API 返回的 usageMetadata），thinking token 单独记05/06 的教训：不报预算口径的准确率没有意义。真模型的"一次采样"成本随输出长度浮动，必须实际计量
答案抽取鲁棒的 extract_answer：先找"答案是 X"模式，再退化到最后一个数字；抽取失败显式记 None 而非算错LLM_Evals_Course 03 的核心教训：抽取器的失败会被算成模型的失败。真模型的输出格式远比模拟器脏——这是搬到真模型后第一个新增误差源
抽取误差会污染所有下游结论。正确顺序是：先在若干条真实输出上人工检查 extract_answer 的命中率， 确认抽取可靠，再去解读 majority@N 曲线。如果发现"加大 N 反而掉点"，第一怀疑对象是抽取器而不是模型—— 把"答案是 12 美元"抽成 None 的 bug 在聚合实验里会被放大 N 倍。

3API 评测的工程纪律：重试 · 限速 · 缓存 · 成本预估

API 评测是工程活。四条纪律，每条都对应一类真实事故：

  1. 成本预估先行：跑任何实验前先算 token 成本。估算公式很粗糙但必须有：
    $$ \text{cost} \approx \sum_{\text{prompt}} n_{\text{samples}} \cdot \left( \frac{T_{\text{in}}}{1000} \cdot P_{\text{in}} + \frac{T_{\text{out}}}{1000} \cdot P_{\text{out}} \right) $$
    其中 $T_{\text{in}} \approx \text{len(prompt)}/4$（英文）。本模块全部实验在 gemini-2.5-flash 上约 $10^5$–$10^6$ token 量级， 成本在一美元以内——但同样的代码换 pro 档模型加 32k thinking budget，成本能翻两个数量级。预估是习惯不是仪式。
  2. 缓存（caching）：以 hash(prompt + 全部采样参数) 为 key 把响应落盘。 好处有三：断点续跑不重复计费、实验可复现、调试下游代码（抽取/聚合/画图）零成本。 注意 key 必须包含 temperature / thinking_budget 等所有影响输出的参数，否则会拿错缓存——一个经典的静默 bug。
  3. 重试与限速（retry & rate limiting）：429/5xx 用指数退避（exponential backoff）重试 2–3 次； 免费档 Gemini 有 RPM/TPD 限额，批量实验要主动 sleep。重试时注意：对幂等的 generateContent 可以安全重试，但重试得到的是新采样—— 如果你在做方差敏感的实验，重试策略本身就是实验设置的一部分，要写进报告。
  4. 优雅回退（graceful fallback）：没有 key 时自动切到确定性 mock。这不只是方便——它把"实验逻辑"与"模型后端"解耦， 让聚合/抽取/画图代码可以在 CI 里零成本测试。生产评测 harness 都长这样：后端可插拔，逻辑可单测。
绝不把 API key 写进代码或 notebook 输出。从环境变量 GEMINI_API_KEY 读取； notebook 提交前检查输出 cell 里没有泄漏 key（报错 traceback 里的 URL 是常见泄漏点——本模块的 API 层会在异常信息里抹掉 key）。

4Gemini API 速览：generateContent 与 thinkingConfig

本模块只用一个 REST 端点，纯标准库 urllib 即可调用，不需要 SDK：

POST https://generativelanguage.googleapis.com/v1beta/models/{model}:generateContent Header: x-goog-api-key: $GEMINI_API_KEY （或 ?key=... 查询参数） Body: { "contents": [{"parts": [{"text": "你的 prompt"}]}], "generationConfig": { "temperature": 1.0, ← 采样温度 "candidateCount": 4, ← 一次请求返回多条采样（上限 8） "maxOutputTokens": 1024, "thinkingConfig": {"thinkingBudget": 512} ← 思考预算（token 数） } } 返回: candidates[i].content.parts[*].text + usageMetadata （promptTokenCount / candidatesTokenCount / thoughtsTokenCount）

关键参数是 thinkingConfig.thinkingBudget——这就是 06 模块 budget forcing 的产品化形态：gemini-2.5 系列允许把内部思考的 token 预算设为 0（关闭思考，flash 档支持）、固定值（128–24576），或 -1（动态：模型自行决定想多久）。 gemini-3 系列则改用粗粒度的 thinkingLevel（low/high）。这给了评测者一个在 s1 [Muennighoff 2025] 里要靠注入 "Wait" 才能实现的能力：外生地控制思考长度，扫出 accuracy-budget 曲线。

对照阅读：s1 的 budget forcing 靠解码端干预（截断思考 / 追加 "Wait" 强制延长），是研究者的 hack； thinkingBudget 是同一思想的 API 原语。两者都把"思考多久"从模型内生变量变成实验自变量—— 这正是 06 模块"预算扫描"实验在现实中可执行的原因。注意 API 文档明言 budget 是软目标， 实际 thoughtsTokenCount 可能略超——所以报告时要记录实际用量而非名义预算。

没有 key 时，notebook 自动切换到 MockGemini：一个对内置题库按难度参数化正确率、 带可复现 rng 的确定性模拟模型，接口与真 API 完全一致。它本质上就是 00–07 的模拟推理器穿上了 API 的衣服—— 所以 mock 路径跑出的曲线会精确复现模拟版结论，这本身就是一次对照实验。

5逐实验设计卡：A/B/C/D + scaling 对照

四个实验共用一个 20 题的小题库（自写 GSM8K 风格应用题 + 数字谜题，唯一数值答案，带难度标签）。 题库小是刻意的：这是方法论演示不是 benchmark——第 6 节会讲小样本下该怎么解读。

实验 A（对应 02）· Self-Consistency：majority@N 曲线
  • 模拟预测：N 增大时准确率单调上升并收敛；若模型对某题有系统性偏差（最频繁的错误答案比正确答案更常见），majority 会收敛到错误答案——加算力救不了 [02 模块]
  • 设计：每题 temperature=1.0 采 16 条，取前 N 条做 majority voting，画 accuracy vs N（N=1..16），按难度分层
  • 看什么：曲线形状是否复现"上升收敛"；难题是否出现 plateau（被偏差卡住的现实版）
实验 B（对应 03）· LLM-as-Verifier 的 Best-of-N
  • 模拟预测：verifier 好于随机时 BoN > random；verifier 与 majority 谁强取决于 verifier 质量与答案分布 [03 模块；Cobbe 2021 的 GSM8K verifier 正是此设计]
  • 设计：复用 A 的采样作候选；用低 temperature 的 Gemini 当 verifier 给每条解答打 1–10 分（prompt 模板在 notebook）；三线对比：BoN（取最高分）vs majority vs random
  • 看什么：真 LLM verifier 是否提供超过 majority 的信号；verifier 给错误解答打高分的案例（Goodhart 的现实素材）
实验 C（对应 06）· Thinking Budget 扫描
  • 模拟预测：简单题在小预算就饱和（早停无损），难题准确率随预算上升 [06 模块的 overthinking/underthinking 不对称]
  • 设计：thinkingBudget ∈ {0, 512, 2048} 三档（模型不支持时退化方案：maxOutputTokens + "直接给答案"/"展示完整推理"的 prompt 控制），按难度分层画 accuracy vs budget
  • 看什么：两条难度分层曲线是否一条平、一条升——这是为"按题分配预算"的 compute-optimal 路由 [Snell 2024] 提供的现实证据
实验 D（对应 07）· GSM-Symbolic 式扰动
  • 模拟预测：模板记忆模型在换数字后大幅掉点、加无关从句后再掉一截；真算术模型基本不掉 [07 模块；Mirzadeh 2024]
  • 设计：题库每题做两种扰动——换数字（答案随之重算）、加无关从句（GSM-NoOp 式）——测三个版本的准确率差
  • 看什么：掉点幅度。前沿模型在这种小学题上通常只轻微掉点，但 NoOp 从句的影响常大于换数字——与 Mirzadeh 2024 的发现定性一致
对照卡（对应 05）· Inference Scaling 视角再看实验 A
  • 模拟预测：coverage / 准确率随 $\log N$ 近似线性上升后饱和 [05 模块；Brown 2024 "Large Language Monkeys" 的幂律]
  • 设计：不跑新实验——把实验 A 的 x 轴换成总 token 数（N × 平均每条 token），就是一条真实的 inference scaling 曲线
  • 看什么：同一份数据换个坐标系就回答另一个问题——这是评测里"一次采集、多次分析"的省钱习惯

6结果解读：外推限度与定性对照

20 道题 × 1 个模型的实验能下什么结论？这是本模块最重要的方法论训练：

  • 能下的结论：定性形状的复现与否（"majority@N 在这组题上单调上升"）；机制存在性（"verifier 确实给一条错误解答打了 9 分"——存在性只需一个反例）；工程可行性（"thinkingBudget 确实能外生控制思考长度"）。
  • 不能下的结论：任何带数值的外推（"Gemini 在小学数学上 majority@16 提升 7 个点"——20 题的二项标准误 $\sqrt{p(1-p)/20} \approx 0.09$，7 个点在噪声里）；跨模型/跨任务的推广（单模型单数据集）；与模拟器参数的数值对应。
  • 正确的报告姿势：每条结论标注样本量与不确定度（02 模块与 LLM_Evals_Course 02 的 CI 纪律）；模拟 vs 真实的对照表只填"一致 / 偏离 / 无法判定"三档，偏离处写下候选解释（抽取误差？题库太易饱和？预算口径不一致？）。
"无法判定"是合法且常见的格子。真模型在你的 20 道题上可能全对——此时 majority@N 是平线， 既不验证也不否证模拟预测，只说明题库难度对该模型饱和了。正确反应不是换结论而是换题库（提高难度）， 这恰好就是 07 模块讲的 benchmark saturation 在你桌面上的微缩版。

7安全与成本提示

  • Key 管理：环境变量注入，不进代码、不进 git、不进 notebook 输出。怀疑泄漏立即在 AI Studio 吊销重发。
  • 成本上限：notebook 默认参数下全部实验约几十万 token（flash 档 ≪ $1）。改大 N、换 pro 档、加大 thinkingBudget 前先重跑成本预估 cell。免费档注意 RPM 限额，触发 429 时 notebook 的退避重试会自动处理，但整体耗时会拉长。
  • 缓存即账本：磁盘缓存目录就是你的完整请求记录，跑完实验可以从缓存统计实际 token 用量与等效成本——审计你自己的实验是个好习惯。
  • 数据卫生：发给 API 的题目视为公开数据（免费档的数据可能被用于改进模型）。不要把私有评测集通过免费 API 跑——这会污染未来模型的训练数据，制造你自己课上学过的 contamination [07 模块]。
  • 本地替代：有 RTX 4090 的话，可把 llm_generate 的后端换成本地推理服务（vLLM / Ollama 的 OpenAI 兼容端点），零 API 成本复跑全部实验——接口已为此解耦。

8从这里出发：把实验台升级成研究项目

  • 换更难的题库：把 20 道自写题换成 AIME 或 GSM-Symbolic 的公开切片，本 notebook 的全部代码不需要改——这是"逻辑与后端解耦"的回报。
  • 跨模型对照：同一套实验在 flash / pro / 本地开源推理模型上各跑一遍，看哪些定性结论是模型不变的（candidate universal laws）、哪些是模型特异的。
  • verifier 研究：实验 B 的 LLM verifier 可以系统升级——换 prompt（rubric 式 vs 直接打分）、换温度、self-consistency 化 verifier 本身，复现 03 模块"verifier 质量决定 BoN 上限"的现实版。
  • thinking 经济学：用 usageMetadata 的 thoughtsTokenCount 做真实的 token-per-correct-answer 核算，复现 06 的帕累托前沿——这是 2025 年后推理模型评测报告的标配图。
