1为什么要"从零手写"：用 API 的人和懂内核的人差在哪

调用 model.generate() 不需要懂 LLM；但解释模型为什么这样输出、把一个失败归因到正确的组件、对一篇架构论文做出可信判断——这些都需要懂内核。 两类人的差距不在"会不会用"，而在遇到异常时能不能打开黑盒：

场景只会调 API 的人懂内核的人
模型算不对 9.11 vs 9.9"模型数学差"检查 tokenizer 怎么切分数字：9.11 可能被切成 9/./11，比较发生在错误的表征上（模块 01）
loss 训到 3.2 不再下降"再训久一点？"先算 baseline：均匀分布的 loss 是 $\ln V$；再查学习率调度、初始化、数据是否重复（模块 03/05）
输出复读机式重复"模型坏了"greedy 解码的已知退化模式 [Holtzman 2019]，换 top-p / 温度即可复现与消除（模块 04）
长对话越来越慢、显存爆炸"换大机器"KV cache 随上下文线性增长，算得出每 token 多少字节（模块 06）
评测分数异常"换个 benchmark"把失败归因到 tokenizer / 架构容量 / 训练数据 / 解码超参中的哪一层（全课目标）

直白讲

本课的规矩是：每个组件你都亲手写一遍，然后和官方实现数值对拍。 你写的 BPE 要和 tiktoken 切出一样的 token；你写的 attention 要和 torch.nn.functional.scaled_dot_product_attention 输出逐元素一致；你写的解码器要能复现 HuggingFace 的采样行为。 对拍通过的那一刻，你才真正"拥有"了这个组件。

严谨讲

这是一种差分测试 differential testing方法论：以参考实现 $f_{\text{ref}}$ 为 oracle， 验证自研实现 $f_{\text{ours}}$ 满足 $\|f_{\text{ours}}(x)-f_{\text{ref}}(x)\|_\infty < \epsilon$（通常 $\epsilon=10^{-5}\sim10^{-6}$，浮点误差容限）。 它把"我大概理解了"变成可证伪的命题——这与做 model evaluation 的方法论同构：先定义 oracle 与容差，再做断言。

全课的参照系是 Karpathy 的 nanoGPT 与 minbpe [Karpathy 2022, 2024]：用最少的代码实现"真正的" GPT。 我们走同一条路，但每一步都补全数学推导、失败模式与评测视角。

3学习法：HTML 建框架 → notebook 手写 → 练习必做

每个模块都是同一个三步循环：

  1. 读 HTML 讲解（30–60 分钟）：建立动机、数学框架与关键论文坐标，不急着写代码。
  2. 跑配套 notebook（30–90 分钟）：notebook 是主战场。先逐 cell 运行理解，再动手改参数观察行为。
  3. ✏️ 练习必做：每本 notebook 含 2–4 道练习，给函数骨架 + TODO，配 assert 自测 cell——全部断言通过才算过关。卡住超过 20 分钟再看末尾的 📖 参考答案。
不做练习等于没学。本课的知识密度全在"手写 + 对拍"这个动作里：看懂 attention 公式只需 5 分钟，写出和 PyTorch 逐元素一致的实现会暴露你以为懂了但没懂的全部细节（mask 的位置、$\sqrt{d_k}$ 除在哪、softmax 沿哪个维度）。
算力零门槛：全课 8 个模块都在 CPU 上跑。mini 规模的 GPT（约 1M 参数级）在笔记本上几分钟训完； scaling law 实验用一组小模型完成；tiktoken / transformers 只用来做参考对照，不下载大模型权重，不需要任何 API key。 有 GPU / Apple MPS 当然更快，但不是必需。

5前置自测 5 问

本课假设你具备以下基础。5 问都能在 2 分钟内答出 → 直接开始；卡住 ≥2 问 → 先补对应基础再回来，否则模块 02/03 会非常吃力。

  1. 矩阵乘形状：$A\in\mathbb{R}^{32\times 64}$，$B\in\mathbb{R}^{64\times 128}$，$AB$ 的形状是什么？$BA$ 呢？ （答：$AB\in\mathbb{R}^{32\times 128}$；$BA$ 不合法，$128\neq 32$。attention 里 $QK^\top$ 的形状推理全靠这个。）
  2. 链式法则：$L = (wx + b - y)^2$，写出 $\partial L/\partial w$。 （答：令 $e = wx+b-y$，则 $\partial L/\partial w = 2e\cdot x$。反向传播 = 链式法则的系统化执行。）
  3. 交叉熵：分类分布 $p$（one-hot 真值）与模型分布 $q$，交叉熵 $H(p,q)$ 的定义是什么？为什么它是语言模型的训练目标？
  4. PyTorch tensor 基础：torch.randn(2,3) @ torch.randn(3,4) 的形状？tensor.sum(dim=-1) 沿哪个维度求和？requires_grad=True 意味着什么？
  5. Python 类：能写一个带 __init__ 和方法的类，并解释 self 是什么吗？（模块 02 起我们用 nn.Module 子类组织全部代码。）

第 3 问是全课最重要的一个公式，这里直接给出，模块 03 会从最大似然完整推导：

$$ H(p, q) \;=\; -\sum_{i=1}^{V} p_i \log q_i \;\;\xrightarrow[\;p=\text{one-hot}(t)\;]{}\;\; -\log q_t \;=\; -\log \frac{e^{z_t}}{\sum_{j=1}^{V} e^{z_j}} \;=\; -z_t + \log\!\sum_{j=1}^{V} e^{z_j} $$

语言模型训练就是在每个位置上最小化这个量：让真实下一个 token $t$ 的 logit $z_t$ 相对其他 token 尽可能大。 最后一步的 $\log\sum e^{z_j}$ 就是 log-sum-exp——直接算会数值溢出，配套 notebook 的练习 2 会让你用稳定技巧亲手实现它。

6LLM 内核全局图景：四大件与后续课程

任何一个 LLM 系统都可以拆成四大件，本课 8 个模块正好覆盖：

┌────────────┐ ┌──────────────┐ ┌────────────┐ ┌─────────────┐ │ Tokenizer │──►│ Architecture │──►│ Training │──►│ Inference │ │ (字符↔ID) │ │ (attention/ │ │ (loss/优化/ │ │ (解码策略/ │ │ │ │ block/位置) │ │ scaling) │ │ KV cache) │ └────────────┘ └──────────────┘ └────────────┘ └─────────────┘ 模块 01 模块 02, 07 模块 03, 05 模块 04, 06 本课（预训练内核）之上，是另外两层： • 后训练 Post-Training（SFT / RLHF / DPO） → 后训练课 • 评测 Evaluation（benchmark / 统计 / 归因） → 评测课

本课只覆盖预训练内核——但它是上面两层的地基：后训练课里的 SFT loss 就是模块 03 的交叉熵换了数据分布； RLHF 的采样器就是模块 04 的解码策略；评测课里所有 log-prob 打分都建立在你理解 logits → softmax → 概率这条链上。

评测视角（本课对 evaluation 工作者的核心价值）：理解内核，才能把评测失败归因到对的层。 一个模型在 benchmark 上翻车，根因可能在四大件的任何一层：tokenizer 把数字/代码切坏了（01 层）、上下文长度外推失败（07 层 RoPE）、 训练数据不足或污染（03/05 层）、解码超参把好模型采样坏了（04 层）。 分不清这些层的评测者，只能报告"分数低"；分得清的，能写出"该模型在长上下文任务的退化源于位置编码外推，而非能力缺失"这样可执行的结论。 这正是 frontier lab 的 model evaluation 岗位与"跑分员"的区别。

7研究前沿与开放问题

  • Tokenizer 会消失吗？ 字节级/无 tokenizer 路线（byte-level 模型、动态 patch 化）试图绕开 BPE 的全部病理（数字切分、多语言不公平）。但序列变长、算力代价大。评测视角：tokenizer 差异使跨模型的 per-token 指标（如 perplexity）不可直接比较——必须换算到 per-byte。
  • Attention 的替代者：SSM（Mamba [Gu & Dao 2023]）与混合架构能否在大规模下追平 Transformer？目前的共识是混合层（少量 attention + 大量线性算子）最实用。评测视角：线性架构的检索/精确回忆（recall）短板需要专门的 needle 类评测才能暴露，平均分看不出来。
  • Scaling law 还成立吗？ 高质量数据逼近耗尽 [Muennighoff 2023]，repeated-data 与合成数据的 scaling 规律仍在重写。评测视角：模型能力预测（先用小模型外推大模型表现）正是 evaluation 与 scaling law 的交叉点，模块 05 亲手做一遍。
  • 推理时计算 test-time compute：更长的思考链/更多采样换更高准确率，改变了"能力"的定义——同一个权重在不同推理预算下是"不同的模型"。评测视角：报告分数必须同时报告解码配置与推理预算，否则不可复现；这会回到模块 04 的解码参数。
