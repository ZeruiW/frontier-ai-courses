1解码 = 从分布到序列：likelihood trap

模块 03 训练出的 mini-GPT，每一步前向只做一件事：给定前缀 $x_{<t}$，输出整个词表上的 logits $z\in\mathbb{R}^{|V|}$，经 softmax 得到下一 token 的条件分布 $p_\theta(x_t\mid x_{<t})$。模型到此为止 —— 它从不"说话"。把一串分布变成一条具体的 token 序列，是解码器（decoder / sampler）的工作。

直白讲

语言模型本体只负责"报概率"：下一个词是"猫"的概率 30%、"狗" 20%……至于到底写下哪个词，是解码策略说了算。同一个模型，换一套解码规则，输出可以从机械复读变成流畅文章。所以"模型行为"永远是"权重 + 解码策略"的合成物。

严谨讲

自回归 LM 定义序列分布 $p_\theta(x_{1:T})=\prod_t p_\theta(x_t\mid x_{<t})$。解码策略是一个（可能随机的）映射 $\mathcal{D}: p_\theta \mapsto x_{1:T}$。确定性策略（greedy/beam）逐步或全局逼近 $\arg\max p_\theta(x_{1:T})$；随机策略（temperature/top-k/top-p）从某个对 $p_\theta$ 做过变换的分布 $\tilde p$ 中采样。不同 $\mathcal{D}$ 诱导的输出分布可以与 $p_\theta$ 相差极远。

一个反直觉的核心事实：对开放式生成，"最大似然的序列"是糟糕的序列。 [Holtzman 2019] 把 GPT-2 的 beam search 输出与人类文本对比，发现两件事：

  • 最大化似然 → 退化的重复文本：beam search 找到的高似然序列充斥着短语级循环（"I'm not sure if I'll ever be able to walk again. I'm not sure if I'll ever…"）。重复一旦开始还会自我强化——重复过的短语条件概率越来越高，形成正反馈。
  • 人类文本不是高似然文本：人写的句子在模型视角下 per-token 概率剧烈波动，常常落进分布的低概率区。自然语言带有信息量，必然偶尔"出人意料"。
[Holtzman 2019] The Curious Case of Neural Text Degeneration：这篇论文给"likelihood trap"提供了决定性的实证 —— 解码目标不应是最大化似然；它同时提出了本章第 4 节的 nucleus sampling（top-p）作为解法。读 LLM 输出"复读机化"的任何讨论，源头都在这里。
为什么"逐 token 最优"不等于"序列最优"，"序列最优"又不等于"好"？前者是搜索问题（greedy 是 beam=1 的近似）；后者是目标函数错了：训练目标（极大似然）衡量的是"模型给人类文本多高概率"，而不是"模型概率最高的文本像不像人话"。两个方向不对称。

2greedy 与 beam search：为什么 beam 在开放生成中失效

Greedy decoding：每步取 $x_t=\arg\max_v p_\theta(v\mid x_{<t})$。$O(T)$ 次前向，无超参，结果（理想中）确定。缺点：每步局部最优，既不保证全局最优序列，也继承上一节的退化问题。

Beam search：维护 $B$ 条候选前缀（beam），每步把每条前缀扩展 $|V|$ 种、按累计 log-prob 留前 $B$ 条，是对 $\arg\max_x \log p_\theta(x)$ 的宽度受限搜索：

beam search (B=2) 的搜索树 —— 数字为累计 log-prob，✦ = 留在 beam 内 <s> ├── "The" (-0.4) ✦ ──┬── "The cat" (-1.1) ✦ ──┬── "The cat sat" (-1.6) ✦ │ │ └── "The cat is" (-2.3) ✗ 被剪 │ └── "The dog" (-1.9) ✗ └── "A" (-0.9) ✦ ──┬── "A cat" (-1.8) ✦ ──┬── "A cat sat" (-2.4) ✦ │ └── "A man" (-2.5) ✗ └── "An" (-2.1) ✗ （第 1 步就出局，后续永远不会被探索）

在封闭式任务（机器翻译、摘要、ASR）里 beam search 长期是标配：输出空间被源文本强约束，高似然 ≈ 高质量。但在开放式生成中它系统性失效，原因有三：

  • 它太成功了：beam 越宽越逼近全局最大似然序列，而第 1 节已说明那是退化文本 —— 搜索越好，结果越差，这就是 likelihood trap 的搜索面。
  • 多样性坍缩：$B$ 条 beam 往往共享前几个 token，最终候选近乎彼此的改写。
  • 长度偏置：累计 log-prob 每步只减不增，天然偏好短序列；length penalty 只是补丁。
实务结论：今天的 chat LLM 推理几乎不用 beam search；它仍活跃在翻译/ASR 等似然与质量对齐的场景。判断要不要 beam，问一句"这个任务里高似然是否就是我要的答案"。

3temperature：logits/T 的数学效果

既然要采样，第一个旋钮是 temperature $T$：采样前把 logits 整体除以 $T$。

$$ p_i^{(T)} \;=\; \frac{\exp(z_i/T)}{\sum_{j} \exp(z_j/T)} $$

关键性质一：任意 $T>0$ 都不改变 token 的概率排序（$z_i>z_j \Leftrightarrow z_i/T>z_j/T$），改变的只有概率差距的悬殊程度。关键性质二：分布的熵随 $T$ 单调变化。考察两个 token 的概率比：

$$ \frac{p_i^{(T)}}{p_j^{(T)}} = \exp\!\Big(\frac{z_i - z_j}{T}\Big) \qquad\Longrightarrow\qquad T\downarrow \;\Rightarrow\; \text{比值愈悬殊（分布尖锐，熵}\downarrow\text{）};\quad T\uparrow \;\Rightarrow\; \text{比值}\to 1\text{（分布平坦，熵}\uparrow\text{）} $$

更一般地，对香农熵 $H(T)=-\sum_i p_i^{(T)}\log p_i^{(T)}$ 求导可得（记 $u_i=z_i/T$）：

$$ \frac{\partial H}{\partial T} \;=\; \frac{1}{T}\,\mathrm{Var}_{i\sim p^{(T)}}\!\left[u_i\right]\;\ge\;0 , $$

即熵是 $T$ 的单调不减函数（softmax 分布族沿温度方向的标准结论；等号仅当所有 logits 相等）。两个极限把这条曲线钉死在两端：

  • $T\to 0^+$：最大 logit 的概率 $\to 1$，采样退化为 greedy（argmax），熵 $\to 0$（若最大值唯一）。
  • $T\to\infty$：所有 $z_i/T\to 0$，分布 $\to$ 均匀分布，熵 $\to \log|V|$，输出变成词表乱码。
$T$ 调的是"敢不敢冒险"：$T<1$ 把概率质量进一步推向头部（保守、可复现性更好）；$T>1$ 把质量摊给长尾（多样、易出错）。但 $T$ 是全局缩放——它无法只削尾巴不动头部。要外科手术式地切掉不可靠长尾，需要下一节的截断采样。

4top-k 与 top-p（nucleus）：截断采样

退化文本的另一来源是长尾误差：softmax 给词表里几万个明显不通的 token 各留一点概率，单个极小、合计不可忽略；纯采样（$T=1$，不截断）每隔几十步就会踩中一次长尾，错误 token 进入上下文后引发连锁跑偏。截断采样（truncated sampling）的思路：先把分布裁剪到一个可信子集，再归一化采样。

Top-k [Fan 2018]：只保留概率最大的 $k$ 个 token。记 $V_k$ 为按概率降序的前 $k$ 个：

$$ \tilde p(v) = \begin{cases} p(v)\,/\!\sum_{w\in V_k} p(w), & v\in V_k \\[2pt] 0, & \text{否则} \end{cases} $$

Top-p / nucleus sampling [Holtzman 2019]：保留累计概率刚达到 $p$ 的最小头部集合（nucleus）$V_p$：

$$ V_p \;=\; \text{最小的 } V' \subseteq V \text{（按 } p(v) \text{ 降序取）使得} \sum_{v\in V'} p(v) \,\ge\, p , \qquad \tilde p(v) = \frac{p(v)\,\mathbb{1}[v\in V_p]}{\sum_{w\in V_p} p(w)} $$

两者的本质区别：top-k 固定"个数"，top-p 固定"概率质量"，于是 top-p 的保留集合大小随分布形状自适应。看两种典型情形：

情形 A：尖峰分布（下一个 token 几乎确定） 情形 B：平坦分布（许多合理延续） prob prob 0.86 █████████████████ "是" 0.08 ██ "猫" ██ "狗" ██ "他" ██ "我" 0.06 █ "就" 0.07 ██ "树" ██ "天" ██ "车" … 0.03 ▌ "也" 0.05 █ …（几十个候选不相上下） 0.01 ▏ … 0.01 ▏ … ────────────────────────── ────────────────────────── top-k (k=40)：硬塞进 40 个候选， top-k (k=40)：也许还砍掉了 其中 ~37 个是垃圾长尾 → 引入噪声 第 41~60 个同样合理的候选 → 损失多样性 top-p (p=0.9)：只留 2~3 个 → 恰到好处 top-p (p=0.9)：留下 ~30 个 → 恰到好处

实践中 temperature、top-k、top-p 常常串联使用（先 $z/T$，再截断，再归一化采样），各管一段：$T$ 整体调形状，截断负责把"不可信尾巴"清零。notebook 里你会把这条流水线在 20 行代码内完整写出来。

5repetition penalty 与 frequency / presence penalty

截断采样降低了"踩长尾"的概率，但没有正面解决重复的自我强化。一类直接的工程对策：在采样前，依据"已出现过的 token"惩罚 logits。

Repetition penalty（最早随 CTRL 模型提出，现为 HF transformers 的标准实现约定）：对已出现 token 的 logit，用系数 $r>1$ 削弱——正 logit 除以 $r$，负 logit 乘以 $r$（两个方向都让该 token 变得更不可能）：

$$ z_v' = \begin{cases} z_v / r, & z_v > 0 \\ z_v \cdot r, & z_v \le 0 \end{cases} \qquad \text{对所有 } v \in \{\text{已生成 token}\} $$

Frequency / presence penalty（OpenAI API 约定）：线性作用在 logits 上，前者按出现次数累加、后者只看是否出现过：

$$ z_v' \;=\; z_v \;-\; \alpha_{\text{freq}}\cdot \mathrm{count}(v) \;-\; \alpha_{\text{pres}}\cdot \mathbb{1}[\mathrm{count}(v)>0] $$
机制作用方式随出现次数增长？主要副作用
repetition penalty $r$乘性（除/乘 $r$）否（出现 1 次与 10 次同罚）对 logit 符号敏感：同一 token 的 logit 在 0 附近抖动时惩罚力度不连续；罚掉功能词伤语法
frequency penalty $\alpha_{\text{freq}}$加性 × 次数是，线性累加长文本里高频必需词（标点、"the"）被越压越狠，后期文风变形
presence penalty $\alpha_{\text{pres}}$加性 × 一次否鼓励换话题，但无法阻止已出现短语的高频循环
这些惩罚全是无原则的 heuristic：它们直接篡改 $p_\theta$，没有任何"输出仍服从某个有意义分布"的保证。$r$ 调大一点就会出现"模型拒绝使用句号"之类的怪相。代码生成、数学推导这类合法重复密集的任务（变量名、缩进、公式符号），开 repetition penalty 往往直接损害正确率 —— 评测时要特别检查 harness 是否悄悄开了它。

6speculative decoding：加速且分布不变

换一个问题：不改变输出分布，能不能让采样更快？自回归解码的瓶颈在于每个 token 都要过一遍大模型，且(在小 batch 下)是访存受限的 —— 算力闲着，权重搬运占满带宽。Speculative decoding [Leviathan 2022] 的洞见：大部分 token 很"容易"，小模型也能猜对；让小模型先起草，大模型一次前向并行验证一串草稿。

draft 模型 q（小、快） target 模型 p（大、慢） ┌──────────────────────┐ ┌─────────────────────────────┐ │ 自回归生成 γ 个草稿 │ x1..xγ │ 一次前向，并行算出 │ │ token: x1, x2, …, xγ │ ──────────► │ p(·|prefix), p(·|prefix,x1),│ └──────────────────────┘ │ …, p(·|prefix,x1..xγ) │ └──────────┬──────────────────┘ ▼ 逐个验证 xi：以 min(1, p(xi)/q(xi)) 接受 ├─ 全接受 → 白赚 γ 个 token，再免费多采 1 个 └─ 第 i 个被拒 → 丢弃 xi..xγ，从残差分布 norm(max(0, p−q)) 补采 1 个

核心是修正版接受-拒绝采样。单步：从 $q$ 采出 $x$，以概率 $\min\!\big(1, \tfrac{p(x)}{q(x)}\big)$ 接受；若拒绝，则从残差分布 $p'(x)=\mathrm{norm}\big(\max(0,\,p(x)-q(x))\big)$ 中重采。定理：无论 $q$ 是什么，最终输出严格服从 $p$。证明梗概：

$$ \Pr[\text{输出}=x] \;=\; \underbrace{q(x)\min\!\Big(1,\tfrac{p(x)}{q(x)}\Big)}_{\text{被接受}} \;+\; \underbrace{\Pr[\text{拒绝}]\cdot p'(x)}_{\text{重采}} \;=\; \min\big(p(x),q(x)\big) + \big(1-\beta\big)\cdot\frac{\max\big(0,\,p(x)-q(x)\big)}{1-\beta} $$ $$ =\; \min\big(p(x),q(x)\big) + \max\big(0,\,p(x)-q(x)\big) \;=\; p(x). \qquad \blacksquare $$

其中 $\beta=\Pr[\text{接受}]=\sum_x \min\big(p(x),q(x)\big) = 1 - \mathrm{TV}(p,q)$：接受率恰好等于 1 减去两分布的总变差距离——draft 和 target 越像，白赚的 token 越多。设每 token 接受率为 $\alpha$（近似 i.i.d.），一次"起草 $\gamma$ 个 + 验证"的迭代期望产出：

$$ \mathbb{E}[\#\text{tokens / 次 target 前向}] \;=\; 1+\alpha+\alpha^2+\cdots+\alpha^{\gamma} \;=\; \frac{1-\alpha^{\gamma+1}}{1-\alpha} $$

例：$\alpha=0.8,\ \gamma=4$ 时期望每次大模型前向产出 $\approx 3.36$ 个 token；扣除 draft 模型开销（设其单次成本为大模型的 $c$ 倍）后的端到端加速比为 $\frac{1-\alpha^{\gamma+1}}{(1-\alpha)(\gamma c+1)}$。

[Leviathan 2022] Fast Inference via Speculative Decoding：与同期 DeepMind 的并行工作共同确立了这套"draft–verify"范式。它的不可替代之处在于无损：输出分布与直接从大模型采样在数学上完全一致 —— 这与量化、蒸馏等"换精度买速度"的手段有本质区别。notebook 里你会用两个固定 categorical 分布 + 蒙特卡洛 10000 次，亲手验证 TV 距离 ≈ 0 和接受率公式。

7评测视角：解码参数是评测配置的一部分

本章对做 evaluation 的人有一个直接推论：你评的从来不是"模型"，而是"模型 × 解码配置"这个系统。同一 checkpoint，$T=0$ 与 $T=1$ 在数学、代码基准上的得分可以差出几个百分点；不报解码参数的评测结果不可复现也不可比。

  • $T=0$（greedy）测"稳定行为"：近似确定性，适合回答"模型最可能怎么做"，单次运行即可。但注意：即便 $T=0$，batch 组合、浮点归约顺序、MoE 路由等仍可能引入非确定性，"greedy = 完全可复现"在真实 serving 栈上只是近似。
  • $T>0$ 必须报方差：采样解码下单次得分是随机变量，正确做法是多 seed 重复、报告均值 ± 标准差（或置信区间）；pass@k 这类指标本身就定义在采样解码之上（$T=0$ 时 $k$ 个样本完全相同，pass@k 退化为 pass@1）。
  • 不同 harness 默认值不同 → 分数不可比：lm-evaluation-harness 的生成式任务默认 greedy；各家 API 不传参时常默认 $T=1$ 或 $T=0.7$ 且 top-p 各异；有的推理框架还默认开 repetition penalty。两篇论文报同一模型同一基准的分数差几个点，第一怀疑对象就是解码配置而非模型本身。
评测报告的最低标配：temperature / top_p / top_k / max_tokens / 重复惩罚 / 采样次数与 seed 全部写明。对比两个模型时解码配置必须对齐；对比两个 harness 的分数时，先 diff 它们的默认解码参数。这条纪律在本课程的姊妹评测课里会反复出现。

8研究前沿与开放问题

  • min-p sampling：按"相对头部概率"截断 —— 仅保留 $p(v)\ge p_{\min}\cdot\max_w p(w)$ 的 token，比 top-p 更直接地随分布尖锐度自适应，在高温下保持连贯性，近两年被多数推理框架收录。截断准则的"最优形状"仍是开放问题。
  • 约束解码（constrained decoding）：用语法/正则/JSON schema 在每步把非法 token 的 logit 置 $-\infty$，保证输出 100% 合法。评测视角的开放问题：约束会改变分布（被截走的概率质量重新归一），同一模型"带约束"与"裸采样 + 后解析"的能力测出来不一样 —— 哪个才是"模型的真实能力"？
  • 并行/非自回归解码：speculative 家族持续演化（自起草、多头预测、token 树验证），以及 diffusion LM 等整段并行生成路线，都在挑战"逐 token 串行"这一前提；其中有损方法（接受阈值放宽换速度）让"推理引擎是否改变了模型分布"成为评测必须核查的新变量。
  • 解码与对齐的纠缠：RLHF 后的模型分布本身已经很尖（低熵），对解码参数的敏感度与 base 模型完全不同 —— "最优 $T$/top-p" 是模型族相关的，盲目沿用 base 模型时代的默认值是常见错误。
