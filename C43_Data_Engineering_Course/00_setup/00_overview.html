1这门课讲什么

欢迎来到 大规模数据工程。这门课只追求一件事：当训练数据是 PB 级、token 是万亿级时，把「能跑」的数据处理变成「跑得动、跑得对、查得清」的基础设施。

如果你读过 C21（大规模预训练）或 C14（深度学习理论与数据），你已经知道数据的科学——该保留什么样的网页、数据怎么配比、合成数据怎么造、tokenizer 怎么训。那些课回答的是「什么样的数据是好数据」。本课接着问一个完全不同、却同样要命的问题：「当好数据有 50 TB、有 1e12 篇文档时，你到底怎么把去重、加载、分词、过滤、溯源这五件事真正做出来？」

这个问题的答案不在任何「数据清洗教程」里，而在规模带来的质变之中。一个在 1000 篇文档上一秒跑完的两两去重算法，在 1e12 篇文档上要跑几万年；一个把数据全读进内存打乱的 dataloader，在 50 TB 语料上第一行就 OOM 崩溃；一个串行的 tokenizer，分完万亿 token 要几个月。规模不是「同一件事做更多遍」，而是让原本正确的做法整体失效、逼你换一类算法和一套工程。本课就是沿着去重/加载/吞吐/质量/溯源五条主线，把这套「规模工程」拆开重建。

学完你应当能回答这类问题（也是数据/训练基础设施岗位的高频面试题）：为什么不能两两比对去重，MinHash+LSH 凭什么把 O(n²) 变可行？流式 dataloader 用有限内存怎么近似全局打乱，缓冲要多大？序列 packing 省掉了什么浪费？多阶段质量过滤为什么要「便宜的放前面」？怎么保证训练集没泄漏评测题、怎么让一份数据集可复现？——并且能在 numpy/pandas 里把这些机制都从零实现、对拍参考、再用复杂度/吞吐账推演到 PB 级。

一句方法论上的话先说在前面：本课的价值不在「我们没有集群也能学」这个妥协，而在它逼你只关注真正难的部分——算法的可扩展性与管线的正确性。具体用哪个分布式框架（Spark / Ray / MapReduce）、用哪家对象存储，这些是会变的、可替换的；而「怎么把一个数据操作从 O(n²) 改成近 O(n)、怎么用有限内存近似全局打乱、怎么让一条管线可追溯可复现」是不随工具过时的硬功夫。把它练扎实，换到任何框架都立刻能上手。

2世界观：三笔账与「规模的断崖」

贯穿全课的世界观可以浓缩成一句话：在 PB 规模下，决定可行与否的不是「会不会做」，而是「复杂度与吞吐撑不撑得住」。所以本课给每个机制都配两笔账：

这笔账回答什么怎么算本课例子
复杂度账 complexity这个算法在 n→1e12 时还能跑完吗写出时间/空间复杂度，代入真实 n 估耗时/存储暴力去重 C(n,2)≈5e23 次比较 vs LSH O(n)
吞吐账 throughput处理完整语料要多久、要多少机器条/秒 × 核数 × 并行效率，对比数据总量分词 1e12 token，单核 1e5 tok/s 要几年
正确性账 correctness工程化的近似版会不会算错与暴力/朴素参考对拍，量化误差与漏检MinHash 估计 Jaccard 的方差、LSH 漏检率
规模的断崖

最反直觉、也最重要的一条：在小数据上「显然正确且够快」的做法，在大数据上往往整体不可行，且失效方式是断崖式的。两两比对去重在 1 万篇文档上 5000 万次比较、一秒搞定；到 1 亿篇就是 5e15 次、要跑几个月；到 1e12 篇是 5e23 次、宇宙年龄也跑不完。这不是「慢一点」，是从可行直接掉进不可行。大规模工程的第一性原理就是：先用复杂度账判生死，再谈优化常数。一个 O(n²) 的算法优化 100 倍常数，在 1e12 规模上依然是死路；换成 O(n) 才是活路。

把这三笔账养成习惯，是做任何大规模数据工程的第一步且最容易被跳过的一步。新手最常犯的错是先写代码、跑通小样例、然后乐观地以为「加机器就能扩」——结果撞上 O(n²) 的墙（再多机器也救不了）、撞上单机内存的墙（流式才行）、撞上串行瓶颈的墙（Amdahl 定律封顶）。先算账、判可行性，再动手：复杂度过不了关就换算法，吞吐不够就横向扩展或流水重叠，正确性没保证就先建对拍。本课每个模块都在反复练这套「先算账」的纪律。

3课程地图：数据管线的五道工序

课程地图：数据从原始网页到训练循环的五道工序

原始语料：CommonCrawl 月度快照 ~数百 TB / 万亿级文档（单机放不下） 模块 01 大规模去重 MinHash+LSH / SimHash / 跨分片合并 │ 「1e12 篇里删掉近重复，但不能两两比对」 ▼ 模块 04 大规模质量过滤 启发式→分类器→perplexity 多阶段 + 语言识别 + PII │ 「便宜的先筛，贵的只看剩下的；各阶段留存率算清」 ▼ 模块 05 溯源与去污染 lineage + n-gram 去污染 + 内容哈希快照 + 审计 │ 「删掉泄漏的考题；让这份数据可追溯、可复现」 ▼ 模块 03 Tokenization 并行分词 + 序列 packing（消 padding 浪费） │ 「万亿 token 分词要跑满核；别在 padding 上烧算力」 ▼ 模块 02 流式加载与分片 shard 格式 + shuffle 缓冲 + 预取流水 「边读边喂，有限内存近似全局打乱，别让 GPU 饿着」

注意这五道工序大致就是真实数据管线的执行顺序（去重/过滤/去污染在离线预处理阶段，分词把文本变 token，流式加载在训练时把 token 喂给模型）。但本课的讲解顺序刻意从最能体现「规模带来质变」的去重切入（模块 01），它把 O(n²) 的墙摆在你面前，是建立「复杂度账」直觉最锋利的入口；然后是同样吞吐导向的加载（02）与分词（03），最后落到质量（04）与可信（05）这两个把工程做成「可信任系统」的主题。读完你会发现，五个模块其实在反复讲同一件事——规模如何改变正确的做法。

每一道工序都对应一个可独立验证的能力：模块 01 你手写的 MinHash+LSH 去重会与暴力 Jaccard 对拍一致，并能算出它把 1e12 规模从「几万年」拉回「可行」；模块 02 你的 shuffle 缓冲模拟器会量化出「缓冲多大才接近全局打乱」；模块 03 你的 packing 会把 padding 浪费率压到接近 0、并用 Amdahl 给并行加速设上限；模块 04 你的多阶段管线会算出端到端留存率、并验证「便宜在前」省了多少昂贵计算；模块 05 你的 n-gram 去污染会抓出泄漏样本、你的内容哈希会让快照可复现。每一步都有 assert 兜底，绝不靠「感觉对了」。

4方法论：小规模模拟 + 复杂度/吞吐账

方法论：没有 PB 集群，怎么学 PB 级数据工程？

本环境没有集群、没有 PB 数据、不装 Spark/Ray。但大规模数据工程的难点从来不是「数据真的很大」这个物理事实，而是两类可以在小数据上精确表达和验证的东西：① 算法的复杂度结构（O(n²) 还是 O(n)、串行还是可并行）；② 管线的正确性（去重有没有漏、打乱够不够随机、去污染抓没抓全）。这两类都能在 numpy/pandas 里用小规模真实数据精确复现。

打个比方：要证明「两两比对去重在大规模不可行」，你不需要真的去比 1e12 篇文档；你只需在 1000 篇上跑通它、确认它正确，再写出它是 C(n,2) = O(n²)，代入 1e12算一笔账——5e23 次比较 ÷ 每秒 1e9 次 ≈ 1.6e7 年。这笔账和你在集群上撞墙得到的结论一模一样，只是便宜了 10^9 倍、还能在 notebook 里复现给别人看。小规模真实模拟负责验证正确性，复杂度/吞吐账负责把规模问题推演出来——这就是本课的全部方法。

直白说

我们把每个 PB 级机制翻译成 numpy/pandas 里看得见摸得着的东西：MinHash 签名就是一个小整数矩阵，LSH 分桶就是按 band 切片做字典，shuffle 缓冲就是一个定长列表 + 随机弹出，序列 packing 就是一个贪心装箱，n-gram 去污染就是两个集合求交。你写的是算法结构与正确性，规模由账目推演。

严谨说

关键纪律有两条。一是对拍（differential testing）：每个工程化的近似/加速版都要和一个暴力/朴素参考比对——LSH 去重的结果要对照暴力两两 Jaccard 算召回率，去污染要对照「真值泄漏集合」算查全。二是算账（accounting）：每个机制都要写出复杂度并代入真实 n、写出吞吐并代入真实数据量，得到一个可被检验的「PB 级要多久/要多少机器」的数字。

PB 级现实本课的小规模复现对应真实工具/语料
1e12 文档去重几千条文本跑 MinHash+LSH + 对拍 JaccardFineWeb/Dolma 的 MinHash 去重
50 TB 流式加载内存里的样本流 + shuffle 缓冲模拟器WebDataset / Mosaic StreamingDataset
万亿 token 分词几千条文本分词 + packing + 吞吐外推SentencePiece / Megatron 数据预处理
多阶段过滤集群pandas 管线 + 各阶段留存率Dolma toolkit / FineWeb 管线
数据集去污染审计训练集 vs 基准的 n-gram 求交 + 哈希快照GPT-3 13-gram 去污染 / Dolma 审计

务必清楚本课不教什么：不教 Spark/Ray 的具体 API、不调真实对象存储、不测真实集群时延、不写真正分布式的代码。这些在你有了正确的算法结构与可信的复杂度/吞吐账之后，是第二步（references 里的 Dolma toolkit、WebDataset、Mosaic 文档接手）。本课负责把第一步——可扩展的算法 + 正确性 + 会算账夯死；这一步搞定，第二步才有意义。

5环境与运行

环境与运行

环境极简：只需 numpy 与 pandas（标准库 hashlib/re/collections 已够用，画图可选 matplotlib）。全课 CPU 秒级运行，无需 GPU、集群、Spark、对象存储。

conda create -n data-eng python=3.11 -y && conda activate data-eng
pip install numpy pandas      # 必需
pip install matplotlib        # 可选，仅用于画曲线（如 shuffle 质量 vs 缓冲大小）
jupyter lab

每个模块配一个 notebook，结构统一：先用 numpy/pandas/标准库把机制从零实现并对拍/算账（5–6 个 worked 小节，每节都跑出可打印的验证与 assert），再做 3–4 道带 assert 判分的 ✏️ 练习（先给骨架，自己填，再对照 📖 参考答案），最后一个真实数据胶囊（用真实语料的公开统计或真实管线配置算一笔账，把纸面知识接到现实，联网失败则回退到内置真实数值）。

建议的学习节奏：先读完整章 HTML 建立「规模带来质变」的直觉与复杂度框架，再打开 notebook 亲手实现并算账。读和做缺一不可——只读会觉得「好像懂了」，真正动手写 LSH 分桶、调 (b,r)、让 assert 通过、把账算到 1e12 时，才会发现魔鬼藏在哪些细节里（哈希独立性、候选爆炸、缓冲偏差、跨文档泄漏）。这门课的深度正是为「动手 + 算账」服务的。

配套先读：Lee et al. 2021（去重为何必要）建立动机；FineWeb（Penedo 2024）与 Dolma（Soldaini 2024）是真实 PB 级管线的两本「配方书」，全课都在和它们对标。完整清单见 references.md。

✅ 学完整门课，你应该能：
  1. 对任一数据操作写出复杂度账与吞吐账，判断它在 PB/万亿 token 规模下是否可行；
  2. 从零实现 MinHash+LSH 与 SimHash 去重（对拍暴力 Jaccard），并把 O(n²)→近 O(n) 的收益算清楚、做跨分片合并；
  3. 设计流式 dataloader：shard 分配 + shuffle 缓冲近似全局打乱 + 预取流水，并量化「缓冲多大够用」；
  4. 做大规模分词的吞吐规划，用序列 packing 消除 padding 浪费、用 Amdahl 给并行加速设上限；
  5. 编排多阶段质量过滤（启发式→分类器→perplexity + 语言识别 + PII），算各阶段留存率与「便宜在前」的省钱效果；
  6. 实现 n-gram 基准去污染、数据 lineage 记录、内容哈希快照与审计报告，让一条管线可追溯、可复现、可信任；
  7. 读懂 FineWeb/Dolma/WebDataset/Mosaic 的工程取舍，为一条真实数据管线做容量/吞吐/正确性的工程规划。
