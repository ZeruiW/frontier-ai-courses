1连接器的三大职责：维度对齐 / 语义桥接 / token 数控制

模块 01 末尾留下的"桥梁"问题，正是本章的主角。视觉编码器吐出 $N\times d_v$ 的 patch 特征（如 CLIP ViT-L/14@336 输出 $576\times1024$），而 LLM 的输入是 $d_{llm}$ 维的词嵌入序列（如 Vicuna-7B 的 $4096$）。中间这块把视觉特征变成"LLM 能读的 token"的模块，就是 connector（也叫 projector / adapter / bridge）。它要同时干三件事：

视觉编码器输出 Connector 三职责 LLM 输入 ┌──────────────┐ ①维度对齐 d_v→d_llm ┌──────────────┐ │ N × d_v │ ───────────────────────► │ M × d_llm │ ──► 与文本 token │ (576×1024) │ ②语义桥接 视觉空间→词嵌入空间│ (M×4096) │ 拼接 / 注入 │ patch 特征 │ ③token 数控制 N→M (M≤N?) └──────────────┘ └──────────────┘ 权衡线: M 大→细节全/占上下文; M 小→省/丢细节

直白讲

视觉编码器说的是"图像语"，向量维度也和 LLM 对不上。连接器就是个翻译官：先把向量改成 LLM 听得懂的长度，再把"图像语"的意思转成"词嵌入语"，顺便决定要说多少句话（token 数）——说太多浪费 LLM 的注意力预算，说太少又漏掉关键细节。

严谨讲

形式化地，connector 是映射 $g_\phi:\mathbb{R}^{N\times d_v}\!\to\!\mathbb{R}^{M\times d_{llm}}$。三个职责对应三个约束：(1) 维度对齐 保证输出落在 LLM 词嵌入维度 $d_{llm}$；(2) 语义桥接 要求输出分布与 LLM 训练时见过的词嵌入分布尽量同构，否则 LLM 把视觉 token 当成 OOD 噪声；(3) token 数 $M$ 决定序列长度与 self-attention 的 $O(M^2)$ 成本。$M=N$（保留全部 patch）还是 $M\ll N$（压缩）是本章贯穿的核心设计选择。

连接器是 VLM 里参数最少、却最常被低估的组件。它通常只占总参数的 <1%，但它决定了视觉编码器辛苦提取的信息有多少能真正"传达"给 LLM。连接器选错或训练不足，编码器再强也白搭——这正是 Prismatic [Karamcheti 2024] 等系统化消融要回答的问题。

2线性 / MLP projector：最简、保 token、易训

最朴素的连接器：对每个 patch token 独立地做一次投影，把 $d_v$ 维映到 $d_{llm}$ 维，token 数原封不动（$M=N$）。这就是 LLaVA 的做法。

$$ h_i = W x_i + b,\qquad x_i\in\mathbb{R}^{d_v},\; W\in\mathbb{R}^{d_{llm}\times d_v},\; i=1,\dots,N $$

初代 LLaVA [Liu 2023] 用单层线性 $W$。LLaVA-1.5 [Liu 2023b] 的一个关键改动是把它升级为两层 MLP + GELU，仅此一项就带来可观的下游提升：

$$ h_i = W_2\,\sigma\!\big(W_1 x_i + b_1\big) + b_2,\qquad \sigma=\text{GELU},\; W_1\in\mathbb{R}^{d_{llm}\times d_v},\; W_2\in\mathbb{R}^{d_{llm}\times d_{llm}} $$
性质MLP projector 的表现
维度对齐✅ 直接由 $W_1$ 完成 $d_v\to d_{llm}$
语义桥接⚠️ 仅靠 token 级非线性，无跨 token 交互；依赖 CLIP 编码器已与语言近似对齐（见模块 02）
token 数控制❌ 不压缩，$M=N$。336 分辨率 = 576 token；高分辨率切片后可达数千 token
训练难度✅ 参数少、无注意力、梯度稳定，stage-1 几小时即可对齐
信息保真✅ 保留全部 patch，细粒度任务（OCR、文档、定位）友好
LLaVA-1.5 [Liu 2023b, arXiv:2310.03744] 的核心信息之一：简单的 MLP projector + 高质量学术数据，就能逼近当时复杂架构。这把领域共识推向"连接器不必复杂，复杂度应放在数据与分辨率上"。后续 MM1、Idefics2 的消融（第 7 节）进一步证实：在保留全部 token 的设定下，连接器类型对最终性能影响很小。

3Q-Former 内部机制：learnable query 与 ITC/ITM/ITG

Q-Former（Querying Transformer）是 BLIP-2 [Li 2023, arXiv:2301.12597] 提出的连接器，目标是用一组可学习的 query 把变长图像特征压成固定数量（论文用 32 个）的 token，同时充当视觉空间与语言空间之间的"信息瓶颈"。

结构：两套注意力交织的 Transformer

Q-Former 维护 $K$ 个可学习向量 learnable queries $Q\in\mathbb{R}^{K\times d}$（$K=32$）。每个 block 里：

  • self-attention：query 之间互相交流（必要时还能与文本 token 交互，用于不同预训练目标）。
  • cross-attention：query 作为 $Q$，冻结的图像特征作为 $K/V$，让 query"主动从图像里提取需要的信息"。
冻结的图像特征 (N×d_v, 如 257×1024) │ 作为 Key / Value ▼ ┌───────────────────────────────────────────────┐ │ Q-Former block × L │ │ ┌─────────────┐ ┌──────────────────────┐ │ │ │ Self-Attn │ → │ Cross-Attn │ │ │ │ (queries↔ │ │ Q=queries │ │ │ │ queries) │ │ K,V=image features │ │ │ └─────────────┘ └──────────────────────┘ │ └───────────────────────────────────────────────┘ ▲ │ │ 32 个 learnable queries ▼ └────────────────── 输出 32 × d ──► 线性投影到 d_llm ──► 喂 LLM

注意：图像特征本身不变长地"穿过"Q-Former，真正离开的只有 $K=32$ 个 query 的输出。无论输入图像产生多少 patch，输出永远是 32 个 token——这就是固定长度压缩。cross-attention 的形式仍是熟悉的：

$$ \text{CrossAttn}(Q,K,V)=\text{softmax}\!\left(\frac{(QW_Q)(KW_K)^\top}{\sqrt{d_k}}\right)(VW_V),\quad Q\in\mathbb{R}^{32\times d},\; K{=}V\in\mathbb{R}^{N\times d} $$

预训练目标：ITC / ITM / ITG

BLIP-2 第一阶段（vision-language representation learning）用三个目标联合训练 Q-Former，靠不同的 attention mask 复用同一组 query：

目标全称做什么mask 策略
ITCImage-Text Contrastive对齐 query 输出与文本 [CLS]，InfoNCE 拉近正样本query 与文本互不可见（单模态）
ITMImage-Text Matching二分类：图文是否匹配，学细粒度对齐双向，query 与文本全可见
ITGImage-grounded Text Generation由 query 提取的视觉信息生成描述文本因果 mask，文本只能看见 query
ITC 提供对齐信号（query 学会抓住与文本语义相关的视觉内容），ITM 提供细粒度判别，ITG 逼 query 提取生成所需的足够信息。三者合力，使 32 个 query 输出成为一个"已经和语言对齐过"的紧凑视觉摘要。BLIP-2 的第二阶段再把这 32 个 token 接到冻结 LLM 上做生成对齐。
Q-Former 强压缩（$N\to32$）省了大量 LLM 上下文，但是信息瓶颈也是细节杀手：固定 32 token 难以承载高分辨率文档/密集文字。这也是为什么 2024 年后主流（LLaVA-1.5、Qwen2-VL、InternVL）多回到"保留更多 token 的 MLP/轻压缩"路线，Q-Former 式重压缩更多见于追求低成本或多帧视频的场景。

4Perceiver Resampler：变长重采样为固定长度

Perceiver Resampler 是 Flamingo [Alayrac 2022, arXiv:2204.14198] 用的连接器，思想源自 Perceiver / Perceiver IO [Jaegle 2021, arXiv:2107.14795]。它和 Q-Former 同属"learnable latent + cross-attention"家族，但更纯粹：用固定数量的 latent query，通过 cross-attention 把任意长度的视觉特征重采样成固定长度，与输入长度完全解耦。

变长视觉特征 (T×N×d, T=视频帧数, 帧内 N patch, 可变) │ flatten + 加时间/位置编码 ▼ ┌──────────────────────────────────────────────┐ │ Perceiver Resampler block × L │ │ R 个 learnable latents (如 R=64) │ │ Cross-Attn: Q=latents, K,V=[latents; 视觉] │ │ FeedForward │ └──────────────────────────────────────────────┘ │ ▼ 固定 R × d 个 visual token ──► 注入 LLM 的 gated cross-attn 层

关键性质：长度无关（length-agnostic）。无论输入是 49 个 patch、256 个 patch，还是多帧视频拼起来的上千个特征，输出永远是 $R$ 个 latent token。这对 Flamingo 处理交错图文 + 多帧视频的任意长度输入至关重要。配套 notebook 会用 49 vs 256 两种输入长度验证输出恒为 64。

维度Q-Former (BLIP-2)Perceiver Resampler (Flamingo)
latent / query 数32（固定）64（固定，可配）
专门的预训练目标有（ITC/ITM/ITG）无独立目标，随整个 VLM 端到端训
cross-attn 的 K/V仅图像特征[latents; 图像特征] 拼接（Flamingo 设计）
典型注入方式shallow（前缀拼接，接冻结 LLM）deep（gated cross-attn 插入 LLM 各层）
面向单图压缩摘要多帧 / 交错图文的变长输入
Perceiver IO [Jaegle 2021] 的核心贡献是用一小撮 latent 做信息瓶颈，把注意力成本从 $O(N^2)$ 降到 $O(N\!\cdot\!R)$（$R\ll N$），从而能吃任意模态、任意长度的输入。Flamingo 把它专门化为视觉重采样器；Idefics、OpenFlamingo 等开源复现沿用此设计。

5注入方式：deep fusion vs shallow fusion

连接器把视觉特征变成 $M\times d_{llm}$ 之后，还有一个正交的设计维度：这些视觉 token 在哪里、以何种方式进入 LLM？ 两条主流路线：

Shallow fusion（前缀拼接）—— LLaVA 路线

把视觉 token 当成"普通的输入 token"，直接拼在文本 token 前面，组成一条序列喂进 LLM 的输入层，之后全靠 LLM 自身的 self-attention 做跨模态融合。LLM 架构不改一行。

Deep fusion（门控交叉注意力）—— Flamingo 路线

在冻结的 LLM 各层之间插入新的 gated cross-attention 层：文本作为 $Q$，视觉 latent 作为 $K/V$，并用一个初始化为 0 的可学习门 $\tanh(\alpha)$ 控制视觉信息的注入强度。

$$ h \leftarrow h + \tanh(\alpha)\cdot \text{CrossAttn}\big(Q{=}h,\; K{=}V{=}\text{visual}\big),\qquad \alpha\ \text{初始化为}\ 0 $$

$\alpha=0$ 的初始化是关键：训练起点时门关闭，LLM 行为与纯文本时一模一样，保证不破坏预训练语言能力，再缓慢学着"开门"引入视觉。

维度Shallow fusion（前缀拼接，LLaVA）Deep fusion（gated cross-attn，Flamingo）
LLM 是否改结构不改，纯靠 self-attn插入新 cross-attn 层（新增参数）
视觉 token 占上下文占（吃 LLM 序列长度）不占输入序列（在层内注入）
计算成本序列变长，self-attn $O((M{+}L)^2)$每层多一次 cross-attn，但序列不变长
实现复杂度极低，几乎零侵入高，需改 LLM forward 并管理门控
训练数据需求少（指令数据即可）大（海量交错图文）
对长视觉输入序列爆炸，需先压缩天然友好（重采样 + 层内注入）
2023 年后开源社区压倒性地倒向 shallow fusion + MLP projector（LLaVA 系），因为它简单、复用现成 LLM、调试容易、数据需求低。deep fusion 的优势主要在变长/多图/视频与保护语言能力场景；Idefics2 [Laurençon 2024] 的消融甚至发现，在数据充足时 fully-autoregressive（shallow）架构反超 cross-attention（deep）架构——见第 7 节。

6训练范式：两阶段对齐 + 视觉指令微调

有了连接器，怎么训？现代 VLM 几乎统一采用两阶段（two-stage）训练，由 LLaVA 系奠定范式：

┌─────────────────────────────────────────────────────────────────────┐ │ Stage 1 · 特征对齐 (feature alignment / pre-training) │ │ 冻结: Vision Encoder ❄ + LLM ❄ │ │ 只训: Connector 🔥 │ │ 数据: 大量 图-文 caption 对 (如 CC3M/LAION 子集 ~558K) │ │ 目标: 让 connector 学会把视觉特征投到 LLM 词嵌入空间 (语义桥接) │ └─────────────────────────────────────────────────────────────────────┘ │ ▼ ┌─────────────────────────────────────────────────────────────────────┐ │ Stage 2 · 视觉指令微调 (visual instruction tuning) │ │ 冻结: Vision Encoder ❄ (通常仍冻; 也有解冻或微调高层的变体) │ │ 解冻: Connector 🔥 + LLM 🔥 (全量) 或 LLM 上 LoRA 🔥 │ │ 数据: 高质量多轮 图文指令 (LLaVA-Instruct-150K + 学术 VQA/OCR 等) │ │ 目标: 学会遵循指令、对话、推理 (模块 05 深入) │ └─────────────────────────────────────────────────────────────────────┘

直白讲

第一阶段像"对暗号"：编码器和 LLM 都按住不动，只让中间的翻译官学会怎么把图像的话翻成 LLM 听得懂的词。用便宜的"图片配一句描述"数据就够了。第二阶段才教模型真正"听话办事"——看图回答问题、多轮对话，这时可以放开 LLM 一起学。

严谨讲

Stage-1 仅优化 $\phi$（connector 参数），损失是对 caption 的自回归语言建模 $-\sum_t\log p_\theta(w_t\mid w_{<t},\,g_\phi(v))$，其中 $\theta$（LLM）与视觉编码器冻结。这把 connector 推向一个"视觉条件 ≈ 合理词嵌入前缀"的解。Stage-2 解冻 $\theta$（或注入 LoRA $\Delta\theta$）与 $\phi$ 联合优化指令数据，使模型在保留语言能力的同时获得指令遵循与视觉推理能力。

冻结策略与数据配比的工程要点

  • 为什么 stage-1 冻 LLM？ 若一开始就用未对齐的随机投影视觉 token 去更新 LLM，会把高质量的语言权重往 OOD 方向拽，损害语言能力（灾难性遗忘）。先把 connector 训到"视觉 token 看起来像合理词嵌入"，再解冻 LLM 更安全。
  • 视觉编码器多数全程冻结。 解冻它收益有限且容易过拟合小指令集；少数工作（如 Prismatic 的部分配置、Qwen2-VL）会微调编码器或其高层。
  • LoRA vs 全量微调。 stage-2 用 LoRA 可在 24GB 单卡训 7B VLM，效果接近全量（模块 05 详述）；全量微调上限略高但成本大。
  • 数据配比。 stage-2 需混入足量纯文本/学术 VQA 以防遗忘并提升泛化；纯靠 GPT 生成的对话数据易"过度健谈"、幻觉上升。配比是经验活，MM1 对此有系统消融（第 7 节）。
本章 notebook 的 stage-1 演示是教学简化版：用 gpt2 的词嵌入维度作目标、构造一个简单回归/对齐目标、只训 connector 几步看 loss 下降。它演示的是plumbing（数据流与梯度只流经 connector），不是真实的 caption 语言建模训练。真实 stage-1 需要海量图文对与多卡，超出单 notebook 范围。

7消融实证：编码器 / 分辨率 / 连接器 / 数据，谁影响最大？

"造一个好 VLM，钱该花在哪？" 2024 年三项系统化消融给出了高度一致的答案。做 model evaluation 时，这些结论是归因 VLM 能力差异的先验。

研究核心设定关键结论
Prismatic VLMs
[Karamcheti 2024]		控制变量扫 connector / 编码器 / 训练配方① 视觉编码器选择影响巨大，SigLIP/DINO 融合特征 > 单 CLIP；② 单阶段训练（去掉 stage-1 单独对齐）也能 work，挑战了"必须两阶段"的教条；③ connector（线性 vs MLP）影响相对较小。
Idefics2
[Laurençon 2024]		"What matters when building VLMs?"，逐项对照① 在数据/参数匹配下，fully-autoregressive（shallow）架构 > cross-attention（deep）架构；② 视觉编码器质量 + 分辨率是最大杠杆；③ learned pooling（如 Perceiver）能在保性能下减 token。
MM1
[McKinzie 2024]		大规模 pre-training 消融，分清各因素重要性排序重要性排序：图像分辨率 > 视觉 token 数 / 编码器 ≫ 连接器架构（VL connector 设计影响很小）；预训练数据需交错图文 + caption + 纯文本混合以兼顾 few-shot 与零样本。
三家共识，一句话： 影响 VLM 性能的杠杆，分辨率 ≳ 视觉编码器 > 数据配比 ≫ 连接器架构。连接器要"够用且训练充分"，但把工程预算砸在连接器的花式设计上回报很低；真正的高 ROI 在提高分辨率、选/融合更强的视觉编码器、调好数据配比。这直接反驳了"复杂连接器更强"的直觉。
注意别过度外推：以上结论是在各家自己的训练规模与数据下得到的，"连接器影响小"成立的前提是采用保留较多 token 的连接器并训练充分。若用 Q-Former 式强压缩，连接器（及其 token 数）就重新变成瓶颈——这正是下一节评测视角的切入点。

8评测视角：连接器瓶颈如何表现为下游短板

做 VLM 评测的核心技能，是把一个失败归因到具体组件。连接器（尤其是 token 数）作为信息瓶颈，会以可预测的方式表现为特定的下游能力短板：

连接器特征下游表现 / 失败模式对应基准
强压缩（如 32 token）细粒度任务崩：OCR、密集文字、小目标计数、空间定位差TextVQA、DocVQA、OCRBench、MMStar 细粒度子集
token 数充足但分辨率低整体语义可，但小字/图表/远处物体看不清DocVQA、ChartQA、InfographicVQA
语义桥接不足（stage-1 训练不够）视觉 token 像 OOD 噪声，模型"无视图片"、幻觉高POPE（物体幻觉，模块 08）、MME
连接器与编码器分辨率不匹配位置/空间关系错乱MMBench 空间推理、CV-Bench
评测诊断三连问：(1) 该 VLM 的视觉编码器是什么、分辨率多少？(2) 连接器是哪类、保留多少 token？(3) 失败集中在需要细粒度像素信息的任务（→ 怀疑分辨率/token 瓶颈）还是需要推理的任务（→ 怀疑 LLM）？能把"看不懂图"的失败分流到编码器/连接器 vs LLM，是模块 07/08 评测工作的关键判别力。
一个常见误判：把"模型答错图里的小字"归咎于 LLM 推理弱，其实根因常在连接器压缩过度或分辨率不足，细节根本没传到 LLM。验证方法：放大/裁剪相关区域单独喂入，若答对，则瓶颈在视觉前端（编码器+连接器+分辨率）而非 LLM。

9研究前沿与开放问题

  • token 数自适应。 固定 token（32/64/576）对所有图像一视同仁是否浪费？根据图像复杂度动态分配 token 数（如 LLaVA-NeXT 的多分辨率切片、Qwen2-VL 的 naive dynamic resolution，模块 06）是当前热点。评测视角：动态 token 是否在文档类任务上真正缩小了与高 token 数的差距？
  • 压缩与保真的帕累托前沿。 在给定 token 预算下，什么连接器能保留最多任务相关信息？这本质是有损视觉压缩问题，缺乏统一的信息论度量。
  • 单阶段 vs 两阶段之争。 Prismatic 显示单阶段也可行，但两阶段在防遗忘上更稳。最优训练课程（curriculum）、各阶段数据配比仍无定论，且强依赖编码器是否已对齐。
  • 连接器是否终将消失？ encoder-free（Fuyu/EVE）与 early-fusion（Chameleon，模块 09）路线把"视觉块直接进 LLM"，连接器退化为一层 patch embedding。规模化后这条路是否更优？
  • 评测的归因难题。 现有基准多给端到端分数，难以把误差解耦到编码器/连接器/LLM。设计能单独探测"连接器信息保真度"的诊断基准，是评测研究的开放方向。
