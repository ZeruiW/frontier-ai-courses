1从对齐到生成：为什么 CLIP 不够

模块 02 里的 CLIP / SigLIP 是双塔（dual-encoder）结构：图像走一条 ViT 塔、文本走一条 Transformer 塔，最后只在 embedding 空间算一个相似度分数。这套设计在检索 / 零样本分类上极强，但它的能力天花板也写在结构里。

直白讲

CLIP 只会回答"这张图和这句话像不像"——它给的是一个分数。它没有一个能逐字往外吐文本的解码器，所以你没法让它"描述这张图"、"回答图里有几只猫"、"按图写代码"。要会说话，必须把视觉接到一个能生成的语言模型上。

严谨讲

CLIP 建模的是匹配分数 $s(x,t)=\langle f_v(x),f_t(t)\rangle$，是一个判别式（discriminative）双塔，两塔之间没有 token 级交互，也没有自回归头。生成式 VLM 要建模条件分布 $p(t\mid x)=\prod_i p(t_i\mid t_{decoder LM，并让视觉信息以某种方式进入它的注意力计算。本模块讨论的"架构"，本质就是视觉信息进入 LM 的方式。

一句话锚点：模块 01 把图变成视觉 token，模块 02 让视觉空间和语言空间对齐，模块 03 解决"对齐好的视觉特征到底以什么方式喂进 LLM"。这就是 connector + 融合策略的设计空间。具体的 connector 训练细节（两阶段、数据配方）留给模块 04。

所以从 CLIP 走到生成式 VLM，要补三样东西：①一个能自回归生成的 LLM（通常是冻结的预训练 LLM）；②一个把视觉特征接进 LLM 的 connector；③一种"在哪一层、以何种注意力"融合的策略。后两者的不同组合，就长出了下面的整张架构谱系。

2融合策略分类法：五种范式 + 骨干之分

把视觉接进 LLM，文献里收敛出五条主线。可以用两个正交的轴来切分它们：

  • 融合深度（fusion depth）：视觉信息只在输入层拼一次（shallow / early），还是在 LLM 的每一层都通过 cross-attention 反复注入（deep）。
  • token 预算（token budget）：保留全部 patch token（细节多、占上下文），还是压缩成固定的少量 query token（省、但可能丢细节）。
#范式代表connector融合方式视觉 token 去向
①dual-encoder 双塔CLIP / SigLIP无（只对齐 embedding）embedding 点积，无 token 交互不进 LLM —— 不能生成
②deep-fusion via cross-attnFlamingoPerceiver Resampler在冻结 LLM 的多层插入 gated cross-attention作为 cross-attn 的 K/V，不占主序列
③query-based 压缩BLIP-2Q-Former（32 query）先压成 32 token，再当前缀接 LLM32 个软 prompt token
④shallow projection 前缀拼接LLaVAMLP 投影投影后直接拼到输入序列当前缀全部 patch token（如 576 个）进主序列
⑤encoder-freeFuyu一个线性层像素 patch 直接线性投影进 decoderpatch 直接当 token，无独立视觉塔

另一条容易被忽略却很重要的轴是语言骨干的形态：

直白讲

decoder-only：就是一个 GPT 式的纯解码器，视觉 token 和文本 token 拼在同一条序列里、一起做带因果掩码的自注意力。今天绝大多数开源 VLM（LLaVA、Qwen2-VL、Fuyu）都是这一类，因为可以直接复用现成的强 LLM。

encoder-decoder：图像/前缀走 encoder，文本在 decoder 端通过 cross-attention 取用。BLIP-2 接 Flan-T5 时、PaLI 都属于这种。

严谨讲

decoder-only 用因果自注意力统一处理 $[\,\text{vis tokens};\,\text{text tokens}\,]$ 的拼接序列，视觉以"前缀"或"软 prompt"身份参与 $p(t_i\mid t_{独立的 cross-attention 子层取 encoder 输出作 K/V。Flamingo 的"在冻结 decoder LM 里插 cross-attn 层"是一种混合：骨干是 decoder-only，但融合借用了 encoder-decoder 式的 cross-attention 机制。

分类法不是为了背名词，而是为了评测时快速定位：拿到一个陌生 VLM，先问它"哪种融合 + 多少视觉 token + 冻结了谁"，基本就能预判它的强项与失败模式（细节见 §8）。下面四节各取一个里程碑，配一张架构图逐一拆开。

3Flamingo：Perceiver Resampler + gated cross-attention

Flamingo [Alayrac 2022] 是第一个把冻结的视觉编码器 + 冻结的大 LLM桥起来、并支持交错图文（interleaved image-text）少样本的标志性工作。它的两个关键部件：

  • Perceiver Resampler：视觉编码器对每帧/每图吐出变长特征，Resampler 用一组固定数量的可学习 latent query（如 64 个）通过 cross-attention 把它们重采样成定长视觉 token。好处是无论输入多少帧、分辨率多大，进 LLM 的视觉 token 数恒定。
  • Gated cross-attention dense（GATED XATTN-DENSE）层：在冻结的 LLM 的若干层之间，新插入带门控的 cross-attention 子层。文本是 query，视觉 latent 是 key/value。门控用一个初值为 0 的 $\tanh$ 标量，保证训练初期新层近似恒等，不破坏原 LLM 的语言能力。
交错输入： <img1> 文本A <img2> 文本B ... （支持少样本：图-文-图-文 示例堆叠） 每张图 ─► [冻结 Vision Encoder] ─► 变长特征 │ ▼ ┌──────────────────────────┐ │ Perceiver Resampler │ 64 个可学习 latent │ (cross-attn 重采样) │ ──► 定长视觉 token (K/V) └──────────────────────────┘ │ 文本 token ─►┌────────────────────────────────────────────────────┐ │ 冻结 LLM (decoder-only) │ │ 层 i ── self-attn (text) ──┐ │ │ ┌─────────────────────────┐ │ 插入 │ │ │ GATED XATTN-DENSE │◄─┘ 门控 tanh(α), α₀=0 │ │ │ Q=text, K/V=视觉 latent │ │ │ └─────────────────────────┘ │ │ 层 i+1 ── self-attn ── ... │ └────────────────────────────────────────────────────┘ │ ▼ 自回归生成文本

cross-attention 的数学就是模块 01 那条注意力公式，只是 $Q$ 来自文本、$K,V$ 来自视觉，外加一个门控标量：

$$ h \;\leftarrow\; h + \tanh(\alpha)\cdot \mathrm{CrossAttn}\big(Q=h_{\text{text}},\; K,V = z_{\text{vis}}\big),\qquad \alpha \text{ 初始化为 } 0 $$
Flamingo [Alayrac 2022] 的核心贡献不止架构，还在于证明了"冻结大 LLM + 少量新增可训层"这一范式能在仅用交错网页数据下习得强大的少样本多模态 in-context learning。它的最大代价是：cross-attention 层是新增并从头训练的，参数与工程都更重，且交错数据稀缺。后来的开源复现是 OpenFlamingo 与 Idefics（模块 04 会再提）。
为什么"插在每层"叫 deep fusion？因为视觉信息反复参与 LLM 的每一层推理，而不是只在输入端拼一次。代价是改了 LLM 的内部结构；收益是融合更充分、对少样本/长上下文交错更友好。

4BLIP-2：Q-Former 与查询式压缩

BLIP-2 [Li 2023] 的设计哲学是极致省钱：冻结一个现成图像编码器、冻结一个现成 LLM，中间只训一个轻量的桥——Q-Former（Querying Transformer）。

Q-Former 持有 32 个可学习 query 向量。这些 query 通过 cross-attention 从冻结图像编码器的特征里"问"出信息，把任意长度的视觉特征压成固定 32 个 token，再经一个线性层投到 LLM 维度，作为 LLM 的软前缀（soft prompt）。

冻结图像编码器 (如 EVA-CLIP ViT) ─► 图像特征 (K/V) │ ▼ 32 个可学习 query ─►┌───────────────────────────────────┐ │ Q-Former (轻量 Transformer) │ │ • query 间 self-attn │ │ • query→图像 cross-attn (抽取) │ │ • (阶段1) 还与文本交互做对比/匹配 │ └───────────────────────────────────┘ │ 输出 32 个视觉 token ▼ [Linear 投影到 d_llm] │ 32 个软 prompt token ▼ ┌───────────────────────────────────┐ │ 冻结 LLM (OPT / Flan-T5) │ ──► 文本输出 └───────────────────────────────────┘ 两阶段训练： 阶段1 Vision-Language Representation：冻结图像编码器，用 ITC/ITM/ITG 三目标 训 Q-Former，让 32 query 学会抽取与文本最相关的视觉信息。 阶段2 Vision-to-Language Generative：接上冻结 LLM，只训 Q-Former+投影， 让 32 token 成为 LLM 能读懂的前缀。

第一阶段联合优化三个目标（沿用 BLIP 家族）：图文对比 ITC、图文匹配 ITM、基于图像的文本生成 ITG；用不同的注意力掩码控制 query 与文本能否互相看见，从而在同一个Q-Former 里学到既能对齐又能抽取的表征。

$$ \underbrace{32 \times d}_{\text{Q-Former 输出，与图像分辨率/patch 数无关}} \;\xrightarrow{\;W_{\text{proj}}\;}\; \underbrace{32 \times d_{\text{llm}}}_{\text{LLM 软前缀}} $$
32 个 token 是 BLIP-2 的灵魂，也是它的软肋。 把一整张图压成 32 个 token 极省上下文、训练极便宜（只训 Q-Former），但压缩必然丢细节：密集文字、小目标计数、精细 OCR、空间关系这类任务上，固定 32 token 的瓶颈很明显。这直接引出了 LLaVA 路线"干脆别压"的反方向选择。

5LLaVA：最简前缀投影，为什么简单却强

LLaVA [Liu 2023]（Visual Instruction Tuning）把 connector 简化到极致：一个投影把 CLIP 的 patch token 直接当作 LLM 的前缀 token。初版用单个线性层，LLaVA-1.5 换成两层 MLP。没有 Q-Former，没有 cross-attention 新层，没有压缩。

图像 ─► [CLIP ViT-L/14 @336] ─► 576 个 patch token (24×24)，每个 d_v 维 │ ▼ ┌───────────────────────────┐ │ MLP projector │ d_v ─► d_llm │ (Linear→GELU→Linear) │ token 数不变 = 576 └───────────────────────────┘ │ 576 个视觉 token ▼ "USER: 描述这张图\nASSISTANT:" 文本 token │ │ └──── 拼接成一条序列 ─┴──►┌──────────────────────────┐ [ 576 视觉 token | 文本 token ] │ LLM (Vicuna, decoder-only)│ ─► 回答 │ 统一因果自注意力 │ └──────────────────────────┘

关键在于：视觉 token 和文本 token 进入同一条序列、共用同一套因果自注意力——视觉就是一段"用图片写成的前缀"。LLM 不需要任何新结构，原封不动地把它们当 token 处理。

直白讲：为什么这么简单还这么强

因为重活早就被别人干完了。CLIP 已经把视觉特征对齐到语言语义（模块 02），LLM 已经会推理会说话，剩下的"翻译"近乎一个线性映射，一个 MLP 足矣。再配上 GPT-4 生成的高质量视觉指令数据，效果就上来了。简单 = 训练快、易复现、易 scale。

严谨讲

由于视觉骨干已是语言对齐的 CLIP 空间，connector 只需近似一个线性桥接 $W:\mathbb{R}^{d_v}\to\mathbb{R}^{d_{llm}}$ 即可，无需同时承担"空间对齐+语义桥接"。LLaVA 采两阶段：阶段1 冻结视觉与 LLM，只训投影做特征对齐；阶段2 用视觉指令数据微调投影+LLM。LLaVA-1.5 进一步用 MLP 投影 + 学术任务数据，刷新当时多项 benchmark，确立了"shallow projection + 全 patch token"成为开源主流配方。

代价是视觉 token 多：336 分辨率下 576 个 token，一旦上高分辨率（模块 06 的 AnyRes 把图切块）token 数可破数千，严重吃上下文、拖慢推理。"保细节"和"省 token"的张力在这里达到顶点——这正是模块 06 高分辨率压缩要解决的问题。

6Fuyu：encoder-free，像素直入 decoder

Fuyu-8B [Bavishi 2023, Adept] 走到了另一个极端：干脆不要独立视觉塔。没有 CLIP、没有 ViT、没有 Q-Former——图像 patch 经过一个线性层直接投影成 token，和文本 token 一起喂进同一个 decoder-only Transformer。

图像 (任意分辨率) ─► 切成 patch (如 30×30 像素一块) │ ▼ 把每个 patch 拉平 ┌──────────────────────────────┐ │ 单个 Linear projection │ patch 像素 ─► d_llm │ (没有 ViT，没有 CLIP！) │ └──────────────────────────────┘ │ 视觉 token（用特殊的 newline token 标记图像每行结束，保留 2D 结构） ▼ ┌──────────────────────────────────────────────────────┐ │ 单一 decoder-only Transformer │ │ [ 视觉 patch token | 文本 token ] 同一序列、同一注意力 │ ─► 文本输出 └──────────────────────────────────────────────────────┘

直白讲

别人是"先用一个专门的视觉网络把图理解一遍，再交给语言模型"；Fuyu 是"图就是一串没人预处理过的色块 token，让语言模型自己从头学怎么看"。少了一整个视觉塔，接口干净到极点，而且天然吃任意分辨率——图多大就多少 patch token，不用为某个固定分辨率重训编码器。

严谨讲

Fuyu 取消了 vision encoder 与 connector 的区分：raw patch 经线性投影即作为 token 序列进入 decoder，融合发生在输入层且骨干不冻结（统一端到端训练）。代价是放弃了 CLIP 预训练赋予的视觉先验，需要更多多模态数据/算力让 decoder 自学视觉特征；收益是架构极简、原生支持可变分辨率与高分辨率文档/图表。这一 encoder-free 思路在 EVE、后续原生多模态（模块 09）里被继续探索。

Fuyu 是产品驱动的架构选择：Adept 做 UI/文档 agent，需要任意长宽比的高分辨率屏幕截图，固定 224/336 的 CLIP 编码器恰恰是瓶颈。架构选择往往由下游任务的分辨率/接口需求倒逼——这是评测时理解一个 VLM "为什么长这样"的关键线索。

8选型权衡与评测视角：典型失败模式

做 model evaluation 时，架构不是中性的——每种融合策略都自带一组可预测的失败模式。把失败归因到架构，是评测科学家的核心技能。

架构结构性优势典型失败模式（评测要盯的）
BLIP-2（Q-Former 压缩） token 极省、训练便宜、接口干净 压缩丢细节：32 token 容不下密集文字/小目标/精细空间关系 → OCR、计数、细粒度 VQA 弱；对图像细节问"具体写了什么"易含糊
LLaVA（全 patch 前缀） 细节保留好、实现简单、易 scale token 多吃上下文：576+（高分辨率破千）视觉 token 挤占 LLM 上下文、推理慢；多图/长文档场景易爆长度；视觉 token 过多还可能放大幻觉
Flamingo（gated cross-attn） 少样本/交错 in-context 强、视觉不占主序列 训练复杂：新增 cross-attn 层需从头训、交错数据稀缺、工程重；复现门槛高；指令跟随不如指令微调路线自然
Fuyu（encoder-free） 任意分辨率、接口极简 缺视觉先验：丢掉 CLIP 预训练，数据/算力需求大；小数据下视觉理解可能弱于有编码器方案；细粒度语义对齐更难保证
评测归因实操： 看到一个 VLM 在 OCR / 文档 / 计数上崩，先别怪 LLM 推理弱——
① 它是不是 query 压缩（BLIP-2 式）把细节压没了？
② 还是分辨率太低（CLIP 224/336，模块 06）根本没看清？
③ 还是 token 太多爆上下文截断了？
架构 + 视觉 token 数 + 分辨率三件套，往往比"模型不够聪明"更能解释失败。这套归因框架在模块 07（评测）和模块 08（幻觉）会系统展开。
选型的一句话总结：要省上下文/低成本 → 查询压缩（BLIP-2）；要细节/易复现 → 全 patch 投影（LLaVA）；要少样本/交错/视频 → deep cross-attn（Flamingo）；要任意分辨率/极简接口 → encoder-free（Fuyu）。没有免费的午餐，每一条都在 token 预算、细节保真、训练复杂度之间做不同取舍。

9研究前沿与开放问题

  • 统一架构趋势：连接器在收敛。 2024 后的系统性消融（Idefics2 [Laurençon 2024]、MM1 [McKinzie 2024]、Prismatic [Karamcheti 2024]）反复显示：在数据/算力充足时，简单的投影 + 全 patch token 往往不输甚至胜过 Q-Former 式压缩，Q-Former 的优势主要在极低 token 预算。连接器设计是否正在"被简化掉"？开放。
  • encoder-free 能否规模化追平？ Fuyu / EVE 取消视觉塔，接口最干净，但要靠规模化补回 CLIP 先验。在何种数据/算力规模下，encoder-free 能稳定追平甚至超过有编码器方案？这关系到下一代架构的形态。
  • 原生多模态（native multimodal）。 GPT-4o、Gemini、Chameleon [Chameleon Team 2024] 走 early-fusion / any-to-any：图像与文本从预训练第一步就在同一个 token 空间里联合训练，而非"对齐一个现成视觉塔到现成 LLM"。这是本课模块 09 的主题，也是当前最前沿的范式迁移。
  • 融合深度的最优解未定。 deep cross-attention（Flamingo）vs shallow prefix（LLaVA），在长上下文、多图交错、视频、agent 场景下孰优孰劣，仍缺乏在统一条件下的干净对比。
  • 评测视角的开放问题： 现有 benchmark 多为单图短问答，难以暴露不同融合策略在多图交错、长视频、高分辨率文档上的差异。设计能区分架构能力而非仅测 LLM 知识的 benchmark，是评测研究的空白（模块 07）。
