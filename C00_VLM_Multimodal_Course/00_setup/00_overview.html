1这套教材教什么、不教什么

这是一条从原理 → 架构 → 训练 → 评测 → 前沿的完整研究路径，面向做 model evaluation 的研究科学家， 而不是"怎么调多模态 API"的速成班。如果你的目标只是把图片塞进 GPT-4o 的接口拿个 caption，本教材会显得过重； 但如果你要读懂任意 VLM 论文的架构图、复现核心组件、设计一套评测、把失败归因到具体模块，那这正是为你准备的。

直白讲

市面上"VLM 教程"大多停在"怎么用 API"。本教材偏要往下挖一层：这个能力是怎么被训练出来的、 它在什么情况下会坏、你怎么用一组数字证明它好或坏。学完你写得出评测、看得懂论文、说得清失败的根因。

严谨讲

每个模块都围绕同一个三问框架组织：(1) 它解决什么问题（motivation）； (2) 它在数学与工程上怎么实现（推导 + 真实可运行代码）； (3) 怎么衡量它好不好、它会怎么坏（评测 metric + 失败模式 failure mode）。 第三问是贯穿全课的主线，也是研究科学家区别于工程师的核心视角。

本教材教本教材不教
视觉编码器 / 连接器 / 融合架构的原理与推导某个具体 SDK 的逐行 API 用法（查官方文档更快）
对齐目标的数学（InfoNCE、sigmoid loss、DPO）把模型部署成生产服务（serving / 蒸馏 / 量化工程）
评测体系设计、LLM-as-judge、数据污染识别刷某个榜单分数的 trick
幻觉、鲁棒性、多模态越狱、危险能力评估提示词工程的"魔法咒语"集
把失败归因到编码器 / 连接器 / LLM / 数据从零实现一个工业级训练框架
贯穿全课的一句话："能力"和"评测"是一枚硬币的两面。你越懂一个能力是怎么被造出来的，就越知道它会从哪里崩、该用什么指标去抓它。 这就是为什么本教材把 07（评测体系）和 08（幻觉/安全）抬成两条主线（README 中标 ★）。

3两件套怎么配合用：HTML 建直觉 + notebook 动手

每个模块都是一份 HTML 讲解 + 一个 Jupyter notebook的两件套。它们的分工很明确，请按这个顺序用：

┌──────────────────────┐ ┌───────────────────────────┐ │ NN_讲解.html │ 先读 │ 动机 / 数学推导 / 架构图 │ 建立"为什么、是什么" │ (建直觉与理论框架) │ ──────► │ 失败模式 / 评测视角 │ 的心智模型 └──────────────────────┘ └───────────────────────────┘ │ 带着问题去 ▼ ┌──────────────────────┐ ┌───────────────────────────┐ │ NN_xxx.ipynb │ 再跑 │ 真实模型权重 + HF API │ 把直觉落到"怎么做、 │ (动手验证与实验) │ ──────► │ 逐 cell 中文讲解 + 练习 │ 看哪个输出"上 └──────────────────────┘ └───────────────────────────┘
推荐节奏：HTML 读到"研究前沿与开放问题"那一节时，先别急着关 —— 带着其中一个开放问题去跑 notebook， 你会更主动地观察输出、改参数、形成自己的判断。被动跑完所有 cell 的学习收益远低于"带着一个问题去跑"。

三种用法，对应不同目标：

  • 系统学：按 00 → 09 顺序，每模块先读 HTML 再跑 notebook。这是默认路径。
  • 查漏补缺：直接挑模块。07/08 评测主线可独立学 —— 如果你已有 VLM 基础、只想补评测与安全，可直接从 07 切入，遇到不懂的架构名词再回查 03/04。
  • 面试 / 研究准备：每章末尾的「研究前沿与开放问题」是深挖入口；本章第 7 节给出全局大图景，可作为面试时画"领域地图"的脚本。

4环境配置详解（可复制代码块）

所有 notebook 的目标是真实可运行。下面这套配置在 Linux + NVIDIA CUDA 12.x、macOS（Apple Silicon，MPS）、以及纯 CPU 上都能起步； 重型 cell（大模型/训练）需要 GPU，详见第 5 节。

① 建隔离环境

# 推荐 conda（也可用 venv）。Python 3.10/3.11 都可
conda create -n vlm python=3.11 -y
conda activate vlm

② 按 PyTorch 官网命令装对应 CUDA 的 torch

torch 一定要先单独装、且对准你机器的 CUDA 版本，不要让 requirements.txt 替你随便拉一个。 打开 pytorch.org/get-started/locally，选你的 OS / 包管理器 / CUDA 版本，复制它给的命令。下面只是示例：

# 示例：CUDA 12.1（以官网为准！cu118 / cu124 等按需替换）
pip install torch torchvision --index-url https://download.pytorch.org/whl/cu121

# macOS（Apple Silicon，走 MPS，无需 CUDA）：
pip install torch torchvision

# 纯 CPU：
pip install torch torchvision --index-url https://download.pytorch.org/whl/cpu

③ 装其余依赖

# 在课程根目录执行；requirements.txt 已列全 transformers/peft/datasets 等
pip install -r requirements.txt

④ 注册 Jupyter kernel

把 vlm 环境注册成 Jupyter 内核，名字定为 vlm、显示名 VLM Course —— 这与 notebook 的 kernelspec 对齐，打开就能直接选中。

python -m ipykernel install --user --name vlm --display-name "VLM Course"

5算力分级说明（CPU / GPU / API）

每个模块和 notebook 都带算力 badge。先看懂它们，再据此规划你的硬件。

Badge含义典型需求
CPU笔记本电脑即可跑，不需要独显概念演示、小张量实验、可视化
GPU需要 NVIDIA 显卡（或 Apple MPS 部分可跑）加载/推理 2–7B VLM、LoRA/QLoRA 微调；建议 ≥16GB 显存，多数配方单张 24GB 卡足够
API需要闭源模型的 API key用 GPT-4o / Claude 做评测对比、当 LLM-as-judge

没有 GPU 怎么办？

本教材刻意把"读懂逻辑"和"跑出结果"解耦，所以无 GPU 也能学到大部分内容：

  • 读逻辑：每个重型 cell 上方的 markdown 都讲清了"这步在干嘛、为什么、看输出哪里"。即使不跑，也能把代码当伪代码读懂，配合 HTML 推导建立完整理解。
  • 用小模型 / 量化：notebook 尽量提供小模型（如 2B 量级）或 4-bit 量化选项，让 16GB 显存甚至部分 CPU 也能起步。模块 01/02 的不少实验在 CPU 上几分钟即可完成。
  • 云 GPU / Colab：把 notebook 上传到 Google Colab（免费档常给 T4 16GB，足够多数推理与小 LoRA）或租用云卡（如 A10/L4/A100 按时计费）。先按第 4 节装好 torch + requirements.txt 即可。
  • API 替身：标 API 的评测实验，本质是把"被测模型"换成闭源 API —— 没有本地 GPU 时，这反而是最省事的路径。
显存估算的粗略经验：FP16 推理约需 "参数量(B) × 2 GB"，4-bit 量化约 "参数量(B) × 0.6 GB" 再加激活/KV cache 余量。 例如 7B 模型 FP16 约 14GB+、4-bit 约 5–6GB。训练（含优化器状态）远高于此，所以本教材训练实验一律走 LoRA/QLoRA。

6前置知识自测

本教材假设你具备这三块基础：Transformer / self-attention、PyTorch、对比学习（contrastive learning）的基本概念。 下面 5 个问题用来自测 —— 如果某题答不上来，照后面的补课指引补一下，再进模块 01。

自测 5 问：
  1. 写出 scaled dot-product attention 的公式，并解释为什么要除以 $\sqrt{d_k}$。
  2. self-attention 是置换不变（permutation-invariant）的吗？这对处理图像 patch 或文本 token 意味着要额外补什么？
  3. 在 PyTorch 里，tensor.requires_grad、loss.backward()、optimizer.step() 各自做了什么？三者的先后关系是？
  4. 什么是对比学习的"正样本对 / 负样本对"？为什么 batch 越大、负样本越多，对比目标通常学得越好？
  5. 多头注意力（multi-head）相比单头多了什么？"多头"在表达能力上的直觉收益是什么？

参考要点：①见模块 01 第 4 节，$\sqrt{d_k}$ 是为了防止点积随维度增大而进入 softmax 的饱和区、稳定梯度； ②是置换不变的，所以必须显式加 position embedding； ③backward 算梯度、step 用梯度更新参数，顺序是 forward → backward → step（且每步前 zero_grad）； ④正样本=语义匹配的对（如配套图文），负样本=不匹配的对，更多负样本提供更强的判别信号（模块 02 的 InfoNCE）； ⑤多头让模型在不同子空间并行学习不同关系，等价于多个"关注视角"。

补课指引：Transformer 看 Attention Is All You Need [Vaswani 2017] + Jay Alammar 的 The Illustrated Transformer； PyTorch 看官方 60-Minute Blitz 与 autograd 教程；对比学习看 SimCLR [Chen 2020] 与本课模块 02 的 CLIP [Radford 2021]。 这三块都是本教材的硬前置 —— 不必精通，但要能看懂公式和代码。

7研究前沿与开放问题：VLM 的全局大图景

在扎进单个模块之前，先把整个领域的大图景摆出来，帮你建立坐标系。当前 VLM 研究大致沿四条主线展开， 本教材的模块都能挂到这四条线上：

┌─────────────────────────────────────────────────────────────────────┐ │ ① 评测 Evaluation ── 我们真的会"测"VLM 吗？ │ │ 榜单饱和/数据污染、纯文本捷径(MMStar)、CircularEval、judge 偏置 │ │ → 模块 07/08 │ ├─────────────────────────────────────────────────────────────────────┤ │ ② 对齐与可信 Alignment ── 它会不会胡说、被越狱、泄露危险能力？ │ │ 幻觉(POPE/HallusionBench)、DPO/RLHF、多模态 jailbreak、危险能力评估│ │ → 模块 05/08 │ ├─────────────────────────────────────────────────────────────────────┤ │ ③ 原生多模态 Native MM ── 能否一个模型 any-to-any 收发图文音视？ │ │ 早融合(Chameleon)、统一 tokenizer、GPT-4o/Gemini 式原生架构 │ │ → 模块 06/09 │ ├─────────────────────────────────────────────────────────────────────┤ │ ④ 多模态智能体 Agents ── 它能否"看着屏幕"自主操作完成任务？ │ │ GUI grounding、computer-use、长程规划、可自主性的安全评估 │ │ → 模块 09（+ 评测视角回到 ①②） │ └─────────────────────────────────────────────────────────────────────┘

把这四条线串起来看，几个跨主线的开放问题值得你在学习时始终带在脑子里：

  • 评测的有效性危机：很多 VLM benchmark 只靠语言先验就能蒙对（MMStar [Chen 2024] 指出大量样本"不看图也能答"），训练数据污染又让分数虚高。如何设计真正需要视觉、且抗污染的评测？这是研究科学家最该深耕的问题。
  • 失败归因：当一个 VLM 答错图里的小字，根因是视觉编码器分辨率不足、连接器丢信息、还是 LLM 推理弱？把失败归因到具体模块是评测的高阶能力（模块 01/06/07 反复训练）。
  • 对齐与能力的张力：抑制幻觉的 DPO/RLHF 会不会同时削弱有用性？多模态越狱（如把有害指令画进图里 [Gong 2023]）如何系统性评测与防御？
  • 原生 vs 拼接：早融合 any-to-any（Chameleon [Chameleon Team 2024]）能否在规模化后超过"视觉编码器 + LLM"的拼接式架构？接口更统一，但训练与评测都更难。
  • 智能体的危险能力评估：能操作电脑的多模态 agent 一旦具备长程自主性，如何在它造成实际后果前提前评测其危险能力（dangerous capability eval，参见 METR、[Phuong 2024]）？这是对齐与评测的交叉前沿。
怎么把本教材用于研究与面试准备：① 研究上，把每章末尾的开放问题当 idea 池，挑一个能设计出可测量实验的去做； ② 面试上，用本节这张"四主线"图当脚本，先画领域地图、再指出当前最关键的张力（评测有效性、失败归因、危险能力评估）， 最后落到"我会怎么设计一个评测去回答它" —— 这正是评测方向研究科学家最被看重的表达方式。
