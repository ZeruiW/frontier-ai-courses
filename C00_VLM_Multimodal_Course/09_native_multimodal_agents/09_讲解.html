1后期拼接 vs 原生多模态：GPT-4o / Gemini 范式转移

到模块 08 为止，我们讲的几乎都是后期拼接式（late-fusion / bolt-on）VLM：一个预训练好的视觉编码器（CLIP/SigLIP）+ 一个预训练好的 LLM，中间用 connector 缝起来，再做指令微调。这条路工程上高效、复用强，但有结构性短板。原生多模态（native multimodal）指的是：模型从预训练第一天起就在多模态数据上联合训练，文本、图像、音频、视频共享同一套参数与表征空间，而非事后拼接。

直白讲

后期拼接像是先各自培养一个"画家"和一个"作家"，再请翻译让他们勉强对话。原生多模态则是从小让同一个大脑同时学看和学说，所以它对"看到什么该怎么说"的理解是长在一起的，反应也更快。

严谨讲

令训练目标为联合似然 $\mathcal{L}=\mathbb{E}_{(x_{\text{txt}},x_{\text{img}},x_{\text{aud}})}\big[-\log p_\theta(\text{序列})\big]$，原生方案让所有模态在同一自回归（或扩散）目标下、用同一参数 $\theta$ 从随机初始化共同优化。后期拼接则先独立优化视觉/语言子目标，再以小规模对齐数据微调 connector，跨模态梯度信号被结构性截断，难以学到深层联合先验。

GPT-4o [OpenAI 2024] 的 "o" 即 omni：单一模型原生处理文本、音频、图像，端到端音频对话延迟可低至约 320ms（接近人类对话），而旧的"语音转文字 → LLM → 文字转语音"级联管线延迟在秒级且丢失语气、笑声、多说话人等副语言信息。Gemini [Gemini Team 2023] 在技术报告中明确强调"natively multimodal, pre-trained from the start on different modalities"。

"原生"不是营销词，而是有可观测的能力差异：跨模态联合推理（如"听这段音频里背景的鸟叫，结合这张图判断拍摄季节"）、副语言信息保留、低延迟实时交互，是后期拼接很难补齐的。但代价是预训练算力呈数量级上升，且评测更复杂（见第 7 节）。

2早融合 any-to-any：Chameleon 与统一接口

实现原生多模态最彻底的路线是早融合（early fusion）：在输入层就把所有模态变成同一种 token，放进同一个序列里做自回归建模。Chameleon [Chameleon Team 2024] 把图像用一个学习到的图像 tokenizer（基于 VQ-VAE 思想）离散量化成 image token，与文本 token 共用一个词表、共用一个 Transformer、共用一个 next-token 目标 —— 模型完全不知道某个 token 来自文字还是图像。

直白讲

把图片也切碎成"词"，丢进和文字一样的句子里。模型只做一件事：预测下一个词。下一个词可能是文字，也可能是图块。这样它天然就能"图文交错地读、图文交错地写"。

严谨讲

Unified-IO [Lu et al. 2022] 更进一步把分割图、深度图、检测框、关键点等结构化输出全部序列化成离散 token，用一个统一的 seq-to-seq 接口处理数十种视觉/语言任务 —— 体现了"统一接口"（unified interface）的设计哲学：任务不再靠不同的 head，而靠不同的 token 序列来区分。

Chameleon 的关键工程难点在于训练稳定性：当文本与图像 token 共享 softmax 时，两种模态的 logit 量级差异巨大，原始 Transformer 会发散。论文引入 query-key normalization 与对 norm 顺序的调整来稳定混合模态训练。这提示我们：早融合理论优雅，但把异质模态塞进同一目标会带来非平凡的优化病态（optimization pathology）。

4稀疏专家 MoE 在多模态中的作用

原生多模态意味着同一个模型要同时承载文本、视觉、音频等异质能力，参数需求暴涨。Mixture-of-Experts (MoE) 是前沿大模型应对这一矛盾的核心手段：用稀疏激活（sparse activation）把参数总量做大，但每个 token 只路由到少数几个专家，使计算量（FLOPs）几乎不随总参数线性增长。

$$ y=\sum_{i\in \mathrm{TopK}(g(x))} g_i(x)\, E_i(x), \qquad g(x)=\mathrm{softmax}(W_g\,x) $$

其中 $E_i$ 是第 $i$ 个专家（通常是一个 FFN），$g(x)$ 是路由门控（router/gating），只取 Top-$K$（常 $K{=}1$ 或 $2$）个专家激活。于是总参数可达万亿级，而每 token 实际计算只相当于一个小得多的稠密模型。

直白讲

不是让一个全能巨人处理所有 token，而是养一群各有专长的专家，每个 token 来了只叫最相关的一两个专家出手。这样"团队"很大（参数多、知识广），但每次"出工"的人很少（算力省）。

严谨讲

稠密模型的算力 $\propto$ 参数量；MoE 通过条件计算（conditional computation）解耦二者，算力 $\propto K\times$ 单专家规模。代价是：路由不均衡（load imbalance）需 auxiliary load-balancing loss 约束；显存仍要存下全部专家；分布式下专家并行（expert parallelism）带来通信开销。多模态场景中，专家可能隐式按模态/任务分化，这既是效率来源，也给可解释性与评测带来新问题。

评测视角：MoE 模型的"有效容量"和"激活算力"解耦，导致用参数量横向比较两个模型变得不公平 —— 一个 8×7B MoE 与一个 7B 稠密模型，参数差近 8 倍但单 token 算力相近。报告/评测前沿多模态模型时，应同时给出总参数、激活参数、每 token FLOPs，否则结论会误导。

5智能体基础：GUI grounding 与 set-of-marks

原生多模态让模型能"看懂屏幕"，这是迈向多模态智能体（multimodal agent）的前提。智能体最基础的能力是 GUI grounding：把自然语言指令对应到屏幕上的具体坐标或控件 —— 例如把"点击提交按钮"映射为屏幕坐标 $(x,y)$ 或一个边界框 $(x_1,y_1,x_2,y_2)$。

这本质是 referring expression grounding 在屏幕域上的特化，难点在于：①界面元素小而密集（图标、菜单项）；②文字渲染细，需高分辨率视觉（呼应模块 06）；③同一语义控件外观跨应用差异极大，需强泛化。SeeClick [Cheng et al. 2024] 专门提出 GUI grounding 预训练任务，显著提升了 agent 在真实界面上的定位准确率。

直接让模型回归像素坐标对很多 VLM 仍偏难。Set-of-Marks (SoM) 提示法换了个思路：先用分割/检测在图上叠加带编号的可视标记，让模型只需回答"该点哪个编号"，把连续坐标回归问题降级为离散选择问题，大幅降低 grounding 难度、提升可靠性。

── 直接坐标 grounding ────────────── ── Set-of-Marks 提示 ────────────── 指令: "点击 提交" 先叠加编号标记: │ ┌─────────────────────┐ ▼ VLM 直接回归 │ [1]文件 [2]编辑 [3]× │ ┌─────────────────────┐ │ │ │ (x=412, y=088) │ ← 像素级回归 │ [4]搜索框 │ │ 对小图标常常偏掉 │ 易错 │ [5]提交 ◄── │ └─────────────────────┘ └─────────────────────┘ 指令→ "点击 提交" VLM 只需答: "5" ← 离散选择，更稳
Set-of-Marks 是一个极具实践价值的"评测/工程"技巧：它把感知（定位在哪）与决策（该点什么）解耦。定位交给专门的检测/分割模块产生编号，VLM 只负责高层决策。做 agent 评测时，区分失败是"看不到/定位错"还是"决策错"，SoM 正好提供了这种归因切面。

6computer-use agent：感知-行动循环

把 grounding 嵌入一个闭环，就得到 computer-use agent：模型看屏幕截图 → 推理当前该做什么 → 输出鼠标/键盘动作 → 环境执行 → 产生新截图，如此循环直到完成任务。这是经典的感知-行动循环（perception-action loop），也是强化学习里 agent 的标准形态，只不过策略由一个 VLM 充当。

┌──────────────────── 感知-行动循环 perception-action loop ─────────────────┐ ▼ │ ┌────────────┐ 截图(observation) ┌──────────────┐ action(click/type/scroll) │ │ 环境/OS │ ─────────────────────► │ VLM 策略 │ ────────────────────────────┘ │ (screen) │ │ 观察→推理→动作 │ └────────────┘ ◄───────────────────── └──────────────┘ ▲ 执行动作，状态更新 │ │ ▼ └────────────── 直到任务完成 / 触发停止条件 / 安全护栏拦截 ────────────────

代表工作：CogAgent [Hong et al. 2023] 用高低分辨率双路视觉专门处理 GUI 截图里的细小文字与图标；SeeClick 强化 grounding；Anthropic Computer Use [2024] 让 Claude 直接输出鼠标键盘动作操作真实桌面；Qwen2.5-VL [Bai et al. 2025] 把 GUI 操作、对象定位、文档解析作为原生能力训练，并支持结构化的动作/坐标输出。动作空间通常形如：

$$ a_t \in \{\,\texttt{click}(x,y),\ \texttt{type}(\text{text}),\ \texttt{scroll}(\Delta),\ \texttt{key}(k),\ \texttt{done}\,\} $$
让模型直接操作真实计算机是高风险能力：误删文件、误付款、被网页上的注入文本劫持（prompt injection 通过屏幕内容进入）、自我繁殖式操作等。本模块的 notebook只做教学模拟（toy 环境），绝不触碰真实 OS。生产级 computer-use 必须配沙箱、动作白名单、人类确认（human-in-the-loop）与硬性停止条件 —— 这正是下一节"安全护栏"的内容。

7智能体评测：为什么比静态 benchmark 更难也更重要

模块 07/08 评的是"模型回答一个问题对不对"——单步、静态、确定。智能体评测评的是"模型能不能在多步交互中真正完成一项任务"——多步、动态、有状态、强随机。这呼应 METR 这类机构的核心关切：评估前沿模型的自主能力（autonomy）与潜在危险能力。

维度静态 benchmark（模块 07/08）agentic 评测（本节）
单位单条 QA / 单步预测完整任务（多步轨迹 trajectory）
主指标准确率 accuracy任务完成率 task success rate / 完成时长
状态无状态，题目独立有状态，误差跨步累积
可复现性高（确定输入输出）低（环境随机、长轨迹方差大）
失败归因相对清晰（对/错）难（感知错？规划错？执行错？环境变了？）
安全维度主要看有害输出还要看有害行动与不可逆后果

几个评测核心维度：

  • 任务完成率 (task success rate)：在一组真实任务上端到端成功的比例。需要可程序化判定的 success oracle，构造成本远高于一道选择题。
  • 多步可靠性 (multi-step reliability)：单步 95% 准确，10 步连乘只剩 $0.95^{10}\approx 60\%$。长时程任务对单步错误率极其敏感，这是 agent 落地的头号瓶颈。
  • 自主性评估 (autonomy evaluation)：模型在无人干预下能走多远、能否自我纠错与恢复（self-correction / recovery）。METR 用"模型能独立完成的任务时长（task horizon）"作为自主能力的可比刻度。
  • 安全护栏 (safety guardrails)：危险动作拦截率、对 prompt injection 的鲁棒性、是否遵守停止条件、不可逆操作前是否请求人类确认。评的不只是"说错话"，更是"做错事"。
$$ \Pr[\text{任务成功}] \approx \prod_{t=1}^{T} \Pr[\text{第 }t\text{ 步正确}] \;\xrightarrow{\;\text{长时程 }T\uparrow\;}\; \text{对单步错误率高度敏感} $$
为什么 agentic 评测更重要：模型一旦能行动，其能力与风险都不再停留在"文本"层面，而是落到真实世界后果上。静态 benchmark 跑满分也无法保证 agent 安全可靠；反过来，agentic 评测的高方差、难复现、人工搭建环境成本高，又使它远比刷榜困难。可复现的任务环境、可信的 success oracle、对长时程方差的统计处理，是当前 agent 评测方法学的前沿。这是从 model evaluation 走向 system / agent evaluation 的关键一跃。

8研究前沿与开放问题

  • 统一任意模态 (truly any-to-any)：能否用一个目标、一套参数无缝处理文/图/音/视频的输入与输出？早融合（Chameleon）优雅但有优化与保真度瓶颈，扩散+自回归混合（Transfusion 类）是热点，但"统一接口"与"单模态最优质量"之间的取舍仍未定论。
  • 长时程可靠性 (long-horizon reliability)：单步错误在长轨迹上指数累积，如何让 agent 自我监控、错误恢复、知道何时停下或求助？这是 agent 从 demo 走向生产的核心瓶颈。
  • agent 安全 (agentic safety)：从屏幕/网页注入的 prompt injection、不可逆动作、自主性带来的失控风险，如何在不牺牲能力的前提下加护栏？危险能力评估（dangerous capability eval，呼应模块 08 与 METR）正成为前沿模型发布前的必经环节。
  • 评测方法学 (evaluation methodology)：如何构造可复现、可信、可扩展的 agentic benchmark？success oracle 自动化、长时程方差的统计严谨性、避免任务被训练数据污染，都是开放难题。
  • 统一表征的可解释性：MoE 专家是否、如何按模态/任务分化？原生联合表征里"跨模态推理"具体发生在哪？这关系到我们能否归因一个多模态 agent 的成功与失败 —— 评测的终极目标。
