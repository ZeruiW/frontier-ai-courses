C66 教你怎么量一个 agent，C67 教你怎么验证判分器——但这两课的方法都只被执行了一次。当同一套评测要被跑几百次、被十个人跑、被跑一年，它需要长成另一个东西。本课的核心主张：基础设施的价值不在于跑得快，而在于它让「这个数字变了」这件事有唯一的解释。全课的每一个工程决策——spec 是纯数据、缓存键含指纹、主键三元组、聚合后置、阈值从方差推、线上信号回灌——都是在服务这一条。

6 模块 四层：spec · runner · store · report 三性质：确定性 · 可归因 · 幂等 六个反模式（都不会报错） CI 门禁 + 线上闭环 纯标准库 · CPU · 断网可跑
怎么用： 先读模块的 NN_讲解.html，再跑同目录下的同名 .ipynb。notebook 用可控的假模型与本地 SQLite——被评对象是一个能精确注入失败（超时/限流/格式错误）的假函数，这比真实 API 更适合验证基础设施的正确性：你可以控制第几次调用会失败。所有幂等性、并发、续跑、门禁阈值的逻辑都能在上面完整验证。每个模块末尾的 🧪 真实工程胶囊 给出可原样复制的落地代码（inspect-ai 的 task 定义、数据集目录结构与 CI 检查、OpenTelemetry 埋点、GitHub Actions 的门禁分层）——但本课全程 CPU、断网、无需 API key。
