# C68 · Eval 基础设施与线上监控

> **一句话**：C66 教你怎么<strong>量</strong>一个 agent，C67 教你怎么<strong>验证判分器</strong>，
> 本课教你怎么让这套测量能被**可靠地、重复地、便宜地执行一千次**。

6 个模块 · 纯标准库 + numpy / CPU / 断网可跑 · 每个模块 4 道 `✏️ 练习`（assert 判分）+
`📖 参考答案` + `🧪 真实工程胶囊`。

## 这门课补的洞

C66 与 C67 给出的都是「做对一次评测」的方法。但真实系统里的问题是：

| 问题 | C66/C67 能答吗 | 本课在哪 |
|---|---|---|
| 「上个月这个数字是多少？」 | ✗ | 03 存储 |
| 「这两次运行到底差在哪？」 | 部分（harness 指纹） | 01 spec 与指纹 |
| 「跑到一半崩了怎么办？」 | ✗ | 00/02 幂等与续跑 |
| 「改了 prompt 分数却没变，是改动无效吗？」 | ✗ | 02 缓存键 |
| 「什么时候该阻断合并？阈值定多少？」 | ✗ | 04 CI 门禁 |
| 「离线涨了线上没涨，为什么？」 | ✗ | 05 线上监控 |

核心主张：

> **基础设施的价值不在于跑得快，而在于它让「这个数字变了」这件事有唯一的解释。**

全课的每一个工程决策都在服务这一条：
spec 是纯数据（可归因）→ 缓存键含指纹（执行不污染）→ 主键三元组（幂等）→
聚合后置（未来能问新问题）→ 阈值从方差推（门禁可信）→ 线上信号回灌（闭环）。

## 六个反模式（它们都不会报错）

| # | 反模式 | 后果 | 解在 |
|---|---|---|---|
| 1 | 配置写在代码里 | 无法比较两次运行的差异；无法生成指纹 | 01 |
| 2 | 就地修改任务集 | **所有历史分数一夜之间失去意义** | 01 |
| 3 | 用内容哈希当样本 ID | 改一个错别字，历史结果就对不上 | 01 |
| 4 | 缓存键不含配置指纹 | **改了 prompt 却读到旧结果**，被误读成「改动无效」 | 02 |
| 5 | 失败样本静默跳过 | 分母变小，成功率虚高 | 02/03 |
| 6 | 门禁阈值拍脑袋定 | 误报 → 团队关掉门禁 → 门禁形同虚设 | 04 |

## 一条贯穿全课的信息流

```
① SPEC      评什么、怎么判、版本与指纹        ─┐
     │                                        │
② RUNNER    并发/重试/缓存/预算，幂等可续      │  离线
     │                                        │
③ STORE     一条 rollout 一行，只追加          │
     │                                        │
④ CI GATE   确定性检查 + 配对统计门禁         ─┘
     │
     ▼  发布
⑤ ONLINE    漂移 / guardrail / 无标签信号
     │
     └──────────► 回灌 ──► ① 的新版本任务集
```

## 学习路径

### 路径 A · 完整走一遍（约 10–12 小时）

`00 → 01 → 02 → 03 → 04 → 05`，每天一个模块。

判断走完了没有的标准：**给你一套现有的评测流程，
你能不能按六个反模式逐条打分，并说出每一条不做的具体后果。**

### 路径 B · 手上已经有评测，想让它别再骗人（约 4 小时）

`00 全部 → 02 全部 → 03 第 5 节（完整性校验）→ 04 第 2 节（阈值三步法）`。

理由：**02 的缓存键与重试偏倚是「正在悄悄污染你数字」的两件事**，
03 的完整性校验是最便宜的兜底，04 的阈值推导能立刻替换掉拍脑袋的门禁。

### 路径 C · 只有两小时

`00 的四层架构与三性质 → 01 的稳定 ID 与版本语义 → 02 的缓存键 → 04 的 α 换算`。

这四块是「知道了就能立刻少犯错」的部分。

## 环境

```bash
pip install numpy jupyterlab ipykernel
jupyter lab
```

全程 CPU、断网可跑、不需要任何 API key。

**关于假模型的一个说明**：本课用可控的假函数而不是真实 API，不是为了省钱，
而是因为**基础设施的正确性本来就不该依赖真实模型**——
而且假函数能让你精确控制「第几次调用会失败」，
这是验证重试、熔断、续跑逻辑的唯一可靠方式。

notebook 会在 `./_eval_tmp/` 下创建临时文件，**每个 notebook 开头都会先清空它**，
所以重复运行是安全的。
