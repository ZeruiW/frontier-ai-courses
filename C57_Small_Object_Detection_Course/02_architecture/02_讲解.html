1多尺度不是「多跑几遍」：FPN 解决的到底是什么矛盾

卷积主干有一个无法回避的内在矛盾：语义强度随深度增长，空间分辨率随深度衰减，而它们由同一条链路决定。ResNet-50 的四个阶段输出 C2/C3/C4/C5，stride 分别是 4/8/16/32，通道 256/512/1024/2048——通道数（语义容量）涨了 8 倍，格子数掉了 64 倍。

把这个矛盾具体到 TSR：一个 60 cm 的限速牌在 50 米外、1920×1080/60°FOV 的相机上是 20 像素。它在 C5（stride 32）上占 20/32 = 0.625 个格子——注意，不是「变小了」，是根本没有属于自己的格子。它的响应被摊进一个覆盖 32×32 原图像素的 2048 维向量里，而那 32×32 里还有天空、树叶、灯杆、后面那辆车的车顶。要在这个向量里把「限速 60」和「限速 80」分开，是在要求网络做一件信息论上就不成立的事。

直白说

FPN 的直觉是「让每一层都既看得清、又看得懂」：分辨率由这一层自己提供，语义由上面那层送下来。横向连接的 1×1 卷积做两件事——把通道数统一到 256（否则没法相加），以及给浅层一次线性重组的机会；最后那个 3×3 是为了消除最近邻上采样带来的混叠（aliasing），不加会在特征图上留下棋盘格。

严谨说

但要精确地说：FPN 并没有「在 stride 4 上跑一个深网络」，它只是把 stride 32 的语义插值到了 stride 4。P2 上的语义是借来的，它的空间分辨力上界仍受制于深层的 stride——一个 20 px 的目标在 C5 上被摊在 0.6 个格子里，这个信息损失无法通过上采样恢复。这就是为什么后来出现了两条完全不同的路线：① HRNet 全程保持高分辨率分支（不下采样再上采样，而是并行多分辨率互相交换）；② Deformable DETR 的多尺度稀疏采样（让 query 自己去高分辨率层取证据）。理解「FPN 的语义是借来的」，才能理解这两条路线为什么存在。

一句可迁移的判断：看到「小目标 AP 低」，先问「这个目标在它被分配到的那一层上占几个格子」。少于 1 个格子 = 网络在猜；1–2 个格子 = 能检出但框不准；4 个格子以上才谈得上正常学习。这个数字是 目标像素边长 / 该层 stride，两秒就能算出来，却能直接决定接下来该改分辨率、改 stride 还是改分配。

2层级分配：k = k₀ + ⌊log₂(√(wh)/224)⌋，以及 TSR 分布下的层级负载

有了金字塔，下一个问题是：一个框该由哪一层负责？ FPN 原文（以及 Mask R-CNN 的 RoIAlign）给出的规则是一条闭式公式：

\[k \;=\; \left\lfloor k_0 + \log_2\!\left(\frac{\sqrt{wh}}{224}\right) \right\rfloor, \qquad k \leftarrow \mathrm{clip}(k,\; k_{\min},\; k_{\max})\]

三个常数各有来历：224 是 ImageNet 预训练的输入边长；k₀ = 4 表示「一个 224×224 的框应该由 P4（stride 16）处理」——因为在 ImageNet 预训练里，224 的整图正是被 C4 那一级的感受野覆盖的；clip 到 [2, 5] 是因为金字塔只有这几层。公式的含义很朴素：框的边长每减半，就往上（分辨率更高的那一层）挪一级。

一阶段检测器用的是尺度区间，但结论一样

YOLO / RetinaNet / FCOS 不用这条公式：YOLO 用 anchor 的 IoU 匹配，FCOS 用回归范围（regression range）——P3 负责 [0, 64)、P4 负责 [64, 128)、P5 负责 [128, 256)、P6 [256, 512)、P7 [512, ∞)。形式不同，效果完全一样：所有小目标被压在最高分辨率那一层。FCOS 的 P3 区间下界是 0，上界 64，意味着 6 px 和 63 px 的目标共用同一层同一套回归尺度。

TSR 尺寸分布：小目标占比不是数据集偏差，是几何必然

很多人以为「TT100K 里小目标多」是数据集的采集偏好。不是——它是针孔几何 + 均匀采样的必然结果，可以推导出来。针孔模型给出像素尺寸

\[s \;=\; \frac{f\,S}{Z}, \qquad f \;=\; \frac{W_{\text{px}}/2}{\tan(\mathrm{HFOV}/2)}\]

对 1920×1080、水平 FOV 60° 的前视相机，f ≈ 1662.8 px；一块 60 cm 的圆形限速牌于是有 s ≈ 997.7 / Z（Z 以米计）。50 米外 20 px，100 米外 10 px，150 米外 6.7 px。 现在关键的一步：车匀速前进、按固定帧率采样，则同一块标志被采到的距离近似均匀分布。做变量代换 s = c/Z，得

\[p(s) \;=\; p(Z)\left|\frac{\mathrm{d}Z}{\mathrm{d}s}\right| \;=\; \frac{1}{Z_{\max}-Z_{\min}}\cdot\frac{c}{s^{2}} \;\propto\; \frac{1}{s^{2}}\]

尺寸密度以 1/s² 衰减——这是一个非常陡的幂律。代入 Z ∈ [8, 150] m：84% 的标志实例小于 32 px（COCO 的「small」定义），62% 小于 16 px，18% 小于 8 px。notebook 里会把这个解析结果和蒙特卡洛对上。

这张表是本模块最重要的一个数字。在 TSR 的尺寸分布下，一个 P3–P7 的 RetinaNet 等价于一个「单尺度、stride 8」的检测器——多尺度金字塔的全部收益在这个任务上归零，而它的计算成本你一分不少地付了。更糟的是，这一层的 stride 是 8，对一个 10 px 的标志只有 1.25 个格子。

面试里这是一个能立刻显出水平的点：被问「小目标怎么办」时，标准答案是「加 P2 / 提分辨率 / 用 NWD」；而能先把「你现在这套配置下各层的负载是多少」算出来再谈方案的人，面试官会立刻知道你真的调过。面试官想听的是「我先统计了尺寸分布和层级负载，发现 99% 压在 P3，所以先动的是分辨率而不是 backbone」这种归因过程。

3加 P2 的账：分辨率的平方增长有多贵

既然所有目标都挤在最高分辨率那层，最直接的解法就是再加一层更高分辨率的 P2（stride 4）。它的收益是确定的：10 px 的目标从 1.25 个格子变成 2.5 个格子，正样本候选点数量按面积翻 4 倍。代价也同样确定，而且可以精确算出来。

成本：为什么恰好是 85/21 ≈ 4.05 倍

neck 与 head 的计算量正比于特征图位置数，而位置数 = HW/s²。以 P3 为 1 归一化，各层的相对成本是 4^(3−l)：

\[\frac{\mathcal{C}_{\text{P2--P5}}}{\mathcal{C}_{\text{P3--P5}}} \;=\; \frac{4 + 1 + \tfrac14 + \tfrac1{16}}{1 + \tfrac14 + \tfrac1{16}} \;=\; \frac{85/16}{21/16} \;=\; \frac{85}{21} \;\approx\; 4.05\]

加一层，检测头的计算量变成原来的 4 倍。 这不是「多了一层的开销」，而是「新加的这一层比原来整个金字塔还贵 3 倍」——因为 P2 一层的位置数就是 P3+P4+P5 之和的 3 倍。

直白说

所以「加 P2 太贵」这个结论要打个折扣：朴素地加确实是 4 倍，但把 P2 当成一个「便宜的、只管小目标的辅助层」来设计，可以压到 1.4 倍左右。关键的心法是——P2 不需要和 P3–P5 同构。它面对的目标只有 4–30 px，既不需要 128 通道去区分 200 类的精细语义（那部分可以靠上层送下来的语义），也不需要 4 层卷积塔去做大范围回归。

严谨说

但有一个必须一起算的隐性代价：加 P2 会让前景-背景比进一步恶化约 4 倍。以 1536×864、一张图 5 块标志、center-based 分配每个 GT 约 9 个正样本计算：P3–P5 下正样本占比 45/27216 = 0.165%，加 P2 后总位置数变成 110160，而正样本数几乎不变（中心采样半径按 stride 缩放，落在框内的点数由目标尺寸决定而不是由 stride 决定），占比掉到 0.041%。也就是说，你花 4 倍算力买来的分辨率，同时把分类头的正负样本比推到了 1:2400。这不是加 P2 的反对理由，而是说明架构改动必须和分配 / 损失改动一起做——这正是下一个模块的内容。

一个实现细节的坑：加了 P2，anchor 的尺度设置也必须跟着改。RetinaNet 默认每层的基础 anchor 边长是 4×stride（P3 → 32 px）。如果你直接把 P2 挂上去而不改 anchor 配置，P2 的基础 anchor 是 4×4=16 px——听起来合理，但配上 {1, 2^(1/3), 2^(2/3)} 三档尺度后最小 anchor 仍是 16 px，而你要检的目标是 6–10 px。结果是加了 P2 但 AP_s 几乎没涨，然后得出「加 P2 没用」的错误结论。 正确做法：先统计尺寸分布，再让最小 anchor 落在分布的 5% 分位上。

4信息该往哪个方向流：PAN、BiFPN 与加权融合

FPN 的信息流是单向的——语义从深层往浅层广播。反过来的方向呢？浅层拥有最精确的边缘与定位信息，深层却拿不到它。在原始 backbone 里，C2 的信息要到达 C5 需要穿过一百多层卷积，经过这么长的路径，精确的空间信息早就被平均掉了。

PANet（Path Aggregation Network）的解法直白得近乎粗暴：在 FPN 之后再接一条自底向上的路径。这条捷径只有不到 10 层，浅层的定位信息可以近乎无损地送到深层。notebook 里有一个只用 numpy 就能跑的实验来验证这件事：在 P2 上放一个脉冲，跑完 FPN 的 top-down 后 P5 的响应严格为零；接上 PAN 的 bottom-up 之后 P5 才有响应。这不是比喻，是可以 assert 的事实。

BiFPN（EfficientDet）在 PAN 基础上做了三个改动，其中第三个对小目标最关键：

  1. 删掉只有单个输入的节点——它只做了一次卷积，对「融合」没有贡献，纯粹浪费算力。
  2. 同层加一条从原始输入到输出的跨接——保留该层自己的信息不被上下层稀释，成本几乎为零。
  3. 加权融合（weighted feature fusion）——不同层的特征分辨率不同，直接相加等于默认它们同等重要，这是错的。BiFPN 给每个输入配一个可学标量权重。
\[O \;=\; \sum_i \frac{w_i}{\varepsilon + \sum_j w_j}\cdot I_i, \qquad w_i = \mathrm{ReLU}(\tilde w_i), \quad \varepsilon = 10^{-4}\]

这个形式叫 fast normalized fusion：用 ReLU 保证非负、用求和归一化保证权重落在 [0,1]，比 softmax 快得多而效果相当。为什么它对小目标重要？ 因为 P2 的特征是整个金字塔里语义最弱、噪声最大的（它离 backbone 的深层最远，语义全靠上采样借来）。如果 P2 和上采样来的 P3 等权相加，等于强制规定「这一层自己的证据和借来的语义一样可信」。加权融合让网络自己去学这个比例——而学出来的结果通常是：在小目标密集的层上，自身分辨率的权重更高。

重复 N 次的 BiFPN同上，堆叠同上×N边际递减，N=3–7小目标受益于更多轮跨层交换

两个常见误解。①「BiFPN 的加权是 attention」——不是。 它是每个输入一个标量（或每通道一个标量），与输入内容无关，训完就固定了；attention 的权重是逐样本、逐位置动态计算的。这个区别决定了 BiFPN 的加权几乎不增加推理成本，也决定了它的表达力上限。②「neck 越复杂越好」——在大模型上不成立。 BiFPN 的增益在 EfficientDet-D0/D1 这类小模型上有 1–2 AP，到 D7 就基本被主干的容量淹没了。车端 TSR 恰好在「小模型」那一档，所以 neck 的改动在这里性价比反而更高。

5三笔不同的账：提高输入分辨率 vs 加 P2 vs 换更强主干

「小目标检不到」有三个看起来都合理的解法，但它们解决的根本不是同一件事。分清楚这一点，是这一节唯一要传达的东西。

方案改变了什么全模型 FLOPs目标的像素数目标占的格子数本质
加 P2（stride 8 → 4）只改采样网格neck+head ×4.05；主干不变不变×2（每轴）把已有信息采得更细
输入分辨率 ×2改输入信息量全模型 ×4×4×2（每轴）恢复被 resize 丢掉的传感器信息
换更深/更宽主干改表示容量主干 ×1.5–3不变不变对小目标几乎无效
把 resize 改回原生分辨率停止丢信息按面积比例×(比例)²×比例免费的、最高 ROI 的一招

为什么这个区分是决定性的：一个 TSR 的具体数字

典型的工程现状是：相机给 1920×1080，训练脚本 letterbox 到 640×640。缩放比例是 640/1920 = 0.333。 于是：

  • 50 米外的限速牌：原生 20 px → 送进网络时 6.7 px；在 stride 8 上占 0.83 个格子——不到一个格子，结构上不可能检出。
  • 100 米外：原生 10 px → 3.3 px；在 stride 8 上占 0.42 个格子。这不是「难检」，是「不存在」。
  • 把输入换成 1280×720（比例 0.667）：50 米外变成 13.3 px，stride 8 上 1.67 个格子；100 米外 6.7 px。
  • 用原生 1920×1080：50 米外 20 px / 2.5 格，100 米外 10 px / 1.25 格。同样是 stride 8，检出距离从 30 米推到了 80 米以上。

直白说

所以顺序应该是：先把输入分辨率提到延迟预算允许的上限，再考虑加 P2，最后才轮到换主干。原因是——加 P2 只是把同样的信息采得更细，而提高输入分辨率是真的把信息拿回来。一个 6.7 px 的目标无论用多细的网格去采，它也只有 6.7 px 的信息；而把它变回 20 px，是把传感器本来就捕捉到的、被 resize 扔掉的那部分像素找回来。

严谨说

严格地说，两者的作用可以分解为：「目标的像素数」决定了信息量上界，「目标占的格子数」决定了网络能不能表示它。加 P2 只动第二项，提分辨率两项都动。而换主干——把 ResNet-50 换成 ResNet-101 或 Swin——两项都不动，它增加的是「在给定信息量下的表示能力」，而小目标的瓶颈根本不在表示能力，在信息量。这解释了一个常见的困惑：换了更强的 backbone，AP_m 和 AP_l 都涨了，AP_s 纹丝不动。

先问分辨率，再谈架构

面试里这是一个分水岭问题。 被问「怎么提升小目标检测」时，如果候选人直接开始讲 FPN / BiFPN / 注意力机制，那是背书；如果候选人先反问「你现在的输入分辨率是多少、原图是多少、目标的像素尺寸分布是什么样」，面试官立刻知道这个人做过真实项目。

因为在工业界，「训练时把 1920 缩到 640」这个配置是压倒性常见的默认值（YOLO 的默认 imgsz=640 就是这么来的），而它在 TSR 上直接把一半以上的目标压到了亚格子尺度。把它改回去往往比任何架构改动的收益都大，而且不需要改一行模型代码。 面试官想听的是：你会先量化问题，再选方案；而不是背一串方法名。

提高输入分辨率不是免费的，有三个必须一起算的代价：① 全模型 FLOPs 按面积平方增长（1920 vs 640 是 9 倍）；② 感受野相对目标变小了——同一个网络在高分辨率输入上，深层的有效感受野覆盖的物理场景范围变小，可能伤害大目标与上下文；③ 训练-推理分辨率必须一致，否则 anchor 尺度、回归范围、归一化尺度全部错位（这是 C60 讲的一致性问题的一个具体实例）。

6可变形注意力：稀疏采样为什么对小目标天然友好

Transformer 检测器给出了第三条路。但先要说清楚：朴素的多尺度全局注意力在检测上是算不动的。把 1536×864 的 P2–P5 全部展平成 token：

P2: 216×384 =  82,944
P3: 108×192 =  20,736
P4:  54× 96 =   5,184
P5:  27× 48 =   1,296
                -------
总计            110,160 个 token

全局 self-attention 的复杂度 O(N²·C) = 110160² × 256 ≈ 3.1 × 10¹² MAC
—— 比整个 ResNet-50 主干贵四个数量级。不可行。

Deformable attention 的做法是：每个 query 不看全部 110,160 个位置，而是只采样 M×L×K 个点（M 个注意力头 × L 个金字塔层 × 每层 K 个采样点），采样位置由 query 自己预测的偏移量决定。取 M=8、L=4、K=4，就是 128 个采样点：

\[\frac{\text{全局注意力的 key 数}}{\text{可变形采样点数}} \;=\; \frac{110{,}160}{8\times4\times4} \;=\; \frac{110{,}160}{128} \;\approx\; 861\times\]

对小目标，这个机制有两个具体的好处，都能量化：

  1. 注意力质量不被背景稀释。 在全局 softmax attention 里，一个 10 px 的目标在 P2 上只占 6.25 个格子，占全部 110,160 个 key 的 5.7 × 10⁻⁵。初始化时注意力接近均匀，目标能拿到的注意力质量是十万分之五——这正是 DETR 收敛慢的根因之一（见 C54 m04）。而可变形注意力用一组学到的偏移把采样点直接放到目标上，notebook 的模拟显示：在 P2 上，采样点落进 10 px 目标框内的比例可达 62%。从 5.7×10⁻⁵ 到 0.62，是四个数量级的差别。
  2. 天然跨层。 一个 query 同时在 P2–P5 上采样，不需要「先决定这个目标属于哪一层」。这等于把上一节讲的「层级分配」问题从硬性划分变成了软性加权——对处在层级边界上的目标（比如 60 px 恰好在 P2/P3 分界处）尤其重要。

直白说

所以可变形注意力对小目标友好，本质上是因为它把「在哪里取证据」变成了可学的。卷积的采样位置是固定网格，全局注意力的采样位置是「全部」，可变形注意力的采样位置是「学出来的少数几个」——对一个只有几个格子的目标，这恰好是最有效的形式。

严谨说

但有两个必须知道的约束。① 初始化极其关键：Deformable DETR 把采样偏移的初始值设成围绕参考点的规则网格（不同的头指向不同方向），并且把预测偏移的线性层权重初始化为 0、偏置设成那个网格。如果随机初始化，采样点会散到图像各处，小目标上根本收不回来，训练直接不收敛——这是一个「论文里一句话、复现时踩三天」的细节。② 采样用双线性插值，梯度可以传到亚像素位置，这既是优点（定位精度不受网格限制）也是隐患（对 4–8 px 的目标，插值出来的梯度信噪比很低）。

把三代方案排成一条线就清楚了：FPN 是「把语义搬到高分辨率上」，PAN/BiFPN 是「让搬运双向且可加权」，可变形注意力是「不搬了，让需要的人自己去取」。而所有这些都在同一个前提下工作：高分辨率的那一层必须存在。 如果你的金字塔从 P3 开始，那么再精巧的采样机制也只能在 stride 8 的网格上采——这就是为什么本模块的顺序是「先分辨率，后融合，再采样」。

7上下文：一个 8 像素的目标必须靠周围

把信息瓶颈算清楚：一个 8×8 px 的标志，在 stride 8 的 P3 上占据恰好一个格子。这一个格子是一个 C 维向量（典型 C=256），而它要同时编码：

  • objectness——这里有没有东西
  • 类别——中国 GB 5768 体系下含限速变体有 200+ 类，需要 log₂(200) ≈ 7.6 bit 的可区分度
  • 框回归——中心偏移 + 宽高，4 个连续量
  • （若有）属性——是否电子牌、是否对向车道、遮挡程度

而这个向量的输入信息来自原图 8×8 = 64 个像素，经过 ISP、JPEG 压缩、运动模糊、下采样之后，有效信息远低于 64×3 字节的名义上界。结论是清楚的：仅靠目标自身的像素，不足以完成这个任务。必须用上下文。

直白说

上下文的收益是真实的：一个 8 px 的红色圆形本身可能是标志、可能是尾灯、可能是广告牌上的圆点；但「装在竖直杆上、位于地平线上方、在道路右侧带状区域内」的 8 px 红色圆形，几乎一定是禁令标志。这个联合先验能把一个几乎不可解的分类问题变成可解的。

严谨说

但上下文有一个具体的失效模式，必须提前防：当目标自身的信息太弱时，模型会退化成「只学上下文」。症状是——在有杆件的位置产生高置信度误检（而那里其实是路牌背面或者路灯），同时对不在典型位置的标志（临时施工牌放在地上、龙门架上的标志）完全漏检。诊断方法很直接：把目标区域遮黑只留上下文，看模型的置信度掉多少。如果掉得不多，说明模型根本没在看目标本身。

所以上下文的大小是一个需要调的超参，而不是「越大越好」。经验区间：上下文范围取目标尺寸的 3–6 倍。低于 3 倍拿不到杆件；高于 6 倍开始引入无关背景，并且让模型学到「路边区域 = 有标志」的捷径。在 TSR 上这个捷径的直接后果就是广告牌与车身贴纸的误检——而误检在量产系统里的代价远高于漏检（会触发莫名其妙的减速）。

8超分、特征增强，以及轻量化与小目标的根本矛盾

最后两类做法值得单独一节，因为它们在论文里看起来很有吸引力，但在量产系统里的实际排序远低于前面几节的方法。

超分与特征级增强：为什么排在最后

这一类方法的思路是：既然小目标像素少，就先把它放大——图像级超分（先超分再检测）、特征级超分（Perceptual GAN 把小目标特征映射到大目标特征的分布上）、或者用 GAN 判别器逼迫小目标特征「看起来像」大目标特征。

方法做什么论文报告增益真实代价工程建议
图像级超分整图 2–4× 超分后再检测AP_s +1–3额外一个大网络 + 分辨率翻倍的检测，延迟不可接受❌ 车端不考虑
特征级超分（Perceptual GAN 系）把小目标的浅层特征映射到「大目标风格」AP_s +1–2多一个生成器 + 判别器，训练不稳定⚠️ 收益不如直接提分辨率

超分不创造信息，它发明信息

超分在 TSR 上有一个特有的、安全相关的风险：幻觉（hallucination）。 超分网络的本质是「用学到的先验补全缺失的高频信息」——它不创造信息，它发明信息。在自然图像上，把模糊的树叶补成清晰的树叶无伤大雅；但在一个 8 px 的限速牌上，超分网络完全可能把「60」补成「80」，而且补得非常清晰、非常自信。

下游拿到的是一个高置信度的错误限速。这类错误无法通过置信度过滤，因为超分让整条链路的置信度都升高了。 结论：任何在安全关键路径上引入生成式补全的做法，都必须有一条不依赖它的旁路来交叉验证（例如地图先验、多帧一致性）。这是量产 TSR 系统的一条红线。

轻量化与小目标：三板斧，每一斧都砍在小目标上

车端模型必须轻量化，而轻量化的三个标准手段恰好都直接伤害小目标——这不是巧合，是因为小目标依赖的正是被裁掉的那些东西。

轻量化手段省了什么为什么专门伤小目标缓解
降输入分辨率FLOPs ∝ 面积直接删除小目标的像素；20 px → 6.7 px不要做；改用 ROI 裁剪保留关键区域的原生分辨率
减通道FLOPs ∝ C²小目标的判别信息本就集中在少数通道，减通道优先损失细粒度纹理只减深层通道，保留 P2/P3 的通道数
减深度 / 用 depthwiseFLOPs 线性下降depthwise 去掉了通道间混合，而小目标的语义恰恰需要跨通道组合弱信号大核 depthwise + 1×1 pointwise（RTMDet 的做法）保留混合能力
结构化剪枝去掉低激活通道小目标的激活本来就低 → 负责小目标的通道被优先剪掉按分尺寸的 AP 做剪枝敏感度评估，而不是只看总 mAP
INT8 量化算力 / 带宽小目标的 logit 分布集中在低分区，量化后区分度下降更明显分类头保 FP16；校准集必须含足量小目标（见 C60 m03）

直白说

所以「又要轻量又要小目标好」这个需求本身是有内在张力的。解决张力的方式不是在两者之间折中，而是让计算量花在该花的地方：整图用低分辨率跑一个粗检测器找 ROI，只在 ROI 上用高分辨率精检（这就是模块 04 要讲的两级级联）；或者只对图像的上半部分算 P2。「均匀地降低所有地方的精度」是最差的一种轻量化。

严谨说

还有一个容易被忽略的评测陷阱：剪枝 / 量化的敏感度评估如果只看总 mAP，几乎必然会牺牲小目标。因为在 COCO 式的评测里 AP_s 只占 mAP 的三分之一权重，而在 TSR 的真实分布里小目标占 84%。一个「总 mAP 只掉 0.5」的剪枝方案，完全可能对应「AP_s 掉 4、AP_l 涨 1」。正确做法是把按尺寸分桶的 AP 作为剪枝与量化的主指标——这一点在模块 05 和 C60 m03 会再展开。

把本模块的所有手段按「收益 / 成本」排一次序，对 TSR 场景大致是：① 把输入分辨率改回接近原生（收益极大，成本 = FLOPs 按面积增长，无工程风险）→ ② 加 P2 且用减半通道 / ROI 限制成本（收益大，1.4× 成本）→ ③ neck 换 BiFPN 或加权融合（收益中，成本小）→ ④ 上下文与位置先验（收益中，成本几乎为零，但要防捷径）→ ⑤ 特征蒸馏（收益小，推理零成本）→ ⑥ 超分（收益不确定，有安全风险）。注意前两条都是「分辨率」，这不是巧合——小目标问题在架构层面上，八成是分辨率问题。

9研究前沿与开放问题

架构层面的小目标解法在 2020 年之后进入了一个「大方向已定、细节仍在动」的阶段。以下是几个仍然开放、且与 TSR 直接相关的问题。

  • 高分辨率主干 vs 编码-解码金字塔。 HRNet 路线主张全程保持高分辨率分支并行交换，而不是「先降采样再上采样」。它在姿态估计上确定性地更好，但在检测上因为计算量分布不友好（高分辨率分支贯穿全网）一直没成为主流。随着车端算力上升、以及「小目标才是瓶颈」的共识增强，这条路线值得重新评估——尤其是「只在浅层保持高分辨率、深层正常下采样」的混合形态。
  • P2 的成本该怎么摊。 目前的做法（减通道、减头深度、ROI 限制）都是工程折中，缺少原则性的答案。一个开放问题是：能否让 P2 只承担「定位」而把「分类」完全交给上层——即把检测头按任务拆到不同分辨率上（定位需要分辨率，分类需要语义）。已有零星工作（task-decoupled heads across levels），但尚无公认结论。
  • 可变形采样在极小目标上的退化。 当目标只有 2–3 个格子时，K=4 个采样点已经覆盖了目标的大部分，继续增大 K 没有收益；而学到的偏移量的方差可能超过目标本身的尺寸，使采样退化为噪声。「采样点数与目标尺寸的匹配」目前靠调参，缺少自适应机制。
  • 上下文的可控注入。 如何在利用上下文的同时防止模型学成「位置捷径」，目前只有经验做法（限制上下文范围、加位置扰动增强）。一个有价值的方向是显式建模「目标证据」与「上下文证据」的分离，并在推理时能报告两者各贡献了多少——这对可解释性与安全论证都有意义。
  • 与事件相机 / 多曝光的结合。 小目标的根本瓶颈是信息量，而传统 RGB 相机在远距离 + 高动态范围场景下的信息采集本身就是受限的。事件相机的高时间分辨率、多曝光 HDR 的高动态范围，都是「在传感器端增加信息」的路线。这一路线绕过了所有架构技巧，直接从源头解决问题，但成本与成熟度仍是障碍。
  • 神经架构搜索的回归。 NAS-FPN 之后这条路一度沉寂（不可解释、迁移性差）。但在「给定车端芯片的算子支持与延迟模型，搜索最优金字塔拓扑」这个受约束的设定下，它重新变得实用——因为约束足够强，搜索空间小到可以穷举，结果也可解释。

必读：Feature Pyramid Networks for Object Detection（Lin et al., CVPR 2017，层级分配公式的出处，第 4.2 节）；Path Aggregation Network for Instance Segmentation（Liu et al., CVPR 2018，PAN 的自底向上路径与「路径长度」论证）；EfficientDet: Scalable and Efficient Object Detection（Tan et al., CVPR 2020，BiFPN 与 fast normalized fusion，第 3.2 节）；Deformable DETR: Deformable Transformers for End-to-End Object Detection（Zhu et al., ICLR 2021，多尺度可变形注意力，注意附录里的偏移初始化细节）；Deep High-Resolution Representation Learning（Wang et al., TPAMI 2020，HRNet）。小目标专题综述：Towards Large-Scale Small Object Detection: Survey and Benchmarks（Cheng et al., TPAMI 2023）。相邻课程：C53 m03（RTMDet 的大核与共享头）、C54 m04（可变形注意力的收敛分析）、C57 m03（分配与损失）、C57 m04（切片推理）。完整清单见 references.md。
