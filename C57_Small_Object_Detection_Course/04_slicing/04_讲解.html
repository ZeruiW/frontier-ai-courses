1切片为什么有效：它不是超分，是「不丢信息」

模块 01 已经把账算清楚了：一个 60 米外的 60cm 限速牌，在 1920×1080 / 60° FOV 的前视主摄上只有 16.6 像素。而绝大多数检测器的训练输入是 640×640——把 1920 宽的图 letterbox 到 640 宽，缩放比是 1/3，那个 16.6 px 的标志进入网络时只剩 5.5 px。

5.5 px 意味着什么？在 stride 8 的 P3 特征图上，它占 0.69 个格子；在 stride 16 的 P4 上占 0.35 个。没有任何一个特征点的感受野中心落在它身上，标签分配阶段它连一个正样本都拿不到。这不是「模型学得不够好」，这是信息在预处理阶段就被扔掉了。

\[p_{\text{input}} \;=\; p_{\text{native}} \cdot \frac{L_{\text{input}}}{L_{\text{crop}}} \qquad\Longrightarrow\qquad \text{全图: } 16.6\cdot\frac{640}{1920}=5.5\;\text{px}, \quad \text{切片: } 16.6\cdot\frac{640}{640}=16.6\;\text{px}\]

Slicing inference（切片推理，代表实现是 SAHI：Slicing Aided Hyper Inference）的全部机理就在这个公式里：把裁剪窗口 Lcrop 从 1920 缩到 640，目标在网络输入里的线性尺寸就放大 3 倍、面积放大 9 倍。

直白说

很多人第一次听会以为切片是某种「超分辨率」——不是。切片没有创造任何新信息，它只是拒绝丢弃已有信息。原图里那 16.6×16.6 ≈ 276 个像素一直都在，只是被 resize 抽成了 30 个。切片做的事情是：别 resize，直接把原生像素喂进网络。所以切片的收益上限，就是「原图里本来有多少信息」——原图里就只有 4 px 的目标，切多少片都救不回来。

严谨说

严谨地说，下采样是一个低通滤波 + 重采样过程。标志的判别性特征（数字笔画、图案边缘）位于高频段，1/3 下采样会把高于 Nyquist 频率的分量直接混叠掉，而且混叠是不可逆的。更致命的是第二重损失：检测头的输出是离散网格，目标尺寸小于 stride 时，它在特征图上连一个完整格子都占不满，此时无论用什么标签分配策略（ATSS / SimOTA / TaskAligned），可用的正样本候选都趋于零。切片同时缓解了这两重损失——但它只对「原生分辨率里信息充足、被 resize 毁掉」的目标有效，对原生分辨率里就已经模糊的目标无效。

一句话心法：切片推理的收益 = 你在预处理阶段丢掉的信息量。所以判断「切片值不值得做」的第一个动作不是跑实验，而是算一算你的目标在网络输入里还剩几个像素。如果全图 resize 后目标还有 40 px，切片几乎没有收益；如果只剩 5 px，切片可能带来两位数的 APsmall 提升。面试时被问「怎么提升小目标」，先给出这个判据再给方案，比直接背方法名高一个层次。

切片的第一个代价常被忽略：它破坏上下文。交通标志的识别高度依赖周边线索——杆件、龙门架、路侧护栏、它在图像中的垂直位置（模块 05 会推导「标志只出现在地平线附近的窄带里」）。把 1920×1080 切成 640×640 之后，一个只看到 640×640 局部的检测器丢掉了「这块区域在整幅图的哪里」这个强先验。实践中的表现是：切片提升了远处小标志的召回，同时抬高了近处大目标与广告牌的误检。这就是为什么真实系统几乎总是「切片结果 + 全图结果」一起融合，而不是只用切片。

2切片网格：尺寸 s、步长与重叠率 r 的几何

切片推理的参数只有两个半：切片边长 s、重叠率 r，以及一个工程上的第三个——是否额外跑一遍全图。先把网格的几何写清楚。

给定图像宽 W、切片边长 s、重叠率 r，步长（stride，相邻切片原点的间距）为

\[\text{stride} \;=\; s\,(1-r), \qquad \text{overlap}_{\text{px}} \;=\; s - \text{stride} \;=\; s\cdot r\]

切片原点取 0, stride, 2·stride, …，直到再往前会越界；最后一片贴右边界（原点取 W-s），保证覆盖完整。这是 SAHI 的标准做法，代价是最后一片与前一片的重叠可能远大于 r。

W = 1920, s = 640, r = 0.10 -> stride = 576 0 576 1152 1280 1920 |---------|--------|-------| | [===== slice 0 =====] x∈[0,640] [===== slice 1 =====] x∈[576,1216] [===== slice 2 =====] x∈[1152,1792] [===== slice 3 =====] x∈[1280,1920] ← 贴边，重叠更大 ↑ 每相邻两片共享 s·r = 64 px 的重叠带 ────────────────┘ 一个宽 d = 64 px 的目标，落在哪里都至少被某一片**完整**包住？ -> 见下一节：当且仅当 s·r >= d

直白说

表里有个反直觉的现象：r 从 0.10 涨到 0.30，片数完全没变。原因是切片数是向上取整出来的——1920 宽在 stride 576 与 stride 448 下都恰好需要 4 片（3 片不够、4 片有余）。所以在离散化允许的范围内，把 r 从 0.10 调到 0.30 是「免费」的：一分钱不多花，抗截断能力却翻了三倍。不算这笔账就按默认 0.2 一把梭，等于白扔了一半的鲁棒性。

严谨说

严谨地说，横向片数为 n = ⌈(W-s)/stride⌉ + 1，它是 r 的阶梯函数而非连续函数。正确的调参姿势是：先由「最大目标尺寸」定出 r 的下界（下一节），再在不增加片数的前提下把 r 尽量往上推。数学上就是求满足 ⌈(W-s)/(s(1-r))⌉ = n 的最大 r。工程上更简单：写个循环把 r 从下界扫到 0.5，打印片数，选片数跳变前的那个 r。这个「阶梯函数上找免费午餐」的模式在 batch size、padding 对齐、tile 划分里反复出现。

切片边长 s 的选择还有一个硬约束容易被忽略：s 应当等于（或接近）检测器训练时的输入尺寸。如果模型是在 640×640 上训练的，你切 1024×1024 再 resize 到 640，就等于把放大倍数从 3× 降到 1.875×，白切了；你切 320×320 再 pad 到 640，模型看到的是一张 1/4 面积有内容、3/4 是灰边的图，与训练分布严重不符。切片边长 = 训练输入尺寸，是默认起点。

3重叠率的下界：一个必须会推的不等式

这是本模块最值得记住、面试也最容易问到的一个推导。问题：重叠率 r 至少要多大，才能保证「图像里任意位置的、尺寸不超过 d 的目标，一定被某一片完整包含」？

一维推导

只看横轴。切片原点为 oi = i·stride，第 i 片覆盖 [oi, oi+s]。一个目标占 [x, x+d]。目标被第 i 片完整包含的条件是

\[o_i \le x \quad\text{且}\quad x+d \le o_i + s \qquad\Longleftrightarrow\qquad x + d - s \;\le\; o_i \;\le\; x\]

也就是说，合法的原点 oi 必须落在一个长度为 s − d 的区间 [x+d−s, x] 里。而原点是以 stride 为间隔的等差数列——一个等差数列必然与任意长度为 L 的闭区间相交，当且仅当公差 ≤ L。于是

\[\text{stride} \;\le\; s - d \qquad\Longleftrightarrow\qquad s\,(1-r) \le s - d \qquad\Longleftrightarrow\qquad \boxed{\;\underbrace{s\cdot r}_{\text{重叠像素}} \;\ge\; d\;}\]

结论极其干净：重叠的像素数必须不小于最大目标的像素尺寸，等价地

\[r \;\ge\; \frac{d_{\max}}{s}\]

直白说

用一句话讲透：重叠带就是「接住跨界目标的安全网」，网的宽度必须大于目标本身，否则总有一个位置能让目标同时被两片各切走一半、两边都不完整。下界是紧的——只要 s·r 比 d 小 1 个像素，就存在一批位置（宽度恰好等于 d − s·r）让目标必然被截断。二维情况下横竖都要满足，两个方向独立成立。

严谨说

严谨地补三个边界条件。① d > s 时无解：r ≥ d/s > 1，几何上不可能——目标比切片还大，只能靠全图那一路兜底。② 这是「完整包含」的下界，不是「能检出」的下界：多数检测器对被截掉 10–20% 的目标仍能给出一个（偏小的）框，所以实践中 r 略小于下界不会立刻归零，但会系统性地压低边界区域的召回并抬高定位误差。③ dmax 指的是「你希望切片这条路负责的最大目标」，不是图里最大的目标。TSR 里近处 2 米远的标志有 500 px，按它算 r 会大于 1；正确做法是让切片只负责小目标（d ≤ 64 px），大目标交给全图那一路，然后 r ≥ 64/640 = 0.10。

一个真实会在评测里翻车的错误：用「平均目标尺寸」而不是「最大目标尺寸」去定 r。假设标志平均 20 px、最大 64 px，按平均值算 r ≥ 0.031，取 0.05；结果是所有 20 px 左右的标志都没问题，而恰恰是那些近一点、更重要、更该检出的 40–64 px 标志，在切片边界上被系统性截断。更阴险的是：这类漏检与位置强相关（只发生在几条固定的竖线附近），随机划分的验证集上被平均掉，看不出来；上路后表现为「某些路段总是漏牌」。定 r 用的是 d 的上分位数（p99），不是均值。

4跨片合并：坐标还原、NMS 与 NMM

切片推理的后处理有三步，每一步都有坑。

① 坐标还原

检测器在第 i 片上输出的是切片局部坐标，还原到全图只需平移：

x_global = x_local + slice_x0
y_global = y_local + slice_y0
# 注意：如果切片本身还被 letterbox 到网络输入尺寸，必须先做 letterbox 逆变换，
# 再加切片原点。两次变换的顺序写反 = 框整体偏移（车端最常见的"框错位"根因之一）

这一步最容易出的错不是公式，而是顺序。切片 → letterbox → 网络 → 反 letterbox → 加原点，四步必须严格逆序回来。C60 模块 04 会专门讲这个逆变换。

② 同一目标被多片检出

重叠带里的目标会被两片（角落上是四片）各检出一次。还原后就是若干个几乎重合的框——这是标准 NMS 能处理的情形，因为它们 IoU 很高。

③ 跨边界目标被截断——NMS 处理不了的情形

真正的难点在这里。当 r 小于下界，或目标恰好比 dmax 大时，一个目标会被两片各看到一部分，产生两个「半截框」。它们之间的 IoU 很低，NMS 认为它们是两个不同目标，于是输出两个错框而不是一个对框。

真值框: [590, 654] (d = 64 px) 切片 0: [0,640] 切片 1: [608,1248] 590 640 654 |----------|------| [######### 真值 ###] [## 片0 只看到 50px #] -> 碎片 A = [590, 640] [## 片1 只看到 46px ##] -> 碎片 B = [608, 654] IoU(A,B) = 2048 / 4096 = 0.50 <- NMS(thr=0.6) 判定为「两个不同目标」❌ IoS(A,B) = 2048 / 2944 = 0.70 <- 交集 / **较小框面积** union(A,B) = [590, 654] <- 与真值**完全一致** ✅ NMS : 抑制得分低的 -> 剩 1 个**半截**框（定位错）或 2 个框（重复） NMM : 把 IoS 高的**合并成并集** -> 恢复完整框

解法是把 NMS（Non-Maximum Suppression，非极大值抑制）换成/补上 NMM（Non-Maximum Merging，非极大值合并），并且把判据从 IoU 换成 IoS（Intersection over Smaller area，交集除以较小框的面积）：

\[\mathrm{IoU}(A,B)=\frac{|A\cap B|}{|A\cup B|}, \qquad \mathrm{IoS}(A,B)=\frac{|A\cap B|}{\min(|A|,|B|)}\]

直白说

为什么必须换成 IoS？因为「一个碎片是另一个框的一部分」这件事，IoU 天生看不见。一个 30 px 的碎片完全落在一个 64 px 的框里时，IoU 只有 (30/64)²≈0.22，而 IoS = 1.0。IoU 度量的是「两个框有多像」，IoS 度量的是「小的那个有多大比例被大的包住」——跨片截断场景要问的恰恰是后者。

严谨说

NMM 的完整算法：按分数降序取种子框，把与它 IoS ≥ τ 的所有框并入（取包围盒的并集、分数取最大值、类别取分数最高者），标记为已消费，继续下一个种子。与 NMS 的唯一区别是「抑制」变成了「吸收」。实践中的标准配方是两级：先在同类别内做 IoS-NMM 把碎片缝合，再做一次常规 IoU-NMS 去掉真正的重复。SAHI 的默认参数是 NMM IoS 阈值 0.5 与 NMS IoU 阈值 0.5。另一个必须做的工程细节是「贴边标记」：记录每个框是否触到所在切片的边界（距边 ≤ 2 px），只对贴边的框启用 NMM——否则两个真实靠得很近的标志（比如上下叠放的限速牌+辅助牌）会被错误地并成一个大框。

还有一个必须显式处理的类：贴边但对侧无碎片的框。目标被切片边界削掉一半、而另一片因为可见比例太低根本没检出，此时你手上只有一个「半截框」。它的分数通常仍然不低（模型看到半个红圈也会给 0.6），但框是错的，尺寸小了一半。下游如果按框的像素尺寸估距离（TSR 常这么做），半截框会让距离估计翻倍出错。处理方式有两种：① 直接丢弃贴边且无法配对的框（牺牲召回换定位可靠性）；② 保留但打上 truncated=True 标记，让跟踪与距离估计模块降权。量产系统里几乎都选 ②——因为丢掉的往往正是最远、最需要早发现的那个。

把这一节压成一句可迁移的话：NMS 的世界观是「重复的检测应该被删掉」，而跨片场景的世界观是「不完整的检测应该被拼起来」。凡是「同一个物理实体被切成多份分别观测」的场景——切片推理、多相机重叠视场、时序多帧、点云分块——你需要的都是合并算子而不是抑制算子，判据都是「包含关系」而不是「相似关系」。

5代价账：切片数、像素吞吐与车端的现实

讲完收益必须讲代价，否则就是推销而不是工程。切片推理的代价是把一次前向变成 N 次前向，而 N 的量级由一个简单的估计给出：

\[N \;\approx\; \left\lceil\frac{W-s}{s(1-r)}\right\rceil\!+\!1 \;\times\; \left\lceil\frac{H-s}{s(1-r)}\right\rceil\!+\!1 \;\;\xrightarrow[\;W,H\gg s\;]{}\;\; \frac{W\cdot H}{s^{2}(1-r)^{2}}\]

把 N 乘回每片的像素数 s²，得到一个非常有用的不变量：

\[\text{总像素吞吐} \;=\; N\cdot s^{2} \;\approx\; \frac{W\cdot H}{(1-r)^{2}}\]

直白说

这个式子说了一件反直觉的事：在大图渐近意义下，总计算量几乎与切片大小 s 无关，只由重叠率 r 决定。切成 64 个小片和切成 16 个大片，处理的总像素数是一样的（都是原图像素 × 1/(1−r)²）。s 决定的不是成本，而是放大倍数 W/s。所以调参的正确顺序是：先按「目标要被放大到多少像素」定 s，再按重叠下界 d/s 定 r，成本自动落定。

严谨说

严谨地补两点。① 这是渐近结论，对 1920×1080 这种「s 与 H 同量级」的情形不成立——H=1080 而 s=640 时，纵向只能放下 2 片，贴边冗余把实际吞吐推高到渐近值的 1.07–1.3 倍。notebook 里会在 4096×3072 上验证渐近公式（误差 <7%），在 1920×1080 上用精确计数。② 像素吞吐不等于延迟：N 次小前向比 1 次大前向多付 N−1 次 kernel launch、内存分配、后处理与 H2D 拷贝的固定开销；在车端 SoC 上这部分固定开销占比可能到 20–40%。所以真实的延迟倍数通常比像素倍数还差。

把数字落到 TSR 的真实场景。设检测器在 640×640 上的推理耗时 5.0 ms（Orin 级 SoC、FP16、一个 tiny/small 量级的模型），耗时按像素线性外推：

面试高频：切片能上车吗

「切片推理在车端量产系统里基本不可用」——这句话你要能说出来，并且能用上面这张表把它论证清楚。这是面试里区分「读过论文」与「做过工程」的分水岭：SAHI 在 VisDrone / xView 这类离线、单帧、无延迟约束的高分辨率基准上是标准操作，APsmall 提升可以到两位数；但它的代价结构（4–16× 计算、且随分辨率平方增长）与车端的实时约束结构性冲突。只说「SAHI 能提升小目标」而不给代价，会被追问到崩；主动给出代价再给替代方案，才是完整答案。

但也别把话说死。切片在车端有两个仍然成立的用法：① 离线数据挖掘与自动标注——用切片跑一个「慢但准」的教师模型给车队回传数据打伪标签，再蒸馏给车端小模型（C58 会讲）；② 低频触发——不是每帧都切，而是在「地图提示前方有标志」或「上一帧有低分候选」时，对某一个 ROI 做一次高分辨率精检。后者其实已经滑向了下一节的两级级联。

6两级级联：量产系统的现实选择

既然「全图高分辨率」太贵、「全图低分辨率」看不见，出路就只剩一条：只在可能有目标的地方付高分辨率的钱。这就是two-stage cascade（两级级联）。

┌── Level 1：便宜、高召回、可以很不准 ────────────────────────┐ │ 输入：1920×1080 下采样到 640×384（或只跑 ROI 带） │ │ 任务：**类别无关**的「这里可能有个标志」提议 │ │ 阈值：**故意调得很低**（score > 0.05），宁可多提议 │ │ 输出：K 个 ROI（典型 K = 2–6），耗时 ~0.5–3 ms │ └───────────────────┬────────────────────────────────────────┘ │ ROI 坐标映射回**原始分辨率** ▼ ┌── Level 2：贵、精确、只跑 K 次小图 ─────────────────────────┐ │ 输入：从**原生 1920×1080** 上裁 K 个 256×256 patch │ │ 任务：精检 + 细分类（限速 40/50/60/…） │ │ 阈值：正常（score > 0.4），这里才决定最终输出 │ │ 耗时：K × 0.8 ms │ └────────────────────────────────────────────────────────────┘ 关键：ROI 裁剪用的是**原图像素**，不是 Level 1 的下采样图 —— 所以 Level 2 看到的标志仍然是 16.6 px 而不是 5.5 px。

级联的收益结构与切片完全不同：切片是「无差别地把整图放大 3 倍」，级联是「只把 K 个小窗口放大 3 倍」。当目标稀疏（一帧里通常只有 0–3 个标志）时，后者的浪费小得多。

级联的代价：召回是乘法

\[R_{\text{cascade}} \;=\; R_{\text{level1}} \times R_{\text{level2}} \;\le\; \min(R_1, R_2)\]

直白说

这个乘法是级联系统的阿喀琉斯之踵，也是必考点：Level 1 漏掉的目标，Level 2 永远没有机会看到。所以级联设计的第一原则是——Level 1 的工作点必须极度偏向召回，精度完全不重要。做法是：类别无关（只判「是不是一个牌子状的东西」，任务比多类分类简单得多）、score 阈值压到 0.05、输出 top-K 而不是阈值过滤、必要时把 Level 1 的正样本分配放宽（模块 03 的 NWD / center-based 分配在这里正合适）。Level 1 多提 3 个假 ROI 的代价只是 2.4 ms，漏掉 1 个真标志的代价是漏检。

严谨说

严谨地说，级联的单帧召回确实低于切片（notebook 里的模拟：切片 0.91、级联 0.52–0.76、全图下采样 0.04）。但单帧召回不是 TSR 的正确指标——标志是静止的、自车在接近它，同一个标志会在连续几十帧里反复出现。若把每帧的检出近似为独立事件，N 帧内至少检出一次的概率是 1−(1−R)N：级联 R=0.76 时 5 帧后是 99.9%，切片 R=0.91 时是 99.999%——两者在「首次检出距离」上的差距被时序累积几乎抹平，而 8× 的延迟差距是抹不平的。C55 模块 04 会把这个时序累积讲透。注意独立性假设是乐观的：遮挡、逆光、运动模糊会让相邻帧的失败强相关，实际需要更多帧。

方案16.6 px 标志进入网络时的尺寸单帧召回（模拟）5 帧累积召回延迟车端可行
全图下采样 640×3845.5 px0.040.183.0 ms✅ 但基本检不出

级联有一个隐蔽的失败模式：Level 1 与 Level 2 的训练分布不一致。Level 2 只在「Level 1 提议的窗口」上推理，而这些窗口是以目标为中心、带一定 padding 的裁剪——如果 Level 2 是在整图上训练的，它见过的目标位置分布是均匀的，而线上见到的目标几乎总在窗口正中央。模型会学到「中心先验」并在 ROI 边缘的目标上失效（而 ROI 边缘恰恰是 Level 1 定位不准时目标所在的位置）。解法是用 Level 1 的真实提议（含定位误差）去生成 Level 2 的训练裁剪，而不是用 GT 框裁——这叫「按推理时的分布训练」，是所有级联系统的通用纪律。

级联的第三个好处常被忽略：它天然把「检测」和「细分类」解耦。Level 1 只需要知道「有个牌子」，Level 2 在高分辨率 crop 上做 100+ 类的细分类。这正是 C55 模块 02 讲的 TSR 两级方案——新增一个限速档位只要重训 Level 2，检测器完全不动。所以在 TSR 里，两级级联同时解决了小目标问题和长尾类别问题，这是它比切片更受量产系统青睐的深层原因。

7先验驱动的 ROI：地图、车道与消失点

上一节的 Level 1 还是要跑一遍全图。能不能连全图都不跑？能——只要你有先验知道标志会出现在哪。这是把延迟继续往下压的最后一招，也是把召回往上抬的最有效一招。

直白说

这些先验的正确用法不是「圈出来只看这里」，而是「在这里多花算力」。两种用法差别巨大：前者是 hard gating，先验错一次就是一次彻底漏检；后者是 算力的非均匀分配——ROI 内用原生分辨率精检，ROI 外仍然跑一遍便宜的全图下采样兜底。后者的最坏情况退化成「只有全图下采样」，而不是「什么都没有」。

严谨说

严谨地说，这是一个foveated inference（中心凹式推理）架构：模仿人眼「周边视觉低分辨率 + 中央凹高分辨率」的资源分配。设 ROI 面积占比 α、ROI 内分辨率倍数 β，总像素吞吐 ≈ (1−α)·1 + α·β²（相对全图下采样）。TSR 的关键数字：模块 05 会算出远距标志所在的地平线带只占全图约 7% 的面积，取 β=3（原生分辨率），吞吐 = 0.93 + 0.07×9 = 1.56×——用 1.56 倍的算力买到了远距目标 3 倍的有效分辨率，而全图原生分辨率要 9 倍。这就是 ROI 先验的全部价值。

ROI 先验必须是软的

把先验做成 hard gating 是一个会出安全事故的设计。真实案例形态：ROI 按平路标定的地平线固定在图像 42% 高度处，车辆上坡时相机俯仰变化，标志跑到 ROI 之外，整段坡道上的限速牌全部漏检——而且这类失效与地点强相关、可复现、集中爆发，恰恰是最糟糕的失效形态（不是随机漏一两个，而是某段路必然全漏）。纪律：任何基于先验的 ROI 都必须 ① 带足够的余量（俯仰 ±3° 换算成像素的余量）、② 用实时估计的俯仰角/地平线而不是标定常数、③ 保留一路无先验的全图兜底。

动态分辨率是同一思想的另一种实现：不裁剪，而是让整张图的采样密度非均匀——远处（图像上部靠近地平线）用高采样率，近处（图像下部）用低采样率。工程上可以用一次可微的重采样（类似 Learning to Zoom / FOVEA 的思路）实现。好处是仍然只有一次前向、张量形状固定，对 TensorRT 友好；代价是几何畸变要在后处理里精确反解，且与增强/标定的耦合更强。

把先验驱动 ROI 与前两节合起来看，会发现一条清晰的演进线：「全图均匀高分辨率」（太贵）→「全图均匀低分辨率」（看不见）→「切片：均匀高分辨率但分次做」（还是太贵）→「级联/ROI：非均匀分辨率」（可行）。每一步都在做同一件事——把算力从「哪里都花」变成「花在该花的地方」。这条线在 LLM 推理（KV cache 稀疏化）、视频编码（ROI 码率分配）、雷达波束调度里长得一模一样。

8切片训练：SAHI 的另一半，也是最常被漏掉的一半

绝大多数人用 SAHI 只用了推理那一半（SAHI = Slicing Aided Hyper Inference），而论文里还有另一半：slicing aided fine-tuning（切片辅助微调，SF）。不做 SF 而只做切片推理，收益会显著低于预期，甚至可能掉点。

为什么必须重新微调

原因是训练与推理的目标尺度分布不一致。假设你的模型是在「1920×1080 整图 letterbox 到 640」上训练的，那么它见过的标志尺寸分布是 5.5 px 附近；而切片推理时它见到的是 16.6 px 附近。这是一个 3 倍的尺度漂移。

训练时（整图 letterbox 640）推理时（切片 640 原生）后果
标志的输入像素5.5 px（60 m 外）16.6 px尺度分布整体右移 3×
被分配到的 FPN 层P2/P3（最浅）P3/P4负责该尺度的分支权重没被充分训练
anchor / 回归目标范围集中在最小几档中档回归头输出分布偏移
背景上下文比例整幅街景局部 640 窗口上下文先验失效，误检上升
近处大标志常见（几百 px）被切成碎片或超出切片大目标 AP 下降

直白说

SF 的做法非常朴素：训练集也切片——把训练图按与推理相同的 (s, r) 切成小图、同步变换标注、丢掉可见比例过低的框，然后把切片小图与原始整图按一定比例混合训练。混合是关键：只用切片训练会毁掉大目标；SAHI 论文的做法是切片图 + 全图一起喂。一句话：让训练分布长得像推理分布。

严谨说

严谨地说，SF 修正的是四件事里的三件（尺度分布、FPN 层负载、回归目标范围），第四件（上下文缺失）是切片这个方法本身的固有损失，SF 修不了。这也解释了一个常见观察：SF 之后小目标 AP 大涨，但某些强依赖上下文的类别（悬挂在龙门架上的指路牌、需要靠杆件确认的方向牌）反而略降。另外，切片训练的标注处理有个必须定死的规则：一个被切片边界截断的 GT 框，可见比例低于阈值 τ（典型 0.3–0.5）就丢弃，高于阈值就裁剪到切片内作为新 GT。τ 太低会引入大量「半个标志」的噪声标签，τ 太高会造成「图里明明有东西却标成背景」的负监督污染——C56 模块 01 讲的越界处理规则在这里完全适用。

同样的「训练-推理分布一致」纪律也适用于两级级联：Level 2 必须用「Level 1 真实提议裁出来的 crop」训练，而不是用 GT 框裁出来的 crop。前者带着 Level 1 的定位噪声与假阳性，后者是理想化的。用后者训练、用前者推理，是级联系统掉点的头号原因。这与预处理一致性（C60 模块 01）是同一类问题的不同层次：凡是推理时的输入由另一个模块产生，训练时就必须用那个模块的真实输出，而不是真值。

所以本模块的三条路径各自需要什么，可以列成一张对照：切片推理需要切片微调；两级级联需要用真实提议训练 Level 2；ROI 裁剪需要把 ROI 内的分布也放进训练集。三者的共同结构是「推理时输入被某种裁剪/缩放变换过，训练时就必须复现那个变换」——记住这个结构，比记住三个方法名有用得多。

9研究前沿与开放问题

  • 可学习的 ROI 提议与端到端 foveation：目前的 ROI 先验（消失点、地图、跟踪外推）都是手工规则。让网络自己学「该往哪看」——如 Learning to Zoom、FOVEA、Efficient Adaptive Resolution 这一系——在离线基准上已能匹敌固定高分辨率且省 2–4× 算力，但可学习的注意力区域在安全关键系统里难以验证（它可能学到与训练集地理位置强相关的捷径），这是上车的主要障碍。
  • 切片与端到端检测器的融合：DETR 系（C54）的 query 本身就是稀疏的，理论上可以让不同 query 在不同分辨率的特征上采样（Deformable DETR 的多尺度可变形注意力已经部分做到）。「让一部分 query 去原生分辨率上采样，其余 query 用低分辨率」——这是把级联思想内化进单个模型的路线，目前的难点是采样位置的学习信号在小目标上仍然稀疏。
  • 跨片合并的可学习化：NMM 的 IoS 阈值、贴边判定余量、碎片是否可信，目前全是手工阈值。把「这两个碎片是不是同一个物理目标」建模成一个轻量的关系判别（类似多目标跟踪里的关联网络）是自然的方向，但训练数据需要「被切片截断」的成对标注，构造成本高。
  • 硬件侧的非均匀采样：event camera、可变焦/可变分辨率 sensor、以及 ISP 侧的 ROI 直出，能把「非均匀分辨率」从算法层下沉到传感器层，从根上消除下采样损失。量产可行性与标定复杂度是当前瓶颈。
  • 评测方法学的空白：几乎所有小目标基准报告的都是整图 APsmall，没有一个公开基准报告「切片边界附近的召回」这一项——而这正是重叠率下界所刻画的失效模式。模块 05 会给出按像素尺寸分桶的评测实现，但「按位置分桶」（边界 vs 中心）同样必要且几乎无人做。
  • 切片推理的能耗账：车端真正的约束往往不是峰值算力而是热与功耗。8× 的持续计算会触发降频（C60 模块 05），使延迟在长时间行驶后漂移——这类「跑得久了变慢」的效应在离线基准上完全不可见，也是学术方法与量产之间少有人量化的鸿沟。

必读：Akyon et al., Slicing Aided Hyper Inference and Fine-tuning for Small Object Detection (ICIP 2022)——SAHI 原论文，务必读它的 fine-tuning 一节而不只是 inference；Unel et al., The Power of Tiling for Small Object Detection (CVPRW 2019)——最早系统性论证切片有效性的工作，重叠率的经验取值来自这里；Recasens et al., Learning to Zoom (ECCV 2018) 与 Thavamani et al., FOVEA: Foveated Image Magnification for Autonomous Navigation (ICCV 2021)——可学习非均匀采样的两篇代表作，FOVEA 直接以自动驾驶为背景，是本模块「动态分辨率」一节的一手来源；Zhu et al., Deformable DETR (ICLR 2021)——稀疏采样的另一条路线；VisDrone / xView / TT100K 三个基准的官方报告，用来对照「离线基准上切片能涨多少」的真实数量级。相邻课程：C53 m05（端到端延迟拆解）、C55 m04（时序累积如何抹平单帧召回差距）、C56 m01（裁剪与越界规则）、C60 m01/m05（预处理一致性与降频）。完整清单见 references.md。
