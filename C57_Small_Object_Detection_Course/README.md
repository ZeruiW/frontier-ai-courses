# 小目标检测 · Small Object Detection

这门课处理的是目标检测里最顽固的一个横切问题：**当目标只有十几个像素时，
整条流水线的每一个假设都开始失效。**

它不是某个模型的问题。COCO 上 AP_L 能做到 60+ 的检测器，AP_S 往往还在 20 出头——
这个差距在过去八年里没有被任何单一架构改进抹平，因为它不是一个问题，**是五个互相独立的问题叠在一起**：

1. **信息量少** —— 8×8 个像素里能编码的判别信息本来就少；
2. **IoU 对位移极度敏感** —— 8×8 的框对角位移 2 px，IoU 就从 1.00 掉到 **0.39**（同样位移下 64×64 的框还有 0.88）；
3. **正样本稀缺** —— 上一条直接导致按 IoU 阈值分配时，小目标可能一个正样本都匹配不到，
   这意味着它**根本没有梯度**，不是「学不好」而是「没学过」；
4. **下采样抹掉** —— stride 32 的特征图上，8 像素的目标只占 0.25 个格子，低于采样率的细节是被**混叠**掉的；
5. **标注噪声的相对量级大** —— 人工标注 ±2 px，对 8 px 的框是 25% 的相对误差，**标签本身就带噪**。

**这五个原因各自有各自的解法。** 混在一起当成一个问题去治，就会出现
「照着论文加了一堆 trick，总 mAP 涨了 0.2，AP_S 纹丝不动」的经典局面。
所以本课的组织方式是：**先分别量化，再分层给解法，最后合成方案。**

## 🎯 为什么这门课对 TSR 岗位是核心

**交通标志识别本质上就是小目标检测问题。** 这句话不是修辞，是可以用针孔模型算出来的：

```
px = f · S / Z          f = (W / 2) / tan(FOV_h / 2)

1920 宽、60° 水平 FOV 的前视相机：f ≈ 1663 px
一块 60 cm 的限速牌：
    30 m 处 → 33 px
    60 m 处 → 17 px          ← 已经在 COCO 的 small 桶深处
   100 m 处 → 10 px          ← 接近可标注、可检测的物理下界
```

而「**要在多远看见限速牌**」不是感知可以讨价还价的——它由制动距离与规控响应时间
倒推出来，是**整车安全需求**。于是小目标检测同时卡住了：相机选型（FOV / 焦距 / 多相机分工）、
输入分辨率、backbone 的 stride、金字塔要不要加 P2、标签分配策略、损失函数、
以及部署侧的算力预算。**几乎每一个设计决策，最后都要回到「最小的那块牌还剩几个像素」这个问题上。**

这也是为什么它是这个岗位**最核心、也最难绕过去的技术难点之一**：
面试里问「你会怎么提升远距离标志的召回」，考的从来不是你知不知道 SAHI，
而是你能不能从物理量出发，把这个问题拆成可算的几段，并说清每一段的代价。

| 阶段 | 模块 | 预计时长 | 你会带走什么 |

## 三条贯穿全课的纪律

1. **先分因，再下药。** 五个难因对应五类解法：信息量少 → 提分辨率/引上下文；
   IoU 敏感 → 换度量（NWD）；正样本稀缺 → 改分配；下采样丢失 → 加高分辨率层/降 stride；
   标注噪声 → 改标注协议与损失鲁棒性。**动手前先说清你在治哪一条。**
2. **一切都要算出来，不要试出来。** 切片数、P2 的显存与 FLOPs 增量、
   重叠率的下界、检出距离对应的像素数、级联的召回乘积——本课涉及的每一个工程决策都有闭式解或简单算术，
   *用一次昂贵的训练去换一个「行/不行」的比特，是最贵的做法*。
3. **不分桶的指标等于没有指标。** 小目标的改进在总 mAP 上几乎不可见（权重太小），
   必须按像素尺寸分桶（<8 / 8–16 / 16–32 / 32–64 / >64）报告；
   而且每次都要同时看 AP_L 有没有掉——**很多小目标方法是以牺牲大目标为代价的**。

## 与相邻课程的关系

这门课是「小目标」这一个横切问题的**纵深**，它假设你已经有检测的基本盘，
并且会大量复用其它课的机制。

| 课 | 它讲什么 | 与本课的分工 |
|---|---|---|
| **C18 · Computer Vision** | 检测的基本盘：anchor、IoU、NMS、mAP、FPN 初见、两阶段与单阶段 | **前置课**。本课默认你知道 anchor 是什么、mAP 怎么算。C18 讲「检测怎么工作」，本课只问「目标很小时它为什么不工作」 |
| **C53 · 实时检测器架构** | YOLO 演进 / RTMDet / RT-DETR，以及标签分配的**总论**（ATSS / SimOTA / TaskAligned） | **姊妹课**。C53 从「延迟-精度」的角度讲分配，本课从「尺度公平性」的角度重讲同一批方法——**同一个 ATSS，在 C53 是「省调参」，在这里是「天然缓解尺度不公平」** |
| **C54 · DETR 与集合预测** | 匈牙利匹配、集合损失、object query、Deformable DETR | **互补课**。C54 的 m05 提到「DETR 对小目标弱」，本课给出它的完整根因（单尺度特征 + query 数固定 + 一对一匹配对小框的匹配代价极不稳定），并解释多尺度可变形注意力为什么是解药 |
| **C55 · TSR 与自动驾驶感知** | TSR 的领域知识：数据集、标志分类学、两级 vs 端到端、失效模式、时序融合、安全评测 | **上位课**。C55 的失效模式全景里「远距离小目标」是第一条，**本课就是那一条的完整展开**。C55 讲「TSR 会在哪些地方出错」，本课讲「其中最大的那一类错怎么修」 |
| **C56 · 检测数据增强工程** | 几何/光度增强、Mosaic、MixUp、**Copy-Paste**、增强流水线与消融 | **数据侧的对偶**。本课讲模型与推理侧的解法，C56 讲数据侧的：Mosaic 变相制造更多小目标、copy-paste 补稀有小目标、随机裁剪的丢弃阈值对小目标是致命的。**两门课的方案要合起来才完整** |

再往后：**C58**（难例挖掘与长尾闭环）负责把「哪些小目标场景还没修好」变成可回传的数据；
**C60**（车端部署与一致性）负责把本课算出来的分辨率/stride/P2 决策真正塞进算力预算；
**C61**（实战与面试）会把本课的主线整理成可讲 10 分钟的项目叙事。

## 环境

见 `requirements.txt`。**纯 numpy + 标准库、CPU 可跑，不需要 GPU，也不需要装 torch / mmdetection / ultralytics。**
本课复现的是这些方法的**数学与账本**——IoU 的几何、Wasserstein 距离的闭式解、
金字塔的像素预算、切片的组合数、针孔的成像公式——而这恰恰是可迁移的那部分：
框架 API 会变，这些式子不会。

每个模块末尾有一个 🧪 **真实工程胶囊**，把当天学到的东西翻译成可原样复制到
真实项目里的配置片段（mmdetection / ultralytics 的 config、SAHI 的调用参数、评测分桶脚本）。
