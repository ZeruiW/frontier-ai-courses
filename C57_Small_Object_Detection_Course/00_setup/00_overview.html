1这门课讲什么：检测里唯一没被架构进步解决的问题

过去十年目标检测的整体精度涨了很多，但有一个数字几乎原地踏步：COCO 上小目标的 AP_S 一直只有大目标 AP_L 的三分之一到二分之一。换掉 backbone、换掉 neck、从 anchor-based 换到 anchor-free、从 CNN 换到 Transformer——这个比例都没有实质改变。

这说明一件重要的事：小目标之难不是「模型不够强」，而是问题本身在几个不同的地方被同时卡住了。换一个更强的模型只能缓解其中一两处，剩下几处纹丝不动，所以总账看不到变化。

典型检测器在 COCO 上的表现AP_S（面积<32²）AP_MAP_LAP_S / AP_L
Faster R-CNN + FPN约 21约 43约 540.39
RetinaNet约 21约 44约 540.39
YOLO 系（同量级）约 26约 47约 580.45
DETR（单尺度）约 20约 46约 610.33
Deformable DETR / DINO（多尺度）约 32–37约 55–58约 65–680.49–0.54

直白说

这张表里唯一真正把比例往上抬的，是多尺度（Deformable DETR、DINO、以及所有带 FPN/P2 的方案）。而多尺度解决的恰恰是「下采样把小目标抹掉了」这一个原因——它对「IoU 阈值不公平」「标注本身带噪」这两条一点忙都帮不上。所以比例只能从 0.33 抬到 0.5 左右，抬不到 1.0。

严谨说

更严谨的读法是：AP_S 与 AP_L 的差距是「多个独立瓶颈的乘积」，而不是「一个瓶颈的强度」。若把五个原因分别记作 r₁…r₅（每个是小目标相对大目标的效率折损），总折损约为它们的乘积。这解释了为什么单点改进的边际收益总是低于预期——修好一个 rᵢ，剩下四个还在乘。反过来，这也是本课把「五个原因」拆开讲的全部理由。

本课要建立的第一个也是最重要的心智模型：「小目标难」不是一句抱怨，而是五个可以分别量化、分别修复、并且互相正交的工程问题。面试里被问到「小目标怎么做」，能把这五条拆开、说清每条的量级与对应解法，和只会说「加 FPN、加分辨率、用 copy-paste」是两个完全不同的水平。后者是招式清单，前者是诊断框架。

2「小目标」的三套定义，以及它们并不重合

讨论之前必须先约定「多小算小」。工程里流通着三套定义，它们在同一批数据上给出的答案并不一致，混用是很多口径争论的根源。

定义判据优点致命弱点
① 绝对定义（COCO）目标像素面积 < 32² = 1024 px²（即约 32×32 以下）客观、可比、评测通用与图像分辨率强耦合：同一块牌子，1080p 下算小目标，4K 下就不算了，可模型的困难其实没变多少
② 相对定义目标边长 / 图像短边 < 某比例（如 3%），或面积占比 < 0.1%对分辨率不变，跨数据集可比与物理距离脱钩：广角相机拍的近处大牌子和长焦拍的远处小牌子可能给出同一个比例
③ 网络相对定义目标边长 / 最细特征层 stride < 2（即在最细的特征图上不足 2 个格子）直接对应「模型能不能看见」，是最有工程意义的一套依赖具体架构，换网络就要重算，不能写进公开评测

直白说

三套定义的关系可以一句话说清：① 说的是「相机给了多少像素」，② 说的是「在这张图里它有多不起眼」，③ 说的是「网络还剩多少格子来描述它」。真正决定检测难度的是 ③，但只有 ① 能写进论文表格。于是就出现了「论文里 AP_S 提升了，换到自己的 1080p 车载数据上完全没动」这种常见困惑——因为两边的 ③ 根本不同。

严谨说

工程上的正确做法是三套都不当作唯一标准，而是直接按像素尺寸分桶评测：把验证集按 √(wh) 切成 [0,16) / [16,24) / [24,32) / [32,64) / [64,+∞) 若干桶，每桶单独算 AP 与召回。任何小目标改进的收益都必须在最小的两个桶里可见，否则它就不是小目标改进。这一点在模块 05 会被做成一套可复用的评测代码；本模块的 notebook 里先把分桶算清楚。

一个必须避免的口径事故：把「小目标」定义在缩放后的输入上，还是原始图像上。训练时图像被 letterbox 到 640×640，一块原图里 32px 的牌子在网络输入上可能只有 11px。论文报的 AP_S 是在标注坐标系（原图）上算的，而模型看到的是缩放后的。这两个数字差一个缩放因子，讨论时不说清楚就会各说各话。本课的所有数字，除非特别说明，都是「网络输入坐标系下的像素」——因为这才是模型真正面对的尺寸。

3小目标难的五个独立原因

这是全课的骨架。请把它当成五个不同的病，而不是一个病的五种症状——它们的机理不同、量化方式不同、解法不同，而且修好任何一个都不会顺带修好另一个。

一块 8×8 像素的限速牌，从进相机到被判为正样本，要连过五关： ① 信息量少 8×8×3 = 192 个数；64×64×3 = 12288 个数（64 倍差距） │ 数字笔画在 8px 的牌子上不足 1 像素宽 → **低于奈奎斯特极限** │ 病灶：物理层。模型再强也变不出不存在的信息 ▼ ② IoU 对位移极敏感 同样偏 2 像素：8×8 框 IoU=0.391，64×64 框 IoU=0.884 │ 敏感度 dIoU/dd = -4/s，**与尺寸成反比** │ 病灶：度量层。IoU 这把尺子本身对小目标不公平 ▼ ③ 正样本稀缺 RetinaNet 的最小 anchor 是 32px，8px 目标的 │ **最好可能 IoU 只有 (8/32)² = 0.0625** —— 阈值 0.5 下 │ 永远匹配不到，一个正样本都没有。病灶：分配层 ▼ ④ 下采样丢失 stride 32 的特征图上，8px 目标只占 0.25 个格子 │ （面积 0.0625 格）；有效感受野远小于理论感受野， │ 目标只占该神经元有效输入的约 1%。病灶：架构层 ▼ ⑤ 标注误差相对大 人工标注每条边 ±2px：8px 框的平均 IoU 只有 0.62， **只有 8% 的重标能达到 IoU 0.75** → AP@0.75 在小目标上 测的是标注员而不是模型。病灶：数据层 五关的病灶分别在：物理层 / 度量层 / 分配层 / 架构层 / 数据层。 **它们互相正交** —— 加 P2 修的是 ④，换 NWD 修的是 ②③，都修不了 ①⑤。
原因一句话机理对应解法（本课模块）修好它不会顺带修好
① 信息量少像素预算不足，判别性细节低于采样极限提分辨率 / 长焦相机 / 切片推理 / ROI 精检（m04、m05）②③④⑤ —— 信息多了，IoU 阈值还是一样不公平
② IoU 对位移敏感IoU 随绝对位移的衰减率 ∝ 1/s换度量：NWD / KLD / 尺度自适应阈值（m03）①④ —— 换尺子不增加信息，也不改变特征分辨率
③ 正样本稀缺anchor 与阈值的组合让小目标匹配不到监督改分配：ATSS / SimOTA / RFLA / center-based（m03）①⑤ —— 有了正样本，标签仍然带噪
④ 下采样丢失stride 与有效感受野把小目标稀释掉FPN/PAN/BiFPN、加 P2、可变形注意力（m02）②⑤ —— 特征细了，度量与标签的问题原样保留
⑤ 标注误差相对大固定像素级标注抖动对小框是巨大相对误差标注规范、软标签、按尺寸分桶评测、放宽小目标 IoU 判定（m05）①②③④ —— 标得再准也不会多出像素
别在同一个原因上重复加码

这张表最容易被忽略的是最后一列。工程上最常见的浪费，就是反复在同一个原因上加码：AP_S 不涨 → 再加一层 P2 → 再提高一次输入分辨率 → 再换一个更大的 backbone。这些全都在修 ①④，而如果瓶颈其实在 ③（分配根本没给小目标正样本）或 ⑤（标注噪声已经压住了指标上限），投入再多算力也不会有回报。

诊断顺序应该是：先看小目标的正样本数（③）→ 再看标注一致性（⑤）→ 再看特征分辨率（④）→ 最后才是加算力（①）。这个顺序在 notebook 里会被写成一个可执行的诊断器。

4TSR：小目标问题最纯粹的形态

交通标志识别（Traffic Sign Recognition, TSR）不是「碰巧也有小目标」的任务，而是小目标问题的极端样本。用针孔相机模型算一次就明白了。

\[p = f\cdot\frac{S}{Z}, \qquad f = \frac{W/2}{\tan(\mathrm{FOV}_h/2)}\]

其中 p 是标志在图像上的像素直径，f 是以像素为单位的焦距，S 是标志的物理尺寸，Z 是距离，W 是图像宽度。代入一组量产车常见参数：1920×1080、水平 FOV 60°，得 f = 960 / tan(30°) ≈ 1662.8 px；国标限速牌直径 S = 0.6 m。

距离 Z像素直径 p（1920p / 60° FOV）120° 广角3840p / 60°这个尺寸意味着什么
30 m33.3 px11.1 px66.5 px刚好越过 COCO 的「小目标」线，可以稳定分类
60 m16.6 px5.5 px33.3 px接近分类的下限：数字笔画约 1–2 px
100 m10.0 px3.3 px20.0 px只能判「有个红色圆牌」，读不出限速值
150 m6.7 px2.2 px13.3 px低于多数检测器的可检下限

直白说

把这张表和车速放在一起就是安全论证：高速上 120 km/h ≈ 33 m/s。若只能在 60 m 处才把限速值读准，留给系统的反应时间不到 2 秒；而人类驾驶员通常能在一两百米外就注意到牌子的存在。「多远能检出、多远能读准」这两个距离，直接决定了 TSR 功能的可用性上限——它们是像素预算的函数，不是模型精度的函数。

严谨说

更进一步，TSR 把五个原因全部同时触发：① 100 m 处只有 10 px，限速「60」与「80」的笔画差异低于奈奎斯特极限；② 车辆颠簸与检测抖动带来的 1–2 px 位移，对 10 px 的框就是 IoU 从 1.0 掉到 0.4 以下；③ 标准 anchor 集合完全覆盖不到 10 px；④ 车载模型为了延迟通常最细只到 stride 8，10 px 目标只有约 1 个格子；⑤ 标注员在 10 px 的牌子上画框，边界误差就是 20% 的相对误差。没有哪个通用检测任务能把五条同时踩满。

所以本课与 C55（TSR 与自动驾驶感知）的分工是：C55 讲「TSR 这个任务本身有哪些工程问题」，本课讲「其中最硬的那一条——目标太小——在物理、度量、分配、架构、数据五个层面各是什么，各能做到什么程度」。本课的每一节都会在末尾把结论翻译回「对 60 米外的一块限速牌意味着什么」，因为脱离了物理尺寸，小目标的讨论很快会退化成招式罗列。

6环境、方法论与怎么用这门课

本课全程 纯 numpy + 标准库、CPU 可跑、不联网。不需要 GPU、torch、mmdetection 或任何真实数据集。所有 notebook 在 CPU 上实跑验证、assert 全部通过。

pip install -r requirements.txt      # numpy / matplotlib / jupyterlab / ipykernel
jupyter lab                          # 打开 00_setup/00_environment_check.ipynb

这个约束不是妥协，而是本课的方法论：

  • 小目标之难的核心全部是可以精确计算的量——IoU 随位移的衰减是初等代数；anchor 匹配上界是一个面积比；stride 上的格子数是一次除法；有效感受野的宽度是中心极限定理；标注噪声的影响是一次蒙特卡洛。它们不需要训练任何模型就能算清楚，而算清楚之后，「该做什么」几乎是自明的。
  • 训练一个真模型反而会掩盖机理。真实实验里 AP_S 涨了 1.5 点，你很难说清是分配变了、还是特征细了、还是碰巧那批数据标得好。而在合成设定下每个变量都可以单独拧，因果关系是干净的。
  • 凡是结论都要带数字。本课不接受「小目标特征少所以难」这种说法，只接受「8×8 的 patch 是 192 个数、64×64 是 12288 个数，差 64 倍；且在固定 0.8 px 的镜头模糊下，『60』与『80』的可分性 d′ 从 32px 时的约 90 掉到 8px 时的约 6，衰减约按 D^1.95」这种说法。面试里前者是常识，后者是能力。

直白说

怎么用这门课：模块 01 必须先读透，它是后面四个模块的记账本。02–04 三个模块彼此独立，可以按你当前的瓶颈跳读；模块 05 是把前面所有东西组装成一套 TSR 方案，建议最后读。如果你时间只够读一个模块，读 01——因为「能把小目标之难量化」本身就是这门课最值钱的产出。

严谨说

面试视角的用法：本课的高频考点集中在三处——① 为什么同一个 IoU 阈值对不同尺度不公平（要能当场推导 IoU = (s-d)²/(2s²-(s-d)²) 并代入数字）；② NWD 相比 IoU 好在哪（尺度不敏感、且在两框不相交时仍有梯度）；③ 切片推理的重叠率该怎么定（要能从「最大目标不被任何切片边界切断」推出下界）。这三处在讲解里都用 加粗 标出，并说明面试官想听什么。

最后一句方法论：本课所有的数值实验都可以在面试白板上重做一遍简化版。「同样偏 2 像素，8×8 的框 IoU 掉到 0.39，64×64 还有 0.88」——这两个数只需要 (s-d)²/(2s²-(s-d)²) 一个公式，三十秒能算出来。能在白板上把一个定性抱怨变成两个具体数字，是本课想训练的核心能力。

7研究前沿与开放问题

小目标检测是一个「问题定义清晰、但没有统一解」的方向。当前几条活跃的线索：

  • 度量的重新设计：NWD、KLD、RFLA 这一类工作的共同主张是「IoU 不是唯一可用的框相似度」。它们在小目标上确有收益，但代价是与主流评测指标（仍以 IoU 为准）脱钩——训练用 NWD、评测用 IoU，两者的最优解不一定重合。「该不该连评测一起换掉」目前没有共识。
  • 标注噪声下的评测上限：如果两位标注员在 8px 目标上的一致性 IoU 只有 0.62，那么 AP@[.5:.95] 在小目标桶上究竟测的是什么？「按尺寸自适应的 IoU 阈值」是被反复提出但一直没有被主流评测采纳的方案，因为它会破坏跨数据集可比性。这是一个真实的开放问题。
  • 高分辨率的算力墙：提分辨率对小目标几乎总是有效，但代价按分辨率平方增长。稀疏化路线（只在可能有目标的区域做高分辨率计算：稀疏卷积、动态分辨率、query-based 稀疏采样）是当前最有希望绕开平方墙的方向，但工程复杂度与延迟方差都显著上升——对车端尤其敏感。
  • 时序与多帧超分：单帧信息不够时，把相邻多帧的亚像素位移利用起来（多帧超分、时序聚合）在理论上能突破单帧的采样极限。TSR 场景对此格外有利：标志是静止的，自车运动可测，位移可预测。这条线在学术上讨论不少，量产落地的公开报道很少。
  • 合成数据与稀有小目标：copy-paste 与渲染合成能廉价地制造小目标样本，但「合成的小目标」与「真实的远处小目标」在模糊、噪声、ISP 响应上有系统性差异，过度依赖会训出一个只认识合成模糊的模型。如何度量这个域差，仍然缺少标准工具。

必读（按本课顺序）：Feature Pyramid Networks for Object Detection（Lin et al., 2017 —— 多尺度的奠基，本课模块 02 的基础）；Understanding the Effective Receptive Field in Deep CNNs（Luo et al., 2016 —— 证明 ERF 呈高斯形且半径按 √n 增长，本课模块 01 会数值复现）；A Normalized Gaussian Wasserstein Distance for Tiny Object Detection（Xu et al., 2021 —— NWD，模块 03 的核心）；RFLA: Gaussian Receptive Field based Label Assignment for Tiny Object Detection（Xu et al., ECCV 2022）；Slicing Aided Hyper Inference (SAHI)（Akyon et al., ICIP 2022 —— 切片推理，模块 04）；数据集侧读 TT100K（Zhu et al., CVPR 2016 —— 中国交通标志，小目标 + 长尾的典型）与 AI-TOD / TinyPerson 两个专门的小目标基准。相邻课程：C18（检测基础）、C53（实时检测器与标签分配）、C55（TSR 系统）、C56（检测增强）。完整清单见 references.md。
