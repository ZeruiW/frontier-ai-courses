1这门课讲什么（与 C08 的衔接）

欢迎来到 分布式训练工程。这门课只追求一件事：让你从「会算分布式训练的账」变成「会把它工程化地跑起来、调通、并在故障中救活」。

它是 C08（训练系统） 的下一步。C08 给了你一套成本模型与账本——一个模型要多少显存、多少 FLOPs、roofline 在哪、各种并行各省多少——那是纸面上的账。但把账变成一个真能在几百上千张卡上稳定跑几周的训练任务，中间隔着大量可操作的工程：梯度到底怎么在卡间同步？参数怎么切才能既放得下又算得对？流水线为什么会有气泡、怎么填？几千张卡每隔几小时就坏一张，你怎么不让几周的训练前功尽弃？某个 rank 莫名卡住，整个集群陪它干等，你怎么定位？这些问题 C08 不答，本课逐一拆开、亲手重建。

这些答案不在任何 API 文档的「快速上手」里，而在通信的物理约束与算法对这些约束的回应之中。分布式训练给你的，本质上是两样东西：成倍的算力/显存，和一条又慢又有延迟的卡间链路。几乎所有分布式训练工程，归根结底都在回答同一个问题——如何把计算切到多卡上，同时让卡间通信尽量少、尽量和计算重叠、尽量别让任何一张卡掉队。本课就沿着这条主线，把六个核心环节（集合通信、数据并行/FSDP、张量/流水并行、checkpoint/容错、编排/调试）从零拆开。

学完你应当能回答这类问题（也是大模型训练/基础设施岗位的高频面试题）：all-reduce 到底怎么实现的，为什么 ring 版的通信量不随卡数爆炸？ZeRO-1/2/3 各分片了什么、每卡省多少显存、多付多少通信？张量并行的一个 MLP 块为什么只需 1 次 all-reduce？流水线 bubble 比例的公式是什么、1F1B 凭什么省激活显存？几千卡的 MTBF 有多短、最优 checkpoint 间隔怎么定、怎么精确续训？一个 straggler 会把扩展效率拖到多低？——并且能在 numpy 里把这些都从零实现、和单卡参考对拍到 1e-10。

一句方法论上的话先说在前面：本课的价值不在「我们没有多 GPU 也能学」这个妥协，而在它逼你只关注真正难的部分——并行的正确性与成本结构。NCCL 怎么调、环境变量怎么设、哪个框架的哪个 flag，这些有了正确的并行结构之后都是查文档的机械活，且各框架不同、年年在变；而「梯度该怎么聚合才数值正确」「参数切开后前向还对不对」「通信量到底是张量大小的几倍」是不随框架过时的硬功夫。把它练扎实，换到任何框架（PyTorch DDP/FSDP、DeepSpeed、Megatron、JAX pjit）都立刻能上手。

2世界观：三类并行与「通信 ≫ 计算」

先建立一个判断力：什么时候需要哪种并行。分布式训练不是「卡越多越好」的均匀堆砌，而是针对不同瓶颈用不同并行。三类基本并行各打一类问题：

并行类型切什么解决什么瓶颈主要代价通信原语
数据并行 DP切数据（复制模型）吞吐不够、想用更大 batch每卡仍要放下整个模型梯度 all-reduce
张量并行 TP切单层算子（权重矩阵）单层/单卡放不下、要降单卡显存通信极频繁、须高带宽（节点内）层内 all-reduce
流水并行 PP切层序列（分 stage）模型层数多、要把层摊到多卡流水线 bubble、激活在 stage 间传点对点 send/recv
ZeRO/FSDP切冗余状态（优化器/梯度/参数）数据并行下显存冗余太多比 DP 多约 1.5× 通信reduce-scatter + all-gather
通信 ≫ 计算（慢）

最容易被忽略、却支配一切取舍的一条：卡间通信比卡内计算慢得多，且通信量随并行方式天差地别。节点内 NVLink 有几百 GB/s，跨节点 InfiniBand 通常更低且延迟更高；而一次 all-reduce 要搬的字节数、做的次数，直接决定扩展效率。这就是为什么张量并行（每层都要 all-reduce、通信最密）几乎只放在单节点内的 NVLink 上，流水并行（只在 stage 边界点对点传激活、通信最稀）才跨节点，数据并行放最外层——整个 3D 并行的布局，本质是把通信最频繁的并行放在带宽最高的链路上。记住这条，模块 02/03 的所有设计就都顺理成章了。

这张表是全课的骨架。模块 01 打磨所有并行共用的通信积木；模块 02 是数据并行与 ZeRO/FSDP（切数据与冗余状态）；模块 03 是张量并行与流水并行（切模型本身）；模块 04/05 则是让这套并行真能跑完——容错与编排调试。现实中的大模型训练几乎总是几种并行叠加（3D 并行 + ZeRO），而叠加的章法，正来自上表「每种并行的代价与所需带宽」。

课程地图：从一次 all-reduce 到一个能跑完的训练任务

分布式训练给你的：成倍算力/显存 + 一条又慢又有延迟的卡间链路 模块 01 集合通信 all-reduce / all-gather / reduce-scatter；ring 算法；带宽-延迟成本 │ 「卡之间怎么高效地交换与聚合数据？」 ← 一切并行的通信积木 ▼ 模块 02 数据并行/FSDP DDP 梯度 all-reduce；ZeRO-1/2/3 逐级分片；显存↔通信权衡 │ 「模型放得下时，怎么用多卡扩吞吐、并把冗余显存挤掉？」 ▼ 模块 03 张量/流水并行 TP 列切/行切 + all-reduce；PP 切层 + micro-batch + 1F1B；3D 并行 │ 「模型一层都放不下时，怎么把模型本身切到多卡还算得对？」 ▼ 模块 04 checkpoint/容错 分片/异步 checkpoint；原子写；MTBF 与最优间隔；精确续训；弹性 │ 「几千卡每几小时坏一张，怎么不让几周训练白跑？」 ▼ 模块 05 编排/调试 rank/world/通信组；straggler；strong/weak scaling；hang/瓶颈定位 「怎么把脚本拉起到 N 卡、监控、调通、并解释扩展效率？」

注意这不是松散的专题集合，而是一条从底层积木到端到端落地的依赖链：上层的每种并行（02/03）都建立在通信原语（01）之上；而把这套并行真正跑完，离不开容错（04）与编排调试（05）。读到最后你会发现，所谓「在万卡上训练一个大模型」，拆开来无非是这五块零件的组合——本课刻意的编排，就是把一个听起来高不可攀的系统，还原成几个可独立验证的机制的拼装，让你确信「我也能理解并参与它」。

每一级台阶都对应一个可独立验证的能力：模块 01 你手写的 ring all-reduce 会逐位等于直接求和、并能算出它的通信量；模块 02 你的 DP 平均梯度会等于单卡大 batch 梯度、ZeRO 各阶段的每卡显存账能对上；模块 03 你切分的张量并行线性层会逐位等于单卡、bubble 公式能对上你模拟的甘特图；模块 04 你的续训轨迹会和未中断时逐位一致；模块 05 你能量化一个 straggler 让扩展效率掉到多少。每一步都有 assert 兜底，绝不靠「感觉对了」。

4方法论：用 numpy 在单进程内模拟多 rank

方法论：没有多 GPU，怎么学分布式训练？

本环境没有多张 GPU、不装 torch.distributed / NCCL。但分布式训练的难点从来不是 NCCL 的 API，而是并行的结构与成本：梯度怎么聚合才正确、参数怎么切前向还对、通信量是张量的几倍、流水线怎么调度、状态怎么存才能精确恢复。这些用 numpy 在单进程内也能精确地表达和验证。

核心技巧是：把「多个 rank」模拟成一个 Python 列表或多出一维的 numpy 数组，列表的第 r 个元素 = 第 r 个 rank 持有的那份数据。于是一次 all-reduce(求和) 就是把这个列表里的数组逐元素加起来（再广播回每个元素）；一次 reduce-scatter 就是先求和、再把结果切片分给各元素；ZeRO 的「每卡只存 1/W」就是让第 r 个 rank 只持有第 r 片；流水线的 bubble 就是把调度画成甘特图、数里面的空格。真实集群上这些操作并行地、跨网络地发生；我们让它串行地、在一个进程里发生——结构与数值完全相同，只差「同时」与「跨网络」二字，而那两件事恰恰是框架替你处理的部分。

直白说

我们把分布式的每个机制翻译成 numpy 里看得见摸得着的东西：一组 rank 就是一个列表，all-reduce 就是把列表求和，分片就是切数组，通信量就是数出来的字节数，bubble 就是甘特图里的空格，容错就是存/取 RNG 状态。你写的是结构与账，不是性能。

严谨说

关键纪律是对拍（differential testing）：每个分布式机制都和一个单卡参考实现比对。数据并行的平均梯度必须等于把所有 rank 的数据拼成一个大 batch 在单卡上算的梯度；张量并行切分后的线性层必须逐位等于X@W；reduce-scatter + all-gather必须等于all-reduce；续训轨迹必须等于未中断的轨迹。结构正确 → 数值一致；数值一致 → 你的并行逻辑可以原样搬到 torch.distributed。

分布式概念本课的 numpy 模拟对应真实工具
W 个 rank 的张量长度 W 的列表 / 多一维的数组每个 GPU 进程持有的 tensor
all-reduce(sum)对列表逐元素求和再广播dist.all_reduce / NCCL
reduce-scatter / all-gather求和后切片 / 切片后拼接dist.reduce_scatter / all_gather
ZeRO/FSDP 分片每 rank 只切自己那 1/WFSDP / DeepSpeed ZeRO
pipeline 调度与 bubble甘特图矩阵 + 数空格Megatron 1F1B 调度器
容错恢复保存/还原 RNG 状态与步数torch.distributed.checkpoint

为什么把对拍提到方法论的高度？因为分布式训练的 bug 极其阴险：梯度少除了一个 W、某个 rank 的分片错位、collective 不对齐导致 hang、续训后 RNG 没还原导致悄悄发散——这些往往不会报错，只是让训练看起来在收敛但其实错了，等几天后 loss 不对劲才发现，代价极高。在真实集群上这种 bug 要靠几百个 rank 的日志大海捞针；而在 numpy 模拟里，我们有一个绝对可信的单卡参考（直接拼 batch、直接 X@W），任何偏差都会被 np.allclose 当场抓住。本课每个机制都先写单卡参考、再写分布式版、立刻对拍——这套纪律正是真实分布式开发（与单卡/单进程对拍）的核心工作流。

务必清楚本课不教什么：不教 NCCL 调参与拓扑、不测真实跨节点带宽、不写真正并发/跨进程的代码、不覆盖具体框架的每个 flag。这些在你有了正确的并行结构与成本直觉后，是第二步（references 里的 NCCL 文档、FSDP/Megatron/DeepSpeed 文档接手）。本课负责把第一步——并行的正确性与成本结构夯死；这一步搞定，第二步才有意义。

环境与运行

环境极简：只需 numpy（画扩展曲线可选 matplotlib）。全课 CPU 秒级运行，无需多 GPU、NCCL、torch、DeepSpeed。

jupyter lab

每个模块配一个 notebook，结构统一：先用 numpy 把机制从零实现并对拍（5–6 个 worked 小节，每节都跑出可打印的验证与 assert），再做 3–4 道带 assert 判分的 ✏️ 练习（先给骨架，自己填，再对照 📖 参考答案），最后一个真实数据胶囊（用真实模型规模/真实集群参数算一笔账，把纸面知识接到现实）。每个 notebook 里都附真实 torch.distributed / FSDP / Megatron 代码作对照，让你看清 numpy 模拟与真实 API 的逐行对应——学完照着把验证过的逻辑写成真实分布式代码是最自然的下一步。

建议的学习节奏：先读完整章 HTML 建立直觉与成本模型，再打开 notebook 亲手实现。读和做缺一不可——只读会觉得「好像懂了」，真正动手写 all-reduce、算分片显存、让续训轨迹逐位对齐时，才会发现魔鬼藏在哪些细节里（梯度的 1/W、分片的边界、RNG 的还原、collective 的对齐）。这门课的深度正是为「动手」服务的。

配套先读：ZeRO（Rajbhandari 2020）建立分片显存的直觉、Megatron-LM（Shoeybi 2019）建立张量并行的直觉、GPipe（Huang 2019）建立流水 bubble 的直觉、ring all-reduce（Patarasuk 2009）建立通信成本的直觉。完整清单见 references.md。

✅ 学完整门课，你应该能：
  1. 说清 all-reduce/all-gather/reduce-scatter 的语义，手写 ring all-reduce 并算出其通信量；
  2. 解释 DDP 为何等价单卡大 batch，写出梯度 all-reduce 并对拍；
  3. 算清 ZeRO-1/2/3 每卡的显存账与多付的通信，知道何时用哪一阶 / 何时用 FSDP；
  4. 推导张量并行的列切/行切，论证一个 MLP 块只需 1 次 all-reduce，并对拍单卡线性层；
  5. 推导 pipeline bubble 比例 (P−1)/(m+P−1)，说清 1F1B 如何省激活显存；
  6. 组合 DP×TP×PP 成 3D 并行，把 rank 映射到三维坐标、把通信放到合适的链路；
  7. 设计分片/异步 checkpoint 与精确续训（对拍未中断轨迹），用 MTBF 定最优 checkpoint 间隔；
  8. 用 Amdahl/扩展效率解释一个分布式任务为何扩不动，定位它是 compute/comm/straggler-bound。
