1这门课讲什么

欢迎来到 推理模型 RL（o1/o3/R1 前沿）。这门课只追求一件事：让你从「会用 o1/R1」变成「会复现它们的训练配方」。

2024 年底到 2025 年，最前沿的语言模型经历了一次范式转移。在此之前，提升模型主要靠把它做得更大、用更多数据预训练；在此之后，OpenAI 的 o1/o3、DeepSeek 的 R1 展示了一条新路：让模型在回答前先「想很久」——生成一长串带尝试、回溯、自我检查的推理——并用强化学习去优化「最终答对」这个目标。结果是数学、代码、科学推理上的台阶式跃升。更惊人的是 DeepSeek 的发现：你甚至不需要教模型怎么推理，只要在基座模型上用纯 RL 奖励「答对」，长思维链、反思、换路解题这些行为会自发涌现出来。

这门课要回答的，正是这次转移背后到底发生了什么：为什么只奖励最终答案，推理就会变长？怎样的 RL 算法能在没有价值网络的情况下稳定训练（GRPO）？给推理的每一步打分（过程奖励）比只看结果好在哪、又危险在哪？推理时多花算力（多采样、搜索、修订）为什么能换准确率，又该怎么花得最划算？这些问题的答案不在任何 API 文档里，而在RL 的数学与这些前沿实验室对它的工程化之中。

学完你应当能回答这类问题（也是推理/RL/对齐岗位的高频面试题）：结果奖励 RL 为什么能涌现长 CoT？GRPO 怎么去掉 critic、它的优势到底是什么？PRM 比 ORM 强在哪、Goodhart 倒 U 是怎么回事？best-of-N、多数投票、pass@k 有什么区别，哪个能真部署？固定算力下该用大模型还是小模型+多采样？——并且能在 numpy 里把这五样东西都从零实现、和解析解对拍。

一句方法论上的话先说在前面：本课的价值不在「我们没有 GPU 也能学」这个妥协，而在它逼你只关注真正难的部分——算法的结构与正确性。真实训练里那些工程噪声（分布式、显存、采样吞吐、超参玄学）有了正确的算法骨架之后才谈得上；而「策略梯度的优势怎么算才无偏」「组归一化为什么等价于去 critic 的基线」「pass@k 的无偏估计为什么不是 $1-(1-\hat p)^k$」是不随框架版本过时的硬功夫。把它练扎实，换到 trl/verl 任何训练栈都立刻能上手、能 debug。

2范式转移：从 RLHF 到可验证奖励 RL

要理解推理 RL，先得看清它和上一代对齐范式 RLHF 的根本区别。两者都用 RL，但奖励从哪来完全不同，这个差别决定了一切。

维度RLHF（上一代对齐）RLVR / 推理 RL（本课）
奖励来源人类偏好 → 训一个奖励模型 RM程序自动验证（数学答案匹配、代码跑测试）
优化目标「人类觉得这个回答好」「这个答案客观正确」
奖励可 hack 度高（可迎合 RM 的风格偏好）极低（答案对就是对，难以风格性地骗）
典型算法PPO + critic + RMGRPO（去 critic）+ 规则奖励
代表作InstructGPT、ChatGPTo1 / DeepSeek-R1

直白说

RLHF 像请一群人给作文打分，再训模型去讨好这群人——模型可能学会写得「看起来好」但未必对。推理 RL 像做数学题对答案：对就是对、错就是错，模型没法靠花言巧语蒙混，只能真的把题做对。这个「不可糊弄的奖励」，是推理能力能被可靠激励出来的根本原因。

严谨说

形式上：RLHF 的奖励 $r_\phi$ 是一个学习来的、可能被过度优化的代理；RLVR 的奖励是一个近乎 ground-truth 的验证函数（在可验证域上）。前者必须靠强 KL 正则拉住、否则会 reward hacking 崩坏；后者可以放开探索，因为奖励本身几乎不可被 hack。这就是为什么 R1 敢把 KL 调得极小、甚至让模型在训练中把 CoT 写到上万 token——奖励经得起这种探索。

可验证的边界

但「可验证」是有边界的，这是全课最重要的一条警示：规则奖励只在能自动判对错的领域（数学、代码、形式逻辑）才近乎不可 hack。一旦换成学习的奖励模型（ORM/PRM）或开放域任务，奖励就重新变回可被优化到失真的代理——这正是模块 03 要讲的 PRM 倒 U 与 Goodhart。所以推理 RL 的版图是：在可验证域用规则奖励放手 RL，在不可验证域则要小心翼翼地控制过度优化。记住这条边界，你就抓住了本课的张力主线。

把这个范式差想透，本课后面五个模块就有了统一的脉络：模块 01–02 讲在可验证域怎么把 RL 跑稳跑好（结果奖励 + GRPO）；模块 03 讲当我们想要更密的信号、引入学习的奖励时会付出什么代价（PRM 与 Goodhart）；模块 04–05 讲训练之外，推理时还能怎样用算力换准确率（搜索与 TTC scaling）。一条线：奖励的可靠性，与算力花在训练还是推理。

再补一个常被混淆的点：可验证奖励 RL 与「监督微调（SFT）」也不同。SFT 是模仿——给模型看人类写好的正确推理，让它学着复制；它的上限是示范数据的质量，且只会模仿、不会发现示范里没有的解法。可验证奖励 RL 是试错——模型自己生成、自己撞对、被奖励强化；它能发现示范里没有的策略（R1-Zero 涌现的反思、换路就是例子），上限是模型自身的探索能力与基座潜力。这就是为什么 R1 用「少量 SFT 冷启动 + 大量 RL」：SFT 给一个像样的起点（可读、格式对），RL 在此之上放手探索、自我改进。理解 SFT（模仿）、RLHF（对齐人类偏好）、RLVR（追求客观正确）这三者的分工，是看懂任何前沿后训练配方的地图。

一张速记表把三种后训练范式钉死：SFT = 学人类怎么做（模仿，上限=数据）；RLHF = 学人类喜欢什么（对齐偏好，可被风格 hack）；RLVR = 学什么是客观对的（试错追正确，可验证域几乎不可 hack）。推理模型 = SFT 打底 + RLVR 主攻。本课聚焦最后一个——也是 o1/R1 能力跃升的真正引擎。

3课程地图：从结果奖励到测试时计算

课程地图：从结果奖励到测试时计算

推理模型的两大算力维度：训练时 RL（把推理内化进权重） + 测试时计算（按需多想） 模块 01 Long-CoT 结果奖励 只奖励最终答对 → 长 CoT / 反思 自发涌现（R1-Zero） │ 「为什么不教推理，推理却变长了？」 ▼ 模块 02 GRPO 组内归一化优势替代 critic + ratio clip + KL；逐行推 loss │ 「怎么不要价值网络也能稳定 RL？」 ▼ 模块 03 过程奖励 PRM 给每一步打分；MC 自动软标签；min/prod 聚合；Goodhart 倒 U │ 「更密的奖励信号，更准也更危险」 ▼ 模块 04 Verifier 搜索 best-of-N / 加权投票 / beam；pass@k 无偏估计 │ 「推理时怎么用 verifier 把对的挑出来？」 ▼ 模块 05 TTC scaling scaling 律、compute-optimal 分配、难度路由、帕累托 「同样的算力，该买更大模型还是更多采样？」

注意这条线有一个清晰的分水岭：模块 01–03 关心训练时——怎么用 RL 把推理能力塞进模型权重；模块 04–05 关心推理时——给定一个训好的模型，怎么用额外算力把它的能力榨出来。这两者是推理模型的两条腿，缺一不可，也常常互相替代（训练时的能力可以省下推理时的搜索，反之亦然）。理解它们的分工与权衡，是本课想给你的最高层心智模型。

这条链还有一个反复出现的暗线，建议你带着它读完全课：奖励/信号的「可信度」决定一切设计选择。可验证的结果奖励近乎不可 hack→ 可以放手 RL、把 KL 调到极小（模块 01–02）；学习的 PRM可被 hack→ 必须 KL 正则 + 早停、且更适合当推理时的裁判而非训练目标（模块 03）；推理时的 verifier有多准→ 决定该用 BoN/引导搜索还是投票（模块 04）、该把算力投在选得准还是投得稳（模块 05）。几乎每个模块的关键判断，最后都归到同一个问题：你手里这个信号，有多值得信？把这条暗线记住，零散的技术就串成了一个有内在逻辑的整体。

每一级台阶都对应一个可独立验证的能力：模块 01 你能写出结果奖励的策略梯度更新并用数值梯度对拍；模块 02 你手算的 GRPO 优势会逐位等于组归一化定义、loss 的裁剪行为可被构造的例子触发；模块 03 你的 MC 步级标签会收敛到解析答对概率、min/prod 聚合的排序符合直觉；模块 04 你的 pass@k 估计会等于组合数公式、加权投票在构造例子上胜过裸投票；模块 05 你的 compute-optimal 分配会在固定预算下最大化准确率、难度路由会跑赢一刀切。每一步都有 assert 兜底，绝不靠「感觉对了」。

4方法论：用 numpy 玩具环境模拟并对拍

方法论：没有 GPU、不训真模型，怎么学推理 RL？

本环境没有 GPU，也不会去微调任何真实大模型（那要几十张卡、几天时间）。但推理 RL 的难点从来不是「把 70B 模型塞进显存」，而是算法的结构与正确性：策略梯度的优势怎么算才无偏、GRPO 的组归一化为什么等价于一个合法基线、PRM 的 MC 标签是否收敛到真实价值、pass@k 的无偏估计长什么样、TTC 预算怎么分配才最优。这些用 numpy 在 CPU 上就能精确地表达、运行、验证。

打个比方：学下棋不一定要有红木棋盘。推理 RL 的「棋理」是奖励怎么定义、优势怎么估计、信用怎么分配、算力怎么分配；这些都是和模型规模、框架版本无关的算法结构。一个真实 GRPO 训练里，策略是一个几十亿参数的 Transformer；我们在 numpy 里用一个softmax 参数表格当策略——它一样有 $\pi_\theta(a\mid s)$、一样能算 $\nabla\log\pi$、一样能做组采样和 ratio clip。算法结构一模一样，只差「参数多少」与「环境复杂度」。

直白说

我们把推理 RL 的每个机制翻译成 numpy 里看得见摸得着的东西：策略是一张 softmax 概率表，环境是一道能自动判对错的算术题，一组 rollout 是几次带随机的采样，verifier 是一个带可控噪声的打分函数，TTC 是「采几个样、搜多宽」的预算。你写的是算法结构，不是训练吞吐。

严谨说

关键纪律是对拍（differential testing）：每个算法都和一个可信的参照比对——策略梯度对拍数值梯度（有限差分）、GRPO 优势对拍组归一化的解析定义、MC 标签对拍可枚举环境里的真实答对概率、pass@k 估计对拍组合数闭式解、online 投票对拍批量 Counter 统计。结构正确 → 数值一致；数值一致 → 你的实现可以原样搬到 trl/verl。

推理 RL 概念本课的 numpy 模拟对应真实系统
策略 $\pi_\theta$softmax 参数表格几十亿参数的 Transformer 策略
可验证环境/奖励能自动判对错的算术题 / GridWorldGSM8K/MATH 答案匹配、代码单测
一组 rollout对同一题采样 $G$ 条带随机序列vLLM 批量生成 $G$ 条 completion
GRPO 优势组内 (r−mean)/stdtrl GRPOTrainer 的组归一化优势
verifier (ORM/PRM)带可控噪声的打分函数学习的奖励模型 / 规则验证器
正确性判定assert 对拍解析解/数值梯度与已知实现/单测对拍

为什么把对拍提到方法论的高度？因为 RL 与搜索算法的 bug 极其阴险：一个写错符号的优势、一个边界没处理的 pass@k、一个有偏的估计量，往往不报错，只是悄悄让你的训练「看起来在学但其实在学错的东西」、或让你的评测数字系统性偏高/偏低。在真实大模型上，这种 bug 要烧几百 GPU 小时才隐约觉得不对、且极难定位（是算法错了？数据错了？还是只是没收敛？）。而在 numpy 玩具里，我们有一个绝对可信的参照（解析梯度、枚举真值、组合数闭式解），任何偏差当场被 assert 抓住。本课每个算法都先写参照、再写实现、立刻对拍——这套「先有 ground truth、再实现」的纪律，正是真实 RL 研究（与已知实现/单测对拍）的核心工作流，只是我们在更干净的环境里把它练成肌肉记忆。

务必清楚本课不教什么：不教分布式训练、不调真实大模型超参、不测真实生成吞吐、不碰显存优化。这些在你有了正确的算法结构后，是第二步（references 里的 trl/verl/DAPO 接手）。本课负责把第一步——算法的结构与正确性夯死；这一步搞定，第二步才有意义、也才 debug 得动。

5环境与运行

环境与运行

环境极简：只需 numpy（画 scaling 曲线可选 matplotlib）。全课 CPU 秒级运行，无需 GPU、无需 torch/transformers、无需联网（真实数据胶囊带 try/except 离线回退到内置真实数值）。

pip install matplotlib       # 可选，仅用于画 TTC scaling / 帕累托曲线
jupyter lab

每个模块配一个 notebook，结构统一：先用 numpy 把机制从零实现并对拍（5–6 个 worked 小节，每节都跑出可打印的验证与 assert），再做 3–4 道带 assert 判分的 ✏️ 练习（先给骨架，自己填，再对照 📖 参考答案），最后一个真实数据胶囊（用真实 GSM8K 配置或真实模型/scaling 的公开数字算一笔账，把纸面知识接到现实）。玩具环境的选择是刻意的：算术题（如「凑出目标数」「多步加减」）天然可自动判对错、可枚举从而能算出真实答对概率，是验证 RL/PRM/搜索算法正确性的理想试验台——既简单到能在 CPU 秒跑，又保留了「稀疏末端奖励 + 多步决策」这一推理任务的本质。

建议的学习节奏：先读完整章 HTML 建立直觉与数学框架，再打开 notebook 亲手实现。读和做缺一不可——只读会觉得「好像懂了」，真正动手写策略梯度、调组归一化、让 pass@k 估计的 assert 通过时，才会发现魔鬼藏在哪些细节里（优势的零均值、ratio 的 clip 边界、组合数的退化情形、难度路由的阈值）。这门课的深度正是为「动手」服务的。

配套先读：DeepSeek-R1（理解 R1-Zero 与 GRPO 的全局）、DeepSeekMath（GRPO 原文）、Lightman《Let's Verify Step by Step》（PRM）、Snell《Scaling Test-Time Compute》（TTC）。完整清单见 references.md。

✅ 学完整门课，你应该能：
  1. 解释从 RLHF 到可验证奖励 RL 的范式转移，说清规则奖励为什么近乎不可 hack、边界在哪；
  2. 写出结果奖励的策略梯度更新（含基线降方差），并用数值梯度对拍验证；论证长 CoT 为何能涌现；
  3. 从零推导并实现 GRPO 的组相对优势与裁剪 loss，讲清它如何去掉 critic、与 PPO 的异同；
  4. 用蒙特卡洛 rollout 自动标注步级软标签训一个玩具 PRM，理解 min/prod 聚合与 Goodhart 倒 U；
  5. 实现 best-of-N、加权多数投票、beam search，并写出 pass@k 的无偏估计、说清它与 pass^k 的区别；
  6. 模拟 TTC scaling 曲线、做 compute-optimal 预算分配与难度路由，画出「小模型+TTC vs 大模型」的帕累托前沿；
  7. 把以上 numpy 实现映射到 trl/verl 的训练与推理栈，知道下一步在真模型上怎么落地。
