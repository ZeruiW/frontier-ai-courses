1从训练信号到推理搜索

前三模块都在讲训练时——怎么用 RL 把推理能力塞进模型权重。这一模块开始转向推理时：给定一个已经训好的模型，怎么用额外的算力在生成时把它的能力榨出来？答案的核心工具是搜索——生成多个候选、用一个 verifier 把好的挑/引导出来。

这其实是 o1/R1 范式的第二条腿：OpenAI 的 o1 博客明确说「准确率随训练计算和测试时计算双双 scaling」。模块 01–03 是第一条腿（训练），本模块和下一模块是第二条腿（推理时计算）。一个关键事实让这条腿格外有用：对很多任务，「生成一个对的解」比「判断一个解对不对」难得多——所以「生成 N 个、挑出对的」往往比「一次就生成对的」便宜。

直白说

打个比方：让你写出一道难题的正确证明很难，但给你 20 份证明、让你挑出或看出哪份对要容易得多。搜索就是利用这个不对称：让模型多写几份（生成便宜、可并行），再用 verifier 挑（判别比生成易）。这也是为什么「采样 N 次取最好」能用算力换准确率——你把难的「生成对」问题，换成了相对易的「生成多个 + 挑出对」。

严谨说

形式上，本模块要区分两个根本不同的量：能力上界（这个模型有没有可能解出来，即 N 个样本里至少一个对的概率 pass@k）与可部署性能（在不知道答案的情况下，我们实际能选出对的解的概率，取决于 verifier 多准）。BoN 用一个 verifier 去逼近上界；majority vote 不需 verifier、靠答案聚合；二者各有适用，且都受「verifier/聚合有多可靠」支配。这是本模块的主轴。

这个「生成难、判别易」的不对称值得再追问一句：它为什么经常成立，又何时会失效？成立，是因为很多推理任务的答案有结构可检验——数学解可代回验算、代码可跑测试、证明可逐步核对，而「构造」一个满足这些约束的解，要在巨大的空间里搜索，本就比「检查」一个给定解难得多（这正是计算复杂度里「难解易验」在日常中的体现）。但它会失效在那些「判别本身也很难」的任务上：开放式写作的好坏、长程 agent 决策的对错、没有清晰 ground-truth 的领域——此时 verifier 本身就不可靠，搜索的天花板随之坍塌（第 6 节、模块 03 的 hacking 都源于此）。所以本模块所有方法的威力，都预设了「判别比生成易」这个前提；前提越成立，搜索越有效。

一句话抓住本模块：搜索 = 用「生成多个候选 + verifier 挑选/引导」把测试时算力换成准确率，前提是『判别比生成易』。pass@k 衡量「能力上界」（有没有可能），但它不可直接部署（部署得选一个答案，可你不知道哪个对）；真正能用的是 majority vote（靠答案众数）、best-of-N（靠 verifier 打分）、加权投票（二者结合）。本模块教你实现它们，并用无偏估计正确地度量它们。

2best-of-N

best-of-N：采样多个，verifier 选最好

最简单也最强力的搜索是 best-of-N（BoN，N 选优）：对同一问题独立采样 $N$ 个候选解，用一个 verifier（ORM 或聚合后的 PRM）给每个打分，选分最高的那个作为最终答案。

\[o^*=\arg\max_{i\in\{1,\dots,N\}}\ \text{verifier}(o_i)\]

BoN 的威力来自上一节的不对称：生成 $N$ 个解（便宜、可并行），把「生成对」的难题转成「从 $N$ 个里挑对」（判别相对易）。它的性能上界是 pass@N（如果 verifier 完美，总能挑出那个对的，只要 $N$ 个里有对的）；实际性能则取决于 verifier 多准——verifier 越接近完美，BoN 越接近 pass@N。

方法需要 verifier？性能上界实际能选对？可部署
随机选一个否pass@1= 单样本正确率✅（基线）
best-of-N是pass@N看 verifier 多准✅
pass@N（oracle）需真答案—100%（作弊）否（只是上界）

一个手算例子：verifier 多准，BoN 就多强

把三条曲线的关系算实。设单样本正确率 $p=0.3$、采 $N=8$ 个候选。天花板 pass@8 $=1-0.7^8\approx0.94$——这 8 个里有对的概率高达 94%。但能不能选出那个对的，全看 verifier。完美 verifier：实际准确率 $\approx$ pass@8 $\approx0.94$（有对的就一定挑出来）。瞎选（无 verifier）：实际准确率 $=$ pass@1 $=0.3$（随机抽一个）。一个不完美的 verifier（比如它只在 70% 的时候能把对的解排在错的之上）：实际准确率落在二者之间，约 $0.3+0.7\times(0.94-0.3)\approx0.75$（粗估）。看清楚了——同样 8 个候选、同样 94% 的「天花板」，verifier 从瞎选到完美，实际性能在 0.3 ~ 0.94 之间天差地别。BoN 的全部价值，都压在 verifier 这一个变量上，这也是为什么把 pass@N 当作 BoN 性能是评测里最常见的高估——它默认了一个现实中不存在的完美 verifier。

BoN 还有一个常被忽视的自我反噬效应，值得现在就埋下伏笔（第 6 节展开）：BoN 本质是对 verifier 做一次优化（在 $N$ 个候选里选它给最高分的）。$N$ 越大，越可能翻出一个「verifier 看走眼、给了虚高分但其实错」的候选——这是 verifier 版的 Goodhart（模块 03 的倒 U 在推理时的化身）。所以 BoN 的性能未必随 $N$ 单调上升：用一个不够好的 verifier，$N$ 过大反而可能让性能掉头向下。最优 $N$ 取决于 verifier 多准——这又一次把一切归结到「你的 verifier 有多可信」。

常见混淆：pass@N 不是 best-of-N 的性能，而是它的『天花板』。pass@N 假设有一个完美 oracle（知道真答案）来挑——这在部署时不存在（你要是知道答案就不用模型了）。真实 BoN 用一个不完美的 verifier，性能介于 pass@1（瞎选）和 pass@N（完美选）之间。把 pass@N 当作实际能达到的性能，是评测里最常见的高估错误。notebook 会让你量化这个 gap。

3多数投票与加权投票

多数投票与加权投票：不需要 verifier 的搜索

BoN 需要一个 verifier。但有一类任务（有唯一最终答案，如数学题的数值答案）可以完全不用 verifier——直接对 $N$ 个解的最终答案取众数。这就是 self-consistency（自洽 / 多数投票，Wang 2022）。

原理简单而深刻：模型可能通过不同的推理路径得到答案，但对的路径更可能殊途同归到同一个（正确）答案，错的路径则各错各的、答案分散。于是正确答案往往是出现频率最高的那个。投票把「分散的错」过滤掉，让「集中的对」胜出。

多数投票：对的答案殊途同归，错的各错各的 解1 -> 答案 42 ┐ 解2 -> 答案 42 ├─ 42 出现 3 次 ◀── 众数=42 (正确) 解3 -> 答案 42 ┘ 解4 -> 答案 17 (某种错法) 解5 -> 答案 99 (另一种错法) => 正确答案集中、错误答案分散 => 投票选出正确答案 (无需 verifier!)

直白说

多数投票像民意调查：问 100 个人同一道题，对的人往往答出同一个数，错的人五花八门。取最多人说的那个，大概率是对的。妙在完全不需要「裁判」——只需要能比较「最终答案是否相同」。这是它最易部署的原因（数学/代码题尤其适合）。

严谨说

加权投票（weighted majority vote）是升级版：每条解不是「一票」，而是按 verifier 分数加权投票——$\text{vote}(a)=\sum_{i:\,\text{ans}(o_i)=a}\text{verifier}(o_i)$，选总权重最高的答案。它结合了投票的鲁棒（多条解相互印证）与 verifier 的判别力（高质量解权重更大），实践中常优于纯投票或纯 BoN——因为它既不像 BoN 那样把宝全押在单条「最高分」解上（可能 verifier 看走眼），也不像纯投票那样无视解的质量差异。

三者的关系值得记牢：BoN信任 verifier，选单条最高分解；majority信任答案的集中度，无视 verifier；weighted majority兼取——用 verifier 加权、但靠多条解的答案聚合来抗单点误判。选哪个取决于：有没有 verifier、verifier 多准、答案是否可比较。notebook 会构造例子让你看到加权投票如何在 verifier 有噪声时胜过裸 BoN。

多数投票也有它致命的失效模式，必须警惕：当模型有系统性偏见（一致地错向同一个错误答案）时，投票会自信地放大这个错误。比如一道题模型 70% 的时候算出同一个错答案、只有 30% 算对，投票会笃定地选那个错的。投票放大的是「一致性」——而一致的对会被放大，一致的错同样会被放大。这正是它和 BoN 互补的深层原因：BoN（靠 verifier 判别）能在「多数错、少数对」时仍挑出对的（只要 verifier 识货），而投票在这种情形必然失败。没有系统偏见、错误分散时用投票；可能有系统偏见时靠 verifier——这是部署时的关键判断。

4pass@k vs pass^k 与无偏估计

pass@k vs pass^k 与无偏估计

要度量搜索方法，必须先把指标搞对。两个核心指标方向相反、各有用途：

指标定义随 k衡量适用场景
pass@kk 个样本至少一个对单调升能力上界 / 覆盖率有 verifier 能筛（代码可跑测试）
pass^kk 个样本全部对单调降稳定性 / 可靠性多步 agent（每步都要对）

$\text{pass}@k$ 关心「有没有可能成功」（有一个对就行），随 $k$ 增加单调上升——采样越多，覆盖越广，撞对的机会越大（Brown 2024 发现它常随 $k$ 近似幂律上升）。$\text{pass}^k$（all-correct@k）关心「能不能次次成功」，随 $k$ 单调下降——对一个 $k$ 步都要做对的 agent，单步正确率 $p$ 下整体成功率是 $p^k$，步越多越脆。两者是覆盖率与可靠性的对立面，混用会得出荒谬结论。

现在是本模块最容易出错、也最重要的技术点：怎么从有限样本无偏地估计 pass@k。直觉上，用 $n$ 个样本里 $c$ 个正确算出 $\hat p=c/n$，再用 $1-(1-\hat p)^k$？错！这是有偏的（尤其小样本、小 $c$ 时偏差大）。Chen 2021（Codex）给出了正确的无偏估计：

\[\widehat{\text{pass@}k}=1-\frac{\dbinom{n-c}{k}}{\dbinom{n}{k}}\]

它的含义很美：$\binom{n-c}{k}/\binom{n}{k}$ 是「从 $n$ 个样本里抽 $k$ 个、全抽到错的（避开全部 $c$ 个正确的）」的概率；1 减去它就是「抽 $k$ 个里至少一个对」的概率——这正是 pass@k 的定义，且无偏（直接在有限样本上数组合，不经过 $\hat p$ 这个有偏中介）。当 $n-c

一个数字例子

具体看偏差有多大。设 $n=8$ 个样本、$c=1$ 个正确，估 pass@4。无偏：$1-\binom{7}{4}/\binom{8}{4}=1-35/70=0.5$。有偏：$\hat p=1/8=0.125$，$1-(1-0.125)^4=1-0.875^4\approx 0.414$。两者差了近 9 个百分点（0.5 vs 0.414）！差异来自：无偏公式直接问「抽 4 个里至少含那 1 个对的概率」（组合计数，精确）；有偏公式把「$\hat p=0.125$」当真实概率再代入，而 $\hat p$ 在 $c=1$ 这种小计数下是个方差很大的随机估计，经过凸函数 $1-(1-x)^4$ 放大后系统性偏低。在难题（$c$ 小）、样本不多（$n$ 小）的评测里，这个偏差足以让一个模型看起来比另一个差——而其实只是估计方法错了。

别用 1−(1−p̂)^k

为什么 $1-(1-\hat p)^k$ 有偏？因为 $\hat p=c/n$ 本身是随机变量，而 $1-(1-x)^k$ 是 $x$ 的非线性（凸）函数，由 Jensen 不等式 $\mathbb{E}[g(\hat p)]\ne g(\mathbb{E}[\hat p])$。组合数公式则是对「pass@k 事件」本身做无偏计数，绕开了这个非线性中介。做评测时务必用组合数版——尤其在 $c$ 小（难题）、$n$ 不大时，两者差异可达数个百分点，足以颠倒模型排名。notebook 会让你亲眼看到这个偏差。

5beam search 与引导搜索

beam search 与 verifier 引导搜索

BoN 和投票都是独立采样完整解再筛（并行 TTC）。但我们也可以让 verifier 在生成过程中就介入，更系统地探索——这需要一个能给部分解打分的 verifier（正是 PRM！）。最经典的是 beam search（束搜索）。

beam search 维持一个宽度为 $b$ 的「候选前缀集合」（beam）。每一步：把 beam 里每个前缀各扩展出若干后续，得到一批更长的部分解，用 PRM 给它们打分，只保留分数最高的 $b$ 个进入下一步。如此逐步生长，最后从 beam 里选最优完整解。

beam search (宽度 b=2) + PRM 打分剪枝 步1: [A](.6) [B](.5) [C](.3) --PRM选top2--> 保留 A,B 步2: A->[AX](.7) A->[AY](.4) B->[BX](.5) B->[BY](.6) --PRM选top2--> 保留 AX,BY 步3: AX->... BY->... (继续生长 beam) => 用 PRM 在『过程中』剪掉没希望的分支，把算力集中在有希望的前缀上

直白说

beam search 像带向导的探险：不是漫无目的乱走（独立采样），而是每到一个岔路口，让向导（PRM）评估每条路的前景，只沿最有希望的几条继续。比独立采样更系统——算力不浪费在明显的死路上。

严谨说

更激进的是 MCTS（蒙特卡洛树搜索，AlphaGo 系）：用「选择-扩展-模拟-回传」在解空间建树，把 PRM 当价值函数、生成当策略，能深度探索并平衡 explore/exploit。它比 beam 更强但贵得多（要建树、多次模拟）。Tree of Thoughts（Yao 2023）是把推理组织成可搜索树的代表。这些都属于 verifier-guided search：用 verifier 引导生成，而非仅在末端筛选。

为什么 beam 比 BoN「省」？算一笔账感受一下。BoN 要让 $N$ 个候选各自独立走完整条——若每条 20 步、采 64 条，就是 $64\times20=1280$ 步生成，且其中大量算力花在「一开头就走歪、注定错」的解上（它们照样被生成到底）。beam（宽度 $b=4$）则在每一步就用 PRM 砍掉没希望的前缀，只让 4 条有前途的前缀继续生长——同样探索到「第 20 步」的深度，花的生成量远少于让 64 条全程跑完，因为死路在很浅处就被剪掉、算力始终集中在 PRM 看好的分支上。这就是「剪枝集中算力」的含义：用 verifier 在过程中的判断，把本会浪费在死路上的生成量省下来。

一个重要的权衡：引导搜索（beam/MCTS）比独立采样（BoN）更省样本（剪枝集中算力），但更依赖 verifier 的质量——如果 PRM 在中途打分不准，会过早剪掉其实有希望的分支（false negative）或在死路上浪费（false positive）。而 BoN/投票虽然「笨」（不剪枝），却更鲁棒（每条解独立走到底，不会被中途的错误评分误杀）。verifier 越可信，越该用引导搜索；越不可信，越该用独立采样 + 投票——这又一次呼应「方法的选择取决于 verifier 多可靠」这条主线。

6实践组合与陷阱

实践组合与陷阱

把这些方法落到实处，有几条经验与陷阱：

  1. 方法选择取决于任务结构。有唯一可比较答案（数学数值）→ majority/weighted majority 极强且免 verifier；解可自动验证（代码跑测试）→ pass@N 可真实达到（用测试当 oracle）；都没有 → 只能靠学习的 verifier 做 BoN，且受 verifier 质量与 hacking 限制。
  2. 温度要调高一点。搜索依赖多样性——若温度太低、$N$ 个样本几乎一样，搜索就退化成单样本。BoN/投票通常用比最终作答更高的温度（如 0.6–1.0）来保证候选有区分度、覆盖更多解法。
  3. verifier 也会被 hack。BoN 是对 verifier 的一次「优化」（选它给最高分的）——$N$ 越大，越可能选到「verifier 看走眼给高分但其实错」的解（这叫 verifier 的 over-optimization，BoN 版的 Goodhart）。所以 $N$ 不是越大越好，超过某点 BoN 性能会因 hacking 而下降。
  4. majority 的失效模式。当模型有系统性偏见（一致地错向同一个答案）时，投票会自信地选出错误答案——多数投票放大的是「一致性」，而错误若一致，它放大错误。这是它和 BoN 互补的原因。
  5. 正确度量。报告 pass@k 用组合数无偏估计；区分 pass@k（上界）与实际可部署性能（BoN/投票）；区分 pass@k（覆盖）与 pass^k（可靠）。度量错了，结论全错。

这些不是孤立技巧，而是同一个判断的不同侧面：你的 verifier/答案聚合有多可信，决定了你该把算力投在「选得更准」（强 verifier + BoN/引导搜索）还是「投得更稳」（投票 + 多样性）。本课的 numpy 实现会把 BoN、投票、加权投票、beam、pass@k 估计都做对并对拍，让你对「每种方法在什么时候赢」有量化的直觉——这正是下一模块「把算力花在刀刃上」（compute-optimal）的基础。

7研究前沿与开放问题

研究前沿与开放问题

测试时搜索是推理模型当前最热的方向之一，前沿在快速演进：

  • 生成易、验证难的瓶颈。Brown 2024 显示采样足够多时 pass@k 极高（覆盖率惊人），但瓶颈转移到了「怎么从海量样本里挑出对的」——verifier 的质量成了天花板。如何训练/获得更强、更难 hack 的 verifier 是核心问题。
  • verifier 的过度优化。BoN 的 $N$ 越大越可能 hack verifier（BoN 版 Goodhart）。最优 $N$、verifier 的标定（calibration）、用集成/对抗缓解 hacking，都是活跃方向。
  • 搜索 vs 训练的边界。能力可以「训进权重」也可以「搜索时榨出」，二者可互相替代（R1 把很多搜索能力内化进了模型，使它推理时不需复杂搜索）。最优的训练/搜索分工是开放问题，直通模块 05。
  • 过程 verifier 引导的搜索。PRM-guided beam/MCTS 的效率高度依赖 PRM 的步级标定与策略匹配。把 PRM（模块 03）与搜索（本模块）做到协同，是把测试时计算用到极致的关键。
  • 自我修订 vs 重采样。并行（BoN/投票）与串行（self-refine：读自己上一版改进）的最优配比随难度变化（Snell 2024）。什么任务该重采、什么该修订，是模块 05 compute-optimal 的一部分。

贯穿本模块的一条主线，值得在结尾点透：搜索的每一种方法，本质都是在『生成的多样性』与『挑选的可靠性』之间做文章。BoN 押注挑选（靠 verifier）；投票押注多样性下的统计规律（对的集中）；加权投票兼顾两者；引导搜索（beam/MCTS）则在生成过程中就用挑选来塑造多样性。而它们共同的天花板，是verifier/聚合的可靠性——这把我们带回贯穿全课的暗线：信号越可信，越该激进地用它来挑（强 verifier + BoN/引导搜索）；越不可信，越该退回到稳健的统计聚合（投票 + 多样性）。测试时搜索不是一堆孤立技巧，而是『在不确定的判别力下，如何把算力最稳地变成正确答案』这一问题的不同答案。下一模块把这个问题再推一层：不仅怎么搜，还有搜多少、算力怎么在题目间分配。

奠基与前沿：Cobbe 2021（GSM8K verifiers）（BoN 重排的源头）、Wang 2022（Self-Consistency）（多数投票）、Brown 2024（Large Language Monkeys）（pass@k 随采样幂律上升 + 验证瓶颈）、Chen 2021（Codex）（pass@k 无偏估计）、Yao 2023（Tree of Thoughts）（树搜索）。下一模块把搜索的「该花多少算力、怎么分配」正式化为 test-time compute scaling 与 compute-optimal。完整清单见 references.md。
