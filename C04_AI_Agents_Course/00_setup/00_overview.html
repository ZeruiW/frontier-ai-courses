1什么是 agent？为什么 agentic 评测是当前评测的最前线

聊天机器人是"文本进、文本出"的一次性映射；agent 则是一个感知-行动系统： 以 LLM 为大脑、以工具（tools）为手、在一个循环（loop）里反复"思考 → 行动 → 观察"， 并把历史轨迹存进记忆 / 上下文（memory / context），直到完成任务或触发停止条件。四个组件，一个循环：

┌──────────────────────────── AGENT ────────────────────────────┐ │ │ 任务 task ─►│ ┌──────────┐ action (工具调用) ┌─────────────────┐ │ │ │ LLM │ ──────────────────────► │ Tools │ │ │ │ (大脑) │ │ 代码/文件/检索/… │ │ │ └────▲─────┘ └────────┬────────┘ │ │ │ observation │ 执行 │ │ │ (工具结果回灌) ▼ │ │ ┌────┴──────────┐ ┌─────────────────┐ │ │ │ Memory / 上下文│ ◄───────────────── │ Environment │ │ │ │ (轨迹历史) │ 状态变化 │ (沙箱/repo/GUI) │ │ │ └───────────────┘ └─────────────────┘ │ └───────────────────────────────────────────────────────────────┘ 循环：think → act → observe → think → … → 提交结果 / 超时停止

直白讲

给 LLM 一双手（工具）、一个能反复行动的循环、一份不断累积的"事情做到哪了"的记录，它就从"答题机器" 变成了"做事系统"：能自己跑代码、读报错、改了再跑，直到任务完成。agent 的能力上限不只取决于模型， 还取决于工具、循环和记忆这套脚手架（scaffolding）怎么搭。

严谨讲

agent 可形式化为部分可观测环境中的策略 $\pi_\theta(a_t \mid \tau_{<t},\, g)$：给定目标 $g$ 与历史轨迹 $\tau_{<t}=(a_1,o_1,\dots,a_{t-1},o_{t-1})$，输出下一个动作 $a_t$（一次工具调用），环境返回观察 $o_t$， 直到终止。一次完整交互称为一个 episode，其记录称为 trajectory（轨迹） —— 它是 agentic 评测的基本分析单元 [Yao et al. 2022, ReAct]。

为什么 agentic 评测是现在评测工作的最前线？三个原因：

  • 静态基准饱和：MMLU、HumanEval 这类"单轮问答/单函数补全"基准已被前沿模型逼近上限，区分度持续衰减；前沿能力的增量越来越多地体现在多步、长程、与环境交互的任务上 —— 只有 agentic 评测能测到。
  • 安全决策依赖它：前沿实验室的安全框架（RSP / Preparedness 类）把"是否触发更高安全等级"押在危险能力评测（dangerous capability evals）上，其中自主行动能力（autonomy）必须用 agent 任务来测。
  • 方法论尚未定型：非确定性、部分得分、成本核算、任务难度刻度……每一项都还是开放问题，这正是研究机会所在。
METR 的核心业务就是这件事：构建标准化的 autonomy evals（自主能力评测）， 度量前沿模型完成长程任务的能力，为实验室与政府的部署决策提供证据。其 2025 年的 time horizon 工作 [Kwa et al. 2025] 发现：模型能以 50% 成功率完成的任务长度（按人类专家耗时计）约每 7 个月翻一倍 —— 这条曲线已成为讨论 AI 自主能力进展时被引用最多的单一结果。本课程模块 06 将完整复现这套方法论。

3学习法：HTML → notebook → ✏️ 练习，从零造轮子

每个模块的固定节奏：

  1. 读 HTML 讲解（如本页）：建立动机、理论框架、关键论文坐标 —— 知道"为什么这样设计"。
  2. 跑 notebook：逐 cell 执行，观察真实输出，改参数做实验 —— 知道"它实际怎么动"。
  3. 做 ✏️ 练习（必做，不可跳过）：每本 notebook 有 2–4 道练习，补全 # TODO 后运行自测 cell，assert 全过即达标。文末附 📖 参考答案，先自己做再对照。
本课大量"从零造轮子"，并且刻意禁用 LangChain / LlamaIndex / AutoGen 等 agent 框架。 所有循环、registry、harness 都用裸 Python（外加 numpy / transformers）手写。理由：框架把 agent 的核心机制 ——提示拼装、工具分发、错误回灌、停止条件——封装在抽象层之下，而做评测研究恰恰需要看见并控制这些机制： 你要能回答"这个失败是模型弱，还是 scaffold 烂？"。框架 API 会过时，循环与评测的原理不会。 学完本课再回头看任何框架，你会发现它们只是这些机制的不同包装。

5安全立场声明（必读）

本课程的一切 agent 实验都运行在 toy 环境或 subprocess 沙箱中，绝不操作真实系统。
  • agent 能"动"的文件系统、邮件 API、网页，全部是课程自带的假环境（toy environment）；执行代码一律走带 timeout 的 subprocess 沙箱，可随时杀掉。
  • 不给 agent 你的 shell、不给真实浏览器、不给生产凭据。课程代码也不会要求这些。
  • 模块 08 及散布各模块的安全内容均为防御与评测视角：演示 prompt injection、数据外渗等攻击模式是为了教你检测、监控、防御；所有 payload 都是良性占位（如让模型输出 "HELLO"），不提供任何可操作的有害内容。
这不只是合规姿态，也是方法论立场：METR 风格的危险能力评测同样必须在受控沙箱中进行 —— 你在本课养成的隔离习惯，就是将来做真实评测的操作规范。

横跨三种形态的是两条主线，也是本课的重心：评测（这个 agent 到底多能干？花多少钱？多可靠？） 与安全（它会怎么坏？怎么监控？）。两条主线在 METR 的 autonomy evals 中合流： 用标准化任务族测量模型的自主行动能力，作为"是否接近危险能力阈值"的证据。其中两个核心统计量本课会反复出现，先混个脸熟：

① pass@k —— $n$ 次独立运行中 $c$ 次成功时，"$k$ 次尝试至少成功一次"概率的无偏估计 [Chen et al. 2021]：

$$ \widehat{\text{pass@}k} \;=\; \mathop{\mathbb{E}}_{\text{tasks}}\!\left[\, 1-\frac{\binom{n-c}{k}}{\binom{n}{k}} \,\right] $$

推导直觉：从 $n$ 次运行中均匀抽 $k$ 次，全部落在 $n-c$ 个失败里的概率是 $\binom{n-c}{k}/\binom{n}{k}$，取补即"至少一次成功"。 注意它的镜像指标 pass^k（$k$ 次全部成功，每任务为 $p^k$）度量的是可靠性而非能力上限 [Yao et al. 2024, τ-bench] —— 部署决策往往更关心后者。模块 06 推导两者的方差与样本量要求。

② 50% time horizon —— 把每个任务标定一个"人类专家耗时" $t$，用 logistic 模型拟合模型成功率随 $t$ 的衰减 [Kwa et al. 2025]：

$$ P(\text{success}\mid t) \;=\; \sigma\!\big(\beta\,(\log t_{50} - \log t)\big), \qquad \sigma(x)=\tfrac{1}{1+e^{-x}} $$

$t_{50}$ 即该模型的 50% time horizon：它能以一半把握完成的任务时长。 这个标量把"agent 多能干"压成一条可以跨年比较的曲线 —— 也正是"每 7 个月翻倍"结论的来源。模块 06 将用模拟数据完整复现这个拟合。

路线图式阅读：agent 机制看 [Yao et al. 2022, ReAct] 与 Anthropic 的工程综述 [Anthropic 2024, Building Effective Agents]； 评测方法论看 [Kwa et al. 2025] 与 [Kapoor et al. 2024, AI Agents That Matter]（成本-准确率必须联合报告）； 安全主线看 [Greenblatt et al. 2023, AI Control]。全部条目在 references.md。

7研究前沿与开放问题

  • 评测的保质期：time horizon 每 ~7 个月翻倍 [Kwa et al. 2025]，意味着任务集会快速"被穿透"。如何设计一个两年后仍有区分度的任务族？难度刻度（人类耗时）是不是唯一可扩展的标尺？
  • benchmark 与真实世界的 gap：SWE-bench 需要人工复核才能变成 Verified [OpenAI 2024]；数据污染、对特定 scaffold 的过拟合、"任务在训练集里见过"都会让数字虚高。评测者的第一反射应是怀疑数字。
  • 非确定性与统计严谨：同一 agent 同一任务多次运行结果不同。单次运行的"X% 成功率"在统计上几乎无意义 —— 需要多少次重复、报告什么区间？pass@k 与 pass^k 的选择如何随部署场景改变？（模块 06）
  • 能力引出（elicitation）与 sandbagging：评测测到的是"模型在这套 scaffold 下表现出的能力"的下界；模型也可能在被评测时策略性地藏拙 [van der Weij et al. 2024]。安全评测低估能力的代价是不对称的 —— 这是 autonomy evals 最深的方法论难题。
  • 成本作为一等公民：抬高 pass@k 只需多采样花钱。不联合报告 cost-per-success，排行榜就会奖励烧钱 [Kapoor et al. 2024]。怎样的成本-能力前沿才是公平的模型比较？
