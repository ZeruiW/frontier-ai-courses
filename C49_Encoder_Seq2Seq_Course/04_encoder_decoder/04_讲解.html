1为什么需要第三种形态

前三个模块的世界里，输出要么是一个标签、要么是原文的一个片段。但有一大类任务的输出是一段新的文本：翻译、摘要、改写、结构化转换、语法纠错。这类任务的输入和输出是两个不同长度、不同语言/形式的序列——这正是 sequence-to-sequence（seq2seq）问题。

这里有个容易被忽略的历史事实：Transformer 最初就是为 seq2seq 设计的。Vaswani et al. 2017 的标题是《Attention Is All You Need》，解决的问题是机器翻译，架构是 encoder-decoder。BERT（只取 encoder）和 GPT（只取 decoder）都是后来的裁剪。所以本模块讲的不是「另一种变体」，而是回到原点。

方案怎么做 seq2seq问题
encoder-only（BERT）❌ 做不了无法自回归生成（模块 01 的三层原因）
decoder-only（GPT）把输入输出拼成一个序列 [输入][SEP][输出]，因果掩码输入部分只能被单向编码——读到第 3 个词时看不到第 10 个词
encoder-decoder输入过双向编码器，输出自回归解码，中间用 cross-attention 连接参数多一套，训练更复杂
prefix-LM（GLM/UniLM）一个模型，前缀双向、后缀因果折中方案；表达力接近 enc-dec，参数只有一套

直白说

decoder-only 做 seq2seq 的那个缺陷值得说清楚：输入被单向编码。翻译一个长句时，模型读到源句第 3 个词时看不到第 30 个词，而后者可能决定前者的译法（比如中文的「他/她」需要看后文才知道性别）。encoder-decoder 让输入享受完整的双向注意力，理论上更适合「输入是给定的、需要被充分理解」的任务。

严谨说

但实践给出了一个更微妙的答案。decoder-only 虽然对输入是单向的，但它可以通过足够的深度和规模弥补——高层的表示会把后文信息「回传」到前面位置的后续处理中（虽然不是直接注意）。加上 decoder-only 的训练与推理形式完全统一（都是自回归）、预训练数据无限（任何文本都能用）、KV 缓存实现简单，这些工程优势在规模上来后压倒了架构上的理论劣势。这就是为什么 2023 年后主流 LLM 几乎全是 decoder-only——不是 encoder-decoder 不好，是它的优势不够大而代价明确。

但 encoder-decoder 并没有消失，它在两类场景里仍然是更优解：①输入远长于输出的任务（长文档摘要——编码器只需跑一次，解码器在短输出上自回归，而 decoder-only 每生成一个 token 都要对全部输入做注意力）；②需要极致效率的专用任务（翻译、语法纠错——一个 220M 的 T5-base 就能做得很好，不需要 7B）。模块 05 会把这两笔账算清楚。

2架构：三种注意力的分工

输入 x = [x1 x2 x3 x4] 输出 y = [y1 y2 y3] ┌─────── ENCODER (N 层) ────────┐ ┌────── DECODER (N 层) ───────┐ │ │ │ │ │ ① self-attention │ │ ② masked self-attention │ │ 双向：每个 x 看到所有 x │ │ 因果：y_t 只看 y_<t │ │ ↓ │ │ ↓ │ │ FFN │ │ ③ cross-attention │ │ ↓ │ │ Q 来自解码器 │ │ (重复 N 层) │─────▶│ K,V 来自**编码器输出** │ │ ↓ │ 只算 │ → y_t 能看到全部 x │ │ 编码器输出 memory (n,d) │ 一次! │ ↓ │ └───────────────────────────────┘ │ FFN │ │ (重复 N 层) │ │ ↓ │ │ 输出投影 → P(y_t | y_<t, x)│ └─────────────────────────────┘ 关键: **编码器只跑一次**，其输出被解码器的每一步、每一层复用。 这就是「输入长、输出短」场景下 enc-dec 的效率优势来源。

cross-attention：唯一的新组件

整个 encoder-decoder 里，唯一你在前面模块没见过的东西就是 cross-attention。而它的公式和 self-attention 一模一样，只是 Q、K、V 的来源不同：

\[\text{CrossAttn}(H_{dec}, M_{enc}) = \text{softmax}\!\left(\frac{(H_{dec}W_Q)(M_{enc}W_K)^T}{\sqrt{d}}\right)(M_{enc}W_V)\]
Q 来自K, V 来自掩码形状
编码器 self-attn编码器隐状态编码器隐状态双向（全 1）(n, n)
解码器 self-attn解码器隐状态解码器隐状态因果（下三角）(m, m)
cross-attn解码器隐状态编码器输出全 1（输出可看全部输入）(m, n)

直白说

cross-attention 的注意力矩阵是 (m, n)——输出位置 × 输入位置。这个矩阵有一个很好的可解释性：它近似于词对齐。翻译时看这个矩阵，你能看到「生成这个目标词时，模型主要在看源句的哪几个词」。这在神经机器翻译时代是标准的可视化手段，也是「注意力即对齐」这个直觉的来源。

严谨说

工程上有一个重要性质：cross-attention 的 K、V 只依赖编码器输出，在整个解码过程中不变，所以可以算一次、缓存起来。而解码器 self-attention 的 KV 缓存要随生成逐步增长。这两种缓存的生命周期不同，是 enc-dec 推理实现里的一个关键细节——也是它相对 decoder-only 的效率优势所在：decoder-only 每步都要对「输入+已生成」的全部 token 做注意力，而 enc-dec 的输入部分是固定的预计算结果。

参数量的账要算清楚：encoder-decoder 的参数量约是同深同宽 encoder-only 的 2.3 倍——编码器 N 层 + 解码器 N 层，且解码器每层多一个 cross-attention（4 个 d×d 矩阵）。所以 T5-base（12+12 层）是 220M，而 BERT-base（12 层）是 110M。比较不同形态时必须在同等参数量或同等 FLOPs 下比，否则结论没有意义——这是文献里常见的不公平比较来源。

3T5：把一切都变成文本到文本

T5（Text-To-Text Transfer Transformer）的核心主张极其简单，但影响深远：所有 NLP 任务都可以表述成「输入一段文本、输出一段文本」。

# 同一个模型、同一套权重、同一个损失函数，靠任务前缀区分：

"translate English to German: That is good."      →  "Das ist gut."
"cola sentence: The course is jumping well."      →  "not_acceptable"
"stsb sentence1: ... sentence2: ..."              →  "3.8"          # 回归也变成生成数字!
"summarize: state authorities dispatched..."      →  "six people hospitalized after..."
"question: What is 42? context: ..."              →  "the answer to everything"

直白说

这个统一带来三个好处：①一个模型多任务（不用为每个任务建头）；②任务间迁移（多任务预训练让低资源任务受益）；③接口极简（输入输出都是字符串，工程上极好集成）。这套「万物皆文本」的思路，后来被指令微调（instruction tuning）和 LLM 的 prompt 范式完全继承——今天你给 GPT 写 prompt 的方式，思想上就是 T5 的任务前缀。

严谨说

代价也要看清：把分类变成生成，你就失去了输出空间的约束。分类头的 softmax 保证输出必是 C 个类之一；生成式则可能吐出 "acceptabl"（拼错）、"maybe"（不在类集里）、或者一段解释。实践中需要受约束解码（把生成限制在合法标签集上）或后处理匹配。回归任务尤其别扭——T5 把 STS-B 的连续分数量化成 "1.0" "1.2" ... "5.0" 这样的字符串，本质上是把回归退化成了 21 类分类。这是「统一接口」的真实成本。

Span corruption：T5 的预训练目标

T5 的预训练目标不是 BERT 式的逐 token 掩码，而是 span corruption——连续片段整体挖掉，用一个哨兵 token 代替，让解码器把它们依次生成出来。

原文: Thank you for inviting me to your party last week . ① 随机挑若干**连续片段**（平均长度 3），总共覆盖约 15% 的 token ┌───┐ ┌──────────┐ Thank you for inviting me to your party last week . └───┘ └──────────┘ ② 编码器输入：每个片段整体换成一个**唯一的哨兵 token** "Thank you <X> me to your <Y> week ." ③ 解码器目标：依次生成 哨兵 + 对应的原片段，最后一个哨兵收尾 "<X> for inviting <Y> party last <Z>" 对比 BERT 的 MLM: BERT: "Thank you [MASK] me to your [MASK] [MASK] ." → 逐位置预测原词 T5: 把连续片段整体挖掉 → 目标序列**短得多**（只含被挖内容，不含未挖部分）
设计T5 的选择为什么
片段而非单 token平均长度 3 的连续片段更难、更接近下游生成任务；也更贴近「填一段话」而非「填一个词」
哨兵 token<extra_id_0>…<extra_id_99>，100 个专用 token让模型知道「这里挖了一段」以及「挖的是第几段」
目标只含被挖内容不重复输出未被挖的部分目标序列短 → 解码计算量小得多，训练效率显著提升
掩码比例 15%、片段长 3论文做了系统消融更高比例或更长片段都会降低效果

「目标序列只含被挖内容」这个设计常被忽略，但它是 T5 效率的关键。如果让解码器重建整句（BART 的做法之一），目标长度 = 输入长度；只输出被挖片段，目标长度 ≈ 输入的 15%+哨兵。解码器的计算量与目标长度成正比，所以这一个设计就省了约 5 倍的解码计算。notebook 会把这笔账算出来。

4BART：去噪自编码器的多种噪声

BART 与 T5 同期、思路相近但不同：用多种噪声破坏原文，让模型重建完整原文。它是一个标准的去噪自编码器（denoising autoencoder）。

噪声类型做法教会模型什么
token masking随机 token 换成 [MASK]（同 BERT）局部词汇恢复
token deletion随机删除 token（不留占位符）模型必须自己判断哪里少了东西——比 masking 难
text infilling连续片段换成单个 [MASK]（片段长服从 λ=3 的泊松，可以为 0）必须预测「缺了多少个词」——BART 论文认为这是最有效的单项
sentence permutation打乱句子顺序篇章级连贯性
document rotation把文档旋转到从某个随机 token 开始识别文档真正的开头

直白说

BART 与 T5 的核心区别：BART 重建整个原文，T5 只生成被挖的片段。BART 的目标更「完整」（解码器要输出整篇），因此天然更适合摘要这类需要生成完整流畅文本的任务；T5 的目标更「高效」（解码器只输出 15%），训练更快。两者在下游微调后的效果相近，选哪个更多取决于生态与可用 checkpoint。

严谨说

BART 还有一个常被引用的实用发现：text infilling（片段换单个 mask，长度未知）是最有效的单项噪声。原因在于它同时训练了三种能力——恢复内容、判断缺失长度、以及在长度不确定时保持流畅。相比之下 token masking 泄漏了「缺了几个词」这个信息（有几个 [MASK] 就缺几个），任务更简单。这与 T5 span corruption 的哨兵设计形成对照：T5 的哨兵也不指示长度，所以两者在这一点上是一致的。

BART 的一个实现细节容易踩坑：解码器的起始 token。BART 用 </s>（eos）作为 decoder 的第一个输入 token，而不是常见的 <s>（bos），这是历史遗留。自己实现 teacher forcing 时如果 shift 错了一位，训练能跑但效果会莫名很差——因为模型学的是「预测当前 token」而不是「预测下一个 token」。这类 off-by-one 是 seq2seq 实现里最常见的 bug，notebook 会用一个 assert 把它钉死。

5训练：teacher forcing 与 exposure bias

teacher forcing：并行训练的关键

自回归生成在推理时是串行的（生成 y_t 需要 y_{t-1}），但训练时不能这么做——太慢，而且早期模型生成的东西全是垃圾，学不到东西。teacher forcing 的做法是：训练时把真实的目标序列右移一位喂给解码器，让所有位置的预测并行计算。

目标序列 y = [Das, ist, gut, </s>] 训练时（teacher forcing，所有位置并行）: decoder 输入: [<s>, Das, ist, gut ] ← 真实 y 右移一位 decoder 目标: [Das, ist, gut, </s>] ← 原始 y 因果掩码保证位置 t 看不到 t 及之后的目标 → 一次前向算出全部 4 个位置的损失 推理时（自回归，串行）: step 1: 输入 [<s>] → 生成 "Das" step 2: 输入 [<s>, Das] → 生成 "ist" ← 用的是**自己生成的** Das step 3: 输入 [<s>, Das, ist] → 生成 "gut" step 4: 输入 [<s>, Das, ist, gut] → 生成 "</s>" 停止 ⚠️ 训练时喂真实前缀，推理时喂自己生成的前缀 —— **这个不一致就是 exposure bias**。

exposure bias：训练-推理的分布偏移

直白说

问题在于：训练时模型永远看到完美的历史前缀，从未见过自己犯错后的状态。推理时一旦生成了一个不太对的词，后续的输入就落在了训练分布之外，模型不知道怎么办，错误会累积放大。这就是 exposure bias（暴露偏差，Ranzato et al. 2016）。典型症状：生成前几个词很好，越往后越离谱；或者陷入重复循环（「非常非常非常……」）。

严谨说

缓解方案有几类，但都不完美：①scheduled sampling（训练时以一定概率用模型自己的预测替换真实前缀，概率随训练递增）——简单有效，但破坏了并行性且理论上有偏；②序列级训练（用 REINFORCE 或 minimum risk training 直接优化 BLEU 等序列指标）——理论上更对，但方差大、训练不稳；③在解码时缓解（beam search 通过保留多条候选降低单步错误的影响；重复惩罚直接堵住退化模式）。实践中第三类用得最多，因为它零训练成本。

exposure bias 这个概念在 LLM 时代依然重要，只是换了名字。RLHF 中的「on-policy 采样」正是在解决同一个问题——让模型在自己生成的分布上被训练，而不是只在人类数据的分布上。DPO 与 PPO 的一个核心区别也在这里（PPO 是 on-policy，DPO 用的是离线偏好数据）。C02/C22 讲这些方法时，你可以回想这里：它们都在解决「训练分布 ≠ 推理分布」这个同一个古老问题。

6解码：beam search 与它的陷阱

训练完了，怎么生成？贪心（每步取 argmax）是最简单的，但它是短视的——当前最优的词可能导致后续全盘皆输。

贪心的失败模式（概率是编造的示意）: step 1: P(the)=0.4 P(a)=0.35 P(dog)=0.25 → 贪心选 "the" step 2: 已选 "the" 后，最好的续接只有 P=0.1 → 总分 0.4 × 0.1 = 0.04 但若第一步选了 "a"，续接可以有 P=0.8 → 总分 0.35 × 0.8 = 0.28 ← 更好! 贪心看不到这一步，因为它在 step 1 就把 "a" 扔了。 beam search (beam=3): 每步保留 3 条最优部分序列，不急着扔 step 1: [the(0.4), a(0.35), dog(0.25)] step 2: 对每条各扩展全词表 → 3×V 个候选 → 按累积 log 概率取前 3 ... 直到所有 beam 都生成 </s> 或达到最大长度

解码策略适合问题
greedy确定性任务、追求速度短视；容易重复
beam search翻译、摘要等有「标准答案」的任务beam 太大反而变差（见下）；输出偏「安全」缺乏多样性
sampling (top-k / top-p)开放生成、对话、创意写作不适合翻译（会引入随机错误）
constrained decoding输出必须落在合法集合（如分类标签、JSON）实现复杂
beam 越大越好？不对

beam search 的诅咒：直觉上 beam 越大搜索越充分、结果越好，但实证反复发现——beam 超过 5~10 之后，BLEU 反而下降（Koehn & Knowles 2017 等）。原因很微妙：更大的 beam 更接近「真正的最大似然序列」，而模型的最大似然序列往往是退化的（空串、极短句、高频套话）。也就是说，小 beam 的搜索不充分性，意外地起到了正则化作用。这个现象揭示了一件重要的事：我们的训练目标（最大似然）与我们真正想要的（好的翻译）之间存在系统性错位。这也是后来 RLHF 等「直接优化人类偏好」方法的动机之一。

7算一笔账：enc-dec 与 decoder-only 的推理成本

这是本模块最有实操价值的一节，也是模块 05 选型的基础。任务：输入 n token，输出 m token。

encoder-decoderdecoder-only
编码阶段编码器对 n 个 token 跑一次（可并行）prefill：对 n 个 token 跑一次（可并行）
解码每步的注意力范围self-attn 看已生成的 t 个；cross-attn 看固定的 n 个（K/V 预计算）看 n + t 个（输入与已生成混在一起）
解码 m 步的注意力总量Σ_t (t + n) ≈ m²/2 + mnΣ_t (n + t) ≈ mn + m²/2
KV 缓存大小解码器 self KV（随 m 增长）+ cross KV（固定 n，只算一次）全部 n+m 的 KV
参数量（同深同宽）≈ 2.3×1×

直白说

注意力总量上两者其实接近——真正的差异在参数量与每步的矩阵乘法规模。enc-dec 用 2.3 倍参数换取输入的双向编码；decoder-only 用单向输入换取参数效率与实现简洁。在小规模（<1B）且任务明确时，enc-dec 的双向优势更容易体现；规模上来后，decoder-only 的其他优势占了上风。

严谨说

但有一个场景 enc-dec 的优势是结构性的：n ≫ m（输入远长于输出）。比如「把一篇 8000 token 的文档摘要成 100 token」。enc-dec：编码器跑一次 8000（O(n²) 但只一次），解码 100 步、每步 cross-attn 到预计算的 8000 个 KV。decoder-only：prefill 8000，然后 100 步、每步对 8000+t 做注意力——看起来差不多，但 decoder-only 的这 8000 个 KV 占用的显存是「全部层 × 全部头」的，而 enc-dec 的 cross-attn KV 只需存编码器最后一层的输出投影。在长输入下这个显存差异很可观。

最后一笔账：T5 的「目标只含被挖片段」到底省了多少训练算力。设输入长 L、掩码率 15%、片段长 3。BART 式重建整句的目标长度是 L；T5 式只输出被挖内容，目标长度约 0.15L + L/3·0.15（内容 + 哨兵）≈ 0.2L。解码器计算量与目标长度成正比（自注意力还是平方关系），所以解码侧省约 5 倍，端到端约省 40–50% 的训练算力。notebook 会把这个算清楚。

把本模块浓缩成一句可迁移的智慧：encoder-decoder 不是「更复杂的 BERT」也不是「更笨的 GPT」，它是把「理解输入」和「生成输出」这两件事显式分工的架构。这个分工带来的好处（输入双向、编码只算一次、cross-attn 可预计算）在「输入固定且长、输出短」的任务上是实打实的；带来的代价（参数翻倍、两套栈、训练复杂）在追求通用性的场景下不划算。知道分界线在哪，比知道谁「更先进」有用得多。

8研究前沿与开放问题

  • 架构形态的公平比较：Tay et al. 2022 UL2 等工作试图在同等算力下系统比较 enc-dec / dec-only / prefix-LM，并提出混合去噪目标（mixture-of-denoisers）统一它们。但「在什么规模、什么任务上哪种更优」仍缺乏干净的缩放律。
  • exposure bias 的真实影响有多大：这个概念被广泛引用，但也有工作（如 He et al. 2021）论证在强模型上它的影响被高估了——大模型的自生成前缀已经足够接近训练分布。它到底是个真问题还是一个流传的直觉，取决于规模，尚无定论。
  • 似然与质量的错位：beam search 的诅咒揭示了「最大似然序列往往是退化的」。这个现象的理论刻画（为什么 MLE 训练的模型其众数是退化的）以及如何设计不错位的训练目标，是生成模型的根本问题之一。对比解码（contrastive decoding）、typical sampling 等都是缓解尝试。
  • 非自回归生成：一次性并行生成全部输出（NAT），速度快一个数量级，但质量差（因为输出 token 之间的依赖被忽略）。迭代式精化（如 CMLM、掩码扩散）是折中。encoder-decoder 天然适合 NAT（编码器已经给了完整输入表示），这条线在翻译上有实用价值。
  • 长输入的编码器：enc-dec 在长文档任务上的优势要求编码器能吃长输入，但注意力是 O(n²)。稀疏注意力（LED、BigBird）、层次编码、检索增强各有取舍，最优方案仍未收敛（C25 有系统讨论）。

必读：Vaswani et al. 2017 Attention Is All You Need（原始 enc-dec 与 cross-attention 的定义，重新读一遍你会发现很多细节被后来的教程简化掉了）、Raffel et al. 2020 T5（第 3 节的系统消融是本领域最完整的架构/目标对比实验之一）、Lewis et al. 2020 BART（五种噪声的消融）、Ranzato et al. 2016 Sequence Level Training（exposure bias 的提出）、Koehn & Knowles 2017 Six Challenges for NMT（beam search 诅咒的实证）、Wu et al. 2016 GNMT（长度惩罚公式的出处）。完整清单见 references.md。
