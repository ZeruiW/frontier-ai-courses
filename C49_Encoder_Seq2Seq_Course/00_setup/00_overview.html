1这门课讲什么

欢迎来到 编码器与 Seq2Seq 模型家族。这门课补的是一个在 2023 年之后被普遍忽略、但在工业界仍然天天用到的洞：Transformer 不只有 decoder-only 这一种形态。

如果你的 Transformer 知识是从 GPT 系列学起的（多数人如此，C01 也是这个路线），那么你熟悉的是因果注意力 + 下一个 token 预测 + 自回归生成这一套。这套东西极其成功，以至于容易让人以为它就是 Transformer 的全部。但实际上，原始 Transformer（Vaswani et al. 2017）是一个 encoder-decoder 架构，BERT 打开的是 encoder-only 这条线，T5/BART 走的是 encoder-decoder 的复兴。三种形态解决的是不同的问题，各自的注意力掩码、预训练目标、推理成本都不一样。

直白说

为什么现在还要学这个？三个非常实际的理由。其一，工业界大量在跑——分类、NER、意图识别、内容审核、检索的 embedding 与 reranker，这些场景里 BERT 系模型（及其后代）仍是默认选择，因为它们快一到两个数量级、便宜同样的数量级。其二，面试与 JD 明确要求——「hands-on experience with GPT, BERT, RoBERTa, LLaMA」「expertise in NLP and sequence-to-sequence models」是标准写法。其三，也是最重要的：理解三种形态的差异，你才真正理解注意力掩码与预训练目标是可设计的，而不是天经地义的。

严谨说

更技术地说，三种形态的本质区别只有一件事：注意力掩码矩阵的形状。encoder-only 用全 1 的双向掩码（每个位置能看到所有位置），decoder-only 用下三角的因果掩码，encoder-decoder 则是「编码器双向 + 解码器因果 + 交叉注意力全可见」。其余的一切差异——预训练目标能不能做、能不能自回归生成、推理成本是 O(1) 次前向还是 O(n) 次——都是从这一个矩阵推导出来的。本课就沿着这条线索把三种形态拆开重建。

学完你应当能回答这类问题（也是 NLP 岗位的高频面试题）：为什么 BERT 不能像 GPT 那样生成文本？MLM 的 80/10/10 掩码策略为什么不是简单地全换成 [MASK]？RoBERTa 相对 BERT 到底改了什么、为什么有效？ELECTRA 凭什么样本效率高得多？T5 的 span corruption 与 BERT 的 token 掩码差在哪？做文本分类，今天到底该用 BERT 微调还是 LLM few-shot？——并且能在 numpy 里把双向注意力、MLM 目标、[CLS] 分类头、BIO 标注解码、span 抽取、cross-attention、beam search 都从零实现出来。

一个必须先破除的误解：「decoder-only 更强所以取代了一切」是不准确的。准确的说法是——decoder-only 在生成与通用指令跟随上取得了压倒性优势，因为它的预训练目标（预测下一个 token）能无监督地吃下整个互联网，且天然与「生成」这个能力对齐。但在「输入定长、输出是一个标签或一个片段」的任务上，encoder 的双向表示 + 单次前向仍然在精度/延迟/成本的联合权衡上占优。模块 05 会把这笔账算清楚——你会看到，同样的分类任务，BERT 系方案的单位成本可能比 LLM 低两到三个数量级。

4方法论：纯 numpy 重建 + 与理论对拍

本课全程 纯 numpy / CPU，不加载任何预训练权重、不联网。这看起来是个限制，但对本课的目标恰恰合适——因为这门课要讲的是「设计选择」，不是「调 API」。

直白说

「BERT 为什么不能生成」这个问题，读十篇博客不如自己写一遍：用双向掩码做一次前向，你会亲眼看到位置 t 的表示里已经混入了位置 t+1 的信息，于是「预测下一个 token」这个训练目标退化成了抄答案（损失瞬间趋零、模型什么也没学到）。这个实验在 notebook 里三十行就能跑出来，而且它的结论是不可辩驳的数值事实，不是别人告诉你的结论。

严谨说

本课的对拍策略有三层：①与理论对拍——注意力掩码的实现要满足可证明的性质（因果掩码下 ∂y_t/∂x_{t+1} = 0，我们直接用数值梯度验证）；②与朴素参考对拍——beam search 与穷举搜索在小词表小长度下应给出相同的最优序列；③与公开报告的量级对拍——参数量、FLOPs、样本效率的账要与论文中报告的数字在同一量级（notebook 里的 🧪 胶囊会做这件事）。

一句话说明本课与 C01/C17/C20 的分工：C01 教你从零写一个 decoder-only Transformer；C17 讲神经网络之前的经典 NLP（word2vec/HMM/CRF）；C20 讲现代架构组件（RoPE/GQA/MoE/SSM）。本课补的是「另外两种 Transformer 形态」以及它们独有的预训练目标与任务范式。三门课的注意力实现是同一套，只是掩码不同——这正是本课要让你亲手体会的。

讲解里会出现 HuggingFace transformers 的真实调用片段作为对照展示（不参与运行）——它们标注了「你在 numpy 里手写的这一步，在真实库里叫什么、参数在哪」。想真正上手这些库，见 C50（HuggingFace 生态与 API 实操），那门课与本课是配套的：本课讲模型形态与目标，C50 讲怎么用生态把它跑起来。

你需要本课怎么处理
预训练权重（BERT/T5）用小随机初始化的迷你模型（词表几十、维度几十）验证机制；效果数字引用公开论文报告
GPU 训练所有实验都是几百到几千步的小规模，CPU 秒级完成
GLUE/SQuAD 数据用程序生成的小型合成数据集，保留任务的结构（标签体系、span 边界、BIO 约束）
tokenizer用一个几十词的字符/词级迷你词表；真实 subword 分词见 C01/C21/C50

关于学习顺序还有一条建议：如果你只有时间读两个模块，读 01 和 05。模块 01 讲清 MLM 为什么必须存在（这是理解一切 encoder 的钥匙），模块 05 讲清今天该怎么选（这是你真正要做的决策）。中间三个模块是把这两端连起来的推导链——02 说明同一个架构上还能改什么、改哪里有效，03 说明预训练好的表示怎么接到具体任务、以及那些不写在论文里却决定成败的解码与评估细节，04 说明当输出必须是新文本时架构要怎么变。但如果你要面试或者要做真实项目，五个模块的内容都会被问到、都会被用到。

最后一句：本课的每个模块都会明确回答「这个设计解决了什么问题、代价是什么、今天还成立吗」。有些设计（NSP）后来被证明是错的，有些（动态掩码）被证明是对的，有些（encoder-decoder）经历了衰落又部分复兴。把「为什么当时那样设计、后来为什么改」搞清楚，比记住哪个模型在 GLUE 上多了 0.5 分有用得多。
