1三种任务范式：头怎么接决定了一切

预训练给了你一个东西：一个把 token 序列映射成上下文相关向量序列的函数 f: (x_1..x_n) → (h_1..h_n)。微调要做的就是在它上面接一个「头」，把 h 变成任务需要的输出。

绝大多数 NLU 任务落在三种范式里，它们的区别只在用哪些 h、输出什么形状：

[CLS] 这 家 店 的 服 务 很 好 [SEP] h0 h1 h2 h3 h4 h5 h6 h7 h8 h9 │ │ │ │ │ │ │ │ │ │ ① 序列分类 (sequence classification) 用 h0（[CLS]）或所有 h 的平均 → 一个 C 类 softmax h0 ──▶ [Linear C] ──▶ P(正面/负面) 输出: 1 个标签 任务: 情感、意图、NLI、句对匹配、内容审核 ② token 分类 (token classification) 每个 h_i 独立过同一个头 → 每个位置一个标签 h1..h8 ──▶ [Linear K] ──▶ BIO 标签序列 输出: n 个标签 任务: NER、词性标注、分块、槽位填充 ⚠️ 关键约束: 标签序列有**语法**（I-PER 不能跟在 B-LOC 后面）→ 需要约束解码 ③ span 抽取 (extractive QA) 两个头，各自在序列上做一次 softmax，选出答案的起止位置 h ──▶ [Linear 1] ──▶ start_logits ──softmax over positions──▶ 起点 h ──▶ [Linear 1] ──▶ end_logits ──softmax over positions──▶ 终点 任务: SQuAD 式抽取问答、信息抽取 ⚠️ 关键约束: end >= start，且长度有上限 → 需要联合搜索最优 span

直白说

三种范式的参数量差异小到可以忽略——分类头就是一个 768×C 的矩阵，几万个参数，相比 110M 的主干微不足道。这带来一个重要认识：微调的绝大部分工作发生在主干里，头只是把表示「翻译」成任务格式。这也解释了为什么同一个预训练模型能在几十种任务上都表现良好——它学到的是通用表示，不是任务特定的技能。

严谨说

但三种范式的输出空间结构差异巨大，这才是设计的重点。① 输出空间是 C 个互斥类，无结构；② 输出空间是 K^n，但有硬性语法约束（BIO 的合法转移），朴素逐位置 argmax 会产生非法序列；③ 输出空间是 O(n²) 个 span，有顺序约束（end≥start），独立取两个 argmax 可能得到 end<start 的无效答案。后两者都需要在解码时施加约束，这是本模块最有实操价值的部分。

一个非常常见的实现错误：token 分类时忘记处理子词。tokenizer 会把「Washington」切成 Wash ##ing ##ton 三个 token，但标注数据里它只有一个标签 B-LOC。标准做法是：只对每个词的第一个子词计损失，其余子词的标签设为 -100（HF 的 word_ids() 就是为此存在的）。忘了这一步，模型会学到把同一个实体的后续子词标成 O，评估时 F1 莫名其妙地低。这个坑几乎每个人都踩过一次。

2① 序列分类：[CLS] 还是平均池化

最简单的范式，但有一个值得较真的细节：句子的向量表示该怎么取？

池化方式做法什么时候好注意
[CLS]取首位隐状态（BERT 还过一层 tanh(W·h) 的 pooler）微调时——梯度会教会 [CLS] 汇总信息未微调时很差，因为没有预训练目标在用它（RoBERTa 去掉 NSP 后尤甚）
mean pooling对所有非 padding 位置的 h 求平均不微调直接取表示时（检索、相似度）必须用 attention mask 加权，否则 padding 会稀释
max pooling逐维取最大关键词触发型任务（如毒性检测）对长文本不稳定
attention pooling学一个查询向量对所有 h 做注意力加权任务需要「找重点」时多几千参数，通常小幅提升

直白说

实践经验：要微调就用 [CLS]，不微调就用 mean pooling。原因在模块 01 说过——[CLS] 之所以能代表整句，是因为有目标在训练它；如果你只是拿一个预训练模型直接抽向量（不训练），[CLS] 从未被任何梯度教过要汇总什么，效果常常显著差于简单平均。这个反直觉的事实在做检索时是致命的（模块 05 展开）。

严谨说

还有一个几何层面的问题：BERT 的句向量空间高度各向异性——所有向量挤在一个狭窄的锥体里，导致任意两个句子的余弦相似度都很高（0.7+），失去区分度。缓解手段有白化（whitening）、去除高频方向、或者用对比学习重新训练（SimCSE）。直接把 BERT 的 [CLS] 当句向量做检索，是一个经典的、效果很差的做法——但因为它「看起来合理」，被反复重新发明。

句对任务：两种编码方式

NLI、语义相似度、检索这类任务涉及两个句子，有两种截然不同的做法，它们的取舍在模块 05 会算成一笔账，这里先建立概念：

  • cross-encoder（交叉编码）：把两句拼成 [CLS] A [SEP] B [SEP] 一起过模型。两句的每个 token 之间都能互相注意 → 精度最高。代价：无法预计算，N 个候选就要跑 N 次前向。
  • bi-encoder（双塔）：两句分别编码成向量，用余弦相似度打分。可以离线预计算所有文档向量、在线只算查询 → 快几个数量级。代价：两句之间没有交互，精度低一截。

记住这个二分，它在整个 NLP 系统设计里反复出现：「交互带来精度，独立带来可预计算」。检索系统的标准架构就是这两者的组合——双塔做召回（从百万里选 100），交叉编码做精排（对 100 个重排）。这不是妥协，是在成本-精度前沿上的正确取点，模块 05 会把这个前沿画出来。

3② token 分类：BIO 标注与约束解码

NER 这类任务要给每个 token 一个标签。标签体系通常是 BIO（也叫 IOB2）：

句子: 张 三 在 北 京 工 作 BIO : B-PER I-PER O B-LOC I-LOC O O │ │ │ │ │ │ │ │ │ └─ Inside-LOC: 「北京」的后续 token │ │ │ └─────── Begin-LOC: 一个地点实体的开始 │ │ └──────────── Outside: 不属于任何实体 │ └────────────────── Inside-PER └──────────────────────── Begin-PER **合法性约束（这是关键）**： ✓ O → B-X 或 O ✗ O → I-X （实体不能凭空「继续」） ✓ B-X → I-X 或 B-Y 或 O ✗ B-PER → I-LOC （类型不能中途变） ✓ I-X → I-X 或 B-Y 或 O ✗ I-LOC → I-PER 朴素逐位置 argmax **不知道这些约束**，会产出 O → I-PER 这种非法序列。

直白说

为什么非法序列是个真问题？因为下游要把标签序列解析成实体列表。遇到 O I-PER I-PER，解析器要么报错、要么用启发式补救（当作 B-PER？丢弃？），无论哪种都会让评估指标失真、让产品行为不可预测。而且这不是罕见情况——朴素解码在真实数据上产生非法转移的比例通常在百分之几，足以影响实体级 F1。

严谨说

解决办法是约束解码：把「找最优标签序列」建模成在一个带非法转移屏蔽的图上找最高分路径，用 Viterbi 动态规划求解。复杂度 O(n·K²)，K 是标签数（通常几十），完全可以接受。更进一步，可以把转移分数也变成可学习参数——那就是 CRF 层（C17 讲过 CRF 本身，这里是把它接在 BERT 上）。BERT+CRF 是 NER 的经典组合，虽然近年发现在强预训练模型上 CRF 的增益变小了（表示已经足够好），但约束解码本身仍然必要——它保证输出合法，这是零成本的正确性保证。

Viterbi：三行递推

设 e[i][k] 是位置 i 标签 k 的发射分数（模型输出的 logit），T[j][k] 是从标签 j 转移到 k 的分数（非法转移设为 −∞）。定义 δ[i][k] = 以位置 i 标签 k 结尾的最优路径分数：

\[\delta[0][k] = e[0][k], \qquad \delta[i][k] = e[i][k] + \max_j \big(\delta[i-1][j] + T[j][k]\big)\]

回溯指针记录每步的 argmax j，最后从 argmax_k δ[n-1][k] 倒推出整条路径。notebook 会把它实现出来，并与暴力枚举所有 K^n 条路径对拍——在小规模下两者必须给出完全相同的最优路径。

评估 NER 时的另一个坑：token 级 F1 与实体级 F1 不是一回事，而且前者会系统性地高估。「北京」被标成 B-LOC O（第二个 token 错了），token 级 F1 = 50%，但实体级 F1 = 0（这个实体根本没被正确抽出来）。产品关心的是实体级——用户要的是「北京」这个实体，不是「一半正确」。seqeval 库算的就是实体级，notebook 会把两种指标都实现并展示它们的差距。

4③ span 抽取：两个 softmax 与联合搜索

抽取式问答（SQuAD 范式）的输出是原文中的一个连续片段。做法是两个独立的位置分类器：

start_logits = h @ W_start   # (n,) —— 每个位置作为「答案起点」的分数
end_logits   = h @ W_end     # (n,) —— 每个位置作为「答案终点」的分数

# 训练：两个交叉熵之和
loss = CE(start_logits, gold_start) + CE(end_logits, gold_end)

训练很直接，推理才是重点。天真的做法是分别取两个 argmax，但这会产生三类无效答案：

问题例子为什么发生
end < startstart=8, end=3两个分类器独立，没有任何机制保证顺序
跨越 [SEP] 或落进问题区答案片段包含了问题的 token位置分类器在整个序列上做 softmax，包括问题部分
答案过长抽出 200 个 token 作为答案没有长度约束；通常真实答案 < 30 token

正确做法是联合搜索：在满足约束的 (i,j) 对里最大化 start_logit[i] + end_logit[j]：

\[(\hat{i}, \hat{j}) = \arg\max_{\substack{i \le j \le i + L_{max} \\ i, j \in \text{context}}} \big( s_i + e_j \big)\]

直白说

朴素实现是双重循环 O(n²)，对 n=384 是 15 万次比较，还能接受。但有个 O(n·L_max) 的写法：对每个 i，只看窗口 [i, i+L_max] 内的 j。更巧的是可以用后缀最大值做到 O(n)：预计算 suffix_max[i] = max_{j≥i} e_j 及其 argmax，然后对每个 i 直接查表。notebook 会实现这三种并对拍。

严谨说

还有一个实践中必须处理的问题：不可回答的问题（SQuAD 2.0 引入）。做法是把 [CLS] 位置当作「无答案」的特殊 span，即 (0,0)。推理时比较「最优有答案 span 的分数」与「s_0 + e_0」，后者更高就输出「无法回答」。这个设计很优雅——不需要额外的分类头，复用同一套 logits。阈值需要在验证集上调（因为两类分数的尺度不同）。

长文档：滑窗与跨窗合并

BERT 只能吃 512 token，但很多文档更长。标准解法是滑动窗口：用 stride（如 128）切成重叠的多个片段，每段独立预测，最后合并。合并时的关键是分数要可比——不同窗口的 softmax 是各自归一化的，直接比概率不对，应该比未归一化的 logit 之和。这是个很容易写错的细节。

span 抽取范式的一个重要优点，在 LLM 时代反而更明显了：它的输出天然是「原文中的片段」，不可能编造。生成式 QA 会幻觉，抽取式不会——答案要么在原文里，要么模型说不知道。在合规、法律、医疗等对可溯源性要求高的场景，这个性质本身就是选择抽取式的充分理由，即使生成式的「灵活性」看起来更强。

5微调配方：那些让分数差 3 分的细节

微调看起来简单（加个头、跑几个 epoch），但配方不对会显著掉分，而且失败模式很隐蔽。

细节推荐做法不这么做会怎样
学习率2e-5 ~ 5e-5（比从头训练小 100 倍）太大（1e-3）会灾难性遗忘，几步就把预训练知识冲掉；太小则学不动
warmup前 6~10% 步数线性升温开头的大梯度会破坏预训练权重
epoch 数2~4（小数据集 3~5）超过 5 个 epoch 在小数据上必过拟合
判别式学习率底层学习率更小（如逐层 ×0.95 衰减）底层学的是通用特征，改动它们收益小、破坏大
随机种子跑多个种子取均值±方差小数据集上 BERT 微调的种子方差可达 2~3 分——单次结果不可信
最大长度按任务的实际长度分布设，不要无脑 512attention 是 O(L²)，无脑 512 可能浪费 10 倍算力
类别不平衡加权损失或重采样；用 macro-F1 而非 accuracy99:1 的数据上，全预测多数类就有 99% accuracy

直白说

种子方差这一条特别值得强调，因为它直接影响你能不能相信自己的实验结论。Dodge et al. 2020 系统研究发现：在 GLUE 的小数据集（如 RTE、MRPC）上，仅改变随机种子，BERT 微调的最终分数波动可达 2–3 个点，甚至有些种子会「训崩」（退化到多数类基线）。这意味着「我的方法比 baseline 高 1 分」这种结论，如果只跑了一个种子，很可能纯属噪声。

严谨说

工程上的做法：至少 3–5 个种子，报告均值与标准差，用配对检验判断显著性（C03/C10 有完整的统计方法）。这不是学术洁癖——在工业界，一个「涨了 1 分」的模型上线后没有效果，浪费的是真实的时间与信任。C40（研究方法论）把这件事作为实验设计的核心纪律。

灾难性遗忘：为什么学习率要这么小

预训练权重是在数十亿 token 上学到的，而微调数据可能只有几千条。如果学习率太大，几个 batch 的梯度就足以把权重推离预训练的「好区域」，模型退化成一个在小数据上过拟合的随机初始化网络。判别式学习率（discriminative fine-tuning，Howard & Ruder 2018）的思路是：底层学的是词法/句法等通用特征，应该几乎不动；顶层学的是语义/任务相关特征，可以多动。

\[\eta_{\ell} = \eta_{top} \cdot \gamma^{(L - \ell)}, \qquad \gamma \approx 0.95\]

更极端的做法是只训练头、冻结主干（linear probing）。它极快、极省显存、不可能遗忘，但通常比全量微调低几个点。这两者之间有一整条谱系：冻结主干 → 只解冻顶部几层 → 判别式学习率全量微调 → 均一学习率全量微调。数据越少，越应该往「冻结」那端靠。而 LoRA 等参数高效方法（C02/C50）本质上是在这条谱系上开的一条新路——让全部层都能更新，但只更新一个低秩子空间。

6评估：选错指标比模型差更糟

任务常用指标为什么不用 accuracy陷阱
情感二分类（均衡）accuracy / F1——
毒性检测（1% 正例）PR-AUC / macro-F1全预测「无毒」就有 99% accuracyROC-AUC 在极度不平衡时也会虚高
CoLA（语法可接受性）MCC（马修斯相关系数）类别不平衡且两类都重要MCC 在 [-1,1]，0 表示随机
NER实体级 micro-F1token 级会系统性高估必须用 seqeval 式的实体匹配
抽取式 QAEM + F1（token 重叠）EM 太严（差一个标点就 0 分）要做答案归一化（去冠词、标点、大小写）
语义相似度（STS）Spearman 相关这是回归不是分类Pearson 对非线性单调关系不敏感

其中 MCC 值得单独说，因为它是 GLUE 里 CoLA 任务的指标，很多人第一次见。它综合了混淆矩阵的全部四个格子：

\[\text{MCC} = \frac{TP \cdot TN - FP \cdot FN}{\sqrt{(TP+FP)(TP+FN)(TN+FP)(TN+FN)}}\]

它的好处是对类别不平衡鲁棒：只有当模型在两个类上都做得好时 MCC 才高，而 accuracy 和单一 F1 都可以被多数类刷高。notebook 会用一个不平衡数据集对比这几个指标的表现，你会看到 accuracy 0.95 而 MCC 0.0 的情况——模型什么也没学到，但 accuracy 看起来很棒。

先归一化，再算 EM

QA 评估的一个具体陷阱：EM（exact match）对答案归一化极其敏感。金标答案是「the White House」，模型输出「White House」——不归一化的话 EM = 0。SQuAD 的官方评估脚本会做四步归一化：转小写、去标点、去冠词（a/an/the）、压缩空格。自己实现评估时忘了这一步，会低估模型 5–10 个点，然后你会以为模型很差，去做一堆无用的优化。notebook 会把归一化函数实现出来，量化它的影响。

7算一笔账：三种范式的成本与选型

把三种范式的计算特征放在一起。假设 n=128、d=768、12 层。

范式头的参数量推理前向次数解码复杂度输出空间大小
序列分类（C 类）768×C ≈ 1.5k（C=2）1O(C)C
token 分类（K 标签）768×K ≈ 7k（K=9）1O(nK²)（Viterbi）K^n（受约束）
span 抽取768×2 ≈ 1.5k1（长文档要 ⌈L/stride⌉ 次）O(n·L_max) 或 O(n)O(n²)

三点观察：

  • 头的参数量都可以忽略（几千 vs 主干 110M）。微调的成本几乎完全由主干决定，与任务类型无关。
  • 推理都只要一次前向——这是 encoder 范式相对生成式的核心优势。生成式做同样的任务要自回归解码几十到几百步（模块 05 会算这笔账）。
  • 解码复杂度虽然不同，但都远小于前向。Viterbi 的 O(nK²) = 128×81 ≈ 1 万次操作，而一次 BERT 前向是 ~10¹⁰ FLOPs。所以约束解码是「免费」的正确性保证，没有理由不做。

最后给一个选型的决策树，它比任何模型对比表都实用：

任务的输出是什么？ ├─ 一个标签（整段/整对） │ └─▶ ① 序列分类。微调用 [CLS]；不微调抽向量用 mean pooling。 │ 句对任务：要精度用 cross-encoder，要速度用 bi-encoder。 │ ├─ 每个 token 一个标签 │ └─▶ ② token 分类 + **约束解码**（Viterbi/CRF）。 │ 子词只在首片计损失；评估用**实体级** F1。 │ ├─ 原文中的一个片段 │ └─▶ ③ span 抽取（双 softmax + 联合搜索）。 │ 长文档滑窗；不可回答用 [CLS] 作为 (0,0) span。 │ └─ 自由文本（改写、摘要、翻译） └─▶ 不是本模块的范式 —— 需要生成，见模块 04（encoder-decoder） 或 decoder-only LLM（模块 05 会算成本账）。

把本模块浓缩成一句可迁移的智慧：微调的技术含量不在「接个头」，而在「输出空间的结构约束怎么在解码时被强制执行」以及「评估指标是否真的度量了你关心的东西」。头的代码十行就写完了，但忘记 Viterbi 会让你输出非法序列、忘记归一化会让 EM 低估十个点、忘记跑多种子会让你相信一个不存在的改进。这些细节不体现在论文的方法章节里，但决定了你的模型能不能上线。

8研究前沿与开放问题

  • CRF 层在强预训练模型上还有没有用：早期 BiLSTM-CRF 时代 CRF 增益明显，但 BERT+CRF 相对 BERT+softmax 的增益已经很小（部分数据集上甚至为负）。约束解码（保证合法性）与学习转移分数（CRF）是两件事，前者仍必要，后者的价值在缩小——这个边界尚未被系统刻画。
  • 指令化的 NLU：把分类/NER/QA 全部转成「文本到文本」的生成任务（T5 的路线，模块 04），或者用 LLM 的 few-shot / 结构化输出来做。它牺牲效率换取零样本能力与统一接口，但在有标注数据的场景下精度通常不如专门微调。这个取舍点随模型能力提升在移动，模块 05 会正面讨论。
  • 微调的稳定性：小数据集上的种子方差问题（Dodge et al. 2020）至今没有彻底解决。重初始化顶层、更长 warmup、混合精度的数值问题、以及 Adam 的 bias correction 都被提出过，但缺乏统一理论。
  • 参数高效微调的边界：LoRA/adapter/prefix-tuning 在多大程度上能匹配全量微调，取决于任务与数据量，尚无可靠的先验判据。对 encoder 的 NLU 任务，这方面的系统研究比对 decoder 少得多。
  • 结构化预测的现代化：嵌套实体、重叠 span、篇章级关系抽取这些超出 BIO 表达力的任务，需要更丰富的输出结构（span-based、图结构、seq2seq 生成）。哪种表示在什么条件下最优，仍是活跃方向。

必读：Devlin et al. 2019 BERT 第 4 节（四种下游范式的原始定义）、Rajpurkar et al. 2016/2018 SQuAD 1.1/2.0（span 抽取范式与「不可回答」的设计）、Wang et al. 2019 GLUE（多任务基准与各任务的指标选择理由）、Howard & Ruder 2018 ULMFiT（判别式学习率与逐层解冻）、Dodge et al. 2020 Fine-Tuning Pretrained Language Models: Weight Initializations, Data Orders, and Early Stopping（种子方差的系统研究，做实验前必读）、Lample et al. 2016 Neural Architectures for NER（BiLSTM-CRF 与 BIO 约束）。完整清单见 references.md。
