1动机：新模型从哪来——反馈闭环

监控（模块 04）告诉你模型在变差，门禁（模块 03）告诉你新模型够不够格——但中间缺了一环：新模型从哪来？答案是retraining（重训练），而重训的燃料是反馈：从线上收集真实结果，反哺下一轮训练。这条收集反馈 → 判断该不该重训 → 重训 → 评估 → 再上线的回路，就是 feedback loop（反馈闭环）——它让模型能随世界变化持续进化，是生命周期之所以是个环而非一条直线的原因。

但这一环是整个生命周期里最微妙、最容易出错的。它牵涉三个深水区：反馈从哪来、质量如何（用户行为是有偏的弱信号）；什么时候该重训（太频繁烧钱、太晚则模型已劣化）；以及重训会不会越学越坏——在新数据上继续训练，可能让模型灾难性地遗忘旧知识，或被有偏的反馈带进一个自我强化的恶性循环。本模块从零把整条闭环模拟出来，并亲手量化这些风险。

先把它和前四个模块的关系摆正：前四个模块大体是防御性的——追踪让你不丢失、版本让你能回滚、门禁挡住坏模型、监控发现劣化。它们守住一个既有模型的安全与可追溯。而本模块是进取性的：它要让系统主动变好，跟上一个不断变化的世界。这也是为什么它最难——防御只需「别出错」，进取却要在「学新」与「不忘旧」、「快速跟进」与「别被噪声/偏差带歪」之间走钢丝。把这条钢丝走稳，一个 ML 系统才算真正活了起来，而不只是被维护着不死。

直白说

把反馈闭环想成一个学徒：他上岗后不断接到「这次做对了 / 做错了」的反馈，据此改进。理想情况他越来越好。但坏事也可能发生：他可能只从「他敢做的事」拿到反馈（没做过的永远学不到 = 反馈偏差）；他可能学了新活就忘了老活（灾难性遗忘）；他也可能因为一次过度纠正而矫枉过正。管理这个学徒，远不止「有反馈就喂给他」这么简单。

严谨说

形式上，闭环在时间上展开：模型 M_t 服务产生预测，环境回流（部分、延迟、有偏的）真值，聚合成新训练数据 D_t；当触发条件满足，用 D_t（可能混合历史数据）训出 M_{t+1}，过门禁后替换 M_t。关键变量是：触发策略（何时重训）、数据策略（新数据 vs 新旧混合）、以及对稳定性（别忘旧）与可塑性（学得进新）的平衡。

反馈闭环有一个传统软件完全没有的特性：模型会影响它未来的训练数据，形成自我强化的回路（Sculley 论文专门点名的「隐藏反馈回路」）。推荐系统只推它推过的内容 → 用户只能点它推过的 → 这些点击成为训练数据 → 模型越推越窄，最终与真实世界的偏好脱节。这种失控回路（runaway feedback loop）不会触发任何报错，却会让模型悄悄滑向偏见或单一化。现实里这类回路造成过严重后果：预测性警务模型把警力派往它预测的高发区，那里因此记录到更多案件，又「证实」了预测、派去更多警力——一个自我实现的偏见放大器。设计闭环时，「模型在塑造自己的数据」这件事必须时刻警惕——这是闭环系统区别于一切静态系统的根本风险，也是为什么本模块把它放在最前面讲。

2反馈从哪来：直接 vs 间接

反馈是重训的燃料，但燃料质量参差。在动手收集前，先想清楚一个根本问题：你要的「真值」到底从哪来、可信度多高、要等多久。这决定了你的闭环能多快、多准地进化，也决定了你会不会被劣质反馈带歪。反馈大致分两类，质量天差地别。直接反馈：用户显式给的真值（点赞/点踩、纠错、人工标注、客服打的标签）——信号清晰但量少、贵、慢。间接反馈：从行为推断的弱信号（点击、停留时长、是否完成购买）——量大、即时，但有偏且含糊（没点击 ≠ 不喜欢，可能只是没看到）。

维度直接反馈间接反馈
例子点赞/点踩、人工标注、纠错点击、停留、转化、跳出
质量高（接近真值）低（有偏的代理）
数量少（用户懒得给）海量（每次交互都有）
偏差选择偏差（爱给反馈的人不代表全体）曝光偏差（只有被推过的才有反馈）
延迟可能很长（标注排期）即时

3反馈偏差与主动学习

把间接反馈当作标签直接喂回训练，是闭环最常见的翻车点。一个「用户没点击」的样本被当成负例，但他没点可能只是没看到、或在刷另一个 tab——这种曝光偏差若不纠正，会让模型系统性地误判。生产中要么用因果/去偏方法校正，要么把间接信号只当作弱监督而非硬标签。本模块的 worked 会演示「聚合反馈」时如何区分置信度不同的信号。

还有一个更隐蔽的偏差源——反馈本身只覆盖模型「敢做的事」。一个贷款模型只对它批准的申请人看到「是否违约」的真值（被拒的人根本没机会违约或还款），于是它永远学不到「那些被它拒掉的人其实是好客户」。这叫选择性标签问题（selective labels）：反馈数据的覆盖范围被模型自己的决策剪裁了，训练数据系统性地缺了一块。它和前面的失控回路是同一枚硬币的两面——模型的行为决定了它能看到什么反馈，而这些反馈又塑造下一代模型。识别并补偿这种「模型看不到自己没做过的事」的盲区，是闭环数据质量最深的一层。

一个关键的成本意识：标注是闭环里最贵、最慢的一环。与其随机挑样本标注，不如用 active learning（主动学习）：让模型挑它最不确定的样本优先送标——这些样本信息量最大，用最少标注换最大提升。对二分类，「最不确定」就是预测概率最接近 0.5 的样本；模型对它们摇摆不定，一个真值标签能带来最大的信息增益。「模型说不准的，正是最该问人的」——这个朴素直觉是降低闭环标注成本的核心杠杆，本模块练习会让你实现它。

主动学习的核心选样只要一行，但威力很大，用 stdlib 演示「不确定性采样」：

# 模型对一批未标注样本输出的正类概率
probs = [0.97, 0.51, 0.04, 0.48, 0.99, 0.52, 0.88, 0.50]
# 不确定性 = 离 0.5 多近（越近越该问人）；这里用 |p-0.5|
order = sorted(range(len(probs)), key=lambda i: abs(probs[i]-0.5))
budget = 3                                   # 标注预算：只能标 3 条
to_label = order[:budget]                    # -> [7, 1, 5]（p≈0.50/0.51/0.52）
# 模型对 0.97/0.99/0.04 这些已经很笃定，标它们几乎学不到新东西

看清这笔账：模型对 0.97、0.99、0.04 已经很确定，花钱标它们近乎浪费（标签只会确认它已知的）；而 0.50、0.51、0.52 这几条它在抛硬币，一个真值标签能直接告诉它「决策边界到底该往哪偏」，信息增益最大。在固定的标注预算下，这种「专挑边界样本问人」的策略，常能用 1/5 甚至 1/10 的标注量 达到随机抽样同样的提升——对动辄按条计费的人工标注，这是实打实的省钱。代价是它会让标注数据偏向边界（不再是 i.i.d. 抽样），评估测试集时要当心这层采样偏差，别拿主动学习挑出的样本去估真实分布上的性能。

4重训触发：何时该重训（抖动与冷却）

重训不是越勤越好——每次重训都烧算力、占工程、且每个新模型都带引入回归的风险（哪怕过了门禁）。但太晚则模型早已劣化、损失已经造成。所以触发策略是闭环的核心决策。常见的触发条件有四类，通常组合使用：

触发类型条件优点缺点
定时每周/每月固定重训简单、可预期可能在不需要时白训、或在剧变时不够及时
漂移驱动PSI/KS 超阈（模块 04）对分布变化敏感、无需标签漂移≠性能降，可能误触发
性能驱动线上指标跌破 SLO直接对准目标依赖真值，有标签延迟
数据量驱动攒够 N 条新标注数据效率高数据来得慢时迟迟不触发

成熟系统把这些组合成一个触发器：例如「漂移超阈 或 性能跌破 SLO 或 距上次重训超过 30 天」。但要小心触发抖动：若条件刚好在阈值附近反复横跳，会导致频繁无谓重训。解法和模块 04 的告警一样——加持续性（连续若干窗口满足才触发）和冷却期（cooldown：刚重训完一段时间内不再触发，给新模型时间稳定）。本模块的 worked 会把这个触发器从零实现，含持续性与冷却。

注意四类触发条件背后是一个时效与可信的谱系，恰好对应模块 04 的三层监控栈：漂移驱动最早（无标签、实时，但漂移≠性能降）、性能驱动最准（直接对准目标，但要等真值）、数据量与定时则是兜底（防止前两者都没触发时模型无限期不更新）。一个稳健的触发策略往往是「以漂移做早期预警、以性能做最终依据、以定时做安全网」的组合——这再次印证了本课的主线：没有单一信号是万能的，靠多个互补信号叠出可靠的决策。

还要破除一个常见迷思：重训不一定能解决漂移。如果漂移是因为某个上游数据管道坏了（特征算错了、单位变了、上游表结构改了），那不是「世界变了，模型该学新」，而是「数据脏了，该修管道」。对这种情况重训，只会把脏数据学进新模型，让事情更糟。所以触发重训前，一个成熟的流程会先分诊（triage）：这次漂移是真实的世界变化（该重训），还是数据质量事故（该修管道）？模块 02 的 schema diff、数据校验在这里派上用场——先确认数据本身没坏，重训才有意义。盲目地「一漂移就重训」是把重训当成了万能锤，而很多漂移其实是别的问题伪装的。

一个微妙但常见的事故：重训触发器和监控告警共用一套漂移信号，但目的不同。告警是「叫人来看」，触发是「自动重训」。如果把「PSI 一超阈就自动重训」直接连上，等于让噪声驱动昂贵的自动重训。务必给自动重训设更严的条件（更高阈值 + 更长持续性 + 冷却期），并且——重训出的模型必须过门禁（模块 03）才能上线，绝不能漂移一触发就把未经审查的模型推上去。自动重训 + 自动门禁 = 安全的持续训练；自动重训 - 门禁 = 自动事故。

5持续学习与灾难性遗忘

触发了重训，怎么训？最简单是每次从头全量训（用全部历史 + 新数据）——稳，但贵、慢。诱人的替代是continual learning（持续/增量学习）：只在新数据上接着训现有模型，省算力、反应快。但它埋着一个深坑——catastrophic forgetting（灾难性遗忘）。

灾难性遗忘是指：在新数据/新任务上继续训练时，模型急剧丢失它在旧数据上的能力。神经网络用同一组权重编码所有知识，新数据的梯度会无情地覆写承载旧知识的权重——学了新的，旧的就塌了。这是 stability-plasticity dilemma（稳定-可塑性困境）的体现：模型既要可塑（学得进新）又要稳定（不忘旧），两者天然矛盾。这个词最早由 French 1999 系统提出，几十年来始终是持续学习领域绕不开的核心难题——直到今天的大模型时代它依然棘手，只是换了个更昂贵的舞台。

为什么神经网络会这么「健忘」，而人脑不会？根源在于分布式表示 + 共享参数：网络把所有知识叠在同一组权重里，没有「这块权重专管任务 A」的隔离。当新数据的梯度下降去优化任务 B 时，它会毫不留情地改写那些恰好也承载着 A 的权重——优化器只看当前 batch 的损失，根本不知道（也不在乎）某个权重对旧任务有多重要。这与人脑用不同神经回路、并有巩固机制保护旧记忆形成鲜明对比。理解了这个机制，对抗遗忘的各种方法就都好懂了：要么把旧数据混回来让梯度「记得」旧任务（回放），要么显式标记重要权重别乱动（EWC 正则化），要么干脆给新任务分配独立参数（参数隔离）。

6量化遗忘与回放修复

怎么量化遗忘？很直接：在持续学习之前记下模型在旧测试集上的表现，学完新数据后再测一次旧测试集，跌幅就是遗忘的度量：

\[\text{Forgetting} = \mathrm{acc}_{\text{old}}^{\text{before}} - \mathrm{acc}_{\text{old}}^{\text{after}}\]

跌幅越大、遗忘越严重。这个度量虽简单，却是评估任何持续学习方案的基石——所有「防遗忘」方法的好坏，最终都落在「旧任务掉了多少分」这把尺子上。本模块 notebook 会用一个玩具的两阶段学习（先学任务 A、再学任务 B）亲手复现灾难性遗忘——你会看到学完 B 后，A 的准确率断崖式下跌，触目惊心。然后实现最简单有效的解药 replay（回放/复演）：重训时往新数据里混入一批旧数据，提醒模型别忘了旧分布——你会看到混入旧数据后，遗忘被显著抑制。这正是 GEM、经验回放等方法的核心思想（见 references）。

把「回放有没有用」用一组典型数字摆出来，遗忘的代价与解药的效果一目了然：

任务A(旧) acc 任务B(新) acc 遗忘=A_before - A_after 学完 A（基线） 0.95 — — 朴素接着学 B（无回放） 0.61 0.93 0.95-0.61 = 0.34 ← 灾难 学 B + 回放 20% 旧数据 0.89 0.91 0.95-0.89 = 0.06 ← 救回

读这张表：朴素增量学习让任务 A 的准确率从 0.95 崩到 0.61，遗忘高达 0.34——模型为了学会 B，几乎把 A 忘干净了，这就是「灾难性」三个字的由来。而仅仅在新数据里混入 20% 的旧样本（回放），就把遗忘从 0.34 压到 0.06，同时任务 B 只从 0.93 略降到 0.91——用一点点对新任务的让步，换回了绝大部分旧能力。这个 0.34 → 0.06 的对比，正是本模块要你亲手跑出来的「啊哈时刻」：它让「灾难性遗忘」从一个吓人的术语，变成你能量化、能复现、也能修复的具体现象。注意回放比例（这里 20%）本身是个权衡旋钮——太低防不住遗忘，太高则挤占新数据、拖慢对新分布的适应。

对抗遗忘的方法大致分三个流派，都在「稳定-可塑」这条权衡线上取不同的点：回放（rehearsal）——存一批旧数据/代表样本，重训时混进去（最简单有效，但要存旧数据，有隐私/存储成本）；正则化（regularization）——如 EWC，用 Fisher 信息估出哪些权重对旧任务重要，给它们加「弹簧」约束别乱动（不用存旧数据，但长序列任务上仍会缓慢遗忘）；参数隔离（parameter isolation）——给不同任务分配不同的网络子结构（彻底不冲突，但参数随任务数膨胀）。对 MLOps 实践者，回放因其简单与有效，是性价比最高的第一选择，本模块就实现它。

用一句话抓住稳定-可塑性困境：学得太狠会忘旧（灾难性遗忘），学得太怂学不进新（欠拟合新分布）。持续学习的所有方法——回放、正则化（EWC）、参数隔离——本质都是在这条权衡线上找一个好点。对 MLOps 实践者，最务实的一课是：如果拿不准，全量重训（从头训）最安全——它天然不遗忘（因为旧数据都在）。增量学习省成本，但要付出管理遗忘的复杂度，只在算力/时效逼得你不得不增量时才上。一个朴素的判断：数据量小、重训不贵时，别折腾增量，全量重训既简单又稳；只有当数据大到全量重训慢得无法接受、或要求分钟级跟进时，才值得引入增量学习及其全套防遗忘机制。

7把整条闭环跑起来 · 全课收官

现在把五个模块拼成一条转动的闭环。前面四个模块各自是一块零件，这一节把它们串成一个能自我维持的整体——这也是本课从第一行就在铺垫的终点：不是五个孤立的工具，而是一条让模型能在变化的世界里持续存活、持续变好的流水线。一个完整的迭代长这样：

┌──────────────────── 反馈闭环（本模块） ───────────────────┐ ▼ │ [部署 M_t]──服务──▶ 收集反馈（直接+间接，部分/延迟/有偏） │ (模块03 过门禁) │ │ ▲ ▼ 聚合 + 标注（主动学习挑样本） │ │ 触发器？(漂移↑[模块04] 或 性能↓ 或 攒够N 或 定时) │ │ │ 满足(持续性+冷却) │ │ ▼ │ [门禁:M_{t+1}>M_t?]◀─训练 M_{t+1}（新数据 + 回放旧数据防遗忘）◀───────┘ (模块03 bootstrap) (追踪[模块01] + 版本/血缘[模块02]) 过 -> 晋升上线；不过 -> 留守 M_t，继续收集

看清这张图里每个模块各司其职：监控（04）触发，反馈+重训（本模块）产出候选，门禁（03）把关，追踪（01）记录这次重训，版本/血缘（02）让新模型可回滚、可追溯它用了哪批反馈数据。这正是 Google MLOps 白皮书里 CT（持续训练）的全貌——把「训练」本身自动化成一条按条件触发、经门禁、可追溯的流水线。本模块的 worked 会把这整条闭环用一个状态机模拟出来，让你看到它一轮轮转动、模型一代代进化（或在没管好遗忘/偏差时退化）。

这里有一个常被忽略却至关重要的设计原则：自动化的程度应当与风险匹配。Google 的成熟度分级 L0/L1/L2 不是「越高越好」的单调阶梯——把一个高风险场景（信贷、医疗、内容安全）一步做到「全自动重训 + 全自动上线、人完全不在回路」，是危险的。更稳妥的路径是渐进地把人移出回路：先自动产出候选 + 自动评测，但晋升要人点头（human-in-the-loop）；等门禁与监控被验证可信、跑了足够久没出事，再逐步放手到全自动。本模块的闭环模拟刻意保留了「门禁」这道关——它就是那个即便全自动也绝不能省的安全闸：自动重训可以快，但每个新模型上线前必须过统计显著性门禁，这是自动化与安全的不可妥协的交汇点。

跑通这条闭环，你就完成了本课的全部拼图——从「训练完一个模型」到「养着一个会自我更新、可追溯、有质量闸门、被持续监控的活系统」。这正是开篇 Sculley 那张图想说的：中间那个小小的 ML 代码方块，终于被一整圈基础设施稳稳托住了；而本课五个模块，正是这一整圈基础设施里最关键、也最常被技能课跳过的五块。而且你不是用了某个平台来做这件事，而是从零把每块基础设施的内核都亲手写了一遍——这意味着无论将来用 MLflow、DVC、Evidently 还是它们的继任者，你都能一眼看穿它在替你做什么、它的取舍在哪、出了问题该去哪查。这种「看穿工具」的能力，比记住任何一个 API 都更持久、更值钱，也正是本课刻意不走「API 巡游」路线、坚持让你从零造工具的全部理由所在。

把本模块（以及整条闭环）的玩具组件对应到生产工具，给全课的「从零造内核」画一张通往真实世界的地图：

五个模块的五张映射表合起来，就是一句话：MLflow + DVC + Evidently + Airflow（或它们的同类）拼起来的那套「生产 MLOps 栈」，你已经把每一块的内核都亲手写过了。平台帮你做的是规模化、多人协作、可视化与运维，但底下那些不变的抽象——run 存储、内容寻址、显著性闸、漂移度量、防遗忘——正是这五个模块教给你的。这就是为什么本课赌的是「造内核」而非「学按钮」：按钮年年换，内核十年不变。

8研究前沿与开放问题

  • 灾难性遗忘的根治：回放要存旧数据（隐私/存储成本）、EWC 等正则化方法在长序列任务上仍会缓慢遗忘。持续学习如何在不存旧数据、不限任务数的情况下真正「学不忘」，是开放的核心难题（Parisi 2019 综述）。
  • 反馈偏差的去除：曝光偏差、位置偏差让间接反馈系统性失真。用反事实/因果推断（counterfactual learning、IPS 加权）去偏是活跃方向，但在闭环里在线去偏仍很难，且容易引入新的方差。
  • 失控回路的检测与阻断：怎么自动发现「模型正在把自己的数据带偏」（如推荐越来越窄）？需要监控反馈数据本身的多样性/分布漂移，而不只是输入特征——这把模块 04 的漂移检测对准了闭环自身产生的数据。
  • 最优重训策略：重训的「何时、用多少数据、增量还是全量」本质是一个成本 vs 收益的序贯决策问题。把它形式化为（强化学习式的）最优控制、让系统自己学会何时重训，仍是前沿。
  • LLM 时代的持续学习：大模型的「重训」成本极高，于是转向持续预训练、参数高效微调（LoRA）、RAG（用检索而非重训来更新知识）。「如何让大模型低成本地跟上世界变化而不灾难性遗忘」是当下最受关注的方向之一。

延伸阅读：Kirkpatrick 2017《Overcoming Catastrophic Forgetting (EWC)》、French 1999（遗忘现象的源头）、Lopez-Paz & Ranzato 2017（GEM，回放类方法）、Parisi 2019（持续学习综述）、Sculley 2015 反馈回路一节、Huyen 2022 持续学习与线上测试章。完整清单见 references.md。
