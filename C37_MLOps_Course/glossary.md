# 术语词典 · Glossary（MLOps 与生产生命周期）

> 按主题分组，每条 2–3 句释义。读 MLflow / DVC / Evidently 文档、Google MLOps 白皮书、漂移检测论文遇到生词回这里查；英文术语保留原文（社区与工具文档的通用语言）。本课用标准库 + numpy/pandas 从零实现这些概念，但术语与真实 MLOps 平台一一对应。

## 总体范式 · The MLOps Paradigm

| 术语 (EN) | 中文 | 释义 |
|-----------|------|------|
| MLOps | 机器学习运维 | 把 DevOps 的工程纪律（版本、CI/CD、监控、自动化）扩展到机器学习全生命周期的实践集合。它管的不只是代码，还有数据、模型与持续演化的生产行为。 |
| ML lifecycle | 机器学习生命周期 | 从问题定义→数据→训练→评测→部署→监控→反馈→重训练的循环。关键在于它是一个**闭环**：上线不是终点，而是下一轮的起点。 |
| hidden technical debt | 隐藏的技术债 | Sculley 等 2015 的核心论点：ML 系统里真正的 ML 代码只占一小块，环绕它的配置、数据依赖、胶水代码、监控、复现才是债务主体，且比传统软件债更隐蔽、更难偿还。 |
| CACE principle | 改一处动全身 | 「Changing Anything Changes Everything」。ML 系统中没有真正独立的输入：动一个特征、一个超参、一份数据，整个模型的行为都可能变，所以无法像传统模块那样隔离测试。 |
| training/serving skew | 训练-服务偏斜 | 训练时的数据处理与线上服务时不一致（特征计算、缺失值、时区、单位），导致线上效果远差于离线评测。是生产事故的高发区。 |
| pipeline | 流水线 | 把数据处理→训练→评测→部署等步骤串成可自动重跑、可追溯的有向流程。MLOps 的目标之一是让整条 pipeline 一键可复现。 |
| reproducibility | 可复现性 | 给定同一份代码 + 数据 + 配置 + 随机种子，能复现出同一个模型与同一组指标的能力。是实验追踪、版本控制、门禁一切信任的地基。 |
| determinism | 确定性 | 同样输入每次得到字节级相同输出。ML 里要靠固定 seed、固定库版本、固定运算顺序（甚至关闭某些并行/GPU 非确定算子）才能逼近。 |
| ML Test Score | ML 测试评分 | Breck 等 2017 提出的 28 项生产就绪度清单，覆盖数据、模型、基础设施、监控四大类。每项 0/0.5/1 计分，总分越低系统越脆。本课大量条目对应它的检查项。 |
| level 0/1/2 automation | 自动化成熟度 | Google MLOps 白皮书的分级：L0 全手工、L1 自动化训练流水线（持续训练 CT）、L2 自动化 CI/CD 流水线。等级越高，人从循环里退得越远。 |

## 实验追踪 · Experiment Tracking

| 术语 (EN) | 中文 | 释义 |
|-----------|------|------|
| experiment / run | 实验 / 运行 | run 是一次具体训练的记录（一组参数 → 一组指标 + 产物）；experiment 是一组相关 run 的容器。MLflow 的核心数据模型即 experiment ⊃ run。 |
| parameter (param) | 参数 | run 的**输入**配置，训练期间不变：学习率、层数、随机种子、数据版本号等。与 metric 的区别是「输入 vs 输出」。 |
| metric | 指标 | run 的**输出**测量，常随训练步变化：loss、accuracy、AUC、F1。可只存最终值，也可存整条曲线（带 step/time）。 |
| artifact | 产物 | run 产出的文件：模型权重、混淆矩阵图、预测 CSV、特征重要性。追踪器要记录它的路径与（理想情况下）内容哈希以便复现。 |
| run id | 运行号 | 一次 run 的唯一标识，常用随机 UUID 或基于内容/时间的哈希。它是把参数、指标、产物、日志串起来的主键。 |
| tag / metadata | 标签 / 元数据 | 附在 run 上的轻量键值（git commit、数据集名、负责人、环境）。用于检索、过滤、归类，不参与训练。 |
| leaderboard / comparison | 排行榜 / 比较 | 把多个 run 按某指标排序、并排看参数差异的视图。MLOps 的「选最优模型」就是在这上面做的，必须固定比较口径（同一测试集、同一指标）。 |
| config hash | 配置哈希 | 对一次实验的全部配置（参数 + 数据版本 + 代码版本）做哈希得到的指纹。两个 run 配置哈希相同 ⇒ 应当可复现出相同结果，是复现性的廉价校验。 |
| seed | 随机种子 | 控制随机数生成器初始状态的整数。固定它（且固定库版本与运算顺序）是可复现的第一步；不记录 seed 的 run 几乎不可复现。 |
| logging API | 记录接口 | 追踪器暴露给训练代码的调用，如 `log_param` / `log_metric` / `log_artifact`。本课模块 01 从零实现这套接口并落盘到 JSON。 |

## 版本与血缘 · Versioning & Lineage

| 术语 (EN) | 中文 | 释义 |
|-----------|------|------|
| content-addressable storage (CAS) | 内容寻址存储 | 用「对内容做哈希得到的指纹」当存储地址，而非用文件名/路径。相同内容只存一份（天然去重），且地址即校验和——Git、DVC、IPFS 的共同基石。 |
| content hash / digest | 内容哈希 / 摘要 | 对数据字节做 SHA-256 等得到的定长指纹。内容变一比特，哈希就全变；哈希相同则内容（几乎必然）相同。是不可变性与完整性校验的来源。 |
| immutability | 不可变性 | 一旦写入就永不修改的存储语义。版本系统靠它保证「v3 永远是当时那份数据」，从而让实验可复现、可审计。改动只能产生新版本，不能覆盖旧版本。 |
| snapshot | 快照 | 某一时刻数据/模型的完整、不可变记录。内容寻址下，快照就是一组内容哈希的集合（manifest）。 |
| version tag | 版本标签 | 给某个内容哈希起的人类可读别名（如 `v1.2`、`prod`、`champion`）。标签是可移动的指针，哈希是不可变的真身——类似 Git 的 tag/branch 指向 commit。 |
| lineage / provenance | 血缘 / 来源 | 记录「这个模型由哪份数据、哪段代码、哪些上游产物得到」的依赖关系，通常是一张有向无环图（DAG）。出问题时靠它回溯根因、做影响分析。 |
| DAG (Directed Acyclic Graph) | 有向无环图 | 节点是资产（数据/代码/模型）、边是「由…产生」的依赖。lineage、pipeline 都用 DAG 表达；无环保证可以拓扑排序、可重放。 |
| diff | 差异 | 两个版本之间的变化集合。数据 diff 可以是行级（新增/删除/修改的行）或 schema 级（列增删、类型变化）；本课从零实现一个数据集 diff。 |
| manifest / index | 清单 / 索引 | 列出一个版本包含哪些文件及其内容哈希的元数据文件。pull 一个版本 = 读 manifest，按哈希取回每个文件。 |
| schema | 模式 | 数据的结构契约：列名、类型、取值范围、可空性。schema 校验能在数据进入训练前拦住「上游悄悄改了格式」这类事故。 |
| data drift vs schema change | 数据漂移 vs 模式变化 | 前者是分布变了但结构没变（模块 04），后者是结构本身变了（列消失、类型改）。两者都要监控，但检测手段与处理方式不同。 |

## 评测门禁与 CI/CD · Evaluation Gates & CI/CD

| 术语 (EN) | 中文 | 释义 |
|-----------|------|------|
| evaluation gate | 评测门禁 | 在模型晋升（promote）到下一环境前自动跑的一组检查，不通过就拦截。它把「上线靠人拍脑袋」变成「上线靠可重复的规则」。 |
| promotion | 晋升 | 把一个模型版本从一个阶段推进到下一个（staging→production）。门禁就守在每次晋升的关口。 |
| threshold / SLO | 阈值 / 服务水平目标 | 指标必须达到的绝对底线（如 AUC ≥ 0.85、p95 延迟 ≤ 100ms）。SLO 是面向用户承诺的可靠性目标，门禁常把它编码成硬阈值。 |
| regression | 回归 | 新版本在某指标上比基线（当前生产模型）**变差**。门禁不仅看绝对阈值，还看相对回归——哪怕仍达标，掉得太多也该拦。 |
| champion / challenger | 冠军 / 挑战者 | champion 是当前生产模型，challenger 是候选新模型。门禁的本质是让 challenger 在公平条件下与 champion 比较，赢了且显著才放行。 |
| statistical significance | 统计显著性 | 观测到的指标差异有多大概率只是随机波动。两个模型差 0.3% 可能纯属噪声；要先确认差异显著，再据此做晋升决策。 |
| bootstrap | 自助法 | 用「有放回重采样测试集 + 重算指标」上千次，得到指标的经验分布与置信区间。无需分布假设，是给 ML 指标加误差棒、判显著的实用利器。 |
| confidence interval (CI) | 置信区间 | 指标真值有较高概率落入的区间（如 95% CI）。两模型 CI 不重叠是差异显著的一个直观信号；本课用 bootstrap 从零算它。 |
| permutation test | 置换检验 | 把两组样本的标签随机打乱多次，看「观测差异」在零假设（无差异）下有多极端，得到 p 值。判两模型指标差异是否显著的无分布方法。 |
| canary / shadow deployment | 金丝雀 / 影子部署 | canary：先把新模型放给一小部分流量，出问题影响面小、可快速回滚。shadow：新模型只接收流量但不返回结果，纯用于离线对比。 |
| rollback | 回滚 | 把生产模型切回上一个已知良好的版本。版本不可变 + 标签可移动让回滚变成「把 `prod` 指针指回旧哈希」，秒级且确定。 |
| flakiness | 偶发失败 | 同样输入下时而通过时而失败的不稳定测试/门禁，常因随机种子未固定或资源竞争。它会侵蚀团队对门禁的信任。 |

## 监控与漂移 · Monitoring & Drift

| 术语 (EN) | 中文 | 释义 |
|-----------|------|------|
| data drift / covariate shift | 数据漂移 / 协变量偏移 | 输入特征分布 $P(x)$ 随时间变化，而 $P(y\mid x)$ 不变。模型本身没坏，但见到的输入越来越偏离训练分布，效果随之下滑。 |
| concept drift | 概念漂移 | 输入到输出的映射关系 $P(y\mid x)$ 本身变了（用户偏好变、欺诈手法变）。这才是模型「过时」的根本原因，且常常更难察觉。 |
| label shift / prior shift | 标签偏移 / 先验偏移 | 类别比例 $P(y)$ 变了（如欺诈率从 1% 升到 5%）。它会让阈值、校准、甚至准确率的解读全部失真。 |
| PSI (Population Stability Index) | 群体稳定性指数 | 衡量同一变量在两个时期分布差异的工业界常用指标：按分箱比较占比，$\sum (p_i-q_i)\ln(p_i/q_i)$。经验阈值 0.1 / 0.25 区分轻微/显著漂移。 |
| KS statistic | KS 统计量 | Kolmogorov–Smirnov 两样本检验的统计量：两个经验累积分布函数（ECDF）之间的最大纵向距离 $\sup_x|F_1(x)-F_2(x)|$。对连续变量漂移敏感且无分布假设。 |
| KL / JS divergence | KL / JS 散度 | 衡量两个概率分布差异的信息论量。KL 不对称（$D_{KL}(P\|Q)\ne D_{KL}(Q\|P)$），JS 是其对称、有界的变体。PSI 本质是对称化的 KL。 |
| ECDF (Empirical CDF) | 经验累积分布函数 | 由样本估计的累积分布：$\hat F(x)=\frac1n\sum \mathbb 1[x_i\le x]$。KS 检验、分位数、QQ 图都建立在它之上。 |
| sliding / rolling window | 滑动窗口 | 只用最近一段时间的数据来估计当前分布/性能（如最近 7 天）。窗口太短噪声大、太长反应慢，是漂移监控的关键调参。 |
| reference / baseline window | 参考 / 基线窗口 | 被当作「正常」的历史分布（常是训练集或上线初期），用来和当前窗口比对。漂移 = 当前窗口显著偏离参考窗口。 |
| alerting threshold | 告警阈值 | 触发告警的统计量临界值（PSI > 0.25、KS p < 0.01）。设太松漏报、太紧误报刷屏（alert fatigue），需结合滑窗与多重检验校正。 |
| performance monitoring | 性能监控 | 直接追踪线上真实指标（准确率、AUC、业务 KPI）。难点是**标签延迟**：真值往往要等很久才到，期间只能靠漂移做「性能下滑的早期预警」。 |
| label delay / feedback latency | 标签延迟 / 反馈时延 | 从模型预测到拿到真值之间的时间差（贷款是否违约要等几个月）。它决定了你能多快知道模型变差，也决定监控为何要依赖无标签的漂移信号。 |
| proxy metric | 代理指标 | 真值未到前，用可立即获得的信号（漂移分、置信度分布、预测分布变化）近似模型健康度。是性能监控在标签延迟下的现实替身。 |
| multiple testing / FDR | 多重检验 / 错误发现率 | 同时对几百个特征做漂移检验，纯靠运气就会有一批「显著」。需用 Bonferroni / Benjamini–Hochberg 等校正控制假阳性，否则告警全是噪声。 |

## 反馈闭环与重训练 · Feedback Loop & Retraining

| 术语 (EN) | 中文 | 释义 |
|-----------|------|------|
| feedback loop | 反馈闭环 | 把线上结果（用户点击、人工标注、真值回流）收集起来反哺下一轮训练的回路。它让模型能随世界变化持续进化，但也可能放大偏差（见下）。 |
| direct/indirect feedback | 直接/间接反馈 | 直接：用户显式标注（点赞、纠错）；间接：从行为推断的弱信号（停留时长、是否点击）。间接反馈量大但有偏，需谨慎当作标签。 |
| labeling / annotation | 标注 | 给收集到的样本打上真值的过程，常是闭环里最贵、最慢的一环。主动学习用模型的不确定性挑「最值得标」的样本以省成本。 |
| active learning | 主动学习 | 让模型挑选信息量最大的样本（如预测最不确定的）优先送去标注，用最少标注换最大提升。是反馈闭环里降本的关键策略。 |
| retraining trigger | 重训练触发 | 决定「何时该重训」的条件：定时（每周）、漂移超阈、性能跌破 SLO、或攒够 N 条新标注。触发逻辑写错会导致要么重训过频烧钱，要么太晚而模型早已劣化。 |
| continual / online learning | 持续 / 在线学习 | 模型在新数据上增量更新而非每次从头训。省算力、反应快，但有灾难性遗忘与稳定性风险，需配合回放、正则等手段。 |
| catastrophic forgetting | 灾难性遗忘 | 在新任务/新分布上继续训练时，模型急剧丢失旧任务上的能力。是持续学习的核心难题；本课用一个玩具实验量化它（旧测试集准确率的跌幅）。 |
| stability–plasticity dilemma | 稳定-可塑性困境 | 模型既要可塑（学得进新知识）又要稳定（不忘旧知识），两者天然矛盾。持续学习的所有方法本质都在这条权衡线上取点。 |
| replay / rehearsal | 回放 / 复演 | 重训时混入一批旧数据（或其代表样本/生成样本），提醒模型别忘了旧分布。是对抗灾难性遗忘最简单有效的手段之一。 |
| feedback bias / runaway loop | 反馈偏差 / 失控回路 | 模型影响了它将来要学的数据（只推荐过的内容才有点击，于是越推越窄）。这种自我强化回路会让模型逐渐脱离真实世界，是闭环系统的特有风险。 |
| human-in-the-loop (HITL) | 人在回路 | 在关键决策点保留人工审核/标注/否决。高风险场景（医疗、风控）用它兜底，也为闭环提供高质量真值。 |
| model decay / staleness | 模型劣化 / 陈旧 | 模型效果随时间自然下滑（因数据/概念漂移）。重训练就是对抗 decay 的手段；监控漂移则是判断 decay 何时严重到需要重训的依据。 |

## 工具与生态 · Tooling & Ecosystem

| 术语 (EN) | 中文 | 释义 |
|-----------|------|------|
| MLflow | —— | 开源的实验追踪 + 模型注册 + 打包/部署平台。其 Tracking 的 experiment/run/param/metric/artifact 数据模型是本课模块 01 的现实对照。 |
| DVC (Data Version Control) | 数据版本控制 | 把大数据/模型用内容寻址存到对象存储、用小指针文件纳入 Git 管理，并能定义可复现 pipeline。本课模块 02 从零实现它的内容寻址内核。 |
| model registry | 模型注册表 | 集中登记模型版本、阶段（staging/production/archived）、元数据与审批的系统。晋升、回滚、审计都在这里发生，是版本+门禁的落地处。 |
| feature store | 特征存储 | 集中计算、存储、复用特征的系统，保证训练与服务用**同一份**特征定义，专治 training/serving skew。 |
| Evidently / NannyML / Alibi-Detect | —— | 开源的数据/概念漂移与模型监控库，内置 PSI、KS、分布报告与告警。本课模块 04 从零实现它们的统计内核。 |
| Great Expectations | —— | 数据质量校验框架：把「这列不应为空、取值应在 0–1」等期望写成可执行断言并在 pipeline 里把关。对应本课的 schema/数据校验思想。 |
| CT (Continuous Training) | 持续训练 | 在 CI/CD（持续集成/交付）之上，ML 特有的第三个 C：自动化地按触发条件重训并经门禁后部署。Google MLOps 白皮书 L1/L2 的核心能力。 |
| Airflow / Kubeflow / Argo | —— | 编排 DAG 式 pipeline 的工作流引擎，负责「按依赖顺序、可重试、可追溯地」跑数据/训练/部署各步。本课不用它们，但 lineage DAG 的思想一致。 |
| observability | 可观测性 | 通过日志、指标、追踪让系统内部状态对外可见的能力。MLOps 把它从「服务是否在线」扩展到「模型是否还准、数据是否还正常」。 |
