1这门课讲什么：训练完才是开始

欢迎来到 MLOps 与生产生命周期。这门课只想纠正一个新手最常见的误解：以为模型训练完、指标跑得漂亮，活就干完了。

真相恰恰相反。借用 Sculley 等人那篇被引爆的论文标题——Hidden Technical Debt in Machine Learning Systems——里最有名的一张图：在一个真实的生产 ML 系统里，你亲手写的那段「ML 代码」只是正中间一个很小的方块，环绕它的是体量大得多的配置、数据收集、特征工程、数据校验、机器资源管理、流程管理、监控、服务基础设施。训练一个好模型，只是点亮了这个小方块；把它安全地、可复现地、能长期运转地嵌进那一大圈基础设施里，才是 MLOps 的主战场，也是本课的全部内容。

更扎心的是：ML 系统的技术债比传统软件更隐蔽。传统代码有清晰的模块边界，可以隔离测试；而 ML 系统遵循一条叫 CACE（Changing Anything Changes Everything，改一处动全身）的铁律——动一个特征、一个超参、一份数据，整个模型的行为都可能漂移，没有哪个输入是真正独立的。再加上数据会随时间变（用户变了、世界变了），一个今天 95% 准确率的模型，三个月后可能悄无声息地烂掉，而你的单元测试一个都不会红。

一句话概括本课的世界观：传统软件部署后行为基本不变，坏了会报错；ML 系统部署后行为持续漂移，坏了往往不报错、只是慢慢变差。所以 MLOps 要解决的根本问题，是给一个活的、会变质的系统装上：可复现的资产（实验追踪 + 版本）、安全的放行闸门（门禁）、上线后的体温计（监控/漂移）、和随环境进化的能力（反馈/重训）。这正是本课五个模块。

2生命周期闭环与五个模块

把上面的世界观落成一张生命周期循环图。注意它是个闭环——最后一步绕回第一步，因为上线不是终点，而是下一轮的起点：

问题定义 ──▶ 数据 ──▶ 训练 ──▶ 评测 ──▶ 部署 ──▶ 监控 ──▶ 反馈 ─┐ ▲ │ └──────────────── 重训练 ◀──── 触发条件满足 ◀─────────────────┘ 传统软件：写代码 → 测试 → 部署 → （行为冻结，坏了会抛异常） ML 系统 ：上面那个环，永远在转 —— 数据在变、概念在变、模型在静默劣化

本课不平均用力，而是聚焦在这个环里最容易被技能课跳过、却最决定系统能否长期存活的五段。每段对应一个模块，每个模块对应偿还 Sculley 论文里的一类债：

模块生命周期阶段从零造的工具偿还的技术债
01训练 / 实验实验追踪器（params/metrics/artifacts + 比较 + 复现）复现债、配置债
02数据 / 资产内容寻址版本库（hash + lineage + diff）数据依赖债、不可追溯
03评测 → 部署评测门禁（阈值 + 回归 + bootstrap 显著）无质量闸门、靠人拍脑袋上线
04监控漂移检测器（PSI + KS + 滑窗告警）监控缺位（最贵的债）
05反馈 → 重训反馈→触发→重训→评估闭环（含遗忘度量）反馈回路、模型静默劣化

Breck 等人的 ML Test Score 把「系统是否生产就绪」拆成 28 项可勾选的检查（数据测试、模型测试、基础设施测试、监控测试四大类），每项 0/0.5/1 计分。本课很多 worked 与练习就是在亲手实现其中的具体条目——比如「特征分布有监控吗」「模型能一键回滚吗」「训练可复现吗」。读完本课，你应当能给自己手上的系统打一个 ML Test Score。详见 references.md。

3课程地图：从可复现资产到上线后的生命

课程地图：从可复现资产到上线后的生命

训完之后的世界（本课的领地）： 模块 01 实验追踪 「这个模型是怎么来的？换个 seed 能复现吗？哪个 run 最好？」 │ → 从零写 tracker：log params/metrics/artifacts + 比较 + config 哈希 ▼ 模块 02 版本与血缘 「上线的到底是哪份数据、哪份权重？出事能回滚吗？」 │ → 内容寻址存储 + 不可变快照 + lineage DAG + 数据 diff ▼ 模块 03 评测门禁 「这个新模型该不该放行？它真比线上那个好，还是只是噪声？」 │ → 阈值 + 相对回归 + bootstrap 置信区间 + 放行决策 ▼ 模块 04 监控与漂移 「上线三个月了，它还准吗？没有标签我怎么知道？」 │ → PSI 分箱 + KS/ECDF 两样本检验 + 滑窗 + 告警阈值 ▼ 模块 05 反馈与重训 「世界变了，模型该什么时候、怎么重训？会不会越训越窄、越学越忘？」 → 反馈聚合 + 重训触发 + 灾难性遗忘度量 + 完整闭环模拟

这不是松散的专题集合，而是一条时间上严格递进的链：你得先能复现并版本化一个模型（01–02），才谈得上用门禁判断该不该放它上线（03），上线后才需要监控它何时变质（04），变质了才触发反馈与重训（05），而重训出的新模型又回到 01 被追踪、被版本化——环就这样转起来。每个模块都为后一个模块提供它需要的「信任基础」。

每一站都对应一个可独立验证的能力：模块 01 你能从一堆 run 里用代码挑出最优且可复现的那个；模块 02 你算出的内容哈希能在内容变一比特时全变、能回放任意历史版本；模块 03 你写的门禁会在「提升不显著」时正确地拦住一次晋升；模块 04 你的 PSI/KS 会在分布真的漂移时报警、在只是抖动时保持安静；模块 05 你能量化出持续学习里旧任务掉了多少分（灾难性遗忘）。每一步都有 assert 兜底，绝不靠「看起来对了」。

4方法论：从零造工具，而非调平台 API

方法论：为什么从零造工具，而不是教你调 MLflow？

市面上的 MLOps 课大多是API 巡游：教你 mlflow.log_metric(...)、dvc add ...、evidently.Report(...)。这有用，但有个致命问题——工具会过时、会换、会改 API，而它们背后的机制不会。三年后你用的可能不叫 MLflow，但「实验追踪」这件事的内核（params/metrics/artifacts 的数据模型、run 比较、config 哈希复现）一定还在。

直白说

所以本课反其道而行：把每个工具的核心机制用标准库从零写一遍。你会亲手实现一个「小 MLflow」、一个「小 DVC」、一个「小 Evidently」。代码很短（每个几十行），但逻辑完全正确、能真跑、assert 全过。写完你再去看真工具的文档，会有一种「哦，原来它就是在做这件事，只是加了存储后端/并发/UI」的通透感。

严谨说

技术上：全课只用 numpy / pandas 和标准库（hashlib 做内容寻址、json 做记录落盘、sqlite3 做轻量查询、tempfile 做隔离的真实小工具）。不装任何 MLOps 平台、不联网（漂移数据用合成的真实分布偏移）。每个工具都配 assert 验证它的不变量（哈希确定性、版本可回放、PSI 对相同分布≈0、门禁拦截逻辑正确），保证你写的是对的工具而不只是「能跑的」工具。

MLOps 工具本课的 stdlib 实现对应真实工具
实验追踪log_param/metric/artifact → JSON 文件 + run 比较函数MLflow Tracking
数据/模型版本hashlib.sha256 内容寻址 + manifest + lineage dictDVC / Git internals
评测门禁阈值规则 + 相对回归 + bootstrap 重采样 CITFX gating / CI 检查
漂移检测PSI 分箱 + KS/ECDF 两样本检验 + 滑窗Evidently / NannyML
重训触发触发规则函数 + 闭环状态机 + 遗忘度量Continuous Training (CT)

务必清楚本课不教什么：不教某个具体平台的 UI/CLI 全部参数、不搭真实的分布式存储/编排集群、不接真实云服务。这些在你理解了机制之后都是「读文档 + 填配置」的工程活（references 里的 MLflow/DVC/Airflow 文档接手）。本课负责把机制与正确性夯死——这一步搞定，换任何平台你都能秒懂它在干嘛、出了问题知道去哪查。

5环境与运行

环境与运行

环境极简：numpy + pandas + 标准库，全部 CPU 秒级运行，无需 GPU，无需联网（漂移模块的「真实数据」用受控的合成分布偏移，逻辑与真实 CSV 漂移完全一致）。

conda create -n mlops python=3.11 -y && conda activate mlops
pip install numpy pandas       # 必需
pip install matplotlib         # 可选，仅用于画漂移/指标曲线
jupyter lab

每个模块配一个 notebook，结构统一：先用标准库把工具从零实现并验证（worked 小节，每节都跑出可打印的结果与 assert 自检），再做 3–4 道带 assert 判分的 ✏️ 练习（先给骨架，自己填，再对照 📖 参考答案），最后一个真实数据胶囊（用尽量真实的数据/配置把工具跑一遍，把纸面机制接到现实）。

建议的学习节奏：先读完整章 HTML 建立「生命周期视角」与机制直觉，再打开 notebook 亲手把工具写出来。读和做缺一不可——只读会觉得「这些概念我都知道」，但真正动手写「内容哈希为什么要不可变」「bootstrap 怎么重采样」「PSI 分箱边界怎么定」「重训触发条件怎么不抖」时，才会发现魔鬼藏在哪些细节里。这门课的深度正是为「动手造一套能跑的工具」服务的。

配套先读：Sculley《Hidden Technical Debt in ML Systems》建立「训完才是开始」的世界观；Breck《ML Test Score》当生产就绪自查表；Google MLOps 白皮书看完整流水线长什么样。完整清单见 references.md。

✅ 学完整门课，你应该能：
  1. 说清 ML 系统为何比传统软件债更重（CACE、数据漂移、监控缺位），并对照 ML Test Score 给系统打分；
  2. 从零写一个实验追踪器，记录 params/metrics/artifacts，比较多个 run 并可复现地选出最优；
  3. 用内容寻址哈希实现不可变版本库，构建 lineage 血缘 DAG，对两版数据做 diff；
  4. 实现评测门禁：绝对阈值 + 相对回归 + 用 bootstrap 判断提升是否统计显著，给出放行/拦截决策；
  5. 从零实现 PSI 与 KS 两样本检验，配滑动窗口与告警阈值，检测数据/概念漂移；
  6. 把反馈→触发→重训→评估串成闭环，并用旧测试集准确率的跌幅量化灾难性遗忘；
  7. 把以上 stdlib 实现映射到 MLflow/DVC/Evidently/Airflow，知道生产里下一步该用什么、为什么。
