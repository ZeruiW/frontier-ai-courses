1这门课讲什么

欢迎来到 前沿智能体（MCP / computer use / agentic RL）。这门课只追求一件事：让你从「会调用一个 agent 框架」变成「会写 agent 的内核」。

过去两年 AI 最大的范式迁移，不是模型又大了多少，而是它从「一次问答」变成了「在循环里自主行动」：Claude / Operator 这样的系统不再只回答问题，而是调工具、连软件、改代码、操作界面，跨几十上百步把一个真实任务做完。这门课要往下钻一层：当一个 agent「自己去查资料、改文件、跑测试、点按钮」时，包在那个 LLM 外面的那层代码到底在做什么？它怎么把模型的输出解析成动作、怎么执行、怎么把结果喂回去、怎么在出错时不崩、怎么不被网页里藏的一句话劫持？

这些问题的答案不在任何模型里，而在模型外面的脚手架（scaffold）里。一个朴素的事实是：同一个模型，配一个好 scaffold 和一个差 scaffold，能力可能差十倍（SWE-agent 论文正是证明了这一点）。前沿 agent 的能力，与其说长在模型权重里，不如说长在「让模型可靠地调工具、连软件、自主多步行动」的那套工程上。本课就是把这套工程的五个核心零件——结构化工具调用、MCP 协议、computer use、agentic RL、评测与安全——从零拆开、亲手重建。

学完你应当能回答这类问题（也是 agent / infra 岗位的高频面试题）：function calling 的一次完整往返里发生了什么？JSON Schema 校验该挡住什么、怎么挡？MCP 凭什么能解决 M×N 集成爆炸，它的握手长什么样？computer use 的截图→动作循环怎么终止、怎么防误操作？编码 agent 的 RL 用什么当奖励、信用怎么分配？为什么 pass@k 高的 agent 在生产里 pass^k 可能很低？——并且能在 numpy / 标准库 + MockLLM 里把这五样东西都从零跑通、用 assert 验证。

一句方法论上的话先说在前面：本课的价值不在「我们没有大模型/API key 也能学」这个妥协，而在它逼你只关注真正难、真正不过时的部分——协议、控制流与正确性。模型会换代、厂商接口会变、提示工程的奇技淫巧明年就过时；而「一次工具调用如何编解码与校验」「一个 agent 循环如何安全地终止」「一条轨迹的成败如何归因」这些结构性的东西，换到任何模型、任何厂商都立刻能用。把它们练扎实，就抓住了 agent 工程里真正稳定的那一层。

2世界观：agent = 感知-动作循环

贯穿全课的世界观，是把 agent 理解成一个感知-动作循环（perceive-act loop），而非一次问答。一次问答是「输入 → 输出」，结束；一个 agent 是：

┌──────────────────────────────────────────────┐ ▼ │ 观察 observation ──► LLM（策略 policy） ──► 动作 action │ (工具结果/截图/报错) 想 + 决定调什么 (工具调用/点击) ▲ │ │ 环境 environment 执行 │ └────────────── 返回新观察 ◄─────────────────┘ 直到：完成 / 超步数 / 模型声明结束 / 触发护栏

这张图就是整门课的总纲：每个模块都是在实现或加固这个循环的某一部分。模块 01（工具调用）实现的是「动作」如何被结构化地表达、校验、分发——循环里 LLM→环境 的那条边；模块 02（MCP）实现的是「环境」如何用一套开放协议把工具与数据接进来——让这个循环能即插即用地连上任意外部能力；模块 03（computer use）把「观察」换成截图、把「动作」换成鼠标键盘，让循环能操作任意 GUI；模块 04（agentic RL）问的是「如何用这个循环产生的轨迹去改进策略 LLM 本身」——把循环从「使用」变成「训练」；模块 05（评测与安全）则是给整个循环装上「能不能信」的度量（pass^k）与「会不会被劫持」的防线（注入攻防、权限沙箱）。

把这张循环图记牢，你会发现五个看似分散的前沿话题其实是同一个循环的五个面：动作怎么表达（01）、环境怎么接入（02）、观察怎么换成屏幕（03）、循环怎么反过来训练模型（04）、整个东西可不可靠可不可信（05）。这也是本课刻意的编排——不堆专题，而是绕着一个核心对象层层加深。

3为什么「调工具」是枢纽：能力递进链

为什么「调工具」是这一切的枢纽

如果只能记住一句话来理解当代 agent，那就是：一个 LLM 单靠自己只能产生文本；它要改变世界、要获取新信息，唯一的通道就是「调工具」。搜索引擎、代码执行、文件读写、数据库、浏览器、乃至 MCP 接进来的任意外部系统——在 agent 眼里都是「工具」。所以工具调用是 agent 与世界之间的全部接口，本课把它放在第一个实质模块（01）不是偶然。

顺着这条枢纽往外看，本课的五个模块构成一条能力递进链：

模块在循环里加了什么一句话能力
01 工具调用把「动作」结构化：定义、校验、分发、并行、重试让 LLM 能可靠地调一个工具
02 MCP把「环境」标准化：用开放协议即插即用地接入任意工具/数据让任意外部能力都能被任意 agent 复用
03 computer use把「观察/动作」换成屏幕与鼠标键盘让 agent 能用没有 API 的任意软件
04 agentic RL用循环产生的轨迹 + 可验证奖励反过来训练策略让 agent 越用越强（而非只靠提示）
05 评测与安全给循环装上可靠性度量与被劫持的防线让 agent 可被信任地放到生产里

注意这不是松散的专题集合，而是一条有内在逻辑的链：先有可靠的工具调用（01），才谈得上用协议把工具规模化接入（02）；把工具的边界从「有 API 的」推广到「任意 GUI」（03），动作空间就完整了；有了能产生轨迹的完整循环，才谈得上用 RL 改进它（04）；而一个能调工具、连软件、自我改进的 agent，一旦放到真实世界，可靠性与安全就从锦上添花变成生死攸关（05）。读到最后你会看到：所谓「前沿 agent」，就是把这五块严丝合缝地拼起来。

4方法论：用 MockLLM 模拟 agent 并对拍

方法论：没有大模型、没有 API key，怎么学写 agent？

本环境没有 GPU、不接任何真实大模型、不需要任何 API key。但 agent 工程的难点，从来不是「调用模型这一行 API」，而是包在模型外面的那一切：工具怎么定义与校验、循环怎么组织与终止、协议怎么编解码、动作怎么解析、错误怎么恢复、轨迹怎么算奖励、注入怎么防、可靠性怎么量。这些用纯 numpy / 标准库 + 一个假模型就能精确地表达和验证。

我们的核心工具叫 MockLLM：一个确定性的、规则驱动的假模型。它不学习、不联网、没有神经网络——只是对给定的上下文，按预设规则返回一个结构正确的工具调用或文本（比如「看到问 天气 就返回 调用 get_weather(city=...)」）。这听起来像作弊，恰恰相反：把模型换成确定性的桩，能力的不确定性就被剥离，剩下的全是 scaffold 的对错。你写的工具注册表、schema 校验器、agent 循环、MCP 握手、注入检测器，在 MockLLM 下要么对、要么错，没有「模型今天状态不好」的借口——这正是把工程逻辑练成肌肉记忆的最干净环境。

直白说

打个比方：学开车不一定要在高速上练。agent 的「车技」是怎么把模型输出变成动作、怎么管循环、怎么校验与防护；这些在一个安全、可重复的「驾校场地」（MockLLM）里能练得更扎实。等场地里每个动作都做对了，换到真实路况（真实模型）只是把方向盘从教练车换成自己的车——逻辑一模一样。

严谨说

关键纪律是对拍 + assert：每个内核都和一个朴素参考实现或明确的不变量比对。schema 校验器要在合法输入上放行、在每一类非法输入上拦截；agent 循环要在 N 步内终止且产出正确答案；MCP server 对 `tools/call` 要返回与直接调用函数一致的结果；pass^k 的计算要等于 $p^k$ 的解析值。结构正确 → assert 通过；assert 通过 → 这套逻辑可以原样搬到真实模型。

真实 agent 系统里的东西本课的模拟对应真实接口
大模型（决定调什么工具）MockLLM：规则驱动的确定性桩Anthropic messages.create / OpenAI chat
工具定义（含 JSON Schema）Python dict + 自写 schema 校验器Anthropic input_schema / OpenAI parameters
一次工具调用往返tool_use → 执行 → tool_result（自写）Anthropic tool_use / tool_result 内容块
MCP server 进程一个本地 Python 对象 + JSON-RPC 编解码真实 MCP server（stdio / HTTP）
截图与 GUI 动作numpy 数组当「屏幕」+ 结构化动作computer use 截图 + click/type
RL 训练回路玩具 REINFORCE + 可验证奖励PPO + SWE-bench 式测试奖励

务必清楚本课不教什么：不教提示工程的具体话术、不调真实模型的超参、不接真实危险工具、不追求 SOTA 分数。这些在你有了正确的 scaffold 之后，是第二步（references 里的官方文档、SWE-bench、τ-bench 接手）。本课负责把第一步——协议、控制流与正确性夯死；这一步搞定，第二步才有意义。也正因如此，本课的代码刻意不调用任何需要密钥的服务，你随时能 `python` 跑通每一个 cell。

5环境与运行

环境与运行

环境极简：只需 Python 3 标准库 + numpy（个别可视化可选 matplotlib）。全课 CPU 秒级运行，无需 GPU、无需联网、无需任何 API key。凡是用到「模型」的地方都是 MockLLM。

conda create -n frontier-agents python=3.11 -y && conda activate frontier-agents
pip install numpy            # 必需
pip install matplotlib       # 可选，仅个别图
jupyter lab

每个模块配一个 notebook，结构统一：先用 numpy / 标准库把机制从零实现并验证（5–6 个 worked 小节，每节都跑出可打印的输出与 assert 自测），再做 3–4 道带 assert 判分的 ✏️ 练习（先给骨架，自己填，再对照 📖 参考答案），最后一个真实数据胶囊（用真实工具 schema / 真实任务配置 / 真实协议形状，把纸面知识接到现实）。每个 notebook 都端到端可跑、不需要密钥；并在关键处旁附真实 Anthropic / OpenAI / MCP 接口的形状对照，让你看清 MockLLM 与真实模型的逐行对应——学完照着把验证过的 scaffold 接到真实模型，是最自然的下一步。

建议的学习节奏：先读完整章 HTML 建立直觉与协议框架，再打开 notebook 亲手实现。读和做缺一不可——只读会觉得「好像懂了」，真正动手写校验器、调维度、让循环正确终止、让 assert 通过时，才会发现魔鬼藏在哪些细节里（必填字段漏检、并行结果回传方式、握手顺序、坐标换算、信用分配、注入边界）。这门课的深度正是为「动手」服务的。

配套先读：Anthropic tool use 文档（工具调用接口）、MCP 规范（modelcontextprotocol.io）、ReAct（Yao 2022，循环范式）、SWE-agent（Yang 2024，scaffold 即能力）、τ-bench（Yao 2024，pass^k 可靠性）、Greshake 2023（间接注入）。完整清单见 references.md。

✅ 学完整门课，你应该能：
  1. 把一个任务拆成「感知-动作循环」，说清 scaffold 在每条边上做什么；
  2. 从零写工具注册表 + JSON Schema 校验 + 调用分发，处理并行调用与错误重试，对接（Mock）LLM 跑通一个 ReAct 回路；
  3. 讲清 MCP 的 host/client/server 与 resources/tools/prompts，并从零实现一个 mini MCP 的 JSON-RPC 握手、列举、调用闭环；
  4. 实现一个 computer-use 的截图→动作循环：动作解析、坐标映射、循环终止、防误操作护栏；
  5. 写一个玩具 agentic RL：轨迹采样 + 可验证奖励 + REINFORCE 更新，并理解信用分配、reject sampling、pass@k；
  6. 区分并计算 pass@k 与 pass^k，搭注入检测 + 权限沙箱 + 监控信号，做最基本的 agent 安全评测；
  7. 把验证过的 numpy / MockLLM scaffold 映射到真实 Anthropic / OpenAI / MCP 接口，知道下一步怎么接真模型。
