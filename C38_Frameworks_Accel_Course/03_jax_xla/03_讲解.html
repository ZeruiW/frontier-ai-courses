1两条路线：操作张量 vs 变换函数

模块 01、02 走的是 PyTorch 的路线：命令式 + 动态图——张量带着梯度状态（.grad），loss.backward() 改写这些状态，再 torch.compile 事后捕获优化。本模块换一条根本不同的路线：JAX 的函数式 + 可组合变换。它的世界观和 PyTorch 截然不同，理解这个不同，你对「框架」的认识会立刻立体起来。

一句话点出分野：在 PyTorch 里你操作张量（x.backward()、opt.step()）；在 JAX 里你变换函数。求梯度不是「让张量反向传播」，而是 grad(f)——接受一个函数 f，返回一个新函数（它算 f 的梯度）。批处理不是「加一维循环」，而是 vmap(f)——返回 f 的批量化版本。编译不是事后捕获，而是 jit(f)——返回 f 的编译版本。全是函数 → 函数的高阶操作。

直白说

打个比方：PyTorch 像在工作台上摆弄零件——你直接拿起张量、给它求导、更新它。JAX 像有一套能改装函数的工具：给它一个函数，它还你一个「会求导的版本」「会批处理的版本」「编译过的版本」。而且这些改装工具能叠着用——「先批处理、再求导、再编译」就是 jit(grad(vmap(f)))，像乐高一样拼。

严谨说

形式上：JAX 的核心是一组functional transform（函数变换），每个都是 (函数) → (函数) 的高阶函数：grad（reverse-mode AD）、vmap（自动向量化）、jit（XLA 编译）、pmap（多设备并行）。它们可任意组合，因为每个都只是「再 trace 一遍、做某种变换」，输入输出都是纯函数。

把两种世界观逐项摆出来，你会看清这不是表面语法差异，而是两套对「计算」的根本不同的组织方式：

维度PyTorch（命令式）JAX（函数式）
核心动作操作有状态的张量（.backward()、.step()）变换无状态的纯函数（grad/vmap/jit）
梯度副作用：写进 x.grad返回值：g = grad(f)(x)
状态（参数/RNG）藏在 Module/全局 RNG（可变）显式传入传出（不可变）
批处理手写 batch 维 / 循环vmap 自动向量化
编译torch.compile 事后附加jit 一等公民、与变换共生
控制流原生 Python（eager 下自由）需 lax.cond/scan（纯函数约束）
调试直观（随时 print、动态）较陡（jaxpr、jax.debug.print）

一句话抓住本模块：JAX = 纯函数 + 可组合的函数变换。本模块用模块 01 的 autograd 思想，从零实现 numpy 版的 grad 与 vmap，并验证它们能自由组合（如 grad(vmap(f)) == 逐样本求导）。你会亲手体会为什么「函数式」是变换可组合的前提——这正是 JAX 与 PyTorch 最深的设计差异。

2纯函数：一切的前提

纯函数：一切的前提

JAX 的一切变换都有一个硬性前提：被变换的必须是pure function（纯函数）——输出只由输入决定，没有副作用（不改全局变量、不做 IO、不依赖隐藏的可变状态、不原地修改输入）。这不是风格建议，而是能不能安全变换的根本要求。

为什么纯函数如此关键？因为 JAX 的变换都要trace（追踪）这个函数——用抽象值跑一遍、记录它做了什么（模块 02 讲过 tracing）。如果函数有副作用（比如依赖一个全局计数器、或打印），trace 只会捕获到第一次的行为，副作用本身丢失；如果函数原地改了输入，重排或并行执行就会出错。只有纯函数，trace 出来的图才忠实、可缓存、可重排、可并行。

直白说

纯函数像数学里的函数：同样的输入永远给同样的输出，不留痕迹、不看外界脸色。这样的函数你可以放心地求导、批处理、编译、并行——因为它的行为完全由输入决定，没有任何「暗箱」。

严谨说

代价是 JAX 要求你把状态显式化。PyTorch 的 nn.Module 把参数藏在对象里（可变状态），JAX 则把参数作为显式输入传进纯函数、把更新作为显式输出传出来。随机数也一样：JAX 不用全局 RNG（那是隐藏状态），而是把随机 key 显式传递、显式分裂（split）。这套「无隐藏状态」的纪律，正是函数式的精髓。

一个直接后果：JAX 里不能随手写 for i in range(n): state += ... 去依赖外部可变状态，也不能指望 Python 的 if x > 0 在 trace 后还起作用（模块 02 的「控制流被烤死」）。数据相关的控制流要用 jax.lax.cond/scan/while_loop 这些结构化原语显式写——它们能被 trace 进图并保留语义。这是 JAX 换取「全程序可变换」付出的代价：你得用它的方式写控制流。

3grad：把求导变成函数变换

grad：把求导变成函数变换

JAX 求梯度的接口是 grad：给定纯函数 f: 参数 → 标量，grad(f) 返回一个新函数，输入同样的参数、输出梯度。底层仍是模块 01 的反向模式 AD，但暴露方式完全不同：

PyTorch（命令式）JAX（函数式）
求梯度loss = f(x); loss.backward()；读 x.gradg = grad(f)(x)
状态梯度作为张量的副作用属性 .grad梯度作为返回值，无副作用
二阶导create_graph=True 再 backwardgrad(grad(f))（直接再变换一次！）
对谁求导对 requires_grad=True 的张量对第几个参数（argnums）

这个差异看似只是语法，实则深刻。因为 grad(f) 返回的还是一个纯函数，你可以再对它做任何变换：grad(grad(f)) 就是二阶导（对求导函数再求导，自然得很），vmap(grad(f)) 就是「对一批输入分别求梯度」，jit(grad(f)) 就是「编译过的梯度函数」。在 PyTorch 里这些都要特殊处理（create_graph、手动批处理、compile），在 JAX 里只是把变换叠起来。

\[\texttt{grad}:\ (f:\mathbb{R}^n\!\to\!\mathbb{R})\ \longmapsto\ (\nabla f:\mathbb{R}^n\!\to\!\mathbb{R}^n)\qquad\text{——一个把函数映成函数的算子}\]

这个「返回值 vs 副作用」的差别，决定了组合是否可能。PyTorch 的 x.grad 是张量的一个属性（副作用）——你没法对「一个副作用」再求一次导、再批处理一次，因为它不是函数。而 grad(f) 是个函数，函数天生可以再被任何接受函数的高阶操作处理。把梯度做成返回值、把求导做成函数变换，是 JAX 一切组合能力的源头——这不是 API 品味问题，而是数学结构问题：只有「函数 → 函数」的东西才能像函数复合一样自由叠加。

本模块 notebook 会用模块 01 的 autograd 思想，实现一个 numpy 版 grad(f)：它内部 trace f、建图、反向传播，但对外暴露成「函数 → 函数」。你会验证 grad(f)(x) 与数值梯度一致，并体会到「梯度是返回值而非副作用」带来的组合性——这是理解 JAX 的钥匙。

4vmap：自动向量化

vmap：自动向量化

第二个核心变换 vmap（向量化映射）解决一个极常见的痛点：你写了一个处理单个样本的函数，却要把它高效地应用到一批样本上。传统做法要么写 Python 循环（慢），要么手动给每个运算加 batch 维、处理广播（易错、改写量大）。vmap(f) 让你只写单样本逻辑，它自动把函数提升为批量版本。

直白说

打个比方：你写好了「怎么处理一张图片」，vmap 自动帮你变成「怎么处理一批图片」——而且不是套个 for 循环，而是把每个运算整体向量化（一次算完整批），高效得多。你不用在代码里到处操心 batch 维，逻辑保持单样本的清爽。

严谨说

形式上：vmap 沿一个新增的批轴把函数里的每个原语提升——标量运算变成逐元素、matmul 变成批量 matmul。它在 trace 时就把批维「推」过整个计算图，等价于自动插入正确的广播/批处理，但比手写更不易错、且能被 XLA 进一步融合。in_axes/out_axes 控制哪些参数沿哪个轴批处理。

你写的（单样本）: f(x) x: (d,) -> 标量 vmap 后（一批） : vmap(f)(X) X: (B, d) -> (B,) vmap 不是 for 循环，而是把每个算子整体向量化： 单样本里的 w·x (点积) --vmap--> X @ w (一次算完 B 个点积)

机制再说细一点，破除「vmap 是不是偷偷套了循环」的疑惑。vmap 在 trace 时给每个中间值附带一个批维标记（这维是批轴、还是没有批轴），然后逐 primitive 改写规则：x*y 两个操作数都带批 → 仍是逐元素（批维对齐）；w·x 里 w 无批维、x 有 → 升成 X @ w（批量矩阵-向量积）；遇到 sum 这类规约则只沿非批轴规约。整条链改写完，得到的是一个一次处理整批、没有任何 Python 循环的新计算图——这就是它比手写 for 快的根因：批并行被表达进了算子本身，交给 BLAS/XLA 一次算完。

最妙的是 vmap 与 grad 的组合。vmap(grad(f)) 给出「每个样本各自的梯度」（per-sample gradients，差分隐私、影响函数都要它，PyTorch 里很麻烦）；grad(vmap(f_sum)) 则是「批损失对参数的梯度」（普通训练）。同样两个变换，叠的顺序不同，语义不同——而你只写了一遍单样本的 f。本模块 notebook 会实现一个 numpy 版 vmap（最简版用沿批轴映射 + 结果堆叠表达语义），并验证 vmap(f)(X) 与逐样本 for 循环逐位一致、且能与 grad 组合。

5jit 与 pytree：编译与嵌套结构

jit 与 pytree：编译与嵌套结构

jit：把 XLA 接上

jit(f) 返回 f 的编译版本：首次调用时 trace 出 jaxpr（JAX 的 IR，模块 02 讲过 IR），交给 XLA 编译器融合、优化、生成内核，缓存编译产物；之后同形状调用直接复用。这和 torch.compile 殊途同归（都是 trace + 编译 + 缓存），区别在 JAX从设计之初就是函数式，jit 是一等公民、与其他变换天然可组合，而非事后附加。

和模块 02 一样，jit 也受 tracing 的约束：控制流被烤死（要用 lax 原语）、形状变化触发重编译（有 guard/缓存机制）。一个 JAX 特有的坑是 jit 里不能用普通 Python if x>0（x 是抽象 tracer，没有具体值），必须 lax.cond——这正是「纯函数 + 结构化控制流」纪律的体现。

pytree：穿过嵌套容器

真实模型的参数不是单个张量，而是嵌套的字典/列表（每层一组 W/b）。JAX 用 pytree 统一处理这种嵌套：变换会自动「穿过」pytree、作用到每个叶子（张量）上。核心操作是 tree_flatten（把嵌套结构拆成「扁平的叶子列表 + 结构定义 treedef」）和 tree_unflatten（用 treedef 把叶子装回原结构）。

# pytree：一个模型参数的嵌套结构
params = {'layer1': {'W': W1, 'b': b1},
          'layer2': {'W': W2, 'b': b2}}
leaves, treedef = tree_flatten(params)   # leaves=[W1,b1,W2,b2], treedef 记住嵌套形状
# grad(loss)(params) 自动对每个叶子求梯度，返回【同样结构】的梯度 pytree
# 优化器更新：new = tree_map(lambda p,g: p - lr*g, params, grads)  <- 逐叶子

pytree 解决的核心矛盾是：变换想作用在「一堆张量」上，而模型参数是「有结构的一堆张量」。tree_flatten 把结构（treedef）与内容（叶子列表）分离——于是变换只管对扁平的叶子列表做事（求导、更新、分片），完全不用懂结构有多复杂；做完再用 treedef 把结果装回同样的结构。这就是为什么 grad(loss)(params) 能对任意嵌套的 params 工作、还返回同构的梯度：它内部就是 flatten → 对叶子求导 → unflatten。结构与内容分离，是 pytree 让函数式范式能驾驭真实模型的关键抽象。

pytree 是 JAX 处理复杂模型的黏合剂：grad(loss)(params) 返回与 params同构的梯度 pytree；tree_map 让你对所有叶子做同一操作（如梯度下降更新）。本模块 notebook 会从零实现 tree_flatten/tree_unflatten/tree_map，并验证「展平再装回 == 原结构」、用它对一个嵌套参数做梯度更新——你会看到为什么函数式范式下，处理任意复杂的模型参数也只是「对叶子列表操作」这么简单。

6组合：函数式训练循环

把它们组合：函数式训练循环

把上面四件事拼起来，JAX 的训练循环呈现出一种独特的函数式美感——没有可变状态，每步是「旧状态 → 新状态」的纯函数：

# JAX 风格训练步（纯函数，可被 jit） @jit def train_step(params, batch): loss, grads = value_and_grad(loss_fn)(params, batch) # 一次拿 loss + 梯度 pytree new_params = tree_map(lambda p, g: p - lr * g, params, grads) return new_params, loss # 显式返回新状态，无副作用 for batch in data: params, loss = train_step(params, batch) # 旧 params -> 新 params

直白说

对比 PyTorch 的 opt.zero_grad(); loss.backward(); opt.step()（三步都在改状态），JAX 的一步是 params, loss = train_step(params, batch)——参数进、参数出，整个 step 是个纯函数，可以整体 jit 编译、可以 vmap 到多组超参、可以 pmap 到多设备。状态显式化的回报，是整个训练步都能被变换。

严谨说

这里 value_and_grad 是 grad 的变体，一次同时返回函数值和梯度（避免重复前向）。整个循环里没有一处原地修改：params 每步被一个新的 pytree 替换。这正是纯函数范式——也是为什么 JAX 在需要对训练过程本身求导/并行的研究场景（元学习、大规模并行）特别受欢迎。

为什么纯函数对并行如此关键，值得再点一句。要把计算切到上千个芯片上跑，编译器必须能自由地重排、复制、分片你的运算——而这只有在没有隐藏状态、没有副作用时才安全（否则重排会改变结果、复制会让副作用发生多次）。纯函数恰好给了这个保证，所以 JAX 能把 pmap/shard_map 也做成一个变换：你写单设备的纯函数，它自动切分到多设备、插入通信。这就是「函数式」在大规模训练上的隐藏红利——可变换性 = 可并行性，两者同源于纯函数。这也是为什么前沿大模型（尤其 TPU 上的）大量用 JAX。

退一步看两条路线的取舍：PyTorch 的命令式让调试直观、上手快（随时 print 张量、动态控制流自由），代价是变换（编译、批处理）要事后附加、有缝；JAX 的函数式让变换天然可组合、极适合并行与高阶导，代价是要遵守纯函数纪律、控制流得用原语、调试曲线更陡。没有谁绝对更好——理解了这个取舍，你就能按任务选框架，也能在两者间迁移思想（PyTorch 的 functorch/torch.func 正是把 JAX 的 vmap/grad 函数式变换搬进 PyTorch）。

7工程现实与陷阱

工程现实与陷阱

先把本模块的「numpy 玩具复刻」与「真实 JAX」逐项对上号——你会看到我们复刻的是机制与心智模型，真版多的是编译与并行的工程：

维度本模块 numpy 玩具复刻真实 JAX/XLA
gradtrace 计算图 + 反向传播，对外是「函数→函数」同样语义，底层 XLA 编译的 VJP，支持 jacfwd/hessian
vmap沿批轴 map + 结果堆叠（讲清语义）在 trace 期把批维推过每个 primitive，零循环、可被 XLA 融合
jit（不实现）只讲 trace+缓存的道理trace 成 jaxpr → XLA 融合/优化/生成内核 → 按形状缓存
IR无（直接在 numpy 上跑）jaxpr（可 make_jaxpr 打印），再降到 HLO
设备只有 CPU/numpypmap/shard_map 自动切到多 TPU/GPU

看这张表的要点：玩具版不追求快（甚至 vmap 用 for 循环表达语义），它的价值是让你在没有 JAX 的环境里把「函数式 + 可组合变换」练成肌肉记忆；真版的全部额外复杂度，都是为了把同一套语义编译并行到上千芯片上高效执行。下面这些坑，正是真版为换取「全程序可变换」而要求你遵守的纪律：

  • 控制流必须用原语：jit 下 Python 的 if x>0/for 依赖具体值的部分会报错或被烤死。要用 lax.cond/lax.scan/lax.while_loop。scan 还能避免循环展开导致的编译爆炸。
  • 随机数显式化：没有全局 RNG。每次要随机就得有一个 key，用 jax.random.split(key) 分裂出新 key——忘了 split 会得到相同的随机数。这是纯函数对「随机」的必然要求。
  • 重编译陷阱：传入 Python int/bool 作为参数会被当成静态值，每变一次就重编译。要么标 static_argnums（确实想按它特化），要么转成数组（按值不重编译）。
  • 就地更新语法：不能 x[i] = v（张量不可变），要用 x.at[i].set(v)（返回新张量）。这是函数式「无副作用」的直接体现。
  • 调试更难：jit 里不能直接 print（trace 时机不对），要用 jax.debug.print；报错栈对应 jaxpr 而非源码。函数式的调试税。

一个统一的心法：把所有状态和随机性都显式地穿进穿出，把控制流交给 lax 原语。一旦接受了「函数进、函数出，没有暗箱」这套纪律，JAX 的所有变换就会像数学一样干净地组合起来。本模块的 numpy 复刻刻意保留这套纪律（纯函数、显式状态、grad/vmap 作为函数变换），让你在没有 JAX 的环境里也能把这套思维练成肌肉记忆。

8研究前沿与开放问题

研究前沿与开放问题

  • 可组合变换的边界：grad/vmap/jit 之外，还能定义哪些有用的函数变换（如 checkpoint、custom_vjp、自动并行）？它们如何与已有变换无缝组合，是 JAX 生态持续探索的。
  • 自动并行与分片：从 pmap 到 shard_map/Mesh/GSPMD——让编译器根据张量的分片标注自动插入通信、切分计算。把单设备程序自动扩展到上千芯片，是 JAX 在大模型训练的核心竞争力（与 C08 交叉）。
  • 函数式与命令式的融合：PyTorch 的 torch.func（前 functorch）把 JAX 式的 vmap/grad/jacrev 搬进 PyTorch。两种范式的边界在模糊，理想是「命令式的易用 + 函数式的可组合」兼得。
  • 高阶导与科学计算：grad(grad(...))、jacfwd/jacrev/hessian 让 JAX 在物理模拟、优化、概率推断等需要高阶导的领域大放异彩。如何让高阶导也高效（而非朴素嵌套）是活跃方向。
  • 编译器与 IR 的统一：jaxpr → HLO → XLA，与 PyTorch 的 FX → Inductor，是否会收敛到统一的 IR（如 StableHLO/MLIR），让模型在框架间无损迁移、共享编译优化？这是整个生态的开放问题。

必读：JAX 文档与《Autodidax: JAX core from scratch》（从零搭 trace/grad/vmap/jit，与本模块 numpy 复刻精确对应）、Bradbury 等的 JAX（函数式 + 可组合变换的出处）、Frostig 等 2018《Compiling ML programs via high-level tracing》（tracing 编译方法论）、XLA 文档。清单见 references.md。
