1这门课补什么洞

欢迎来到 深度学习框架与加速计算工程。在打开这门课之前，你大概已经走完了一段很长的路：在这套课程体系里，你用纯 numpy 从零写过反向传播、写过注意力、写过优化器，甚至在 C36 里用 numpy 模拟 GPU、从零拼出过 FlashAttention 的分块逻辑。你对「机制本身」已经了如指掌。

但有一个洞一直没补：真实的框架，是怎么把这些机制工程化地跑起来的？当你在 PyTorch 里写下 loss.backward()，是谁、按什么顺序、怎么把梯度算出来并分发到每个参数的？当你写 torch.compile(model)，框架对你的 Python 代码做了什么手术，才让它快了一截？当你写 jax.jit(jax.grad(f))，这两个变换为什么能像乐高一样叠在一起？当你开 autocast() 用半精度训练，为什么有时会得到 NaN、又为什么 GradScaler 能救回来？

这些问题的答案，不在任何一个「机制」里，而在框架这一层工程里——自动微分引擎、图捕获与编译器、函数式变换系统、混合精度与显存管理、性能剖析器。它们是把「能算对」变成「能在真实硬件上又快又稳又省地算」的那层胶水。这门课就专讲这层胶水：把你已经会的「纯 numpy 从零」，对接到「真实框架工程」。

学完你应当能回答这类问题（也是框架/系统岗位的高频面试题）：autograd 是怎么用一张计算图 + 链式法则把梯度反向传播的？torch.compile 的 tracing 与 scripting 差在哪、它怎么做算子融合？jax 的 grad/vmap/jit 为什么能自由组合？fp16 训练为什么需要 loss scaling，bf16 为什么通常不需要？gradient checkpointing 用多少算力换了多少显存？GPU 计时为什么必须先 synchronize？——并且能在 numpy 里把这五样东西的内核都从零复刻、与朴素参考或数值梯度对拍。

一句话先说在前面：本课不是教你调框架 API（那查文档即可），而是带你把框架的内核重写一遍。你会发现 autograd 不过是「一张图 + 每个算子的 VJP 规则 + 拓扑逆序遍历」，编译器的融合不过是「在图上做几个 pass」，jax 的变换不过是「接受函数、返回函数」的高阶组合。把这些内核亲手写通、用 assert 钉死正确性，你再回头看 PyTorch/JAX 的源码与设计文档，会有一种原来如此、我也能写的踏实。

2为什么需要框架：五栏能力

为什么需要框架？把一个最朴素的问题想清楚：如果你只有 numpy，训练一个模型缺了什么？

你用 numpy 已经能做但框架替你做了什么（本课讲）对应模块
写前向：matmul、激活、loss自动求所有参数的梯度（你不必手推每个 backward）01 autograd
一个算子一个算子地调用把整段计算捕获成图、融合、编译成少数快内核02 torch.compile
手写 for 循环处理 batch、手推梯度用 可组合变换 grad/vmap/jit 自动批处理与求导03 jax/xla
用 fp64/fp32 算，显存随手就爆混合精度提速省显存、checkpointing再省一截04 精度与显存

这张表就是本课的全部内容：框架 = autograd + 编译 + 变换 + 精度/显存管理 + 观测。每一栏都是一个「你用 numpy 能算对、但框架替你算得又快又省又稳」的能力，而本课要做的，是把每一栏背后的内核用 numpy 拆开重写，让你看清那层胶水到底是什么。

先归类，再优化

一个贯穿全课的认知（来自 Horace He 的名篇）：让深度学习跑得快，首先要分清瓶颈在哪——是等算（算力受限）、等数据搬运（访存受限），还是等调度与启动（开销受限）。框架的几乎每一项工程都在打其中一类瓶颈：算子融合打访存受限（中间结果不落主存）、图捕获 + CUDA Graph 打开销受限（少启动内核）、混合精度同时打算力与访存（半精度算得快、搬得少）。记住这三分法，本课每个模块你都能说清「它在省什么」。

还要破除一个常见误解：框架不是「更高级的 numpy」，而是一套编译/微分/调度系统。numpy 是「立刻把这个数组运算算出来」；而 torch.compile 和 jax.jit 是「先把你要算的整件事记下来、整体优化、再一次性高效执行」。理解这个从即时执行（eager）到图/编译执行的转变，是理解现代框架的总纲——也是模块 02/03 的主线。

3课程地图：从「会算」到「驾驭框架」

课程地图：从「会算」到「驾驭框架」

你已会：纯 numpy 从零写出每个机制（反向传播、注意力、优化器……） 本课补：真实框架怎么把它们跑快 / 跑稳 / 跑省显存 模块 01 autograd 自动微分内核 计算图 + 链式法则 + 每算子 VJP + 拓扑逆序 │ 「loss.backward() 内部到底做了什么？」 ▼ 模块 02 torch.compile 编译 tracing/scripting → IR → 融合/折叠/DCE │ 「编译器怎么把慢的 eager 代码变快？」 ▼ 模块 03 jax/xla 函数式变换 纯函数 + grad/vmap/jit 可组合 + pytree │ 「为什么变换能像乐高一样叠起来？」 ▼ 模块 04 混合精度与显存 fp16/bf16 + loss scaling + 激活重算 + 显存账 │ 「怎么又快又省地训练而不 NaN/OOM？」 ▼ 模块 05 性能剖析与调试 profiler(耗时/显存) + 瓶颈定位 + NaN 溯源 「慢在哪？NaN 从哪来？怎么测得准？」

这条链有一个清晰的逻辑：01 是地基（一切训练都从自动微分开始）；02、03 是两条编译/执行路线（PyTorch 的命令式 + 编译，JAX 的函数式 + 编译），它们是当今两大主流框架的灵魂；04 是资源工程（在固定硬件上把模型训得起、训得快）；05 是观测闭环（任何优化都得先能测、能调）。读完你会发现，所谓「框架」不是一个黑箱，而是这五块各自可拆、可重写的工程。

每一模块都对应一个可独立验证的能力：模块 01 你手写的 autograd 会与数值梯度对拍一致，并能训通一个小 MLP；模块 02 你的玩具 tracer 会捕获出正确的图、融合/折叠后结果不变；模块 03 你的 grad 和 vmap 能自由组合且与逐样本循环一致；模块 04 你能从 fp16 的位宽推出它何时下溢、给定梯度分布选对 loss scale、算出 checkpoint 的时间-显存权衡；模块 05 你的玩具 profiler 能按算子归因耗时、定位首个 NaN。每一步都有 assert 兜底，绝不靠「感觉对了」。

4方法论：numpy 复刻内核 + 真实 API 对照

方法论：用 numpy 复刻框架内核，真实 API 作对照

本课的核心方法，和这套课程一脉相承：用纯 numpy 把框架的内核从零写一遍。但这里要特别讲清楚，为什么对「框架工程」这个主题，numpy 复刻反而是最佳教学，而不是退而求其次。

直白说

真实框架的源码里，真正难的算法骨架（autograd 的图与 VJP、编译器的融合 pass、变换的组合）往往只占很小一部分，却被埋在浩如烟海的工程外壳里：CUDA 内核、调度器、内存分配器、各种 dtype/设备分支、几十层抽象。直接读源码，你会迷失在外壳里，看不清骨架。用 numpy 复刻，等于把外壳全部剥掉，只留下那段真正难的骨架，让它一览无余。

严谨说

形式上：框架的内核都是与硬件无关的算法结构——reverse-mode AD 是「DAG 上的拓扑逆序 + 局部 VJP」，算子融合是「图重写」，vmap 是「沿新批维提升每个原语」，loss scaling 是「IEEE 754 位宽下的一个数值技巧」。这些结构用 numpy 在 CPU 上能精确地表达和验证，和它将来运行在 A100 还是 TPU 上毫无关系。学的是骨架，骨架不随硬件过时。

具体怎么对接「真实框架」？本课的纪律是numpy 实现 + 真实 API 对照 + 对拍验证三件套：

框架机制本课的 numpy 复刻对照的真实 API
反向模式 autograd一个 Value/Tensor 类，记录图、定义每个算子的 VJP、拓扑逆序 backwardtorch.autograd / Function
图捕获 + 融合编译一个玩具 tracer 记录算子序列成图，再做融合/常量折叠/DCE 的 passtorch.compile / fx / Inductor
可组合函数变换纯函数 + grad/vmap 高阶函数 + pytree 展平jax.grad/vmap/jit
混合精度 + loss scaling模拟 fp16 舍入/溢出、选 loss scale、显存账与 checkpoint 权衡autocast / GradScaler
profiler + NaN 溯源计时 + 显存追踪的上下文管理器、逐算子检查 NaNtorch.profiler / anomaly

为什么把对拍（differential testing）提到方法论的高度？因为框架内核的 bug 极其阴险：梯度漏累加、广播没 sum 回去、融合改变了语义、loss scale 选错导致悄悄下溢——这些往往不报错，只是给出看起来差不多但其实错了的结果。所以本课每个内核都配一个绝对可信的参考：autograd 对拍数值梯度（有限差分，与你的实现无关），融合后的图对拍融合前的结果，vmap 对拍逐样本 for 循环。任何偏差都会被 assert 当场抓住。这套「先有 ground truth，再优化」的纪律，正是真实框架开发（与 PyTorch/JAX 对拍）的核心工作流。

关于环境，务必读清楚：本课不依赖 torch/jax 也能完整学完。所有 notebook 的核心代码是纯 numpy、CPU 可跑、assert 全过。真实的 torch.autograd/torch.compile/jax/autocast 代码作为对照展示在 markdown 里——若你的环境恰好装了 torch，少数对照 cell 可选实跑（用 try/except 优雅检测、缺了就当讲解读）；缺 torch/jax绝不会阻断任何练习或自测。本课要你掌握的是内核与原理，不是某个库的安装。

环境与运行

环境极简：只需 numpy。torch/jax 全部可选——有则少数对照可实跑，无则当讲解读，对练习与 assert 零影响。全课 CPU 秒级运行。

conda create -n frameworks python=3.11 -y && conda activate frameworks
pip install numpy            # 必需
pip install torch jax        # 可选：仅用于运行「真实 API 对照」cell；缺了不影响任何练习
jupyter lab

每个模块配一个 notebook，结构统一：先用 numpy 把内核从零复刻并对拍（5–6 个 worked 小节，每节都跑出可打印的验证与 assert），再做 3–4 道带 assert 判分的 ✏️ 练习（先给骨架，自己填，再对照 📖 参考答案），最后一个真实数据胶囊（用真实框架的配置/数值算一笔账，把内核接到现实）。每个 notebook 都附真实 PyTorch/JAX 对照代码，让你看清 numpy 复刻与真实框架的逐行对应——学完照着把验证过的逻辑接回真实框架是最自然的下一步。

建议的学习节奏：先读完整章 HTML 建立机制图景，再打开 notebook 亲手复刻内核。读和做缺一不可——只读会觉得「好像懂了」，真正动手写 backward 的拓扑逆序、调广播梯度的维度、让数值梯度对拍通过时，才会发现魔鬼藏在哪些细节里（梯度累加、广播 sum、就地操作、数值稳定）。这门课的深度正是为「动手」服务的。

配套先读：Baydin 等 2018 的 AD 综述（破除 autodiff 的误解）、Karpathy 的 micrograd（100 行看懂 autograd）、Horace He《Making Deep Learning Go Brrrr》（建立瓶颈三分直觉）。进阶：PyTorch 论文（Paszke 2019）、torch.compile 论文（Ansel 2024）、JAX 文档、混合精度（Micikevicius 2018）与 checkpointing（Chen 2016）。完整清单见 references.md。

✅ 学完整门课，你应该能：
  1. 从零写出一个反向模式 autograd 引擎（标量 + 张量版），用数值梯度对拍、训通一个小 MLP；
  2. 解释 tracing vs scripting，写一个玩具 tracer 捕获计算图，并在图上做算子融合、常量折叠、死代码消除；
  3. 实现 numpy 版的 grad 与 vmap 并自由组合，理解 JAX「纯函数 + 可组合变换 + pytree」的范式；
  4. 从 IEEE 754 位宽推出 fp16/bf16 的范围与精度，解释 loss scaling 为何必要、bf16 为何通常不需要，并选对 scale；
  5. 算出 gradient checkpointing 的时间-显存权衡与训练显存峰值（参数+梯度+优化器状态+激活）；
  6. 写一个玩具 profiler 按算子归因耗时与显存、用 roofline 定性瓶颈、定位首个 NaN 的来源；
  7. 把以上每个 numpy 内核映射到 torch.autograd/compile、jax、autocast/GradScaler、torch.profiler，知道下一步怎么用真框架。
