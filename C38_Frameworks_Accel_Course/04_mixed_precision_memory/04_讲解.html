1为什么要混合精度与省显存

前三个模块讲的是「怎么算对、怎么算快」。这个模块换一个维度——在固定的硬件上，怎么把模型训得起、训得省。答案有两条主线：用更低的数值精度（混合精度）省显存、提算力；以及精打细算激活显存、必要时用重算换显存（gradient checkpointing）。两条线都围绕一个现实约束：显存（与带宽）是稀缺资源。

先讲精度。深度学习长期默认 fp32（单精度，32 位）。但现代加速器在半精度（16 位）上算得快得多、显存与带宽只用一半。于是混合精度训练成了标配：大部分计算用 fp16/bf16，关键处保 fp32。但天下没有免费午餐——降精度会带来数值风险（溢出、下溢、舍入误差），理解并驯服这些风险，正是本模块前半的核心。

直白说

打个比方：fp32 像用高精度的尺子量东西，准但笨重；fp16 像用刻度粗一点的尺子，轻快但量不了太大或太小的东西（范围窄），还容易读不准最后一位（精度低）。混合精度的智慧是：大批量的粗活用粗尺子（快），少数要命的精细活换回精尺子（准）。

严谨说

形式上：一个浮点数把位分给指数（决定dynamic range动态范围）和尾数（决定相对精度）。fp16 是 1+5+10（范围窄、精度尚可），bf16 是 1+8+7（范围与 fp32 同、精度低）。范围窄是 fp16 训练的命门——梯度太小会下溢成 0（梯度消失），这就是 loss scaling 要解决的问题。

一句话抓住本模块前半：混合精度 = 用低精度算（快、省显存）+ 用技巧补偿低精度的数值缺陷（loss scaling、fp32 主权重）。本模块 notebook 会用 numpy模拟 fp16 的舍入与溢出，亲手看到梯度如何下溢消失、loss scaling 如何把它救回来——这些在真实 GPU 上是 autocast+GradScaler 自动做的，但你要看清它在做什么。

2IEEE 754：fp16 vs bf16

IEEE 754：fp16 vs bf16 的取舍

要理解混合精度的风险，得先看清三种格式如何分配它们的 16/32 个比特：

格式符号+指数+尾数动态范围（约）机器精度 eps（约）特点
fp321 + 8 + 231e±381e-7范围精度都够，但占 4 字节
fp161 + 5 + 106e-5 ~ 655041e-3范围窄！梯度易上溢/下溢 → 需 loss scaling
bf161 + 8 + 71e±38（同 fp32）8e-3范围大（通常免 loss scaling），但精度低

关键对比是 fp16 与 bf16：两者都是 16 位，但把比特花在了不同地方。fp16 多给尾数（精度），却只留 5 位指数——能表示的最大数约 65504，最小正规数约 6e-5，范围窄得危险。bf16 干脆把指数对齐到 fp32 的 8 位（范围几乎相同），代价是尾数只剩 7 位（精度低）。

直白说

为什么 bf16 后来居上成了大模型训练的主流？因为训练里最怕的不是「精度差一点」，而是「数值溢出/下溢导致 NaN 或梯度消失」。bf16 的大范围让它基本不溢出、不需要 loss scaling，训练稳得多；精度低一点，神经网络的鲁棒性大多能扛住。范围比精度更重要——这是混合精度的一条重要经验。

严谨说

形式上：动态范围 ≈ 2^(指数位决定)，机器精度 eps ≈ 2^(-尾数位)。fp16 指数 5 位 → 范围 ~2^15 量级（故 max≈65504）；bf16 指数 8 位 → 范围 ~2^127（与 fp32 同）。深度学习的梯度常常很小（1e-4 ~ 1e-8），在 fp16 的 6e-5 下限附近就开始成片下溢成 0；bf16 则游刃有余。这就是为什么 fp16 必须配 loss scaling，而 bf16 通常不必。

一个常被忽略的细节会在 notebook 里现身：fp16 还有次正规数（subnormal）。最小正规数是 ~6.1e-5，但靠损失精度，fp16 能用次正规表示到更小的 ~6e-8——所以 1e-7 的梯度其实勉强活着（次正规），而 1e-8 才真正被冲成 0。这解释了为什么「fp16 下溢」不是一刀切在 6e-5，而是个渐变的过程：先损失精度（进入次正规）、再彻底归零。工程上这无关紧要（次正规又慢又不准），结论不变——小梯度在 fp16 里岌岌可危，需要 loss scaling 把它们拉回正规范围。

把「为什么小更新会被吃掉」用 fp16 的尾数位算一遍，机制就具体了。fp16 尾数 10 位，意味着在 1.0 附近，能分辨的最小间隔（一个 ulp）≈ 2^-10 ≈ 1e-3；更一般地，在量级 2^e 处，相邻可表示数的间隔是 2^(e-10)。所以任何比当前值小约 1000 倍以上的加项，都落进同一个量化格、被直接舍掉：

fp16 的「大数吃小数」(尾数 10 位 → 相对分辨率 ~1e-3)： 0.1 + 1e-7 --fp16--> 0.1 ❌ 1e-7 远小于 0.1 的 ulp(~1e-4)，被吃 1.0 + 5e-4 --fp16--> 1.0 ❌ 5e-4 < 1.0 的 ulp(~1e-3)，被吃 1.0 + 2e-3 --fp16--> 1.002 ✅ 超过一个 ulp，留住了 启示: 参数(~0.1) + 微小更新(lr·grad ~1e-7) 在 fp16 里 == 没更新 → 必须在 fp32 主权重上累积更新（见第 4 节）

这正是后面「fp32 主权重」配方的数值动因：更新量 lr·grad 常比权重小 4~7 个数量级，在 fp16 里整段落在权重的一个 ulp 之内，加了等于没加；只有把更新累积在 fp32（尾数 23 位、ulp 小得多）上，这些微小增量才不会被舍入吞掉。一个「精度不够」的细节，直接决定了混合精度的整套架构。

本模块 notebook 会用 numpy 的 float16 实测这些边界：把一个 fp32 数转成 fp16 看舍入误差、把一个小梯度转 fp16 看它如何下溢成 0、把一个大数转 fp16 看它如何上溢成 inf、再现上面的「大数吃小数」。你会亲眼看到「同一个数，fp32 没事、fp16 出事」——这是混合精度一切技巧的动机。

3Loss scaling：救回下溢的梯度

Loss scaling：把梯度从下溢里救回来

fp16 训练最致命的问题是梯度下溢：反向传播算出的梯度常常很小（量级 1e-4 到 1e-7），落在 fp16 的最小正规数（~6e-5）附近或以下，于是被舍入成 0——梯度消失，参数不再更新，训练悄悄失败（不报错！）。loss scaling（损失缩放）是一个简单而精妙的对策。

核心思路：反向传播是线性的（梯度对 loss 线性）。所以如果在反向之前把 loss 乘一个大常数 S（如 1024、65536），那么所有梯度都会同比放大 S 倍——把它们从 fp16 的下溢区推到可表示的范围里。等梯度算完、转回 fp32 之后，再除以 S还原，更新参数。一放一缩，数值上完全等价，却避开了下溢。

\[\text{反向前：}\ L' = S\cdot L\ \Rightarrow\ \nabla' = S\cdot\nabla\quad(\text{放大，逃离下溢})\qquad\text{更新前：}\ \nabla = \nabla'/S\quad(\text{还原})\]
梯度量级 ~1e-8（fp16 含次正规, 下限 ~6e-8, 更小则冲成 0）： 不缩放: 1e-8 --转fp16--> 0.0 ❌ 梯度消失，参数不动 ×S=65536: 6.6e-4 --转fp16--> 6.6e-4 ✅ 落在可表示范围 反向后 /S 还原 --> 1e-8 ✅ 数值等价，但没丢

直白说

记一句话：loss scaling 把梯度临时『撑大』到 fp16 看得见的范围，算完再缩回来。放大和缩小相互抵消，对最终更新量没有影响——它纯粹是为了让中间的 fp16 表示不丢信息。

严谨说

S 怎么选？太小，下溢没救够；太大，梯度会上溢成 inf（fp16 上限 65504）。实践用动态 loss scaling（GradScaler 的默认）：遇到梯度出现 inf/nan（S 太大溢出了）就跳过本步更新、把 S 减半；连续若干步正常就把 S 翻倍试探更大的安全值。这样 S 自动跟着训练动态调整。

注意 bf16 通常不需要loss scaling——它的大动态范围让 1e-7 量级的梯度也能直接表示，不会下溢。这是 bf16 相对 fp16 在工程上的一大便利，也是它成为主流的原因之一。本模块 notebook 会模拟：一个小梯度在 fp16 下如何消失、loss scaling 如何救回、S 过大如何又上溢，并实现一个动态 loss scaler（遇 inf 减半、平稳翻倍）的判断逻辑。

下溢与上溢的双悬崖

loss scaling 走在两道悬崖之间：下面是下溢（S 太小，梯度成片归 0、训练停滞却不报错），上面是上溢（S 太大，梯度超 65504 变 inf，再与有限值相减还会冒出 nan）。动态 scaler 的精妙正在于把 S 顶到「快上溢但还没溢」的位置——一旦本步梯度里检出 inf/nan 就丢弃这步、S 减半（梯度已被污染，更新它只会把 nan 写进权重）；连续稳定若干步就 S 翻倍，重新逼近上界。实现时务必先检查 inf/nan、确认干净后再 unscale 并更新；顺序反了，nan 会先一步污染参数，整个训练当场报废。这是 fp16 训练最容易翻车、也最值得在 notebook 里亲手复现的一处。

4混合精度的完整配方

混合精度的完整配方

把上面拼起来，就是 Micikevicius 等 2018 提出、至今通用的混合精度训练配方。它不是「全部用 fp16」，而是一套精心的混合：

  1. fp32 主权重（master weights）：保留一份 fp32 的参数副本。这是权威的参数。
  2. 前向/反向用半精度：把权重转成 fp16/bf16 副本，用它算前向和反向（快、省显存、省带宽）。
  3. loss scaling（仅 fp16）：反向前乘 S、还原时除 S，防梯度下溢（bf16 通常跳过这步）。
  4. 在 fp32 主权重上更新：把（还原后的）梯度转 fp32，在 fp32 主权重上做优化器更新。
为什么要 fp32 主权重

为什么必须保留 fp32 主权重、在它上面更新？因为参数更新量 lr · grad 常常比权重本身小几个数量级（如权重 0.1、更新 1e-7）。如果直接在 fp16 权重上加这个微小更新，会被 fp16 的舍入吃掉——0.1 + 1e-7 在 fp16 里就等于 0.1，等于没更新。保留 fp32 主权重，让这些微小更新在 fp32 里累积起来，才不会丢失。这是混合精度里最容易被忽略、却最关键的一环。

直白说

直白说：你用「粗尺子」（fp16）干快活（前向反向），但把「真账本」（fp32 主权重）记在精尺子上。每次更新都更新真账本，再从真账本复制一份粗尺子版去算下一轮。这样既享受了 fp16 的速度，又不让微小的更新在粗尺子上丢掉。

严谨说

显存代价：fp32 主权重 + fp16 计算副本，参数显存其实略增（多了一份）。但激活（前向中间结果，往往是显存大头）用 fp16 减半，且 fp16 算力翻倍、带宽减半，总体仍是大赚。这也引出本模块后半的主题——激活显存才是大模型显存的真正大头，需要专门的招数（checkpointing）来对付。

PyTorch 把这套配方封装成 torch.autocast（自动为每个算子选精度：matmul/conv 用半精度、softmax/loss/规约用 fp32）+ GradScaler（自动 loss scaling）。你只需几行就能开启混合精度，但理解它内部在做这四步，才知道出问题时（NaN、不收敛）该查哪里——这正是本模块要给你的。

5激活显存与显存账

激活显存与显存账

训练一个模型，显存到底花在哪？算一笔显存账，是判断「能不能放进卡」「该怎么省」的基础。训练时的显存峰值由四部分构成：

显存项大小（量级）说明
参数 parametersP模型权重本身
梯度 gradientsP每个参数一个梯度，与参数同样大
优化器状态 optimizer state2P ~ 3PAdam 存一阶+二阶矩（2P），加 fp32 主权重，可达 3P
激活 activations∝ batch × seq × layers前向中间结果，为反向保留 —— 常是大头，且随 batch/序列/层数线性增长

一个反直觉但关键的事实：对大模型、长序列、大 batch，激活显存常常超过参数+梯度+优化器状态的总和。因为参数相关的部分（前三项）是固定的（≈4P~5P），而激活随 batch × seq_len × hidden × layers 增长——序列一长、batch 一大，激活就爆炸。这就是为什么长上下文、大 batch 训练特别吃显存。

\[\text{显存峰值}\ \approx\ \underbrace{P + P + kP}_{\text{参数+梯度+优化器(固定)}}\ +\ \underbrace{A(\text{batch},\text{seq},\text{layers})}_{\text{激活(可变,常是大头)}}\]

算一笔具体的账，体会比例。一个 P=1B（10 亿参数）的模型，用 Adam、fp32 训练：参数 4GB、梯度 4GB、Adam 两个矩 8GB——光参数相关就 16GB（≈16P 字节，因为 fp32 是 4 字节、Adam 是 2 份矩）。这还没算激活。若 batch=8、序列=2048、48 层，激活轻松再吃几十 GB——于是一张 40GB 的 A100 连个 1B 模型都未必训得动。这正是为什么大模型训练必须上混合精度（参数项减半、激活减半）+ checkpointing（激活再砍）+ 分片（参数项摊到多卡）的组合拳。

显存峰值发生在反向传播开始的那一刻：此时参数、梯度、优化器状态都在场，且前向产生的全部激活都还留着（反向要用）。理解这个峰值的构成，就知道每种省显存手段在省哪一块：混合精度把激活（和计算副本）减半；梯度检查点专砍激活这一项；ZeRO/FSDP（C08）把参数+梯度+优化器状态分片到多卡。本模块 notebook 会把这笔账用 numpy 算出来——给定模型规模、batch、序列长，估算显存峰值，并看每种手段省了多少。

6Gradient checkpointing：算力换显存

Gradient checkpointing：用算力换显存

既然激活是显存大头，能不能少存激活？gradient checkpointing（梯度检查点 / 激活重算）给出了一个漂亮的答案：反向需要哪个激活，就在反向时重新算它，而不是前向时存它。

朴素反向需要所有层的前向激活（用来算梯度），显存 O(L)（L 层）。checkpointing 的做法是：前向只保存少数几个检查点处的激活（如每 √L 层存一个），其余丢弃；反向走到某段时，从最近的检查点重新前向算出该段的激活，用完再丢。这样激活显存从 O(L) 降到 O(√L)，代价是多做约一次额外的前向计算。

朴素: 前向存下全部 L 层激活 显存 O(L)，反向不重算 [x0]→[x1]→[x2]→...→[xL] 全部留着 checkpoint: 只存 √L 个检查点 显存 O(√L)，反向重算段内 [x0]→ . → . →[x_ck]→ . → . →[xL] 只留●，反向时从●重算○ 时间代价 ≈ 多一次前向；显存省 ≈ √L 倍

直白说

打个比方：与其把做菜每一步的半成品都摆在台面上占地方（存全部激活），不如只留几个关键节点的半成品，需要中间某步时从最近的节点重做几步。台面（显存）清爽了，代价是有些步骤要做两遍（多花时间）。

严谨说

形式上是经典的时间-空间权衡（Chen 等 2016）。设 L 层，每 k 层放一个检查点：激活显存 ∝ k + L/k（段内激活 + 检查点数），在 k=√L 时最小，得 O(√L)。额外计算 ≈ 一次前向（每段重算一遍）。这是用大约 33% 的额外时间，换来平方根级的显存节省——对训得起更大模型/更长序列，极其划算。

checkpointing 其实是一条光谱的一端，另一端是「全存」（朴素反向）。两端之间，你可以选择存多少：存得多则显存大、重算少；存得少则显存小、重算多。更激进的一端是可逆网络（RevNet）——把层设计成数学上可逆，于是激活能从输出反推出来、几乎不用存（连检查点都省）；代价是网络结构受限、反推也是计算。再加上前沿的激活量化存储（把激活压成 fp8/int8 存、反向时解压），整个谱系都是同一个主题的变奏：在「存 vs 算 vs 压」之间为激活找最省的表示。checkpointing 是其中最简单通用、收益最稳的一招，故成了标配。

本模块 notebook 会实现这个权衡的计算：给定层数 L 和检查点间隔 k，算出激活显存与额外计算量，并验证 k=√L 附近显存最省；还会用一个玩具的「分段重算」模拟，确认重算得到的激活与原始前向逐位一致（重算不改结果，只换执行方式——和模块 02 融合的「保语义」一个道理）。

7工程现实与陷阱

工程现实与陷阱

混合精度与显存优化在生产中有不少坑，了解它们能让你训练更稳：

  • 哪些算子该留 fp32：autocast 默认让 matmul/conv 走半精度，但 softmax、loss、LayerNorm、规约（求和大量数）留 fp32——因为这些对精度/范围敏感，半精度会累积误差或溢出。理解这个清单，才知道为什么 autocast 不是「全 fp16」。
  • loss scaling 调不好：S 太小仍下溢、太大则上溢。动态 scaler 偶尔会因连续溢出反复跳步、训练停滞。bf16 免这个麻烦，是它更省心的原因。
  • checkpointing 的非确定性：重算若涉及 dropout/随机，必须用相同随机种子重放，否则重算的激活与原前向不一致、梯度算错。框架（torch.utils.checkpoint）会处理 RNG 状态，但自定义时要小心。
  • 显存碎片与缓存：实测显存常高于理论账（分配器碎片、缓存未释放）。OOM 不一定是「总量超了」，可能是碎片化。torch.cuda.empty_cache、调分配器策略是手段。
  • 精度与收敛：极少数模型在 fp16/bf16 下收敛变差（敏感的归一化、极端 logits）。对策是把敏感模块强制 fp32、或用 fp8 时配更精细的 per-tensor scaling（前沿）。

一个统一的判断：混合精度和 checkpointing 都是『用一种便宜资源换一种贵资源』——混合精度用「一点精度」换「算力+显存+带宽」，checkpointing 用「一点算力（重算）」换「大量显存」。做哪个取舍，取决于你卡在哪：缺算力就别过度 checkpoint，缺显存就上 checkpoint + 混合精度。这又回到模块 00 的瓶颈三分法——先知道瓶颈，再选省哪种资源。

8研究前沿与开放问题

研究前沿与开放问题

  • fp8 与更低精度训练：Hopper 起支持 fp8（E4M3/E5M2）。如何在 8 位下稳定训练（per-tensor/per-block scaling、混合 fp8/bf16）是前沿。再往下还有 int4/fp4 推理（与 C27 量化交叉）。
  • 显存-计算权衡的自动化：checkpointing 放哪几层、用什么精度，目前多靠经验。能否让编译器/调度器自动在给定显存预算下选最优重算策略（与模块 02 编译、C08 并行交叉），是活跃方向。
  • 激活压缩与可逆网络：除了重算，还能压缩激活（量化存储）或用可逆网络（激活可从输出反推、几乎不存）来省激活显存。各有精度/适用性的权衡。
  • 分布式显存：ZeRO/FSDP 把参数+梯度+优化器状态分片到多卡，配合 checkpointing 和混合精度，是训练超大模型的组合拳（C08 详述）。如何最优地协同这几种手段仍在演进。
  • 数值稳定性的理论：低精度训练何时收敛、何时发散，缺乏好的理论刻画。loss scaling 的最优策略、bf16 的精度损失对最终模型质量的影响，仍多靠实证。

必读：Micikevicius 等 2018《Mixed Precision Training》（fp16 + 主权重 + loss scaling 的奠基配方）、Chen 等 2016《Training Deep Nets with Sublinear Memory Cost》（checkpointing 原始论文）、Kalamkar 等 2019《A Study of BFLOAT16》（bf16 为何免 loss scaling）、Horace He《Making DL Go Brrrr》（瓶颈三分）。清单见 references.md。
