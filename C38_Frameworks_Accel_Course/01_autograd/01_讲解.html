1autograd 是什么、不是什么

你早就会手推反向传播了。给一个网络，你能一层层写出每个 backward。但 PyTorch 里你从不这么做——你只写前向，一句 loss.backward() 就把所有参数的梯度算了出来。这中间的「自动」二字，就是 autograd（自动微分引擎）。这门课的第一块地基，就是把它从零写出来。

先破除一个最普遍的误解：自动微分既不是符号微分，也不是数值差分。符号微分（如 SymPy）对表达式求导，复合层数一多表达式就指数爆炸；数值差分（有限差分）有截断误差和舍入误差、还慢。自动微分是第三条路：它把程序看成一串初等运算的复合，用链式法则在这串运算上精确（到机器精度）地传播导数——既没有表达式爆炸，也没有差分误差。

直白说

打个比方：自动微分不去「化简出导数公式」，也不去「左右各试一下看变化」，而是跟着你的计算一步步走，每过一个运算就顺手记下「这一步对结果的敏感度」，最后把这些敏感度按链式法则乘起来。它求的是你这段具体代码的导数，不是某个抽象公式的导数。

严谨说

形式上：任何程序都可分解为初等运算的复合 y = fₙ(…f₂(f₁(x)))。其雅可比是各步雅可比的连乘（链式法则）。自动微分就是把这个连乘按某个顺序求值——从左到右是前向模式，从右到左是反向模式。深度学习几乎只用反向模式，原因下一节讲。

把三条路并排看，差异一目了然——这也是面试里最爱考、初学者最易混的一点：

求导方式怎么做精度代价 / 问题
符号微分 symbolic对数学表达式套求导法则，得到导数的解析式精确复合层数一多，表达式指数爆炸（嵌套的乘积法则）；要求程序是闭式表达式
数值差分 finite-diff扰动输入、看输出变化 (f(x+ε)−f(x−ε))/2ε近似（有截断+舍入误差）每个输入要重算一次 → 对百万参数不可行；ε 难选
自动微分 autodiff沿程序的初等运算逐步传播导数（链式法则）精确（到机器精度）需记录计算图；但代价与函数求值同阶——这正是它的胜处

注意自动微分的精度和符号微分一样精确（它本质就是在用链式法则，只是逐数值地用、不展开成大表达式），却没有表达式爆炸；代价又和数值差分一样自动（不用手推公式），却没有差分误差、还能一次拿到对所有输入的梯度。它是把符号法则的精确与数值方法的可机械化两个优点合一——这就是为什么所有现代框架都用它。本模块的 Value 引擎，就是这第三条路最朴素的实现。

一句话抓住 autograd 的本质：一张记录了「谁由谁算来」的计算图，加上每个算子「本地怎么求导」的规则，再按拓扑逆序把梯度乘一路传回去。本模块就是把这三件事——建图、定义每个算子的本地导数、逆序传播——用 numpy 写成一个 ~100 行的引擎，然后用它训练一个真的小网络。你会发现 loss.backward() 真的没有魔法。

2前向 vs 反向模式

两种模式：为什么深度学习只用反向

链式法则给出的雅可比连乘，可以从两端任一端开始算，对应两种模式：

模式传播方向一次得到什么适合原子操作
前向模式 forward与计算同向（输入→输出）输出对一个输入的导数输入少、输出多JVP（雅可比×向量）
反向模式 reverse与计算反向（输出→输入）一个输出对所有输入的梯度输入多、输出少VJP（向量×雅可比）

深度学习的场景是一个标量损失，对成千上万到数十亿个参数求梯度——输入（参数）极多、输出（loss）只有一个。这恰好是反向模式的主场：一次反向传播就能拿到 loss 对所有参数的梯度。若用前向模式，得对每个参数各跑一次，代价与参数量成正比，完全不可行。所以 loss.backward() 用的是反向模式，本模块也聚焦它。

\[\text{反向模式：}\quad \bar{x} \;=\; \left(\frac{\partial y}{\partial x}\right)^{\!\top}\!\bar{y}\;=\;J^\top \bar{y}\qquad(\bar{\cdot}\ \text{表示 “loss 对它的梯度”})\]

这个式子是反向传播的全部。ȳ 是从下游传来的梯度（loss 对本运算输出的梯度），Jᵀ 是本运算的雅可比转置，乘起来得到 x̄（loss 对本运算输入的梯度），继续往上游传。关键在于：反向模式从不显式构造雅可比 J（它可能是 (百万×百万) 的巨阵），而是直接算 Jᵀ·ȳ 这个向量-雅可比积 VJP。每个算子只需会算自己的 VJP——这就是写 autograd 的核心工作。

代价的不对称是关键。设函数有 n 个输入、m 个输出。前向模式一趟给出一列雅可比（所有输出对一个输入），要 n 趟才凑齐整个雅可比；反向模式一趟给出一行（一个输出对所有输入），要 m 趟。深度学习里 m=1（标量 loss）、n 是参数量（巨大），所以反向模式一趟搞定，而前向模式要跑参数量那么多趟——这就是为什么 loss.backward() 必然是反向模式。代价上，一次反向的开销约为一次前向的 1–3 倍（与参数量无关），这是 AD 最惊人的性质：求全部梯度，和算一次函数值差不多贵。

为什么强调 VJP 而非雅可比？因为雅可比是「整个映射的全部偏导」，巨大且多数用不上；而 VJP 是「把一个具体的上游梯度向量，乘过这个映射的灵敏度」，正好是反向传播每一步要的东西，且通常有简洁的闭式（如 matmul 的 VJP 就是再做两个 matmul）。autograd 引擎 = 给每个算子配一条 VJP 规则 + 一套把它们串起来的机制。

3计算图：记录谁由谁算来

计算图：记录「谁由谁算来」

反向传播要按正确顺序把 VJP 串起来，就必须知道数据依赖。autograd 在前向时顺手建一张computational graph（计算图）：每产生一个新值，就记下它由哪个运算、从哪些父节点算来。

最小的实现（micrograd 风格）：把每个标量包成一个 Value 对象，它携带三样东西——数值 data、梯度 grad（初始为 0）、以及一个闭包 _backward（知道如何把自己的梯度分发给父节点）。每个运算（加、乘、tanh……）做两件事：算出结果的 data，并给结果挂一个 _backward 闭包，闭包里写死了「本运算如何把下游梯度按链式法则传给上游」。

# micrograd 风格的核心（标量版，本模块 notebook 从零写）
class Value:
    def __init__(self, data, _children=()):
        self.data = data
        self.grad = 0.0                 # loss 对本节点的梯度，反向时累加
        self._prev = set(_children)     # 父节点（建图）
        self._backward = lambda: None   # 把 self.grad 分发给父节点的规则
    def __mul__(self, other):
        out = Value(self.data * other.data, (self, other))
        def _backward():                # 乘法的 VJP：d(ab)/da=b, d(ab)/db=a
            self.grad  += other.data * out.grad   # 注意 += （梯度累加！）
            other.grad += self.data  * out.grad
        out._backward = _backward
        return out

反向时，从 loss 节点出发，按计算图的拓扑逆序依次调用每个节点的 _backward。拓扑逆序保证：轮到一个节点时，它所有下游的梯度都已传入、累加完毕，于是它能拿到完整的 out.grad 再分发给父节点。这就是 backward() 的全部骨架——建图在前向、逆序传播在反向。

用一个最小例子走一遍，把抽象坐实。算 L = (a·b) + a²，其中 a=2, b=-3。前向建出这张图，反向按逆序传梯度：

前向建图 (a=2, b=-3): 反向 (拓扑逆序, 从 L 起 L.grad=1): a───┐ L.grad = 1 ├─[*]──ab=-6──┐ 加法把 1 原样给两个加数: b───┘ ├─[+]──L=-2 ab.grad=1, a²(=t).grad=1 a───[²]──t=4─────┘ 乘法 ab: a.grad += b·1 = -3 b.grad += a·1 = 2 注意 a 出现两次(*和²) 幂 t : a.grad += 2a·1 = 4 (累加!) → 它的梯度要把两条路径相加 ⇒ a.grad = -3+4 = 1, b.grad = 2

看最后一步：a 同时喂给了乘法和平方两个运算，所以它的梯度是两条路径之和（-3 来自乘法、+4 来自平方），共 1。这正是下面那条「必须 += 累加」铁律的由来——也是 notebook 第 2 节会专门验证的点（若误用 =，a.grad 会变成 4 而非 1）。

梯度累加，不是赋值

最容易错、也最隐蔽的一个细节：梯度必须 += 累加，而不是 = 赋值。当一个节点被多个下游用到（计算图分叉再汇合，如同一个权重在多处出现），它的梯度是各条路径贡献之和。若写成 =，后一条路径会覆盖前一条，梯度算错却不报错——这是手写 autograd 的头号 bug。对应地，每次 backward 前要先把所有 grad 清零（PyTorch 的 optimizer.zero_grad() 就是干这个）。

4从标量到张量：VJP 与广播

从标量到张量：VJP 与广播

标量引擎讲清了原理，但深度学习是张量运算。张量版 autograd 的结构完全一样，只是每个算子的 VJP 变成张量运算。几个最常用算子的 VJP：

前向对输入的 VJP（ȳ = 上游梯度）说明
z = x + yx̄ += ȳ；ȳ += ȳ加法把梯度原样分给两个加数
z = x * y（逐元素）x̄ += y·ȳ；ȳ += x·ȳ乘法的本地导数是对方
Z = X @ WX̄ += Ȳ @ Wᵀ；W̄ += Xᵀ @ Ȳmatmul 的 VJP 是两个 matmul
z = relu(x)x̄ += (x>0)·ȳrelu 在负区梯度为 0
z = sum(x)x̄ += ȳ（标量）广播回原形状

张量 autograd 唯一新增的复杂度是broadcasting（广播）。前向时 numpy/torch 会把小张量自动广播以匹配大张量（如 (n,d)+(d,) 里偏置被复制 n 份）。反向时，这个复制操作的 VJP 是沿被广播的维度求和。直觉上：偏置的每一份拷贝都收到一份梯度，而它们其实是同一个参数，所以梯度要加总回去。

\[\text{广播是“复制”}\;\Rightarrow\;\text{它的 VJP 是“求和”}\quad(\text{沿被广播/被扩张的维度 } \texttt{sum})\]

直白说

记一句话就够：前向广播了哪个维度，反向就沿那个维度 sum 回去。比如偏置 (d,) 被广播到 (n,d) 上，它的梯度形状本该是 (d,)，但上游传来的是 (n,d)，所以沿 n（被广播出来的那维）求和。

严谨说

一般规则：把上游梯度 ȳ 还原回参数原形状，需要 (1) 对参数中不存在的前导维度求和，(2) 对参数中大小为 1但被广播成大于 1 的维度求和（保持维度）。notebook 里会写一个 unbroadcast(grad, shape) 工具专门干这件事——它是张量 autograd 正确性的关键。

把这些 VJP 规则各写一遍、再配上拓扑逆序遍历，你就有了一个能对任意由这些算子组成的计算图求梯度的张量 autograd。本模块 notebook 会从零写出标量版与张量版两套，并都用数值梯度对拍——任何 VJP 写错、任何广播没 sum 对，数值梯度都会当场抓出来。

5自定义算子：插一只手

自定义算子：当你想插一只手

有时你想为某个运算自定义反向：可能前向用了不可微的近似（如量化、argmax），需要给它一个「假装可微」的梯度；可能某个算子有数值更稳的解析梯度（如 softmax+交叉熵合并）；也可能你想嵌入一个外部内核。框架都留了这个口子——PyTorch 的 torch.autograd.Function（实现 forward 与 backward）、JAX 的 custom_vjp。

# PyTorch 自定义算子（对照；本课 notebook 用 numpy 复刻同一接口）
class MyReLU(torch.autograd.Function):
    @staticmethod
    def forward(ctx, x):
        ctx.save_for_backward(x)        # 存反向要用的张量
        return x.clamp(min=0)
    @staticmethod
    def backward(ctx, grad_out):        # 收到上游 ȳ，返回对输入的 VJP
        (x,) = ctx.saved_tensors
        return grad_out * (x > 0)       # relu 的 VJP

这个接口揭示了 autograd 引擎与算子之间的契约：引擎负责建图、按拓扑逆序调度、把上游梯度 grad_out 喂给你；你只负责回答一个本地问题——「给定上游梯度，本算子对它的各个输入的 VJP 是什么」。这正是本模块的核心抽象：autograd = 调度 + 一组 VJP 规则，而自定义算子就是让你往这组规则里加一条。

自定义反向的一个经典用途是 straight-through estimator（直通估计）：前向做一个不可微操作（如取整 round），反向却假装它是恒等函数（梯度直接穿过去）。这在量化训练里很常见——数学上「不对」，工程上却让梯度能流过不可微点。能这么做的前提，正是 autograd 把 forward 与 backward 解耦了：反向用的不是前向的真实导数，而是你声明的 VJP。

理解了这个契约，你也就理解了为什么 detach()/stop_gradient 能「切断梯度」——它不过是给一个节点装一条空的 VJP（前向值照传，反向梯度不再上溯）。target 网络、对抗样本的某些写法、EMA 等都靠它。autograd 的灵活，全在于这条「前向归前向、反向归你声明」的解耦。

6把引擎用起来：训练小 MLP

把引擎用起来：训练一个小 MLP

有了张量 autograd，训练循环就是它的直接应用，结构和 PyTorch 一模一样：

for epoch in range(E): pred = model(x) # 前向：自动建计算图 loss = mse(pred, y) # 标量损失，是图的根 zero_grad(params) # 清零（因为梯度是 += 累加的） loss.backward() # 反向：拓扑逆序传播，填好每个 param.grad for w in params: # 梯度下降 w.data -= lr * w.grad

notebook 会用从零写的张量 autograd 训一个两层 MLP 去拟合一个小回归任务，并验证两件事：(1) 每一步的解析梯度都对拍数值梯度通过；(2) 训练若干步后 loss单调下降。看着自己写的 backward() 真的把一个网络训出来，是这门课最有说服力的「啊哈」时刻——你会彻底相信 PyTorch 的 autograd 没有任何你不理解的魔法。

从这个训练循环也能看清几个 PyTorch 习惯的由来：zero_grad 是因为梯度 += 累加、不清零会叠加上一步的；「loss 必须是标量」是因为反向的起点 ȳ 要初始化为 1，只有标量才天然如此（对非标量 backward 需手动给一个 grad_output）；更新参数时操作 .data（而非 Value 本身）是因为我们不想让「梯度下降这步」也被记进计算图。这些小约定，写过一遍引擎就再也不会记混。

退一步看，整个深度学习训练 = 前向建图 → 标量 loss → 反向填梯度 → 优化器用梯度更新 这个循环的反复。autograd 是其中唯一需要框架魔法的一环，而你现在把这环也亲手写通了。后面模块 02/03 讲的「编译」「变换」，本质都是在这个循环之上做加速与重组；模块 04/05 讲的是让这个循环跑得省显存、可观测。地基就是这里。

7工程现实：真实 autograd 多了什么

工程现实：真实 autograd 比玩具多了什么

本模块的引擎抓住了 autograd 的全部算法骨架，但真实框架（PyTorch/JAX）在它之上还有大量工程，了解它们能让你读懂源码、避开坑。先把「玩具版」与「真版」逐项摆出来——你会看到差的全是工程，不是原理：

维度本模块 numpy 玩具引擎真实 torch.autograd
本地导数Python 闭包 _backward，逐节点调用C++ 的 grad_fn 节点（在 .grad_fn 可见），融合内核实现
调度自己写的拓扑逆序遍历（Python）C++ 反向引擎，多流并行、按依赖就绪触发
梯度累加手动 +=，靠纪律不出错引擎自动 accumulate，并用 version counter 检测就地改写
显存中间值一直留着（不释放）反向走完即释放保存的中间张量，retain_graph 才保留
dtype/设备只有 numpy fp64 在 CPUfp16/bf16/fp32、CPU/GPU、稀疏张量都要分发

记住这张表的一句话总结：你写的每条 <code>_backward</code> 闭包，对应 PyTorch 里一个 C++ <code>grad_fn</code>；你写的拓扑逆序遍历，对应它的反向引擎。结构同构，真版只是用 C++ 写、还做了并行、内存与多 dtype 的工程化。把下面这些点对照着看，源码就不再神秘：

  • 动态图 vs 静态图：PyTorch 每次前向都重新建图（define-by-run），灵活、易调试，但每步有建图开销；JAX/TF 倾向 trace 一次、复用图（define-then-run），快但控制流受限。模块 02/03 正是讲这条分野。
  • 就地操作（in-place）：x += 1 这类原地改写会破坏反向需要的中间值，框架要么报错、要么版本计数检测。手写引擎时最简单的纪律是不做就地操作。
  • 内存与 retain_graph：反向一旦走完，为省显存框架会释放图里保存的中间张量；要二次反向需 retain_graph=True。这也呼应模块 04 的显存账——保存多少中间值是显存大头。
  • 高阶导数：对 backward 再求导（如 MAML、某些正则）。实现上是「让反向过程本身也建图、再对它反向」，PyTorch 的 create_graph=True、JAX 的 grad(grad(f))。
  • 性能：真实 VJP 是高度优化的融合内核（呼应模块 02），还要处理 dtype/设备/稀疏等。我们的 numpy 版只求正确，不求快——但正确的结构是一切优化的前提。

一个值得记住的对应关系：你在 notebook 里给每个算子写的那条 _backward 闭包，在 PyTorch 里就是 C++ 实现的 grad_fn（你能在张量的 .grad_fn 看到它）；你写的拓扑逆序遍历，就是 PyTorch 的反向引擎（autograd engine）。结构同构，只是它用 C++ 写、还做了并行与内存优化。你写过玩具版，再看真版就只是「同一件事的工程化」。

就地改写会污染反向

真版有一个玩具版不会遇到、却在实战中高频踩的坑：反向需要的中间张量被就地（in-place）改写了。例如 y = x.exp(); x.add_(1)——exp 的反向要用原始的 x（其 VJP 是 y·ȳ，而 y 依赖原 x），但 add_ 已把 x 改了，反向若读到被改写的值，梯度静默算错。PyTorch 用 version counter 给每个张量记版本号，反向时发现「保存时的版本」与「当前版本」不一致就报错而非算错——这正是它比我们玩具引擎多出的安全网。手写引擎时最省心的纪律就是永不就地操作：每个算子都产出新张量，原始输入保持不变，反向才有据可依。

8研究前沿与开放问题

研究前沿与开放问题

  • 可微编程（differentiable programming）：把 autograd 推广到整个程序——可微物理引擎、可微渲染、可微优化器（对优化过程求导）。挑战是让控制流、循环、外部调用都可微且高效。
  • 函数式 AD 与高阶变换：JAX 把 AD 做成可与 vmap/jit 自由组合的函数变换（模块 03 的主题），高阶导数、前向+反向混合（如计算 Hessian-向量积）变得优雅。这是 AD 设计的前沿方向。
  • 检查点与可逆网络：反向需要前向的中间值，显存是瓶颈。gradient checkpointing（模块 04）用重算换显存；可逆网络（RevNet）则让中间值可从输出反推、几乎不存激活。AD 与显存的交叉课题。
  • 稀疏与结构化雅可比：当雅可比稀疏或有结构时，能否比通用反向更省？着色（coloring）等技术利用稀疏性减少 VJP 次数，是 AD 与数值线代的交叉。
  • 数值稳定性：某些复合的解析梯度数值不稳（如 softmax、log-sum-exp、SVD 的反向），框架需手写稳定的 VJP。这正是自定义算子（第 5 节）在生产中的重要用途。

必读：Baydin 等 2018《Automatic Differentiation in ML: a Survey》（破除 AD 的三大误解、讲清前向/反向模式）、Karpathy 的 micrograd（100 行 reverse-mode 引擎）、Griewank & Walther《Evaluating Derivatives》（AD 权威专著）、Paszke 等 2019（PyTorch autograd 的工程化）。清单见 references.md。
