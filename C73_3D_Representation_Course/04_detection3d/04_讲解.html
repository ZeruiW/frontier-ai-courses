13D 框的 7 个自由度，以及一个容易漏掉的对称性

\[\text{box} = (x,\ y,\ z,\ w,\ l,\ h,\ \theta)\]

自动驾驶里通常只保留绕 $z$ 的偏航角（车辆不会侧翻），所以是 7 而不是 9。而 $\theta$ 这一维带来的问题占了本模块的一半。

性质说明后果
周期性$\theta$ 与 $\theta+2\pi$ 相同直接回归 $\theta$ 会在 $\pm\pi$ 处炸：真值 179°、预测 −179°，几何差 2° 而 L1 损失是 358°——放大 179 倍
中心对称$\theta$ 与 $\theta+\pi$ 给出同一个框notebook 验证 IoU(0°, 180°) = 1.000000；所以角度只在 $[0,\pi)$ 内可辨识，而「车头朝哪」需要额外的方向分类头
与尺寸耦合$w$ 与 $l$ 互换 + $\theta$ 转 90° 是同一个框所以「长宽」的定义必须钉死（本课：$l$ 沿车长、$w$ 沿车宽）
三条合起来意味着：$\theta$ 不是一个普通的回归目标。它活在一个商空间 $S^1/\{\pm1\}$ 上，而普通的 L1/L2 损失假设目标活在 $\mathbb{R}$ 上。第 8 节给出三种编码方式与它们各自解决了上面哪一条。

2旋转框 IoU：多边形裁剪

2D 的轴对齐 IoU 是两行代码。旋转框需要真正的多边形求交。notebook 第 2 节用 Sutherland–Hodgman 裁剪从零实现，并用四个精确自检验证：

自检期望值实测
同一个框11.0
沿长轴平移 $l/2$$1/3$0.333333333
沿宽轴平移 $w/2$$1/3$0.333333333
$\theta$ 转 180°1（中心对称）1.0

直白说

第二、三行那个 $1/3$ 值得记，因为它是一个好用的心算基准。两个同尺寸的框沿某轴平移半个边长时，交集是 $1/2$、并集是 $3/2$，所以 IoU 恰好 $1/3$。而它同时说明「IoU 0.5」比想象的严格：它对应的平移小于半个边长。

严谨说

而实现上有一个必须注意的细节：多边形的绕向。Sutherland–Hodgman 的「在内侧」判据依赖裁剪多边形是逆时针的；给成顺时针会让所有 IoU 变成 0——而这个 bug 不会报错，它只会让所有匹配失败（本课作者第一版就栽在这里，四个自检全变成 0.0）。所以用有符号面积检查绕向应当是实现的第一步。

3朝向不匹配的代价

两个同心、同尺寸的 $4.5\times1.9$ m 框，只差一个角度：

$\Delta\theta$0°5°10°15°22.5°30°45°60°90°
BEV IoU1.00000.89160.80420.73170.64200.56620.42540.32230.2676

直白说

45° 的朝向误差就把 IoU 压到 0.4254——低于 0.5 的常用阈值。而 30° 时是 0.5662，刚刚过线。所以「IoU ≥ 0.5」这个阈值隐含了「朝向误差必须小于 37.1°」（下一节把它对四种长宽比精确反解出来——差别高达 9 倍）。

严谨说

而 90° 时 IoU 还有 0.2676 而不是 0——因为两个矩形交叉成一个「十字」，中间那块正方形是共有的。所以对长宽比接近 1 的目标（行人），朝向几乎无所谓；而对细长目标（车、卡车），朝向是主导误差源。这也解释了为什么 nuScenes 的朝向误差（AOE）是一个独立上报的指标，而不是被吸收进 IoU 里。

4反解：IoU 阈值隐含了多少朝向精度

上一节只算了一种长宽比。把它推广到四种目标，就能看出「IoU ≥ 0.5」这个阈值对不同目标其实是完全不同的要求。

直白说

同一个阈值 0.5，对轿车允许 37.1° 的朝向误差，对标志的 BEV 投影只允许 9.6°——差 3.9 倍；而对行人完全不约束（90°）。行人那一行的 90° 不是数值问题：正方形转 90° 就是它自己，所以 IoU 回到 1.000——也就是说 IoU 对朝向不是单调的，对方形目标它以 90° 为周期。

严谨说

这解释了两件常见的评测设计。① KITTI 对车用 0.7、对行人和骑车人用 0.5——0.7 对车意味着 17.5° 的朝向要求（合理），而对近方形的行人，任何 IoU 阈值都管不到朝向；② nuScenes 把朝向误差（AOE）作为独立指标上报，而不是让它被 IoU 吸收——因为上表说明「被吸收的程度」完全取决于长宽比。所以「我们的 mAP@0.5 很高」这句话，在方形目标上并不包含任何朝向信息。

5锚框：朝向必须离散化，而离散得不够就漏掉整个目标

2D 检测的锚框按「尺度 × 长宽比」枚举。3D 多了一维：朝向。而最常见的做法是只放 0° 与 90° 两个朝向（车道平行或垂直）。

notebook 第 4 节在 $80\times80$ m 的 BEV 网格（$0.2$ m，160,000 个位置）上扫全部锚框，统计每个目标能拿到几个 IoU ≥ 0.5 的正锚：

锚框朝向总锚框数正锚总数正负比各目标的正锚数（朝向 0° / 22.5° / 45° / 70°）
0°, 90°（2 个）320,0001330.0416%53 / 37 / 0 / 43
0°, 45°, 90°, 135°（4 个）640,0002580.0403%53 / 78 / 51 / 76
第一行第五列：朝向 45° 的那个目标拿到 0 个正锚。因为 0° 与 90° 的锚框对它的最好 IoU 只有 0.4254（第 3 节），低于 0.5 的阈值。于是这个目标在训练时完全没有正样本——它对损失的唯一贡献是「所有锚框都应该说这里没有东西」。

直白说

而第二行说明「加朝向」解决的不是正负比，只是漏掉。正锚从 133 涨到 258（约 2 倍），而总锚框也从 32 万涨到 64 万——正负比几乎不变（0.0416% → 0.0403%）。所以锚框方案的两个问题要分开看：① 漏掉（朝向离散得不够）——加朝向能解决；② 极端的正负不平衡（万分之四）——加朝框只会更糟。

严谨说

而 ② 的常规解法是 focal loss / OHEM（C58 的主题），但那是在治症状。真正的结构性修法是放弃「用 IoU 匹配锚框」这件事本身——而这正是 CenterPoint 的做法（第 6 节），也是 DETR 用匈牙利匹配替代锚框的动机（C54）。三条路的共同点是：让正样本的定义不再依赖一个 IoU 阈值。

63D 的 NMS：两个新问题

2D 的 NMS 是「按分数排序，抑制掉 IoU 过高的」。搬到 3D 会遇到两个新问题，而第二个是真实的失效模式。

问题一：旋转 IoU 贵 40 倍

候选数 $N$最多的配对数轴对齐 IoU旋转 IoU（多边形裁剪）
1004,950~0.05 MFLOP~2.0 MFLOP

每一对贵约 40 倍（多边形裁剪 vs 四个 min/max）。所以实践里普遍先按分数取 top-$k$（第 7b 节）再做 NMS，而 $k$ 的选择直接决定这一步的耗时。

问题二：BEV NMS 会抑制掉在 $z$ 上分开的目标

为了省钱，NMS 常常只在 BEV 平面上做（忽略 $z$）。而这会把「上下叠在一起的两个目标」当成重复。

目标对（$\delta x{=}0.2$ m）$\Delta z$BEV IoU3D IoU

最后一行是 TSR 的一个真实失效：一块离地 2.2 m 的限速牌，与它正下方的地面标记（或另一块低位牌），在 BEV 上完全重叠（IoU 0.600）而在 3D 上毫不相交（IoU 0.000）。BEV NMS 会把其中一个抑制掉，而被抑制的通常是分数低的那个——也就是更远、更小、更需要被检出的那个。而这个漏检在「按距离分层的召回」上才看得见，总体 mAP 上看不见。

直白说

修法有三条，成本递增。① NMS 时加一个 $z$ 的门——只有 $|\Delta z| <$ 阈值时才允许抑制；零成本，而它解决了绝大多数情形；② 按类别分组做 NMS——标志与地面标记本来就是不同类，不该互相抑制；③ 真正的 3D IoU NMS——最贵，且对轴对齐的 $z$ 区间其实只需要多算一维。

严谨说

而这一节要留下的一般性教训是：为了省钱而降维的操作，会在「被降掉的那一维上分开」的样本上失效。模块 01 的柱体（把 $z$ 压掉）有同样的结构；C72 模块 04 的 IPM（假设 $z{=}0$）也是。三处都是同一个模式：$z$ 是自动驾驶里最容易被压掉、而对交通标志最关键的那一维。

7中心点头：把「匹配」换成「峰值 + 回归」

锚框头 中心点头（CenterPoint） ┌────────────────────────┐ ┌────────────────────────┐ │ 每个位置 × 每个朝向 │ │ 每个位置一个「是不是中心」│ │ → 分类 + 框回归 │ │ → 一张热图（每类一张） │ │ 正样本 = IoU ≥ 0.5 │ │ 正样本 = **目标中心那一格**│ │ 需要 NMS │ │ 需要局部极大值抑制（3×3） │ └────────────────────────┘ └────────────────────────┘ │ │ 正负比 0.0416% 正样本 4/160,000 = 0.0025% 45° 目标 → **0 个正样本** 每个目标**恒有** 1 个正样本

直白说

中心点头的关键性质是「每个目标恒有一个正样本」——与它的尺寸、朝向、长宽比都无关。这直接消掉了第 4 节的问题 ①（漏掉）。而朝向从「用来枚举锚框」变成「一个待回归的量」，于是离散化的问题也不存在了。

严谨说

但正负比看起来更糟了（0.0025% vs 0.0416%）——而这里有一个关键设计：高斯软标签。CenterNet 不是只把中心那一格标成 1，而是在中心周围画一个高斯，半径由目标尺寸决定（让「偏移半径个格子的框」仍有 0.7 的 IoU）。于是有效正样本面积从 1 格涨到 $\pi r^2$ 格——而下一节会说明：这个 $r$ 对薄目标会退化到 0。

目标网格尺寸（$0.2$ m 格）高斯半径 $r$有效正样本面积 $\pi r^2$
轿车 $1.9\times4.5$ m22.5 × 9.5 格1.23 格4.7 格
行人 $0.6\times0.6$ m3.0 × 3.0 格0.28 格0.2 格
标志 $0.8\times0.1$ m0.5 × 4.0 格0.08 格0.0 格

8中心点头对薄目标同样退化

上一节表格的最后一行是这一节的全部内容。交通标志在 BEV 里的投影是 $0.8\times0.1$ m——在 $0.2$ m 的网格上只有 $4.0\times0.5$ 格。

它的宽度（0.5 格）小于一个格子。于是 CenterNet 的高斯半径公式给出 0.08 格，有效正样本面积 $\pi r^2 = 0.02$ 格——四舍五入是 0。也就是说：热图上只有恰好那一格是正样本，而中心落在格边界上时连那一格都可能标错。

直白说

所以「从 anchor 换到 center」并没有解决薄目标的问题，它只是把问题从「0 个正锚」换成了「1 个孤立正样本、没有软标签」。而模块 03 已经从另一个方向给出同样的结论：要让标志连通需要 $r{=}0.8$ m 的分辨率，而那时量化误差是 IoU-0.5 预算的 20.8 倍。两条独立的推理指向同一件事：$0.2$ m 的 BEV 网格对交通标志太粗。

严谨说

三条可行的出路，而它们都不是「换检测头」：① 为薄目标单独用更细的网格（标志的 $z$ 范围很窄，所以可以只在 1.5–3 m 这一层用 $0.05$ m 的网格，代价可控）；② 不在 BEV 里检测标志——用图像检测 + C72 模块 03 的已知尺寸测距（50 m 处 ±1.30 m）；③ 换评测口径——用中心距离而不是 IoU（模块 05），此时 0.2 m 的网格是够用的。而实践中 TSR 普遍走 ②，这不是因为 LiDAR 不好，而是因为上面这条约束链。

9热图怎么解码成框：局部极大值 + top-$k$

中心点头输出的是一张热图，而「取出目标」这一步有两个必须的操作。

1000.062%2×
5000.312%10×

直白说

① 那个 11.20% 值得记：它几乎正好是 $1/9$。因为在无结构的热图上，$3\times3$ 窗口里每个格子等可能是最大的。所以局部极大值抑制只能把候选降一个数量级，远不够——top-$k$ 是必需的第二步。

严谨说

而 $k$ 的选择是一个显式的召回-成本取舍。$k$ 太小会截掉低分的真目标（而那些正是远处的小目标）；$k$ 太大会让第 4b 节的旋转 NMS 变贵（成本 $\propto k^2$）。实践里 $k{=}500$ 给约 10 倍余量，是一个常见的默认值——而它应当按「场景里最多可能有多少个目标」来定，而不是抄一个数。而 offset 回归这一项解决的是量化误差：中心落在格子中间时，热图只能指到格心，而 offset 头把那半个格子（$0.2$ m 网格上是 $\le0.14$ m）补回来——这正好是模块 01 第 7 节量化误差的一个直接补偿手段。

offset 回归能补偿多少，是可以算的：它把量化误差从 $r\sqrt3/2$（$0.2$ m 网格上是 0.173 m）降到「offset 头自身的回归误差」。所以模块 03 第 5b 节那张「量化误差 vs 允许误差」的表，在有 offset 头时应当用回归误差而不是 $r\sqrt3/2$——而那个数只能实测，本课给不出。但结论的方向不变：网格越粗，offset 头要补的越多。

10角度的三种编码

编码怎么做解决了哪一条残留问题
直接回归 $\theta$L1/L2 损失无周期性：179° vs −179° 的 L1 是 358°，而几何差只有 2°——放大 179 倍
$(\sin\theta,\cos\theta)$回归两个分量，再 atan2周期性：179° vs −179° 的 L2 = 0.03490，恰好等于 $2\sin1°$不含中心对称：0° 与 180° 被当成完全不同
$(\sin2\theta,\cos2\theta)$把角度加倍再编码周期性 + 中心对称：89° 与 −89°（几何差 2°）的 L2 = 0.06980 = $2\sin2°$丢掉了「车头朝哪」——需要一个额外的二分类头
第三行的实现里有一个真实的坑：dir_offset。方向二分类的标签是「$\theta$ 落在 $[0,\pi)$ 还是 $[\pi,2\pi)$」，而这个区间的起点是一个超参数（SECOND 与 CenterPoint 的默认值不同）。起点定在训练数据里朝向的密集处，会让恰好落在边界上的样本标签抖动——而车辆朝向在直路场景里恰好密集分布在 0° 与 180° 附近。所以 dir_offset 通常取 $\pi/4$ 这类「远离密集处」的值。

直白说

第二行那个「恰好等于 $2\sin1°$」不是巧合：单位圆上两点的弦长就是 $2\sin(\Delta\theta/2)$。所以 $(\sin,\cos)$ 编码把角度差正确地线性化了（小角度下）——而这就是它替代直接回归的全部理由。

严谨说

而第三行的取舍是真实的：中心对称与方向信息不可兼得。$(\sin2\theta,\cos2\theta)$ 把 $\theta$ 与 $\theta+\pi$ 映到同一点，所以它无法区分车头车尾。实践中的标准做法是「$(\sin2\theta,\cos2\theta)$ 回归朝向+ 一个二分类头判方向」——而这也是 SECOND 引入 direction classifier 的原因。它把一个「在商空间上回归」的问题拆成「在商空间上回归」+「在商上的纤维里分类」，而这是处理这类对称性的通用套路。

11本模块的清单

  1. 实现旋转框 IoU 的第一步是用有符号面积检查绕向（第 2 节）——给错绕向会让所有 IoU 变成 0，而它不报错
  2. 统计每个目标的正样本数，而不只是总正负比（第 4 节）——「某个目标 0 个正样本」在总比例上看不出来
  3. 报 IoU 阈值时要说明它对这个类别意味着多少朝向精度（第 3b 节）——0.5 对轿车是 37.1°，对方形的行人是「不约束」
  4. 加朝向解决漏掉，不解决正负不平衡（第 4 节）：133 → 258 个正锚，而比例 0.0416% → 0.0403%
  5. 算一次每类目标的高斯半径（第 5 节）。$\pi r^2 < 1$ 就说明这一类在当前网格下没有软标签
  6. 薄目标的问题不能靠换检测头解决（第 6 节）——三条出路是更细的局部网格 / 换传感器通路 / 换评测口径
  7. BEV NMS 必须加一个 $z$ 的门或按类别分组（第 4b 节）——否则标志与它正下方的地面标记会互相抑制（BEV IoU 0.600 而 3D 是 0）
  8. top-$k$ 按「场景里最多多少个目标」定（第 6b 节），而不是抄一个数——它同时决定召回余量与旋转 NMS 的成本（$\propto k^2$）
  9. 角度用 $(\sin2\theta,\cos2\theta)$ + 方向二分类（第 7 节），不要直接回归 $\theta$
如果只做一条，做第 4 条。「每个目标拿到几个正样本」这个数不需要训练，在数据准备阶段就能算出来；而它能抓到一整类「某些朝向/尺寸的目标从来学不会」的问题——而那类问题在总体 mAP 上只表现为「差一点」。
