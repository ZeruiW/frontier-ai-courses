1奖励模型就是一个被固化下来的 judge

前四个模块讲的 judge，都是用来测量的。这一节开始讲当它被用来训练时，会发生什么本质不同的事。

先说一个结构上的连续性：奖励模型（reward model, RM）的训练目标，就是模块 04 的 Bradley–Terry 对数似然。

\[\mathcal{L}_{\text{RM}} = -\mathbb{E}_{(x,\,y_w,\,y_l)}\left[\log \sigma\big(r_\phi(x, y_w) - r_\phi(x, y_l)\big)\right]\]

直白说

对照模块 04 的 BT：那里每个模型有一个标量 $\theta_i$；这里每个 (问题, 回答) 对有一个标量 $r_\phi(x,y)$，由一个神经网络算出来。数学形式完全一样，区别只是「强度参数」从一张查找表变成了一个函数。所以模块 04 关于 BT 的一切——只有差值有意义、需要正则化、假设了传递性——全部原样适用于奖励模型。

严谨说

更精确地说，RM 是 BT 模型的参数化推广：BT 的参数空间是 $\mathbb{R}^{|M|}$（每个模型一个数），RM 的参数空间是函数空间 $\{r_\phi: \mathcal{X}\times\mathcal{Y}\to\mathbb{R}\}$。推广带来的能力是泛化（能给没见过的回答打分），推广带来的风险是外推——在训练分布之外，$r_\phi$ 的值没有任何数据约束，而优化过程恰恰会把策略推到那里去。这句话就是本模块后面所有内容的种子。

身份被谁消费关键性质本课程哪里讲
LLM judge（prompt 驱动）评测流程可解释、易改、无需训练本课 01–04
奖励模型（训练出来的打分网络）RL / best-of-n快、便宜、可微；但会被优化压力主动攻击本模块
隐式奖励模型（DPO 等）直接进策略更新不显式存在，但数学上等价于一个 RMC02 讲训练，本模块讲它的评测
可验证奖励（RLVR）RL不可被 hack（只要验证器正确）第 7 节的边界讨论

一个值得记住的判断：把 judge 用作测量，误差让你得到错误的读数；把 judge 用作训练信号，误差会被主动放大——因为优化过程会专门去找它出错的地方。这就是为什么「够用的 judge」和「够用的奖励模型」是两个不同的标准。

2过优化：那条必然出现的倒 U 曲线

这是本模块的核心现象，也是 RLHF 工程里最重要的一条经验规律。

分数 │ 代理奖励 (RM 分数) │ ╱───────────────────────── 单调上升，永远不会告诉你出问题了 │ ╱ │ ╱ 真实质量 (人类/金标准) │ ╱ ╱────╲ │╱ ╱ ╲______ 倒 U：先升后降 │ ╱ ╲____ └──┴────────┴──────────────────────► 优化强度（KL 距离 / best-of-n 的 n / RL 步数） 拐点 ← 有效优化 →│← 过优化（RM 分涨、真实质量跌）→ 致命之处：**你只能看到上面那条线。**下面那条需要人类标注才能画出来。

这条曲线在 best-of-n 和 RL 两种优化方式下都会出现，但 Gao et al. (2023) 强调两者的经验形式并不相同：

\[R_{\text{bon}}(d) \approx d\,(\alpha - \beta d), \qquad R_{\text{RL}}(d) \approx d\,(\alpha - \beta \log d), \qquad d = \sqrt{\mathrm{KL}(\pi \,\|\, \pi_{\text{ref}})}\]

其中 $R$ 是真实质量的提升，$d$ 是 KL 距离的平方根。$\alpha$ 是有效优化的斜率，$\beta$ 是过优化的惩罚项。best-of-n 的拐点在 $d^{*} = \alpha/(2\beta)$，RL 的拐点在 $d^{*} = \exp(\alpha/\beta - 1)$——形式不同，但都有拐点，这才是那篇论文的核心结论。关键的经验发现是：$\alpha$ 和 $\beta$ 都随奖励模型的规模与数据量变化，更大的 RM 推得更远、掉得更慢，但拐点依然存在。

优化方式「优化强度」是什么KL 与它的关系实践含义
best-of-n候选数 $n$$\mathrm{KL} \approx \log n - \frac{n-1}{n}$便宜、可控、随时能退回去；调试期的首选
RL (PPO 等)训练步数 / KL 惩罚系数直接被 KL 项控制更强但更贵，且退不回去——权重已经变了

过优化最危险的地方不是它会发生，而是它在你的监控面板上看起来像成功。代理奖励单调上升，训练曲线漂亮，而真实质量的下降只有在人类看到输出时才会被发现——通常是在上线之后。所以任何 RLHF 流程都必须有一条独立于 RM 的验证信号，哪怕它很小、很慢、很贵（第 6 节展开）。

为什么必然发生

机制在第 1 节的 DUAL 里已经埋好了：RM 只在训练分布上被约束。优化过程的本质就是去找 RM 给高分的地方，而 RM 给高分最容易的地方，恰恰是它没见过、因此外推得很离谱的区域。这是 Goodhart 定律的一个数学上必然的版本，不是实现缺陷。

3奖励 hacking 的具体形态：从长度到谄媚

抽象地说「过优化」不够用，工程上需要知道它具体长什么样。下面这些形态的共同点是：它们全部对应模块 02 里的某个 judge 偏差——偏差在测量时是误差，在训练时就是被优化的目标。

形态表现对应的 judge 偏差（模块 02）检测手段
长度膨胀输出越来越长，信息密度下降长度偏差监控输出长度分布；长度控制版指标
格式套路化什么问题都用标题 + 编号列表风格/格式偏差监控 markdown 元素密度
谄媚（sycophancy）顺着用户的错误前提说、不纠正标注者偏好「让人舒服」的回答构造「用户说了错话」的探针集
自信化含糊表述消失，一律给确定的答案自信语气被奖励校准检查（模块 03）：ECE 恶化
套话开场「这是一个很好的问题」类的固定前缀标注者对礼貌的偏好前缀 n-gram 频率监控
拒答漂移该答的也拒答（安全 RM 过强）或该拒的不拒安全维度的权重失衡拒答率的双向监控

这张表最有价值的是第三列。如果你在模块 02 已经量过 judge 的偏差，你就已经知道你的 RM 会往哪个方向被 hack 了。长度偏差 $\gamma = 0.8$ 的 judge，训出来的 RM 一定会把输出推长——这不需要等实验结果，可以事先预测并提前布置监控。

一个反直觉的点：hack 不需要「聪明」

这些形态没有一个需要模型「理解」奖励模型的漏洞。梯度下降只是在做它该做的事：沿着奖励上升最快的方向走。如果「加一句礼貌开场」能稳定地涨 0.1 分，那么在几万次更新之后，模型必然学会永远加这句开场——这和「模型在钻空子」这种拟人化描述无关，它就是优化。

这个视角有一个实用推论：与其试图让 RM「更聪明地识破 hack」，不如从一开始就把可 hack 的维度从奖励里去掉。长度控制的 RM（在训练时就把长度回归掉）比事后惩罚长输出有效得多——这正是模块 02 的去偏方法在训练侧的对应物。

4怎么评测一个奖励模型：切片准确率与它的局限

RM 的评测有一个天然的形式：给一批 (prompt, chosen, rejected) 三元组，看 RM 是否给 chosen 更高的分。这就是 RewardBench 类基准的核心。

\[\text{RM accuracy} = \Pr\big[r_\phi(x, y_w) > r_\phi(x, y_l)\big]\]

切片是关键

总准确率几乎没有信息量。有信息量的是按能力维度切片：

切片考察什么典型难点
Chat一般对话的偏好容易饱和——多数 RM 都在 95% 以上
Chat-Hard刻意构造的困难对：拒绝对比、细微事实差异、风格诱导最能区分 RM；许多 RM 在这一片掉到 60% 以下
Safety该拒的拒、不该拒的别拒（双向）单向优化会在另一个方向翻车
Reasoning数学/代码的正确性偏好RM 常常偏好「看起来严谨」而非「实际正确」

RM 基准准确率有一个必须知道的局限：它是在固定的、静态的偏好对上测的，而 RM 在实际使用时面对的是被自己的梯度推着走的分布。一个在 RewardBench 上 90% 的 RM，完全可能在 RL 训练的第 2000 步就开始给垃圾输出打高分——因为那些输出不在任何静态基准的分布里。静态准确率是必要条件，不是充分条件。

必须补的两类评测

  1. 分布外探针：拿被优化过的策略的输出（而不是静态数据集）去测 RM，看它是否仍然与人类一致。这是唯一能提前发现过优化的离线手段；
  2. 校准：RM 的分差应当能被翻译成胜率（模块 04 的 BT 性质）。分差 1.0 应当对应 73% 的胜率——如果实测只有 55%，说明 RM 的分数尺度是虚的，用它做 best-of-n 的截断阈值会完全失准（第 6 节）。

5缓解手段：集成、保守化、迭代

过优化不能被消除（第 2 节说过它是数学上必然的），但可以被推后和检测。

手段怎么做效果代价
KL 惩罚在目标里加 $-\beta\,\mathrm{KL}(\pi\|\pi_{\text{ref}})$最基本、必做：直接限制走多远$\beta$ 是超参；太大则学不动
奖励模型集成训练 $K$ 个 RM（不同 seed / 数据划分），取最小值或均值减方差显著推后拐点：分歧大的区域自动被压低训练与推理成本 $\times K$
保守化 / 悲观估计用 $\bar{r} - \lambda\,\mathrm{std}(r)$ 代替 $\bar{r}$把「不确定的高分」自动折价$\lambda$ 需要调；过大则过于保守
迭代式数据收集训练一轮 → 用新策略的输出收集新偏好 → 重训 RM最根本的解法：把分布外变成分布内每轮都要人类标注，最贵
早停用独立验证信号定位拐点，停在那里简单有效需要那条独立信号（第 6 节）
可验证奖励能用程序验证的部分不交给 RM（第 7 节）该部分完全免疫 hack只适用于可验证的任务

集成为什么有效，有一个很直观的解释：过优化找到的是「某一个 RM 的漏洞」，而不同 seed 训出来的 RM，漏洞位置不一样。取最小值意味着要骗过所有 RM 才能拿高分，这比骗过一个难得多。但它治不了「所有 RM 共有的偏差」——如果偏好数据本身就奖励长回答，那么每个 RM 都会奖励长回答，集成毫无帮助。这与模块 02 第 7 节「集成只能治噪声，治不了共有偏差」是完全同一条结论。

迭代式为什么是根本解法

回到第 1 节的病根：RM 只在训练分布上被约束。迭代式数据收集直接解决这个问题——把优化后策略产生的输出拿去标注，那些原本的「分布外区域」就变成了分布内。代价是每一轮都需要新的人类标注，所以实践中通常是「几轮迭代 + 每轮内用集成与 KL 惩罚」的组合。

6那条独立信号：过优化的唯一可靠检测方式

本模块反复提到「独立于 RM 的验证信号」。这一节把它讲清楚——因为它是整个 RLHF 流程里最容易被省掉、也最不该被省掉的一环。

为什么必须独立

直白说

如果你用同一个 RM（或它的同门兄弟）来验证训练效果，那么你测到的只是「优化是否有效地提高了 RM 分数」——而这在过优化阶段依然是真的。换句话说，非独立的验证信号在你最需要它的时候恰好失效。

严谨说

形式化：设真实效用 $U$、代理奖励 $\hat{R}$。过优化的定义就是 $\frac{\partial U}{\partial d} < 0$ 而 $\frac{\partial \hat{R}}{\partial d} > 0$。任何与 $\hat{R}$ 高度相关的验证量，在这个区域都会继续上升，因此无法检出。要检出，验证量必须与 $\hat{R}$ 的误差项不相关——这正是「独立」的技术含义，也是为什么「用一个更强的模型当 judge」经常不够（它可能共享同样的偏差，呼应模块 03 第 1 节）。

候选信号独立性成本评价
人类偏好抽样★★★ 最独立最高金标准。哪怕每轮只标 200 条，也比没有强得多
可验证任务的正确率（数学/代码/单元测试）★★★低性价比最高：完全客观，且能自动跑（C66 的判分器）
异族 LLM judge★★☆中有用，但要先确认它与 RM 的偏差方向不同（模块 02 的探针）
行为分布监控（长度、格式、拒答率、校准）★★★极低不测质量，但能测「有没有在被 hack」——第 3 节的形态清单
留出的 RM（不参与训练的同门 RM）★☆☆低只能检出「训练 RM 的过拟合」，检不出共有偏差

一个便宜且强烈推荐的组合：「可验证任务正确率」+「行为分布监控」。两者都能全自动跑、成本近乎为零，而且覆盖了过优化的两类表现——能力退化（数学题做错了）与形态漂移（输出变长变套路）。人类抽样再补在上面，作为最终的校验。

拐点怎么定位

有了独立信号，定位拐点就是一个曲线拟合问题。实用做法：

  1. 在若干个优化强度上取检查点（best-of-n 取几个 $n$；RL 取几个 step）；
  2. 在每个检查点上跑独立信号，得到 $(d_k, U_k)$；
  3. 拟合 $U \approx d(\alpha - \beta d)$，解出 $d^{*} = \alpha/(2\beta)$；
  4. 把生产用的 KL 预算设在 $d^{*}$ 之前留有余量的位置——因为 $d^{*}$ 本身是有估计误差的，而越过它的代价是不对称的。

7边界：什么该交给验证器，什么只能交给 judge

本课最后一节，回到模块 00 第 2 节埋下的那条线：校验（verification）与 judge 的分界。在训练语境下，这条线就是 RLVR 与 RLHF 的分界。

┌────────────────────────────────────────────────────────────────┐ │ 可验证奖励 RLVR │ 学习到的奖励 RLHF/RM │ ├────────────────────────────────────┼─────────────────────────────┤ │ 数学答案对不对（对答案） │ 这段解释清不清楚 │ │ 代码过不过测试 │ 这个回答有没有帮到人 │ │ 格式合不合 schema │ 语气是否得体 │ │ 引用的条款存不存在 │ 优先级排得对不对 │ ├────────────────────────────────────┼─────────────────────────────┤ │ **不可被 hack**（验证器正确的前提下）│ **必然可被 hack** │ │ 信号稀疏（只有对错） │ 信号密集（连续分数） │ │ 覆盖窄 │ 覆盖宽 │ └────────────────────────────────────┴─────────────────────────────┘ 实践：**能验证的部分绝不交给 RM**，剩下的才用 RM，并接受它会被 hack。

一个必须补充的诚实说明：RLVR 的「不可被 hack」是有条件的——条件是验证器本身正确且完整。如果测试写得弱，策略照样能学会「让测试变绿但代码是错的」——这正是 C66 模块 02 讲的判分器 hack，只是发生在训练侧。所以「用可验证奖励」不等于「不用操心奖励设计」，它只是把问题从「RM 会不会外推错」换成了「验证器写得全不全」。后者通常容易得多，但不是零。

组合的实践形态

真实系统里两者几乎总是组合使用，常见形态：

  • 可验证部分做硬约束：格式不合法、测试不通过直接给 0 或负奖励，不进入 RM 打分——这一步能挡掉大量最粗糙的 hack；
  • RM 只负责剩余维度，并且这些维度尽量 rubric 化（模块 01）——rubric 项越接近可判定，可 hack 空间越小；
  • 把已知的 hack 形态写成负向验证器：「开头是不是套话」「markdown 元素密度是否异常」都可以写成程序检查，直接扣分，而不是指望 RM 学会不喜欢它们。

全课收尾

把这门课的五个模块串起来看，是同一条逻辑的五次展开：

  1. 00 judge 是测量仪器，误差与被测物相关，所以要先验证仪器；
  2. 01 仪器的设计决定了它的量程与噪声——能写成校验就别打分；
  3. 02 把系统偏差量出来、减掉，并诚实报告残留的不可识别性；
  4. 03 用人类上界校准你对「一致率」的解读，用校准度决定分诊；
  5. 04 把成对比较聚合成排名时，看区间不看名次；
  6. 05 一旦仪器变成目标，它就开始失效——所以永远要有一条独立于它的信号。

下一门课 C68 把这一切工程化：judge 与 RM 的调用怎么缓存、怎么接进 CI、怎么监控漂移、怎么做线上线下的双回路。

8上线前的 judge/RM 检查清单

把这门课的六个模块压缩成一份可以逐项打勾的清单。按用途分三档——用途越重，要求越严。

档位 A · judge 只用于内部看趋势

  • ☐ swap 一致性 ≥ 0.80，且已做 swap 平均（模块 01/02）
  • ☐ 长度系数 $\gamma$ 已拟合，raw 与 LC 两个数一起看（模块 02）
  • ☐ judge prompt 有版本指纹，改动会让指纹变（模块 01）
  • ☐ 解析失败率已记录，失败样本按重试→平局处理而非丢弃（模块 01）

档位 B · judge 用于选型或对外报告

在档位 A 之上追加：

  • ☐ 与人类的一致率，且给出人类之间的一致率作为上界（模块 03）
  • ☐ 风格探针与自偏好探针的幅度已量化（模块 02）
  • ☐ 报告了系统级分辨力：能检出多大的差距（模块 03）
  • ☐ 若出榜单：名次区间、比较图连通性、配对策略、传递性检查（模块 04）
  • ☐ 若出榜单：风格控制版与 Δrank 并列给出（模块 04）
  • ☐ 有哨兵集，且从未被用来调 prompt（模块 03）

档位 C · judge/RM 用作训练信号

在档位 B 之上追加——这一档的要求显著更严，因为误差会被优化过程主动放大：

  • ☐ RM 的切片评测已做，且 worst slice 达标（不是 macro）（本模块）
  • ☐ RM 的校准已检验：分差 1.0 是否真的对应约 73% 的胜率（本模块）
  • ☐ 已在被优化过的策略输出上测过 RM 一致率（分布外探针）（本模块）
  • ☐ 存在一条与 RM 误差不相关的独立信号，且它是停止规则的依据（本模块）
  • ☐ 行为分布监控已接上：长度、格式密度、拒答率、ECE（本模块）
  • ☐ 已知的 hack 形态写成了负向验证器，而不是指望 RM 学会不喜欢它们（本模块）
  • ☐ 能验证的部分走验证器，不进 RM（本模块）

档位 C 里最不能省的是倒数第四条（独立信号）。其余每一条缺失都只是让你少一层保护；缺了独立信号，你在过优化开始之后就完全失明了——而那正是你最需要看见的时候。哪怕它只是「每轮跑 200 道数学题」这么简陋，也远好过没有。

直白说

为什么要按用途分档，而不是一律要求做全套？因为「太贵所以不做」的实际后果是「一项都不做」。档位 A 的四项加起来只需要几行代码和零额外调用（长度回归甚至是零成本），但它们已经能挡掉最常见的两类误读——位置偏差和长度偏差。先把便宜的做完，再按用途往上加。

严谨说

从决策理论的角度，检查项的价值等于「它能避免的错误决策的期望损失」。内部看趋势时，一个偏了的数字造成的损失有限；而当 judge 被用作训练信号时，误差不再是一次性的读数错误，而会通过优化过程被固化进模型权重——损失从「这次结论错了」变成「这个模型的行为被永久带偏了」，而且退不回去（best-of-n 可以退，RL 不能）。这就是档位 C 的要求显著更严的形式化理由。
