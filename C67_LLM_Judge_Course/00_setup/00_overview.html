1judge 是测量仪器，不是裁判

这门课只有一个核心主张，值得放在最前面：当你用一个 LLM 去给另一个 LLM 的输出打分时，你并没有得到「答案」，你得到的是一台测量仪器的读数——而这台仪器自己有零点漂移、有量程限制、有系统性的方向偏差。

这个视角带来的第一个推论是顺序上的：在用 judge 去比较两个模型之前，必须先评测 judge 本身。C66 模块 02 已经用确定性判分器（跑测试）演示过这条逻辑：判分器有假阳率 $\alpha$ 时，观测成功率是 $p(1-\beta)+(1-p)\alpha$，偏差不随样本量消失。LLM judge 只是把这个问题放大了一个数量级——因为它的 $\alpha$ 和 $\beta$ 不是常数，而是随着被评对象的长度、风格、格式、甚至是不是它自己写的而系统性变化。

判分器类型$\alpha,\beta$ 的性质怎么估计本课程哪里讲
执行式（跑测试）常数，且通常很小金标准集，几十条即可C66 模块 02
终态匹配 / 不变量常数，取决于不变量写得全不全同上C66 模块 02
LLM judge随被评对象的属性系统性变化——长文本被高估、自己的输出被高估、排在后面的被高估需要人类标注的对照集 + 专门的偏差探针本课 02–03 模块

直白说

为什么不能像用尺子一样直接用 judge？因为尺子的误差与被测物无关——量一根 10 厘米的棍子和量一根 20 厘米的棍子，误差都是 ±0.5 毫米。而 LLM judge 的误差与被测物强相关：给一个写得长、格式漂亮、语气自信的答案，它系统性地打高分。这意味着误差不会在平均之后抵消，而是会系统性地奖励某一类输出——如果你再拿这个 judge 去做训练信号，模型就会朝那个方向漂过去。

严谨说

形式化地说，理想的 judge 是真实质量 $q$ 的无偏估计：$\hat{q} = q + \varepsilon$，$\mathbb{E}[\varepsilon] = 0$。实际的 judge 更接近 $\hat{q} = q + f(\text{length}, \text{style}, \text{position}, \text{authorship}) + \varepsilon$，其中 $f$ 是一个与内容质量无关但与可观测表面属性相关的系统项。本课 02 模块的全部工作，就是把 $f$ 的各个分量识别出来、量化出来、并在可能时把它从读数里减掉。

一个直接的推论，也是这门课最实用的一句话：「我们用 GPT/Claude 做了 judge，结果显示我们的模型更好」——这句话在没有给出 judge 体检数据时，所包含的信息量接近于零。体检至少要包括：与人类的一致率、位置偏差幅度、长度偏差幅度、以及人类自身的一致率上界。六项清单在本模块 notebook 的最后一节。

2judge 的三种用法：打分、比较、校验

「LLM judge」这个词其实覆盖了三种在数学结构上完全不同的用法。混用它们是很多混乱的来源，所以先把它们分开。

① 打分 pointwise ② 比较 pairwise ③ 校验 verification ┌──────────────┐ ┌──────────────┐ ┌──────────────┐ │ 输入: 一个答案 │ │ 输入: 两个答案 │ │ 输入: 一个答案 │ │ 输出: 分数 1-5 │ │ 输出: A/B/平局 │ │ 输出: 通过/不通过│ └──────────────┘ └──────────────┘ └──────────────┘ 量: 绝对质量 量: 相对偏好 量: 是否满足某个可判定条件 问题: 分数分布压缩 问题: 位置偏差、不传递 问题: 需要条件本身可判定 用途: 监控、门禁 用途: 模型选型、RLHF 用途: 事实核查、格式约束、约束满足 → 01 模块 → 01/04 模块 → 05 模块（与 verifier 的边界）
用法被估计的量典型失效什么时候该选它
pointwise 打分绝对质量 $q_i$分数分布严重压缩——绝大多数样本都落在 4 分，判别力接近零需要一个可以设阈值的绝对指标时（线上监控、CI 门禁）
pairwise 比较偏好概率 $P(A \succ B)$位置偏差、长度偏差、平局处理不当、可能违反传递性模型选型、构造偏好数据、排行榜
校验某个可判定条件是否成立条件本身写得不可判定（「回答得好吗」不是条件）有明确规格可查时——能用校验就不要用打分

一条选择顺序，按可靠性从高到低：能写成校验的就写成校验，写不成校验的用 pairwise，实在需要绝对分数才用 pointwise。理由是它们对 judge 能力的要求依次升高——判断「这段代码有没有调用指定的 API」比判断「这个回答好不好」容易得多，也客观得多。很多被当成「主观质量」的东西，其实可以被拆成一组客观校验项——这是 01 模块 rubric 设计的核心思想。

需要强调一个边界：校验（verification）与 judge 不是同一件事。当条件可以由代码判定（正则、单元测试、schema 校验）时，那属于 C66 的确定性判分器范畴，不该请 LLM 来做。只有在条件需要语义理解才能判定时（「这段话有没有回答用户的问题」），才落进本课的范围。05 模块会把这条边界重新画一遍，因为它同时也是 RLVR（可验证奖励）与 RLHF（judge/RM 奖励）的分界线。

3judge 为什么难：四个结构性原因

如果 judge 只是「另一个模型调用」，它不值得一门课。它难在四个结构性的地方。

  1. 没有金标准，或者金标准本身有噪声。「哪个回答更好」这个问题，两个人类标注员的一致率往往只有 70%–85%。这意味着 judge 与人类的一致率存在一个由人类自身决定的上界——judge 达到 82% 可能已经接近天花板，而不是「还差 18 个点」。不知道这个上界就无法判断 judge 好不好。（03 模块）
  2. 偏差与内容强相关，因此不会被平均掉。位置、长度、风格、自偏好这四个偏差都是系统性的（第 1 节已述）。（02 模块）
  3. 被评对象会适应 judge。一旦 judge 被用作训练信号或选型标准，优化压力就会去找它的漏洞。「写长一点分数就高」这件事一旦被发现，所有输出都会变长。（05 模块）
  4. 成对比较到排名之间隔着一个模型。你手上是一堆「A 赢 B」，你想要的是一个排行榜。这中间需要 Bradley–Terry 或 Elo，而这两个模型都假设了传递性——而 LLM judge 的成对偏好经常违反传递性。（04 模块）

直白说

把四条合起来看，你会发现一个规律：judge 的问题都不是「不够准」，而是「以特定方向不准」。随机误差可以靠多跑几次解决，系统偏差不行——它只会让你更自信地相信一个偏了的结论。所以这门课花在「测量偏差」上的篇幅，远多于花在「提高准确率」上的篇幅。

严谨说

从测量学的角度，这四条分别对应：效标效度的上界问题（criterion validity，金标准自身有噪声）、系统误差（systematic error）、Goodhart 效应（指标被优化后失效）、以及测量模型的适配性（把成对偏好聚合成一维分数，本身就假设了偏好可以被一个标量刻画）。C10 用心理测量学的语言讲过前两条，本课把它们全部落到 LLM judge 这个具体对象上。

5环境、依赖与本课的运行约定

本课全程 CPU、断网可跑、不需要任何 API key。做法与 C66 相同：把「judge 的测量学」与「judge 的调用」分开。

  • 测量学部分（偏差的识别与去除、kappa、人类上界、校准、Bradley–Terry 拟合、过优化曲线）全部是确定性计算。本课用一个可控的 judge 模拟器：先设定每个回答的「真实质量」，再用几个显式的偏差旋钮（位置、长度、自偏好、噪声）生成 judge 的判断。这比调真实 API 更适合学习——因为你知道真值，可以直接验证你的去偏方法有没有把偏差真的减掉。
  • 真实调用部分放在每个模块末尾的「🧪 真实工程胶囊」里：judge prompt 模板、结构化输出的 schema、swap 一致性的批量跑法、长度控制回归的实现、RewardBench 风格的评测脚本——可原样复制到有 key 的环境。

关于模拟器有一个必须说清楚的地方：模拟器不是为了「假装有一个真 judge」，而是为了让你能在知道真值的条件下检验估计量。真实实验里你永远不知道真实质量是多少，所以你无法判断「去偏之后的胜率」到底更接近真值还是更远。在模拟里你可以——这是学习阶段唯一能做到的验证方式，也是本课每个练习都用 assert 检查「去偏后更接近真值」的原因。

6五个真实场景：judge 在哪里骗过了人

最后用五个具体场景收尾。它们不是假想的——每一个都对应本课后面某个模块的主题，而且都不需要 judge「犯低级错误」就会发生。

场景表面上看到的实际发生的本课哪里给出解法
新版本「提升了 6 个点」同一套 judge，新版本胜率从 48% 涨到 54%新版本的输出平均长了 40%，而这个 judge 的长度系数是 0.8——6 个点里有 5 个来自长度模块 02：长度控制回归
「我们的 judge 与人类一致率 82%」听起来还差 18 个点人类之间的一致率只有 84%——82% 已经是天花板的 94%，继续优化 judge 的边际收益接近零模块 03：人类上界
「A 和 B 差不多，都是 5 分」pointwise 打分区分不出来五档量表的有效档位数只有 1.6，八成样本都落在同一档——不是它们一样好，是尺子只有一个刻度模块 01：分布压缩与 rubric 分解
「榜单第一名换人了」上周 M3 第一，这周 M1 第一两者的置信区间从头到尾就是重叠的，换人只是重采样噪声模块 04：名次区间
「RL 训练曲线很漂亮」奖励分数持续上升 20k 步真实质量在 8k 步就见顶了，而代理奖励永远不会告诉你这件事模块 05：独立信号与拐点定位

直白说

这五个场景的共同结构值得说破：每一个里面，judge 都在忠实地执行它被要求做的事，数字也都是真的算出来的——错的是「这个数字支持什么结论」这一步推理。所以本课的重点不在「怎么让 judge 更准」，而在「怎么知道这个数字能支持什么、不能支持什么」。

严谨说

用测量学的语言，这五个场景分别是：构念无关方差被误读为效应（长度）、效标上限被忽略（人类一致率）、量表分辨率不足被误读为「没有差异」、抽样误差被误读为真实变化（榜单换人）、以及代理指标与目标指标背离（过优化）。五个都是经典的测量学错误，只是换到了 LLM 这个新对象上——这也是为什么本课大量复用 C10 的工具，而不是发明新的。

如果你只带走一句话，带走这句：「judge 说 A 更好」这个结论，在你知道这个 judge 的长度系数、swap 一致率和人类上界之前，是一个还没有完成的结论。本课剩下的五个模块，就是把它补完的方法。
