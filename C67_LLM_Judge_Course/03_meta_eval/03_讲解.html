1元评测问的是什么：judge 要和「谁」对齐

元评测（meta-evaluation）就是评测这个评测器。但在算任何数字之前，必须先回答一个经常被跳过的问题：judge 要和什么对齐？

对齐目标什么时候是对的怎么获得陷阱
单个人类标注员几乎从不最便宜标注员之间本来就不一致，对齐到某一个人没有意义
多个标注员的多数意见最常见、通常是对的默认3–5 人重复标注多数意见在「难题」上本身就不稳定
专家共识（讨论后）高风险场景（安全、医疗、法务）最贵共识可能掩盖真实的合理分歧
下游任务表现judge 用作训练信号时需要跑完整的训练-评测回路反馈慢，但这是最终极的效标
另一个更强的 judge几乎从不便宜两个 judge 可能共享同样的偏差（模块 02 第 7 节）

最后一行值得单独警告：用一个更强的模型当「金标准」来验证一个更便宜的 judge，只能证明两者一致，不能证明两者对。长度偏差、格式偏差在几乎所有主流模型上方向一致——用 A 验证 B，会把这些共有偏差一路带进你的「验证通过」结论里。这个做法可以用来省钱（确认小 judge 能替代大 judge），但不能用来验证正确性。

确定了对齐目标之后，元评测要回答三个层次的问题，本模块依次展开：

  1. 一致性：judge 和目标有多像？（第 2–3 节）——但必须配着人类自身的一致率一起读，否则数字无法解释。
  2. 分辨力：judge 能不能把你真正关心的两个东西区分开？（第 4 节）——样本级一致率低，不代表系统级排序不对。
  3. 校准：judge 说「我 80% 确定」时，它对了 80% 吗？（第 5 节）

2人类上界：为什么 82% 可能已经是天花板

这是元评测里最常被忽略、也最容易导致错误结论的一件事。

直白说

「我们的 judge 与人类标注的一致率是 82%」——这句话单独看，读者会自然地把它和 100% 比较，得出「还差 18 个点」的结论。但如果两个人类标注员之间的一致率也只有 84%，那么 82% 已经几乎顶到天花板了——剩下的 18 个点里，绝大部分是「这道题本来就没有唯一答案」，不是 judge 的错。

严谨说

形式化地说，设 $a_{HH}$ 是人类之间的一致率、$a_{JH}$ 是 judge 与人类的一致率。在「每个标注者独立地以概率 $p$ 给出与潜在真值一致的判断」这一简单模型下，二元任务里 $a_{HH} = p_H^2 + (1-p_H)^2$，$a_{JH} = p_J p_H + (1-p_J)(1-p_H)$。因此从 $a_{HH}$ 可以反解出 $p_H$，进而把 $a_{JH}$ 翻译成 $p_J$——这个 $p_J$ 才是「judge 有多准」的、不受人类噪声污染的度量。notebook 第 1 节会把这个反解写成代码。

三个必须一起报的数字

数字含义缺了它会怎样
$a_{JH}$ judge–人类一致率judge 与目标的一致程度—
$a_{HH}$ 人类–人类一致率天花板读者会把 $a_{JH}$ 和 100% 比，系统性低估 judge
随机一致率瞎猜能得多少（二元任务是 50%）读者会把 $a_{JH}$ 和 0% 比，系统性高估 judge
\[\text{天花板归一化一致率} = \frac{a_{JH} - a_{\text{chance}}}{a_{HH} - a_{\text{chance}}}\]

这个归一化量的读法很直接：1.0 表示 judge 已经和人类一样好（顶到天花板），0 表示 judge 只相当于瞎猜。上面那个例子：$(0.82 - 0.5)/(0.84 - 0.5) = 0.94$——judge 达到了人类水平的 94%，而不是「只有 82 分」。这两种表述会导向完全不同的资源分配决策。

需要一个诚实的提醒：归一化量可能超过 1（judge 比人类更一致）。这不一定是好事——它也可能意味着 judge 有一个稳定的系统偏差，使它比人类更「自洽」但不更「正确」。一致性高不等于正确性高，这正是为什么模块 02 的偏差探针不能被一致率替代。

3一致性系数：accuracy、kappa、Krippendorff 各自的适用面

「一致率」有很多种算法，它们在不同情形下给出差别很大的数字。选错会得出错误结论。

系数公式要点什么时候用失效方式
原始一致率$a_o = \Pr(\text{两者相同})$类别均衡、只做粗略汇报类别不均衡时严重虚高：如果 90% 的样本人类都判 A，全判 A 的 judge 也有 90%
Cohen's kappa$\kappa = \dfrac{a_o - a_e}{1 - a_e}$，$a_e$ 是按各自边缘分布算的随机一致两个评判者、名义类别——最常用边缘分布极不均衡时 kappa 会异常地低（kappa 悖论）
Krippendorff's α基于观测不一致与期望不一致之比，支持任意评判者数、缺失值、有序/区间数据多个评判者、有缺失、或有序量表实现复杂；对小样本不稳定
Spearman / Kendall 相关秩相关有序打分（1–5 分）而非分类对并列（tie）敏感；不惩罚系统性平移
kappa 悖论值得知道：当两个评判者都高度倾向于某一类时（比如 92% 的样本都被判为「通过」），即使原始一致率高达 90%，kappa 也可能只有 0.2 左右。这不是 kappa 算错了——它在告诉你「在这个极度不均衡的分布上，你们的一致大部分可以由「都爱说通过」解释」。正确反应不是换一个更好看的系数，而是承认「这个任务在当前分布下几乎没有区分度」，并去找更均衡的样本来评（第 8 节的元评测集设计）。

pairwise 场景的特殊处理

在 A/B/tie 三分类的 pairwise 判断上，有一个实践细节：「A vs B」的分歧与「A vs tie」的分歧，严重程度不同。前者是方向相反，后者只是强度不同。因此建议：

  • 报两个数字：严格一致率（三类完全相同）与方向一致率（把 tie 视为可接受，只看有没有判反方向）；
  • 或者用有序版本的 Krippendorff α（把 A < tie < B 视为有序），它会自动给「差一档」比「差两档」更轻的惩罚。

4样本级 vs 系统级：一致率 70% 的 judge 可能排序完全正确

这是元评测里最有实用价值、也最反直觉的一条结论。

样本级一致性 系统级一致性 ┌──────────────────────┐ ┌──────────────────────────┐ │ 逐条比对 judge 与人类 │ │ 比对「模型排名」是否一致 │ │ 指标: accuracy/kappa │ │ 指标: 排名相关 / 胜负一致 │ │ 关心: 单条判断准不准 │ │ 关心: **选型结论对不对** │ └──────────────────────┘ └──────────────────────────┘ │ │ 一致率 70% ──► 聚合 200 条 ──► 排序正确率 ~86%（1000 条 → ~99%） （单条经常判错） （随机误差被平均掉，但要靠 n 补回差距）

直白说

为什么会这样？因为随机误差在聚合时会被平均掉。judge 在单条样本上有 30% 的概率判错，但如果这些错误是随机的，那么在 200 条样本上取平均，胜率的估计误差只有几个百分点——足以把两个真实差距 5 个点的模型区分开。所以「judge 一致率只有 70%，不能用」这个判断经常是错的——取决于你要用它回答什么问题。

严谨说

形式化：设单条一致率为 $p$，模型 A、B 的真实胜率差为 $\delta$。judge 观测到的胜率差约为 $(2p-1)\delta$（误差把差距压缩了但没有翻转方向），而观测的标准误约为 $\sqrt{2 \cdot 0.25/n}$。因此系统级结论的可靠性取决于 $(2p-1)\delta\sqrt{n}$，而不是 $p$ 本身。$p = 0.70$、$\delta = 0.10$、$n = 200$ 时这个量约为 $0.4 \times 0.10 \times 14.1 = 0.57$……notebook 第 3 节会把这个量算准并给出所需样本量。

但是——这条结论有一个致命的前提：误差必须是随机的。如果 judge 的误差是系统性的（模块 02 的四大偏差），那么聚合不会把它平均掉，反而会让它在统计上显得更显著。所以正确的顺序永远是：先用探针确认没有共有的系统偏差，再用「样本级一致率低但系统级可用」这个论证。跳过第一步直接用第二步，是这门课里最危险的推理捷径。

该报哪个

两个都报，并且说明你的结论依赖哪一个。如果你的用途是「选模型」「排名」，系统级是决定性的；如果你的用途是「筛出坏样本送人工复核」「作为训练信号」，样本级才是决定性的——因为这些用途直接消费单条判断。

5校准：judge 说「我 80% 确定」时，它对了 80% 吗

如果你的 judge 输出的不只是判断，还有置信度（或者你用 logprob 构造了一个置信度），那么就有一个额外的性质需要检验：校准。

\[\text{ECE} = \sum_{b=1}^{B} \frac{|B_b|}{n}\left|\operatorname{acc}(B_b) - \operatorname{conf}(B_b)\right|\]

做法是把样本按置信度分桶，每桶里比较「平均置信度」与「实际准确率」，加权求和它们的差。ECE = 0 表示完美校准。

现象可靠性图上的表现常见原因处理
过度自信曲线在对角线下方：说 90% 只对了 70%最常见——RLHF 后的模型倾向于表达确定性温度缩放（对 logit 除以 $T > 1$）
信心不足曲线在对角线上方较少见；过度保守的 prompt 会造成温度缩放（$T < 1$）
置信度无信息曲线接近水平线judge 的置信度与正确率无关——这个置信度不该被使用换置信度的构造方式（如用 swap 一致性代替自报置信度）

一个非常实用的替代方案：与其相信 judge 自报的置信度，不如用「多次采样的一致性」或「swap 一致性」当置信度。两次调用判断一致 → 高置信；不一致 → 低置信。这个「置信度」通常比模型自报的更校准，因为它是从行为里测出来的而不是模型说出来的。而且你在做 swap 探针（模块 02）时已经把它算出来了，边际成本为零。

校准的用途：分诊

校准好的置信度最大的用途不是让报告更好看，而是分诊：把低置信度的样本送人工复核。如果置信度校准良好，那么「复核最低置信度的 10%」能捕捉到远超 10% 的错误——这是把有限的人力投入回报最大化的直接方法（呼应 C66 模块 02 的三级复核流水线）。

6成本-一致性前沿：更贵的 judge 值不值

judge 的选择是一个典型的成本-质量权衡，而且它的数量级经常被低估：一次大规模评测可能有几十万次 judge 调用，judge 模型的选择直接决定了这次评测的账单。

下面这张表里的一致率变化是经验量级，用来排优先级，不是文献结论；在你自己的任务上必须用模块 03 的方法重新量。

选项相对成本典型一致率变化（经验量级）什么时候值得
换更大的 judge 模型3–10×+3 到 +8 个点样本级判断被直接消费时（训练信号、分诊）
加 CoT1.5–3×（输出 token 变多）+2 到 +5 个点几乎总是值得，且它同时提升了可解释性
swap 双跑2×去掉位置偏差，一致率通常 +1 到 +3出结论的评测必做
多 judge 集成（3 个）3×+1 到 +4（仅当偏差方向不同）已经处理完共有偏差之后
rubric 化1–1.5×+3 到 +10 个点性价比最高的一项（模块 01）

这张表最重要的读法是顺序：便宜的手段先做完再考虑贵的。rubric 化（几乎免费）→ CoT（1.5×）→ swap（2×）→ 换大模型（3–10×）→ 集成（3×）。常见的错误是跳过前三步直接换最贵的模型——结果是花了十倍的钱，买到的提升还不如免费的 rubric 化。

另一个值得算的账：judge 的成本应该和评测规模一起决定。如果换个便宜的 judge 能让你把样本量翻三倍，而一致率只掉 3 个点——那么在「系统级结论」这个用途上，便宜 judge + 大样本几乎必然更优（因为第 4 节说过，系统级的可靠性取决于 $(2p-1)\delta\sqrt{n}$，$\sqrt{n}$ 的收益经常压过 $p$ 的损失）。这个取舍必须被显式计算，而不是靠直觉选贵的。

7漂移监测：judge 会在你不知道的时候变

judge 是一个外部依赖，而外部依赖会变。变化的来源至少有四个：

  • 模型版本更新——同一个模型名指向的权重可能变了；
  • prompt 被人改了——模块 01 第 8 节已经讲过；
  • 被评内容的分布变了——你的模型变得更长/更结构化，而 judge 的偏差在新分布上的表现不同；
  • 采样温度或解码参数被改了。

这四者的共同表现是：指标曲线上出现一个无法用模型改动解释的跳变。检测方式是维护一个不变的哨兵集（sentinel set）：

哨兵集 = 一批固定不变的、已有人类标注的样本（100-300 条）

每次评测运行都跑一遍哨兵集，记录:
  - judge 在哨兵集上的一致率
  - judge 在哨兵集上的分数分布（均值、标准差、各档比例）
  - swap 一致率

告警规则:
  - 一致率相对基线下降超过 2 个标准误  → 调查
  - 分数分布的均值平移超过阈值          → 调查（严厉度漂移）
  - swap 一致率下降                     → 调查（可能换了模型版本）

哨兵集有一个必须遵守的纪律：它必须永远不变，而且不能被用来调 prompt。一旦你用哨兵集的结果去改进 judge，它就从「监测工具」变成了「优化目标」，从此不再能告诉你任何关于漂移的事（Goodhart，又一次）。正确做法是维护两套：一套开发集用来调 judge，一套哨兵集只用来监测、结果只看不改。

检测方法上，比「单点阈值」更好的是累积和（CUSUM）：它累积微小的同向偏离，因此能检出「每次只掉 0.5 个点、但连续掉了十次」这种缓慢漂移——而这恰恰是单点阈值最容易漏掉的模式。notebook 第 6 节给出实现。

8元评测集怎么建：样本选择比样本数量更重要

最后一节讲元评测的输入：那批带人类标注的样本从哪来。选错样本，做再多的一致性分析都是白做。

选择策略怎么选适合回答什么问题问题
随机抽样从真实分布里随机抽「judge 在我的实际流量上有多准」难样本太少——如果 85% 的样本都很好判，你测的主要是简单题
难度分层按「judge 置信度」或「两个模型输出的接近程度」分层抽「judge 在难样本上有多准」需要一个难度代理变量
分歧驱动专挑「两个 judge 意见不同」或「swap 不一致」的样本最省人力：直接命中判分器的薄弱区得到的一致率不能代表整体分布，必须做重要性加权才能外推
对抗构造刻意构造长度/格式/自信语气不同的对照（模块 02 的探针）「judge 的偏差有多大」不能用来估计整体一致率

推荐的组合：「随机抽样的主集」+「分歧驱动的加强集」+「对抗构造的探针集」，三者分开报告、绝不混算。主集回答「整体有多准」，加强集回答「难的地方有多准」，探针集回答「有没有系统偏差」。把它们混成一个数字，三个问题一个都答不了——这与 C66 模块 02 的「主表 micro + 附表 macro」是同一种报告纪律。

样本量：比你想象的少

一个好消息：元评测集不需要很大。估计一个一致率到 ±5 个百分点（95% 置信），只需要约 400 条；±3 个点需要约 1000 条。而做偏差探针（配对设计）需要的更少——几十到一两百对通常就够（模块 02 第 6 节）。真正贵的不是样本数，是标注质量——每条需要多个标注员、需要标注规范、需要处理分歧，这才是成本所在。

9廉价而有效的人类标注：把最贵的一环压到最小

本模块反复说「必须有人类标注做对照」，而这通常是整个流程里最贵的一环。这一节讲怎么把它压到可承受的规模——因为「太贵所以不做」的实际后果是「没有任何对照」，那比小规模对照差得多。

四条降本手段

  1. 用 pairwise 而不是打分：让人类比较两个回答，比让他们打绝对分更快、一致性更高、也不需要校准会。「哪个更好」这个问题人类天然擅长，「打几分」不擅长（与第 3 节的量表讨论同源）。
  2. 分歧驱动抽样：优先标注 judge 自己拿不准的样本（swap 不一致、多 judge 意见不同、置信度低）。同样的标注预算，信息量能高出好几倍——但要记住这批样本不能直接用来估计整体一致率（第 8 节），需要单独报告。
  3. 只标注两端：如果目的是校准量表（模块 01 的锚点），标 1 分与 5 分的样例比标中间档有价值得多——中间档会被内插出来。
  4. 把标注变成检查而不是判断：不问「这个回答好不好」，问「这个回答有没有提到 X / 有没有事实错误 / 有没有回答用户的问题」。可判定的问题标得更快、一致性更高，而且天然对应 rubric 项——这是第 1 节可判定性阶梯在标注环节的应用。

关于样本量的一个好消息，值得重复：元评测集不需要很大。估计一致率到 ±5 个百分点只需约 400 条；而模块 02 的偏差探针因为是配对设计，几十到一两百对就够。真正贵的不是样本数，是每条需要多人标注 + 处理分歧这个流程。所以降本的重点应该放在「让每条标注更快、分歧更少」上，而不是放在「少标几条」上。

标注流程的五条硬规范

  • 随机化 A/B 顺序——否则人类标注本身就带位置偏差，你的「金标准」不干净；
  • 隐藏模型身份——否则带品牌偏差；
  • 每条至少 3 人——2 人只能算一致率，3 人才能取多数意见；
  • 先开 20 条的校准会——对齐口径的收益远大于它的成本；
  • 记录标注耗时——耗时长的样本就是难样本，天然是难度分层的候选，这个字段免费但很多人忘了记。
