1问题：手上是一堆胜负，想要的是一个排行榜

模块 01–03 解决的是「一次比较可不可信」。这一节开始解决下一个问题：你有几千条「A 赢 B」的记录，涉及十几个模型，怎么把它们变成一个带误差棒的排行榜？

这一步引入了一个新的假设，它必须被显式说出来：「模型的质量可以被一个标量刻画」。这个假设在多数情况下够用，但它不是免费的——第 5 节会讲它什么时候崩掉。

方法核心思想优点缺点
朴素胜率每个模型对所有对手的总胜率极简单被对手强度污染：只和弱模型比过的模型胜率虚高
Bradley–Terry极大似然拟合每个模型的强度参数正确处理对手强度与稀疏性；有标准误假设传递性；批量计算
Elo在线逐条更新评分可增量更新，适合流式数据结果依赖比赛顺序；K 因子是个自由参数
带协变量的 BTBT + 长度/风格作为协变量可以同时做去偏（模块 02）与排名需要更多数据

为什么不能直接用胜率？因为对手不一样。一个只和弱模型比过 200 场的模型，胜率可能高达 80%；一个专挑强对手比的模型可能只有 45%。朴素胜率把这两者放在同一个尺度上比较，是没有依据的。BT 模型的全部价值就是：它同时估计所有模型的强度，让「赢了谁」这件事被正确地加权。

2Bradley–Terry 模型：定义、拟合与它的三个性质

BT 模型只有一个式子。设模型 $i$ 的强度参数为 $\theta_i$，则

\[\Pr(i \succ j) = \frac{e^{\theta_i}}{e^{\theta_i} + e^{\theta_j}} = \sigma(\theta_i - \theta_j)\]

其中 $\sigma$ 是 sigmoid。这等价于一个逻辑回归：把每场比较编码成一个只有两个非零元素的特征向量（胜者位置 +1、败者位置 −1），标签是「前者是否获胜」，拟合出来的系数就是 $\theta$。所以模块 02 写的那个 fit_logistic 可以直接复用。

三个必须知道的性质

  1. 只有差值有意义，绝对值没有。$\theta_i \to \theta_i + c$ 对所有 $i$ 同时加一个常数，所有预测概率都不变。所以必须固定一个基准（把某个模型设为 0，或让所有 $\theta$ 之和为 0），否则拟合出来的绝对数字每次都不一样。
  2. 差值直接翻译成胜率：$\theta_i - \theta_j = 0$ → 50%；$= 1$ → 73%；$= 2$ → 88%。这条让 BT 分数比 Elo 分数更容易解释——它就是 logit 尺度上的距离。
  3. 存在性条件：如果比较图不连通（有一组模型从没和另一组比过），两组之间的相对强度无法确定；如果某个模型全胜或全败，它的 $\theta$ 会发散到无穷。两种情况都需要正则化（等价于加一个先验）来处理。

第 3 条在真实数据上非常常见，尤其是刚加入榜单的新模型（比赛场次少、可能全胜）。标准处理是加 L2 正则（等价于给 $\theta$ 一个高斯先验），或者用「加一个虚拟的平局对手」的方式做平滑。不做正则化的 BT 拟合在这类数据上会给出荒谬的巨大分数，而且这个问题不会报错，只会安静地毁掉你的排行榜。

Elo 分数：BT 的一个仿射变换

Arena 类榜单常报的 Elo 分数，本质上是 BT 参数的线性重标：

\[\text{Elo}_i = 1000 + \frac{400}{\ln 10}\,\theta_i \approx 1000 + 173.7\,\theta_i\]

这个换算的意义是让「差 400 分 = 胜率 10:1」这条国际象棋的老约定成立。它不增加任何信息，只是换了一个更多人熟悉的刻度。知道这一点很重要：当有人说「A 比 B 高 20 个 Elo 分」，你可以立刻换算成 $20/173.7 = 0.115$ 的 logit 差，即约 52.9% 的胜率——一个远比「20 分」听起来更小的差距。

3在线 Elo：为什么它的结果依赖比赛顺序

在线 Elo 是另一条路线：不做批量拟合，而是每来一场比赛就更新一次评分。

\[\theta_i \leftarrow \theta_i + K\left(y - \sigma(\theta_i - \theta_j)\right), \qquad \theta_j \leftarrow \theta_j - K\left(y - \sigma(\theta_i - \theta_j)\right)\]

其中 $y \in \{0, 1\}$ 是实际结果，$K$ 是学习率（国际象棋里叫 K 因子）。这就是对 BT 对数似然做随机梯度上升——它是 BT 的在线版本，不是另一个模型。

性质在线 Elo批量 BT (MLE)实践含义
顺序依赖有：打乱比赛顺序会得到不同的分数无：只取决于胜负计数报告 Arena 类分数时，批量 BT 是更可复现的选择
增量更新天然支持需要重新拟合（但通常很快）流式场景用 Elo，定期发布用 BT
自由参数K 因子（大 = 跟得快但噪声大）只有正则化强度K 选不好会让榜单剧烈抖动
不确定度没有原生的标准误有（Hessian 或自举）要画误差棒必须用 BT 或对 Elo 做自举
处理能力漂移能（旧比赛权重自然衰减）不能（所有比赛等权）如果模型本身在变，Elo 反而更合适

顺序依赖不是一个理论洁癖问题。同一批比赛数据，换一个随机顺序跑一遍在线 Elo，模型的名次可能改变。这意味着「Elo 分数」这个数字本身不是数据的函数，而是数据加上你处理它的顺序的函数。公开榜单如果用在线 Elo，必须固定并公布顺序，否则不可复现——这与 C66 模块 05 的 harness 指纹是同一件事。notebook 第 2 节会把这个抖动量化出来。

一个折中方案在实践中很常用：用批量 BT 出正式排名，用在线 Elo 做实时预览。两者的差距本身也是一个有用的监控信号——差得越大，说明数据里的时间结构越强（可能是模型在漂移，也可能是配对策略随时间变了）。

4置信区间：排行榜上相差 20 分算不算差距

这是本模块最有实际价值的一节。没有区间的排行榜，是一份鼓励过度解读的文档。

两种算区间的方式

方法怎么做优点注意
自举对比较记录重采样，每次重新拟合 BT，取分位数不依赖渐近假设；能处理正则化慢（要拟合几百次）；重采样单位必须是「一场比较」而不是「一个模型」

推荐自举——它慢，但 BT 拟合本身很快（几千场比较、十几个模型，一次拟合是毫秒级），跑 500 次自举也就几秒钟。

从区间到「名次」

直白说

有了每个模型的区间，怎么报名次？正确做法不是按点估计排 1、2、3，而是给出「排名区间」：在自举的每一次重采样里都算一遍名次，然后报这个名次的分布。Arena 类榜单报的「rank」通常就是这个意思：与你区间重叠的模型都算并列。

严谨说

形式化：设自举重采样得到 $B$ 组参数 $\{\theta^{(b)}\}$，模型 $i$ 的排名分布为 $\{r_i^{(b)}\}$。报告 $[\text{quantile}_{2.5\%}(r_i),\ \text{quantile}_{97.5\%}(r_i)]$。这个区间比分数区间更直接地回答了读者关心的问题——「这个模型到底是第几名」。另一个等价的报法是显著优于计数：模型 $i$ 显著优于多少个其他模型（区间不重叠且方向为正），用这个数排序得到的名次天然是并列友好的。

那 20 个 Elo 分到底算不算

把第 2 节的换算和区间宽度放在一起，就能回答这个问题：

  • 20 个 Elo 分 ≈ 0.115 logit ≈ 52.9% 的胜率；
  • 要把 52.9% 与 50% 区分开（$z = 2$），按模块 03 的公式需要约 1200 场比较；
  • 而 Arena 类榜单上一对模型之间的直接对局往往只有几百场（其余信息来自与共同对手的间接比较）。

所以一条可以直接用的读榜规则：看区间，不看名次。区间重叠的模型就是并列，无论它们的点估计差了多少分。而如果一份榜单不给区间，你可以用一个粗糙的心算：几千场比较对应的区间半宽通常在 ±10 到 ±20 Elo 分之间，所以相差 30 分以内的名次基本可以当成并列。

5传递性：BT 假设了它，而 LLM judge 经常违反它

BT 模型把每个模型压缩成一个标量，这隐含了一个强假设：如果 A 通常赢 B、B 通常赢 C，那么 A 通常赢 C。这叫随机传递性。

而 LLM judge 的成对偏好经常违反它。违反的典型来源有两个：

  1. 能力不是一维的。A 擅长代码、B 擅长写作、C 擅长推理，在一个混合任务集上，三者可能形成一个循环——这不是 judge 出错，而是「一个标量」这个模型本身不够用。
  2. judge 的偏差与对局有关。如果 A 长 B 短、B 结构化 C 不结构化，长度偏差与格式偏差在不同对局里权重不同，也会造出循环。这一种是真的错，可以靠模块 02 的去偏减轻。

怎么检测

方法怎么做读法
三元环计数枚举所有三元组，统计形成循环（A>B>C>A）的比例与「随机胜负下的期望循环率」比较，显著更高才算异常
BT 拟合优度用拟合出的 $\theta$ 预测每一对的胜率，与实际胜率比较系统性的残差结构（不是随机噪声）说明一维不够用
分任务类型拟合在代码/写作/推理子集上各拟合一套 BT，看排名是否一致最有信息量：排名不一致直接证明能力是多维的

有一个特别值得警惕的现象：「总榜第一」经常在每个子任务上都不是第一。这不矛盾——总榜是各子任务按某个隐含权重加权的结果，而这个权重来自任务集的构成比例，往往没人显式选择过。换句话说，总榜的排名有一部分是由「任务集里代码题占多少比例」决定的。这就是为什么分任务榜比总榜更有决策价值。

如果检测到严重的传递性违反，处理方式按代价从低到高：

  • 分维度报告——最简单也最诚实：不出总榜，出几个子榜；
  • 先去偏再拟合——如果循环来自 judge 偏差（第 2 类来源），去偏能减轻；
  • 多维模型——把 $\theta_i$ 换成向量，用类似 Blade-Chest 的低秩模型。数据需求大幅上升，通常只在数据非常充足时才值得。

6主动配对：同样的预算，多买到多少信息

配对策略是排名系统里一个经常被忽略、但收益很大的杠杆。随机配对会把大量预算浪费在「早就知道结果」的对局上。

随机配对 主动配对（不确定性最大化） ┌─────────────────────┐ ┌─────────────────────────────┐ │ 最强 vs 最弱: 大量场次│ │ 最强 vs 最弱: 少量场次(结果已知)│ │ 结果几乎确定 → 0 bit │ │ 强度接近的对: 大量场次 │ │ │ │ 预测胜率≈50% → 接近 1 bit/场 │ └─────────────────────┘ └─────────────────────────────┘ 信息效率低 信息效率高（但引入了选择偏倚）
\[\text{单场信息量} \approx H\big(\sigma(\theta_i - \theta_j)\big) \quad\text{（二元熵，在 } \theta_i = \theta_j \text{ 时最大）}\]
策略怎么选下一对收益代价
随机均匀抽两个模型无偏；覆盖均匀；实现最简单把预算浪费在结果已知的悬殊对局上
不确定性最大化选当前预测胜率最接近 50% 的一对相邻名次的区间显著变窄悬殊对的估计变成纯外推，那些对的区间反而变宽
方差缩减选能最大程度缩小某个特定名次判断不确定度的一对针对性最强需要先声明你关心哪个判断
混合$\epsilon$ 概率随机 + $1-\epsilon$ 主动推荐：兼顾效率与覆盖多一个超参数

notebook 第 6 节会跑出一个值得记住的结果：主动配对并不是「全面更好」，而是「把精度搬了个地方」——相邻名次的差值区间窄了，但「能被显著区分开的模型对」总数反而少了。这完全说得通：预算是守恒的，你把它挪到难分的对上，悬殊的对就只能靠模型外推。所以「用哪种配对策略」取决于你要回答哪个问题——「谁是第一」用主动，「给我一个完整可信的全表」用随机。

主动配对有一个必须处理的副作用：它让数据不再是「随机缺失」的。如果你只在强度接近的对之间收集数据，那么「强弱悬殊的对」的估计就完全依赖模型外推——而这恰恰是传递性假设发挥作用最强、也最可能失效的地方。缓解：保留一定比例的随机配对（$\epsilon \ge 0.1$），并在报告里注明配对策略。

顺带一提：这个问题与 C13 的 bandit 探索-利用是同一个结构——「利用」是去比最有信息量的对，「探索」是保持覆盖。区别在于这里的目标不是最大化累积回报，而是最小化排名的不确定度。

7把去偏接进排名：带协变量的 BT

模块 02 讲了长度控制回归，模块本节讲排名。两者可以合成一个模型——这是目前 Arena 类榜单「风格控制」版本的做法。

\[\operatorname{logit}\Pr(i \succ j) = (\theta_i - \theta_j) + \gamma^\top (x_i - x_j)\]

其中 $x$ 是风格特征向量（长度、markdown 标题数、列表项数、代码块数…），$\gamma$ 是这些特征的效应。拟合后把 $x_i - x_j$ 设为 0，得到的 $\theta$ 就是「控制风格后的强度」。

版本$\theta$ 的含义什么时候看这个
原始 BT「模型在这个 judge 眼里有多受欢迎」你关心真实用户偏好，且用户也吃这一套—
风格控制 BT「排除掉长度与格式效应后的强度」你关心内容质量本身，或者担心模型在优化风格—
两者之差这个模型的排名有多少来自风格这个差值本身是最有信息量的一列—

第三行值得强调：「原始名次 vs 风格控制后名次」的变化量，是一个直接可读的诊断量。一个模型在风格控制后掉了五名，说明它的优势有相当部分来自「写得长、排版好」；这未必是坏事（如果用户确实喜欢），但它必须被知道，而不是被混在一个总分里。

实现上有两个细节值得注意：

  • 风格特征要标准化，理由与模块 02 相同——量纲不同会让某个特征获得不成比例的杠杆；
  • $\gamma$ 应当全局共享而不是每个模型一份：$\gamma$ 描述的是judge 的偏好，不是模型的属性。如果你给每个模型一个自己的 $\gamma$，模型就能通过「假装自己的风格特别有效」来吸收掉质量差异，参数不可识别。

9榜单卫生：三个会安静毁掉排行榜的操作

最后一节讲三件在实践中反复出现、而且都不会报错的操作。它们的共同点是：数字照样算得出来，只是不再有意义。

① 把不同 judge / 不同 prompt 的比较混在一起拟合

这是最常见也最严重的一个。judge 换了，或者 prompt 改了一句，之前所有的比较记录就不能与新记录混在一起拟合 BT——因为 BT 假设所有比较来自同一个「评判者」。混拟合的结果是：早期用旧 judge 比得多的模型，与后期用新 judge 比得多的模型，它们之间的相对位置由两个 judge 的系统差异决定，而不是由模型质量决定。

缓解办法只有两个，没有第三个：① judge 变更时作废历史数据，重新开始积累；② 在变更时设一个双跑重叠期，用同一批样本同时跑新旧 judge，估计出两者的系统差异，把它作为一个额外的协变量放进 BT（形式上与第 7 节的风格控制完全一样，只是协变量换成了「哪个 judge 判的」）。第二个办法更好，但需要提前计划——变更之后再想做就来不及了。

② 让新模型只和强对手比（或只和弱对手比）

BT 能修正赛程不均衡（第 2 节演示过），但它修正的能力是有限的：一个模型只和 2 个对手比过 50 场，它的区间会非常宽——而宽区间在按点估计排的榜单上是看不见的。规范：榜单必须列出每个模型的总场次与对手数，并对场次低于阈值的模型显式标记「数据不足」而不是给它一个名次。

③ 在同一个榜单里混合「不同任务分布」的比较

这是第 5 节传递性讨论的实践版本。如果早期的比较大多来自代码任务、后期大多来自写作任务，那么拟合出来的「总强度」实际上是一个随时间变化的加权平均，而这个权重从来没有人显式选择过。症状是：一个模型的名次随着榜单积累新数据而缓慢漂移，而它自己一行代码都没改。

操作症状为什么不会报错规范
混合不同 judge早期模型与后期模型的相对位置莫名其妙BT 拟合对「谁判的」一无所知作废历史 或 双跑重叠期 + judge 作为协变量
赛程严重不均衡某些模型的名次每周都在跳点估计照样算得出来列出场次与对手数；场次不足的标「数据不足」
混合不同任务分布模型自己没变，名次却在漂总强度是一个隐含加权平均按任务分榜；总榜必须公布任务构成比例

三条的共同教训：排行榜的可信度，主要不取决于拟合方法有多精巧，而取决于喂进去的比较记录是不是同质的。而「同质」这件事必须靠流程保证（记录 judge 指纹、监控赛程、按任务打标），拟合阶段已经来不及了。
