LLM-as-a-Judge 与评分模型

C03 模块 04 用一节的篇幅告诉你「有 LLM judge 这回事，要小心偏差」；C66 全课都在使用判分器。但「judge 本身怎么设计、怎么量它的偏差、怎么验证它到底有多准」，全库此前没有系统覆盖。本课的核心主张：judge 不是裁判，是一台测量仪器——而它的误差与被测物强相关，因此不会在平均之后抵消，而是系统性地奖励某一类输出。先验证仪器，再相信读数；而一旦仪器变成优化目标，它就开始失效。

6 模块 三种用法：校验 > pairwise > pointwise 四大偏差：位置 · 长度 · 自偏好 · 风格 人类上界 · 天花板归一化 BT / Elo / 风格控制排名 纯 numpy · CPU · 断网可跑
怎么用： 先读模块的 NN_讲解.html，再跑同目录下的同名 .ipynb。notebook 用一个可控的 judge 模拟器——先设定每个回答的「真实质量」，再用显式的偏差旋钮（位置/长度/自偏好/风格/噪声）生成判断。这比调真实 API 更适合学习：你知道真值，可以直接验证去偏方法有没有把偏差真的减掉，所以每道 ✏️ 练习 的 assert 检查的都是「去偏后更接近真值」。每个模块末尾的 🧪 真实工程胶囊 给出可原样复制到有 key 环境的代码（judge prompt 模板、swap 批量跑法、长度控制回归、RM 评测卡）——但本课全程 CPU、断网、无需 API key。
