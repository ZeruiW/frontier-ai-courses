02 · Judge 偏差与去偏

「我知道 judge 有偏差」和「我量过这个 judge 的偏差有多大」，在工程上是两件完全不同的事——前者只能加一句免责声明，后者能把偏差从数字里减掉 · swap 一致率低有两种成因，修法完全相反：位置偏差靠 swap 平均，纯噪声靠多采样；notebook 给出把两者分开的判据 · 长度控制回归的好处是它估计长度效应而不是假设它——没有偏差时 $\gamma$ 拟合成 0，方法自动退化成不做任何事 · 最危险的配置是「用模型 M 做 judge 来评测 M 的新版本」，而这恰恰是最常见的内部评测配置 · 统一的探针范式：造一批只差某个表面属性的成对样本 + 配对检验，几十到一两百对就能把任何新怀疑的偏差量出来 · 多 judge 集成只能治噪声，治不了所有 judge 共有的偏差，而且会让区间变窄——让你更自信地相信一个偏了的结论 · 去偏的正确输出不是一个更准的数字，而是一个更窄的区间加一句关于假设的说明

1四大偏差全景：机制、探针、去偏手段

模块 00 把 judge 的读数写成 $\hat{q} = q + f(\cdot) + \varepsilon$。这一节把 $f$ 拆开：它主要由四个分量构成，每一个都有明确的探针（怎么把它量出来）和明确的去偏手段（怎么把它减掉）。

偏差机制（为什么会有）探针（怎么量）去偏手段残留问题
位置偏差
position		自回归生成 + 提示结构，使得某个位置的候选被系统性偏好swap 一致性：交换 A/B 位置再判一次，看翻转比例两个位置各判一次取平均（成本翻倍）翻转样本怎么处理（记平局最保守）
长度/冗长偏差
verbosity		更长的回答提供更多「看起来相关」的内容，也更像训练数据里的高质量回答控制质量后，看长度对胜率的边际效应（回归系数）长度控制回归：把长度作为协变量回归掉长度与质量真的相关时会矫枉过正（第 8 节）
自偏好
self-preference		judge 对自己的生成分布有更高的似然，可能把「熟悉」误读为「好」同一批内容分别由同族/异族模型改写后再评换异族 judge；多 judge 集成「异族」的边界不清晰（同一批数据训出来的模型可能共享偏好）
风格与格式偏差
style		markdown 标题、要点列表、自信语气被系统性奖励把同一内容重排成不同格式，看分数变化去风格化（统一格式后再评）或在 prompt 里显式禁止格式在某些任务上确实是质量的一部分

这张表最重要的是第三列。「我知道 judge 有偏差」和「我量过这个 judge 的偏差有多大」，在工程上是两件完全不同的事。前者只能让你在报告里加一句免责声明，后者能让你把偏差从数字里减掉、或者至少判断出「这个 3 个点的差距是不是完全由长度差异造成的」。本模块的每一个探针都只需要几十到几百次额外的 judge 调用——相对于评测本身的成本，这是很便宜的。

除了这四个主要分量，还有几个二级偏差值得知道名字：bandwagon（告诉 judge「多数人认为 A 更好」会改变它的判断）、authority（虚构的引用与权威署名会提高分数）、身份偏差（提到作者身份会改变判断）。它们的共同点是：都可以用「加/不加某个无关信息，看分数变不变」这个统一的探针范式来测。

2位置偏差：最容易测、也最容易修的一个

位置偏差是四个里唯一有干净修法的：因为「A 在前」和「B 在前」是一个完全对称的操作，把两种顺序各跑一次取平均，位置项就被消掉了。

\[\hat{P}(A \succ B) = \tfrac{1}{2}\left[\Pr(\text{judge 说 A} \mid A \text{ 在前}) + \Pr(\text{judge 说 A} \mid A \text{ 在后})\right]\]

swap 一致率：一个必须报告的数字

swap 一致率含义该怎么办
> 90%位置偏差很小，judge 判断稳定正常使用；仍建议做 swap 平均
80% – 90%存在可观的位置偏差或判断噪声必须做 swap 平均；不一致样本记平局
70% – 80%偏差严重，或任务本身区分度低先检查是不是任务太难分——如果是，加大平局比例反而更诚实
< 70%这个 judge 的胜率数字不可用回到模块 01 重新设计（rubric 化、加参考答案、换更强的 judge 模型）

直白说

一个容易混淆的点：swap 不一致 ≠ 位置偏差。不一致有两个来源：位置偏差（系统性地偏向某个位置）和随机噪声（judge 就是不稳定）。区分方式很简单：看不一致样本里，「两次都说前面那个赢」占多少。如果不一致主要表现为「总是选第一个」，那是位置偏差；如果不一致是随机分布的，那是噪声。两者的修法完全不同——前者靠 swap 平均，后者靠多次采样或换更强的 judge。

严谨说

形式化：设 $p_1 = \Pr(\text{选第一个} \mid \text{顺序 AB})$、$p_2 = \Pr(\text{选第一个} \mid \text{顺序 BA})$。位置偏差的强度是 $\frac{p_1 + p_2}{2} - \frac{1}{2}$（两种顺序下「选第一个」的平均倾向偏离 0.5 的程度），而这个量与 A、B 的真实质量差无关——这正是它可以被消掉的原因。噪声则表现为不一致率高但上述偏差量接近 0。

工程上还有一个细节容易忘：swap 之后要把 verdict 翻译回来。第二次调用时 "A" 指的是原来的 B。这个翻译如果写错，你会得到一个看起来「一致率极低」的假象——而且这个 bug 极其常见，因为它不会报错，只会让数字变难看。自检方法：拿一批「A 明显优于 B」的样本跑一遍，如果 swap 一致率异常地低，先怀疑翻译写反了。

3长度偏差与长度控制回归

长度偏差是四个里影响最大、修起来最微妙的一个。它的麻烦之处在于：长度与质量之间存在真实的相关性——一个完整回答确实通常比一个敷衍的短回答长。所以不能简单地「惩罚长回答」。

探针：控制质量后看长度的边际效应

正确的探针必须控制住质量。三种做法，成本递增、可信度也递增：

  1. 回归法：拿现有的 judge 结果，把「胜负」对「质量代理变量 + 长度差」做回归，看长度差的系数。便宜，但需要一个质量代理变量（例如人类标注的子集）。
  2. 改写法：把同一个回答扩写/精简成不同长度但信息量相同的版本，送 judge 打分，看分数随长度的变化。中等成本，最直观。
  3. 配对法：找出「人类判为平局」的成对样本，看 judge 在这些样本上是否系统性偏向长的那个。需要人类标注，但结论最硬。

去偏：长度控制回归

这是 AlpacaEval 的 LC（length-controlled）版本采用的思路，也是目前最实用的去偏方法。核心是一个逻辑回归：

\[\operatorname{logit}\Pr(A \succ B) = \theta_m + \gamma \cdot \Delta_{\text{len}} + \beta^\top x\]

其中 $\theta_m$ 是模型 $m$ 的质量参数（我们真正想要的量）、$\Delta_{\text{len}}$ 是两个回答的长度差（通常取 token 数之差或其某种标准化形式）、$\gamma$ 是长度偏差的强度。拟合完之后，把 $\Delta_{\text{len}}$ 设为 0 再算胜率，就得到「长度控制后的胜率」。

为什么这个做法比「直接惩罚长回答」好？因为它估计了长度效应而不是假设了它。$\gamma$ 是从数据里拟合出来的：如果这个 judge 其实没有长度偏差，$\gamma$ 会接近 0，去偏后的胜率与去偏前几乎一样——方法自动退化成不做任何事。这是一个好的去偏方法应有的性质：没有偏差时不引入伤害。

需要注意的实现细节：长度差要做某种归一化（例如除以两者长度之和，或者取对数长度之差），否则一条 5000 token 的回答会在回归里占据不成比例的杠杆。另外，$\gamma$ 应当按 judge 分别估计——不同的 judge 模型长度偏差差别很大，共用一个 $\gamma$ 是没有依据的。

4自偏好：最难证明、也最难修的一个

自偏好（self-preference / self-enhancement）指的是：judge 在评价自己（或同族模型）生成的内容时，倾向于给更高的分。

为什么难证明

困难在于混杂：如果 judge 模型 M 评价 M 的输出得分更高，有两种同样合理的解释——① M 偏爱自己的输出（偏差）；② M 的输出确实更好（事实）。要分开这两者，必须控制住质量。

实验设计怎么做能证明什么局限
交叉评审让 M1、M2 互评对方与自己的输出如果每个模型都把自己排第一，那至少有一个是偏差不能定量给出偏差幅度
人类锚定取一批人类判为等质量的成对样本，看 judge 在其中是否偏向同族输出能定量需要人类标注
风格迁移把 M2 的内容用 M1 改写成 M1 的风格（保持信息不变），看分数是否上升能分离「内容偏好」与「风格偏好」改写可能无意中改变了内容质量
识别度关联先问 judge「这是不是你写的」，再看它给的分与识别度的相关揭示机制（自我识别 → 偏好）识别本身可能不准

自偏好在一个具体场景下危害最大：用模型 M 做 judge 来评测 M 的新版本。这是最常见的内部评测配置，而它恰好踩中了自偏好——新版本相对旧版本的「提升」，可能有一部分只是「新版本的输出更像 judge 自己」。最低限度的缓解：用一个异族 judge 做交叉验证，至少确认两个 judge 给出的排序一致。

缓解手段

  • 换异族 judge——最直接，但要注意「异族」的边界并不清晰：在相似数据上训练、用相似方法对齐的模型，可能共享同样的风格偏好。
  • 多 judge 集成——如果各 judge 的自偏好指向不同方向，集成会部分抵消（第 7 节）。
  • rubric 化（模块 01）——把整体判断拆成客观检查项，自偏好在「有没有引用正确条款」这种项上很难发挥作用。这是被低估的一条。
  • 去风格化——如果自偏好主要通过风格起作用，统一格式能消掉一部分。

5风格与格式偏差：以及「格式什么时候真的算质量」

markdown 标题、要点列表、加粗、开头的一句总结、自信而不含糊的语气——这些都被观察到能系统性地提高 judge 给的分，即使内容不变。

探针：同内容、不同格式

原始回答（纯文本）:
  要解决这个问题，先检查配置文件里的超时设置，然后确认网络策略允许出站请求，
  最后看一下日志里有没有 429 错误。

重排后（结构化）:
  ## 排查步骤
  1. **检查超时设置** — 配置文件中的 timeout 值
  2. **确认网络策略** — 是否允许出站请求
  3. **查看日志** — 搜索 429 错误

  信息量完全相同。如果 judge 给第二个更高的分，差值就是格式偏差。

直白说

关键问题来了：格式偏差到底算不算偏差？如果最终用户读的就是这段文本，那么「更好读」确实是质量的一部分，judge 给它更高分是对的。但如果这段文本要被程序解析、或者你评测的是「事实准确性」，那么格式就是纯粹的噪声。所以答案取决于你的评测目标——而这必须被显式声明，不能靠默认。

严谨说

用测量学的语言：格式是不是构念的一部分（part of the construct）还是构念无关方差（construct-irrelevant variance），取决于构念的定义。同一个 judge 读数，在「整体有用性」这个构念下格式是信号，在「事实准确性」这个构念下格式是噪声。这也是为什么模块 01 主张 rubric 化：把「格式清晰」单列成一项，它就从一个隐藏的混杂变量变成了一个可以被显式加权（甚至权重设为 0）的维度。

一个实际会发生的坏结果：如果你用一个有格式偏差的 judge 做训练信号或选型标准，模型会学会「把简单答案包装成有标题有列表的长文」——在需要简洁回答的场景，这是纯粹的退化。而且这个退化在 judge 的分数上表现为「提升」，所以只看分数你永远发现不了。唯一的发现方式是监控输出的长度分布与格式分布——这条监控在 C68 模块 05 里是一条标准的漂移告警。

6统一的探针范式：加一个无关变量，看读数变不变

前面五节的探针看起来各不相同，其实是同一个模式的实例。把它抽象出来，你就能给任何新怀疑的偏差自己设计探针。

探针范式（反事实对照） ┌─────────────────────────────────────────────────────────────┐ │ 1. 选一个你怀疑的表面属性 X（位置/长度/风格/署名/引用/…） │ │ 2. 构造成对样本：内容与质量完全相同，只有 X 不同 │ │ 3. 送同一个 judge 打分 │ │ 4. 分数差的均值 = X 的偏差幅度；差的方差 = 这个探针的噪声 │ │ 5. 用配对检验（同一内容成对）判断偏差是否显著 │ └─────────────────────────────────────────────────────────────┘ 关键在第 2 步：「质量完全相同」这件事必须是**构造出来的**， 不能靠"我觉得这两个差不多"。最可靠的构造方式是「同一份内容的变体」。
怀疑的属性 X怎么构造只差 X 的成对样本注意
位置交换 A/B 顺序最干净——交换是严格保内容的
长度扩写/精简到不同长度但信息量相同很难做到「信息量严格相同」，需要人工核对
格式把同一内容重排成纯文本 / markdown相对容易保内容
署名 / 身份在 prompt 里加上「这是 X 写的」干净，但要注意 judge 可能拒绝回答
虚构引用加一条格式正确但不存在的引用这条同时也是安全探针——judge 被虚构权威提分，说明它没在核实
自信语气把「可能是……」改成「就是……」保内容但改变认知标记，是校准相关的重要探针

第 5 步用配对检验而不是独立检验，理由与 C66 模块 04 完全相同：成对样本共享内容，内容质量这个最大的方差源被直接消掉。这意味着探针需要的样本量比你想象的少得多——几十到一两百对通常就足以把偏差幅度定位到有用的精度。

7多 judge 集成：什么时候真的有用

「用三个 judge 投票」是一个被广泛推荐的做法。它有效，但只对某一类误差有效，而人们常常把它当成万能解药。

误差类型集成有没有用原因
随机噪声✅ 非常有用独立噪声按 $1/\sqrt{K}$ 衰减，这是集成的标准收益
各 judge 方向不同的偏差✅ 有用方向不同的系统项在平均后部分抵消
各 judge 共有的偏差❌ 完全无用所有 judge 都偏向长回答时，平均之后还是偏向长回答——而且置信区间会变窄，让你更自信地相信一个偏了的结论

第三行是这一节的全部重点。长度偏差、格式偏差在几乎所有主流 judge 模型上都存在，且方向一致。对这类偏差，多 judge 集成不但没用，还有害——它把随机噪声压下去，使得残留的系统偏差在统计上显得更「显著」。集成只能治噪声，不能治共有的偏差。

那什么时候值得做集成

  • judge 之间确实异质——不同厂商、不同规模、不同对齐方式。先用第 6 节的探针测一下它们的偏差方向，方向一致的 judge 集成起来没有额外收益；
  • 你已经把共有偏差处理掉了——先做 swap 平均、先做长度控制，剩下的才交给集成；
  • 预算允许——集成的成本是线性的，而收益是 $1/\sqrt{K}$ 的。三个 judge 通常是性价比拐点，五个以上很少划算。

最后一个实用提示：集成的聚合方式要与用法匹配。pairwise 场景用多数投票（并把「无多数」记为平局）；pointwise 场景用均值（并报告 judge 间的标准差——这个标准差本身就是一个有用的「这个样本难判」信号，可以拿去做人工复核的分诊）。

8去偏的极限：当长度与质量真的相关时

最后一节讲一个必须诚实面对的问题：去偏不是免费的，它有可能矫枉过正。

长度控制回归的隐含假设是：在控制住模型身份之后，长度差与质量差无关。但这个假设并不总成立——如果模型 A 真的因为「回答更完整」而更长，那么把长度效应全部回归掉，就把 A 的一部分真实优势也一起减掉了。

\[\Delta_{\text{len}} = \underbrace{\delta_{\text{quality}}}_{\text{因为更完整而更长}} + \underbrace{\delta_{\text{padding}}}_{\text{纯粹的注水}}\]

直白说

问题在于：这两项在观测数据里是无法分离的——你看到的只有总长度差。这是一个典型的不可识别问题：同一份数据可以由「A 更完整」和「A 更爱注水」两种假设同样好地解释。所以长度控制后的胜率不是「真值」，而是「假设长度全是注水时的下界」。

严谨说

要打破不可识别，必须引入额外的识别假设或额外的数据。实践中有三条路：① 用人类标注的子集去估计 $\delta_{\text{quality}}$（人类判定「这段额外内容有没有增加信息」）；② 构造反事实样本（第 6 节的改写法：造出「同信息量不同长度」的对照，此时 $\delta_{\text{quality}} = 0$ 被构造性地保证了）；③ 报告一个区间而不是一个点——「原始胜率 62%，长度控制后 54%，真值在两者之间」。第三条最诚实，也最容易执行。

把这条推广成本模块的总结论：去偏的正确输出不是一个更准的数字，而是一个更窄的区间加上一句关于假设的说明。「LC 胜率 54%」如果不附带「原始 62%」和「差值 8 个点全部归因于长度」这个假设，它给读者的确定感就超过了它实际拥有的信息。

9偏差预算：一份评测该花多少钱在探针上

本模块给了五个探针。它们都很便宜，但加起来也是成本。这一节回答一个很实际的问题：该按什么顺序做、做到什么程度就可以停。

优先级探针额外调用量什么时候可以跳过
P0 必做swap 一致性×2（全量）永远不能跳过——它同时是去偏手段和质量指标
P0 必做长度偏差（回归法）0（用已有结果拟合）永远不能跳过：零边际成本，只需要日志里有长度字段
P1 强烈推荐风格探针（同内容不同格式）~200 对被评内容的格式高度统一时可跳过
P1 强烈推荐自偏好探针~300 对judge 与被评模型确定异族时可跳过
P2 按需虚构引用 / 权威 / 从众探针各 ~150 对非事实密集任务可跳过
P2 按需多 judge 集成×K（全量）先确认候选 judge 的偏差方向不同，方向一致就别做

注意第二行：长度偏差的回归法探针边际成本是零——它只需要你在日志里记了 a_len_tokens 与 b_len_tokens，然后对已有的判断结果拟合一个逻辑回归。这可能是整个评测流程里性价比最高的一件事：几行代码，换来「这 6 个点的差距有多少来自长度」这个关键答案。而它的前提只是「日志里有那两个字段」——这又一次说明 schema 是事前决定（呼应 C66-03）。

什么时候可以停

一个可操作的停止规则，按结论的用途分：

  • 只是内部看看趋势：做完 P0 两项即可，把 raw 与 LC 两个数一起看；
  • 要写进报告或做选型决策：P0 + P1 全做，并在报告里给出 raw–LC 区间与两个探针的幅度；
  • judge 要被用作训练信号：全部做完，而且要定期重做——因为模块 05 会讲到，训练信号的误差会被优化过程主动放大，你在这里量到的每一个偏差，都会在训练后变成一种 reward hacking 形态。

最后一条值得展开一句：偏差探针的结果，是可以直接预测 hack 方向的。如果你量到长度系数 $\gamma = 0.8$，那么用这个 judge 训出来的模型一定会把输出推长——这不需要等实验结果，可以提前布置监控。模块 05 第 3 节会把这条对应关系列成一张完整的表。
