1这门课讲什么：补「如何做研究」的洞

欢迎来到 研究方法论与科学实践。这门课和这套培训里的其他每一门都不同：别的课教你知识内容——模型怎么工作、算法怎么推导、系统怎么搭、内核怎么写；而这门课教你如何做研究本身。这是整套培训里一直缺的那块拼图。

打个比方：前面所有课教你的是各种食材和刀工——这块肉怎么处理、那种火候怎么控。但没有一门课教你怎么当一个厨师：怎么判断一道别人的菜好在哪、怎么设计一道能稳定复刻的新菜、怎么在只尝一口的情况下分辨「这真的好吃」还是「我今天运气好」、怎么把菜谱写到别人照着也能做出来。「会用模型」和「能产出可信的新知识」之间，隔着的正是这套元技能。

为什么说「会做研究」是研究员的定义性技能？因为研究的产物从来不是代码或模型本身，而是可信的新知识——一个别人能信、能在其上继续建造的主张。一个工程师交付「能跑的系统」；一个研究员交付「站得住脚的结论」。后者要求的不是更会写代码，而是一整套如何让一个主张值得被相信的功夫：怎么读懂前人到哪了、怎么设计实验把功劳归对、怎么用统计排除运气、怎么让结果可复现、怎么诚实地把它写出来扛住挑剔的同行。缺了这套功夫，再漂亮的实验也只是 demo，不是研究。

一句话定义研究：提出一个可证伪的主张，并用强到配得上它的证据去支持它。这句话里每个词都是一个模块——「可证伪的主张」（怎么读懂与提出，模块 01/05）、「证据」（怎么用实验产生，模块 02）、「强到配得上」（怎么用统计衡量强度，模块 03）、「可支持」（怎么可复现地呈现，模块 04/05）。本课就是把这句话拆开、逐块练扎实。

还有一个现实理由：你读的每一篇论文、你做的每一个实验、你投的每一篇稿、你审的每一份稿，都在用这套技能——而几乎没人系统教过它。大多数人是在踩坑中零散学会的（只跑一个种子被打脸、一次改两个量结论作废、图表被审稿人质疑误导）。本课把这些坑一次性、系统地、用能跑的代码摆给你看，让你在自己的研究里提前避开。

要先破除一个常见的误解：很多人以为「方法论」是软的、虚的、靠悟性的东西，比不上学一个具体的模型或算法实在。恰恰相反——方法论是这套培训里最硬、回报最高、也最通用的技能。一个具体的模型架构可能三年后就过时了，但「如何设计一个能下结论的实验」「如何用统计区分信号与噪声」「如何让工作可复现」这些功夫跨领域、跨时代地有效：无论你将来做大模型、做机器人、做计算生物，还是转去做完全不同的实证科学，这套元技能原样适用。本课用机器学习的语境来教（因为这是你最熟悉的场景），但它教的其实是一切经验科学的通用方法。

2研究 = 主张 + 证据：贯穿全课的主线

研究 = 主张 + 证据：一条贯穿全课的主线

把研究还原到最朴素的结构，它只有两个零件：一个主张（claim）和支持它的证据（evidence）。一切方法论，都是在打磨这两个零件以及它们之间的连接。

研究的解剖：一个主张，由证据支撑 你想说的话（CLAIM） 支撑它的东西（EVIDENCE） 「方法 X 优于基线 B」 ←—— 一张对照实验表 + 消融 + 多种子方差 + 显著性 │ │ │ 主张越大、越反直觉， │ 证据必须越强： │ 需要的证据越强 │ 有对照吗？有消融归因吗？ ▼ ▼ 报方差了吗？基线够强吗？ 过度声明 = 主张 > 证据所能承担 可复现吗？ 模块 01 读懂别人的「主张-证据」 模块 02/03 产生强证据 模块 04/05 让证据可复现、诚实呈现

这条主线解释了本课每个模块的存在理由。模块 01教你读别人的主张-证据对（读论文、复现、给可信度打分）——这是输入端；模块 02 与 03教你生产强证据（受控实验把功劳归对、统计排除随机种子的运气）——这是过程；模块 04 与 05教你让证据可复现并诚实呈现（工程卫生、诚实图表、扛住审稿）——这是输出端。读入、生产、输出，构成研究的完整闭环。

直白说

最常见、最致命的研究错误，几乎都能归结成一句话：主张的重量超过了证据能承担的。「我加了个模块涨了 0.5 分」——证据（一次运行、无对照、无方差）根本扛不起「这个模块有用」这个主张。本课大半的功夫，就是教你把这两端称重、对齐。

严谨说

形式化地说：每个主张都有一个隐含的置信度，证据决定这个置信度能有多高。extraordinary claims 需要 extraordinary evidence（Sagan）。读论文时，你要不断问「这个证据撑得起这个主张吗」；做研究时，你要不断问「我的证据配得上我想说的话吗」。这种称重的本能，就是研究品味的核心。

3本课地图：读入 → 生产 → 输出的闭环

本课地图：从读入到输出的研究闭环

【输入 · Consume】 模块 00 总览 研究=主张+证据；为什么「会做研究」是定义性技能 │ ▼ 模块 01 读论文与复现 三遍读法、拆主张-证据、复现检查表、可信度打分 │ 「我能读懂并相信别人的工作吗？」 ▼ 【过程 · Produce】 模块 02 实验设计与消融 受控实验、对照、消融、混杂、随机化、OFAT │ 「我的实验能把功劳归对吗？」 ▼ 模块 03 研究统计 种子方差、bootstrap CI、功效、多重比较、效应量 │ 「这是真信号，还是随机种子的运气？」 ▼ 【输出 · Communicate】 模块 04 研究工程 config、sweep、可复现(种子/版本)、结果聚合 │ 「别人(和半年后的我)能重跑出来吗？」 ▼ 模块 05 写作与审稿 IMRaD、claim-evidence 映射、诚实图表、rebuttal、品味 「我能诚实地讲清楚并扛住挑剔的同行吗？」

这不是六个松散专题，而是一条研究的工作流：你读懂前人到哪了（01），设计实验产生证据（02），用统计判断证据强度（03），把整个过程管到可复现（04），最后诚实地写出来交给同行检验（05）。每一步都对应研究里一个真实、反复出现的决策点，也都对应一类最常见的翻车方式。

每个模块都配一个真实可跑的 numpy/pandas notebook——这门课偏方法论，但绝不只是讲道理。你会亲手：从一张论文结果表复现一个数字并核对（01）、跑一个带对照与消融的受控玩具实验（02）、用 bootstrap 算置信区间并做功效分析（03）、写一个轻量 config+sweep 并固定种子核验可复现（04）、从实验结果生成带误差棒的诚实图表数据并做 claim-evidence 核对（05）。方法论只有跑过、被 assert 验证过，才会变成你的本能而非口号。

4与全栈培训的关系：收口的元课程

本课与全栈培训的关系：收口的元课程

这门课在整套培训里的位置很特殊：它是收口课，也是元课程。前面每一门课（模型内部机制、后训练、评测、安全、智能体、系统、GPU 内核……）教的都是某个领域的知识；本课教的是如何把任何一个领域的研究做得可信——它的内容作用在其他所有课之上。

其他技术课教你本课教你（作用在它们之上）
某个模型/算法怎么工作怎么读懂提出它的论文、复现它的结果
怎么训练/微调一个模型怎么设计实验证明你的改动真的有用（而非混杂或运气）
怎么评测一个能力怎么用统计判断分数差异是真信号还是种子方差
怎么搭一个系统/写一个内核怎么把实验管到别人能重跑、把结果诚实写出来
领域的 SOTA 是什么怎么不被「刷榜」误导、怎么追求理解而非排行榜名次

所以学习建议是：本课可以现在通读建立框架，更应该在你学完任何一门技术课、真正开始做该领域的实验时回头重读。当你在 C03 评测课里跑出一个分数、在 C02 后训练课里调出一个提升、在 C36 内核课里测出一个加速——回到本课问自己：我有对照吗？我报方差了吗？我的基线够强吗？我这个结论可复现吗？本课的检查表，是你做任何技术研究时的安全带。

也正因为它作用在其他所有课之上，本课的回报是复利的：你在这里学到的每一条纪律，会在你今后做的每一个实验里反复兑现。学一个具体模型，回报是你会用那个模型；学会做研究，回报是你做的所有研究都更可信——这个差别，正是为什么再忙也值得把这门「元课程」认真学透。

一个要破除的误解：「方法论是等我成了资深研究员才需要的东西」。恰恰相反——方法论的坑在你做第一个实验时就开始坑你。新手与老手的实验差距，往往不在模型多复杂，而在老手有对照、报方差、不过度声明，新手只跑一次、晒最好结果、把相关当因果。越早把这套纪律变成肌肉记忆，越早能产出别人愿意相信、愿意在其上继续建造的工作。

环境与运行

环境极简：只需 numpy 与 pandas（画图可选 matplotlib）。全课 CPU 秒级运行，无需 GPU。所有 notebook 纯标准科学栈、自洽可跑，每个 worked、练习自测、答案 cell 都有 assert 兜底，且已实跑验证 0 失败。

每个模块配一个 notebook，结构统一（对标全套课程）：先用 numpy/pandas 把方法论操作从零做一遍并打印验证（5–6 个 worked 小节，每节都有可打印结果与 assert 自测），再做 3–4 道带 assert 判分的 ✏️ 练习（先给骨架自己填，再对照 📖 参考答案），最后一个真实数据胶囊（用真实论文报告的数字、真实统计场景，把纸面方法接到现实，含联网回退到内置真实数值）。

建议的学习节奏：先读完整章 HTML 把「为什么」想透，再打开 notebook 亲手做。方法论尤其如此——只读会觉得「道理我都懂」，真正动手跑「只跑一个种子 vs 跑十个种子」、亲眼看到结论翻盘时，那条原则才会刻进你的直觉。读和做缺一不可。

每个 notebook 的结尾都有一段小结，把该模块的核心纪律浓缩成几条；做完六个模块，这些小结串起来就是一份可随身携带的研究自查清单。建议你做完全课后，把六份小结抄成一页纸，贴在做实验的地方——它就是你今后每个项目的安全带。

配套先读：Keshav《How to Read a Paper》（3 页，今天就能读完）建立读论文框架；Wilson《Good Enough Practices in Scientific Computing》建立工程卫生底线；Lipton & Steinhardt《Troubling Trends》看清要规避的学术通病。完整清单见 references.md。

✅ 学完整门课，你应该能：
  1. 用三遍读法高效读一篇论文，把它拆成「主张-证据」对，并给每个结果的可信度打分；
  2. 设计一个带对照与消融的受控实验，识别并排除混杂变量，遵守「一次只变一个量」；
  3. 用 bootstrap 算置信区间、做功效分析估所需样本量、对多重比较做 Holm 校正、报告效应量；
  4. 判断一个性能差异是真信号还是随机种子方差，并知道该跑多少个种子；
  5. 把实验组织成显式 config + sweep，固定所有随机源做到可复现，用 pandas 聚合多次运行；
  6. 从实验结果生成带误差棒的诚实图表数据，做 claim-evidence 核对，写可复现声明，并审一份稿、写一份 rebuttal；
  7. 把以上变成做任何技术研究时的默认安全带——让你的工作从 demo 升级为可信的研究。
