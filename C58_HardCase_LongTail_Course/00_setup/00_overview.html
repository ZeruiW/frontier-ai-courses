1护城河：模型架构会趋同，数据飞轮不会

先把这门课的立场亮出来：在量产自动驾驶感知里，真正的护城河是数据闭环，不是模型架构。这不是一句励志口号，而是一个可以被论证、也可以被证伪的工程判断。

论证分三层。

  1. 架构可复制，数据不可复制。RT-DETR、RTMDet、YOLOv10 的论文与权重都是公开的。任何一个有 8 张卡的团队，一周内就能把 COCO 上的数字复现到论文的 ±0.5 mAP 以内。但没有任何一个团队能在一周内拿到「十万段中国高速隧道出口逆光下的限速牌」。前者是知识，知识会扩散；后者是资产，资产要靠车队里程一公里一公里地攒。
  2. 架构红利是一次性的，数据红利是复利的。把 backbone 从 ResNet-50 换成 CSPNeXt，涨 1.5 mAP，然后就到顶了——你不能再换一次同样的 backbone 再涨 1.5。而数据闭环是一个正反馈环：车越多 → 遇到的 badcase 越多 → 挖回来修好 → 模型越好 → 用户越敢用 → 里程越多 → 车越多。这个环每转一圈，下一圈的起点都更高。
  3. 长尾是无限的，架构穷举不了。被树叶遮住一半的「注意行人」、褪色到发白的限速牌、贴在货车尾门上的假标志、临时施工用手写板改过的限速——这些场景写不完，也没有哪个 attention 变体能凭空推理出它们。唯一的解法是「遇到 → 收回来 → 学会」，也就是闭环。
架构红利数据红利
来源论文 + 开源权重车队里程 + 闭环基础设施
可复制性几乎完全可复制（一周内）不可复制（要几年里程 + 一整套工具链）
收益形态一次性阶跃，很快到顶复利：每一轮闭环抬高下一轮的起点
对长尾的作用几乎为零（架构不产生新知识）唯一有效的手段
典型量级同一延迟档位内 1–3 mAP针对场景切片可以是 10–30 AP
失效方式被别人一周内追平被自己的流程拖垮（下一节讲）

直白说

所以「上更强的 backbone」在面试里是一个典型的初级回答。面试官问「如果给你更多资源你会做什么」，他真正想知道的是：你会不会做误差分析、会不会定位到具体场景、会不会为那个场景建触发器和评测切片。回答「先做分场景误差分析，找出拖后腿的切片，为它建一条触发-挖掘-标注-验证的闭环，并用切片指标证明它涨了而其他切片没掉」——这才是量产团队想要的人。

严谨说

但必须同时承认反面：有数据 ≠ 有闭环。很多团队存了 PB 级的路采视频，硬盘天天在烧钱，却没有触发器（不知道该回传什么）、没有检索（找不到「和这个 badcase 长得像的」）、没有切片评测（不知道改动有没有用）。这时数据不是资产，是负债。本课就是把「PB 级视频」变成「可持续提升的模型」中间那一整套东西拆开讲。

一句话心法：模型架构决定你的天花板有多高，数据闭环决定你多快能撞到天花板、以及天花板本身会不会往上长。在 COCO 上比架构，在路上比闭环。

2闭环三环节：触发 → 挖掘 → 验证

把「数据闭环」这个词拆开，它其实是三个可以分别失败、分别度量、分别优化的环节。这三个环节的划分是本课的骨架——后面五个模块正好一一对应。

┌──────────────── 车队（每天百万公里）────────────────┐ │ │ ▼ │ ① 触发 TRIGGER │ 「什么样的帧值得回传？」 │ · 不确定性（熵 / margin / 低置信） │ · 一致性（多模型分歧 / 多帧类别跳变 / TTA 分歧） │ · 规则（跟踪丢失 / 与高精地图不符 / 接管与急刹前后） │ 约束：**回传带宽有限** → 触发率必须可控（典型 1e-5 ~ 1e-4） │ │ 回传 10^4 ~ 10^6 帧/天 │ ▼ │ ② 挖掘 MINING │ 「从回传里挑出真正该标的那一小撮」 │ · 嵌入检索：找「和这个 badcase 长得像的」 │ · 场景打标：天气/光照/道路/标志类别/遮挡度（规则 + VLM） │ · 去重与多样性：近重复过滤、core-set、聚类均衡 │ · 预算分配：按「类别缺口 × 难度 × 标注成本」分钱 │ 约束：**标注预算有限** → 只有 10^3 ~ 10^4 帧能进标注 │ │ │ ▼ │ ③ 验证 VALIDATION │ 「怎么证明这批数据真的有用」 │ · 分场景切片评测（目标切片涨了吗？） │ · 回归门禁（其他切片掉了吗？掉多少算掉？） │ · 显著性（涨的是数据的功劳还是种子噪声？） │ · 边际收益曲线（还值不值得再标 1000 张？） │ │ 通过门禁 → 发布 → 上车 │ └──────────────────────────────────────────────────────┘ 闭环的核心度量：**cycle time** = 从「发现一个 badcase」到「修复版本上车」的天数。 一流团队 1–2 周；做不动的团队 3 个月，或者根本量不出来。
环节输入 → 输出本课模块最常见的断点
① 触发车端连续帧 → 少量候选帧m03（主动学习与触发策略）触发率没预算约束，一天回传几十 TB，管道直接堵死
② 挖掘候选帧 → 待标注清单m02（难例挖掘）· m04（挖掘基础设施）不去重：回传的 1000 张里 900 张是同一个路口的连续帧
③ 验证新模型 → 发布 / 打回m05（闭环验证）只看整体 mAP，不做切片；改动到底有没有用没人说得清
贯穿类别分布本身就是歪的m01（类别不平衡）把长尾当成「数据不够」，其实还有一半是「损失与分类器的问题」

直白说

三个环节里，最容易被跳过的是 ③ 验证，而它恰恰是唯一能防止你白干的环节。「标了 2 万张夜间数据，整体 mAP +0.2」——这句话什么也没说明：+0.2 可能在种子方差以内（检测任务同配置换种子的典型波动就是 ±0.2~0.5），也可能是「夜间 +3、白天 -2」被平均掉了。没有切片评测的闭环，是一个把钱变成硬盘占用的机器。

严谨说

而最贵的是 ② 挖掘：标注是唯一一个成本随数据量线性增长且不可摊薄的环节（触发和验证都是写一次代码用无数次，标注是每一张都要花钱）。所以挖掘环节的全部工程努力，本质上都在做一件事：提高「每一块标注预算换到的模型提升」。去重、多样性采样、按类别缺口分配预算、用嵌入检索精确定位同类 badcase——它们的收益都应该折算成「每千元标注费带来的目标切片 AP」来衡量。

一个反复出现的组织性失败：三个环节分属三个团队，而闭环的度量（cycle time）不属于任何一个团队。感知团队负责模型，数据团队负责标注，工具团队负责管道，每个团队的 KPI 都达标，但从「发现问题」到「修好上车」要三个月。面试里如果你能主动提出「我会先把 cycle time 量出来」，这是一个很强的系统性思维信号。

3为什么「加数据」常常无效：四种失效

「效果不好？加数据。」这是所有回答里最安全也最没用的一句。加数据在实践中失败的频率高得惊人，而且失败的方式高度可归类。把这四类背下来，你就能在面试里把「长尾怎么办 / recall 怎么提」这类问题答到别人答不到的深度。

失效机制症状（怎么看出来）检查方法
① 加的是已经会的随机采样的帧里 95%+ 是模型 loss ≈ 0 的样本，反传梯度接近零，它们不携带任何新信息训练 loss 曲线几乎不变；指标在噪声内波动；新增 10 万张与新增 0 张没区别算新数据的「有效样本数」：用当前模型跑一遍，看 loss 分布；sum(loss)/参考难样本loss 才是真正的增量
② 加的分布不对问题出在隧道出口逆光，加的是城市晴天；新数据落在已经饱和的切片上整体 mAP 微涨 0.1–0.3，目标切片纹丝不动加数据之前先做分场景误差分析；新数据也要按同一套切片打标，看它落在哪个桶
③ 加的标注有噪众包标注对小目标漏标严重；漏标的 GT 变成负样本监督——模型被明确告知「这里没有标志」recall 反而下降；训练 loss 反而升高；小尺寸桶掉得最狠抽检 200 张算标注一致性（IoU + 类别 agreement）；用当前模型的高分假正例反查漏标
④ 加完没验证只看整体指标；不同切片的涨跌互相抵消；提升量在种子方差以内「涨了 0.2」但没人能说清是哪涨了；下一次改动又「涨了 0.2」，累计起来却没涨切片评测 + 多种子 + 配对检验；旧切片不掉点设为硬门禁

四类里，③ 最危险，因为它的方向是反的：其他三类最多是白花钱，③ 是花钱把模型变差。

漏标 = 负监督，不是缺失

漏标的危害是不对称的。在检测里，一个没被标注的真实目标不只是「少了一个正样本」——它所在的位置会被标签分配判定为背景，从而产生一条明确的负梯度：「这个位置没有交通标志」。模型学到的不是「不确定」，而是「确定没有」。

在 TSR 里这一点尤其致命：最容易漏标的恰恰是最远、最小、最需要提前检出的那一批标志（20×20 像素以下，标注员在 1080p 图上要放大才看得见）。于是漏标噪声与「远距离早检出」这个核心指标精确地打在同一个位置上。「加了 5 万张远距离数据，60 米外的召回反而掉了 3 个点」——这是真实会发生的事，原因就在这里。

直白说

把四类失效倒过来读，就是加数据之前必须回答的四个问题：这批数据模型现在会不会（不会才值得加）？它落在哪个切片（必须是目标切片）？标注质量抽检过没有（尤其小目标）？我打算用什么切片、什么显著性标准来判定它有用（加之前就要定好）？

严谨说

更进一步，这四个问题定义了「一份数据的价值」这个量的可测形式：价值 = 增量信息（不是已经会的）× 分布对齐（落在目标切片）× 标注保真度（不是噪声）× 可验证性（能被切片指标检出）。四项任何一项为零，整批数据的价值就是零——它们是乘法关系，不是加法关系。这也解释了为什么「多加点数据总没坏处」这个直觉是错的：③ 那一项可以是负数。

4长尾的幂律本质与边际收益递减

现在给上面的判断一个定量的底座。交通标志的类别分布不是「有点不均衡」，它是幂律（power law）——按频次排序后，第 r 名类别的实例数近似满足：

\[n_r \;=\; n_1 \cdot r^{-\alpha}, \qquad \alpha \in [1.5,\,2.5] \ \ \text{(典型交通标志数据集)}\]

取对数后是一条直线：log n_r = log n_1 − α log r。这条直线是可以在你自己的数据集上画出来的，而且它非常稳——换城市、换年份，斜率变化很小。它带来三个必须内化的结论。

结论内容工程后果
① 尾部的类别数占多数，实例数占极少α≈1.9、80 类时，排名 40 之后的 41 个类（占类别数 51%）只占实例总数的 约 3%按实例采样时，一个 epoch 里尾部类几乎不出现；macro 指标（每类平均）与 micro 指标（每实例平均）会给出完全相反的结论
② 头部早已饱和头部类有 10 万实例，AP 已经 0.90+；再加 3 万张对它的边际收益接近 0随机加数据 = 把绝大部分预算花在饱和区；这是失效 ① 与 ② 的数学根源
③ 长尾没有尽头幂律没有截断：你解决了排名 60 的类，排名 61 会顶上来目标不是「消灭长尾」，而是把「发现→修复」的 cycle time 压到足够短

再看单个切片的边际收益。经验上，某个场景切片的 AP 随该切片训练样本数 n 的增长近似满足一条饱和幂律：

\[\mathrm{AP}(n) \;=\; \frac{A_{\max}}{1 + (k/n)^{\beta}}, \qquad \frac{d\,\mathrm{AP}}{dn} \propto n^{-(\beta+1)}\]

k 是「半饱和样本数」（AP 达到一半上限时的样本量），β 是陡峭度。关键在导数：边际收益按 n^{-(β+1)} 衰减。取 β=0.6，把一个切片从 25 张加到 5000 张，AP 从 0.21 涨到 0.80；而把另一个切片从 5 万张加到 5.3 万张，AP 只涨 0.001。两张标注的边际价值可以差三个数量级。

直白说

所以「数据越多越好」是错的，正确的说法是「每一张数据的边际收益差了几个数量级，你要做的是把预算搬到陡峭段」。10 张精准定位的隧道出口逆光数据，可能比 10000 张随机路采更有用——这不是修辞，notebook 里会把这个倍数算出来（在合成设定下定向加数据的宏观收益是随机加数据的 15–20 倍）。

严谨说

这条曲线还有一个更实用的用法：它是「还值不值得再标 1000 张」的决策工具。在目标切片上标 200 / 500 / 1000 张各训一次，拟合 A_max、k、β，就能外推「再标 2000 张能涨多少」，再与标注成本比较。这是把「数据决策」从拍脑袋变成算账的唯一办法，也是 m05 的核心内容。反过来，如果拟合出来的 A_max 只有 0.55，那说明瓶颈根本不是数据量（可能是分辨率、是标注定义、是任务本身在该切片上不可解），继续标下去是浪费。

把幂律与边际收益合起来看，长尾问题的真正结构是：类别频率是幂律的，而每类的边际收益是它自身样本数的减函数——两者叠加，导致「按自然分布采样」几乎必然把预算花在最没用的地方。本课后面所有技术（重采样、重加权、触发器、嵌入检索、core-set、预算分配）都是在对抗这一句话。

  • C57（小目标检测）——与长尾高度纠缠。稀有类往往同时也是小目标（稀有 → 采集机会少 → 只在远处拍到过几次），两个问题叠加，误差分析时必须双向分桶才能看清。
  • C40（研究方法论）/ C52（工业研究实务）——m05 的显著性检验、多重比较校正、实验记录规范在那两门课里有更完整的统计基础。

本课的贯穿式练习是：把每一个模块的产物都写成一个「可以塞进流水线的函数」——触发器是 should_upload(frame) -> bool，挖掘器是 rank(candidates) -> list，门禁是 gate(before, after) -> verdict。到 m05 结束时，你会把这些函数拼成一个完整闭环的状态机。能在面试里画出这个状态机并说清每一步的门禁条件，就已经超过绝大多数候选人了。

7研究前沿与开放问题

这门课讲的是一套已经在量产系统里跑通的工程方法学，但它的每一环都还有真正的开放问题。

  • 数据价值的事前可预测性。目前判断一批数据有没有用，唯一可靠的办法是「标了、训了、测了」——一个完整的 cycle。能不能在标注之前就估出一张图的边际价值？influence function、data Shapley、TracIn 这条线在小模型小数据上可行，但在检测这种「一张图含多个实例、损失是结构化的」的任务上，扩展性与稳定性都还没解决。这是本领域最值钱的开放问题。
  • 触发器的选择偏差。不确定性触发只能回传「模型知道自己不确定」的样本，而最危险的失效恰恰是「模型自信地错了」（高分假正例：把广告牌当限速牌）。这类样本在不确定性度量上看起来完全正常。多模型分歧与多帧一致性能覆盖一部分，但系统性的解法尚不存在。
  • 合成数据能替代多少真实长尾。扩散模型生成稀有类样本、copy-paste 合成、仿真渲染——三条路都能提升尾部指标，但都存在域差，且「合成数据涨的点在真实路测上兑现多少」缺少可信的度量。目前的共识是合成能救「实例数不足」，救不了「场景多样性不足」。
  • 闭环的评测污染。挖掘出来的难例既进了训练集也可能进了测试集；触发器本身依赖当前模型，于是评测集会逐渐向「当前模型的弱点」倾斜。几轮闭环之后，你的验证集还能代表真实路况分布吗？这个问题在工业界普遍存在但很少被公开讨论。
  • 长尾方法与大规模预训练的交互。有证据表明，足够强的预训练表示会让很多长尾专用方法的增益大幅缩水（因为尾部类的表示本来就够好了，问题只在分类器）。如果这个结论成立，那么长尾研究的重心应当从「怎么学表示」彻底移到「怎么校准分类器与先验」——这正是 m01 里 logit adjustment 与解耦训练那条线的理论意义。
  • 开放词表检测（open-vocabulary detection）把长尾推向极端：稀有类干脆不在训练集里，用 CLIP/VLM 的文本嵌入做零样本识别。对 TSR 这种「类别体系随法规变化、新标志会不断出现」的任务，它的吸引力显而易见，但当前的零样本精度距离量产安全要求还有明显差距。

本模块必读（长尾与数据闭环的地基，★ 为优先）：★ LVIS: A Dataset for Large Vocabulary Instance Segmentation（Gupta et al., CVPR 2019）——repeat factor sampling 的原始出处，也是长尾检测评测的事实标准；★ Deep Long-Tailed Learning: A Survey（Zhang et al., TPAMI 2023）——方法谱系的最好地图，m01 的骨架来自它；★ Deep Learning Scaling is Predictable, Empirically（Hestness et al., 2017）与 Revisiting Unreasonable Effectiveness of Data in Deep Learning Era（Sun et al., ICCV 2017）——数据量-精度幂律的两篇奠基工作，本节边际收益公式的来源；Pervasive Label Errors in Test Sets Destabilize ML Benchmarks（Northcutt et al., NeurIPS 2021）——标注噪声危害的量化，对应失效 ③；Active Learning Literature Survey（Settles, 2009）——触发策略的经典总结，m03 的前置；Active Learning for Convolutional Neural Networks: A Core-Set Approach（Sener & Savarese, ICLR 2018）——多样性采样，m04 的前置。相邻课程：C55（TSR 感知）、C56（数据增强）、C57（小目标）、C43（数据工程）。完整清单见 references.md。
