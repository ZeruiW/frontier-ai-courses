# 术语词典 · Glossary（难例挖掘与长尾数据闭环）

> 按主题分组：**不平衡与长尾 / 难例挖掘 / 主动学习与触发 / 挖掘基础设施 / 闭环验证**。
> 每条给「英文 / 中文 / 一句话定义 / 为什么重要 / 常见误解」五项。
> 「常见误解」那一列是本词典最值得读的部分——它们大多是线上事故、白烧的标注预算，
> 或者面试当场翻车的来源。英文术语一律保留原文。

## 一 · 不平衡与长尾 · Imbalance & Long-Tail

| 术语 (EN) | 中文 | 一句话定义 | 为什么重要 | 常见误解 |
|---|---|---|---|---|
| long-tail distribution | 长尾分布 | 少数类别占据绝大多数样本，大量类别各自只有极少样本；按频次排序后曲线有一条又长又薄的尾巴。 | 真实世界的数据几乎总是长尾的——TSR 里限速牌几万个，某个地方性警告牌可能全库只有十几个。**它是本课全部问题的起点。** | 以为长尾是「数据没收够」——再收十倍数据，分布形状基本不变，尾部类的绝对数量涨了但**相对占比不变**，长尾是稳态而不是过渡态。 |
| power law / Zipf's law | 幂律 / 齐夫定律 | 频次与排名满足 f(r) ∝ r^(−α)。自然类别体系里 α 常在 0.8–1.2。 | 它让长尾**可外推**：拟合出 α 就能估计「再采集 N 小时，尾部类各能拿到几个样本」。α ≈ 1 时前 20% 的类吃掉约 72% 的样本。 | 以为幂律只是描述性的——它有工程后果：**尾部类靠随机采样在数学上就是采不到的**，期望等待时间与频次成反比，这直接否定了「多跑几天就有了」。 |
| head / medium / tail split | 头/中/尾划分 | 按每类样本数分档（LVIS 口径：frequent > 100 张、common 10–100、rare < 10）。 | 所有长尾指标都必须**分档报告**（AP_r / AP_c / AP_f），否则头部类的表现会淹没一切。 | 以为分档阈值是通用的——阈值必须按你自己数据的分布定；照抄 LVIS 的 10/100 在一个总量小十倍的数据集上毫无意义。 |
| foreground-background imbalance | 前景-背景不平衡 | 单张图里正样本（前景 anchor/query）与负样本的数量比，典型是 1:1000 到 1:10000。 | 这是**检测独有**的不平衡，与类别长尾是两个问题：它发生在一张图内部，靠 Focal Loss / OHEM / 采样比例控制解决。 | **以为它和类别长尾能用同一套方法治**——重采样图片解决不了「一张图里负样本占 99.9%」，Focal Loss 也解决不了「这个类全库只有 8 个实例」。混着治是「加了一堆技巧但尾部纹丝不动」的头号原因。 |
| class-balanced sampling | 类别均衡采样 | 采样时让每个类别被抽中的概率相等（而不是正比于样本数）。 | 最直接的重采样方案，在分类任务上很有效。 | **在检测里几乎不能直接用**——一张图里有多个类别的多个实例，「按类采样」在图像级没有良定义；强行按主类采会让共现类别的分布被扭曲。 |
| repeat factor sampling (RFS) | 重复因子采样 | LVIS 的做法：类别重复因子 r_c = max(1, √(t/f_c))，f_c 是含该类的图像占比、t 是阈值（常取 0.001）；图像的重复因子取其所含类别 r_c 的最大值。 | **检测长尾的默认基线**，因为它优雅地解决了「一图多类」：在图像级做重复，不破坏图内共现结构。t = 0.001、f_c = 1e-4 时该类被重复 3.16 倍。 | 以为平方根是随便加的——**平方根就是刹车**：按 1/f_c 补偿会让 f_c = 1e-4 的类被重复一万倍，几十张图被看几千遍，必然过拟合。√ 把补偿从「完全均衡」退到「部分均衡」，是效果与过拟合之间的经验折中。 |
| instance-level vs image-level resampling | 实例级 vs 图像级重采样 | 前者调整每个目标实例被采到的概率，后者调整整张图被采到的概率。 | 检测只能做图像级（你没法只把图里的一个框喂进网络），所以「重采一张稀有类的图」会顺带把图里的头部类也重采一遍。 | 以为重采样只影响目标类——它会**同时放大共现的头部类**，在极端重复因子下反而加剧不平衡；这也是 RFS 要限制上限的原因之一。 |
| over-sampling overfitting | 过采样过拟合 | 对尾部类反复重复同一批少量样本，模型记住的是这几张图而不是这个类。 | 它是所有重采样方法的天花板：**重复采样不增加信息量**。尾部类验证集上「训练 loss 极低但召回不涨」就是它的指纹。 | 以为「重复采样 = 更多数据」——重复 100 次和 1 次的**信息量完全相同**，只是梯度权重变了。要真正解信息不足只有两条路：挖真数据（本课）或造数据（C56 的 copy-paste）。 |
| effective number of samples | 有效样本数 | E_n = (1 − β^n) / (1 − β)，把 n 个样本折算成「等效的独立样本数」，β ∈ [0,1) 控制样本间的重叠假设。 | Class-Balanced Loss 的核心：**样本之间是有信息重叠的**，第 10000 张限速牌带来的新信息远小于第 10 张，所以权重不该按 1/n 而该按 1/E_n。 | 以为 β 是随便调的——β 隐含「每类的有效数据体积」假设：β → 0 退化成不加权，β → 1 退化成按 1/n 反频加权。β = 0.999 时 n = 1000 与 n = 10000 的权重只差 **1.58** 倍，而 1/n 会差 10 倍。 |
| Class-Balanced Loss | 类别均衡损失 | 给每个类的损失乘以 (1 − β) / (1 − β^{n_c})，可套在 CE / Focal / sigmoid 上。 | 提供了一个有理论动机的重加权方案，比拍脑袋的 1/n 或 1/√n 更稳，且**不改采样流程**（不重复读图，训练吞吐不变）。 | 以为它能替代重采样——重加权改的是梯度大小，重采样改的是模型**见到样本的次数**（进而影响 BN 统计量与数据增强的多样性）；两者常常叠加使用。 |
| Focal Loss | 焦点损失 | FL = −α_t (1 − p_t)^γ log p_t，用 (1 − p_t)^γ 把已经学会的易样本的梯度压下去。 | 单阶段检测处理**前景-背景不平衡**的标准答案；也是理解「软性难例挖掘」的入口。 | **以为 Focal Loss 能治类别长尾**——它按「样本难易」加权，与「类别频次」无关。一个头部类的困难样本照样拿高权重，一个尾部类的容易样本照样被压制。它治的是另一种不平衡。 |
| LDAM | 标签分布感知 margin 损失 | 给每类分配与频次相关的分类 margin：Δ_j ∝ n_j^(−1/4)，样本越少 margin 越大。 | 从**泛化边界**出发而非启发式加权：尾部类样本少、经验风险估计方差大，所以需要更大的间隔来换取更好的泛化。配合 DRW（延迟重加权）效果更好。 | 以为 n^(−1/4) 是调出来的——它来自泛化误差界的推导（在总 margin 预算固定下最优分配）。另一个误解是以为 LDAM 可以直接搬到检测：检测的分类分支是逐 anchor 的二分类/多标签，margin 的定义需要重新设计。 |
| EQL | 均衡损失 | Equalization Loss：在计算 sigmoid 多标签分类损失时，**屏蔽掉频繁类样本对稀有类分类器产生的负梯度**。 | 抓住了检测长尾的一个独有机制：稀有类的分类器在每一步都被成千上万个「不是我」的负样本推向零，**它被负梯度淹死，而不是被正样本饿死**。 | 以为 EQL 是又一个重加权——它动的是**梯度的来源结构**（哪些负样本该参与），不是权重大小。也别以为屏蔽越多越好：屏蔽过度会让稀有类的假正例暴涨。 |
| EQLv2 | 梯度均衡损失 | 用一个在线统计的**正负梯度比**作为每个类的反馈信号，动态调整该类正/负梯度的权重，把梯度比拉回 1 附近。 | 把 EQL 的「按频次硬阈值屏蔽」换成**闭环控制**，不需要预先划分 rare/frequent，对新类别与分布漂移更鲁棒。 | 以为它需要类别频次表——EQLv2 的一大卖点就是**不需要先验频次统计**，它从训练过程中实测的梯度比自适应；这在类别表会变的量产系统里很关键。 |
| Seesaw Loss | 跷跷板损失 | 用「缓解因子」按类间累计样本比降低尾部类受到的负梯度，再用「补偿因子」按误分类率把该加的惩罚加回来。 | 是 EQL 系的改进：既压住淹没稀有类的负梯度，又不放任稀有类乱报（后者是 EQL 的副作用）。 | 以为两个因子作用相同——缓解因子解决「学不到」，补偿因子解决「学过头乱报」，去掉任何一个都会失衡。 |
| logit adjustment | 对数几率调整 | 推理时把 logit 减去 τ·log π_y（π_y 是类先验），或训练时把它加进 logit。 | **零训练成本、可随时回滚、有贝叶斯最优性保证**——它本质是把训练时的先验偏置在推理时除掉。工程上是长尾方法里性价比最高的一招，也是决策树的第一问「你能不能改推理」的答案。 | 以为它只是「调阈值」的花哨说法——按类调阈值是启发式，logit adjustment 有明确的理论目标（最小化平衡误差率）且 τ 只有一个超参。另一个误解是以为 τ = 1 一定最好——τ 要在验证集上调，τ 过大会把头部类的召回压垮。 |
| decoupled training (cRT / LWS) | 解耦训练 | 两阶段：第一阶段用**原始长尾分布**学表示（instance-balanced sampling），第二阶段冻结表示、只用平衡数据重训（cRT）或只重缩放（LWS）分类器。 | 这条结论极其实用：**长尾主要伤的是分类器，不是表示。** 所以你不需要重训整个模型，只需要用少量平衡数据重训最后一层——训练成本和风险都低一个数量级。 | 以为「用平衡采样从头训」更好——实验反复表明它**更差**：平衡采样会损害表示学习（尾部类被重复过多、头部类的丰富样本被浪费）。正确顺序是「表示用原分布、分类器用平衡分布」。 |
| two-stage architecture as remedy | 两级架构缓解长尾 | 先做类别无关/粗类检测，再把 crop 送进独立的细粒度分类器。 | **TSR 里最实用的一招**：分类器的数据可以单独按类均衡组织，新增标志类别不必重训检测器，且能用更高分辨率的 crop。 | 以为它消除了长尾——长尾只是被移到了第二级分类器里；好处是那里更容易治（可以自由重采样、可以用分类领域的全套长尾方法），代价是**级联召回相乘**。 |
| label shift / prior shift | 标签偏移 | 训练与部署时类别先验 P(y) 不同，但 P(x/y) 不变。 | 长尾方法（尤其 logit adjustment）本质就是在校正标签偏移；部署到不同城市/国家时，标志类别先验会真实地变。 | 以为部署分布等于训练分布——TSR 里换个省份，某些标志的频次能差一个数量级，**在 A 地调好的阈值到 B 地就偏了**。 |
| calibration under imbalance | 不平衡下的置信度校准 | 长尾训练后的模型对头部类过度自信、对尾部类欠自信，输出的概率不可直接当置信度用。 | 下游（跟踪、融合、VLA）都要消费置信度；**没校准的置信度会让触发器和门禁一起失灵**。 | 以为 softmax 输出就是概率——它是未校准的分数；重加权与重采样会**进一步破坏**校准，所以用了长尾方法之后必须重新做温度缩放或分类校准。 |

## 二 · 难例挖掘 · Hard Example Mining

| 术语 (EN) | 中文 | 一句话定义 | 为什么重要 | 常见误解 |
|---|---|---|---|---|
| hard example mining | 难例挖掘 | 有选择地把「模型当前学不好的样本」更多地送进训练，而不是均匀对待所有样本。 | 大部分样本对梯度的贡献接近零（模型早就学会了），把算力花在它们身上是浪费；这是从 DPM 的 bootstrapping 一路传下来的思想。 | 以为难例挖掘总是有益——它同时放大了**标注噪声**与**分布外异常**的权重。在噪声率 5% 以上的数据上，激进的挖掘常常直接让指标掉。 |
| OHEM | 在线难例挖掘 | 前向计算所有 RoI 的 loss，按 loss 降序取 top-k（或按固定正负比）只对这部分反传。 | 免去了「负样本比例」这个超参，且随训练进程自动跟踪当前最难的样本；是两阶段检测器上的经典做法。 | **以为直接排序就行——必须先做 NMS 去重。** 一个难区域会产生几十个高度重叠的 RoI，它们的 loss 都很高，不去重就会把整个 batch 的名额吃光，等于每步只学了一个位置。这是原论文里最容易被忽略却最致命的实现细节。 |
| hard negative | 难负样本 | 被模型给了**高分**的负样本，即「模型自信地错了」的那些。 | 它们才是 precision 的真正来源；TSR 里典型的难负样本是广告牌、车身贴纸、后车圆形尾灯、路侧圆形反光镜。 | **以为「难负样本 = 分数低的负样本」——正好相反。** 分低的负样本是「易负样本」，模型已经学会了，它们对梯度几乎没贡献。 |
| easy negative dominance | 易负样本主导 | 数量巨大的易负样本即使单个梯度很小，加总后仍主导整个梯度方向。 | 这是 Focal Loss 与 OHEM 共同要解决的问题；也解释了为什么「不做任何处理的单阶段检测器会把一切预测成背景」。 | 以为提高学习率能救——梯度方向本身是错的，放大它只会更快地收敛到「全部背景」这个平凡解。 |
| Focal Loss ≈ soft OHEM | 焦点损失是软性 OHEM | OHEM 用 0/1 硬截断丢弃易样本；Focal Loss 用连续权重 (1 − p_t)^γ 平滑地压低它们。 | **高频面试题。** 标准答案要点：两者目标相同（把梯度预算给难样本），OHEM 省计算但丢信息、有截断超参 k；Focal 全样本参与、可微、只有 γ/α 两个超参，但不省计算。 | 以为二者可以随便叠加——同时用会**双重压制**易样本，实测常常让模型欠拟合背景（假正例上升）。要叠加就得同时调低 γ。 |
| mining ratio / batch quota | 挖掘比例 | 每个 batch 中难例（或正负样本）占的固定配额，如 1:3。 | 配额是最简单也最稳的控制手段；它给「挖掘过头」设了一个硬上界。 | 以为比例越激进越好——挖掘比例是**噪声放大系数**：噪声标签几乎必然落在高 loss 区，配额越大它们的占比越高。 |
| GHM | 梯度调和机制 | 按**梯度模长的密度**加权：梯度密度高的区域（既包括海量易样本，也包括异常离群的极难样本）都降权。 | 它比 Focal Loss 多做了一件关键的事：**把「极难到不正常」的样本也压下去**，而这些往往就是噪声标签。 | 以为 GHM 只是 Focal 的变体——两者对「最难的那一小撮」处理相反：Focal 给它们最大权重，GHM 认为它们是离群噪声而降权。**这个差别正是「难例还是噪声」这个判断的两种立场。** |
| PISA / prime sample | 主样本注意 | 认为不是所有正样本同等重要——对最终 mAP 有贡献的是每个 GT 的最高分预测，据此对样本重排序加权。 | 提醒你：**训练目标（每个样本的 loss）与评测目标（AP）并不一致**，难例挖掘按 loss 排序其实是个代理指标。 | 以为 loss 高就等于对指标重要——一个永远排不进 top 的低分难例，即使学好了也可能不影响 AP。 |
| curriculum learning | 课程学习 | 先易后难地安排训练样本顺序。 | 与难例挖掘方向相反但可以互补：训练早期喂难例会让模型学到噪声方向，**先建立基本能力再挖难例**通常更稳。 | 以为课程学习和难例挖掘矛盾——实践中的常见配方是「前期均匀采样，中后期开启挖掘」，两者是时间上的分工。 |
| self-paced learning | 自步学习 | 让模型自己按当前 loss 决定哪些样本「够简单可以学」，随训练逐步放宽阈值。 | 提供了一个自动化的课程；也是「小损失准则」这类噪声鲁棒方法的理论背景。 | 以为它能自动避开噪声——它只是把噪声推迟到后期学，**在训练足够久之后模型依然会记住噪声标签**。 |
| label noise | 标签噪声 | 标注本身是错的：类别标错、框位置不准、漏标、多标。 | **本课最重要的警告的主角。** 噪声标签的 loss 天然很高，任何按 loss 排序的挖掘都会把它们排到最前面。 | 以为噪声率很低可以忽略——检测任务的实际漏标率常在 3–10%（小目标场景更高）；而挖掘会把这几个百分点**放大成 batch 里的几十个百分点**。 |
| memorization effect | 记忆效应 | 深度网络倾向于**先学会规律样本，后记住噪声样本**；噪声样本的 loss 下降发生得更晚、更突然。 | 它给出了区分「难例」与「噪声」的可操作信号：**看 loss 随 epoch 的轨迹形状，而不是某一时刻的值。** | 以为可以靠单点 loss 阈值区分——单看某个 epoch，真难例和噪声的 loss 完全重叠，**必须看轨迹**。 |
| loss trajectory | 损失轨迹 | 同一样本的 loss 在整个训练过程中的曲线。 | 真难例：缓慢单调下降；噪声标签：长期高位后突然塌陷（被记住）；分布外异常：始终高位。**三种形状对应三种处理方式。** | 以为记录轨迹成本很高——每个样本每 epoch 存一个 float，百万样本 100 epoch 也就几百 MB，是性价比极高的一份诊断数据。 |
| AUM (area under the margin) | margin 曲线下面积 | 训练过程中「标注类 logit 减去最大其他类 logit」的平均值。 | 一个只需一次训练就能算出的噪声检测量：**误标样本的 AUM 显著低**，可用插入的「阈值样本」自动定分界线。 | 以为它只适用于分类——检测里对每个 GT 的匹配预测同样能算 AUM，只是要先固定匹配关系。 |
| confident learning | 置信学习 | 用模型的（交叉验证）预测概率估计「标注类 ↔ 真实类」的联合分布，据此定位可能的错标样本。 | 给「找出错标」提供了有理论保证、与模型无关的流程（cleanlab 的内核），比人工抽检高效得多。 | 以为它需要干净的验证集——它的卖点正是**不需要**；但它要求概率**校准良好**，而长尾训练出的模型往往不校准，用之前必须先校准。 |
| co-teaching / small-loss criterion | 协同教学 / 小损失准则 | 训练两个网络，每个只把「自己认为 loss 小」的样本喂给对方更新。 | 利用两个模型不会在同一批噪声上同时犯错，来过滤噪声；是噪声标签学习的经典基线。 | 以为它与难例挖掘可以同时开——**它们的方向完全相反**（一个只留小 loss、一个只留大 loss）。同时开等于什么都没做。 |
| hard example vs noisy label | 难例与噪声的区分 | 三把尺：① 多模型/多种子的**预测一致性**（真难例大家一致地错得像，噪声则各不相同）；② **损失轨迹**形状；③ **重标注抽检**（唯一的地面真值）。 | **这是本课最可迁移的一项技能。** 一个挖掘系统如果没有这一步，它的长期效果一定是负的。 | 以为可以完全自动化——前两把尺只能给出**候选清单**，最终必须有人工抽检来估计噪声率并校准阈值。工程上正确的做法是「自动筛出 top 1%，人工看 200 张，估出噪声率，再决定挖掘力度」。 |
| false positive mining | 误检挖掘 | 专门收集模型的高分假正例（尤其是背景误检），作为负样本补进训练集。 | TSR 里 precision 的提升几乎全靠它：广告牌、车身贴纸这些误检源在通用数据集里根本没有对应的负样本。 | 以为把误检图整张加进去就行——必须**明确标注为「这里没有标志」**（即完整标注该图），否则模型会把它当漏标处理，效果适得其反。 |
| hard positive | 难正样本 | 被模型给了低分的真实目标：严重遮挡、极小、逆光、褪色、非常规角度。 | 它们是 recall 的来源，且往往正是安全上最关键的那些（远处的、被遮挡的限速牌）。 | 以为难正样本越多越好——难正样本与漏标/错标在数据里长得一模一样（都是「有 GT 但模型不认」），必须先过噪声筛。 |

## 三 · 主动学习与触发 · Active Learning & Triggers

| 术语 (EN) | 中文 | 一句话定义 | 为什么重要 | 常见误解 |
|---|---|---|---|---|
| active learning | 主动学习 | 让模型自己挑选「最值得标注」的样本，用尽可能少的标注量达到尽可能高的性能。 | 车队数据无限、标注预算有限——**问题从「挖什么」变成「回传什么」**，这就是主动学习的标准设定。 | 以为主动学习一定优于随机采样——文献里它在**高噪声、强类别不平衡、批量选择**这三种情况下都可能输给随机，而这三条 TSR 全占。所以任何主动学习策略都必须**与随机基线对比**才算数。 |
| pool-based sampling | 池式采样 | 有一个巨大的未标注池，每轮从中选一批送去标注。 | 这就是车队数据闭环的形式化：池 = 影子模式回传的所有帧。 | 以为池可以全量打分——千万级帧上跑一遍完整模型是昂贵的；实践中要先用便宜的规则/元数据把池砍到 1% 再打分。 |
| uncertainty sampling | 不确定性采样 | 选模型最「拿不准」的样本，用熵、margin 或最小置信度度量。 | 最简单、最常用、通常也是最强的基线之一。 | 以为不确定性高就等于有价值——**不确定性高的样本可能只是模糊到人也标不了**（10 像素的糊牌）。有价值的定义是「标了之后模型会变好」，两者不等价。 |
| predictive entropy | 预测熵 | H[p] = −Σ p_c log p_c，衡量预测分布的整体不确定性。 | 度量简单、无需多次前向。 | **以为熵高就是模型不会**——熵里混着两部分：模型不会（认知）与数据本身就模糊（偶然）。**标注只能消除前者**，对后者标一万张也没用。 |
| margin sampling | 间隔采样 | 用 top1 与 top2 的概率差衡量，差越小越不确定。 | 在细粒度混淆上比熵更敏感——TSR 里「限速 60 vs 80」正是典型的 top1/top2 相近。 | 以为它总是不如熵——在类别数很多时熵会被大量低概率类稀释，margin 更聚焦于**真正在竞争的那两类**，反而更好用。 |
| least confidence | 最小置信度 | 用 1 − max_c p_c 衡量。 | 最容易实现，与线上阈值天然对齐。 | 以为它等价于熵——只看最高分，完全忽略剩余分布的形状；在「一个类 0.5、另一个 0.5」和「一个类 0.5、其余 50 类各 0.01」之间无法区分。 |
| epistemic vs aleatoric uncertainty | 认知 vs 偶然不确定性 | 前者源于「模型没见过这种数据」（可通过标注消除），后者源于「数据本身有歧义」（标注也消除不了）。 | **主动学习的第一性原理**：预算应该只花在认知不确定性上。 | 以为可以从单个模型的 softmax 里区分——单模型的输出把两者混在一起，必须靠**多模型/多次采样的分歧**才能分开。 |
| BALD | 贝叶斯主动学习的分歧准则 | 取参数后验与预测之间的互信息：I = H[E_θ p(y/x,θ)] − E_θ H[p(y/x,θ)]，即「平均预测的熵」减去「各模型熵的平均」。 | **它精确地把偶然不确定性减掉了**：如果所有模型都说「五五开」，两项相等、BALD = 0；只有各模型**互相矛盾**时 BALD 才高。这正是「标了会有收益」的信号。 | 以为 BALD 需要贝叶斯神经网络——用 MC dropout、深度集成、甚至不同 epoch 的 checkpoint 都能近似 θ 的后验样本。另一个误解是以为它能直接批量选：**BatchBALD 才处理批内冗余**，朴素 BALD 会选出一批互相极其相似的样本。 |
| MC dropout | 蒙特卡洛 dropout | 推理时保持 dropout 打开，多次前向得到一组预测，近似后验采样。 | 最便宜的不确定性估计手段，不改训练流程。 | 以为它等价于深度集成——MC dropout 的多样性来自同一组权重的局部扰动，**系统性错误在所有采样里都存在**，因此常低估认知不确定性。 |
| query-by-committee / ensemble disagreement | 委员会查询 / 集成分歧 | 训练多个模型，选它们分歧最大的样本。 | 分歧是最可靠的认知不确定性信号；工程上也最容易实现（不同种子/不同增强/不同架构各一个）。 | 以为委员会成员必须是不同架构——不同随机种子的同架构模型已经能提供有效分歧；但**如果它们共享同一份错标数据，就会一致地错**，此时分歧信号失效。 |
| box-level → image-level aggregation | 框级到图级聚合 | 检测的不确定性是逐框的，但回传的单位是帧，必须聚合（max / mean / sum / top-k 平均）。 | **这是检测主动学习里最被低估的设计决策**：用 sum 会偏向目标多的图，用 mean 会被大量易检目标稀释，用 max 会被单个噪声框主导。 | 以为聚合方式是实现细节——它直接决定了触发器的系统性偏好。TSR 是**稀疏场景**（一帧常常只有 0–2 块牌），用 mean 会让「一块难牌 + 零个其他目标」的关键帧排到很后面。 |
| consistency trigger | 一致性触发 | 不看绝对置信度，而看**同一目标在不同视角下的结论是否一致**：多模型、多帧、TTA、教师-学生。 | **零标注成本的难例信号**：不一致本身就是错误的证据，不需要知道正确答案。 | 以为一致就等于正确——**一致地错**是最危险的情况（所有模型都把广告牌当限速牌），一致性触发对这类错完全失明，必须靠影子模式与用户反馈补。 |
| temporal inconsistency | 多帧不一致 | 同一被跟踪目标在相邻帧之间类别跳变、置信度剧烈震荡、或检出后突然消失。 | **TSR 上最有效的触发器**：标志是静止的刚体，自车在接近它，物理上类别不可能变。跳变几乎必然意味着难例。 | 以为需要真值才能判定——完全不需要，跟踪 ID 内部的自洽性就够了。但要注意**跟踪本身也会错**（ID switch 会伪造一次「类别跳变」），所以要求跟踪片段有最小长度与稳定的 IoU 链。 |
| TTA disagreement | 测试时增强分歧 | 对同一帧做翻转/多尺度等变换后分别推理，看结果是否一致。 | 单模型即可获得分歧信号，不需要部署多个模型。 | 以为对 TSR 可以用水平翻转——**「左转」翻过来就是「右转」**，翻转 TTA 在方向性标志上会制造假分歧。TTA 的变换集必须做类别安全性检查（见 C56）。 |
| teacher-student disagreement | 教师-学生分歧 | 车端小模型与云端大模型（或量化前后模型）对同一帧的结论差异。 | **量产系统里最实用的触发器之一**：它同时捕捉「难例」和「蒸馏/量化损失」，而后者是车端特有的错误来源。 | 以为分歧一定是学生错——也可能是教师错（云端模型没见过这个地区的标志），所以分歧样本仍要经过人工确认才能进训练集。 |
| shadow mode | 影子模式 | 新模型在车上真实运行但**输出不接入控制**，只记录并与现网模型/真值比对。 | **唯一能拿到「模型自信地错了」样本的通道**——不确定性触发按定义就看不见这类错误，而它们恰恰是安全上最危险的。 | 以为影子模式只是「上线前的验证」——它的主要价值是**持续的数据来源**，是数据飞轮的燃料入口，而不是一次性的发布关卡。 |
| trigger rate | 触发率 | 触发器判定「值得回传」的帧占总帧数的比例。 | 它直接乘以车队规模与行驶里程 = 回传数据量，**必须与带宽和存储预算对齐**。触发率是阈值的另一种表达。 | 以为触发率可以事后调——阈值一改，回传数据的分布就变了，此前积累的统计（命中率、类别构成）全部失效，所以**触发率应当先按预算定死，再反推阈值**。 |
| trigger precision / hit rate | 触发命中率 | 回传的帧中真正含有难例（经人工确认）的比例。 | 与触发率一起构成触发器的 PR 分析：触发率 1%、命中率 30% 意味着每 1000 帧回传 10 帧、其中 3 帧真有用。**没有这两个数就无法谈论触发策略的好坏。** | 以为命中率越高越好——命中率接近 100% 通常说明阈值太保守，只捞到了最明显的错误，**真正的长尾还在阈值下面**。这与检索里的 precision-recall 权衡完全同构。 |
| trigger sampling bias | 触发器偏差 | 触发器本身是一个有偏的采样器，它决定了你的训练数据将来长什么样。 | **本课的一条核心警告**：只回传模型不确定的样本，模型就永远看不到「它自信且错」的那一类，这个盲区会被闭环**自我强化**。 | 以为多加几种触发器就能覆盖——不同触发器可能共享同一个盲区。正确做法是**保留一条随机回传通道**（如 0.1% 的均匀采样）作为无偏参照，用来估计触发器漏掉了什么。 |
| cold start | 冷启动 | 模型还很弱时，不确定性度量本身不可靠，主动学习无从谈起。 | 决定了闭环的启动顺序：**第一轮必须随机（或按场景分层）采样**，等模型达到基本可用后再开启不确定性触发。 | 以为可以一上来就用主动学习——弱模型的不确定性几乎是随机的，此时的「主动」选择通常还不如分层随机采样。 |
| expected model change | 期望模型变化 | 另一族主动学习准则：选那些「如果标了，会引起最大梯度/参数更新」的样本。 | 比不确定性更接近「有价值」的真实定义（价值 = 标了之后模型变好多少）。 | 以为它可以直接用在大模型上——需要对每个候选样本估计梯度范数，计算量随池大小线性增长，工程上通常只在已经筛过一轮的小池上用。 |
| label budget | 标注预算 | 一个周期内可以标注的样本数（或钱数、人时）。 | **它是整条链的硬约束**，触发阈值、去重强度、类别配额全部由它反推。 | 以为预算只限制数量——它同时限制**标注质量**：同样的钱，标 10000 张粗标还是 2000 张精标（含属性、遮挡度、距离），这是一个必须显式做的取舍。 |

## 四 · 挖掘基础设施 · Mining Infrastructure

| 术语 (EN) | 中文 | 一句话定义 | 为什么重要 | 常见误解 |
|---|---|---|---|---|
| embedding retrieval | 嵌入检索 | 把每帧（或每个目标 crop）编码成向量，用向量近邻搜索找「长得像的」。 | **长尾挖掘的主力工具**：拿到一个 badcase，从千万级帧里捞出同类场景，是把「一个错」变成「一批训练数据」的最短路径。 | 以为随便一个 backbone 的特征都能用——检测 backbone 的特征偏向前景类别，可能把「所有有车的场景」聚成一类。通用视觉-语言嵌入（如 CLIP 系）在**场景级**检索上往往更好，而目标级检索要用 crop 特征。两者用途不同。 |
| ANN index | 近似最近邻索引 | HNSW（图索引，高召回低延迟但内存大）、IVF-PQ（倒排 + 乘积量化，省内存但有量化误差）等。 | 千万到十亿级向量上暴力搜索不可行；索引类型的选择直接决定挖掘的迭代速度。 | 以为召回率无所谓——ANN 的 recall@10 若只有 0.8，你就系统性地丢掉了 20% 的相似样本，而且**丢掉的往往是稀疏区域的样本，正是长尾**。 |
| recall@k | 前 k 召回率 | 近似检索返回的 top-k 中，有多少属于精确检索的 top-k。 | **没有 recall@k 评估的检索等于抽奖。** 建索引后必须用暴力搜索在一个小子集上对拍。 | 以为它等于「找到了我想要的」——recall@k 只衡量索引对暴力搜索的逼近程度，**不衡量嵌入本身好不好**。后者要靠人工抽检语义相关性。 |
| index staleness | 索引过期 | 模型更新后嵌入分布变了，但索引还是老模型建的。 | **最常见的静默失效**：检索还能返回结果，只是结果越来越不相关，而没有任何报错。 | 以为可以增量混用新旧嵌入——**不同模型的嵌入空间不可比**，混在一个索引里的距离没有意义。要么全量重建，要么给每个模型版本一个独立索引。 |
| scenario tagging | 场景打标 | 给每帧打上结构化标签：天气、光照、道路类型、国家/地区、标志类别、遮挡度、车速等。 | 它把「数据」变成**可查询的数据**：「给我 500 张夜间 + 雨天 + 有限速牌的帧」这种需求，没有标签体系就只能靠人翻。也是分场景评测切片的来源。 | 以为标签体系可以边做边加——**标签体系的变更是回溯性的灾难**（老数据没有新标签，切片评测就断代了）。要一开始就设计好维度与取值，并预留 unknown 值。 |
| taxonomy | 标签体系 | 标签维度与取值的正式定义，包括互斥性、层次关系与缺省值。 | 决定了后续所有查询与切片的表达能力；也是与标注团队沟通的契约。 | 以为维度越细越好——维度过细会导致每个切片的样本数太少，**评测时统计功效不足**，切片指标全是噪声。 |
| VLM auto-labeling | 视觉语言模型自动打标 | 用通用视觉-语言模型对帧做零样本/少样本的属性标注（天气、光照、场景描述、是否含某类标志）。 | **现在的主流做法，也是 JD 里 "automated data mining workflows" 的直接指向**：它让标签体系可以廉价地覆盖千万级数据。 | **以为可以直接信任它的输出**——你是在用一个未评估的模型给另一个模型选数据。上线前必须在人工标注的小集上量出每个标签维度的准确率/召回率，并对低可信维度设置人工复核。另一个误解是以为它能替代检测标注——它擅长**场景级属性**，框级精标仍然要人。 |
| near-duplicate | 近重复 | 内容几乎相同的帧：同一路口的连续帧、等红灯时的静止序列、同一段路的重复通行。 | **去重是挖掘的第一道闸**：回传 1000 张同一路口的连续帧，信息量约等于一张，标注预算就白烧了。 | 以为按时间戳抽稀就够了——等红灯 90 秒产生的帧无论怎么抽稀都是同一个场景；反过来高速行驶时相邻帧差异很大，抽稀会丢信息。**必须按内容而不是按时间去重。** |
| perceptual hash (pHash) | 感知哈希 | 缩放灰度 → DCT → 取低频系数与中位数比较 → 得到 64 位指纹，用汉明距离判定相似。 | 极便宜（无需模型前向），能高效抓出**像素级**近重复；是去重流水线的第一级粗筛。 | 以为它能判断语义相似——pHash 对光照/裁剪/压缩鲁棒，但**换个天气、换辆车，哈希就完全不同**。语义级重复必须靠嵌入聚类，两级是互补的。 |
| embedding dedup (SemDeDup 式) | 语义去重 | 在嵌入空间聚类，把每簇内距离极近的样本只保留代表。 | 抓住 pHash 抓不到的「不同帧但同一场景/同一目标」的重复；在大规模数据整理里被证明能在**几乎不掉点**的前提下砍掉可观比例的数据。 | 以为阈值可以照抄——去重阈值与嵌入模型强绑定，换模型必须重新标定；标定方法是人工看若干对被判为重复的样本。 |
| core-set selection | 核心集选择 | 选一个小子集，使得整个数据集中任意样本到子集的距离都尽可能小（k-center 问题）。 | **多样性采样的标准形式化**：目标是**覆盖**而不是「找最难的」。贪心算法（每次选距离当前子集最远的点）是 2-近似。 | **以为 core-set 是在选难例——正相反，它在选「代表」。** 难例挖掘与多样性采样是两个目标，实践中要串联使用（先用触发器筛难，再用 core-set 在难例里保多样），而不是二选一。另一个坑：k-center 对离群点极敏感，一个损坏的帧会被贪心第一个选中。 |
| coverage radius | 覆盖半径 | 所有样本到所选子集的最大距离。 | core-set 的目标函数，也是评估任何采样策略多样性的通用指标——**可以直接用来和随机采样对比**。 | 以为半径越小越好——半径受离群点主导，实践中常用分位数半径（如 95% 分位）而不是最大值。 |
| cluster-balanced sampling | 聚类均衡采样 | 先聚类，再从每簇按配额采样。 | 比 core-set 便宜得多，且天然抵抗离群点；工程上最常用的多样性保证手段。 | 以为簇数无所谓——簇数太少会把不同场景混在一起，太多则每簇只有几个样本、退化成随机采样。 |
| submodularity | 次模性 | 「边际收益递减」的形式化：向更大的集合添加同一元素，收益不会更大。 | 覆盖类目标（facility location、集合覆盖）多为次模，因此**贪心算法有 (1 − 1/e) 的近似保证**——这就是为什么挖掘里到处是贪心。 | 以为贪心只是拍脑袋——在次模目标下它有理论保证；但**难例挖掘的目标不是次模的**（两个难例的价值可能超过各自之和），所以那里的贪心没有保证。 |
| annotation budget allocation | 标注预算分配 | 按「类别缺口 × 难度 × 单价」把有限预算分到各类别/各场景上。 | 把预算决策从「谁嗓门大」变成一个可优化问题；也是与数据团队协作时的共同语言。 | 以为应该平均分——缺口最大的类往往也是**最难采集**的（地方性标志），单位成本可能高十倍；正确目标是最大化**总的预期指标提升**，而不是补齐每个类的数量。 |
| data lineage | 数据血缘 | 记录每条数据的来源（哪辆车、哪次触发、哪个挖掘任务）、加工过程与去向（进了哪个数据集版本、训了哪个模型）。 | **出问题时能不能回溯全靠它**：发现一批标注有系统性错误，你要能在十分钟内回答「哪些模型受影响、要不要召回」。 | 以为它等价于数据版本号——版本号只回答「这批是什么」，血缘还要回答「它从哪来、去了哪」。缺了后半段，一次错标事故就只能全量重训。 |
| dataset version / snapshot | 数据集版本 | 给训练用的数据集打不可变快照（内容寻址或不可变清单）。 | 实验可复现的前提；也是回归门禁能公平比较的前提（**评测集绝对不能悄悄变**）。 | 以为「同一个目录」就是同一份数据——目录里的文件会被人补标、修标、删除；没有不可变快照，上周的实验今天就复现不出来了。 |
| mining pipeline | 挖掘流水线 | 触发 → 回传 → 去重 → 打标 → 检索/采样 → 预算分配 → 送标 → 入库的完整任务链。 | 把一次性的脚本变成可重复、可监控、可回滚的系统；每一步都应有产物与质量门。 | 以为流水线的瓶颈是算力——实践中瓶颈几乎总是**标注环节的排队时间与返修率**，这也是「周期时间」这个 KPI 的主要构成。 |
| eval set contamination | 评测集污染 | 挖掘出来的数据与评测集有重叠或强相关（同一路口相邻帧被分到两边）。 | **数据闭环里最隐蔽的作弊**：指标会假涨，而且越挖越涨，直到上路时崩掉。 | 以为按帧去重就够了——必须按**采集片段/路段/时间段**分组划分（group split），同一段路的所有帧要整体落在同一侧。 |

## 五 · 闭环验证 · Closed-Loop Validation

| 术语 (EN) | 中文 | 一句话定义 | 为什么重要 | 常见误解 |
|---|---|---|---|---|
| sliced evaluation | 分场景切片评测 | 按场景标签（夜间/雨天/远距离/稀有类/遮挡）分别计算指标，而不是只看总体 mAP。 | **不切片，数据工作的效果基本不可见**：总 mAP 会把「雨天 +3、晴天 −1」平均成 +0.3。切片是数据闭环的仪表盘。 | 以为切片只是「多算几个数」——切片的**设计**才是难点：切片要与失效模式一一对应（见 C55），要有足够样本量，且各切片之间的重叠要可控。 |
| slice design | 切片设计 | 决定切哪些维度、每个切片多少样本、如何避免切片间强相关。 | 切片太小则指标全是噪声，切片太粗则掩盖问题；**每个切片至少要能检出你关心的最小效应量**。 | 以为切片可以事后随便加——每加一个切片就多一次比较，多重比较问题随之恶化（见下条）。切片集合应当**预注册**（实验前定好）。 |
| regression gate | 回归门禁 | 发布前的硬性检查：关键切片的指标不得低于基线超过容差，否则阻断发布。 | 把「不要把已经修好的东西弄坏」从口头承诺变成自动化关卡；这是 data-model-evaluation loop 能闭合的关键。 | 以为门禁越严越好——容差设得比种子噪声还小，会导致**大量假阻断**，团队很快学会绕过门禁，等于没有门禁。 |
| tolerance | 容差 | 门禁允许的最大退化幅度。 | 它必须**由实测的种子方差决定**，而不是拍脑袋的「不许掉」。 | 以为容差应该是 0——同一份代码、同一份数据、只换随机种子，检测 mAP 就会有 ±0.2–0.5 的波动；把容差设成 0 等于要求模型比它自身的复现精度还稳定。 |
| seed variance | 种子方差 | 只改随机种子时指标的波动幅度。 | **面试里能立刻显出水平的一个数**：检测任务典型 ±0.2–0.5 mAP，所以「我的方法涨了 0.3」本身不构成任何证据。 | 以为固定种子就没有方差了——固定种子只是让你复现自己，**它不改变结论的不确定性**；报告单种子结果等于报告一次抽样。 |
| paired comparison | 配对比较 | 在**同一批样本**上比较两个模型的逐样本表现，而不是比较两个独立的总指标。 | 配对能消掉「样本本身难易」这个最大的方差来源，**同样的数据量下检出能力显著更高**。 | 以为要跑更多种子才能提高功效——先做配对，往往比多跑三个种子更划算。 |
| paired bootstrap | 配对自助法 | 在样本层面有放回重采样，重复计算两模型的指标差，得到差值的分布与 p 值。 | 对 AP 这种**非线性、非均值型**的指标，t 检验的假设不成立，bootstrap 是标准做法。 | 以为重采样图片和重采样框等价——AP 的计算跨图耦合（全局排序），**必须以图（或以采集片段）为单位重采样**，否则会低估方差。 |
| multiple comparison correction | 多重比较校正 | 同时做 m 次检验时调整显著性水平：Bonferroni（α/m，保守）或 Benjamini-Hochberg（控制 FDR，更实用）。 | **20 个切片、α = 0.05，即使方法完全无效，至少出现一个「显著」的概率也有 1 − 0.95²⁰ ≈ 64%。** 不校正就等于允许自己在切片里挑好看的汇报。 | 以为 Bonferroni 总是对的——它控制的是「一个假阳都不许有」，在 20+ 个切片时过于保守，几乎什么都检不出。工程上通常用 BH 控制 FDR（允许 10% 的发现是假的）。 |
| effect size | 效应量 | 差异的实际大小（如 +1.2 AP），与「是否显著」是两件事。 | 样本量足够大时微小差异也会显著；**要问的是「这个提升值不值得付出的代价」**。 | 以为 p 值小就说明提升大——p 值只回答「是不是噪声」，不回答「有多大」。两个都要报。 |
| catastrophic forgetting | 灾难性遗忘 | 在新数据上继续训练后，模型在旧分布上的能力显著退化。 | 数据闭环里它的典型表现是**「上一版修好的 bug 又回来了」**——这是最打击团队信心的一类回归。 | 以为只有在完全不含旧数据时才会发生——**新数据占比过高就足以引发**；而闭环恰恰倾向于不断加入同类难例，配比会悄悄漂移。 |
| data mixing ratio | 新旧数据配比 | 每个 batch（或每轮训练集）中新挖数据与历史数据的比例。 | **它是防遗忘最直接的旋钮**，也是「目标场景涨多少 vs 其他场景掉多少」这条权衡曲线的自变量。 | 以为新数据越多越好——新数据往往是**经过难例触发筛选**的偏分布，占比过高会让模型对「正常场景」的先验被扭曲，出现「简单样本反而错了」。 |
| replay / rehearsal | 回放 | 训练时始终混入一定比例的历史（或代表性）样本以保持旧能力。 | 工程上最简单有效的防遗忘手段，比任何正则化方法都好落地。 | 以为随便留一点旧数据就行——回放集应当是**按切片分层抽样**的代表集，而不是随手截取的一段；否则你保住的是某几个场景而不是整体。 |
| marginal return curve | 边际收益曲线 | 目标切片的指标随该切片新增标注量 n 的变化曲线，常可用 AP(n) ≈ a − b·n^(−c) 拟合。 | **数据决策唯一的量化工具**：拟合出来就能回答「再标 5000 张预计涨多少、还值不值得」，把会议争论变成一个数字。 | 以为它是通用的——曲线**按切片各不相同**：某些场景（夜间小目标）很快饱和，某些（新增标志类别）还在陡峭段。用总体曲线做局部决策会系统性犯错。另一个误解是外推可以很远——幂律外推超过 2–3 倍数据量就非常不可靠。 |
| data scaling law | 数据规模律 | 误差随数据量呈幂律下降的经验规律。 | 边际收益曲线的理论背景；也解释了为什么「数据翻倍」的收益会越来越小。 | 以为幂律不可打破——**通过数据剪枝/定向选择可以打破随机采样的幂律**（这是本课存在的理由）：定向加 2000 张尾部数据，效果可能超过随机加 10 万张。 |
| shadow evaluation | 影子评测 | 新模型在真实车流中运行但不接管控制，用真实分布评估其表现。 | 离线指标与路测体验会背离；影子评测是两者之间唯一的桥。 | 以为它能替代离线评测——影子模式**没有真值**，只能给出与现网模型的差异和自洽性指标；真值仍需抽样送标。 |
| A/B test | A/B 测试 | 将车队/用户分组，分别运行不同模型版本并比较线上指标。 | 唯一能测量「端到端业务影响」的方法（接管率、误报投诉）。 | 以为感知模块可以随便 A/B——安全相关模块的 A/B 有伦理与合规约束，通常只能在影子模式或受限场景下做。 |
| canary / staged rollout | 金丝雀 / 分阶段放量 | 先在少量车/少量场景放开，观察指标无异常再逐步扩大。 | 把「发布」从一个瞬间变成一个可回滚的过程；是安全相关系统的标准做法。 | 以为放量只看崩溃率——要盯的是**分切片的感知指标与接管率**，很多回归不会导致崩溃，只会让体验变差。 |
| cycle time | 周期时间 | 从「发现一个 badcase」到「修复版本上线」所经过的时间。 | **闭环真正的 KPI 不是 mAP，是周期时间。** 一个 mAP 略低但周期 4 天的团队，会在半年内碾压一个 mAP 更高但周期 6 周的团队。 | 以为它主要由训练时长决定——实际构成里标注排队、评测排期、发布窗口通常占大头；优化周期时间要先测量各环节耗时。 |
| data flywheel | 数据飞轮 | 部署 → 采集难例 → 标注 → 训练 → 更好的模型 → 更精准的难例采集 → …… 的正反馈循环。 | **它是自动驾驶感知唯一不会被架构趋同抹平的护城河**，也是本课的组织主线。 | 以为飞轮会自动转起来——飞轮有摩擦：触发器的偏差、标注的噪声、评测的失真都会让它**反向自锁**（模型越自信 → 触发越少 → 越学不到新东西）。必须显式设计随机回传通道与外部审计。 |
| Simpson's paradox | 辛普森悖论 | 各分组内都下降，合并后却上升（或反之），因为分组的样本占比变了。 | 数据闭环里非常常见：加了大量夜间数据后，评测集的场景构成变了，总 mAP 的变化可能与任何一个切片的变化方向相反。 | 以为总指标是各切片的加权平均就没问题——**权重本身在变**，这正是悖论的来源。所以必须报告固定权重（预注册切片占比）下的指标。 |
| golden set | 黄金评测集 | 高质量、多轮复核、长期冻结的评测集。 | 门禁的地基：**它一旦变，历史结果就全部不可比**。 | 以为可以持续往里加新场景——新场景应当放进**新增的切片**并单独跟踪，而不是稀释原有的黄金集；否则你会失去纵向比较能力。 |
