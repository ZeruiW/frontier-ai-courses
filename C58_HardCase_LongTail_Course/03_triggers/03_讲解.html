1问题重述：车队数据无限，标注预算有限

模块 02 讨论的是「已经标好的数据里，该多看哪些」。这一模块的问题完全不同，也更贴近量产：

一支 10 万辆车的车队，每天产生的视频数据以 PB 计。你的标注预算是每天几万个框。回传哪些帧？

这就是 active learning（主动学习）在自动驾驶里的真实形态，而且它比教科书里的主动学习多了三个硬约束：

约束教科书主动学习车端主动学习
候选池几万个已存储的无标注样本近乎无限的流式数据，且大部分永远不会被存储
打分时机可以离线跑大模型给全池打分必须在车端实时算（算力只剩几个百分点给触发器）
选择方式全局排序取 top-k只能用阈值做在线判决（看到这一帧就得决定留不留，没有全局视野）
回传成本≈ 0带宽有钱，且用户流量与隐私都要顾
评价指标标注 N 个后的模型精度「回传的东西里有多少真的是 badcase」+ 「真 badcase 有多少被抓到」

换个角度看，这就是一个「二分类器」的设计问题：输入是一帧（或一小段），输出是「回传 / 丢弃」。它有 precision（回传的里面有多少真值钱）和 recall（真正的 badcase 抓到了多少），有工作点，有 PR 曲线，也有偏差。把触发器当成一个需要评估的模型来对待，是这一模块最重要的思维转变——而绝大多数人只把它当成「几行 if 语句」。

车端触发 → 回传 → 挖掘 → 标注 → 训练 的完整链路 ┌── 车端（实时，算力预算 < 5%）──────────────────────────────┐ │ │ │ 相机 ─► 感知模型 ─► 检测/分类结果 + 跟踪 │ │ │ │ │ ▼ │ │ ┌───────────────────────┐ │ │ │ 触发器（三类并联） │ │ │ │ ① 不确定性 │ │ │ │ ② 一致性（含多帧） │ │ │ │ ③ 规则/事件 │ │ │ └───────────┬───────────┘ │ │ │ 触发率必须 <= 带宽预算 │ │ ▼ │ │ 环形缓冲区（保留触发点前后 ±3s） │ │ │ 脱敏（人脸/车牌模糊） │ └──────────────────────────┼───────────────────────────────┘ ▼ ┌── 云端 ────────────────────────────────────────────────┐ │ 回传队列 ─► **去重**（近重复检测/聚类）─► 多样性采样 │ │ │ │ │ ▼ │ │ 大模型/离线模型复检（离线可以跑 10× 大的模型） │ │ │ │ │ ▼ │ │ 标注 ─► 训练 ─► 评测 ─► 门禁 ─► 发布 │ │ │ │ │ 影子模式验证 ◄──────┘ │ └────────────────────────────────────────────────────────┘ ⚠️ 整条链路的**瓶颈永远是标注**，所以触发器的 precision （回传的里面有多少值得标）直接决定整个数据飞轮的效率。

直白说

先把最容易被忽略的一点说清楚：「回传什么」的答案不是「模型不确定的」，而是「能让模型变好的」。这两者只在一部分情况下重合。模型对某一帧不确定，可能是因为那一帧真的信息不足（远处 8 像素的标志，标了也学不到）；模型对某一帧很确定，也可能是它自信地错了（把限速 80 稳稳当当认成 60）。后一类才是最危险的，而它恰恰是不确定性触发器的系统性盲区——这是本模块的第 6 节主题。

严谨说

形式化一点：主动学习的理想目标是选出使expected model change（期望模型改变量）或期望误差下降最大的样本。但这两个量都需要「知道真标签」才能算，所以实践中只能用代理量：不确定性、分歧、规则命中。每一个代理量都有它偏离真实目标的方式，而这些偏离在长期运行的闭环里会被不断放大（因为下一版模型是在这些数据上训的，触发器又跟着模型走）。所以触发器组合里必须有一条「与模型无关」的通路——随机基线、规则、外部先验（高精地图），三者缺一不可。

把数字摆出来会更有感觉。假设每辆车每天行驶 1 小时、30 FPS，那就是 10.8 万帧/天/车。1 万辆车 = 10.8 亿帧/天。如果标注预算是 5 万帧/天，触发率必须控制在 4.6×10⁻⁵——也就是每两万帧里只能挑出一帧。在这个量级下，触发器 precision 从 5% 提到 20% 意味着标注效率翻两番，其价值远超模型上的大部分改动。这也是 JD 里「define mining strategies for long-tail scenarios」这条职责的真实分量。

2不确定性触发：三种度量与它们各自的失效方式

最基础的一类触发器。给定模型对某个框输出的类别概率分布 p，用一个标量刻画「模型有多不确定」。三种常用度量：

\[H(p) = -\sum_{c} p_c \log p_c, \qquad\quad M(p) = p_{(1)} - p_{(2)}, \qquad\quad LC(p) = 1 - p_{(1)}\]

分别是entropy（熵）、margin（最大与次大概率之差）与 least confidence（最小置信度，即 1 减去最大概率）。它们看起来差不多，但在类别数很多的场景下差别巨大——而 TSR 恰好是类别数很多的场景（百来个细分类）。

度量抓住的是在 TSR 上的表现失效场景
熵 H(p)整个分布的弥散程度会被「长尾小概率」拉高：100 个类各分到 0.5% 的残余概率，熵就已经不低了，即使 top-1 是 0.5类别数多时对「真正的二选一混淆」不敏感；被无关类的噪声概率污染
margin M(p)最像样的两个候选之间的竞争TSR 上最好用：限速 60 vs 80、禁止驶入 vs 禁止通行，都是典型的二选一三个及以上类别势均力敌时会低估不确定性
least confidence只看 top-1 有多高最便宜（不需要排序），常用于车端粗筛第一层完全忽略「输给谁」；0.5 对 0.49 与 0.5 对 0.05 被视为一样

直白说

选哪个？在 TSR 这类「细粒度多类别 + 混淆成对出现」的任务上，margin 明显优于熵。原因很具体：熵是全分布的函数，当类别数 C 很大时，即使模型已经把答案锁定在两个类之间，剩下 C-2 个类上残余的小概率仍会贡献可观的熵值——于是熵在「限速 60 vs 80」和「一片模糊什么都不像」这两种完全不同的情况上给出接近的分数。而 margin 只看前两名，正好对应了 TSR 的错误结构。

严谨说

但有一个前提条件必须先满足：这三个度量都建立在「softmax 概率是可信的」这一假设上，而现代神经网络的 softmax 是系统性过自信的（Guo et al., 2017）。未校准的模型上，0.9 的置信度可能对应 70% 的真实正确率，这会让阈值完全失去意义，而且校准误差在不同类别、不同尺寸桶上还不一样（小目标通常更过自信）。所以不确定性触发器上线前必须先做校准（温度缩放最简单），并且按尺寸/光照分桶分别校准——否则触发器会系统性偏向某些桶。

还有一个检测特有的维度常被忘掉：定位不确定性。分类概率只刻画「是什么」，不刻画「在哪里」。一个框如果类别很确定但位置抖动很大（多帧之间 IoU 反复跳、或用 MC-dropout / TTA 时框位置方差大），同样是值得回传的 badcase。在 TSR 里这尤其重要——远处小标志的框抖动会直接导致跟踪断裂。实现上可以用「回归头输出分布的方差」（如 GFL 的 distribution focal loss 天然给出分布）或「多帧框位置的方差」，成本都很低。

3框级 → 图级：检测里最容易做错的一步聚合

上一节的度量都定义在单个框上，但回传决策是整帧（或整段）的。这一步聚合看起来是个小细节，实际上它决定了触发器会系统性偏向什么样的场景。

聚合算子定义偏向什么什么时候用
maxU = max_j u_j只要有一个可疑框就触发。对「单个关键错误」最敏感默认选择；TSR 关心的是「有没有一个标志被认错」而不是平均质量
meanU = mean_j u_j偏向框少的帧：一帧只有 1 个可疑框时 mean 很高，10 个框里 1 个可疑时 mean 被稀释几乎不该单独用——它会系统性漏掉复杂路口
top-k mean最高的 k 个的均值介于两者之间，比 max 抗噪k=2~3，对单帧噪声更稳
count 超阈U = #{j : u_j > τ}偏向框多的帧（拥挤路口天然计数高）要做归一化才能用，否则触发的全是市区路口
加权（按尺寸/距离）U = max_j w_j u_j可以显式偏向「近处大标志」或「远处小标志」与安全代价挂钩时用：近处的错误后果更严重

这里有一个必须点破的偏差机制：

聚合算子是一个隐藏的采样偏差源

用 mean 聚合，会让触发器系统性地漏掉「复杂场景」；用 count 聚合，会让触发器几乎只回传市区拥挤路口。两者都是由聚合算子引入的、与模型无关的采样偏差——而它会在闭环里被固化：回传的数据偏向某类场景 → 模型在那类场景上变好 → 其他场景的问题永远发现不了。这类偏差比模型的问题更难察觉，因为它不体现在任何模型指标上。

除了聚合算子，还要处理三个检测特有的细节：

  1. 只对「已检出的框」算不确定性，会漏掉漏检。模型完全没检出的目标，压根不会产生任何框级分数。解法是同时用低阈值的候选（比如 score > 0.05 的所有 proposal）参与打分，或者依赖规则触发（跟踪丢失、地图先验）来覆盖漏检。这是不确定性触发器的第二个结构性盲区（第一个是「自信地错」）。
  2. 要不要按框数归一化。如果用 max，不需要；如果用 count 或 sum，必须除以框数或做长度归一化，否则触发率与场景复杂度强相关。
  3. 时间维度上的去重。30 FPS 下，一个 badcase 会连续触发几十帧。必须做时间窗内抑制（同一 track、同一场景在 N 秒内只触发一次），否则带宽预算会被少数几个片段吃光。这是「触发器 NMS」——和模块 02 里 OHEM 的 NMS 去重是同一个道理：不去重，预算就被少数几件事重复消耗。

直白说

第三条特别值得展开：在时序数据上，「触发一次」和「触发一段」是完全不同的成本。一次触发实际回传的是触发点前后各 3 秒（约 180 帧）的片段。如果不做时间窗抑制，一段 10 秒的困难路段可能产生 200 次触发、回传 200 个高度重叠的片段——占满预算却只贡献一个场景的信息。

严谨说

正确做法是两级抑制：车端做时间窗抑制（同一 track 在 T 秒内只触发一次，且优先保留分数最高的那一帧）；云端做内容去重（感知哈希 / 嵌入聚类，见模块 04）。两级都需要，因为车端不知道这个路口昨天已经回传过 50 次了，而云端不知道这 200 帧其实是同一个 3 秒。把这两级说清楚，就说明你理解了「触发」是一个分布式系统问题而不是一个打分问题。

4一致性触发：多模型分歧，以及 TSR 的杀手锏「多帧不一致」

不确定性触发器只能看到模型自己报告的不确定性——而它系统性地不报告「自信地错了」那一类。一致性触发器绕开了这个问题：它不问模型「你有多确定」，而是把同一个东西的多个独立预测放在一起，看它们对不对得上。

一致性来源怎么做抓到什么车端可行性
多模型分歧（query-by-committee）K 个独立训练的模型投票，算 vote entropy 或平均 JS 散度「模型集体不确定」与「单模型自信但集体分歧」两类车端跑不动 K 个模型；通常只在云端影子复检时用
TTA 分歧同一帧做翻转/多尺度推理，看结果是否一致对增强不鲁棒的样本；标注边界模糊的样本延迟翻倍，车端一般只在低负载时抽样开启
教师-学生分歧车端小模型 vs 云端/离线大模型的预测差异蒸馏损失最大的样本——直接对应「小模型学不会的东西」车端只跑学生；分歧在云端影子模式里算
多帧不一致（temporal inconsistency）同一个 track 在连续帧上的类别序列是否跳变TSR 上极其有效——见下文几乎零成本（跟踪本来就要跑），车端首选

为什么「多帧不一致」在 TSR 上如此有效

因为交通标志有一个别的目标没有的强物理性质：它是静止的刚体，类别在时间上恒定。一个限速 60 的标志，在车辆接近的整个过程中永远是限速 60。所以——

同一个 track 上出现类别跳变，就是一个「无需标注即可确认的错误」：不管跳变前后哪一帧是对的，至少有一帧一定是错的。这是一个免费的、零标注成本的自动标签——你不需要知道正确答案，就能确定「这里出了问题」。行人跟踪、车辆跟踪都没有这个性质（它们的属性会真的变化），这是 TSR 独有的红利。
多帧一致性触发：同一个 track 的类别序列 帧号: t0 t1 t2 t3 t4 t5 t6 t7 距离: 80m 70m 60m 50m 40m 30m 20m 15m 像素: 9px 11px 13px 16px 20px 27px 40px 53px ✅ 正常 track（无需回传） 类别: SL60 SL60 SL60 SL60 SL60 SL60 SL60 SL60 置信: 0.42 0.51 0.63 0.75 0.88 0.94 0.97 0.98 → 类别恒定，置信度随距离单调上升 —— 教科书式的正常行为 ⚠️ 类别跳变 track（**必须回传**） 类别: SL80 SL80 SL80 SL60 SL60 SL60 SL60 SL60 置信: 0.91 0.93 0.88 0.72 0.85 0.93 0.96 0.98 ↑ **远处「自信地」认成 SL80，近处才纠正过来** · 单帧不确定性完全抓不到（t0-t2 的置信度都 > 0.88） · 多帧一致性一抓一个准，而且**自动告诉你哪几帧错了** （用近处高置信的结果反标远处的低分辨率帧 = **免费的困难样本**） ⚠️ 闪烁 track（**必须回传**） 类别: SL60 SL80 SL60 SL80 SL60 SL60 SL60 SL60 → 跳变次数 = 4，典型的「决策边界上反复横跳」 可用的量化指标： flip_count = 相邻帧类别变化次数 mode_fraction = 众数类别占比（越低越不一致） class_entropy = track 上类别分布的熵 stabilize_frame = 第几帧之后不再变（越晚越糟）

直白说

「多帧不一致」不只是一个触发器，它还是一台自动标注机。因为 TSR 有一个额外的结构：置信度随距离单调上升——近处的预测几乎总是对的。于是可以用「近处高置信的结果」去反标「远处低分辨率的同一个 track」，自动产出一批「远距离小目标 + 正确标签」的困难样本，而这正是 TSR 最缺的数据类型。这个技巧的正式名字叫 auto-labeling by temporal propagation / track-level label propagation，在量产系统里价值极高。

严谨说

但要小心两个失效条件。① 跟踪本身可能错：如果两个相邻的标志被跟成同一个 track（ID switch），类别「跳变」其实是跟踪的错，不是分类的错。所以反标之前必须先验证 track 的纯度（用几何一致性：静止标志在自车运动下的图像位置是可预测的，偏离预测太多就说明 track 有问题）。② 可变电子牌的类别是真的会变的——限速 80 的电子牌可能在你接近的过程中变成 60。这类标志必须从「类别恒定」假设里排除掉，否则你会把真实变化当成模型错误反复回传。这两条例外是这个技巧能不能真正落地的分水岭。

5规则触发：最便宜、最可解释，也最容易被低估

第三类触发器完全不依赖模型的输出分布，而是依赖系统级的、可以被外部验证的矛盾。它们的共同结构是：「如果系统是对的，这件事不该发生；它发生了，所以某处出错了」。

规则触发器信号抓到什么类型的 badcase误触发风险 / 注意事项
检测到但跟踪丢失一个 track 存在 < N 帧就消失，且不是因为出画面不稳定检测：远距离小目标、遮挡边缘、光照突变（隧道出入口）真实遮挡（被大车挡住）也会触发 → 要结合几何判断是否出画面

规则触发器有三个被严重低估的优点：

  • 它们与模型无关。不确定性和一致性触发器都是模型的函数，所以它们的盲区会随着模型一起演化（模型在某处系统性地错，触发器也就在那处系统性地沉默）。规则触发器打破了这个耦合。
  • 它们可解释、可审计。「与高精地图不符」这个触发条件，可以直接生成一句人能读懂的说明，标注员和工程师都能立刻理解在看什么。而「熵 > 1.7」不能。
  • 它们几乎不花算力。跟踪、地图匹配、车辆信号本来就在跑，触发条件只是几个比较。在车端只剩几个百分点算力的约束下，这是决定性的优势。

但规则触发器有一个共同的失效模式：规则会随着系统演进而悄悄失效。「跟踪丢失」这条规则的触发率，会因为跟踪器换了一版而整体漂移；「与高精地图不符」会因为地图版本更新而突然爆量。所以每条规则触发器都必须有触发率监控与告警——触发率的异常漂移本身就是一个极有价值的信号：它意味着模型、跟踪器、地图或真实世界中的某一个变了。在成熟的团队里，触发率看板与模型指标看板是同等重要的两块屏。

6触发器本身会引入偏差：「模型自信地错了」这个系统性盲区

不确定性触发器的结构性盲区

本模块最深的一个洞察：只回传「模型不确定的」样本，会系统性地漏掉「模型自信地错了」的样本。 而在安全关键系统里，后者才是真正会出事的那一类——模型不确定时，下游还能靠迟滞、多帧投票、保守策略兜住；模型自信地错时，整条链路都会相信它。

把所有样本按「置信度 × 是否正确」摆成四象限 正确 错误 ┌───────────────────────┬───────────────────────┐ │ │ │ 高置信度 │ ① 已经学会 │ ② **自信地错了** │ │ （占绝大多数） │ ⚠️ **最危险** │ │ 回传价值 ≈ 0 │ 回传价值 **最高** │ │ │ │ │ 不确定性触发：不触发 ✅│ 不确定性触发：**不触发** ❌│ │ │ ← **系统性盲区** │ ├───────────────────────┼───────────────────────┤ │ │ │ 低置信度 │ ③ 蒙对了 / 边界 │ ④ 不确定且错了 │ │ 回传价值 中 │ 回传价值 高 │ │ │ │ │ 不确定性触发：触发 ⚠️ │ 不确定性触发：触发 ✅ │ │ （**误触发**，占用预算）│ │ └───────────────────────┴───────────────────────┘ 不确定性触发器实际做的是「按行切」（只看下面那一行）， 而我们真正想要的是「按列切」（只看右边那一列）。 **两者的交集只有 ④ 一格。** ⇒ 象限 ② 只能靠：**一致性触发（多帧/多模型）** + **规则触发（地图/事件）** + **随机基线采样**（唯一能覆盖「未知的未知」的通路）

这个盲区还有一个更麻烦的性质：它是自我强化的。

  1. 触发器只回传模型不确定的样本 →
  2. 标注 + 训练后，模型在「原本不确定的区域」上变得确定 →
  3. 下一轮触发器在这些区域沉默，转向新的不确定区域 →
  4. 而象限 ② 的那些样本，模型从一开始就很确定，所以从头到尾都不会被触发 →
  5. 这块盲区会一直存在，而且不会体现在任何离线指标上（因为验证集是从同一个有偏的回传流里抽的）。
偏差来源具体机制会漏掉什么对策
不确定性偏差只按模型自报的不确定性选样本象限 ②：自信地错一致性触发 + 规则触发 + 随机基线
漏检不可见没有检出就没有框，也就没有分数模型完全没看到的目标（远处、极端遮挡）低阈值候选参与打分；地图先验；跟踪丢失规则
聚合偏差mean 偏向框少的帧，count 偏向拥挤帧整类场景（简单场景 / 复杂路口）用 max 或 top-k mean；按场景桶分别设阈值
触发率的地理/时段偏差触发率在夜间/雨天天然更高 → 预算被这些时段吃光白天晴天下那些「罕见但确实存在」的错误按桶分配预算而不是全局阈值
闭环反馈偏差触发器是模型的函数，模型是回传数据的函数盲区会被固化并随时间加深固定比例的随机采样（10–20%）作为无偏基线，并用它定期审计触发器

直白说

随机基线采样是这一整套里最容易被砍掉、也最不能砍的一环。它看起来极其低效——随机回传的帧里 99% 都是模型已经会的东西。但它有一个无可替代的作用：它是唯一一条不经过模型判断的数据通路，因此是唯一能发现「未知的未知」的手段。而且它同时提供了一个无偏的评测集——所有触发器的 precision / recall 都必须在这个无偏样本上度量，否则你根本不知道自己漏了多少。

严谨说

具体做法：把总预算的 10%–20% 划给纯随机采样（分层随机更好：按地理/时段/天气分层），这批数据有两个用途——① 作为触发器的评测集：在这上面标注全部样本，就能算出每个触发器的真实 recall（分母是所有真 badcase，而不是「被触发的 badcase」）；② 作为模型的无偏验证集：它的分布才是真实路况分布，而回传流的分布已经被触发器扭曲了。面试里能主动说出「必须留一部分随机采样做无偏审计」，是判断一个人是否真的做过闭环的分水岭。

7把触发器当模型来评：PR 分析与带宽预算下的阈值优化

既然触发器是一个二分类器，就应该用二分类器的方式评估它。定义清楚三个量：

  • 触发率 rate = P(触发)——这是成本，直接对应带宽与标注预算；
  • 精确率 precision = P(是真 badcase | 触发)——回传的东西里有多少值得标；
  • 召回率 recall = P(触发 | 是真 badcase)——真 badcase 抓到了多少。注意分母必须来自随机基线采样，否则算不出来。

于是「设阈值」就变成一个标准的约束优化问题：在总触发率不超过预算 B 的前提下，最大化召回。多个触发器并联时（OR 关系），目标写成：

\[\max_{\tau_1,\dots,\tau_T}\; \Big|\bigcup_{t} S_t(\tau_t) \cap \mathcal{B}\Big| \qquad \text{s.t.} \qquad \Big|\bigcup_{t} S_t(\tau_t)\Big| \;\le\; B\cdot N\]

其中 S_t(τ_t) 是触发器 t 在阈值 τ_t 下选中的帧集合，𝓑 是真 badcase 集合。因为是「集合并集的覆盖」，这是一个 submodular（次模）最大化问题——贪心算法有 1-1/e ≈ 63% 的近似保证，而且实现只要十几行。notebook 里会把这个贪心分配器写出来。

组合方式怎么算优点问题
OR（并联）任一触发器命中即回传召回高；各触发器独立可调、可单独下线触发率是并集，重叠部分白白算了两次预算 → 必须做全局去重
AND（串联）多个同时命中才回传精确率高召回极低；容易只留下最平凡的 badcase
加权打分s = Σ w_t·u_t，对 s 设单一阈值只有一个阈值要调；天然做了融合可解释性差；某个触发器坏掉时不易发现；权重难标定（量纲不同）
级联车端便宜触发器粗筛 → 云端贵触发器精筛算力与带宽最优两级都要维护；粗筛的漏检无法被精筛挽回
按桶配额每个场景桶（夜间/雨天/城区…）独立预算直接消除地理/时段偏差桶的划分本身是一个设计决策，需要定期回顾

量产系统里的真实做法：级联 + 按桶配额 + 随机基线

把上面几条合起来，一个能上车的配置大致是这样：车端跑最便宜的三个触发器（多帧一致性、跟踪丢失、地图不符）做粗筛，触发率控制在 10⁻³ 量级；回传后在云端用大模型 + 多模型分歧做精筛，把 precision 提到 20–40%；总预算按场景桶分配，每桶有独立配额；额外划 15% 给分层随机采样做无偏审计。这套结构的每一部分在前面都有对应的理由，没有一条是拍脑袋的。

直白说

调阈值时有一个非常实用的经验：不要直接调「熵 > 1.7」这种绝对阈值，而是调「触发率」这个百分位。因为绝对阈值会随模型版本漂移——换一版模型，同样的熵阈值可能让触发率翻十倍，直接打爆带宽。而按分位数设阈（「触发 top-0.1% 最高熵的帧」）天然是自适应的。实现上需要车端维护一个滑动窗口的分位数估计（P² 算法或简单的直方图即可），成本很低。

严谨说

还有一个必须提前设计的东西：安全阀（circuit breaker）。触发率一旦异常升高（模型换版、进入新区域、天气突变），必须能自动降级——例如把阈值临时上调、或直接停止回传并告警。没有安全阀的触发器，会在某个雨夜把整个车队的流量打满。这条在面试里说出来，会立刻显出「上过线」和「只写过 notebook」的区别：任何在车端持续运行、且消耗共享资源的组件，都必须有自我限流的能力。

8影子模式与线上工程：触发器怎么真的跑在车上

shadow mode（影子模式）是这套体系的运行载体：新模型（或新触发器）在车上实时运行，但它的输出不接入控制，只用于与线上模型对比、记录分歧。它同时解决了三个问题——验证新模型、发现 badcase、收集数据——所以是量产团队的标配。

影子模式的三种用法比什么产出注意
新模型 vs 线上模型两者的检测/分类结果差异发布前的真实路况验证，不用等 A/B只知道「不一样」，不知道「谁对」→ 分歧片段仍需标注或大模型复检
大模型 vs 车端小模型教师-学生分歧蒸馏最需要的样本 + 车端模型的能力边界大模型跑不动就只能抽样跑，或者回传后在云端跑
新触发器 vs 旧触发器触发率、重叠度、命中率触发器本身的 A/B 验证触发器也需要灰度发布，直接全量上线会打爆带宽

车端落地时的五个硬约束，每一条都会实实在在地砍掉一些方案：

  1. 算力预算：TSR 只是众多感知任务之一，触发器能分到的算力常常不足 1 ms/帧。这直接排除了「车端跑 K 个模型做分歧」，也排除了大部分 TTA 方案。多帧一致性与规则触发之所以是首选，正是因为它们几乎免费。
  2. 存储与环形缓冲：触发发生时，你需要的是触发点之前的几秒（问题往往在触发前就开始了）。所以必须常驻一个环形缓冲区，滚动保存最近 N 秒的原始帧。缓冲区大小 = 回看时长 × 帧率 × 分辨率，是一笔要提前算的账。
  3. 隐私与合规：回传前必须对人脸、车牌做模糊/脱敏，且要满足数据出境与用户授权的要求。脱敏本身要花算力，且做得太狠会破坏训练数据的有效性（把整块区域涂黑会制造训练-推理不一致）。
  4. 触发器的版本与回滚：触发器配置（阈值、开关、桶配额）必须像模型一样有版本、可灰度、可远程回滚。「改一个阈值要等下次 OTA」是不可接受的。
  5. 触发率监控与安全阀：实时上报每个触发器的触发率与带宽占用，异常时自动降级。触发率漂移本身是最早的系统异常信号——它比模型指标更早暴露「环境变了」或「上游变了」。

直白说

最后一行值得单独强调：数据闭环的核心 KPI 不是「回传了多少数据」，而是「从发现问题到修复上线的周期时间」。回传量是投入，修复速度才是产出。一个每天回传 100 万帧但修一个 badcase 要六周的团队，远不如一个每天回传 5 万帧但两周就能闭环的团队。而周期时间的瓶颈通常不在模型，在标注排期与门禁流程——这也是模块 05 的主题。

严谨说

从这个角度反推，触发器设计还有一个常被忽略的目标：让回传的数据「好标」。同样是 badcase，一个「远处 9 像素的模糊标志」标注员标不了（也标不准），而一个「近处清晰但被认错的标志」几分钟就能标完且质量高。所以触发时最好带上「可标注性」的信号——比如优先回传那些「同一 track 里既有远处的困难帧、也有近处的清晰帧」的片段，这样标注员标一次近处，就能通过 track 传播反标出整段的困难样本。这是把第 4 节的时序反标技巧反过来用于触发器设计，收益极高而几乎无人在意。

9研究前沿与开放问题

主动学习是一个有 30 年历史的领域，但它在深度学习 + 流式车队数据上的形态，绝大部分问题仍然是开放的。

  • 批量主动学习的多样性问题：按不确定性取 top-k 会选出一批互相高度相似的样本（都是同一个失效模式），信息严重冗余。BatchBALD（Kirsch et al., NeurIPS 2019）用互信息显式建模了批内冗余；Core-set（Sener & Savarese, ICLR 2018）从覆盖角度选样本。但两者在千万级流式数据上都跑不动——如何在「只能看一遍、只能用阈值」的在线设定下保证批多样性，目前没有好答案。
  • 不确定性估计本身的可靠性：深度集成（deep ensembles）目前仍是最可靠的不确定性来源，但车端跑不起。单模型近似（MC-dropout、evidential deep learning、Laplace 近似、conformal prediction）各有各的问题。Conformal prediction（保形预测）因为能给出有覆盖率保证的预测集合，近年在自动驾驶里关注度上升很快——它对触发器的意义是：可以把「触发率」直接和「真实错误率的上界」挂钩，而不是靠经验调阈值。
  • 「自信地错了」的检测：这是本模块指出的核心盲区，也是学术上的开放问题。相关方向包括 OOD detection（分布外检测）、failure prediction（失败预测，训练一个专门预测「主模型会不会错」的辅助模型）、以及用外部先验（地图、物理约束、多传感器一致性）做交叉验证。其中「用物理/几何约束做自监督验证」在自动驾驶里最有前途，因为它完全不依赖模型自身的判断。
  • 主动学习的理论保证在深度模型上基本失效：经典主动学习的样本复杂度分析依赖凸性与可实现性假设，深度网络两个都不满足。实践中甚至存在「主动学习不如随机采样」的报告（尤其在数据量已经很大、或不确定性估计很差时）——所以「用随机基线作对照」不只是工程上的谨慎，也是学术上的必需。
  • 用 VLM 做触发器：直接让视觉-语言模型判断「这一帧有没有异常/罕见场景」，可以表达远比阈值规则丰富的条件（「有临时施工标志」「有被遮挡一半的限速牌」）。目前的瓶颈是车端跑不动，所以只能作为云端二级筛选；蒸馏出一个极小的「场景异常打分器」放到车端，是当前很热的工程方向，也直接对应 JD 里的「automated data mining workflows」。
  • 闭环反馈偏差的理论刻画：触发器 → 数据 → 模型 → 触发器 是一个反馈系统，它会收敛到什么分布？盲区会如何演化？这与推荐系统里的 feedback loop / filter bubble 研究是同构问题，但在感知系统上几乎没有系统性研究。目前唯一可靠的对策仍然是那条最朴素的：留一条不经过模型的随机通路。

必读：Settles, Active Learning Literature Survey（2009）——把不确定性采样、query-by-committee、expected model change 等基本框架讲全了，读第 3 章即可；Beluch et al., The Power of Ensembles for Active Learning in Image Classification（CVPR 2018）——证明集成分歧优于 MC-dropout，是「一致性触发」的实证基础；Kirsch et al., BatchBALD（NeurIPS 2019）——批量选择的冗余问题与互信息解法；Sener & Savarese, Active Learning for CNNs: A Core-Set Approach（ICLR 2018）——覆盖视角，与模块 04 的多样性采样直接相关；Guo et al., On Calibration of Modern Neural Networks（ICML 2017）——不确定性触发器的前提条件；Lakshminarayanan et al., Simple and Scalable Predictive Uncertainty Estimation using Deep Ensembles（NeurIPS 2017）；Angelopoulos & Bates, A Gentle Introduction to Conformal Prediction（2021）——把触发率与错误率上界挂钩的现代工具。相邻模块：C58 m02（难例挖掘）、C58 m04（大规模挖掘基础设施）、C58 m05（闭环验证）、C55 m04（时序融合与跟踪）。完整清单见 references.md。
