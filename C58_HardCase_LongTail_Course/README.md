# 难例挖掘与长尾数据闭环 · Hard-Case Mining & the Long-Tail Data Loop

模型架构是会趋同的。今天你用 RT-DETR、明年大家都用 RT-DETR；
今天你的 backbone 领先半年，半年后它躺在别人的开源仓库里。
**但数据飞轮不会趋同**——一支跑了三年的车队、一套能把「路上出的错」在四天内变成
「训练集里的新样本」的流水线，是竞争对手花钱也买不到的东西。

这门课讲的就是那条流水线。它有三个环节，而且是**串联**的：

```
   触发                        挖掘                        验证
 (Trigger)                   (Mining)                 (Validation)
车队里什么值得回传   →   回传之后怎么选出真正   →   怎么证明标完之后
（带宽是硬约束）          该标的那几千张             模型真的变好了
                          （预算是硬约束）           （种子噪声是硬约束）
```

**串联的意思是：任何一环断了，整条链的收益就是零。**

- 触发器有偏（比如只回传低置信度的），后面挖得再准，也只是在一个偏样本池里挑；
- 去重没做好，标注预算会烧在同一个路口的一千张连续帧上，而它们的信息量约等于一张；
- 验证不分场景，你会拿着一个「总 mAP +0.3」去汇报——而它完全落在种子噪声里。

## 🎯 为什么这门课直接对应 JD

XPENG 这个 TSR 岗位的职责清单里，有两条几乎是逐字对应本课的：

> **"Collaborate with data teams to define mining strategies for long-tail TSR scenarios."**
>
> **"...data-model-evaluation feedback loops."**

第一条对应模块 **03（触发）+ 04（挖掘）**：什么叫「define mining strategy」？
它不是「我们用主动学习」这种一句话，而是要能说清：
用哪些触发信号、触发率定在多少、带宽预算怎么换算成阈值、
回传后用什么去重、按什么规则分配标注预算、以及**这套策略本身怎么评估**。

第二条对应模块 **05（验证）**：feedback loop 的关键词是 loop——
它必须闭合。而闭合的判据只有一个：**你能用数据证明这一轮迭代确实让模型变好了，
并且没有把别的场景弄坏。** 模块 05 的分场景切片评测、回归门禁、
多重比较校正、边际收益曲线，就是把这个「证明」变成可执行的工程动作。

模块 **01（不平衡）+ 02（难例挖掘）** 则对应 JD 资格要求里的
"class imbalance"、"hard-case mining"——它们是这条链的**训练侧对偶**：
数据回来了之后，怎么让模型真的把这些稀有且困难的样本学进去。

面试里问「你们的数据闭环怎么做的」，考的从来不是你知不知道主动学习，
而是你能不能把这三环各自的**约束、指标和失败模式**说清楚。

## 学习路径

**建议顺序：00 → 01 → 02 → 03 → 04 → 05（线性）。**
但要注意本课的依赖结构和别的课不太一样：

- **01 与 02 是训练侧**（数据已经在手里，怎么用好），
- **03 与 04 是数据侧**（数据还在车上/云上，怎么找出来），
- **05 是把两侧接起来的验收关**。

如果你时间紧，**05 不能跳**——它是这门课唯一不可替代的部分。
挖掘工具网上到处都是，但「怎么证明它有用」才是把数据工作
从体力活变成工程学科的那一步。

| 阶段 | 模块 | 预计时长 | 你会带走什么 |
|---|---|---|---|
| ① 训练侧对付不平衡 | 00 + 01 + 02 | 6–7 h | 拿到一份长尾数据，能在十分钟内给出方法选型并说清代价；能手写 RFS、CB 权重、logit adjustment、带去重的 OHEM |
| ② 数据侧找数据 | 03 + 04 | 5–6 h | 能设计一套完整的触发策略并给它做 PR 分析；能搭出「检索 → 去重 → core-set → 预算分配」的挖掘链路 |
| ③ 闭上环 | 05 | 3–4 h | 能设计切片评测与回归门禁、能拟合边际收益曲线回答「还值不值得标」、能说清闭环的周期时间 KPI |

**如果你只有一个晚上**：读 02 的「难例 vs 噪声标签」一节 + 03 的触发器 PR 分析一节 +
05 的边际收益曲线一节。这三段串起来就是一条能在面试里讲十五分钟的主线：
*怎么找到真正的难例（而不是错标）→ 怎么在带宽预算下把它们捞回来 → 怎么证明它们真的有用。*

**每个模块的用法**：先读 `NN_讲解.html`（含双轨「直白说 / 严谨说」卡片），
再跑 `NN_*.ipynb`（纯 numpy 从零实现 + ✏️ 练习 + `assert` 自测判分 + 🧪 真实工程胶囊）。

## 四条贯穿全课的纪律

1. **先分清你在治哪一种不平衡。** 前景-背景不平衡（一张图里 1 个正样本对上千个负样本）
   和类别间长尾（限速牌几万个、某个地方性警告牌十几个）是**两个问题**，
   解法族完全不同。混着治就会出现「Focal Loss 也加了、重采样也做了，尾部类还是零召回」。
2. **挖掘出来的东西必须先分类，再使用。** 高 loss 的样本里同时混着
   *真难例*和*标注错误*，而后者的 loss 往往更高。
   **不做区分的难例挖掘，是在把错标当教材反复讲**——这是本课最重要的一条警告。
3. **任何采样器都是有偏的，包括你的触发器。** 只回传低置信度样本，
   就会系统性漏掉最危险的一类错误：**模型自信地错了**。
   设计触发策略时必须显式回答「这套触发器看不见什么」。
4. **没有分场景验证的数据工作等于没做。** 总 mAP 会把「雨天 +3、晴天 −1」
   平均成 +0.3，而 +0.3 在检测任务的种子噪声（±0.2–0.5）里什么都不是。
   **切片 + 多种子 + 显著性校正**是最低配置，不是加分项。

## 与相邻课程的关系

这门课是「数据闭环」这一条纵深，它会大量复用其它课的机制，也被其它课引用。

| 课 | 它讲什么 | 与本课的分工 |
|---|---|---|
| **C37 · MLOps** | 实验追踪、可复现性、CI/CD、模型注册、监控与回归测试，以及**通用的 data-model-evaluation 反馈环** | **上位方法论课**。C37 讲「一个 ML 系统怎么持续交付」，**本课是它在感知/长尾这一垂直场景下的展开**：C37 的「回归测试」在这里变成按天气/距离/类别分桶的门禁；C37 的「模型注册」在这里必须加上**数据血缘**才能回溯。面试答 feedback loop 时，C37 给骨架、本课给血肉 |
| **C43 · 数据工程** | 数据管道、存储与格式、版本化、数据质量与校验、批流处理 | **基础设施课**。模块 04 的挖掘流水线跑在 C43 讲的那套东西上：向量索引要落到某个存储、场景标签要有 schema、数据版本要能快照。**C43 讲「怎么把数据搬来搬去且不出错」，本课讲「搬哪些数据、为什么是这些」** |
| **C55 · TSR 与自动驾驶感知** | TSR 领域知识：数据集与标志分类学、两级 vs 端到端、**失效模式全景**、时序融合、安全导向评测 | **问题来源课**。C55 的失效模式全景告诉你「TSR 会在哪里出错」并给出优先级排序，**本课接过那份清单，把每一条变成可触发、可挖掘、可验证的数据动作**。C55 的分桶评测与本课模块 05 的切片门禁是同一套东西的两个视角 |
| **C56 · 检测数据增强工程** | 几何/光度增强、Mosaic、**Copy-Paste**、增强流水线与消融 | **对偶解法课**。长尾有两条路：**挖真数据**（本课）与**造假数据**（C56 的 copy-paste 把稀有标志贴到新背景）。两者不是替代关系：copy-paste 便宜但有域差、挖真数据准但贵，**实践中的正确答案通常是「先用增强顶住，同时用挖掘补真数据」**，而判断哪条更划算靠的正是本课模块 05 的边际收益曲线 |
| **C61 · 检测实战与面试实务** | 实验设计与归因、**TIDE 式误差分析**、调试手册、项目叙事与面试题库 | **下游落地课**。C61 的误差分解（Cls/Loc/Dupe/Bkg/Miss 各修好能涨多少 mAP）是本课**触发策略的输入**——你得先知道哪类错最值钱，才知道该挖什么；而本课的完整闭环叙事是 C61 里「设计一个 TSR 数据闭环」这道系统设计题的标准答案骨架 |

再往旁边看：**C57**（小目标检测）负责把「远距离标志」这一类难例在模型侧修好，
本课负责把它在数据侧持续供给；**C18** 是检测基本盘（mAP、PR 曲线、匹配逻辑），
本课默认你已经会算 AP；**C14**（数据与泛化）讲数据规模律的理论侧，
本课模块 05 的边际收益曲线是它的工程用法。

## 环境

见 `requirements.txt`。**纯 numpy + 标准库、CPU 可跑，不需要 GPU，
也不需要装 torch / faiss / mmdetection / cleanlab。**
本课复现的是这些系统的**数学与账本**——重采样后的期望频次、有效样本数、
不确定性的信息论分解、k-center 贪心的覆盖半径、幂律的拟合与外推、
配对显著性检验与 FDR 校正——而这恰恰是可迁移的那部分：
向量库会换、标注平台会换，这些式子不会。

每个模块末尾有一个 🧪 **真实工程胶囊**，把当天学到的东西翻译成可原样复制到
真实项目里的配置片段（采样器与损失的 config、触发器的阈值表、
挖掘流水线的任务定义、门禁脚本的判定规则）。
