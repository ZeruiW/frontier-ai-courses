1加了数据之后，必须回答的三个问题

模块 04 结束时，1200 张隧道口施工牌已经标完入库了。现在有人把它加进训练集，重训，跑了一遍评测，说「mAP 从 0.612 涨到 0.618，有效」。这句话里至少有三处站不住脚。本模块就是把这三处补上——这也是数据闭环里唯一真正难的一环：挖数据和标数据都有明确的产出物，只有「证明它有用」没有。

必须回答的问题不回答的后果本模块对应的工具
① 目标场景涨了吗？整体 mAP 涨了 0.6 点，可能全部来自晴天城区；你花钱修的隧道场景纹丝不动分场景切片评测（第 2 节）
② 其他场景掉了吗？隧道 +4.1，夜间城区 −2.3。整体看是涨的，但你刚刚让一个更常见的场景变差了回归门禁 + 数据配比（第 4、5 节）
③ 涨的部分是数据的功劳，还是噪声？换个随机种子重训，+0.6 变成 −0.2。你把一次抽样波动写进了周报显著性与多重比较（第 3 节）

直白说

这三个问题有一个共同的形状：它们都在追问「这个数字还能不能再被解释成别的东西」。① 追问平均值掩盖了什么；② 追问收益的另一面代价是什么；③ 追问随机性能不能单独解释它。能把这三问自动化成一套流程，数据闭环才算真正闭上；否则每一轮迭代都是在赌博。

严谨说

更精确地说，这是一个因果归因问题：我们想知道「加这批数据」这个干预（treatment）对「目标场景 AP」这个结果的因果效应。理想实验是同一模型、同一超参、同一评测集，只改训练数据这一个变量，重复多次取分布。而实践中几乎所有的「数据有效性结论」都是在单次训练、单个种子、单个整体指标上下的——这就是为什么「加了数据没效果」在工业界如此普遍：不是数据没用，是验证方法压根没有能力检出效果，或者反过来，把噪声当成了效果。

泄漏产生的提升，稳定到没人会怀疑

一个真实且极其常见的翻车路径：目标场景的数据既进了训练集，又（因为是同一批回传、同一段路）进了评测集。于是目标场景 AP 从 0.34 涨到 0.71，看起来是本季度最大的胜利，实际是数据泄漏。

模块 04 已经给过防线：划分必须按 clip / 路段 / 日期，而不是按帧。但闭环里还有第二道必须做的检查：新加入的训练 batch 与评测集做一次 ID 与近重复的交集检查，非空就直接拒绝这次实验——不是警告，是拒绝。因为泄漏产生的指标提升足够大、足够稳定，稳定到没人会怀疑它。

2分场景切片评测：平均值是用来骗人的

整体 mAP 是一个按样本数加权的平均。而车队数据的分布是极度长尾的——晴天白天城区可能占了评测集的 40%，雾天隧道占 1.5%。于是「雾天隧道 AP 掉 8 个点」在整体 mAP 上只体现为 −0.12，被任何一个其他场景的小幅波动淹没。这不是统计学的缺陷，是加权平均的定义。

同一次实验，两种读法 整体 mAP: 0.612 -> 0.618 (+0.6 点) "有效，合入" ───────────────────────────────────────────────────────────── 按场景切片看： 切片 n_eval base new Δ 判定 day_clear_urban 2400 .861 .869 +0.8 涨（但这不是我们花钱的地方） night_urban 720 .774 .751 -2.3 ◄── **回归！而且是常见场景** rain_highway 310 .706 .712 +0.6 涨 fog_tunnel 95 .341 .682 +34.1 ◄── 目标场景，确实修好了 snow_any 48 .559 .554 -0.5 噪声范围内 ───────────────────────────────────────────────────────────── 加权平均 = (2400*.869 + 720*.751 + ...) / 3573 = 0.618 ↑ fog_tunnel 的 +34 点，被 95/3573 = 2.7% 的权重压成了 +0.9 点的贡献 ↑ night_urban 的 -2.3 点，被 20% 的权重放大成 -0.46 点 结论：整体 +0.6 点里，**目标场景的贡献和一个未被发现的回归，恰好互相抵消了一部分**

切片该怎么设计

切片不是随便切的。一个能用的切片体系要同时满足三条：

  1. 切片来自失效模式，而不是来自数据字段。有 weather 字段就按天气切，是把工具当目的。正确的顺序是：先列出模块 03 的失效模式清单（远距离小目标、隧道逆光、广告牌误检……），每一个对应一个切片。切片是失效模式的可度量化身。
  2. 每个切片有足够的样本量。切片太细会让每个切片只有二三十张图，此时 AP 的抽样噪声大到任何结论都不可信。经验下界：目标类别的实例数 ≥ 200，或图片数 ≥ 100；不够就先合并，或者专门去补评测数据。
  3. 切片要正交且可组合，并且必须包含一个「整体/常见场景」切片作为回归哨兵。只盯着目标切片是本模块要反复强调的错误。

直白说

切片评测最直接的价值是把「模型变好了吗」变成一个有结构的答案：它在哪里变好了、哪里变差了、代价换在了哪。面试里被问「你怎么验证你的改动有效」，如果回答只有「mAP 涨了 0.8」，基本就到此为止了；如果回答是「整体 +0.8，其中目标切片 +34、夜间城区 −2.3，我们发现后者是数据配比导致的，调整后 −0.4 落在容差内」，这是完全不同的层次。

严谨说

但要警惕切片评测的反向失效：切片一多，「至少有一个切片显著变差」就成了必然事件——这是第 3 节要处理的多重比较问题。更隐蔽的是切片本身的漂移：如果切片的标签由 VLM 打（模块 04），而 VLM 换了版本，那么「fog 切片的 AP 变化」里就混进了「哪些图算 fog」的变化。评测集的切片标签必须冻结、版本化、且尽量人工核过——评测集是尺子，尺子不能跟着被测物一起变。

还有一个必须做但常被忘的切片：「新加入数据所属的场景」与「新数据没有覆盖的场景」要分开报。前者是你期望涨的，后者是回归风险最高的地方。把它们混在一张大表里，人眼会自动只看涨的那几行——所以报告模板要把「预期收益切片」和「回归哨兵切片」物理分成两块，并且回归块放在前面。

3涨了多少才不是噪声：配对检验与多重比较

检测任务在同一配置、只换随机种子时，mAP 的波动典型在 ±0.2–0.5 个点。这意味着「+0.3 的提升」本身没有任何信息量——它落在噪声带里。这是面试里最能立刻显出水平的一个点，也是模块 05 与 C61 模块 01 共享的核心方法论。

三个层次的随机性，来源不同、对策不同

随机性来源怎么表现怎么处理
评测集抽样噪声换一批评测图，AP 就变bootstrap 置信区间（对图像重采样）
训练随机性（种子）同配置重训，AP 变 ±0.2–0.5多种子重复（3–5 个），报均值 ± 标准差
多重比较切片一多，总有几个「显著」Bonferroni / BH-FDR 校正

最容易被跳过的是第二行。但它的代价最大：评测集噪声可以靠 bootstrap 量化（不用重训，几乎免费），种子噪声却必须真的重训 3–5 次。于是绝大多数团队的做法是「单种子 + 单次评测」，然后把 ±0.4 的随机波动当成结论——这是行业里最普遍的方法论债务。

配对（paired）比较：免费拿回大量统计功效

baseline 和新模型是在同一批图上评测的，所以两者的误差高度相关：一张本来就很难的图，两个模型都会做得差。对每张图算差值 d_i = s_new,i − s_base,i，再对 d 做统计，而不是分别对两组分数做统计——图像固有难度这一大块方差被直接抵消掉了。

\[\bar{d} = \frac{1}{n}\sum_i d_i, \quad \mathrm{SE} = \frac{s_d}{\sqrt{n}}, \quad z = \frac{\bar{d}}{\mathrm{SE}}, \quad p = 2\left(1 - \Phi(|z|)\right)\]

配对能把所需样本量降低一个数量级。notebook 里会实测：同一组数据上，非配对检验说「不显著」，配对检验说「p < 0.001」——而后者才是对的，因为前者把「有些图天生就难」也算进了噪声。

多重比较：切片一多，假阳性是必然的

假设你有 20 个切片，且新模型其实完全没有变化。在 α = 0.05 下，每个切片有 5% 的概率被误判为「显著变化」，那么至少出现一个假阳性的概率是 1 − 0.95²⁰ ≈ 64%。也就是说：只要你切片够多，每次实验都能「发现」一个回归或一个提升，而它们都是假的。

\[\text{FWER} = 1 - (1-\alpha)^m \xrightarrow{\ m=20,\ \alpha=0.05\ } 0.64, \qquad \text{Bonferroni: } \alpha' = \frac{\alpha}{m}\]
校正方法控制什么怎么算什么时候用
不校正什么也不控制—只有一个预先声明的主指标时
BonferroniFWER（一个假阳性都不要）阈值除以 m回归门禁——宁可漏报也别乱报警
Benjamini–HochbergFDR（假阳性占比 ≤ q）按 p 排序，找最大的 k 使 p₍k₎ ≤ k·q/m探索性分析——找「哪些切片值得深挖」

直白说

选哪个取决于你更怕哪种错。回归门禁怕的是「误报」——每次误报都会浪费一个工程师半天去查一个不存在的回归，久了就没人看门禁了，那才是真正的灾难。所以门禁用 Bonferroni（保守）。而在探索阶段，你想知道「哪几个切片可能有问题、值得看看」，漏掉真问题比多查两个更亏，所以探索用 BH-FDR（宽松但可控）。

严谨说

还有一个更本质的做法可以避开整个多重比较问题：预注册（pre-registration）——在跑实验之前就声明「这次实验的主指标是 fog_tunnel 切片的 AP，回归哨兵是 day_clear_urban 和 night_urban 两个切片」。预先声明的少数几个指标不需要重校正，事后翻遍 20 个切片找亮点才需要。「先声明再看数」这个纪律，比任何统计校正都有效——它把 p-hacking 从源头上堵住了。这条在 C61 模块 01 里会展开。

一句能直接用的话：「我们要求提升必须同时满足三条：① 效应量超过预设容差；② 配对检验在多重比较校正后仍显著；③ 在 3 个种子上方向一致」。这三条互相独立地排除了三类假象（太小、随机、种子运气）。面试里说出这句，比说任何一个具体的统计量都有说服力。

4回归门禁：旧场景不掉点是硬门槛

闭环的最后一道闸门是regression gate（回归门禁）：一个自动运行、输出 PASS/FAIL、且 FAIL 就不允许发布的判定器。它存在的意义不是「监控」，而是把「不掉点」这件事从人的自觉变成流程的强制——因为每一轮迭代都有交付压力，而「先合进去、回归下轮再修」在感知系统上是不可接受的。

直白说

门禁最大的敌人不是统计学，是人。一个天天误报的门禁，三周内就会演化出「加 --skip-gate 参数」的文化，然后它就等于不存在了。所以门禁的第一设计目标是「误报率足够低，低到 FAIL 出现时所有人都相信它是真的」——这比「不漏报」更重要。宁可容差设宽一点、只守住真正要命的几个切片，也不要建一个覆盖 50 个切片但天天红的门禁。

严谨说

第二个要提前想清楚的是门禁的可解释输出。FAIL 之后，工程师需要在几分钟内知道「哪个切片、掉了多少、置信区间多宽、有多少张图变差了、变差的是哪几张」。一个只输出 FAIL 的门禁，会把定位成本推给下游，最终还是没人用。所以门禁的产物应该是一份结构化报告：切片表 + 置信区间 + 变差样本的 top-20 列表 + 与上一版的 diff。这份报告本身就是模块 04 里下一轮挖掘的输入——闭环在这里真正闭上了。

门禁的尺子不能跟着被测物一起变

门禁必须跑在一个「不参与本轮挖掘」的评测集上。如果评测集也在按「当前模型最弱的场景」持续补充（模块 04 的缺口矩阵驱动），那么评测集会和训练集一起漂移，门禁就在自己给自己出题。

规范做法：维护两套评测集——① 固定基准集（按部署真实分布随机采样，冻结，只在版本升级时整体替换，是回归门禁的唯一依据）；② 失效模式集（每个失效模式一个小集合，随挖掘持续扩充，用来看目标场景有没有修好）。把这两套混用，是数据闭环最常见的系统性错误。

5灾难性遗忘与新旧数据配比

上一节的门禁会 FAIL，最常见的原因不是新数据有问题，而是新数据太多了。加进 1200 张隧道场景，如果训练时对它们做了 10× 的重采样（因为「稀有类要加权」），那这一个场景就占了每个 batch 的相当比例，模型会以牺牲其他场景为代价去拟合它。

两种不同的机制，别混为一谈

机制发生条件表现对策
数据饥饿（starvation）总训练量固定，新数据挤占了旧数据的采样份额旧场景 AP 缓慢下降，且与被挤占的比例成正比加总训练量，或按饱和度分配采样权重
灾难性遗忘（catastrophic forgetting）顺序训练 / 微调，只用新数据更新权重旧场景 AP 断崖式下降（可以掉 10+ 点）混合重放（rehearsal）：新旧数据混在同一个 batch 里
特征竞争新旧场景的最优特征互相冲突（如低光增强 vs 正常光）两边都不到位，容量不足的小模型尤其明显扩容 / 分支 / 场景条件化

最关键的一条实践结论：不要「拿新数据微调」，要「把新数据混进全量重训」。 前者省算力但会触发真正的灾难性遗忘（旧场景断崖下跌）；后者贵，但旧场景只会因为采样份额被稀释而缓慢下降，而且这个下降是可以用配比精确控制的。在量产感知系统里，全量重训几乎总是默认选项——除非算力实在不允许，此时也必须做重放（rehearsal），即把旧数据的一个代表性子集混进微调。

配比的最优点是内点，不是端点

把新场景数据的比例记为 p（占每个 batch 的比例）。新场景 AP 随 p 单调上升但很快饱和；旧场景 AP 随 p 单调下降且加速下降。于是「在旧场景不掉超过 tol 的前提下最大化新场景 AP」这个约束优化问题，答案几乎总是一个内点——典型落在 10%–30%。

\[p^{\star} = \arg\max_{p\in[0,1]} \ \mathrm{AP}_{\text{new}}(p) \quad \text{s.t.} \quad \mathrm{AP}_{\text{old}}(p) \ \ge\ \mathrm{AP}_{\text{old}}(0) - \text{tol}\]

直白说

为什么「几乎总是内点」值得单独强调？因为两个端点都对应着一种常见的错误直觉：p 很小（比如按自然分布，隧道场景占 1.5%）= 「加了数据但没效果」的头号原因；p = 1（只用新数据微调）= 灾难性遗忘。而中间那一段有一个明确的最优点，它由「新场景的饱和速度」和「旧场景的容差」共同决定，是可以算出来的，不需要猜。

严谨说

工程上实现配比有三种粒度，效果和代价递增：① 重复采样（oversampling）——把新数据在采样列表里重复 k 次，最简单，但会加剧对这几百张图的过拟合；② 加权采样器（weighted sampler）——按场景标签给采样概率，等价于连续可调的 p，是推荐做法；③ 损失加权——不改采样，改 loss 权重，梯度效果类似但对 BN 统计量的影响不同（BN 看到的仍是原分布，这个细微差别在小模型上有时会显现）。面试里能说清「重采样和损失加权不完全等价，差别在 BN 与数据增强的暴露次数」，是一个不错的加分点。

别忘了评测集的配比不能跟着训练集动。有人在调 p 的同时，也把评测集里目标场景的比例调高了「以便看得更清楚」——于是整体 mAP 的含义变了，与历史版本不可比。训练分布可以随便调，评测分布必须冻结。要「看得更清楚」就去看切片 AP，而不是改评测集的构成。

6边际收益曲线：还值不值得继续标

这是本模块、也可以说是整门课最有实用价值的一个工具。问题非常具体：隧道场景已经标了 1200 张，AP 从 0.34 涨到 0.68。要不要再标 2000 张？「再标标看」不是答案，「标到 AP 0.85 为止」也不是答案——因为你并不知道 0.85 是否可达。

把 AP 对数据量的关系拟合成一条饱和曲线

在同一场景内，AP 随该场景训练样本数 n 的增长，经验上非常接近一条指数饱和曲线（也有用幂律的，工程上两者都够用，指数式的参数更好解释）：

\[\mathrm{AP}(n) = A_\infty - (A_\infty - A_0)\,e^{-n/\tau}\]

三个参数各有明确的工程含义，这才是这个模型真正的价值：

参数含义它回答什么问题
A∞（渐近线）数据加到无穷时这个场景能达到的 AP「继续标数据的天花板在哪」——这是最重要的一个数
τ（时间常数）每积累 τ 张样本，与天花板的差距衰减到 1/e「还要多久才能接近饱和」
A₀零样本（只靠其他场景泛化）时的 AP「这个场景的迁移基线有多高」

三个可以直接拿去用的决策规则

有了拟合的 (A∞, τ, A₀)，下面三个量都是闭式的：

\[\Delta_{\text{next}}(n, B) = \big(A_\infty - \mathrm{AP}(n)\big)\left(1 - e^{-B/\tau}\right), \qquad n^{\star}(\text{target}) = -\tau \ln\!\frac{A_\infty - \text{target}}{A_\infty - A_0}\]
  1. 下一批还能涨多少：Δ_next(n, B)。这直接给出「再标 B 张的预期收益」，可以和成本对比：每提升 1 个 AP 点要花多少钱。
  2. 达到目标要标多少：n*(target)。如果 target ≥ A∞，公式返回无穷——这就是「不可达」的数学表达，也是最有价值的一个输出。
  3. 什么时候停：当「每千张样本的预期 AP 提升」低于阈值（例如 0.3 点/千张），或者「每 AP 点的成本」超过预算上限时，停止标注。把这条写成自动判据，就不会有人凭感觉说「再标点吧」。

直白说

这条曲线最大的作用是把「还标不标」从一个立场之争变成一个算术题。 数据团队说「再标」、算法团队说「该改模型」，两边其实在争论同一个未知数 A∞。拟合出来一看：A∞ = 0.79，产品目标 0.85，那就没什么可争的了——继续标注不可能达标，讨论应该立刻转向「换什么方法」。反过来，如果 A∞ = 0.88 而当前 0.68，那就闭嘴接着标。

严谨说

拟合本身有几个必须注意的地方。① 至少要 4–5 个数据点，且要横跨一个数量级（比如 200 / 500 / 1200 / 3000 张），只有两个点拟合不出饱和形状。这意味着标注必须分批进行、每批都重训并评测——「一次标 5000 张」不但风险高，还让你永远拿不到这条曲线。② 每个点的 AP 本身带噪声（种子 + 评测抽样），所以要给拟合出的 A∞ 一个置信区间，用区间下界做决策更稳。③ 曲线只在「其他条件不变」时成立——中途换了 backbone 或改了增强，曲线就得重拟。

把这一节压成面试答案：「我们对每个重点场景维护一条边际收益曲线。标注分批做，每批重训后测该切片 AP，拟合 AP(n) = A∞ − (A∞ − A₀)e^{−n/τ}。用 A∞ 判断天花板是否够得着目标，用 ΔAP/千张 与标注单价换算出「每个 AP 点多少钱」，低于阈值就停止标注、转向方法改进。」 这段话同时体现了三件事：数据决策是量化的、你知道数据不是万能的、你会算成本。

7影子评测与 A/B：离线指标之外的最后一道关

离线指标全绿了，就能上车吗？不能。离线评测集是历史数据的一个快照，而车上跑的是此刻的、连续的、有时序的、经过完整软件栈的真实世界。这两者之间有一条系统性的鸿沟，需要两种额外的验证方式来跨越。

验证方式怎么做能发现什么代价 / 局限
离线切片评测历史数据 + 标注精度类问题、回归看不到时序稳定性、看不到与下游的交互
影子模式（shadow mode）新模型在车上与旧模型并行推理，但输出不接管控制，只记录分歧真实分布下的差异、分歧场景、算力与延迟的真实表现占额外算力；只能看到分歧，没有真值
回灌 / 重放（replay）用录制的原始传感器流重跑完整软件栈端到端一致性、时序行为、与跟踪/融合的交互需要完整的回放基础设施
灰度 A/B小比例车辆用新模型，对比业务指标接管率、误报投诉、真实体验周期长、样本量要求高、有安全风险

影子模式为什么是数据闭环的枢纽

影子模式常被当成「上车前的最后一道保险」，但它更大的价值在别处：它是一个高质量的触发器。新旧模型的分歧本身就是极好的挖掘信号——两个模型意见不一致的地方，几乎必然是难例、边界样本、或标注规范有歧义的地方。这些帧回传去标，就是下一轮的高价值数据。于是「验证」和「挖掘」在这里合成了同一个动作（这也呼应模块 03 讲的一致性触发）。

直白说

影子模式的核心限制必须说清楚：它没有真值。 你只知道「新模型说有牌、旧模型说没有」，不知道谁对。所以影子模式的输出永远是「分歧率」和「分歧样本」，不是「新模型更好」。要把分歧变成结论，必须再走一次人工标注（抽样即可）。把「分歧率下降」当成「模型变好」是一个典型的误读——分歧率下降也可能是新模型变得更像旧模型了。

严谨说

A/B 测试在自动驾驶上有两个和互联网产品完全不同的约束。① 指标极度稀疏：接管、误刹这类事件的发生率可能是 10⁻⁵/km 量级，要检出 10% 的相对变化需要天文数字的里程——所以实践中会用代理指标（perception-level 的误报率、规控的介入次数）而不是最终安全指标。② 有真实安全风险：不能像做推荐系统那样「先上 5% 流量看看」。所以行业标准路径是「影子 → 内部车队 → 有限 ODD 灰度 → 全量」的分阶段放开，每一阶段都有独立的退出准则与回滚预案。

一个反复出现的现象：离线指标涨了，路测体验反而变差。最常见的三个原因是——① 离线评测是逐帧的、路测体验是时序的（模型变「敏感」了，AP 涨但检测框闪烁，下游状态机反复跳变）；② 离线用 mAP、体验取决于某个工作点的 FP 率（PR 曲线整体右移，但你实际用的那个 score 阈值处反而变差）；③ 评测集与真实分布脱节。对策：评测里必须包含时序稳定性指标（闪烁率、首检距离）与固定工作点的 FP/km——这两个是 C55 模块 05 的重点。

8把闭环做成流水线：产物、门禁与周期时间

前面所有环节，如果靠人工串联，实际会变成「工程师 A 挖数据 → 邮件给标注 → 三周后收到 → 工程师 B 训练 → 忘了跑切片评测 → 合入」。闭环的价值不在于每个环节多聪明，而在于它是否真的能一圈一圈自动转起来。所以最后一步是把它做成一条有明确产物与门禁的流水线。

闭环的核心度量：周期时间（cycle time）

闭环系统真正该被优化的指标，不是任何一个模型指标，而是「从发现问题到修复上线」的天数。因为长尾问题是源源不断的——你永远不可能一次修完，能决定竞争力的是转一圈要多久。

直白说

「返工率」这一行值得特别注意，因为它的影响是乘性的而不是加性的。 假设一轮 25 天、门禁通过率 60%，那么期望轮数是 1/0.6 ≈ 1.67 轮 → 期望周期 ≈ 42 天。把通过率从 60% 提到 85%，期望周期直接降到 29 天——效果比把标注速度提升 30% 还大，而且便宜得多。提高一次通过率的手段很具体：在训练前就先跑一遍「配比预演」、在标注前先小批量试标验证规范、在门禁前先跑轻量的自检。

严谨说

另一个反直觉但重要的点：缩短周期时间往往要靠「减少每轮的雄心」，而不是靠加速每个环节。一轮同时修 5 个失效模式，任何一个出问题整轮都卡住，且归因困难（到底是哪批数据导致夜间回归？）。拆成 5 个独立的小轮次，每轮只改一件事，周期更短、归因更清晰、返工代价更低。这与软件工程里「小批量、快反馈」的结论完全一致，而且在数据闭环上更成立——因为数据的因果归因比代码难得多。

把整个 C58 压成一句：「模型架构会趋同，数据飞轮不会。而数据飞轮的竞争力不在于你挖到了多好的数据，在于你转得有多快、每一圈都真的证明了自己有用。」 面试里被问「你怎么看数据闭环」，从「周期时间」和「一次通过率」切入，比罗列一堆挖掘算法更有说服力——因为前者说明你理解这是一个系统工程问题。

9研究前沿与开放问题

闭环验证是工程与统计的交界地带，也正因为如此，它有一批既没有理论答案也没有工程共识的问题。

  • 数据缩放律在检测与长尾上的形式。语言模型的 scaling law 已经很成熟，但「某个子分布的性能随该子分布样本数如何增长」缺少同等严谨的刻画。本模块用的指数饱和曲线是经验拟合，幂律形式（AP ≈ A∞ − c·n^{−α}）在有些场景拟合得更好——两者对「天花板」的外推差别很大，而外推恰恰是我们要用它做的事。「用几个点外推 A∞ 的置信区间」目前没有好方法。
  • 数据贡献的因果估计。「这 1200 张让 AP 涨了多少」严格说是一个反事实问题，现在的答案靠「训两次做对比」，成本极高且被种子噪声污染。influence functions、datamodels、data Shapley 试图给出更便宜的估计，但在检测任务、非凸优化、千万级数据上仍不实用。
  • 持续学习的评测标准。灾难性遗忘的度量（backward transfer、forgetting measure）来自持续学习文献，但工业场景是「全量重训 + 配比」，与学术设定（严格顺序、不能回看旧数据）不同。「工业配比式持续更新」缺少标准的评测协议与基准，导致各家的「不遗忘」都是自己定义的。
  • 离线-在线指标的鸿沟。为什么离线 mAP 涨了路测体验会变差，目前的解释是零散的（时序稳定性、工作点、分布脱节）。「什么样的离线指标能可靠预测在线体验」是一个开放问题，也是自动驾驶评测领域最有价值的研究方向之一。相邻领域（推荐系统的离线-在线一致性）有一些可借鉴的方法论，但迁移得并不好。
  • 门禁的自动化与自适应。容差与显著性阈值目前都是手工设定的常数。能否根据历史波动自动标定每个切片的容差、能否用序贯检验（sequential testing）在样本积累过程中动态决策，是一个明确可做但少有系统工作的方向。序贯分析（always-valid p-values、e-values）在 A/B 领域已有成熟工具，尚未系统进入感知闭环。
  • 合成数据与真实数据的等价性度量。如果一张合成的雪夜施工牌能顶 0.3 张真实数据，边际收益曲线该怎么算？「合成数据的有效样本数」缺少可操作的定义，而这直接影响标注预算该不该花。
  • 闭环的长期稳定性。每一轮都按「当前最弱场景」补数据，长期迭代后训练分布会持续偏离真实分布。这个反馈系统会收敛、震荡、还是发散？目前只有工程上的经验对冲（固定比例随机采样、冻结基准集），缺少理论刻画。这可能是数据闭环里最深、也最少被讨论的问题。
