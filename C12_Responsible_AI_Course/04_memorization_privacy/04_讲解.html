1记忆化为何是隐私问题

到目前为止，本课度量的都是模型对不同人群的不公（公平、毒性、多语）。这一模块换一类伤害——模型对训练它的那些人的隐私威胁：大语言模型会逐字（或近逐字）地背下训练语料里的片段，并在适当的提示下把它们吐出来。

这件事的严重性在于它一箭三雕地触发三类风险：① 隐私——训练数据里的真实姓名、地址、电话、邮件被原样复现（Carlini 2021 真的从 GPT-2 提取出了在世个人的联系方式）；② 版权——逐字复现受版权保护的文本、代码；③ 评测污染——模型把测试集的答案背了下来，导致基准分数虚高（这正好把本课和前几门能力评测课接上：记忆是数据污染的微观机制）。

记忆化的关键观念是把它当成一个可测量的量，而不是一个有/无的开关。Carlini 2021 给了一个分级定义 k-eidetic memorization：一段在训练集中只出现 ≤ k 次、却能被模型逐字复现的字符串。k 越小越触目惊心——只出现一两次就被背下意味着模型在做的远不止 “学习统计规律”。本模块就是要把 “模型记住了多少”“外人能提取多少”“某条数据在不在训练集” 这三个问题，全部变成 numpy 能算出的数字。

为什么记忆几乎不可避免？因为训练目标（最大化训练数据的似然）和 “逐字记住训练数据” 在数学上是同向的——把一段文本的概率压到极高，最极端的方式就是把它背下来。模型容量越大、某段数据重复越多、训练越久，这种 “顺手就记住了” 的压力就越强。所以记忆不是 bug，而是最大似然训练的副产品；问题不在于 “能不能完全消除”（不能），而在于如何度量它、评估它能被利用到什么程度、并用代价可控的手段把高风险的那部分压下去。这正是隐私评测区别于 “我们做了脱敏所以没问题” 这种空头承诺的地方。

还要厘清一个常见混淆：记忆不等于过拟合的传统定义。一个在测试集上泛化良好（低泛化误差）的模型，依然可能逐字记住了训练集里成千上万条罕见样本——泛化与记忆可以并存。Feldman 2020 甚至论证：对长尾分布，记住罕见样本是达到最优泛化的必要手段。这就埋下了本模块反复出现的张力：有用的记忆（学到知识）与有害的记忆（背下隐私）共享同一套机制，无法靠 “别记那么多” 一刀切，只能靠精细的度量与针对性缓解。

一句话抓住本模块：记忆 = 模型对见过的数据给出反常的高置信（低损失）。无论是 canary 暴露度、提取攻击，还是成员推断，底层信号都是同一个——见过的样本，损失低得不正常。把这个信号量化、并诚实地评估它能被攻击者利用到什么程度，就是隐私评测的全部。

2canary 与暴露度

canary 与暴露度：往训练集里埋探针

怎么测一个模型 “记住了多少”？最干净的做法是主动埋探针。Secret Sharer（Carlini 2019）的思路：往训练语料里插入一条随机生成、与任何真实数据无关的唯一字符串，叫 canary（金丝雀，取自矿工用金丝雀探测毒气的典故），例如 The secret code is 8 2 7 3 5 1。训练后看模型对这条 canary 的偏好有多反常——偏好越反常，记得越牢。

怎么量化 “偏好反常”？关键是和一群同格式的随机候选比。设 canary 的填空槽有 R 种可能取值（比如 6 位数字就有 $10^6$ 种），把真实 canary 和所有候选按模型给的对数似然（log-likelihood）从高到低排序，真 canary 的名次记作 rank。暴露度定义为：

\[\mathrm{exposure}(c) \;=\; \log_2 |R| \;-\; \log_2 \mathrm{rank}(c)\]

直白说

如果模型没记住 canary，它对真 canary 和随机候选一视同仁，真 canary 的名次大致落在正中间（$\mathrm{rank}\approx|R|/2$），暴露度 ≈ 1，接近 “纯属偶然”。如果模型把 canary 背得滚瓜烂熟，真 canary 会排到第 1 名（$\mathrm{rank}=1$），暴露度 = $\log_2|R|$ 达到最大。暴露度就是 “这个串被模型偏爱的程度” 的对数尺度。

严谨说

为什么取对数？因为 rank 的分布在 “没记住” 时近似均匀，暴露度 $=\log_2|R|-\log_2\mathrm{rank}$ 在零假设下近似服从一个良性分布，使 “暴露度显著高于 $\log_2|R|$ 的一半” 成为一个有统计意义的判据。Carlini 2019 证明暴露度还能换算成 “需要枚举多少候选才能靠模型把 canary 提取出来”，把一个抽象的记忆量直接接到提取攻击的代价上。

canary 法的精妙之处在于它绕开了 “真值” 难题。要测真实 PII 被记住多少很麻烦：你得先知道训练集里有哪些 PII、它们各自重复了几次，而这些往往不可得。canary 则是你自己埋下的、完全受控的探针——你知道它的确切内容、确切插入次数、确切候选空间，于是暴露度成了一个可校准、可比较的标准刻度。想知道 “重复 10 次会被记住到什么程度”？埋一条重复 10 次的 canary，量它的暴露度即可。这就是为什么 Secret Sharer 成了记忆审计的事实标准：它把 “模型会不会泄露我的数据” 这种焦虑，变成了一个有受控实验、有数字、可复现的科学问题。

本模块 notebook 会用一个玩具计数模型完整复现：插入一条 canary，构造 $|R|$ 个同格式候选，算每个候选的损失、给真 canary 排名、套上面的公式得到暴露度——并验证 “插入次数越多，暴露度越高” 这条 Carlini 反复观测到的规律。一个实现细节值得留意：完整候选空间 $|R|=10^6$ 太大无法穷举，我们用一批随机候选估计 rank（真 canary 在样本中的相对位次按比例放大到 $|R|$），平局对半分，使未记住的 canary 自然落在暴露度 ≈ 1 处——这正是从样本估计总体排名的标准做法。

3可提取记忆 vs 仅仅记住

可提取记忆 vs 仅仅记住

记住不等于可提取。extractable memorization（Carlini 2021）要求更强：不仅模型内部编码了这段数据，而且存在一个现实可行的提示能把它问出来。这才是攻击者真正能利用、隐私上真正危险的那部分。区分二者很重要——一段被记住但永远问不出来的数据，隐私风险远低于一段随手就能套出来的数据。

Carlini 2021 的提取流程是：用大量种子提示让模型生成，再用一个成员资格信号（如极低的困惑度 perplexity、或多个模型 / 多种温度下的一致性）给生成结果打分，挑出最可能是逐字记忆的样本去核对。他们由此从 GPT-2 提取出数百条逐字训练样本，含真实 PII。更惊人的是 Nasr 2023 的发散攻击（divergence attack）：让对齐后的 ChatGPT 重复某个词上千次，模型会 “跑飞” 进而吐出训练数据——证明对齐（alignment）并不消除记忆，只是盖住了入口。

这里的区分对评测的实际含义是：暴露度（上一节）衡量的是模型固有的记忆程度，它不随攻击手段变化、是模型一旦训练好就钉死的属性；而 “能提取多少” 衡量的是当前攻击把这份记忆兑现成实际泄露的能力，它会随攻击技术进步而单调上升。两者之间的差，就是 “模型确实记住了、但今天还没人能问出来” 的那部分——它不是安全余量，而是尚未兑现的风险。一个负责任的隐私报告必须把这两个数都给出来，并明确：提取攻击给的是下界，明天更强的攻击只会让这个下界往上抬，绝不会往下掉。

评测上的教训：“我们没提取到” 不等于 “模型没记住”，更不等于 “安全”。提取是攻击者能力的下界——你的红队没问出来，不代表更强的攻击者问不出来。负责任的隐私评测要同时报告 “记住了多少”（暴露度，模型固有属性）与 “当前攻击能提取多少”（随攻击进步而上升的下界），并把二者的差距视为未知风险而非安全余量。

4成员推断攻击（MIA）

成员推断攻击（MIA）：你在不在训练集？

隐私的另一条主线是 membership inference attack（成员推断，MIA，Shokri 2017）：给定一条具体样本和对模型的访问权，判断这条样本是否在模型的训练集中。它既是攻击，也是审计工具——如果攻击成功率显著高于抛硬币，就证明模型泄露了 “谁在训练集里” 这一成员信息。

为什么这是隐私问题？设想一个用 “某医院糖尿病患者病历” 微调的模型。若攻击者能确认 “张三的记录在训练集里”，他就推断出张三是糖尿病患者——即使模型从没吐出张三的病历原文。成员资格本身就是敏感信息。MIA 因此是衡量隐私泄露最通用的标尺，也是差分隐私（DP）想要形式化封堵的攻击。

MIA 之所以被当作隐私的通用度量，还有一个更深的原因：它是几乎所有隐私威胁的公分母。数据提取要先能区分 “这段是不是训练数据”（本质是成员推断）；属性推断（推出某人的敏感属性）通常以成员推断为前置；连差分隐私的形式化定义，骨子里就是 “限制任何成员推断攻击的成功率”。所以把 MIA 的 ROC 测准，等于给一个模型的隐私泄露上了一把通用的标尺——这也是为什么本模块把它和模块 00 的混淆矩阵基建直接对接：member / non-member 就是两个类，模型 loss 就是分数，隐私攻击的强弱最终落成一条 ROC 曲线。

成员推断的威胁模型 攻击者：拿到 目标样本 x + 对模型的查询权（至少能拿到 loss/置信度） │ ▼ 信号：模型在 x 上的 loss（或 perplexity / 置信度） │ 见过的样本(member) → loss 偏低 │ 没见过(non-member) → loss 偏高 ▼ 判决：loss < 阈值 ⇒ 判为 member → 扫阈值画 ROC / 算 AUC │ ▼ 泄露程度：AUC 越高于 0.5、低 FPR 区 TPR 越高，隐私泄露越严重

注意 MIA 与本课模块 00 立下的度量基建完全同构：member / non-member 就是两个 “类”，模型 loss 就是分数，扫阈值就得到 ROC——隐私攻击的成败，落到最后还是一张混淆矩阵。

5loss 阈值攻击与它的 ROC

loss 阈值攻击：最简 MIA 与它的 ROC

最简单的 MIA 是 loss-threshold attack：训练样本上模型损失通常更低（模型见过、拟合过它们），于是规则就是 “loss 小于阈值 τ 则判为成员”。这是 MIA 的入门基线，也是理解 “隐私泄露 = 两个损失分布可分离” 的最直观方式。

把成员的损失分布记作 $p_{\mathrm{in}}(\ell)$、非成员的记作 $p_{\mathrm{out}}(\ell)$。扫遍阈值 τ，真阳率与假阳率分别是：

\[\mathrm{TPR}(\tau)=\Pr_{\mathrm{in}}[\ell<\tau],\qquad \mathrm{FPR}(\tau)=\Pr_{\mathrm{out}}[\ell<\tau]\]

把 $(\mathrm{FPR}(\tau),\mathrm{TPR}(\tau))$ 连成 ROC 曲线，曲线下面积 AUC 有一个免积分的等价定义（Mann–Whitney 统计量）：随机抽一个成员、一个非成员，成员损失更低（更像成员）的概率。AUC = 0.5 表示攻击毫无信息（完美隐私），越接近 1 泄露越严重。notebook 会用纯 rank 统计从零实现 AUC，不依赖任何库。

这套流程和本课模块 00 立下的度量基建一模一样，只是换了语义：把 “成员” 当正类、“非成员” 当负类，把 “loss 越低越像成员” 当分数，扫阈值就得到混淆矩阵、ROC、AUC。换句话说，隐私攻击的成败最终落成一张你已经会算的混淆矩阵——这也是为什么本课坚持先把混淆矩阵基建打牢：公平、毒性、隐私三类看似无关的伦理问题，到了度量层面共用同一套工具。唯一要小心的是方向：毒性里分数高代表 “更像正类（有毒）”，而 MIA 里 loss低才代表 “更像成员”，所以实现 AUC 时要把成员性分数取成 $-\ell$，否则 AUC 会算反（得到 $1-\mathrm{AUC}$）。

直白说

直觉：两个损失分布离得越开，阈值就越能把成员和非成员分开，AUC 越高。模型对训练数据 “过拟合” 得越狠（见过的损失压得越低），这两个分布就拉得越开，隐私泄露越严重。这也解释了为何小数据、多 epoch、大模型更易泄露——它们都加剧了对训练样本的过拟合。

严谨说

严谨地说，loss 阈值法假设 $p_{\mathrm{in}}$ 与 $p_{\mathrm{out}}$ 只差一个全局平移，对每条样本一视同仁地用同一个阈值。这正是它的弱点：有些样本天生就好预测（损失低但并非因为被记住），有些天生难（损失高却可能是成员）。下一节的 LiRA 正是冲着这个弱点来的。

6LiRA：平均 AUC 会骗你

LiRA：为什么平均 AUC 会骗你

Carlini 2022（LiRA，Likelihood Ratio Attack）指出旧 MIA 评测的一个致命问题：用平均 AUC（或平均准确率）汇报攻击，会掩盖真实的隐私风险。原因是隐私伤害是个体化的——攻击者只要能高置信地确认少数几个人在训练集里，对那几个人就是灾难，哪怕对其余大多数人攻击都失败、平均 AUC 看起来温和。

正确的度量是看 ROC 的低假阳率区：在 FPR = 0.1% 这种 “几乎不冤枉无辜” 的工作点上，TPR 有多高？这才对应 “攻击者敢于断言、且很少出错” 的真实威胁。LiRA 的做法是为每条样本训练许多 shadow model（影子模型，模仿目标模型行为的替身），分别在 “该样本是成员 / 非成员” 两种情况下估计其损失分布，再对目标做似然比检验。这把 “一刀切的全局阈值” 升级成 “针对每条样本校准的检验”，在低 FPR 区的 TPR 比 loss 阈值法高出几个数量级。

为什么 “每条样本校准” 这么关键？因为 loss 阈值法的隐含假设——所有样本共用一个阈值——对难易不均的样本是灾难性的。一句常见套话（“the cat sat on the mat”）天生 loss 就低，哪怕模型从没见过它；一个罕见的人名地址天生 loss 就高，哪怕模型背得滚瓜烂熟。用全局阈值，前者会被误判成成员（假阳），后者会被漏判（假阴）。LiRA 的破解是问一个相对的问题：对这一条具体样本，模型在它上面的 loss，相比 “如果它没被训练过” 的预期 loss，低得是否反常？这个 “与自己的反事实比” 的相对信号，剔除了样本固有难易的干扰，正是它在低 FPR 区碾压全局阈值的原因。本模块 notebook 用一小撮重复多次的罕见样本演示了这个尾部效应的雏形——它们整体 AUC 不高，却在极低 FPR 处被 100% 抓出。

平均数会骗人

这是本模块最重要的评测教训，且和模块 04 的精神完全一致：永远不要用一个平均数下隐私结论。一个 “平均 AUC = 0.55，看起来还行” 的模型，完全可能在 FPR = 0.1% 处对某些异常样本（罕见姓名、独特病历）有 90% 的 TPR——对那些人隐私已被击穿。报告 MIA 必须给出对数尺度的 ROC并明确低 FPR 区的 TPR；只报平均 AUC 是不负责任的，正如模块 01 只报整体准确率会掩盖子群崩盘。

notebook 会在玩具数据上把这一点演示透：构造一小撮 “异常易记” 的样本，显示它们即使在整体 AUC 不高时，也能在极低 FPR 处被高置信识别——亲眼看到平均数如何掩盖尾部风险。

7缓解：去重与差分隐私

缓解：去重最划算，差分隐私最彻底

既然记忆是隐私的根源，怎么压它？两条主线，代价与彻底程度不同：

缓解手段机制代价效果
训练数据去重 deduplication删掉语料里重复 / 近重复的文本一次性数据清洗，几乎不损能力（反而常提升）强：重复次数↓→记忆↓，提取风险大幅下降
差分隐私 DP-SGD训练时裁剪梯度 + 加噪声，证明性地限制单样本影响效用明显下降、训练变慢、超参敏感最彻底：对 ε 给出可证明的成员推断上界
输出过滤 / n-gram 拦截生成时屏蔽与训练集逐字匹配的片段只挡逐字复现，绕过容易（改一个词即可）弱：治标，应对版权逐字复现尚可
早停 / 正则减少对训练样本的过拟合可能牺牲性能中：缩小 in/out 损失分布间隔

为什么去重被反复强调为 “性价比之王”？因为记忆强烈依赖重复次数：Lee 2022、Kandpal 2022、Carlini 2022 一致发现，一段文本在训练集里出现得越多，被逐字记住的概率越高（近似超线性）。去重把高频重复的样本砍到低频，直接掐断最易被提取的那部分记忆——而且去重还顺带提升模型质量（减少对重复内容的过度加权）。一次数据清洗，隐私和性能双赢，这就是为什么它几乎是当前所有大模型训练的标配第一步。

差分隐私（differential privacy）则提供可证明的保证：形式上要求 “单条样本的有无，对输出分布的影响被 ε 限制”，从而给成员推断的成功率一个数学上界。代价是 DP-SGD 的噪声会拖累效用、且对长尾、低资源数据伤害更大（又和模块 03 的公平问题缠在一起）。负责任评测要报告的不是 “我们用了 DP”，而是缓解后的残余风险：去重后 canary 暴露度降了多少、DP 后 MIA 在低 FPR 区的 TPR 降到哪——这才对部署决策有意义。

把缓解当成一次评测前后对照来做，是本模块想留给你的工作流：先在缓解前测一组基线（一批 canary 的暴露度、MIA 的 ROC 尤其低 FPR 区的 TPR），施加缓解（去重 / 早停 / DP），再测同一组指标，报告下降幅度与残余值。notebook 的去重实验就是这个工作流的最小版——去重前后各算一次 canary 暴露度，用差值量化缓解的实际效果。这比 “我们采取了隐私保护措施” 这种无法证伪的说法有用得多：一个能写出 “暴露度从 6.4 降到 2.0、残余 MIA AUC 0.52” 的报告，才真正进入了可问责的隐私评测。

8研究前沿与开放问题

研究前沿与开放问题

  • 记忆的规模律：Carlini 2022 给出记忆随模型规模、数据重复次数、上下文长度单调上升的经验规律，但 “多大的模型 + 多少重复 = 多少记忆” 仍缺乏可预测的闭式模型，给隐私审计带来不确定性。
  • 提取攻击的天花板：Nasr 2023 的发散攻击表明对齐模型仍可被提取，攻击仍在快速进步。今天的 “提取不到” 是会过期的安全声明——如何报告一个随时间贬值的风险下界，本身就是开放问题。
  • MIA 的真实威胁标定：LiRA 之后，社区转向低 FPR 区的 TPR，但不同数据分布、不同访问权限（仅 logits？仅文本？仅 API？）下的可比报告规范尚未统一，使跨论文的隐私结论难以横向比较。
  • 记忆 vs 泛化的纠缠：有用的泛化和有害的记忆共享同一套机制（Feldman 2020），彻底消除记忆可能损害能力。在 “记住有益知识” 与 “背下私密数据” 之间寻找可控权衡，是开放的科学问题。
  • 与公平 / 多语的交叉：DP 的噪声、去重的阈值都对长尾 / 低资源数据更不利——隐私缓解可能加剧模块 01/03 的群体不公。把隐私、公平、效用放进同一张帕累托前沿评测，是社会技术评测的前沿。

把这一模块的方法论收束成一句话：隐私不是一个能用 “做了 / 没做” 回答的合规项，而是一组要测量、要报告残余值的连续量。它和本课其余模块共享同一种评测纪律——不轻信平均数（LiRA 的教训，呼应模块 01 的子群崩盘）、把含混的担忧（“会不会泄露”）翻译成受控可复现的数字（canary 暴露度、MIA 的低 FPR TPR）、并诚实标注这些数字是下界还是上界、固有属性还是当前攻击能力。掌握了这套纪律，你面对任何新的记忆 / 隐私威胁时，第一反应都会是：我能埋什么探针？我该报哪个工作点的什么数？缓解后还剩多少？——而这正是负责任评测科学家与 “走个隐私流程” 的根本区别。

必读：Carlini 2019《The Secret Sharer》（canary 与暴露度，本模块的实现蓝本）、Carlini 2021《Extracting Training Data from LLMs》（提取攻击奠基）、Shokri 2017（MIA 开山）、Carlini 2022《MIA From First Principles》（LiRA，重塑评测标准）、Lee 2022（去重缓解）。完整清单见 references.md。
