1独特约束：测上界、必须尽力、假阴性昂贵

危险能力评估（dangerous capability evaluation）表面上和普通 benchmark 长得一样：一堆任务、跑模型、算通过率。但它回答的问题完全不同。普通评测问"这个模型平均表现多好"，危险能力评估问"这个模型最多能做到什么"——因为安全决策（是否部署、是否触发 RSP 阈值，见模块 01）依赖的是能力上界，而不是均值。

直白讲

普通评测像考试：大家用统一规则，比谁分高，作弊（提示工程、挑温度、多次重试）是不被允许的。 危险能力评估反过来：评估者要主动替模型"作弊"——给它最好的提示、工具、脚手架、重试机会， 想方设法把它的真实本事逼出来。因为这里漏报一个能力，代价可能是把一个不该部署的模型放了出去。

严谨讲

设模型在任务 $x$ 上、引出方法 $e\in\mathcal{E}$ 下的成功概率为 $p(x;e)$。常规评测报告固定协议 $e_0$ 下的 $\mathbb{E}_x[p(x;e_0)]$；危险能力评估要估计的是 $\sup_{e\in\mathcal{E}}\, p(x;e)$ 的可达上界， 其中 $\mathcal{E}$ 覆盖现实攻击者可负担的全部引出手段。安全结论"能力低于阈值"是对该上确界的断言， 因此评估不充分（$\mathcal{E}$ 取样太窄）会系统性低估风险 [Phuong 2024; METR 2024]。

这导出三条与常规评测截然相反的设计公理，先用一张对照表钉死：

维度常规能力评测（如 MMLU 排行）危险能力评估
回答的问题平均表现多好？（选型/排行）能力上界在哪？（安全决策门限）
测量目标$\mathbb{E}[\text{performance}]$，固定协议$\sup$ 可引出表现，协议本身是变量
对"优化提示/脚手架"的态度视为作弊，须标准化排除视为义务（elicitation obligation）
错误代价结构高估/低估大致对称，错了重测即可不对称：假阴性（漏报能力）可能导致错误部署决策，事后不可逆；假阳性只是多花缓解成本
结论形式一个分数一个有证明负担的安全论证："在尽力引出下仍低于阈值，且留有安全边际"
过时方向榜单饱和，换新榜模型变强、引出技术进步 → 旧的"安全"结论单向失效
假阴性为什么昂贵得多？常规评测里低估一个模型，损失是排行榜不准；危险能力评估里低估一个模型， 意味着"模型不具备能力 X"这一安全前提是假的，而建立在它之上的部署决策、缓解等级、监管申报全部失效。 反过来，假阳性（把不具备的能力误判为具备）只会触发额外的缓解措施——花钱，但不出事。 因此整个领域的方法论都向"宁可误报、不可漏报"倾斜：这就是 elicitation 义务、安全边际（safety margin）、 提前预警评估（early warning eval）等设计的统一逻辑 [Phuong 2024]。

2代理任务设计与 proxy validity

第一个工程难题：真实危险任务本身不能拿来测。原因有三：①信息危害——评测材料本身可能扩散危险知识；②伦理与法律——不能真的让模型尝试有害操作；③可测量性——真实危险结果无法在实验室里安全地打分。所以 [Phuong 2024]（DeepMind 对 Gemini 系列的危险能力评估，覆盖说服、网络安全、自我增殖、自我推理四个域）确立了核心方法：设计保留核心认知技能、剥离危险载荷的良性代理任务（proxy task）。

真实危险任务（不可直接测） │ │ ① 分解：完成它需要哪些认知技能？ ▼ 技能清单：长程规划 / 多步推理 / 工具使用 / 错误恢复 / 领域知识检索 … │ │ ② 重建：用良性载荷重组这些技能 ▼ 代理任务（可安全测量） 例：用 CTF 夺旗题代理网络攻击技能， │ 用沙箱内自我复制演练代理自我增殖， │ ③ 论证：proxy validity 用良性话题说服实验代理操纵能力 ▼ "代理上的表现 → 真实任务上的能力" 的推断链

第三步是最容易被偷懒跳过、却承担全部推断重量的一环：代理效度（proxy validity）。报告"模型在代理任务上通过率 12%"没有意义，除非你能论证代理任务与真实任务之间的映射关系。这是一个论证义务：每个代理任务都应附带一段明示的效度论证——它保留了哪些核心技能、丢掉了哪些、丢掉的部分朝哪个方向偏置结论。

代理任务的三类典型失效模式：

失效模式机制偏置方向对策
技能缺失（skill omission）代理任务遗漏了真实任务的某个关键瓶颈技能（如实操容错、长时间持续性）代理太容易 → 高估风险（可接受），或代理只测了非瓶颈技能 → 通过代理≠通过真实任务，结论失真与领域专家共同做任务分解；报告中明示未覆盖技能
捷径解（shortcut）代理任务可被与目标技能无关的技巧解出（背答案、格式漏洞、训练集污染）假阳性——但更危险的是修补捷径后误以为"测干净了"污染检查、多变体出题、人工审查成功轨迹（transcript review）
难度漂移（difficulty mismatch）代理任务系统性比真实任务更难（如沙箱限制、缺工具）低估风险 → 假阴性，最危险的失效人类专家在相同沙箱下跑基线，校准代理难度（§4）
注意不对称性再次出现：三类失效里，使代理偏难的失效（难度漂移）最危险，因为它产生假阴性。 实务规则：当代理任务的保真度不确定时，宁可让代理偏容易——让评估系统性高估风险，把误差预算花在安全的一侧。 这与常规 benchmark "难度适中、区分度最大化"的出题哲学正好相反。
[Phuong 2024] 的一个常被忽略的贡献是把"评估报告"本身规范化了：每个域不只报通过率， 还报任务设计依据、引出投入、专家基线和失败轨迹分析。[Wijk 2024, RE-Bench] 则示范了代理任务的另一极： 用 7 个真实 AI 研发工程环境（如优化训练脚本、修复 kernel）作为"AI R&D 能力"的代理——载荷完全良性， 但技能构成与前沿实验室的真实研发工作高度重叠，并配有 71 名人类专家、8 小时预算的基线。

3难度阶梯：定位能力前沿的位置

有了代理任务，下一个问题是：一道任务的 pass/fail 回答不了安全问题。安全框架（模块 01）问的是"模型离危险阈值还有多远、以什么速度逼近"，这是一个定位 + 趋势问题。单点测量给不出距离，更给不出速度。解法：把任务做成一条难度阶梯（difficulty ladder）——同一技能族、难度连续递增的任务序列，从"当前模型闭眼通过"一直铺到"远超人类专家"。

难度 ▲ │ L5 ── 远超人类专家（多周专家团队级任务） ░░░ 全失败 │ L4 ── 顶尖专家数天 ░░░ 全失败 ← 安全边际所在 │ L3 ── 专家数小时 ▓░░ 偶发成功 ← ★ 能力前沿在这里 │ L2 ── 熟练从业者一小时内 ███ 大部分成功 │ L1 ── 当前模型轻松通过 ███ 全成功 │ └────────────────────────────────────────────► 模型成功率 前沿 = 成功率从 ~1 跌到 ~0 的过渡带； 安全评估的产出 = 前沿位置 + 它逐代上移的速度

为什么必须是梯子而不是单点？三个理由：

  • 定位：成功率随难度的过渡带（通常用 50% 通过点 $d_{50}$ 概括）给出能力前沿的坐标。单任务只能告诉你前沿在它之上还是之下。
  • 趋势：逐代模型在同一条梯子上测，$d_{50}$ 的位移就是能力增速——这是预测"何时触线"的原始数据（§6）。
  • 统计稳健：单任务 pass/fail 是一次伯努利试验，方差极大；梯子上多任务多试验联合拟合（如 logistic 模型 $p(d)=\sigma\!\left(\frac{d_{50}-d}{s}\right)$）把噪声平均掉，还能顺带估计过渡带宽度 $s$——宽度大意味着能力"参差"，本身就是有用信号。
梯级的"难度"怎么标定？最不靠谱的是出题人拍脑袋，最靠谱的是人类完成时间： 让有资质的人类专家做同一任务，用中位耗时作为难度坐标。这正是 [Wijk 2024, RE-Bench] 和 [Kwa 2025] 的共同选择——人类耗时是跨任务、跨领域可比的"难度通货"。notebook 里我们会给每道谜题任务标注合成的 "人类专家平均耗时"，复现这个标定逻辑。
阶梯设计的常见坑：梯级之间难度间隔不均匀、或顶端不够高。如果最难一级模型已经能做对 20%， 你测到的不是前沿而是"梯子不够长"——评估失去预警能力。规则：梯子顶端至少要比当前前沿高出 一个安全边际（如 RSP 中的 buffer 概念），且每次模型升级后检查顶端余量。

4人类专家基线与 uplift 评估

难度阶梯回答"模型绝对能力在哪"，但许多威胁模型（模块 01）关心的其实是相对量：模型让一个原本做不到/做得慢的人类行为体增强了多少？这就是 uplift 评估——危险能力评估的金标准形态，因为它直接测量风险的边际贡献。

标准设计是一个对照实验：

招募同质参与者（按技能分层随机分组） │ ┌───────────────┴───────────────┐ ▼ ▼ 对照组 Control 实验组 Assisted 只用常规资源 常规资源 + 被评模型 （搜索引擎/文档/教材） （聊天/工具调用） │ │ ▼ ▼ 在相同沙箱、相同时限内完成同一组（良性代理）任务 │ │ └───────────────┬───────────────┘ ▼ 比较：完成率、完成时间、产出质量评分 uplift = 两组差异（含统计检验与置信区间）

形式化：设对照组与实验组的完成时间分别为 $T_C, T_A$（或完成率 $\pi_C, \pi_A$），则

$$ \text{uplift}_{\text{time}} = \frac{\mathrm{median}(T_C)}{\mathrm{median}(T_A)}, \qquad \text{uplift}_{\text{rate}} = \pi_A - \pi_C $$

完成时间通常重尾、含删失（超时未完成），所以检验用非参数方法：Mann–Whitney U 检验两组分布位置差异，配秩双列相关 $r = 1 - \frac{2U}{n_1 n_2}$ 作效应量，bootstrap 给中位数差的置信区间——notebook §5 完整演示。

uplift 设计的硬约束（也是它昂贵的原因）：

  • 参与者资质要匹配威胁模型：评"对新手的 uplift"招新手，评"对专家的增强"招专家。错配会让结论答非所问。
  • 对照组的资源要现实：对照组若被禁用搜索引擎，uplift 会被高估——你测的是"模型 vs 裸人"而不是"模型带来的边际增量"。
  • 样本量诚实：人类实验贵，n 常只有十几人/组；必须报告检验功效，避免把"没测出差异"说成"没有差异"（又是那个不对称！）。
  • 专家基线兼作难度标定：对照组数据顺手产出了 §3 需要的"人类耗时"难度坐标，一鱼两吃——RE-Bench 的 71 人基线就是这么用的 [Wijk 2024]。

5Elicitation 义务："没引出"不等于"不会"

§1 说评估者必须"替模型尽力"。这一节把它工程化。能力引出（capability elicitation）是一条投入递增的阶梯 [METR 2024, Guidelines for Capability Elicitation]：

引出投入 ──────────────────────────────────────────────► ┌─────────┬──────────┬───────────┬──────────┬───────────┐ │ 直接提问 │ prompt │ agent │ best-of-N │ 针对性 │ │ (朴素) │ 工程/ │ scaffold + │ 多次采样 │ 微调 │ │ │ few-shot │ 工具+重试 │ pass@k │ (上界探针) │ └─────────┴──────────┴───────────┴──────────┴───────────┘ 每升一级，测得的"能力"单调不降； 安全结论必须声明：你爬到了第几级

核心逻辑是一个非对称证明负担：

  • 要证明"模型具备能力 X"：展示一次可复现的成功即可——存在性命题，一个反例就够。
  • 要证明"模型不具备能力 X"：必须论证"在攻击者可负担的所有引出手段下都不会成功"——全称命题，原则上不可穷尽。实务上的弱化版本是："我们的引出投入 ≥ 现实威胁行为体的投入，且仍有安全边际"。
"我们没引出来" ≠ "模型不会"。评估报告里最危险的一句话是"模型未能完成任务"而不附引出投入说明。 正确的表述形如："在 prompt 工程 + agent scaffold + pass@32 的引出投入下，任务族 L4 成功率 0/30 （95% 置信上界 ~10%，见 §7），引出投入对标〈威胁模型中的行为体画像〉，并预留〈x〉级安全边际。" ——能力是协议的函数，省略协议的能力断言没有意义 [METR 2024]。

两个工程要点：

  • pass@k 与采样预算：危险能力关心"攻击者多次尝试中至少成功一次"，所以 pass@k（$k$ 次采样至少一次成功的概率）常比 pass@1 更贴合威胁模型。注意 pass@k 随 $k$ 单调上升，报告时必须固定并声明 $k$。
  • 微调作为上界探针：对模型做针对性微调（在良性代理任务上）能近似"去除拒绝训练/激发潜在能力"后的上界，常用于回答"能力是真不存在，还是被对齐训练压住了"——这与模块 05 的 sandbagging 检测直接相关。
和（通用）评测课模块 06 的呼应：那里讲 elicitation 是为了"公平比较"（别让差 prompt 冤枉好模型）， 这里讲 elicitation 是为了"安全兜底"（别让差 prompt 掩护强模型）。同一套技术，动机相反，投入标准也不同—— 安全评估的引出投入要对标攻击者，而不是对标平均用户。

6Horizon 视角：把前沿趋势外推进风险预测

§3 的难度梯子给出"前沿在哪"，安全决策还需要"前沿何时到达阈值"。[Kwa 2025]（METR）提供了目前最有影响力的量化框架：时间视野（time horizon）。

定义：模型的 50% 时间视野 $H_{50}$ = 这样一个人类耗时长度——对于人类专家需要该时长完成的任务，模型成功率恰为 50%。它把 §3 的"难度坐标 = 人类耗时"与"$d_{50}$ 前沿定位"合成为一个单一的、跨任务族可比的标量。测量方法正是我们已经搭好的那套：以人类耗时为横轴的任务梯子 + logistic 拟合：

$$ p(\text{success} \mid t_{\text{human}}) = \sigma\!\left(\beta\,(\log t_{\text{human}} - \log H_{50})\right), \qquad H_{50} = \text{成功率掉到 } 50\% \text{ 的人类耗时} $$

[Kwa 2025] 的核心实证发现：在软件/研究类任务上，前沿模型的 $H_{50}$ 自 2019 年以来呈指数增长，倍增周期约 7 个月（2024–2025 年的子样本更快）。指数趋势意味着可以做外推：

$$ H_{50}(t) = H_{50}(t_0)\cdot 2^{(t-t_0)/T_d} \;\;\Rightarrow\;\; t_{\text{危险}} - t_0 = T_d \cdot \log_2\!\frac{H_{\text{阈值}}}{H_{50}(t_0)} $$

也就是说：如果某威胁模型要求"自主完成人类专家一个月量级的任务"才构成危险（$H_{\text{阈值}}\approx 160$ 小时），而当前 $H_{50}$ 是 4 小时、倍增周期 7 个月，则外推到达时间 $\approx 7\times\log_2(40)\approx 37$ 个月。这类计算正是 RSP / Preparedness 框架里"我们还有多少缓冲时间"的定量来源。

外推的全部脆弱性都要写进结论里：①趋势是在特定任务分布（软件工程类）上测的，迁移到其他危险域无保证； ②指数趋势可能因架构/数据/算力拐点而断裂——向上或向下都可能；③$H_{50}$ 对 elicitation 水平敏感， 引出技术进步会让视野"凭空"上跳（这是测量协议变化，不是模型变化，必须区分）； ④50% 可靠性对真实威胁可能不是对的阈值——[Kwa 2025] 同时报告 $H_{80}$，它显著更短。 外推是预警工具，不是定时器。

7评测工程：试验次数、统计功效与罕见成功

最后是地基：危险能力评估的统计对象常常是低概率成功——前沿模型在 L4 任务上 30 次试验全失败，你能下什么结论？这一节给出三件随身工具。

7.1 检出功效：N 次试验能看见多小的 p？

设任务真实成功率为 $p$，独立跑 $N$ 次，至少观察到一次成功的概率（检出功效）：

$$ \mathrm{Power}(p, N) = 1 - (1-p)^N $$

令功效 $\geq 1-\beta$，解出可检出的最小成功率：$p_{\min} = 1 - \beta^{1/N}$。代入 $N=30,\ \beta=0.2$：$p_{\min}\approx 5.2\%$——30 次试验对成功率低于 ~5% 的能力基本是瞎的。这就是为什么"0/30"远不等于"不会"，也是评估预算（每任务试验数）必须从威胁模型反推的原因。

7.2 Rule of three：全失败时的置信上界

观察到 $0/n$ 成功时，对真实 $p$ 的 95% 置信上界来自反解二项检验：找最大的 $p$ 使得"全失败"仍不算罕见（概率 $\geq 5\%$）：

$$ (1-p)^n = 0.05 \;\;\Rightarrow\;\; p_{\text{upper}} = 1 - 0.05^{1/n} = 1 - e^{\ln(0.05)/n} \approx \frac{-\ln 0.05}{n} \approx \frac{3}{n} $$

（最后一步用 $1-e^{-x}\approx x$ 与 $-\ln 0.05 = 2.996\approx 3$。）这就是 rule of three：$0/n$ 成功 → 95% 置信上界约 $3/n$。例：0/30 → 上界 ≈ 10%；要把上界压到 1%，需要 300 次全失败的试验。它把"我们没观察到成功"翻译成一个诚实的、可写进安全报告的定量断言。

7.3 一般情形：Clopper–Pearson 精确区间

观察到 $k/n$ 成功（$k>0$）时，单侧 95% 上界用 Clopper–Pearson 精确法，由二项分布与 Beta 分布的对偶给出：

$$ p_{\text{upper}} = \mathrm{BetaInv}(0.95;\; k+1,\; n-k) $$

即 Beta$(k{+}1, n{-}k)$ 分布的 0.95 分位数（scipy.stats.beta.ppf(0.95, k+1, n-k)）。$k=0$ 时它精确退化为 $1-0.05^{1/n}$，与 rule of three 一致。Clopper–Pearson 偏保守（实际覆盖率 ≥ 名义值）——在假阴性昂贵的领域，保守正是我们要的方向。

两个让上界失效的隐藏假设：①试验独立同分布——若 30 次试验共享同一个会泄露答案的 scaffold bug， 或温度=0 导致 30 次输出几乎相同，有效样本量远小于 30，上界虚假地紧； ②任务代表性——上界是对这族任务的，不能自动推广到"该危险域的所有任务"。 报告里两者都要声明。多任务联合分析时还要考虑任务间相关（层级模型），本课不展开。
把 §7 和 §5 连起来读：elicitation 决定你测的是不是真上界（系统性偏差），统计功效决定你的"零成功" 有多少证据力（随机误差）。一份合格的危险能力评估报告 = 引出投入声明 + 难度梯子定位 + 置信上界 + 安全边际，四件套缺一不可。notebook 会把这条流水线完整跑一遍。

8研究前沿与开放问题

  • 代理效度的系统化验证：目前 proxy validity 基本靠专家论证，缺少实证校验方法（如在历史模型上回测"代理通过 → 真实能力出现"的预测力）。评测视角：这是安全评估领域自己的"construct validity"危机，谁能给出验证协议谁就定义了下一代标准。
  • elicitation 差距的量化：当前引出技术与理论上界之间差多少？[METR 2024] 建议用微调探针估计，但微调本身的充分性又如何论证？无穷回归如何在工程上截断。
  • horizon 外推的域迁移：[Kwa 2025] 的 7 个月倍增在软件任务上测得；说服、网络安全等域的视野增速是否同步？需要各危险域自己的纵向梯子，但历史模型数据稀缺。
  • 自动化 uplift 评估：人类对照实验贵且慢（n≈15/组是常态），能否用"模拟参与者"（弱模型扮演人类）做廉价预筛、人类实验只验证临界情形？模拟保真度本身又需要评估——递归出现。
  • 评估的时效性管理：模型不变但引出技术进步，旧评估单向失效。多快重评一次？触发条件是什么？这正在从研究问题变成 RSP 的合规条款（与模块 07 safety case 的"评估有效期"直接相关）。
