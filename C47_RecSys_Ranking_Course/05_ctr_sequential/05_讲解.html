1CTR 预估：精排的核心目标

到了精排的模型形态。模块 04 讲了排序的损失（pairwise/nDCG），这一模块讲精排的模型——尤其是工业精排的两大主线：CTR 预估（点击率，广告/推荐精排的核心目标）和序列推荐（用行为序列捕捉兴趣演化）。最后讲一个贯穿始终的暗礁：偏置与去偏。

先说 CTR (click-through rate)。精排要给每个候选打一个分，最常见的分就是点击概率。广告系统更直接——eCPM = CTR × 出价，CTR 预估准不准直接等于钱。CTR 预估的演化是一部精彩的「如何处理稀疏特征交叉」的历史：从 LR 到 FM 到深度模型。

CTR 预估模型的演化（核心问题：怎么处理「特征交叉」？） LR (逻辑回归) σ(w·x) 线性, 交叉靠【人工】组合特征 -> 累 │ 「城市×品类」要手工造, 组合爆炸 ▼ FM (因子分解机) +Σ⟨v_i,v_j⟩x_i x_j 给每个特征一个向量, 【自动】学所有二阶交叉 │ 稀疏数据也能学, 预测 O(kn) 线性时间 ▼ Wide&Deep/DeepFM FM/线性 ⊕ DNN 记忆(wide)+泛化(deep), 学高阶交叉 │ ▼ DLRM (Meta) embedding+点积交互+MLP 工业级, embedding 表 TB 级, 通信是瓶颈

CTR 预估的核心难点一句话：特征极度稀疏，而信号藏在「特征组合」里。单看「用户是学生」「物品是篮球鞋」可能都很普通，但「学生 × 篮球鞋」这个组合 CTR 很高。怎么从亿级稀疏的 one-hot 特征里自动学出有用的交叉，是 CTR 模型演化的主线——LR 靠人工（累且爆炸），FM 靠隐向量内积（自动、高效），深度模型靠 DNN（高阶）。这一节会把 LR→FM 从零写出来。

2从 LR 到 FM：自动学交叉

从 LR 到 FM：自动学特征交叉

逻辑回归（LR）是 CTR 的经典基线：$\hat y=\sigma(w_0+\sum_i w_i x_i)$。特征 $x$ 通常是 one-hot 的 ID（用户 ID、物品 ID、品类…）。LR 简单、可扩展、可解释，曾是工业 CTR 主力。但它是线性的——只看单个特征的权重，看不到特征组合的效果。

要让 LR 看到交叉，得人工构造组合特征（如「城市_品类」当一个新 one-hot）。问题致命：① 组合数爆炸（$n$ 个特征有 $n^2$ 个二阶组合）；② 稀疏数据下，很多组合在训练集里从没出现过（比如「西藏用户 × 某冷门商品」），LR 学不到它们的权重（没样本）。人工交叉既累又学不全。

因子分解机（FM）（Rendle 2010）的天才解法：给每个特征学一个隐向量 $v_i$，二阶交叉的权重用两个隐向量的内积 $\langle v_i,v_j\rangle$ 表示：

\[\hat y = w_0 + \sum_{i=1}^{n} w_i x_i + \sum_{i=1}^{n}\sum_{j=i+1}^{n} \langle v_i, v_j\rangle\, x_i x_j\]

这一步妙在哪？① 自动学所有二阶交叉，不用人工造；② 稀疏也能学——即使「西藏用户 × 冷门商品」这个组合从没共现，只要「西藏用户」和别的商品共现过（学到 $v_{\text{西藏}}$）、「冷门商品」和别的用户共现过（学到 $v_{\text{商品}}$），它们的内积就给出了一个合理的泛化预测。这正是 FM 比 LR 强的根本——把「交叉权重」从「每对一个独立参数」压成「每个特征一个向量」，参数从 $O(n^2)$ 降到 $O(nk)$，且能泛化到未见组合。

直白说

FM 的精髓：用「特征的向量表示」的内积，代替「每对特征一个独立权重」。就像 MF 用用户/物品向量内积代替每个评分一个参数——FM 是 MF 思想推广到任意特征交叉。事实上 MF 是 FM 的特例（只有 user-ID 和 item-ID 两个特征时）。

严谨说

还有一个 FM 的计算神迹：朴素算二阶项要 $O(n^2)$，但 Rendle 证明它可以化简成 $O(kn)$ 线性时间（下一节推导）。这让 FM 在亿级稀疏特征上依然可在线推理——是它能上工业的关键。FM 同时解决了「自动交叉」「稀疏泛化」「高效计算」三个问题，是 CTR 史上的里程碑。

FM 必读：Rendle 2010《Factorization Machines》。延伸：FFM（域感知，Juan 2016）、DeepFM（FM+DNN，Guo 2017）、Wide&Deep（Cheng 2016）。见 references.md。

为什么这个化简如此重要？因为它把 FM 从「理论漂亮但算不动」变成「工业能上线」。没有这个 $O(kn)$ 技巧，FM 就和「人工枚举所有二阶交叉」一样慢，毫无优势。有了它，FM 才能在亿级特征、毫秒级延迟的真实 CTR 系统里运行。这也是个通用教训：一个模型能否落地，往往不取决于它多准，而取决于能否高效地算——推荐系统尤其如此。

4深度 CTR 与 DLRM

深度 CTR 与 DLRM：embedding 表是主角

FM 只学二阶交叉。要学高阶、非线性的交叉，就上深度模型。工业精排的深度 CTR 大同小异，核心结构是：

深度 CTR 的通用结构（以 DLRM 为例） 稀疏特征(ID): 用户ID 物品ID 品类 ... 稠密特征: 价格 时长 ... │ 每个过 embedding 表 │ ▼ ▼ [e_u, e_i, e_cat, ...] (一堆 embedding) [dense MLP] └──────── 特征交互(两两点积/FM)─────────┘ │ ▼ 顶层 MLP │ ▼ σ -> CTR

DLRM（Naumov 2019，Meta 开源）是这类模型的代表。它的特点不在结构多新，而在揭示了工业推荐的真正瓶颈：embedding 表巨大。亿级用户、亿级物品、每个 ID 一个向量——embedding 表可达TB 级，远超单卡显存。于是 DLRM 强调：① embedding 表要模型并行（切到多卡，接 C39 分布式）；② 训练/推理的瓶颈是embedding 的查找与通信（all-to-all），而非 MLP 的算力。这和模块 03 双塔、模块 02 MF 一脉相承——推荐模型的参数主体永远是 embedding 表。

这个「embedding 表是参数主体」的事实有深远的工程含义：① 推荐模型大但不深（参数 TB 级但 MLP 只有几层），和 LLM 的「深而稠密」正相反；② 训练瓶颈在通信而非计算（embedding 查找要跨卡 all-to-all），所以推荐的分布式训练（C39）和 LLM 很不一样；③ 推理时 embedding 查找 + 缓存是延迟关键。理解了这点，你就明白为什么工业推荐团队有大量精力花在 embedding 的存储、分片、缓存、量化上——这是推荐系统工程的独特战场。

Wide&Deep（Cheng 2016）是另一经典思路：把线性部分（wide，记忆具体组合）和DNN（deep，泛化）并联。wide 负责记住「这个特定组合就是高 CTR」（记忆），deep 负责泛化到没见过的组合。DeepFM（Guo 2017）用 FM 替代 wide 部分、和 DNN 共享 embedding，免去人工特征工程。这些都是工业精排的常见起点。

直白说

一句话串起 CTR 模型谱系：LR（线性）→ FM（自动二阶）→ DeepFM/Wide&Deep（记忆+高阶泛化）→ DLRM（工业级 embedding 工程）。越往后表达力越强、工程越复杂，但内核都是「embedding + 特征交互」。

严谨说

注意呼应模块 02 的 Rendle 警示：深度 CTR 不一定碾压调好的 FM。很多场景下 FM/DeepFM 已经够好，盲目上更复杂的模型常常收益递减、成本剧增。工业实践是先把 FM 这个强基线打满，再视收益决定是否深度化——这是省钱也是科学。本模块 notebook 因此聚焦 FM（CTR 的性价比之王），深度部分理解思想即可。

DLRM：Naumov 2019。Wide&Deep：Cheng 2016。DeepFM：Guo 2017。DIN（行为注意力）：Zhou 2018。见 references.md。

5序列推荐：GRU4Rec → SASRec

序列推荐：从 GRU4Rec 到 SASRec

到目前为止我们都把用户当成一个静态的向量（或一堆特征）。但真实的兴趣是动态、有时序的——你刚买了相机，接下来想看的是镜头、存储卡，而不是又一台相机。序列推荐（sequential recommendation）把用户历史行为当成一个有序序列，预测下一个交互，捕捉兴趣的演化与短期意图。

序列推荐的演化和 NLP 惊人地平行（因为「行为序列」和「词序列」结构相同）：

模型用什么建序列类比 NLP特点
GRU4Rec (Hidasi 2016)RNN/GRURNN 语言模型开创序列推荐；序列长时难并行、长程依赖弱
Caser (Tang 2018)CNNTextCNN卷积捕捉局部行为模式
SASRec (Kang 2018)单向自注意力GPT并行、长程依赖好，序列推荐强基线
BERT4Rec (Sun 2019)双向 TransformerBERT掩码物品预测，常优于单向 SASRec

GRU4Rec 用 GRU 逐个吃 session 内的点击，最后的隐状态预测下一项——和 RNN 语言模型一模一样。它开创了序列推荐，但有 RNN 的老问题：序列长时难并行、远处的行为信号会衰减。

SASRec（自注意力序列推荐）用单向自注意力（每个位置只能看自己和之前的，像 GPT 的 causal mask）建模行为序列：每个位置的表示是它之前所有行为的加权聚合，权重由注意力自动学（哪些历史行为对预测下一项更重要）。它比 RNN并行（一次算完整个序列）、长程依赖更好，是当前序列推荐的强基线。训练目标是next-item prediction：给定前缀，预测下一物品（softmax / 采样 softmax over 物品表）。

序列推荐有几个评估陷阱务必小心：① 必须按时间切分（用前缀预测下一项），随机切分会泄漏未来、指标虚高；② 采样 softmax 评估时负例采样方式影响排名（在采样负例里排序 vs 在全库排序结果不同，文献里 sampled metrics 有争议，Krichene 2020）；③ 序列模型容易过拟合到「重复上一个」（很多数据集里下一项=刚交互的相似物品），要检查它是否真的学到了模式而非捷径。评估序列推荐比静态推荐更需谨慎。

序列推荐的训练目标 next-item prediction 和语言模型的 next-token 完全同构：给定前缀序列，最大化下一个真实物品的概率（softmax over 物品表，物品多时用采样 softmax，接模块 03 的负采样）。这种结构上的统一让 NLP 的几乎所有进展（注意力、Transformer、预训练、掩码）都能平移到推荐——这也是序列推荐近年爆发的原因。notebook 会用一个去掉注意力复杂度的玩具版（历史 embedding 平均）抓住「序列→下一项」的内核，纯 numpy 可跑。

序列推荐的核心洞察：「你最近做了什么」比「你是谁」更能预测「你下一步想要什么」。一个平时爱看科幻的人，刚点进一个做饭视频，此刻最该推的是更多做饭内容，而非科幻——短期意图压过长期画像。SASRec 的自注意力恰好能动态地决定历史中哪些行为此刻最相关。这也是为什么现代工业推荐（尤其信息流、短视频）越来越依赖序列模型——它抓的是此刻的意图。

6偏置与去偏：点击数据的暗礁

偏置与去偏：点击数据的暗礁

最后一个贯穿推荐始终的硬核问题：用点击数据训练，会学到偏置而非真实偏好。最典型的是position bias（位置偏置）——用户更容易点击排在前面的结果，与内容是否相关无关。如果直接拿点击当标签训排序，模型会把「排在前面」误学成「相关」，形成恶性循环。

位置偏置的标准模型是检验假设（examination hypothesis）：一次点击 = 被看到（examine）× 内容相关（relevant）：

\[P(\text{click}=1 \mid u, i, \text{pos}) = \underbrace{P(\text{examine} \mid \text{pos})}_{\text{只依赖位置}} \times \underbrace{P(\text{relevant} \mid u, i)}_{\text{我们真正想要的}}\]

$P(\text{examine}\mid\text{pos})$ 叫倾向得分（propensity）——位置越靠前越接近 1，越靠后越小。我们真正想学的是 $P(\text{relevant})$，但它被位置因素污染了。去偏的经典武器是IPW (inverse propensity weighting)（逆倾向加权）：给每个点击样本的损失除以它的 propensity，补偿位置带来的曝光差异：

\[\mathcal{L}_{\text{IPW}} = \sum_{\text{clicks}} \frac{\ell(u, i)}{P(\text{examine}\mid \text{pos}_i)}\]

直觉：排在第 10 位还被点击的物品，比排在第 1 位被点击的物品更能说明它真的相关（它克服了低曝光），所以给它更高权重（除以更小的 propensity）。IPW 把「有位置偏置的点击」纠正成「无偏的相关性估计」（Joachims 2017）。notebook 会从零实现位置偏置的模拟与 IPW 去偏，验证去偏后能恢复真实排序。

一个微例把「为什么不去偏会学歪、IPW 怎么救」算给你看。设两个物品真实相关性相同，但物品 A 历史上常被展示在第 1 位（$P(\text{examine})=0.9$），物品 B 常被展示在第 5 位（$P(\text{examine})=0.3$）。假设二者的真实相关概率都是 $P(\text{relevant})=0.4$。按检验假设，观测到的点击率：A 是 $0.9{\times}0.4=0.36$，B 是 $0.3{\times}0.4=0.12$。直接拿点击当标签，模型会以为 A 的相关性是 B 的 3 倍（0.36 vs 0.12）——纯属位置造成的假象，于是它把 A 越排越前、B 越压越下，反馈回路自我强化。现在上 IPW：给每个点击样本的损失除以其 propensity，A 的有效权重 $\propto1/0.9$、B 的 $\propto1/0.3$。去偏后的相关性估计：A 是 $0.36/0.9=0.40$，B 是 $0.12/0.3=0.40$——两者恢复相等，位置偏置被精确抵消。直觉也对上了：B 在那么靠后的位置还能被点（克服了 0.3 的低曝光），单次点击「含金量」本就更高，所以该乘更大的权重。notebook 正是模拟这组 propensity、对比「裸点击训练 vs IPW 训练」，验证只有后者能还原「两物品其实一样相关」。

偏置全家桶

位置偏置只是冰山一角。推荐里还有一群偏置在啃食你的模型：流行度偏置（热门越推越热，模块 01/03）、选择偏置（用户只对自己选的物品评分，数据 MNAR）、曝光偏置（没推给你≠你不喜欢）、反馈回路（推荐影响行为、行为又成训练数据，自我强化，制造信息茧房）。这些偏置共同导致一个危险后果：离线指标提升 ≠ 线上收益。这就是工业推荐最难的离线-在线鸿沟——也是为什么最终一切要靠 A/B 测试裁决。

7在线学习与反馈回路

在线学习与反馈回路

推荐系统不是训一次就完事的静态模型，而是一个持续运转的回路：模型推荐 → 用户反馈 → 反馈成为新数据 → 更新模型 → 再推荐。这个反馈回路（feedback loop）带来独特的挑战与机会。

挑战是前述的偏置自我强化：模型只推它认为好的，用户也只能对推荐的东西反馈，于是模型永远看不到它没推过的东西到底好不好——它在自己制造的数据上越陷越深（流行度放大、信息茧房）。破解之道是探索-利用（exploration-exploitation）：刻意拿出一小部分流量做随机/探索性推荐，收集无偏数据。这正是bandit / 强化学习在推荐里的用武之地（接 C13 RL）——把推荐当成序贯决策，平衡「推已知好的（利用）」和「试不确定的（探索）」。

机会是实时性：用户兴趣秒级变化（刚搜了「羽绒服」），系统要能近实时地把这个信号用上。工业上有在线学习（参数实时更新）、实时特征（session 内行为）、近线召回（实时建索引）等机制。序列推荐（上一节）正是为捕捉这种实时意图而生。

还有一个反馈回路的伦理与产品维度值得一提：回路放大流行度、制造信息茧房（你只看到越来越窄的内容）、可能强化偏见、甚至被用于操纵。负责任的推荐系统（接 C12/C45）要主动打破回路——注入多样性、保护长尾、给用户控制权、监控公平性。这不只是技术问题，更是这类系统作为社会基础设施的责任。会做推荐的人，也该懂得它的副作用。

把整门课收束一下：你现在掌握了一条工业推荐链路的全部核心算法——召回（CF/双塔）、排序（LTR/BPR）、精排模型（FM/序列）、以及去偏与回路。真实系统是这些组件的精心编排：多路召回 → 粗排 → 精排（多目标深度模型）→ 重排（多样性/业务规则），全程与偏置和反馈回路搏斗，最终以 A/B 为准。这就是支撑万亿级互联网经济的推荐系统的全貌。

8研究前沿与开放问题

研究前沿与开放问题

  • 生成式推荐：用 LLM/生成模型直接「生成」下一个物品 ID（如 TIGER 的语义 ID、P5 把推荐统一成文本生成）。能否取代「embedding + 检索」范式，是最热的方向之一。
  • 大模型与推荐：用 LLM 的世界知识做冷启动、可解释推荐、对话式推荐；用 LLM 当特征提取器或 reranker。LLM4Rec 是活跃前沿。
  • 无偏学习与因果推荐：把推荐当因果干预，用 IPS/doubly-robust 估计器同时去偏训练与评估；反事实推荐、off-policy 评估仍有大量开放问题。
  • 多目标与长期价值：从优化即时点击转向优化长期用户价值（留存、满意度），用 RL 建模长期回报，避免短视的标题党/信息茧房。
  • 统一的序列/生成架构：把召回、排序、序列建模统一进一个大模型（类似 NLP 的统一），减少多阶段的目标不一致，是工业架构的长期愿景。
