1这门课讲什么：最大的 ML 就业面

欢迎来到 推荐系统与大规模排序。先说一句不夸张的话：推荐、搜索、排序是机器学习落地最广、雇人最多的方向，没有之一。

你每天醒着的时间里，有多少是被一个排序模型安排的？打开 YouTube/TikTok 的首页、刷 淘宝/Amazon 的「猜你喜欢」、看 Netflix 的推荐墙、读 小红书/Instagram 的信息流、甚至 Google 搜一个词——背后都是同一类系统在工作：从一个巨大的物品库里，为此刻的你挑出几个最该看的并排好序。这些系统直接决定了这些公司的绝大部分收入（广告、电商 GMV、订阅留存）。所以业界对会做推荐/排序的人需求极大，岗位从算法工程师到机器学习平台、从广告到搜索，遍布每一家有用户的科技公司。

这门课要把这条工业推荐链路从头到尾拆开、亲手重建。绝大多数人和推荐系统的关系止于 pip install lightfm 或调一个云端 API。我们要往下钻：当系统面对十亿级物品、却要在几十毫秒内给你排好序时，它是怎么做到的？为什么要分成召回、粗排、精排、重排四层？矩阵分解、双塔、BPR、FM、序列推荐这些名字背后到底是什么数学？我们会用纯 numpy 把它们一个个从零写出来，在真实 MovieLens 数据上跑出真实的指标。

学完你应当能回答这类问题（也是推荐/搜索/广告岗位的高频面试题）：一条工业推荐链路的召回/粗排/精排/重排各在做什么、为什么要分层？显式和隐式反馈有什么本质区别？矩阵分解和双塔是什么关系？BPR 为什么适合隐式反馈？nDCG 怎么算、为什么比准确率更适合排序？FM 凭什么能在稀疏数据上自动学特征交叉？位置偏置怎么去？——并且能在 numpy 里把这些模型都从零实现、在真实数据上验证。

一句方法论上的话先说在前面：本课的价值不在「教你调某个库」，而在把推荐系统的第一性原理夯实。库会过时、框架年年换（从 LibFM 到 TensorFlow Recommenders 到 RecBole 到 Merlin），但「稀疏交互怎么压成低维表示」「召回为什么要双塔」「排序为什么要 pairwise」「点击数据为什么有偏」这些不随工具过时的硬道理，学扎实了换任何框架都立刻能上手，也才看得懂工业系统的设计取舍。

2工业世界观：召回→粗排→精排→重排

工业推荐的世界观：一条四级漏斗

现代工业推荐系统几乎都是级联漏斗（cascade funnel）结构。原因是一个硬约束：物品库可能有十亿个，而你只能在几十毫秒里返回几十个结果，且每层算力有限。没法用最贵的模型给十亿物品逐个打分，于是先粗后精：每一层把候选数量级砍小、把模型复杂度调高。

用户请求来了，要从十亿物品里挑几十个排好序（预算：几十毫秒） 物品库 10^6 ~ 10^9 │ ▼ ① 召回 Retrieval → 几百~几千候选 极快、低精度容忍 │ 双塔+ANN / 协同过滤 / 多路召回 「别漏掉好的」→ 看 Recall@K ▼ ② 粗排 Pre-ranking → 几百候选 轻量打分（小双塔/蒸馏） │ 「在延迟内初筛」 ▼ ③ 精排 Ranking → 几十候选 重模型逐个精细打分（DLRM/深度CTR） │ 多目标：CTR/时长/转化 「排得准」→ 看 nDCG / AUC ▼ ④ 重排 Re-ranking → 最终列表 列表级目标：多样性/打散/业务规则 「整个列表好」→ 看多样性+精度

每一层都对应本课的一两个模块，且都是一个可独立掌握的能力：模块 01（协同过滤）、03（双塔召回）是召回层的两条主力技术；模块 02（矩阵分解）既是召回也是排序的基石（它学的隐因子是后面一切的雏形）；模块 04（排序学习）是精排的核心方法论；模块 05（CTR/序列）是精排里最主流的模型形态。重排（多样性、去偏）我们在模块 05 的去偏部分与术语表里覆盖。读到最后你会有一张完整的工业链路地图。

分层 = 分目标

最关键、也最容易被新手忽略的一条：漏斗每一层的优化目标不一样，评估指标也不一样。召回层追求不漏（高 Recall@K），哪怕精度低——它的工作是「把可能的好东西都捞上来」；精排层追求排得准（高 nDCG/AUC）——它的工作是「在召回给的候选里排出最好的顺序」；重排追求整个列表好（多样、不重复、合规）。用精排的指标去评召回、或反过来，是工业推荐里最常见的认知错误。先想清楚这一层在漏斗里干什么，再选指标、选模型。

为什么不能用一个大模型一步到位？因为算力和延迟。给十亿物品都过一遍深度精排模型，延迟和成本都是天文数字。漏斗的本质是用便宜的模型快速排除大量明显不相关的，把昂贵的算力集中花在最有希望的少数候选上——和搜索引擎、广告系统的逻辑完全一致。理解了这个「先粗后精」的工程哲学，你就理解了整个工业推荐架构的骨架。

3两种燃料：显式 vs 隐式反馈

两种燃料：显式反馈 vs 隐式反馈

推荐系统的「数据」长什么样？核心是一个用户-物品交互矩阵 $R$：行是用户、列是物品、元素是「这个用户对这个物品的态度」。但「态度」从哪来？有两种来源，性质天差地别，决定了你能用什么模型、什么损失、什么评估。

维度显式反馈 explicit隐式反馈 implicit
来源用户主动表态：1–5 星评分、点赞/点踩行为推断：点击、观看时长、加购、停留
信号质量干净、有正有负（1 星=不喜欢）有噪声、只有正例（没点≠不喜欢，可能没看到）
数据量极稀疏（多数人不评分）海量（每次行为都是数据）
典型任务评分预测（预测 r_ui，回归）Top-N 排序（隐式正例排前面）
典型损失观测项上的 MSE/RMSEBPR / 加权 MSE / 采样 softmax
典型评估RMSE / MAERecall@K / nDCG@K / Hit@K
代表方法FunkSVD、带偏置 MF（Netflix Prize）iALS、BPR、双塔（现代工业主力）

直白说

打个比方：显式反馈像问卷调查——你认真填了，数据很准，但大多数人懒得填，样本少得可怜。隐式反馈像监控摄像头——记录你的一举一动，数据海量，但你「路过没进店」到底是不感兴趣还是没注意到，它分不清。

严谨说

形式上，隐式反馈是个单类（one-class）问题：我们只观测到正向交互 $\{(u,i): r_{ui}=1\}$，没有可靠的负例。未观测的 $(u,i)$ 既可能是「不喜欢」也可能是「没见过」。这就是隐式推荐的根本难题——怎么构造负例（随机负采样？热门负采样？难负例？），以及怎么给信号加置信度（看了 10 次 vs 看了 1 次）。模块 01/03/04/05 会反复处理它。

一个昂贵的教训：「没交互」不等于「负反馈」。你没看某条视频，可能只是它没被推给你（曝光偏置），而不是你不喜欢。把所有未观测项当成确定的负例去训练，会系统性地惩罚那些「本来会喜欢但没机会看到」的物品，让模型陷入只推已知热门的恶性循环。这正是模块 05 要讲的偏置与去偏的起点——隐式反馈的「负例」永远要小心对待。

本课两条线都会走：模块 02 用显式评分讲清矩阵分解的数学（看 RMSE 收敛，最干净）；模块 01/03/04/05 转向隐式反馈与 Top-N 排序（这是现代工业的主流）。两者的模型骨架（隐因子、embedding、点积）其实一脉相承，区别主要在损失函数与负例处理——这正是本课希望你建立的统一视角。

4评估：Top-N 排序的指标

怎么评估？Top-N 排序的指标

推荐做得好不好，怎么量化？评分预测时代用 RMSE（预测评分与真实评分的均方根误差），但现代推荐基本是Top-N 排序问题——我们只关心排在前面的少数几个对不对，不关心精确评分。于是有一套排序指标：

  • Recall@K：Top-K 里命中的相关物品数 ÷ 用户全部相关物品数。召回层最看重它——「该捞的捞上来了吗」。
  • Precision@K：Top-K 里命中的相关物品数 ÷ K。「推的这 K 个里有多少是对的」。
  • Hit@K / HR@K：Top-K 里至少命中一个相关物品的用户比例。最宽松，常用于 leave-one-out 评估。
  • nDCG@K：带位置折损的命中——排第 1 命中比排第 10 命中更值钱。最常用的排序质量指标，模块 04 详讲。
  • MAP / MRR：平均精度均值 / 第一个命中的倒数排名。也是 Top-N 常用指标。

为什么不用准确率（accuracy）？因为推荐是极度不平衡的排序问题：用户喜欢的物品占全库可能不到万分之一，一个「全部预测不喜欢」的模型准确率能到 99.99%，却毫无用处。排序指标只看把相关物品排到前面的能力，这才是推荐真正要的。nDCG 还额外奖励「把最相关的排到最前」，最贴合用户体验——你只看前几条。

时间因果

评估里最致命的坑是时间泄漏（temporal leakage）。如果随机划分训练/测试集，就可能用「未来」的交互预测「过去」，离线指标虚高、上线却崩。正确做法是按时间切分：用每个用户最后一次交互（leave-last-out）或某个时间点之后的交互做测试，之前的做训练。本课 notebook 严格遵守这一点。记住：推荐的离线评估必须尊重时间因果，否则你测的是一个不存在的能力。

还要记住一句工业界的清醒话：离线指标只是代理，线上 A/B 测试才是裁判。离线 nDCG 提升不一定带来线上点击/时长/留存的提升（因为离线评估本身有偏、且单一指标无法代表真实业务目标）。弥合这道离线-在线鸿沟是工业推荐最难也最值钱的能力之一。本课打的是离线这一端的扎实基础，让你先把模型和指标都搞对。

5与 C11(检索) 的关系，及环境

与 C11(检索) 的关系，以及环境

如果你学过 C11（RAG/检索），会发现召回层和向量检索是同一件事。双塔召回（模块 03）= 把用户和物品编码成向量、用最大内积搜索（MIPS）取 Top-K——这和 RAG 里「把 query 和文档编码成向量、检索最相似文档」一模一样，连底层工具都共用（FAISS、HNSW、ScaNN）。区别只在：检索的「query」是一段文本，推荐的「query」是一个用户（及其历史行为）。理解了双塔，你同时理解了语义检索——这是两门课的交汇点。

直白说

一句话连接两门课：RAG 的检索器和推荐的召回器，是同一个双塔 + ANN 的骨架，只是喂的东西不同（文本 query vs 用户画像）。学会一个，另一个直接迁移。

严谨说

更广地说，推荐的精排（模块 04/05）也和搜索的排序（learning to rank）同源——nDCG、BPR、RankNet 这些本就是从信息检索（IR）借来的。推荐 = 「没有显式 query 的检索 + 排序」，把 C11 的检索/排序知识平移过来，加上「用户建模」和「隐式反馈」两味料，就是推荐。
