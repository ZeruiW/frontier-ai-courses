1配比决定模型的能力分布

数据干净了、tokenizer 定了、超参迁好了、训练也稳了。还剩最后一个、却可能最影响模型「性格」的旋钮：各类数据按什么比例喂。网页、代码、书籍、论文、多语——它们都进训练集，但配比（data mixture）决定模型在各项能力上的强弱。代码占比高，模型会写程序；论文占比高，模型更会推理；配比偏了，某项能力就瘸腿。

配比是预训练最被低估、又最难调的决策之一。难在哪？因为它是一个高维、互相牵制、且评估昂贵的优化问题：调高代码比例，挤占的是网页/书籍的比例，可能伤害通用语言能力；而要知道某个配比好不好，理论上得真训一个模型测下游——贵到没法网格搜。本模块讲怎么科学地定配比（DoReMi）、数据不够时怎么办（重复 epoch 与 data-constrained scaling）、以及能不能用模型造数据（合成数据与崩溃风险）。

直白说

打个比方：配比像配一份均衡膳食。光吃肉（代码）会缺维生素（通用语言），光吃菜（网页）会缺蛋白质（推理/专业知识）。营养师（DoReMi）要在有限的「胃容量」（token 预算）里，配出让各项营养都达标的比例——而且不能靠「吃完体检」（训完测下游）来反复试，太贵。

严谨说

形式化：设有 $K$ 个 domain，配比是概率单纯形上的权重 $\mathbf{w} = (w_1, \dots, w_K)$，$\sum w_k = 1$。训练时按 $\mathbf{w}$ 从各 domain 采样 token。目标是找 $\mathbf{w}^*$ 使某个目标（平均验证 loss、最差 domain loss、或下游能力）最优。本模块的核心是：在不真训大模型的前提下，用代理模型 + 分布鲁棒优化（DoReMi）逼近 $\mathbf{w}^*$。

为什么配比比想象中重要？因为它直接决定模型把有限容量花在学什么上。一个固定大小、固定 token 预算的模型，是一块有限的「学习带宽」——配比就是在分配这块带宽。分配错了，再多算力也补不回某项瘸腿的能力（除非后训练专门补，但那更贵）。所以前沿团队在配比上做大量消融，DoReMi 这类自动方法正是为了让这个分配有依据而非拍脑袋。

还有一个常被忽视的连锁效应：配比与去重、重复深度纠缠。去重（模块 01）决定每个 domain 有多少独特 token；若某 domain 独特数据少，要么降低它的配比，要么重复它（多 epoch）。所以「配比」从来不是孤立地定权重——它和「这个 domain 还剩多少独特数据」「重复几遍划算」是同一个决策的三个面。本模块会把这三者放在一起看，这正是 data-constrained 时代的正确视角。

2配比是个优化问题

配比是个优化问题：从均匀到加权

最朴素的配比是按数据自然量（哪个 domain 数据多就多采）或均匀。但这几乎肯定不是最优——因为不同 domain 的学习难度和价值不同。

考虑一个简单事实：给定配比 $\mathbf{w}$，模型的整体表现是各 domain 表现的加权组合。若各 domain 单独的验证 loss 是 $\ell_k$，最朴素的目标是最小化加权平均：

\[\mathcal{L}_{\text{avg}}(\mathbf{w}) = \sum_{k=1}^{K} w_k\, \ell_k(\mathbf{w}) \qquad \text{(注意 } \ell_k \text{ 本身依赖 } \mathbf{w}\text{)}\]

关键的微妙处在那个括号注解：$\ell_k$ 依赖于 $\mathbf{w}$——给一个 domain 更多权重，它学得更好（$\ell_k$ 下降），但挤占了别的 domain。这让配比成为一个自洽的优化问题，不是简单地「给重要的 domain 多分点」。

配比策略怎么定问题
按自然量数据多的 domain 多采网页数据淹没一切，代码/专业知识太少
均匀每个 domain 等权忽略难度差异，难学的 domain 学不够
人工调凭经验 + 少量下游验证高维难搜、主观、不可复现
DoReMi (自动)代理模型 + group-DRO 优化本模块核心：让最差 domain 也学好

直白说

配比不是「把蛋糕分给最爱吃的人」那么简单。给一个 domain 多分，它确实学得好，但别的 domain 就饿着了。而且有些 domain（如代码）学起来更难，需要额外的权重才能跟上——怎么在「难度」和「价值」之间分配权重，正是配比优化要回答的。

严谨说

从优化视角，这是个不动点/博弈问题：理想配比下，没有哪个 domain 能通过「再多要点权重」获得不成比例的收益。DoReMi 用 group-DRO（下一节）来逼近这个平衡——它不最小化平均 loss，而是最小化最差 domain 的 loss，自动给「学得慢、吃亏」的 domain 加权，得到更均衡的配比。

notebook 第 1-2 节会让你把配比建模成单纯形上的权重，先看均匀/偏重配比对加权 loss 的影响，再实现 DoReMi 式的自动优化。

3DoReMi：group-DRO 自动找配比

DoReMi：用 group-DRO 自动找配比

DoReMi（Xie 2023）是配比优化的里程碑：它不需要下游标签、只用一个小代理模型就能自动找出好配比，再迁移到大模型。核心思想是 group DRO（分组分布鲁棒优化）。

普通训练最小化平均 loss；group-DRO 最小化最差一组的 loss：

\[\min_{\theta} \; \max_{k} \; \ell_k(\theta) \qquad \text{(让表现最差的 domain 尽可能好)}\]

为什么最小化「最差 domain」是个好主意？因为平均 loss 会被容易、数据多的 domain 主导——模型在网页上 loss 低，平均就低，于是优化器懒得管学得慢的代码/专业 domain。盯住最差 domain，等于强制模型不抛弃任何一个 domain，得到更均衡、更鲁棒的能力分布。

DoReMi 的两阶段流程

  1. 训一个小参考模型：用某个初始配比（如均匀）训一个小模型，记录它在各 domain 上的 loss（作为「这个 domain 本该能达到多好」的基准）。
  2. 训小 proxy 模型 + group-DRO 调权重：再训一个小 proxy，但用 group-DRO动态调整域权重——哪个 domain 当前相对参考模型差得多（excess loss 大），就给它加权。用乘法权重（multiplicative weights）更新：$w_k \leftarrow w_k \cdot e^{\eta \cdot (\text{excess loss}_k)}$，再归一化。
  3. 用学到的平均权重训大模型：把 group-DRO 过程中域权重的平均值，当作最终配比去训真正的大模型。
DoReMi 的权重动态(group-DRO): 初始: 均匀 [0.25, 0.25, 0.25, 0.25] 迭代: 测各 domain 当前 loss -> 给「相对最差」的 domain 加权 ┌──────────────────────────────────┐ │ w_k ← w_k · exp(η·excess_loss_k) │ (上调学得慢的) │ w ← w / sum(w) │ (归一化回单纯形) └──────────────────────────────────┘ 收敛: 各 domain 的 loss 被「拉平」-> 没有 domain 被抛弃 产出: 平均权重 [0.29, 0.09, 0.43, 0.20] ← 难的 domain 自动获更多权重

直白说

DoReMi 像一个公平的教练：他不只看全队平均成绩（会被尖子生拉高），而是盯着最弱的队员，谁拖后腿就给谁多安排训练时间。最后全队成绩更均衡，没有人被放弃。

严谨说

group-DRO 的优雅在于它把「配比」变成一个有明确目标的优化（minimax），而非拍脑袋。且它在小代理上做（便宜），产出的权重再迁到大模型——这与模块 03 的 μP「小模型调、大模型用」是同一种代理优化哲学。本课反复出现这个模式：把昂贵的大模型决策，转化为便宜的小模型实验 + 有理论依据的迁移。

DoReMi（Xie 2023）是配比优化必读；它建立在 group-DRO（Sagawa 2020）之上。相关的还有 DSIR（Xie 2023，重要性重采样选数据）。本模块 notebook 实现 group-DRO 的乘法权重核心，复现「自动给难 domain 加权、拉平各 domain loss」。完整清单见 references.md。

4数据墙：重复 epoch 的收益递减

数据墙：重复 epoch 的收益递减

配比解决「怎么分」，但还有个更根本的约束：高质量数据正在用完。这就是 data wall（数据墙）。当独特的高质量 token 不够填满你的 token 预算时，你不得不重复已有数据（训多个 epoch）。问题是：重复划算吗？

Muennighoff 2023（data-constrained scaling laws）系统回答了这个问题。核心结论惊人地具体：

  • 约 4 个 epoch 以内，重复数据的价值接近全新数据（重复一遍 ≈ 新增等量数据）；
  • 超过约 4 个 epoch，每多重复一遍的收益迅速衰减，趋近于零；
  • 极端重复（几十个 epoch）甚至有害（过拟合、加剧记忆）。

一个常用的简化模型把「重复 $R$ 个 epoch 的有效数据量」写成带衰减的形式（独特数据量 $D$，衰减常数 $\tau \approx 4$）：

\[D_{\text{eff}}(R) = D \cdot \tau \cdot \left(1 - e^{-R/\tau}\right) \quad\Longrightarrow\quad R \text{ 小时} \approx RD,\;\; R \text{ 大时饱和到 } D\tau\]
有效数据量 D·τ ┤ ╭──────────── 饱和(再重复几乎无收益) │ ╭────╯ │ ╭────╯ ← 收益递减区(第4 epoch 后) │ ╭───╯ │ ╭─╯ ← 近线性区(前几个 epoch，重复≈新数据) 0 ┤─╯ └──────────────────────────────→ 重复轮数 R 1 2 4(τ) 8 16

直白说

重复数据像反复看同一本书：第一遍收获最大，第二三遍还能捡漏，但看到第十遍，新东西几乎没有了——时间（算力）花在重读上，不如去找新书（新数据）或换种学法（加参数）。

严谨说

这条曲线有直接的资源分配后果：数据受限时，与其无脑重复，不如把算力部分转去加参数（Muennighoff 发现数据不够时，在重复和加参数之间有最优配置），或引入新数据源（代码、合成数据）。数据墙把模块 01（去重，决定有多少独特 token）、本节（重复收益）、和下一节（合成数据补充）连成一个整体决策。

数据墙与去重（模块 01）是一枚硬币的两面：去重越狠，独特 token 越少，越早撞墙、越早要重复。这带来一个反直觉的张力——激进去重提升单遍质量，但减少可用的独特数据量。最优去重激进度因此也依赖你的 token 预算：数据极度受限时，也许该保留一些近重复（它们重复利用的代价更低）。把去重、重复、配比放在一起权衡，才是 data-constrained 时代的正确视角。

5data-constrained scaling laws

data-constrained scaling laws：外推到数据受限区

经典 scaling law（Chinchilla）假设数据充足（每个 token 只见一次）。但数据墙下这个假设破了，需要修正的缩放定律。Muennighoff 2023 给出了 data-constrained 版本。

直觉修正：把 Chinchilla 公式里的「数据量 $D$」替换成「有效数据量 $D_{\text{eff}}$」（上一节那条饱和曲线）。重复使 $D_{\text{eff}} < R \cdot D$（边际递减），所以数据受限时，单纯堆 epoch 的 loss 改善会比 Chinchilla 预测的慢——曲线在数据轴上提前压平。

\[L(N, D, R) \approx E + \frac{A}{N^\alpha} + \frac{B}{D_{\text{eff}}(R)^\beta}, \quad D_{\text{eff}}(R) = D\tau(1-e^{-R/\tau})\]

这个修正的实用价值：它让你能外推——给定独特数据量 $D$ 和算力预算，预测重复几个 epoch、配多大模型能达到的最优 loss，而不必盲试。Muennighoff 的具体建议包括：数据受限时，把多出的算力分一部分给参数（而非全砸在重复上），且重复别超过约 4 个 epoch。

直白说

data-constrained scaling 回答的是：「我只有这么多独特数据和这么多算力，最好能训出多好的模型？」答案不再是 Chinchilla 的「等比例放大 N 和 D」，而要把「数据其实在重复、边际递减」算进去。

严谨说

从工程上，这把「放大」环节的决策树补全了：① Chinchilla 在数据充足时定 N:D；② 当 D 不够（数据墙）时，用 data-constrained scaling 重新权衡「重复 vs 加参数 vs 找新数据」；③ μP（模块 03）保证无论选多大的 N，超参都能迁过去。三者合起来，才是数据受限时代完整的预训练规划。

notebook 第 4-5 节会让你实现有效数据量曲线、用它修正 scaling law 外推，并在「重复 vs 加参数」之间做一次资源分配。

6合成数据与模型崩溃

合成数据与模型崩溃

既然真实高质量数据会用完，一个诱人的出路是：用模型生成数据来训模型。这就是 synthetic data（合成数据）。它在补充稀缺领域、提升数据质量上确有威力（phi 系列用高质量合成「教科书」训出强小模型），但也藏着一个致命陷阱。

陷阱叫 model collapse（模型崩溃，Shumailov 2023）：反复用模型自己生成的数据去训练后续模型，会导致分布的尾部逐渐丢失、多样性塌缩、质量退化。几代之后，模型只会生成「平均、单调」的内容，丢掉了真实数据里丰富的长尾。

为什么会崩？根源是采样 + 有限样本会系统性地丢失尾部。每次「生成 → 用生成数据重训」，都相当于对分布做一次有限采样再拟合——而有限采样低估方差、欠采样罕见事件。这个误差逐代累积：第一代丢一点尾部，第二代在「已经少了尾部」的数据上训、再丢一点，几代下来尾部就没了。

真实分布(丰富尾部) ▁▂▃▅▇█▇▅▃▂▁ gen 0 ▁▂▃▅▇█▇▅▃▂ gen 1 ← 采样丢失最罕见的尾 ▂▃▅▇█▇▅▃ gen 2 ← 尾部继续缩 ▃▅▇█▇▅ gen 3 ← 方差变小、变尖 ▅▇█▇ gen 4 ← 多样性塌缩 = model collapse 每代「生成→重训」= 一次有限采样，系统性低估方差、欠采样长尾

直白说

model collapse 像反复复印复印件：第一张复印件已经比原件糊一点，拿复印件再复印更糊，几轮之后字都看不清了。每次「用生成数据训新模型」就是复印一次，误差越积越多，最后只剩模糊的「平均脸」。

严谨说

形式化：设真实分布方差 $\sigma^2$。每代用 $n$ 个样本估计并重新生成，MLE 的方差估计是有偏的（$\hat\sigma^2$ 期望略小于 $\sigma^2$）。迭代 $t$ 代后方差近似按 $(1-\frac{1}{n})^t$ 衰减——指数级丢失。这就是为什么纯合成数据的递归训练会崩，而把合成数据与真实数据混合（用真实数据「锚住」尾部）能缓解。

实践教训很明确：合成数据不能无限自产自销。安全用法是——① 与真实数据混合（真实数据锚住分布尾部，防塌缩）；② 用更强的模型生成给更弱的模型（蒸馏，不是同代自循环）；③ 严控合成比例并监控多样性（如生成内容的方差、n-gram 多样性）。把合成数据当「调味料」（补特定能力）而非「主食」（替代真实数据）。当前哪个合成比例安全、如何检测早期崩溃，仍是活跃的开放问题。

7课程学习与质量退火

课程学习与质量退火

配比不一定是静态的——数据顺序也是个旋钮。curriculum learning（课程学习）按「由易到难」或「由通用到高质量」安排训练数据，而非全程随机。

预训练里最有效、最常用的课程是 quality annealing（质量退火）：训练末期把数据切换为高质量子集（同时常配合学习率衰减）。用少量优质 token 给模型「最后打磨」，多个前沿模型报告这能显著提升下游能力——相当于「先用海量普通数据建立广博基础，再用精选数据精雕细琢」。

直白说

质量退火像学习的两个阶段：先广泛涉猎（海量普通数据打基础、建立语言与世界知识），临考前再精读重点（高质量数据 + 小学习率，精细收敛到好的解）。两阶段结合，比全程一种数据更有效。

严谨说

从优化视角，质量退火与 WSD 调度（模块 04）天然配合：WSD 的末段衰减期，正好切换到高质量数据——学习率小、数据精，模型在损失面的好区域做最后的精细下降。这也是为什么 WSD 近年流行：它让「末段用高质量数据 + 小 lr 冲刺」变得自然。配比（喂什么）、顺序（何时喂）、调度（多大 lr 喂）在这里交汇成一个协同的设计。

课程学习的更广形式（严格按难度排序整个训练）在预训练里效果不一、且难设计「难度」度量，所以不如「末期质量退火」这种简单版普及。但它提示了一个方向：数据的时间安排是一个尚未充分开发的旋钮，与配比、调度共同构成「训练动态」的设计空间。

把配比、重复、调度、退火放在一起，你会看到「放大」与「喂数据」其实是一个统一的资源分配问题：在固定的算力与独特数据约束下，决定喂什么（配比）、喂多少遍（重复）、按什么顺序（课程/退火）、用多大学习率（调度）。这四个旋钮协同作用、彼此牵制——这也是为什么前沿预训练既是科学（scaling law、DoReMi 给依据）又是工程手艺（大量消融找具体配置）。本课给你的是看懂这些旋钮各自在调什么的框架。

8研究前沿与开放问题

研究前沿与开放问题

  • 配比的可迁移性：DoReMi 在小代理上找的权重，迁到大模型还最优吗？配比是否像 μP 的超参那样可跨规模迁移，证据尚不充分——最优配比可能随模型规模/能力变化（大模型也许该多吃难数据）。这是配比研究最重要的开放问题。
  • 合成数据的安全边界：多大比例的合成数据是安全的？如何早期检测 model collapse（在多样性塌缩前发现）？如何设计「不崩」的合成数据生成（如保证覆盖尾部）？这是突破数据墙的关键，也是当前最活跃的方向之一。
  • 数据质量 vs 数量的定量权衡：Sorscher 2022 证明好的数据剪枝能突破幂律 scaling。「一个高质量 token 顶几个普通 token」能否定量化？这把模块 01（质量过滤）与本模块（配比/重复）统一成「有效数据」的度量问题。
  • 课程与动态配比：最优配比是否该随训练阶段变化（早期多通用、晚期多高质量/难）？如何自动调度这个时变配比？质量退火只是最简单的一步，更精细的动态配比仍待探索。
  • 多模态与跨语言配比：当数据不止文本（图像、音频、代码），跨模态/跨语言的配比怎么定？各模态的「token」价值不可直接比较，配比优化要在异质数据上进行——这是通向多模态基座的前沿难题。

延伸阅读：Xie 2023（DoReMi）、Muennighoff 2023（data-constrained scaling）、Shumailov 2023（model collapse）、Albalak 2024（数据选择综述）、Sorscher 2022（数据剪枝突破 scaling）、Gunasekar 2023（phi，合成/高质量数据的威力）。完整清单见 references.md。
