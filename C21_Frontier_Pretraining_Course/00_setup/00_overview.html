1这门课要解决什么

欢迎来到 大规模预训练工程。这门课只追求一件事：让你看懂并能动手复现「把一个基座大模型从零训出来」背后那些决定成败、却很少被写进架构论文的工程决策。

大众对大模型的想象常常是「架构 + 算力」：换个 attention 变体、堆更多 GPU。但真正训过基座的人都知道，在架构与算力之外，有一条又长又脏的流水线——从 CommonCrawl 的原始网页，到一个能力强的 checkpoint——这条流水线上的每个环节（清洗、去重、配比、tokenizer、超参、稳定性）都可能让你的钱白烧。同样的 Transformer、同样的 FLOPs，数据脏一点、配比偏一点、tokenizer 选差一点、lr 没迁对、训到一半 spike 了没救回来——最终 loss 就差出一个身位，甚至直接训崩。

这门课把这条流水线上五个非架构、却最决定成败的环节逐个拆开：数据清洗与去重（喂进去的是金子还是垃圾）、tokenizer 设计（文本与模型的接口效率）、μP 超参迁移（怎么不在大模型上烧钱调参）、训练稳定性（怎么让它别崩）、数据配比与合成数据（喂多少、按什么比例、能不能用模型造数据）。每个环节都从零用 numpy 复现核心算法，再用真实论文的配置算一笔账。

学完你应当能回答这类问题（也是预训练/数据岗位的高频考点）：MinHash 凭什么能用一个短签名估出两篇文档的 Jaccard 相似度？LSH 的 banding 怎么把 O(n²) 去重变得可行？BPE 的 merge 表是怎么训出来的，词表大小如何权衡序列长度与 fertility？μP 凭什么能把小模型调好的 lr 直接搬到大模型？loss spike 怎么检测、怎么救？DoReMi 怎么不用下游标签就把数据配比优化出来？——并且能在 numpy 里把这些机制都从零实现、和朴素参考对拍。

一句方法论上的话先说在前面：本课的价值不在「我们没有大集群也能学」这个妥协，而在它逼你只关注真正难、真正不随硬件过时的部分——算法结构与正确性。真实管线里的分布式、并行、IO 优化是第二步（C36/C39 接手）；而「MinHash 为什么无偏、BPE merge 顺序为什么不能乱、μP 的缩放因子为什么是这几个、配比优化为什么收敛」是不随规模过时的硬功夫。把它练扎实，换到 datatrove、SentencePiece、mup 任何真实工具都立刻能上手。

2预训练流水线全景

预训练流水线全景：从 CommonCrawl 到 checkpoint

先把整条流水线摆出来，让你知道本课五个模块各自卡在哪一环。一个现代基座大模型的诞生，大致要走完下面这条链：

原始网络 (CommonCrawl, 每月 PB 级 WARC) │ 正文抽取：从 HTML 剥离菜单/广告/页脚 (trafilatura) ▼ 【模块 01】数据清洗与去重 ────────────────────────────── ├─ 质量过滤：启发式规则(Gopher) + 分类器打分(fastText) ├─ 去重：MinHash/SimHash 签名 → LSH 分桶 → 删近重复 └─ 去污染：n-gram 重叠删掉与评测集重合的文本 ▼ 得到「干净、不重复、不泄题」的语料 【模块 02】Tokenizer 设计 ────────────────────────────── └─ 在干净语料上训 BPE/Unigram，定词表大小(↔序列长度/fertility) ▼ 文本 → token id 序列 【模块 05】数据配比 ──────────────────────────────────── └─ 各 domain(网页/代码/书/多语)按权重采样(DoReMi)；定重复 epoch ▼ 采样好的 token 流 【模块 03】μP 超参迁移 ───────────────────────────────── └─ 小模型网格搜最优 lr/init → 按 μP 规则缩放迁到大模型 ▼ 定好的超参 【模块 04】训练稳定性 ────────────────────────────────── └─ grad clip / z-loss / QK-norm / warmup-decay / bf16 护着训 ▼ 基座 checkpoint ──→ (下游：C02 后训练 / 对齐)

注意这五个模块不是平行的专题，而是同一条流水线上前后咬合的工序：清洗去重决定喂进去的是金子还是沙子；tokenizer 决定这些文本被压成多长的序列、多高效；配比决定各 domain 喂多少；μP 决定你敢不敢直接在大模型上用某个 lr；稳定性决定这一切努力会不会因为一次 spike 前功尽弃。任何一环掉链子，前面的投入都打折。本课按「数据→放大→稳住&喂对」的逻辑组织，正是顺着这条依赖链走。

一个常被低估的事实：在固定算力预算下，这些「数据与训练工程」决策的杠杆，常常比架构改进更大。FineWeb（Penedo 2024）用 FLOPs 对齐的消融证明：把清洗管线做对，下游收益相当于把模型规模显著放大；Chinchilla（Hoffmann 2022）发现此前的大模型因为「数据/参数配比」错了而严重训练不足——这些都不是新架构，而是数据与训练配方的胜利。本课讲的就是这些杠杆。

3为什么数据与超参常比架构更决定成败

为什么数据与超参工程常比架构更决定成败

这是本课的世界观，值得单独说清。过去几年，真正拉开基座模型差距的，往往不是 attention 的新变体，而是下面这几件「脏活」做得好不好：

维度朴素/草率做法认真做法代价/收益
数据质量直接拿原始 CommonCrawl 训重度清洗 + 分类器过滤FineWeb：清洗后小模型可超过没清洗的大模型
去重只删完全相同的MinHash/LSH 删近重复Lee 2021：更少步数达到同样 loss、记忆下降
配比各 domain 凭感觉DoReMi 自动优化域权重Xie 2023：更快收敛、各能力更均衡
超参在大模型上反复试 lrμP 在小模型调好直接迁Yang 2021：省下大模型上的调参算力
稳定性崩了重来grad clip/z-loss/监控护栏PaLM/OPT：避免几十万美元算力打水漂

直白说

打个比方：训大模型像做一锅顶级高汤。架构是锅和灶（重要，但选定后变化不大）；而食材新不新鲜（数据清洗）、有没有重复的烂菜叶（去重）、各种料的比例（配比）、火候（超参与稳定性），才是决定这锅汤好坏的日常功夫。同一口锅，食材和火候不同，结果天差地别。

严谨说

更技术地说：在 Chinchilla 之后，大家逐渐认识到给定算力下，loss 由有效数据量与训练配方主导，而非架构常数因子。架构改动通常只动 loss 公式里的小常数；而数据质量、配比、是否训稳，动的是能不能把这条 scaling 曲线走到位。这就是为什么前沿实验室把大量人力压在数据与训练基础设施上——本课正是这部分知识的浓缩。

当然，这不是说架构不重要（架构是 C01/C20 的主题）。而是说：在架构选定之后，决定你这次预训练烧的钱值不值的，是本课讲的这条数据—超参—稳定性流水线。一个想真正训出好基座的团队，这两块缺一不可。本课补的，正是常被教程忽略的后一块。

4方法论：没有大集群怎么学

方法论：没有大集群，怎么学预训练工程？

本环境纯 CPU、不训真模型、不装分布式框架。但预训练工程的难点，从来不是「敲 torchrun 启动多少张卡」，而是算法是否正确、决策是否有依据：MinHash 的签名怎么构造才无偏、BPE 的 merge 顺序怎么定、μP 的缩放因子怎么算、spike 怎么检测、配比怎么迭代收敛。这些用 numpy 在玩具规模上完全能精确表达和验证。

打个比方：学厨艺不必先有能炒一百份的大锅。预训练的「厨理」是怎么判断食材好坏、怎么去重、怎么配比、怎么控火候；这些都是和「锅多大」无关的算法与判断。一条真实管线里把 MinHash 跑在亿级文档上，靠的是 Spark/分布式；但 MinHash本身——「取一组随机哈希的最小值当签名、签名相等比例估 Jaccard」——在 100 篇文档的 numpy 实现里和在亿级管线里是同一个算法，只差并行规模。我们在小规模上把它写对、验对，放大只是工程。

直白说

我们把每个预训练机制翻译成 numpy 里看得见、跑得动、验得了的东西：一篇文档就是一个 token 集合，MinHash 签名就是几个最小哈希值，LSH 桶就是一个字典，BPE 训练就是反复数 pair 频率、合并最高频对，μP 检查就是画激活尺度随宽度的曲线，配比优化就是一个加权 loss 的迭代。你写的是算法结构与正确性，不是规模。

严谨说

关键纪律是对拍（differential testing）：每个「优化版」实现都和一个朴素但绝对正确的参考比对。MinHash 估出的 Jaccard 要逼近暴力算的真值（大样本下偏差趋零）；从零训的 BPE 编码要能可逆还原；μP 的坐标检查要看到「激活尺度随宽度水平」；配比优化要看到 loss 单调下降。结构正确 → 数值对得上 → 逻辑可以原样放大到真实库。

预训练概念本课的 numpy 复现对应真实工具/规模
亿级文档去重几百个 token 集合 + 字典分桶datatrove / Spark + MinHashLSH
训练 tokenizer数 pair 频率、贪心合并SentencePiece / tokenizers (Rust)
超参迁移玩具网络的坐标检查曲线mup 库 + 小模型网格搜
稳定性护栏模拟梯度序列 + clip/z-lossMegatron / 训练框架的 callback
配比优化加权 loss 的 group-DRO 迭代DoReMi proxy + 大模型采样

务必清楚本课不教什么：不教分布式并行（数据/张量/流水并行是 C39）、不教 GPU 内核（C36）、不测真实训练时延、不调集群。这些在你有了正确的算法与决策之后，是第二步。本课负责把第一步——每个环节的算法与判断夯死；这一步搞定，第二步（放大到真集群）才有意义，也才不会在错误的算法上浪费昂贵的算力。

每个模块配一个 notebook，结构统一：先用 numpy 把机制从零实现并验证（5–6 个 worked 小节，每节都跑出可打印的结果与 assert 自检），再做 3–4 道带 assert 判分的 ✏️ 练习（先给骨架，自己填，再对照 📖 参考答案），最后一个真实数据胶囊（用真实论文/真实模型的配置算一笔账，把纸面知识接到现实）。

建议的学习节奏：先读完整章 HTML 建立直觉与理论框架，再打开 notebook 亲手实现。读和做缺一不可——只读会觉得「好像懂了」，真正动手写 MinHash 签名、调 LSH 的 (b,r)、跑 BPE 合并、做坐标检查、迭代配比权重时，才会发现魔鬼藏在哪些细节里（哈希怎么取最小、band 怎么切、merge 平局怎么破、缩放因子放哪、权重怎么归一）。这门课的深度正是为「动手」服务的。

配套先读：FineWeb（Penedo 2024）建立数据清洗全局观；Chinchilla（Hoffmann 2022）建立资源分配观；μP（Yang 2021）理解超参迁移；DoReMi（Xie 2023）理解配比优化。完整清单见 references.md。

✅ 学完整门课，你应该能：
  1. 设计一条数据清洗管线：用启发式 + 分类器做质量过滤，说出每步过滤的 precision/recall 权衡；
  2. 用 MinHash 估 Jaccard、用 LSH banding 把近重复检测从 O(n²) 降到可行，并会调 (b,r) 控制 S 曲线阈值；
  3. 从零训练 BPE，算 fertility 与压缩率，权衡词表大小↔序列长度↔多语公平；
  4. 解释 μP 为什么能让超参跨宽度迁移，做一次 coordinate check 验证缩放正确；
  5. 检测并处理 loss spike：grad clipping、z-loss、warmup-decay schedule，说清各自治的是什么病；
  6. 用 DoReMi 思想优化数据配比，理解重复 epoch 的收益递减与 data-constrained scaling，判断合成数据的崩溃风险；
  7. 把以上 numpy 验证过的逻辑，对应到 datatrove / SentencePiece / mup / DoReMi 等真实工具，知道放大到集群是下一步。
