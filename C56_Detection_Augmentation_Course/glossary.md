# 术语词典 · Glossary（检测数据增强工程）

> 按主题分组。每条给「英文 / 中文 / 一句话定义 / 为什么重要 / 常见误解」五栏。
> **「常见误解」那一栏是本词典的重点**——检测增强的坑几乎全在"看起来对但其实错"上，
> 而这类错误的共同特征是：**不报错，只让指标少涨一点。**
> 读增强库文档、调 YOLO 超参、或在面试里被追问时回这里查；英文术语保留原文。

## 一 · 几何变换 · Geometric Transforms

| 术语 (EN) | 中文 | 一句话定义 | 为什么重要 | 常见误解 |
|---|---|---|---|---|
| **augmentation as prior injection** | 增强即先验注入 | 每加一个增强算子，就等于向模型声明"这类变化不改变标签"。 | 这是全课的第一性原理：增强不是"造数据"，是**写一份不变性契约**。契约写错，模型会一丝不苟地学错。 | 以为增强是"免费的更多数据"。它不免费——每条不变性都占用模型容量，声明错了则直接注入错误标签。 |
| **affine transform** | 仿射变换 | 保持直线与平行性的线性变换 + 平移，用 2×3 矩阵表示，涵盖平移/缩放/旋转/错切。 | 检测里 99% 的几何增强都是仿射，且**多个操作可以先乘成一个矩阵再一次性 warp**——省一次重采样，画质与速度双赢。 | 以为"先旋转再缩放"和"先缩放再旋转"结果一样。矩阵乘法不交换，顺序不同结果不同；库里的参数顺序必须看文档。 |
| **perspective transform / homography** | 透视变换 / 单应变换 | 3×3 矩阵描述的投影变换，**不保持平行性**，能模拟相机视角变化。 | 车载场景的视角变化本质上是透视而非仿射（远处的标志随车道弯曲而倾斜）。适度透视增强能提升视角鲁棒性。 | 幅度设太大。透视会把矩形拉成任意四边形，取轴对齐外接框后框会剧烈膨胀，标注质量崩塌得比旋转还快。 |
| **corner transform method** | 四角法 | 把 bbox 的四个角点当作普通点做变换，再取变换后四点的轴对齐外接框作为新 bbox。 | **这是检测增强里唯一正确的 bbox 跟随方式**。只变换左上/右下两个点是经典错误——旋转后这两个点根本不是新框的极值点。 | 以为变换 (x1,y1) 和 (x2,y2) 两个角就够。旋转 45° 时这样得到的框会明显偏小且偏移，而代码完全不报错。 |
| **bbox inflation** | 框膨胀 | 旋转/透视后取轴对齐外接框，导致新框面积大于目标真实占据面积的现象。 | 这是旋转增强的**隐性代价**：一个正方形框旋转 45° 后外接框面积变成原来的 2 倍，多出来的全是背景。膨胀会污染回归目标，也会让 IoU 分配的语义漂移。 | 以为"旋转小角度没关系"。15° 对长宽比 3:1 的框（比如指路牌）就能带来 30%+ 的面积膨胀——**膨胀率同时依赖角度和长宽比**。 |
| **bbox clipping** | 框裁剪 | 变换后落到图像外的框，把坐标截断到图像边界内。 | 不裁剪会产生负坐标或超出图幅的框，多数训练框架要么报错要么静默产生 NaN 损失。裁剪是流水线里的强制步骤。 | 以为裁剪完就万事大吉。裁剪只修坐标不修**语义**：一个只剩 5% 可见的标志被裁成一个小框，标签却还是完整的类别——这就是下一条要处理的问题。 |
| **min visibility / min_area** | 最小可见比例 / 最小面积阈值 | 裁剪后可见面积占原面积的比例低于阈值时，把这个框整个丢弃。 | **对小目标是生死线。** 阈值设 0.3 在通用检测上合理，但 TSR 里一个 12×12 的标志被裁掉 70% 就整框丢弃，会让本就稀缺的小目标正样本进一步减少。 | 以为这是个无关紧要的默认值。它同时控制两类错误：太松 → 训练里全是"只剩一角却标着完整类别"的噪声样本；太紧 → 系统性丢掉小目标与边缘目标，模型学会"边上没东西"。 |
| **letterbox** | 信箱填充 | 保持长宽比缩放到目标尺寸，剩余区域用固定值（YOLO 惯例 114）填充。 | 它是**训练-推理鸿沟的头号发生地**：padding 值、是否居中、缩放比例是否取整、是否只 pad 到 stride 倍数，任何一项不一致，推理时框就整体偏移。 | 以为 letterbox 只是"resize 的一种"。它是一个**带参数的可逆几何变换**，逆变换必须实现，否则模型输出的框还原不回原图坐标系。 |
| **inverse letterbox / coordinate restore** | 逆变换 / 坐标还原 | 把模型在 letterbox 图上输出的框，减去 padding 再除以缩放比，还原到原图坐标。 | 部署端必须有它。**减 padding 与除 scale 的顺序反了是最常见的 bug**，症状是框在图像中心附近还准、越靠边越偏。 | 以为可以用"按比例缩放"糊弄过去。有 padding 时缩放不是线性的，必须先平移再缩放。 |
| **horizontal flip semantic hazard** | 翻转语义禁区 | 水平翻转对某些类别会改变或破坏其语义，因而不能无条件使用。 | **TSR 的必知坑，也是面试里最好的主动发挥点**：「左转」翻成「右转」是标签直接反了；限速牌上的数字镜像后变成不存在的字形；箭头类、文字类指路牌全部中招。 | 以为"翻转是最安全的增强"。它在 ImageNet 分类上确实几乎无害，但在**有手性（chirality）语义**的检测任务里是错误标签生成器。正解是按类别白名单：圆形禁令/警告牌可翻，方向类与文字类不可翻。 |
| **shear** | 错切 | 沿一个轴按另一个轴的坐标线性偏移，把矩形变成平行四边形。 | 轻度错切能模拟相机与标志平面不平行的情况，是 YOLO 默认增强里的一项（通常 0–2°）。 | 幅度设大。错切同样会造成框膨胀，而且它对"竖直立杆"这类结构的破坏比旋转更违反物理。 |
| **scale jitter / LSJ** | 尺度抖动 / 大尺度抖动 | 训练时把图像随机缩放到 [smin, smax] 区间；LSJ 用 0.1×–2.0× 这样的极大范围。 | **提升尺度不变性最直接的手段**，也是小目标增强的主力：把大图缩小就凭空造出了小目标。Copy-Paste 论文证明 LSJ 是其收益的重要来源。 | 以为范围越大越好。范围过大时同一目标在不同 epoch 的尺度差异过大，FPN 层级分配剧烈跳变，会显著拖慢收敛且需要更长 schedule 才回本。 |
| **multi-scale training** | 多尺度训练 | 每隔若干 iteration 随机换一个输入分辨率（如 480–800，步长 32）。 | 一份权重适应多档推理分辨率，部署上很有用；也是尺度鲁棒性的廉价来源。 | 忘了分辨率必须是 stride 的整数倍。不是的话特征图尺寸对不齐，轻则报错重则静默 pad。 |
| **RandomIoUCrop / RandomSizeCrop** | 随机 IoU 裁剪 | 随机裁一块区域，并约束裁剪后至少与某个 GT 框保持一定 IoU。 | SSD 时代的经典增强，本质上是**同时做了平移、缩放与上下文变化**。IoU 约束保证裁出来的图里还有可学的目标。 | 以为它对小目标友好。恰恰相反：裁剪会放大目标的相对尺寸（对小目标有利），但也常把小目标整个裁掉（对召回不利），净效果依赖阈值设置。 |
| **padding value (114)** | 填充值 | letterbox 与 mosaic 空白区域填的灰度值，YOLO 系惯用 114。 | 它是个**约定**而非最优值，其意义在于训练与推理必须用同一个数。用 0 填充会在图像边缘制造强边缘响应，模型可能学到"黑边=边界"这种伪特征。 | 以为改成 0 或 127 无所谓。改可以，但**训练端和部署端要一起改**，否则就是一个典型的训练-部署不一致。 |

## 二 · 光度与域 · Photometry & Domain

| 术语 (EN) | 中文 | 一句话定义 | 为什么重要 | 常见误解 |
|---|---|---|---|---|
| **HSV jitter** | HSV 抖动 | 在色相(H)/饱和度(S)/明度(V) 空间上分别加随机扰动，模拟光照与色偏。 | 检测里最常用的光度增强（YOLO 默认 `hsv_h=0.015, hsv_s=0.7, hsv_v=0.4`）。分开调三个通道比在 RGB 上乱调更可控。 | 以为三个通道可以同等幅度地调。**色相是最危险的那个**：H 的默认幅度只有 0.015（约 ±5°）而 S 有 0.7，这个数量级差异不是随意的。 |
| **color-as-semantics** | 颜色即语义 | 在交通标志域中，颜色本身携带类别信息：红=禁令、蓝=指示、黄=警告、绿=指路。 | **TSR 特有的硬约束。** 色相抖动过强会把红色禁令牌推进其他类别的色域，等于在生成错误标签。正确做法是幅度保守 + 按类别区分策略。 | 以为"颜色鲁棒性"越强越好。在通用检测里对颜色不变是好事，在 TSR 里**对颜色不变就是把判别信息扔了**。 |
| **gamma correction** | 伽马校正 | 用 `out = in^γ` 做非线性亮度映射，γ>1 变暗、γ<1 变亮。 | 比线性乘法更贴近真实相机响应，是低光合成的第一步。它对暗部的压缩/拉伸是非线性的，能真实地模拟暗部细节丢失。 | 以为"调亮度"就是加个常数。线性加减会整体抬升直方图并造成大量截断（clipping），而真实曝光变化是非线性的。 |
| **atmospheric scattering model** | 大气散射模型 | `I = J·t + A(1−t)`：观测图 I 由清晰图 J 按透射率 t 衰减，再叠加大气光 A 的散射分量。 | **雾/霾/雨天合成的物理底座**，也是所有去雾算法的反问题基础。用它合成的雾在物理上自洽，比"叠一层白色半透明"真实得多。 | 以为雾是均匀的。t 随深度指数衰减（`t = exp(−β·d)`），所以**雾的浓度必须随距离变化**——远处的标志比近处的更糊，而这恰好是 TSR 里最要命的情形。 |
| **transmission map / t** | 透射率图 | 每个像素的光线穿透比例，`t = exp(−β·d)`，β 是散射系数、d 是景深。 | 它把"雾有多浓"参数化成两个物理量（β 与 d），于是雾的强度可控、可扫参、可做消融。 | 以为需要真实深度图才能合成雾。没有深度时可以用**图像纵坐标近似深度**（车载前视图里越靠上通常越远），这个近似对增强目的已经足够。 |
| **airlight / A** | 大气光 | 无穷远处的环境光颜色，通常取图中最亮、最无纹理区域的颜色。 | 决定了雾的"颜色"：白天的雾偏白、黄昏的霾偏橙。A 设错会让合成图整体色偏，反而制造域差。 | 直接取图像最亮点。最亮点常常是高光反射或过曝点，正确做法是取暗通道最亮的前 0.1% 像素的均值。 |
| **motion blur kernel** | 运动模糊核 | 一条带方向与长度的线段状卷积核，模拟曝光期间的相对运动。 | 车载相机的模糊几乎都是运动模糊而非高斯模糊。**方向 + 长度两个参数就能覆盖大部分真实情况**，且长度可以从车速与曝光时间算出来。 | 用高斯模糊代替。高斯模糊是各向同性的，与真实运动模糊的各向异性完全不同，模型学到的鲁棒性迁移不过去。 |
| **defocus blur** | 失焦模糊 | 圆盘（disk）状卷积核，模拟镜头对焦不准。 | 与运动模糊并列的两大真实模糊来源，尤其在近距离大目标上。 | 与运动模糊混为一谈。二者的核形状不同（圆盘 vs 线段），恢复难度与对检测的影响也不同。 |
| **rolling shutter** | 卷帘快门 | CMOS 传感器逐行曝光，导致高速相对运动下画面产生倾斜/果冻效应。 | 车载相机绝大多数是卷帘快门。**高速通过时竖直的标志立杆会倾斜**，这是一个真实存在但几乎没人做增强的域差来源。 | 以为它只影响高速摄影。60 km/h 下横向相对运动配上 ~20ms 的行扫描时延就足以产生可测量的几何畸变。 |
| **ISP (image signal processor)** | 图像信号处理器 | 从传感器 RAW 到最终 RGB 之间的一整套处理：去马赛克、白平衡、降噪、锐化、色调映射。 | **训练数据的 ISP 与车端的 ISP 不同 = 一个隐形的域差。** 你增强的是"ISP 之后的图"，而部署端 ISP 参数可能随场景自动变化。 | 以为图像就是传感器读数。ISP 是一条重度非线性、且**会随场景自适应**的流水线，它本身就是一个不可控的增强器。 |
| **JPEG compression artifact** | JPEG 压缩伪影 | 有损压缩产生的块效应与振铃，尤其在高频边缘处。 | 数据回传常带压缩，训练集与线上流的压缩质量若不一致就是域差。把 JPEG 压缩当增强加进去是廉价且有效的一招。 | 以为质量因子 90 以上就"无损"。对 8×8 像素的小标志来说，块效应的相对影响远大于对大目标——**压缩伤害与目标尺寸成反比**。 |
| **ISO / shot noise** | 感光度噪声 / 光子散粒噪声 | 低光下增益放大带来的噪声，其方差**与信号强度相关**（泊松性质）而非常数。 | 真实低光噪声是信号相关的；用固定方差的高斯噪声合成会在亮区噪声过多、暗区过少。 | 全图加同一强度的高斯噪声。这会制造出真实相机里不存在的噪声分布，训练出的"鲁棒性"在实车上不生效。 |
| **low-light synthesis** | 低光合成 | gamma 压暗 → 加信号相关噪声 → 降低位深/量化 → 可选加眩光，四步合成夜间图像。 | 夜间是 TSR 的重灾区，而夜间真实数据的采集与标注成本很高。**顺序不能乱**：噪声必须加在压暗之后，因为真实噪声是在低信号上被增益放大的。 | 只做第一步（调暗）。只压暗得到的是"很干净的暗图"，与真实夜间图的噪声结构相差极远，模型学不到有用的东西。 |
| **domain randomization (DR)** | 域随机化 | 把仿真/合成参数（光照、纹理、颜色、天气）大幅随机化，使真实域成为训练分布的一个子集。 | 一条不需要真实标注就能提升泛化的路。在稀有条件（暴雪、极端逆光）上尤其有价值，因为这些数据你根本采不到。 | 以为"随机得越狠越好"。DR 用**精度换不变性**：随机化超出真实分布太多时，模型被迫学习过于宽泛的不变性，在常见条件上反而掉点。这是一个可测量的权衡，不是信仰。 |
| **domain gap / sim2real gap** | 域差 | 训练分布与部署分布之间的系统性差异。 | 本课三判据的第二条就是冲它去的。**大部分"合成增强没用"的结论，实际原因是合成的域差比它修复的域差还大。** | 以为域差只有"合成 vs 真实"一种。相机型号、ISP 版本、地区、季节、时段、甚至标注规范的变化都是域差。 |
| **photometric-vs-geometric ordering** | 光度/几何顺序 | 流水线里几何变换在前、光度变换在后的惯例。 | 几何操作涉及重采样（插值），先做光度再插值会让噪声与伪影被平滑掉，**削弱光度增强的效果**；反过来则保留。此外几何操作决定了哪些像素最终存在，先做能省掉对被裁掉区域的光度计算。 | 以为顺序只是习惯。它同时影响**效果**（噪声是否被插值抹平）与**开销**（是否白算了被裁掉的像素）。 |

## 三 · 混合类增强 · Mixing Augmentations

| 术语 (EN) | 中文 | 一句话定义 | 为什么重要 | 常见误解 |
|---|---|---|---|---|
| **Mosaic** | 马赛克拼接 | 把 4 张（或 9 张）图按随机中心点拼成一张，标注一并平移到各自象限。 | YOLOv4 引入后成为实时检测器标配。三重收益：**一次前向见到 4 份上下文**（变相增大 batch 的统计多样性）、**目标被缩小**（凭空制造小目标）、**打破了目标与背景的固有关联**。 | 以为它只是"省显存的拼图"。它最大的价值是制造小目标与破坏上下文捷径；也正因如此，**它造出的分布与真实分布差得很远**，见下一条。 |
| **close-mosaic** | 收尾关闭马赛克 | 训练最后 N 个 epoch（YOLO 默认 10）关闭 Mosaic，用干净图像收尾。 | **不是玄学，是分布对齐。** Mosaic 图里到处是拼接缝、被截断的目标、不合理的上下文，推理时永远不会出现。最后阶段切回真实分布，让模型在部署分布上完成收敛。 | 以为可以省掉。省掉通常掉 0.5–1.5 mAP，且掉点集中在大目标与完整目标上——正是 Mosaic 破坏最狠的那部分。 |
| **MixUp** | 像素混合 | 两张图按 λ 加权叠加，标签也按 λ 加权（检测里通常是把两张图的框**全部保留**）。 | 分类上是强正则；检测上的做法是"图叠加、框取并集"，效果有争议但在长 schedule + 大模型上普遍有正收益。 | 以为检测 MixUp 也做标签插值。检测里**框不能插值**——一个框要么存在要么不存在。主流实现是保留两张图的全部框，让模型在半透明目标上仍要检出。 |
| **CutMix** | 剪贴混合 | 从一张图剪一块矩形贴到另一张图上，标签按面积比例混合。 | 比 MixUp 更"局部"，天然是一种遮挡增强；在分类上通常优于 MixUp。 | 直接搬到检测上。检测里剪贴块会**部分覆盖已有目标**，此时被盖住的框该删、该改、还是该留？没有标准答案——这就是 CutMix 在检测上争议大的根源，也是 Copy-Paste 更受欢迎的原因（它贴的是有标注的实例而非任意矩形）。 |
| **Copy-Paste** | 实例复制粘贴 | 把带 mask/框的目标实例从一张图抠出来，贴到另一张图的合理位置，并添加对应标注。 | **长尾问题最直接的数据侧解法**，在 TSR 里价值极高：稀有标志（施工、动物出没、特殊限速）的样本数可以被直接放大一个数量级，成本远低于采集与标注。Ghiasi 等证明它与 LSJ 组合时收益显著且几乎无副作用。 | 以为"随便贴就行"。它有四条硬约束（尺度服从透视、位置合法、光照匹配、边缘融合），任何一条违反都会让模型学到**贴图伪影**这条捷径——症状是训练指标飞涨、真实场景毫无提升。 |
| **instance bank** | 实例库 | 从训练集标注中批量抠出的目标实例集合，按类别/尺度/清晰度索引，供 Copy-Paste 采样。 | 它把 Copy-Paste 从"每次现抠"变成"离线建库 + 在线采样"，速度快得多，并且**建库时可以做质量筛选**（剔除模糊、遮挡、过小的实例）。 | 建库时不做筛选。把模糊或被遮挡的实例入库，等于把噪声按倍数放大——**Copy-Paste 会把实例库的质量缺陷成倍复制到训练集里**。 |
| **scale-aware pasting** | 尺度感知粘贴 | 粘贴时按目标在图中的纵向位置（近似深度）采样合理的尺寸，使其符合透视规律。 | 车载前视图有强透视先验：越靠图像上方的目标越远、越小。违反它等于告诉模型"尺度与位置无关"，会直接破坏模型已有的一条极强的位置-尺度先验。 | 随机采尺度。一个和车一样大的限速牌，或者一个贴在图像上沿却有 200 像素的标志，都是在教模型学错的物理。 |
| **context violation** | 上下文违例 | 把目标贴到现实中不可能出现的位置（天上、车顶、路面中央）。 | 检测器**大量依赖上下文**（交通标志有立杆、在路侧、在特定高度）。违例样本会削弱这条先验，也是 Copy-Paste 最常见的翻车方式。 | 以为"多样性越高越好，贴哪都行"。有研究显示随机位置粘贴在分割任务上仍有收益，但**在检测上位置合法性的重要性明显更高**，尤其对依赖上下文的小目标。 |
| **blending / feathering** | 融合 / 羽化 | 粘贴边缘做高斯羽化或泊松融合，消除硬接缝。 | 硬接缝是一条**完美的捷径特征**：模型可以只靠"这里有个突兀的边"就检出目标，从而完全不学目标本身。 | 以为羽化只是"为了好看"。它是防止捷径学习的功能性步骤。有意思的是 Ghiasi 等发现在分割任务上简单粘贴（不融合）也很有效——**所以这条要在自己的任务上验证，别照抄结论**。 |
| **Cutout / Random Erasing / GridMask** | 遮挡类增强 | 随机把图像的一块/多块区域置零或置随机值，模拟遮挡。 | 廉价的遮挡鲁棒性来源。GridMask 用规则网格避免了"整个目标被完全遮住"的极端情况。 | 在检测上无脑用大遮挡块。遮住整个小目标却仍保留它的框 = 生成了一条"无中生有"的错误监督，对小目标尤其致命。 |
| **augmentation strength × model capacity** | 增强强度与模型容量的交互 | 强增强相当于加大任务难度；小模型容量不足时会从过拟合直接滑向欠拟合。 | **这是 YOLO 各尺寸用不同增强超参的原因**（n/s 用弱增强，l/x 用强增强 + MixUp）。照抄大模型的增强配方到小模型上是常见的掉点原因。 | 以为增强配方可以跨模型尺寸直接复用。同一套强增强在 YOLOv8x 上涨点、在 YOLOv8n 上掉点是完全正常的现象。 |

## 四 · 流水线工程 · Pipeline Engineering

| 术语 (EN) | 中文 | 一句话定义 | 为什么重要 | 常见误解 |
|---|---|---|---|---|
| **augmentation pipeline / Compose** | 增强流水线 | 把一串带概率的算子按固定顺序组合成一个可调用对象，样本依次流过。 | 它是增强的**执行语义定义处**：顺序、概率、以及哪些算子共享随机参数，全在这里决定。也是版本管理与复现的最小单元。 | 以为流水线里算子的顺序无关紧要。见「光度/几何顺序」，以及裁剪必须在 Mosaic 之后、归一化必须在最后。 |
| **effective trigger rate** | 实际触发率 | 一个样本真正被某组算子作用到的概率，等于路径上各算子概率的**乘积**。 | **概率相乘的直觉陷阱**：三个 p=0.5 的算子串联，三者全命中只有 12.5%；你以为开了"强增强"，实际上大部分样本几乎没被增强。 | 把配置里写的 p 当成实际强度。正确做法是**在流水线里埋计数器，直接统计每个算子与每种组合的真实触发率**——这是本课 04 模块的第一个练习。 |
| **worker RNG** | worker 随机数状态 | DataLoader 多进程时，每个 worker 进程各自持有一份随机数生成器状态。 | **真实事故的高发地**：fork 出的子进程会**继承父进程的 RNG 状态**，如果不给每个 worker 重新播种，所有 worker 在同一 epoch 会生成完全相同的增强序列，数据多样性直接除以 worker 数。 | 以为 `torch.manual_seed()` 就搞定了。它只管主进程；numpy 的全局 RNG 在 fork 后是复制的。需要 `worker_init_fn` 按 `worker_id` 重新播种，且种子要随 epoch 变化，否则每个 epoch 的增强序列还是一样的。 |
| **`worker_init_fn`** | worker 初始化钩子 | DataLoader 在每个 worker 启动时调用的函数，用来给该 worker 独立播种。 | 修复上一条的标准手段。典型写法是 `seed = base_seed + worker_id`，其中 `base_seed` 每个 epoch 变一次。 | 以为设了就一定对。要验证：**跑两个 epoch，把每个 worker 生成的增强参数打出来比对**，重复了就是没生效。 |
| **deterministic eval transform** | 确定性验证变换 | 验证/测试集只做确定性的、与部署端完全一致的变换（resize + letterbox + 归一化），不做任何随机增强。 | 验证集加随机增强会让指标带上额外方差，**导致你根本无法判断模型改进是不是真的**；更糟的是它会掩盖训练-推理不一致。 | 以为"验证时也增强能更鲁棒地评估"。评估要的是**低方差 + 与部署一致**，不是鲁棒。要评估鲁棒性请单独建鲁棒性切片测试集。 |
| **CPU-bound dataloading** | 数据加载 CPU 瓶颈 | 增强算子跑在 CPU 上，速度跟不上 GPU 消费，导致 GPU 周期性空转。 | **增强常常才是训练吞吐的真正瓶颈**，尤其是 Mosaic（4 张解码 + 4 次 warp）与高分辨率输入。诊断信号是 GPU 利用率呈**锯齿状周期性掉到低位**，而不是稳定在高位。 | 看 GPU 平均利用率。平均 60% 可能是"稳定 60%"（计算瓶颈）也可能是"0 和 100 交替"（数据瓶颈），处方完全相反——**要看时间序列的波动模式**。 |
| **prefetch / persistent_workers** | 预取 / 常驻 worker | 提前准备下一批数据；worker 进程跨 epoch 不销毁重建。 | 解 CPU 瓶颈的第一梯队手段，几乎零成本。`persistent_workers=False` 时每个 epoch 重建进程池，小数据集上开销占比可以很夸张。 | 以为加 worker 数总能解决。worker 数超过物理核数后会因上下文切换而反向下降，且每个 worker 都要占一份内存。 |
| **GPU-side augmentation** | GPU 侧增强 | 用 DALI / Kornia 把解码与增强搬到 GPU 上执行。 | CPU 实在跟不上时的终极手段，能把数据管线开销降一个数量级。 | 以为一定更快。它会**和训练抢 GPU 算力与显存**；在 GPU 已经是瓶颈的场景下搬过去反而更慢。要先确认瓶颈在 CPU。 |
| **TTA (test-time augmentation)** | 测试时增强 | 推理时对同一张图做多尺度/翻转等变换，分别预测后融合结果。 | 刷榜标配，通常能带来 +1–2 mAP。它是"用延迟换精度"的最直接手段。 | 以为可以直接用在车端。TTA 的延迟是 N 倍（N = 变换数），**在 33ms 的帧预算里几乎不可用**；而且翻转 TTA 在有手性语义的 TSR 上会引入错误假设。 |
| **WBF (weighted boxes fusion)** | 加权框融合 | 把多个模型/多次 TTA 的框按置信度加权**平均**成一个新框，而不是像 NMS 那样保留一个、删掉其余。 | **融合场景下 WBF 明显优于 NMS**：NMS 会丢弃所有非最高分的框，等于扔掉了其他视角提供的定位信息；WBF 让它们共同贡献坐标，定位精度更高。 | 把 WBF 当成 NMS 的通用替代。**单模型单次推理时 NMS 仍是标准做法**；WBF 的收益来自"多个来源的框描述同一目标"这个前提。 |
| **Soft-NMS** | 软性非极大抑制 | 不直接删除重叠框，而是按重叠度衰减其分数。 | 密集场景下比硬 NMS 召回更高，是理解"删 vs 降权"这一思路差异的好例子。 | 以为它能替代 WBF 做融合。Soft-NMS 仍然是**抑制**机制，不做坐标融合。 |
| **augmentation config versioning** | 增强配置版本管理 | 把增强流水线的完整定义（算子、参数、概率、顺序、随机种子）作为实验元数据的一等公民记录下来。 | 没有它，三个月后你无法回答"这个模型当时到底用了什么增强"，也就无法复现或归因。**增强配置的信息量不比模型结构少。** | 以为记个 `strong_aug=True` 就够了。要记录的是**能重建出完全相同流水线的全部信息**，包括库的版本号（同一个 API 在不同版本行为可能变化）。 |
| **train-inference gap** | 训练-推理鸿沟 | 训练时的预处理与推理时不一致造成的系统性精度损失。 | 本课三判据的第三条。**增强流水线是这个鸿沟最常见的发生地**：letterbox 参数、归一化顺序、通道顺序、插值方式。 | 以为"跑通了就说明对齐了"。这类不一致**从不报错**，只是掉点。唯一可靠的检查是拿同一张图跑训练端与部署端的预处理，做逐像素对拍。 |

## 五 · 消融与验证 · Ablation & Validation

| 术语 (EN) | 中文 | 一句话定义 | 为什么重要 | 常见误解 |
|---|---|---|---|---|
| **sliced evaluation** | 分场景切片评测 | 按距离/像素尺寸/光照/天气/类别/遮挡度把测试集切开，分别算指标。 | **本模块最重要的一条。** 整体 mAP +0.3 完全可能是"雨天 +3、晴天 −1"的合成结果；不切片你既看不见收益来自哪，也看不见代价付在哪。 | 以为切片只是"更细的报告"。它是**归因工具**：一个增强如果只在它针对的切片上涨，那是真信号；如果各切片均匀微涨，多半是噪声。 |
| **seed variance** | 种子方差 | 同一配置只换随机种子时，最终指标的自然波动。 | **检测任务的典型种子方差是 ±0.2–0.5 mAP。** 这意味着「+0.3」这个量级的单次结果不具备任何信息量。在面试里主动说出这一点能立刻拉开差距。 | 以为跑一次赢了就是赢了。单次对比的**方向都可能是错的**——两个等效配置里总有一个会"赢"。 |
| **paired significance test** | 配对显著性检验 | 同一批种子/同一批样本上做 A/B，对**配对差值**做检验，而非比较两组独立均值。 | 配对消掉了种子与样本带来的共同方差，**检验功效远高于非配对检验**，因此需要的重复次数少得多。这是小样本实验里最划算的一招。 | 用独立两样本 t 检验比较两组跑分。这浪费了配对结构，会让本来显著的结果检不出来（也可能反过来给出虚假信心）。 |
| **bootstrap CI** | 自助法置信区间 | 对评测样本有放回重采样多次，重算指标，用分布的分位数给出置信区间。 | mAP 没有解析的方差公式，bootstrap 是给它加误差棒的标准做法。**报告"+0.3 [−0.2, +0.8]"比报告"+0.3"诚实得多。** | 以为 bootstrap 能替代多种子。二者度量的是**不同的方差来源**：bootstrap 度量评测集抽样方差，多种子度量训练随机性方差，两者都要有。 |
| **multiple comparison correction** | 多重比较校正 | 同时做 N 个比较时调整显著性阈值（Bonferroni / Holm / Benjamini-Hochberg）。 | **切片评测天然产生多重比较**：切 12 个片，在 α=0.05 下即使全无效果也大概率会有 1 个"显著"。不校正的切片结论基本不可信。 | 以为校正是学术洁癖。它直接决定你会不会为一个纯噪声的"雨天涨了 3 分"去改整条流水线。 |
| **power analysis** | 功效分析 | 在给定效应量与方差下，计算"要多少次重复才能以 80% 概率检出这个效应"。 | 它把"我要跑几个种子"从拍脑袋变成计算。**结论常常令人不适**：在 σ=0.3 时检出 +0.3 的效应需要约 16 对重复——这就是为什么很多增强论文的结论不可靠。 | 以为 3 个种子就够。3 个种子只能检出约 1σ 以上的效应，即 mAP +0.6 以上。 |
| **equal-budget comparison** | 同预算对比 | 对比两个配置时，训练 epoch、算力、调参次数都必须相同。 | 不同预算的对比是**结构性不公平**，而且方向可预测：强增强在短 schedule 下必然吃亏。 | 以为"都训到收敛就公平了"。收敛判据本身就受增强强度影响；强增强的模型收敛更慢，你的早停策略会系统性地惩罚它。 |
| **augmentation × schedule interaction** | 增强 × 训练时长的交互 | 增强强度与所需训练轮数存在强交互：增强越强，回本所需的 epoch 越多。 | **这是增强消融里最大的混杂因子。** 一个在 300 epoch 上涨 1.5 的增强，在 50 epoch 上可能掉 0.8——两个结论都对，只是问的不是同一个问题。 | 以为可以在短 schedule 上"快速筛选"增强再上长训练。这个筛选会系统性地淘汰掉恰恰是最有价值的强增强。 |
| **over-augmentation symptoms** | 增强过强的指纹 | 训练 loss 居高不下、**验证指标优于训练指标**、收敛显著变慢、小模型明显掉点。 | 有了这组指纹，"增强是不是开太猛了"可以在训练早期就判断，不用等跑完。**"验证优于训练"这一条最具诊断性**——它几乎唯一地指向训练分布比验证分布难。 | 把"验证优于训练"当好事。它说明训练时看到的样本比验证时难得多，通常意味着增强强度已经越过了最优点。 |
| **effect size (Cohen's d)** | 效应量 | 差值除以标准差，衡量"这个提升相对于噪声有多大"。 | 比 p 值更能回答"值不值得做"。**p 值只说"不是零"，效应量说"有多大"**——在样本量足够时任何微小差异都能显著。 | 只看 p 值。p<0.05 且 d=0.1 的提升，工程上几乎没有意义。 |
| **regression gate** | 回归门禁 | 发布前的自动检查：关键切片不得掉点超过容差，否则阻断发布。 | 增强改动是**全局性**的（影响每一个训练样本），最容易造成"目标场景涨、其他场景掉"的隐蔽退化。门禁是唯一能系统性拦住它的机制。 | 门禁只看整体 mAP。整体指标恰恰是最容易掩盖切片退化的那个数——门禁必须建在切片上。 |
| **failure-mode-driven recipe** | 失效模式驱动的配方 | 先枚举失效模式，再为每个模式挑对应增强，最后为每个模式建一个验证切片。 | 本课的收口方法论，也是把 C55 的失效模式清单变成可执行工作的桥：夜间弱 → 低光合成 + 切片验证；远处小目标弱 → Mosaic + LSJ + 按像素尺寸分桶；稀有类少 → Copy-Paste + 逐类 AP。 | 从增强列表出发挑"看起来有用的"。**正确方向是从失效模式反推**，因为只有这样每个增强才自带一个可证伪的验证切片。 |
| **augmentation vs more data** | 增强 vs 采新数据 | 两条互补路径：榨干现有数据 vs 花钱扩充数据。 | 它们的成本差一到两个数量级，所以决策顺序几乎总是"**先增强，不够再挖掘/采集**"。Copy-Paste 是二者的交汇点——它用已有实例合成新样本。 | 以为增强能无限替代真实数据。增强只能在**已有样本张成的流形附近**扩展；一个从未见过的标志类别，再强的增强也造不出来。 |
