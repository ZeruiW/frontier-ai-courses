1增强的本质：往模型里注入「不变性先验」

大多数教材把数据增强讲成「变着法子造更多训练样本」。这个说法不能算错，但它解释不了任何一个真正的工程决策——为什么 Mosaic 在最后 10 个 epoch 必须关掉？为什么交通标志检测里水平翻转是错的？为什么色相抖动幅度要按类别分开设？要回答这些，必须换一个更准确的定义。

直白说

增强是你在告诉模型：「这些变化不改变答案」。把一张图左右镜像，它还是一只猫——所以你把镜像后的图配上同一个标签喂进去，模型就被迫学到「左右镜像不影响类别」这条规则。数据本身没有变多，变多的是「约束」。你没有采集新信息，你只是把自己已经知道的物理/语义规律，翻译成了模型能听懂的形式（成对的输入-标签样本）。

严谨说

形式化地说，标准经验风险最小化是在数据分布 D 上最小化损失；增强则是在一个增广分布（augmented distribution）上最小化损失，其中变换 T 从一个变换族 𝒯 中采样，而标签同时按一个配套映射 g_T 变换。当 𝒯 恰好是模型任务真正不变的那个群时，增强等价于在假设空间上施加不变性约束，理论上可以看作一种方差缩减（Chen, Dobriban & Lee, 2020）。当 𝒯 超出真实不变性范围时，它就变成了在教模型错误的规律。

\[\mathcal{R}_{\text{aug}}(f)\;=\;\mathbb{E}_{(x,y)\sim\mathcal{D}}\;\mathbb{E}_{T\sim\mathcal{T}}\Big[\;\ell\big(f(T(x)),\;g_T(y)\big)\;\Big]\]

这个公式里藏着本课全部内容的种子，值得逐项拆开看：

  • 𝒯（变换族）选错 → 你在教模型一条现实中不成立的规律。TSR 里的水平翻转就是这个错误的教科书案例：镜像后的「向左转弯」在物理世界里就是「向右转弯」，标签却没跟着变。
  • g_T（标签变换）写错 → 图变了标注没变，或者变得不对。这是检测增强独有的失败模式，而且极其隐蔽：图看起来完全正常，框错了却没人看得出来。模块 01 整章都在处理这件事。
  • 𝒯 的强度过大 → 增广分布与部署分布严重脱节，模型把容量花在了永远不会遇到的输入上。Mosaic 就是典型：拼接图在真实相机里不存在。
  • 训练用了 𝒯 而推理没有 → 训练-推理鸿沟。letterbox 与归一化这类「必须两端一致」的算子如果实现不同，框会整体偏移几百像素（模块 01 会给出精确数字，C60 会给出定位方法）。

把这句话记住，本课后面所有判断都能从它推出来：增强不是在造数据，是在写一条你相信的物理规律，并且用「成对的样本」这种模型唯一能听懂的语言把它说出来。既然是「你相信的规律」，那它就可能是错的——而错误的先验比缺少数据更有害，因为模型会稳定地、自信地学会它。

2三个判据：一个增强到底该不该用

既然增强是先验注入，那「该不该用某个增强」就有了可操作的判据。本课全程会反复使用下面这三条，它们互相独立、缺一不可，而且必须按顺序检查——第一条不过，后两条就不用看了。

判据问题不满足会发生什么本课在哪里展开
① 保标签语义变换后，原来的标签还是正确答案吗？（对检测：类别不变、且框仍紧贴目标）模型学到错误规律，而且它学得很扎实。表现为「某一类稳定地被判成另一类」，用更多数据也救不回来模块 01（几何/翻转白名单）、模块 02（色相与颜色语义）
② 贴近部署分布增强产生的图像，车上那台相机有可能拍到吗？模型容量被浪费在不存在的输入上；更糟的是它会稀释真实分布的有效样本比例，小模型上直接掉点模块 02（天气/低光合成）、模块 03（Mosaic 的 close 策略）
③ 不制造训练-推理鸿沟推理端会做同样的事吗？如果不会，差异有多大、有没有显式对齐？离线 mAP 好看、上车掉一大截。这是「离线 0.82、路测像 0.6」的头号成因之一模块 01（letterbox 逆变换）、模块 04（TTA 与流水线）、C60（一致性对拍）

直白说

三条判据的顺序不是随便排的，它反映了危害的量级。判据① 失败是正确性问题：模型学错了，且错得稳定，你在验证集上也看不出来（因为验证集用了同样错误的标注约定，或者根本没有那个类别的镜像样本）。判据② 失败是效率问题：模型没学错，只是把力气花在了没用的地方，多训练一会儿通常能补回来。判据③ 失败是交付问题：训练本身没问题，只是交出去的东西和训练时不是一个东西。

严谨说

工程上还有第四个隐含判据：成本。增强跑在 CPU 上，而 CPU 常常是训练吞吐的真正瓶颈（模块 04 会量化：一个 GPU 利用率在 40%–95% 之间周期性抖动的训练任务，几乎可以断定卡在数据管线上）。一个只涨 0.1 mAP 却让训练慢 30% 的增强，在有限的调参预算下是净亏损——因为省下的时间本可以多跑两个种子，而模块 05 会证明，两个种子的价值往往超过 0.1 mAP。

判据① 有一个特别容易被忽略的子情况：标签「语义上」还对，但「几何上」不再紧贴目标。旋转增强就是如此——旋转 45° 后取四角外接框，框仍然框住了标志，类别也没变，看起来一切正常；但框的面积膨胀了整整一倍，一半是背景。模型被反复告知「框住一半背景也算对」，定位精度就这么被慢慢教坏了。模块 01 会把这笔账算到小数点后。

3增强 vs 正则化 vs 更多数据：三者不能互相替代

面试里有一个高频问题：「增强和 dropout / weight decay 都是防过拟合，有什么区别？」 很多人答「增强是数据层面的正则化」就停了——这个回答不算错，但它没有回答任何有用的东西。真正的区别在于：三者注入的信息完全不同，因此它们的失效场景也完全不同。

增强正则化（dropout / weight decay / label smoothing）更多真实数据
注入了什么关于任务的具体先验（哪些变化不改变标签）对函数复杂度的通用偏好（更平滑、更稀疏）真实的新信息
需要什么知识领域知识——你必须知道什么是不变的几乎不需要钱和时间
能覆盖长尾吗部分能：copy-paste 可以把稀有类样本数翻十倍（模块 03）❌ 完全不能✅ 能，但稀有类正因为稀有才难采集
能修正偏差吗❌ 不能：增强只在已有样本的邻域内生成，没见过夜间就变不出夜间（合成除外）❌ 不能✅ 能
典型失败先验错了 → 稳定学错过强 → 欠拟合，且症状不明显加的是模型已经会的 → 边际收益≈0（C58）
工程代价CPU 吞吐 + 实现正确性风险几乎为零标注成本 + 数据闭环基建

直白说

第四行「能修正偏差吗」是最关键的一行，也是最常被误解的一行。增强只能在已有样本的邻域里生成新样本——如果训练集里一张夜间图都没有，你把亮度调低 60% 得到的也不是真正的夜间图（真实夜间的噪声结构、光源眩光、ISP 的自动曝光行为、运动模糊长度全都不同）。它像夜间，但它不是夜间。所以「用低光合成代替夜间采集」在幅度小的时候是有效的鲁棒性训练，幅度大的时候就是自欺欺人。

严谨说

反过来，也有一个方向的替代是成立的：当某个变化确实属于「真实分布内的、可精确建模的」变换时，增强的性价比远高于采集。TSR 里最典型的就是尺度——同一块标志在 20 米和 60 米处的像素尺寸差 3 倍，而这个变换就是一次缩放，物理上精确、实现上零风险。与其花钱采集「同一块牌子在各个距离下的样本」，不如把缩放增强的范围开对。这就是为什么模块 01 里「随机缩放」被列为 TSR 收益最高的几何增强，而不是翻转。

一句可迁移的判断法则：先问「这个变化在部署环境里是不是真的会发生、并且我能不能精确建模它」。两个都「是」→ 用增强，性价比最高（缩放、平移、轻微光照、JPEG 压缩）。第一个是、第二个否 → 优先采集真实数据，增强只做兜底（夜间、雨雾、极端逆光）。第一个否 → 根本不该做这个增强（垂直翻转、45° 旋转、极端色相抖动）。

4检测增强难在哪：图变了，标注必须跟着一起变

分类增强的标签变换 g_T 是恒等映射——不管你怎么翻转裁剪调色，标签还是那个整数。这一点让分类增强几乎不可能写错：图看起来不对，你一眼就发现了。

检测不是这样。检测的 g_T 是一个真正的函数：它要把每个框做同样的几何变换，处理越界，决定哪些目标该丢弃，还要在多目标之间保持一致。而它写错的时候，图看起来完全正常。

分类增强：只有一条轨道 image ──T──> image' label ───────> label （g_T = 恒等，不可能写错） 检测增强：两条轨道必须严格同步 image ──────T──────> image' │ │ └── 必须是同一个 T ──────┘ boxes ─────g_T─────> boxes' ← **这里是所有 bug 的产地** │ ├─ 几何：四角变换 -> 外接框（模块 01） ├─ 越界：裁剪 / 丢弃 / 标记为 ignore（模块 01） ├─ 尺度：变换后过小的框怎么办（模块 01，对小目标致命） └─ 语义：类别是否需要跟着改（左转 <-> 右转，模块 01） ⚠️ 失败的特征：图是对的、框是错的、loss 照样下降、 验证集上也「正常」（因为验证集不做增强）—— **只有在训练集与验证集的 AP 差距上留下一点点异常。**
维度分类增强检测增强
标签变换 g_T恒等框的仿射作用 + 越界规则 + 丢弃规则 + 类别映射
越界不存在这个概念目标可能被切掉一部分、甚至完全切出画面 → 要判「留、裁、丢、还是标为 ignore」
多目标交互一图一标签一图多目标；规则必须对每个目标独立成立——一张图里只要有一个目标不能翻，整张图就不能翻
尺度的语义缩放几乎无害缩放直接改变「小目标」的构成与正样本数量；缩小后的框可能被 min_size 规则整批删掉
遮挡类增强Cutout 只是遮住部分特征遮住整个目标 → 该框变成纯噪声监督（要求模型从纯背景里预测一个框）
混合类增强MixUp 混合标签即可框不能「混合」，只能拼接（Mosaic）或粘贴（Copy-Paste）——这是两个完全不同的算子族（模块 03）
错误的可见性肉眼可见肉眼几乎不可见：图正常、框偏了，需要专门的可视化或断言才能发现

直白说

「错误的可见性」这一行值得展开，因为它决定了本课的工程方法。检测增强的 bug 不会让程序崩溃，也不会让 loss 变成 NaN，它只会让指标低一点点——低到你以为是「模型不够好」而不是「数据管线有 bug」。真实项目里，一个「旋转后框没有正确膨胀」的实现错误可以在代码库里活好几个月，直到某个人偶然把增强后的图和框画出来看了一眼。

严谨说

所以本课的纪律是：每一个增强算子都必须附带一个可执行的正确性断言，而不是靠可视化抽查。断言的形式在 notebook 里会反复出现——用目标的掩码/轮廓点算出「真实的紧框」，再和算子输出的框比 IoU。能写出这个断言，说明你真的理解了这个算子的 g_T；写不出来，说明你只是抄了一段代码。这条纪律与 C60 的「训练-部署逐层对拍」是同一个思路：用可验证的断言代替「我看着挺对的」。

被丢弃但仍可见的目标 = 假负样本监督

一个在 TSR 项目里真实发生过、且代价极高的错误：随机裁剪后，对「被裁到画面外超过一半」的目标直接 drop（从标注里删掉），但图像里那半个标志还清清楚楚地留着。结果是模型被明确训练成「看到半个标志 → 这里没有东西」。而 TSR 里目标被画面边缘截断是极常见的情况（标志从画面上方进入视野的整个过程都是这样）。症状：远处标志的首次检出距离明显偏近，且 recall 在图像边缘区域系统性偏低。正确做法是标为 ignore 区域（既不算正样本也不算负样本），而不是删除。模块 01 会把这三种处理方式（keep / ignore / drop）的边界讲清楚并实现出来。

真实图像数据集（TT100K 等）用 np.random 按物理合理的规则合成场景（圆形/三角形标志、长尾类别分布、符合透视的尺寸），并说明合成规则
YOLO 的 letterbox()手写正变换 + 逆变换，并复现三种常见的逆变换 bug，量化它们造成的像素偏移
mmdet 的 gt_bboxes_ignore手写 ignore 区域的生成规则，量化「误删可见目标」对召回的伤害

三条贯穿全课的纪律，与前面的三个判据一一对应：

  • 每个算子都要能写出 g_T。如果你说不清「这个变换对标注做了什么」，就不要把它放进流水线。说不清，通常意味着它对某些类别是错的。
  • 每个算子都要有可执行的正确性断言。断言的标准形式：用目标的轮廓点算出「真实紧框」，与算子输出比 IoU。可视化抽查发现不了系统性偏移，断言可以。
  • 每个增强都要说清它对应部署分布里的什么现象。说不出来的，八成属于「看起来很酷但没用」那一类，而它还在吃你的 CPU 预算。

最后提醒一件事，它会让你读这门课时省很多力气：本课几乎所有「坑」的根源都是同一件事——增强作用在图像上，而标注是另一个对象。几何变换要同步（模块 01）、颜色变换会破坏「颜色即语义」（模块 02）、拼接与粘贴会创造出标注体系里不存在的构图（模块 03）、并发执行会让随机性失控（模块 04）、而这一切的效果又只能通过分场景切片才看得见（模块 05）。抓住「图像与标注是两个必须同步的对象」这条线，五个模块就串成一条了。

7研究前沿与开放问题

检测增强是一个「工程上极其成熟、理论上仍很粗糙」的领域。下面几条是目前真正开放的问题，也是面试里聊到深处会碰到的地方。

  • 增强策略的自动搜索：成本与可迁移性。AutoAugment 用强化学习搜出的策略在 ImageNet 上很强，但搜索成本以数千 GPU 小时计；RandAugment 证明「只用两个超参（算子数 N、强度 M）随机采样」几乎能达到同等效果——这个结果本身就说明「搜出来的策略」里大部分结构是冗余的。检测版的 Learning Data Augmentation Strategies for Object Detection（Zoph et al., 2020）显示搜到的策略跨数据集迁移性尚可，但跨任务（分类→检测）几乎不迁移。为什么？目前没有令人满意的解释。
  • 群论视角覆盖不了现代增强。Chen–Dobriban–Lee 的方差缩减理论要求 𝒯 是一个群（有单位元、逆元、封闭）。翻转、旋转、平移都满足；但 Mosaic、CutMix、Copy-Paste 都不是群作用——它们把多个样本组合成一个新样本，根本不在这个框架里。而恰恰是这几个算子贡献了检测上最大的收益。「为什么混合类增强有效」目前只有直觉解释（增大批内多样性、制造更多小目标、丰富上下文），缺少理论。
  • 生成式增强的可控性与标注问题。用扩散模型合成罕见场景（夜间施工区、被树叶遮挡的限速牌）在概念上极有吸引力，但有两个硬问题：① 生成图与真实相机图之间存在系统性域差（ISP 特性、噪声结构、镜头畸变），模型可能学到「生成图的指纹」而不是场景内容；② 标注从哪来——如果标注也是生成的，就有循环论证的风险。目前工业界的主流用法是只用生成图做「难负样本」（例如生成各种广告牌来压误检），而不是生成正样本。
  • 增强与大规模预训练的替代关系。一个反复被观察到但缺少定论的现象：预训练规模越大，增强的边际收益越小。直觉解释是预训练已经把不变性学进去了。但这在检测的长尾类别上似乎不成立——copy-paste 对稀有类的提升在有无预训练时都很显著。「哪些增强会被预训练吸收、哪些不会」是一个有实用价值的开放问题。
  • 检测增强缺少统一的评测协议。同一个增强在不同检测器、不同训练时长、不同数据规模下经常给出相反的结论（模块 05 会量化这一点：强增强在 12 epoch 下掉点、在 300 epoch 下涨点）。目前论文里报的增强收益大多不可比。这也是为什么面试里问「你怎么证明这个增强有用」比问「你用了哪些增强」更能区分水平。
  • 语义敏感变换的自动发现。「哪些类别不能水平翻转」目前完全靠人工整理白名单（模块 01 会给出 TSR 的完整方法）。能否从数据里自动学出来——比如通过「翻转前后模型置信度的类别间转移」来识别镜像对——是一个尚无成熟方案、但工程价值明确的方向：标志类别有成百上千种，人工维护白名单本身就是长期负担。

必读：AutoAugment: Learning Augmentation Strategies from Data（Cubuk et al., CVPR 2019，搜索式增强的起点）★；RandAugment: Practical Automated Data Augmentation with a Reduced Search Space（Cubuk et al., 2020，证明搜索大多是冗余的）★；Learning Data Augmentation Strategies for Object Detection（Zoph et al., ECCV 2020，检测专用策略搜索，含 bbox 级算子）★；Bag of Freebies for Training Object Detection Neural Networks（Zhang et al., 2019，把「不增加推理成本的技巧」系统化）；YOLOv4: Optimal Speed and Accuracy of Object Detection（Bochkovskiy et al., 2020，Mosaic 的出处与 BoF/BoS 分类法）★；Simple Copy-Paste is a Strong Data Augmentation Method for Instance Segmentation（Ghiasi et al., CVPR 2021，长尾最直接的解法）★；A Group-Theoretic Framework for Data Augmentation（Chen, Dobriban & Lee, JMLR 2020，增强为何有效的理论视角）；Albumentations: Fast and Flexible Image Augmentations（Buslaev et al., 2020，工业界事实标准库的设计文档）；Traffic-Sign Detection and Classification in the Wild（Zhu et al., CVPR 2016，TT100K 数据集，本课合成数据的分布依据）★。相邻课程：C55（TSR 领域与失效模式）、C57（小目标）、C58（长尾与数据闭环）、C60（训练-部署一致性）、C61（实验设计与显著性）。完整清单见 references.md。
