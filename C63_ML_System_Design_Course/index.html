ML 系统设计面试

HR 白纸黑字写着一面包含 system design，而全库 62 门课里只有 C07 模块 07 的一节讲过 ML/eval system design 框架——没有方法论，没有案例库。这门课要澄清一件常被误解的事：system design 面试评的不是你画的框图有多复杂，而是三件事——你有没有先把模糊需求变成可验收规格、你的每一次取舍有没有显式说出来、以及最后你敢不敢自己指出方案的弱点。七步框架、45 分钟时间预算、六个完整案例演练，都是为了把这三件事练成可执行的动作。

6 模块 七步框架 · 45 分钟时间预算 · 四种失败模式 六个完整案例：TSR / 车道线 / 图搜图 / 内容审核 / 推荐排序 / 数据闭环 容量估算锚点表：QPS→实例数 · 参数量→显存 · FLOPs→算力 CPU only · 纯 numpy/标准库 · 无需 GPU
怎么用： 每个模块先读 HTML 讲解（讲的是面试官在每一步想听到什么、以及大多数人在这一步漏了什么），再跑 notebook——把「设计方法」变成能运行的小工具，而不是停留在概念层面。你会亲手实现的东西包括：七步框架的检查器（给一份设计稿，自动指出缺了哪个环节）与 45 分钟时间预算模拟器、需求澄清问题清单生成器与三层指标映射一致性检查、给定代价矩阵求最优工作点、把端到端延迟预算拆到各子系统的分解器、标注成本模型与预算分配、能构造并检出四类数据泄漏（时间/地理/设备/track）的检测器、baseline 阶梯设计器与约束驱动的模型选型求解、离线评测方案生成器（切片 + 回归门禁）与 A/B 样本量 / 功效计算、容量估算器（QPS/显存/算力/成本，含数量级校验）与降级策略决策表、以及六个案例的自评分器与一份可直接复用的设计文档模板。本课的核心主张是：45 分钟里拉开差距的从来不是「你懂不懂 Transformer」，而是三件事——有没有先花 5 分钟把题目问清楚（面试官需要看到你不会替他做假设）、有没有把每一次取舍的理由说出来（「我选 A 是因为延迟预算不允许 B」比只说「我选 A」值钱得多）、有没有在结尾主动说出方案的弱点（这是唯一能证明你不是在背模板的动作）。本课与 C37（MLOps 生命周期）/ C48（云端部署）/ C58（数据闭环）/ C60（车端一致性）/ C55（TSR 领域知识）的分工必须说清楚：那几门课讲的是技术怎么做（怎么建 CI/CD、怎么在云上部署、怎么挖长尾难例、怎么定位训练-部署不一致），本课讲的是45 分钟面试里怎么组织和取舍——案例库里引用它们的结论，而不会重述它们已经讲过的实现细节。本环境不需要 GPU：所有检查器、求解器、估算器都是纯 numpy + 标准库，断网可跑，秒级出结果。
