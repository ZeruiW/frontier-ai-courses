1这门课讲什么

欢迎来到 工业研究工程实务。这门课收拢的是一批没有归属、却在工业界天天要用的技能——它们不属于任何一个「算法方向」，所以在课程体系里总是被漏掉，但在工作里几乎每周都会遇到。

能力为什么被漏掉工作里什么时候需要
TensorFlow / Keras 的心智模型整个生态已经 PyTorch 化，教材也是接手遗留系统；对接 TF 栈的团队；读 2019 年前的代码与论文实现
跨框架迁移与权重对齐「换个框架重训一遍」听起来简单，实际全是坑复现论文（作者用 TF、你用 PyTorch）；把研究模型交给用别的栈的团队
模型导出与推理运行时研究不关心导出，部署课又假设你会模型要上边缘设备/移动端/嵌入式；要接 TensorRT/CoreML/TFLite
真机 GPU 工作流云上「有卡就能跑」，直到出问题OOM、CUDA 版本地狱、性能远低于预期、多卡拓扑问题
专利与研究产出学术课只讲论文，不讲专利企业研究院几乎都有专利指标；开源合规是法务红线

直白说

这五项的共同点是：它们都在「算法之外、产品之前」的那段。你不会因为它们写出更好的论文，但会因为它们把一个模型真正交出去——交给另一个团队、交给一台没有网络的设备、交给专利审查员。而「交出去」恰恰是工业研究与学术研究最本质的区别。

严谨说

本课的另一个动机是直面 JD。「Proficiency with deep learning frameworks such as TensorFlow, PyTorch, or JAX」——注意 TensorFlow 排在第一位，因为大量企业的生产栈仍是 TF；「Strong understanding of distributed computing and GPU acceleration using CUDA」——这要求的不只是「知道 CUDA 是什么」，而是能诊断一台真机上的问题；「Contribute to research papers, patents, and open-source projects」——专利是明确写出来的。这些条目在全谱课程里此前都没有对应的落点。

学完你应当能回答这类问题：tf.function 与 torch.compile 的语义差别在哪、为什么前者会「重追踪」？把 TF 的权重搬到 PyTorch 时，哪些层的形状/顺序需要转置、哪些 eps 默认值不同？ONNX 导出时「动态轴」没设会怎样、算子不支持时有几条出路？nvidia-smi 里的 utilization 为什么不代表「跑满了」？一个想法要满足什么条件才可能获得专利、交底书该写什么？Apache-2.0 与 GPL 混在一个仓库里会发生什么？

本课与相邻课程的分界要说清楚，避免重复：C38（框架与加速）讲 autograd、torch.compile、JAX/XLA、混合精度的原理；C36 讲 GPU kernel 怎么写；C39 讲多机分布式；C27 讲量化算法；C48 讲部署与云原生；C40 讲研究方法论与论文写作。本课只讲那些「跨过边界」时才会遇到的问题——跨框架、跨运行时、跨到真实硬件、跨到法务与知识产权。

3方法论：用 numpy 复现框架语义 + 真实命令作对照

本课有一个尴尬的约束：它讲的东西本质上都需要真实环境——TensorFlow、ONNX Runtime、NVIDIA GPU、专利数据库。而本环境一个都没有。

直白说

但和 C50 一样，这个约束其实指向了更好的学法。因为这些工具的困难几乎都不在「怎么调 API」，而在「它的语义与你以为的不一样」——tf.function 的重追踪、权重布局的转置、ONNX 的形状推断、CUDA 的版本矩阵、专利的可专利性判断。这些语义全都可以用几十行 Python 精确复现，而复现之后你对真实工具的理解会比「跑通一个 tutorial」深得多。

严谨说

所以本课沿用「迷你复现 + 真实对照」的两条腿：notebook 里用纯 numpy 写一个 tracing 编译器、一个权重映射器、一个迷你 IR 与导出器、一个显存计算器、一个许可兼容性求解器；讲解里紧跟真实的 tf.function 代码、torch.onnx.export 参数、nvidia-smi 输出、以及一份可直接用的交底书模板。后者都是可原样复制到有环境的机器上使用的。

三条贯穿全课的纪律：

  • 数值对拍：任何「迁移」「导出」「优化」都必须给出逐层的数值等价证明，而不是「跑通了、输出看起来对」。模块 02/03 会把这套方法学写成可复用的函数。
  • 版本即环境：跨框架/跨运行时的问题里，有相当比例是版本问题（opset 版本、CUDA/driver 矩阵、算子在某版本才支持）。凡是报告问题，必须同时报告版本三元组。
  • 边界要显式：交出去的东西必须附带「它在什么条件下成立」——支持的输入形状范围、精度损失、依赖的运行时版本。不写清边界的交付，等于把问题推给下游。

这三条其实是同一件事的三个侧面：「交出去」意味着你不再控制运行环境，所以必须用「可验证的断言」代替「我这边是好的」。数值对拍是对正确性的断言、版本三元组是对环境的断言、边界说明是对适用范围的断言。工业研究工程的成熟度，很大程度上就体现在这三类断言写得有多具体。

4边界：这门课不讲什么，以及怎么用它

把边界画清楚，你才知道遇到问题时该翻哪一门课。本课与相邻课程的分工是「层次」而不是「主题」——同一个词（比如「量化」「显存」「编译」）在不同课里指的是不同层次的问题。

问题本课讲的层次去哪门课看更深的层次
编译与图追踪语义、重追踪、图 IR 的约束C38（autograd 与编译器内部）、C36（kernel 融合怎么做）
量化导出时的精度降级怎么验证、容差怎么设C27（量化算法本身：GPTQ/AWQ/SmoothQuant）
推理加速选哪个运行时、有什么约束、怎么发现静默回退C24（引擎内部：PagedAttention、continuous batching）
显存怎么算、OOM 怎么按成本诊断C39（ZeRO/FSDP 的分片机制）、C36（内存层级）
部署把模型交给运行时的那一步C48（容器、K8s、扩缩容、成本）
HuggingFace—（本课不讲）C50（Auto* / Trainer / PEFT / accelerate）

直白说

换个说法：其它课程讲「怎么把某件事做好」，本课讲「怎么把做好的东西交出去，并证明交出去之后它还是对的」。这是一个被系统性低估的技能——因为它在论文里不出现、在教程里不出现，只在「上线前一周发现导不出去」的时候突然变成最重要的事。

严谨说

也正因为如此，本课的五个模块彼此独立，更像一本按问题组织的手册而不是一条学习路径。建议的用法是：先通读一遍（约两小时），建立「遇到这类问题时该想到什么」的索引；真正遇到问题时再回来精读对应模块并跑 notebook。第二次读的收获通常远大于第一次——因为那时你有一个具体的、正在痛的问题。

还有一类内容本课刻意不覆盖：具体框架 API 的用法细节。原因是 API 三年就换一茬，而语义不会——tf.function 的参数名会变、torch.onnx.export 正在换实现路径、TensorRT 每个大版本都调整接口。但「Python 只在追踪时执行一次」「不设动态轴就被写死」「优化器状态是参数的 6 倍」这些不会变。所以本课把篇幅花在语义与账本上，把 API 放进每个模块末尾的 🧪 胶囊里——胶囊会过时，正文不会。

5环境与运行

本课全程 纯 numpy + 标准库、CPU 可跑、不联网。不需要 TensorFlow、ONNX、CUDA 或任何专利数据库。所有 notebook 在 CPU 上实跑验证、assert 0 失败。

pip install -r requirements.txt      # numpy / pandas / jupyterlab / ipykernel
jupyter lab                          # 打开 00_setup/00_environment_check.ipynb
你需要本课怎么处理
TensorFlow / Keras用 numpy 实现一个 tracing 编译器，复现 tf.function 的追踪、缓存与重追踪语义
PyTorch用 numpy 定义等价的层，做逐层数值对拍
ONNX / ONNX Runtime手写一个迷你 IR（节点/边/形状推断/opset 版本），并实现导出与算子覆盖检查
NVIDIA GPU用参数化的显存模型与 profiler 时间线模拟器；真实 nvidia-smi 输出作对照解读
专利数据库用一套可专利性自检规则与权利要求结构校验；附真实的交底书模板
法务意见用许可兼容性矩阵做机械判断；明确标注「这不是法律意见」
这不是法律意见

关于模块 05 的一个必要声明：本课关于专利与开源许可的内容是工程视角的实用指南，不是法律意见。可专利性的最终判断由专利审查员做出，许可合规的最终判断由法务做出。本课的目标是让你能：①识别出「这可能值得申请专利」；②写出一份质量合格的交底书，让专利代理人少问你三轮问题；③在把某个开源库引入项目前，判断出「这需要法务看一眼」。能准确识别「什么时候需要专业意见」，本身就是这项能力的主要价值。

最后一句：本课的五个模块彼此独立，可以按需单独读。如果你现在正接手一个 TF 项目，直接读 01+02；如果要把模型上边缘设备，读 03；如果在调 GPU 问题，读 04；如果被要求写专利交底书，读 05。它更像一本按问题组织的手册，而不是一条必须顺着走的学习路径。
